### v2详细记录——FLT例子触发："局部/非局部/全局"不是tell属性

**触发**：用户提出FLT例子——"题目就是证明FLT"vs"中间需要FLT"，两种情况下tell相同（都是FLT跨域桥接），但"局部/非局部/全局"表现不同（前者全局，后者局部）。如果"局部/非局部/全局"是tell固有属性，它不应随题目位置变化——但它变了。

**修正**：
- "局部/非局部/全局"从形式背景属性维度中剔除
- 改为"观察Level参数"——检索时选择从哪个粒度观察trace的参数
- 属性维度从四层改为三层：domain→段结构模式→具体概念
- 形式背景表格去掉"局部/非局部/全局"列

**FCA理论依据**：FCA要求形式背景的属性必须是对象的固有特征。"局部/非局部/全局"是观察者的观察方式，不是tell的固有特征——同一个tell在不同题目位置有不同Level显现，但tell本身不变。

**覆盖性检查**：v1的所有情况在v2中是否可表达？
- v1的"局部tell"→v2中"从局部Level观察的tell显现" ✅
- v1的"非局部tell"→v2中"从非局部Level观察的tell显现" ✅
- v1的"全局tell"→v2中"从全局Level观察的tell显现" ✅
- v1的四层分类→v2的三层属性维度+观察Level参数，表达能力不减少（观察Level作为参数比作为属性更灵活）✅
- **结论**：v2完全覆盖v1的所有情况，且表达能力更强（观察Level作为参数可以灵活组合，作为属性则固定死板）

### v3详细记录——FCA理论审查触发："无尽追逐"不是独立的段结构模式

**触发**：用FCA理论审查v2的自洽性——FCA要求形式背景的属性必须是对象的固有特征。对"无尽追逐"做测试：tell"应该转向代数因式分解"在AI追逐时出现，在AI不追逐但同样需要转向时也出现——tell相同，但"无尽追逐"在前者中出现后者中不出现。所以"无尽追逐"不是tell的固有属性。

**进一步分析**："无尽追逐"本质是"探索-诊断-修复"循环断裂的trace表现——AI在探索（试模3），但没有诊断（没有识别"追逐无效"），所以没有修复（没有转换方向）。"无尽追逐"是"探索-诊断-修复"的子模式，不是独立的段结构模式。

**修正**：
- "无尽追逐"从第二层（段结构模式属性维度）移到第三层（具体概念）——作为"探索-诊断-修复"的子模式
- 第二层从6大类改为5大类：构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛
- "无尽追逐"的子模式表格保留，但标注为"探索-诊断-修复的子模式"
- "无尽追逐"同时具有双重角色：(1)作为tell属性的具体化（第三层，"探索-诊断-修复"的子模式）；(2)作为trace特征（AI在trace中的行为模式，属于观察方式那一侧）

**FCA理论依据**：FCA的属性维度应该是独立的、正交的分类标签。"无尽追逐"不是独立的——它是"探索-诊断-修复"的具体化。就像"模算术"不是独立的domain（它是"数论"的子领域），"无尽追逐"不是独立的段结构模式（它是"探索-诊断-修复"的子模式）。属性维度用粗粒度的"探索-诊断-修复"，子模式在具体概念层体现。

**覆盖性检查**：v2的所有情况在v3中是否可表达？
- v2的"无尽追逐"tell（如"模分析追逐"）→v3中属性是"探索-诊断-修复"，具体概念是"探索-诊断-修复×无尽追逐" ✅
- v2的"无尽追逐"子模式（模分析追逐/闭式猜测追逐/枚举追逐/近似追逐/放缩追逐）→v3中作为"探索-诊断-修复"的子模式保留在具体概念层 ✅
- v2的其他5大类段结构模式→v3中不变 ✅
- v2的形式背景表格中"无尽追逐"列→v3中改为"探索-诊断-修复"列（"无尽追逐"的tell现在在"探索-诊断-修复"列打✓）✅
- **结论**：v3完全覆盖v2的所有情况，且属性维度更干净（消除了非独立属性）

## 高Level概念作为分类学坐标轴——结构知识与内容知识的分离

**来源**：336号（高Level概念是分类学的坐标轴不是点）、338号（高Level概念的存储和使用方式）

### 核心洞察

高Level概念（如"同构之桥"）不是分类学中的"点"（被分类的对象），而是分类学的"坐标轴"（分类的维度本身）。

"跨域桥接"是段结构模式这个分类维度上的一个值——它是坐标轴上的一个刻度，不是被分类到一个类别中的对象。你不能把"跨域桥接"再归入一个更高的类别，它已经是属性维度本身了。

降低Level后的具体形式（如"构造Frey曲线"）才是分类学中的"点"——它们有明确的{domain, 段结构模式}属性，可以被归入{跨域, 跨域桥接}这个分类。

### 坐标系类比

```
分类学 = 坐标系
  domain = x轴（数论/代数/组合/几何/分析/跨域）
  段结构模式 = y轴（构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛）
  
具体tell/hint = 坐标系中的点
  "构造Frey曲线" = (跨域, 跨域桥接) ← 这个点在坐标系中有明确位置
  
高Level概念"同构之桥" = y轴上"跨域桥接"这个刻度的名字
  它不是坐标系中的点——它是坐标轴的组成
```

**高Level概念是分类学的结构，不是分类学的内容。**

### 结构知识与内容知识分离

| 知识类型 | 内容 | 存储位置 |
|---|---|---|
| **结构知识**（不可分类的） | domain定义、段结构模式定义、子模式定义（如"同构之桥"是"跨域桥接"的子模式）、高Level概念的三种解释文本 | 分类学Schema（本文件）+ 高Level概念解释库（技术说明书04-概念树/07） |
| **内容知识**（可分类的） | 具体tell条目、具体hint条目，每个条目有{domain, 段结构模式}属性和`case_source`标记 | tell库/hint库 |

**设计原则**：分类学文档（本文件）应该只定义坐标轴和刻度（高Level概念作为结构），不应该包含具体tell/hint（那是内容，放在库中）。

### "同构之桥"在分类学中的定位

"同构之桥"是"跨域桥接"这个段结构模式下的一个子模式——它有明确的{跨域, 跨域桥接, 子模式=同构之桥}分类，可以被归入分类目录。它有专门的AGENTS.md目录承载，有devin cli从中启动进行识别（338号）。

### tell和hint的多对多关系

**来源**：333号§2.1

tell和hint是多对多关系：
- 一个tell可以对应多个hint——同一个trace识别结果可以触发多个不同的方向提示
- 一个hint也可能被多个tell指到——同一个方向提示可能被不同的识别结果触发

"同构之桥tell"和"同构之桥hint"两者都有意义：
- "同构之桥tell" = 识别到"AI没做跨域翻译"这个trace，匹配到"同构之桥"这个tell
- "同构之桥hint" = "考虑把问题翻译到另一个领域"这个方向提示

一个"同构之桥tell"可以对应多个"同构之桥hint"——因为跨域翻译有多个可能的目标领域。

## 用FCA框架理解Tell分类学

### Tell分类学在FCA语言里是什么

**帮你回忆FCA的"概念格"**（concept lattice——相当于你的看法空间，就是所有名副其实的分类排成层级）：概念格是所有形式概念（formal concept——相当于你的Level视图，就是一个"名副其实的分类"）按粗细排成的层级。

**Tell分类学在FCA语言里就是**：把所有tell当作**对象**（object——就是"被分类的东西"），把分类维度当作**属性**（attribute——就是"用来分类的标签"），构成一个**形式背景**（formal context——就是"谁有什么特点的表"），然后从这个形式背景算出**概念格**（concept lattice——就是所有tell的名副其实的分类排成层级）。

用日常例子讲：把所有tell排成一张表——行是tell，列是分类维度（domain/trace类型/段结构模式/具体概念），打✓表示"这个tell属于这个分类"。从这张表算出所有名副其实的分类——这就是Tell分类学。

### 修正后的结构——三层属性维度 + 一个观察Level参数

**帮你回忆313号的初始构想**（四层结构）：

```
第一层：domain（数论/代数/组合/几何/跨域）
  第二层：trace类型（局部trace / 非局部trace）
    第三层：段结构模式（追逐 / 桥接 / 构造-分析-排除 / ...）
      第四层：具体概念（大概念→小概念）
```

**这个初始构想有一个错误——"局部/非局部/全局"不应该是tell的属性维度。** 下面用FLT例子说清楚为什么，然后给出修正后的结构。

#### 关键论证：FLT例子——"局部/非局部/全局"不是tell的固有属性

考虑两种情况：
- **Case A**：一道题目本身就是"证明费马大定理"——FLT是整体目标
- **Case B**：一道题目是别的什么，中间某一步需要证明FLT——FLT是中间步骤

**对于tell本身——没有区别。** 两种情况下tell都是"AI不会证明FLT"或更精确地"AI没有跨域桥接意识（数论→椭圆曲线→模形式）"。tell的数学内容完全一样。

**有区别的不是tell，而是trace和观察方式。** Case A中AI从一开始就在FLT的证明空间里打转；Case B中AI做到某一步才撞上需要FLT。trace不同，但tell（AI缺什么）相同。

**结论**：如果"局部/非局部/全局"是tell的固有属性，它不应该随题目位置变化——但它变了（同一个FLT tell在Case A中表现为全局，在Case B中表现为局部）。所以它不是tell的固有属性，而是**你选择从哪个Level看trace**。

- 从局部Level看trace → 你看到"AI在第47步没想到FLT" → 局部视角的tell显现
- 从非局部Level看trace → 你看到"AI在第40-50步没有跨域到椭圆曲线" → 非局部视角的tell显现
- 从全局Level看trace → 你看到"AI整体没有走数论→椭圆曲线→模形式的路线" → 全局视角的tell显现

**这三个不是三个不同的tell——是同一个tell（FLT的跨域桥接）在三个Level视图下的三种显现。**

#### 修正后的结构

```
tell的固有属性（形式背景的属性维度——tell本身的特点，不随题目位置变化）：
  第一层：domain（数论/代数/组合/几何/分析/跨域）
  第二层：段结构模式（构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛）
  第三层：具体概念（domain×段结构模式的交叉，大概念→小概念；子模式在此层体现，如"无尽追逐"是"探索-诊断-修复"的子模式）

观察trace的Level选择（不是tell的属性，是检索时的参数——取决于trace结构，不取决于tell本身）：
  局部Level / 非局部Level / 全局Level
```

**用FCA语言讲**：tell的固有属性是形式背景的**属性维度**（attribute dimensions——"用来分类tell的标签"），每个tell在这些维度上有固有取值。而"局部/非局部/全局"是你在概念格的**哪一层做检索**——它是观察Level，不是属性维度。同一个tell在概念格中只有一个位置（由它的固有属性决定），但你可以从不同Level的视图去观察它和trace的匹配关系。

## 第一层：domain——数学领域分类

**这一层是Telling AI分区的依据**（311号——每个Telling AI负责一个domain区的tell）。

### 先验的domain分类

| domain | 包含什么 | 常见方法 | 常见trace |
|---|---|---|---|
| **数论** (number_theory) | 整除性、素数、同余、模运算、p-adic赋值、二次剩余、Dirichlet定理 | 模分析、p-adic分析、筛法、二次剩余理论 | "模分析无尽追逐""素数性判定方向未尝试""p-adic赋值未尝试" |
| **代数** (algebra) | 群/环/域、多项式、线性代数、矩阵、特征值、Galois理论 | 代数构造、不变量分析、对称性利用 | "代数构造未尝试""不变量分析方向""对称性未利用" |
| **组合** (combinatorics) | 计数、鸽巢、图论、组合设计、Ramsey理论、概率方法 | 鸽巢论证、双计数、概率方法、构造性组合 | "鸽巢论证未尝试""概率方法未尝试""双计数方向" |
| **几何** (geometry) | 欧氏几何、解析几何、拓扑、微分几何、代数几何 | 几何构造、坐标化、不变量、几何变换 | "几何构造未尝试""坐标化方向""几何变换未利用" |
| **分析** (analysis) | 微积分、不等式、极限、连续、函数空间、复分析 | 估计、放缩、凸性、积分变换、复分析 | "放缩方向""凸性利用""积分变换未尝试" |
| **跨域** (cross_domain) | 跨领域构造、同构之桥、归约、表示转换 | 跨域翻译、对偶转换、归约 | "同构之桥未尝试""跨域翻译方向""归约到更小问题" |

**为什么是这6个domain**：因为这6个领域覆盖了数学竞赛和数学研究的主要领域。前5个是传统数学分支，第6个"跨域"是特殊的——它处理的是"把问题从一个领域翻译到另一个领域"的tell，这种tell不属于任何单一领域。

**用FCA语言讲**：domain是形式背景的第一个属性维度——每个tell在这个维度上有一个取值（属于哪个domain）。这个维度对应概念格的**最顶层划分**（top-level partition——就是概念格里最粗的分类，把所有tell分成6大类）。

**和Telling AI分区的关系**：Pipe 1（选择Telling AI实例——你在311号定义的Pipe 1新角色）用domain分类结果确定启动哪些区的Telling AI。如果thinking被判断为"数论+代数"，就启动数论区和代数区的Telling AI。

## 观察Level参数——局部/非局部/全局（不是tell的属性，是检索参数）

> **重要修正**：这一节原来被当作"第二层属性维度"——这是错的。FLT例子已经说明"局部/非局部/全局"不是tell的固有属性，而是观察trace的Level选择。它不进入形式背景的属性维度，而是作为检索时的参数。

**帮你回忆你的"局部trace/非局部trace/全局trace"**（你在303/305/322号定义的）：
- 局部trace：单段/单操作的特征——"AI在这一步做了什么操作"
- 非局部trace：跨多段的模式——"AI在这几步构成了什么模式"
- 全局trace：整体策略——"AI在整个证明中用了什么策略"

### 这三个Level是什么

它们不是tell的分类标签，而是**你选择从哪个粒度观察trace**：

| 观察Level | 什么意思 | 例子 | 对应什么Level视图 |
|---|---|---|---|
| **局部** (local) | 单步骤的特征 | "这一步在做排序""这一步在定义变量""这一步需要鸽巢论证但不知道" | 最细Level视图（每个段独立） |
| **非局部** (non_local) | 跨多段的模式 | "模分析无尽追逐""构造-分析-排除""探索-诊断-修复循环" | 中间Level视图（几个段合并） |
| **全局** (global) | 整体策略 | "强归纳+情况分析+鸽巢计数的组合策略""反证法+归约" | 最粗Level视图（所有段合并） |

### 为什么它是检索参数而不是属性维度

**用FLT例子的结论**：同一个tell（FLT的跨域桥接）在Case A（题目就是证明FLT）中表现为全局，在Case B（中间需要FLT）中表现为局部。如果"局部/非局部/全局"是tell的固有属性，它不应该随题目位置变化——但它变了。所以它是**观察方式**，不是**tell的特点**。

**用FCA语言讲**：tell在形式背景中由它的固有属性（domain+段结构模式+具体概念）决定其位置。"局部/非局部/全局"不进入形式背景——它是你在概念格的哪一层做检索的选择。这个选择取决于trace的结构（trace有多长、有没有跨步骤模式），不取决于tell本身。

### 这个修正对系统设计的影响

**对Telling AI分区**：分区按tell的固有属性（domain）分，不按观察Level分。同一个Telling AI可以从多个Level观察trace——它加载的tell决定了它关注什么domain和什么段结构模式，但观察Level是它分析trace时灵活选择的。

**对tell库建设**：314号问题1说"现有4164个tell全是局部tell没有非局部tell"——修正后的理解是：现有tell库的tell在固有属性上可能覆盖了非局部模式（跨域桥接、累积-收敛等），但**分析时只从局部Level观察了trace**，没有从非局部/全局Level观察。问题不是"缺非局部tell"，而是"缺非局部观察"。当然，如果tell的段结构模式属性本身是空的（现有tell没有标注段结构模式），那确实需要补充——这是固有属性层面的补充。

**对trace识别**：Telling AI在识别trace时，应该从多个Level观察——先从局部Level看每一步，再从非局部Level看跨步骤模式，再从全局Level看整体策略。同一个tell在这三个Level下有三种显现，Telling AI应该都能识别。

## 第二层（属性维度）：段结构模式——跨步骤模式的分类

**这一层是先验Tell分类学的核心——用内在数学知识推断"数学解题中有哪些跨步骤的模式"。**

> **v3修正**：原v2有6大类段结构模式，v3将"无尽追逐"降级为"探索-诊断-修复"的子模式（在第三层具体概念中体现），第二层改为5大类。理由见版本历史v3记录。

**帮你回忆304号§8.15的三个例子**：
- 欧拉证明素数无穷：构造N=p1...pn+1的目的是"必然逃逸"——构造必然逃逸的数
- 柯西-施瓦茨不等式：构造f(t)=Σ(aᵢt+bᵢ)²的目的是"用非负性约束"——辅助函数+非负性约束
- 鸽巢整除：奇偶分解的目的是"建立映射"——为鸽巢准备映射

**帮你回忆305号的例子**：
- n⁴+4^n素数题：a5到a11连续做模分析——"模分析无尽追逐"

**帮你回忆308号的真实thinking**：
- AIME 2024 P12：连续做PSLQ尝试——"PSLQ闭式追逐"

### 先验的段结构模式分类

我从内在数学知识中推断出**5大类段结构模式**（v3修正后，原"无尽追逐"降级为"探索-诊断-修复"的子模式），每类有若干子模式：

---

### 模式1：构造-分析-排除 (construct-analyze-exclude) ——"构造对象→分析性质→排除不可能"

**什么意思**：AI构造一个对象（辅助函数/反例/特殊值），分析它的性质，用性质排除不可能的情况。

**为什么是tell**：因为"构造的目的"只在段层面才显现——单看"构造了一个函数"看不到"为什么要构造"（构造的目的是"用非负性约束"），只有把构造+后续步骤合起来看才能看到目的。（你在304号§8.15.4说的"构造步骤的目的不是构造步骤的局部特征，是段的结构特征"）这个tell的段结构模式属性是"构造-分析-排除"——从哪个Level观察它是参数，不是属性。

**子模式**：

| 子模式 | 什么意思 | 例子 | 对应的hint |
|---|---|---|---|
| 辅助函数+非负性约束 | 构造辅助函数→用非负性（平方≥0/模≥0）约束 | 柯西-施瓦茨：构造f(t)=Σ(aᵢt+bᵢ)²≥0→判别式≤0 | "构造非负辅助函数用其非负性约束" |
| 必然逃逸构造 | 构造一个必然"逃逸"现有分类的对象 | 欧拉素数无穷：N=p1...pn+1必然不被任何已知素数整除 | "构造必然逃逸的对象" |
| 反例构造+分析 | 构造反例→分析为什么是反例 | "构造一个反例→分析它的性质→推出矛盾" | "构造反例证明不可能" |
| 特殊值+排除 | 代入特殊值→排除不可能的情况 | "代x=0→排除A，代x=1→排除B，代x=∞→排除C" | "用特殊值排除不可能情况" |

---

### 模式2：探索-诊断-修复 (explore-diagnose-repair) ——"探索方向→发现gap→诊断→修复"

**什么意思**：AI探索一个方向，发现走不通或发现有gap，诊断为什么走不通，修复方向继续。

**为什么是tell**：因为"完整的探索-诊断-修复循环"只在跨多段时才出现——单看任何一步只是"做了一个操作"，看不到"探索→发现gap→诊断→修复"的循环。（304号§8.11费马大定理例子中的"探索-诊断-修复循环"）这个tell的段结构模式属性是"探索-诊断-修复"。

**子模式**：

| 子模式 | 什么意思 | 例子 | 对应的hint |
|---|---|---|---|
| gap发现+修补 | 探索→发现证明有gap→诊断gap→修补 | Wiles证明FLT：3/5可表性→发现gap→Taylor-Wiles方法修补 | "识别证明的gap并用变形理论修补" |
| 方向折返+重新选择 | 走了一条路→走不通→折返→换方向 | "试贪心→失败→折返→试归纳" | "从失败中学习需要换策略" |
| 假设修正 | 做了假设→发现假设太强→修正假设→继续 | "假设所有元素都有性质P→发现只需要部分元素有P→修正" | "减弱假设使证明成立" |
| **无尽追逐**（v3降级至此） | 反复试同一类方法，每次失败换参数再来——探索-诊断-修复循环在"诊断"环节断裂（AI探索了但没有诊断"追逐无效"） | 305号：试模3→模5→模7→模11→模13；308号：PSLQ with不同常数集 | "识别追逐无效并转换方向" |

**无尽追逐的详细子模式**（v3从第二层降级至此，作为探索-诊断-修复的具体化）：

| 无尽追逐子模式 | 什么意思 | 例子 | 对应的hint |
|---|---|---|---|
| 模分析追逐 | 反复试不同的模p | 305号：试模3→模5→模7→模11→模13 | "转向代数因式分解" |
| 闭式猜测追逐 | 反复试不同的常数组合猜闭式 | 308号：PSLQ with不同常数集→连分数→近似式 | "停止猜闭式，考虑数值答案或分单元计算" |
| 枚举追逐 | 反复试不同的参数值枚举 | "试a=1→a=2→a=3→...都失败" | "停止枚举，尝试构造性方法或存在性论证" |
| 近似追逐 | 反复试更精确的近似 | "提高精度→换方法→再提高精度→..." | "停止追求精度，尝试解析方法" |
| 放缩追逐 | 反复试不同的放缩方向 | "试Cauchy放缩→试AM-GM放缩→试Jensen放缩→..." | "停止试放缩，尝试精确计算或构造" |

**v3降级说明**：在v2中"无尽追逐"是独立的第二层段结构模式。v3用FCA理论审查发现它不是独立的——它是"探索-诊断-修复"循环在"诊断"环节断裂的trace表现。tell的内容是"缺乏诊断追逐无效并修复（转换方向）的能力"，这是"探索-诊断-修复"的具体化，不是独立的段结构模式。详见版本历史v3记录。

---

### 模式3：跨域桥接 (cross-domain bridge) ——"把问题从一个领域翻译到另一个领域"

**什么意思**：AI在一个领域内打转，没有跨到另一个领域。跨域桥接的tell识别的是"没有做跨域翻译"。

**为什么是tell**：因为跨域构造是最有价值的段结构模式之一——它不在任何单步中可见，只有跨多步才能看到。（304号§8.15.2费马大定理的"同构之桥"——数论→椭圆曲线→模形式）这个tell的段结构模式属性是"跨域桥接"。FLT例子已经说明：同一个FLT跨域桥接tell在"题目就是证明FLT"中从全局Level观察，在"中间需要FLT"中从局部Level观察——tell的属性不变，变的只是观察Level。

**子模式**：

| 子模式 | 什么意思 | 例子 | 对应的hint |
|---|---|---|---|
| 同构之桥 | 把问题从一个领域翻译到另一个领域通过同构 | FLT：数论→椭圆曲线→模形式 | "把数论问题翻译到椭圆曲线/模形式" |
| 表示转换 | 从一种表示切换到另一种表示 | "代数表示→几何表示""连续→离散""组合→代数" | "换一种表示看问题" |
| 对偶转换 | 把问题翻译到它的对偶问题 | "把存在性问题翻译到构造性问题""把证明翻译到反证" | "考虑对偶问题" |

---

### 模式4：归约策略 (reduction) ——"把大问题归约到小问题"

**什么意思**：AI没有把大问题归约到更小更容易的问题。

**为什么是tell**：因为归约策略是整体策略层面的——通常从全局Level观察才能看到"这个问题可以归约到那个更小的问题"。但归约策略本身是tell的段结构模式属性（固有属性），"从全局Level观察"是观察Level参数——两者不要混淆。

**子模式**：

| 子模式 | 什么意思 | 例子 | 对应的hint |
|---|---|---|---|
| 归纳归约 | 用归纳法把n的问题归约到n-1 | IMO 2009 P6蚱蜢题：对n做强归纳 | "识别归纳结构，去掉最大元素后定义关键变量x" |
| 反证归约 | 假设结论不成立→推出矛盾 | "假设不存在→构造反例→矛盾" | "用反证法假设结论不成立" |
| 分解归约 | 把问题分解为独立的子问题 | "把大问题分解为Case 1/Case 2/Case 3" | "按关键变量分类讨论" |
| 递降归约 | 找到递降量→无限递降不可能→结论 | "找到正整数递降序列→不可能→结论" | "用无限递降法" |

---

### 模式5：累积-收敛 (accumulate-converge) ——"逐步累积信息→最终收敛到结论"

**什么意思**：AI没有逐步累积信息最终收敛——而是试图一步到位。

**为什么是tell**：因为"累积→收敛"是跨多步的策略——每一步看起来只是"得到了一个中间结果"，但多步合起来才看到"信息在累积，最终会收敛"。这个tell的段结构模式属性是"累积-收敛"。

**子模式**：

| 子模式 | 什么意思 | 例子 | 对应的hint |
|---|---|---|---|
| 信息累积 | 逐步收集条件→最终推出结论 | "从条件1推出A，从条件2推出B，A+B推出C，C推出结论" | "逐步从条件提取信息" |
| 不等式链 | 逐步加强不等式→最终达到目标 | "Cauchy→加强→AM-GM→加强→目标" | "逐步加强不等式" |
| 自由度消去 | 逐步消去自由度→最终唯一确定 | "消去第一个自由度→消去第二个→...→唯一确定" | "逐步消去自由度" |

**第二层分化**（按段结构模式分——这是属性维度的第二层，不是观察Level）：
- 数论+探索-诊断-修复tell——共同特点={数论,探索-诊断-修复}——"模分析追逐""素数性判定追逐"属于这个分类（v3修正：原"无尽追逐"降级为"探索-诊断-修复"的子模式）
- 数论+构造-分析-排除tell——共同特点={数论,构造-分析-排除}——"p-adic赋值分析"属于这个分类
- 跨域+跨域桥接tell——共同特点={跨域,跨域桥接}——"同构之桥""FLT跨域桥接"属于这个分类
- ...

**底层概念**（最细的分类）：
- 每个具体的tell自己一类

**这就是Tell分类学的概念格——所有tell的名副其实的分类从粗到细排成层级。用你的话说，这就是你的"看法空间"——所有tell的分类从最粗（所有tell一类）到最细（每个tell一类）排成层级。**

## 先验Tell分类学的用途

### 1. Telling AI分区的初始框架

**帮你回忆你的"Telling AI分区"**（311号）：每个Telling AI负责一个区的tell。

**先验分类学提供初始分区方案**：按第一层domain分6个区——数论区/代数区/组合区/几何区/分析区/跨域区。每个区的Telling AI加载自己区的tell。

**用FCA语言讲**：按domain分区就是取**子背景**（subcontext——就是"只看表格的一部分"，文件06讲过的）——数论区Telling AI只看"数论"列打✓的那些tell。

### 2. tell库建设的方向

**帮你回忆314号问题1**：现有4164个tell全是局部tell没有非局部tell。

**修正后的理解**：这个问题需要分两层看——
1. **固有属性层**：现有tell库的tell有没有标注段结构模式（跨域桥接、累积-收敛等）？如果没有标注，那确实需要补充——这是固有属性层面的补充。先验分类学的第二层（段结构模式）列出了"应该有哪些段结构模式tell"——6大类模式×每类若干子模式=约20-30个先验模式tell。
2. **观察Level层**：现有tell库的tell可能覆盖了非局部模式，但**分析时只从局部Level观察了trace**，没有从非局部/全局Level观察。问题不是"缺非局部tell"，而是"缺非局部观察"——Telling AI应该从多个Level观察trace，识别同一个tell在不同Level下的显现。

**先验分类学指出建设方向**：先补充固有属性（给现有tell标注段结构模式），再补充缺失的模式（6大类约20-30个先验模式tell），最后在trace识别时用多Level观察。

### 3. trace识别的"应该找什么"清单

**先验分类学给Telling AI的提示词提供"应该找什么"的清单**：Telling AI在识别trace时，应该从多个Level观察——
- 从局部Level看每一步——"这一步在做什么操作？有没有局部tell匹配？"
- 从非局部Level看跨步骤模式——"这几步构成了什么模式？有没有追逐？有没有构造-分析-排除？有没有跨域桥接？..."
- 从全局Level看整体策略——"AI整体走了什么路线？有没有累积-收敛？有没有归约？..."

**用你在322号V2提示词第三部分的说法**：先验分类学的段结构模式就是"可能遇到的复杂情况"——Telling AI应该逐一检查这些模式有没有出现。同时，同一个tell在三个Level下有三种显现，Telling AI应该都能识别（FLT例子：从局部看是"第47步没想到FLT"，从非局部看是"第40-50步没有跨域到椭圆曲线"，从全局看是"整体没有走数论→椭圆曲线→模形式路线"——三个显现都是同一个tell）。

### 4. 程序验证完全格的初始形式上下文

**帮你回忆你的"程序验证完全格"**（332号VMS-28c）：AI输出结构化JSON（包含形式上下文和闭元素清单），程序运行Next Closure算法验证完备性。

**先验分类学提供初始形式上下文**：上面的"Tell分类学的形式背景"表格就是初始形式上下文——程序可以用它来验证AI的tell分类是否完备。

## 先验Tell分类学的局限性

### 1. 可能遗漏真实存在的段结构模式

先验分类学是基于内在数学知识推断的——可能遗漏真实数学解题中存在但我没想到的模式。**后续需要从真实数据（455个profile的thinking）中提取段结构模式，补充到分类学中。**

### 2. domain分类可能不够细

6个domain可能太粗——比如"代数"可以细分为"线性代数""抽象代数""多项式代数"。**后续需要从真实数据中验证domain分类的粒度是否合适。**

### 3. 三层属性维度可能是层次关系也可能是正交关系

313号§4.1提出的问题：属性维度之间是严格的层次关系（第一层包含第二层包含第三层），还是正交维度（独立的标签）？**先验分类学假设是层次关系，但真实数据可能显示某些tell同时属于多个domain或多个段结构模式——这时正交维度更合适。**

### 4. "局部/非局部/全局"作为观察Level参数的验证

FLT例子从逻辑上论证了"局部/非局部/全局"不是tell的固有属性而是观察Level参数。但这个论证需要用真实数据验证——是否存在同一个tell在不同题目中确实表现为不同Level的显现？如果真实数据不支持，可能需要重新考虑这个维度是属性还是参数。

### 4. 具体概念层（属性维度第三层）需要真实数据补充

先验列举的具体概念只是部分——完整版需要从真实数据中提取。**先验列举的价值在于给出了方向，不是完整清单。**

## 一句话总结

**先验Tell分类学用FCA框架（形式背景→形式概念→概念格）+内在数学知识，预先建立了Tell的分类体系。分类体系由两部分组成：（1）tell的固有属性——三层属性维度：第一层domain（数论/代数/组合/几何/分析/跨域）→第二层段结构模式（构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛——v3修正后5大类，原"无尽追逐"降级为"探索-诊断-修复"的子模式）→第三层具体概念（domain×段结构模式的交叉，子模式在此层体现）；（2）观察Level参数——局部/非局部/全局，这不是tell的属性而是检索时选择从哪个粒度观察trace的参数（FLT例子说明：同一个tell在"题目就是证明FLT"中表现为全局，在"中间需要FLT"中表现为局部——所以"局部/非局部/全局"不是tell的固有属性）。这个分类学是先验的——基于推断而非观察，后续需要用真实数据验证和补充。版本历史在文件顶部明面记录，每次修正做覆盖性检查。它的价值在于给Telling AI分区提供初始框架、给tell库建设提供方向（补充段结构模式属性+多Level观察）、给trace识别提供"应该找什么"的清单、给程序验证完全格提供初始形式上下文。**
