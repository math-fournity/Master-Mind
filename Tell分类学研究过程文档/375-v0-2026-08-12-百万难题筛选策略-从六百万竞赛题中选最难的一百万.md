## 1. 背景与目标

### 1.1 为什么需要100万题

项目已有67838道题录入DB（problem_extraction_progress表），但只跑了789道。要系统性地评测AI数学能力分布、积累思维路径数据基座，现有题量不够。

212号文档调研了全球可下载的数学题库，发现电子化竞赛级题目约600万道。用户要求：**从中筛选最难的100万道，作为项目的核心题库**。

### 1.2 "最难"的定义

不是找千禧年难题（人类也没做出来），不是找K12基础题。是找**竞赛级及以上**的题——AI有知识储备但需要推理能力才能做的题：

| 层次 | 定义 | 典型来源 |
|---|---|---|
| **极难** | IMO/研究级，最强AI也大概率做不出来 | compfiles, FATE, miniF2F |
| **奥赛** | 国家级奥赛/IMO Shortlist级 | NuminaMath olympiad子集, olympiadbench |
| **竞赛** | AMC/AIME/Putnam级 | MathNet, Hendrycks L4-5, AoPS |
| **大量竞赛** | 竞赛题但难度分布广 | NuminaMath完整版, ODA-Math, OpenMathReasoning |

### 1.3 排除范围

- **纸质/PDF来源不取**——电子化文本来源已经足够多，不需要OCR
- **K12基础题不取**——GSM8K、Math23K、Orca-Math等，不是"最难"
- **合成题不取**——MetaMathQA、MathScale-QA等合成数据，不是真实竞赛题
- **预训练语料不取**——OpenWebMath、Proof-Pile等是训练用，不是测试题

## 3. 筛选策略——四层漏斗

### 3.1 总体架构

```
L1 极难（全取）:           ~1,800题    ← 已有
L2 奥赛（全取）:           ~40,000题   ← 已有 + 补充
L3 竞赛（全取）:           ~100,000题  ← 已有 + 补充
L4 大量竞赛（筛选最难的）:  ~860,000题  ← 下载+筛选
────────────────────────────────────
合计:                     ~1,000,000题
```

### 3.2 L1 极难（全取，~1,800题）

**定义**：IMO级、研究级形式化证明题。最强AI也大概率做不出来。

| miniF2F | 488 | ✅ 已录入 |

| amc | 40 | ✅ 已录入 |

## 7. 与自动化运营系统的衔接

本文档的筛选策略产出题目录入`problem_extraction_progress`表后，用`enqueue_problem.py`送入`problem_queue`表，`auto_runner.py`自动取题做题。

**工作流**：
```
Phase 1-5筛选 → problem_extraction_progress表
                    ↓
enqueue_problem.py --from-progress --tier <n>
                    ↓
problem_queue表 → auto_runner.py → devin cli → 判定落盘
```

**送题策略**：
- 先送L1（极难）——量小但价值最高
- 再送L2（奥赛）——AI能力的核心测试区
- 最后送L3+L4——大规模数据积累
