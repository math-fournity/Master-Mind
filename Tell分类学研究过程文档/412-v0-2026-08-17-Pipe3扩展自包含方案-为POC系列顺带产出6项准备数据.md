## §1 本工作的定位与核心问题

### 1.1 名称

**Pipe 3扩展——为POC系列顺带产出6项准备数据**

### 1.2 在执行顺序中的位置

```
[前置] Pipe 3扩展（本工作）——扩展提示词+规模化运行
  → 产出：30-50道候选题 + 6项POC准备数据
  ↓
Phase A：策略对象成形
  POC-0 CasePack冻结——用Pipe 3产出精筛→22道CasePack
  POC-0.5 变形关系声明
  POC-1 因果取商增强版
  ↓
Phase B~D：POC-2~9
```

### 1.3 核心问题

**Pipe 3扩展回答**：

> 在大规模语义选题（约1500条审计通过的结果→30-50道候选题）的同时，能否顺带为后续POC系列产出6项准备数据，使POC-0的精筛更高效？

### 1.4 为什么放在POC-0之前

POC-0的精筛需要输入——30-50道候选题从哪里来？从Pipe 3的语义选题来。Pipe 3的原始版只产出suitable/batch/d2_reclassified/selection_reason四个字段，不产出POC系列需要的假朋友候选/边界题候选/过程信号可观察性预评/泄漏风险预评/难度预估/卡点位置标注。

扩展Pipe 3的提示词，增加6个输出字段，让Pipe 3在规模化运行时顺带产出这些数据。这样POC-0精筛时可以按这些标注优先审查——Pipe 3标注为`process_signal_observability=low`或`leakage_risk=high`的题可以降低优先级。

### 1.5 为什么不能用关键词匹配替代

387号§1.3和§6.1明确说了——关键词匹配只能判断"技巧是否出现"，不能判断"技巧是否是关键转折点"。923条d2=other中含"modular"关键词，但"modular"出现不代表局部-全局切换是关键转折点。Pipe 3用devin cli的语义判断做大规模粗筛，关键词匹配替代不了。详见396号§7.4"Pipe 3在识别端中的角色"。

## §5 方法——这个工作怎么做

### 5.1 扩展提示词模板

在现有`templates/selection_agents_md.md`的输出格式中增加6个字段。以下是**扩展后的完整提示词模板**（粗体标注新增部分）：

```markdown
# Selection Task

You are a problem selection assistant for the Mid-Hint experiment.
You will decide whether a problem is suitable for the Mid-Hint experiment,
AND provide additional metadata for downstream POC experiments.

**CRITICAL CONSTRAINTS:**
- Do NOT use any tools. Do NOT write files. Do NOT execute commands.
- All information you need is in your prompt above.
- Output your selection decision directly in your response.
- End with: ### SELECTION COMPLETE

## Mid-Hint Experiment Background

The Mid-Hint experiment tests whether a non-specific hint ("switch to local
representation: Z/pZ or Q_p, find hidden algebraic structure, lift to global
conclusion"), injected mid-trajectory, can correct an AI's wrong direction.

## Selection Criteria

A problem is SUITABLE for Mid-Hint if ALL three conditions hold:
1. d1=DIRECTION_ERROR — the AI went in a wrong direction
2. The standard solution uses local-global representation switching
   (mod p / p-adic / QR+Euler / LTE / CRT / finite field structure)
3. The AI did NOT attempt this local-global switching direction

A problem is NOT SUITABLE if:
- d1=TOKEN_LIMIT (AI was on the right track, hint has no value)
- d1=CONNECTION_ERROR (technical failure)
- d1=PARTIAL_PROGRESS — NOT suitable
- The standard solution does NOT use local-global switching

## d2=other Handling

If d2=other, read d2_exp and standard_solution_key_technique CAREFULLY
(semantic understanding, not keyword matching). Determine:
- Does the standard solution use local-global representation switching?
- If yes, which subtype (mod_p_grouping / mod_p_non_obvious / ... / lte_lemma)?
- If no, the problem is NOT suitable for Mid-Hint

## Batch Assignment

If suitable, assign to a batch:
- Batch 1 (low difficulty): mod_p_grouping
- Batch 2 (medium): mod_p_non_obvious, p_adic_valuation, multi_step_mod_p
- Batch 3 (high): quadratic_residue_euler, crt, lte_lemma
- Extended: finite_field_structure, permutation_polynomial

**## POC Preparation Metadata**

**In addition to the selection decision, provide the following metadata
for downstream POC experiments. These are SECONDARY tasks — your primary
task is still the selection decision. Provide your best judgment based on
the analysis result text (d1_exp, d2_exp, etc.) — you do NOT need to read
the original problem or thinking.**

**1. false_friend_candidate (yes/no/unclear):**
   For suitable=NO problems: Could this problem be a "false friend" —
   i.e., it LOOKS like it needs local-global switching (surface features
   similar) but the key structure is MISSING (mechanism different)?
   Answer "yes" if d1_exp suggests the AI tried something that resembles
   local-global switching but the problem's core is actually different.

**2. boundary_case_candidate (yes/no/unclear):**
   Is this problem a "boundary case" — i.e., it is CLOSE to the trigger
   boundary of local-global switching, where only one key condition is
   different from a clear positive or clear negative?
   Answer "yes" if the problem partially matches the trigger but has
   a complicating factor that makes it uncertain.

**3. process_signal_observability (high/medium/low/unclear):**
   Based on d2_exp and standard_solution_key_technique: If the AI were
   to use local-global switching on this problem, would the process
   signals (introducing new representation, finding hidden structure,
   lifting back to global) be OBSERVABLE in thinking?
   - "high" if d2_exp describes a clear, distinct technique (e.g., "mod 4 grouping")
   - "medium" if d2_exp describes a technique that might blend with other steps
   - "low" if d2_exp is vague or the technique is hard to distinguish
   - "unclear" if insufficient information

**4. leakage_risk (low/medium/high):**
   If we give a hint about local-global switching for this problem,
   how likely is it that the hint would LEAK the answer?
   - "low" if the hint can only give strategy ("switch to local representation")
     without revealing the specific technique or answer
   - "medium" if the hint might partially reveal the technique
     (e.g., "use mod p" when p is obvious from the problem)
   - "high" if the hint would almost give away the key step
     (e.g., "use mod 4 grouping" when mod 4 grouping IS the answer)

**5. difficulty_estimate (easy/medium/hard):**
   Based on d2 subtype and d1_exp: How difficult is this problem for
   GLM-5.2 High?
   - "easy" if d2 is mod_p_grouping (Batch 1) and d1_exp suggests
     a straightforward wrong direction
   - "medium" if d2 is multi_step_mod_p or mod_p_non_obvious (Batch 2)
   - "hard" if d2 is quadratic_residue_euler or crt (Batch 3)
   - Use d1_exp to adjust: if AI's wrong direction was very naive,
     the problem might be easier than its batch suggests

**6. branch_position_hint (root/line/unclear):**
   Based on d1_exp: Did the AI go wrong from the ROOT (first step)
   or from a POINT ALONG THE LINE (mid-reasoning)?
   - "root" if d1_exp suggests AI chose a wrong approach from the start
     (e.g., "AI tried polynomial analysis" when mod p was needed)
   - "line" if d1_exp suggests AI's initial direction was reasonable
     but went wrong mid-way (e.g., "AI used p-adic but expansion was wrong")
   - "unclear" if d1_exp doesn't clearly indicate the position

## Output Format

<selection>
  <problem_id>{pid}</problem_id>
  <suitable>YES/NO</suitable>
  <batch>ONE_OF: 批次1, 批次2, 批次3, 可扩展, N/A</batch>
  <d2_reclassified>original_d2 → new_d2 (or "unchanged")</d2_reclassified>
  <selection_reason>1-3 sentence explanation</selection_reason>
  **<false_friend_candidate>yes/no/unclear</false_friend_candidate>
  <boundary_case_candidate>yes/no/unclear</boundary_case_candidate>
  <process_signal_observability>high/medium/low/unclear</process_signal_observability>
  <leakage_risk>low/medium/high</leakage_risk>
  <difficulty_estimate>easy/medium/hard</difficulty_estimate>
  <branch_position_hint>root/line/unclear</branch_position_hint>**
</selection>

### SELECTION COMPLETE

## Analysis Result (from Pipe 1)
{analysis_result_text}

## Audit Status (from Pipe 2)
{audit_status}
```

POC-0使用Pipe 3的产出做精筛：
1. 从suitable=YES的30-50道候选题中，用5否决项做精筛→22道CasePack
2. 从false_friend_candidate=yes的题中选取4-6道假朋友题
3. 从boundary_case_candidate=yes的题中选取2-4道边界题
4. Pipe 3的6项预评作为5否决项审查的参考（不是替代——POC-0仍然直接看题面做一阶判断）

## §10 与后续工作的关系

### 10.1 产出如何被POC-0使用

```
Pipe 3扩展产出：
  suitable=YES的30-50道候选题 → POC-0正迁移题精筛
  false_friend_candidate=yes的题 → POC-0假朋友题选取
  boundary_case_candidate=yes的题 → POC-0边界题选取
  每道题的6项预评 → POC-0的5否决项审查参考
  ↓
POC-0 CasePack冻结（399号方案）：
  30-50道候选题 → 5否决项精筛 → 22道CasePack
  ↓
POC-1~9：使用POC-0冻结的CasePack
```

### 10.2 如果Pipe 3扩展不做的后果

如果没有Pipe 3扩展，POC-0只能退回到从错题分析系统d1=DIRECTION_ERROR题中人工筛选——1071条DIRECTION_ERROR题中人工选30-50道。这：
- 规模太大（1071条人工审查不现实）
- 没有语义判断（不知道标准解答的"关键转折点"是否用了局部-全局切换）
- 没有6项预评（POC-0的5否决项审查没有参考数据）

**所以Pipe 3扩展是POC-0的前置依赖**——不是硬依赖（POC-0可以退回人工筛选），但有了Pipe 3扩展后POC-0的质量和效率都显著提升。

### 10.3 与错题分析系统selfrun的关系

错题分析系统selfrun（AGENTS.md第792行"当前任务：错题分析系统selfrun载体接替"）正在处理1579/3180题的Pipe 1分析。Pipe 3扩展的输入是Pipe 2审计通过的结果——如果selfrun还在跑Pipe 1/2，Pipe 3扩展需要等selfrun产出了足够的Pipe 2审计通过结果后再运行。

但**Pipe 3扩展的代码和提示词模板修改可以现在做**——不需要等selfrun完成。只是规模化运行需要等Pipe 2有足够的审计通过结果。

### 10.4 与非特化研究任务线的关系

AGENTS.md第810行"当前任务：非特化研究"定义了三线并行关系：
- 任务线1：大规模解题系统运行（Pipe 0 Solver AI跑题）
- 任务线2：错题分析系统运行（Pipe 1/2/3）
- 任务线3：非特化研究（POC-0~9）

**Pipe 3扩展属于任务线2**（错题分析系统运行），但它的产出服务于任务线3（非特化研究的POC-0）。所以Pipe 3扩展是任务线2到任务线3的桥梁。
