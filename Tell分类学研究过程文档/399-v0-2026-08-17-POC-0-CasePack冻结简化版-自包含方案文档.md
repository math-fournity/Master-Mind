## §0 自包含POC方案文档的设计规范（本节是所有POC方案文档的共用规范）

### 0.1 设计目标

一份POC方案文档要让未来20万上下文的AI**只加载这份文档+它索引的少数核心文档**，就能完整了解做好这次POC所需的所有背景知识，不需要用户另外指点应该读什么。

### 0.2 文档结构（每份POC方案文档必须包含的10节）

| 节 | 内容 | 作用 |
|---|---|---|
| §0 | 自包含POC方案文档的设计规范 | 共用规范（所有POC文档相同） |
| §1 | 本POC的定位与核心问题 | 这个POC是什么、在系列中的位置、回答什么问题 |

| §5 | 方法——这个POC怎么做 | 具体实验设计/对照矩阵/操作步骤 |

### 0.3 "自包含"的含义

"自包含"不是把所有背景知识复制进文档——那样文档会膨胀到无法加载。"自包含"是指：

1. **文档本身包含这个POC执行所需的全部操作信息**——输入/方法/输出/通过标准/执行约束
2. **文档明确列出需要全文加载的背景文档清单**——每份说明加载理由（这个POC为什么需要这份文档的内容）
3. **未来AI加载这份POC方案后，按照§8清单去全文加载被索引的文档**——不需要用户另外指点

### 0.4 被索引文档的精挑细选原则

每份POC方案文档的§8清单应该精挑细选——只列这个POC真正需要的背景文档，通常3-7份。如果索引太多，未来AI加载不完。

**挑选标准**：
- **必须加载**：这个POC不加载这份文档就无法正确执行（如题包/TellCore定义/通过标准来源）
- **建议加载**：这个POC加载这份文档能更好理解为什么这么做（如理论背景/原设计文档）
- **不列**：这个POC不需要这份文档的内容（如其他POC的方案文档）

```
{编号}-v0-{日期}-POC-{POC编号}-{POC名称}-自包含方案文档.md
```

## §2 理论背景——为什么需要这个POC

### 2.1 实验诚信的基础

非特化Tell的验证有一个根本困难——Tell本质上是一套提示词，提示词可能因为信息泄漏、提示强度、挑题偏差而产生虚假成功。POC-0的冻结机制是防止这些虚假成功的第一道门：

- **防追认**——实验后不能因为某题成功就追认其为正例
- **防挑题**——不能因为结果不好临时换题
- **防证据越级**——局部组件PASS不能升级成端到端PASS

### 2.2 397号审视的简化建议

397号§2.1指出382号CaseCard约30字段对首批22道题偏重，建议简化为10核心字段。397号§2.2指出373号评分表10维度对首批小规模POC偏重，建议用5否决项替代。本文档采纳这两个建议。

## §4 输入——这个POC需要什么

### 4.1 题目来源

| 层级 | 来源 | 可用方式 |
|---|---|---|
| S级 | 历史真实bare失败，有完整thinking/trajectory/verified solution | 优先作为正迁移题或source trace题 |
| A级 | 真实奥赛母题抽出的Level 3-4机制，经换壳/核验/bare失败确认 | 正迁移题或变形题 |
| B级 | 人工构造的变形题/假朋友题/边界题，解答已核验 | 选择/边界/学习POC材料 |
| C级 | 预测bare失败但尚未测试 | 候选池，不能作为正迁移证据 |
| D级 | toy题/经典外壳强题/无解答题/泄漏风险高题 | 不进入首批POC |

**特别纳入**：错题分析系统（387号dev-docs目录）的d1=DIRECTION_ERROR题应作为source trace和正迁移题的优先来源——这些题已有bare失败记录和d1判定。

**与Pipe 3的接力关系**：错题分析系统有三层Pipe——Pipe 1（分析AI判定d1/d2）→ Pipe 2（审计AI检查质量属性）→ Pipe 3（选题AI按Mid-Hint标准做语义选题判定）。Pipe 3的价值在于**大规模粗筛中的语义判断**——从约1500条审计通过的结果中，用devin cli的语义判断（不是关键词匹配）粗筛出适合Mid-Hint的30-50道候选题。关键词匹配做不了这件事——因为"出现"≠"是关键转折点"（如923条d2=other中含"modular"关键词，但"modular"出现不代表局部-全局切换是关键转折点，可能只是辅助步骤提到了模算术）。

**Pipe 3和POC-0是接力关系，不是替代关系**：

```
Pipe 3（大规模粗筛·语义判断+POC准备数据）：约1500条审计通过的结果 → 30-50道候选题 + 6项POC准备数据
  ↓
POC-0（少量精筛·一阶判断）：30-50道候选题 → 22道CasePack
  ↓
POC-1（深度分析·提取完备性）：4道source trace题 → TellCore
```

Pipe 3用二阶判断（只读Pipe 1文本，不读原题/thinking）做大规模粗筛，POC-0用一阶判断（直接看题面和verified solution）做少量精筛。两者层次不同，不可互相替代——Pipe 3的规模（1500条）POC-0做不了，POC-0的精度（5否决项直接看题面）Pipe 3做不了。

**Pipe 3顺带产出的6项POC准备数据**（详见410号）：Pipe 3在大规模语义选题时，顺带为POC系列产出6项准备数据——d2子类型标注（已在做，零额外成本）/假朋友候选标注/边界题候选标注/过程信号可观察性预评/泄漏风险预评/难度预估。POC-0精筛时按这些标注优先审查——Pipe 3标注为`process_signal_observability=low`或`leakage_risk=high`的题可以降低优先级。但Pipe 3的预评只是粗筛参考，POC-0的5否决项审查仍然直接看题面做一阶判断。

### 4.2 题包结构

| 题目类别 | 数量 | 作用 |
|---|---|---|
| source trace题 | 3-5道 | 用于抽取TellCore，提供成功/失败分支事件 |
| 正迁移题 | 4-6道 | bare失败，目标Tell应触发并推动目标过程 |
| 结构保持变形题 | 3-5道 | 换外壳但保留核心机制，测试非特化迁移 |
| 假朋友题 | 4-6道 | 表面像但结构不成立，目标Tell应拒绝或降权 |
| 边界题 | 2-4道 | 只改一个关键条件，测试trigger边界 |
| 组合题 | 2-3道 | 需要目标Tell和另一条Tell合作（POC-5推迟后，组合题在首批可选） |

## §5 方法——这个POC怎么做

### 5.1 简化CaseCard（10核心字段）

每道题进入题包前必须建卡，但只填10个核心字段：

```yaml
CaseCard:
  case_id:                    # 唯一标识
  source:                     # 来源（historical_bare_failure/olympiad_mechanism/constructed等）
  role:                       # 角色（source_trace/positive_transfer/metamorphic/false_friend/boundary/composition）
  statement:                  # 题面
  verified_solution:          # 解答+核验状态（verified/partial/unverified）
  bare_status:                # bare失败状态+failure_mode（route_failure/proof_failure/output_failure/timeout/token_limit）
  expected_decision:          # 预期selector决策（select/reject/abstain/boundary）
  expected_progress_signal:   # 预期过程信号（引入新表示/找到不变量/产生可验证lemma等）
  leakage_risk:               # 泄漏风险（low/medium/high）
  frozen_role:                # 冻结的角色——实验后不能改
```

### 5.2 5否决项（替代10维度评分表）

每道候选题用5个否决项审查——任一不满足则不准入：

1. **bare真实失败**——有完整bare失败记录（正迁移题必须满足；source trace题可以不满足）
2. **解答可核验**——有verified solution
3. **泄漏安全**——Tell只给策略不给答案信息
4. **经典风险可控**——外壳与路线有足够新鲜度（不是训练数据中见过的经典题面）
5. **过程可观察**——thinking中能看见目标过程信号

### 5.3 冻结流程

1. 确定目标Tell家族（首批：局部-全局表示切换）
2. **从Pipe 3选题结果获取候选题**——Pipe 3从约1500条审计通过的结果中用语义判断粗筛出30-50道适合Mid-Hint的候选题（关键词匹配做不了这个粗筛——"出现"≠"是关键转折点"）。如果没有Pipe 3产出，退回到从错题分析系统d1=DIRECTION_ERROR题中人工筛选
3. 对Pipe 3产出的30-50道候选题，用5否决项做精筛（直接看题面和verified solution，一阶判断）
4. 为通过精筛的每道题写简化CaseCard（10字段）
5. 用5否决项审查，记录否决原因
6. 冻结CasePack，之后只能写入exclusion_log，不能实验后改角色

## §7 通过标准

- 每道正迁移题有bare失败或明确准入理由
- 每道假朋友题说明"为什么表面相似、为什么结构不应触发"
- 每道边界题只改变一个关键条件
- 每道题都预注册预期触发/不触发/弃权
- 写明哪些题来自历史记录，哪些是新构造
- 写明禁止在实验后移动题目类别
