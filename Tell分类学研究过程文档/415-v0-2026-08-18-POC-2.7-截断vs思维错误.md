### 0.3 "自包含"的含义

"自包含"不是把所有背景知识复制进文档——那样文档会膨胀到无法加载。"自包含"是指：

1. **文档本身包含这个POC执行所需的全部操作信息**——输入/方法/输出/通过标准/执行约束
2. **文档明确列出需要全文加载的背景文档清单**——每份说明加载理由（这个POC为什么需要这份文档的内容）
3. **未来AI加载这份POC方案后，按照§8清单去全文加载被索引的文档**——不需要用户另外指点

### 0.4 被索引文档的精挑细选原则

每份POC方案文档的§8清单应该精挑细选——只列这个POC真正需要的背景文档，通常3-7份。如果索引太多，未来AI加载不完。

### 1.3 核心问题

**在续传机制下，被Pipe 1判定为"方向错误"（DIRECTION_ERROR）的948道题，有多少是真正的思维错误，有多少只是被截断的thinking spin？**

- 如果续传后大部分成功 → 这些题是截断错误，不是思维错误 → Pipe 1的判定基础有问题 → POC-2.5需要重新选题
- 如果续传后大部分失败 → 这些题是真正的思维错误 → POC-2.5候选题基础成立
- 如果续传后部分成功部分失败 → 失败的题是真正的思维错误候选 → 进入POC-2.5b

POC-2.6验证了续传机制的技术可行性（4道bare题续传成功）。POC-2.7把续传机制应用到948道DIRECTION_ERROR题上，验证续传能否大规模解决截断问题，并区分截断错误和真正的思维错误。

### 1.5 触发洞察

用户发现：POC-2.5候选题的原始run可能全部被截断（comp=25000, msg=0, tc=0），而非真正的思维错误。Pipe 1在截断的thinking上做"方向错误"判定，判定基础本身有问题。

用户的深层洞察：**即便AI的解题思路真的错了，只要AI没有明确放弃答题，持续给它续传机会，AI可能自我纠正方向，最终也能得到正确解答。**

## §2 理论背景——为什么需要这个POC

### 2.1 completion_tokens限制与thinking spin

glm-5-2单次API调用的completion_tokens上限是25000（thinking+content+tool_calls都算在内）。竞赛数学题的thinking spin可能需要超过25000 tokens，导致AI在thinking中被截断（reasoning_content有46-73K字符，但message=0、tool_calls=0），无法进入working阶段。

### 2.2 续传机制（POC-2.6验证）

续传机制把AI之前完成的reasoning_content作为新prompt的上下文注入，让AI在新的API调用中继续思考。每轮25000 completion_tokens推进一部分，多轮累积完成。POC-2.6验证了4道bare题续传全部成功。

### 2.3 Pipe 1的判定基础问题

Pipe 1（错题分析系统）对原始做题的thinking spin进行分析，判定d1（失败类型）。ArangoDB `analysis_results`集合（2050条）的d1分布：

| d1判定 | 题数 | 说明 |
|---|---|---|
| **DIRECTION_ERROR** | **1096**（去重后**948**题） | **AI走了错误方向**——Pipe 2/3从中选题 |
| TOKEN_LIMIT | 360 | token不够——不是方向错误 |
| CONNECTION_ERROR | 360 | 连接错误——技术失败 |
| PARTIAL_PROGRESS | 167 | 部分进展——中间地带 |
| NO_VERDICT | 67 | 解析失败 |

**948道DIRECTION_ERROR题，96%的原始做题状态是failed_token_limit——thinking被截断。** Pipe 1在不完整的thinking上判定"方向错误"，但这些thinking是被截断的（AI还没来得及完成思考）。

### 2.4 不验证会留下什么gap

如果不做POC-2.7：
1. POC-2.5会在截断错误（不是思维错误）的题上测试Hint因果效应 → 实验结果无意义
2. Pipe 1的948道DIRECTION_ERROR判定会被当作可靠依据 → 后续选题建立在错误基础上
3. 6400道failed_token_limit题的续传机会被浪费 → 大量可解的题被标记为"不可解"

## §5 方法——这个POC怎么做

### 5.1 实验设计

**单条件设计**：只测bare+续传（不需要vein/hint对照——这一步是验证选题前提，不是测试因果效应）。

每道题的续传流程：
1. Round 1：复用原始export（截断的thinking spin）
2. Round 2..N：把前序轮次的reasoning_content拼接为续传prompt，启动新的devin -p
3. 每轮检测：是否被截断（comp≥24000, msg=0, tc=0）vs 是否完成（msg>0或tc>0）
4. 完成则停止，截断则继续下一轮，最多5轮

### 5.2 续传prompt构造

**v1方案（机械拼接）**：

```
{原始题目}

=== 你之前的思考过程（Round {prev_round}，被截断）===

你已经在上一轮中开始了这道题的思考，但因为输出长度限制，思考过程被截断了。
以下是你之前的完整思考过程，请仔细阅读，在此基础上**继续**思考并完成解答（不要从头开始）：

{previous_reasoning}

=== 请继续思考并完成解答 ===

你之前的思考在上方被截断了。请从截断处继续，完成这道题的解答。

要求：
1. **在之前的思考基础上继续**，不要重复已经做过的分析
2. 给出完整的解答过程
3. 最终答案用 \boxed{答案} 格式给出
4. 数学公式用LaTeX
5. 把证明写到proof.md文件中，不要在对话里输出完整证明
```

### 5.3 截断检测标准

| 指标 | 截断 | 完成 |
|---|---|---|
| reasoning_content | >1000字符 | 任意 |
| message | =0 | >0 |
| tool_calls | =0 | >0 |
| completion_tokens | ≥24000 | 任意 |

### 5.4 判定标准

每道题的最终状态：

| final_status | 含义 | 判定 |
|---|---|---|
| COMPLETED | 写出proof.md且有working产出 | 截断错误（不是思维错误） |
| TRUNCATED_AT_MAX | 5轮后仍未完成 | 可能是思维错误 |
| ERROR | 脚本异常 | 需排查 |
| NO_PROBLEM_TEXT | 无法提取题目文本 | 数据问题 |

## §7 通过标准

### 7.1 通过标准

**POC-2.7通过**：948道题中COMPLETED≥50%（即续传能解决至少一半的DIRECTION_ERROR题）。

- 如果COMPLETED≥80% → 大部分是截断错误 → POC-2.5需要重新选题，Pipe 1判定基础有严重问题
- 如果50%≤COMPLETED<80% → 部分是截断错误，部分是思维错误 → 失败的题进入POC-2.5b
- 如果COMPLETED<50% → 大部分是真正的思维错误 → POC-2.5候选题基础基本成立，但仍有部分截断错误

### 7.2 不通过的处理

如果COMPLETED<50%：
- 检查是否是续传机制本身的问题（v1方案在复杂情况下失败）
- 对失败的题尝试v2交接文档方案
- 如果v2仍然失败 → 确认是真正的思维错误

### 7.3 失败案例的处理

对TRUNCATED_AT_MAX的题：
1. 检查是否有proof.md但答案错误 → 真正的思维错误
2. 检查是否5轮全部纯thinking spin → 可能需要v2交接文档
3. 用v2交接文档重试 → 如果仍然失败 → 确认是真正的思维错误

### 7.4 通过后意味着什么

POC-2.7通过意味着：
1. 续传机制能大规模解决截断问题
2. Pipe 1的DIRECTION_ERROR判定中大部分是截断导致的误判
3. POC-2.5需要在续传后的完整数据上重新选题（POC-2.5b）
4. 续传后仍然失败的题是真正的思维错误候选
