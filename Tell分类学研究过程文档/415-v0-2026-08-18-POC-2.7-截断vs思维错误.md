# POC-2.7 · 截断 vs 思维错误——续传机制对POC-2.5候选题基础的挑战

**日期**：2026-08-18
**性质**：POC方案文档——挑战POC-2.5的选题前提
**触发洞察**：用户发现POC-2.5候选题的原始run可能全部被截断，而非真正的思维错误

---

## §1 核心发现

### 1.1 原始POC-2.5的16个run全部被截断

对POC-2.5 Round 1的16个原始run的export进行检测：

| 状态 | 数量 | 说明 |
|---|---|---|
| TRUNCATED (comp=25000, msg=0, tc=0) | 13 | 有export的run，全部在thinking spin中被截断 |
| 无export (TUI模式) | 3 | CC-103-bare, CC-104-bare, CC-105-vein（TUI模式无export，但有workdir脚本说明有多步tool calls） |
| COMPLETED | 0 | **没有任何一个run正常完成** |

**13个有export的run，100%被截断。** 每一个都是 comp=25000, msg=0, tc=0——AI在thinking中耗尽了25000 token上限，从未进入working阶段。

### 1.2 续传后bare条件全部成功

POC-2.6对bare条件启动了续传机制：

| 题目 | 原始run | bare+续传 | 续传方案 |
|---|---|---|---|
| CC-101_bare | 截断(comp=25000) | ✅ boxed{4} | v1（2轮） |
| CC-103_bare | 截断(comp=25000) | ✅ boxed{3} | v2交接文档（3轮） |
| CC-104_bare | 截断(comp=25000) | ✅ boxed{200} | v1（2轮） |

**3道bare题，续传后全部成功。** 没有一道需要Hint。

### 1.3 这意味着什么

POC-2.5的选题前提是：Pipe 2错题分析系统判定这些题为"裸模型思维错误"（DIRECTION_ERROR）——AI走了错误方向，没有使用目标TellCore机制（局部-全局切换）。

但实际上：
1. **原始run全部被截断**——AI从未完成thinking，从未输出任何working内容
2. **Pipe 2分析的是截断的thinking**——只有46-73K字符的不完整thinking，AI可能还在正确方向上探索，只是没来得及完成
3. **bare+续传全部成功**——给AI足够的thinking空间后，裸模型自己就能解出来

**结论：这些题不是"思维错误"，是"截断错误"。** Pipe 2在不完整的thinking上做"方向错误"判定，判定基础本身就有问题。

## §2 对POC-2.5的影响

### 2.1 POC-2.5的判定逻辑失效

POC-2.5的4个场景（398号§5.3）：

| 场景 | 条件 | 判定 |
|---|---|---|
| 场景1 | bare失败+vein_hint成功，但vein也成功 | vein够，Hint无因果作用 |
| 场景2 | bare失败+vein失败+vein_hint成功 | Hint有因果作用（最理想） |
| 场景3 | 全失败 | Hint无效 |
| 场景4 | bare成功 | 题目不是真正的bare失败 |

**当前数据指向场景4**：bare+续传全部成功 → 这些题不是真正的bare失败 → POC-2.5无法在这些题上测试Hint的因果作用。

### 2.2 POC-2.5的实验数据仍然有价值

虽然POC-2.5无法测试Hint的因果作用，但实验数据揭示了更重要的问题：

1. **completion_tokens限制是"裸模型失败"的主要原因**——不是思维错误，是输出超限
2. **续传机制是必要的基础设施**——没有续传，任何需要长thinking的竞赛数学题都会失败
3. **Pipe 2的选题需要在完整thinking上做**——在截断的thinking上做方向判定不可靠

---

## §3 POC-2.7方案

### 3.1 目标

回答一个关键问题：**在续传机制下，bare模型能解出多少道原始候选题？**

- 如果bare+续传解出全部 → POC-2.5候选题全部是截断错误，不是思维错误 → 需要重新选题
- 如果bare+续传解出大部分但有些仍然失败 → 失败的题是真正的思维错误 → 可以用于Hint因果实验
- 如果bare+续传解出少数 → 大部分是真正的思维错误 → POC-2.5候选题基础成立

### 3.2 实验设计

**条件**：只测bare+续传（不需要vein/hint对照——这一步是验证选题前提，不是测试因果效应）

**题目**：POC-2.5的4道候选题（CC-101, CC-103, CC-104, CC-105）的bare条件

**已有数据**：
- CC-101_bare+续传：✅ 成功
- CC-103_bare+续传：✅ 成功（v2交接文档）
- CC-104_bare+续传：✅ 成功

**需要补充的数据**：
- CC-105_bare+续传：待运行

**判定标准**：
- bare+续传写出proof.md且答案正确 → 截断错误（不是思维错误）
- bare+续传5轮后仍未完成 → 可能是思维错误（需要进一步分析）
- bare+续传写出proof.md但答案错误 → 真正的思维错误

### 3.3 执行步骤

1. 启动CC-105_bare的续传（唯一缺失的数据点）
2. 汇总4道bare题的续传结果
3. 形成结论：截断错误 vs 思维错误的比例
4. 如果全部是截断错误 → 形成POC-2.5b方案：在续传机制下重新选题（找bare+续传仍然失败的题）

### 3.4 后续POC-2.5b（如果需要）

如果POC-2.7确认POC-2.5候选题全部是截断错误，则需要POC-2.5b：

**POC-2.5b目标**：在续传机制下，找到bare模型仍然失败的题（真正的思维错误），在这些题上测试Hint的因果效应。

**POC-2.5b选题流程**：
1. 从Pipe 2的1982条分析结果中筛选候选题
2. 对每道候选题启动bare+续传
3. bare+续传仍然失败的题 → 真正的思维错误 → 进入POC-2.5b的因果实验
4. bare+续传成功的题 → 截断错误 → 排除

**POC-2.5b实验设计**：与POC-2.5相同（4条件对照），但题目是bare+续传仍然失败的题。

## §4 对Pipe 2的影响

### 4.1 Pipe 2的判定基础问题

Pipe 2在截断的thinking上做"方向错误"判定。截断的thinking只有46-73K字符（不完整），AI可能还在正确方向上探索，只是没来得及完成。在 不完整thinking上判定"方向错误"是不可靠的。

### 4.2 修复方案

**方案A：在续传后的完整thinking上重新分析**
- 对每道候选题先做bare+续传，获得完整thinking
- 在完整thinking上重新跑Pipe 2
- 如果Pipe 2仍然判定"方向错误" → 真正的思维错误
- 如果Pipe 2改判 → 原始判定是截断导致的误判

**方案B：在续传后的working产出上判定**
- 不看thinking，只看working产出（proof.md/脚本/答案）
- bare+续传写出正确proof.md → 不是思维错误
- bare+续传写出错误proof.md → 思维错误
- bare+续传5轮未完成 → 可能是思维错误

**推荐方案B**——更客观，不依赖thinking分析的准确性。
