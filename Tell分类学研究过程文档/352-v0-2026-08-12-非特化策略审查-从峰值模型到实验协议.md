# 352号 · 非特化策略审查——从峰值模型到实验协议

**日期**：2026-08-12
**触发原因**：351号委托提示词提出三个任务方向；本文件先完成任务3：审查344-347号形成的非特化策略是否有改进空间。
**前置文档**：344号（去特化=泛化=Level提升）、345号（Tell族+钟形曲线）、346号（三步法）、347号（三种提示词形态）、350号（全面验证方案）、351号（委托提示词）
**核心结论**：当前策略方向正确，但还不是完整实验协议。它已经解决了“如何从trace生成可迁移Tell”的主问题；下一步必须补上触发条件、反事实泄漏检测、提示词形态的成本控制、Tell内部结构化、以及失败归因机制，否则后续出题和验证会把“提示有效”误判为“思维力被激发”。

---

## 0. 总体判断

### 0.1 当前策略做对了什么

344-347号的核心贡献是把“去特化”从一个模糊动作变成了可讨论的认知对象：

1. **把去特化、泛化、Level提升统一起来**：避免了“普通Tell”和“高Level Tell”被误当成二元类别。
2. **提出Tell族**：承认同一trace可以产生多个不同泛化程度的Tell，系统不必押注唯一版本。
3. **提出指导力非单调**：Level太低没有迁移，Level太高不可操作，中间存在最优区间。
4. **引入三步法**：IBE找本质、结构映射保留关系、可操作性检查，三者合在一起是目前合理的去特化工作流。
5. **修正提示词形态**：认识到高Level Tell可以通过思维流程引导恢复可操作性，避免把“抽象”直接等同于“无效”。

### 0.2 最大风险

最大风险不是Tell写得不够抽象，而是**Tell在实验中承担了多个混杂功能**：

- 它可能是真正的思维力引导；
- 也可能是题目难度提示；
- 也可能是解法空间裁剪；
- 也可能是隐性方法泄漏；
- 也可能只是增加了模型重试深度和自信。

如果不把这些功能拆开验证，实验结果会很漂亮，但不可解释。

### 0.3 本文建议的总修正

把非特化策略从“三步法”扩展为：

```
trace
  → 候选Tell族生成（IBE + 结构映射 + 可操作性）
  → 触发条件定义（什么时候该用）
  → Tell内部结构化（触发/执行/退出/校验）
  → 反事实泄漏审查（答案盲审 + 方法盲审 + 题族盲审）
  → 形态成本校准（提示长度/强度/搜索空间裁剪度）
  → 实验归因矩阵（成功、失败、误触发分别归因）
  → 入库或废弃
```

三步法仍然保留，但它只是“生成Tell”的核心，不再承担全部质量控制职责。

## 1. 审查方面一：三步法是否完备

### 当前策略

346号提出三步法：

1. IBE：问“这个思维模式为什么在数学解题中有价值？”
2. 结构映射：保留因果、依赖、角色等关系结构，剥离变量、条件、对象等表面特征。
3. 可操作性检查：AI拿到Tell后是否知道具体做什么。

### 评估

三步法是合理的，但**只覆盖了Tell生成，不覆盖Tell使用**。它可以帮助从trace得到一个看似好的Tell，却不能保证：

- 这个Tell应该在什么情境触发；
- 这个Tell是否会误触发到不相关题目；
- 这个Tell是否隐含裁剪了解法空间；
- 这个Tell失败时应判定为Tell无效、题目太难，还是触发条件错误。

因此三步法不应被称为完整的非特化策略，只应称为“候选Tell生成法”。

### 具体改进建议

在三步法后新增两步：

**步骤4：触发条件显式化**

每个Tell必须同时写出：

- 正触发条件：什么thinking信号说明该Tell可能适用；
- 负触发条件：什么信号说明不该用；
- 最小证据量：需要观察到几个信号才触发；
- 误触发代价：错用这个Tell会让AI往哪里跑偏。

**步骤5：退出与校验条件**

Tell不能只告诉AI“往哪想”，还要告诉它何时停止这条尝试：

- 如果3-5步内没有产生可验证对象，回退；
- 如果转换后问题复杂度没有下降，回退；
- 如果构造对象无法产生新约束，回退；
- 如果导出的必要条件与题设无关，回退。

### 理论依据

这是把Tell从“提示词”升级为“控制策略”。认知上对应元认知监控：有效解题不只需要策略选择，还需要监控策略是否继续值得执行。工程上对应策略的precondition/postcondition设计：一个可执行规则必须有进入条件和退出条件。

## 2. 审查方面二：三种形态是否穷尽

### 当前策略

347号把Tell提示词分成三种形态：

1. 一句话指示；
2. 思维流程/步骤引导式；
3. 抽象标签。

形态3不应作为真正Tell存储，只可作为分类学刻度名。

### 评估

三种形态覆盖了“提示词表面形态”，但没有穷尽“认知功能形态”。至少还缺三类：

1. **判别式Tell**：不是让AI执行一个策略，而是让AI判断当前方法是否还值得继续。
2. **对照式Tell**：要求AI构造两个候选视角并比较，而不是直接走某一路。
3. **检查器式Tell**：不推进解题，而是检查当前解法是否违反不变量、极端例、局部条件或边界条件。

这些都不是抽象标签，也不完全是普通步骤引导。它们更像“元策略模块”。

### 具体改进建议

把三种“表面形态”保留，但新增一个正交维度：**Tell功能类型**。

建议先用五类：

| 功能类型 | 作用 | 示例 |
|---|---|---|
| 执行型 | 直接推动一条策略 | “尝试构造一个局部修复操作” |
| 判别型 | 判断当前路线是否该停 | “检查你是否只是在更换参数而没有产生新约束” |
| 对照型 | 并列比较多个框架 | “用原问题视角和反问题视角各写一个约束，看哪边更简单” |
| 检查型 | 验证候选解法的结构缺陷 | “检查你的构造是否在极端情形下仍成立” |
| 生成型 | 生成可选分支给后续筛选 | “列出三种可能的表示转换，并评估转换成本” |

于是一个Tell可标记为：

```
形态 = 思维流程引导式
功能 = 判别型 + 生成型
```

这比只说“形态2”更利于检索、触发和负对照设计。

### 理论依据

教育心理学中的脚手架提示不只有“告诉学生怎么做”，还包括监控、反思、比较和自我解释。AI提示也类似：很多高价值Tell不是提供新动作，而是改变选择动作的标准。

## 3. 审查方面三：钟形曲线模型是否准确

### 当前策略

345号提出：同一trace的Tell族按Level升高时，AI指导力呈钟形曲线。347号进一步修正：提示词形态会改变曲线，因此不是一条固定曲线，而是曲线族。

### 评估

“钟形曲线”作为直觉模型有价值，但作为实验假设太强。真实情况可能出现：

1. **多峰曲线**：同一个trace可能在具体技巧层和高Level流程层各有一个峰。
2. **平台型曲线**：多个相邻Level指导力差不多，差异小于实验噪声。
3. **阈值型曲线**：低于某抽象度完全不可迁移，高于阈值突然可迁移。
4. **任务依赖反转**：对相似题，低Level峰值最高；对远迁移题，高Level流程峰值最高。
5. **模型依赖差异**：GLM-5.2、Claude、GPT对同一Tell族的峰值可能不同。

因此“钟形曲线”更准确的表述应是：**指导力通常存在非单调性，但曲线形状需要由题族和模型共同估计**。

### 具体改进建议

将“钟形曲线”降级为“非单调峰值假设”，并在实验中记录三个指标：

| 指标 | 含义 |
|---|---|
| 近迁移成功率 | 表面不同但结构接近的题是否成功 |
| 远迁移成功率 | 结构抽象相似、表面很远的题是否成功 |
| 误触发率 | 不该用时使用该Tell导致跑偏的概率 |

峰值不要只按“成功率”定义，而应按综合效用定义：

```
综合效用 = 匹配题成功率 - 不匹配题误触发率 - 提示成本 - 泄漏风险
```

### 理论依据

这是把“指导力”从单一心理量改成可实验分解的效用函数。否则一个很强的Tell可能只是因为它裁剪了大量搜索空间，而不是因为它更好地表达了思维力。

## 4. 审查方面四：高Level概念两种类型是否完备

### 当前策略

340号和347号把高Level概念分为：

1. 可展开的：如构造-分析-排除，可以展开为具体形式列表或流程；
2. 无法指定展开方向的：如同构之桥，不能预列所有目标域，只能用流程引导。

### 评估

这两类覆盖了很多情形，但还缺两类：

1. **约束重排型**：不是展开，也不是开放探索，而是改变哪些条件先被使用、哪些条件暂存。
2. **语言创造型**：不是在已有方向中展开，而是发明一个新的中间表示或符号系统，让原问题可表达。

“框架创造”“本质重构”往往属于语言创造型。它们无法简单归入“可展开”或“无法指定展开方向”，因为它们的关键动作不是找方向，而是制造可承载方向的语言。

### 具体改进建议

把高Level概念从二分改成四类：

| 类型 | 核心动作 | 处理方式 |
|---|---|---|
| 可展开型 | 抽象模式展开为具体策略列表 | 形态1或形态2 |
| 开放寻路型 | 目标方向不可预列，需要探索 | 形态2 |
| 约束重排型 | 重新安排题设信息的使用顺序 | 判别型/对照型Tell |
| 语言创造型 | 创造新表示、新对象、新框架 | 生成型Tell + 强校验条件 |

### 理论依据

数学突破不总是“选择一个策略”，也常是“创造一个能让策略存在的表示”。如果分类学只关心策略展开，就会低估框架创造、层级抽象、本质重构这类思维力。

## 5. 审查方面五：智识诚实约束是否足够严格

### 当前策略

350号提出Tell纯洁性三重检验：

1. 去特化审查：Tell中不能含题目特定词汇；
2. 迁移性检验：同一Tell能用于至少3道不同题；
3. 盲审：不知道答案的审查者不能从Tell猜出答案。

### 评估

三重检验必要，但不充分。存在三种“通过三重检验但仍泄漏”的情况：

1. **方法类泄漏**：Tell不含题目词汇，却把方法类别裁得太窄。例如“寻找一个单调下降的整数参数”虽通用，但对某些题几乎等同于告诉它用无穷递降。
2. **题族泄漏**：Tell无法猜出单题答案，但能猜出题族的标准路线。
3. **搜索空间泄漏**：Tell没有给答案，却排除了99%的错误方向，实验上仍可能接近泄漏。

### 具体改进建议

新增三个审查：

**审查4：方法盲审**

问审查者：“只看Tell，不看题，你能否判断这题大概率属于哪种经典方法族？”如果能，记录为高泄漏风险。

**审查5：搜索空间裁剪度评估**

给每个Tell打一个粗分：

| 分数 | 含义 |
|---|---|
| 0 | 只改变元认知姿态 |
| 1 | 提示一类很宽的策略 |
| 2 | 提示一类中等宽度的方法 |
| 3 | 指向很窄的方法族 |
| 4 | 几乎等于具体解法路线 |

正式实验中优先使用0-2分Tell；3分只能用于内部探索；4分禁止。

**审查6：同题多Tell等强度对照**

不匹配Tell不能随便选，必须选“提示长度、抽象度、强度相近”的Tell。否则匹配Tell有效可能只是因为它更长、更强、更像教程。

### 理论依据

信息泄漏不只存在于词汇层，也存在于先验分布层。一个提示可以不含具体对象，却显著改变模型对解法空间的概率分布；这仍然是实验混杂变量。

## 6. 审查方面六：认知科学、教育心理学、AI研究盲区

### 当前策略

当前策略主要引用IBE、结构映射、可操作化原则，并自创Tell族、钟形曲线、三种形态、高Level两类型。

### 评估

理论基础够启动，但有四个盲区：

1. **认知负荷**：形态2可能因为太长、太多步骤，反而降低性能。
2. **元认知校准**：Tell可能让AI更自信，但不一定更正确。
3. **自我解释效应**：很多Tell有效不是因为给了策略，而是因为要求AI解释当前状态。
4. **提示依赖性**：同一思维力的不同措辞可能效果差别很大，不能把一次措辞成败等同于思维力成败。

### 具体改进建议

新增四个实验记录字段：

| 字段 | 作用 |
|---|---|
| prompt_token_count | 控制提示长度带来的认知负荷 |
| action_count_required | 记录Tell要求AI执行多少个显式动作 |
| self_explanation_required | 标记Tell是否要求AI解释自己为何卡住 |
| confidence_change | 记录AI是否只是更自信而非更正确 |

新增一个对照组：

```
结构等长空流程提示：
请先列出已尝试路线，再列出障碍，再选择一条新路线。
```

这个对照不包含特定思维力，但包含“反思+重启”的一般结构。若它也有效，则匹配Tell的增益不能完全归因于特定思维力。

### 理论依据

教育心理学中，提示效果常来自脚手架、自我解释、注意力重分配和负荷管理，而不一定来自提示内容本身。AI实验也必须把“格式效应”和“内容效应”拆开。

## 7. 审查方面七：整体哲学基础是否稳固

### 当前策略

当前策略依赖两个核心假设：

1. 思维力可以被非特化为通用Tell；
2. Tell可以激发AI的思维能力，而不是只提供信息。

### 评估

第一个假设基本成立，但应限定为：**一部分思维力可以被非特化为可迁移的控制策略**。不是所有数学思维力都能同等程度Tell化。

第二个假设可以成立，但必须可证伪。若没有严格对照，任何成功都可能被解释成“Tell提供了信息”。350号已经有bare、负对照、不匹配Tell，这是正确方向，但还需要等强度对照和反事实泄漏审查。

### 具体改进建议

把主命题改写为更可证伪的版本：

**原命题**：

> 对每种思维力，都存在非特化Tell，使bare失败题在Tell后成功。

**建议命题**：

> 对某些可程序化表达的思维力，存在非题目特化、低泄漏风险、可迁移的Tell；在控制提示长度、反思结构、强度和不匹配Tell后，它能显著提高GLM-5.2在对应题族上的成功率。

这个命题更窄，但更诚实，也更容易被实验支持或证伪。

### 理论依据

科学命题需要可失败条件。若“Tell有效”可以在任何成功后成立、任何失败后都解释为题太难或Tell没写好，那么它就不可证伪。把命题缩窄后，失败反而更有信息价值。

### 8.1 预注册新增字段

每个Tell预注册时新增：

```
Tell功能类型：执行型/判别型/对照型/检查型/生成型
触发条件：
负触发条件：
退出条件：
搜索空间裁剪度：0-4
prompt_token_count：
action_count_required：
等强度对照Tell：
方法盲审结果：
题族盲审结果：
```

### 8.2 交叉验证矩阵新增两类对照

在350号已有的“不匹配Tell×5”和“纯鼓励”外，新增：

1. **等长通用反思提示**：控制“流程结构”效应；
2. **等强度不匹配Tell**：控制“提示强度”效应。

### 8.3 单题通过条件修正

350号原条件：

- bare全部失败；
- 匹配Tell成功率 > 60%；
- 不匹配Tell成功率 < 20%；
- 纯鼓励失败。

建议改为：

- bare全部失败；
- 匹配Tell成功率 > 60%；
- 不匹配Tell成功率 < 20%；
- 纯鼓励失败；
- 等长通用反思提示成功率低于匹配Tell；
- 等强度不匹配Tell成功率低于匹配Tell；
- 匹配Tell的搜索空间裁剪度不超过2，或在报告中标记为高泄漏风险实验。

### 8.4 失败归因表

每次失败不能只记录“失败”，应归入：

| 失败类型 | 含义 |
|---|---|
| F1 Tell未触发 | AI没有按Tell思考 |
| F2 Tell触发但误用 | AI执行了Tell但方向跑偏 |
| F3 Tell正确但数学能力不足 | 路线对了但推理失败 |
| F4 Tell泄漏风险过高 | 成功不可解释为思维力 |
| F5 题目窗口不对 | bare太强或Tell后仍太难 |
| F6 评估不确定 | 证明正确性无法稳定判定 |

## 9. 对任务1和任务2的影响

### 9.1 对新思维力发现的影响

新增思维力不能只问“数学史上是否重要”，还要问：

1. 它能否表达为低泄漏Tell？
2. 它是否有可观察的触发信号？
3. 它的失败是否能被归因？
4. 它是否不同于已有思维力的功能类型，而不只是换了历史案例？

因此任务1中每个新思维力都应多加一项：

```
Tell化可行性：高/中/低
可观察触发信号：
泄漏风险：
与已有思维力的功能差异：
```

### 9.2 对竞赛级难题的影响

任务2中“只有这种思维力才能解决”应改成更可审查的说法：

> 该思维力是最自然、最低搜索成本、最稳定的成功路径；其他路径在至少3种对照尝试中失败或显著更不稳定。

## 10. 最终结论

351号要求审查非特化策略是否有改进空间。结论是：

**有改进空间，但不是推翻，而是补全。**

344-347号已经形成了一个强的Tell生成理论；它最可贵的地方是承认Level连续、指导力非单调、提示词形态影响指导力。但它还缺少实验协议层面的护栏：什么时候触发、什么时候退出、如何判断泄漏、如何控制提示强度、如何给失败归因。

下一步建议：

1. 先把350号验证方案按本文件§8修订；
2. 再做任务1的新思维力筛选，并加入“Tell化可行性”；
3. 最后做任务2的小批量试产题，不要直接冲130题。

这条顺序能最大限度减少后续的假阳性：我们不是先造题再找证据，而是先把证据标准磨锋利，再让题和Tell通过它。
