### 1.3 核心问题

**POC-3回答**：

> AI拿到HintInstance后，是否真的执行了Tell预期的认知动作？

这个问题**不只看最终证明是否成功**——要看AI的thinking中是否出现了目标认知动作的过程信号。POC-2.5验证的是"Hint有没有基础因果效应"（结果层），POC-3验证的是"Hint有没有触发预期的认知动作"（过程层）。

两者的区别：
- **POC-2.5**：bare失败 + bare+Hint成功 → Hint有基础因果效应（结果层）
- **POC-3**：目标Tell组的目标认知动作出现率 > bare和通用鼓励 → Hint触发了预期的认知动作（过程层）

一个Tell可能让AI最终做出题，但完全没有执行目标Tell的认知动作（比如AI用了另一条路线恰好做出来了）。POC-3要区分这种情况——成功不等于执行。

### 1.4 为什么POC-3在POC-3.5之后

POC-3使用的HintInstance必须是**POC-3.5确定的峰值区间的非特化程度的HintInstance**。原因：

1. POC-3.5已经验证了同一个TellCore渲染成不同非特化程度的Hint时，AI指导力是否呈钟形曲线/Pareto前沿，并确定了峰值位置
2. POC-3应该用峰值区间的HintInstance来测试"可执行性"——如果用非峰值的HintInstance（太特化或太抽象），即使AI没有执行预期认知动作，也不能说明Tell不可执行，只能说明这个非特化程度不合适
3. 所以POC-3必须在POC-3.5之后——先确定峰值，再用峰值区间的Hint测可执行性

**如果POC-3.5未完成**——POC-3不能开始（没有确定的峰值HintInstance可用）。

## §2 理论背景——为什么需要这个POC

### 2.1 396号§4.3：TellCore / HintRenderer / HintInstance三对象分离

396号§4.3（源自372号§7）建立了三对象分离：

```
TellCore     = 系统内部学到的可迁移认知技能（不变量内核 + 认知Option + 边界 + critic）
HintRenderer = 把TellCore编译成某类Solver能理解的提示的渲染器
HintInstance = TellCore针对当前题、当前脉络、当前模型、当前预算的一次实例化
```

POC-3验证的是**HintInstance这一层**——当HintRenderer把TellCore渲染成HintInstance并注入AI后，AI是否真的执行了TellCore预期的认知动作。

三对象分离的意义在于：如果AI没有执行预期认知动作，可以归因到三个不同的层：
- **HintInstance的问题**——渲染出的提示词不够清楚，AI不知道该做什么
- **HintRenderer的问题**——渲染器选错了非特化程度（POC-3.5已部分排除）
- **TellCore的问题**——TellCore本身没有定义清楚预期的认知动作（POC-1已部分排除）

POC-3通过排除法：既然POC-1已经验证了TellCore的结构、POC-3.5已经确定了峰值区间的HintInstance，那么如果AI仍然没有执行预期认知动作，问题更可能出在**HintInstance的执行性**——提示词虽然给出了，但AI没有把它绑定到题目对象上，而是简单复述或忽略。

### 2.2 396号§5：有效性 = 因果贡献证明——过程层指标

396号§5.7修正了用户框架：

> Hint有效 ≠ 解题成功。有效性是"trigger→认知动作→进展信号→成功"这条因果链出现，且在控制混杂后仍成立，且在结构保持变换下维持作用。

POC-3验证的是这条因果链的**第二环"认知动作"**——trigger（POC-2 selector验证）之后、进展信号和成功之前。

372号§16的六门审计中，"可执行"门的定义是：

> AI拿到它后知道下一步具体做什么吗？——不通过时的典型失败：Tell退化成"考虑不变量""换个角度"等口号。

POC-3就是"可执行门"的实验验证——确认Tell没有退化成口号，AI拿到HintInstance后真的执行了预期的认知动作。

### 2.3 372号§16六门审计——可执行门

372号§16的六门审计框架中，可执行门是第二门（可选择之后、可终止之前）：

| 审计门 | 核心问题 | 不通过时的典型失败 |
|---|---|---|
| 可选择 | 系统知道何时选它、为何选它、何时拒绝它吗？ | 检索命中被误当成策略选择，导致假朋友迁移 |
| **可执行** | **AI拿到它后知道下一步具体做什么吗？** | **Tell退化成"考虑不变量""换个角度"等口号** |
| 可终止 | 系统知道执行到什么状态应停止、回退或让位吗？ | AI一直围绕同一提示打转，或过早放弃有效方向 |

POC-3是可执行门的实验验证。它要区分三种情况：
1. **AI执行了预期认知动作且有进展**——可执行门通过
2. **AI执行了预期认知动作但无进展**——执行了但方向可能不对（需要POC-4可终止来处理）
3. **AI没有执行预期认知动作**——HintInstance没有让AI知道下一步做什么（可执行门不通过）

### 2.4 不验证会留下什么gap

如果跳过POC-3直接做POC-4（可终止）或POC-6（可归责）：

- **POC-4无法做**——可终止的前提是AI已经在执行Tell。如果AI根本没执行预期认知动作，"何时停止"无从谈起
- **POC-6归责不准**——可归责要看full Tell相对bare有过程层增益。如果连"过程层有没有出现预期认知动作"都没验证，归责矩阵的"过程层指标"没有基准
- **整个因果链断裂**——"trigger→认知动作→进展信号→成功"这条链中，"认知动作"这一环没有验证，后续环节的验证都建立在未经验证的基础上

## §4 输入——这个POC需要什么

### 4.1 题包

从382号CasePack v0的22道题中取：
- **正迁移题4道**——bare失败、目标Tell是低搜索成本主路、过程可观察
- **过程信号强的变形题**（如有）——保留核心结构但换外壳的题，用来测试非特化条件下的可执行性

正迁移题的标准（来自382号§1.2和373号§14.8/§14.9）：
- 真实bare失败（有完整bare失败记录）
- 目标Tell（局部-全局表示切换）是低搜索成本主路
- **过程可观察**——thinking中能看见表示切换的过程信号（POC-3尤其需要这条——373号§14.9说"POC-3可执行最需要的题：正迁移题、过程信号强的变形题；不适合的题：即使执行Tell也看不出中间动作的题"）
- 解答可核验（有verified solution）
- 泄漏安全（Tell只给策略不给答案）

### 4.2 TellCore

383号确定的TellCore v0候选C（局部-全局表示切换），7字段最小充分集：
1. invariant_claim
2. trigger_boundary
3. negative_boundary
4. parameter_slots
5. internal_policy
6. **progress_model**——本POC尤其需要这个字段，它定义了预期的中间信号（引入新表示/比较原表示与新表示/找到不变量/产生可验证lemma），是POC-3过程信号的判据来源
7. termination

### 4.3 HintInstance——POC-3.5确定的峰值区间

**本POC使用POC-3.5确定的峰值区间的HintInstance**。

POC-3.5对同一个TellCore渲染了3-5个非特化程度的HintInstance（如Hint-L1到Hint-L5），在正迁移题上测试AI指导力，确定峰值位置。POC-3用峰值区间的HintInstance作为"目标Tell"组的Hint。

例如，如果POC-3.5确定Hint-L3（中非特化程度，一句话指示形态"当问题在自然表示下陷入困境时，切换到局部表示Z/pZ"）是峰值，则POC-3的"目标Tell"组用Hint-L3。

**如果POC-3.5发现峰值是一个区间**（如L3-L4都是峰值，差异不显著），POC-3可以同时用L3和L4作为"目标Tell"组的两个变体，看哪个的可执行性更强。

### 4.4 对照组

POC-3需要以下对照组（来自373号§8.2）：

| 对照组 | 给AI什么 | 验证什么 |
|---|---|---|
| **bare** | 只有题目 | 基线——AI自然是否会执行目标认知动作 |
| **通用鼓励** | 题目+"仔细思考，换个角度试试" | 鼓励效应——通用鼓励是否能触发目标认知动作 |
| **等长空流程** | 题目+与目标Tell等长但无策略内容的空流程提示 | 提示长度/结构效应——等长空流程是否能触发目标认知动作 |
| **错配Tell** | 题目+非目标Tell的HintInstance（如"用归纳法"） | 提示强度效应——等强度的错配Tell是否能触发同一认知动作 |
| **目标Tell** | 题目+POC-3.5确定的峰值HintInstance | 目标——是否触发预期认知动作 |

此外，373号§8.2还提到把同一个TellCore渲染成若干HintInstance做梯度对比：

| HintInstance变体 | 形态 | 验证什么 |
|---|---|---|
| 低强度根提示 | 极简提示 | 最低限度能否触发 |
| line分叉提示 | 在具体分叉点给提示 | 精准位置注入 |
| method-only提示 | 只给操作步骤 | 操作步骤本身是否足够 |
| method+critic提示 | 操作步骤+评判标准 | 加critic是否增强执行性 |
| full Tell提示 | 完整TellCore渲染 | 完整认知Option的执行性 |

**注意**：这些梯度变体中，"full Tell提示"应使用POC-3.5确定的峰值区间的HintInstance。其他变体（低强度/line分叉/method-only/method+critic）是这个峰值HintInstance的组件分解，用来归因"执行性来自哪个组件"（这部分与POC-6可归责有重叠，但POC-3的角度是"是否执行"而非"增益归因"）。

## §5 方法——这个POC怎么做

### 5.1 实验设计

对4道正迁移题（+可选变形题），每道做5个对照组×（可选）5个HintInstance变体。

**核心对照矩阵**（5组对照）：

| 条件 | 给AI什么 | 预期 |
|---|---|---|
| bare | 只有题目 | 目标认知动作出现率低（AI自然不走这条路） |
| 通用鼓励 | 题目+"仔细思考，换个角度试试" | 目标认知动作出现率低（鼓励不等于策略） |
| 等长空流程 | 题目+等长无策略提示 | 目标认知动作出现率低（提示长度不等于策略） |
| 错配Tell | 题目+非目标Tell的HintInstance | 目标认知动作出现率低（错配Tell触发的是其他认知动作） |
| **目标Tell** | 题目+**POC-3.5确定的峰值HintInstance** | **目标认知动作出现率高** |

**可选梯度矩阵**（在目标Tell组内做组件分解）：

| 条件 | 给AI什么 | 预期 |
|---|---|---|
| 低强度根提示 | 极简提示 | 可能不足以触发 |
| line分叉提示 | 在具体分叉点给提示 | 精准注入可能更有效 |
| method-only | 只给操作步骤 | 操作步骤可能足够触发动作 |
| method+critic | 操作步骤+评判标准 | 加critic可能增强执行准确性 |
| full Tell | 完整TellCore渲染（峰值HintInstance） | 完整认知Option应最强触发 |

### 5.2 过程信号清单

对于"局部-全局表示切换"型Tell，过程信号来自TellCore v0的progress_model字段（383号定义）和373号§8.3：

| 过程信号 | 含义 | 在thinking中如何观察 |
|---|---|---|
| **引入新表示** | AI引入了局部表示（如Z/pZ、Z/nZ） | thinking中出现"考虑模p""用Z/pZ""取局部"等表述，并开始在该表示下操作 |
| **比较原表示与新表示** | AI明确比较了全局表示和局部表示 | thinking中出现"原表示下...但局部表示下..."的对比推理 |
| **找到不变量** | AI在局部表示下找到了保持量/单调量/证书对象 | thinking中出现"在模p下不变""局部保持""周期性"等发现 |
| **产生可验证lemma** | AI把题目目标改写成新表示中的局部条件，产生中间lemma | thinking中出现可验证的中间命题，如"只需证mod p下..." |
| **放弃自然错路** | AI放弃了原先的自然但无效入口 | thinking中出现"这条路走不通""换一个角度"后转向局部表示 |

**判定标准**：每个过程信号按"出现/部分出现/未出现"三档判定。至少"引入新表示"+"比较原表示与新表示"两个核心信号出现，才算"执行了预期认知动作"。

### 5.3 对照矩阵的执行规模

**核心对照矩阵**：4道正迁移题 × 5个条件 = 20个run。

**可选梯度矩阵**：4道正迁移题 × 5个HintInstance变体 = 20个run（如果做）。

**可选变形题**：如果加入过程信号强的变形题（2-3道），每个变形题做核心5组对照 = 10-15个run。

**总规模**：20-55个run（视是否做梯度矩阵和变形题而定）。

每个run记录：
- 解题成功/失败（二元指标——结果层）
- 用时
- 证明方法（是否用了局部-全局切换）
- **过程信号清单**（5个信号各按出现/部分出现/未出现三档判定——过程层，本POC的核心）
- **AI是否简单复述提示词**还是**把提示绑定到题目对象**（373号§8.4通过标准第3条）

### 5.4 判定逻辑

**目标认知动作出现率**（核心指标）：

对每个条件组，计算"执行了预期认知动作"的run比例（"执行"=至少"引入新表示"+"比较原表示与新表示"两个核心信号出现）。

**场景1：目标Tell组出现率 >> bare和通用鼓励组**
- **可执行门通过**——目标Tell确实触发了预期认知动作，不只是提示长度或鼓励效应
- 继续做POC-4（可终止）

**场景2：目标Tell组出现率 ≈ bare和通用鼓励组**
- **可执行门不通过**——目标Tell没有比bare和通用鼓励更好地触发预期认知动作
- 可能原因：HintInstance退化为口号、AI简单复述但不执行、TellCore的progress_model定义的动作不可观察
- 需要分析：是HintInstance的问题还是TellCore的问题

**场景3：目标Tell组出现率 > bare，但等长空流程/错配Tell组也高**
- **可执行门模糊**——目标Tell有效，但不是特异有效的（提示长度或强度就能触发）
- 需要POC-6可归责进一步拆解

**场景4：目标Tell组出现率高，但AI是简单复述提示词**
- **可执行门不通过**——AI没有真正执行认知动作，只是复述了提示
- 373号§8.4通过标准第3条明确要求"AI不是简单复述提示词，而是把提示绑定到题目对象"

### 5.5 失败案例分类

373号§8.4通过标准第5条要求失败案例能区分三类：

| 失败类型 | 定义 | 在thinking中如何观察 |
|---|---|---|
| **没有执行** | AI没有执行预期认知动作 | 过程信号全部"未出现"；AI走了完全不同的路线 |
| **执行但无进展** | AI执行了预期认知动作但没有产生进展信号 | "引入新表示"出现，但"找到不变量"和"产生可验证lemma"未出现；AI切到了局部表示但没找到有用结构 |
| **执行后方向错误** | AI执行了预期认知动作但方向错了 | 过程信号出现，但AI在局部表示下做了错误推理或绑定了错误对象 |

这三类失败的归因不同：
- "没有执行"→HintInstance的执行性问题
- "执行但无进展"→TellCore的progress_model问题（动作对了但没产生进展）或题目不适合此Tell
- "执行后方向错误"→HintInstance的参数绑定引导问题或AI的执行能力问题

### 5.6 操作步骤

1. 从382号CasePack v0取4道正迁移题（+可选2-3道过程信号强的变形题）
2. 从POC-3.5的EvidenceRecord获取峰值区间的HintInstance
3. 从383号TellCore v0的progress_model字段提取过程信号清单（5个信号）
4. 准备5个对照组的提示（bare/通用鼓励/等长空流程/错配Tell/目标Tell）
5. （可选）准备5个HintInstance梯度变体（低强度/line分叉/method-only/method+critic/full Tell）
6. 对每道题，通过solver_harness启动核心对照矩阵的5个run（+可选梯度矩阵的5个run）
7. 对每个run的thinking导出，按过程信号清单逐项判定（出现/部分出现/未出现）
8. 判定AI是否简单复述提示词还是绑定到题目对象
9. 对失败案例按§5.5的三类分类
10. 按§5.4的判定逻辑分析结果
11. 产出ProcessEvidence

## §7 通过标准

### 7.1 通过标准（来自373号§8.4）

**POC-3通过，需要满足**：

1. **目标Tell组的目标认知动作出现率明显高于bare和通用鼓励**——目标Tell确实触发了预期认知动作，不只是鼓励效应
2. **错配Tell不应稳定触发同一动作**——目标认知动作的触发是Tell特异的，不是任何等强度提示都能触发的
3. **AI不是简单复述提示词，而是把提示绑定到题目对象**——AI真的执行了认知动作，不是表面复述
4. **至少部分案例出现progress model预期的中间信号**——不只"引入新表示"，还有"找到不变量"或"产生可验证lemma"等进展信号
5. **失败案例能区分"没有执行""执行但无进展""执行后方向错误"**——失败归因能落到具体环节

### 7.2 不通过的处理

**如果条件1不满足（目标Tell组出现率不比bare和通用鼓励高）**：

停下来分析原因：
- **HintInstance退化为口号？**——提示词太抽象，AI不知道具体做什么。需要回到HintRenderer调整渲染
- **AI简单复述但不执行？**——提示词给出了方向但AI没有把它绑定到题目对象。可能需要更强的参数绑定引导
- **TellCore的progress_model定义的动作不可观察？**——过程信号在thinking中看不出来。可能需要调整过程信号的定义
- **题目不适合观察过程信号？**——373号§14.9说"即使执行Tell也看不出中间动作的题"不适合POC-3。可能需要换题

**如果条件2不满足（错配Tell也稳定触发同一动作）**：

- 目标认知动作不是Tell特异的——任何等强度提示都能触发
- 需要POC-6可归责进一步拆解——是提示强度效应还是认知动作本身太泛

**如果条件3不满足（AI简单复述提示词）**：

- HintInstance没有让AI执行，只让AI复述
- 需要调整HintInstance的渲染方式——让提示更偏向"做什么"而非"说什么"

### 7.3 模糊结果的处理

**如果结果是ambiguous（目标Tell有效但等长空流程/错配Tell也高）**：

- 记录哪些对照也触发了目标认知动作
- 这不阻塞POC-4，但要在ProcessEvidence中明确记录——POC-6可归责需要处理这个混杂
- 模糊结果意味着"可执行门部分通过"——AI确实执行了预期认知动作，但执行性不是Tell特异的

### 7.4 通过后不意味着Tell"有效"——只意味着"可执行"

**重要**：POC-3通过只说明HintInstance让AI执行了预期认知动作——这是六门审计中的"可执行门"。但这不意味着Tell"有效"——因为：
- 可执行不等于可终止——AI可能执行了认知动作但一直打转（需要POC-4）
- 可执行不等于可归责——执行性可能来自提示长度或强度而非Tell特异内容（需要POC-6）
- 可执行不等于可持续学习——执行成功但遇到反例时能否修订（需要POC-7）

POC-3通过后，继续做POC-4（可终止）和POC-6（可归责）来进一步验证。

### 9.4 POC运行记录

POC运行记录必须保留thinking、trajectory、proof或TUI导出。通过solver_harness自动保存。

**POC-3尤其需要完整的thinking导出**——过程信号的判定完全依赖thinking内容。如果thinking导出不完整，过程信号判定无法进行。

### 9.5 证据分层

POC结论必须写成证据分层——不把"可执行"升级成"有效"。可执行只是六门审计中的一门，Tell是否真正"有效"还需要POC-4（可终止）、POC-6（可归责）和POC-7（可持续学习）来进一步验证。

### 9.6 过程信号判定的可靠性

过程信号判定是POC-3的核心——整个POC的结论依赖于对thinking中过程信号的准确判定。判定时需要注意：
- **区分"执行"和"复述"**——AI说"提示让我考虑局部表示"是复述；AI说"我们来看mod p下x的性质"是执行
- **区分"出现"和"部分出现"**——"出现"是完整执行了该认知动作；"部分出现"是提到了但没深入操作
- **多个信号之间有依赖关系**——"引入新表示"通常是前提，"找到不变量"和"产生可验证lemma"通常是后续。如果"引入新表示"未出现但"找到不变量"出现，需要检查判定是否准确

### 9.7 失败不是废结果

如果POC-3不通过（目标Tell没有触发预期认知动作），这不是废结果——这揭示了HintInstance的执行性问题。不通过的结果必须完整记录，并触发对HintRenderer渲染方式或TellCore progress_model的修订。

## §10 与其他POC的关系

### 10.1 前置关系

```
POC-0（题包冻结）→ POC-1（TellCore确定）→ POC-2（selector验证）→ POC-2.5（基础因果效应）→ POC-3.5（峰值Hint确定）→ ★ POC-3（可执行）★
```

POC-3依赖：
- POC-0的题包（正迁移题+变形题）
- POC-1的TellCore（progress_model定义过程信号）
- POC-2.5的基础因果效应验证（必须通过——基础效应不存在则过程层验证无意义）
- **POC-3.5的峰值HintInstance（必须通过——POC-3用峰值区间的Hint测可执行性）**

### 10.2 后续关系

```
★ POC-3（可执行）★ → POC-4（可终止）→ POC-6（可归责）→ POC-7（可持续学习）→ POC-8（端到端闭环）
```

POC-3通过后才能做POC-4——可终止的前提是AI已经在执行Tell。如果AI根本没执行预期认知动作，"何时停止"无从谈起。

POC-3通过后才能做POC-6——可归责要看full Tell相对bare有过程层增益。POC-3验证了过程层指标（目标认知动作出现率），为POC-6的归责矩阵提供了过程层基准。

### 10.3 与POC-6的关系——过程层指标的重叠

POC-3和POC-6都关注过程层指标，但角度不同：
- **POC-3**：目标Tell是否触发了预期认知动作（是/否——可执行性）
- **POC-6**：增益来自哪个组件（bare/通用鼓励/等长空流程/错配Tell/method only/full Tell——归责）

POC-3的对照矩阵（bare/通用鼓励/等长空流程/错配Tell/目标Tell）是POC-6干预矩阵的子集。POC-3通过后，POC-6可以复用POC-3的数据，扩展为完整干预矩阵（加trigger only/critic only/trigger+method/method+critic/过强窄方法提示）。

### 10.4 如果POC-3不通过

- **不通过阻塞POC-4**——AI没有执行预期认知动作，可终止无从谈起
- **不通过阻塞POC-6**——没有过程层基准，归责矩阵无意义
- **不通过阻塞POC-7/8**——可执行是后续所有门的前提
- **不通过不阻塞POC-9（识别端验证）**——识别端从失败trace读分叉，不依赖Hint是否可执行
- **不通过触发对HintRenderer的修订**——如果AI没有执行预期认知动作，可能是渲染方式的问题
- **不通过触发对TellCore progress_model的修订**——如果过程信号不可观察，可能是progress_model定义的问题
