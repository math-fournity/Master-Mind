## 0. 本方案要解决的三个核心问题

### 难点1：Tell就是提示词——如何区分"思维力指导"和"信息泄漏"？

**问题**：非特化、启发式Tell本质上是一套提示词。提示词可能包含两种内容：
- **思维力指导**：告诉AI应该用什么思维方式（"当你反复尝试同一类方法失败时，考虑诊断这个方向本身是否有效"）
- **信息泄漏**：告诉AI应该用什么具体方法（"用Galois理论证明这个五次方程没有根式解"）

**区分标准**：Tell中是否包含**题目特定的信息**（具体方法、具体对象、具体领域）。
- 不包含→思维力指导（纯洁的Tell）
- 包含→信息泄漏（造假的Tell）

**灰色地带**："当你反复试模分析失败时，考虑模分析本身是否有效"——这里"模分析"是题目特定的，所以这是信息泄漏。正确的去特化应该是"当你反复试同一类方法失败时，考虑这个方法本身是否有效"。

**本方案的解决机制**：Tell纯洁性三重检验（§2.1）。

### 难点2：出题——如何找到"只有这种思维力才能解决"的题？

**问题**：需要同时满足四个条件：
1. **必要性**：只有思维力X才能解决
2. **bare失败**：GLM-5.2做不出来
3. **Tell有效**：给Tell后能做出来
4. **Tell纯洁性**：Tell不泄漏答案

**内在张力**：
- 条件1和4有张力：如果题目"只有这种思维力才能解决"，那Tell说"用这种思维力"就等于泄漏答案。解决：Tell不说是哪种思维力，只给思维流程引导
- 条件2和3有张力：bare做不出来但Tell后能做出来——难度要恰好在这个窗口。解决：多档难度筛选

**根本困难**：我们无法100%确认"只有这种思维力才能解决"——无法穷举所有解法。只能用证据间接证明。

**本方案的解决机制**：混合出题策略+四道筛选关卡（§3）。

### 难点3：智识诚实——如何确保不是在造假、不是在模拟？

**5种造假风险**：

| 风险 | 描述 | 例子 |
|---|---|---|
| R1：Tell泄漏答案 | Tell包含了题目特定方法 | Tell说"用Galois理论"=给了答案 |
| R2：选择性偏差 | 先设计Tell再找Tell恰好有效的题 | 等于自己出题自己答 |
| R3：题目不是真的只有一种解法 | 题目可能有多种解法，Tell只是其中一条 | Tell的"必要性"是虚假的 |
| R4：bare失败不是因为题难 | bare AI可能因为格式/理解问题失败 | 不是真的做不出来 |
| R5：Tell只是提供了"元信息" | "这道题有解""仔细思考"本身就能提高表现 | Tell的有效性不来自思维力指导 |

**本方案的解决机制**：预注册+盲审+交叉验证矩阵+负对照（§2）。

## 1. 验证目标与范围

### 1.1 验证目标

**主命题**：对于26种思维力中的每一种，存在一套非特化的Tell（提示词），使得：
1. GLM-5.2在bare条件下做不出来的题，在Tell指导下能做出来
2. Tell不包含题目特定信息（不是信息泄漏）
3. 不匹配的Tell无效（不是"额外动力"）
4. 纯鼓励性提示无效（不是"元信息"效应）

### 1.2 验证范围

| 维度 | 范围 |
|---|---|
| 思维力种类 | 26种全部（348号11种+349号新发现15种） |
| 每种思维力的题量 | 5道题（最少） |
| Tell形态 | 三种全部（一句话/思维流程引导式/抽象标签） |
| bare对照 | 每道题5次bare |
| 交叉验证 | 每道题5种不匹配Tell |
| 负对照 | 每道题1次纯鼓励提示 |

### 1.3 总工作量估算

| 实验类型 | 每道题次数 | 每种思维力（5道题） | 26种总计 |
|---|---|---|---|
| bare对照 | 5 | 25 | 650 |
| 匹配Tell（3形态×3次） | 9 | 45 | 1170 |
| 交叉验证（5种不匹配Tell×1次） | 5 | 25 | 650 |

## 2. 智识诚实保障机制

### 2.1 Tell纯洁性三重检验（解决难点1）

**检验1：去特化审查**
- Tell中不能包含任何题目特定的词汇（具体方法名、具体对象名、具体领域名）
- 审查方法：Tell设计完成后，逐词检查——如果某个词只出现在这道题的语境中，必须替换为通用表述
- 通过标准：Tell中的每一个词都应该能适用于多道不同的题

**检验2：迁移性检验**
- 同一Tell必须能用于至少3道不同的题（不同表面特征，同一思维力）
- 如果Tell只对一道题有效→Tell是信息泄漏
- 通过标准：同一Tell在3道不同题上都有效（或至少在2道上有效，1道部分有效）

**检验3：盲审**
- Tell设计完成后，让一个不知道题目答案的审查者（另一个AI session）看Tell
- 审查问题："你能从这个Tell猜出这道题的答案或解法吗？"
- 如果能猜出→Tell泄漏了答案，需要进一步去特化
- 通过标准：审查者无法从Tell猜出答案

### 2.2 预注册机制（解决R2选择性偏差）

**预注册内容**（在实验前全部公开，不可修改）：
1. 每种思维力的定义
2. 每道题的题目文本
3. 每道题的设计意图（应该需要哪种思维力）
4. 每个Tell的文本（三种形态）
5. 评估标准（什么算"做出来"，什么算"做不出来"）
6. 交叉验证矩阵（哪5种不匹配的Tell用于哪道题）

**预注册后**：实验结果无论正面还是负面都必须报告。不能因为结果不支持假设就隐藏。

### 2.3 交叉验证矩阵（解决R3和R5）

**核心设计**：对每道题，不只给匹配的Tell，还给5种不匹配的Tell和1种纯鼓励提示。

| 实验类型 | Tell内容 | 预期结果 | 如果结果与预期不符 |
|---|---|---|---|
| 匹配Tell | 题目需要的思维力的Tell | AI做出来 | 如果做不出来→Tell无效 |
| 不匹配Tell×5 | 其他5种思维力的Tell | AI做不出来 | 如果做出来了→Tell不是在指导特定思维力，只是"额外动力" |
| 纯鼓励 | "这道题有解，请仔细思考" | AI做不出来 | 如果做出来了→Tell的有效性来自"元信息"而非思维力指导 |

**交叉验证矩阵的意义**：如果只有匹配的Tell有效，不匹配的Tell和纯鼓励都无效，那么：
- 排除了R3（Tell不是"任何提示都有效"）
- 排除了R5（Tell的有效性不是来自"元信息"）
- 间接证明了"题目确实需要这种思维力"

### 2.4 bare失败确认（解决R4）

**5次bare规则**：
1. 每道题跑5次bare GLM-5.2（不给任何Tell）
2. 5次全部失败才纳入实验
3. 如果有任何1次成功→该题不纳入（太简单）
4. 失败的确认标准：
   - AI明确表示"我做不出来"或"我放弃了"
   - AI的最终答案错误
   - AI超时未给出答案
   - **不算失败的情况**：AI理解错了题意（这是格式问题，不是题难）→需要修正题目表述

### 2.5 评估标准（解决主观判断风险）

**二元指标**（不用连续指标）：
- **成功**：AI给出了正确的数学证明/解答
- **失败**：AI没有给出正确证明/解答

**正确性判断**：
1. **自动检查**：对于有数值答案的题，直接比对
2. **人工检查**：对于证明题，由数学家（或另一个AI session）审查证明的正确性
3. **审查标准预注册**：在实验前公开"什么样的证明算正确"

**禁止的评估方式**：
- ❌ "AI的表现更好了"（连续指标，难以客观判断）
- ❌ "AI的思路更接近正确解法了"（主观判断）
- ❌ "AI似乎理解了这种方法"（不可量化）

## 3. 出题策略（解决难点2）

### 3.1 混合策略

用户选择了"混合策略"——核心思维力用历史案例，新思维力用专门设计，全部用竞赛题做交叉验证。

| 思维力类型 | 出题来源 | 理由 |
|---|---|---|
| 348号11种（有丰富历史案例） | 历史案例改编+竞赛题筛选 | 有历史证据证明"只有这种思维力" |
| 349号新发现15种 | 专门设计+竞赛题筛选 | 无历史案例，需根据思维力定义设计 |
| 全部26种 | 竞赛题交叉验证 | 用竞赛题验证Tell的迁移性 |

### 3.2 四道筛选关卡

每道题必须通过四道关卡才能纳入实验：

**关卡1：思维力必要性审查**
- 题目是否真的需要这种思维力？
- 审查方法：让数学家（或另一个AI session）尝试用其他思维力解决
- 通过标准：尝试了至少3种其他思维力都失败

**关卡2：bare失败确认**
- 5次bare GLM-5.2全部失败
- 通过标准：5次全部失败（§2.4）

**关卡3：AI训练数据检查**
- 题目是否在AI训练数据中出现过？
- 检查方法：让bare AI"回忆"是否见过这道题
- 通过标准：AI没有直接回忆出答案（如果AI说"这是一道经典题，解法是..."→该题不可用）

**关卡4：难度窗口确认**
- 题目难度是否在"bare做不出来但Tell后能做出来"的窗口内？
- 确认方法：给匹配的Tell跑1次试探实验
- 通过标准：AI在Tell指导下能做出来（如果Tell后也做不出来→太难，不可用）

### 3.3 历史案例改编（用于348号11种思维力）

**改编原则**：
1. 保留思维力结构——题目在结构上和菲尔兹奖得主的工作同构（需要同样的思维力）
2. 改变表面特征——题目在表面特征上完全不同（避免AI通过模式匹配做出来）
3. 降低难度——把菲尔兹奖级别的工作简化为AI可做的题（但简化后仍需原思维力）
4. 避免经典案例——不用太经典的案例（AI可能通过训练数据知道解法）

**每种思维力的历史案例来源**（从349号提取）：

| 思维力 | 历史案例来源 | 改编方向 |
|---|---|---|
| 同构之桥 | Galois理论/FLT/庞加莱猜想 | 设计一道需要跨域翻译但不是经典案例的题 |
| 构造必然逃逸 | 欧拉素数无穷/Cauchy-Schwarz/Frey曲线 | 设计一道需要构造有必然后果的对象的题 |
| 诊断追逐无效 | Riemann探索/模分析追逐 | 设计一道AI会无尽追逐但应诊断转向的题 |
| 找对递降量 | Fermat递降/IMO归纳/Goodstein | 设计一道需要找到正确递降量的题 |
| 信息融合时机 | Wiles路径/信息论证明 | 设计一道需要多步累积才能收敛的题 |
| 不变量识别 | Euler示性数/奇偶性/特征值 | 设计一道需要找变换下不变量的题 |
| 对偶/反演 | 反证法/射影对偶/几何反演 | 设计一道正面攻击困难但翻转视角简洁的题 |
| 极值原理 | 调和极值/Erdős-Szekeres/博弈min-max | 设计一道需要考虑极端情况的题 |
| 类比迁移 | Euler Basel/Riemann zeta | 设计一道和经典题结构相似但表面不同的题 |
| 化归/转化 | 解析几何/对数/复数 | 设计一道需要转化到另一形式的题 |
| 退中求进 | Euler Σ1/n²/竞赛先看小case | 设计一道需要先看n=1,2,3找规律的题 |

### 3.4 专门设计（用于349号新发现15种）

**设计原则**：
1. 根据思维力定义构造"最小测试题"——最简单的需要这种思维力的题
2. 题目应该足够简单以至于有Tell就能做，但bare做不出来
3. 题目不能有其他解法路径

**每种新思维力的设计方向**：

| 新思维力 | 设计方向 | 难度控制 |
|---|---|---|
| 本质重构(#12) | 设计一道需要完全改变问题框架的题 | 中——需要跳出框架但不需要复杂计算 |
| 层级抽象(#13) | 设计一道在当前层级难但升维后简单的题 | 中——升维概念需要洞察但计算简单 |
| 分层递进构造(#14) | 设计一道需要多步构造每步依赖前步的题 | 高——递进过程复杂 |
| 覆盖-提升技术(#15) | 设计一道直接做难但构造覆盖空间后简单的题 | 高——覆盖空间构造复杂 |
| 局部-全局桥接(#16) | 设计一道需要从局部信息推导全局的题 | 中——局部-全局联系需要洞察 |
| 平均化消解(#17) | 设计一道单个实例不可控但平均可控的题 | 高——统计直觉在确定性数学中罕见 |
| 近似-精确转化(#18) | 设计一道理想构造不可行但近似可行的题 | 中——近似概念需要洞察 |
| 结构化嵌入(#19) | 设计一道需要嵌入更大结构才能控制的题 | 高——构造大结构复杂 |
| 统一化框架(#20) | 设计一道需要统一框架才能解决的题 | 高——框架构造复杂 |
| 先验估计(#21) | 设计一道需要先假设存在再证明的题 | 高——循环论证反直觉 |
| 精确边界识别(#22) | 设计一道需要找到充分必要条件的题 | 高——边界识别需要极深洞察 |
| 结构二分识别(#23) | 设计一道需要证明要么A要么B没有中间的题 | 高——二分证明复杂 |
| 跨尺度不变性识别(#24) | 设计一道需要识别尺度不变量的题 | 中——尺度不变性概念需要洞察 |
| 刚性洞察(#25) | 设计一道需要识别系统刚性的题 | 高——刚性概念抽象 |
| 框架创造(#26) | 设计一道现有框架不足需创造新框架的题 | 最高——框架创造是最难的思维力 |

### 3.5 竞赛题交叉验证

**用途**：验证Tell的迁移性——同一Tell在竞赛题上也应该有效。

**来源**：
- IMO/USAMO/PUTNAM等竞赛题库
- 筛选标准：题目需要同一种思维力，但表面特征和历史案例完全不同

**验证逻辑**：
1. 为每种思维力设计的历史案例/专门设计题→Tell A
2. 从竞赛题库筛选需要同一种思维力的题→用Tell A测试
3. 如果Tell A在竞赛题上也有效→Tell A是通用的思维力指导（通过迁移性检验）
4. 如果Tell A只在历史案例上有效→Tell A是信息泄漏（未通过迁移性检验）

## 4. Tell设计

### 4.1 三种形态的设计原则

**形态1（一句话）**：
- 格式：一个简短的指令
- 去特化要求：不能包含题目特定的词汇
- 例子（诊断追逐无效）："当你反复尝试同一类方法失败时，考虑诊断这个方法本身是否有效，而不是继续试更多参数"

**形态2（思维流程引导式）**：
- 格式：一系列引导性问题，引导AI按思维力的步骤思考
- 去特化要求：问题中不能包含题目特定的词汇
- 例子（同构之桥）：
  ```
  你当前在什么领域打转？
    → 识别当前领域的核心对象和操作
  你尝试过什么方向？
    → 列出已尝试的方向
  这些方向都失败了，说明什么？
    → 当前领域可能缺少处理这个问题的工具
  那哪个领域可能有？
    → 检查是否有同构对象（同样的结构在不同领域出现）
    → 检查是否有对偶问题（这个问题的反面在另一个领域可能更简单）
    → 检查是否有表示转换（换一种表示看问题）
  如果找到一个可能的目标领域，怎么判断值不值得跨？
    → 评估跨域成本 vs 当前领域继续探索的成本
  ```

**形态3（抽象标签）**：
- 格式：一个抽象的思维力名称+简短描述
- 去特化要求：只有思维力名称，不能有任何题目特定信息
- 例子（同构之桥）："考虑跨域桥接——把问题从一个领域翻译到另一个领域"

### 4.2 Tell的预注册

每个Tell在实验前必须预注册以下内容：

```
Tell ID：T-<思维力编号>-<形态编号>
思维力：<思维力名称>
形态：<一句话/思维流程引导式/抽象标签>
Tell文本：<完整文本>
去特化审查：<逐词检查结果——每个词是否通用>
盲审结果：<另一个AI session能否从Tell猜出答案>
设计意图：<这个Tell应该指导哪种思维力>
预期效果：<在匹配的题上有效，在不匹配的题上无效>
```

### 4.3 26种思维力的Tell设计工作量

| 思维力 | 形态1 | 形态2 | 形态3 | 总计 |
|---|---|---|---|---|
| 26种 | 26个 | 26个 | 26个 | 78个Tell |

每个Tell需要：设计+去特化审查+盲审 ≈ 30分钟
总计：78 × 0.5h = 39小时

## 5. 实验执行流程

### 5.1 单道题的完整实验流程

```
关卡1：思维力必要性审查
  → 让另一个AI尝试用3种其他思维力解决
  → 全部失败→通过

关卡2：bare失败确认
  → 跑5次bare GLM-5.2
  → 5次全部失败→通过

关卡3：AI训练数据检查
  → 让bare AI"回忆"是否见过这道题
  → 没有直接回忆出答案→通过

关卡4：难度窗口确认
  → 给匹配的Tell跑1次试探实验
  → AI能做出来→通过

正式实验（如果四道关卡都通过）：
  → 匹配Tell×3形态×3次 = 9次
  → 不匹配Tell×5种×1次 = 5次
  → 纯鼓励×1次 = 1次
  → 总计15次正式实验
```

### 5.2 实验的自动化

用脚本自动执行：
1. `solver-tmux-launch` skill启动devin cli实例
2. 给AI题目（和Tell，如果有）
3. 等AI做完（设置超时，如2小时）
4. 自动提取AI的最终答案
5. 对有数值答案的题自动判对错
6. 对证明题人工审查

### 5.3 并行执行

- session 1：bare对照实验
- session 2：匹配Tell实验
- session 3：交叉验证实验

## 9. 开放问题

1. **"只有这种思维力才能解决"的可证伪性**——我们无法穷举所有解法，所以这个命题永远不能100%确认。交叉验证是间接证据，但不是证明。这是本方案的固有局限性，必须在报告中明确说明。

2. **专门设计题目的"设计痕迹"**——专门设计的题目可能有设计者的偏见（设计者知道答案，无意中在题目中留下线索）。缓解方法：让另一个AI session审查题目是否有设计痕迹。

3. **框架创造(#26)的验证困难**——框架创造是最难的思维力，可能很难找到"bare做不出来但Tell后能做出来"的窗口。如果框架创造验证失败，可能是题目难度窗口不对，而不是Tell无效。

4. **AI的随机性**——GLM-5.2的输出有随机性，同一题同一Tell可能有时成功有时失败。9次实验中6次成功的标准是否合理？可能需要更多次实验才能达到统计显著性。

5. **时间成本**——24天的预估是乐观的。如果筛选阶段大量题目被淘汰需要重新出题，或正式实验阶段AI做题时间超预期，总时间可能延长到30-40天。
