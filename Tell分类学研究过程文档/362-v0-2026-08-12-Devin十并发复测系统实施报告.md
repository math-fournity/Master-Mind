## 3. 失败归因（361号§10/§12.9）

### 3.1 5个failed_token_limit

**统一根因**：GLM-5.2命中max output token limit（"response truncated: model hit max output token limit"）。

**证据路径**：每个attempt的`trajectory_dir/tmux/tmux_pipe.log`包含：
```
warning: response truncated (model hit max output token limit)
Error: Response truncated: model hit max output token limit. The output above is incomplete.
```

**thinking特征**：5个失败均在thinking达到~25000 chunk上限时终止（47-67K字符）。thinking内容显示AI在持续推理但未收敛到证明写入阶段。

| 题 | thinking大小 | 轮次 | 备注 |
|---|---|---|---|
| 1631 | 156KB | Round 1020 | 历史强证据复测确认 |
| 1843 | 60KB | 中途截断 | 历史强证据复测确认；thinking停在"also in $L$, the nearest roots of $g$..." |
| 1962 | 103KB | Round 1016 | 历史强证据复测确认 |
| 1974p6 | 52KB | Round 1040 | Tier1 predicted fail |
| 1976p5 | 68KB | Round 1062 | Tier1 predicted fail |

### 3.2 2个proof_invalid

**IMO 1967 P5 (p329042)**：
- 错误点：Step 3的dominant balance论证中，下标选择错误。证明取"最大下标"ℓ*，但因γ₁>γ₂>...>γ_s，最大下标对应最小γ，导致因式分解丢弃了γ更大的主导项。
- 修正方法：将"largest index"改为"smallest index"。
- 评价：结论正确，整体思路正确，错误可定位可修正。

**IMO 1971 P5 (p329057)**：
- 错误点：关键断言"f_{I,σ}不恒等于1"的验证中，声称|∑σ_i|"要么≥2要么为0"，但|I|奇数且混合符号时∑σ_i可为±1，(∑σ_i)²=1，该特取值无法区分f与1。
- 修正方法：用"非常值"论证（f含cos(θ_i-θ_j)项故不恒为1），证明后半段已用此思路。
- 评价：方法正确，gap可填补，但原文有明确错误陈述。

## 6. 核心发现与启示

### 6.1 GLM-5.2 bare能力远超profile预测

10道Tier1 `bare_ai_expected=fail`的IMO P5/P6题中，**7道生成了数学正确的完整证明**。这意味着：

- profile侧写的`bare_ai_expected`预测过于保守
- GLM-5.2在IMO P5/P6级代数/组合题上有可观的bare解题能力
- 需要重新校准"bare失败"的难度门槛

### 6.2 token limit是主要失败模式

5个失败全部是`failed_token_limit`——AI生成大量thinking（47-156KB）但未在token上限内收敛到证明写入。无rate limit、无tool stall、无connection error。

### 6.3 proof_invalid的模式

2个proof_invalid都是"方法正确但关键步骤有可定位错误"——不是方向性错误，而是技术性gap。这提示GLM-5.2的推理能力强于其严格性验证能力。

### 6.4 历史强证据题仍稳定失败

1631/1843/1962在Phase 3中全部复测确认failed_token_limit，与历史VMS记录一致。这些题是稳定的bare失败样本，适合作为Tell实验的基线。
