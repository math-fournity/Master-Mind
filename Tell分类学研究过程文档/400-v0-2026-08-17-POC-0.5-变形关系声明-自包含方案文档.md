## §0 自包含POC方案文档的设计规范（本节是所有POC方案文档的共用规范）

### 0.1 设计目标

一份POC方案文档要让未来20万上下文的AI**只加载这份文档+它索引的少数核心文档**，就能完整了解做好这次POC所需的所有背景知识，不需要用户另外指点应该读什么。

### 0.2 文档结构（每份POC方案文档必须包含的10节）

| 节 | 内容 | 作用 |

### 0.3 "自包含"的含义

"自包含"不是把所有背景知识复制进文档——那样文档会膨胀到无法加载。"自包含"是指：

1. **文档本身包含这个POC执行所需的全部操作信息**——输入/方法/输出/通过标准/执行约束
2. **文档明确列出需要全文加载的背景文档清单**——每份说明加载理由（这个POC为什么需要这份文档的内容）
3. **未来AI加载这份POC方案后，按照§8清单去全文加载被索引的文档**——不需要用户另外指点

### 0.4 被索引文档的精挑细选原则

每份POC方案文档的§8清单应该精挑细选——只列这个POC真正需要的背景文档，通常3-7份。如果索引太多，未来AI加载不完。

**挑选标准**：
- **必须加载**：这个POC不加载这份文档就无法正确执行（如题包/TellCore定义/通过标准来源）
- **建议加载**：这个POC加载这份文档能更好理解为什么这么做（如理论背景/原设计文档）
- **不列**：这个POC不需要这份文档的内容（如其他POC的方案文档）


## §1 本POC的定位与核心问题

### 1.1 核心问题

**POC-0.5回答**：

> 对目标TellCore，哪些变换是允许的（不应改变Tell触发），哪些变换是禁止的（应使Tell失效）？

### 1.2 为什么需要这个POC

372号§4D路线D2（Metamorphic Testing）说："变形关系比随机找几道题更直接地检验非特化主张——声明一组变换并逐一验证。"但373号的POC虽然有"结构保持变形题"，却没有系统化的变形关系声明——变形题是随意构造的，不是按声明的变换逐一构造的。

POC-0.5在POC-0冻结题包后、POC-1确定TellCore前，先声明允许变换和破坏变换。这个声明指导POC-0中变形题和假朋友题的构造，也指导POC-1中TellCore的字段设计。

## §2 理论背景——为什么需要这个POC

### 2.1 396号的核心论断

396号§4.2说"非特化是因果充分的取商"——把表面不同但目标关系下等价的认知动作视为同一个认知技能。"取商"的关键是声明哪些变换是允许忽略的（nuisance），哪些变换会破坏机制（mechanism-bearing）。

### 2.2 372号的变形测试

372号§4D路线D2列出了变形关系：
- 变量重命名后，Tell选择不应改变
- 表面外壳替换但机制保持时，Tell仍应触发
- 破坏必要关系后，Tell不应触发
- 对偶化后，参数绑定应按角色对应变化
- 增加无关诱饵后，Tell效用不应大幅下降

POC-0.5把这些变形关系系统化声明，指导变形题和假朋友题的构造。

### 2.3 397号审视的缺失项

397号§3.6指出373号有"结构保持变形题"但没有系统化的变形关系声明。POC-0.5填补这个缺失。

## §5 方法——这个POC怎么做

### 5.1 变形关系声明表

对目标TellCore（局部-全局表示切换），声明以下变换：

| 变换类型 | 是否允许 | 理由 | 验证方式 | 对应题目 |
|---|---|---|---|---|
| 变量重命名 | ✅允许 | 不改变数学结构 | 构造重命名变形题，Tell应仍触发 | 变形题 |
| 数值缩放 | ✅允许 | 不改变数学结构 | 构造缩放变形题，Tell应仍触发 | 变形题 |
| 对象换壳（整数→多项式） | ✅允许 | 保持"自然表示→局部表示"的切换结构 | 构造换壳变形题，Tell应仍触发 | 变形题 |
| 领域迁移（数论→组合） | ✅允许（如果TellCore声称跨域） | 局部-全局切换不限于数论 | 构造跨域变形题，Tell应仍触发 | 变形题 |
| 表示形式改变（mod p → p-adic） | ✅允许 | 都是局部表示 | 构造表示形式变形题，Tell应仍触发 | 变形题 |
| 机制破坏：问题核心在构造性而非整除性 | ❌禁止 | 局部-全局切换不适用 | 构造机制破坏题，Tell应拒绝 | 假朋友题 |
| 机制破坏：问题已在局部表示下 | ❌禁止 | 不需要切换 | 构造"已在局部表示"题，Tell应拒绝 | 假朋友题 |
| 机制破坏：问题核心在几何而非代数 | ❌禁止 | 局部-全局切换（Z/pZ/Q_p）不适用 | 构造几何题，Tell应拒绝 | 假朋友题 |
| 增加无关诱饵 | ✅允许 | 不应改变Tell效用 | 构造诱饵题，Tell效用不应大幅下降 | 假朋友题/decoy题 |
| 改变一个关键条件（如去掉整除性约束） | 边界 | 测试trigger边缘 | 构造边界题，Tell应标为boundary或abstain | 边界题 |

### 5.2 变形题构造原则

变形题按声明的变换**逐一构造**，不是随意构造。每道变形题必须显式写出：
- 保留了什么（TellCore的因果内核）
- 改变了什么（表面特征）
- 哪个声明变换对应这道题

### 5.3 假朋友题构造原则

假朋友题按声明的禁止变换**逐一构造**。每道假朋友题必须显式写出：
- 哪几个表面特征诱导误触发
- 哪一个关键结构缺失导致Tell不应执行
- 对应哪个禁止变换

## §6 输出——这个POC产出什么

```yaml
MetamorphicRelationDeclaration:
  tell_family: 局部-全局表示切换
  allowed_transformations:
    - name: 变量重命名
      reason: 不改变数学结构
      test_case_id: [对应的变形题case_id]
    - name: 数值缩放
      ...
  forbidden_transformations:
    - name: 机制破坏——构造性而非整除性
      reason: 局部-全局切换不适用
      test_case_id: [对应的假朋友题case_id]
    - name: 机制破坏——已在局部表示
      ...
  boundary_transformations:
    - name: 改变一个关键条件
      test_case_id: [对应的边界题case_id]
```

## §7 通过标准

- 每个允许变换至少有1道对应变形题
- 每个禁止变换至少有1道对应假朋友题
- 至少1道边界题测试trigger边缘
- 每道变形题/假朋友题/边界题都显式写出对应的声明变换
- 变形题和假朋友题不是随意构造的，是按声明逐一构造的
