### 0.3 "自包含"的含义

"自包含"不是把所有背景知识复制进文档——那样文档会膨胀到无法加载。"自包含"是指：

1. **文档本身包含这个POC执行所需的全部操作信息**——输入/方法/输出/通过标准/执行约束
2. **文档明确列出需要全文加载的背景文档清单**——每份说明加载理由（这个POC为什么需要这份文档的内容）
3. **未来AI加载这份POC方案后，按照§8清单去全文加载被索引的文档**——不需要用户另外指点

- **必须加载**：这个POC不加载这份文档就无法正确执行（如题包/TellCore定义/通过标准来源）
- **建议加载**：这个POC加载这份文档能更好理解为什么这么做（如理论背景/原设计文档）
- **不列**：这个POC不需要这份文档的内容（如其他POC的方案文档）

### 1.3 核心问题

**POC-3.5回答**：

> 同一个TellCore渲染成不同非特化程度的HintInstance时，AI指导力是否有差异？如果有差异，是呈钟形曲线（先升后降的单峰），还是Pareto前沿（多轴非支配集），还是352号指出的替代形状（多峰/平台/阈值/任务依赖/模型依赖）？

这个问题是396号整个非特化理论框架的核心——用户的厘清说钟形曲线绑在Hint上，GPT的深化说峰值应改成Pareto前沿，352号的批判说钟形曲线作为实验假设太强。POC-3.5就是用实验数据来判定这三种说法哪个更接近真实。

### 1.4 为什么是"最关键的新增POC"

397号审视发现，373号的9个POC中**没有一个覆盖396号的核心论断**：

- 396号§1：用户厘清——钟形曲线绑在**Hint**上，不是Tell上。同一个TellCore渲染成不同非特化程度的Hint时，AI指导力呈钟形曲线（"非特化程度太高了，AI不知道应该如何应用；非特化程度太低了，AI只掌握一道题怎么做"）
- 396号§3：GPT深化——峰值应改成**Pareto前沿**，不是单轴钟形曲线的最高点。多个HintInstance在不同维度上各有优势，应保存非支配集
- 352号§3：批判——钟形曲线作为实验假设**太强**，真实情况可能是多峰/平台/阈值/任务依赖/模型依赖
- 347号§2：修正——钟形曲线不是一条固定曲线，而是**曲线族**——提示词形态（一句话/思维流程引导式/抽象标签）影响指导力，同一Level不同形态的Hint有不同的AI指导力

**373号的POC-3只测试"HintInstance能否让AI执行预期认知动作"，不测试"同一TellCore的不同非特化程度Hint的AI指导力差异"**。POC-3.5填补这个缺失。

397号§3.1明确将此缺失列为"GPT未考虑到的8项缺失"中的**最关键缺失**——"396号的核心论断没有被POC覆盖"。

## §2 理论背景——为什么需要这个POC

### 2.1 396号的核心论断：钟形曲线绑在Hint上

396号§1记录了用户的重要概念厘清：

> Tell应该是一种需要被识别的思维脉络中的存在，而这种存在，它们在思维脉络中，是分在不同的层中存在的。而Hint则是需要被非特化的内容，也就是找到那个钟形曲线的最高点——非特化程度太高了，也就是Level太高了，反而AI不知道应该如何应用Hint提示；非特化程度太低了，那么AI就更像是只掌握了一道题怎么做，而不是一类题怎么做。

这个厘清修正了345号（GPT写的）的错误——345号把钟形曲线绑在了**Tell**上。用户纠正：钟形曲线应绑在**Hint**上，因为：

- Tell是识别端——它的属性是"在思维脉络的哪一层被识别"，是关于**识别位置**的
- Hint是注入端——它的属性是"非特化到什么程度"，是关于**注入效果**的
- "AI不知道怎么应用"和"AI只掌握一道题怎么做"——这两个问题都是**注入端的问题**，都是Hint的非特化程度问题

**POC-3.5要验证的正是这个论断**：同一个TellCore（局部-全局表示切换），渲染成5个不同非特化程度的HintInstance时，AI指导力是否有差异，是否呈钟形曲线。

### 2.2 396号§3：钟形曲线→Pareto前沿

396号§3记录了GPT在372号看到的更深一层——钟形曲线假设Level是单轴的，但这可能是错的：

372号§6.1指出，Level至少是一个向量：

```
L(T) = (
  object_generality,      # 对象泛化度
  relation_generality,    # 关系泛化度
  operation_generality,   # 操作泛化度
  goal_generality,        # 目标泛化度
  trigger_generality,     # 触发泛化度
  evidence_generality,    # 证书泛化度
  temporal_span,          # 时间跨度
  domain_distance         # 领域距离
)
```

372号§6.3指出，峰值应改成Pareto前沿：

> Tell质量至少包含：触发准确率、操作可执行性、近迁移效用、远迁移效用、负迁移率、提示成本、泄漏风险、可组合性、模型适配性。一个Tell可能远迁移强但成本高，另一个近迁移强且极便宜。两者都可能值得保留。因此不应寻找一个全局"最优Level Hint"，而应保存当前证据下的Pareto前沿——没有另一个候选在所有重要指标上都更好。

**POC-3.5要验证的不仅是"是否有钟形曲线"，更是"钟形曲线是否足够描述真实情况，还是需要Pareto前沿"**。具体来说：

- 如果5个HintInstance的成功率呈单峰先升后降→钟形曲线假设得到支持
- 如果某些HintInstance在不同维度上各有优势（如L2近迁移强但远迁移弱、L4远迁移强但近迁移弱）→Pareto前沿假设得到支持
- 两者都可能部分成立

### 2.3 396号§4.3：TellCore/HintRenderer/HintInstance三对象分离

POC-3.5的实验设计直接基于396号§4.3的三对象分离：

```
TellCore    = 系统内部学到的可迁移认知技能
              （不变量内核 + 认知Option + 边界 + critic）
HintRenderer = 把TellCore编译成某类Solver能理解的提示的渲染器
HintInstance = TellCore针对当前题、当前脉络、当前模型、当前预算的一次实例化
```

POC-3.5的实验逻辑：**固定TellCore不变，只改变HintRenderer的渲染参数（非特化程度），观察HintInstance的AI指导力变化**。这正是三对象分离的实验价值——如果TellCore和HintInstance不分离，就无法做"同一TellCore不同Hint"的对比。

372号§7.1明确说了为什么一定要分离：

> - TellCore回答系统学到了什么；
> - HintRenderer回答怎样把这项技能讲给某类Solver；
> - HintInstance回答这一次在这个分叉上具体说了什么。
>
> 不分离会导致：改了措辞就被误认为改了Tell；一个renderer失败就否定整个思维力；无法比较同一Tell在不同模型、位置和强度下的表现。

**POC-3.5正是利用这种分离，做"同一TellCore不同渲染参数"的系统对比**——这是三对象分离的直接实验验证。

### 2.4 347号：三种提示词形态与钟形曲线是曲线族

347号发现Tell提示词有三种形态，这直接影响POC-3.5的实验设计：

**形态1：一句话指示**
- 特征：简洁、具体、直接告诉AI做什么操作
- Level位置：钟形曲线中间偏左（具体概念层）
- AI指导力：中-高（可操作，但泛化范围有限）
- 例子："用鸽巢论证找存在性元素"

**形态2：思维流程/步骤引导式**
- 特征：不是一句话，而是一段逐步引导AI思维的流程——问问题、给步骤、引导AI自己发现方向
- Level位置：钟形曲线中间偏右（高Level，但通过步骤引导恢复可操作性）
- AI指导力：中-高（虽然是高Level概念，但通过步骤引导可操作化，恢复指导力）
- 例子：逐步引导AI"你当前在什么领域打转→哪个领域可能有→怎么判断值不值得跨"

**形态3：抽象标签**
- 特征：只有一个抽象的分类标签，没有具体操作引导
- Level位置：钟形曲线右端（最高抽象）
- AI指导力：低（不可操作，AI不知道具体该怎么做）
- 例子："考虑跨域桥接"（只有标签没有步骤）

347号§2的关键修正：

> 同一Level的Tell，提示词形态不同，AI指导力不同。所以钟形曲线不是一条固定的曲线，而是一个**曲线族**——每条曲线对应一种提示词形态。

**POC-3.5的5个HintInstance正是跨越三种形态的**：Hint-L1/L2/L3是形态1（一句话指示），Hint-L4是形态2（思维流程引导式），Hint-L5是形态3（抽象标签）。这样的设计可以同时验证：
1. 非特化程度的影响（L1→L3，同一形态内部的变化）
2. 提示词形态的影响（L3→L4/L5，跨形态的变化）
3. 钟形曲线是否是曲线族（不同形态是否有不同峰值）

### 2.5 352号§3：钟形曲线作为实验假设太强

352号对345号钟形曲线做了重要的自我批判——这是POC-3.5必须在实验设计中考虑的：

> "钟形曲线"作为直觉模型有价值，但作为实验假设太强。真实情况可能出现：
> 1. **多峰曲线**——同一个trace可能在具体技巧层和高Level流程层各有一个峰
> 2. **平台型曲线**——多个相邻Level指导力差不多，差异小于实验噪声
> 3. **阈值型曲线**——低于某抽象度完全不可迁移，高于阈值突然可迁移
> 4. **任务依赖反转**——对相似题低Level峰值最高，对远迁移题高Level峰值最高
> 5. **模型依赖差异**——GLM-5.2、Claude、GPT对同一Tell族的峰值可能不同

352号的修正建议：

> 把"钟形曲线"降级为"**非单调峰值假设**"——指导力通常存在非单调性，但曲线形状需要由题族和模型共同估计。
>
> 峰值不要只按"成功率"定义，应按综合效用定义：**综合效用 = 匹配题成功率 - 不匹配题误触发率 - 提示成本 - 泄漏风险**

**POC-3.5的实验设计必须考虑这5种替代形状**——不只验证"是否呈钟形曲线"，而是记录实际数据，然后判定数据更符合哪种形状。通过标准（§7）也覆盖了这5种替代形状的情况。

### 2.6 397号§3.1：最关键缺失

397号§3.1明确指出：

> 396号的核心论断：钟形曲线绑在Hint上——同一个TellCore渲染成不同非特化程度的Hint时，AI指导力呈钟形曲线（或Pareto前沿）。
>
> 373号的覆盖：POC-3只测试"HintInstance能否让AI执行预期认知动作"，没有测试"同一个TellCore渲染成不同非特化程度的Hint（Level低/中/高）时，AI指导力是否有差异"。
>
> 为什么关键：这是396号整个理论框架的核心——用户的厘清说钟形曲线绑在Hint上，GPT的深化说峰值应改成Pareto前沿。如果POC不验证这个，整个396号的理论框架就没有实验证据。

397号§4.3将此缺失列为8项缺失中的**最关键缺失**。POC-3.5就是为了填补这个缺失而设计的。

### 2.7 不验证会留下什么gap

如果POC-3.5不被执行：

1. **396号的核心论断永远停留在理论层面**——"钟形曲线绑在Hint上"没有任何实验证据
2. **POC-3（可执行）不知道该用什么非特化程度的HintInstance**——POC-3需要知道"哪个Level的HintInstance让AI执行预期认知动作的效果最好"，但如果没有POC-3.5的数据，POC-3只能盲选一个Level
3. **Pareto前沿概念无法被验证**——396号§3说峰值应改成Pareto前沿，但如果没有实验数据，无法判断钟形曲线和Pareto前沿哪个更准确
4. **非特化策略缺乏实验指导**——未来做非特化Pipe设计时，不知道该把Hint渲染到什么非特化程度，不知道是否有"最优Level"还是应该保存多个非支配候选

| 前置POC | 状态 | 本POC需要的产出 |
|---|---|---|

### 3.2 为什么POC-2.5必须先通过

POC-3.5的前提是**Hint有基础因果效应**——POC-2.5已经确认"给HintInstance后AI比bare更可能成功（或至少更可能进入正确方向）"。

如果POC-2.5未通过（Hint无基础因果效应），那么：

- 测试5个不同非特化程度的HintInstance的差异，可能只是测试5种"都无效"的差异——信号太弱
- 如果所有Level的HintInstance都和bare一样——POC-3.5的结果是"所有Level都无差异"，但这不是因为非特化程度无差异，而是因为Hint整体无效
- 需要先回到POC-1审视TellCore或POC-0审视题包，而不是做POC-3.5

**所以POC-2.5通过是POC-3.5的硬前置条件。**

### 3.3 本POC不依赖的POC

- POC-3/4/6/7/8/9——这些POC在POC-3.5之后，本POC不依赖它们
- POC-0.5变形关系声明——本POC只用正迁移题，不用变形题
- POC-5可组合——推迟到第二个Tell家族

### 3.4 如果前置POC未完成

- 如果POC-0题包未冻结——不能做POC-3.5（没有正迁移题）
- 如果POC-1 TellCore未确定——不能做POC-3.5（没有HintInstance的来源）
- 如果POC-2 selector未验证——可人工指定用目标TellCore（同POC-2.5的处理方式）
- 如果POC-2.5未通过——**不能做POC-3.5**（基础因果效应不存在则测试程度差异无意义）

## §4 输入——这个POC需要什么

### 4.1 题包

从382号CasePack v0的22道题中取**正迁移题4道**。

正迁移题的标准（来自382号§1.2和373号§14.8，同POC-2.5）：
- 真实bare失败（有完整bare失败记录）
- 目标Tell（局部-全局表示切换）是低搜索成本主路
- 过程可观察（thinking中能看见表示切换的过程信号）
- 解答可核验（有verified solution）
- 泄漏安全（Tell只给策略不给答案）

**为什么用正迁移题而不是变形题或假朋友题**：POC-3.5验证的是"同一TellCore的不同非特化程度Hint在匹配题上的AI指导力差异"——正迁移题是目标Tell的匹配题，是最适合测试Hint非特化程度效果的题型。变形题测试的是结构保持变换下的效果，假朋友题测试的是拒绝能力——这些都不是POC-3.5的核心问题。

### 4.2 TellCore

383号确定的TellCore v0候选C（局部-全局表示切换），7字段最小充分集：

1. **invariant_claim**——不变量声明：问题的全局困难在局部表示（Z/pZ或Q_p）下可被化简
2. **trigger_boundary**——触发边界：在自然表示下反复尝试无法推进时
3. **negative_boundary**——负边界：问题本身不含整除性/周期性/符号结构时不适用
4. **parameter_slots**——参数槽：需要绑定的问题对象（原表示/局部表示的选择/不变量类型）
5. **internal_policy**——内部策略：引入局部表示→在局部表示下找结构→提升回全局
6. **progress_model**——进展模型：在局部表示下发现整除性/周期性/符号结构
7. **termination**——终止条件：局部表示下的发现已足以解决全局问题，或局部表示无隐藏结构

**关键**：POC-3.5中TellCore**固定不变**——5个HintInstance都来自同一个TellCore，只是HintRenderer的渲染参数（非特化程度）不同。这正是三对象分离（396号§4.3）的实验价值。

### 4.3 HintInstance——5个不同非特化程度

由HintRenderer把TellCore v0渲染成5个不同非特化程度的HintInstance。这是POC-3.5的核心输入，下面详细说明每一个。

#### 4.3.1 Hint-L1：极低非特化程度（题目特化）

| 属性 | 内容 |
|---|---|
| 非特化程度 | 极低 |
| 提示词形态 | 形态1（一句话指示） |
| 特征 | 包含题目特定信息（具体的模数、具体的对象），几乎等同于"告诉AI这道题怎么做" |
| 设计意图 | 模拟非特化程度最低的极端——AI拿到后知道具体做什么，但只适用于这一道题，不能迁移到其他题 |
| 泄漏风险 | 高——包含题目特定信息（如具体模数），但POC-3.5只在正迁移题（匹配题）上测试，不测试泄漏问题（那是POC-6可归责的工作） |

**Hint-L1示例**（针对排列存在性问题）：

> "对这道题，考虑用模4将排列分成两类，利用奇偶性分析元素的对换结构。"

**为什么这是"极低非特化程度"**：
- "模4"是题目特定的参数（TellCore的parameter_slots中"局部表示的选择"被绑定为Z/4Z）
- "排列分成两类"是题目特定的操作（TellCore的internal_policy被具体化为这道题的操作）
- "对换结构"是题目特定的对象（TellCore的invariant_claim被具体化为这道题的不变量）
- 这个Hint只适用于这一道排列存在性题，换一道题（如整除性问题）就不能用

**预期AI指导力**：高（在这道题上）——因为Hint-L1几乎等于告诉AI解法。但这不意味着非特化策略有效——这只是题目特化的强提示效应。POC-3.5记录这个结果作为"特化提示的上界"参照。

#### 4.3.2 Hint-L2：低-中非特化程度

| 属性 | 内容 |
|---|---|
| 非特化程度 | 低-中 |
| 提示词形态 | 形态1（一句话指示） |
| 特征 | 去掉了题目特定参数（具体模数），但保留了问题类型（排列存在性问题），操作仍然比较具体 |
| 设计意图 | 模拟非特化程度稍高——去掉了最具体的题目参数，但仍然明确指出问题类型和操作类型 |
| 泄漏风险 | 中——保留了问题类型信息，但不含题目特定参数 |

**Hint-L2示例**：

> "排列存在性问题中，考虑用模p分组，利用群结构分析排列的性质。"

**为什么这是"低-中非特化程度"**：
- "排列存在性问题"是问题类型（比Hint-L1的"这道题"更一般，但仍限定了问题类型）
- "模p"保留了参数的符号形式（不指定p=4，但仍然指定了"用模p"这一操作类型）
- "群结构分析"比"对换结构"更一般（不指定具体的不变量类型）
- 这个Hint适用于排列存在性问题类，但不能迁移到其他类型的问题（如整除性/符号结构问题）

**预期AI指导力**：中-高——去掉了题目特定参数后，AI需要自己确定p的值和分析的具体方向，但Hint仍然指明了问题类型和操作类型。

#### 4.3.3 Hint-L3：中等非特化程度（钟形曲线峰值附近）

| 属性 | 内容 |
|---|---|
| 非特化程度 | 中 |
| 提示词形态 | 形态1（一句话指示） |
| 特征 | 去掉了问题类型和具体操作，只保留了TellCore的核心认知动作——"当陷入困境时切换到局部表示"。不指定用什么局部表示，不指定在局部表示下找什么结构 |
| 设计意图 | 模拟396号§1用户描述的钟形曲线峰值附近——"非特化程度适中，AI知道该做什么操作，但适用于一类题而不是一道题" |
| 泄漏风险 | 低——不含题目特定参数，不含问题类型限定，只给认知策略 |

**Hint-L3示例**：

> "当问题在自然表示下陷入困境时，切换到局部表示Z/pZ。"

**为什么这是"中等非特化程度"**：
- "自然表示下陷入困境"是TellCore的trigger_boundary的渲染（不指定什么问题类型）
- "切换到局部表示Z/pZ"是TellCore的internal_policy的核心动作（不指定在局部表示下做什么）
- "Z/pZ"仍保留了一个具体的选择（整数模p），但比Hint-L2的"模p分组"更一般——没有指定"分组"操作
- 这个Hint适用于所有可以用局部-全局表示切换解决的题，不限于排列问题

**为什么这是"钟形曲线峰值附近"**：根据396号§1用户的描述——"非特化程度太高了，AI不知道应该如何应用；非特化程度太低了，AI只掌握一道题怎么做"——Hint-L3恰好处于中间：它给了一个明确的认知动作（切换到局部表示），但留有足够的空间让AI自己确定参数和操作。这应该是最可能产生高AI指导力的非特化程度。

**预期AI指导力**：高——这是理论预测的峰值。Hint-L3给AI一个明确的方向（切换表示），但保留了足够的灵活性让AI适配不同题目。

#### 4.3.4 Hint-L4：中-高非特化程度（思维流程引导式）

| 属性 | 内容 |
|---|---|
| 非特化程度 | 中-高 |
| 提示词形态 | 形态2（思维流程/步骤引导式） |
| 特征 | 不直接告诉AI做什么，而是一段逐步引导AI思维的流程——问问题、给步骤、引导AI自己发现"需要切换表示"这个方向。比Hint-L3更不特化（不直接说"切换到Z/pZ"），但通过步骤引导恢复可操作性 |
| 设计意图 | 模拟347号形态2——高Level概念通过思维流程引导可操作化。验证347号的论断："高Level Tell不一定是低指导力的——如果提示词是思维流程引导式而不是抽象标签，它可以通过可操作化恢复指导力" |
| 泄漏风险 | 低——不直接给认知动作，引导AI自己发现 |

**Hint-L4示例**：

```
你当前在什么表示下打转？
  → 识别当前表示的核心对象和操作
当前表示为什么走不通？
  → 列出已尝试的方向和它们失败的原因
这些方向都失败了，说明什么？
  → 当前表示可能缺少处理这个问题的结构
那哪个局部表示可能有隐藏结构？
  → 考虑Z/pZ或Q_p——哪个与问题的整数结构相关
  → 检查问题中是否有整除性、周期性或符号结构的线索
切换到这个局部表示后做什么？
  → 在局部表示下寻找不变量、周期性或符号结构
  → 将局部发现提升回全局表示
```

**为什么这是"中-高非特化程度"**：
- 不直接说"切换到Z/pZ"——而是引导AI自己发现"需要切换表示"并自己确定切换到什么
- 仍然包含"Z/pZ或Q_p"作为候选（没有完全不指定目标表示）——如果完全不指定，可能退化为形态3（抽象标签）
- 步骤引导提供了可操作性——AI不是拿到一个抽象标签不知道做什么，而是被引导逐步思考
- 这个Hint比Hint-L3更不特化（不直接给认知动作），但通过步骤引导可能恢复部分可操作性

**预期AI指导力**：中-高或高——根据347号的理论，形态2（思维流程引导式）可以让高Level概念恢复指导力。但实际效果需要实验验证——可能Hint-L4比Hint-L3更好（步骤引导比直接指示更有效），也可能更差（步骤太多增加认知负荷，352号§6指出了这个风险）。

**关键验证点**：Hint-L3 vs Hint-L4的对比直接验证347号的核心论断——"形态2（思维流程引导式）是否比形态1（一句话指示）在高Level上更有指导力"。如果Hint-L4 > Hint-L3，说明步骤引导确实恢复了高Level概念的指导力；如果Hint-L4 < Hint-L3，说明在这类Tell上，一句话指示比步骤引导更有效（可能因为局部-全局切换本身不需要步骤引导那么强的脚手架）。

#### 4.3.5 Hint-L5：极高非特化程度（抽象标签）

| 属性 | 内容 |
|---|---|
| 非特化程度 | 极高 |
| 提示词形态 | 形态3（抽象标签） |
| 特征 | 只有一个抽象的分类标签，没有具体操作引导。不指定切换到什么表示，不指定在局部表示下做什么，不给出步骤引导 |
| 设计意图 | 模拟非特化程度最高的极端——396号§1用户描述的"非特化程度太高了，AI不知道应该如何应用"。验证347号形态3的论断："抽象标签只有标签没有步骤，AI不知道具体该怎么做" |
| 泄漏风险 | 极低——不含任何操作信息 |

**Hint-L5示例**：

> "考虑表示切换。"

**为什么这是"极高非特化程度"**：
- "表示切换"是一个完全抽象的认知策略标签——不指定切换到什么表示，不指定什么时候切换，不指定切换后做什么
- 这是347号§1定义的形态3（抽象标签）——"只有一个抽象的分类标签，没有具体操作引导"
- 347号明确说形态3"不应作为Tell存储——这是分类学坐标轴的刻度名，不是Tell本身"
- 但POC-3.5需要测试它，因为它是非特化程度谱系的极端——不测L5就不知道曲线的右端是什么样的

**预期AI指导力**：低——根据347号的理论，抽象标签"AI不知道具体该怎么做"。但实际效果需要实验验证——GLM-5.2 High可能有足够的内部知识，仅凭"表示切换"这个标签就能联想到Z/pZ和具体操作。如果Hint-L5也比bare好，说明模型内部知识弥补了Hint的信息不足。

### 4.5 脉络（vein）

**POC-3.5不给脉络**。

这是一个重要的设计选择——POC-2.5测试了bare/bare+vein/bare+vein+Hint的对照，发现"vein够时Hint无因果作用"的风险。POC-3.5的目的是测试不同非特化程度Hint的差异，如果给vein，vein本身的效果可能掩盖Hint非特化程度的差异。

## §5 方法——这个POC怎么做

### 5.1 实验设计

对4道正迁移题，每道给5个HintInstance，共20个run。

每个run的输入：题目 + 1个HintInstance（无vein）。

### 5.2 对照矩阵

| 题目 | Hint-L1 | Hint-L2 | Hint-L3 | Hint-L4 | Hint-L5 |
|---|---|---|---|---|---|
| 正迁移题1 | run 1 | run 2 | run 3 | run 4 | run 5 |
| 正迁移题2 | run 6 | run 7 | run 8 | run 9 | run 10 |
| 正迁移题3 | run 11 | run 12 | run 13 | run 14 | run 15 |
| 正迁移题4 | run 16 | run 17 | run 18 | run 19 | run 20 |

共20个run。

**注意**：POC-3.5不做bare对照——bare对照是POC-2.5的工作，已经确认了4道正迁移题的bare全部失败。POC-3.5只比较5个HintInstance之间的差异。

### 5.3 每个run记录的指标

每个run记录以下指标：

**结果层指标**：
- 解题成功/失败（二元指标）
- 用时

**过程层指标**：
- 证明方法（是否用了局部-全局表示切换）
- thinking中是否出现目标认知动作（4个过程信号，同POC-2.5）：
  1. 引入新表示（AI是否引入了Z/pZ或Q_p等局部表示）
  2. 比较原表示与新表示（AI是否在局部表示下分析问题结构）
  3. 找到不变量（AI是否在局部表示下发现了整除性/周期性/符号结构）
  4. 产生可验证lemma（AI是否将局部发现提升回全局表示产生可验证的结论）
- 过程信号出现的时间点（在thinking的什么阶段出现的）

**多维度指标**（用于Pareto前沿分析）：
- 近迁移效用：在正迁移题（表面相似）上的成功率
- 操作可执行性：AI是否成功执行了Hint指示的操作（不只是"想到"而是"做到"）
- 提示成本：HintInstance的token长度
- 泄漏风险：HintInstance是否包含题目特定信息（人工评估，0-4分，352号§5的搜索空间裁剪度）

### 5.4 数据分析——画Level-AI指导力散点图

对4道正迁移题的20个run，画出Level-AI指导力散点图：

- X轴：非特化程度（L1=1, L2=2, L3=3, L4=4, L5=5）
- Y轴：AI指导力（可用多个指标作为Y轴，分别画图）：
  - 成功率（4道题中成功几道）
  - 过程信号出现率（4道题中目标认知动作出现几道）
  - 综合效用（成功率 - 提示成本 - 泄漏风险，352号§3的定义）

### 5.5 曲线形状判定

根据散点图的数据，判定实际曲线更符合哪种形状：

**形状1：钟形曲线（单峰先升后降）**
- 判定条件：AI指导力随非特化程度先升后降，存在一个明显的峰值区间
- 数据特征：某个Level的AI指导力显著高于两端，且两侧递减
- 理论对应：396号§1用户的钟形曲线假设

**形状2：Pareto前沿（多轴非支配集）**
- 判定条件：不同Level的HintInstance在不同维度上各有优势，没有单一"最优"
- 数据特征：如L2近迁移效用高但操作可执行性低，L4远迁移效用高但提示成本高
- 理论对应：396号§3 GPT的Pareto前沿假设

**形状3：多峰曲线**
- 判定条件：AI指导力随非特化程度有多个局部峰值
- 数据特征：如L2有一个峰、L4有另一个峰，L3反而低
- 理论对应：352号§3的多峰曲线假设

**形状4：平台型曲线**
- 判定条件：多个相邻Level的AI指导力差不多，差异小于实验噪声
- 数据特征：L2/L3/L4的成功率都在75%左右，差异不显著
- 理论对应：352号§3的平台型曲线假设

**形状5：阈值型曲线**
- 判定条件：低于某非特化程度完全不可迁移，高于阈值突然可迁移
- 数据特征：L1/L2/L3都失败，L4/L5突然成功（或反过来）
- 理论对应：352号§3的阈值型曲线假设

**形状6：单调型（无峰值）**
- 判定条件：AI指导力随非特化程度单调上升或单调下降
- 数据特征：L1最好，L5最差（或反过来）
- 理论含义：非特化程度在一个方向上越多越好（或越少越好），没有钟形曲线

**形状7：无差异（所有Level都一样）**
- 判定条件：5个Level的AI指导力没有显著差异
- 数据特征：L1-L5的成功率都在50%左右
- 理论含义：非特化程度对AI指导力没有影响——这与396号的核心论断矛盾

### 5.6 操作步骤

1. 确认POC-2.5已通过（基础因果效应存在）——如果未通过，不能开始POC-3.5
2. 从382号CasePack v0取4道正迁移题（与POC-2.5相同的4道题，以便对照）
3. 从383号TellCore v0用HintRenderer渲染5个HintInstance（L1-L5，具体内容见§4.3）
4. 对每道正迁移题，通过solver_harness启动5个run（每run给1个HintInstance，无vein）
5. 记录每个run的解题成功/失败/用时/证明方法/thinking过程信号/多维度指标
6. 汇总20个run的数据，画出Level-AI指导力散点图
7. 按§5.5的判定逻辑判定曲线形状
8. 如果出现Pareto前沿特征，做多维度Pareto分析
9. 产出EvidenceRecord和散点图

### 5.7 与POC-2.5的关键差异

| | POC-2.5 基础因果效应验证 | POC-3.5 Hint非特化程度验证 |
|---|---|---|
| HintInstance数量 | 1个（中等非特化程度） | 5个（L1极低→L5极高） |
| 对照方式 | Hint vs bare（有/无） | Hint L1 vs L2 vs L3 vs L4 vs L5（多/少/优/劣） |
| 脉络 | 给vein（测试vein和Hint的贡献） | 不给vein（避免vein掩盖Hint差异） |
| 总run数 | 12-16个（4题×3-4条件） | 20个（4题×5个Hint） |
| 核心问题 | Hint有没有用？ | 哪个非特化程度的Hint最好？曲线什么形状？ |

### 5.8 小样本注意事项

POC-3.5的20个run是小样本——4道题×5个Level，每个Level只有4个数据点。这意味着：

1. **不能做严格的统计显著性检验**——4个数据点不足以达到统计显著性
2. **结果应作为探索性证据**——观察趋势和模式，而非确认性结论
3. **如果差异明显**（如L3成功率4/4，L5成功率0/4）——趋势清晰，可以给出初步判定
4. **如果差异不明显**（如所有Level成功率都在2/4左右）——可能需要扩大样本（增加到8-12道正迁移题）才能区分平台型和无差异
5. **小样本结果明确标注为"初步证据"**——不升级为"钟形曲线已验证"的结论

## §7 通过标准

### 7.1 通过标准（POC-3.5通过的最低条件）

**POC-3.5通过，需要满足以下条件之一**：

**条件A：AI指导力随非特化程度有非单调性**

不是所有Level的AI指导力都一样——至少存在一个Level显著好于另一个Level。具体来说：

- 5个Level的成功率不全相同（至少有一个Level的成功率比其他Level高或低至少1道题）
- 或5个Level的过程信号出现率不全相同（至少有一个Level的目标认知动作出现率比其他Level高或低至少1道题）

**条件B：至少存在一个峰值区间**

某些Level的HintInstance显著好于其他Level。具体来说：

- 至少有一个Level的成功率≥3/4，且至少有一个其他Level的成功率≤2/4
- 或至少有一个Level的过程信号出现率≥3/4，且至少有一个其他Level的过程信号出现率≤2/4

**条件C（替代A/B）：Pareto前沿特征**

如果成功率差异不明显，但多维度指标显示不同Level在不同维度上各有优势——如L2近迁移效用高但操作可执行性低，L4远迁移效用高但提示成本高——也通过。具体来说：

- 至少在2个维度上，不同Level的排名不一致（如L2在维度1最好但在维度2不是最好）
- 存在非支配集（至少有2个Level互不被对方在所有维度上支配）

### 7.2 为什么通过标准包含多种曲线形状

396号说钟形曲线，396号§3说Pareto前沿，352号§3说可能是多峰/平台/阈值——POC-3.5的通过标准不预设哪种形状是"正确"的，而是要求**AI指导力与非特化程度之间存在某种系统性关系**。

- 如果呈钟形曲线→条件A/B满足→通过
- 如果呈Pareto前沿→条件C满足→通过
- 如果呈多峰→条件A满足（有非单调性）→通过
- 如果呈平台→可能不满足条件A（多个Level一样好）→需要分析
- 如果呈阈值→条件A满足（有非单调性）→通过
- 如果单调→条件A满足（有差异）→通过
- 如果无差异→不满足任何条件→不通过

### 7.3 不通过的处理

**如果POC-3.5不通过（所有Level无显著差异）**：

停下来分析原因：

1. **样本太小？**——4道题×5个Level可能不足以检测差异。考虑扩大到8-12道正迁移题重做
2. **Hint设计有问题？**——5个HintInstance的非特化程度区分可能不够明显。重新审视Hint-L1到Hint-L5的内容，确认它们确实代表了不同的非特化程度
3. **Hint整体无效？**——如果POC-2.5的bare+Hint组本来就成功率很低（如只有1/4），那么不同非特化程度的差异可能在噪声中不可见。需要回到POC-2.5分析原因
4. **非特化程度真的不影响AI指导力？**——这是最需要认真对待的可能性。如果GLM-5.2 High足够强，任何Level的Hint（只要包含"表示切换"这个核心信息）都能让它做出来——那么396号的核心论断"非特化程度影响AI指导力"就需要修正

### 7.4 通过后的不同曲线形状对后续POC的指导

**如果呈钟形曲线（峰值在L3）**：
- POC-3（可执行）应使用L3或L3附近的HintInstance
- 非特化策略的目标是把Hint渲染到钟形曲线峰值附近
- 396号§1的钟形曲线假设得到实验支持

**如果呈Pareto前沿**：
- POC-3（可执行）应保存多个非支配的HintInstance
- 非特化策略不应追求单一最优Level，而应保存Pareto前沿
- 396号§3的Pareto前沿假设得到实验支持

**如果呈多峰**：
- 分析为什么有多个峰——可能是不同类型的题目偏好不同的非特化程度
- 352号§3的多峰假设得到实验支持
- POC-3可能需要按题目类型选择不同Level的Hint

**如果呈平台**：
- L2-L4效果差不多——说明在中等非特化程度区间内，精确Level不重要
- 352号§3的平台假设得到实验支持
- POC-3可以用平台区间内任何一个Level的Hint

**如果呈阈值**：
- 存在一个非特化程度阈值——低于阈值完全不可迁移，高于阈值可迁移
- 352号§3的阈值假设得到实验支持
- POC-3应使用高于阈值的HintInstance

**如果单调（L1最好或L5最好）**：
- 如果L1最好——非特化程度越低越好，但这是题目特化提示，不是非特化策略的胜利
- 如果L5最好——非特化程度越高越好，但需要确认这不是因为GLM-5.2 High内部知识足够强
- 需要重新审视非特化理论

### 7.5 通过不意味着"钟形曲线已验证"

**重要**：POC-3.5通过只说明AI指导力与非特化程度之间存在系统性关系——不意味着"钟形曲线假设已被验证"。具体曲线形状需要由数据判定（§5.5），且小样本结果应标注为"初步证据"。

POC-3.5通过后：
- 如果曲线形状是钟形曲线→396号§1的假设得到初步支持
- 如果曲线形状是Pareto前沿→396号§3的假设得到初步支持
- 如果曲线形状是352号的替代形状→352号§3的批判得到验证
- 无论哪种形状，都需要更大规模的实验确认

## §9 执行约束

### 9.1 Solver启动

数学Solver必须通过`xishujuzhen/solver_harness/solver_harness.py launch`启动，不能手动tmux、nohup或绕过harness。

### 9.2 ArangoDB

启动任何连接ArangoDB的脚本前，必须确认`echo $ARANGO_DB`输出`xishujuzhen_math_glm52`。

### 9.3 Git

- Git add必须显式路径，不能`git add -A`或`git add .`
- 产物文件（poc_3_5_result.yaml / poc_3_5_scatter_plot.png / poc_3_5_analysis.md / 每个run的导出）必须commit

### 9.4 POC运行记录

POC运行记录必须保留thinking、trajectory、proof或TUI导出。通过solver_harness自动保存。

### 9.5 证据分层

POC结论必须写成证据分层——不把"AI指导力有非单调性"升级成"钟形曲线已验证"。具体曲线形状由数据判定，小样本结果标注为"初步证据"。

### 9.6 5个HintInstance的非特化程度必须可区分

5个HintInstance（L1-L5）的非特化程度必须有明确的区分度——不能出现L2和L3实际上非特化程度差不多的情况。在实验开始前，应让独立审查者确认5个HintInstance确实代表了5个不同的非特化程度，且区分度足够明显。

### 9.7 Hint-L1的泄漏风险声明

Hint-L1（极低非特化程度）包含题目特定信息，泄漏风险高。这是**有意为之**的——L1是非特化程度谱系的极端，不包含题目特定信息就无法达到"极低非特化程度"。但必须在EvidenceRecord中明确记录：

- Hint-L1的泄漏风险为4（高），不作为可迁移的HintInstance入库
- Hint-L1的结果只用于标定"特化提示的上界"——如果L1成功率高，这是因为提示太强（接近告诉答案），不是因为非特化策略有效
- POC-3.5的核心关注点是L2-L5的差异，L1作为参照上界

### 9.8 失败不是废结果

如果POC-3.5不通过（所有Level无显著差异），这不是废结果——这可能是重要发现。可能揭示了：
- GLM-5.2 High足够强，任何包含核心信息的Hint都能让它做出来——非特化程度对强模型不重要
- 非特化程度的影响需要更大样本才能检测——4道题不足以区分
- 396号的核心论断需要修正——非特化程度可能不是影响AI指导力的主要因素

不通过的结果必须完整记录，并触发对396号理论框架的审视。

## §10 与其他POC的关系

### 10.1 前置关系

```
POC-0（题包冻结）→ POC-1（TellCore确定）→ POC-2（selector验证）→ POC-2.5（基础因果效应）→ ★ POC-3.5（Hint非特化程度验证）★
```

POC-3.5依赖：
- POC-0的题包（4道正迁移题）
- POC-1的TellCore（7字段最小充分集）
- **POC-2.5必须通过**（基础因果效应存在才测试程度差异）

如果POC-2未完成，可人工指定用目标TellCore（同POC-2.5的处理方式）。

### 10.2 后续关系

```
★ POC-3.5（Hint非特化程度验证）★ → POC-3（可执行）→ POC-4（可终止）→ POC-6（可归责）
```

**POC-3.5的结果直接指导POC-3用什么非特化程度的HintInstance**：

- 如果POC-3.5显示钟形曲线峰值在L3→POC-3用L3的HintInstance测试可执行性
- 如果POC-3.5显示Pareto前沿→POC-3用Pareto非支配集中的HintInstance测试可执行性
- 如果POC-3.5显示平台→POC-3用平台区间内的任何一个HintInstance
- 如果POC-3.5显示无差异→POC-3可任选一个Level的HintInstance，但要记录"非特化程度无显著差异"

**POC-3.5通过后才能做POC-6（可归责）**——POC-6的干预矩阵（bare/通用鼓励/等长空流程/等强度错配Tell/method only/full Tell）需要一个明确的"full Tell"的HintInstance。POC-3.5的结果帮助确定"full Tell"应该用什么非特化程度。

### 10.3 并行关系

POC-3.5与POC-9（识别端验证）可以并行——POC-3.5是注入端的验证，POC-9是识别端的验证，两者不互相依赖。

### 10.4 如果POC-3.5不通过

- **不通过不阻塞POC-9（识别端验证）**——识别端从失败trace读分叉，不依赖Hint非特化程度
- **不通过不阻塞POC-2.5已确认的基础因果效应**——POC-2.5已经确认Hint有基础因果效应，POC-3.5不通过只说明"不同非特化程度之间无差异"，不否定"Hint比bare更好"
- **不通过可能阻塞POC-3（可执行）的精确设计**——如果不知道哪个非特化程度最好，POC-3只能任选一个Level，但POC-3仍然可以进行（只是不知道选的Level是否最优）
- **不通过触发对396号理论框架的审视**——如果非特化程度对AI指导力没有影响，396号§1"钟形曲线绑在Hint上"的核心论断需要修正
- **不通过可能需要扩大样本**——4道题×5个Level可能不足以检测差异，考虑扩大到8-12道正迁移题重做
