## §1 问题背景

### 1.1 POC-2.5发现的问题

在POC-2.5执行中，16个run用`devin -p --prompt-file ... --export ...`运行竞赛数学题。13个run的export显示：

- 只有1个agent step
- reasoning_content有46-73K字符（thinking）
- message=0（没有最终输出）
- tool_calls=0（没有工具调用）
- metrics显示`completion_tokens: 25000`

**根因**：glm-5-2的单次API调用completion_tokens上限是25000。竞赛数学题需要大量thinking（46-73K字符≈12-18K tokens），AI在thinking spin中耗尽25000 token，还没进入working阶段（输出content/tool_calls）就被截断。

### 1.2 关键概念

- **thinking spin**：模型开启thinking功能后，在thinking spin中输出的内容。thinking spin中模型不调用工具。
- **working**：thinking spin结束后，模型输出的content/tool_calls。这才是实际的工作产出。
- **completion_tokens**：单次API调用的总输出token上限（thinking + content + tool_calls都算在内）。
- **非交互模式支持多轮工具调用**：`-p`模式是"处理完prompt后自动退出"，不是"只做一轮"。AI可以thinking → tool call → observation → thinking → ... → 最终输出 → 退出。3个没有export的run实际上进行了多轮工具调用（写了Python脚本）。

### 1.3 为什么需要续传机制

竞赛数学题的thinking spin可能需要超过25000 tokens。当thinking spin被截断时：
- AI没有输出message（没有最终答案）
- AI没有调用tool_calls（没有工具调用）
- AI的thinking在中间断掉（reasoning_content不完整）

**续传机制**：把AI之前完成的thinking作为新prompt的上下文注入，让AI在新的API调用中继续思考。每轮25000 token的thinking可以推进一部分，多轮累积完成。

## §2 续传机制设计

### 2.1 基本流程

```
Round 1:
  prompt = 题目 + vein + hint（原始prompt）
  devin -p --prompt-file round1.txt --export round1.json
  → 检测round1.json：reasoning_content被截断？message=0？tool_calls=0？

Round 2（如果Round 1被截断）:
  prompt = 题目 + "你之前已经思考了以下内容：" + round1的reasoning_content + "请继续思考并完成解答。"
  devin -p --prompt-file round2.txt --export round2.json
  → 检测round2.json：是否完成？还是再次被截断？

Round N（重复直到完成或达到最大轮次）:
  prompt = 题目 + "你之前已经思考了以下内容：" + 所有前序轮次的reasoning_content + "请继续思考并完成解答。"
  devin -p --prompt-file roundN.txt --export roundN.json
```

### 2.2 截断检测

```python
def is_truncated(export_path):
    """检测export是否被completion_tokens截断。"""
    with open(export_path) as f:
        data = json.load(f)
    agent_steps = [s for s in data.get('steps', []) if s.get('source') == 'agent']
    if not agent_steps:
        return False  # 没有agent step，可能是其他错误
    last_agent = agent_steps[-1]
    rc = last_agent.get('reasoning_content', '')
    msg = last_agent.get('message', '')
    tc = last_agent.get('tool_calls', [])
    metrics = last_agent.get('metrics', {})
    completion_tokens = metrics.get('completion_tokens', 0)
    
    # 截断判定：有thinking但没有working产出，且completion_tokens接近25000
    return len(rc) > 1000 and len(msg) == 0 and len(tc) == 0 and completion_tokens >= 24000
```

### 2.3 续传prompt构造

```python
def build_continue_prompt(original_problem, previous_reasoning, round_num):
    """构造续传prompt。"""
    return f"""{original_problem}

=== 你之前的思考过程（Round {round_num - 1}）===

你已经在上一轮中开始了这道题的思考。以下是你之前的思考过程，请在此基础上继续思考并完成解答：

{previous_reasoning}

=== 请继续思考并完成解答 ===

要求：
1. 给出完整的解答过程
2. 最终答案用 \\boxed{{答案}} 格式给出
3. 数学公式用LaTeX
4. 把证明写到proof.md文件中，不要在对话里输出完整证明
"""
```

### 2.4 关键设计决策

1. **只传reasoning_content，不传tool_calls/observation**：续传prompt中只包含之前的thinking，不包含工具调用结果。因为被截断的run没有tool_calls（AI在thinking中被截断，没进入working阶段）。

2. **续传prompt的token预算**：之前的reasoning_content是46-73K字符≈12-18K tokens。作为input传入新轮次，不算completion_tokens。新轮次的25000 completion_tokens全部用于新的thinking + working。

3. **最大轮次**：建议3-5轮。如果5轮后仍未完成，说明题目对AI来说太难，不是续传机制的问题。

4. **多轮tool call的run**：3个没有export但有多轮tool call的run（CC-103-bare/CC-104-bare/CC-105-vein）说明AI有时能在第一轮thinking中控制长度，进入working阶段。续传机制主要解决的是thinking被截断的情况。

## §3 验证方案

### 3.1 验证目标

续传机制能让AI完成竞赛数学题——即多轮累积thinking后，AI输出最终答案（message非空）或调用工具完成验证（tool_calls非空）。

### 3.2 验证步骤

1. **单题测试**：选1道POC-2.5中被截断的题（如CC-101-bare），用续传机制运行3轮，检查是否完成
2. **对比测试**：选1道POC-2.5中成功多轮tool call的题（如CC-103-bare），不用续传直接运行，检查是否完成
3. **批量测试**：如果单题测试成功，对POC-2.5的16个run全部用续传机制重新运行

### 3.3 通过标准

- 续传机制运行后，AI输出最终答案（message非空）或完成工具调用验证（tool_calls非空 + 有PROOF COMPLETE）
- 至少8/16个run完成（50%以上）

### 3.4 不通过的处理

如果续传机制也不行：
- 可能是题目对AI来说太难（不是thinking长度问题，是能力问题）
- 可能需要换用`glm-5-2-max`（Max推理，可能有更高的completion_tokens限制）
- 可能需要换用交互模式（不带`-p`，让AI自己控制thinking长度）
