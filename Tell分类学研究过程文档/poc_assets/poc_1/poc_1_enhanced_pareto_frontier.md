### §2.3 维度1：触发准确率——详析

**评分方法**：用CasePack v1的4道假朋友题（CC-201~204）测试trigger/negative_boundary的触发与拒绝能力。

**候选A（0分）**：无negative_boundary。trigger_boundary的"整除性/素性/符号/周期性"条件过宽——4道假朋友题全部有表面特征匹配trigger：
- CC-201（megaprime计数）：表面有prime/divisibility → trigger会误触发
- CC-202（被3整除着色）：表面有mod 3 → trigger会误触发
- CC-203（部分和mod d鸽巢）：表面有mod d → trigger会误触发
- CC-204（集合A+B mod N²）：表面有mod → trigger会误触发
无任何拒绝机制 → **经常误触发 = 0分**

**候选B（1分）**：有trigger_boundary + negative_boundary。383号§4.7分析（映射到v1的假朋友题）：
- CC-202（被3整除着色）：negative_boundary"已在局部表示下"拒绝 → 正确拒绝
- CC-204（概率方法）：negative_boundary"分析估计而非代数结构"拒绝 → 正确拒绝
- CC-201（megaprime容斥）：trigger会触发（涉及prime），negative_boundary"构造性而非分析性"不完全匹配（容斥不是严格"构造性"）→ 可能误触发
- CC-203（鸽巢+子集计数）：trigger会触发（涉及mod d），negative_boundary无法精确拒绝（鸽巢不是"构造性/几何/分析估计"的任一类）→ 可能误触发
2/4正确拒绝，2/4可能误触发 → **偶尔误触发 = 1分**

**候选C（2分）**：有trigger_boundary + negative_boundary + critic。critic的4个自检问题可以拦截B无法拒绝的假朋友：
- CC-201：critic"局部发现是否真正对应原问题的目标？"——容斥不是局部表示下的隐藏结构 → 拦截
- CC-203：critic"局部发现是否真正对应原问题的目标？"——鸽巢计数不是表示切换揭示的隐藏结构 → 拦截
4/4可拒绝（2/4靠negative_boundary，2/4靠critic安全网） → **精确触发/拒绝 = 2分**

### §2.4 维度2：操作可执行性——详析

**评分方法**：用383号§4.4的验证方法——internal_policy是否是操作路径而非口号，用1962的操作路径验证。

**候选A（1分）**：有internal_policy（step2-5）但无binding_rules。AI知道大致方向（"切换到局部表示"），但具体选哪个p、选模p还是p-adic需要自己猜。383号§4.3发现"p的绑定需要binding_rules辅助"——CC-009需要分析底数3的剩余理论来确定模数，CC-010需要识别n=2022不是4的倍数来调整模数。无binding_rules时AI可能选错p或选错level。 → **AI知道大致方向 = 1分**

**候选B（1分）**：同候选A——有internal_policy但无binding_rules。7字段最小充分集不含binding_rules（383号将binding_rules归为"重要补充"）。操作路径存在但参数绑定准确性不足。 → **AI知道大致方向 = 1分**

**候选C（2分）**：有internal_policy + binding_rules。binding_rules显式给出：
- 整除性/符号/周期性 → 模p（层次1）
- "是p的幂"/"被p^k整除" → p-adic赋值（层次2）
- 多模数 → CRT组合
AI知道具体步骤：选什么p、选什么level、找什么结构。 → **AI知道具体步骤 = 2分**

### §2.5 维度3：近迁移效用——详析

**评分方法**：用CasePack v1的6道正迁移题（CC-101~106）和4道变形题（CC-009~012）测试同类型题的预期效用。

**候选A（1分）**：trigger会触发正迁移题（表面特征匹配），internal_policy给出操作方向。但无negative_boundary意味着trigger也可能在不应触发的题上触发，selector的置信度降低。无binding_rules意味着p绑定可能出错（如CC-101需要3-adic而非2-adic，CC-103需要mod 2+mod 3组合）。 → **同类型题部分有效 = 1分**

**候选B（1分）**：trigger+negative_boundary让selector更精确地选择正迁移题。但无binding_rules，p绑定仍可能出错。383号§4.3发现CC-009/010的p绑定不是机械的——需要分析具体问题结构。 → **同类型题部分有效 = 1分**

**候选C（2分）**：binding_rules让p绑定准确（整除性→模p，幂→p-adic，多模数→CRT）。CC-101（3-adic赋值）→binding_rules正确选择v_3。CC-103（mod 2+mod 3 CRT）→binding_rules选择CRT组合。 → **同类型题有效 = 2分**

### §2.6 维度4：远迁移效用——详析

**评分方法**：用变形关系声明表的A4（领域迁移）和A3（对象换壳）测试跨域场景。注意：A3/A4是gap（无题目验证），评分基于结构推断。

**候选A（1分）**：trigger_boundary的"整除性/素性/符号/周期性"不限于数论——理论上可覆盖组合/代数领域的类似结构。但无negative_boundary和binding_rules，跨域绑定的准确性更不确定。 → **不同类型题部分有效 = 1分**

**候选B（1分）**：同A——trigger_boundary覆盖跨域，但binding_rules的绑定规则是数论特定的（"整除性→模p，幂→p-adic"），跨域时需要AI自己类比。 → **不同类型题部分有效 = 1分**

**候选C（1分）**：binding_rules虽然更详细，但规则本身是数论特定的。跨域（如组合→代数）时binding_rules无法直接套用，需要AI自己泛化。A3/A4是gap无题目验证。 → **不同类型题部分有效 = 1分**

### §2.7 维度5：负迁移率（越低越好）——详析

**评分方法**：用4道假朋友题（CC-201~204）测试误触发后的误导程度。

**候选A（0分）**：无negative_boundary，4道假朋友题全部会误触发。误触发后AI会尝试局部表示切换，但假朋友题的核心不在表示切换——AI会浪费时间在错误方向上。 → **经常误导 = 0分**

**候选B（1分）**：有negative_boundary，2/4假朋友题被正确拒绝（CC-202, CC-204）。CC-201/203可能误触发，但negative_boundary的存在让selector有拒绝能力。 → **偶尔误导 = 1分**

**候选C（2分）**：negative_boundary + critic双重防线。2/4靠negative_boundary拒绝，2/4靠critic拦截。即使误触发，critic的自检"局部发现是否真正对应原问题的目标？"会让AI意识到方向错误并退出。 → **从不误导 = 2分**

### §2.8 维度6：提示成本（越低越好）——详析

**评分方法**：估算渲染成HintInstance后的字段数量和认知负载。

**候选A（1分）**：6字段（7字段 - negative_boundary）。字段数量与B差异极小（仅少1个字段），认知负载基本相同。 → **中等长度 = 1分**

**候选B（1分）**：7字段。invariant_claim + trigger_boundary + negative_boundary + parameter_slots + internal_policy + progress_model + termination。每个字段内容中等长度。 → **中等长度 = 1分**

**候选C（0分）**：9字段（7字段 + binding_rules + critic）。binding_rules包含3条选择规则，critic包含4个自检问题+4种失败模式诊断。总内容量显著大于A/B。 → **很长很复杂 = 0分**

### §2.9 维度7：泄漏风险（越低越好）——详析

**评分方法**：用383号§5的信息泄漏审查方法——是否包含具体lemma/题目特定信息。

**候选A（2分）**：383号§5.1审查确认运行时字段无具体lemma（Euler准则/Fermat小定理/v_2性质等均不在TellCore中）。删除negative_boundary不增加泄漏。 → **低泄漏 = 2分**

**候选B（2分）**：同A——383号确认7字段最小充分集无具体lemma泄漏。 → **低泄漏 = 2分**

**候选C（2分）**：binding_rules只说"整除性→模p，幂→p-adic"——是策略规则不是具体lemma。critic只说"p是否匹配、发现是否对应"——是自检方向不是具体数学内容。无具体lemma泄漏。 → **低泄漏 = 2分**

### §2.10 维度8：可持续学习——详析

**评分方法**：评估从失败中学习的能力——能否诊断失败原因并修复TellCore。

**候选A（0分）**：无critic。当TellCore执行失败时，无自检机制来诊断是哪一步出了问题。无法区分"trigger误触发"、"p绑定错误"、"操作路径不足"等不同失败模式。 → **无法从反例学习 = 0分**

**候选B（0分）**：同A——7字段最小充分集不含critic。383号将critic归为"重要补充"而非"必要"，但在可持续学习维度上critic是关键。 → **无法从反例学习 = 0分**

**候选C（2分）**：有critic，包含4个自检问题 + 4种失败模式诊断：
- 误触发 → 诊断：检查negative_boundary是否被忽略 → 修复：加强trigger条件
- 绑定错误 → 诊断：检查binding_rules → 修复：调整选择逻辑
- 执行但无进展 → 诊断：检查local_representation选择 → 修复：尝试其他表示
- 局部成功但全局失败 → 诊断：检查提升步骤 → 修复：增加提升步骤
可精确诊断失败模式并给出修复方向。 → **可精确诊断+修复 = 2分**

## §5 分析结论

### §5.1 Pareto前沿上的候选

**Pareto前沿 = {候选B（baseline），候选C（扩展版）}**

1. **候选B（baseline=383号7字段最小充分集）**在前沿上，因为它在**提示成本**维度上不被C支配（B=1 > C=0）。B是"低成本方案"——7字段足够通过383号的7项结构标准，但在操作可执行性和可持续学习上有局限。

2. **候选C（扩展版=7字段+binding_rules+critic）**在前沿上，因为它在**触发准确率、操作可执行性、近迁移效用、负迁移率、可持续学习**5个维度上不被B支配（C>B）。C是"高质量方案"——binding_rules让参数绑定准确，critic让失败可诊断可修复，但提示成本更高。

3. **候选A（精简版=7字段-negative_boundary）**不在前沿上，被B支配。删除negative_boundary只减少了1个字段（提示成本从1到1，无显著改善），但失去了假朋友拒绝能力（触发准确率从1到0，负迁移率从1到0）。**negative_boundary的删除是纯损失——成本未降但质量显著下降。**

### §5.2 关键发现

1. **negative_boundary是必要的**——候选A（删除negative_boundary）被B支配，说明negative_boundary在Pareto前沿上贡献了"触发准确率"和"负迁移率"两个维度，而删除它几乎不降低提示成本。383号将negative_boundary纳入7字段最小充分集是正确的。

2. **binding_rules+critic是Pareto前沿上的增量价值**——候选C在5个维度上优于B，仅在提示成本上劣于B。这说明binding_rules+critic不是"冗余字段"——它们在操作可执行性、触发准确率、近迁移效用、负迁移率、可持续学习上都有增量贡献。383号将它们归为"重要补充"而非"必要"是准确的——它们不是通过7项结构标准的必要条件，但在Pareto前沿上提供了显著的质量提升。

3. **提示成本是B vs C的核心trade-off**——B和C互不支配的唯一原因是提示成本。如果提示成本不是关键约束（如有足够token预算），C严格优于B在5个维度上。如果提示成本是关键约束（如token受限场景），B是更经济的选择。

4. **远迁移效用是所有候选的弱项**——3个候选在远迁移效用上都只有1分。这是因为变形关系声明表的A3（对象换壳）和A4（领域迁移）是gap（无题目验证），binding_rules的绑定规则是数论特定的，跨域泛化能力有限。这是未来题包扩展需要补强的维度。

5. **可持续学习是B的弱项**——B在可持续学习上得0分（无critic）。这意味着如果用B作为生产TellCore，失败时无法诊断原因。C的critic提供了4种失败模式诊断+修复方向，是可持续学习的关键。

### §5.3 对后续POC的建议

1. **POC-2（selector测试）**：建议用候选B作为baseline测试trigger/negative_boundary的区分能力。如果selector的假朋友拒绝率不足，考虑升级到候选C（用critic做安全网）。

2. **POC-3（可执行验证）**：建议用候选C测试internal_policy的操作路径充分性。binding_rules让AI知道具体步骤（选什么p、选什么level），是操作路径可执行性的关键。特别是1962——binding_rules的"幂→p-adic赋值"规则可以直接引导AI选择v_2分析。

3. **POC-3.5（Hint非特化程度验证）**：用Pareto前沿上的B和C分别渲染不同非特化程度的HintInstance，验证钟形曲线/Pareto前沿。B代表"中度非特化"（7字段），C代表"高度非特化"（9字段含绑定规则和自检）。

4. **POC-7（可持续学习）**：必须用候选C——只有C有critic，能从失败中诊断和修复。B和A在可持续学习维度上都是0分。

5. **远迁移效用补强**：未来题包扩展应补充A3（对象换壳）和A4（领域迁移）的变形题，验证TellCore的跨域泛化能力。

## §7 评分局限性

1. **结构分析非经验验证**——所有评分基于结构分析（字段内容审查+CasePack v1题目对照），不基于Solver运行时数据。经验验证需要POC-2~POC-8。

2. **远迁移效用评分受gap限制**——A3/A4是gap无题目验证，远迁移效用评分（3个候选都是1分）基于结构推断，不确定性较高。

3. **假朋友拒绝评分基于383号分析**——383号对假朋友题的分析是结构性的（trigger/negative_boundary/critic的字段内容对照），不是运行时selector的实际触发结果。实际触发率需要POC-2验证。

4. **提示成本评分是定性估算**——未实际渲染HintInstance计算token长度，仅按字段数量和内容复杂度定性估算。

5. **0-2分制的粒度限制**——0-2分制比1-5分制粒度更粗，某些维度的细微差异可能被掩盖。但0-2分制更适合结构分析（无经验数据时精细评分无意义）。
