## §3 候选TellCore v0.2草案（三条新候选，源自独立提取的共同策略）

每条附：不变量宣称 / 触发 / 内部策略要点 / 进展信号 / 来源锚点（R4 thinking行号区间，见独立提取.md）。

### v0.2-候选Ⅰ：实例检验纪律（Instance-Check Discipline）

- **invariant_claim**：任何推导出的公式/结论，其可信度必须由至少一个已验证具体实例的计算来背书；"感觉不对"和"过于顺利"都触发同一动作——代入实例。
- **trigger**：公式首次导出时；结论"太好/太坏/太顺利"时；两个来源不一致时。
- **policy要点**：①选已知解作试金石 → ②代入中间产物逐项核对 → ③不一致时定位到具体步 → ④修复后在同一实例复验 → ⑤为公式标注适用域标签。
- **progress signal**：实例通过；隐藏适用域被发现并被标注。
- **termination**：公式带标签进入台账，或被证伪并记录死因。
- **锚点**：动作7（L139-235区）、动作11（假矛盾验尸）、动作17（丢因子自检）。
- **预期优势维度**：触发准确率、负迁移率、可持续学习（自带诊断修复闭环）。

### v0.2-候选Ⅱ：荒谬即警报的错误定位协议（Absurdity-as-Alert）

- **invariant_claim**：荒谬结论是定位错误的线索而非宣布失败的战果；接受一个"有利"的假矛盾会永久丢失真解。
- **trigger**：推导即将得出强否定结论（"情形不存在"/"无解"）时强制触发。
- **policy要点**：①找一个已验证实例测中间产物 → ②定位到具体某一步 → ③修复 → ④同一实例复验 → ⑤追问"谁依赖这条链"做传染审计。
- **progress signal**：错误被定位到步；传染范围清零。
- **锚点**：动作11、17、21（错误依赖审计）。
- **预期优势维度**：负迁移率、可持续学习、近迁移效用。

### v0.2-候选Ⅲ：信号驱动的工具升级阶梯（Signal-Driven Tool Ladder）

- **invariant_claim**：每类工具有各自的失效信号（"无信息"/"平凡"/"循环"/"太强"）；给信号命名并尊重其判决，沿阶梯逐级换保信息的更强工具，而不是在同一工具上加大尝试次数。
- **trigger**：当前工具输出零约束/平凡/循环结果时。
- **policy要点**：①识别失效信号类型 → ②按阶梯选择信息保真度更高的下一级工具（同余→赋值读数→精确方程→比值结构→整除性→夹逼）→ ③关系数超5条时外化为命名台账 → ④新工具扫过所有对称位置扩大战果。
- **progress signal**：新工具产出第一个非平凡约束。
- **termination**：阶梯顶端仍无进展 ⟹ 该情形确认为硬骨头，转专职攻坚。
- **锚点**：动作3、9、10、12、15、16（贯穿阶段1-5）。
- **预期优势维度**：操作可执行性、近迁移效用、提示成本。
