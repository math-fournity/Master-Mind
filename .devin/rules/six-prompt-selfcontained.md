# 提示词自包含原则

## 触发条件

创建或修订第六代系统提示词文件时（pipe_1_parser/step_2_grid_vein等目录下的v*.md文件）。

## 核心原则

**每个提示词文件必须自包含——提示词中用到的所有术语必须在提示词内部有定义，不允许引用外部文档来定义术语。**

这是328号POC方案自包含标准向提示词的延伸——328号要求POC方案自包含，本rule要求提示词也自包含。

## 具体规则

### 1. 术语表是必填项

每个提示词文件开头必须有**术语表**，定义提示词中用到的所有术语。

**不允许**：
- 没有术语表就开始正文
- 术语表只定义部分术语——用到的所有术语都必须定义
- 术语表引用外部文档（如"详见322号§1"）——术语必须在提示词内部定义

### 2. 术语表的双轨格式

术语表按双轨术语原则（`.devin/rules/six-dual-terminology.md`）编写——每个术语同时给出：
- FCA标准定义（数学语言——如果有FCA对应）
- 工程对应（我们的人话——subagent理解"要做什么"的关键）

### 3. 自包含的验证

提示词的自包含性可以通过以下方式验证：
- 把提示词单独拿出来，不给任何外部文档——读者能否理解提示词中每个术语的含义？
- 如果不能——缺少术语定义，违反自包含原则
- 如果能但理解偏差——术语定义不清晰，需要修正

### 4. 和328号的关系

| 规则 | 管什么 | 适用对象 |
|---|---|---|
| 328号自包含标准 | POC方案自包含——概念、背景、来源都自包含 | POC方案文档 |
| 本rule（提示词自包含） | 提示词自包含——术语自包含 | 提示词文件 |
| 双轨术语rule | 术语怎么写——FCA定义+工程含义并重 | 所有涉及术语的场景 |

三者互补——328号管POC方案，本rule管提示词，双轨术语rule管术语的写法。
