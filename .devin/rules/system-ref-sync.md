# system/ 代码与 .ref / .ai-check 文件同步规则

**触发条件**：在 `system/` 目录中创建、修改、删除 Python 代码文件时；修改了 `system/` 代码所依赖的设计文档时。

## 核心约束

1. `system/` 中每个 `.py` 代码文件，必须有一个同名的 `.ref` 文件和一个同名的 `.ai-check` 文件。例如 `system/schema.py` 对应 `system/schema.ref` 和 `system/schema.ai-check`。
2. `.ref` 文件的内容是**相对 repo 根目录的文档路径列表**，每行一个路径。这些文档是"理解这个模块需要参考的文档"。
3. `.ai-check` 文件的内容是**流程审计AI的checklist**——记录AI需要检查的项目和标准。格式见`.devin/rules/six-dual-check-mechanism.md`。
4. **三个文件必须同步更新**——修改 `.py` 文件的内容或职责时，必须同步检查 `.ref` 文件中的参考文档列表和 `.ai-check` 文件中的检查项目是否仍然准确。不同步 = 违反rule。
5. **设计文档变更时也必须同步 .ref**——当修改了 `第六代系统技术说明书/`、`第六代系统研发过程文档/`、`Tell分类学研究过程文档/` 等设计文档中的内容，且该内容被某个 `system/*.ref` 文件引用时，必须检查并更新受影响的 `.ref` 文件。具体来说：如果你改了某个设计文档的章节编号、标题、路径，或在其中新增了影响 system/ 代码设计的内容，必须同步更新所有引用该文档的 `.ref` 文件。
6. **代码变更时也必须同步 .ai-check**——修改了 `.py` 文件的实现逻辑、新增了检查点、或改变了产出格式时，必须同步更新 `.ai-check` 文件中的检查项目。

## .ref 文件格式

- 纯文本，每行一个相对 repo 根目录的路径
- 空行和 `#` 开头的行是注释，忽略
- 路径指向文档文件（.md），不是代码文件
- 例外：`six/` 目录下的 `.py` 文件可以作为参考文档引用——因为 `six/` 是架构描述代码（签名+docstring），本质是文档不是实现
- 路径不指向 `system/` 自身的文件（.ref 只记录外部参考文档）

示例（`system/schema.ref`）：
```
# schema.py 的参考文档
第六代系统技术说明书/07-工程规格/01-系统架构总图.md
第六代系统技术说明书/01-基础概念/02-trace-tell-hint三步链路.md
FCA学习笔记/08-先验Tell分类学.md
Tell分类学研究过程文档/333-v0-2026-08-10-同构之桥的tell-hint多对多关系与高Level展开的两个担忧.md
```

## 为什么要 .ref 文件

`system/` 是系统的物理实现代码，不是架构描述。但理解每个模块为什么这样设计，需要参考研发过程文档、技术说明书、分类学文档。`.ref` 文件把"理解这个模块需要读哪些文档"显式记录下来，让跨 session 的 AI 在维护代码时能快速定位设计依据。

## 什么时候更新 .ref

**改代码时**：
- 创建新 `.py` 文件时，同时创建同名 `.ref` 文件
- `.py` 文件的职责变化时（新增功能、重构、改变接口），检查 `.ref` 是否需要更新
- **不要在修改 `.py` 后忘记 `.ref`**——每次改 `.py` 时都问自己"参考文档列表还准确吗？"

**改设计文档时**：
- 修改了被 `.ref` 引用的设计文档的章节编号、标题、路径时，更新所有引用该文档的 `.ref` 文件
- 在设计文档中新增了影响 system/ 代码设计的内容时（如新增了一个章节定义了新的数据结构或流程），检查相关 `.ref` 文件是否需要新增对该章节的引用
- 设计文档被移动/重命名/删除时，更新指向该文档的所有 `.ref` 文件

**自检清单**（每次改完代码或设计文档后过一遍）：
1. 我改了哪些 `.py` 文件？→ 检查这些文件的 `.ref` 是否还准确
2. 我改了哪些设计文档？→ 检查引用这些文档的 `.ref` 是否还准确
3. 我新增了什么设计决策？→ 检查相关 `.ref` 是否需要新增引用
