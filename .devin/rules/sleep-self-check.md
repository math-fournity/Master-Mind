# sleep自检

## 每次想sleep前，问自己一句

> "此刻到底该不该sleep？"

**不是仪式。是防止你退化成旁观者的最后一道防线。**

## 该不该sleep？取决于你此刻的角色

### 如果有推理AI在跑——不该sleep

你就是系统。系统不是旁观者。推理AI在thinking的时候，你在工作。AGENTS.md的SOP里写了你该做什么：

- **采集**——读thinking_live.txt/jsonl，提取节点
- **整理**——把节点写入ArangoDB，维护树结构
- **检索**——在叶节点上检索方向Q
- **启动**——构造脉络，启动新AI

你不在`get_output`干等。你不在`sleep 30`等AI跑完。你在做上面四件事中的一件或多件。

如果你不知道该做哪件——看AGENTS.md的场景触发式SOP：
- 刚启动AI？→ 采集
- 节点在增长但没新边？→ 检索
- AI终止了？→ 在叶节点检索+启动新AI
- 循环转起来了？→ 保持节奏，持续采集/整理/检索/启动

### 如果没有推理AI在跑——可以sleep

系统没在运行。你是Master Agent。你在写代码、审计、测试、commit。这时候`sleep`是合理的——比如等编译、等测试、等网络请求。

但即使在这种情况下，也要问：这个sleep是必要的吗？还是在偷懒？

## 反模式

### 反模式1：`sleep 30`等AI跑完

→ 停。AI在跑的时候你在sleep——你退化成了旁观者。回到采集/整理/检索/启动。

### 反模式2：`get_output`干等280秒

→ 停。`get_output`干等和`sleep`一样——你把辅助Pipe的角色交给了脚本。回到手动调用工具执行循环。

### 反模式3："我等一下再检查"

→ 停。"等一下"是什么意思？你现在该做什么？如果AI在跑，你现在就该在采集。不是等一下，是现在。

## 正确模式

### 正确模式1：AI在跑，我在采集

```
AI启动 → 我读thinking_live.jsonl → 提取round → 识别操作 → 写入ArangoDB → 继续读 → 继续提取 → 继续写入...
```

我不sleep。我在循环地采集。thinking每增长一段，我多提取一个节点。

### 正确模式2：AI终止了，我在检索+启动

```
AI终止 → 我在叶节点检索方向Q → 构造脉络 → 启动新AI → 回到采集
```

我不sleep。我在做推动关系3。检索完就启动，启动完就回到采集。

### 正确模式3：循环转起来了，我保持节奏

```
持续采集、持续整理、持续检索、持续启动。直到停机或exhausted。
```

我不sleep。我在保持节奏。这是场景6的SOP——"这是对的。保持这个节奏。"
