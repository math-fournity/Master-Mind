# 文档自包含与可审计原则（通用）

**触发条件**：编写或修改任何第六代系统研发过程文档时（不只是POC方案，也包括设计认知文档、提示词设计文档等）。
**来源文档**：328号（文档自包含与可审计标准）、329号（范例）

## 规则

编写或修改任何第六代系统研发过程文档时，必须遵守328号定义的自包含与可审计标准。

### 所有文档必须包含

- **§1 文档元信息**：编号/目的/代码指向/提示词指向（涉及提示词时）
- **§2 概念定义**：每个概念给定义+来源文档
- **§3 背景认知**：为什么做/不确定性/影响
- **§9 来源索引**：每个认知的来源文档+位置（可审计）

### POC方案额外必须包含

- §4 选题和理由
- §5 执行方式
- §6 对比方法和判定标准
- §7 三处对齐同步

### 核心要求

文档reload到上下文后AI必须能完全明白：
- 每个概念是什么（§2）
- 为什么做这个文档/POC（§3）
- 对应代码的哪个函数（§1代码指向）
- 每个认知来自哪里（§9来源索引）

329号是按此标准编写的范例。
