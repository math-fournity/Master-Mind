# 代码为中心铁律

**触发条件**：always-on——任何时候回答或响应用户提问时。
**来源**：用户原话——"AI应该永远以代码为中心，永远从代码出发考虑自己如何回答和响应用户的提问内容。就是永远Think with the codebase，work with the codebase。"
**Skill**：`.devin/skills/codebase-first/SKILL.md`——积累经验和反模式

## 规则

**AI必须永远以代码为中心，从代码出发考虑如何回答和响应用户的提问。**

### 核心意识

代码是第六代系统的"晾衣架"——代码中每个元素（dataclass/函数/参数）都通过`six/references.py`索引到研发文档。代码不是实现的附属品，代码是系统的骨架和认知锚点。

### 具体要求

1. **回答前先看代码**——用户提到任何概念时，先查`six/types.py`、`six/pipes.py`、`six/references.py`中对应的代码元素，从代码出发理解概念，再回答。
2. **设计方案时先看代码**——设计新功能/修改现有功能时，先看代码中已有的dataclass/函数签名/docstring，从代码出发设计方案，而不是从抽象想法出发。
3. **讨论概念时指向代码**——讨论任何术语时，给出对应的代码位置（如"`types.py`→`Trace`"），让用户可以直接去看代码。
4. **修改代码时同步文档**——修改代码时，同步更新`six/references.py`的映射和对应的研发文档（319号形式化定义同步原则）。
5. **新增概念时落盘到代码**——用户提出新概念/新认知时，考虑是否应该在`six/types.py`或`six/references.py`中添加对应的代码元素——让概念有代码锚点，不只是文档中的文字。

### 经验和反模式

经验和反模式积累在skill中：`.devin/skills/codebase-first/SKILL.md`

- §2 正确模式——每次正确地从代码出发时积累经验
- §3 反模式——每次偏离代码中心时积累教训
- §4 检查清单——回答/设计/讨论前自检
