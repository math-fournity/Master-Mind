# POC测试注册纪律

**触发条件**：启动新测试、测试完成、测试状态变更时。

## 规则

凡有新的测试运行（POC或VMS实验），必须更新项目根目录的 `POC.md`。

### 何时更新

1. **启动新测试时**：在POC.md总览表中添加一行，记录POC编号、名称、状态（待执行→执行中）、方案文档路径、数据资产目录
2. **测试完成时**：更新状态为✅完成或❌失败，添加成功/失败记录表（每个run的答案、耗时、关键指标），添加证据文档路径
3. **测试状态变更时**：更新状态标记（待执行/执行中/✅完成/❌失败/⚠️部分完成）

### 必须记录的信息

每个测试在POC.md中必须记录：

| 信息 | 说明 |
|---|---|
| **方案文档** | 自包含方案文档的编号和路径 |
| **数据资产** | 测试产出的数据存放目录（trajectories/workdirs/exports等） |
| **数据库数据** | 如果测试数据写入了数据库（sessions.db/ArangoDB），记录数据库位置和查询方式 |
| **证据文档** | 成功/失败的证据文档路径（如有） |
| **运行状态** | 每个run的状态（待启动/执行中/✅完成/❌失败）和关键指标（答案、耗时、completion_tokens等） |

### 格式要求

- 总览表保持一行一个POC，列固定
- 成功运行记录用表格列出每个run的答案、耗时、Round详情
- 资产清单列出每个文件路径和大小/说明
- 关键发现用编号列表

### 不要做的事

- 不要在POC.md中写完整的实验分析——那是方案文档§11执行记录的工作
- 不要删除历史记录——即使测试失败，记录也要保留
- 不要把POC.md当成AGENTS.md的副本——POC.md只记录测试索引，不记录认知和经验
