# 系统代际演进命名规则

**触发条件**：数学大师系统发生重大架构演进，或AI需要判断当前系统状态时。

## 规则

### 1. 代际识别

当系统发生以下任一变化时，AI应分析是否迭代出了新一代：
- 核心信念发生变化（如硬公理降级为可证伪假设）
- 运行模式发生根本转换（如静态前置→动态控制→非特定提问→形式化边界）
- 状态模型发生本质变化（如静态图G→动态工作区W_t→DFS树→闭环）
- 角色设计发生重构（如单角色→8角色隔离→AI引导者）
- 出现新的危机诊断且危机指向架构理念层面而非实现层面

判断标准：如果变化是**架构理念层面**的（不是实现细节、不是参数调优），则视为新一代。如果只是实现优化、bug修复、参数调优，不视为新一代。

### 2. 代际命名

每一代系统必须有一个**中国神话名字**，用于方便指称。命名原则：
- 名字应与该代的**核心理念**有隐喻对应关系
- 使用中国神话中有代表性的人物名（盘古、女娲、燧人、伏羲、神农、仓颉等）
- 名字一旦确定，不改换

### 4. 发现新一代时的操作

当AI判断系统迭代出了新一代时：
1. 给新一代取一个中国神话名字（遵循上述命名原则）
2. 写新一代的技术说明书（编号顺延，遵循238/239/249/250的规范化写法）
3. 更新AGENTS.md中的"四代技术说明书系列"索引节
4. 更新本rule文件的"当前四代命名"表
