# audit-trigger rule

当以下场景发生时，触发对应模块的审计：

## 触发条件

### 1. run结束后审计
任何一次guided loop run结束后，触发P0审计：
- 184号：12步循环与引导循环审计
- 195号：数学正确性验证

### 2. 模块代码变更后审计
当以下模块的代码被修改时，触发对应审计：
- state_reducer/ 变更 → 188号审计
- heuristics/ 变更 → 189号审计
- verification/ 变更 → 192号审计
- events/ 变更 → 187号审计
- retrieval/ 变更 → 190号审计
- context_compiler/ 变更 → 191号审计
- runtime/controller.py 或 policy_pi.py 变更 → 185号审计
- runtime/budget.py 变更 → 186号审计
- auditor/ 变更 → 193号审计
- runtime/devin_cli_adapter.py 变更 → 194号审计

### 3. 认知图变更后审计
认知图（ArangoDB）变更后，触发相关模块的回归审计。

### 4. 定期回归审计
定期（如每周或每个Phase完成后）对所有模块执行回归审计。

## 审计执行

审计触发后，加载 `audit-module` skill，按以下流程执行：
1. 确定审计范围（哪些模块）
2. 读取对应的审计标准文档（dev-docs/183-195号）
3. 按文档中的检查项逐项检查
4. 输出审计报告（通过/有缺陷/失败）
5. 记录审计结果到run目录或dev-docs/
