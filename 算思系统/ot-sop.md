# 算思 SOP（OT Standard Operating Procedure）— v1.3

> **配套**：`ot-closure.md`（加载闭包）+ 本 SOP = 执行算思的完整规程。本 SOP 规定：目录
> 结构、批次流程、**文档合同（每份文档的章节结构与刻画维度，精确到字段）**、质量门与审计。

## 1. 目录结构（新任务开卷时创建）

```
<任务根>/                        # 建议 算思系统/ot-<任务名>/
├── CLOSURE.md                  # 本任务闭包（从 ot-closure.md 实例化+任务参数）
├── corpus/                     # OP-0 冻结语料（原件+提取+MANIFEST）
├── matrix/                     # 本任务稀疏矩阵（四表，从模板起）
│   ├── objects.tsv  relations.tsv  units.tsv  batches.tsv
├── notes/                      # NTE 叙事/中间文档（按 SOP §4 模板）
│   ├── grid-*.md               # facet 轮读矩阵与层面标定
│   ├── ops-*.md                # 算子抽取与消融
│   └── transfer-*.md           # 迁移/假朋友/酸测
└── report/                     # 终局交付
    ├── OT-REPORT-<任务名>.md    # 技术报告
    └── plain/OT-PLAIN-<任务名>.md  # 人话报告（强制）
```

## 2. 批次流程（两模式通用）

1. **开卷**：实例化 CLOSURE.md（填任务参数：语料范围/模式 M-A|M-B/算子族引用/完成判据）；
   建四表；units 预注册（M-A 按 OP 阶段开 8 单元，M-B 按交付物开）。
2. **执行**：按 SOP §3 各阶段细则；每单元产出登记表行+NTE（如需）；三支柱纪律的执行痕迹
   必须落盘（反先验审计结论、现实对齐重述、请求判断清单）。
3. **收口**：batches.tsv 一行（含 `sediment` 列：A/B/C 沉淀清点）→ **沉淀分拣**（按
   `docs/SEDIMENTATION.md`：A 留任务内；B 资产入 `assets/`+ASSETS.tsv 登记；C 改进提案入
   `docs/proposals/`，满足触发条件后才合入本体）→ 一致性审计（悬空 ID=0、单元状态终态）→
   `git diff --check`→ 精确 commit。
4. **恢复**：新会话/压缩后读任务 CLOSURE + 本 SOP §当前阶段 + units 状态列 + batches 末 3 行。

## 3. 阶段细则（M-A 增量建造；M-B 只执行 5–7）

| 阶段 | 细则要点 | 强制痕迹 |
|---|---|---|
| OP-0 冻结 | 语料清单+来源+SHA256+选择偏差声明；检索性语料留 URL | corpus/MANIFEST |
| OP-1 轮读 | 每 facet 单独一遍；**定向轮读优先**（上轮空格清单为指定透镜）；空胞显式留痕 | grid-NTE |
| OP-2 标定 | 每条观察标 L1–L6（允许多标）；跨层移动单独登记；层面混淆=拆分信号 | grid-NTE |
| OP-3 抽取 | 七字段+第八字段（机器化状态）；入册前查重；新旧算子族对照（复用/特化/新增三分） | ops-NTE |
| OP-4 消融 | 历史死亡记录优先（天然实验）；逐字段删除测最小充分集；收据等级标注 | ops-NTE |
| OP-5 迁移 | 跨对象正迁移+假朋友构造测试+（如可）酸测；酸测判据须事先声明 | transfer-NTE |
| OP-6 定位 | 算子挂格；空格清单=下轮定向透镜；out-of-grid 率计算 | transfer-NTE |
| OP-7 挂钩 | 每算子评估机器化路径（Lean/脚本/无）；缺口如实登记 | report §6 |

## 4. 文档合同（章节结构与刻画维度——本 SOP 的核心规定）

### 4.1 grid-NTE（轮读与标定）

章节：①任务参数回顾（语料/模式）②轮读矩阵（行=facet，列=该透镜下核心事实/层面标定/
锚点）③空胞清单④跨层移动登记⑤反先验审计小结。
维度字段：每条观察必须带 [facet, 层面, 锚点, 置信] 四元组；矩阵外观察单独列。

### 4.2 ops-NTE（算子与消融）

章节：①算子总表（编号/名称）②逐算子七字段卡+第八字段③消融记录（消融项/历史后果/证明的
字段必要性/收据等级）④新旧族对照（复用/特化/新增）⑤现实对齐重述（每算子一段人话+现实
例子；卡壳处登记）⑥请求判断清单（价值排序待决点）。
维度字段：算子卡八字段固定序：名称/输入/前置条件/动作/输出/失败模式/粒度/机器化状态；
每字段值须可追溯到语料锚点。

### 4.3 transfer-NTE（迁移/假朋友/酸测/网格）

章节：①迁移对与结果（含预测性迁移）②假朋友案例与拒绝理由③酸测设计（判据事先声明）与
逐步重放（每步标注所用算子与字段）④网格定位表与 out-of-grid 统计⑤空格清单（=下轮定向
透镜）。
维度字段：每步重放必须可指回算子编号+字段；酸测判据在任何重放开始前成文。

### 4.4 技术报告（OT-REPORT）

章节（固定序）：①任务与判据（含预注册判据，不得事后修改）②OP-0 语料与偏差③网格与层面
结论④算子族与消融⑤迁移/假朋友/酸测⑥网格定位与空格⑦机器化挂钩与缺口⑧三支柱纪律执行
记录⑨诚实边界（未读/未验证/置信不足处逐条列）⑩下一步。
维度：每条主张配锚点；证据等级（一手/二手/推断）逐条标注；数字结论（复用率/扩容比/
out-of-grid 率）给计算口径。

### 4.5 人话报告（OT-PLAIN，强制）

章节（固定序）：①这一关在干什么（比喻先行，禁术语裸奔）②做了什么（叙事体，可读性优先）
③结果（含 surprising 点）④意外收获⑤要坦白的部分（必须存在，不许省略）。
维度：全文禁未解释的行话；每个技术结论须有一个日常对应物；长度以陌生人 15 分钟读完为度。

## 5. 质量门

- G1 开卷门：CLOSURE 实例化完整+判据先注册，方可开始 OP-1；
- G2 抽取门：算子卡八字段齐+查重+三支柱痕迹齐，方可入族；
- G3 酸测门：判据先声明+逐步可指回，方可宣 PASS；
- G4 收口门：四表一致+悬空 0+人话报告存在+诚实边界节非空，方可宣布任务终态；
- G5 名义门：对外引用一律用"算思/OT"名（naming.md 约定）；
- G6 沉淀门：任务终态前必须完成 A/B/C 三类沉淀分拣（batches.tsv sediment 列非空；B 类
  资产已登记 ASSETS.tsv；C 类提案已入 proposals 并带触发条件）。

## 6. 反思迭代步骤的护栏（目的不变式）

> **设立动机（用户 2026-09-28 纠偏）**：不希望算思系统被改造错——尤其是未来 AI 执行
> "反思算思系统该如何迭代"步骤时。两轮距离考察后执行 AI 曾把目的从"产生方案"漂移到
> "分析距离"，此护栏防该类漂移在自我迭代中被放大和固化。

**目的不变式（不可被任何迭代提案覆盖）**：

```
算思系统的首要目的 = 通过系统化方法，产生完整的、怀尔斯级别的数学解决方案。
（选路线→选零件→组装→验证，整条链；不是分析工具，不是评测框架。）
```

**迭代提案的目的检验（G6 沉淀门新增前置条件）**：

任何 C 类提案（系统迭代）在写入 proposals/ 之前，必须通过以下检验并写进提案文件头部：

| 检验项 | 通过标准 | 不通过的后果 |
|---|---|---|
| I-1 目的对齐 | 提案内容**直接或间接服务于**"产生完整方案"这条链上的某个环节 | 标记为"目的偏移"→ 存入 proposals/drift/ 而非主目录，留作历史警示范例 |
| I-2 层级定位 | 提案改善的是链条上的哪一环（策略/货架/执行/验证），明写 | 没有层级定位=提案没有靶点，退回 |
| I-3 漂移检测 | 提案是否把算思系统从"生产系统"改造为"分析工具/元方法论"——**这是漂移** | 一旦检出=强制拒绝，写 PROD 纠偏文档 |

**"反思迭代"步骤的执行协议**（SOP 承认该步骤存在——它就是 G6 沉淀门的 C 类分拣，但加了
护栏）：

1. 先重读 `docs/PROD-purpose-recalibration.md` 的目的声明（每次必读，不可跳过）；
2. 对照当前迭代方向与目的不变式——发现偏移即写 PROD 纠偏文档（`docs/PROD-*.md` 命名约定）；
3. 通过 I-1/I-2/I-3 三项检验的提案才能写入 proposals/ 主目录；
4. 不通过的提案写入 `proposals/drift/`（标记"目的偏移"），保留作历史警示范例——**不删除，
   因为偏移本身是有价值的反面教材**。

## 7. Git 提交环节（强制）

1. **开卷提交**：任务卷 CLOSURE+四表骨架建立后，当批即 commit（信息含任务名+开卷）；
2. **批次提交**：每批次收口必出 commit（收口流程第 3 步）；多批次不攒批——每批一个可审计
   增量；commit message 必含 unit/批次 ID 与内容摘要；
3. **阶段提交**：OP-0 冻结、算子族定稿、酸测 PASS/FAIL、报告落盘四个节点各出一笔显式
   commit（即便与批次提交同日）；
4. **纪律**：只 stage 任务根内精确路径；`git diff --check` 先行；token 字面量自检零命中
   后方可 commit；禁止 push（除非用户当轮授权）；禁 `git add -A/./u`；
5. **历史保全**：只用普通 commit 记录过程，不 rewrite；矩阵/日志类 append-only 文件的
   可审计性依赖此条（审计史=git log --follow -p）；
6. **收尾对账**：任务终态时核对 `git status` clean（除用户并行改动）+ 本任务全部产物
   已入库（G6 沉淀门的资产/提案亦须已 commit）。
