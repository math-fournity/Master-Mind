# 算思系统沉淀协议（OT Sedimentation Protocol）— v1.0

> **回答的问题**：一次算思任务（如"考察算思对 FLT 的处理与 Anthropic 证明的距离"）结束后，
> 产出物中哪些内容**沉淀**到哪里？特别是：算思系统自身的新内容（新算子、新框架、新纪律、
> 工具改进）如何回流进系统本体？
> **设立动机（用户 2026-09-28 原话要义）**：任务执行会产生系统级的新内容；闭包本身不够，
> 系统应携带一个 docs 子目录用于非闭包内容的积累；沉淀规则必须在 SOP 中规定。
> **沉淀三层模型**（B1 批实证复盘后归纳）：
> **对象知识**（关于研究对象的结论）/ **任务资产**（本任务锻造的可复用工具）/ **系统迭代**
> （对算思制度本身的改进）——三者目的地不同，混放即失传。

## 1. 三类沉淀物与目的地

| 类 | 识别特征（怎么认出它） | 目的地 | B1 批实例 |
|---|---|---|---|
| **A 对象知识** | 关于研究对象的结论/证据/锚点 | 任务自身（notes/report/corpus）+ 对象知识索引行 | 距离六轴结论、算子映射表 |
| **B 任务资产** | 本任务锻造、**下一个任务还会用**的可复用件：新算子/新算子族、新框架（如六轴）、新测试协议（如酸测模板）、新单元模板、可复用清单 | `算思系统/assets/`（带登记） | W1–W10 算子族；六轴距离框架；矩阵规程的 B1 实战验证 |
| **C 系统迭代** | 对算思制度本身的改进候选：SOP/闭包/文档合同/质量门的修订建议、新纪律、新质量门 | `算思系统/docs/` 提案 → 定期/触发式合入 ot-sop 等本体文件（走版本节追加） | "酸测判据先声明"从 FLT 实战确认后应入 SOP 正文（已入）；"可执行性加权"意见（D6 产出，未定案）；人话报告强制坦白节（已入） |

**判定规则（一句话版）**：下个任务还要直接用 → B（进 assets）；制度要不要改 → C（进
docs 提案）；只是这个研究对象的结论 → A（留在任务内）。

## 2. 目录增补（系统本体）

```
算思系统/
├── ot-closure.md  ot-sop.md  naming.md  README.md   # 本体（制度层）
├── assets/                # 【新】B类：可复用任务资产（带登记表）
│   └── ASSETS.tsv         # 资产登记：asset_id/类/名称/来源任务/版本/被引用计数/锚点
├── docs/                  # 【新】C类：非闭包内容积累区
│   ├── proposals/         # 系统迭代提案（未合入本体的修订建议，附依据与触发条件）
│   ├── cases/             # 案例研究（跨任务复盘、方法论战例分析）
│   └── theses/            # 算思对外的立场/论述文档（如"算思与Autoformalization的关系"）
├── tasks/                 # 任务卷（今后 ot-<任务名>/ 建在此，与系统本体分离）
├── corpus/  distance-matrix/  plain/                  # 既有（归属说明见§4）
└── 调查报告与FLT报告等md   # 历史任务遗留（不迁移，宪法禁批量移动；新任务不再效仿）
```

## 3. 沉淀流程（批次收口时强制执行）

1. **清点**：批次/任务收口时，按 §1 判定规则把产出分拣为 A/B/C 三类（清点结果写进
   batches.tsv 新列 `sediment`：如 `A×12/B×2/C×1`）；
2. **B 类入库**：新资产以独立文件进 `assets/`（命名 `AS-<类>-<slug>.md`，类=OP/FRAME/
   PROTO/UNIT/CHKLIST），同步登记 ASSETS.tsv（来源任务/版本/锚点）；**算子族入库须带
   八字段完整卡**（W1–W10 即首个入库资产 AS-OP-W）；
3. **C 类提案**：改进建议写成提案文件进 `docs/proposals/`（模板：现象/证据/建议修订条/
   触发条件/状态[open|accepted|rejected]）；**提案不合入本体文件**，直到满足触发条件
   （如"第二个独立任务复现同一改进需求"）——防止单次经验污染制度；
4. **合入**：accepted 提案按 ot-sop 版本节追加方式合入本体，提案状态改 accepted 并记
   合入 commit；被合入的提案文件保留（历史证据）；
5. **索引更新**：README 的资产索引节同步。

## 4. 存量归位说明（本次实行的最小迁移）

- `distance-matrix/` → 实为 **B 类资产**（矩阵规程+四表模板），登记为 AS-FRAME-MATRIX，
  位置暂不物理迁移（避免中断其四表活跃状态），目录头加归属注记；
- `corpus/` → A 类语料（任务性），保留原位；今后任务语料进 `tasks/<任务>/corpus/`；
- `plain/` → A 类人话报告，保留原位；今后任务人话进 `tasks/<任务>/report/plain/`；
- 根级七份任务报告 → 历史任务遗留，位置不动；其可复用件（W 算子族、六轴框架、FLT 判据
  模板）以引用方式登记进 ASSETS.tsv（锚点指向现文件），不复制正文。
