# PROD-006 — 第0层：计算阅读框架是所有算子的前提

> **触发**：用户 2026-09-28 指出——PROD-005 说"更深入地反思了罗素原文"但没说**为什么**
> 能看到构造/查询二分。答案：因为用户从**计算/程序的角度**去拆解原文。
> **修正**：计算阅读框架不是众多算子之一——它是**所有算子的阅读前提**（第0层）。

## 1. 两种读法，两个世界

| 逻辑读法（默认） | 计算读法（用户的框架） |
|---|---|
| "S是所有…的集合" = 定义 | = 程序：遍历所有x，检查x∉x，放入S |
| "S是否包含自身？" = 问题 | = 函数调用：调用一个底层计算未完成的函数 |
| 自指+否定 → 矛盾 | 循环+递归调用 → **永不停机** |
| 看到：**逻辑结构** | 看到：**计算结构** |
| 构造/查询裂缝：**不可见** | 构造/查询裂缝：**可见** |

**同一个文本，两种读法看到完全不同的结构。** 构造/查询裂缝在逻辑读法下是隐形的——只有
把文本当作程序来读，才能看到"这是一个不停机的循环，而理论在对它调用函数"。

## 2. 层级修正

```
第0层：阅读框架（计算/程序视角）—— 使结构特征可见     ← 之前缺失
第1层：结构特征（构造/查询裂缝、不停机、非法程序）      ← 通过第0层才可见
第2层：算子（Z1/R1/Z6…）—— 结构特征的形式化           ← 已有
第3层：应用—— 算子作用于新理论                        ← 已有
```

**Z1（过程化）不是众多算子之一——它是第0层阅读框架在第2层的显式化。** 没有第0层，
Z1-Z10、R1-R4 全部空转：你告诉 AI "从时间角度看看"，但 AI 用逻辑读法看，看到的只有
命题关系，看不到"这是一个不停机的循环"。

## 3. Z6 修正

原 Z6 定义："把悖论文本分解为思维操作"——**不完整，没说镜头**。
修正 Z6：**"把数学文本当作程序来读——识别计算操作（循环/递归/调用/终止检查）→标注
哪些操作会终止→找到'理论假装未终止的计算已完成'的位置→裂缝=幽灵候选"**

## 4. 对 AI 可达性的最终修正

```
AI 能否自动发现最后一跃？
  → 需要第0层（计算阅读框架）+ 第2层（算子）+ 第3层（应用）
  → 第2/3层已齐（算子入库+酸测PASS）
  → 第0层目前是隐含的（AI 的训练数据包含编程知识，但没有"读数学文本时自动切换到
    计算读法"的习惯）
  → 缺口 = 把"读数学文本时切换到计算读法"从隐含变成显式+训练成反射
```

**好消息**：第0层不需要发明——计算视角已经存在（Z1 就是它的显式化），只是没有被承认为
**前提**而非**算子**。修正只需要：在 ot-closure 中声明第0层为必读前提。

**坏消息**：把第0层变成 AI 的自动反射，仍需要练习（同 PROD-003 的结论）——但练习的
内容精确化了：不是"练习使用算子"，是**"练习用计算读法读数学文本"**——每读一篇大师作品
时，先问"这里的定义/定理如果是一个程序，它停机吗？"
