# Distance SOP — "距离"研究标准作业流程（2026-09-28 立卷）

> **配套关系**：本 SOP 是 `flt-anthropic-distance-closure.md`（任务闭包）的执行规程，两者共同
> 构成 Tier 0 必读件。闭包回答"研究什么、为什么"；本 SOP 回答"怎么干、怎么留痕、怎么恢复"。
> **设立依据（用户 2026-09-28 原话要义）**：认知闭包必须有一套 SOP，不能让接手 AI 随便工作；
> 系统化工作必须有标准流程和文档留存；文档会很多，必须解决海量文档问题——引入本项目源头
> 仓的稀疏矩阵思想管理海量认知对象之间的关系。

## 0. 两件武器与各自职责

1. **稀疏认知矩阵**（源头仓 K/T/H 方法论的回归应用）：海量对象之间只登记**实际断言过的
   关系**——稀疏性是纪律不是巧合。职责：承载一切原始观察与对象间关系（广度问题）。
2. **长文档分片索引**（HoTT 交接仓已验证的 governance-shard 模式）：单个叙事文档超软目标
   （300 行）即分片+索引表，禁止无限追加。职责：管理单文档体量（深度问题）。
   叙事文档只写**已定型的结论**；原始观察一律先进矩阵，不写散文。

## 2. 对象与 ID 规程

对象类前缀：`AXIS`（六轴 D1–D6）、`OP`（算子 W1–W10）、`ART`（对象仓工件）、`OUR`
（本项目工件）、`EXT`（外部来源）、`FND`（发现条目）、`NTE`（叙事文档）。
新对象必须先登记 objects.tsv 再被引用；锚点格式：对象仓文件路径（或网页节/外部文献）+
行号/节号。**对象仓工件锚点必须落到具体文件或 html 页**，不得只写目录名。

## 3. 关系词表（封闭集，新增须修本 SOP）

`对应`（语义对应/映射）｜`证据`（支持某断言）｜`反驳`｜`依赖`（推导/构建依赖）｜`同构`
（结构同构，须给出同构描述）｜`货架来自`（素材/机械来源）｜`粒度包含`（粗细层关系）｜
`待查`（显式标记未决）。每行关系五要素齐全：src、rel、dst、anchor、置信
（high=原文可引/med=推断有据/low=线索）。

## 4. 工作单元协议

1. 单元在 units.tsv 预注册（已预置 12 个，源自六轴）；状态列：`open→active→done|blocked`。
2. 每个会话批次：读 Tier 0 → 查 units.tsv 取 `open` 单元置 `active` → 按闭包 §3 地图执行 →
   产出（关系行/对象行/必要时一份 NTE）→ 状态置终态 → 批次日志 + 精确 commit。
3. **禁止无单元自由漫游**：任何对象仓阅读必须挂在某 active 单元下；读到计划外高价值内容时，
   先登记 `FND` 对象 + `待查` 关系 + 新单元行（open），不在当批展开。
4. 单元可加不可删；改问题表述须在新行留修订痕迹。

## 5. 分层加载纪律（解决海量文档的读取侧）

- **Tier 0**（每次会话/压缩恢复后必读）：闭包 + 本 SOP + `units.tsv` 状态列。
- **Tier 1**：按 ID/关系词 grep 查询加载，禁止全文顺序读入。
- **Tier 2**：仅当单元结论涉及时按文件名加载。
- 对象仓本体：只按闭包 §3 地图抽样；**禁止全仓遍历、禁止 lake build/verification 脚本**。
- 上下文预算：单批对象仓新增读取量建议 ≤ 30 个文件/页；超出即拆批。

## 6. 批次收口与 Git 纪律

每批：登记表更新 → batches.tsv 一行（units_touched/objects_added/relations_added/commit）→
`git diff --check` → 精确路径 stage+commit（信息含 unit_id）。宪法级禁令全量沿用：不 push、
不写库、无 Sub Agent、token 字面量零落盘、不修判据原文。

## 7. 恢复协议

新会话或压缩后：读根 AGENTS（宪法）→ 本目录 closure + 本 SOP → units.tsv 状态列 →
batches.tsv 末 3 行 → 从最早 `active`（若有半途批次）或队首 `open` 继续。**不依赖任何
会话记忆。**

## 8. 一致性审计

- 每完成 4 个单元跑一次轻审计：悬空 ID（relations 引用了 objects 没登记的行）=0；
  `open` 单元队首无阻塞依赖却长期搁置=须写明原因；低置信关系无 `待查` 升级路径=补。
- 终局审计：units 全终态；六轴各至少 1 份结论性关系行或 NTE；交付物按闭包 §6 对账；
  人话文档落盘后本卷方可宣布完成。
