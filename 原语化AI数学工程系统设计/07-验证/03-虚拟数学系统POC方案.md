## 核心思想

构造一个虚拟数学系统，它和真实数学系统**HoTT同构**（结构相同，内容虚拟）。在虚拟系统中批量生成题目，让AI做真实的推理（逻辑推理过程是真实的，只是推理对象是虚拟的），用于POC验证检索系统的技术方案——尤其是超大规模基座时，形式化+AI加持下的检索能力。

## 为什么需要虚拟数学系统

真实数学POC有三个根本困难：

| 困难 | 真实数学POC | 虚拟数学系统POC |
|---|---|---|
| **数据量** | 真实数学题数量有限，需要数学专家出题 | 批量生成任意数量虚拟题目 |
| **正确性验证** | 需要数学专家验证答案 | 虚拟系统正确答案已知（构造时确定） |
| **覆盖度积累** | 真实Pattern慢慢积累，等不起 | 虚拟系统快速积累数千-数万Pattern |
| **变量控制** | 真实数学有大量背景知识干扰 | 虚拟系统控制变量，只测检索能力 |

虚拟数学系统同时解决了这三个困难。

## "HoTT同构"的含义

在HoTT（同伦类型论）中，数学结构由类型/构造子/inhabitants/等价组成。说虚拟数学系统和真实数学系统HoTT同构，不是内容相同，而是**结构相同**：

| HoTT概念 | 真实数学 | 虚拟数学 |
|---|---|---|
| 类型（Type） | 数学对象类（群、环、域、图） | 虚拟对象类（虚拟群、虚拟图） |
| 类型构造子 | π类型/Σ类型/等式类型 | 相同的构造子 |
| inhabitants | 具体的群/环/图 | 具体的虚拟群/虚拟图 |
| 证明结构 | 构造子序列 | 相同的构造子序列 |
| 依赖图 | 类型之间的依赖关系 | 同构的依赖关系 |

**关键**：推理过程是真实的——AI在虚拟系统中仍然需要做真正的逻辑推理（验证封闭性、构造证明、识别模式）。只是推理的对象是虚拟的。这就像在虚拟世界中测试自动驾驶——物理引擎是虚拟的，但AI的决策过程是真实的。

## 构造方案：虚拟群论

### 为什么选群论

群论是POC虚拟数学系统的最佳起点：

1. **结构简单清晰**：一个运算+四条公理（封闭性/结合律/单位元/逆元），容易构造虚拟实例
2. **证明结构丰富**：子群/正规子群/商群/同态/同构，覆盖多种推理模式
3. **AI有群论推理能力**：GLM-5.2等AI模型有群论知识，能在虚拟群上做真实推理
4. **对象完全虚拟**：虚拟群的元素和乘法表是人为构造的，不依赖真实数学的具体内容
5. **可批量生成**：用程序生成不同规模/结构的虚拟群，批量出题

### 虚拟群论的构造

#### 第1层：虚拟群实例

```
定义虚拟群G：
- 元素：{e, a, b, c, d, ...}（符号集，e是单位元）
- 乘法表：人为构造，满足群公理（封闭性/结合律/单位元/逆元）
- 可以批量生成不同规模的虚拟群（6阶/12阶/24阶/...）

生成方法：
1. 选择群的结构类型（循环群/二面体群/对称群/直积群/...）
2. 用程序按结构生成乘法表
3. 验证群公理（程序自动验证）
4. 随机化元素符号（e/a/b/c/... → α/β/γ/δ/... 或 x₁/x₂/x₃/...）
   ——随机化符号防止AI依赖真实数学中对特定符号的先验知识
```

**具体例子**：虚拟群V_1
```
元素：{e, α, β, γ}（4阶循环群，但AI不知道它是循环群）
乘法表：
  e·e=e  e·α=α  e·β=β  e·γ=γ
  α·e=α  α·α=β  α·β=γ  α·γ=e
  β·e=β  β·α=γ  β·β=e  β·γ=α
  γ·e=γ  γ·α=e  γ·β=α  γ·γ=β
```

AI需要通过推理发现这个群的性质（是循环群，α是生成元），而不是靠符号识别。

#### 第2层：虚拟定理

虚拟定理和真实群论定理**结构同构**，但用虚拟语言表述：

| 真实定理 | 虚拟定理 | 同构关系 |
|---|---|---|
| Lagrange定理：\|H\|整除\|G\| | "虚拟群G的虚拟子群H的阶整除G的阶" | 结构相同 |
| 正规子群判定：∀g, gHg⁻¹=H | "虚拟群G中，对所有元素g，gHg⁻¹=H则H是虚拟正规子群" | 结构相同 |
| 第一同构定理：G/ker(φ)≅im(φ) | "虚拟群G到虚拟群G'的虚拟同态φ，G/ker(φ)≅im(φ)" | 结构相同 |
| Cayley定理：G嵌入某对称群 | "虚拟群G虚拟嵌入某虚拟对称群" | 结构相同 |

#### 第3层：虚拟题目

```
1. "给定虚拟群V_1（乘法表如上），找出所有虚拟子群"
2. "给定虚拟群V_1和虚拟子群H={e,β}，判断H是否是虚拟正规子群"
3. "给定虚拟群V_1和V_2，构造V_1到V_2的虚拟同态"
4. "给定虚拟群V_1，判断它是否是虚拟循环群"
5. "给定虚拟群V_1，求它的虚拟中心"
6. "给定虚拟群V_1，求它的虚拟共轭类"
```

AI在解这些虚拟题目时：
- 需要理解虚拟群的运算性质（真实推理）
- 需要构造虚拟证明（真实逻辑推理）
- 需要识别什么时候该用什么策略（真实的模式识别）
- 但不需要真实数学的具体知识（虚拟群自包含）

#### 第4层：虚拟思维模式

和真实数学思维模式**结构同构**：

| 真实思维模式 | 虚拟思维模式 | Level |
|---|---|---|
| "先检查单位元是否在子群中" | "先检查虚拟单位元是否在虚拟子群中" | 0.3 |
| "尝试构造商群验证正规性" | "尝试构造虚拟商群验证虚拟正规性" | 0.5 |
| "寻找同态核" | "寻找虚拟同态核" | 0.6 |
| "考虑群的阶的因子分解" | "考虑虚拟群的阶的因子分解" | 0.4 |
| "尝试用共轭关系分析群结构" | "尝试用虚拟共轭关系分析虚拟群结构" | 0.7 |
| "检查是否是循环群——寻找生成元" | "检查是否是虚拟循环群——寻找虚拟生成元" | 0.5 |

## Pattern的生成和积累

### 批量生成流程

```
1. 程序生成1000个虚拟群（不同规模/结构/符号）
2. 每个群出5-10道虚拟题
3. 每道题跑预演模式（Master知道答案）生成QA序列
4. 从QA序列中提炼Pattern
5. Pattern存入虚拟数据基座

总计：
  1000个虚拟群 × 8道题/群 × 6个Pattern/题 ≈ 48,000个Pattern
```

这直接解决了缺口5（覆盖度）的数据问题——不需要等真实数学Pattern慢慢积累，虚拟系统可以快速生成大规模基座。

### Pattern的结构

虚拟群论生成的Pattern和真实数学Pattern结构相同：

```json
{
  "pattern_id": "VG-001-subgroup-check-identity",
  "domain": "virtual_group_theory",
  "trigger_conditions": {
    "deterministic": {
      "task_type": "find_subgroups",
      "group_order": {"op": ">", "value": 4},
      "has_multiplication_table": true
    },
    "non_deterministic": {
      "reasoning_state": "AI seems to be trying to enumerate subsets without checking closure"
    }
  },
  "Q": "你已经列出了一些子集。对于每个子集，你是否检查了它包含单位元？",
  "Level": 0.3,
  "non_specificity": 0.9,
  "situation_type": "思维操作引导",
  "source": "virtual_group_V_001, QA_round_3"
}
```

**关键**：trigger_conditions分为deterministic和non_deterministic两部分——这正好对应缺口2的"形式化先行+AI收尾"架构：
- deterministic字段可以被Rete alpha network/形式化方法查询
- non_deterministic字段需要AI（辅助智能体）做最终判断

### Pattern的跨域迁移

虚拟群论Pattern能否迁移到真实群论？理论上可以——因为HoTT同构，虚拟群论的"检查单位元是否在子群中"和真实群论的"检查单位元是否在子群中"是同一个思维模式，只是作用对象不同。

**迁移验证**是POC的重要部分（见下文POC-VMS-4）。

## POC-VMS系列方案

虚拟数学系统POC（POC-VMS）是一个独立的POC系列，和原有POC系列并行，专门用虚拟数学系统验证检索系统技术方案。

### POC-VMS-0：虚拟群论基础设施

**目标**：验证虚拟群论系统的基本功能

**步骤**：
1. 用程序生成100个虚拟群（4阶/6阶/8阶/12阶，循环群/二面体群/对称群）
2. 用程序生成虚拟题目（子群/正规子群/同态/循环性/中心/共轭类）
3. 用程序验证虚拟题目的正确答案
4. 让裸跑AI（无提示）解10道虚拟题，记录baseline表现

**通过条件**：
- 虚拟群生成正确（程序验证群公理）
- 虚拟题目有明确正确答案
- 裸跑AI能在虚拟群上做真实推理（不是直接放弃）

### POC-VMS-1：预演模式+Pattern生成

**目标**：验证从虚拟QA序列中提炼Pattern的可行性（缺口4）

**步骤**：
1. 对10道虚拟题跑预演模式（Master知道答案，引导AI解题）
2. 记录完整QA序列
3. 从QA序列中提炼Pattern（人工或AI辅助提炼）
4. 验证提炼的Pattern的结构完整性

**通过条件**：
- 预演QA序列成功引导AI解出虚拟题
- 提炼的Pattern有完整的trigger_conditions/Q/Level/非特定性
- Pattern的trigger_conditions可以拆分为deterministic和non_deterministic字段

### POC-VMS-2：小规模检索验证（10个Pattern）

**目标**：验证缺口1（状态提取）和缺口2（模式匹配）的基本可行性

**步骤**：
1. 用POC-VMS-1生成的10个Pattern构建小规模虚拟数据基座
2. 让AI解新的虚拟题（不在预演集中的题）
3. 形式化方法提取状态（已证命题/当前表示/已完成步骤）
4. AI补充非确定性状态（卡点诊断）
5. 形式化方法用deterministic字段做粗筛
6. AI用non_deterministic字段做精筛
7. 检查检索到的Pattern是否正确

**通过条件**：
- 状态提取能从context中提取出结构化状态
- 形式化粗筛能缩小候选集
- AI精筛能从候选集中找到正确Pattern
- 检索到的Pattern能引导AI解出新虚拟题

### POC-VMS-3：中规模检索验证（1000个Pattern）

**目标**：验证Rete/MiniCon类算法在中规模的scalability

**步骤**：
1. 批量生成1000个Pattern（从125个虚拟群的预演QA序列中提炼）
2. 构建Rete network（alpha节点=deterministic字段，beta节点=non_deterministic字段）
3. 或用K-D tree做粗筛
4. 让AI解新虚拟题，测试检索效果

**通过条件**：
- Rete/MiniCon类算法在1000个Pattern时检索时间可接受（<1秒）
- recall≥80%（找到所有相关Pattern中的80%）
- precision≥90%（检索到的Pattern中90%确实相关）

### POC-VMS-4：大规模检索验证（10,000+个Pattern）

**目标**：验证超大规模基座的检索能力——这是核心验证

**步骤**：
1. 批量生成10,000-48,000个Pattern（从1000+个虚拟群中提炼）
2. 构建大规模Rete network或K-D tree索引
3. 测试形式化粗筛的剪枝效果（从10,000+缩小到多少候选）
4. 测试AI精筛的准确率（对候选Pattern做最终判断）
5. 测试recall（是否找全所有相关Pattern）
6. 测试增量计算（虚拟群状态变化时的检索更新效率）

**通过条件**：
- 形式化粗筛能从10,000+缩小到<100候选
- AI精筛对<100候选的判断准确率≥90%
- recall≥80%
- 检索时间<5秒

### POC-VMS-5：Pattern生成闭环验证

**目标**：验证缺口4（Pattern生成闭环）——从解题记录树中提炼Pattern，用于新题

**步骤**：
1. 用预演模式生成初始Pattern集合（1000个）
2. 用这些Pattern引导AI解新虚拟题（实际模式，Master不知道答案）
3. 记录AI的解题记录树（成功路径+失败路径+分叉点）
4. 从解题记录树中提炼新Pattern
5. 把新Pattern加入数据基座
6. 用扩大的数据基座引导AI解更多新虚拟题
7. 验证数据基座增长后检索效果是否提升

**通过条件**：
- 能从解题记录树中提炼出有效的Pattern
- 新Pattern加入后，后续题目的检索效果提升
- 闭环跑通——数据基座自我增殖

### POC-VMS-6：跨域迁移验证

**目标**：验证虚拟群论Pattern能否迁移到真实群论

**步骤**：
1. 用虚拟群论生成的Pattern集合
2. 让AI解真实群论题（如"证明Z/6Z的子群都是正规子群"）
3. 检查虚拟Pattern能否引导AI解真实题
4. 对比：有虚拟Pattern引导 vs 无引导 vs 有真实Pattern引导

**通过条件**：
- 虚拟Pattern引导下AI表现 > 无引导
- 虚拟Pattern引导下AI表现 ≥ 真实Pattern引导的80%

**意义**：如果通过，说明虚拟系统生成的Pattern可以**直接用于真实数学**——虚拟系统不只是POC工具，是系统的永久组成部分。

## POC-VMS系列与原POC系列的关系

| 原POC | POC-VMS替代 | 关系 |
|---|---|---|
| POC-0（10个Pattern小规模） | POC-VMS-2（10个虚拟Pattern） | POC-VMS-2用虚拟群论替代真实数学，变量控制更好 |
| POC-1~3（状态提取可靠性） | POC-VMS-2+VMS-3 | 虚拟群论批量出题，多道题验证状态提取 |
| POC-2（大规模匹配算法） | POC-VMS-3+VMS-4 | 虚拟群论快速生成10,000+Pattern，测试Rete/MiniCon |
| POC-4（recall） | POC-VMS-3+VMS-4 | 虚拟系统知道正确答案，可以精确计算recall |
| POC-7（闭环） | POC-VMS-5 | 虚拟系统快速跑通闭环 |
| 无对应 | POC-VMS-6 | 跨域迁移是虚拟系统独有的验证 |

**POC-VMS系列的优势**：每个验证都有精确的正确答案（构造时确定），可以精确计算recall/precision，可以批量生成任意规模的数据，可以控制变量。

## 虚拟数学系统作为系统的永久组成部分

如果POC-VMS-6（跨域迁移）通过，虚拟数学系统不只是POC工具，而是**系统的永久组成部分**：

- **系统初期**：主要靠虚拟系统积累Pattern（快速建立大规模基座）
- **系统成熟期**：虚拟Pattern + 真实Pattern混合使用
- **系统最终态**：以真实Pattern为主，虚拟Pattern补充覆盖度

这就像飞行模拟器——飞行员在模拟器中训练的能力可以迁移到真实飞行。虚拟数学系统是AI数学大师的"飞行模拟器"。

## 长期扩展：多领域虚拟系统

POC-VMS验证通过后，扩展到其他领域：

| 领域 | 虚拟系统 | 推理模式 |
|---|---|---|
| 群论 | 虚拟群（已方案） | 代数推理 |
| 图论 | 虚拟图（虚拟节点+虚拟边） | 组合推理 |
| 序/格 | 虚拟偏序集 | 序推理 |
| 形式系统 | 虚拟公理系统 | 纯形式推理 |
| 拓扑 | 虚拟拓扑空间（虚拟开集族） | 拓扑推理 |

多领域虚拟系统覆盖多种推理模式，更接近真实数学的多样性。

## 开放问题

1. **符号随机化的程度**：完全随机化符号（α/β/γ）vs 部分随机化（保留e作单位元）vs 真实符号（e/a/b/c）？完全随机化可能让AI难以推理，部分随机化可能引入先验知识污染。
2. **虚拟群的规模范围**：小群（4-12阶）够不够？需要大群（100+阶）吗？大群的乘法表会占用大量context。
3. **Pattern提炼的自动化程度**：POC-VMS-1中Pattern提炼是人工还是AI辅助？如果AI辅助，AI怎么从QA序列中识别"值得提炼的模式"？
4. **Rete network的构建**：虚拟群论Pattern的deterministic字段（task_type/group_order/has_multiplication_table）是否足够构建有效的alpha network？需要更多deterministic字段吗？
5. **跨域迁移的边界**：虚拟群论Pattern能迁移到真实群论的哪些题目类型？所有类型都能迁移，还是只有结构简单的类型能迁移？

## 真实难题驱动的虚拟验证（用户洞察·核心方法论修正）

> **本节是对原POC-VMS方案的核心方法论修正。** 原方案是"虚拟系统自包含验证"——VMS-0到VMS-5都在虚拟系统内完成，只有VMS-6做跨域迁移。用户提出新思路：**真实难题驱动的虚拟验证**——从一开始就用真实难题抽象驱动虚拟构造，最终用真实难题+干扰数据验证。这确保虚拟系统验证对真实数学世界有实际价值。

### 核心思路

我们手上有**AI做不出来但有正确解答的真实难题**（如MathArena竞赛题baseline中81.1%做不出的30道题，以及矩条件极差题第二问）。这些难题是宝贵的资源——我们可以分析AI为什么做不出，把挑战抽象出来，然后用虚拟数学系统构造同类挑战，在虚拟环境中打磨系统，最终用真实难题验证。

### 4个阶段

```
阶段1·挑战抽象：真实难题（AI做不出+有解答）→ 分析AI为什么做不出 → 抽象出挑战类型
阶段2·虚拟构造：在虚拟数学系统中构造同类挑战 → 批量生成类似挑战
阶段3·系统打磨：在虚拟挑战上优化检索系统 → 打磨形式化粗筛+AI精筛
阶段4·真实验证：在测试基座中注入大量干扰数据 → 让真实难题进入系统 → 验证系统是否能在干扰中找到正确方向
```

这和自动驾驶的"模拟器训练→真实路测"完全同构——虚拟系统不是独立的，而是被真实难题驱动的。

### 具体例子：矩条件极差题第二问

**阶段1·挑战抽象**：
- AI为什么做不出？分析QA序列，发现AI卡在Q8——"已证明稳定性方程，需要判断badly approximable性质"但AI不知道该往哪个方向走
- 挑战类型抽象：**"已证明A性质，需要判断B性质，但A→B的路径不显然"**——跨概念推理跳跃挑战

**阶段2·虚拟构造**：
- 在虚拟群论中构造同类挑战：**"已证明虚拟群G是交换群，需要判断G是否是循环群"**——同样是跨概念推理跳跃
- 批量生成：不同虚拟群上的"已证明X，需要判断Y"挑战

**阶段3·系统打磨**：
- 在虚拟挑战上优化检索系统——能否在数据基座中找到"从交换群到循环群的推理路径"Pattern
- 打磨形式化粗筛的trigger_conditions字段设计
- 打磨AI精筛的准确率

**阶段4·真实验证**：
- 在测试基座中注入48,000个干扰Pattern（虚拟群论生成的）
- 把矩条件极差题第二问的真实Pattern（只有3-5个）混入
- 让系统面对"48,000个Pattern中找3-5个相关的"的真实场景
- 验证系统是否能在大量干扰中找到正确的真实Pattern

**关键**：阶段4的"干扰数据"正是模拟真实运行场景——数据基座有大量Pattern，但当前处境只和极少数相关。系统能否在干扰中找到正确的，是检索系统的核心能力。

### 这个思路解决了什么风险

虚拟数学系统验证对真实数学的价值，存在5个风险。这个思路逐一解决：

| 风险 | 这个思路怎么解决 |
|---|---|
| **先验知识污染** | 虚拟挑战从真实难题抽象而来，不是随机生成的虚拟群——AI的先验知识对抽象后的挑战类型可能无效 |
| **结构复杂度差距** | 挑战从真实难题抽象而来，继承了真实数学的复杂度profile |
| **联想网络密度** | 干扰数据模拟了真实数据基座的密度——在大量干扰中找相关Pattern正是真实场景 |
| **Pattern迁移有效性** | 最终用真实难题测试——直接验证迁移 |
| **覆盖度增长代表性** | 虚拟系统不再追求数量，而是追求"和真实挑战同构" |

### 对POC-VMS方案的修正

原方案VMS-0到VMS-5在虚拟系统内自包含完成，VMS-6才接触真实数学。新思路要求**从VMS-0开始就连接真实难题**：

| 阶段 | 原方案 | 修正后 |
|---|---|---|
| VMS-0 | 纯虚拟群论基础设施 | **+真实难题挑战抽象**：从MathArena 30道做不出的题中抽象挑战类型 |
| VMS-1 | 纯虚拟Pattern生成 | **+真实难题QA序列分析**：从矩条件极差题QA序列提炼真实Pattern作为对照 |
| VMS-2 | 纯虚拟小规模检索 | **+真实Pattern混入测试**：10个虚拟Pattern + 3-5个真实Pattern混合检索 |
| VMS-3 | 纯虚拟中规模检索 | **+干扰数据测试**：1000个虚拟Pattern作为干扰，找3-5个真实Pattern |
| VMS-4 | 纯虚拟大规模检索 | **+真实难题最终验证**：48,000虚拟干扰 + 真实难题进入系统 |
| VMS-5 | 纯虚拟闭环 | 不变（闭环验证在虚拟系统内完成） |
| VMS-6 | 跨域迁移 | **升级为全面验证**：真实难题+干扰数据的完整验证 |

### 真实难题资源

我们已有的真实难题资源——**25道AI做不出但有解答的真实难题**是POC-VMS挑战抽象的起点：

**核心资源：25道MathArena竞赛最难题**

| 资源 | 题量 | 有解答 | AI做不出 | 用途 |
|---|---|---|---|---|
| **MathArena 25道难题** | **25** | **✅** | **25/25做不出** | **挑战抽象的主要来源** |
| 矩条件极差题第二问 | 1道（10轮QA） | ✅ | ✅ | 详细QA序列分析 |
| FATE（北大博士资格考） | 350 | ✅Lean4 | ✅ | 高难度挑战抽象 |
| Berkeley Problems | 200 | ✅ | — | 研究生级挑战 |
| Hendrycks MATH Level 5 | ~2500 | ✅ | ✅ | 竞赛级挑战 |

**25道难题的构成**（详见 `runs/matharena_25_hard_problems.json`）：

| 类型 | 数量 | 来源 | 难度分布 |
|---|---|---|---|
| 数值题（有数值答案） | 23 | AIME 2024-2026 / BRUMO / HMMT / SMT / CMIMC / APEX | diff 76-164 |
| 证明题（有sample_solution） | 2 | USAMO 2026 P4/P5 | 竞赛最高难度 |

**25道题的AI表现**（GLM-5.2 Phase 1b验证，修复截断后）：
- 0/25做出来
- 21道stuck（AI看到完整题目但做不出）
- 3道no_answer_format（有思路但没给出boxed答案）
- 1道wrong_answer（推理有误）

**为什么从这25道题开始**：
1. **AI确实做不出**——两轮测试0/25，确认是真实能力边界
2. **有正确解答**——23道有数值答案，2道有sample_solution，可以分析"正确路径是什么"
3. **难度跨度大**——diff 76到164，从AIME #12到SMT #51，覆盖多种挑战类型
4. **类型多样**——数值题+证明题，代数/几何/数论/组合全覆盖
5. **已有baseline数据**——每道题有AI的完整response，可以分析AI为什么做不出

### 用户直觉思路的长期价值

> 用户原话："这是我的直觉思路，不一定都对，但是我的这些思路保留下来，对以后的系统发展之路，必然是极具启发意义的。"

这个思路的核心价值不在于具体实现细节，而在于**方向性原则**：

1. **虚拟系统必须被真实驱动**——不是自包含的玩具，而是被真实难题的挑战类型驱动
2. **干扰数据是必要条件**——真实运行场景就是"大量干扰中找少数相关"，没有干扰的测试不代表真实
3. **真实难题是最终裁判**——虚拟系统打磨得再好，最终必须用真实难题验证
4. **挑战抽象是桥梁**——不是直接用真实难题训练（数据太少），也不是纯虚拟训练（可能不相关），而是抽象挑战类型后在虚拟环境中批量训练

## 虚拟→真实有效性审查机制

> 虚拟数学系统验证对真实数学的价值，需要随时审查。不能等到VMS-6才发现虚拟→真实无效——必须在每个阶段嵌入审查。

### 5个审查维度

| 维度 | 审查问题 | 审查方法 |
|---|---|---|
| **先验知识污染** | AI在虚拟群论上的表现是否来自先验知识而非检索系统？ | 对比：AI裸跑虚拟群论 vs AI裸跑真实群论。如果表现相当，说明AI在用先验知识，检索系统没起作用 |
| **结构复杂度差距** | 虚拟群论的trigger_conditions复杂度是否代表真实数学？ | 对比：虚拟群论Pattern的trigger_conditions字段数 vs 矩条件极差题Pattern的字段数 |
| **联想网络密度** | 虚拟群论的联想网络是否和真实数学一样密集？ | 对比：虚拟群论中一个概念关联多少其他概念 vs 真实数学中一个概念关联多少 |
| **Pattern迁移有效性** | 虚拟Pattern能迁移到真实群论的哪些类型？ | 在VMS-6之前，每个阶段都做小规模迁移测试 |
| **覆盖度增长代表性** | 虚拟系统的Pattern增长速度是否代表真实系统？ | 对比：虚拟系统生成48000 Pattern需要多少解题 vs 真实系统生成同等Pattern需要多少 |

### 审查时机

不同阶段审查不同维度：

| 阶段 | 审查维度 | 理由 |
|---|---|---|
| VMS-0 | 先验知识污染 | baseline测试时就要检查AI是否在用先验知识 |
| VMS-1 | 结构复杂度差距 | Pattern生成时检查trigger_conditions复杂度 |
| VMS-2 | Pattern迁移有效性（小规模） | 10个Pattern时做初步迁移测试 |
| VMS-3 | 联想网络密度 | 1000个Pattern时检查网络密度 |
| VMS-4 | 覆盖度增长代表性 | 10000+ Pattern时检查增长速度 |
| VMS-5 | 覆盖度增长代表性（闭环） | 闭环跑通时检查真实增长速度 |
| VMS-6 | 全部维度 | 最终跨域迁移验证，全面审查 |

### Hard Gate

如果某个阶段审查发现虚拟→真实有效性不足，**必须停下来**，不能继续下一个阶段：

| 阶段 | Hard Gate条件 | 触发后的行动 |
|---|---|---|
| VMS-0 | AI裸跑虚拟群论正确率和裸跑真实群论差异<10% | 设计更强的虚拟系统（更彻底的随机化），或换AI先验知识更少的领域 |
| VMS-2 | 10个虚拟Pattern迁移到真实群论效果<无引导效果的1.2倍 | 重新设计Pattern结构 |
| VMS-4 | 虚拟系统Pattern增长速度和真实系统差距>10倍 | 虚拟系统只用于算法验证，不用于覆盖度估计 |

### Fallback方案

如果审查发现虚拟群论不可行，有备选方案：

| 风险发现 | Fallback方案 |
|---|---|
| 先验知识污染严重 | 换用AI先验知识更少的领域（虚拟公理系统/虚拟序论） |
| 结构太简单 | 扩展到更复杂的虚拟领域（虚拟环论/虚拟域论） |
| Pattern迁移无效 | 放弃虚拟系统，回到真实数学POC（接受数据量小的限制） |
| 覆盖度增长不可代表 | 虚拟系统只用于算法验证（Rete/MiniCon适配），不用于覆盖度估计 |
