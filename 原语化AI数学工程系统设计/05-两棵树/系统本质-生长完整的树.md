## 系统的本质：生长完整的解题记录树

把两棵树的本质厘清后，系统的本质也变得清晰了：

**数学大师系统的本质是：在不知道答案的情况下，通过引导展开机制，让AI生长出一棵尽可能完整的解题记录树。**

拆开说：
- **"不知道答案"** = 系统和AI都不知道正确路径，这是和"预演模式"的根本区别
- **"引导展开机制"** = 辅助智能体做模式识别，找到此刻应考虑的所有方向，注入提示驱动展开
- **"让AI生长出"** = 树是AI在提示下自己长出来的，不是系统预先画好的
- **"尽可能完整"** = 这是目标——不是只找一条成功路径，而是把所有值得探索的方向都探索到

### "更全"是什么意思

一棵完整的解题记录树包含：

| 组成 | 价值 | 没有系统时AI的表现 |
|---|---|---|
| 成功路径 | 这道题的解答 | AI可能找到1条或0条 |
| 失败路径 | 什么方向走不通、为什么 | AI卡住就停了，不记录失败 |
| 分叉点 | 在什么处境下有哪些方向 | AI只走自己想到的一个方向，不知道还有其他 |
| 中间处境 | 解题经过的各个状态 | AI不记录中间状态，只给最终答案 |

**裸跑的AI只产出一条路径（如果运气好），或者直接卡住（如果运气不好）。** 它不产出树——它不探索多个方向，不记录失败，不保留中间状态。

**系统的作用是让AI从"产出一条路径"升级为"产出一棵树"。** 通过引导展开，让AI在卡住时换方向，在岔口并发探索，把成功和失败都记录下来。

### 各组件的统一角色

如果系统的本质是"生长完整的解题记录树"，那之前讨论的所有组件都有了清晰的角色：

| 组件 | 在"生长树"中的角色 |
|---|---|
| 引导展开树 | 正在生长的树（过程） |
| 解题记录树 | 展开完成的树（产物） |
| 模式识别/检索 | 在每个节点决定"该往哪些方向展开"——树的分叉来源 |
| 辅助智能体 | 树的园丁——识别方向、注入提示、驱动展开 |
| 推理智能体 | 树的生长点——在每个节点做数学、产出下一个处境 |
| 稀疏矩阵/数据基座 | 模式识别的知识来源——决定分叉方向的依据 |
| 并发DFS | 同时展开多个分支——让树长得更快更全 |
| Level排序 | 决定展开顺序——优先展开高Level方向 |
| Hint梯度 | 控制每条边的"知识泄漏量" |
| 回溯铁律 | 不在同一Session回溯——保证树的每个分支context干净 |
| 四门审计 | 审计每条边是否泄漏答案——保证树的"诚实性" |
| 单任务双产出（伏羲） | 跑一次树的生长，同时产出树的解和数据基座条目 |

**之前这些组件看起来是分散的设计点，现在它们统一了——都是为了让树长得更全、更诚实、更可复用。**

### 数据基座是过去解题记录树的沉淀

数据基座（稀疏矩阵）的作用是什么？

**数据基座是过去解题记录树的沉淀——把过去树中的分叉点、成功路径、失败路径提炼成Pattern，供未来生长新树时做模式识别。**

- 过去的解题记录树 → 提炼 → 数据基座中的Pattern
- 未来的引导展开树 ← 模式识别 ← 数据基座中的Pattern

这是一个**自我增殖的循环**：树越长越全 → Pattern越积越多 → 模式识别越准 → 未来的树长得越全。

### 评测标准：不是"做没做出来"，而是"树长得多完整"

如果系统的本质是"生长完整的解题记录树"，那系统的能力边界不是"能不能做出某道题"，而是**"能长出多完整的树"**。

- **弱系统**：长出一条路径就停了（裸跑AI）
- **中等系统**：长出几条路径，找到一条成功的（当前guided实验）
- **强系统**：长出完整的树，所有值得探索的方向都探索到，成功路径和失败路径都记录，分叉点都标注（目标）
- **大师级系统**：长出的树足够完整，从中提炼的Pattern能让未来类似题的树长得更快更准

**评测系统不应该只看"做没做出来"，应该看"树长得多完整"。** 一道题做出来了但只探索了一条路径，不如一道题做出来了同时记录了5条失败路径和3个分叉点——后者才是更完整的解题记录树，才是更有价值的资产。

## 从面相4回指其他面相：系统全景

§6.8用面相4（树的生长）作为统一视角。但树的生长不是孤立的——它需要其他面相提供基础设施。从面相4回指其他6个面相，得到系统全景：

| 面相 | 在"树的生长"中的角色 | 回指位置 |
|---|---|---|
| 面相1·两种计算 | 树生长需要两种计算：经典计算做节点状态提取和拓扑验证（确定性部分），AI计算做模式识别和方向选择（非确定性部分） | [盘古-静态图前置](../03-四代系统/盘古-静态图前置.md)G'_topo+AQL、[伏羲-形式化边界推进](../03-四代系统/伏羲-形式化边界推进.md)"不自然"识别 |
| 面相2·语料双路径 | 树生长的知识来源有两条路径：路径1（训练）让AI有模式识别能力，路径2（抽取）让数据基座有Pattern。两条路径的产物在树生长中汇合——AI用训练获得的能力从数据基座的Pattern中做模式识别 | [伏羲-形式化边界推进](../03-四代系统/伏羲-形式化边界推进.md)[233]双重知识生产 |
| 面相3·Pipeline网络 | 树生长的执行基础设施——辅助智能体是模式识别引擎Pipe，推理智能体是数学推理引擎Pipe，Pipe之间的认知激活就是树的分叉机制 | [女娲-动态控制与角色隔离](../03-四代系统/女娲-动态控制与角色隔离.md)8角色 |
| **面相4·树的生长** | **系统本质——生长完整的解题记录树** | **本文件** |
| 面相A·实践涌现 | 树生长的设计从实践中涌现——guided实验暴露了串行DFS的局限，催生了并发DFS的洞察 | [燧人-非特定元认知提问](../03-四代系统/燧人-非特定元认知提问.md)guided实验、[并发展开](../04-核心洞察/并发展开.md) |
| 面相B·知识选取 | 树生长的设计从知识中选取——AQL/图论/形式化边界/伴随关系为树的生长提供数学基础 | [盘古-静态图前置](../03-四代系统/盘古-静态图前置.md)AQL、[伏羲-形式化边界推进](../03-四代系统/伏羲-形式化边界推进.md)形式化边界 |
| 面相C·设计过程自举 | 树生长的设计过程是自举的——四代演进是自举循环，每代暴露的差距催生下一代对树生长机制的改进 | [四代演进与互补共存](../03-四代系统/四代演进与互补共存.md) |

**系统全景**：数学大师系统通过引导展开机制生长解题记录树（面相4）。树的生长需要两种计算（面相1）——经典计算做确定性部分，AI计算做非确定性部分。两种计算通过Pipeline网络（面相3）执行——模式识别引擎Pipe决定分叉方向，数学推理引擎Pipe产出新节点。树生长的知识来自语料双路径（面相2）——AI的计算能力来自训练，Pattern来自数据基座抽取。四代演进（面相C）中，每代对树生长机制的改进来自实践涌现（面相A）或知识选取（面相B）。

## 对文档术语的统一修正

基于§6.7-6.8的讨论，本文档及关联文档中的术语应做以下修正：

| 旧术语 | 新术语 | 修正理由 |
|---|---|---|
| DFS引导架构 | 引导展开树 | DFS是遍历策略不是树的名字 |
| DFS树 | 引导展开树（展开中）/ 解题记录树（完成态） | 区分过程和产物 |
| 引导者用DFS维护这些方向 | 引导者维护引导展开树的分叉 | 去掉DFS预设 |
| 串行DFS / 并发DFS | 串行展开 / 并发展开 | 遍历策略有独立名字，不混入树名 |

**注意**：[214]第8章的"DFS引导架构"是历史命名，本文档在引用时保留原名但注明新命名。未来新文档应使用新术语。
