## §6 分类学作为排除机制

### §6.1 从"加速模型"到"排除模型"

Pipe 0的粗domain分类不仅是加速机制（快速定位相关区的Telling AI），更是**排除机制**（排除不相关区的Telling AI，避免不必要的devin cli启动）（337号）。

**之前的理解（加速模型）**：
```
trace → 分类 → 启动对应分类目录的devin cli → 遍历该分类的tell → 识别到tell → 找hint
```

**现在的理解（排除模型）**：
```
trace → 分类 → 排除不相关分类的devin cli → 保留相关分类的devin cli → 识别 → 找hint
```

### §6.2 排除的精确性

对一道数论题，排除"几何tell目录""组合tell目录"等。但"跨域tell目录"是否被排除，取决于这道题的trace是否可能涉及跨域——如果trace显示AI在数论内打转没跨域，"跨域tell目录"**不应该被排除**（因为可能需要提示跨域），反而应该被启动。

### §6.3 排除模型的意义

分类学的作用不是"加速找到正确的tell"，而是"排除不可能相关的tell目录"——缩小搜索空间的方式不是"精确定位"，而是"排除不可能的"。

对于无法被分类的内容（高Level概念作为坐标轴），它们无法被排除——但它们有专门的AGENTS.md目录和devin cli（338号修正），不是"始终在场"的背景知识。
