## §1 Telling AI提示词的设计目标

告诉辅助AI"你应该怎么分析thinking，应该形成什么样的识别结果"。

---

## §2 低Level Telling AI提示词的组成部分

### §2.1 提示词组成

1. **你的区里有哪些tell**（完整列表）——从AGENTS.md加载的该区tell内容
2. **当前推理AI的thinking**（完整文本）
3. **你的任务**（识别thinking中和你区的tell相关的trace）

### §2.2 分析thinking时关注什么

操作序列的结构、操作之间的关系、返回值模式。

### §2.3 识别trace时怎么判断"这是一个trace"

操作的累积构成有意义的模式。

### §2.4 局部trace和非局部trace的判断标准

单段vs跨段。

### §2.5 Telling AI返回格式

trace列表，每个trace包含：trace描述/局部或非局部/匹配的tell候选/置信度。

### §2.6 这是309号§8"规范化方法"的工程实现

不再是306号的四类提取规范（给机械提取的），是给AI分析的规范。

## §3 高Level Telling AI提示词模板

### §3.1 两种高Level Telling AI的提示词不同（340号）

高Level概念分两种类型，它们的Telling AI提示词不同：

- **第一种（可展开的）**——如构造-分析-排除：提示词包含概念解释+展开后的具体形式列表，识别逻辑是"遍历具体形式列表+理解概念"
- **第二种（方向型的）**——如同构之桥：提示词包含概念解释+例子+适用条件（无具体形式列表），识别逻辑是"理解概念+格化脉络+判断适用条件"

### §3.2 第一种高Level Telling AI提示词（可展开型）

提示词组成部分：
1. **你需要理解的高Level概念**——概念定义+识别型解释
2. **展开后的具体形式列表**——按展开维度预先降低Level的具体形式（如构造-分析-排除的3阶段×每阶段具体形式）
3. **当前推理AI的thinking**（完整文本）
4. **你的任务**——遍历具体形式列表，逐一匹配trace；同时理解概念，判断是否有列表外的概念适用情况

### §3.3 第二种高Level Telling AI提示词（方向型）

提示词组成部分：
1. **你需要理解的高Level概念**——从高Level AGENTS.md加载的概念定义+识别型解释+例子+适用条件+反pattern
2. **当前推理AI的thinking**（完整文本）
3. **你的任务**——不是遍历tell条目（因为没有具体形式列表可遍历），而是理解概念+格化脉络+判断适用条件

### §3.4 高Level Telling AI的识别型解释

高Level Telling AI加载的是**识别型解释**（335号§2.1，335号§3.2）：

> "同构之桥的trace pattern是____。识别特征：AI在____域内____。反pattern：如果AI已经____，则不是同构之桥缺失"

识别型解释关注"怎么识别"——知道跨域桥接的pattern长什么样，不是"怎么执行"（知道怎么跨域）。

### §3.5 高Level Telling AI的核心识别任务

提示词中必须完整描述以下识别任务（338号§3.5详解）：

```
你的任务是识别推理AI是否需要考虑使用[高Level概念名]这种思维。

具体步骤：
1. 拿到推理AI的上下文和trace
2. 理解[高Level概念名]——通过上面的充分描述和例子，达到充分理解
3. 对推理脉络做格化，找出有意义的Level视图
   - 最细Level视图：每个推理步骤是一段
   - 中间Level视图：几个步骤合并成一段
   - 最粗Level视图：整个脉络是一段
4. 在每个Level视图下，检查思维脉络的每个位置：
   - 这个位置是否是两个不同domain的段之间的交界处？
   - 推理AI在这个位置是否在同一个domain内反复尝试未突破？
   - 这个位置是否符合[高Level概念名]的适用条件？
5. 如果在某个Level视图的某个位置认定"推理AI应该考虑使用[高Level概念名]"
   → 识别到tell → 输出方向性hint
```

### §3.6 "某个推理脉络Level视角下的思维脉络的某个位置"的精确含义

这是高Level Telling AI识别任务中最核心的长短语。提示词模板中必须包含以下精确解释，让设计Telling AI提示词的人理解这个长短语的精确含义：

**"推理脉络"** = 推理AI的thinking/trajectory构成的脉络——从起点到当前节点的推理路径。一串推理步骤的序列A = (a1, a2, ..., an)。

**"推理脉络Level视角"** = 对推理脉络的一种Level视图——即"看法"（连续划分）。同一个脉络在不同Level视图下有不同的段结构：
- 最细Level视图：每个推理步骤是一段——B_finest = (a1), (a2), ..., (an)
- 中间Level视图：几个步骤合并成一段——如B = (a1), (a2,a3), (a4,a5), ...
- 最粗Level视图：整个脉络是一段——B_coarsest = (a1,a2,...,an)

**"某个推理脉络Level视角"** = 不是任意Level视图，是**某个特定的**Level视图——在这个视图下，高Level概念的tell才显现。跨域桥接在中间Level视图下才显现，在最细Level视图下看不到。

**"思维脉络"** = 推理AI的实际思维过程——和"推理脉络"指同一个东西，但强调的是"思维"的层面（AI在想什么），不是"步骤"的层面（AI做了什么操作）。

**"某个推理脉络Level视角下的思维脉络"** = 在某个特定Level视图下看到的思维脉络——不是最细视图下的一堆独立步骤，也不是最粗视图下的一个整体，而是某个中间视图下的几段思维。

**"某个位置"** = 在那个Level视图下的某个特定位置——某个段的边界处、某个段内部、或某两个段之间的交界处。同构之桥的tell通常出现在"两个不同domain的段之间的交界处"——比如数论段结束、椭圆曲线段开始的位置。

**完整含义**："某个推理脉络Level视角下的思维脉络的某个位置" = 在某个特定的中间Level视图下，思维脉络中的某个特定位置——这个位置是高Level概念tell显现的位置。

### §3.7 "考虑使用"和"想想新的解题进攻方向"

**"考虑使用[高Level概念名]这种思维"** = 不是"执行"（构造一个具体的实例），而是"考虑使用"——识别AI认定的是"推理AI在这里应该考虑这种思维方向"，不是"推理AI在这里应该已经构造好了实例"。

推理AI可能还不知道这种思维模式存在（277号的"范式引入"故事），"考虑使用"意味着识别AI认定"这里是一个应该引入这种思维模式的分叉点"——系统应该在这里给hint，让推理AI知道有这种思维方向。

**"想想新的解题进攻方向"** = 高Level概念的作用是打开思路，不是给出具体步骤。"新的"= 推理AI当前没有走的方向。"解题进攻方向"= 战略层面的方向。

**高Level hint的Level**：它给的是"进攻方向"（战略层），不是"具体步骤"（战术层）。识别AI认定的是"推理AI需要一个新的进攻方向"，高Level概念是这个新方向的名字。

### §3.8 高Level Telling AI返回格式

```
{
  "concept": "同构之桥",
  "recognized": true/false,
  "level_view": "中间视图B=(a1),(a2,a3),(a4,a5)",
  "position": "a3和a4之间的交界处——数论段结束、椭圆曲线段应开始的位置",
  "reasoning": "AI在数论域内尝试了3种方法未突破，未尝试跨域翻译",
  "directional_hint": "考虑使用同构之桥——把当前问题翻译到另一个数学领域",
  "confidence": 0.7,
  "layer3_empty": true  // 没有当前域案例，提示是方向性的
}
```
