## §1 FCA的数学框架

### §1.1 形式背景

形式背景(formal context) = (G, M, I)：
- G = 对象集合（在系统中对应具体tell）
- M = 属性集合（在系统中对应domain + 段结构模式 + 具体概念）
- I ⊆ G × M = 关系（对象g具有属性m当且仅当(g,m) ∈ I）

### §1.2 概念

概念 = (extent, intent)：
- extent（外延）= 所有具有intent中属性的对象集合
- intent（内涵）= 所有extent中对象共有的属性集合

### §1.3 概念格

概念格(concept lattice) = 所有概念的偏序集，按⊆关系组织。概念格是完备格——有上下确界，支持格遍历。

### §1.4 闭包算子

- extent的闭包 = 所有具有extent中对象共有属性的对象集合
- intent的闭包 = 所有extent中对象共有的属性集合

闭包算子保证查询的完备性——给定一组属性，闭包算子返回包含这组属性的最小概念。

## §2 FCA与工程方案的对应

| FCA概念 | 系统工程对应 |
|---|---|
| 形式背景(G,M,I) | tell分类学——tell集合G、属性维度M（domain+段结构模式+具体概念）、tell-属性关系I |
| 概念(extent,intent) | tell分类——一组tell(extent)共享一组属性(intent) |
| 概念格 | tell的组织结构——所有tell分类的偏序集 |
| 闭包算子 | 查询的完备性保证——给定属性查询tell，闭包算子返回所有满足条件的tell |
| 格遍历 | Pipe 1选择Telling AI实例——从概念格顶层遍历到特定子格 |

## §4 脉络格化（304号§8.11）

### §4.1 推理脉络

推理脉络 = 推理AI的thinking/trajectory构成的脉络——从起点到当前节点的推理路径。一串推理步骤的序列A = (a1, a2, ..., an)。

### §4.2 连续划分与Level视图

对推理脉络的"看法"（连续划分）= Level视图。同一个脉络在不同Level视图下有不同的段结构：
- 最细Level视图：每个推理步骤是一段——B_finest = (a1), (a2), ..., (an)
- 中间Level视图：几个步骤合并成一段——如B = (a1), (a2,a3), (a4,a5), ...
- 最粗Level视图：整个脉络是一段——B_coarsest = (a1,a2,...,an)

### §4.3 不同Level视图下不同tell显现

同一个推理脉络，在不同Level视图下，不同的tell才显现：
- 局部tell在最细Level视图下显现——单步操作的特征
- 非局部tell在中间Level视图下显现——跨段模式（追逐/桥接/构造-分析-排除）
- 全局tell在最粗Level视图下显现——整个脉络的特征

**跨域桥接（同构之桥）在中间Level视图下才显现**——需要看到至少两段不同domain的段，才能识别"AI在domain A内打转，没有桥接到domain B"。

## §5 高Level概念作为分类学坐标轴

### §5.1 高Level概念不是分类学中的"点"

高Level概念（如"同构之桥"）不是分类学中的"点"（被分类的对象），而是分类学的"坐标轴"（分类的维度本身）。

"跨域桥接"是段结构模式这个分类维度上的一个值——它是坐标轴上的一个刻度，不是被分类到一个类别中的对象。

降低Level后的具体形式（如"构造Frey曲线"）才是分类学中的"点"——它们有明确的{domain, 段结构模式}属性，可以被归入{跨域, 跨域桥接}这个分类。

### §5.2 坐标系类比

```
分类学 = 坐标系
  domain = x轴（数论/代数/组合/几何/分析/跨域）
  段结构模式 = y轴（构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛）
  
具体tell/hint = 坐标系中的点
  "构造Frey曲线" = (跨域, 跨域桥接) ← 这个点在坐标系中有明确位置
  
高Level概念"同构之桥" = y轴上"跨域桥接"这个刻度的名字
  它不是坐标系中的点——它是坐标轴的组成
  你不能把y轴的刻度放入坐标系中定位——它是坐标系本身的组成
```

**高Level概念是分类学的结构，不是分类学的内容。**

### §5.3 结构知识与内容知识分离

| 知识类型 | 内容 | 存储位置 |
|---|---|---|
| **结构知识**（不可分类的） | domain定义、段结构模式定义、子模式定义（如"同构之桥"是"跨域桥接"的子模式）、高Level概念的三种解释文本 | 分类学Schema + 高Level概念解释库 |
| **内容知识**（可分类的） | 具体tell条目、具体hint条目，每个条目有{domain, 段结构模式}属性和`case_source`标记 | tell库/hint库 |

结构知识定义分类学本身（坐标轴和刻度），内容知识被分类学分类（坐标系中的点）。修改结构知识等于修改分类学的维度，影响所有使用该分类的tell；修改内容知识只是增删tell条目，不影响分类学的维度。

### §5.4 FCA概念格中的坐标轴与点

在FCA框架中：
- **坐标轴**（结构知识）= 属性集合M的定义——M中有哪些属性（domain值、段结构模式值），这些是概念格的维度定义
- **点**（内容知识）= 对象集合G中的元素——每个tell是一个对象，它在概念格中的位置由它的属性确定

概念格的"格结构"由M的定义决定（坐标轴），概念格中的"概念"由G和I共同决定（点）。修改M会改变整个概念格的结构，修改G只改变概念格中的概念数量和位置。

## §6 FCA和概念膨胀应对

概念格的层次结构天然支持概念膨胀的应对——新tell加入时更新概念格，不影响已有层次。新tell作为新对象加入G，根据其属性在概念格中找到位置，不需要修改已有的概念定义。
