## §1 为什么需要高Level概念解释库

### §1.1 核心问题

高Level概念（如"同构之桥""构造-分析-排除""探索-诊断-修复""归约策略""累积-收敛"）可以被AI理解，但前提是**说清楚**。不是一句抽象的话（如"考虑同构之桥"），而是定义+例子+为什么有用的完整解释。

277号曾经判断"同构之桥这种极高Level hint，可能即便给了AI，它也是不知道如何做的"。这个判断的前提是"hint只给了一个术语'同构之桥'"。如果hint给的是完整的解释（定义+例子+怎么用），这个判断需要修正为：

> 高Level概念如果被充分解释（定义+例子+怎么用），AI是可以理解的。277号说的"AI不知道这种思维模式存在"——通过在hint中附带充分解释，AI就知道了这种思维模式存在。问题从"AI不知道"变为"系统是否把概念说清楚了"。

### §1.2 与降低Level的关系

281号方案是"提前全部Low Level化"——把高Level概念展开为具体形式列表。本文件提出另一条路径：**不降低Level，而是充分解释高Level概念本身**。

两条路径不矛盾——可以并发存在（333号的并发思想）：
- 充分解释高Level概念（本文件）→ AI理解了概念，自己尝试找具体形式
- 降低Level到具体形式列表（281号）→ 直接给AI具体形式

前者依赖AI的理解力和数学知识，后者依赖预先展开的完备性。两者并发，互为补充。

## §2 同一个高Level概念需要三种不同的解释

系统运行时涉及AI的环节有五个：

| 环节 | AI角色 | 输入 | 产出 |
|---|---|---|---|
| A. 推理AI收到hint后解题 | 解题 | 脉络+hint | thinking |
| B. Telling AI识别trace | 读thinking识别tell | thinking文本 | tell列表 |
| C. tell→hint映射 | 系统内部匹配 | tell | hint候选 |
| D. 脉络构造 | 构造给新AI的输入 | 路径+hint | 脉络文本 |
| E. 动态生成方向 | 根据题目内容生成跨域方向 | 题目+thinking | 方向性hint |

逐环节分析是否需要高Level概念解释：

| 环节 | 需要解释吗 | 解释侧重点 | 解释对象 |
|---|---|---|---|
| A. 推理AI收到hint | **需要** | 怎么做（定义+例子+怎么用） | 所有出现在hint中的高Level概念 |
| B. Telling AI识别trace | **需要** | 怎么识别（定义+pattern特征+反pattern） | 所有用来识别trace的高Level概念 |
| C. tell→hint映射 | 不需要 | — | — |
| D. 脉络构造 | 需要（=A的解释落点） | 同A | 同A |
| E. 动态生成方向 | **需要** | 什么时候用（定义+适用条件+判断标准） | 所有用来判断"是否适用"的高Level概念 |

### §2.1 三种解释文本

"同构之桥"这一个高Level概念，在三个环节需要三种不同的解释：

| 环节 | 解释类型 | 解释内容 |
|---|---|---|
| A/D（推理AI） | **执行型解释** | "同构之桥是____。例子：FLT中____。你可以这样用：先看当前问题有没有____特征，如果有，尝试构造____" |
| B（Telling AI） | **识别型解释** | "同构之桥的trace pattern是____。识别特征：AI在____域内____。反pattern：如果AI已经____，则不是同构之桥缺失" |
| E（动态生成AI） | **判断型解释** | "同构之桥适用于____类问题。判断标准：如果题目有____特征，则可能适合同构之桥。不适用于____类问题" |

**这意味着**：高Level概念的"充分解释"不是一个东西，是三个东西——同一个概念的三种视角（执行/识别/判断）。系统需要为每个高Level概念准备三种解释文本，在不同环节注入不同的解释。

### §2.2 三种解释的关系

三种解释描述的是同一个概念，但从不同视角、用不同语言、服务于不同决策：
- **执行型解释**关注"怎么做"——给推理AI用的，它需要知道如何执行这个概念
- **识别型解释**关注"什么时候需要"——给Telling AI用的，它需要知道在trace中识别什么特征
- **判断型解释**关注"值不值得"——给动态生成AI用的，它需要判断在当前处境下是否值得尝试这个方向

## §3 高Level概念的存储和使用方式

### §3.1 低Level部分和高Level部分的存储使用方式相同

高Level部分和低Level部分的存储和使用方式**相同**：
- 都是放到一个AGENTS.md目录中
- 都有devin cli从中启动
- devin cli中的AI对推理AI的上下文及其中的trace进行识别

**区别在描述方式，不在存储和使用方式**：
- 低Level部分：具体tell条目，如"AI未尝试从a^p+b^p=c^p构造椭圆曲线E: y²=x(x-a^p)(x+b^p)"——这本身就是具体的，不需要额外解释
- 高Level部分：不能只是一句很抽象的话（如"考虑同构之桥"），要"说清楚"+带例子

### §3.2 低Level和高Level的完整对比

| 方面 | 低Level部分 | 高Level部分 |
|---|---|---|
| 存储位置 | 单独目录的AGENTS.md文件 | 单独目录的AGENTS.md文件 |
| 使用方式 | devin cli从中启动，对推理AI的上下文及trace进行识别 | devin cli从中启动，对推理AI的上下文及trace进行识别 |
| 承载内容 | 可分类的具体tell（如"构造Frey曲线"） | 高Level概念（如"同构之桥"）及其充分描述+例子 |
| 描述方式 | 具体tell条目，本身即具体，不需要额外解释 | 不能只是一句抽象的话，要"说清楚"+带例子 |
| 识别逻辑 | 遍历tell条目，逐一匹配trace | 理解概念+格化脉络+判断适用条件 |
| 产出 | 识别到具体tell → 找hint | 认定需要新的进攻方向 → 给方向性hint |

### §3.3 高Level AGENTS.md目录的结构

高Level AGENTS.md目录中应该包含：
1. **高Level概念的定义**——这个概念是什么
2. **三种解释文本**——执行型/识别型/判断型（§2.1）
3. **例子**——让识别AI通过例子理解概念
4. **适用条件**——在什么条件下应该认定需要这个概念
5. **反pattern**——什么情况下不是这个概念的适用场景

devin cli启动时根据角色加载对应的section：
- 推理AI收到hint时 → 加载执行型解释
- Telling AI识别trace时 → 加载识别型解释
- 动态生成AI判断方向时 → 加载判断型解释

## §4 高Level概念作为分类学的坐标轴

### §4.1 高Level概念不是分类学中的"点"

高Level概念（如"同构之桥"）不是分类学中的"点"（被分类的对象），而是分类学的"坐标轴"（分类的维度本身）。

"跨域桥接"是段结构模式这个分类维度上的一个值——它是坐标轴上的一个刻度，不是被分类到一个类别中的对象。

降低Level后的具体形式（如"构造Frey曲线"）才是分类学中的"点"——它们有明确的{domain, 段结构模式}属性，可以被归入{跨域, 跨域桥接}这个分类。

### §4.2 坐标系类比

```
分类学 = 坐标系
  domain = x轴（数论/代数/组合/几何/分析/跨域）
  段结构模式 = y轴（构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛）
  
具体tell/hint = 坐标系中的点
  "构造Frey曲线" = (跨域, 跨域桥接) ← 这个点在坐标系中有明确位置
  
高Level概念"同构之桥" = y轴上"跨域桥接"这个刻度的名字
  它不是坐标系中的点——它是坐标轴的组成
  你不能把y轴的刻度放入坐标系中定位——它是坐标系本身的组成
```

**高Level概念是分类学的结构，不是分类学的内容。**

### §4.3 结构知识与内容知识的分离

| 知识类型 | 内容 | 存储位置 |
|---|---|---|
| **结构知识**（不可分类的） | domain定义、段结构模式定义、子模式定义（如"同构之桥"是"跨域桥接"的子模式）、高Level概念的三种解释文本 | 分类学Schema + 高Level概念解释库（本文件） |
| **内容知识**（可分类的） | 具体tell条目（如"AI未尝试从整数方程构造椭圆曲线"）、具体hint条目（如"构造Frey曲线"） | tell库/hint库 |

结构知识定义分类学本身（坐标轴和刻度），内容知识被分类学分类（坐标系中的点）。

### §4.4 高Level概念在系统中的承载方式

| 内容 | 承载位置 | 形式 |
|---|---|---|
| "跨域桥接"作为段结构模式 | AGENTS.md分类学Schema节 | 属性维度定义（y轴刻度） |
| "同构之桥"作为跨域桥接的子模式 | AGENTS.md分类学Schema节 | 子模式定义 |
| "同构之桥"的三种解释文本 | 高Level概念解释库（本文件） | 独立的解释文本 |
| "同构之桥"降低Level后的具体tell/hint | tell库/hint库 | 可分类的条目，有{跨域,跨域桥接}属性 |
| FLT案例的完整hint链 | tell库/hint库，标记`case_source: mathematics` | 可分类的条目 |

## §5 高Level Telling AI的识别任务

### §5.1 识别AI的任务

从高Level AGENTS.md目录启动的识别AI（devin cli中的AI）的任务是：

1. 拿到推理AI的上下文和trace
2. 理解高Level概念（如"同构之桥"）——通过AGENTS.md中的充分描述+例子，达到"充分理解"
3. 对推理脉络做格化（304号§8.11），找出有意义的Level视图
4. 在每个Level视图下，检查思维脉络的每个位置：
   - 这个位置是否是两个不同domain的段之间的交界处？
   - 推理AI在这个位置是否在同一个domain内反复尝试未突破？
   - 这个位置是否符合同构之桥的适用条件（AGENTS.md中描述的条件）？
5. 如果在某个Level视图的某个位置认定"推理AI应该考虑使用同构之桥" → 识别到tell → 从tell找到hint → 输出方向性hint

**关键**：识别AI不是在遍历具体tell条目，而是在**理解高Level概念后，在格化后的脉络的特定Level视图的特定位置，判断当前trace是否符合这个概念的适用条件**。这和低Level部分的"遍历tell库"不同——高Level部分是"理解概念 + 格化脉络 + 判断适用性"。

### §5.2 "某个推理脉络Level视角下的思维脉络的某个位置"的精确含义

这是高Level Telling AI识别任务中最核心、最需要精确理解的长短语。逐层拆解：

**"推理脉络"** = 推理AI的thinking/trajectory构成的脉络——从起点到当前节点的推理路径。一串推理步骤的序列A = (a1, a2, ..., an)。

**"推理脉络Level视角"** = 对推理脉络的一种Level视图——即"看法"（连续划分）。同一个脉络在不同Level视图下有不同的段结构：
- 最细Level视图：每个推理步骤是一段——B_finest = (a1), (a2), ..., (an)
- 中间Level视图：几个步骤合并成一段——如B = (a1), (a2,a3), (a4,a5), ...
- 最粗Level视图：整个脉络是一段——B_coarsest = (a1,a2,...,an)

**"某个推理脉络Level视角"** = 不是任意Level视图，是**某个特定的**Level视图——在这个视图下，同构之桥的tell才显现。跨域桥接在中间Level视图下才显现，在最细Level视图下看不到。

**"思维脉络"** = 推理AI的实际思维过程——和"推理脉络"指同一个东西，但强调的是"思维"的层面（AI在想什么），不是"步骤"的层面（AI做了什么操作）。

**"某个推理脉络Level视角下的思维脉络"** = 在某个特定Level视图下看到的思维脉络——不是最细视图下的一堆独立步骤，也不是最粗视图下的一个整体，而是某个中间视图下的几段思维。

**"某个位置"** = 在那个Level视图下的某个特定位置——某个段的边界处、某个段内部、或某两个段之间的交界处。同构之桥的tell通常出现在"两个不同domain的段之间的交界处"——比如数论段结束、椭圆曲线段开始的位置。

**完整含义**："某个推理脉络Level视角下的思维脉络的某个位置" = 在某个特定的中间Level视图下，思维脉络中的某个特定位置——这个位置是同构之桥tell显现的位置。

### §5.3 "考虑使用"和"想想新的解题进攻方向"

**"考虑使用同构之桥这种思维"** = 不是"执行同构之桥"（构造一个具体的桥），而是"考虑使用"——识别AI认定的是"推理AI在这里应该考虑这种思维方向"，不是"推理AI在这里应该已经构造好了桥"。

推理AI可能还不知道同构之桥这种思维模式存在（277号的"范式引入"故事），"考虑使用"意味着识别AI认定"这里是一个应该引入这种思维模式的分叉点"——系统应该在这里给hint，让推理AI知道有这种思维方向。

**"想想新的解题进攻方向"** = 同构之桥的作用是打开思路，不是给出具体步骤。"新的"= 推理AI当前没有走的方向。"解题进攻方向"= 战略层面的方向——"从数论跨到椭圆曲线"是一个进攻方向，"构造Frey曲线"是这个方向下的具体步骤。

**同构之桥hint的Level**：它给的是"进攻方向"（战略层），不是"具体步骤"（战术层）。识别AI认定的是"推理AI需要一个新的进攻方向"，同构之桥是这个新方向的名字。

### §5.4 整句完整含义

> 让从高Level AGENTS.md目录启动的识别AI，通过AGENTS.md中的充分描述和例子，深度理解：在什么条件下，应该认定推理AI的trace——在某个特定的中间Level视图下，思维脉络中的某个特定位置（通常是两个不同domain的段之间的交界处）——呈现出"推理AI应该考虑使用同构之桥这种思维方向，打开一个新的解题进攻方向"的特征。

## §6 高Level概念解释库的存储schema

### §6.1 每个高Level概念的三种解释文本

每个高Level概念在解释库中有三条记录：

```
{
  "concept_name": "同构之桥",
  "parent_pattern": "跨域桥接",
  "explanations": {
    "execution": {
      "type": "执行型解释",
      "target_role": "推理AI",
      "content": "同构之桥是____。例子：FLT中____。你可以这样用：____",
      "examples": ["FLT: a^p+b^p=c^p → Frey曲线 → 模形式"]
    },
    "recognition": {
      "type": "识别型解释",
      "target_role": "Telling AI",
      "content": "同构之桥的trace pattern是____。识别特征：AI在____域内____。反pattern：____",
      "examples": ["AI在数论域内反复尝试未突破，未尝试跨域翻译"]
    },
    "judgment": {
      "type": "判断型解释",
      "target_role": "动态生成AI",
      "content": "同构之桥适用于____类问题。判断标准：____。不适用于____类问题",
      "examples": ["适用于：问题结构有跨域对应关系。不适用于：纯计算问题"]
    }
  }
}
```

### §6.2 当前需要解释的高Level概念

高Level概念分两种类型（340号），它们的展开特性和处理策略不同：

| 高Level概念 | 父段结构模式 | 类型 | 展开维度 | 处理策略 |
|---|---|---|---|---|
| 构造-分析-排除 | 构造-分析-排除 | 第一种（可展开） | 3阶段×每阶段若干具体形式 | 预先降低Level + 充分解释 |
| 累积-收敛 | 累积-收敛 | 第一种（可展开） | 2阶段×每阶段若干具体形式 | 预先降低Level + 充分解释 |
| 探索-诊断-修复 | 探索-诊断-修复 | 第一种（可展开） | 3阶段×每阶段若干具体形式 | 预先降低Level + 充分解释 |
| 归约策略 | 归约策略 | 第一种（可展开，展开维度不如前三个明确） | 归约到什么类型×怎么归约 | 预先降低Level + 充分解释 |
| 同构之桥 | 跨域桥接 | 第二种（无法指定展开方向） | 无——目标领域开放 | 充分解释 + 启发式触发 + 案例积累 |

**第一种（可展开的）**：概念本身定义了展开的维度——概念是过程型的，描述了多步骤过程，每个步骤（阶段）就是一个展开方向。可以按展开维度预先列举具体形式，存入tell库。组合爆炸风险可控，覆盖缺口风险低。

**第二种（无法指定展开方向的）**：概念本身不定义展开的维度——概念是方向型的，只告诉你一个动作方向是可能的，但不告诉你往哪些具体方向展开。不能预先降低Level（目标领域开放，无法穷举）。组合爆炸风险高，覆盖缺口风险永远存在。主要靠充分解释+启发式触发+案例积累来处理。

### §6.2.1 第一种概念的展开维度

**构造-分析-排除**的展开维度：
```
构造-分析-排除
  ├── 构造方向：构造什么对象？（辅助函数/反例/序列递推/图组合对象）
  ├── 分析方向：分析什么性质？（极值最值/单调性凸性/对称性不变量/渐近行为）
  └── 排除方向：排除什么可能？（矛盾情况/不满足约束的/被反例否定的）
```

**累积-收敛**的展开维度：
```
累积-收敛
  ├── 累积方向：累积什么类型的信息？（数值数据/解析表达式/不等式关系）
  └── 收敛方向：用什么方式收敛？（极限收敛/归纳收敛/递推收敛）
```

**探索-诊断-修复**的展开维度：
```
探索-诊断-修复
  ├── 探索方向：探索什么？（特殊情形/极端情形/简化版本）
  ├── 诊断方向：诊断什么gap？（方法不适用/假设不满足/方向错误）
  └── 修复方向：怎么修复？（换方法/加强减弱假设/换方向）
```

**归约策略**的展开维度：
```
归约策略
  ├── 归约到什么类型的小问题？（更小的n/更弱的命题/已知结论/特殊情况）
  └── 怎么归约？（直接归约/分步归约/反证归约）
```

### §6.2.2 第二种概念为什么无法指定展开方向

**同构之桥**="把问题从一个领域翻译到另一个领域"。

"另一个领域"是什么？概念本身不告诉你——翻译的目标领域完全取决于具体问题的结构：

```
同构之桥
  ├── 翻译到哪个领域？← 概念本身无法回答
  │    ├── FLT：数论 → 椭圆曲线 → 模形式
  │    ├── Brouwer：拓扑 → 组合（Sperner引理）
  │    ├── Brouwer：拓扑 → 代数拓扑（同调群）
  │    ├── 某代数问题：代数 → 表示论
  │    ├── 某组合问题：组合 → 概率
  │    └── ... 无限开放
  └── 怎么翻译？← 也取决于具体问题
       ├── 构造对应对象（Frey曲线）
       ├── 建立范畴等价
       ├── 翻译不变量
       └── ... 每个案例不同
```

FLT案例指明了"数论→椭圆曲线"这个方向，Brouwer案例指明了"拓扑→组合"这个方向——但这些是**案例指明的方向**，不是**概念本身内含的方向**。在没有案例的领域，你不知道应该翻译到哪——这就是334号讨论的"层3为空"问题。

### §6.3 解释库的维护

高Level概念的解释文本需要随系统演进更新。更新的触发条件：
- 发现新的成功案例（如新的跨域桥接证明）→ 更新执行型解释的例子
- 发现新的trace识别特征 → 更新识别型解释的pattern特征
- 发现新的适用/不适用条件 → 更新判断型解释的判断标准
