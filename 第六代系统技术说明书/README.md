## 1. 第六代系统是什么

第六代系统是第五代系统的演进，仍然是一个**引导式数学解题系统**。它的核心思想不变：

> 一个AI（推理AI）在做数学题时可能会走错路。另一个AI（辅助AI）观察推理AI的完整思维过程，识别出那些"可以分叉但AI没分叉"的位置，在这些位置上匹配一个新的探索方向，然后启动一个新的推理AI走这个新方向。一道题的探索过程长成一棵树——而不是一条路。

第六代相对于第五代的核心变化可以概括为三点：

- **trace→tell→hint 三步链路**：辅助AI从thinking中识别出trace（结构化识别结果），用trace查库匹配到tell（标准化描述），从tell关联取出hint（方向提示）。三步动作不同——发现、匹配、取用。替代了第五代tell+hint二元组中tell身兼两职（既是识别结果又是库内容）的混淆。
- **并发Telling AI**：Pipe 2从单AI串行变为多Telling AI并行。每个Telling AI负责一个tell分区，带着自己区的tell视角理解thinking，产出自己区视角下的trace。汇总AI从各Telling AI的trace中精筛出最终tell。
- **Pipe 0简化**：从精确拓扑化（3维度8种组合+手工信号词）降级为粗domain分类（数论/代数/组合/几何/跨域），用LLM轻量判断或题目domain标签。Pipe 1角色从"缩小tell范围"变为"选择启动哪些区的Telling AI"。

## 2. 系统全景图

```
推理AI在解题（走了一条路，产生了thinking）
     │
     ▼
[Pipe 0 简化] 粗domain分类——判断thinking属于哪些domain
     │          数论 / 代数 / 组合 / 几何 / 跨域
     │          实现：LLM轻量判断 / 题目domain标签 / thinking开头分类
     ▼
[Pipe 1 新角色] 选择Telling AI实例——根据domain分类确定启动哪些区的Telling AI
     │            不再是缩小tell范围，而是选择Telling AI实例
     ▼
[Pipe 2 并行化] 多Telling AI并行trace识别
     │
     ├── Telling AI #数论 [thinking + 数论区tell] → trace集合#数论
     ├── Telling AI #代数 [thinking + 代数区tell] → trace集合#代数
     └── ...（只启动相关区，不是全部N个区）
     │
     ▼
[汇总AI] 从各Telling AI的trace中精筛——去重/排序/冲突解决
     │     处理几十个trace（不是4164个tell）
     ▼
trace → 匹配tell（库中标准化描述）→ 取出hint（方向提示）
     │
     ▼
构造脉络（从根到当前节点的路径+方向Q）
     │
     ▼
启动新推理AI（给它脉络+方向，在全新Session中运行）
     │
     ▼
新AI走新分支 → 两棵树生长（引导展开树+解题记录树）
     │
     ▼
在终点节点检索 → 识别新trace → 匹配新tell → 取出新hint → 启动新AI → ...
     │
     ▼
某条脉络到达正确解答 → 停机
```

## 3. 六代演进定位

数学大师系统经历了六代演进：

| 代际 | 神话名 | 核心理念 | 在第六代中的角色 |
|---|---|---|---|
| 第一代 | 盘古 | 静态图前置——Master预先知道路线 | 提供拓扑覆盖验证、meta/normal分离、确定性图遍历 |
| 中间代 | 女娲 | 动态控制+角色隔离 | 提供外显思维图T、W_t六类分量、8角色隔离、Hint梯度 |
| 第二代 | 燧人 | 非特定元认知提问——不给答案给启发 | 提供形状匹配、Level连续谱、DFS引导架构、回溯铁律 |
| 第三代 | 伏羲 | 形式化边界推进 | 提供识别"不自然"、两种计算、数据基座、路径结构匹配 |
| 第五代 | （集大成者） | tell+hint二元组+三层Pipe架构+概念树 | 第六代的直接基础——trace/tell/hint命名、概念树、引导树闭环均继承自第五代 |
| **第六代** | **（待命名）** | **trace→tell→hint三步链路 + 并发Telling AI + Pipe 0简化** | **并发化、粗分类化、非局部trace正式化** |

第六代从第五代继承了核心架构（引导树闭环、两棵树、概念树、hint端），但有4项独特贡献是第五代没有的：
1. trace/tell/hint三步链路命名（309号）
2. 并发Telling AI——Pipe 2并行化（311号）
3. Pipe 0简化——从精确拓扑化到粗domain分类（311号）
4. 非局部trace的正式化——局部trace和非局部trace统一为trace，用修饰词区分（303/305/309号）

## 5. 文件格式约定

每个文件包含以下结构：

- **标题**：文件的主题
- **前置阅读**：理解本文件需要先读的文件（如有）
- **关联文件**：与本文件有概念交叉的文件
- **正文**：自包含的内容，不依赖其他文件即可理解
- **来源**：内容来自哪些已加载文档（第六代研发过程文档303-311号 + 第五代技术说明书 + dev-docs）

## 6. 关键约定

- **自包含原则**：每个文件可以独立阅读。新概念在首次出现时给出完整解释，不假设读者已经读过其他文件。
- **术语一致性**：trace/tell/hint/Pipe/拓扑/概念树等术语在全说明书中的定义一致，详见09-附录/01-术语表.md。
- **和第五代的关系**：第六代技术说明书中继承自第五代的内容会明确标注"继承自第五代"，新增内容会标注"第六代新增"。读者可以对照第五代技术说明书理解继承关系。
- **代码引用**：涉及工程实现的内容会引用具体代码文件和函数名，但不包含完整代码。
