# 闭环（loop）

## 定义

闭环不是"AI提出意义，经典计算兑现意义"——闭环是形式化边界的推进过程。每一次闭环运行：AI读取当前处境和证书账本，提出语义移动，移动通过执行契约编译成经典计算任务，经典计算执行返回结果，结果反射回语义场更新处境，同时写入数据基座。循环往复，边界逐步推进。

## 指导了什么

- **execution-contract 的协议设计**：闭环每一步通过执行契约编译语义移动成经典计算任务——执行契约是闭环每一步的协议，其四字段结构直接服务于闭环的运行。
- **certificate 的产生时机**：闭环每一步尝试产生证书——成功→证书加入账本（边界推进），反例→反驳证书加入（边界推进——排除错误方向），障碍→诊断反馈加入反馈层（边界以外的信号），未知→保留为待解释的压力。这定义了证书在系统中的产生时机和类型。
- **data-pedestal 的写入时机**：闭环的每一步写入数据基座（单任务双产出）——这定义了数据基座的写入时机和内容。
- **situation 的更新机制**：闭环每一步更新处境S_t → S_{t+1}——结果反射回语义场，更新处境。这指导了处境的生长机制设计。

## 适用边界

- **完整闭环从未实现**：闭环从未被实现为一个完整的运行系统。239号§17定义了闭环的动力学（6步循环），但没有跑过一次完整的闭环。
- **guided_001是简化版闭环，不是系统级闭环**：guided_001可以被视为闭环的特例——但缺少经典计算的系统级参与和证书账本。guided_001的"闭环"是AI内部的闭环：AI读取处境（通过Q被激活感知）→AI提出语义移动（中心化、找q(x)）→AI自己执行（没有系统级经典计算）→结果改变处境（找到新方向）→没有证书账本（没有持久化）→没有数据基座写入（单任务单产出）。所以guided_001是闭环的"AI内部"版本，不是239号的"系统级"版本。
- **闭环与认知激活的关系未整合**：239的闭环里AI直接感知"不自然"，不需要被问问题。但guided_001表明AI裸跑时感知能力不够——需要被问问题才能激活。闭环需要整合认知激活吗？如果需要，提问在闭环的哪一步？这是未解决的张力。
- **停止条件未定义**：闭环什么时候停止？当问题被解决（成功叶）？当所有方向都失败（死路叶）？当超时（截断叶）？需要明确的停止条件。

- **239号§6/§17**：给出闭环的完整定义和6步动力学：

### 闭环动力学（6步）

```
循环：
  1. AI读取当前处境S_t和证书账本I_t，提出语义移动m
  2. m通过执行契约编译成经典计算任务
  3. 经典计算执行，返回结果r
     - 成功 → 证书c加入I_t（边界推进）
     - 反例 → 反驳证书加入I_t（边界推进——排除错误方向）
     - 障碍 → 诊断反馈加入反馈层（边界以外的信号）
     - 未知 → 保留为待解释的压力
  4. 结果r反射回语义场，更新S_t → S_{t+1}
  5. 同时，这一步的记录写入数据基座（单任务双产出）
  6. 回到1
```

### 核心原则

> 语义可以自由探索，但每一轮都要尝试产生可兑现的证书；证书可以局部失败，但每一次失败都要回流成更好的语义理解。

### 闭环的力量

闭环的力量不在于让AI更聪明，而在于让每一次感知都变成不可逆的进展。

一个更强的AI模型但没有闭环，可能不如一个稍弱的AI模型但有完整闭环——因为前者只能产生"可能的意义"，后者能把意义不断压成"可确认的资产"。

## 开放问题

### 1. 闭环和认知激活的关系

239的闭环里AI直接感知"不自然"，不需要被问问题。但guided_001表明AI裸跑时感知能力不够——需要被问问题才能激活。闭环需要整合认知激活吗？如果需要，提问在闭环的哪一步？

### 2. 闭环怎么实现

6步循环是清晰的，但实现需要：AI怎么读取处境和证书账本？语义移动怎么编译成经典计算任务？经典计算的结果怎么自动回流？这些都需要具体的工程实现。

### 3. 闭环的停止条件

闭环什么时候停止？当问题被解决（成功叶）？当所有方向都失败（死路叶）？当超时（截断叶）？需要明确的停止条件。
