# 336号 · 综合分析阶段文件拆分流程控制方案——不会退化的4阶段拆分

**日期**：2026-08-11
**状态**：方案设计（待实现）
**来源**：335号方案D验证通过后，用户提出"最后一步是不是可以进行系统化的步骤拆分，让每一步的thinking时间没有那么长，而且也不会发生退化？"

---

## 1. 问题背景

脉络分析三阶段架构的综合分析阶段（阶段2）目前是一个完整的AI session完成所有工作——6步+审计。0009运行中综合分析阶段耗时约8分钟。

V8格化阶段已通过文件拆分流程控制（方案D）成功将thinking从8分钟降到4分钟。现在的问题是：综合分析阶段是否也可以做文件拆分流程控制？

**关键约束**：不能退化。V8的4步文件拆分方案曾导致退化（段数21 vs 32），根因是"段划分和特征标注是同一个认知过程，拆分后step1禁止标注特征→改变了认知内容→退化"。综合分析的文件拆分必须避免这个问题。

## 2. 综合分析各步骤的依赖关系分析

### 步骤、输入、产出

| 步骤 | 依赖什么输入 | 产出 |
|---|---|---|
| step1 综合对比4版本 | 4版本segments.json+fc.json | 选择基础格化+看法差异 |
| step2 形式上下文回溯 | step1的选择+闭元素清单 | 修正建议 |
| step3 nonlocal trace | 段内容(input.md)——不依赖闭元素 | nonlocal traces |
| step4 闭元素语义解读 | 闭元素清单——独立于step3 | 入选/排除判定 |
| step5 跨闭元素元模式 | step4的闭元素解读+key_entities | cemp traces |
| step6 cross_case_merge | 段内容——不依赖闭元素 | ccm traces |
| step6B global trace | 段内容——不依赖闭元素 | global traces |
| step7 审计 | 所有trace | 去冗余+质量检查 |

### 依赖图

```
step1(对比) → step2(回溯)
step3(nonlocal) ← 独立，只需段内容
step4(闭元素解读) ← 独立，只需闭元素清单
step5(跨闭元素元模式) ← 需要step4
step6(ccm) ← 独立，只需段内容
step6B(global) ← 独立，只需段内容
step7(审计) ← 需要所有trace
```

### 高独立性分析

**高独立性步骤**（只需段内容，不依赖闭元素）：
- step3(nonlocal) + step6(ccm) + step6B(global) → 可以合并为一步

**闭元素相关步骤**：
- step4(闭元素解读) + step5(跨闭元素元模式) → 可以合并为一步

**对比+检查步骤**：
- step1(对比) + step2(回溯) → 可以合并为一步

**审计步骤**：
- step7(审计) → 需要看到所有trace，单独一步

## 3. 不会退化的4阶段拆分方案

### 阶段1：对比+回溯检查 → comparison.json

**做什么**：
- 综合对比4个版本的格化结果（段划分、形式上下文、特征标注）
- 选择基础格化（以哪个版本为基础做trace识别）
- 形式上下文回溯检查（有没有特征标注遗漏）
- 记录修正建议

**输入**：4版本segments.json + formal_context.json + closed_elements.json + input.md

**输出**：comparison.json
```json
{
  "base_grading": "V10",
  "version_comparison": {
    "V5": {"segments": 26, "features": "描述性", "closed_elements": null},
    "V7": {"segments": 21, "features": 15, "closed_elements": 23},
    "V8": {"segments": 22, "features": 40, "closed_elements": 39},
    "V10": {"segments": 35, "features": 26, "closed_elements": 52}
  },
  "viewpoint_differences": ["V5→V7: ...", "V7→V8: ...", "V8→V10: ..."],
  "formal_context_issues": [
    {"issue": "段10标注错误", "correction": "应改为s的代数角色"},
    {"issue": "验证特征过粗", "correction": "应拆分为前缀和验证+终点验证"}
  ],
  "base_grading_rationale": "V10最细粒度段划分+显式元模式特征+key_entities"
}
```

**thinking量**：中等（读4版本+对比+回溯检查）

### 阶段2：闭元素解读+跨闭元素元模式 → closed_element_traces.json

**做什么**：
- 对每个闭元素做入选/排除判定（语义解读——程序做不了的）
- 识别跨闭元素元模式（某个变量/技巧/策略贯穿多个闭元素）
- 参考V10的key_entities.json发现跨闭元素元模式

**输入**：closed_elements/*.json + comparison.json + V10_key_entities.json

**输出**：closed_element_traces.json
```json
{
  "closed_element_judgments": [
    {"id": "ce_V10_3", "verdict": "入选", "trace_description": "终点验证s∉M", "reason": "..."},
    {"id": "ce_V10_0", "verdict": "排除", "reason": "平凡闭元素（空外延）"}
  ],
  "cross_element_meta_patterns": [
    {"id": "trace_CEM1", "description": "x的多功能角色元模式", "segments": ["段2","段4",...], "level": "L3"},
    {"id": "trace_CEM2", "description": "aₙ的多功能角色元模式", "segments": [...], "level": "L3"}
  ]
}
```

**thinking量**：中等（52个闭元素+元模式识别）

### 阶段3：内容trace识别 → content_based_traces.json

**做什么**：
- 从段内容出发识别nonlocal trace（不依赖闭元素）
- 识别cross_case_merge trace（跨Case非相邻合并）
- 识别global trace（贯穿全证明的结构性模式）

**输入**：input.md + comparison.json（获取基础格化的段划分信息）

**输出**：content_based_traces.json
```json
{
  "nonlocal_traces": [
    {"id": "trace_NL1", "description": "bad index存在性论证链", "segments": ["段7","段8","段9","段10","段11","段12"], "level": "L3"}
  ],
  "cross_case_merge_traces": [
    {"id": "trace_CCM1", "description": "递归调用归纳假设到缩减子问题", "segments": ["段15","段23","段30"], "level": "L2"}
  ],
  "global_traces": [
    {"id": "trace_G1", "description": "强归纳统一框架", "segments": ["段1","段3","段15","段23","段30"], "level": "L2"}
  ]
}
```

**thinking量**：中等（段内容分析+3类trace）

### 阶段4：审计+合并+AI优势+关键实体+元反思 → output.json

**做什么**：
- 合并阶段2和阶段3的所有trace
- 去冗余（不同类型不合并——335号修复的约束）
- 识别AI优势元素（程序做不了的语义判断）
- 列举关键实体
- 元反思——系统化方法的局限
- 审计项检查

**输入**：comparison.json + closed_element_traces.json + content_based_traces.json

**输出**：output.json（最终产出，和当前格式一致）+ output.md（人类可读报告）

**thinking量**：中等（合并+审计+元反思）

## 4. 为什么不会退化

### 和V8的关键区别

**V8退化根因**：段划分和特征标注是"同一个认知过程"——拆分后step1禁止标注特征→改变了认知内容→退化。

**综合分析不会退化**：6步之间是"不同的认知工作"——
- nonlocal trace识别"不依赖闭元素"——它从段内容出发
- 闭元素解读"依赖闭元素"——它从闭元素清单出发
- 它们本来就是不同的认知过程，拆分不会改变认知内容

### 不会退化的4个保证

1. **每步做完整的认知工作**——不禁止某步做某些事。阶段1做完整的对比+回溯，阶段2做完整的闭元素解读+元模式，阶段3做完整的nonlocal+ccm+global，阶段4做完整的审计+合并。

2. **步骤之间是真正不同的认知工作**——和V8不同。nonlocal trace识别和闭元素解读本来就是不同的认知过程，拆分只是把它们分到不同的thinking中，不改变认知内容。

3. **步骤之间通过文件传递**——前一步的产出是后一步的输入。阶段1的comparison.json告诉阶段2和阶段3"选了哪个版本作为基础格化"，阶段2的closed_element_traces.json和阶段3的content_based_traces.json告诉阶段4"有哪些trace需要合并"。

4. **审计在最后一步做**——阶段4看到所有trace后做去冗余和质量检查。这和当前的工作流程一样——审计本来就是在所有trace识别完成后做的。

### 拆分前后认知内容对比

| 认知工作 | 当前（一个session） | 拆分后（4个阶段） | 认知内容变化 |
|---|---|---|---|
| 综合对比4版本 | step1 | 阶段1 | 无变化 |
| 形式上下文回溯 | step2 | 阶段1 | 无变化 |
| nonlocal trace | step3 | 阶段3 | 无变化 |
| 闭元素语义解读 | step4 | 阶段2 | 无变化 |
| 跨闭元素元模式 | step5 | 阶段2 | 无变化 |
| cross_case_merge | step6 | 阶段3 | 无变化 |
| global trace | step6B | 阶段3 | 无变化 |
| 审计 | step7 | 阶段4 | 无变化 |
| AI优势 | step7中 | 阶段4 | 无变化 |
| 关键实体 | step7中 | 阶段4 | 无变化 |
| 元反思 | step7中 | 阶段4 | 无变化 |

**每一项认知工作在拆分前后都完整保留，只是被分到了不同的thinking中。**

## 7. 风险分析

### 风险1：阶段4审计时看不到所有trace的上下文

**问题**：阶段4做审计时，trace是在阶段2和阶段3中识别的。阶段4的AI只能看到closed_element_traces.json和content_based_traces.json中的trace描述，不能看到识别这些trace时的thinking过程。

**影响**：审计可能不够深入——AI可能无法判断两个trace是否在描述同一个模式，因为它没有看到识别这些trace时的推理过程。

**缓解**：要求阶段2和阶段3在输出文件中不仅列出trace，还列出识别理由。阶段4做审计时可以读这些理由。

### 风险2：阶段3的global trace可能和阶段2的跨闭元素元模式重叠

**问题**：global trace和cross_element_meta_pattern有重叠——"x作为核心边界量贯穿全证明"既是global也是cemp。阶段3识别global trace时不知道阶段2识别了哪些cemp，可能产生重复。

**影响**：阶段4审计时需要去冗余，但335号修复的约束是"不同类型不合并"——如果同一个模式被标为不同类型，阶段4不应该合并它们，但也不应该删除任何一个。

**缓解**：阶段3在识别global trace时，可以读阶段2的closed_element_traces.json，了解已识别的cemp。如果某个模式已经被识别为cemp，阶段3可以决定是否还需要标为global（按335号修复的规则：如果是贯穿全证明的结构骨架，标为global）。

### 风险3：阶段1的选择基础格化可能影响后续阶段

**问题**：阶段1选择基础格化后，阶段2和阶段3都基于这个选择。如果阶段1的选择不好，后续阶段都会受影响。

**影响**：和当前方案一样——当前方案中step1的选择也影响后续步骤。这不是拆分引入的新风险。

**缓解**：阶段1的comparison.json中记录选择理由，后续阶段可以参考。如果后续阶段发现选择不好，可以在自己的输出中记录问题。

## 9. 验证结果——不仅没有退化，还大幅提升

用入题序号0010单独测试了综合分析的4阶段流程（用0009的格化结果作为输入），对比0009（原版综合分析）：

| 维度 | 0009（原版） | 0010（4阶段拆分） | 变化 |
|---|---|---|---|
| trace总数 | 43 | **88** | +45 ✅ 大幅提升 |
| local | 21 | 50 | +29 |
| nonlocal | 5 | 11 | +6 |
| global | 7 | 8 | +1 |
| cross_case_merge | 6 | 10 | +4 |
| cross_element_meta_pattern | 4 | 7 | +3 |
| 闭元素 | 52 | 52 | 不变 |
| AI优势 | 7 | **20** | +13 ✅ 大幅提升 |
| 元反思 | 3 | 2 | -1（仍≥0005的2） |

**关键发现**：
1. **trace总数从43提升到88**——翻了一倍多！没有退化，反而大幅提升
2. **AI优势从7提升到20**——大幅提升
3. **闭元素数量不变（52）**——格化输入一样，闭元素一样
4. **元反思从3降到2**——唯一的小退化，但2仍≥0005的2，不算退化

**trace数量翻倍的原因**：4阶段拆分让每个阶段的thinking更专注——阶段2可以更细致地对52个闭元素逐个做入选判定（原版在一个大thinking中可能跳过了一些），阶段3可以更细致地识别nonlocal/ccm/global trace。

**各阶段耗时**：
- step1（对比+回溯）：约2分钟
- step2（闭元素解读+元模式）：约4分钟
- step3（内容trace）：约2.5分钟
- step4（审计+合并+元反思）：约3.5分钟
- 总计：约12分钟

**结论：4阶段拆分方案验证通过，不仅没有退化，还大幅提升了trace数量和AI优势数量。**

### 和V8的对比

V8文件拆分：闭元素数量不变（48=48），不退化 ✅
综合分析文件拆分：trace数量翻倍（43→88），大幅提升 ✅

两者的共同点：不改变认知内容，只改变执行顺序。
两者的不同点：V8是"同一个认知过程"拆分（需要小心不改变认知内容），综合分析是"不同的认知工作"拆分（天然不改变认知内容，且每步更专注→更细致→更多trace）。
