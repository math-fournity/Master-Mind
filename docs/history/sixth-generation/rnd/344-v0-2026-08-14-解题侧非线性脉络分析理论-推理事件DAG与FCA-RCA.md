## 0. 一句话结论

真实Solver的thinking不是一条线，甚至不只是一棵树；它应先被保存为**只追加的有类型推理事件DAG**，然后才在这个事实图上分别运行FCA、关系上下文迭代和trace识别。

本方案不把FCA当成“能自动还原一切推理结构”的魔法。FCA负责共享属性的闭包和概念组织；时序、因果、折返和融合仍由显式的图关系保存。

---

## 1. 用户看到的根本问题

入题侧看到的是已完成的解答。解答通常把失败探索、回退和重写都抹去，因而可以近似成一条从题目到结论的线性脉络。

真实Solver却可能经历：

1. 同时探索多个方向；
2. 某个方向遇到矛盾后回到早先的数学处境；
3. 保留失败方向中的局部引理；
4. 把这个引理和后来分支的新结构融合；
5. 从多个不同父状态合成一个新处境。

第324号文档已经正确识别了“树状thinking”和“折返后的语义关联”，但它建议把树拆成N条root-to-leaf路径各自格化。这对纯树可用，但会丢失**真实融合**：一个新结论可能同时依赖两条分支，它不属于任何一条独立的root-to-leaf路径。

## 2. 对旧概念的必要校准

### 2.1 三种“格/图”不能混成一个对象

| 对象 | 它记录什么 | 数学身份 | 能否互相代替 |
|---|---|---|---|
| 推理事件DAG | Solver实际经过的状态、跳转、回访、依赖与融合 | 有类型时序/因果图 | 不能被FCA概念格代替 |
| 观察/分区格 | 同一个图在不同粒度下如何合并 | 分区或商结构的偏序 | 不自动等于FCA概念格 |
| FCA概念格 | 哪些对象共享哪些属性 | 形式上下文的概念闭包系统 | 不保存原始时序/因果边 |

第304号文档自己已指出“序列划分格与FCA对象—属性格不同”的gap。第330号中“LevelView就是形式概念”的字面对应因此只能视为早期类比，不能作为新管线的数据合同。

### 2.2 `structure="dag"`不等于已经表示DAG

现有`system/schema.py` 虽然允许`Vein.structure="dag"`，但其`Segment` 只有线性`order`，`Branch` 只有一个分叉点、已选路径和未选路径。它不能表示：

- 一个节点有多个父节点；
- 新发生的状态回访早先数学状态；
- 失败方向中的结果被后续分支复用；
- 两个分支在后面合流；
- 不同类型的依赖边。

因此新管线必须有独立Schema，不得为了复用旧Schema而修改入题侧共享文件。

## 3. 核心事实层：只追加的推理事件DAG

### 3.1 为什么必须是DAG

推理可以“回到”旧数学处境，但时间不会倒流。因此不在图中真正画一条指向旧事件节点的逆时边，而是：

1. 新建一个当前时刻的**状态发生项**；
2. 让它通过`REVISIT`边与上一个发生项相连；
3. 让它引用早先状态的同一`canonical_math_state_id`。

这样事件节点仍严格按时间向前，而语义上可以回访任意旧状态。

### 3.2 双重身份

| 字段 | 含义 | 为什么不能合并 |
|---|---|---|
| `occurrence_id` | 这一次、这个时刻的状态发生 | 用于时序、边和审计 |
| `canonical_math_state_id` | 去掉措辞后的数学状态身份 | 用于识别“真正回到同一处境” |

如果只保留canonical ID，时序会被压扁；如果只保留occurrence ID，系统又无法知道两个远隔的发生项其实是同一数学状态。

### 3.3 边类型的最小完备集

| 边类型 | 含义 |
|---|---|
| `CONTINUE` | 沿当前思路继续 |
| `REFINE` | 将某个目标、引理或对象细化 |
| `BRANCH_FROM` | 从一个可分叉处境选择新方向 |
| `CONTRADICT` | 新处境表明某个旧假设/方向矛盾 |
| `ABANDON` | 显式放弃一个活动方向 |
| `REVISIT` | 在新时刻回访早先的数学处境 |
| `REUSE` | 复用另一分支已得的结论/对象 |
| `DEPENDS_ON` | 当前状态逻辑依赖另一状态 |
| `MERGE` | 多个父分支共同合成当前新处境 |
| `CONCLUDE` | 将中间状态推到一个局部或最终结论 |

边类型是可版本化合同。POC不得通过自由文本边名字临时增加新语义。

### 3.4 融合与折返不能混淆

- **折返**：新发生项回访了早先的canonical state；它可以只有一个主要进入边。
- **融合**：新发生项的数学内容同时依赖至少两条可区分的上游分支；它必须有多个进入`MERGE/REUSE/DEPENDS_ON`边的证据。

“后来的文本提到了早先的词”不足以判融合。

## 4. FCA在这个系统中的正确职责

### 4.1 状态形式上下文

定义 `K_state = (G_state, M_state, I_state)`：

- `G_state`：状态发生项，不是被去重后的canonical state；
- `M_state`：经过实体化的数学对象、目标、方法、证书、状态和警戒属性；
- `I_state`：某一发生项具有某属性。

它回答“哪些推理处境共享哪些不变量”，而不回答“先发生什么”。

### 4.2 转移形式上下文

定义 `K_transition = (G_edge, M_edge, I_edge)`：

- 对象是有类型边；
- 属性包括边类型、源/目标状态的特征、是否跨分支、是否导致progress。

它回答“哪些转移具有相同的认知功能”。

### 4.3 关系上下文族与RCA

对每种边类型 `r`，保存关系 `R_r ⊆ G_state × G_state`。然后用明确的关系缩放算子（POC首先使用存在量化的最小版）迭代产生如下关系属性：

`exists(MERGE, target_concept_fingerprint)`

这与RCA的正统用法一致：RCA处理多个对象—属性上下文和对象间二元关系，用关系缩放把链接迭代转为关系属性和概念格族。但本POC实现只称为**RCA-style relational scaling**，不宣称已实现完整Multi-FCA/RCA定理体系。

### 4.4 Pattern Structures的后续位置

对于“带标签子图”这种不适合压成简单二值属性的对象，Pattern Structures提供了用半格上的复杂pattern描述对象的框架，并引入projection降低计算复杂度。这与“图片段的共同结构”高度契合，但不在VMS-31首个可执行POC中实现完整子图同态和projection lattice。

### 4.5 Temporal/Incremental FCA的后续位置

- Temporal Concept Analysis可为状态、转移、life track和时间粒度提供更严格的概念语言；
- 增量概念格算法证明新对象到来时可以更新已有概念格，而非每次从零重算。

VMS-31的首版以“小样本全量重算+批处理/逐事件等价性”先验证语义正确性。只有在概念和关系定义稳定后，才进入增量性能实现。

## 5. 从DAG到trace的系统遍历

### 5.1 不枚举所有root-to-leaf路径

在有融合的DAG中，根到叶的路径数可能指数增长，同一节点还会被重复出现在多条路径里。管线必须以图为一等对象，路径只是需要时的投影，不是真值源。

### 5.2 五层遍历

1. **发生项层**：按`sequence_index`只追加事件，验证父节点已存在且时间更早。
2. **图层**：建立有类型边，计算分支、活动前沿、归并和不可达部分。
3. **上下文层**：建立state/transition contexts与关系上下文族。
4. **概念层**：枚举FCA闭元素，迭代加入关系属性，保留每一轮的fingerprint。
5. **trace层**：在图事件和概念共享内涵之间建立可审计的trace，不从最终答案倒推过程。

### 5.3 首版trace家族

| trace家族 | 最小结构证据 |
|---|---|
| `LINEAR_PROGRESS` | 连续的CONTINUE/REFINE链且共享有效属性 |
| `BRANCH_EXPLORATION` | 同一发生项后有可区分的BRANCH_FROM后继 |
| `FAILED_BRANCH` | 分支内出现CONTRADICT/ABANDON且未在本分支继续 |
| `REVISIT_WITH_NEW_INFORMATION` | REVISIT后回到同一canonical state，且属性严格增加 |
| `CROSS_BRANCH_REUSE` | REUSE/DEPENDS_ON跨越可区分分支 |
| `TRUE_MERGE` | 一个发生项有至少两个有证据的多分支输入 |
| `RECOVERY_AFTER_CONTRADICTION` | 矛盾/放弃后通过折返或分叉形成有效progress |

## 6. 正确性不变量

1. **时序无环**：每条边的源发生项必须早于目标发生项。
2. **事实不覆盖**：不删除失败分支，不把折返前的状态改写成后来的理解。
3. **双身份分离**：发生项不按canonical state去重。
4. **边证据完整**：每条非CONTINUE边必须引用原始事件证据。
5. **融合不伪造**：只有多父数学依赖才可标`TRUE_MERGE`。
6. **FCA闭包可复算**：小样本下Next Closure结果必须与穷举闭包结果一致。
7. **批/流等价**：同一有序事件集逐条输入与一次批输入生成相同图和trace。
8. **归因层级正确**：FCA概念只证明属性共性，不单独证明时序或因果。

## 8. 学术回源与吸收边界

1. **Relational Concept Analysis**：Rouane-Hacene, Huchard, Napoli, Valtchev, *Relational Concept Analysis: Mining Concept Lattices From Multi-Relational Data*. RCA的输入是多个形式上下文与对象间二元关系，通过关系缩放迭代建格。  
   https://www.lirmm.fr/~huchard/Documents/Papiers/RCA-amai13-Springer.pdf
2. **RCA健全性/完备性工作**：相关工作将RCA输出描述为固定点概念格族，并分析其与输入关系结构的联系。  
   https://www.lirmm.fr/~huchard/Documents/Papiers/icfca13-multifca.pdf
3. **Pattern Structures**：Ganter & Kuznetsov, *Pattern Structures and Their Projections*, DOI 10.1007/3-540-44583-8_10。复杂对象可用半格上的pattern描述，projection用于近似和降复杂度。  
   https://doi.org/10.1007/3-540-44583-8_10
4. **Temporal Concept Analysis**：Wolff的TCA工作把状态、转移和life track纳入概念时间系统。  
   https://ceur-ws.org/Vol-757/paper_11.pdf
5. **增量概念格**：Godin, Missaoui, Alaoui, *Incremental Concept Formation Algorithms Based on Galois (Concept) Lattices*, 1995。论文给出对二元关系概念格的增量更新算法与实验。  
   https://doi.org/10.1111/j.1467-8640.1995.tb00031.x

这些来源只支持“可借用的数学工具存在”，不自动支持“本项目的具体编码已正确”。具体编码必须由POC-VMS-31独立验证。
