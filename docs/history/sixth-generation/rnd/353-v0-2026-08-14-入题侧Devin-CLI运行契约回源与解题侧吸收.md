## 1. 先给结论

解题侧不应继续猜 Devin 怎么用。入题侧已经跑通的主契约是：

1. 一个认知角色一个独立工作目录；
2. 在启动前由程序把固定 `AGENTS.md`、`prompt.md`、`input.md` 和分阶段 requirements 文件复制到目录；
3. 只给 Devin 一个很短的启动提示，让它自己读工作目录内的冻结文件；
4. Devin 用工具直接写阶段 JSON/Markdown 和完成标志；
5. 启动时使用 `--permission-mode dangerous`，**不使用 `--sandbox`**；
6. 使用 `--export` 保留 ATIF trajectory；
7. 程序轮询阶段完成标志，再做确定性枚举、收集、审计和归档。

这不等于照抄旧代码。解题侧应复用它已经有实证的认知/文件契约，同时修复旧管线在 argv 安全、精确模型绑定、DONE 完整性、export 竞态、权限边界和 Schema 验证上的缺口。

## 3. Devin CLI 的精确启动方式

### 3.1 交互/tmux 分支

`system/vein_analysis.py::_launch_devin()` 的 tmux 分支实质上执行：

```text
cd <workdir> &&
devin
  --permission-mode dangerous
  --respect-workspace-trust false
  --export <workdir>/trajectory.json
  -- '<short launch prompt>'
```

当前代码中 `USE_TMUX=True`。该命令通过一个 shell 字符串交给 `tmux new-session`。

### 3.2 非交互/Popen 分支

非交互分支使用结构化 argv：

```text
devin
  --permission-mode dangerous
  --respect-workspace-trust false
  --export <workdir>/trajectory.json
  -p '<short launch prompt>'
```

它把 stdout/stderr 合并写入 `devin_cli.log`，把 PID 写入 `devin_pid.txt`，然后同样由主管线轮询 `DONE.md`。

### 3.3 没有的参数也很重要

入题侧已成功运行的命令没有：

- `--sandbox`；
- `--resume` / `--continue`；
- 显式 `--model glm-5-2`。

历史 trajectory 观测到的实际模型是 `agent.model_name = GLM-5.2 High`，且所有 generation-bearing step 的 `extra.generation_model = glm-5-2`。这说明当时默认模型恰好是目标模型，但不是可复现的模型冻结方式。解题侧必须改为显式 `--model glm-5-2`。

## 4. 工作目录与运行资产契约

### 4.1 启动前全部物化

以 `0013_imo2009p6/phase1_grading/V8/` 为例，启动前程序已经放入：

```text
AGENTS.md
prompt.md
input.md
step1_requirements.md
step2_requirements.md
```

V5/V7/V10 的固定资产也在启动前复制；综合阶段还会先把格化结果复制到 `grading/`，把程序枚举的闭元素复制到 `closed_elements/`。

这实现了一个重要原则：**AI 不需要去 repo 内搜索任务依赖，任务允许见到的输入在启动前就应备齐。**

### 4.2 短启动提示

启动提示不重复长 prompt，只说：

- 读 `AGENTS.md`；
- 读 `prompt.md`；
- 读 `input.md` 或阶段输入目录；
- 写哪些明确的输出；
- 最后创建 `DONE.md`。

完整指令作为文件保留，既避免长命令行，又能追溯“当时到底给了模型什么”。

### 4.3 同 session 内的文件分阶段

V8 在同一个 Devin session 中：

```text
创建输出骨架
→ 读 step1_requirements.md
→ 做“划段+所有特征标注”的完整认知单元
→ 写 segments.json
→ 读 step2_requirements.md
→ 机械构造 formal_context.json
→ DONE
```

历史实验曾把它拆成四步，但错误切断了“划段与特征标注”这个同一认知过程，产生退化。修订后的原则是：

> 文件拆分只能管执行顺序，不能为了降 token 而把一个不可分的认知单元切开。

综合分析的四步也遵守同一原则：每一步是一个完整的认知任务，中间 JSON 是下一步的输入和可审计检查点。

## 5. 实跑证据

### 5.1 0011：非交互模式

Git 历史表明 `7a4484a` 将 `USE_TMUX` 改为 `False`，理由是“修复 trajectory 导出不完整”。`0011_imo2009p6` 的实物表明：

- V5/V7/V8/V10/综合阶段都有 `DONE.md`；
- 5 个角色全部有 `trajectory.json`；
- 5 个角色全部有 `devin_cli.log` 和 `devin_pid.txt`；
- Devin 成功通过 `read`/`write`/`exec` 直接生成阶段文件；
- DONE 后 trajectory 通常还要约 7–14 秒才完成导出。

这是“非交互、模型直接写文件、完整 export”的强实证。

### 5.2 0013：tmux 模式

`105fdc1` 明确记录：0013 使用 `USE_TMUX=True`。4 个格化角色和 1 个综合角色均成功生成 `DONE.md`，非退化审计也通过。历史 trajectory 还直接显示：

```text
agent.version = 3000.4.16
agent.model_name = GLM-5.2 High
generation_model = glm-5-2
```

但是 5 个已完成角色中只有 4 份 `trajectory.json`，V8 缺失。这与代码的清理顺序一致：主管线看到 `DONE.md` 后便 kill tmux session，而 `--export` 可能仍在 Devin 退出阶段写入。

**因此，tmux + DONE 成功不等于调用物证完整。**

### 5.3 历史评估的边界

0013 的非退化审计报告评估了段数、特征数、闭元素数、trace 数和类型分布，结论是“全管线无退化”。它没有把“V8 trajectory 缺失”当作协议失败。

所以那份 PASS 支持的是内容质量非退化，不是完整的运行可审计性 PASS。

| 入题侧经验 | 解题侧吸收方式 |

| 角色工作目录预先物化 | 每个 attempt 只看自己的冻结 view，不去 repo 搜索依赖 |

## 8. 不能直接照搬的部分

1. **shell 拼接的 tmux 命令**：prompt 和路径未做可证的 argv 边界；解题侧必须用结构化 argv 或冻结 wrapper。
2. **依赖当时默认模型**：必须显式请求 `glm-5-2` 并从 export 观测实际 generation UID。
3. **DONE 出现就 kill**：必须等进程正常退出且 export 可解析，DONE 只是输出提交候选。
4. **空 DONE**：不能证明输出完整；解题侧使用 `filename SHA256=<hash>`。
5. **只看文件存在**：必须严格 Schema 验证、跨文件语义验证与程序验收。
6. **没有严格最小视图能力证明**：“专用工作目录”不自动等于“无法读取外部”。无 sandbox 路径必须用兄弟目录/Vault 拒读 canary 做独立能力测试。
7. **全局 AGENTS 污染**：0013 trajectory 同时包含工作目录 `AGENTS.md` 和 Devin 全局 AGENTS。解题侧必须冻结它实际加载的 rules/config 视图，不能只 hash 本地角色资产。
8. **同步写生产 DB**：本轮解题侧 POC 继续 file-only；不借入题侧接库代码。
9. **内容指标代替证据完整性**：内容 PASS 不能覆盖缺 export、缺 log、模型不可观测或权限越界。

## 9. 解题侧的下一个最小充分 POC

下一次实验应当不改变内容任务、fixture、evaluator、模型、冷却时间或角色资产语义，只改启动契约：

```yaml
carrier: devin_cli
model_uid: glm-5-2
effort: high_by_model_uid
mode: noninteractive_print
sandbox: false
permission_mode: dangerous
workspace: fresh_attempt_directory
output_capture: model_writes_files
export: required
wait_condition:
  - DONE candidate exists
  - process exited
  - export JSON parses
retry_count: 0
inter_role_cooldown_seconds: 75
```

这是一个单因素实验：相对 POC-VMS-33，只取消 `--sandbox`。如果文件写入恢复，就直接复现了入题侧的已知路径；如果外部拒读 canary 失败，则运行功能和信息边界要分开判定，不能因为“能写”就升级生产能力。

352 号 response-marker 方案保留为二线备选，本轮不执行，不产生结果性证据。
