# 342号 · 系统时间意识方案——全管线全子管线运行时间记录

**日期**：2026-08-11
**状态**：方案设计
**来源**：用户要求"必须在日志中给出时间戳，也必须通过数据库记录管线和子管线的运行时间记录，整个系统要有时间意识、效率意识"

---

## 1. 问题——系统没有时间意识

当前系统的时间记录是零散的：
- 数据库`problem_entries`有`started_at`/`completed_at`，但只有管线级别，没有子管线级别
- 日志有时间戳（341号方案），但没有结构化的耗时统计
- 各阶段（格化/枚举/综合分析）的耗时没有记录到数据库
- 各子管线（V5/V7/V8/V10）的耗时没有记录到数据库
- 综合分析的4阶段拆分（step1-4）的耗时没有记录

**后果**：
- 无法回答"V8格化平均耗时多少？综合分析step2最慢吗？"
- 无法做效率分析——不知道瓶颈在哪
- 无法做超时阈值调优——没有历史耗时数据支撑

---

## 2. 方案设计——3层时间记录

### 2.1 第1层：日志时间戳（341号已实现）

日志格式：`[2026-08-11 10:55:38] [INFO] [vein_analysis] 格化版本V8完成，耗时200秒`

**已有**：341号方案的`system/log.py`已经给每条日志加了时间戳。

**补充**：在关键位置加耗时统计日志——开始时间+结束时间+差值。

### 2.2 第2层：数据库结构化时间记录

`problem_entries`集合新增时间记录字段：

```json
{
  "timing": {
    "total_duration_sec": 600,
    "phase1_grading": {
      "started_at": "2026-08-11T10:00:00",
      "completed_at": "2026-08-11T10:05:00",
      "duration_sec": 300,
      "versions": {
        "V5": {"started_at": "...", "completed_at": "...", "duration_sec": 180},
        "V7": {"started_at": "...", "completed_at": null, "duration_sec": null, "status": "timeout"},
        "V8": {"started_at": "...", "completed_at": "...", "duration_sec": 200},
        "V10": {"started_at": "...", "completed_at": "...", "duration_sec": 280}
      }
    },
    "phase1_5_enumerate": {
      "started_at": "...",
      "completed_at": "...",
      "duration_sec": 5,
      "versions": {
        "V7": {"duration_sec": 1, "closed_elements_count": 27},
        "V8": {"duration_sec": 2, "closed_elements_count": 46},
        "V10": {"duration_sec": 2, "closed_elements_count": 26}
      }
    },
    "phase2_synthesis": {
      "started_at": "...",
      "completed_at": "...",
      "duration_sec": 720,
      "steps": {
        "step1_comparison": {"duration_sec": 120},
        "step2_closed_element": {"duration_sec": 240},
        "step3_content_based": {"duration_sec": 150},
        "step4_audit_merge": {"duration_sec": 210}
      }
    }
  }
}
```

### 2.3 第3层：运行结束后的耗时摘要

运行结束时打印耗时摘要表：

```
=== 耗时摘要 ===
阶段1 格化: 300秒（V5:180s V7:超时 V8:200s V10:280s）
阶段1.5 枚举: 5秒（V7:1s V8:2s V10:2s）
阶段2 综合分析: 720秒（step1:120s step2:240s step3:150s step4:210s）
总耗时: 1025秒（17分钟）
```

## 4. 综合分析4阶段拆分的耗时记录

综合分析的4阶段拆分（336号方案）的各阶段耗时，通过中间文件的创建时间计算：
- `comparison.json`的mtime → step1完成时间
- `closed_element_traces.json`的mtime → step2完成时间
- `content_based_traces.json`的mtime → step3完成时间
- `output.json`的mtime → step4完成时间

**实现**：在`_phase2_synthesis()`完成后，读取这些文件的mtime，计算各阶段耗时。

## 5. 和340/341号方案的关系

| 方案 | 关系 |
|---|---|
| 340号（超时降级） | 340号需要时间记录来判断超时——342号提供结构化时间数据 |
