## 0. 实验要回答什么

VMS-31不问“AI能不能把某道题做出来”，而问三个更局部、可被代码反驳的问题：

1. 只追加的有类型DAG能否无损表示线性、分支、折返和真融合？
2. FCA状态/转移上下文与RCA-style关系属性能否为trace提供可复算的共性证据？
3. 相比线性压平和树投影，DAG方案是否确实避免折返/融合关系的结构丢失？

## 1. 实验单位

一个实验单位是：

`(fixture trajectory, frozen expected structure, pipeline version, rule-set version)`

每个fixture有两个物理文件：

- `*.trajectory.json`：管线真正消费的输入；
- `*.expected.json`：只由测试器读取的gold，管线代码不得导入。

## 2. 五类预注册案例

### C1 Linear

`root → define invariant → derive lemma → conclude`

- 无分支、无折返、无融合；
- 应识别`LINEAR_PROGRESS`；
- 不得伪造branch/revisit/merge。

### C2 Branch

`root → approach A → failure`  
`root → approach B → progress`

- 应识别`BRANCH_EXPLORATION`和`FAILED_BRANCH`；
- 不得把两个分支误报为merge。

### C3 Revisit

`root → A → contradiction → revisit(root with new guard) → B`

- revisit发生项与root的`canonical_math_state_id`相同；
- occurrence ID必须不同；
- 应识别`REVISIT_WITH_NEW_INFORMATION`和`RECOVERY_AFTER_CONTRADICTION`。

### C4 True Merge

`root → branch A → lemma A`  
`root → branch B → construction B`  
`lemma A + construction B → merged state → conclusion`

- merged state至少有两个分支来源的进入关系；
- 应识别`CROSS_BRANCH_REUSE`与`TRUE_MERGE`；
- 树投影baseline必然丢失至少一条merge依赖。

### C5 Branch-Revisit-Merge Composite

组合上述所有结构，并包含一条失败分支的局部引理在后续成功分支中被复用。

这是首个能反驳“只要拆成N条root-to-leaf路径就足够”的对照案例。

## 3. 三个对照管线

| Arm | 做法 | 可保留什么 | 预期损失 |
|---|---|---|---|
| F | Flattened sequence | 文本顺序 | 显式分支、回访身份、多父依赖 |
| T | Tree projection | 单父分支树 | 合流边，并将共享节点复制到多路径 |
| D | Typed DAG + FCA/RCA-style | 全部发生项和显式有类型关系 | 首版仍依赖上游结构化标注 |

对照F/T只用同一DAG输入做机械投影，不调用另一个AI，因此不引入模型差异。

## 4. 指标

### 4.1 结构指标

- `typed_edge_recall = recovered_gold_edges / gold_edges`
- `revisit_identity_recall`
- `merge_parent_recall`
- `false_merge_count`
- `acyclicity_pass`
- `unreachable_occurrence_count`

### 4.2 trace指标

- `trace_family_recall`
- `trace_evidence_precision`：trace的每个事件/边引用是否真正存在；
- `required_trace_recall`：按fixture必需trace集计算；
- `forbidden_trace_false_positive_count`。

### 4.3 FCA/RCA-style指标

- `next_closure_equals_bruteforce`；
- `concept_fingerprint_deterministic`；
- `relational_scaling_fixed_point_reached`；
- `relational_attribute_provenance_complete`；
- `batch_incremental_scientific_fingerprint_equal`。

### 4.4 成本指标

- 节点数、边数、属性数、概念数；
- 每阶段墙钟时间；
- relational scaling迭代次数；
- 输出总字节数。

小样本时这些只是描述性指标，不由此外推大规模性能。

## 5. PASS / PARTIAL / FAIL

### Pipeline PASS

- 五个fixture均可密封完整artifact集；
- 所有输出可由manifest复核；
- 所有负向fixture被fail-closed；
- 受保护路径聚合哈希不变。

### Scientific structure PASS

- D arm在五案例上typed edge recall = 1.0；
- D arm的required trace recall = 1.0；
- D arm false merge count = 0；
- C3的revisit双身份全部正确；
- C4/C5的merge parent recall = 1.0；
- Next Closure/Brute Force全例一致；
- batch/incremental scientific fingerprint全例一致。

### Comparative PASS

- C4或C5中，T arm的merge parent recall < D arm；
- C3或C5中，F arm的revisit identity recall < D arm；
- 比较差异来自投影丢边，而不是不同输入或不同预算。

### PARTIAL

- 管线物证完整，但某个非核心relational scaling未在预设次数收敛；或
- 必需trace已被识别，但共性概念归因不完整。

### FAIL

- 任一核心结构引用缺失；
- 伪造merge；
- 图有环；
- 概念闭包错误；
- 批/流不等价；
- 受保护入题侧改动。

### Live extraction

本轮固定为`NOT_TESTED`。不允许用离线fixture PASS将它上调为PARTIAL或PASS。

## 6. 负向测试矩阵

1. 重复event ID；
2. 重复sequence index；
3. 父事件不存在；
4. 父事件比子事件更晚；
5. 首事件带进入边；
6. 非首事件无进入边；
7. 未知edge relation；
8. 未知event kind/status；
9. 空canonical state ID；
10. 一个单父MERGE试图冒充TRUE_MERGE；
11. 输出目录已存在；
12. asset manifest哈希不匹配。
