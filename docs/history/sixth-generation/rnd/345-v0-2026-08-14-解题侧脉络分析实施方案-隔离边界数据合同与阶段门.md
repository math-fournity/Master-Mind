## 0. 目标模型

### 最终目标

交付一条独立、可运行、可审计的解题侧非线性脉络分析POC管线：它从已结构化的Solver reasoning events构建有类型DAG，建立state/transition FCA contexts，执行RCA-style关系缩放，识别线性、分支、折返、跨分支复用和真融合trace，并生成机器可读与人可读证据。

### 本轮DONE

1. 新package可通过CLI处理结构化trajectory JSON；
2. 四类基准（线性/分支/折返/真融合）与一个组合案例全部通过；
3. Next Closure与独立穷举闭包在小样本上一致；
4. 批处理与逐事件处理结果一致；
5. 线性/树投影baseline与DAG管线的结构损失有量化对比；
6. 新增每个`.py`都有同名`.ref`和`.ai-check`；
7. 完整技术文档、运行手册、POC报告和受保护路径零改动证据落盘。

### 本轮FAIL

- 任一受保护入题侧文件哈希改变；
- 管线丢失明示的多父MERGE关系；
- 折返被实现为逆时有向边并制造环；
- FCA概念枚举与穷举闭包不一致；
- 批/流结果不一致；
- 评测使用最终成功与否倒推边类型或trace；
- 离线POC被文档写成真实Solver提取PASS。

## 3. 输入合同

### 3.1 ReasoningTrajectory v1

```yaml
schema_version: solve-vein/reasoning-trajectory/v1
trajectory_id: string
problem_id: string
source:
  carrier: fixture | devin_cli | codex_exec | imported
  source_artifact_ref: string
  source_artifact_sha256: 64hex
events:
  - event_id: string
    sequence_index: integer >= 0
    event_kind: STATE | DECISION | FAILURE | RETURN | SYNTHESIS | CONCLUSION
    text: string
    canonical_math_state_id: string
    attributes: [namespaced-string]
    status: ACTIVE | ABANDONED | CONTRADICTED | SOLVED | UNKNOWN
    source_span: {start: integer, end: integer, sha256: 64hex}
    incoming_edges:
      - source_event_id: string
        relation: CONTINUE | REFINE | BRANCH_FROM | CONTRADICT | ABANDON |
                  REVISIT | REUSE | DEPENDS_ON | MERGE | CONCLUDE
        evidence: string
```

强制条件：

- `sequence_index`唯一且连续；
- `event_id`唯一；
- 所有父事件必须已在更早的sequence中出现；
- 首事件不得有进入边；
- 非首事件至少有一条进入边；
- `MERGE`不能仅凭一个父事件构成TRUE_MERGE；
- 未知字段fail-closed，不默默忽略。

### 3.2 真实thinking的入口边界

首版CLI不伪装成能理解任意自然语言thinking。它只消费已结构化的ReasoningTrajectory v1。

真实Solver原始轨迹将来通过独立`ReasoningEventExtractorPort`产生该合同。本轮提供三份运行时AGENTS资产和输入/输出规格，但不调用真实Devin/Codex，不给这一阶段写PASS。

## 6. 六个执行面

### 6.1 可观测性

- 每一阶段产生独立JSON；
- 每个trace保留源事件、源边、共享属性和规则ID；
- 错误不只有自由文本，还有稳定error code。

### 6.2 验证

- 输入字段/枚举/唯一性/时序校验；
- DAG环检测与不可达节点检测；
- 概念格双算法小样本交叉验证；
- gold edge/trace对比；
- 输出哈希与manifest交叉核对。

### 6.3 失败模型

- 输入无效：不产生科学输出；
- 图无效：保留错误证据，不继续FCA；
- FCA验证不一致：整次运行FAIL；
- 关系缩放未在上限内收敛：PARTIAL，不伪装PASS；
- trace未达阈值：科学FAIL，不等于基础设施故障。

### 6.4 恢复模型

首版不实现活体调用恢复。离线运行用临时目录：

- 未密封目录可以删除后从同一输入重跑；
- 已密封目录不覆盖；
- 相同输入的重跑必须产生相同canonical scientific fingerprint，但可有不同墙钟时间。

### 6.5 并发模型

POC单进程、确定性执行。不用入题侧tmux编排，不继承其并发上限。未来的Event Extractor/Normalizer/Auditor是三个逻辑角色，是否并发由解题侧自己的runtime contract决定。

## 7. 适合无人值守吗

首版离线POC适合无人值守，因为它：

- 不连数据库；
- 不调用模型；
- 不写入受保护路径；
- 只在显式输出目录中组装证据；
- 任一验证失败都以非零状态退出。

真实Devin/Codex抽取不适合直接继承这一结论。活体调用前还必须有独立能力报告、答案ACL、attempt/fence/reconcile和成本合同。
