# 340号 · 子管线超时降级方案——不卡住整个系统

**日期**：2026-08-11
**状态**：方案设计
**来源**：0011运行中V7卡住5分钟，用户要求"不能任由卡住的子管线耽误整个系统的工作"

---

## 1. 问题——卡住的子管线耽误整个系统

0011运行中，V5/V8/V10在3-5分钟内完成，但V7卡住了（CPU 0%，log 0字节）。当前逻辑是等所有4个版本完成或30分钟超时——这意味着V7卡住时，整个系统要等30分钟才能继续。

**用户的要求**：
1. 只要有一个管线在规定时间内通过，就可以
2. 剩下失败的管线直接舍弃结果
3. 必须在数据库中详细记录这件事——最后一步synthesis处理的是哪些子管线的结果
4. 超时时间按题目文本大小粗略设定（经验值）
5. 如果所有子管线失败，记录到数据库，入口脚本返回值也予以呈现

---

## 2. 方案设计

### 2.1 超时时间计算——按题目文本大小

```python
def _calc_grading_timeout(solution_text: str) -> int:
    """根据解答文本长度计算格化超时时间（秒）

    经验值（基于0004-0011的历史数据）：
    - 短文本（<2000字符）：10分钟
    - 中等文本（2000-5000字符）：15分钟
    - 长文本（5000-10000字符）：20分钟
    - 超长文本（>10000字符）：30分钟

    IMO 2009 P6解答约2400字符 → 15分钟
    """
    text_len = len(solution_text)
    if text_len < 2000:
        return 600   # 10分钟
    elif text_len < 5000:
        return 900   # 15分钟
    elif text_len < 10000:
        return 1200  # 20分钟
    else:
        return 1800  # 30分钟
```

### 2.2 降级逻辑——至少1个版本通过即可

**当前逻辑**：等所有4个版本完成或30分钟超时，超时后收集已完成的。

**新逻辑**：
1. 每个版本有独立的超时检查——超过`grading_timeout`秒还没完成，标记为`timeout`
2. 但不立刻降级——继续等其他版本，直到**至少1个版本完成**且**其他版本要么完成要么超时**
3. 如果所有版本都超时 → 记录到数据库，返回失败
4. 如果至少1个版本完成 → 用完成的版本继续，舍弃超时的版本

**关键变化**：不是等30分钟才降级，而是每个版本独立超时。V7卡住15分钟后标记timeout，其他版本已完成 → 立刻继续。


### 2.4 入口脚本返回值——所有子管线失败时呈现

`vein_analysis_three_phase()`的返回值`AnalysisOutput`新增字段：

```python
@dataclass
class AnalysisOutput:
    traces: List[Trace]
    veins: List[Vein]
    level_views: List[LevelView]
    # 340号新增
    phase1_success_versions: List[str]  # 成功的版本
    phase1_failed_versions: List[str]   # 失败的版本
    all_failed: bool                     # 是否所有版本都失败
```

`run_imo2009p6_three_phase.py`中检查`all_failed`：

```python
output = vein_analysis_three_phase(input)
if output.all_failed:
    print("❌ 所有格化子管线失败，无法进行综合分析")
    sys.exit(1)
```

### 2.5 综合分析阶段的适配

综合分析阶段需要适配——当只有3个版本（而非4个）的格化结果时，synthesis.md的提示词需要说明"V7因超时被舍弃，只有V5/V8/V10的格化结果"。

**实现方式**：在`_phase2_synthesis()`中，只复制成功的版本的格化结果到综合分析工作目录。综合分析AI看到哪些版本的文件就知道哪些版本可用。

## 4. 和现有逻辑的关系

**当前逻辑**（vein_analysis.py 1276-1292行）：
```python
timeout = 1800  # 30分钟超时
v8_timeout = 900  # V8超时阈值
# 等所有版本完成或30分钟超时
# V8超过15分钟标记失败，用V5/V7/V10继续
```

**新逻辑**：
- 所有版本统一用`_calc_grading_timeout()`计算超时（不再对V8特殊处理）
- 至少1个版本完成即可继续（不是等所有版本）
- 每个版本独立超时，超时后立刻标记timeout（不是等全局超时）
