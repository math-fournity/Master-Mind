## 1. 当前结论

本轮完成了零模型的Stage A与按预注册停止规则执行的Stage B。使用Devin CLI `3000.4.25 (7e8e528a)`：

- 静态`rules show AGENTS`对16,383—262,144 bytes全部完整返回；
- live ATIF中16,383和16,384-byte fixture均单system message完整出现；
- 16,385-byte与32,768-byte fixture均出现Devin明示`Rule content truncated to 16384 bytes`；
- 32,768-byte格的严格最长前缀恰为16,384 bytes，且边界后三个sentinel全部不可见；
- 因此在该冻结CLI版本、`glm-5-2`、平台与运行profile内，effective root `AGENTS.md` rule content上限被定位为16,384 bytes。

Stage A在每个cell独立的空HOME、空XDG配置和无认证环境中执行：

```text
devin --version
devin rules paths
devin rules list
devin rules show AGENTS
```

七个精确尺寸cell全部满足：

```text
STATIC_SHOW_FULL_EXACT
```

最大已测文件为262,144 bytes。`rules show AGENTS`的stdout包含完整fixture字节，而不只是头部、尾部或sentinel。因此：

- 16 KiB不是本机该版本`rules show`静态显示路径的硬上限；
- 静态loader至少完整显示到256 KiB；
- 这**不等于**模型实际effective system prompt完整收到256 KiB；
- Stage B已用ATIF system message精确比对裁决该冻结profile的真实会话边界。

官方文档仍没有给出16K数值上限，只说明根`AGENTS.md`在启动时加载、嵌套规则按路径使用，并建议规则保持精简。官方回源与链接见364号。

## 4. 收据缺陷与证据校准

首次静态运行器在原子rename前记录了fixture绝对路径，因此receipt中的七个`fixture.path`仍指向已经被rename的`.partial-*`目录。最终fixture实际都在：

```text
<final-bundle>/<cell>/workspace/AGENTS.md
```

这不是fixture丢失：每个最终文件的size和SHA都与receipt一致，原始command stdout/stderr也全部验证。但是首版receipt还没有索引CLI在隔离HOME/XDG生成的49个辅助文件。所以证据分轴为：

```text
primary_artifact_integrity = PASS
auxiliary_artifact_integrity = UNINDEXED
artifact_integrity = PARTIAL_UNINDEXED_AUXILIARY
```

补充审计没有篡改旧receipt，而是另建bundle，逐项哈希全部101个文件。现行runner已修正为相对`fixture_ref`并在未来receipt中索引全部isolated HOME/XDG副作用；当前源码SHA为`2ebf3499f5df1c05971ac88790ad4af9e2b5022584687a03e8d174eba93502df`。历史runner hash与现行runner hash不得互换。

该元数据缺陷不影响“七个静态show均包含完整fixture”的观察，但禁止把Stage A称为端到端协议PASS。
