# POC-VMS-34：只读认知角色与机械响应封存协议

> 状态：`PAUSED_BEFORE_EXECUTION`  
> 类型：`EXECUTION_CONTRACT_REVISION_FIT`  
> 上游反例：POC-VMS-32、POC-VMS-33

> 2026-08-14 回源注记：用户要求先回源入题侧的真实 Devin CLI 经验，本 POC 在任何模型调用前暂停。353号证明入题侧已有“无 sandbox + dangerous + 独立工作目录 + 模型直写文件 + export”的成功实跑。因此本 response-marker 方案保留为未运行的二线备选，不是下一次实验主线，也没有产生任何结果性证据。

---

## 1. 新假设

模型认知能力和文件提交能力不应混成一个组件。当前 Devin sandbox 能执行只读工具，但在非交互模式下不能稳定批准写文件工具。因此本 POC 验证：

> 模型只读取最小视图并在 final response 返回机器边界明确的 JSON；可信 adapter 是否能无语义改写地提取该 JSON、写入规定文件、生成 DONE/hash，再由既有 evaluator 评价？

---

## 2. Asset set 0.2.0

三个 v2 角色资产必须：

- 禁止模型调用 Write/Edit/Exec/MCP/Subagent；
- 只允许读取 workspace 内列出的文件；
- 不要求模型计算已经可以由可信代码给出的 source span/hash；
- 最终响应必须只含一对标记：

```text
BEGIN_SOLVE_VEIN_JSON
{...one JSON object...}
END_SOLVE_VEIN_JSON
```

- 标记之间不允许 Markdown fence 或解释文字；
- 标记之外如有载体固定前缀，由 adapter 忽略并在 raw stdout 中保留；
- adapter 只做 marker extraction、JSON parse、canonical JSON serialization、文件写入和 SHA-256，不增删语义字段。

---

## 3. 输入修订

原问题、raw trajectory、normalizer candidate、auditor candidate traces 和 evaluator gold 全部不变。

Extractor 额外得到 `source-spans.json`：它只包含每个 `[NN]` raw record 的冻结 byte start/end/hash 和完整 raw file hash，不含 event kind、canonical state、edge、trace 或 expected verdict。这个信息本来就在348号允许视图中，只是从“让模型算”改成“可信机械层给”。

---

## 4. Carrier profile

```yaml
carrier: devin_cli
```

## 6. Verdict边界

- adapter与三个内容组件全PASS：`PASS_WITHIN_RESPONSE_ADAPTER_REVISION_FIT_SCOPE`；
- adapter PASS、内容部分失败：按原预注册指标给 `PARTIAL/FAIL`；
- marker、JSON、模型身份、限流或副作用尝试失败：`INCONCLUSIVE_PROTOCOL`或`FAIL_SECURITY_BOUNDARY`；
- 即使总PASS，也不证明未见新题、流式、生产规模、Codex、真实Solver或Tell/Hint效果。
