

这正是交互模式相对单纯等待最终文件的价值：系统不仅知道“没有输出”，还能定位到第一次分叉——不是数学抽取失败，而是自身 workspace 被权限策略拒绝。

## 5. 根因

当前配置同时存在两条分别合理、组合后矛盾的规则：

1. 为防止 no-sandbox Devin读取主repo，`dedicated_devin_config()`拒绝`Read(~/master-mind-glm5.2-worktree/**)`；
2. `start_tmux_debug_role()`把持久 live bundle和workspace建在目标输出目录旁，而本轮输出目录位于上述repo中。

Devin read工具要求绝对路径。即使提示词写`Read ./AGENTS.md`，工具层也会解析到repo内绝对workspace，deny优先后将自身输入一起封死。

POC-VMS-35没有暴露这个问题，是因为 noninteractive runner用`tempfile.mkdtemp()`在repo外建立临时workspace，进程退出后才把文件复制到repo内partial并封存。tmux为了跨控制命令保持会话，把live workspace与最终输出错误地绑定在同一位置。

## 6. 下一版修复，不在本轮重试

下一版必须把“运行中的workspace”和“最终证据bundle”分成两个物理对象：

```text
approved external runtime root / per-attempt live workspace
  ├─ AGENTS/TASK/input/config
  ├─ interactive Devin + private tmux socket/session
  └─ raw export / live snapshots
          ↓ process exit or explicit abort
target-filesystem partial evidence bundle
          ↓ hash + fsync + atomic commit
final append-only evidence bundle
```

修复要求：

1. `runtime_workspace_root`必须显式传入并进入control/launch receipt；
2. 它必须在repo与所有入题侧目录之外，无祖先symlink；正式运行优先使用批准的D盘专属根；
3. repo deny规则保留，不能为了让测试过而整体删除；
4. live→final若跨文件系统，不能假装`rename`原子；应复制到目标同文件系统partial，逐哈希/fsync后再rename；
5. 增加“模型调用前的自身workspace read/write capability probe”，但probe不得调用模型或伪造角色能力；
6. 以新ID预注册POC-VMS-37。VMS-36不得重跑、覆盖或改判。

## 7. 对理论与工程的反哺

这次负结果说明，解题侧脉络分析的“发生史”不仅包括数学事件，也需要区分载体事件：

- `COGNITIVE_EVENT`：模型形成某个数学判断；
- `TOOL_ATTEMPT`：模型试图读取、计算或写入；
- `POLICY_REJECTION`：载体策略阻止动作；
- `ROLE_TERMINATION`：任务结束、idle、timeout或abort。

权限拒绝不能被误标为“Solver放弃数学路线”。未来 raw→ReasoningTrajectory 前必须先做载体事件去混淆；否则会把运行时失败写进数学脉络，产生伪分叉、伪失败和错误Tell。

FCA/RCA-style层也应保留事件来源命名空间，例如：

```text
source:cognitive
source:tool
source:policy
source:orchestrator
```

只有`source:cognitive`且通过过程审计的事件才可直接进入数学状态/策略概念格；载体事件进入独立运行图或作为审计关系，不得污染数学闭包。
