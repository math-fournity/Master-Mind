## 4. 核心理论：Trace积累与Tell/Hint积累

### 4.1 三类对象不可混同

| 对象 | 本质 | 是否题目特定 | 如何积累 |
|---|---|---:|---|
| `Trace` | 某次Solver实际探索的不可变事件事实 | 是 | append-only trajectory/event/DAG，保留成功、失败、折返、合流 |
| `Tell` | 从多个Trace中抽出的可识别分叉机制与适用边界 | 否；但有作用域 | 由对照证据支持的版本化知识对象，不能从单条成功事后命名 |
| `Hint` | 某Tell在某一状态上的题目化方向实例 | 是 | renderer根据Tell+当前state+lineage生成，记录exact payload/hash |

关键关系不是`Trace → 一个Tell标签`，而是：

```text
Trace occurrence/state window
  ──evidence_for / contradicts / boundary_of──> TellVersion
TellVersion + current StateBinding + RendererVersion
  ──instantiate──> HintInstance
HintInstance + BranchSnapshot
  ──causal treatment──> child Trace
child Trace
  ──new evidence──> Tell/Renderer/Selector/Boundary revision proposal
```

因此：

- Trace库是事实账本；
- Tell/Hint库是经证据治理的策略账本；
- 二者通过带scope、版本、contrast和provenance的边连接；
- 不得为了Tell升级而改写历史Trace；
- off-mechanism成功不支持该Tell；
- 单题Hint文本不能自动外推为跨题通用Tell。

### 4.2 Trace/Tell分片文件是数据面，`AGENTS.md`是短控制面

用户最新决策取代“把Tell库分片成多个`AGENTS.md`”的早期假设。Trace/Tell项不依赖Devin规则加载机制，而应进入独立文件，由负责该分片的AI逐项分析。这里的“一个文件”冻结解释为“一个不可变输入分片文件”；AI的结果进入另一个append-only报告文件，禁止边分析边改输入项集。冻结规则是：

- 权威Trace/Tell库必须是结构化、版本化、可查询、可哈希的registry；
- registry生成内容寻址的`TraceShard`/`TellShard`文件，每项有稳定`item_id`和顺序；
- 确定性enumerator按项发布工作，AI对每项只能输出`MATCH | NO_MATCH | ABSTAIN | ERROR`及证据引用；
- `ShardCoverageVerifier`机械核对`expected_item_ids == reported_item_ids`，并要求`missing=duplicate=unknown=0`；AI不得靠一句“已全部遍历”自证完成；
- append-only `ShardCursor`记录已领取、已开始、已封存和失败项；中断后从游标恢复，不重复处理已封存项，不丢弃`ERROR`；
- 长分片允许按预注册的item数/session滚动换新AI，但每个item仍只有一条科学attempt lineage；
- `AGENTS.md`只保留短小的遍历协议、权限边界、输入/输出Schema指针和停止条件，不承载Tell/Trace全量内容；
- 候选检索仍可以缩小分片，但必须记录候选全集、路由过程、被分配项和拒绝项，不得把“没有被路由”混成“Tell无效”。

所谓“16K上限”已经分层裁决为：

```text
documented_limit = NOT_STATED_BY_OFFICIAL_DOCS
static_rules_show = FULL_EXACT_THROUGH_262144_BYTES
effective_prompt_visibility = EXACT_CAP_16384_BYTES_WITHIN_FROZEN_PROFILE
cross_version_or_mode_generalization = NOT_TESTED
```

因此实现可以把“短控制面显著低于16,384 bytes”作为本profile的保守运行约束，但不得把16,384编码成Tell/Trace数据库容量，也不得外推到其他Devin版本、headless/resume模式或平台。

## 9. SV-K1/K2：知识积累与运行资产

本节的独立技术规格见370号；363只维护阶段状态、依赖和Gate，不复制其全部Schema细节。

### 9.1 最小Registry对象

- `TellCoreVersion`
- `ApplicabilityBoundaryVersion`
- `TellEvidenceLink`
- `HintRendererVersion`
- `HintInstance`
- `SelectorDecision`
- `TraceShardManifest` / `TellShardManifest`
- `ShardCursor`
- `PerItemAnalysisRecord`
- `ShardCoverageReport`
- `ShardCompletionReceipt`
- `RevisionProposal`

每条Tell Evidence必须说明来自哪个随机contrast、哪个problem/source rollout、支持什么scope；episode只可记录观察，不可直接写因果`supports`。

### 9.2 Trace/Tell文件分片与逐项遍历

候选结构：

```text
authoritative structured registry
  → deterministic prefilter
  → content-addressed TraceShard / TellShard file
  → deterministic item enumerator + append-only ShardCursor
  → shard worker逐项生成PerItemAnalysisRecord
  → ShardCoverageVerifier做ID集合与顺序核验
  → ShardCompletionReceipt
  → reducer生成selector/matcher候选与统计
```

分片文件必须是非可变snapshot，不得边遍历边改项集。可按Tell family、数学分支、触发特征、negative guard和priority分片；每个item保留matched、distractor、abstain/error状态与证据。单个session只处理预注册数量的item，超出则从已封存cursor换新session，避免上下文无界增长。不得把“模型没选到Tell”混成“Tell无效”。

### 9.3 分片与汇报文件的最小机器合同

这里正式采纳“每个分片使用一个文件装入待分析项，由负责该分片的AI逐项遍历”的思路，但必须区分**一个权威输入文件**与**一个可变万能文件**：

- 每个分片只有一个权威项集：`<shard_id>.items.jsonl`；它是不可变snapshot，也是expected item set的唯一真值源；
- AI不得修改、补写或重排这个输入文件，只能按其中稳定`item_id + ordinal + input_item_hash`逐项读；
- AI的逐项判断进入独立append-only结果流，恢复信息、覆盖对账和完成收据也与输入分离；
- AI可以在汇报中声明“我已遍历全部项”，但该声明没有Gate效力；只有程序重枚举输入、核对输出并得到exact set equality后，分片才算完成。

因此首版是“**一个items文件 + 四个派生证据文件**”，而不是把输入、结果、进度和完成状态混进同一个会被反复改写的大文件。这样既保留逐项轮询的简单性，又能重放、恢复、并发、审计且不污染权威项集。

首版优先采用UTF-8 JSONL：首行是冻结header，其后每行一个item；如果实现选择JSON数组，也必须提供完全等价的确定性enumerator和canonical hash。输入与输出物理分离：

```text
<shard_id>.items.jsonl            # 不可变输入；header + ordered items
<shard_id>.analysis.jsonl         # append-only；每item一条分析记录
<shard_id>.cursor.jsonl           # append-only状态跃迁
<shard_id>.coverage.json          # 机械集合对账
<shard_id>.completion.json        # 仅coverage PASS后签发
```

输入header至少冻结：

```yaml
schema_version:
shard_id:
registry_snapshot_id_and_hash:
item_kind: trace | tell | trace_tell_pair
split_rule_id_and_hash:
ordered_item_ids: []
item_count:
items_sha256:
analysis_contract_id_and_hash:
```

每条`PerItemAnalysisRecord`至少包含：

```yaml
shard_id:
item_id:
ordinal:
attempt_lineage_id:
worker_profile_id_and_hash:
input_item_hash:
decision: MATCH | NO_MATCH | ABSTAIN | ERROR
matched_tell_ids: []
evidence_refs: []
reason_summary:
started_at:
sealed_at:
record_hash:
```

程序而不是AI签发完成结论。`ShardCoverageVerifier`必须从输入文件重新枚举expected集合，从报告文件枚举reported集合，并同时验证：item hash未漂移、ordinal唯一、每个item恰有一个sealed科学attempt、失败/弃权未被漏掉、`missing_ids=[]`、`duplicate_ids=[]`、`unknown_ids=[]`。AI写下“已经遍历全部项目”只是普通文本，不是完成证据。

首版完成等式固定为：

```text
expected_ids = ordered IDs from immutable items file
reported_ids = sealed IDs from append-only analysis file

set(expected_ids) == set(reported_ids)
len(expected_ids) == len(reported_ids)
missing_ids == duplicate_ids == unknown_ids == []
all input_item_hash and ordinal bindings match
all terminal outcomes, including ABSTAIN and ERROR, are represented
```

游标只是恢复journal，不是完成真值；即使cursor写到EOF，只要coverage未PASS，就不得签发completion。反之，恢复时应从已封存分析记录和cursor共同重建状态，不能盲信AI最后一句话或单个offset。

一个worker可以在同一session中顺序处理整个小分片；大分片按预注册的`max_items_per_session`滚动session。滚动只改变执行载体，不改变`shard_id`、item顺序或科学attempt lineage。上下文不足、进程退出或工具失败都写入cursor和`ERROR`记录，不允许静默跳项或通过重新运行直到得到期望结论。

## 10. SV-T1/T2/T3：两棵树与Grove闭环

### 10.1 推理树（Reasoning/Solution Record Tree）

节点是版本化数学处境/occurrence view，边是Solver实际动作。必须表达：

- source rollout和attempt identity；
- root/point branch；
- revisit与representation change；
- lemma/certificate复用；
- 多父合流；
- failure/abandon/timeout/token-limit；
- proof completion与正确解答脉络相遇；
- raw Trace/Event/DAG provenance。

### 10.2 引导树（Guided Expansion Tree）

节点引用可启动的`BranchSnapshot`；边至少冻结：

- selector candidates/decision；
- Tell/Boundary/Renderer版本；
- HintInstance exact payload；
- lineage/state binding；
- resource contract；
- child launch identity；
- adopted/off-mechanism/failed/terminated outcome。

### 10.3 三个推动关系的机械验收

1. 引导树→Solver：冻结边能启动child且收到正确payload；
2. Solver→推理树：trajectory被增量/批量提取并append；
3. Solver→引导树：终点/分叉状态检索出新方向并产生新边。

`tree_nodes`增长而`guided_edges`为空只能判`HALF_LOOP`。完整POC必须产生至少一个新child；但终止/abstain负例也必须能正确停止，不能为“长边”强行误选Tell。
