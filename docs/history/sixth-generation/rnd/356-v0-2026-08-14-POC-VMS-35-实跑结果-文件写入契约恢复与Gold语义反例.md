### 3.2 Mathematical State Normalizer

```yaml
wallclock_seconds: 384.955198
exit_code: 0
timed_out: false
model: MATCH
output: present_and_strict_json
export: present_and_parseable
retry: 0

```

需要精确纠正一个表述：Normalizer 的 DONE **不是 hash 值错了**。它写入的 SHA-256 与最终 JSON 完全相同：

```text
1936ac45f5d5d6fda5d5cb1968d8196282c0540276117f0af102278a69740a6e
```

失败的是语法：evaluator 冻结要求单行

```text
normalized-reasoning-trajectory.json SHA256=<hash>
```

而角色资产只说“包含文件名和 SHA-256”。模型写成了多行 Markdown，包含正确文件名、正确 hash 和修正说明。这是**角色资产与 evaluator 语法不一致导致的 protocol false negative**，不是文件完整性损坏。机械 verdict 不回写，仍保留 `INCONCLUSIVE_PROTOCOL`。

语义上，Normalizer 做对了 canonical-state 合并和 `e7: CONTINUE→REUSE`，但：

- 将 `e2.status` 从 `ACTIVE` 改成 `ABANDONED`，gold 要求 `CONTRADICTED`；
- 额外改了 `e3` 的两条 incoming relation，违反“只修预埋三处错误”的 evaluator 要求。

所以即使忽略 DONE 形式，按冻结 gold 也会是 FAIL。

## 4. 三个重要反例

### 4.1 Gold 对 `ABANDONED` 与 `CONTRADICTED` 的定义不够可裁决

原始文本是：

```text
This becomes unusable modulo an arbitrary divisor, so I abandon the Binet route.
```

模型选 `ABANDONED`有直接文本根据。gold 选 `CONTRADICTED` 也可以被解释为“该方法与目标算术处境不相容”，但文本没有明言逻辑矛盾。

因此这个校准项不能继续当作单一 gold；应当允许 acceptable set，或者在 glossary 中明确 `CONTRADICTED` 的必要条件。

### 4.2 Revisit 的“状态相同”与“转换方法后目标”需要分层

原文说“回到原 gcd 目标，现在寻找 Euclidean reduction”。它同时包含：

- 与原目标相同的 problem-state；
- 已经改变的 strategy/method-state。

当前单一 `canonical_math_state_id` 迫使 evaluator 在两者中二选一。Extractor 的差异暴露出后续 Schema 可能需要分离：

```yaml
problem_state_id:
strategy_state_id:
representation_state_id:
```

或使用明确的 StateView/EquivalenceRelation，而不是继续把多层相同性压进一个 ID。

### 4.3 Auditor 的 aggregate policy 没有写入角色资产

Auditor AGENTS 只定义了总 verdict 枚举，没有规定：

```text
只要一条 candidate FAIL，整体必须 FAIL
```

对“一条通过、一条失败”，写 `PARTIAL` 并非违反现有资产的自然语义。这是 evaluator-only 政策泄漏：判分规则没有完整地进入被测合同。

下一版必须把 aggregate policy 冻结进角色资产，或者不将总 verdict 作为模型任务，改为由程序从逐条 verdict 机械派生。后者更可取。

- Solver 或 Tell/Hint 管线已接入。

## 6. 修订决策

下一版不应简单“微调 prompt 再跑一次”。必须分层修订：

1. **机械提交层**：所有角色资产统一写入单行 hashed-DONE 精确语法，或将 DONE 生成彻底交给可信 adapter；
2. **审计聚合层**：Auditor 只逐条判 candidate，overall 由机械规则派生；
3. **状态等价层**：发布带多层 state view 或 acceptable-equivalence set 的 Schema 候选；
4. **gold 层**：两位独立 Reviewer 盲审 `ABANDONED/CONTRADICTED` 和 revisit edge 政策，允许 acceptable set；
5. **调试运行层**：按 355 号实现 tmux 交互档，但不把调试 run 冒充确认性证据；
6. **安全层**：对 no-sandbox 路径单独做 sibling workspace/Vault/forbidden-path canary，强隔离未 PASS 前不进生产。

POC-VMS-35 的校准集已经被消费，今后只能作 development/regression；修订后的确认性证据必须来自新的 prospective pack。
