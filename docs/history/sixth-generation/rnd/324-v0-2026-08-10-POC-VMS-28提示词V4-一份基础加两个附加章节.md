```
### 附加章节A：树状输入（过程A——分析推理AI的上下文）

如果你分析的输入是推理AI的thinking/trajectory，你的输入是树状的。

#### 为什么是树状的

推理AI在探索时不会一条路走到底——它可能探索一个方向，走不通就折返，换一个方向继续探索。所以推理AI的上下文不是一条线，而是一棵树：
- 树的根是题目
- 树的每个分叉是AI选择了一个方向
- 树的每条边是一段探索
- 树的每个叶子是AI停止探索的位置（走通了/走不通了/token用尽了）

#### 怎么分析树状输入

**第一步：识别树的结构**

从推理AI的thinking中识别出树的结构：
- AI在哪里分叉了（选择了某个方向）
- AI在哪里折返了（放弃了某个方向）
- AI在哪里重新探索了（折返后选了新方向）
- 从根到每个叶子节点有几条脉络

**第二步：把树看成从根到每一个叶子节点的N条脉络**

这是树状分析的核心——不要把树压扁成线性。树状的上下文不是"一条线"，折返不是"后退"，而是"分叉"。

把树拆成N条脉络——每条脉络是从根到某个叶子节点的一条完整探索路径。每条脉络是一条独立的"线性"思维过程，可以独立格化。

【例子】假设AI的探索树是这样的：
```
根（题目）
├── 方向A：尝试贪心方法
│   ├── 排序后从小到大跳跃
│   └── 发现不work（折返点）
├── 方向B：尝试归纳方法
│   ├── 对n做归纳
│   ├── 定义关键变量x
│   ├── 分三种情况
│   │   ├── Case 1：鸽巢论证找安全元素 → 成功
│   │   ├── Case 2：基数约束应用归纳 → 成功
│   │   └── Case 3：交换技巧跳过最大 → 成功
│   └── 整合三种情况 → 证毕
└── 方向C：尝试概率方法
    └── 发现不适用（折返点）
```

这棵树有3条从根到叶子的脉络：
- 脉络1：根→方向A→排序→发现不work（失败的探索路径）
- 脉络2：根→方向B→归纳→定义x→分情况→Case1/2/3→整合→证毕（成功的探索路径）
- 脉络3：根→方向C→发现不适用（失败的探索路径）

**第三步：每条脉络独立格化**

对每条脉络，用前面说的格化方法（Level视图、有意义的合并）独立格化。N条脉络产出N组Level视图。

脉络1（失败的探索）的Level视图和trace，和脉络2（成功的探索）的Level视图和trace，是独立的——不要混在一起。

**第四步：识别分叉位置本身的trace**

这是树状输入（过程A）特有的trace类型——线性输入（过程B）没有。

AI在分叉位置选了某个方向没选另一个方向，这个选择本身是一个trace。这种trace叫"分叉位置trace"。

【例子】在上面的树中：
- 在"根→方向A vs 方向B"的分叉位置，AI选了方向A（贪心）没选方向B（归纳）。这个选择本身是trace——"AI面对排列存在性问题，优先尝试贪心方法而不是归纳方法"。
- 在"方向B→Case 1/2/3"的分叉位置，AI选择了分三种情况处理。这个选择本身是trace——"AI在归纳方法中，选择按M中元素位置分类讨论"。
- 在"根→方向B vs 方向C"的分叉位置，AI选了方向B（归纳）没选方向C（概率方法）。这个选择本身是trace——"AI在贪心失败后，选择归纳方法而不是概率方法"。

分叉位置trace很重要——它们是系统在引导树上开新边的依据。系统看到"AI选了A没选B"，就会在分叉位置开新边，启动新AI走B方向。

**第五步：识别折返后重新探索的语义关联**

AI折返后选了新方向，新方向和旧方向的关系本身可能是非局部trace。

【例子】AI先尝试贪心方法（方向A），发现不work后折返，选择了归纳方法（方向B）。这个"从贪心转向归纳"本身是一个非局部trace——"AI从贪心方法失败中认识到需要更强的归纳结构"。这个trace跨方向A和方向B，只有把方向A的失败和方向B的选择合在一起看才能识别出。

这种trace非常重要——它反映了AI的"学习"过程——从失败中认识到需要换策略。系统可以用这种trace启发其他AI——"当你尝试贪心方法失败时，考虑转向归纳方法"。

#### 树状分析的产出

你的产出应该包括：
1. **树的结构**——分叉位置、折返位置、从根到每个叶子的脉络
2. **每条脉络的段划分和Level视图**——N条脉络各自格化
3. **每条脉络上的trace**——N条脉络各自的局部/非局部/全局trace
4. **分叉位置trace**——每个分叉位置的选择本身是trace（过程A特有）
5. **折返后重新探索的语义关联trace**——跨方向的非局部trace（过程A特有）

### 附加章节B：线性输入（过程B——分析已有题目和解答）

如果你分析的输入是已有题目和解答记录，你的输入是线性的。

#### 为什么是线性的

已有题目和解答记录是一条完整的解题路径——解答者从题目到答案一路走完，没有折返（或者折返已经在解答文本中被抹去了——解答文本通常只呈现最终的正确路径）。

#### 怎么分析线性输入

线性输入比树状输入简单——不需要识别树的结构，不需要把树拆成N条脉络，不需要识别分叉位置trace。

直接用前面说的格化方法（Level视图、有意义的合并）对这条线性脉络格化，在每个Level视图上识别trace。

#### 线性输入没有的东西

和树状输入（过程A）相比，线性输入（过程B）没有：
- **没有分叉位置trace**——解答文本是已完成的路径，没有"选了A没选B"的分叉位置
- **没有折返后重新探索的语义关联trace**——解答文本没有折返
- **没有失败的探索路径**——解答文本只呈现成功的路径

但这不意味着线性输入的trace比树状输入少——线性输入可能有更丰富的非局部trace和全局trace，因为解答者在一个领域深耕，产出了深层的策略模式。树状输入的trace可能更"广"（多个方向的探索），线性输入的trace可能更"深"（一个方向的深层策略）。

#### 线性分析的产出

你的产出应该包括：
1. **段划分**——把解答分成最细的段
2. **所有有意义的Level视图**——段的不同合并方式
3. **每个Level视图上的trace**——局部/非局部/全局trace
```

## 3. V4的设计思路

### 3.1 为什么用方案C（一份基础+两个附加章节）

- **共用部分占80%**——FCA/Hasse图、trace三种类型、8种复杂情况、7种反模式、"为什么"章节、"影响例子"章节，过程A和过程B完全一样
- **差异只在输入处理**——过程A要把树状输入拆成N条脉络，过程B直接处理线性脉络
- **维护一份**——共用部分不重复，附加章节聚焦

### 3.2 树状分析的核心——N条脉络

用户指出"树状的情况的分析，其实非常重要，需要把树看成是从根到每一个叶子节点的N条脉络"。

V4的附加章节A第二步就是这个核心——把树拆成N条脉络，每条脉络是从根到某个叶子节点的一条完整探索路径，每条脉络独立格化。

### 3.3 分叉位置trace——过程A特有的trace类型

319号types.py中Trace的`is_branch_position`字段就是为这个设计的——过程A中分叉位置本身可能就是trace。V4的附加章节A第四步把这个形式化定义转化为提示词中的具体指导。

### 3.4 折返后重新探索的语义关联——跨方向非局部trace

这是V4新增的认知——AI折返后选了新方向，新方向和旧方向的关系本身可能是非局部trace。这种trace反映了AI的"学习"过程——从失败中认识到需要换策略。系统可以用这种trace启发其他AI。
