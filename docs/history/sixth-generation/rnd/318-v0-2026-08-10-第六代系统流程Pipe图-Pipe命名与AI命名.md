## 1. 完整流程Pipe图

```
[Pipe 0: Solver AI] ── 推理探索
  │
  │ 输入：题目 + 脉络 + 方向Q
  │ 工作：推理AI对题目探索
  │ 输出：thinking / trajectory
  │
  ▼
[Pipe 1: Parser AI] ── 提取格化全Level Trace
  │
  │ 输入：thinking（过程A）或 解答记录（过程B）
  │
  │ 步骤1：分析脉络
  │   过程A：从thinking中分析 → 可能是有分叉的树/DAG
  │   过程B：从解答记录中分析 → 通常是线性脉络
  │
  │ 步骤2：格化脉络 → 所有Level视图
  │   过程A：在有分叉的脉络上格化 → 多个分支分别格化
  │   过程B：在线性脉络上格化
  │
  │ 步骤3：识别trace（全Level）
  │   过程A：分叉位置本身可能就是trace（AI选了A没选B）
  │   过程B：不需要考虑分叉位置
  │
  │ 输出：trace集合
  │
  ▼
[Pipe 2: Telling AI] ── 并发trace→tell匹配
  │
  │ 输入：trace集合
  │ 步骤4：在每个对应分类目录中启动Devin CLI实例
  │        加载该目录AGENTS.md，遍历tell做匹配
  │ 输出：trace→tell匹配结果（每个trace匹配到0个或多个tell）
  │
  │ 注：过程A和过程B完全相同
  │
  ▼
  步骤5分叉 ── 不是独立Pipe，是Parser AI和Guide AI的后续职责
  │
  ├──────────────────────────┬──────────────────────────┐
  │ 过程A（推理AI上下文）      │ 过程B（外部解答记录）      │
  │                          │                          │
  │ 匹配到tell？              │ 匹配到tell？              │
  │   是 → 取hint             │   是 → 确认匹配（不需要新建）│
  │        → 送入Pipe 3       │                          │
  │   否 → [Parser AI]        │   否 → [Parser AI]        │
  │        存档孤悬trace       │        去特化trace        │
  │        （按tell分类学分类） │        建立新(tell,hint)   │
  │        → 启发过程B的Pipe 1 │        存入对应目录AGENTS.md│
  │                          │        → tell库增长        │
  ├──────────────────────────┴──────────────────────────┘
  │（过程A的hint）
  ▼
[Pipe 3: Guide AI] ── 引导树填充
  │
  │ 输入：hint
  │ 工作：
  │   1. 判断hint在引导树哪个Level开新边
  │      （局部trace的hint在单节点开新边）
  │      （非局部trace的hint在段级位置开新边）
  │   2. 在引导树上开新边
  │   3. 构造脉络（从根到新边的路径+方向Q）
  │   4. 启动新Solver AI
  │ 输出：引导树新边 + 新Solver AI
  │
  ▼
  回到Pipe 0 ── Grove核心循环继续
```

## 2. Pipe命名与AI命名

### 2.1 四个Pipe和对应的AI

| Pipe | Pipe名 | AI名 | 职责 |
|---|---|---|---|
| Pipe 0 | Solver Pipe | Solver AI | 推理探索，产生thinking/trajectory |
| Pipe 1 | Parser Pipe | Parser AI | 提取格化全Level Trace（步骤1-3）+ 步骤5的存档/建立新tell |
| Pipe 2 | Telling Pipe | Telling AI | 并发trace→tell匹配（步骤4） |
| Pipe 3 | Guide Pipe | Guide AI | 引导树填充，启动新Solver AI |

### 2.2 命名规则

**用Pipe的名命名承载该Pipe的AI**：
- Solver Pipe承载的AI → Solver AI
- Parser Pipe承载的AI → Parser AI
- Telling Pipe承载的AI → Telling AI
- Guide Pipe承载的AI → Guide AI

### 2.3 和旧命名的对应

| 旧命名（316号/315号/第五代） | 新命名（本文档） | 说明 |
|---|---|---|
| 推理AI | Solver AI | 统一命名 |
| 分析AI | Parser AI（过程A中） | "分析AI"这个名字不再使用，统一为Parser AI |
| Parser AI（315号定义） | Parser AI（过程B中） | 315号中Parser AI只做过程B，现在统一为过程A和过程B都做 |
| Telling AI | Telling AI | 不变 |
| 辅助AI（第五代） | Parser AI + Telling AI + Guide AI | 第五代的"辅助AI"职责被拆分到三个AI |

### 2.4 第五代"辅助AI"的拆分

第五代中"辅助AI"承担了所有非推理AI的工作——采集、整理、检索、启动。第六代中这些工作被拆分到三个AI：

| 第五代辅助AI的工作 | 第六代由谁做 |
|---|---|
| 采集thinking | Parser AI（步骤1的输入） |
| 整理两棵树（提取节点） | Parser AI（步骤1-3） |
| 在节点上识别方向（检索） | Parser AI（步骤1-3）+ Telling AI（步骤4） |
| 构造脉络 | Guide AI（步骤3的工作） |
| 启动新AI | Guide AI |
| 检查停机 | Guide AI |
| 并发管理 | Guide AI |

## 3. Parser AI的完整定义

### 3.1 Parser AI的核心能力

**提取格化全Level Trace**——这是Parser AI的核心能力，在过程A和过程B中都用。

### 3.2 Parser AI在过程A中的职责

1. **步骤1-3：提取格化全Level Trace**
   - 输入：推理AI的thinking/trajectory
   - 分析脉络（可能是有分叉的树/DAG）
   - 格化脉络→所有Level视图（多个分支分别格化）
   - 识别trace（全Level，包括分叉位置本身的trace）

2. **步骤5过程A的后续**
   - 匹配到tell → 取hint，送入Guide AI
   - 没匹配到tell → 存档孤悬trace（按tell分类学分类）→ 启发过程B的Parser AI

### 3.3 Parser AI在过程B中的职责

1. **步骤1-3：提取格化全Level Trace**
   - 输入：外部题目+解答记录
   - 分析脉络（通常是线性脉络）
   - 格化脉络→所有Level视图（在线性脉络上格化）
   - 识别trace（全Level，不需要考虑分叉位置）

2. **步骤5过程B的后续**
   - 匹配到tell → 确认匹配（不需要新建）
   - 没匹配到tell → 去特化trace → 建立新(tell,hint) → 存入对应目录AGENTS.md → tell库增长

### 3.4 Parser AI统一了"分析AI"和"Parser AI"

316号中的"分析AI"和315号中的"Parser AI"是同一个AI在不同过程中的角色。现在统一为Parser AI——它在过程A和过程B中都用同一套核心能力（提取格化全Level Trace），只是输入性质不同导致处理方式有差异。

## 4. 步骤1-3在过程A和过程B中的差异——修正315号§6.2.2

### 4.1 315号§6.2.2的说法

315号§6.2.2说"步骤1-4完全相同"——这是不准确的。

### 4.2 修正后的准确说法

| 步骤 | 过程A（推理AI上下文） | 过程B（外部解答记录） | 是否相同 |
|---|---|---|---|
| 步骤1：分析脉络 | 从thinking中分析——可能是有分叉的树/DAG | 从解答记录中分析——通常是线性脉络 | **相似但不完全相同** |
| 步骤2：格化脉络 | 在有分叉的脉络上格化——多个分支分别格化 | 在线性脉络上格化 | **相似但不完全相同** |
| 步骤3：识别trace | 分叉位置本身可能就是trace（AI选了A没选B） | 不需要考虑分叉位置 | **相似但不完全相同** |
| 步骤4：Telling AI并发分类分析 | 拿着trace找tell | 拿着trace找tell | **完全相同** |
| 步骤5：分叉 | 存档孤悬trace / 取hint填引导树 | 确认匹配 / 建立新(tell,hint) | **不同** |

### 4.3 差异的具体内容

**步骤1的差异——脉络结构不同**：
- 过程A的输入是推理AI的thinking——推理AI在探索时可能走多条路，thinking可能是有分叉的树或DAG
- 过程B的输入是解答记录——解答记录通常是一条完整的解题路径，是线性的
- 处理有分叉的脉络和处理线性脉络的方式有差异——需要先梳理成从根到叶子的一条条脉络

**步骤2的差异——格化对象不同**：
- 过程A格化有分叉的脉络——需要在多个分支上分别格化，每个分支找出自己的所有Level视图
- 过程B格化线性脉络——只在一条线上格化，找出这条线的所有Level视图
- 格化树/DAG和格化线性序列是不同的操作

**步骤3的差异——trace类型不同**：
- 过程A中分叉位置本身可能就是trace——推理AI在分叉位置选了A没选B，这个选择本身是一个trace（第五代的核心tell识别就是这种——"AI在哪里可以分叉但没分叉"）
- 过程B中没有这个问题——解答记录是已经完成的解答，没有"选了A没选B"的分叉位置
- 过程A需要识别分叉位置本身的trace，过程B不需要

### 4.4 更准确的说法

**步骤1-3相似但不完全相同**——Parser AI用同一套核心能力（提取格化全Level Trace），但针对输入性质的不同（有分叉/未完成 vs 线性/已完成）做不同的处理。

**步骤4完全相同**——Telling AI并发分类分析对任何trace都一样，不关心trace来自过程A还是过程B。

**步骤5不同**——这是已确认的。

## 5. Pipe之间的关系

### 5.1 数据流

```
Solver AI ──thinking──→ Parser AI ──trace集合──→ Telling AI ──trace→tell匹配──→ 分叉
                                                                                    │
                                              ┌─────────────────────────────────────┤
                                              │ 过程A                                │ 过程B
                                              │                                     │
                                              │ 取hint → Guide AI                    │ Parser AI建立新(tell,hint)
                                              │          │                           │     │
                                              │          ▼                           │     ▼
                                              │ 启动新Solver AI                      │ tell库增长
                                              │          │                           │     │
                                              │          ▼                           │     ▼
                                              │ 回到Solver AI                        │ 启发过程B的Parser AI
                                              │                                     │
                                              └─────────────────────────────────────┘
```

### 5.2 并行关系

- **Solver AI（Pipe 0）和Parser AI（Pipe 1）并行**——Solver AI在thinking的同时，Parser AI就从thinking中增量提取trace。不需要等Solver AI跑完。
- **多个Telling AI（Pipe 2）并发**——每个Telling AI是一个Devin CLI实例，在对应分类目录中并发做trace→tell匹配。
- **多个Solver AI（Pipe 0）并发**——Guide AI启动多个新Solver AI，每个走一个方向。
- **过程A和过程B可以并行**——系统在运行过程A（Grove核心循环）的同时，可以间歇运行过程B（Parser AI处理外部解答记录增长tell库）。

### 5.3 循环关系

**Grove核心循环**（过程A）：
```
Solver AI → Parser AI → Telling AI → Guide AI → Solver AI → ...
```

**tell库增长循环**（过程B）：
```
外部解答记录 → Parser AI → Telling AI → Parser AI（建立新tell）→ tell库增长
                                                              ↓
                                                    启发过程A的未来匹配
```

**两个循环的交汇点**：
- 过程A的"没匹配到tell的trace"存档后启发过程B的Parser AI
- 过程B的"建立新(tell,hint)"让tell库增长，让过程A的未来匹配能找到更多tell
