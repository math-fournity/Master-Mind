## 2. 关键概念：什么是原语

### 2.1 原语定义

**原语 = 构造系统的积木。** 你能说"用这个"然后知道下一步做什么（操作原语），或者能把它放置到系统架构中（结构原语）。

**原语三判据**（必须同时满足）：

1. **可执行性**：对应一个可执行的操作，或一个可放置的结构元素
2. **可验证性**：能在实验中观察"用了它"和"没用它"的区别
3. **构造性**：是积木不是地图——用来构造系统，不是用来理解系统

**不满足三判据的归入**：
- **概念框架**（`concepts/`目录）——理解系统的视角（如形式化边界、两种计算、闭环）。不满足"构造性"——是用来理解系统而不是构造系统的。
- **性质标准**（`criteria/`目录）——判断原语好坏的标准（如自然性、生死条件）。不满足"可执行性"——是判断标准而不是可执行操作。

## 6. 并发度策略：滑动窗口（max 5 concurrent）

### 失败教训

原计划用"分批20个subagent"的同步屏障策略，因瞬间并发量过大导致计划挂掉。

### 修正策略：滑动窗口

**逻辑上**：每份文档一个subagent，Pass 1共~200个任务。

**执行上**：用滑动窗口控制并发——任何时刻最多5个subagent在跑。

- **不是分批**：分批是同步屏障（一批全做完才启动下一批），有等待空窗
- **滑动窗口**：始终保持5个在跑，跑完一个立刻从队列取下一个启动，没有等待屏障

### Pass 2-5 并发策略

- Pass 2：7个subagent，滑动窗口max 5并发
- Pass 3-5：subagent数少（2→1→1），顺序执行
