# 原语提取：206-203提示作弊CheckList

## 文档概述

本文档是203号方案的细化Check List，用于解决200号诊断出的"提示作弊"问题——即系统给Solver的提示中可能泄漏了答案等价信息，导致增益来源不诚实。文档包含三个模块：203-A提示分级+泄漏审计、203-B truth_vault隔离、203-C诚实降级实验。与检索机制的关系在于：提示分级定义了检索结果的知识层级分类，四门审计是检索结果的泄漏过滤机制，truth_vault隔离是检索过程中的角色级访问控制，诚实降级实验是验证检索结果是否真正有贡献的评估方法论。

## 提取的原语

### 原语：提示三级分级体系
- **ID**：206-P1
- **类型**：结构原语
- **描述**：将提示/检索结果按知识泄漏程度分为三级（knowledge/strategy/meta），每级有明确判定标准和边界处理规则。
- **溯源**：206, 第21-25行, 原文引用："定义3级提示：`knowledge`（给具体数学事实）/`strategy`（给解题方向）/`meta`（给元提示）……边界情况：一条提示同时包含knowledge和strategy（按最高级别标注）"
- **依赖关系**：
  - 依赖：无
  - 支撑：206-P2（四门审计需要知道提示级别以决定降级目标）、206-P5（诚实降级实验需要按级别分组）
- **与检索机制的关系**：检索结果返回后需要标注知识层级——这决定了检索结果可以被哪些角色消费、需要经过何种过滤。分级体系是检索结果元数据标注的基础结构。

### 原语：提示级别常量化与逐条标注
- **ID**：206-P2
- **类型**：操作原语
- **描述**：将提示级别定义为系统常量（HINT_LEVELS），对每条现有提示逐条标注级别，无法明确分级的标注"mixed"并拆分。
- **溯源**：206, 第27-30行, 原文引用："在guided_loop.py中定义`HINT_LEVELS = {"knowledge": ..., "strategy": ..., "meta": ...}`……5条现有硬编码提示逐条标注级别……边界情况：某条提示无法明确分级（标注"mixed"并拆分）"
- **依赖关系**：
  - 依赖：206-P1（三级分级体系定义）
  - 支撑：206-P3（审计调用需要级别信息）、206-P4（记录到结果文件）
- **与检索机制的关系**：检索结果需要被标注级别标签，这是检索结果的后处理步骤——每条从认知图/依赖图中检索出的Pattern都需要被分级，以便下游消费方按级别过滤。

### 原语：四门审计前置过滤
- **ID**：206-P3
- **类型**：操作原语
- **描述**：在提示/检索结果发出前调用四门审计（run_four_gates），如果审计结果为fail则拒绝该提示并自动降级为meta级提示。
- **溯源**：206, 第32-37行, 原文引用："提示发出前调用`auditor.run_four_gates(hint, task)`……如果overall_result=="fail"，提示被拒绝，降级为meta级提示……边界情况：task为空（无标准答案时四门审计的gate1/gate2无法执行——需定义无答案时的fallback）"
- **依赖关系**：
  - 依赖：206-P1（分级体系，降级目标为meta级）、206-P7（truth_vault存储标准答案供审计比对）
  - 支撑：206-P5（诚实降级实验验证审计有效性）
- **与检索机制的关系**：这是检索结果的质量门控机制——检索到的Pattern在传递给消费者之前，必须经过泄漏审计过滤，确保不包含答案等价信息。这是检索管道中的安全检查点。

### 原语：提示级别与审计结果持久化
- **ID**：206-P4
- **类型**：结构原语
- **描述**：在turn_history的每个turn中增加hint_level和leakage_audit字段，记录提示级别和四门审计分数及结果，无提示的turn记为null。
- **溯源**：206, 第39-42行, 原文引用："在turn_history的每个turn中增加`hint_level`和`leakage_audit`字段……leakage_audit字段包含四门分数和overall_result……边界情况：无提示的turn（hint_level=null, leakage_audit=null）"
- **依赖关系**：
  - 依赖：206-P2（级别标注）、206-P3（审计结果）
  - 支撑：206-P5（实验分析需要读取这些记录）
- **与检索机制的关系**：检索结果的元数据持久化——每次检索操作的级别标签和审计结果都被记录，形成可审计的检索日志，支持后续的检索质量分析和反馈闭环。

### 原语：truth_vault隔离集合
- **ID**：206-P5
- **类型**：结构原语
- **描述**：在数据库中创建独立的truth_vault collection存储标准答案，document schema为{answer, problem_id, source, created_at}，与可检索的知识集合物理隔离。
- **溯源**：206, 第64-67行, 原文引用："在ArangoDB中创建truth_vault collection……定义truth_vault的document schema：`{answer, problem_id, source, created_at}`"
- **依赖关系**：
  - 依赖：无
  - 支撑：206-P3（四门审计需要从truth_vault取标准答案比对）、206-P6（角色隔离的访问对象）
- **与检索机制的关系**：这是检索机制中的"不可检索区"设计——标准答案存储在独立集合中，不参与常规检索流程，仅审计角色可访问。这确保检索结果不会直接包含答案，是检索安全性的数据结构基础。

### 原语：角色级可见性标签强制检查
- **ID**：206-P6
- **类型**：操作原语
- **描述**：为每个角色设置可见性标签（如Controller的can_read_truth_vault=False），编译提示时强制检查可见性，违反时抛出PermissionError。
- **溯源**：206, 第74-78行, 原文引用："Controller的可见性标签设为`can_read_truth_vault=False`……编译提示时只能从K维度取知识，不能从truth_vault取……有可执行的可见性检查代码，违反时抛出PermissionError"
- **依赖关系**：
  - 依赖：206-P5（truth_vault集合存在）
  - 支撑：206-P3（审计角色的独占访问权）
- **与检索机制的关系**：这是检索机制中的访问控制原语——不同角色对认知图/依赖图的不同区域有不同的检索权限。检索请求发出前，先检查请求方角色是否有权检索目标集合，无权则拒绝。这保证了检索结果的安全性。

### 原语：无标准答案时的fallback标记
- **ID**：206-P7
- **类型**：操作原语
- **描述**：当问题无标准答案时，truth_vault为空，四门审计的gate1/gate2标记为N/A而非报错，系统继续运行。
- **溯源**：206, 第72行, 原文引用："边界情况：无标准答案的问题（truth_vault为空——四门审计的gate1/gate2标记N/A）"
- 依赖关系：
  - 依赖：206-P3（四门审计）、206-P5（truth_vault）
  - 支撑：无
- **与检索机制的关系**：检索机制的优雅降级原语——当审计所需的参照数据不存在时，不是报错中断，而是标记N/A并继续。这保证了检索流程在数据不完整时的鲁棒性。

### 原语：A/B/C三组对照实验设计
- **ID**：206-P8
- **类型**：概念框架
- **描述**：通过三组对照实验（A无提示/B完整提示/C去知识提示）比较表现差异，判断增益来源是knowledge还是strategy，从而验证检索结果是否真正有贡献。
- **溯源**：206, 第96-99行, 原文引用："定义三组实验：A组（无提示）/ B组（完整提示）/ C组（去知识提示，只保留strategy+meta）……测量指标：完成率、turn数、提示有效率、数学正确性"
- **依赖关系**：
  - 依赖：206-P1（分级体系，C组去掉knowledge级）、206-P4（实验记录）
  - 支撑：无
- **与检索机制的关系**：这是检索机制有效性的评估方法论——通过消融实验（去掉某一层级的检索结果）来量化该层级检索结果的真实贡献。如果去掉knowledge层后表现不变，说明检索机制没有提供超越答案泄漏的价值。

### 原语：增益来源判断决策树
- **ID**：206-P9
- **类型**：操作原语
- **描述**：基于三组实验结果，用决策树判断增益来源：C≈A→增益来自knowledge→降级为编译器；C≈B→增益来自strategy→不是作弊；A<C<B→部分来自两者→需进一步细分。
- **溯源**：206, 第129-133行, 原文引用："如果C≈A → 增益主要来自knowledge → 降级为编译器……如果C≈B → 增益主要来自strategy → 不是作弊……如果A < C < B → 部分来自strategy，部分来自knowledge → 需要进一步细分"
- **依赖关系**：
  - 依赖：206-P8（三组对照实验）
  - 支撑：无
- **与检索机制的关系**：这是检索机制价值评估的决策原语——通过实验数据驱动判断检索的哪个层级真正提供了价值，而非主观假设。这指导检索机制应保留/强化哪些层级的检索能力。
