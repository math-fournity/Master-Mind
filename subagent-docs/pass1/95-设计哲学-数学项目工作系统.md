# 原语提取：95-设计哲学-数学项目工作系统

## 文档概述

本文档是数学项目工作系统的设计哲学文档，归纳了7+3=10个设计决策，涵盖认知依赖的图管理、版本链处理认知迭代、拓扑覆盖验证、认知检查点集成工作流、经典计算展开依赖图骨架、两套图共享ArangoDB、意识节点双重身份等核心设计。文档虽然以哲学层面为主，但其中多个设计决策直接定义了检索机制所依赖的底层数据结构、索引结构、匹配算法和知识分层方式，是检索机制设计的顶层约束来源。

## 提取的原语

### 原语：有限上下文与无限认知积累的核心矛盾
- **ID**：95-P1
- **类型**：概念框架
- **描述**：AI上下文有上限而项目认知积累无限，跨session无记忆，这是检索机制存在的根本动因——检索机制的本质就是解决"无限积累 vs 有限上下文"的矛盾。
- **溯源**：95, 第11-15行, 原文引用："项目的认知积累是无限的：80-94号文档持续积累数学方法论、POC经验、工作系统设计 / AI的上下文是有限的：无论128K还是200K token，总有上限；上下文压缩后，早期认知会丢失 / 跨session没有记忆：新session的AI不知道上一个session做了什么、想了什么、决定了什么"
- **依赖关系**：
  - 依赖：无（顶层约束）
  - 支撑：95-P2（数学项目特殊矛盾）、95-P8（图管理认知依赖）、95-P9（版本链处理认知迭代）
- **与检索机制的关系**：定义了检索机制的存在理由——检索机制的核心任务就是在有限上下文中，从无限积累的认知库中选取当前任务所需的认知单元。这是检索机制的第一性原理。

### 原语：数学证明的长依赖链约束
- **ID**：95-P2
- **类型**：概念框架
- **描述**：数学证明的依赖链很长（如18个节点25条边2个螺旋环路），AI需要在一次session中保持对整个依赖链的理解，这要求检索机制能沿依赖链进行图遍历式检索而非孤立节点检索。
- **溯源**：95, 第21行, 原文引用："数学证明的依赖链很长：一个证明可能涉及18个节点25条边2个螺旋环路（POC-2），AI需要在一次session中保持对整个依赖链的理解"
- **依赖关系**：
  - 依赖：95-P1（核心矛盾）
  - 支撑：95-P8（图管理认知依赖）、95-P14（图遍历+集合差集做覆盖验证）
- **与检索机制的关系**：要求检索机制支持"依赖链追踪式检索"——不是检索单个节点，而是检索一个连通子图（依赖链的完整上下文）。检索结果必须包含节点间的边关系，而不仅仅是节点列表。

### 原语：螺旋环路处理认知迭代
- **ID**：95-P9

- **描述**：认知依赖不是纯DAG，存在环路，且环路有时在平面上（循环依赖），有时是螺旋上升的（迭代深化），检索机制需要能处理环路结构而非假设纯DAG。
- **溯源**：95, 第47行, 原文引用："其中的依赖线路，不是DAG，出现了环路，但是环路有时候是在平面上的，有时候，却是螺旋上升的。"
- **依赖关系**：
  - 依赖：95-P8（图管理认知依赖）
  - 支撑：95-P10（版本链处理认知迭代）
- **与检索机制的关系**：要求检索机制能处理环路——不能假设依赖图是纯DAG（拓扑排序只在DAG上有效）。螺旋环路意味着同一认知单元在不同迭代轮次中有不同版本，检索需要能区分"同一轮次的循环依赖"和"跨轮次的迭代深化"。
