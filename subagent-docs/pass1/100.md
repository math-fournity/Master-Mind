# 原语提取：100-反哺方案执行计划-细化CheckList与测试方案

## 文档概述

100号文档是99号反哺方案的执行级文档，将6个反哺点细化为可执行的CheckList和测试方案，按P0→P1→P2→P3优先级顺序执行。文档涵盖：经典计算展开替代步骤2（反哺1）、CP1-CP3加载数学意识（反哺2）、版本链管理数学认知演化（反哺3）、回归验证保障持续质量（反哺4）、三层提取版本链管理（反哺6）、自动发现新数学意识（反哺5）。全部测试通过（10/10）。

文档核心围绕ArangoDB图数据库中的认知单元管理——种子选择、图遍历、版本链、回归验证、三层提取——这些机制直接构成了从稀疏矩阵（认知图/依赖图）中检索Pattern的基础设施。与253号定义的检索问题（状态感知→Pattern提取→知识悖论三层结构）高度相关：种子推荐表是索引结构原语，图遍历是Pattern提取算法原语，版本链是知识演化追踪原语，三层提取是知识分层原语，回归验证是效果度量原语。

## 提取的原语

### 原语：种子推荐表——问题类型到意识种子的映射索引
- **ID**：100-P1
- **类型**：结构原语
- **描述**：建立数学问题类型→推荐意识种子的映射表，作为从问题状态到认知存储的入口索引。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第46行, 原文引用："建立"种子推荐表"——数学问题类型→推荐意识种子映射"
- **依赖关系**：依赖：认知单元在ArangoDB中的存在 / 支撑：图遍历检索的入口选择（CP1种子选择）
- **与检索机制的关系**：直接支撑检索第一层（状态感知）。种子推荐表是一种"问题类型→检索入口"的索引结构——当工作智能体处于某种问题状态时，先识别问题类型，再通过种子推荐表定位到起始检索节点。这对应253号第6.4节"按思维模式分类索引"和"按数学结构分类索引"的方向。种子推荐表覆盖5种问题类型（极值/上下界、证明构造、跨领域、逼近/误差分析、一般证明），每种类型有推荐种子+推荐理由（第150行）。

### 原语：从种子出发的图遍历检索
- **ID**：100-P2
- **类型**：操作原语
- **描述**：从数学意识种子节点出发，在依赖图中进行深度受限的图遍历，找到相关的认知单元和数学意识。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第47行, 原文引用："验证从数学意识种子出发的图遍历能找到相关认知单元"
- **依赖关系**：依赖：种子推荐表（100-P1）提供起始节点 / 支撑：Pattern提取（检索第二层）
- **与检索机制的关系**：直接支撑检索第二层（Pattern提取）。这是253号第3.3节"图遍历"方案的具体实现——"从当前状态对应的节点出发，在依赖图中遍历"。图遍历以种子节点为起点，通过depth参数控制遍历深度（实测depth=7找到17个认知单元，第151行），从海量存储中快速定位相关Pattern，避免全量扫描。实测从`numerical_check`+`extreme_testing`出发找到17个认知单元，包含全部6个关键认知单元；从`seven_step_workflow`出发找到26个，包含全部5个数学意识。

- **ID**：100-P3
- **类型**：操作原语
- **描述**：种子选择（CP1）→图遍历（CP2）→缺口检查（CP3）的三阶段检索pipeline，从问题状态到认知加载的完整流程。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第48行, 原文引用："验证CP1-CP3完整流程：种子选择→图遍历→缺口检查"
- **依赖关系**：依赖：种子推荐表（100-P1）、图遍历（100-P2） / 支撑：完整检索流程的管道化
- **与检索机制的关系**：直接对应253号检索问题的三层结构的工程化实现。CP1（种子选择）对应状态感知——从问题状态识别该用什么种子；CP2（图遍历）对应Pattern提取——从种子出发在图中检索；CP3（缺口检查）对应质量验证——检查检索结果是否覆盖所需认知。实测模拟"矩条件极差题"：CP1选4个意识种子→CP2图遍历找到17个认知单元→CP3缺口检查覆盖率100%（9/9所需认知全部覆盖）（第152行）。

### 原语：缺口检查——检索结果完备性验证
- **ID**：100-P4
- **类型**：操作原语
- **描述**：在图遍历检索后，检查已加载的认知单元是否覆盖了当前问题所需的全部认知，计算覆盖率作为完备性度量。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第48行, 原文引用："验证CP1-CP3完整流程：种子选择→图遍历→缺口检查"
- **依赖关系**：依赖：图遍历结果（100-P2）、所需认知集合的定义 / 支撑：检索质量保障
- **与检索机制的关系**：支撑检索第二层（Pattern提取）的质量保障。缺口检查是一种"检索后验证"机制——不仅要求找到相关Pattern，还要求覆盖率达到阈值（实测≥80%，第69行；矩条件极差题实测100%，第152行）。这解决了253号第3.3节"有多个Pattern部分匹配"的问题——通过缺口检查判断检索结果是否充分，不充分则需扩大检索范围或调整种子。

- **ID**：100-P5
- **类型**：性质标准
- **描述**：用已加载认知单元数量与所需认知单元数量的比率（loaded/required）作为检索效果的核心度量指标。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第69行, 原文引用："判定：覆盖率≥80%（loaded/required≥80%）"
- **依赖关系**：依赖：所需认知集合的明确定义 / 支撑：检索效果的量化评估
- **与检索机制的关系**：支撑检索机制的效果度量。253号第5.1节指出本问题"精度要求：需要精准——错误的Pattern会误导工作智能体"。覆盖率度量提供了一种量化精准度的方法——不是简单的"找到/没找到"，而是"找到了多少比例的所需认知"。这可以作为检索系统的质量SLA标准。

### 原语：版本链——认知演化的时间维度追踪
- **ID**：100-P6
- **类型**：结构原语
- **描述**：为每个认知单元建立版本链（v1→v2→...→vN），每个版本记录summary和来源，current_version指向最新理解深度，实现认知演化的可追溯管理。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第75行, 原文引用："回溯POC-1结果，给5个意识节点建立v1版本记录（来源=85号文档）"
- **依赖关系**：依赖：ArangoDB cog_versions集合 / 支撑：跨session认知恢复、认知层级判断
- **与检索机制的关系**：支撑检索机制的知识管理基础设施。版本链为每个Pattern提供了时间维度——同一个认知单元在不同POC实验中有不同深度的理解（如numerical_check: v1"发现能区分上界与下界"→v2"与极端检验形成螺旋环路2圈"，第163行）。检索时可以通过current_version知道认知的当前深度，选择适当层级的Pattern。这对应253号Pattern的"历史使用记录"字段——版本链是历史记录的结构化实现。

- **ID**：100-P7
- **类型**：结构原语
- **描述**：每个版本记录包含summary字段，用自然语言描述该版本认知发现的内容，作为认知单元的元数据。

- **依赖关系**：依赖：版本链结构（100-P6） / 支撑：Pattern自带适用性描述
- **与检索机制的关系**：间接支撑检索第三层（知识悖论）。253号第6.3节提出"Pattern自带适用性描述"作为破解知识悖论的方向——"每个Pattern不只存储Q内容，还存储'我在什么情况下有效'的自然语言描述"。版本记录的summary字段正是这种自然语言描述的雏形——它记录了认知单元在什么情境下被发现、有什么作用，助理智能体可以读summary来判断Pattern是否匹配当前状态。

### 原语：三层提取结构——L1/L2/L3认知层级
- **ID**：100-P8
- **类型**：概念框架
- **描述**：将认知提取分为三层：L1=具体步骤（类似题复用），L2=思维模式（跨题复用），L3=范式思维（跨领域复用），用版本链v1→v2→v3管理，current_version反映当前提取层级。
- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第176行, 原文引用："设计三层提取的认知单元结构（L1/L2/L3如何映射到cognition_units）"
- **依赖关系**：依赖：版本链结构（100-P6） / 支撑：多级索引、按抽象度分层检索
- **与检索机制的关系**：直接支撑检索的多级索引设计。253号第6.4节提出"多级索引：先按大类（思维模式）粗筛，再按小类（具体结构）精排"。三层提取结构正是这种分层索引的实现——L1是具体结构层（精排），L2是思维模式层（粗筛），L3是范式层（最粗筛）。检索时可以先在L3层定位范式，再在L2层定位思维模式，最后在L1层定位具体步骤。这与253号Level标签（→0纯知识，→1纯思维模式）形成对应：L1≈Level→0，L2≈中间，L3≈Level→1。

### 原语：current_version作为复用层级指示器
- **ID**：100-P9
- **类型**：性质标准

- **溯源**：100-反哺方案执行计划-细化CheckList与测试方案.md, 第178行, 原文引用："v1=类似题复用，v2=跨题复用，v3=跨领域复用。current_version=v3意味着这个认知已达到L3级别，可以跨领域复用"
- **依赖关系**：依赖：三层提取结构（100-P8）、版本链（100-P6） / 支撑：检索时的复用范围判断
- **与检索机制的关系**：支撑检索第一层（状态感知）的决策依据。当助理智能体检索到一批候选Pattern时，current_version可以帮助判断哪些Pattern的复用范围与当前问题的距离匹配——如果当前问题和存储Pattern来自同一道题，v1层级的Pattern就够；如果是跨领域问题，需要v3层级的Pattern。这是一种"复用距离"的度量标准。

## 文档与检索机制的关系

100号文档是检索机制的基础设施层文档——它不直接讨论253号定义的"Pattern检索问题"，但其全部内容都在构建检索系统所需的底层组件：

**直接对应的组件**：
- **种子推荐表（100-P1）** → 检索第一层（状态感知）的索引入口
- **图遍历（100-P2）** → 检索第二层（Pattern提取）的核心算法
- **CP1-CP3流程（100-P3）** → 检索三层结构的工程化pipeline
- **缺口检查（100-P4）** → 检索质量验证机制
- **覆盖率度量（100-P5）** → 检索效果量化标准
- **版本链（100-P6）** → Pattern历史记录与认知演化追踪
- **三层提取（100-P8）** → 多级索引与按抽象度分层检索

**间接支撑的组件**：
- **拓扑生成与验证（100-P12/P13）** → 思维状态的结构化表示与匹配
- **A/B对照实验（100-P15）** → 检索机制效果的科学验证方法
- **L3细化空间（100-P23）** → 知识悖论的人机分工破解方向
- **回归验证（100-P10/P11）** → 检索系统的持续质量保障

**关键差距**：100号文档构建的是"从问题类型到认知单元"的检索通路——输入是问题类型（离散分类），输出是认知单元集合。253号需要的检索通路是"从工作智能体的推理状态（连续的、结构化的思维状态）到Pattern"——输入更复杂、更模糊，匹配判据不是分类而是拓扑匹配。100号提供了检索基础设施（存储结构、遍历算法、索引、版本管理、质量验证），但253号第一层（思维状态怎么表示）和第三层（知识悖论怎么破解）的核心问题仍需在此基础上进一步解决。
