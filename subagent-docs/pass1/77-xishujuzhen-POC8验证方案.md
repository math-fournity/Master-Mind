# 原语提取：77-xishujuzhen-POC8验证方案

## 文档概述

本文档是 POC-8 验证方案，目标是"将闭环审计作为标准流程从头实施"并与开环模式做对照实验，量化闭环的边际增益。文档定义了三组对照实验设计（A基线/B开环/B闭环）、6+1维度评分体系、分阶段执行CheckList、预期结果与风险缓解。虽然文档本身是实验验证方案而非直接描述检索机制，但其中包含大量可作为检索机制构造积木的原语：反馈闭环流程、多轮迭代收敛、审计轨迹记录、质量评分体系、变量隔离实验设计、过程保证理念等——这些都是支撑检索机制质量保证和迭代优化的底层原语。

## 提取的原语

### 原语：闭环审计标准流程化
- **ID**：77-P1
- **类型**：概念框架
- **描述**：将闭环审计（审计→发现瑕疵→反馈→修正→再审计→...→无瑕疵）作为标准流程从第一轮就实施，而非事后补救。
- **溯源**：77, 第5行, 原文引用："POC-8的目标是**将闭环审计作为标准流程从头实施**，并与开环模式做对照实验，量化闭环的边际增益。"
- **依赖关系**：
  - 依赖：多轮审计闭环（77-P9）
  - 支撑：过程保证理念（77-P13）
- **与检索机制的关系**：检索机制的Pattern质量保证可以采用同样的闭环标准流程——检索结果→审计→发现不匹配→反馈修正→再检索→...→无瑕疵。闭环是检索质量从"可能98.8%"提升到"保证100%"的核心机制。

### 原语：三组对照实验设计
- **ID**：77-P2
- **类型**：操作原语
- **描述**：通过设置基线组（无干预）、开环组（单轮干预）、闭环组（多轮迭代干预）三组对照，量化不同模式的边际增益。
- **溯源**：77, 第17-23行, 原文引用："| **A组** | 直接分析（无依赖图） | 无审计 | 基线 | | **B开环组** | JSON→解读→交叉审计（1轮）→分析→执行审计（1轮） | 开环（1轮审计） | 对照开环模式 | | **B闭环组** | JSON→解读→交叉审计闭环→分析→执行审计闭环 | 闭环（多轮直到无瑕疵） | 验证闭环标准流程 |"
- **依赖关系**：
  - 依赖：闭环审计标准流程化（77-P1）
  - 支撑：量化假设验证（77-P14）
- **与检索机制的关系**：评估检索机制效果时，可以用同样的三组对照——无检索基线、单轮检索（开环）、多轮迭代检索（闭环）——来量化检索机制的边际增益。这是检索机制A/B测试的方法论原语。

### 原语：开环vs闭环模式定义
- **ID**：77-P3
- **类型**：概念框架
- **描述**：明确定义两种操作模式——开环（单轮审计不修正）vs闭环（多轮审计直到无瑕疵），作为系统行为的两种基本范式。
- **溯源**：77, 第11-13行, 原文引用："| 闭环实施方式 | 事后补救（开环完成后追加闭环） | **从头实施（第1轮就闭环）** | | 对照实验 | 无（只有闭环前后对比） | **开环组 vs 闭环组对照** |"
- **依赖关系**：
  - 支撑：三组对照实验设计（77-P2）
- **与检索机制的关系**：检索机制可以运行在开环模式（单次检索不修正）或闭环模式（检索→验证→修正→再检索）。明确定义这两种模式是设计检索机制操作流程的基础。

### 原语：复用场景控制变量
- **ID**：77-P4
- **类型**：操作原语
- **描述**：在对照实验中复用同一场景（同一输入数据），不重新设计场景，以隔离单一变量（闭环效应）的影响。
- **溯源**：77, 第33-38行, 原文引用："**复用POC-7的12限全量场景**（71节点106边10跨宫边2螺旋环路），不重新设计场景。原因：1. POC-7已有完整的开环结果作为对照 2. POC-7的3处瑕疵+3处预存瑕疵+2处传播瑕疵已经充分暴露了问题 3. 重新设计场景会增加变量，不利于隔离闭环效应"
- **依赖关系**：
  - 支撑：三组对照实验设计（77-P2）
- **与检索机制的关系**：评估检索机制时，应在固定的认知图/依赖图场景上对比不同检索策略，避免场景变化引入额外变量。这是检索机制评估的实验控制原语。

### 原语：全新调用起点对齐
- **ID**：77-P5
- **类型**：操作原语
- **描述**：对照组之间使用全新调用（而非复用已有结果），确保起点相同、区别只在流程模式，从而公平对比。
- **溯源**：77, 第52-58行, 原文引用："**关键设计**：B闭环组的第1轮解读AI是全新调用，不是复用v1。这样B闭环组和B开环组的起点相同（同样的JSON输入），区别只在于流程（开环vs闭环）。"
- **依赖关系**：
  - 依赖：复用场景控制变量（77-P4）
- **与检索机制的关系**：对比不同检索算法时，应确保所有算法面对相同的输入起点（相同的查询、相同的图状态），区别只在检索策略本身。这是检索算法公平对比的控制原语。

### 原语：6维度评分体系
- **ID**：77-P6
- **类型**：结构原语
- **描述**：用6个维度（分析完整性、推理深度、知识准确性、可审计性、转译忠实性、边际增益）对系统输出进行多维度量化评分，每个维度2分共12分。
- **溯源**：77, 第62-71行, 原文引用："| 1. 分析完整性 | 2.0 | - | - | - | | 2. 推理深度 | 2.0 | - | - | - | | 3. 知识准确性 | 2.0 | - | - | - | | 4. 可审计性 | 2.0 | 0 | 1.7（1轮审计） | 2.0（多轮审计+闭环） | | 5. 转译忠实性 | 2.0 | 0 | 1.9（98.8%） | 2.0（100%） | | 6. 边际增益 | 2.0 | - | - | - |"
- **依赖关系**：
  - 支撑：量化假设验证（77-P14）
- **与检索机制的关系**：检索机制的效果评估可以采用类似的多维度评分——检索覆盖率、检索精确度、检索效率、可审计性等。多维度评分比单一指标更能全面刻画检索质量。

### 原语：闭环效率维度（收敛速度度量）
- **ID**：77-P7
- **类型**：性质标准
- **描述**：将"达到无瑕疵所需的轮数"作为独立的效率维度评分——1轮=1.0分，2轮=0.8分，3轮=0.6分，3轮后仍有瑕疵=0.4分。
- **溯源**：77, 第73-82行, 原文引用："| 闭环效率 | 评分 | |---|---| | 1轮达到无瑕疵 | 1.0 | | 2轮达到无瑕疵 | 0.8 | | 3轮达到无瑕疵 | 0.6 | | 3轮后仍有瑕疵 | 0.4 |"
- **依赖关系**：
  - 依赖：多轮审计闭环（77-P9）
  - 支撑：6维度评分体系（77-P6）
- **与检索机制的关系**：检索机制的迭代收敛速度是一个重要质量指标——如果检索需要多轮反馈才能收敛到正确结果，效率维度应反映这一点。这是检索机制收敛性能的度量原语。

### 原语：异总分归一化
- **ID**：77-P8
- **类型**：操作原语
- **描述**：当不同组的评分维度数量不同（总分不同）时，通过总分/最大分×10的归一化方式，使不同组之间的分数可比。
- **溯源**：77, 第84-87行, 原文引用："- A组和B开环组：总分/12 × 10 - B闭环组：总分/13 × 10"
- **依赖关系**：

### 原语：多轮审计闭环流程
- **ID**：77-P9
- **类型**：操作原语
- **描述**：审计→发现瑕疵→反馈→修正→再审计→...→无瑕疵的多轮迭代流程，每轮记录瑕疵数变化，直到收敛。
- **溯源**：77, 第54-56行, 原文引用："2. 第1轮交叉审计→如有瑕疵→反馈→修正→第2轮交叉审计→...→无瑕疵 3. 第1轮B组分析→第1轮执行审计→如有问题→反馈→修正→第2轮执行审计→...→无问题 - 记录每轮审计的瑕疵数变化"
- **依赖关系**：
  - 依赖：审计轨迹记录（77-P10）
  - 支撑：闭环审计标准流程化（77-P1）、闭环效率维度（77-P7）
- **与检索机制的关系**：检索机制可以采用同样的多轮迭代闭环——首轮检索→审计检索结果→发现遗漏/错误→反馈修正查询→再检索→...→结果无瑕疵。这是检索机制迭代精化的核心流程原语。

### 原语：审计轨迹记录
- **ID**：77-P10
- **类型**：操作原语
- **描述**：在每轮审计中记录完整的审计轨迹（瑕疵数变化、修正过程），作为可审计性和过程可追溯的依据。
- **溯源**：77, 第99-100行, 原文引用："- [ ] 记录审计轨迹 - [ ] 输出最终版大师提示词"
- **依赖关系**：
  - 支撑：多轮审计闭环流程（77-P9）、过程保证理念（77-P13）
- **与检索机制的关系**：检索机制应记录每轮检索的轨迹——查询条件、命中Pattern、审计结果、修正动作——使检索过程可审计、可追溯、可复盘。这是检索机制可审计性的数据结构原语。

### 原语：3轮上限降级机制
- **ID**：77-P11
- **类型**：操作原语
- **描述**：为闭环迭代设置最大轮数上限（3轮），超过上限后降级为开环模式并记录残余瑕疵，防止无限迭代。
- **溯源**：77, 第152-155行, 原文引用："**风险**：如果B闭环组的第1轮解读瑕疵比v1多，可能需要超过3轮修正。**缓解**：最大3轮上限。3轮后仍有瑕疵则降级为开环模式，记录残余瑕疵。"
- **依赖关系**：
  - 依赖：多轮审计闭环流程（77-P9）
- **与检索机制的关系**：检索机制的迭代精化也需要设置最大轮数上限，防止因查询条件无法收敛而无限循环。超过上限后降级为返回当前最优结果并标注残余不确定度。这是检索机制的迭代终止与降级原语。

### 原语：分次输出避免截断
- **ID**：77-P12
- **类型**：操作原语
- **描述**：当单次输出可能因长度限制被截断时，将输出拆分为多次subagent调用分别生成，确保完整性。
- **溯源**：77, 第157-160行, 原文引用："**风险**：POC-7中B组审计报告因子代理输出截断未完整生成。**缓解**：B闭环组的分析结果和审计报告分两次subagent调用生成。"
- **依赖关系**：
  - 支撑：审计轨迹记录（77-P10）
- **与检索机制的关系**：当检索结果集很大时，单次返回可能被截断。可以将检索结果分批返回，或在检索机制设计中考虑输出长度限制的容错。这是检索机制输出完整性的工程原语。

### 原语：过程保证理念
- **ID**：77-P13
- **类型**：概念框架
- **描述**：闭环的真正价值不在于边际增益的大小，而在于"过程保证"——确保输出质量达到100%，而不是"可能98.8%"。即从概率性保证升级为确定性保证。
- **溯源**：77, 第143行, 原文引用："**关键洞察**：闭环vs开环的边际增益可能很小（因为开环的98.8%已经很高），但闭环的真正价值在于**过程保证**——确保输出质量达到100%，而不是"可能98.8%"。"
- **依赖关系**：
  - 依赖：闭环审计标准流程化（77-P1）、多轮审计闭环流程（77-P9）
- **与检索机制的关系**：检索机制的设计目标不应只是"大概率检索到正确Pattern"，而应通过闭环验证实现"过程保证"——确保检索结果经过验证后是确定性的正确。这是检索机制质量理念的核心原语。

### 原语：量化假设验证
- **ID**：77-P14
- **类型**：操作原语
- **描述**：在实验前明确定义可量化核心假设（如"闭环组忠实度>开环组"、"闭环效率≤3轮"等），实验后逐一验证。
- **溯源**：77, 第26-31行, 原文引用："1. **闭环组忠实度>开环组**：闭环组的转译忠实度应高于开环组（预计100% vs ~95%） 2. **闭环组发现瑕疵数>开环组**... 3. **闭环组修正瑕疵数>开环组**... 4. **闭环效率≤3轮**... 5. **闭环组总分>开环组**..."
- **依赖关系**：

### 原语：交叉审计+执行审计双闭环
