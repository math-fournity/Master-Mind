# 原语提取：234号-形式化边界视角下232号五个问题的重新审视

## 文档概述

本文档用233号建立的"形式化边界推进"思想武器，重新审视232号对231号数据基座方案提出的五个问题（抽取成本、远期愿景时间标注、九类内容缺结构关系、"不是RAG"工程模糊、与数学结构脱节）。文档直接给出了检索机制的核心设计：检索单位是"边界跨越路径"，相似性度量是"路径结构相似度"，工程实现是"结构化字段匹配粗筛+图查询精化+向量检索排序"的三阶段混合检索。此外还给出了数据基座内容的四阶段组织结构、渐进积累机制、正反馈循环等支撑检索流程底层的数据结构和状态表示原语。

### 原语：路径结构相似度——基于边界推进过程的相似性度量

- **与检索机制的关系**：这是检索机制的核心匹配算法——定义了如何判断两个路径"相似"。四个维度的结构化匹配取代了向量相似度，是检索精度的关键保证。

### 原语：混合检索三阶段——粗筛+精化+排序
- **ID**：234-P10

- **溯源**：234号, 第157-162行, 原文引用："工程实现可以是：1. 第一阶段：用结构化字段匹配（处境类型+移动类型+证书类型）做粗筛 2. 第二阶段：用图查询在依赖图中找连通路径做精化 3. 第三阶段（可选）：用向量检索在剩余候选中做排序" + "这是混合检索，但核心是结构化字段匹配，不是向量检索。数据基座'不是RAG'的区分在工程上变清楚了——RAG的core是向量检索，数据基座的core是路径结构匹配。"
- **依赖关系**：

  - 支撑：检索机制的完整工程实现
- **与检索机制的关系**：这是检索机制的完整工程架构——三阶段流水线直接定义了检索系统的实现方式。粗筛用结构化字段（快速缩小候选集），精化用图查询（利用依赖图拓扑结构），排序用向量检索（可选的最终排序）。这是检索机制最核心的实现原语。
