# 原语提取：66-xishujuzhen POC-3 验证方案

## 文档概述

本文档是稀疏矩阵（xishujuzhen）系统 POC-3 的验证方案，核心命题是验证"AI 自解读 JSON 依赖图生成大师级提示词 + 双重提示 + 双重对照审计"的三步流程能否使依赖图提示的优势显著增大。文档详细设计了从经典计算生成 JSON、AI 解读 JSON、AI 在双重提示下分析的三步流程，以及配套的审计机制、评分标准和诊断逻辑。与检索机制的关系在于：JSON 依赖图本身就是检索结果的载体，文档探讨了如何将结构化检索结果转译为可执行的自然语言引导，以及如何审计检索结果是否被忠实使用。

## 提取的原语

### 原语：JSON 依赖图作为结构化检索结果载体
- **ID**：66-P1
- **类型**：结构原语
- **描述**：依赖图 JSON 作为经典计算的输出，包含节点、边、环路三种结构元素，是结构化的、客观的、可审计的检索结果载体。
- **溯源**：66, 第77-79行, 原文引用："依赖图 JSON（结构化，客观，可审计）"及第116行 "复用 POC-2 的 `graph_v2.py` + `prompt_gen_v2.py` + `knowledge_content.py`，生成 12 节点 16 边的依赖图 JSON。"
- **依赖关系**：
  - 依赖：经典计算生成 JSON 的流程（graph_v2.py 等）
  - 支撑：66-P2（AI 自解读）、66-P4（双重对照审计）
- **与检索机制的关系**：JSON 依赖图是检索机制的输出产物——从认知图/依赖图中检索出的 Pattern 集合以节点+边+环路的结构化形式呈现，是后续所有解读、分析、审计的基础数据结构。

### 原语：AI 自解读——结构化检索结果到自然语言引导的转译
- **ID**：66-P2
- **类型**：操作原语
- **描述**：AI 在拿到结构化检索结果（JSON 依赖图）后、开始分析前，先对 JSON 进行解读，将生硬的依赖关系转译为循循善诱的自然语言引导（大师级提示词），这是 AI 自己写给自己的完美提示词。
- **溯源**：66, 第40-42行, 原文引用："新增环节是 **AI 解读 JSON**——AI 把生硬的依赖图，转译为占星大师级别的循循善诱的提示词。这份提示词是 AI 自己写给自己的。**完美提示词 = 经典计算（JSON，结构）+ AI 解读（Markdown，语言）。**"
- **依赖关系**：
  - 依赖：66-P1（JSON 依赖图作为输入）
  - 支撑：66-P3（双重提示机制）、66-P8（解读忠实性约束）
- **与检索机制的关系**：这是检索结果的后处理环节——将结构化检索结果转译为 AI 可执行的自然语言引导。检索机制不仅需要返回结果，还需要将结果转化为可被消费的引导形式。这个转译环节是检索结果发挥实际效用的关键桥梁。

### 原语：双重提示机制——结构化与自然语言的双轨呈现
- **ID**：66-P3
- **类型**：操作原语
- **描述**：AI 在分析时同时持有两份文件：依赖图 JSON（结构化、客观、可审计）和大师级提示词（自然语言、循循善诱、AI 自己写的），两者缺一不可，分别承担审计基准和引导功能。
- **溯源**：66, 第77-81行, 原文引用："AI 在分析时同时拿着两份文件：- 依赖图 JSON（结构化，客观，可审计）- 大师级提示词（自然语言，循循善诱，AI 自己写的）JSON 是审计基准，大师型提示词是引导。两者缺一不可。"
- **依赖关系**：
  - 依赖：66-P1（JSON 依赖图）、66-P2（AI 自解读生成大师级提示词）
  - 支撑：66-P4（双重对照审计）
- **与检索机制的关系**：检索结果以两种表征形式同时呈现给消费者——结构化形式用于审计和验证，自然语言形式用于引导和执行。这种双轨呈现确保检索结果既可被机器验证又可被人/AI理解使用。

### 原语：双重对照审计——结构覆盖与路径忠实
- **ID**：66-P4
- **类型**：操作原语
- **描述**：审计文件同时对照两份基准：一是对照 JSON 证明覆盖完备性（节点覆盖率、边覆盖率、环路处理正确性），二是对照大师型提示词证明思考路径忠实性（AI 是否循着引导走）。
- **溯源**：66, 第46-51行, 原文引用："审计文件不只是"逐节点/逐边对照 JSON"，它有双重对照：1. **对照 JSON 证明覆盖完备性**（结构基准）……2. **对照大师型提示词证明思考路径忠实性**（路径基准）……**JSON 是审计的锚点。大师型提示词是引导的风。**"
- **依赖关系**：
  - 依赖：66-P1（JSON 依赖图）、66-P3（双重提示机制）
  - 支撑：66-P10（覆盖率审计指标）、66-P11（路径忠实性审计指标）
- **与检索机制的关系**：这是检索结果使用过程的验证机制——不仅验证检索结果是否被完整使用（结构覆盖），还验证检索结果的引导意图是否被忠实执行（路径忠实）。双重审计确保检索结果的价值被真正释放。

### 原语：逐节点/逐边/逐环路解读——检索结果的系统化分解解读
- **ID**：66-P5
- **类型**：操作原语
- **描述**：AI 解读 JSON 时按三个粒度系统化分解：逐节点解读（节点含义和判断目标）、逐边解读（依赖关系的命理含义）、逐环路解读（螺旋环路的上下文变化和深化含义），最后整体串联为思维路径。
- **溯源**：66, 第68-71行, 原文引用："解读要求：- **逐节点解读**：这个节点是什么意思？在这个上下文中要判断什么？- **逐边解读**：为什么从这个节点到那个节点？这条依赖关系的命理含义是什么？- **逐环路解读**：这个螺旋环路意味着什么？第一圈和第二圈的上下文变化在命理上代表什么深化？- **整体解读**：把所有依赖关系串成一条思维路径，用占星大师的语言循循善诱地引导。"
- **依赖关系**：
  - 依赖：66-P1（JSON 依赖图中的节点/边/环路结构）
  - 支撑：66-P2（AI 自解读环节的具体执行方法）
- **与检索机制的关系**：这是检索结果的系统化消费协议——按节点、边、环路三个粒度逐一解读，确保检索结果中的每个元素都被理解和转化为可执行引导，不遗漏任何检索产物。

### 原语：解读忠实性约束——转译非创造
- **ID**：66-P6
- **类型**：操作原语
- **描述**：AI 解读时不能改变 JSON 中的依赖关系——不能添加 JSON 中没有的节点或边，不能跳过 JSON 中的任何节点或边。解读是转译，不是创造。如果发现缺失，只能标注不能自行添加。
- **溯源**：66, 第73行, 原文引用："**约束：AI 解读时不能改变 JSON 中的依赖关系。** 不能添加 JSON 中没有的节点或边，不能跳过 JSON 中的任何节点或边。解读是转译，不是创造。如果 AI 在解读中发现 JSON 缺少了某些应该有的依赖，应该在提示词中标注"依赖图中未覆盖但可能需要的分析维度"，而不是自行添加。"
- **依赖关系**：
  - 依赖：66-P1（JSON 依赖图作为忠实性的基准）
  - 支撑：66-P7（缺失维度标注机制）、66-P10（转译忠实性评分）
- **与检索机制的关系**：这是检索结果转译过程的完整性约束——确保转译过程不引入检索结果中不存在的内容，也不遗漏检索结果中的任何内容。检索结果的权威性在转译过程中被保持。

### 原语：缺失维度标注机制——检索结果缺口的形式化标记
- **ID**：66-P7
- **类型**：操作原语
- **描述**：当 AI 在解读中发现 JSON 缺少了某些应该有的依赖关系时，不自行添加，而是在解读文件中专门标注"依赖图中未覆盖但可能需要的分析维度"，形成对检索结果缺口的形式化标记。
- **溯源**：66, 第162-165行, 原文引用："## 依赖图中未覆盖但可能需要的分析维度 [如果 AI 在解读中发现 JSON 缺少了某些应该有的依赖，在此标注。不自行添加，只标注。]"
- **依赖关系**：
  - 依赖：66-P6（解读忠实性约束——发现缺失但不能添加）
  - 支撑：检索机制的反馈闭环（缺口标记可反馈到检索源改进）
- **与检索机制的关系**：这是检索机制的反馈闭环入口——消费者在使用检索结果时发现的缺口被形式化标记，这些标记可以反馈到检索源（认知图/依赖图）进行补充和完善，形成检索质量的持续改进闭环。

### 原语：螺旋环路解读——检索结果中循环依赖的深化语义
- **ID**：66-P8
- **类型**：概念框架
- **描述**：依赖图中的环路（循环依赖）不是循环论证，而是螺旋上升——第一圈在某个上下文中判断，第二圈在变化后的上下文中重新审视，上下文变了结论也递进了。环路代表深化而非重复。
- **溯源**：66, 第156-160行, 原文引用："五行生克 ↔ 阴阳昼夜 这个螺旋环路，意味着什么？第一圈，我们在"命宫/五行关系"的上下文中判断木星与寅宫的五行关系——比和。第二圈，我们在"命宫/昼生"的上下文中重新审视五行强弱——昼生木旺，木星从"庙+比和"升级为"庙+比和+昼生得时"三得俱全。这不是循环论证，是深化——上下文变了，结论也递进了。"
- **依赖关系**：

### 原语：知识充足时的边际增益定位——检索增值的价值分布分析
- **ID**：66-P13
- **类型**：概念框架
- **描述**：当知识充足时（A 组也拿到了全部知识），依赖图提示的边际增益主要在结构感和逻辑性上，不在完整性和准确性上。完整性和准确性主要由"有没有知识"决定，不是由"有没有依赖图"决定。JSON 作为提示词直接给 AI 价值有限，因为 JSON 是结构化的依赖清单，不是循循善诱的引导。
- **溯源**：66, 第22-24行, 原文引用："当知识充足时（A 组也拿到了全部知识），依赖图提示的边际增益主要在结构感和逻辑性上，不在完整性和准确性上。完整性和准确性主要由"有没有知识"决定，不是由"有没有依赖图"决定。这意味着：**JSON 作为提示词直接给 AI，它的价值有限——因为 JSON 是结构化的依赖清单，不是循循善诱的引导。** AI 拿到 JSON 后知道"该判断什么"，但不知道"该怎么去想"。"
