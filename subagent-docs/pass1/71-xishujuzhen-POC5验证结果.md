# 原语提取：71-xishujuzhen-POC5验证结果

## 文档概述

本文档记录了 POC-5 实验的验证结果，核心是在 POC-4 基础上加码两个维度：场景从静态扩展到静态+动态（大限流年），审计从单步扩展到闭环审计链（自审+审计）。文档详细描述了依赖图结构（30节点40边、跨宫依赖、螺旋环路）、三步流程闭环审计链的执行结果与评分、以及核心发现与局限。与检索机制的关系在于：依赖图本身是检索的对象结构，跨宫依赖边定义了检索的跨域路径，闭环审计链定义了检索结果忠实性的验证机制，覆盖度指标定义了检索完整性的度量标准。

## 提取的原语

### 原语：静态→动态跨宫依赖边
- **ID**：71-P1
- **类型**：结构原语
- **描述**：依赖图中存在一种特殊边，连接静态分析节点与动态分析节点，表达跨分析域的依赖传递关系。
- **溯源**：71, 第7行, 原文引用："新增11个动态分析节点和4条静态→动态跨宫依赖边。"
- **依赖关系**：
  - 依赖：依赖图节点结构（71-P8）
  - 支撑：跨域检索路径构建
- **与检索机制的关系**：跨宫依赖边定义了检索机制中跨域（静态域→动态域）的检索路径。检索 Pattern 时，这类边允许从静态分析结果导航到动态分析所需的 Pattern，是跨域检索的结构基础。

### 原语：闭环审计链
- **ID**：71-P2
- **类型**：操作原语
- **描述**：三步流程中，第2步自审（转译忠实性）与第3步审计（执行忠实性）形成闭环，确保从JSON生成到最终结果的每一步都可追溯、可验证。
- **溯源**：71, 第8行, 原文引用："第2步（AI解读JSON）新增自审报告（转译忠实性审计），与第3步审计报告（执行忠实性审计）形成闭环审计链。"
- **依赖关系**：
  - 依赖：自审报告机制（71-P3）、执行忠实性审计（71-P4）
  - 支撑：检索结果的忠实性验证闭环
- **与检索机制的关系**：检索机制输出 Pattern 后，需要验证检索结果是否忠实于原始知识结构。闭环审计链提供了"转译忠实性→执行忠实性"的两层验证，确保检索→解读→执行链条不丢信息。

### 原语：自审报告（转译忠实性审计）
- **ID**：71-P3
- **类型**：操作原语
- **描述**：AI在解读JSON生成提示词后，自行审计转译过程是否忠实覆盖了所有节点、边、跨宫依赖、环路、知识内容和约束。
- **溯源**：71, 第39-46行, 原文引用："节点转译覆盖：30/30 = 100% / 边转译覆盖：32/32 = 100% / 跨宫依赖转译覆盖：8/8 = 100% / 环路转译覆盖：1/1 = 100% / knowledge_content嵌入：12/12 = 100% / 约束遵守：5/5 = 100% / 转译忠实性总评：100%"
- **依赖关系**：
  - 依赖：依赖图结构（节点、边、环路、跨宫依赖）
  - 支撑：闭环审计链（71-P2）
- **与检索机制的关系**：自审报告定义了检索结果完整性的验证维度——节点覆盖、边覆盖、跨宫依赖覆盖、环路覆盖、知识内容嵌入、约束遵守。这些维度可直接复用为检索机制的完整性度量指标。

### 原语：执行忠实性审计
- **ID**：71-P4
- **类型**：操作原语
- **描述**：在AI执行分析后，审计其执行过程是否忠实覆盖了所有节点、边、环路处理、跨宫依赖和路径引导点。
- **溯源**：71, 第48-53行, 原文引用："节点覆盖：30/30 = 100% / 边覆盖：40/40 = 100% / 环路处理：1螺旋2圈 = 100% / 跨宫依赖覆盖：8/8 = 100% / 路径忠实性：27/27引导点 = 100%"
- **依赖关系**：
  - 依赖：依赖图结构、路径引导点（71-P7）
  - 支撑：闭环审计链（71-P2）
- **与检索机制的关系**：执行忠实性审计验证检索到的 Pattern 是否在执行中被完整使用。路径忠实性（引导点覆盖）特别重要——它验证了检索机制提供的引导路径是否被忠实遵循。

### 原语：螺旋环路结构
- **ID**：71-P5
- **类型**：结构原语
- **描述**：依赖图中存在循环依赖结构（如五行生克↔阴阳昼夜），需要特殊处理（如螺旋2圈）而非简单拓扑排序。
- **溯源**：71, 第14行, 原文引用："螺旋环路 | 1个（五行生克↔阴阳昼夜）"
- **依赖关系**：
  - 依赖：依赖图边结构
  - 支撑：环路检索与处理
- **与检索机制的关系**：检索机制在遍历依赖图时可能遇到环路。螺旋环路原语说明检索不能简单做 DAG 遍历，需要支持环路检测和有限圈数迭代（如2圈），这对检索算法的终止条件和结果完整性有直接影响。

### 原语：覆盖度度量体系
- **ID**：71-P6
- **类型**：性质标准
- **描述**：用"已覆盖/总数"的比率度量各结构元素的覆盖完整性，包括节点覆盖、边覆盖、跨宫依赖覆盖、环路覆盖、知识内容嵌入、约束遵守、路径引导点覆盖。
- **溯源**：71, 第39-53行, 原文引用："节点转译覆盖：30/30 = 100% ... 路径忠实性：27/27引导点 = 100%"
- **依赖关系**：
  - 依赖：依赖图结构定义（节点、边、环路、跨宫依赖的分类）
  - 支撑：自审报告（71-P3）、执行忠实性审计（71-P4）
- **与检索机制的关系**：覆盖度度量体系可直接作为检索机制的质量评估框架——检索是否覆盖了所有应检索的节点、边、依赖路径、环路。这定义了检索完整性的量化标准。

### 原语：路径引导点
- **ID**：71-P7
- **类型**：结构原语
- **描述**：依赖图中存在"引导点"概念，用于引导分析路径，审计时验证这些引导点是否被忠实经过。
- **溯源**：71, 第53行, 原文引用："路径忠实性：27/27引导点 = 100%"
- **依赖关系**：
  - 依赖：依赖图路径结构
  - 支撑：执行忠实性审计（71-P4）
- **与检索机制的关系**：引导点是检索机制中的关键路径节点——检索不仅返回 Pattern，还返回一条经过特定引导点的路径。路径忠实性验证确保检索提供的引导路径被完整执行。

### 原语：扩展依赖图（静态+动态节点+跨宫边+环路）
- **ID**：71-P8
- **类型**：结构原语
- **描述**：一个包含静态节点、动态节点、同宫边、跨宫依赖边、螺旋环路的综合依赖图结构，30节点40边。

- **与检索机制的关系**：这是检索机制的核心检索对象——检索机制从这个依赖图中检索 Pattern。图的节点分类（静态/动态）、边分类（同宫/跨宫）、环路结构共同定义了检索空间的拓扑。

- **描述**：在转译过程中验证是否遵守了所有约束（如5/5=100%），约束是依赖图上附加的规则性限制。
- **溯源**：71, 第45行, 原文引用："约束遵守：5/5 = 100%"

- **与检索机制的关系**：检索机制在返回 Pattern 时，可能附带约束（如使用顺序、互斥关系、前置条件）。约束遵守验证确保检索结果的消费者遵守了这些约束，是检索结果正确使用的保障。

### 原语：三步流程（JSON→解读+自审→分析+审计）
- **ID**：71-P11
- **类型**：操作原语
- **描述**：一个三步执行流程：第1步系统生成结构化JSON，第2步AI解读JSON并自审，第3步AI在JSON+提示词下执行分析并审计。
- **溯源**：71, 第92-99行, 原文引用："第1步：系统生成JSON / 第2步：AI解读JSON → 大师提示词 + 自审报告 / 第3步：AI在JSON+大师提示词下分析 → 结果 + 审计报告 / 闭环：JSON → 转译忠实性100% → 执行忠实性100% → 结果可追溯"
- **依赖关系**：
  - 依赖：闭环审计链（71-P2）
  - 支撑：检索结果的可追溯使用流程
- **与检索机制的关系**：三步流程定义了检索结果从生成到使用的完整生命周期。检索机制可以嵌入这个流程：第1步生成检索查询的JSON表示，第2步解读检索结果并自审覆盖度，第3步使用检索结果并审计执行忠实性。

- **描述**：用6个维度（分析完整性、推理深度、知识准确性、可审计性、转译忠实性、边际增益）对结果进行评分，总分12分制。

- **依赖关系**：
  - 依赖：无（评估框架）
  - 支撑：检索机制效果评估
- **与检索机制的关系**：六维度评分体系可作为检索机制效果的评估框架。特别是可审计性和转译忠实性两个维度，直接衡量检索结果的可追溯性和忠实性——这是检索机制质量的核心指标。

### 原语：边际增益度量
- **ID**：71-P13
- **类型**：性质标准
- **描述**：通过对比有检索增强（B组）与无检索增强（A组）的评分差值，度量检索机制的边际贡献。
- **溯源**：71, 第72行, 原文引用："边际增益+3.95（10分制归一化），相比POC-4的+2.7提升+1.25。"
- **依赖关系**：

  - 支撑：检索机制价值量化
- **与检索机制的关系**：边际增益是检索机制价值的直接量化——A/B对比实验度量"有检索 vs 无检索"的评分差异。这定义了评估检索机制是否值得引入的标准方法。

### 原语：交叉审计（第三方审计）
- **ID**：71-P14
- **类型**：操作原语
- **描述**：第2步自审不由执行AI自身完成，而由另一个AI实例进行审计，避免自审的偏差。
- **溯源**：71, 第119行, 原文引用："交叉审计（第2步自审由另一个AI实例审计）。"
- **依赖关系**：
  - 依赖：自审报告机制（71-P3）
  - 支撑：检索结果忠实性的独立验证
- **与检索机制的关系**：检索结果的忠实性验证如果由检索执行者自审，存在自我确认偏差。交叉审计原语提出由独立实例验证检索结果的覆盖度和忠实性，提高验证可信度。

### 原语：知识缺失测试
- **ID**：71-P15
- **类型**：操作原语
- **描述**：故意在A组（无检索增强）中制造知识缺失，测试B组（有检索增强）的知识补充效果。
- **溯源**：71, 第121行, 原文引用："A组知识缺失测试。"
- **依赖关系**：
  - 依赖：A/B对比实验框架
  - 支撑：检索机制必要性的验证
- **与检索机制的关系**：知识缺失测试是验证检索机制必要性的实验方法——当知识不完整时，检索机制是否能补全缺失的知识。这定义了检索机制"知识补全"能力的测试范式。

### 原语：动态分析复杂度放大效应
- **ID**：71-P16
- **类型**：概念框架
- **描述**：随着分析场景从静态扩展到动态，复杂度增加，检索增强（B组）的优势被放大——边际增益从+2.7提升到+3.95。
- **溯源**：71, 第78行, 原文引用："动态分析复杂度放大B组优势：边际增益从+2.7提升到+3.95。"
- **依赖关系**：
  - 依赖：边际增益度量（71-P13）
  - 支撑：检索机制在高复杂度场景下的价值论证
- **与检索机制的关系**：这个概念框架说明检索机制的价值随问题复杂度增加而放大——简单问题检索帮助有限，复杂问题（多域、动态）检索帮助显著。这为检索机制的投入优先级提供了理论支撑。
