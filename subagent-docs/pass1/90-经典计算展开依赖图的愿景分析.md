# 原语提取：90-经典计算展开依赖图的愿景分析

## 文档概述

本文档分析了一个愿景：用经典计算（代码）替代 AI 来完成依赖图 G 到展开图 G'_topo 的拓扑骨架生成，或至少给出展开推荐供 AI 参考。文档详细拆解了 G'_topo 的节点/边/环路属性，区分了经典计算可自动确定和难以自动确定的部分，提出了 L0-L3 四层分层实现方案，并给出了拓扑排序、类型推断、connection 推断、section 划分等具体算法。这些内容与检索机制密切相关——依赖图的展开、拓扑排序、属性推断、分层处理、覆盖率验证等都是检索流程的底层支撑原语。

## 提取的原语

### 原语：拓扑同构保证——节点集和边集直接拷贝
- **ID**：90-P1
- **类型**：结构原语
- **描述**：从源图 G 生成目标图 G'_topo 时，节点集和边集完全从 G 直接拷贝，保证拓扑同构和 100% 覆盖率，不需要语义判断。
- **溯源**：90, 第64-66行, 原文引用："节点集和边集完全从 G 拷贝——这保证了 100% 覆盖。不需要 AI 参与。"
- **依赖关系**：
  - 依赖：依赖图 G 的存在（源数据结构）
  - 支撑：TopologyVerifier 验证原语（90-P9）、全覆盖保证原语（90-P10）
- **与检索机制的关系**：检索机制的基础保证——从认知图/依赖图中检索 Pattern 时，保证检索结果覆盖图中所有节点和边，不遗漏。直接拷贝是最简单的全覆盖策略，可作为检索机制"无遗漏"保证的底层机制。

### 原语：拓扑排序确定遍历顺序（traversal_order）
- **ID**：90-P2
- **类型**：操作原语
- **描述**：对依赖图中的 depends_on 边构建 DAG，用 Kahn 算法或 DFS 做拓扑排序，得到的线性顺序即为全局遍历顺序 traversal_order。
- **溯源**：90, 第68-78行, 原文引用："对 G 的 depends_on 边做拓扑排序，得到一个线性顺序。这个顺序就是 traversal_order。算法：1. 提取 G 中所有 edge_type == "depends_on" 的边 2. 构建 DAG（如果 depends_on 有环，报错）3. 对 DAG 做拓扑排序（Kahn 算法或 DFS）4. 拓扑序 = traversal_order"
- **依赖关系**：
  - 依赖：DAG 结构（无环依赖图）、edge_type 过滤机制
  - 支撑：position 分配原语（90-P3）、connection 类型推断原语（90-P5）
- **与检索机制的关系**：拓扑排序是检索机制中确定检索顺序的核心算法——从认知图中检索 Pattern 时，需要按依赖关系排序，确保被依赖的 Pattern 先于依赖它的 Pattern 被检索到。这是检索流程中"有序检索"的算法基础。

### 原语：拓扑序分配 section 内位置（position）
- **ID**：90-P3
- **类型**：操作原语
- **描述**：按拓扑序连续分配 position（section 内位置），初始为全局连续编号，后续在 section 划分后重新分配。
- **溯源**：90, 第149-151行, 原文引用："分配 position（section 内位置，先按拓扑序连续分配）for i, node_id in enumerate(topo_order): g_prime_topo.nodes[node_id].position = i + 1 # 初始：全局连续，后续 L2 划分 section 后重分配"
- **依赖关系**：
  - 依赖：拓扑排序原语（90-P2）
  - 支撑：section 划分原语（90-P7）
- **与检索机制的关系**：position 是检索机制中 Pattern 在结果集中的排序维度之一。检索结果不仅需要全局顺序（traversal_order），还需要局部分组内顺序（position），支撑检索结果的层次化呈现。

### 原语：节点类型推断（static/dynamic 映射）
- **ID**：90-P4
- **类型**：操作原语
- **描述**：根据节点已有的 type 字段（step/substep/意识）直接映射为 static 或 dynamic，不需要额外语义判断。
- **溯源**：90, 第80-83行, 原文引用："在数学项目中，节点的 type 字段已经存在于 G 中（step/substep/意识）。可以直接映射：step/substep → static, 意识 → dynamic"
- **依赖关系**：
  - 依赖：节点已有 type 字段
  - 支撑：spiral 遍历类型推断原语（90-P6）
- **与检索机制的关系**：节点类型是检索机制中的过滤维度——检索 Pattern 时可以按 static/dynamic 类型筛选，区分"具体知识步骤"和"意识层面的元认知 Pattern"，支撑分层检索。

### 原语：connection 类型推断（linear/shortcut/cross_section）
- **ID**：90-P5
- **类型**：操作原语
- **描述**：根据拓扑距离和 section 关系自动判断边的 connection 类型：相邻为 linear，回边为 shortcut，跨 section 为 cross_section。
- **溯源**：90, 第86-91行, 原文引用："根据拓扑距离和 section 关系自动判断：from 和 to 在同一 section 且 position 相邻 → linear, from 和 to 在不同 section → cross_section, from 和 to 构成环路的回边 → shortcut"
- **溯源（代码实现）**：90, 第185-203行, 原文引用："def infer_connection_type(edge, topo_order, sections): ... if to_order < from_order: return 'shortcut' ... if abs(from_order - to_order) == 1: return 'linear' ... if sections[edge.from] != sections[edge.to]: return 'cross_section'"
- **依赖关系**：
  - 依赖：拓扑排序原语（90-P2）、section 划分原语（90-P7）、回边检测
  - 支撑：边分类索引
- **与检索机制的关系**：connection 类型是检索机制中边的分类维度——检索 Pattern 间的关联时，区分"线性顺序关联"、"跨章节跳转关联"和"环路回边关联"，支撑不同粒度的关联检索。shortcut（回边）特别重要，它标识了环路结构中的反馈关联。

### 原语：spiral 遍历类型推断（spiral_static/spiral_dynamic）
- **ID**：90-P6
- **类型**：操作原语
- **描述**：用启发式规则推断螺旋环路的遍历类型——如果环路节点的 type 全是 dynamic（意识），则为 spiral_dynamic；如果包含 static 节点，则为 spiral_static。
- **溯源**：90, 第110-114行, 原文引用："可以用启发式规则——如果环路节点的 type 都是 dynamic（意识），则是 spiral_dynamic；如果包含 static 节点，则是 spiral_static。"
- **溯源（代码实现）**：90, 第205-211行, 原文引用："def infer_traversal_type(loop, graph): node_types = [graph.nodes[n].type for n in loop.nodes] if all(t == '意识' for t in node_types): return 'spiral_dynamic' return 'spiral_static'"
- **依赖关系**：
  - 依赖：节点类型推断原语（90-P4）、螺旋环路结构
  - 支撑：环路分类索引
- **与检索机制的关系**：spiral 类型区分了"静态知识循环"和"动态意识循环"，是检索机制中对环路 Pattern 的分类维度。检索时可以按 spiral 类型筛选，区分需要重复遍历的静态知识 Pattern 和需要动态演化的意识 Pattern。

### 原语：section 划分推荐（图论近似 + AI 细化）
- **ID**：90-P7
- **类型**：操作原语
- **描述**：用图论算法做 section 近似划分——按依赖链长度分段、按强连通分量划分、按 calls 边汇聚点划分；经典计算给出推荐，AI 可调整边界和命名。
- **溯源**：90, 第95-102行, 原文引用："可以用图论算法做近似划分：按依赖链长度划分：从入口节点出发，depends_on 链的第 1-5 个节点是第一章，第 6-8 个是第二章... 按强连通分量划分：环路内的节点归为同一章 按 calls 边的汇聚点划分：被多个 calls 边指向的意识节点归为最后一章"
- **溯源（代码实现）**：90, 第216-237行, 原文引用："def recommend_sections(topo_order, graph, max_section_size=5): ... 意识节点单独成章 ... 证明步骤按依赖链分段 ..."
- **依赖关系**：
  - 依赖：拓扑排序原语（90-P2）、强连通分量算法、calls 边分析
  - 支撑：connection 类型推断原语（90-P5）、分层实现原语（90-P8）
- **与检索机制的关系**：section 划分是检索机制中的"聚类/分组"原语——将认知图中的 Pattern 按逻辑结构分组，支撑按章节/主题检索。三种图论划分策略（依赖链长度、强连通分量、汇聚点）提供了不同的聚类视角，可用于多维度索引构建。

### 原语：分层实现（L0-L3 四层）
- **ID**：90-P8
- **类型**：概念框架
- **描述**：将依赖图展开任务分为四层：L0 骨架展开（经典计算，完全可行）、L1 类型推断（经典计算，启发式）、L2 section 划分（经典计算推荐+AI细化）、L3 语义标注（AI），每层有不同的执行者和可行性等级。
- **溯源**：90, 第116-123行, 原文引用："| L0 骨架展开 | 节点集+边集+拓扑排序+traversal_order | 经典计算 | ✅ 完全可行 | L1 类型推断 | static/dynamic + connection 类型 | 经典计算 | ✅ 用启发式规则可行 | L2 section 划分 | 章节归属 | 经典计算（推荐）+ AI（细化） | ⚠️ 经典计算给推荐，AI 可调整 | L3 语义标注 | spiral_static/dynamic + section 命名 | AI | ⚠️ 需要语义理解 |"
- **依赖关系**：
  - 依赖：拓扑同构保证（90-P1）、拓扑排序（90-P2）、类型推断（90-P4）、connection 推断（90-P5）、section 划分（90-P7）
  - 支撑：经典计算+AI 分工模式（90-P11）
- **与检索机制的关系**：分层实现是检索机制的设计框架——检索可以分层进行：L0 保证结构完整性（不遗漏），L1 提供类型过滤，L2 提供分组推荐，L3 提供语义精化。这种分层设计允许检索机制在不同精度/成本之间权衡，先快速检索骨架再语义细化。

### 原语：TopologyVerifier 覆盖率验证
- **ID**：90-P9
- **类型**：操作原语
- **描述**：用 TopologyVerifier 验证展开图 G'_topo 是否覆盖源图 G 的所有节点和边，覆盖率 < 100% 则回退重新生成。
- **溯源**：90, 第19-24行, 原文引用："步骤3 是验证。如果步骤2 的 AI 遗漏了节点或边，步骤3 会发现（覆盖率 < 100%），需要回到步骤2 让 AI 重新生成。"
- **溯源**：90, 第180行, 原文引用："TopologyVerifier 验证：1次通过，100%覆盖（因为是从 G 直接推导的）"
- **依赖关系**：
  - 依赖：拓扑同构保证原语（90-P1）
  - 支撑：全覆盖保证原语（90-P10）、回退重试机制
- **与检索机制的关系**：覆盖率验证是检索机制的质量保证原语——检索完成后，验证检索结果是否覆盖了认知图中所有应检索的 Pattern。如果覆盖率不足，触发回退重新检索。这是检索机制闭环验证的关键环节。

### 原语：全覆盖保证——经典计算从 G 直接推导
- **ID**：90-P10
- **类型**：性质标准
- **描述**：经典计算从 G 直接推导 G'_topo，节点集和边集完全拷贝，TopologyVerifier 验证必然 1 次通过 100% 覆盖，消除了 AI 生成时可能遗漏的不确定性。
- **溯源**：90, 第250-254行, 原文引用："L0 骨架展开从 G 直接推导 G'_topo，节点集和边集完全拷贝。TopologyVerifier 验证必然 1次通过 100%覆盖。这消除了 POC-2 步骤2 的不确定性——meta AI 生成 G'_topo 时可能遗漏节点或边，需要步骤3 验证后回退。经典计算生成则不会有这个问题。"
- **依赖关系**：
  - 依赖：拓扑同构保证（90-P1）、TopologyVerifier（90-P9）
  - 支撑：经典计算+AI 分工模式（90-P11）
- **与检索机制的关系**：全覆盖是检索机制的核心质量标准——检索机制必须保证不遗漏认知图中的任何 Pattern。经典计算直接推导的方式提供了"确定性全覆盖"的范式，与 AI 检索的"概率性覆盖"形成对比，可作为检索机制可靠性设计的参考标准。

### 原语：经典计算+AI 分工模式（推荐+细化）
- **ID**：90-P11
- **类型**：概念框架
- **描述**：经典计算给出推荐（骨架/类型/section），AI 在推荐基础上做语义细化（调整边界/命名/标注），推荐保证全覆盖和合理默认值，AI 只需做语义优化。
- **溯源**：90, 第266-272行, 原文引用："即使不完全实现 L0（经典计算直接生成 G'_topo），只实现"展开推荐"也有价值：AI 在生成 G'_topo 时，可以参考经典计算的推荐 推荐保证了全覆盖——AI 在推荐基础上调整不会遗漏节点 推荐提供了合理的默认值——AI 只需要做语义优化"
- **溯源**：90, 第323-329行, 原文引用："建议实现 L0+L1（骨架展开+类型推断），作为步骤2 的经典计算版本。L2 作为推荐供 AI 参考。L3 保留给 AI。这样：步骤2 变为"经典计算生成骨架 + AI 语义细化""
- **依赖关系**：
  - 依赖：分层实现原语（90-P8）、全覆盖保证原语（90-P10）
  - 支撑：无
- **与检索机制的关系**：这是检索机制的核心架构模式——经典计算负责结构化检索（保证覆盖、提供默认排序和分组），AI 负责语义精化（调整检索结果的相关性排序、命名检索结果集）。推荐+细化的分工模式平衡了确定性和语义质量。

### 原语：G'_topo 节点属性体系
- **ID**：90-P12
- **类型**：结构原语
- **描述**：展开图 G'_topo 的每个节点包含五个属性：node_id（与G相同）、section（章节位置）、position（章节内位置）、type（static/dynamic）、traversal_order（全局遍历顺序），每个属性有不同的确定方式（直接拷贝/拓扑排序/语义判断）。
- **溯源**：90, 第32-40行, 原文引用："| node_id | 与 G 相同 | ✅ 直接拷贝 | section | 章节位置 | ⚠️ 需要语义判断 | position | 章节内位置 | ✅ 拓扑排序可确定 | type | static 或 dynamic | ⚠️ 需要语义判断（意识节点=dynamic）| traversal_order | 全局遍历顺序 | ✅ 拓扑排序可确定 |"
- **依赖关系**：
