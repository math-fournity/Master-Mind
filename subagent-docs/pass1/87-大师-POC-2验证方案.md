# 原语提取：87-大师-POC-2验证方案

## 文档概述

本文档是大师-POC-2验证方案，描述了一个七步骤工作流（ArangoDB + G'_topo + TopologyVerifier）用于数学证明的依赖图提示验证。文档详细设计了依赖图结构（18节点25边2环路）、七步骤pipeline（解析→拓扑规划→拓扑验证→转译→KC审计→分析→分析覆盖审计）、三组对照实验、meta/normal AI角色分离、以及ArangoDB基础设施。文档与检索机制的关系在于：依赖图本身就是检索的底层数据结构，七步骤工作流中的图解析、拓扑规划、覆盖验证等环节都涉及从图中检索和匹配节点/边/环路的操作。

## 提取的原语

### 原语：依赖图多类型节点分类
- **ID**：87-P1
- **类型**：结构原语
- **描述**：依赖图中的节点按类型分类（step/substep/意识），不同类型节点承载不同语义角色——步骤节点表示证明步骤，子步骤节点表示具体技巧，意识节点表示数学思维模式。
- **溯源**：87, 第132-151行, 原文引用："节点 ID | 类型 | 内容 | 上下文 ... `矩条件极差题第二问` | step | ... `平移归一化` | substep | ... `不变量思维` | 意识 | ..."
- **依赖关系**：
  - 依赖：无（基础数据结构）
  - 支撑：87-P2（边类型分类）、87-P3（螺旋环路）
- **与检索机制的关系**：节点类型是检索时的过滤维度——检索可以按类型筛选（只检索step节点、只检索意识节点），也可作为匹配时的语义分类依据。不同类型节点在检索时需要不同的匹配策略。

### 原语：依赖图多类型边分类
- **ID**：87-P2
- **类型**：结构原语
- **描述**：依赖图中的边按类型分类（depends_on/calls），depends_on表示知识依赖关系，calls表示意识调用关系，不同边类型编码不同的语义连接。
- **溯源**：87, 第155-181行, 原文引用："起点 | 终点 | 类型 | 说明 ... 矩条件极差题第二问 | 平移归一化 | depends_on | 第一步 ... 矩恒等式 | 不变量思维 | calls | POC-1 已验证"
- **依赖关系**：
  - 依赖：87-P1（节点分类）
  - 支撑：87-P3（螺旋环路）、87-P8（拓扑覆盖验证）
- **与检索机制的关系**：边类型是检索时的关系过滤维度——检索可以按边类型筛选（只沿depends_on做依赖链检索，或只沿calls做意识关联检索），支持多跳遍历时的路径类型约束。

### 原语：螺旋环路结构
- **ID**：87-P3
- **类型**：结构原语
- **描述**：依赖图中存在螺旋环路——两个节点之间通过calls边形成双向循环，环路带有圈数属性，表示同一思维模式在不同阶段被反复调用。
- **溯源**：87, 第183-188行, 原文引用："环路 | 节点 | 圈数 | 上下文 ... loop_0 | 极端检验 ↔ 数值检验意识 | 2 | 第一次：确认 sqrt5 紧性；第二次：确认 n^(-3/2) 兼容 ... loop_1 | 局部-全局思维 ↔ 逼近论思维 | 1"
- **依赖关系**：
  - 依赖：87-P2（边类型分类）
  - 支撑：87-P8（拓扑覆盖验证——环路圈数保持）
- **与检索机制的关系**：螺旋环路是检索中的循环依赖检测原语——检索时需要识别和保留环路结构，避免无限循环的同时保留环路语义。环路圈数是检索结果的完整性度量指标。

### 原语：ArangoDB多集合图存储
- **ID**：87-P4
- **类型**：结构原语
- **描述**：依赖图存储在ArangoDB中，使用多个集合（dg_nodes + dg_edges + loops + kcs）分别存储节点、边、环路和知识组件，通过图数据库统一管理。
- **溯源**：87, 第71行, 原文引用："输出：ArangoDB 中的 `dependency_graph`（dg_nodes + dg_edges + loops + kcs）"
- **依赖关系**：
  - 依赖：无（基础设施层）
  - 支撑：87-P5（AQL集合差集验证）、87-P6（多阶段图版本管理）
- **与检索机制的关系**：多集合分离存储是检索的基础设施——不同集合对应不同检索粒度（节点级、边级、环路级、知识组件级），支持跨集合联合查询。图数据库的AQL查询语言天然支持图遍历检索。

### 原语：AQL集合差集拓扑验证
- **ID**：87-P5
- **类型**：操作原语
- **描述**：使用AQL（ArangoDB查询语言）的集合差集操作进行拓扑覆盖验证——通过集合运算确定性地判断一个图是否完全覆盖另一个图的节点、边和环路，不依赖主观评分。
- **溯源**：87, 第14行和第224行, 原文引用："拓扑确定性验证（AQL集合差集）" 和 "8. 拓扑确定性 | 1.0 | 0 | 0.4 | 1.0（AQL集合差集）"
- **依赖关系**：
  - 依赖：87-P4（ArangoDB多集合存储）
  - 支撑：87-P8（拓扑覆盖验证步骤）
- **与检索机制的关系**：集合差集是检索完备性的确定性验证原语——检索结果与目标集合做差集，差集为空则检索完备。这提供了一种不依赖主观判断的检索质量评估方法。

### 原语：多阶段图版本管理（G → G'_topo → G'）
- **ID**：87-P6
- **类型**：结构原语
- **描述**：依赖图在七步骤工作流中经历多个版本：原始依赖图G → 拓扑规划图G'_topo（只含拓扑结构）→ 完整展开图G'（含文字内容），每个版本存储在ArangoDB的不同集合中。
- **溯源**：87, 第78-86行和第99-100行, 原文引用："输出：ArangoDB 中的 `unfold_topo`（G'_topo）" 和 "输出：ArangoDB 中的 `unfold_full`（G'，含文字）+ 大师提示词文档"
- **依赖关系**：
  - 依赖：87-P4（ArangoDB多集合存储）
  - 支撑：87-P7（七步骤pipeline）、87-P8（拓扑覆盖验证——G与G'_topo之间的覆盖）
- **与检索机制的关系**：多阶段图版本管理是检索中的版本追踪原语——检索可以从不同版本的图中获取不同粒度的信息（G'_topo提供结构信息，G'提供内容信息），版本间的覆盖关系保证检索的一致性。

### 原语：七步骤pipeline（解析→规划→验证→转译→审计→分析→覆盖审计）
- **ID**：87-P7
- **类型**：操作原语
- **描述**：一个七步骤的顺序工作流：依赖图解析（代码）→ 拓扑规划（meta AI）→ 拓扑覆盖验证（代码）→ 按拓扑转译（normal AI）→ KC忠实审计（meta AI）→ 分析（normal AI）→ 分析覆盖审计（meta AI+代码），每步有明确的输入/输出/执行者/性质。
- **溯源**：87, 第66-127行, 原文引用："步骤1：依赖图解析（代码）... 步骤2：展开图拓扑规划（meta AI）... 步骤3：拓扑覆盖验证（代码）... 步骤4：按 G'_topo 转译（normal AI）... 步骤5：KC 忠实审计（meta AI）... 步骤6：分析（normal AI）... 步骤7：分析覆盖审计（meta AI + 代码）"
- **依赖关系**：
  - 依赖：87-P4（ArangoDB存储）、87-P6（多阶段图版本）、87-P9（meta/normal角色分离）
  - 支撑：87-P8（拓扑覆盖验证作为步骤3）
- **与检索机制的关系**：七步骤pipeline是检索流程的编排原语——检索不是单步操作而是多阶段流程，每阶段有明确的输入输出和执行者。检索机制可以借鉴这种"解析→规划→验证→执行→审计"的流水线结构。

### 原语：拓扑覆盖验证（节点覆盖+边覆盖+环路圈数保持）
- **ID**：87-P8
- **类型**：操作原语
- **描述**：TopologyVerifier代码对两个图进行确定性验证，检查三个维度：节点覆盖（所有节点都被展开）、边覆盖（所有边都被展开）、螺旋环路圈数保持（环路在展开后圈数不变），验证结果100%可复现。
- **溯源**：87, 第88-95行, 原文引用："步骤3：拓扑覆盖验证（代码）... 验证：节点覆盖、边覆盖、螺旋环路圈数保持... 预期：1 次通过，100% 覆盖"
- **依赖关系**：
  - 依赖：87-P5（AQL集合差集）、87-P3（螺旋环路结构）、87-P6（多阶段图版本）
  - 支撑：87-P7（七步骤pipeline中的步骤3和步骤7）
- **与检索机制的关系**：拓扑覆盖验证是检索完备性的三维度检查原语——检索机制需要验证是否检索到了所有应检索的节点、所有应检索的边、以及所有环路结构。三个维度的确定性验证确保检索结果无遗漏。

### 原语：meta/normal AI角色分离
- **ID**：87-P9
- **类型**：结构原语
- **描述**：AI角色完全分离为meta AI（做拓扑规划/审计，不涉及数学知识内容）和normal AI（做转译/分析，涉及数学知识内容），不同步骤由不同角色的独立subagent执行，审计者与被审计者分离。
- **溯源**：87, 第15行和第75-80行和第97-101行和第105-109行, 原文引用："完全分离（meta AI做拓扑规划/审计，normal AI做转译/分析）" 和 "执行者：meta AI（独立 subagent）... 性质：纯拓扑规划，不涉及数学知识内容" 和 "执行者：normal AI（独立 subagent，不是步骤2的 meta AI）... 性质：数学知识，文字生成" 和 "执行者：meta AI（独立 subagent，不是步骤4的 normal AI）"
- **依赖关系**：
  - 依赖：无（角色设计层）
  - 支撑：87-P7（七步骤pipeline——角色分配）、87-P10（KC忠实审计）
- **与检索机制的关系**：角色分离是检索机制中的职责隔离原语——检索的规划（决定检索什么）与执行（实际检索）应由不同角色完成，审计（验证检索质量）应由独立于执行者的角色完成，避免自证。

### 原语：KC忠实审计
- **ID**：87-P10
- **类型**：操作原语
- **描述**：meta AI验证展开图中每个节点的text_content是否忠实于对应的kc（知识组件），只关注数学知识忠实度，拓扑覆盖已由数学保证，因此KC审计只需做1次。
- **溯源**：87, 第105-111行, 原文引用："步骤5：KC 忠实审计（meta AI）... 验证每个 uf_node 的 text_content 忠实于对应的 kc... 性质：数学知识验证，只做 1 次"
- **依赖关系**：
  - 依赖：87-P9（meta/normal角色分离——审计者不是转译者）、87-P4（kcs集合存储）
  - 支撑：87-P7（七步骤pipeline中的步骤5）
- **与检索机制的关系**：KC忠实审计是检索内容质量验证原语——检索到的内容是否忠实于原始知识源。检索机制不仅需要验证结构完备性（拓扑覆盖），还需要验证内容忠实性（KC审计），两者互补。

### 原语：知识组件（KC）与节点的绑定关系
- **ID**：87-P11

- **描述**：依赖图中每个知识节点绑定一个kc（知识组件），kc存储在独立的kcs集合中，节点的text_content需要忠实于其绑定的kc，形成"节点-kc"的引用关系。

- **与检索机制的关系**：KC绑定是检索中的知识溯源原语——每个检索结果可以追溯到其原始知识组件，支持检索结果的可信度验证和知识来源追踪。

### 原语：拓扑规划（从图结构到展开位置的映射）
- **ID**：87-P12
- **类型**：操作原语
- **描述**：meta AI读取依赖图，为每个节点规划其在文字展开中的位置（section/段落），为每条边规划其在文字展开中的连接方式，保持螺旋环路圈数，输出G'_topo——一个只含拓扑结构不含内容的展开规划图。
- **溯源**：87, 第75-86行, 原文引用："步骤2：展开图拓扑规划（meta AI）... 为每个节点规划其在文字展开中的位置（section/段落）... 为每条边规划其在文字展开中的连接方式... 保持螺旋环路圈数... 输出 G'_topo JSON，写入 ArangoDB"
- **依赖关系**：
  - 依赖：87-P1（节点分类）、87-P2（边类型）、87-P3（螺旋环路）
  - 支撑：87-P6（多阶段图版本——G'_topo是中间版本）、87-P8（拓扑覆盖验证——验证G'_topo覆盖G）
- **与检索机制的关系**：拓扑规划是检索结果的布局原语——检索到的节点和边需要被组织成有序的结构（位置、连接方式），而不是散乱返回。拓扑规划将图结构映射为线性展开顺序，是检索结果呈现的关键环节。

### 原语：按拓扑结构转译（结构驱动的文字生成）

### 原语：分析覆盖审计（拓扑验证+知识验证双层）

### 原语：八维评分体系
