# 原语提取：96-诚实评估与未来·数学项目工作系统

## 文档概述

本文档是对数学项目工作系统愿景达成度的诚实评估，对比了认知图系统（工作系统）与数学依赖图系统（目标系统）的当前状态，列出了8条已知局限、HoTT标签的诚实定位、未来演进方向，以及给其他AI的复用建议。文档本身是评估性/反思性文档，不直接描述检索机制的实现细节，但其中大量内容涉及图遍历、种子选择、覆盖验证、三层图结构、版本链、Hook机制等支撑检索流程的底层原语及其已知局限和未来方向，这些对检索机制设计有直接参考价值。

## 提取的原语

### 原语：双图系统架构（认知图 + 依赖图）
- **ID**：96-P1
- **类型**：结构原语
- **描述**：系统由两套图驱动——认知图系统管理AI工作认知（~30个认知单元），数学依赖图系统管理数学证明的依赖结构（dg_nodes/dg_edges/loops），两套图通过意识节点的双重身份关联。
- **溯源**：96, 第9-12行, 原文引用："数学项目有两套图驱动的系统：1. **认知图系统**（工作系统）：管理AI自己的工作认知（~30个认知单元）2. **数学依赖图系统**（目标系统）：管理数学证明的依赖结构（dg_nodes/dg_edges/loops）"
- **依赖关系**：
  - 依赖：无（顶层架构原语）
  - 支撑：96-P2（三层图结构）、96-P12（两套图一致性）
- **与检索机制的关系**：检索机制需要明确从哪个图中检索Pattern——认知图检索工作认知单元，依赖图检索证明节点。双图架构决定了检索的范围和目标。

### 原语：三层图结构（G/G'_topo/G'_full）
- **ID**：96-P2
- **类型**：结构原语
- **描述**：数学依赖图系统采用三层图结构——G（原始依赖图）、G'_topo（拓扑骨架展开图）、G'_full（完整展开图），认知图系统当前为单层。
- **溯源**：96, 第20行, 原文引用："图结构 | 单层 | 三层（G/G'_topo/G'_full）"
- **依赖关系**：
  - 依赖：96-P1（双图系统架构）
  - 支撑：96-P3（BFS图遍历）、96-P5（拓扑覆盖验证）
- **与检索机制的关系**：三层图结构提供了多粒度的检索空间——可以在G层做粗粒度检索，在G'_topo层做拓扑结构匹配，在G'_full层做完整内容检索。检索机制可以按需选择图层。

### 原语：BFS图遍历检索（AQL）
- **ID**：96-P3
- **类型**：操作原语
- **描述**：使用ArangoDB的AQL进行BFS图遍历，从种子节点出发遍历依赖图，加载相关认知单元/证明节点。两套图系统都使用此机制。
- **溯源**：96, 第21行, 原文引用："图展开 | BFS图遍历（AQL） | BFS图遍历 + **经典计算展开骨架**（92号方案）"
- **依赖关系**：
  - 依赖：96-P1（双图系统架构）、96-P4（种子选择）
  - 支撑：96-P5（覆盖验证）、96-P6（七步骤工作流）
- **与检索机制的关系**：BFS图遍历是检索机制的核心算法——从种子节点出发，沿依赖边遍历，检索出相关的Pattern集合。这是最直接的检索操作原语。

### 原语：种子选择（CP1）
- **ID**：96-P4
- **类型**：操作原语
- **描述**：种子选择是检索流程的第一步（CP1），由AI根据任务描述决定选哪些认知单元作为种子，然后从种子出发做BFS图遍历。当前依赖AI概率判断，无确定性算法。
- **溯源**：96, 第57-65行, 原文引用："**问题**：CP1（种子选择）由AI自己决定选哪些认知单元作为种子。AI可能选错种子——漏选重要前置认知，或选了无关的种子。……**未解决**：没有确定性算法自动选择种子。"
- **依赖关系**：
  - 依赖：96-P1（双图系统架构）
  - 支撑：96-P3（BFS图遍历检索）——种子是图遍历的起点
- **与检索机制的关系**：种子选择是检索机制的入口环节——决定了检索从哪里开始。种子选择的质量直接影响检索的覆盖率和精度。未来方向"种子推荐"（第174行）是根据任务描述自动推荐种子，这是检索机制的关键改进方向。

### 原语：覆盖验证（集合差集 + 拓扑验证）
- **ID**：96-P5
- **类型**：操作原语
- **描述**：覆盖验证有两种层级——认知图系统用Python set操作做朴素集合差集（task_ids - loaded_set），数学依赖图系统用TopologyVerifier做四层拓扑覆盖验证（节点+边+跨宫边+环路）。
- **溯源**：96, 第22行, 原文引用："覆盖验证 | 集合差集（found vs ground_truth） | AQL集合差集 + TopologyVerifier"
- **依赖关系**：
  - 依赖：96-P3（BFS图遍历检索）——验证遍历结果是否覆盖目标
  - 支撑：96-P6（七步骤工作流）
- **与检索机制的关系**：覆盖验证是检索机制的闭环环节——验证检索结果是否完整覆盖了任务所需的Pattern集合。集合差集是弱验证（只查遗漏），拓扑验证是强验证（检查依赖关系是否正确使用）。检索机制需要覆盖验证来保证检索质量。

### 原语：螺旋环路检测
- **ID**：96-P7

- **描述**：在依赖图中检测螺旋环路（如极端检验↔数值检验意识，局部-全局↔逼近论），环路圈数在G'_topo中保持，环路有数学含义（对应数学意识迭代）。

- **与检索机制的关系**：螺旋环路是依赖图中的特殊结构——检索机制在遍历时需要识别和处理环路，避免无限循环，同时环路本身携带语义信息（数学意识迭代），可以作为检索结果的语义标注。

### 原语：缺口检查（CP3）

- **溯源**：96, 第63行, 原文引用："**当前缓解**：AGENTS.md中列出所有core认知单元，AI可以参考；CP3缺口检查提醒AI"图遍历可能遗漏与种子无依赖边但任务相关的认知单元"。"
- **依赖关系**：
  - 依赖：96-P3（BFS图遍历检索）、96-P4（种子选择）
  - 支撑：96-P5（覆盖验证）
- **与检索机制的关系**：缺口检查揭示了BFS图遍历检索的固有局限——依赖边驱动的检索无法发现语义相关但无依赖边的Pattern。这是检索机制设计中的核心问题：如何检索无依赖关系但语义相关的Pattern。未来方向"种子推荐"（第174行）可能部分解决此问题。
