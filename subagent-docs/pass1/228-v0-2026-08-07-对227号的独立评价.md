# 原语提取：228-v0-对227号的独立评价——方法论成熟但未贯彻自身警告

## 文档概述

本文档是对227号的独立评价，评估227号对226-v0/v1的回应中的三个实质贡献和七个方法论问题。文档涉及证书分类、证书数据结构、obstruction层级、态射标注、自然性分层、可检查性分层、双标准共存等内容。虽然文档本身是评价性元文档，但其中讨论的多个结构性设计决策（证书带字段对象、纤维内偏序+全局索引范畴、态射标注替代范畴分层、可检查性分层、双标准共存等）都可作为检索机制的原语——它们定义了被检索对象的表示结构、索引方式、匹配标准和质量分层。

## 提取的原语

### 原语：证书三分类（正向证书/反驳证书/诊断反馈）
- **ID**：228-v0-P1
- **类型**：结构原语
- **描述**：将证书分为三类——正向证书（证明X成立）、反驳证书（证明X不成立，通常表现为反例）、诊断反馈（类型错误、工具超时、翻译缺口），前两类属于证书层，第三类属于反馈层。
- **溯源**：228-v0, 第26-30行, 原文引用："227的三分类是正确的：正向证书（证明X成立）→ 证书层 / 反驳证书（证明X不成立，通常表现为反例）→ 证书层 / 诊断反馈（类型错误、工具超时、翻译缺口）→ 反馈层"
- **依赖关系**：
  - 依赖：对"证书"概念的定义（226-v0/v1）
  - 支撑：证书带字段对象（228-v0-P2），因为字段中的status需要区分这三类
- **与检索机制的关系**：检索机制需要按证书类型过滤和路由——正向证书和反驳证书都是可检索的硬证据，诊断反馈则路由到反馈闭环而非证书检索。这三分类是检索结果分类和路由的基础。

### 原语：证书带字段对象（claim/scope/strength/dependencies/checker/status）
- **ID**：228-v0-P2
- **类型**：结构原语
- **描述**：证书不是一个标量或单一偏序中的元素，而是一个带字段的结构化对象，包含claim（断言）、scope（范围）、strength（强度）、dependencies（依赖）、checker（检查器）、status（状态）。
- **溯源**：228-v0, 第39行, 原文引用："把证书写成带字段的对象（claim, scope, strength, dependencies, checker, status），在固定claim和scope的纤维里有偏序，全局上是带索引的证书范畴。"
- **依赖关系**：
  - 依赖：证书三分类（228-v0-P1）提供类型基础
  - 支撑：纤维内偏序+全局索引范畴（228-v0-P3）
- **与检索机制的关系**：这是被检索对象（Pattern/证书）的核心数据结构。检索机制需要按字段查询——按scope检索覆盖某范围的证书、按dependencies检索依赖链、按checker检索可验证的证书、按status过滤有效/失效证书。每个字段都是一个检索维度。

### 原语：纤维内偏序+全局索引范畴
- **ID**：228-v0-P3
- **类型**：结构原语
- **描述**：证书不构成单一偏序，而是在固定claim和scope的纤维（fiber）内有偏序（信息加强、依赖扩张），全局上是带索引的证书范畴。范围收缩不是加强，不能压进同一偏序。
- **溯源**：228-v0, 第35-39行, 原文引用："226-v1说C有三种箭头（信息加强、依赖扩张、范围收缩）但把它们塞进同一个偏序。227正确指出：范围收缩不是加强……把证书写成带字段的对象（claim, scope, strength, dependencies, checker, status），在固定claim和scope的纤维里有偏序，全局上是带索引的证书范畴。"
- **依赖关系**：
  - 依赖：证书带字段对象（228-v0-P2），因为纤维的划分依据是claim和scope字段
  - 支撑：检索时的多维度索引结构
- **与检索机制的关系**：这是证书的索引结构——检索时先按claim+scope定位到纤维，再在纤维内按偏序找最强证书。全局索引范畴支持跨纤维的检索（如找所有依赖某证书的证书）。范围收缩不进入同一偏序，避免了检索时错误地用窄范围证书替代宽范围证书。

### 原语：obstruction四级层级（descent failure→obstruction→Čech→H¹）
- **ID**：228-v0-P4
- **类型**：结构原语
- **描述**：粘合失败不直接等同于H¹≠0，而是有四级层级：descent failure（最一般）→ obstruction object（可记录比较）→ Čech 1-cocycle（差异写成转换函数时）→ H¹ class（系数对象满足条件时）。
- **溯源**：228-v0, 第47行, 原文引用："227的层级是正确的：descent failure（最一般）→ obstruction object（可记录比较）→ Čech 1-cocycle（差异写成转换函数时）→ H¹ class（系数对象满足条件时）。"
- **依赖关系**：
  - 依赖：对粘合失败现象的识别
  - 支撑：诊断检索的分层路由
- **与检索机制的关系**：检索机制在诊断环节需要按obstruction级别分层检索——不同级别的粘合失败需要不同的处理策略。检索诊断信息时，先定位到最一般的descent failure级别，再逐步细化到更精确的级别。这避免了把所有粘合失败都检索为H¹类，丢失中间层级的诊断信息。

### 原语：态射标注替代范畴分层（证书运输能力标注）
- **ID**：228-v0-P5
- **类型**：操作原语
- **描述**：不把语义移动分成五个子范畴（Σ_rep/Σ_red/Σ_spec/Σ_form/Σ_diag），而是给每个态射加标注"证书运输能力"：等价表示（双向运输）、归约（单向运输，从目标到源）、特例化（单向运输，从源到目标但只覆盖特例）、对偶化（双向或单向）、形式化翻译（需要忠实性检查）。
- **溯源**：228-v0, 第132-139行, 原文引用："一个态射τ:S→S'可以有一个属性'证书运输能力'：等价表示：双向运输 / 归约：单向运输（从目标到源）/ 特例化：单向运输（从源到目标，但只覆盖特例）/ 对偶化：双向或单向（取决于强对偶还是弱对偶）/ 形式化翻译：需要忠实性检查。这比分层更简单，也更能处理'一个操作同时属于多种类型'的情况。"
- **依赖关系**：
  - 依赖：对态射（语义移动）的定义
  - 支撑：证书沿态射的运输检索（228-v0-P3的纤维间检索）
- **与检索机制的关系**：这是检索机制中"证书可否沿某条路径运输"的判断依据。检索一个Pattern时，需要知道从当前状态到目标状态之间存在哪些态射，以及这些态射的证书运输能力——双向运输的态射允许证书自由检索，单向运输的态射限制了检索方向，需要忠实性检查的态射需要额外验证。态射标注是路径检索的边权/边属性。

### 原语：自然性三层分级（强自然性/弱自然性/经验稳定性）
- **ID**：228-v0-P6
- **类型**：性质标准
- **描述**：自然性不是单一标准，而是分三层：强自然性（在等价表示下可证交换）、弱自然性（在非等价但保目标的移动下lax交换）、经验稳定性（在变体族上稳定产生同类证书目标）。
- **溯源**：228-v0, 第221-224行, 原文引用："227号§5把自然性分成三层：强自然性：在等价表示下可证交换 / 弱自然性：在非等价但保目标的移动下lax交换 / 经验稳定性：在变体族上稳定产生同类证书目标"
- **依赖关系**：
  - 依赖：对"非特定性"概念的理解（218号危机）
  - 支撑：可检查性分层（228-v0-P7）
- **与检索机制的关系**：检索机制在判断"检索到的Pattern是否非特定"时，需要按自然性级别分级。强自然性的Pattern可以机械验证后直接使用；弱自然性的需要半形式化检查；经验稳定性的需要统计验证。这决定了检索结果的可信度分级和后续验证流程。

### 原语：可检查性分层（数学证明/半形式化比较/统计测试）
- **ID**：228-v0-P7
- **类型**：性质标准
- **描述**：不同层级的标准应有不同的可检查方式：第一层用数学证明（可检查，用于验证）、第二层用半形式化比较（lax交换的度量可被定义，如"交换图的误差项在C中可比较"）、第三层用统计测试（在足够多的变体上测试，用频率代替证明）。
- **溯源**：228-v0, 第245-250行, 原文引用："第一层（强自然性）作为严格标准：可检查，用于验证 / 第二层（弱自然性）作为半形式化标准：lax交换的度量可以被定义（比如'交换图的误差项在C中可比较'），但需要具体例子来确认 / 第三层（经验稳定性）作为统计标准：在足够多的变体上测试，用频率代替证明"
- **依赖关系**：
  - 依赖：自然性三层分级（228-v0-P6）
  - 支撑：检索结果的质量保证流程
- **与检索机制的关系**：检索机制返回的Pattern需要经过可检查性验证才能被信任。不同级别的Pattern用不同的验证方式——这定义了检索后验证pipeline的分支逻辑。如果检索机制只返回可机械检查的Pattern，会过于保守；如果返回所有级别但不区分验证方式，会引入不可信结果。可检查性分层是检索结果质量分级的基础。

### 原语：双标准共存（严格标准+启发式标准）
- **ID**：228-v0-P8
- **类型**：操作原语
- **描述**：不单一标准替代，而是两个标准共存——严格标准（如Pareto改善，可检查但保守）和启发式标准（如受控交换，灵活但不可检查）各司其职。系统在严格标准可用时用严格标准，在需要启发式时用AI判断并记录理由。
- **溯源**：228-v0, 第173-178行, 原文引用："保持Pareto改善作为严格标准（可检查但保守）/ 把'受控交换'作为启发式标准（更灵活但不可检查）/ 系统在Pareto改善可用时用Pareto改善，在需要受控交换时用AI判断（并记录理由）。这样两个标准共存，各司其职。"
- **依赖关系**：
  - 依赖：对Pareto改善和受控交换两种标准的理解
  - 支撑：检索机制的排序/选择策略
- **与检索机制的关系**：检索机制在排序和选择Pattern时，可以用严格标准做确定性筛选（保证可检查性），用启发式标准做探索性扩展（覆盖更多可能性）。两个标准共存意味着检索结果分两个层次：严格层（可机械验证）和启发式层（需AI判断+记录理由）。这避免了检索机制要么过于保守（只用严格标准）要么不可信（只用启发式标准）。

### 原语：范围收缩不是加强（防误替代约束）
- **ID**：228-v0-P13
- **类型**：性质标准
- **描述**：范围收缩（如"对n≥4且n偶数成立，常数更好"）不是信息加强，不能替代原始范围更宽的证书。把范围收缩误当成单调增长，系统可能错误地认为已经证明了原始目标，实际上只证明了更窄的情形。
- **溯源**：228-v0, 第35-37行, 原文引用："227正确指出：范围收缩不是加强——'对n≥4且n偶数成立，常数更好'不能替代'对n≥4成立'。为什么这是对的：把范围收缩误当成单调增长，系统可能以为越来越强，实际只是越来越窄。"
- **依赖关系**：
  - 依赖：证书带字段对象（228-v0-P2）中的scope字段
  - 支撑：纤维内偏序+全局索引范畴（228-v0-P3）的正确构建
- **与检索机制的关系**：这是检索机制中一个关键的防误替代约束——检索时不能用scope更窄的证书替代scope更宽的证书，即使前者的常数更好。检索结果的排序必须考虑scope覆盖关系，避免"看起来更强但实际更窄"的假阳性。

### 原语：Kleisli范畴作为带效应状态转换的候选模型
