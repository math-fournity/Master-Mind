# 原语提取：85-大师-POC-1验证结果

## 文档概述

本文档记录了数学大师系统 POC-1 的验证实验结果：对比"教材 Markdown 提示"（A组对照组）与"依赖图提示 JSON"（B组实验组）在解决一道矩条件极差题上的表现差异。实验证明依赖图提示（含意识标注节点和螺旋环路提示）显著优于纯教材提示，核心增量价值在于"补充思维路径和意识标注"而非"补充缺失的结构"。文档中包含大量关于依赖图节点设计、意识标注机制、螺旋环路、上下文区分等可直接作为检索机制原语的思想片段。

## 提取的原语

### 原语：依赖图提示 JSON 结构（节点+边+意识标注）
- **ID**：85-P1
- **类型**：结构原语
- **描述**：用 JSON 格式的依赖图（节点+边）作为提示载体，节点不仅包含知识，还显式标注"意识"节点（如"数值检验意识"），边表示知识间的依赖与调用关系。
- **溯源**：85, 第10行, 原文引用："B 组（实验组）| 错误题面 + 依赖图提示 JSON（8节点10边，含"数值检验意识"节点和螺旋环路提示）"
- **依赖关系**：
  - 依赖：无
  - 支撑：85-P2（意识标注节点）、85-P3（螺旋环路提示）
- **与检索机制的关系**：这是检索机制的输出格式原语——检索结果以"节点+边+意识标注"的结构化图形式呈现，而非扁平文本。检索机制需要返回的不只是知识点，还有意识标注和节点间的依赖关系。

### 原语：意识标注节点（Awareness Annotation Node）
- **ID**：85-P2
- **类型**：结构原语
- **描述**：在依赖图中设置专门的"意识"节点，将某种思维模式（如"数值检验意识"）显式标注为需要主动调用的意识，而非仅仅是知识描述。意识节点的核心价值是让系统知道"应该做什么类型的思维操作"，而不只是"知道什么知识"。
- **溯源**：85, 第64-66行, 原文引用："B 组的依赖图提示中包含了"数值检验意识"节点和螺旋环路提示。这帮助 B 组：1. 系统检验多个候选指数…2. 区分上界与下界——因为依赖图的"极端检验"节点上下文明确标注了"三点构型数值试探"，而"数值检验意识"节点的上下文是"检验命题自洽性""
- **依赖关系**：
  - 依赖：85-P1（依赖图 JSON 结构）
  - 支撑：85-P5（上下文区分机制）、85-P8（增量价值来源）
- **与检索机制的关系**：检索机制需要能够检索"意识"类型的 Pattern，而非只检索"知识"类型的 Pattern。意识标注节点是一种特殊的检索目标类型——检索时应区分"知识节点"和"意识节点"，并在返回结果中保留这种类型标注。

### 原语：螺旋环路提示（Spiral Loop Hint）
- **ID**：85-P3
- **类型**：操作原语
- **描述**：在依赖图中通过环路结构提示"同一个意识节点在不同上下文中被多次调用"，形成螺旋上升而非平面循环。螺旋环路提示让系统意识到某节点会被在不同上下文中重复调用，且每次调用的目的不同。
- **溯源**：85, 第65行, 原文引用："因为依赖图的螺旋环路提示了"第二次调用在检验指数上下文中""
- **溯源2**：85, 第96-98行, 原文引用："B 组在回答中明确提到了螺旋环路："极端检验在两个不同上下文中被调用——第一次确认 sqrt(5) 是最优常数，第二次检验第二问指数。两次调用的目的不同，是深化不是循环。"这验证了星学 POC 中验证过的螺旋环路机制在数学领域同样有效"
- **依赖关系**：
  - 依赖：85-P1（依赖图 JSON 结构）、85-P2（意识标注节点）
  - 支撑：85-P5（上下文区分机制）
- **与检索机制的关系**：检索机制需要支持"同一 Pattern 在不同上下文中被多次检索并返回"的能力，且每次检索时需标注该 Pattern 在当前上下文中的调用目的。螺旋环路意味着检索不是一次性的，而是可以在推理过程中多次触发同一 Pattern 的检索，每次带不同的上下文标签。

### 原语：盲评对照实验协议（A/B组盲评）
- **ID**：85-P4
- **类型**：操作原语
- **描述**：用 A/B 两组对照 + 盲评方式验证某种提示机制的有效性。评分者不知道哪个是 A 哪个是 B，按多个维度独立评分，通过差值判定显著性。这是一种验证检索机制增量价值的实验协议。
- **溯源**：85, 第9-12行, 原文引用："A 组（对照组）| 错误题面 + 教材 Markdown…B 组（实验组）| 错误题面 + 依赖图提示 JSON…评分方式 | 盲评（评分者不知道哪个是A哪个是B），5维评分"
- **依赖关系**：
  - 依赖：无
  - 支撑：无
- **与检索机制的关系**：这是验证检索机制有效性的实验协议原语。当设计了一个新的检索机制后，可以用此协议验证其增量价值：对照组用旧机制（或无检索），实验组用新检索机制，盲评比较。

### 原语：上下文区分机制（Context Disambiguation）
- **ID**：85-P5
- **类型**：操作原语
- **描述**：同一节点（如"极端检验"/"数值检验"）在不同上下文中具有不同目的，依赖图通过显式标注每个节点出现的上下文来帮助区分。例如"极端检验"节点在"三点构型数值试探"上下文中 vs "数值检验意识"节点在"检验命题自洽性"上下文中，帮助系统意识到同一操作在不同上下文中的含义不同。
- **溯源**：85, 第66行, 原文引用："因为依赖图的"极端检验"节点上下文明确标注了"三点构型数值试探"，而"数值检验意识"节点的上下文是"检验命题自洽性"，两个不同上下文帮助 B 组意识到三点构型只是检验工具，不是下界证明"
- **依赖关系**：
  - 依赖：85-P2（意识标注节点）、85-P3（螺旋环路提示）
  - 支撑：85-P6（系统检验多候选机制）
- **与检索机制的关系**：检索机制在返回 Pattern 时需要附带"上下文标签"——同一个 Pattern 在不同上下文中可能被用于不同目的。检索结果应包含上下文标注，帮助调用方正确理解该 Pattern 在当前场景中的用途，避免误用（如将上界误认为下界）。

### 原语：系统检验多候选机制（Systematic Candidate Verification）
- **ID**：85-P6
- **类型**：操作原语
- **描述**：在发现问题后，不是只检验一个候选就下结论，而是系统检验多个候选（如 n^(-1/3)、n^(-2/3)、n^(-3/2)），通过数值兼容性精确定位正确答案。依赖图的螺旋环路提示帮助触发这种系统检验行为。
- **溯源**：85, 第58行, 原文引用："发现错误后，系统检验了三个候选指数（n^(-1/3)、n^(-2/3)、n^(-3/2)），通过数值兼容性精确定位 n^(-3/2) 为正确指数"
- **溯源2**：85, 第65行, 原文引用："系统检验多个候选指数（而不是只看一个就下结论）——因为依赖图的螺旋环路提示了"第二次调用在检验指数上下文中""
- **依赖关系**：
  - 依赖：85-P3（螺旋环路提示）、85-P5（上下文区分机制）
  - 支撑：无
- **与检索机制的关系**：检索机制应支持"多候选检索"——当需要验证某个假设时，不是只返回一个最匹配的 Pattern，而是返回多个候选 Pattern 供系统逐一检验。检索结果的多候选性是系统检验行为的前提。

### 原语：增量价值来源——思维路径与意识标注 vs 结构补充
- **ID**：85-P7
- **类型**：概念框架
- **描述**：依赖图提示的核心增量价值不是"补充缺失的知识结构"，而是"补充教材中没有的思维路径和意识标注"。数学教材已足够结构化（知识不缺），缺的是"怎么思考"的意识标注和思维路径引导。
- **溯源**：85, 第78-79行, 原文引用："84 号文档第 11 节预判："数学版依赖图提示的核心增量价值，可能不是'补充缺失的结构'，而是'补充教材中没有的思维路径和意识标注'。"POC 结果支持了这个预判"
- **溯源2**：85, 第92行, 原文引用："这正是依赖图提示"补充思维路径和意识标注"的核心价值。A 组有知识但缺意识，B 组的依赖图显式标注了"数值检验意识"并提示了螺旋环路"
- **依赖关系**：
  - 依赖：85-P2（意识标注节点）
  - 支撑：无
- **与检索机制的关系**：这是检索机制的设计哲学原语——检索机制应优先检索"思维路径"和"意识标注"类型的 Pattern，而非仅仅检索"知识"类型的 Pattern。在数学领域，知识本身不缺（教材已足够），检索机制的增量价值在于检索出"怎么思考"的元认知策略。

### 原语：维度化增量来源分析（Per-Dimension Increment Attribution）
- **ID**：85-P8
- **类型**：结构原语
- **描述**：将提示的增量价值按评分维度逐一归因——每个维度的提升来自提示中的哪个具体元素。例如"第二问纠错能力 +2"归因于"数值检验意识节点和螺旋环路提示"，"结构感 +2"归因于"依赖图呈现了知识间的层次关系"。
- **溯源**：85, 第82-88行, 原文引用："| 第二问纠错能力 | 3 | 5 | B组的"数值检验意识"节点和螺旋环路提示 |…| 结构感 | 3 | 5 | B组的依赖图呈现了知识间的层次关系 |"
- **依赖关系**：
  - 依赖：85-P4（盲评对照实验协议）
  - 支撑：无
- **与检索机制的关系**：这是检索机制效果评估的原语——检索机制的贡献应按维度归因，明确每个维度的提升来自检索机制中的哪个具体设计元素。这帮助迭代优化检索机制时知道该改进哪个部分。

### 原语：依赖路径引导完整逻辑链
- **ID**：85-P9
- **类型**：操作原语
- **描述**：依赖图中的依赖路径（节点间的边）引导系统构建完整的逻辑链。B 组的逻辑性维度提升 +2，归因于"依赖路径引导了完整的逻辑链"。
- **溯源**：85, 第87行, 原文引用："逻辑性 | 3 | 5 | B组的依赖路径引导了完整的逻辑链"
- **依赖关系**：
  - 依赖：85-P1（依赖图 JSON 结构）
  - 支撑：无
- **与检索机制的关系**：检索机制返回的不应是孤立的 Pattern，而应返回 Pattern 间的依赖路径——即 Pattern A 依赖 Pattern B，Pattern B 依赖 Pattern C 的链条。这条依赖路径直接引导推理的逻辑链构建。检索结果的拓扑结构（而非集合）是关键。

### 原语：知识层次关系呈现（Knowledge Hierarchy Presentation）
- **ID**：85-P10
- **类型**：结构原语
- **描述**：依赖图通过节点和边的拓扑结构呈现知识间的层次关系，帮助系统获得"结构感"。B 组的结构感维度提升 +2，归因于"依赖图呈现了知识间的层次关系"。
- **溯源**：85, 第88行, 原文引用："结构感 | 3 | 5 | B组的依赖图呈现了知识间的层次关系"
- **依赖关系**：
  - 依赖：85-P1（依赖图 JSON 结构）
  - 支撑：85-P9（依赖路径引导完整逻辑链）
- **与检索机制的关系**：检索机制返回的结果应保留知识的层次结构——哪些 Pattern 是上层的、哪些是下层的、哪些是平行的。层次关系帮助调用方理解 Pattern 间的结构关系，而不仅仅是获取一堆扁平的知识点。

### 原语：意识标注 vs 方法描述的区别（Awareness vs Method Description）
- **ID**：85-P11
- **类型**：概念框架
- **描述**：教材中提到"数值试探"只是一种方法描述，不是意识标注。方法描述告诉系统"有这个方法"，但不告诉系统"应该在什么时候主动调用这个方法"和"这个方法在不同上下文中有不同目的"。意识标注比方法描述多了一层"主动调用指令"和"上下文目的区分"。
- **溯源**：85, 第68行, 原文引用："A 组的教材虽然提到了"数值试探"，但没有将其标注为一种需要主动调用的"意识"，也没有提示"数值试探在不同上下文中有不同目的"（螺旋环路）。所以 A 组虽然做了数值检验，但检验方式单一"
- **依赖关系**：
  - 依赖：85-P2（意识标注节点）、85-P5（上下文区分机制）
  - 支撑：85-P7（增量价值来源）
- **与检索机制的关系**：检索机制在返回 Pattern 时，应区分"方法描述"和"意识标注"两种元数据。方法描述只说明 Pattern 是什么，意识标注说明 Pattern 应在何时被主动调用、在不同上下文中有什么不同目的。检索结果应包含意识标注层，否则调用方虽知道方法但不会主动系统性地使用。

### 原语：三层提取跨题复用（L1/L2/L3 Cross-Problem Reuse）
- **ID**：85-P12
- **类型**：概念框架
- **描述**：从解题过程中提取三层知识（L1/L2/L3），验证跨题复用增益。这是知识分层管理的框架，不同层次的 Pattern 有不同的复用范围。
- **溯源**：85, 第122行, 原文引用："三层提取 POC（83 号文档）：验证 L1/L2/L3 跨题复用增益"
- **依赖关系**：
  - 依赖：无（引用83号文档）
  - 支撑：无
- **与检索机制的关系**：检索机制应支持按层次（L1/L2/L3）检索 Pattern，不同层次的 Pattern 有不同的复用粒度。L1 可能是具体技巧，L2 可能是方法模式，L3 可能是元认知策略。检索时可根据当前需求选择检索哪个层次的 Pattern。

### 原语：具体构造 vs 纯意识提示的分离测试
- **ID**：85-P13
- **类型**：操作原语
- **描述**：POC 中 B 组提示同时包含了具体构造（q(x) = x^2 + x - 1）和意识提示，无法分离两者的贡献。后续 POC 计划测试"不给具体构造、只给意识提示"的情况，以分离具体知识提示和意识提示的各自贡献。
- **溯源**：85, 第102行, 原文引用："B 组提示中包含了 q(x) = x^2 + x - 1 的具体构造：这给了 B 组不公平的优势。但 POC 验证的是"依赖图提示是否有用"，不是"是否公平"。后续 POC 可以测试不给具体构造、只给意识提示的情况。"
- **溯源2**：85, 第117行, 原文引用："消除 q(x) 提示：测试不给具体构造、只给意识提示时 B 组是否仍有优势"
- **依赖关系**：
  - 依赖：85-P4（盲评对照实验协议）
  - 支撑：无
- **与检索机制的关系**：检索机制可以按"具体知识"和"纯意识/策略"两种模式检索。分离测试帮助确定检索机制中"具体知识检索"和"意识策略检索"各自的贡献，指导检索机制在不同场景下选择检索哪种类型的 Pattern。

### 原语：显著优于判定标准（Significance Threshold）
- **ID**：85-P14
- **类型**：性质标准
- **描述**：判定"显著优于"的三条标准：(1) 综合评分差值 > 0.5（满分5分制）；(2) 实验组在全部维度上不低于对照组；(3) 实验组在多数维度上高于对照组1分以上。
- **溯源**：85, 第29-32行, 原文引用："判定依据：1. 综合评分差值：5.00 - 3.25 = 1.75 > 0.5 ✓ 2. B 组在全部 5 个维度上不低于 A 组 ✓ 3. B 组在 4 个维度上高于 A 组 1 分以上…✓"
- **依赖关系**：
  - 依赖：85-P4（盲评对照实验协议）
  - 支撑：无
- **与检索机制的关系**：这是验证检索机制是否"显著有效"的判定标准原语。当用 A/B 对照实验测试检索机制时，需要明确的显著性判定标准来决定是否采纳该检索机制。

### 原语：边际增益跨实验对比（Marginal Gain Cross-Experiment Comparison）
- **ID**：85-P15
- **类型**：性质标准
- **描述**：用"边际增益"（实验组综合分 - 对照组综合分）作为统一度量，跨不同 POC 实验对比效果量级。不同实验满分不同时需换算到同一尺度（如5分制换算到10分制）。
- **溯源**：85, 第34-44行, 原文引用："边际增益：+1.75（满分 5 分的 35%）…注意大师-POC-1 的满分是 5 分（星学是 10 分），所以 +1.75 对应 10 分制的 +3.50，与星学 POC-1 的 +3.95 量级相当。"
- **依赖关系**：
  - 依赖：85-P4（盲评对照实验协议）、85-P14（显著优于判定标准）
  - 支撑：无
- **与检索机制的关系**：这是检索机制效果跨实验对比的度量原语。不同版本的检索机制在不同实验中的效果需要统一度量来比较，边际增益+满分换算是标准化的对比方法。

## 文档中无原语可提取的部分
