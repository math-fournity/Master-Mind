### 原语：K/T/H三图分离
- **ID**：122v3-P01
- **类型**：结构原语
- **描述**：将系统知识分为三个独立图：K（数学知识图——什么数学关系成立）、T（外显思维图——这次Agent实际走了什么路线）、H（启发激活图——当前T出现何种模式时，应从K激活什么方向）。
- **溯源**：122-v3-2026-08-05-完整机制复核与费马极限案例.md, 第267-278行, 原文引用："1. **K：数学知识图**——什么数学关系成立；2. **T：外显思维图**——这次Agent实际走了什么路线；3. **H：启发激活图**——当前T出现何种模式时，应从K激活什么方向。"
- **依赖关系**：依赖：无（顶层架构原语）/支撑：P02动态题目状态、P03外显思维图建模、P16H图匹配四元组、P17最小激活包
- **与检索机制的关系**：直接定义检索系统的三大数据结构——H图是Pattern存储（检索目标库），T图是状态表示（检索查询），K图是知识源（检索结果的数学内容来源）。三图分离是检索机制的结构基础。

### 原语：动态题目状态 Q_t
- **ID**：122v3-P02
- **类型**：结构原语
- **描述**：把题目建模为动态状态 Q_t = Q_0 ⊕ T_{0:t} ⊕ E_{0:t} ⊕ U_t，系统每次不是重新解原题，而是处理原题+已有中间结论+已排除分支+工具证据+当前未决子目标+当前停滞模式的复合体。
- **溯源**：122-v3-2026-08-05-完整机制复核与费马极限案例.md, 第279-293行, 原文引用："$$Q_t=Q_0\oplus T_{0:t}\oplus E_{0:t}\oplus U_t.$$ 系统每次不是重新解原题，而是处理：原题；已有中间结论；已排除分支；工具证据；当前未决子目标；当前停滞模式。"
- **依赖关系**：依赖：P01K/T/H三图分离 /支撑：P03外显思维图建模、P14卡点检测、P16H图匹配四元组
- **与检索机制的关系**：定义检索的"查询"——不是静态的题目文本，而是动态累积的复合状态。检索的输入是Q_t，包含当前推理轨迹T_{0:t}、工具证据E_{0:t}和未决子目标U_t，这是状态感知层的核心数据结构。

### 原语：角色隔离矩阵
- **ID**：122v3-P05
- **类型**：结构原语
- **描述**：将实验/运行角色分离为六个互斥角色：Truth Curator（持有答案，不写提示）、Runner（只见题面和Hint）、Trace Modeler（建模A/B过程，不决定结论）、Hint Designer（只见候选卡点模式和Hint级别约束，不见答案）、Auditor（只见冻结输出和ground truth）、Orchestrator（运行manifest，不修改冻结输入）。
- **溯源**：122-v3-2026-08-05-完整机制复核与费马极限案例.md, 第319-332行, 原文引用："| Truth Curator | 正确答案、完整证明、评分基准 | 不写实验组提示，不生成答题输出 | | Runner | 题面和被分配的Hint | 看不到答案和其他组输出 | | Trace Modeler | A/B外显过程 | 不决定成功结论，不向Runner追加答案 | | Hint Designer | 候选卡点模式、Hint级别约束 | 不看最终答案文本，不能使用Hint-3/4 | | Auditor | 冻结后的输出和ground truth | 不参与提示设计和答题 | | Orchestrator | 运行manifest、随机化、证据归档 | 不修改冻结输入，不补写组别输出 |"
- **依赖关系**：依赖：P04提示梯度 /支撑：P06答案泄漏机制、P38知识悖论隔离机制
- **与检索机制的关系**：直接破解知识悖论的架构原语。角色隔离确保"知道答案的人"不参与Pattern选择和提示生成——Hint Designer只看候选卡点模式和Hint级别约束，不看最终答案。这正是253号第三层"引入第三个角色——专门做Pattern匹配的组件"的实现方案。

### 原语：MathLib逻辑依赖≠思维依赖
- **ID**：122v3-P50
- **类型**：概念框架
- **描述**：MathLib的逻辑依赖关系不等于思维依赖关系——数学上A依赖B，不意味着思维上必须先想到B才能想到A。检索系统不能直接用MathLib的依赖图作为Pattern的触发条件。
- **溯源**：122-v3-2026-08-05-完整机制复核与费马极限案例.md, 第81行, 原文引用："明确MathLib逻辑依赖不等于思维依赖；工具层只是规划"
- **依赖关系**：依赖：无 /支撑：P01K/T/H三图分离
- **与检索机制的关系**：定义检索系统的一个重要约束——K图（知识图）中的依赖关系不能直接用作H图（启发图）的触发关系。逻辑依赖是"什么数学关系成立"，思维依赖是"什么时候该想到什么"。检索系统匹配的是后者，不是前者。

### 原语：成功题解不是失败轨迹
- **ID**：122v3-P51
- **类型**：概念框架
- **描述**：成功题解的路径不包含失败轨迹——题库只记录成功路径，不记录"在哪里卡住、为什么卡住、什么提示帮助越过卡点"。因此题库不能直接作为Pattern来源。
- **溯源**：122-v3-2026-08-05-完整机制复核与费马极限案例.md, 第82行, 原文引用："题库不覆盖研究方向判断和大型证明组织；成功题解不是失败轨迹"
- **依赖关系**：依赖：无 /支撑：P08从相关差异到因果干预
- **与检索机制的关系**：定义Pattern的数据来源约束——Pattern必须从失败轨迹中提取（A失败+B成功对比），不能只从成功题解中提取。因为成功题解不包含"卡点-提示"关系，只有"步骤-步骤"关系。检索系统需要的Pattern是"卡点→提示"映射，不是"步骤→步骤"映射。

### 原语：距离近不等于因果相同
- **ID**：122v3-P52
- **类型**：性质标准
- **描述**：思维图形状距离近不等于需要的Pattern因果相同——两个推理在结构上相似，不代表它们需要的提示相同。这是嵌入向量检索方法的根本局限。
- **溯源**：122-v3-2026-08-05-完整机制复核与费马极限案例.md, 第373行, 原文引用："| 计算几何/嵌入 | 近似比较思维图形状、聚类卡点、检索相似轨迹 | 距离近不等于因果相同 |"
- **依赖关系**：依赖：P27思维图形状近似比较 /支撑：P20效果度量标准
- **与检索机制的关系**：定义检索系统匹配算法的关键约束——嵌入向量相似性（距离近）是检索的必要条件但非充分条件。检索结果需要额外的因果验证（这个Pattern是否真的能让当前状态向前一步）。这要求检索系统在"相似度排序"之上增加"因果有效性"过滤。

## 备注

1. 122-v3是检索机制的架构级原语来源——它提供了检索系统的整体框架（K/T/H三图、动态状态、角色隔离）但未提供具体实现（匹配算法、索引结构、状态表示的具体方案）。
2. 122-v3的核心贡献是明确了检索系统的目标状态（反应式救援、最小Hint、因果验证）和约束条件（角色隔离、知识分层、答案泄漏防范）。
3. 122-v3的费马极限案例提供了多种Pattern类型的实例（辅助对象构造、夹击矛盾、跨领域映射、局部-全局、降层到空空间、加强命题建立桥梁），这些是Pattern内容分类的原语来源。
4. 122-v3明确指出了当前系统的能力边界：经典计算只保证忠实展开，不自动发现P→X；当前矫正只保证保真覆盖，不在线识别思维缺口。这定义了检索系统需要突破的具体边界。
