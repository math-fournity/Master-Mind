# 原语提取：224-AI数学工程的第一性原理框架

## 文档概述

本文档从第一性原理出发，提出了一个统一的AI数学工程框架——问题空间纤维化。框架的核心是：问题空间P配备拓扑τ（"相似性"拓扑），每个问题p对应一个纤维F_p（所有可能解题路径），AI近似拓扑做导航（感知/模糊），经典计算在纤维内做验证/约束（精确/可形式化），两者在解题路径的每一步上交织。文档将非特定性、思维拓扑化、启发式、模式识别、形式化/非形式化分工等之前所有要点统一到这一个数学结构中。与检索机制的关系极为核心：拓扑τ的开集结构就是Pattern的组织方式，拓扑定位就是检索查询，开集归属判断就是匹配算法，纤维中的路径导航就是检索后的策略选择，死路标记就是负反馈索引。

## 提取的原语

### 原语：策略连续性——相似问题共享策略
- **ID**：224-P1
- **类型**：概念框架
- **描述**：如果策略s对问题p有效，那么s对"类似于p"的问题也有效；策略不是针对特定问题的，而是针对一类问题的。
- **溯源**：224, 第48-50行, 原文引用："如果策略s对问题p有效，那么s对'类似于p'的问题也有效。这不是偶然。这是数学思维的本质特征。策略不是针对特定问题的，而是针对**一类问题**的。"
- **依赖关系**：
  - 依赖：无
  - 支撑：224-P2（问题空间拓扑）、224-P3（拓扑连续映射）
- **与检索机制的关系**：这是检索机制的根本前提——如果策略不连续（不覆盖一类问题），那么从认知图中检索Pattern就没有意义。策略连续性保证了"检索到的Pattern可以被复用到相似问题"，是检索结果可复用性的理论基础。

### 原语：问题空间拓扑τ——相似性定义拓扑
- **ID**：224-P2
- **类型**：结构原语
- **描述**：问题空间P上有一个拓扑τ，"p₁和p₂在同一个邻域内"意味着"对p₁有效的策略大概率对p₂也有效"，策略是拓扑τ上的连续映射。
- **溯源**：224, 第54-58行, 原文引用："问题空间P上有一个拓扑τ / 'p₁和p₂在同一个邻域内'意味着'对p₁有效的策略大概率对p₂也有效' / 策略是拓扑τ上的**连续映射**——在邻域内保持有效"
- **依赖关系**：
  - 依赖：224-P1（策略连续性）
  - 支撑：224-P4（商拓扑开集结构）、224-P5（拓扑连通性）、224-P6（拓扑近似）
- **与检索机制的关系**：这是检索机制的核心数据结构——认知图/依赖图的组织方式应该反映拓扑τ的结构。检索不是按关键词匹配，而是按拓扑邻域匹配——找到问题p所在的邻域，返回该邻域对应的Pattern。

### 原语：非特定性=拓扑连续性的推论
- **ID**：224-P3
- **类型**：概念框架
- **描述**：非特定性不是设计目标，而是拓扑τ上连续性的自然推论——策略在开集上连续有效，所以自动覆盖一类问题。
- **溯源**：224, 第60行, 原文引用："非特定性不是设计目标，而是这个拓扑的自然推论。一个策略非特定，是因为它在一个邻域内连续有效，而不是因为它被刻意设计成'不指向特定答案'。"
- **依赖关系**：
  - 依赖：224-P2（问题空间拓扑）
  - 支撑：224-P12（非特定性=连续性定理）
- **与检索机制的关系**：检索机制返回的Pattern应该是非特定的（覆盖一类问题），而不是特定的（只针对一个问题）。这个原语告诉我们：非特定性不需要刻意设计，只要Pattern在拓扑τ的开集上连续有效，它就自动是非特定的。这指导了Pattern的存储粒度——按开集存储，不按单点存储。

### 原语：拓扑不可形式化但可被AI近似
- **ID**：224-P4
- **类型**：性质标准
- **描述**：问题空间的拓扑τ（"什么问题相似"）是不可形式化的，依赖海量数学经验积累；但AI通过训练数据获得了对τ的隐式感知，能做模糊模式匹配来近似拓扑。
- **溯源**：224, 第63-68行, 原文引用："问题空间的拓扑τ——'什么问题相似'——是不可形式化的……但AI见过海量问题。AI能做**模糊模式匹配**——判断'这个问题像那类问题'。这不是精确的拓扑计算，而是对拓扑的**近似**。"
- **依赖关系**：
  - 依赖：224-P2（问题空间拓扑）
  - 支撑：224-P6（AI作为τ的近似器）
- **与检索机制的关系**：这定义了检索机制的匹配算法性质——检索不是精确的图查询，而是AI驱动的模糊拓扑近似。检索引擎不需要精确计算拓扑，而是利用AI的隐式感知能力判断"问题p属于哪些开集"。这决定了检索机制应该以AI为匹配核心，而非以精确规则为匹配核心。

### 原语：验证可形式化——四种验证手段
- **ID**：224-P5
- **类型**：操作原语
- **描述**：给定策略和问题，执行结果是否合法是可形式化的，包括四种验证：形式化验证（证明步骤合法性）、约束求解（约束是否满足）、类型检查（类型是否匹配）、知识库查询（引用的定理是否存在）。
- **溯源**：224, 第72-79行, 原文引用："给定一个策略和一个问题，策略在这个问题上执行的结果是否合法——这是可形式化的。- 证明步骤是否合法？→ 形式化验证 / - 约束是否满足？→ 约束求解 / - 类型是否匹配？→ 类型检查 / - 引用的定理是否存在？→ 知识库查询"
- **依赖关系**：
  - 依赖：无
  - 支撑：224-P10（经典计算验证者角色）、224-P11（合法性检查约束函数）
- **与检索机制的关系**：知识库查询本身就是一种检索——验证"引用的定理是否存在"需要从知识库中检索定理。这四种验证手段构成了检索结果使用后的验证闭环：检索到Pattern → 应用Pattern → 验证应用结果是否合法。

### 原语：问题空间纤维化——基空间+纤维+投影
- **ID**：224-P6
- **类型**：结构原语
- **描述**：整个框架的核心结构是问题空间上的纤维化：基空间P（所有问题+拓扑τ）、纤维F_p（问题p的所有解题路径）、投影π（从解题路径映射回它解决的问题）。
- **溯源**：224, 第87-95行, 原文引用："基空间P：所有数学问题的空间，配备拓扑τ（'相似性'拓扑）/ 纤维F_p：问题p的所有可能解题路径——包括所有可能的换基、所有可能的策略、所有可能的证明路径 / 投影π：从解题路径映射回它解决的问题"
- **依赖关系**：
  - 依赖：224-P2（问题空间拓扑）
  - 支撑：224-P7（AI感知者角色）、224-P8（经典计算验证者角色）、224-P9（动力学循环）
- **与检索机制的关系**：这是检索机制的全局架构原语——检索在基空间P上进行（拓扑定位找Pattern），检索结果在纤维F_p中使用（选择策略、导航路径），投影π保证检索结果可以追溯回它解决的问题类型。纤维化结构定义了检索的"查询空间"（基空间）和"结果使用空间"（纤维）的分离。

### 原语：AI感知者角色——四项职能
- **ID**：224-P7
- **类型**：结构原语
- **描述**：AI在框架中做四件事：拓扑近似（判断问题p在τ中的位置）、起点选择（在F_p中选择初始策略）、路径导航（遇到分叉时选择方向）、不自然感知（识别当前表示的结构不匹配）——全部是感知/模糊/不可形式化的。
- **溯源**：224, 第99-103行, 原文引用："AI（感知者）：近似拓扑τ——判断问题p在拓扑中的位置（'这个问题像哪类问题'）/ 选择纤维F_p中的起点——选择一个策略开始解题 / 在路径上导航——遇到分叉时选择方向 / 感知'不自然'——识别当前路径上的结构不匹配"
- **依赖关系**：
  - 依赖：224-P6（纤维化结构）、224-P4（拓扑可被AI近似）
  - 支撑：224-P9（动力学循环）
- **与检索机制的关系**：AI感知者的第一项职能"拓扑近似"就是检索查询的生成——AI判断"问题p在τ中的位置"等价于"生成检索查询，找到p所属的开集"。第二项职能"起点选择"就是检索结果的选择——从检索到的多个Pattern中选择一个作为起点。这定义了检索机制中查询生成和结果排序的角色接口。

### 原语：经典计算验证者角色——四项职能
- **ID**：224-P8
- **类型**：结构原语
- **描述**：经典计算在框架中做四件事：合法性检查（当前步骤是否有效）、终点验证（是否到达"已证明"）、路径记录（哪些步骤走了哪些没走）、提供约束（哪些路径是死路）——全部是精确/可形式化/可重复的。
- **溯源**：224, 第105-109行, 原文引用："经典计算（验证者）：检查路径合法性——当前步骤是否有效？ / 检查路径终点——是否到达了'已证明'？ / 记录路径——哪些步骤走了，哪些没走 / 提供约束——哪些路径是死路（已验证不可行）"
- **依赖关系**：
  - 依赖：224-P6（纤维化结构）、224-P5（验证可形式化）
  - 支撑：224-P9（动力学循环）、224-P11（死路标记障碍集）
- **与检索机制的关系**：经典计算的"路径记录"和"提供约束（死路标记）"是检索机制的负反馈数据来源——已验证不可行的路径应该被标记，使得后续检索可以排除这些死路。这定义了检索机制中"不可检索区"（死路集合）的维护角色。

### 原语：AI-经典计算交替动力学循环
- **ID**：224-P9
- **类型**：操作原语
- **描述**：解题过程是一个循环：AI感知问题位置→选择策略→走一步→经典计算验证→合法则继续/不合法则反馈给AI重新感知→重复直到到达"已证明"或"确认无法证明"。
- **溯源**：224, 第113-121行, 原文引用："循环：1. AI感知问题p在拓扑τ中的位置 → 选择策略s / 2. AI沿策略s走一步 → 产生中间状态m / 3. 经典计算验证m是否合法——合法 → 继续走——不合法 → 反馈给AI，AI重新感知或换策略 / 4. 重复2-3，直到到达'已证明'或'确认无法证明'"
- **依赖关系**：
  - 依赖：224-P7（AI感知者）、224-P8（经典计算验证者）
  - 支撑：224-P10（有机结合逐步交织）
- **与检索机制的关系**：这个循环中包含了检索的触发时机——每次"AI重新感知或换策略"时，都可能触发新的检索（重新查询拓扑τ中的位置，选择新的策略）。不合法时的反馈是检索的负反馈信号——当前检索的Pattern在该问题上验证失败，需要更新检索策略或标记该Pattern的适用边界。

### 原语：有机结合——每一步交织而非串行分工
- **ID**：224-P10
- **类型**：概念框架
- **描述**：AI和经典计算不是串行分工（一个做完交给另一个），而是在同一条路径的每一步上交织——每一步都有AI的感知和经典计算的验证。
- **溯源**：224, 第227-235行, 原文引用："AI选择方向 → 走一步 → 经典计算检查 → 合法则AI继续选择 → 走一步 → 经典计算检查 → ... 这不是'AI做完交给经典计算'或'经典计算做完交给AI'的串行分工。而是**每一步都有AI的感知和经典计算的验证**——两者在路径的每一点上交织。"
- **依赖关系**：
  - 依赖：224-P9（动力学循环）
  - 支撑：无
- **与检索机制的关系**：检索不是一次性操作，而是在解题过程的每一步上持续触发——每走一步都可能需要重新检索（感知新的中间状态在拓扑中的位置）。这定义了检索机制为"持续检索"而非"一次检索"——检索结果在每一步被验证，验证失败则触发重新检索。

### 原语：τ是商拓扑——按策略有效性分等价类
- **ID**：224-P11
- **类型**：结构原语
- **描述**：问题空间的拓扑τ不是度量拓扑（相似性不是距离），而是商拓扑——把问题按"哪些策略有效"分等价类，等价类构成拓扑的开集。
- **溯源**：224, 第137-141行, 原文引用："问题之间的'相似性'不是距离——没有自然的度量……τ更像是**商拓扑**——把问题按'哪些策略有效'分等价类，等价类构成拓扑的开集。"
- **依赖关系**：
  - 依赖：224-P2（问题空间拓扑）
  - 支撑：224-P12（开集定义）、224-P13（开集重叠与嵌套）
- **与检索机制的关系**：这定义了认知图中Pattern的组织方式——Pattern不是按表面相似性组织（度量），而是按"哪些策略有效"组织（商拓扑）。检索时不是计算距离，而是判断等价类归属。这指导了认知图的索引结构——按策略有效性建立索引，而非按表面特征建立索引。

### 原语：τ的开集定义——策略覆盖的问题集合
- **ID**：224-P12
- **类型**：结构原语
- **描述**：τ的一个开集U是这样一个集合：存在一个策略s，s对U中所有问题都有效。开集可以重叠（一个问题属于多个开集），开集可以嵌套（更具体的策略对应更小的开集）。
- **溯源**：224, 第145-151行, 原文引用："τ的一个开集U是这样的集合：存在一个策略s，s对U中所有问题都有效……开集可以重叠——一个问题可以属于多个开集（多个策略都有效）。开集可以嵌套——'可以因式分解的'是'可以换基的'的子集。"
- **依赖关系**：
  - 依赖：224-P11（商拓扑）
  - 支撑：224-P13（开集重叠嵌套）、224-P14（子模式=更小开集）
- **与检索机制的关系**：开集就是认知图中Pattern的存储单元——每个Pattern对应一个开集（它有效的问题集合）。检索就是判断问题p属于哪些开集。开集的重叠意味着一个问题可以检索到多个Pattern；开集的嵌套意味着检索结果有层次——从通用Pattern到具体Pattern。

### 原语：开集重叠与嵌套——多Pattern匹配与层次检索
- **ID**：224-P13
- **类型**：结构原语
- **描述**：开集可以重叠（一个问题属于多个开集，多个策略都有效），开集可以嵌套（"可以因式分解的"是"可以换基的"的子集），形成层次结构。
- **溯源**：224, 第151行, 原文引用："开集可以重叠——一个问题可以属于多个开集（多个策略都有效）。开集可以嵌套——'可以因式分解的'是'可以换基的'的子集。"
- **依赖关系**：
  - 依赖：224-P12（开集定义）
  - 支撑：224-P14（子模式=更小开集）
- **与检索机制的关系**：这定义了检索结果的多匹配和层次性——检索一个问题时，可能返回多个Pattern（开集重叠），且有层次关系（开集嵌套，从通用到具体）。检索机制需要支持多结果返回和层次化结果排序。

### 原语：τ的连通性——策略可跨问题迁移
- **ID**：224-P14
- **类型**：性质标准
- **描述**：问题空间P是连通的——任何两个问题之间都存在一条路径，沿这条路径策略连续变化，保证策略可以从已知问题迁移到未知问题。
- **溯源**：224, 第153-157行, 原文引用："问题空间P是连通的——任何两个问题之间都存在一条路径，沿这条路径策略连续变化……这个连通性很重要——它保证了策略可以从已知问题迁移到未知问题，只是迁移路径可能很长。"
- **依赖关系**：
  - 依赖：224-P2（问题空间拓扑）
  - 支撑：224-P15（跨领域类比=邻域关系）
- **与检索机制的关系**：这保证了检索机制即使面对从未见过的问题，也能找到相关的Pattern——通过连通性，从已知问题沿路径迁移到未知问题。这支持了检索的"泛化能力"——检索不是精确匹配，而是沿拓扑路径的近似迁移。

### 原语：τ可被持续近似——每解决一个问题近似更精确
- **ID**：224-P15
- **类型**：操作原语
- **描述**：τ的精确定义不可能（数学是开放的），但τ可以被近似：AI通过训练数据隐式学到τ的近似，每解决一个新问题对τ的近似更精确一点，近似永远不完整但足够好用。
- **溯源**：224, 第159-168行, 原文引用："τ可以被**近似**：AI通过海量训练数据，隐式学到了τ的近似 / 每解决一个新问题，对τ的近似更精确一点 / τ的近似永远不完整，但足够好用"
- **依赖关系**：
  - 依赖：224-P4（拓扑可被AI近似）
  - 支撑：无
- **与检索机制的关系**：这定义了检索机制的持续学习原语——每次解题后，检索索引（对τ的近似）应该被更新，使得下次检索更精确。检索机制不是静态的索引，而是随使用持续改进的动态索引。

### 原语：纤维F_p的路径空间——成功/失败/未终止三类路径
- **ID**：224-P16
- **类型**：结构原语
