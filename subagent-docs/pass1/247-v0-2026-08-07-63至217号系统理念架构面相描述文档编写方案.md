# 原语提取：247-v0-63至217号系统理念架构面相描述文档编写方案

## 文档概述

本文档是247号方案文档，描述如何为63-217号文档（基于稀疏矩阵想法的第一代系统）编写一份系统理念·架构·面相描述文档。文档本身是一个文档编写方案（Multi-Pass筛选+精读+编写），但其内容中蕴含了大量与检索机制相关的原语：稀疏矩阵/依赖图作为检索数据结构、图遍历产生判断的检索算法、Multi-Pass筛选的检索策略、并发检索、分类筛选标准、面相切分多视角检索、宁可多选不漏的召回策略等。虽然文档主体是"如何写文档"的元方案，但其描述的系统理念（稀疏矩阵、依赖图、图遍历）和其自身的Multi-Pass筛选方法论都可作为检索机制的原语。

## 提取的原语

### 原语：稀疏矩阵—图遍历产生判断
- **ID**：247-P1
- **类型**：概念框架
- **描述**：大师的"知道该判断什么"可以通过经典计算（图遍历）产生，而非依赖直觉——这是检索机制的根基性信念。
- **溯源**：247-v0, 第27行, 原文引用："起源（63号）：稀疏矩阵想法——大师的"知道该判断什么"可以通过经典计算（图遍历）产生"
- **依赖关系**：
  - 依赖：无（这是起源性原语）
  - 支撑：247-P2（依赖图）、247-P3（Multi-Pass筛选）
- **与检索机制的关系**：这是检索机制的根本信念——检索不需要模拟大师的直觉，而是可以通过图上的经典计算（遍历、匹配）来产生"该判断什么"的结论。检索机制的设计起点。

### 原语：依赖图作为知识组织与检索结构
- **ID**：247-P2
- **类型**：结构原语
- **描述**：依赖图作为知识的组织结构，节点间存在依赖关系，检索即在此图上进行遍历和匹配。
- **溯源**：247-v0, 第21行, 原文引用："那套基于最初的稀疏矩阵想法的系统"；第68行, 原文引用："核心隐喻的演化（稀疏矩阵→依赖图→提示生成器→数学大师→...）"；第71行, 原文引用："系统的组件结构（xishujuzhen系统、依赖图、ArangoDB、POC验证体系、数学大师系统组件等）"
- **依赖关系**：
  - 依赖：247-P1（稀疏矩阵—图遍历产生判断）
  - 支撑：247-P5（ArangoDB技术选型）、247-P9（面相切分多视角检索）
- **与检索机制的关系**：依赖图是检索机制的核心数据结构。Pattern存储在依赖图的节点中，节点间的依赖关系构成检索路径。检索机制在此图上执行遍历、匹配、路径查找等操作。

### 原语：核心隐喻演化链
- **ID**：247-P3
- **类型**：概念框架
- **描述**：系统的核心隐喻经历从"稀疏矩阵"→"依赖图"→"提示生成器"→"数学大师"的演化，每一阶段隐喻对应不同的检索结构理解。
- **溯源**：247-v0, 第68行, 原文引用："核心隐喻的演化（稀疏矩阵→依赖图→提示生成器→数学大师→...）"
- **依赖关系**：
  - 依赖：247-P1（稀疏矩阵）、247-P2（依赖图）
  - 支撑：无直接
- **与检索机制的关系**：隐喻演化链揭示了检索机制可以从不同抽象层次理解——从矩阵检索到图检索到提示生成到大师模拟。每个隐喻阶段对应检索机制的不同设计视角，帮助设计者在不同抽象层次上思考检索问题。

### 原语：Multi-Pass筛选检索策略
- **ID**：247-P4
- **类型**：操作原语
- **描述**：将检索过程分为多Pass——Pass 1粗筛（快速判断相关性，缩小搜索空间），Pass 2精读（对筛选出的候选项做深度信息提取），逐步精化检索结果。
- **溯源**：247-v0, 第112-117行, 原文引用："Multi-Pass的方法：- Pass 1（粗筛）：每个subagent读一个文档，判断它是否和"理念·架构·面相"有关。产出是一份文档列表。- Pass 2（精读）：对Pass 1筛选出的文档，每个subagent精读一个，提取和"理念·架构·面相"相关的具体信息。Pass 1后文档数量会大幅减少（预计从157个减少到30-50个），Pass 2的工作量可控。"
- **依赖关系**：
  - 依赖：247-P6（分类筛选标准）、247-P7（并发检索执行）
  - 支撑：247-P10（结构化返回格式）
- **与检索机制的关系**：这是检索机制的核心策略原语——先粗筛后精读的两阶段检索。在Pattern检索中，可以先快速扫描认知图节点判断粗略相关性，再对候选节点做深度匹配。降低检索的计算成本，提高效率。

### 原语：ArangoDB作为图数据库存储与检索基础设施
- **ID**：247-P5
- **类型**：结构原语
- **描述**：使用ArangoDB（图数据库）作为依赖图的存储后端，支持图遍历查询。
- **溯源**：247-v0, 第71行, 原文引用："系统的组件结构（xishujuzhen系统、依赖图、ArangoDB、POC验证体系、数学大师系统组件等）"；第145行, 原文引用："依赖图的存储方案、ArangoDB的技术选型"
- **依赖关系**：
  - 依赖：247-P2（依赖图作为知识组织结构）
  - 支撑：无直接
- **与检索机制的关系**：ArangoDB提供图遍历查询能力（AQL的图遍历语法），是检索机制的存储与查询基础设施。Pattern检索的底层执行依赖于此。

### 原语：分类筛选标准——三维分类
- **ID**：247-P6
- **类型**：操作原语
- **描述**：将检索目标分为三个维度（理念/架构/面相），每个候选项按这三个维度判断相关性，可多选归属。
- **溯源**：247-v0, 第139-149行, 原文引用："1. 理念（Philosophy）：系统的核心信念、设计哲学、根本想法…2. 架构设计（Architecture）：系统的结构设计、组件划分、模块关系、技术选型、数据流。3. 面相（Facets）：系统从不同角度的理解、系统的维度切分、如何看待这个系统。"
- **依赖关系**：
  - 依赖：无
  - 支撑：247-P4（Multi-Pass筛选）、247-P11（按类型分组结果）
- **与检索机制的关系**：为检索提供分类标签体系。Pattern检索时可以按维度过滤——只检索"理念类"Pattern或"架构类"Pattern。多维度分类也支持多面检索（同一Pattern可属于多个维度）。

### 原语：并发检索执行
- **ID**：247-P7
- **类型**：操作原语
- **描述**：将检索任务分批，每批多个subagent并发执行，每个subagent处理一个候选项，结果统一收集汇总。
- **溯源**：247-v0, 第119-126行, 原文引用："5个subagent并发执行。157个文档，每批5个，需要约32批。但subagent是background的，可以持续运行。Pass 1的执行方式：- 每批启动5个background subagent，每个读一个文档- 每个subagent的任务：读文档，判断相关性，返回结构化结果- 所有批次完成后，汇总结果"
- **依赖关系**：
  - 依赖：247-P4（Multi-Pass筛选）
  - 支撑：247-P10（结构化返回格式）
- **与检索机制的关系**：并行检索策略——当检索空间大时，将候选集分片，多个检索器并发执行，最后合并结果。提高检索吞吐量。

### 原语：边界判断规则——正反例+灰色地带
- **ID**：247-P8
- **类型**：操作原语
- **描述**：为相关性判断提供明确正例（大概率选中）、反例（大概率排除）和灰色地带（需个案判断）三类规则，降低判断不一致性。
- **溯源**：247-v0, 第163-184行, 原文引用："明确相关的文档类型（大概率Pass 1选中）…明确不相关的文档类型（大概率Pass 1排除）…需要subagent判断的灰色地带"
- **依赖关系**：
  - 依赖：247-P6（分类筛选标准）
  - 支撑：247-P12（宁可多选不漏的召回策略）
- **与检索机制的关系**：为检索的相关性判断提供分层规则——硬性正例规则、硬性反例规则、软性灰色地带规则。对应检索机制中的精确匹配、精确排除和模糊匹配三层过滤逻辑。

### 原语：面相切分——多视角检索
- **ID**：247-P9
- **类型**：概念框架
- **描述**：系统可以从不同角度（面相）理解——作为提示生成器、作为大师形式化、作为依赖图导航、作为POC验证系统等，不同面相对应不同的检索视角。
- **溯源**：247-v0, 第76-78行, 原文引用："系统从不同角度看到的样子（作为提示生成器、作为大师形式化、作为依赖图导航、作为POC验证系统、作为数学大师系统等）- 面相之间的关系与演化"
- **依赖关系**：
  - 依赖：247-P2（依赖图）、247-P3（核心隐喻演化链）
  - 支撑：247-P6（分类筛选标准）
- **与检索机制的关系**：面相是检索的多视角维度——同一Pattern从不同面相看可能具有不同的相关性。检索机制可以支持按面相过滤或加权，实现多视角检索。

### 原语：结构化返回格式
- **ID**：247-P10
- **类型**：结构原语
- **描述**：检索结果以结构化格式返回——包含编号、标题、是否相关、相关类型、内容摘要、关键段落定位等字段。
- **溯源**：247-v0, 第154-161行, 原文引用："请返回以下结构化结果：- 文档编号：{编号}- 文档标题：{标题}- 是否相关：是/否- 相关类型（如相关）：理念/架构/面相（可多选）- 相关内容摘要（如相关）：用2-3句话概括…- 关键段落定位（如相关）：列出文档中最相关的章节标题或行号范围"
- **依赖关系**：
  - 依赖：247-P6（分类筛选标准）
  - 支撑：247-P11（按类型分组结果）
- **与检索机制的关系**：定义检索结果的输出schema。Pattern检索的结果应包含：Pattern ID、标题、相关性判定、类型标签、内容摘要、源定位。结构化结果便于下游消费和二次检索。

### 原语：按相关类型分组结果
- **ID**：247-P11
- **类型**：操作原语
- **描述**：检索完成后，将结果按相关类型（理念类、架构类、面相类）分组呈现，一个候选项可属于多组。
- **溯源**：247-v0, 第192行, 原文引用："按相关类型的分组：理念类、架构类、面相类（一个文档可能属于多类）"
- **依赖关系**：
  - 依赖：247-P6（分类筛选标准）、247-P10（结构化返回格式）
  - 支撑：无直接
- **与检索机制的关系**：检索结果的后处理组织策略——按类型分组便于下游按需取用。Pattern检索结果可以按Pattern类型分组，让消费者只取所需类型的Pattern。

### 原语：宁可多选不漏——高召回率优先策略
- **ID**：247-P12
- **类型**：操作原语
- **描述**：在粗筛阶段偏宽松——只要候选项中有实质性相关内容就选入下一阶段，即使同时包含大量无关内容。优先保证召回率，精度由后续阶段保证。
- **溯源**：247-v0, 第247行, 原文引用："宁可多选不漏。Pass 1的筛选标准偏宽松——只要文档中有实质性的理念/架构/面相讨论就选入Pass 2，即使它同时包含大量工程细节。"
- **依赖关系**：
  - 依赖：247-P4（Multi-Pass筛选）、247-P8（边界判断规则）
  - 支撑：无直接
- **与检索机制的关系**：检索机制中召回率与精度的权衡决策——在粗筛阶段优先召回率（不漏），在精读阶段优先精度（不误选）。这是Multi-Pass检索策略的内在设计原则。

- **ID**：247-P13

- **与检索机制的关系**：为检索机制提供架构描述框架——检索系统也由组件（索引器、匹配器、排序器、结果格式化器）、组件关系、数据流（查询→索引→匹配→排序→返回）构成。

### 原语：演化路径作为检索线索
- **ID**：247-P14
- **类型**：概念框架
- **描述**：系统经历从起源→POC验证→项目化→架构设计→实现→审计→问题发现→过渡的演化路径，每个阶段对应不同的知识形态，可作为检索的时间维度线索。

  - 支撑：无直接

### 原语：复原而非摘要——检索结果呈现原则
- **ID**：247-P15
- **类型**：操作原语
- **描述**：检索结果的呈现不是简单摘要，而是复原——让消费者读完结果就能完整理解原始内容的全貌，需要包含背景、核心观念逐个阐述、结构化呈现、演化路径、验证记录、暴露的问题。
- **溯源**：247-v0, 第51-58行, 原文引用："不是摘要，是复原——让一个没读过原始文档的人，读完这一份就能完整理解那套系统的全貌- 有背景与起点- 有核心观念/柱子/奠基性观念的逐个阐述- 有架构设计的结构化呈现- 有演化路径- 有实验验证的记录- 有暴露的问题/危机"
- **依赖关系**：
  - 依赖：247-P10（结构化返回格式）
  - 支撑：无直接
- **与检索机制的关系**：定义检索结果的质量标准——检索返回的Pattern不应是干瘪的摘要，而应是足够自包含的复原，让消费者无需回溯原始来源即可理解和使用。

### 原语：筛选标准不一致的风险与应对——正反例校准
- **ID**：247-P16
- **类型**：操作原语
- **描述**：多个检索器（subagent）对相关性的判断标准可能不一致，应对方法是在指令中给出明确的判断标准和正反例，完成后人工抽查修正。
- **溯源**：247-v0, 第238-241行, 原文引用："不同subagent对"相关"的判断标准可能不一致。应对：在指令模板中给出明确的判断标准和正反例。Pass 1完成后人工抽查部分结果，对不一致的判断进行修正。"
- **依赖关系**：
  - 依赖：247-P8（边界判断规则）
  - 支撑：无直接
- **与检索机制的关系**：检索机制中多检索器一致性问题——当多个检索器并发执行时，需要通过明确的匹配规则+正反例校准来保证判断一致性，并通过事后抽查修正偏差。

### 原语：灰色地带误判风险与宽松策略
- **ID**：247-P17
- **类型**：操作原语
- **描述**：部分候选项既有相关内容又有无关内容，检索器可能误判，应对策略是宁可多选不漏——宽松筛选标准保证不遗漏。
- **溯源**：247-v0, 第243-247行, 原文引用："部分文档可能既有理念内容又有工程细节，subagent可能误判。应对：宁可多选不漏。Pass 1的筛选标准偏宽松——只要文档中有实质性的理念/架构/面相讨论就选入Pass 2，即使它同时包含大量工程细节。"
- **依赖关系**：
  - 依赖：247-P8（边界判断规则）、247-P12（宁可多选不漏）
  - 支撑：无直接
- **与检索机制的关系**：检索机制中模糊匹配的风险管理——当候选项具有混合特征时，采用宽松策略（优先召回）避免遗漏，将精度问题留给后续精筛阶段。
