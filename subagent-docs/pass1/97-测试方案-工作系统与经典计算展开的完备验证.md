# 原语提取：97-测试方案·工作系统与经典计算展开的完备验证

## 文档概述

本文档是针对91号方案（cognition基座）和92号方案（topo_generator）的完备测试方案，包含T1-T15共15个测试项，分6层验证工作系统与经典计算展开的正确性。文档虽然以测试验证为主题，但其测试对象本身就是一套认知图检索系统——从种子选择、图遍历、覆盖验证、版本链管理到有效性评估，完整描述了检索机制的各个构造环节。因此本文档是检索机制原语的重要来源，测试方案中隐含的设计决策和数据结构即为可复用的原语。

## 提取的原语

### 原语：种子驱动的图遍历检索
- **ID**：97-P1
- **类型**：操作原语
- **描述**：从一组种子认知单元出发，沿depends_on边进行AQL图遍历，按深度展开找到所有前置依赖认知单元，作为检索结果返回。
- **溯源**：97, 第158-201行, 原文引用："从'七步骤工作流'种子出发，遍历depth=5……找到前置认知：dependency_graph_prompt, topology_coverage, arangodb_infra, topology_verifier, spiral_cognition, three_layer_extraction等……遍历结果按depth排序，种子depth=0，直接依赖depth=1，间接依赖depth=2..."
- **依赖关系**：
  - 依赖：97-P2（索引结构）、97-P3（depends_on边）
  - 支撑：97-P4（覆盖验证）、97-P14（A/B对照）
- **与检索机制的关系**：这是检索机制的核心操作——给定查询（种子），通过图遍历返回相关Pattern集合。depth参数控制检索范围，depth排序提供结果优先级。

- **依赖关系**：
  - 依赖：无

- **与检索机制的关系**：索引是检索效率的基础。cog_id唯一索引保证精确查找；category/status索引支撑过滤式检索；edge_type索引支撑按边类型遍历；version_order索引支撑版本排序检索。

### 原语：A/B对照实验与认知覆盖率指标
- **ID**：97-P14
- **类型**：性质标准
- **描述**：用A/B对照实验验证检索有效性——A组不使用检索系统，B组使用；用人工标注的ground truth计算认知覆盖率D1 = (找到的ground truth数 / ground truth总数) × 100%，边际增益 = D1(B) - D1(A)。
- **溯源**：97, 第745-786行, 原文引用："用对照实验证明工作系统真的提升了AI的认知覆盖率……人工标注ground truth：对于'设计POC-3验证方案'这个任务，标注15个高度相关认知单元 + 5个中等相关认知单元……D1认知覆盖率 = (找到的ground truth数 / ground truth总数) × 100%……边际增益 = D1(B) - D1(A)……B组覆盖率 ≥ 80%……A组覆盖率 < B组覆盖率"
- **依赖关系**：
  - 依赖：97-P1（图遍历检索）、97-P4（覆盖验证）
  - 支撑：无直接
- **与检索机制的关系**：这是检索机制有效性评估的原语——检索系统不能只验证"能跑"，必须验证"比没有检索系统更好"。ground truth + 覆盖率 + 对照实验是检索评估的标准方法论。
