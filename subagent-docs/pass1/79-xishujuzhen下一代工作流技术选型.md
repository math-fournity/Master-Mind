# 原语提取：79-xishujuzhen下一代工作流技术选型

## 文档概述

本文档是数学大师系统下一代工作流的数据库架构技术选型文档，分析了超大规模知识体系（数千~数万节点、数万~数十万边的依赖图）的存储与查询需求，对比了6种图数据库/文档数据库/稀疏矩阵数据库方案，最终推荐ArangoDB多模型单数据库方案。文档详细设计了数据模型（Collections结构）、拓扑覆盖验证代码、工作流与数据库的7步整合流程、稀疏矩阵运算接口，以及实施路径和兼容性分析。与检索机制的关系极为密切——文档直接定义了图的存储结构、查询语言、遍历操作、覆盖验证算法、矩阵运算接口，这些都是检索机制的基础设施。

- **溯源**：79, 第499-515行, 原文引用："def build_adjacency_matrix(self): '''从ArangoDB图构建稀疏邻接矩阵''' nodes = list(self.db.collection(f'{self.graph_name}_nodes').all()) node_ids = [n['_id'] for n in nodes] id_to_idx = {nid: i for i, nid in enumerate(node_ids)} edges = list(self.db.collection(f'{self.graph_name}_edges').all()) rows = [id_to_idx[e['_from']] for e in edges] cols = [id_to_idx[e['_to']] for e in edges] data = [1] * len(edges) return sp.coo_matrix((data, (rows, cols)), shape=(n, n)).tocsr()"
- **依赖关系**：

### 原语：传递闭包计算（可达性矩阵）
- **ID**：79-P10
- **类型**：操作原语
- **描述**：用Warshall算法或矩阵幂迭代计算图的传递闭包（可达性矩阵），每次迭代做矩阵乘法并二值化，得到全图的可达关系。
- **溯源**：79, 第517-526行, 原文引用："def transitive_closure(self): '''计算传递闭包（可达性矩阵）''' adj = self.build_adjacency_matrix() n = adj.shape[0] closure = adj.copy() for k in range(n): closure = closure + closure @ adj closure.data[:] = 1  # 二值化 return closure"
- **依赖关系**：
  - 依赖：稀疏邻接矩阵构建（79-P9）
  - 支撑：全局可达性检索
- **与检索机制的关系**：传递闭包是一次性计算后可反复查询的全局可达性索引。检索机制可以用它快速回答"Pattern A是否（间接）依赖Pattern B"而无需实时遍历。对于大规模图，传递闭包矩阵可以作为预计算的检索索引。

### 原语：可达性检查（单源-单目标）
- **ID**：79-P11

- **描述**：检查从源节点到目标节点是否可达，通过迭代矩阵乘法逐步扩展可达范围，直到找到目标或遍历完所有节点。

- **依赖关系**：
