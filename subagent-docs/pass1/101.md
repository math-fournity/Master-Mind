# 原语提取：101-UserPromptSubmit提醒机制方案

## 文档概述

101号文档描述了数学项目的UserPromptSubmit提醒机制——每次用户提问时，通过hook自动将提醒内容注入AI上下文，引导AI考虑是否需要进入工作系统（加载认知种子、执行七步骤工作流）。该方案模仿星学项目97号文档的三轮迭代最终方案（v3：纯提醒，无硬门禁），并适配数学项目的独有特点（种子推荐表、七步骤工作流、数学意识节点）。

文档共98行，包含五个部分：星学项目方案要点、数学项目差异分析、方案设计（新增文件/修改文件/提醒内容/hook脚本/hooks配置）、Check List、诚实面对。

该文档虽然是一个工程实现方案，但其核心设计决策——事件触发、内容外置、软干预、角色豁免、类型路由、索引选择、分层内容——与253号文档定义的稀疏矩阵Pattern检索问题（状态感知→Pattern提取→知识悖论三层结构）有丰富的结构性对应关系。以下提取所有可能作为检索机制原语的思想片段。

## 提取的原语

### 原语：事件触发式上下文注入
- **ID**：101-P1
- **类型**：操作原语
- **描述**：每次特定事件发生时（用户提问），自动从外部文件读取内容并注入到AI的上下文中，无需AI主动请求。
- **溯源**：101-UserPromptSubmit提醒机制方案.md, 第9行, 原文引用："**UserPromptSubmit hook**：每次用户提问时，从`UserPromptSubmit.txt`文件读取提醒内容，注入到AI上下文"
- **依赖关系**：依赖：外部文件存储（101-P2）；支撑：状态触发式检索启动（101-P24）
- **与检索机制的关系**：直接相关。253号检索问题的起点是"工作智能体停在某个状态"——这本身就是一个事件。事件触发式注入机制可以作为检索流程的启动原语：当工作智能体输出一段推理后停止，触发检索系统从Pattern存储中读取候选Pattern并注入到助理智能体的上下文中。这与253号3.2.3节"检索的输入和输出"中描述的流程结构一致——输入是工作智能体的当前状态，输出是候选Pattern。

### 原语：内容-机制分离（外置存储）
- **ID**：101-P2
- **类型**：结构原语
- **描述**：将动态内容存储在外部文件中，与执行机制解耦；修改内容只需编辑文件，不需改动代码。
- **溯源**：101-UserPromptSubmit提醒机制方案.md, 第10行, 原文引用："**提醒内容外置到txt文件**：改提醒内容只需编辑txt文件，不用改代码"
- **依赖关系**：支撑：事件触发式上下文注入（101-P1）、内容演化（101-P20）
- **与检索机制的关系**：直接相关。253号文档中Pattern存储在稀疏矩阵（ArangoDB图数据库）中，与检索机制本身分离。内容-机制分离意味着Pattern的增删改不影响检索代码的运行——Pattern库可以独立演化，检索机制作为独立组件读取Pattern存储。这对应253号1.5节描述的"Pattern以某种形式存储在稀疏矩阵中"与检索系统的关系。

### 原语：软干预（无硬门禁）
- **ID**：101-P3
- **类型**：概念框架
- **描述**：系统只提供提示/建议，不强制执行；接收方自行判断是否采纳，干预是"软"的而非"硬"的。
- **溯源**：101-UserPromptSubmit提醒机制方案.md, 第11行, 原文引用："**核心信念**：提示就够了，不需要硬门禁。AI看到提醒后自行判断是否需要进入工作系统"
- **依赖关系**：支撑：非强制设计选择（101-P19）、AI自主判断（101-P21）
- **与检索机制的关系**：直接相关，关联253号第三层知识悖论。253号3.3节第三层提出：助理智能体收到候选Pattern后需要判断"哪个最匹配"——这是一个需要知识的判断。软干预框架提供了一种破解思路：检索系统不需要强制助理智能体发送某个特定Q，而是提供候选Pattern（提示），助理智能体自行判断。如果助理智能体的判断能力不足，可以进一步退化为"把候选都展示给工作智能体"（253号3.3节第三层列出的方向之一）。软干预是"提示而非控制"的设计哲学，与燧人系统"钻木取火"理念一脉相承。

## 文档与检索机制的关系

101号文档虽然是一个工程实现方案（UserPromptSubmit hook机制），但其设计决策与253号文档定义的稀疏矩阵Pattern检索问题有深层的结构性对应关系。以下从253号检索问题的三层结构出发，分析101号文档原语的支撑关系：

### 对第一层（状态感知）的支撑

101号文档中**输入类型分类**（101-P11）、**AI自主分类判断**（101-P21）、**思维模式分类体系**（101-P9）三个原语直接支撑状态感知层。

253号第一层的核心问题是"助理智能体怎么'看到'工作智能体需要什么"。101号文档的实践表明：AI可以自行判断输入的类型（"是否是数学问题"），这种判断不依赖硬编码规则，而是依赖AI的模式识别能力。这为253号第一层提供了一种可行路径：让助理智能体自行识别工作智能体的状态类型（如"需要知识注入"vs"需要思维模式提示"），作为状态感知的第一步。

**思维模式分类体系**（5个数学意识节点）提供了状态分类的骨架——253号2.2节证明路径表中每一步的"思维模式成分"标签（归一化、恒等式挖掘、投影分解等）可以作为状态感知的分类维度。

### 对第二层（Pattern提取）的支撑

101号文档中**类型-种子映射表**（101-P7）、**认知图索引**（101-P10）、**索引选择式种子加载**（101-P12）、**条件工作流分支**（101-P13）、**执行超时约束**（101-P17）五个原语直接支撑Pattern提取层。

253号第二层的核心问题是"怎么从海量存储中快速定位到相关Pattern"。101号文档已经实现了一套从索引中快速定位认知种子的机制：AGENTS.md认知图索引提供导航入口 → 种子推荐表提供类型→种子的映射 → 认知检查点命令按种子ID执行加载。这套"索引→映射→加载"的流程可以直接迁移到Pattern检索：Pattern索引提供导航入口 → 类型→Pattern映射提供快速定位 → 检索命令按Pattern ID执行提取。

**执行超时约束**（5秒timeout）直接对应253号3.4节约束1"提取必须在合理时间内完成"，排除了全量扫描方案。
