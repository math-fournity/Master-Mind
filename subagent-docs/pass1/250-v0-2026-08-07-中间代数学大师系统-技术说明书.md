# 原语提取：250-v0-中间代数学大师系统——技术说明书

## 文档概述

本文档是中间代（女娲代）数学大师系统的完整技术说明书，覆盖122-v1/v2/v3、123-v1、127-v1、178-v1、200-v0/201-v0/202-v0共9份源文档。文档系统呈现了中间代的理念层（从硬公理到可证伪假设）、核心概念（K/T/H三图、动态工作区、事件结构、义务超图、启发规则生命周期）、架构设计（九条公理、12步在线主链、Hint梯度+泄漏审计）、实现层（Schema冻结、角色隔离）、运行时基础设施（全程监控）和危机诊断。与检索机制高度相关——K/T/H三图模型定义了检索的数据源和匹配目标，P→X图改写规则定义了检索的匹配模式，启发规则生命周期定义了检索的准入控制，角色隔离定义了检索的权限边界，种子定位与依赖子图提取是检索的核心操作。

## 提取的原语

### 原语：K/T/H三图分离模型
- **ID**：250-P1
- **类型**：结构原语
- **描述**：将数学知识分为三种独立的图——K图（数学知识图，客观依赖关系）、T图（外显思维图，一次运行的事件轨迹）、H图（启发激活图，条件化干预策略），三者不可混为一张图。
- **溯源**：250-v0, 第183-191行, 原文引用："122-v2的核心架构修正是：数学大师系统不只需要一张数学依赖图，而需要三种不同的图：1. 数学知识图K……2. 外显思维图T……3. 启发激活图H……三图不能混成一张：K中的边可以是客观依赖，T中的边是一次运行发生过的事件，H中的边是条件化干预策略。"
- **依赖关系**：
  - 依赖：无（ foundational ）
  - 支撑：250-P2（P→X图改写）、250-P6（种子定位+依赖子图提取）、250-P7（H图匹配T图模式→从K图选择激活包）
- **与检索机制的关系**：三图分离是检索机制的数据结构基础——检索的本质是"在T图中检测模式P→在H图中匹配规则→从K图中选择激活包X"。如果三类关系混在一张图里（如第一代的dg_edges），检索无法区分"知识依赖""解题轨迹"和"干预策略"，导致模式分裂。

### 原语：P→X带条件的图改写规则（LHS/Guard/RHS）
- **ID**：250-P2
- **类型**：结构原语
- **描述**：启发关系P→X不是普通边，而是带条件的图改写规则——LHS是当前思维图中应出现的局部子图（模式P），Guard是上下文/时序/模型/失败类型等条件，RHS是应加入的概念/子目标/操作/工具节点和连接（激活包X）。形式化为(L, guard) ⇒ R。
- **溯源**：250-v0, 第195-205行, 原文引用："122-v2把启发关系P→X从'普通边'精确化为'带条件的图改写规则'：LHS：当前思维图中应出现的局部子图；Guard：上下文、时序、模型、失败类型等条件；RHS：应加入的概念/子目标/操作/工具节点和连接。形式上：(L, guard) ⇒ R。"
- **依赖关系**：
  - 依赖：250-P1（K/T/H三图分离）
  - 支撑：250-P3（激活包）、250-P8（子图模式匹配+条件合取）、250-P10（启发规则生命周期）
- **与检索机制的关系**：这是检索机制的核心匹配单元——检索不是"查关键词"，而是"在当前思维图T_t中匹配LHS子图模式P，检查Guard条件是否满足，返回RHS激活包X"。LHS/Guard/RHS三段式定义了检索的查询模式、过滤条件和返回结果。

### 原语：激活包（Activation Package）
- **ID**：250-P3
- **类型**：结构原语
- **描述**：P→X中的X不是单个答案节点，而是"激活包"——可以是概念、表示、操作、子目标、意识、工具、反例方向、跨领域类比等多种类型的集合。系统应优先提供能造成进展的最小提示。
- **溯源**：250-v0, 第210-222行, 原文引用："122-v2明确：X不应被限制为一个数学概念。它可以是：一个概念……一个表示……一个操作……一个子目标……一个意识……一个工具……一个反例方向……一个跨领域类比……因此推荐把右侧称为激活包，而不是答案节点。"
- **依赖关系**：
  - 依赖：250-P2（P→X图改写规则）
  - 支撑：250-P4（Hint梯度）
- **与检索机制的关系**：定义了检索的返回结果类型——检索返回的不是单一节点，而是一个结构化的激活包，包含多种类型的候选内容。检索机制需要支持异构结果的组装和打包。

### 原语：Hint梯度（Hint-0到Hint-4）
- **ID**：250-P4
- **类型**：操作原语
- **描述**：提示按泄漏风险分为5个级别——Hint-0只提示检查类型（很低泄漏）、Hint-1提示思维操作（低）、Hint-2提示候选工具/概念（中）、Hint-3提示确定关系（高）、Hint-4给出最终形式或答案（直接答案）。默认从Hint-0开始，无进展时逐级增加。
- **溯源**：250-v0, 第224-234行, 原文引用："122-v2提出了Hint梯度……默认策略应从Hint-0开始，只有没有进展时逐级增加。用于验证核心愿景的实验应默认限制在Hint-0至Hint-2。"
- **依赖关系**：
  - 依赖：250-P3（激活包）
  - 支撑：250-P5（四门泄漏审计）、250-P16（受约束多目标选择）
- **与检索机制的关系**：Hint梯度为检索结果提供了分级机制——检索到的激活包需要按Hint级别排序和过滤，检索机制应优先返回低泄漏级别的结果，只有在低级别无效时才升级。这构成了检索结果的优先级排序策略。

### 原语：动态题目Q_t——检索查询的动态演化
- **ID**：250-P5
- **类型**：概念框架
- **描述**：题目不是静态文本，而是动态研究状态Q_t = Q_0 ⊕ T_{0:t} ⊕ E_{0:t} ⊕ U_t——原始题面+外显思维轨迹+工具/审计证据+未解决子目标/矛盾/停滞信号。任意中间状态都可以重新成为一道题。
- **溯源**：250-v0, 第236-246行, 原文引用："122-v2提出了一个关键修正：题目不是静态文本，而是动态研究状态……第t时刻的真实题目应写成：Q_t = Q_0 ⊕ T_{0:t} ⊕ E_{0:t} ⊕ U_t……这意味着数学大师系统不是一次性prompt生成器，而是一个过程性控制器：它在每个状态重新判断'现在应该想到什么'。"
- **依赖关系**：
  - 依赖：250-P1（K/T/H三图分离，T图提供T_{0:t}）
  - 支撑：250-P6（增量上下文编译）
- **与检索机制的关系**：定义了检索查询的动态性——检索不是一次性查询，而是随研究状态演化的增量查询。每次状态变化后，检索查询Q_t更新，检索机制需要支持增量查询和状态依赖的检索。

### 原语：增量上下文编译
- **ID**：250-P6
- **类型**：操作原语
- **描述**：上下文编译器不能只在任务开始时工作一次，而应在每次状态变化后增量工作：Q_t + 当前思维图T_t → 匹配启发关系 → 选择最小激活包 → 编译为增量提示 → 生成Q_(t+1)。
- **溯源**：250-v0, 第248-256行, 原文引用："上下文编译器因此不能只在任务开始时工作一次，而应当在每次状态变化后增量工作：Q_t + 当前思维图T_t → 匹配启发关系 → 选择最小激活包 → 编译为增量提示 → 生成Q_(t+1)。"
- **依赖关系**：
  - 依赖：250-P5（动态题目Q_t）、250-P2（P→X图改写规则）、250-P3（激活包）
  - 支撑：250-P17（12步在线主链步骤3和步骤7-8）
- **与检索机制的关系**：这是检索机制的核心工作流——每次状态变化触发一次增量检索-编译循环。检索机制需要支持增量触发、增量匹配和增量结果编译，而不是全量重检索。

### 原语：子图模式匹配+条件合取
- **ID**：250-P7
- **类型**：操作原语
- **描述**：启发关系的匹配不是节点集合匹配，而是子图模式匹配+条件合取——在当前思维图T_t中匹配LHS定义的局部子图模式，同时检查Guard中的上下文/时序/模型/失败类型等条件是否全部满足。高频稳定组合才物化为复合模式。
- **溯源**：250-v0, 第205-207行, 原文引用："122-v2推荐：原子模式保留为独立特征，多条件启发用超边、因子或带guard的规则表示，查询时做子图模式匹配和条件合取，只有高频稳定组合才物化为复合模式。"
- **依赖关系**：
  - 依赖：250-P2（P→X图改写规则）、250-P1（K/T/H三图分离）
  - 支撑：250-P17（12步主链步骤7候选规则匹配）
- **与检索机制的关系**：这是检索机制的核心匹配算法——子图同构匹配+多条件合取过滤。检索机制需要支持图模式查询（类似SPARQL/Cypher的子图匹配）和多维度条件过滤的组合查询。

### 原语：时序模式匹配
- **ID**：250-P8
- **类型**：操作原语
- **描述**：时序不能只当普通tag——"先看到P，再经过两次失败才看到R"和"先看到R，随后立即看到P"不一定等价。启发关系应支持先后顺序、时间间隔、重复次数、已尝试但失败的操作、当前路径深度、是否发生回退。时序模式本质上是对路径或事件序列的匹配，不只是节点集合匹配。
- **溯源**：250-v0, 第207-208行, 原文引用："时序也不能只当普通tag——'先看到P，再经过两次失败才看到R'和'先看到R，随后立即看到P'不一定等价。因此启发关系还应支持先后顺序、时间间隔、重复次数、已尝试但失败的操作、当前路径深度、是否发生回退。时序模式本质上是对路径或事件序列的匹配，不只是节点集合匹配。"
- **依赖关系**：
  - 依赖：250-P7（子图模式匹配+条件合取）、250-P9（事件结构L_≤t）
  - 支撑：无直接后续
- **与检索机制的关系**：检索机制需要支持时序查询——不只是匹配当前状态的子图结构，还要匹配事件序列中的时序模式（先后顺序、间隔、重复次数、回退等）。这要求检索机制建立在事件流而非状态快照之上。

### 原语：事件结构L_≤t——带冲突的事件DAG
- **ID**：250-P9
- **类型**：结构原语
- **描述**：研究过程中的每一步都是不可变的事件，系统在第t时刻的状态是这些事件的投影——从所有已发生事件中归约出来的当前快照。事件一旦发生就不可修改，状态的"变化"不是修改旧事件，而是追加新事件。冲突标记#表示两个事件不能同时出现在有效状态中。
- **溯源**：250-v0, 第499-519行, 原文引用："事件结构的核心思想是：研究过程中的每一步……都是一个不可变的事件，而系统在第t时刻的状态是这些事件的投影——从所有已发生事件中归约出来的当前快照……123-v1把事件结构严格化为带冲突的事件DAG L_{≤ t}，包含事件不可变性保证、冲突标记#的语义（两个事件不能同时出现在有效状态中）、事件无环而循环发生在状态商空间等形式化定义。"
- **依赖关系**：
  - 依赖：无（foundational）
  - 支撑：250-P8（时序模式匹配）、250-P10（状态归约规则）、250-P17（12步主链事件溯源架构）
- **与检索机制的关系**：事件结构是检索机制的状态表示基础——检索查询的对象不是静态状态，而是事件流及其投影。检索机制需要能查询事件历史（时序匹配）和当前状态投影（子图匹配），并处理冲突标记（排除互斥事件）。

### 原语：状态归约规则——从事件流投影为当前快照
- **ID**：250-P10
- **类型**：操作原语
- **描述**：当前状态S_t从事件流E_{0:t}归约得出，不是独立存储。状态归约是从所有已发生事件中提取V_t（已验证事实）、F_t（未验证猜想）、O_t（开放义务）、R_t（当前表示）、D_t（依赖关系）的过程。事件不可变，但状态可变——状态的"变化"不是修改旧事件，而是追加新事件后重新归约。
- **溯源**：250-v0, 第661行, 原文引用："状态归约规则：当前状态S_t从事件流E_{0:t}归约得出，不是独立存储。状态归约是把事件流投影为当前快照的过程——从所有已发生事件中提取V_t（已验证事实）、F_t（未验证猜想）、O_t（开放义务）、R_t（当前表示）、D_t（依赖关系）。"
- **依赖关系**：
  - 依赖：250-P9（事件结构L_≤t）、250-P11（动态工作区W_t六元组）
  - 支撑：250-P17（12步主链步骤6状态归约）
- **与检索机制的关系**：状态归约是检索的前置步骤——检索查询的对象是归约后的当前状态W_t，而归约本身是从事件流到状态的投影操作。检索机制需要理解状态归约的输出格式，以正确构造检索查询。

### 原语：动态工作区W_t=(V_t,F_t,O_t,R_t,D_t,E_t)六元组
- **ID**：250-P11
- **类型**：结构原语
- **描述**：系统在第t时刻的完整状态用六元组表示——V_t（已验证核心，只增不减）、F_t（猜想前沿，可升级为V_t或被否定移除）、O_t（开放义务，AND/OR超图）、R_t（表示，当前采用的数学表示方式及历史变换轨迹）、D_t（依赖，各结论之间的逻辑依赖）、E_t（事件，截至当前已发生的事件序列）。
- **溯源**：250-v0, 第472-481行, 原文引用："123-v1把动态状态严格化为六元组W_t=(V_t, F_t, O_t, R_t, D_t, E_t)，其中：V_t：已验证核心……F_t：猜想前沿……O_t：开放义务……R_t：表示……D_t：依赖……E_t：事件。"
- **依赖关系**：
  - 依赖：250-P9（事件结构L_≤t）、250-P12（义务超图O_t）
  - 支撑：250-P10（状态归约规则）、250-P17（12步主链）
- **与检索机制的关系**：六元组定义了检索机制需要查询的状态空间——检索可以针对V_t（已验证事实库）、F_t（猜想库）、O_t（开放义务库）、R_t（表示库）、D_t（依赖关系库）、E_t（事件历史库）分别或组合查询。每个分量是检索的一个维度。

### 原语：义务超图O_t——AND/OR有向超图
- **ID**：250-P12
- **类型**：结构原语
- **描述**：开放义务用AND/OR有向超图表达——AND约束（所有子目标都必须解决）、OR约束（任一路径成功即可）。超边e=(source, {targets}, type)，带有状态标记（开放/进行中/已解决/已否定）。任务类型从证明泛化到证伪/构造/猜想/评估。
- **溯源**：250-v0, 第521-541行, 原文引用："122-v2的T图中，subgoal是一种节点类型，decompose是一种边类型。一个子目标可以被分解为多个子目标……这种'一个目标分解为多个子目标'的结构，本质上就是超图的超边……123-v1把开放义务严格化为AND/OR有向超图O_t。"
- **依赖关系**：
  - 依赖：250-P11（动态工作区W_t）
  - 支撑：250-P17（12步主链步骤2问题建模）
- **与检索机制的关系**：义务超图定义了检索的任务结构——检索不只是"找相关知识"，而是"找能解决当前开放义务的知识"。AND/OR结构决定了检索需要返回满足所有AND子义务或任一OR路径的知识组合，而非单个知识节点。

### 原语：启发规则生命周期状态机
- **ID**：250-P13
- **类型**：操作原语
- **描述**：启发规则有完整生命周期：observed（从A/B轨迹差分观察到）→candidate（已形式化为候选关系）→intervened（已做最小提示干预）→validated（原问题族重复验证）→transferred（新问题迁移验证）→published（进入生产启发图H，可在线自动匹配）→retired（新模型已学会或被反例否定）。只有published状态的规则才能在线自动匹配和提示。
- **溯源**：250-v0, 第587-609行, 原文引用："122-v2定义了启发关系的完整生命周期：observed→candidate→intervened→validated→transferred→published→retired……published：进入生产启发图H，可以在线自动匹配和提示……模型升级后，某些启发可能不再需要；另一些启发可能只对特定模型有效。因此启发图必须版本化，不能假设永恒有效。"
- **依赖关系**：
  - 依赖：250-P2（P→X图改写规则）、250-P14（candidate规则禁止在线自动提示）
  - 支撑：250-P17（12步主链步骤7候选规则匹配——只能匹配published规则）
- **与检索机制的关系**：这是检索机制的准入控制——检索只能返回published状态的规则，candidate及以下状态的规则禁止在线匹配。这构成了检索的过滤条件之一。同时，规则版本化要求检索机制支持版本感知查询。

### 原语：candidate规则禁止在线自动提示（R-4防线）
- **ID**：250-P14
