# 原语提取：227-v0-对226号数学化路线的回应——从漂亮结构到可检验骨架

## 文档概述

本文档是对226号数学化路线的回应，提出一个更稳的三层（后扩展为五层）骨架来替代226-v1过快的数学化升级。文档核心贡献是：将证书系统从单一偏序改为多轴字段化对象、将语义移动分型、将自然性分层、将V/R改为带效应闭环、将site从预设改为从可粘合覆盖族中长出、将obstruction分层、将语义能量改为诊断序量。这些修正中包含大量可直接用于检索机制设计的数据结构、索引结构、匹配算法和分层架构原语。

## 提取的原语

### 原语：可靠性门槛——每个结构必须声明作用层、前提和降级路径
- **ID**：227-P1
- **类型**：概念框架 / 性质标准
- **描述**：任何数学结构（或检索机制组件）在被采纳前，必须说明它作用在哪一层、需要哪些前提条件、失败时降级成什么。
- **溯源**：227-v0, 第33行, 原文引用："每个漂亮结构都必须说明它作用在哪一层、需要哪些前提、失败时降级成什么。"
- **依赖关系**：
  - 依赖：无
  - 支撑：227-P18（五层骨架）、227-P20（结构从例子中长出）
- **与检索机制的关系**：检索机制中每个组件（索引结构、匹配算法、排序策略）都应声明其适用层、前提和降级路径，防止过度承诺导致系统性误检索。

### 原语：证书字段化对象（Certificate data structure）
- **ID**：227-P2
- **类型**：结构原语
- **描述**：证书不是一个标量强度值，而是一个带字段的结构化对象，包含声明、范围、强度、依赖链、检查器和状态六个字段。
- **溯源**：227-v0, 第51-59行, 原文引用："Certificate / claim 被证明的数学声明 / scope 声明适用的范围 / strength 声明的强度 / dependencies 依赖链 / checker 检查机制 / status 已验证、已反驳、诊断失败、未知"
- **依赖关系**：
  - 依赖：无
  - 支撑：227-P3（多轴证书范畴）、227-P5（三类可靠对象分类）
- **与检索机制的关系**：这是检索机制中最核心的检索单元数据结构——Pattern/证书的表示形式。字段化使得检索可以按任意字段过滤、排序、聚合，支撑多维度检索。

### 原语：多轴证书范畴 / 索引偏序
- **ID**：227-P3
- **类型**：结构原语
- **描述**：证书系统不是单一偏序，而是按声明、范围、依赖和检查器分层的索引结构；在固定claim和scope的纤维里有偏序，全局上是带索引的证书范畴。
- **溯源**：227-v0, 第61行, 原文引用："把 C 从单一偏序改成'多轴证书范畴'或'索引偏序'。在固定 claim 和固定 scope 的纤维里，强度可以形成偏序。在固定结论强度时，适用范围按反方向排序。依赖链则更像审计图，不应直接和结论强度混成一个序。"
- **依赖关系**：
  - 依赖：227-P2（证书字段化对象）
  - 支撑：227-P11（证书预层）
- **与检索机制的关系**：这是检索机制的核心索引结构——多轴索引允许在不同纤维（固定某些维度）下做偏序检索，避免把不同语义方向的"加强"混成一个维度导致误检索。

### 原语：纤维化检索——固定部分维度后在纤维内做偏序
- **ID**：227-P4
- **类型**：操作原语
- **描述**：检索时固定某些字段（如claim和scope），在所得纤维内按强度做偏序检索；固定强度时按适用范围反向排序。
- **溯源**：227-v0, 第61行, 原文引用："在固定 claim 和固定 scope 的纤维里，强度可以形成偏序。在固定结论强度时，适用范围按反方向排序。"
- **依赖关系**：
  - 依赖：227-P3（多轴证书范畴）
  - 支撑：无
- **与检索机制的关系**：这是检索机制的核心匹配算法——纤维化检索允许在多维索引中按需固定部分维度，在剩余维度上做偏序比较，实现精确的Pattern匹配。

### 原语：三类可靠对象分类——正向证书、反驳证书、诊断反馈
- **ID**：227-P5
- **类型**：概念框架
- **描述**：系统中的可靠信息分三类：正向证书（证明声明成立）、反驳证书（证明声明不成立，通常为可验证反例）、诊断反馈（尝试失败/翻译不通/工具无法处理/图册拼不上，改变下一步导航但不证明命题真假）。
- **溯源**：227-v0, 第79-87行, 原文引用："第一类是正向证书。它证明某个声明成立。第二类是反驳证书。它证明某个声明不成立，通常表现为可验证反例。第三类是诊断反馈。它说明某个尝试失败、某个翻译不通、某个工具无法处理、某个局部图册拼不上。"
- **依赖关系**：
  - 依赖：227-P2（证书字段化对象）
  - 支撑：227-P6（三层分离架构）
- **与检索机制的关系**：检索机制需要区分三类检索结果——正向匹配（可用Pattern）、反向匹配（排除Pattern）、诊断信息（导航提示）。三类有不同的可靠性性质和不同的使用方式。

### 原语：三层分离架构——证书层C、反馈层D、语义场S
- **ID**：227-P6
- **类型**：结构原语
- **描述**：知识分为三层：证书层C（正向证书+反驳证书+一致性检查）、反馈层D（类型错误/粘合失败/求解器未知/搜索超时/局部翻译缺口）、语义场S（吸收C和D的结果形成新的处境理解）。
- **溯源**：227-v0, 第91-106行, 原文引用："证书层 C / 正向证书 / 反驳证书 / 证书之间的一致性检查 / 反馈层 D / 类型错误 / 粘合失败 / 求解器未知 / 搜索超时 / 局部翻译缺口 / 语义场 S / 把 C 和 D 的结果吸收成新的处境理解"
- **依赖关系**：
  - 依赖：227-P5（三类可靠对象分类）
  - 支撑：227-P18（五层骨架）
- **与检索机制的关系**：检索机制的知识库应分层存储——已验证知识（证书层）、失败/诊断记录（反馈层）、动态理解（语义场）。不同层的检索策略和置信度处理不同。

### 原语：障碍升级路径——从反馈层到反驳证书
- **ID**：227-P7
- **类型**：操作原语
- **描述**：障碍可能从反馈层升级成反驳证书（当它被严格验证为可验证反例时），也可能只是提示需要换表示。
- **溯源**：227-v0, 第87行, 原文引用："障碍可能从反馈层升级成反驳证书，也可能只是提示我们需要换表示。"
- **依赖关系**：
  - 依赖：227-P5（三类可靠对象分类）、227-P6（三层分离架构）
  - 支撑：无
- **与检索机制的关系**：检索机制需要支持知识项的层级升级——一个诊断反馈在获得足够证据后可以升级为反驳证书，改变其检索权重和使用方式。

### 原语：带类型语义移动——Σ分五层
- **ID**：227-P8
- **类型**：结构原语
- **描述**：语义移动不是单一态射，而是分五层：Σ_rep（表示等价，态射可逆）、Σ_red（归约，有损或半有损）、Σ_spec（特例化/推广，有明确逻辑方向）、Σ_form（形式化翻译，带忠实性标注）、Σ_diag（诊断更新，来自失败和反馈）。
- **溯源**：227-v0, 第128-136行, 原文引用："Σ_rep 表示等价层。态射是换表示、换坐标、等价改写。Σ_red 归约层。态射是把一个目标归约为另一个目标。Σ_spec 特例化和推广层。态射有明确的逻辑方向。Σ_form 形式化翻译层。态射带有忠实性标注。Σ_diag 诊断更新层。态射来自失败、反例、障碍和工具反馈。"
- **依赖关系**：
  - 依赖：无
  - 支撑：227-P9（证书运输能力分型）、227-P10（分层自然性）
- **与检索机制的关系**：认知图/依赖图中的边（语义移动）应带类型标签。不同类型的边在检索时有不同的语义——表示等价边可以双向运输证书，特例化边只能单向运输。这是边类型化检索的基础。

### 原语：证书运输能力分型
- **ID**：227-P9
- **类型**：概念框架
- **描述**：不同类型的语义移动有不同的证书运输能力——表示变换可以运输证书，特例化通常不能反向运输证书。系统不能把"换表示"和"证明了一个特例"混为一谈。
- **溯源**：227-v0, 第140行, 原文引用："它是为了防止系统把'换表示'和'证明了一个特例'混为一谈。前者可以运输证书，后者通常不能反向运输证书。"
- **依赖关系**：
  - 依赖：227-P8（带类型语义移动）
  - 支撑：227-P12（证书拉回操作）
- **与检索机制的关系**：检索机制在沿图遍历时必须考虑边的证书运输能力——只有可运输证书的边才允许在遍历中传播匹配结果，防止误传播导致错误检索。

### 原语：分层自然性——非特定性四级
- **ID**：227-P10
- **类型**：性质标准
- **描述**：非特定性（方法的表示无关性）分四级：强非特定（在等价表示下可证交换）、弱非特定（在非等价但保目标的移动下lax交换）、经验非特定（在变体族上稳定产生同类证书目标）、特定化（只能在单一题面或单一表示里工作）。
- **溯源**：227-v0, 第160-165行, 原文引用："强非特定：在等价表示下可证交换。弱非特定：在非等价但保目标的移动下 lax 交换。经验非特定：在变体族上稳定产生同类证书目标。特定化：只能在单一题面或单一表示里工作。"
- **依赖关系**：
  - 依赖：227-P8（带类型语义移动）
  - 支撑：无
- **与检索机制的关系**：检索机制中Pattern的通用性应分级标注——强非特定的Pattern可以在所有等价表示中检索到，特定化的Pattern只能在精确匹配的表示中检索。这决定了检索的召回策略。

### 原语：带效应的语义证书闭环
- **ID**：227-P11
- **类型**：操作原语
- **描述**：可证化V和反射R不是函子间的伴随，而是带效应的闭环：Move(S)→Goals, Check(Goals)→Results, Reflect(Results,S)→Updates, Apply(Updates,S)→S'。效应包括多值、失败、未知、诊断、非确定选择。
- **溯源**：227-v0, 第183-190行, 原文引用："Move(S) → Goals / Check(Goals) → Results / Reflect(Results, S) → Updates / Apply(Updates, S) → S' / 这里的关键是效应：多值、失败、未知、诊断、非确定选择。"
- **依赖关系**：
  - 依赖：227-P8（带类型语义移动）
  - 支撑：227-P12（闭包派生Galois connection）
- **与检索机制的关系**：检索流程本身是一个带效应的闭环——检索可能返回多值结果、可能失败、可能返回未知状态。检索机制必须原生支持这些效应，而不是假设检索总是成功返回单一结果。

### 原语：闭包派生Galois connection（α/γ）
- **ID**：227-P12
- **类型**：结构原语
- **描述**：原始V/R是带效应闭环，只有在做稳定化和闭包之后才可能出现Galois connection：α(S)=从处境S可稳定产生的证书理想，γ(I)=与证书理想I相容的处境约束。
- **溯源**：227-v0, 第194-199行, 原文引用："α(S) = 从处境 S 可稳定产生的证书理想 / γ(I) = 与证书理想 I 相容的处境约束 / 如果 α 和 γ 之间满足某种序关系，那么可以讨论 Galois connection。"
- **依赖关系**：
  - 依赖：227-P11（带效应闭环）、227-P3（多轴证书范畴）
  - 支撑：无
- **与检索机制的关系**：α是从处境到可检索证书集合的抽象函数（检索的正向映射），γ是从证书集合到兼容处境的具象函数（检索的反向映射）。这构成了检索机制中"查询→结果→反馈→查询修正"的抽象/具象对偶。

### 原语：局部证书预层 Cert: Σ_rep^op → Pos
- **ID**：227-P13
- **类型**：结构原语
- **描述**：对每个表示处境S，Cert(S)是这个表示中可表达、可检查、可运输的局部证书偏序；对每个表示变换τ:S'→S，有限制/拉回操作把S上的证书翻译到S'上。
- **溯源**：227-v0, 第218-221行, 原文引用："Cert : Σ_rep^op → Pos / 也就是说，对每个表示处境 S，Cert(S) 是这个表示中可表达、可检查、可运输的局部证书偏序。对每个表示变换 τ : S' → S，有一个限制或拉回操作，把 S 上的证书翻译到 S' 上。"
- **依赖关系**：
  - 依赖：227-P3（多轴证书范畴）、227-P8（带类型语义移动）、227-P9（证书运输能力分型）
  - 支撑：227-P14（descent粘合条件）、227-P15（重叠对象定义）
- **与检索机制的关系**：这是检索机制的核心索引结构——每个图节点（处境）关联一个局部证书偏序，每条边（表示变换）关联一个证书拉回操作。检索就是在图上沿边做拉回操作，收集各节点的局部证书。

### 原语：证书拉回操作（cross-representation certificate translation）
- **ID**：227-P14
- **类型**：操作原语
- **描述**：给定表示变换τ:S'→S，将S上的证书翻译到S'上的操作。这是跨表示检索的基础操作。
- **溯源**：227-v0, 第221行和第231行, 原文引用："对每个表示变换 τ : S' → S，有一个限制或拉回操作，把 S 上的证书翻译到 S' 上。" / "第二，要能定义证书拉回。也就是一个表示里的证书怎么翻译到另一个表示或共同重叠里。"
- **依赖关系**：
  - 依赖：227-P13（局部证书预层）、227-P9（证书运输能力分型）
  - 支撑：227-P15（descent粘合条件）
- **与检索机制的关系**：这是检索机制中跨节点传播匹配结果的核心操作——当在一个表示中找到证书时，通过拉回操作将其翻译到其他表示中，实现跨表示的Pattern检索。

### 原语：Descent粘合条件——局部证书在重叠处一致则粘合成全局证书
- **ID**：227-P15
- **类型**：操作原语
- **描述**：给定覆盖{S_i→S}，如果每个局部表示S_i上有局部证书c_i，并且这些c_i在重叠S_i ×_S S_j上一致，那么它们可以粘合成S上的全局证书c。
- **溯源**：227-v0, 第223-225行, 原文引用："给定覆盖 {S_i → S}，如果每个局部表示 S_i 上有局部证书 c_i，并且这些 c_i 在重叠 S_i ×_S S_j 上一致，那么它们可以粘合成 S 上的全局证书 c。"
- **依赖关系**：
  - 依赖：227-P13（局部证书预层）、227-P14（证书拉回操作）、227-P16（重叠对象定义）
  - 支撑：227-P17（Site从覆盖族中长出）
- **与检索机制的关系**：这是检索机制中多视角合成的核心算法——从多个局部视角检索到的Pattern，如果在重叠区域一致，可以合成为一个更完整的全局Pattern。这是分布式/多视角检索的合成机制。

### 原语：重叠对象定义前提
- **ID**：227-P16
- **类型**：结构原语
- **描述**：要实现descent粘合，必须先能定义重叠——S_i ×_S S_j这样的对象必须存在，或至少有工程上的重叠表示。
- **溯源**：227-v0, 第229-230行, 原文引用："第一，要能定义重叠。也就是 S_i ×_S S_j 这样的对象是否存在，或者至少有一个工程上的重叠表示。"
- **依赖关系**：
  - 依赖：227-P8（带类型语义移动）
  - 支撑：227-P15（descent粘合条件）
- **与检索机制的关系**：检索机制中多视角合成的前提是能定义不同视角的交集——认知图中必须有表示节点间重叠的机制（如公共子图、共享属性），否则多视角检索无法合成。

### 原语：Site从可粘合覆盖族中长出（涌现拓扑）
- **ID**：227-P17
- **类型**：概念框架
- **描述**：Site/Grothendieck拓扑不是预设的，而是从那些让局部证书有descent机会的表示族中长出来的——只有可粘合的覆盖族才构成可用的拓扑。
- **溯源**：227-v0, 第237-239行, 原文引用："先不要说 Σ 是 site。先说：在表示等价层 Σ_rep 上，我们尝试定义一个局部证书预层 Cert。当某些覆盖族满足证书 descent 时，这些覆盖族构成可用的 Grothendieck 拓扑。 / 这样 site 不是预设，而是从可粘合的覆盖族里长出来。"
- **依赖关系**：
  - 依赖：227-P15（descent粘合条件）、227-P13（局部证书预层）
  - 支撑：无
- **与检索机制的关系**：检索机制中的索引结构（哪些节点组合可以联合检索）不应预设，而应从实际可合成的检索结果中涌现——只有那些多次成功合成的覆盖族才被标记为可信的联合检索单元。

### 原语：Obstruction分层——descent failure → obstruction object → Čech cocycle → H¹
