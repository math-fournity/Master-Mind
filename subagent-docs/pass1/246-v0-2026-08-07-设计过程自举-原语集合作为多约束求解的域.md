# 原语提取：246-v0-设计过程自举——原语集合作为多约束求解的域

## 文档概述

本文档记录了用户与AI关于"系统设计过程是自举的"这一洞察的对话。用户提出原语集合相当于约束、系统设计是多约束求解、设计过程自举的洞察，AI独立思考后修正了CSP映射（原语是domain而非constraint），提出"开放世界CSP"概念，并建议创建facet-C面相和design-as-constraint-solving概念。文档与检索机制的关系在于：它提供了将检索过程形式化为多约束求解的框架——检索的搜索空间是domain，检索条件是constraints，检索结果是solution，且这个求解过程是开放世界的（域和约束在求解中动态扩展）。

## 提取的原语

### 原语：原语集合作为域（domain）——检索的搜索空间
- **ID**：246-P1
- **类型**：概念框架
- **描述**：原语集合不是约束，而是域（domain）——构造解的词汇表，即变量的取值范围；约束是"解必须满足什么条件"，域是"解可以用什么来构造"。
- **溯源**：246-v0, 第54-56行, 原文引用："原语不是约束，原语是**域（domain）**——你能用来构造解的词汇表。约束是"解必须满足什么条件"。原语是"解可以用什么来构造"。这两个是CSP中不同的角色。"
- **依赖关系**：
  - 依赖：无
  - 支撑：246-P3（CSP四元组映射）、246-P5（domain扩展机制）
- **与检索机制的关系**：检索机制的搜索空间（认知图/依赖图中的Pattern集合）就是domain——检索是从域中选取满足约束的元素。明确域与约束的区分，使检索机制设计者能区分"可检索什么"（域）和"检索条件是什么"（约束）两个正交维度。

### 原语：开放世界CSP——检索空间与约束的动态扩展
- **ID**：246-P2
- **类型**：概念框架
- **描述**：系统设计的CSP不是标准CSP，而是开放世界CSP——domain在求解过程中扩展（发现新原语），constraint在求解中演化（面相修正、新需求出现），解成为下一轮的约束（自举）。
- **溯源**：246-v0, 第58行, 原文引用："系统设计不是标准CSP——它是**开放世界CSP**：domain在求解过程中会扩展（发现新原语），constraint也会演化（面相会修正）。标准CSP的domain和constraint是给定的、固定的。系统设计的CSP是动态的。"
- **溯源**：246-v0, 第91-96行, 原文引用："这不是标准CSP，是**开放世界CSP**——domain在求解中扩展（发现新原语，就像证明搜索中发现新引理）constraint在求解中演化（面相被修正，新需求出现）解成为下一轮的约束（自举）"
- **依赖关系**：
  - 依赖：246-P1（域的概念）
  - 支撑：246-P5（domain扩展）、246-P6（constraint演化）、246-P7（解成为下一轮约束）
- **与检索机制的关系**：检索机制不应假设搜索空间和查询约束是静态固定的。检索过程中可能发现新的Pattern（扩展域），查询条件可能动态修正（约束演化），检索结果可能成为下一轮检索的约束。这要求检索机制支持增量式、迭代式的检索流程，而非一次性封闭查询。

### 原语：CSP四元组映射——检索机制的形式化骨架
- **ID**：246-P3
- **类型**：结构原语
- **描述**：将设计过程映射为CSP的四元组：domain（可用原语集合+可能架构）、variables（设计决策：用哪些原语、怎么组合、什么角色）、constraints（系统需求+面相期望+已知局限+验证状态+当前系统行为）、solution（下一代系统设计，是解的轨迹而非单个解）。
- **溯源**：246-v0, 第84-89行, 原文引用："| **域（domain）** | 可用原语集合 + 可能的架构 | ... | **变量（variables）** | 设计决策：用哪些原语、怎么组合、什么角色 | ... | **约束（constraints）** | 系统需求 + 面相期望 + 已知局限 + 验证状态 + 当前系统行为 | ... | **解（solution）** | 下一代系统设计 | ... 对，但不是单个解，是**解的轨迹**——每代系统是上一代的解，也是下一代的约束"
- **依赖关系**：
  - 依赖：246-P1（域的概念）、246-P2（开放世界CSP）
  - 支撑：246-P4（验证状态作为约束）、246-P7（解的轨迹）
- **与检索机制的关系**：为检索机制提供形式化骨架——检索的domain是Pattern集合，variables是检索决策（选哪些Pattern、怎么组合），constraints是检索条件（匹配规则+上下文需求+验证状态+当前系统状态），solution是检索结果集。这个四元组让检索机制的设计有明确的结构分工。

### 原语：验证状态作为检索约束
- **ID**：246-P4
- **类型**：操作原语
- **描述**：验证状态（tested原语比untested可靠）是CSP约束的一部分，在求解中作为约束影响解的选择。
- **溯源**：246-v0, 第88行, 原文引用："基本对，但漏了两个：验证状态（tested原语比untested可靠）和当前系统行为（自举中，当前系统是下一代设计的约束之一）"
- **依赖关系**：
  - 依赖：246-P3（CSP四元组映射）
  - 支撑：无
- **与检索机制的关系**：检索Pattern时，验证状态应作为排序/过滤约束——tested的Pattern优先级高于untested的，tested_negative的应降权或排除。这为检索结果的排序提供了可靠性维度的约束。

### 原语：当前系统行为作为检索约束
- **ID**：246-P5
- **类型**：操作原语
- **描述**：在自举过程中，当前系统的行为是下一代设计的约束之一——当前系统已经做到的、做不到的、做错的，都约束下一代设计。
- **溯源**：246-v0, 第88行, 原文引用："当前系统行为（自举中，当前系统是下一代设计的约束之一）"
- **依赖关系**：
  - 依赖：246-P3（CSP四元组映射）、246-P2（开放世界CSP）
  - 支撑：246-P7（解的轨迹）
- **与检索机制的关系**：检索Pattern时，当前系统的状态（已使用哪些Pattern、当前推理链处于什么阶段、当前遇到什么困难）应作为检索约束——检索应返回与当前系统状态相关的Pattern，而非全局无关的Pattern。这支持上下文感知的检索。

### 原语：domain扩展机制——发现新原语扩展搜索空间
- **ID**：246-P6
- **类型**：结构原语
- **描述**：domain通过发现新原语来扩展，constraint通过发现新需求/新面相来扩展——两者的扩展方式不同，这是CSP中domain和constraint区分的重要意义。
- **溯源**：246-v0, 第56行, 原文引用："区分很重要，因为domain和constraint的扩展方式不同：domain通过发现新原语来扩展，constraint通过发现新需求/新面相来扩展。"
- **溯源**：246-v0, 第92行, 原文引用："domain在求解中扩展（发现新原语，就像证明搜索中发现新引理）"
- **依赖关系**：
  - 依赖：246-P1（域的概念）、246-P2（开放世界CSP）
  - 支撑：无
- **与检索机制的关系**：检索机制的搜索空间（Pattern集合）不是静态的——在检索过程中可能发现新的Pattern（类似证明搜索中发现新引理）。检索机制应支持动态添加新Pattern到搜索空间中，而非只从固定索引中检索。这支持增量式知识库构建。

### 原语：constraint演化机制——面相修正与新需求出现
- **ID**：246-P7
- **类型**：结构原语
- **描述**：constraint在求解中演化——面相被修正，新需求出现，约束不是给定的而是动态生长的。
- **溯源**：246-v0, 第93行, 原文引用："constraint在求解中演化（面相被修正，新需求出现）"
- **依赖关系**：
  - 依赖：246-P2（开放世界CSP）
  - 支撑：无
- **与检索机制的关系**：检索的查询条件不是一次性确定的——在检索过程中，查询条件可能被修正（发现新的匹配需求），新的约束可能出现。检索机制应支持迭代式查询精化（query refinement），而非只接受一次性固定查询。

### 原语：解的轨迹——检索结果成为下一轮检索的约束
- **ID**：246-P8
- **类型**：操作原语
- **描述**：解不是单个解，而是解的轨迹——每代系统是上一代的解，也是下一代的约束。自举中，解成为下一轮的约束。
- **溯源**：246-v0, 第89行, 原文引用："对，但不是单个解，是**解的轨迹**——每代系统是上一代的解，也是下一代的约束"
- **溯源**：246-v0, 第94行, 原文引用："解成为下一轮的约束（自举）"
- **依赖关系**：
  - 依赖：246-P2（开放世界CSP）、246-P3（CSP四元组映射）
  - 支撑：246-P10（自举循环）
- **与检索机制的关系**：检索结果不是终点——上一轮检索的结果（选出的Pattern、组合方式、使用效果）应成为下一轮检索的约束条件。这支持检索机制的记忆和反馈闭环：已检索并使用过的Pattern影响后续检索的优先级和方向。

### 原语：自举循环——检索机制的反馈改进闭环
- **ID**：246-P9
- **类型**：概念框架
- **描述**：设计过程是自举的循环：用原语设计系统→发现系统和预期未来之间的差距→用系统求解如何在原语集合上设计下一代系统→发现新原语→循环。与编译器自举同构。
- **溯源**：246-v0, 第71行, 原文引用："C：设计过程是自举的——用原语设计系统→发现差距→用系统求解下一代设计→发现新原语→循环"
- **溯源**：246-v0, 第60行, 原文引用："自举（bootstrapping）是整个洞察的核心：系统用自己来设计自己的下一代。这和编译器自举（用C编译器编译出更好的C编译器）是同构的。"
- **依赖关系**：
  - 依赖：246-P2（开放世界CSP）、246-P8（解的轨迹）
  - 支撑：无
- **与检索机制的关系**：检索机制本身可以自举——用当前检索机制检索Pattern→使用Pattern发现检索效果差距→用差距信息改进检索机制→发现新的检索原语→循环。这为检索机制的持续改进提供了元层面的闭环框架。

### 原语：正交分类视角——归档分类与角色分类的分离
- **ID**：246-P10
- **类型**：概念框架
- **描述**：现有分类（primitives/concepts/criteria/facets）按"东西是什么"分类，用于归档管理；CSP角色分类（domain/constraint/solution）按"东西在设计中扮演什么角色"分类，用于理解设计过程动力学。两者正交，不互相替代。
- **溯源**：246-v0, 第123-137行, 原文引用："现有分类（primitives/concepts/criteria/facets）是**按东西是什么分类**——用于归档和管理。CSP角色分类（domain/constraint/solution）是**按东西在设计中扮演什么角色分类**——用于理解设计过程动力学。两者正交"
- **溯源**：246-v0, 第128-135行, 原文引用正交矩阵："primitives → domain ✓ / constraint × / solution ×; concepts → domain ✓(部分) / constraint ✓(部分) / solution ×; criteria → constraint ✓; facets → constraint ✓; 系统设计(每代) → solution ✓"
- **依赖关系**：
  - 依赖：246-P3（CSP四元组映射）
  - 支撑：无
- **与检索机制的关系**：检索机制的索引组织可以采用正交双视角——一个维度按Pattern的类型/属性分类（归档视角，如操作原语/结构原语/概念框架/性质标准），另一个维度按Pattern在检索中扮演的角色分类（功能视角，如搜索空间元素/匹配约束/检索结果）。双视角索引让检索既能按类型过滤，又能按功能角色匹配。

### 原语：知识选取面相（facet-B）——从知识中选取原语
- **ID**：246-P11
- **类型**：概念框架
- **描述**：设计过程面相B：原语从知识中选取——这是与检索直接相关的过程面相，描述了从已有知识库中选取可用原语的过程。
- **溯源**：246-v0, 第70行, 原文引用："B：原语从知识中选取"

- **依赖关系**：

### 原语：前提条件与域的区分——检索前置状态 vs 检索搜索空间
- **ID**：246-P12
- **类型**：概念框架
- **描述**：前提条件是"开始设计前必须为真的东西"（如"我们有可用的AI模型"），域是"解的词汇表"。两者不同——前提条件是外部给定的状态，域是解可以从中选取的集合。
- **溯源**：246-v0, 第86行, 原文引用："应叫"域"——它是解的词汇表，不是前提条件。前提条件是"开始设计前必须为真的东西"（如"我们有可用的AI模型"）"
- **依赖关系**：
  - 依赖：246-P1（域的概念）
  - 支撑：无
- **与检索机制的关系**：检索机制需要区分"检索的前提条件"（如认知图已构建、索引已建立——这些是外部状态，检索机制假设它们为真）和"检索的搜索空间"（认知图中的Pattern集合——这是检索从中选取的域）。混淆两者会导致检索机制设计错误：把前提条件当作域来搜索，或把域当作前提条件来假设。

### 原语：发现新原语类似证明搜索中发现新引理
- **ID**：246-P13
- **类型**：概念框架
- **描述**：domain在求解中扩展（发现新原语），就像证明搜索中发现新引理——求解过程中产生新的可用构造单元。
- **溯源**：246-v0, 第92行, 原文引用："domain在求解中扩展（发现新原语，就像证明搜索中发现新引理）"
- **依赖关系**：
  - 依赖：246-P2（开放世界CSP）、246-P6（domain扩展机制）
