- **ID**：135-P1
- **类型**：概念框架
- **描述**：Phase 5的核心理念——系统只给当前一步真正需要的数据，不多不少。
- **溯源**：135-v1-2026-08-05-Phase5-CheckList.md, 第3行, 原文引用："Phase 5目标——让系统只给当前一步真正需要的数据。"

- **与检索机制的关系**：直接定义检索的目标——检索不是返回所有相关Pattern，而是返回"此刻最需要的那一个（或那一批）"。253号检索问题的核心约束"精准提取此刻最需要的Pattern"由此原则支撑。

### 原语：五层优先检索顺序
- **ID**：135-P10
- **类型**：操作原语
- **描述**：检索按五层优先级依次执行：①类型/前提可用性 → ②表示变换与领域映射 → ③图关系 → ④语义相似 → ⑤历史因果效果。每层结果按当前激活包需求过滤为最小内容。
- **溯源**：135-v1-2026-08-05-Phase5-CheckList.md, 第56-65行, 原文引用："实现检索顺序（123号§29，153号v2 F10预防修正）……1. 类型/前提可用性 2. 表示变换与领域映射 3. 图关系 4. 语义相似 5. 历史因果效果……有可执行的分层检索函数，按5层优先级依次检索，每层结果按激活包需求过滤为最小内容，7类内容区分返回"
- **依赖关系**：依赖：P4（温层）、P8（四层访问架构）；支撑：P11（最小内容判定）、P12（七类内容区分）、P13（不只对题面做embedding）
- **与检索机制的关系**：核心原语——直接定义253号第二层"Pattern提取"的算法。五层优先级给出了检索的执行顺序：先按类型/前提匹配（结构匹配），再按表示变换匹配（领域映射），再按图关系匹配（拓扑匹配），再按语义相似匹配（文本匹配），最后按历史因果效果匹配（效果度量）。253号说"不是文本相似"——五层顺序把语义相似放在第4层，说明文本相似不是首选策略。

- **与检索机制的关系**：直接相关——253号要求"精准提取此刻最需要的那一个（或那一批）Pattern"，最小内容判定约束给出了实现机制：每个检索结果必须标注它服务于哪个需求，无法标注的不返回。这防止检索返回大量"可能相关"但无法精确对应当前需求的Pattern。
