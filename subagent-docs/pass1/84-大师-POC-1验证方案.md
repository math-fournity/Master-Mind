# 原语提取：84-大师-POC-1验证方案（矩条件极差题版）

## 文档概述

本文档是数学大师系统的第一个 POC 验证方案，通过"矩条件极差题"的对照实验，验证依赖图提示是否比直接读教材更能帮助 AI 调用正确的数学意识（尤其是"数值检验"意识）来解题和发现题面错误。文档详细描述了依赖图的数据结构（节点类型、边类型、环路）、提示 JSON 格式、对照实验设计、评分标准和成功/失败定义。与检索机制的关系：依赖图本身就是检索的目标数据结构，其节点/边/环路的设计、知识指针的映射、提示生成的格式都是检索机制的核心构造积木；对照实验和评分体系则是验证检索机制有效性的方法原语。

## 提取的原语

### 原语：依赖图数据结构（带元属性的有向图）
- **ID**：84-P1
- **类型**：结构原语
- **描述**：用有向图（networkx DiGraph）表示知识依赖关系，节点带 type 和 context 元属性，边带 type 元属性，构成检索的基础数据结构。
- **溯源**：84, 第169-197行, 原文引用："graph = nx.DiGraph() … graph.add_node("矩条件极差题", type="step", context="前三阶矩约束极差下界") … graph.add_edge("矩条件极差题", "平移归一化", type="depends_on")"
- **依赖关系**：
  - 依赖：无（基础数据结构）
  - 支撑：84-P2（节点类型系统）、84-P3（边类型系统）、84-P4（节点上下文字段）
- **与检索机制的关系**：这是检索机制的底层数据结构——认知图/依赖图的物理表示。检索操作（遍历、过滤、匹配）都建立在这个图结构之上。节点和边的元属性为检索提供了多维度过滤和匹配的基础。

### 原语：节点类型分类系统（step / substep / 意识）
- **ID**：84-P2
- **类型**：结构原语
- **描述**：知识节点按粒度和性质分为三类——step（证明步骤入口）、substep（子步骤）、意识（数学思维模式），为检索提供类型过滤维度。
- **溯源**：84, 第115-124行, 原文引用："| `矩条件极差题` | step | 证明任务的入口节点 | … | `平移归一化` | substep | … | `不变量思维` | 意识 | … | `数值检验意识` | 意识 |"
- **依赖关系**：
  - 依赖：84-P1（依赖图数据结构）
  - 支撑：84-P9（意识节点作为检索目标）
- **与检索机制的关系**：节点类型是检索的第一过滤维度——检索可以按"只检索意识节点"或"只检索步骤节点"来缩小搜索空间。类型分类也决定了检索结果的呈现方式（意识节点和步骤节点在提示中的角色不同）。

### 原语：边类型分类系统（depends_on / calls）
- **ID**：84-P3
- **类型**：结构原语
- **描述**：依赖边分为 depends_on（硬依赖，前置步骤必须先完成）和 calls（软调用，调用某种意识或方法），为检索提供关系类型遍历维度。
- **溯源**：84, 第128-139行, 原文引用："| 矩条件极差题 | 平移归一化 | depends_on | 证明的第一步是归一化 | … | 矩恒等式 | 不变量思维 | calls | 恒等式本质上是不变量关系 |"
- **依赖关系**：
  - 依赖：84-P1（依赖图数据结构）
  - 支撑：84-P8（依赖图路径引导）
- **与检索机制的关系**：边类型区分了"必须检索的依赖链"（depends_on）和"可选调用的意识/方法"（calls）。检索时可以按边类型决定遍历策略——depends_on 链是深度优先的必经路径，calls 边是广度扩展的候选集。

### 原语：节点上下文字段（context）
- **ID**：84-P4
- **类型**：结构原语
- **描述**：每个知识节点携带一个 context 字段，用自然语言描述该节点在问题中的上下文角色，为语义匹配检索提供文本基础。
- **溯源**：84, 第115-124行, 原文引用："| `不变量思维` | 意识 | 矩恒等式是不变量关系——无论 x_i 怎么变，Σq(x_i) 和 Σx_i·q(x_i) 恒为 0 | 陪集大小→矩恒等式 | … | `数值检验意识` | 意识 | 用具体数值例子检验命题是否自洽——如果数值与命题矛盾，命题可能有误 | n=500 的三点构型 vs 指数 -1/3 |"
- **依赖关系**：
  - 依赖：84-P1（依赖图数据结构）
  - 支撑：84-P5（知识指针）
- **与检索机制的关系**：context 字段是语义检索的匹配文本——当用户问题或推理状态需要某种知识/意识时，可以通过 context 字段的语义相似度来检索相关节点。context 把抽象的节点 ID 转化为可匹配的自然语言描述。

### 原语：知识指针（从图节点到外部文档的映射）
- **ID**：84-P5
- **类型**：结构原语
- **描述**：依赖图中每个知识节点通过 knowledge_pointers 映射到外部知识文档路径，实现"图结构检索 → 文档内容获取"的两级检索。
- **溯源**：84, 第246-253行, 原文引用："\"knowledge_pointers\": { \"平移归一化\": \"math-notes/分析/矩条件/平移归一化.md\", … \"数值检验意识\": \"math-notes/数学意识/数值检验意识.md\" }"
- **依赖关系**：
  - 依赖：84-P1（依赖图数据结构）、84-P4（节点上下文字段）
  - 支撑：84-P8（依赖图路径引导）
- **与检索机制的关系**：知识指针实现了检索机制中的"二级检索"——第一级在依赖图中检索到相关节点，第二级通过指针获取节点对应的详细知识文档。这是图索引到文档库的桥梁，使检索结果不仅有结构信息还有完整知识内容。

### 原语：SCC 环检测与环路分类
- **ID**：84-P6
- **类型**：操作原语
- **描述**：用强连通分量（SCC）检测依赖图中的环，并根据环中节点的上下文是否不同，将环分类为"螺旋环路"（上下文不同，是深化）或"平面循环"（上下文相同，是重复）。
- **溯源**：84, 第199-201行, 原文引用："SCC 检测会发现 {极端检验, 数值检验意识} 构成一个 SCC（互相可达）。它们的上下文分别是"三点构型数值试探"和"用数值例子检验命题自洽性"——不同上下文，分类为螺旋环路。"
- **依赖关系**：
  - 依赖：84-P1（依赖图数据结构）、84-P4（节点上下文字段）
  - 支撑：84-P7（螺旋环路概念）
- **与检索机制的关系**：环检测是图结构分析原语，用于识别依赖图中的循环依赖。环路分类（螺旋 vs 平面）决定了检索时是否需要重复遍历——螺旋环路意味着同一节点在不同上下文中需要被多次检索（每次检索的上下文不同），平面循环则可能指示设计缺陷。

### 原语：螺旋环路（上下文区分的同节点复用）
- **ID**：84-P7
- **类型**：概念框架
- **描述**：同一组节点在不同上下文中被反复调用构成环路，但每次调用的上下文不同（如"确认最优常数"vs"检验指数正确性"），是螺旋上升而非平面循环——检索时需要区分调用上下文。
- **溯源**：84, 第141-150行, 原文引用："这个环路是螺旋环路：- 第一次极端检验在"确认 √5 是最优常数"上下文中被调用 … - 第二次极端检验在"检验第二问指数是否正确"上下文中被调用 … 两次调用的上下文不同 … 是螺旋上升，不是平面循环。"
- **依赖关系**：
  - 依赖：84-P6（SCC环检测与分类）、84-P4（节点上下文字段）
  - 支撑：84-P10（环路在提示中的显式标注）
- **与检索机制的关系**：螺旋环路揭示了检索的一个关键性质——同一 Pattern（节点）在不同问题上下文中可以被多次检索和复用，每次复用携带不同的上下文信息。检索机制需要支持"同节点多上下文实例"的检索，而非简单的去重。这对 Pattern 的版本管理和上下文标注有直接启示。

### 原语：依赖图路径引导（沿图路径组织推理流程）

- **描述**：通过 analysis_guidance 字段，沿依赖图的 depends_on 路径生成有序的推理引导，将检索到的知识节点按依赖顺序组织成可执行的推理流程。
- **溯源**：84, 第254行, 原文引用："\"analysis_guidance\": \"请沿依赖图路径组织证明：1) 首先做平移归一化 … 2) 寻找一个同时编码二阶矩和三阶矩的关键多项式 … 3) 导出两个矩恒等式 … 4) 用分类讨论证明极差 ≥ √5；5) 用三点构型做极端检验 … 6) 对第二问，调用数值检验意识 …\""

- **与检索机制的关系**：路径引导是检索结果的"排序原语"——检索到的节点集合不是无序的，而是按依赖关系拓扑排序后的有序序列。这使得检索结果可以直接作为推理流程使用，而非需要用户自行组织。

### 原语：可比性保证（控制变量）
- **ID**：84-P13
- **类型**：操作原语
- **描述**：确保对照实验中两组的唯一差异是输入材料（教材 vs 依赖图），题面、任务表述、AI 指令其余部分完全相同，保证实验结果可归因于检索机制本身。
- **溯源**：84, 第96-101行, 原文引用："两组的题面完全相同（都是错误版本，指数 n^{-1/3}）… 两组的分析任务表述完全相同 … 两组的 AI 指令除了输入材料不同外，其余完全相同 … B 组拿到的依赖图提示中的知识指向同一批教材内容"
- **依赖关系**：
  - 依赖：无
  - 支撑：84-P12（对照实验设计）
- **与检索机制的关系**：可比性保证是检索机制验证的"公平性原语"——确保两组拿到的知识内容是等价的，差异只在"知识的组织方式"（线性文本 vs 图结构）。这保证了如果 B 组优于 A 组，差异确实来自检索机制（图结构+路径引导+意识节点），而非来自知识内容的不对等。
