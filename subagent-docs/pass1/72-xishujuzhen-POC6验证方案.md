# 原语提取：72-xishujuzhen-POC6验证方案

## 文档概述

本文档是稀疏矩阵（xishujuzhen）验证体系POC-6的实验方案设计。POC-6的核心问题是：当A组知识缺失时，B组（依赖图+知识嵌入+三步流程+闭环审计）是否能产生A组无法产生的分析结果。文档同时引入了交叉审计机制（独立AI实例审计替代自审）。与检索机制的关系在于：文档描述了依赖图作为知识检索载体的结构、知识嵌入在节点中的方式、跨宫依赖边的显式引导作用、以及通过对照实验验证知识嵌入检索价值的方法论——这些都是检索机制设计的直接参考。

## 提取的原语

### 原语：依赖图作为知识检索载体
- **ID**：72-P1
- **类型**：结构原语
- **描述**：依赖图（30节点40边，8跨宫依赖边）作为承载知识的图结构，节点中嵌入knowledge_content，是知识检索的物理载体。
- **溯源**：72, 第42-43行, 原文引用："复用POC-5的依赖图（30节点40边，8跨宫依赖边）。依赖图不变——变化的只是A组的知识嵌入状态。"
- **依赖关系**：
  - 依赖：无（基础结构原语）
  - 支撑：72-P2（知识嵌入节点）、72-P3（跨宫依赖边）
- **与检索机制的关系**：依赖图本身就是检索机制的底层数据结构——节点是可检索单元，边是检索路径，knowledge_content是检索内容。检索机制在此结构上运行。

### 原语：节点级知识嵌入（knowledge_content）
- **ID**：72-P2
- **类型**：结构原语
- **描述**：依赖图的每个节点嵌入knowledge_content字段，包含与该节点对应的命理知识，使节点不仅是结构单元也是知识单元。
- **溯源**：72, 第57-58行, 原文引用："B组的JSON中knowledge_content包含完整的大限流年知识（同POC-5）。B组的动态分析节点（限宫主庙旺、流年太岁关系、限内星曜配置、限内格局触发、限内行运星）都嵌入了knowledge_content。"
- **依赖关系**：
  - 依赖：72-P1（依赖图载体）
  - 支撑：72-P5（知识缺失对照实验）
- **与检索机制的关系**：knowledge_content是检索机制返回的内容——检索图的节点时，不仅返回节点标识，还返回嵌入的知识内容。这是"检索即知识获取"的核心设计。

### 原语：跨宫依赖边作为跨域检索引导

### 原语：知识嵌入 vs 原始数据分离（知识分层）
- **ID**：72-P4
- **类型**：概念框架
- **描述**：将"原始数据"（排盘数值）与"解读知识"（命理知识）分离为两个层次——A组有原始数据但无解读知识，B组两者都有。这种分层验证了知识嵌入的独特价值。
- **溯源**：72, 第52-54行, 原文引用："A组仍然获得星盘摘要（poc5_chart_summary.txt）——其中包含大限框架、当前大限、限内星曜、流年信息等原始数据，但A组没有解读这些数据的命理知识。这模拟了真实场景：用户可能有排盘数据（原始数值），但不知道如何解读动态分析部分。"
- **依赖关系**：
  - 依赖：72-P2（知识嵌入节点）
  - 支撑：72-P5（知识缺失对照实验）
- **与检索机制的关系**：检索机制需要区分"数据检索"和"知识检索"两个层次。原始数据可以直接获取，但解读知识需要通过知识嵌入的节点检索获得。这个分层是检索机制内容设计的基础。

### 原语：知识缺失对照实验设计
- **ID**：72-P5
- **类型**：操作原语
- **描述**：通过控制知识嵌入状态（A组缺失 vs B组完整），在依赖图结构不变的情况下，验证知识嵌入检索的边际价值——是否能让AI完成知识缺失时无法完成的分析。
- **溯源**：72, 第7-11行, 原文引用："POC-6要回答一个根本性问题：当A组知识缺失时，B组（依赖图+知识嵌入+三步流程+闭环审计）是否能产生A组无法产生的分析结果？如果答案是'是'——依赖图+知识嵌入的价值不仅在于可审计性，更在于知识嵌入本身能让AI完成知识缺失时无法完成的分析。"

### 原语：交叉审计机制（独立实例审计）

- **溯源**：72, 第15行, 原文引用："POC-6引入交叉审计：第2步自审由另一个AI实例审计，而非解读AI自审。"
