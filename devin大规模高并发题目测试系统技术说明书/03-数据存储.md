# 03 · 数据存储

## 3.1 三层存储架构

| 层 | 技术 | 位置 | 用途 |
|---|---|---|---|
| 队列层 | Redis | `localhost:6379` DB 0 | 运行时状态、多进程协作 |
| 持久层 | ArangoDB | `localhost:8529` | 题目元数据、attempt 记录、审计字段 |
| 证据层 | 文件系统 | `/data/math-agent-glm5.2-tmux-agents-trajectory/` | 物理证据（pane 快照、pipe.log、export） |

## 3.2 Redis 队列详解

### 连接配置

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/redis_queue.py" lines="17-25" />

- Host: `localhost`
- Port: `6379`
- DB: `0`
- `decode_responses=True` — 返回字符串而非 bytes

### 队列结构

#### math:pending（Sorted Set）

- **用途**：待解题队列
- **score**：priority（越小越先被取出）
- **member**：problem_key（ArangoDB 中的 `_key`）
- **写入**：Feeder 用 `ZADD`，Retry 用 `ZADD`（重试入队）
- **取出**：Runner 用 `ZPOPMIN`（原子操作，取最小 score）

#### math:running（Hash）

- **用途**：运行中 attempt 的 metadata
- **field**：exp_id（如 `p1a2b3c4d5e6f7g8h9i0`）
- **value**：JSON 字符串，结构如下：

```json
{
  "problem_key": "oda_math_xxx",
  "exp_id": "p1a2b3c4d5e6f7g8h9i0",
  "attempt_key": "pipe_p1a2b3c4d5e6f7g8h9i0",
  "tmux_session": "harness-p1a2b3c4d5e6f7g8h9i0",
  "start_time": 1723567200.0,
  "priority": 30,
  "last_activity": 1723567250.0
}
```

- **写入**：Runner 用 `HSET`
- **移除**：Collector 用 `HDEL`（判定终态后）

#### math:completed（List）

- **用途**：已完成的 attempt（含 `candidate_solved` 和 `answer_leak`）
- **元素**：JSON 字符串，包含 problem_key、exp_id、verdict、elapsed、solve_time_seconds 等
- **写入**：Collector 用 `LPUSH`

#### math:failed（List）

- **用途**：已失败的 attempt
- **元素**：JSON 字符串，同 completed 结构
- **写入**：Collector 用 `LPUSH`
- **读取**：Retry 用 `LRANGE`（扫描后选择性重试）

#### math:stats（Hash）

- **用途**：实时统计
- **字段**：`pending`、`running`、`completed`、`failed`、`updated_at`
- **更新**：Reporter 每轮调用 `update_stats`

#### math:config:concurrency / math:config:poll_interval（String）

- **用途**：实时可调的 Runner 配置
- **读取**：Runner 每轮 poll 时读取，无需重启即生效
- **修改**：`pipe_control.py concurrency 50` 或直接 `redis-cli SET`

### 队列操作 API

<ref_file file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/redis_queue.py" />

| 函数 | 用途 |
|---|---|
| `enqueue_pending(r, key, priority)` | 入 pending 队列 |
| `dequeue_pending(r, count)` | 从 pending 取题（ZPOPMIN） |
| `add_running(r, attempt_id, metadata)` | 加入 running |
| `get_all_running(r)` | 获取所有 running |
| `remove_running(r, attempt_id)` | 从 running 移除 |
| `add_completed(r, result)` | 加入 completed |
| `add_failed(r, result)` | 加入 failed |
| `pending_count/running_count/completed_count/failed_count` | 各队列计数 |
| `update_stats(r)` | 更新 stats |
| `clear_all(r)` | 清空所有队列（dry-run 测试用） |

## 3.3 ArangoDB 集合详解

### 连接配置

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/runner.py" lines="32-37" />

- Host: `http://localhost:8529`
- DB: `xishujuzhen_math_glm52`
- User: `root`
- Collection（题目）: `problem_extraction_progress`
- Collection（attempt）: `devin_problem_runs`

### problem_extraction_progress 集合

存储题目元数据，每道题一条记录。

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `_key` | string | 题目唯一 ID | `oda_math_12345` |
| `problem_text` | string | 题目文本 | `Find the minimum of...` |
| `answer` | string | 标准答案（可能为空） | `42` |
| `solution_text` | string | 标准解答（可能为空） | `By AM-GM...` |
| `extraction_status` | string | 处理状态 | `pending`/`queued`/`completed`/`failed` |
| `difficulty_tier` | int | 难度分层 | 1/2/3 |
| `priority` | int | 入队优先级（越小越先） | 10-100 |
| `source_dataset` | string | 来源数据集 | `deepmath_103k`/`oda_math`/`polymath` |
| `difficulty_score` | float | 难度评分 | 8.0-10.0 |
| `problem_hash` | string | 题目哈希（去重用） | `a1b2c3...` |

**状态流转**：
```
pending → queued → (Runner 启动后) → 
  candidate_solved → completed
  基础设施失败 → pending（回退，可重试）
  模型能力失败 → failed
```

### devin_problem_runs 集合

存储每次解题 attempt 的记录。

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `_key` | string | attempt ID | `pipe_p1a2b3c4d5...` |
| `batch_id` | string | 批次标识 | `pipe-runner` |
| `problem_id` | string | 关联的题目 _key | `oda_math_12345` |
| `exp_id` | string | 实验 ID | `p1a2b3c4d5e6f7g8h9i0` |
| `tmux_session` | string | tmux session 名 | `harness-p1a2b3...` |
| `status` | string | 运行状态 | `running`/`candidate_solved`/`failed` |
| `verdict` | string | 终态判定 | `candidate_solved`/`failed_timeout`/... |
| `model` | string | 模型名 | `glm-5.2-high` |
| `started_at` | string | 开始时间（ISO） | `2026-08-13T10:00:00Z` |
| `ended_at` | string | 结束时间（ISO） | `2026-08-13T10:15:30Z` |
| `runtime_seconds` | int | 总运行时长 | `930` |
| `solve_time_seconds` | float | 精确解题时间 | `850.5` |
| `solve_time_source` | string | 解题时间来源 | `tmux_pipe.log mtime` |
| `init_overhead_seconds` | float | 初始化开销 | `30.2` |
| `truncated_stall_seconds` | float | token_limit 卡住时间 | `120.0` |
| `pane_snapshot` | string | pane 快照路径 | `/data/.../collector/pane_snapshot.txt` |
| `end_reason` | string | 结束原因 | `collector判定: failed_timeout` |

**审计字段**：`solve_time_seconds`、`solve_time_source`、`pane_snapshot`、`init_overhead_seconds`、`truncated_stall_seconds` 是事后审计的物理证据定位信息。

详见 <ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/collector.py" lines="470-533" />。

## 3.4 文件系统布局

```
/data/math-agent-glm5.2-tmux-agents-trajectory/
├── _pipe/                          # 管道化系统工作目录
│   ├── logs/                       # 统一日志目录
│   │   ├── feeder.log
│   │   ├── runner.log
│   │   ├── collector.log
│   │   ├── reporter.log
│   │   ├── retry.log
│   │   └── pipe.log                # 统一日志（所有模块）
│   └── problems/                   # 题目文件目录
│       └── {exp_id}/
│           ├── AGENTS.md           # 注入给 Devin CLI 的题目+约束
│           └── launch.log          # 启动日志
│
├── {exp_id}/                       # 每次解题的 trajectory 目录
│   ├── tmux/
│   │   └── tmux_pipe.log           # Devin CLI 完整 stdout（-p 模式）
│   ├── sessions_db/
│   │   └── *.db                    # Devin CLI 的 sessions.db（SQLite）
│   ├── exports/
│   │   └── conversation.json       # Devin CLI 的 export（ATIF 格式）
│   └── collector/
│       ├── pane_snapshot.txt       # Collector 保存的原始 pane 内容
│       └── pane_snapshot_clean.txt # 清理 ANSI 后的 pane 内容
│
└── (旧版系统的其他目录)
```

### 关键文件说明

| 文件 | 作用 | 谁写入 | 谁读取 |
|---|---|---|---|
| `problems/{exp_id}/AGENTS.md` | 题目文本+解题约束 | Runner | Devin CLI |
| `{exp_id}/tmux/tmux_pipe.log` | Devin CLI 完整输出 | solver_harness.py | Collector（终态判定） |
| `{exp_id}/sessions_db/*.db` | Devin CLI session 数据 | Devin CLI | Collector（工具调用检查） |
| `{exp_id}/exports/conversation.json` | ATIF 格式对话导出 | Devin CLI 退出时 | extract_solve_time.py |
| `{exp_id}/collector/pane_snapshot.txt` | 终态判定时的 pane 快照 | Collector | 事后审计 |

### 日志规范

<ref_file file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/shared_logger.py" />

- 日志目录：`/data/math-agent-glm5.2-tmux-agents-trajectory/_pipe/logs/`
- 单文件分片：1MB
- 总量限制：10GB（约 10000 个分片）
- 循环滚动：达到上限后覆盖最老的文件
- 格式：`[时间] [级别] [模块] 消息`
- 同时输出到文件和 stdout（方便 tmux 中查看）
