# 04 · 服务详解

## 4.1 Feeder — 选题入队

### 职责

从 ArangoDB 的 `problem_extraction_progress` 表按 tier 选题，写入 Redis `math:pending` 队列。

### 工作流程

1. 按 `difficulty_tier` 和 `extraction_status='pending'` 查询 ArangoDB
2. 按 `priority ASC, _key ASC` 排序，取一批（默认 100 题）
3. 用 `ZADD` 写入 Redis `math:pending`（score=priority）
4. 更新 ArangoDB 中 `extraction_status` 为 `queued`
5. 持续运行，当 pending 队列低于 `low_water_mark` 时补充

### 关键代码

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/feeder.py" lines="36-60" />

### 命令行参数

```bash
python feeder.py --tier 1 --batch-size 100 --limit 500
python feeder.py --tier 1,2,3 --batch-size 1000 --low-water-mark 100
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--tier` | 1 | 难度分层，逗号分隔 |
| `--batch-size` | 100 | 每批查询题数 |
| `--limit` | 0（无限） | 总入队上限 |
| `--low-water-mark` | 50 | pending 低于此值时补充 |

### 注意事项

- Feeder 是**轻量级**服务——主要时间在等 ArangoDB 查询
- `auto-restart=True`——退出后 5 秒自动重启
- 不会重复入队——只查 `extraction_status='pending'` 的题

## 4.2 Runner — 启动 Devin CLI

### 职责

从 Redis `math:pending` 取题，启动 Devin CLI，维持固定并发数。

### 工作流程

1. 每轮 poll 读取 `math:config:concurrency`（实时可改）
2. 计算 `slots = concurrency - current_running`
3. 用 `ZPOPMIN` 从 pending 取 `slots` 个题
4. **阶段1（串行预处理）**：读题目文本、检查答案泄漏、写 AGENTS.md
5. **阶段2（串行启动）**：逐个启动 Devin CLI，**每 3 秒一个**（铁律）
6. 创建 ArangoDB attempt 记录，写入 Redis `math:running`

### 3 秒启动间隔（铁律）

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/runner.py" lines="306-334" />

**不可修改**。并行启动 60 个 session 会导致 58/60 个遇到 rate limit。3 秒间隔意味着填满 60 并发需要 180 秒（3 分钟）——这是正常的，不是 bug。

详见 [08-并发与性能.md](08-并发与性能.md)。

### 答案泄漏预检

Runner 在启动前检查题目文本是否包含答案：

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/runner.py" lines="265-300" />

- 检查 `answer` 字段值是否出现在 `problem_text` 中（长答案 >10 字符才查）
- 检查 `solution_text` 前 100 字符是否出现在 `problem_text` 中
- 发现泄漏 → 直接标记 `answer_leak_in_input`，不入 running

### AGENTS.md 模板

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/runner.py" lines="61-86" />

注入四条约束：不用工具、输出 PROOF COMPLETE、放弃时说 I CANNOT SOLVE、泄漏时说 ANSWER LEAK DETECTED。

### 命令行参数

```bash
python runner.py --concurrency 30
python runner.py --concurrency 3 --dry-run  # 不启动 Devin CLI
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--concurrency` | 30 | 并发数（可被 Redis 配置覆盖） |
| `--poll-interval` | 5 | 检查间隔秒数 |
| `--model` | glm-5.2-high | 模型名 |
| `--dry-run` | False | 不启动 Devin CLI |
| `--print-mode` | True | `-p` 模式（输出完自动退出） |

### 实时配置读取

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/runner.py" lines="204-217" />

Runner 每轮 poll 从 Redis 读取 `math:config:concurrency` 和 `math:config:poll_interval`，实时生效，无需重启。

## 4.3 Collector — 状态收集与判定

### 职责

扫描 Redis `math:running` 队列，用"眼见为实"原则检测 Devin CLI 终态，写回 DB。

### 工作流程

1. 每轮 poll 获取所有 running attempt
2. 对每个 attempt：
   - 检查 tmux session 是否存在
   - `capture-pane` 抓取 pane 文本（500 行）
   - 读 `tmux_pipe.log`（完整输出）
   - 调用 `classify()` 判定终态
3. 终态确定后：
   - 保存 pane 快照（物理证据）
   - 等待 export 落盘（最多 120 秒）
   - 提取精确解题时间
   - 更新 ArangoDB
   - 移除 Redis running 记录
   - kill tmux session

### 终态判定逻辑（classify 函数）

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/collector.py" lines="292-413" />

判定优先级（从高到低）：

1. **answer_leak** — 检测到 `ANSWER LEAK DETECTED` 标记
2. **ai_gave_up** — 检测到 `I CANNOT SOLVE` / `无法解决` 等放弃标记
3. **candidate_solved** — 检测到真实 PROOF COMPLETE + 无工具调用
4. **failed_token_limit** — 检测到 `Send a message to continue` / `Response truncated`
5. **rate_limited** — 检测到 `429` / `Too Many Requests`
6. **failed_timeout** — 超过 timeout（默认 1800 秒）
7. **failed_no_proof** — session 结束但无 proof 也无错误标记
8. **dead_session** — pipe.log 中有 `DEVIN_CLI_EXITED` 但无 proof
9. **failed_stall** — 超过 stall_time（默认 300 秒）且无活动
10. **failed_thinking_spin** — 超时且仍在 thinking
11. **failed_connection** — 检测到连接错误标记
12. 未结束 → 继续等待

### 真实 proof 验证

`has_real_proof()` 函数验证 proof 真实性：

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/collector.py" lines="173-239" />

1. 用 `find_ai_proof_marker()` 找到 PROOF COMPLETE 标记（排除提示词中的）
2. 提取 marker 前后的 proof 内容，过滤 TUI UI 元素
3. proof 内容 ≥100 字符
4. 包含 ≥2 个数学推理标记（`\frac`、`therefore`、`hence`、`因此`、`故`等）

### 工具调用检查

`check_tool_use()` 查 sessions.db 的 `message_nodes` 表：

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/collector.py" lines="252-289" />

- 查 `type LIKE '%tool%' OR role LIKE '%tool%'`
- 有工具调用 → `invalid_tool_use`（即使有 proof 也不算成功）

### export 落盘保证

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/collector.py" lines="643-721" />

- **-p 模式**：等 Devin CLI 自动退出（检测 `DEVIN_CLI_EXITED` 标记），最多 120 秒
- **交互模式**：三阶段保证（等 Ask Devin → Ctrl-C → 等 export）
- **基础设施失败**：跳过 export 等待（异常退出不会写 export）

### 命令行参数

```bash
python collector.py --poll-interval 10 --timeout 1800
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--poll-interval` | 10 | 轮询间隔秒数 |
| `--timeout` | 1800 | 超时秒数（30 分钟） |
| `--stall-time` | 300 | stall 判定秒数（5 分钟） |
| `--dry-run` | False | 不实际判定 |

## 4.4 Reporter — 统计报告

### 职责

定时从 Redis 读统计，输出进度报告和告警。

### 工作流程

<ref_file file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/reporter.py" />

1. 每轮（默认 60 秒）调用 `update_stats(r)`
2. 计算完成速率、ETA
3. 输出报告到日志和 stdout
4. 告警检测：
   - `running=0 且 pending>0` → Runner 可能挂了
   - `failed>0 且 success_rate<50 且 done>10` → 失败率过高

### 命令行参数

```bash
python reporter.py --interval 60
```

## 4.5 Retry — 基础设施失败重试

### 职责

扫描 Redis `math:failed` 队列，将基础设施失败的题重新入 `math:pending`。

### 失败分类

<ref_snippet file="~/master-mind-glm5.2-worktree/xishujuzhen/solver_harness/pipe/retry_infrastructure.py" lines="36-44" />

- **基础设施失败（重试）**：`failed_connection`、`rate_limited`、`launch_error`、`dead_session`
- **模型能力失败（不重试）**：`failed_token_limit`、`failed_output_limit`、`ai_gave_up`、`failed_thinking_spin`、`failed_no_proof`、`failed_stall`、`invalid_tool_use`

### 重试次数限制

查询 ArangoDB 中该题已有的基础设施失败次数，超过 `max_retries`（默认 3）则不再重试。

### 命令行参数

```bash
python retry_infrastructure.py --max-retries 3
python retry_infrastructure.py --once  # 执行一次后退出
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--max-retries` | 3 | 最大重试次数 |
| `--interval` | 120 | 扫描间隔秒数 |
| `--once` | False | 执行一次后退出 |
| `--dry-run` | False | 只检查不修改 |
