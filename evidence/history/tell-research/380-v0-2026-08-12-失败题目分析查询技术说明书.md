## 2. 失败题目的数据存储

失败题目分布在三个位置，需要交叉查询：

### 2.1 ArangoDB `devin_problem_runs`集合（主数据源）

每次Devin CLI运行一条记录，`_key`格式为`pipe_{exp_id前40字符}`。

**关键字段**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `_key` | string | 记录主键，格式`pipe_{exp_id}` |
| `problem_id` | string | 题目ID，对应`problem_extraction_progress._key` |
| `exp_id` | string | 实验ID，用于定位trajectory文件 |
| `tmux_session` | string | tmux session名，格式`harness-{exp_id}` |
| `status` | string | 终态状态（见下方分类表） |
| `verdict` | string | 终态判定（见下方分类表） |
| `started_at` | string | 启动时间（ISO格式UTC） |
| `ended_at` | string | 结束时间（ISO格式UTC） |
| `runtime_seconds` | int | 总运行时长（秒） |
| `solve_time_seconds` | float | 精确解题时间（秒，从tmux_pipe.log提取） |
| `solve_time_source` | string | 解题时间数据源 |
| `init_overhead_seconds` | float | 初始化开销（秒） |
| `pane_snapshot` | string | pane快照文件路径（物理证据） |
| `end_reason` | string | 终态原因描述 |
| `model` | string | 模型名（`glm-5.2-high`） |
| `batch_id` | string | 批次ID（`pipe-runner`） |

### 2.2 Redis `math:failed`队列（快速访问）

Collector判定失败后将摘要信息推入Redis `math:failed`队列（List类型）。

**字段**：

| 字段 | 说明 |
|---|---|
| `problem_key` | 题目ID |
| `exp_id` | 实验ID |
| `verdict` | 失败分类 |
| `elapsed` | 运行时长（秒） |
| `attempt_key` | ArangoDB记录的`_key` |
| `tmux_session` | tmux session名 |
| `export_missing` | bool，是否缺少export文件 |
| `solve_time_seconds` | 解题时间 |
| `solve_time_source` | 时间数据源 |

### 2.3 文件系统（物理证据）

每个实验的trajectory数据在`/data/math-agent-glm5.2-tmux-agents-trajectory/{exp_id}/`下：

```
{exp_id}/
├── collector/
│   ├── pane_snapshot.txt          # Collector判定终态时的完整tmux pane内容（最重要——AI输出的原始证据）
│   └── pane_snapshot_clean.txt    # 清理ANSI后的版本
├── exports/
│   └── conversation.json          # Devin CLI导出的完整对话（含steps+token统计）

├── tmux/
│   ├── tmux_pipe.log              # tmux pipe-pane原始流（raw，含ANSI）
│   └── tmux.log                   # tee输出（可能为空）

```

**注意**：失败题目可能缺少部分文件——`export_missing`的题没有`exports/conversation.json`，`dead_session`的题所有文件都可能为空。

## 3. 失败分类详解

### 3.1 完整verdict分类表

| status | verdict | 含义 | 计入Profile | 是否重试 |
|---|---|---|---|---|
| `candidate_solved` | `candidate_solved` | AI输出PROOF COMPLETE+有证明内容 | ✅ | - |
| `failed_token_limit` | `failed_token_limit` | AI输出达到max token limit（25000），被截断 | ✅ | ❌ |
| `failed_thinking_spin` | `failed_thinking_spin` | 超时且仍在thinking中（30分钟未完成） | ✅ | ❌ |
| `failed_stall` | `failed_stall` | 长时间无活动（5分钟stall） | ✅ | ❌ |
| `failed_timeout` | `failed_timeout` | 超时（30分钟）但不在thinking | ✅ | ❌ |
| `failed_no_proof` | `failed_no_proof` | session结束但无PROOF COMPLETE也无错误标记 | ✅ | ❌ |
| `ai_gave_up` | `ai_gave_up` | AI主动放弃（输出"I CANNOT SOLVE"等） | ✅ | ❌ |
| `answer_leak` | `answer_leak` | AI检测到题目包含答案，拒绝解答 | ❌ | ❌ |
| `answer_leak_in_input` | `answer_leak_in_input` | Runner启动前检测到题目包含答案 | ❌ | ❌ |
| `rate_limited` | `rate_limited` | API限流（429错误） | ❌ | ✅ |
| `dead_session` | `dead_session` | tmux session在但pane空白（devin cli 0字节退出） | ❌ | ✅ |
| `dead_session` | `export_missing` | devin cli完成但export文件未生成 | ❌ | ❌ |
| `invalid_tool_use` | `invalid_tool_use` | 有PROOF COMPLETE但检测到工具调用 | ❌ | ❌ |

### 3.2 两大类别

**模型能力失败**（计入Profile，不重试）：
- `failed_token_limit`——AI输出太长被截断
- `failed_thinking_spin`——AI思考30分钟未完成
- `failed_stall`——AI卡住5分钟无活动
- `failed_timeout`——AI超时
- `failed_no_proof`——AI没做完就结束了
- `ai_gave_up`——AI主动放弃

**基础设施失败**（不计入Profile，可重试）：
- `rate_limited`——API限流
- `dead_session`——devin cli 0字节退出（可能是rate limit或连接错误）
- `export_missing`——export文件未生成

**无效数据**（不计入Profile，不重试）：
- `answer_leak`——题目包含答案
- `answer_leak_in_input`——Runner检测到答案泄漏
- `invalid_tool_use`——违规使用工具

## 4. 查询方法

### 4.1 查询所有失败题目（ArangoDB AQL）

```python
from arango import ArangoClient
client = ArangoClient(hosts='http://localhost:8529', request_timeout=300)
db = client.db('xishujuzhen_math_glm52', username='root', password='REDACTED-DB-PASSWORD')

# 所有失败题目（排除candidate_solved和running）
cursor = db.aql.execute('''
FOR a IN devin_problem_runs
  FILTER a.batch_id == 'pipe-runner'
  FILTER a.status != 'candidate_solved' AND a.status != 'running'
  SORT a.ended_at DESC
  RETURN {
    problem_id: a.problem_id,
    exp_id: a.exp_id,
    status: a.status,
    verdict: a.verdict,
    runtime: a.runtime_seconds,
    solve_time: a.solve_time_seconds,
    started_at: a.started_at,
    ended_at: a.ended_at,
    pane_snapshot: a.pane_snapshot
  }
''', ttl=60)
for rec in cursor:
    print(rec)
```

### 4.6 交叉查询：失败题目+原始题面+AI输出

```python
from arango import ArangoClient
from pathlib import Path
import json

client = ArangoClient(hosts='http://localhost:8529', request_timeout=300)
db = client.db('xishujuzhen_math_glm52', username='root', password='REDACTED-DB-PASSWORD')
TRAJ = Path('/data/math-agent-glm5.2-tmux-agents-trajectory')

# 查询所有模型能力失败的题目
cursor = db.aql.execute('''
FOR a IN devin_problem_runs
  FILTER a.batch_id == 'pipe-runner'
  FILTER a.verdict IN ['failed_token_limit', 'failed_thinking_spin', 'failed_stall',
                       'failed_timeout', 'failed_no_proof', 'ai_gave_up']
  SORT a.ended_at DESC
  RETURN a
''', ttl=60)

for rec in cursor:
    eid = rec['exp_id']
    pk = rec['problem_id']
    
    # 1. 获取题面
    prob = db.collection('problem_extraction_progress').get(pk)
    problem_text = prob.get('problem_text', '') if prob else ''
    answer = prob.get('answer', '') if prob else ''
    
    # 2. 读取AI输出（pane_snapshot——AI在tmux中的原始输出）
    snap_path = rec.get('pane_snapshot', '')
    ai_output = ''
    if snap_path and Path(snap_path).exists():
        ai_output = Path(snap_path).read_text(encoding='utf-8', errors='ignore')
    
    # 3. 读取export（如果有——完整的对话记录）
    export_path = TRAJ / eid / 'exports' / 'conversation.json'
    agent_message = ''
    token_stats = {}
    if export_path.exists():
        conv = json.loads(export_path.read_text())
        for step in conv.get('steps', []):
            if step.get('source') == 'agent':
                agent_message = step.get('message', '')
                break
        token_stats = conv.get('final_metrics', {})
    
    # 现在你有了：题面、AI输出、token统计
    print(f'=== {pk} verdict={rec["verdict"]} runtime={rec.get("runtime_seconds",0)}s ===')
    print(f'题面: {problem_text[:200]}...')
    print(f'AI输出长度: {len(ai_output)}字符')
    print(f'agent消息长度: {len(agent_message)}字符')
    print(f'token统计: {token_stats}')
    print()
```

## 5. 关键文件解读

### 5.1 pane_snapshot.txt（最重要的证据）

这是Collector判定终态时用`tmux capture-pane -S -2000`抓取的tmux pane完整内容。包含AI的所有输出——thinking过程、证明内容、错误信息。

**如何判断失败原因**：
- 搜索`PROOF COMPLETE`——AI是否完成了证明
- 搜索`I CANNOT SOLVE`/`无法`/`做不出来`——AI是否主动放弃
- 搜索`token limit`/`Send a message to continue`——是否达到token限制
- 搜索`Thinking`——AI是否还在思考中
- 搜索`ANSWER LEAK DETECTED`——AI是否检测到答案泄漏
- 搜索`Connection error`/`unavailable`/`429`——是否有网络错误
- 看末尾内容——AI最后在做什么

### 5.2 conversation.json（完整对话记录）

Devin CLI导出的ATIF格式对话记录。

**结构**：
```json
{
  "schema_version": "ATIF-v1.7",
  "session_id": "...",
  "agent": {"name": "devin", "version": "...", "model_name": "GLM-5.2 High", ...},
  "steps": [
    {"step_id": 1, "source": "system", "message": "You are Devin..."},
    {"step_id": 2, "source": "system", "message": "..."},
    ...
    {"step_id": 8, "source": "agent", "message": "AI的完整证明/输出"}
  ],
  "final_metrics": {
    "total_prompt_tokens": 22473,
    "total_completion_tokens": 25000,
    "total_cached_tokens": 12398,
    "total_steps": 8
  }
}
```

**关键字段**：
- `steps`中`source=agent`的`message`是AI的完整输出（证明内容）
- `final_metrics.total_completion_tokens`——如果=25000说明达到token limit
- `final_metrics.total_prompt_tokens`——输入token数

### 5.3 tmux_pipe.log（原始流）

tmux pipe-pane的raw输出，包含ANSI转义序列。用于事后审计和activity_signature分析。比pane_snapshot更完整（pane_snapshot有2000行上限），但需要清理ANSI才能读。

## 6. 分析建议

### 6.1 失败模式分析框架

对每类失败，建议分析以下维度：

**failed_token_limit**（AI输出被截断）：
- 题面复杂度（题面长度、涉及的数学领域）
- AI输出到多少token时被截断（看completion_tokens）
- AI在被截断前做了什么（看pane_snapshot末尾——是在写证明还是在反复思考）
- 是否有重复输出模式（AI在循环输出相似内容）

**failed_thinking_spin**（思考30分钟未完成）：
- AI在思考什么（看pane_snapshot中的thinking内容）
- 是否在反复尝试同一种方法
- 是否在正确的方向上但时间不够
- 题目难度（difficulty_score）

**ai_gave_up**（AI主动放弃）：
- AI给出的放弃原因（看pane_snapshot中"I CANNOT SOLVE"附近的内容）
- 放弃前尝试了什么方法
- 题目是否真的超出了GLM-5.2的能力

**failed_no_proof**（没做完就结束）：
- session为什么结束（看pipe.log末尾——是devin cli崩溃还是网络错误）
- pane中有多少内容（AI做了多少工作就中断了）

### 6.2 区分"真做不出来"和"基础设施问题"

**真做不出来**（AI能力边界）：
- pane_snapshot中有大量thinking内容
- AI尝试了多种方法但都没成功
- AI主动输出"I CANNOT SOLVE"
- AI输出达到token limit但证明不完整

**基础设施问题**（不是AI的错）：
- pane_snapshot为空或极短（<100字符）
- pipe.log中有`Connection error`/`unavailable`/`429`
- export_missing（devin cli完成但export没写）
- dead_session（devin cli 0字节退出）

### 6.3 批量分析脚本模板

```python
#!/usr/bin/env python3
"""批量分析失败题目"""
from arango import ArangoClient
from pathlib import Path
import json
from collections import defaultdict

client = ArangoClient(hosts='http://localhost:8529', request_timeout=300)
db = client.db('xishujuzhen_math_glm52', username='root', password='REDACTED-DB-PASSWORD')
TRAJ = Path('/data/math-agent-glm5.2-tmux-agents-trajectory')

# 1. 查询所有失败题目
cursor = db.aql.execute('''
FOR a IN devin_problem_runs
  FILTER a.batch_id == 'pipe-runner'
  FILTER a.verdict IN ['failed_token_limit', 'failed_thinking_spin', 'failed_stall',
                       'failed_timeout', 'failed_no_proof', 'ai_gave_up']
  SORT a.verdict, a.ended_at DESC
  RETURN a
''', ttl=120)

# 2. 逐条分析
results = defaultdict(list)
for rec in cursor:
    eid = rec['exp_id']
    pk = rec['problem_id']
    verdict = rec['verdict']
    
    # 获取题面
    prob = db.collection('problem_extraction_progress').get(pk)
    problem_text = prob.get('problem_text', '') if prob else ''
    difficulty = prob.get('difficulty_score', 0) if prob else 0
    topic = prob.get('topic', '') if prob else ''
    
    # 读取AI输出
    snap_path = rec.get('pane_snapshot', '')
    ai_output = Path(snap_path).read_text(encoding='utf-8', errors='ignore') if snap_path and Path(snap_path).exists() else ''
    
    # 读取export
    export_path = TRAJ / eid / 'exports' / 'conversation.json'
    agent_msg = ''
    completion_tokens = 0
    if export_path.exists():
        conv = json.loads(export_path.read_text())
        for step in conv.get('steps', []):
            if step.get('source') == 'agent':
                agent_msg = step.get('message', '')
                break
        completion_tokens = conv.get('final_metrics', {}).get('total_completion_tokens', 0)
    
    results[verdict].append({
        'problem_id': pk,
        'problem_text': problem_text[:500],
        'difficulty': difficulty,
        'topic': topic,
        'runtime': rec.get('runtime_seconds', 0),
        'solve_time': rec.get('solve_time_seconds', 0),
        'ai_output_len': len(ai_output),
        'agent_msg_len': len(agent_msg),
        'completion_tokens': completion_tokens,
        'ai_output_tail': ai_output[-300:] if ai_output else '',
        'agent_msg_tail': agent_msg[-300:] if agent_msg else '',
    })

# 3. 输出分析报告
for verdict, items in results.items():
    print(f'\n=== {verdict} ({len(items)}题) ===')
    for item in items:
        print(f'  {item["problem_id"]} difficulty={item["difficulty"]} topic={item["topic"]}')
        print(f'    runtime={item["runtime"]}s solve_time={item["solve_time"]}s tokens={item["completion_tokens"]}')
        print(f'    ai_output={item["ai_output_len"]}字符 agent_msg={item["agent_msg_len"]}字符')
        if item['ai_output_tail']:
            print(f'    AI输出末尾: {item["ai_output_tail"][:200]}')
        print()
```

## 8. 注意事项

1. **`verdict=null`的记录是running状态**——这些题还在运行中，不是失败，分析时排除`status=running`。
2. **`dead_session`有两条路径**——`verdict=dead_session`（devin cli 0字节退出）和`verdict=export_missing`（devin cli完成但export没写）。两者status都是`dead_session`。
3. **pane_snapshot可能为空**——`dead_session`和`export_missing`的pane_snapshot通常为空或极短。
4. **export文件可能不存在**——`export_missing`和`dead_session`的题没有`exports/conversation.json`。
5. **`rate_limited`的题会被重试**——如果重试成功了，`devin_problem_runs`中会有多条记录（同一`problem_id`不同`exp_id`），分析时注意去重。
6. **`answer_leak_in_input`的题没有运行devin cli**——Runner在启动前就检测到答案泄漏，这些题没有trajectory数据，只有ArangoDB记录。
7. **时间字段**——`started_at`/`ended_at`是UTC时间（ISO格式），`runtime_seconds`是`ended_at - started_at`，`solve_time_seconds`是从tmux_pipe.log提取的精确解题时间（可能小于runtime_seconds，因为包含启动开销和判定延迟）。
8. **completion_tokens=25000**——这是GLM-5.2的max token limit。如果`final_metrics.total_completion_tokens == 25000`，说明AI输出被截断了。
