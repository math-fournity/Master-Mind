## 0. 一句话结论

**非特化不是把一段trace“总结得更抽象”，而是对解题处境做一次“因果充分的取商”，再把所得等价类编译成可识别、可选择、可实例化、可执行、可终止、可组合、可归责、可验证、可持续学习的认知技能。**

用更紧凑的话说：

```text
非特化 = 因果归因
       + 不变量提取
       + 干扰因素取商
       + 适用边界学习
       + 认知技能编译
       + 运行时选择
       + 迁移与反事实验证
       + 版本化持续细化
```

371号已经把Tell推进到“method + critic + trigger + exit + case pack”的迁移工程对象。本轮进一步发现，仍有三个根本层次需要补齐：

1. **Tell族不应只是一条按Level排列的曲线，而应是一个多轴的候选假设格。**很多Tell彼此不可简单比较高低。
2. **Tell不应只被建模成方法说明，而应被建模成认知Option。**它必须有启动集、选择依据、参数槽、绑定规则、内部策略、终止条件、组合接口、归责接口和结果模型。
3. **Tell有效性不能只靠解题成功率判断，而要证明它在控制混杂后，确实改变了预期的推理过程，并在结构保持变换下维持作用。**

这三个补充分别回答：

- 非特化究竟学到了什么；
- 学到的东西怎样被未来AI真正调用；
- 我们怎样知道学到的是思维力而不是泄漏、偶然或提示强度。

## 1. 此前研究已经解决了什么

在继续扩展之前，先把此前结论压成一条连续思想链。

### 1.1 344号：去特化是Level提升，但Level不是精确刻度

344号建立了最基本的方向：

- trace是与源题绑定的具体脉络；
- 去特化就是剥离题目特有内容、提高泛化程度；
- “普通Tell”和“高Level Tell”只是连续谱系上的人为标签；
- 太具体不能迁移，太抽象不能操作。

这一步否定了“把trace换几个变量名就算学习”的做法。

### 1.2 345号：同一trace会产生Tell族，指导力通常非单调

345号不再要求从一条trace只生成一个Tell，而是承认多个泛化版本并存。它还指出，指导力不会随着抽象度单调增加：

- 过低Level只记住源题；
- 中间Level兼顾迁移与操作；
- 过高Level退化成口号。

这一步否定了“越抽象越高级、越值得存”的做法。

### 1.3 346号：峰值不能靠暴力枚举，要找本质关系

346号提出三步法：

1. 用最优解释追问这个trace为什么有价值；
2. 保留关系结构，剥离表面特征；
3. 检查未来AI能否据此做出具体操作。

这一步把“抽象”从文字改写变成关系结构选择。

### 1.4 347号：高Level可以靠流程化恢复操作性

347号区分一句话指示、思维流程引导和抽象标签，并修正了固定钟形曲线：

- 同一语义内容可以有不同提示形态；
- 高Level不必天然低指导力；
- 只要把高Level概念编译成逐步的认知流程，它仍能推动推理。

这一步否定了“高Level只能作为概念标签”的做法。

### 1.5 352号：三步法只是候选Tell生成法，不是完整协议

352号补入：

- 正触发和负触发；
- 退出条件；
- 执行型、判别型、对照型、检查型、生成型等功能；
- 搜索空间裁剪度；
- 等长、等强度对照；
- 失败归因。

这一步把Tell从静态提示词推进到受控策略。

### 1.6 353号：思维力本身也需要去重、分层和操作化

353号发现，26种思维力混合了父类、机制、策略和历史描述，于是提出多轴框架，并新增概率存在、规范固定、对偶证书、取商、量词博弈、反例压力、语义不变量命名等候选。

这一步说明：**非特化不仅作用于trace，也必须作用于“思维力名称”本身。**否则系统会把同一认知动作在不同历史语言中的名字误当成不同能力。

### 1.7 366/368号：Level不是标签，而是保持什么、改变什么的操作

出题研究进一步揭示：

- 从题面、技巧、解法骨架，到失败机制、命题机制、数学处境生成法，不是单纯抽象等级；
- 每一层都对应一组“保留哪些角色、替换哪些对象、怎样重建自然错路”的操作；
- 一座有效的同构之桥，保留的是角色关系和机制，不是表面相似。

这一步反过来告诉非特化Pipe：**Level必须由允许哪些变换来定义，而不能只靠语言感觉。**

### 1.8 371号：非特化是一套迁移工程

371号将非特化扩展为八个契约，并引入成功解释、anti-unification、version space、类比编码、迁移矩阵、脚手架、proof planning、critic、CEGAR、abstract interpretation、ILP、CBR和运行时提示策略。

它得到的最小结构是：

```text
Tell = invariant relation
     + method
     + critic
     + trigger boundary
     + exit condition
     + case pack
     + runtime strategy
     + refinement history
```

这是正确的第二阶段终点。本轮不是推翻它，而是把三个还隐含着的对象明确定义出来：

- 什么是不变量；
- 什么是可复用技能；
- 什么是因果有效性。

## 2. 重新定义非特化：因果充分的取商

### 2.1 trace不是可直接泛化的最小单位

一条完整trace同时含有：

- 当前数学处境；
- AI已经尝试过的路线；
- 某个可分叉但未分叉的位置；
- 后来采用的转向；
- 转向之后出现的中间结果；
- 最终成功或失败；
- 大量对成功没有因果作用的叙述噪声。

如果直接对整条trace做摘要，最容易学到的是“这份解答讲了什么”，而不是“哪一个认知动作在什么处境下改变了搜索状态”。

因此，非特化的输入不应只是整条trace，而应先切成一个个**分支事件**：

```text
分支事件 e = (
  转向前处境 s,
  已走路线 h,
  未探索分叉 b,
  采取的认知动作 a,
  转向后处境 s',
  可观察进展 delta,
  后续结果 y
)
```

这里最重要的不是最终答案，而是`a`是否造成了`delta`。

### 2.2 什么叫“取商”

数学中的取商，是把若干表面不同但在目标关系下等价的对象视为同一个对象。

对应到非特化：

- 变量重命名不应产生新Tell；
- 数字替换不应产生新Tell；
- 对象从集合换成图，如果角色关系和认知动作没有改变，可能仍属于同一Tell；
- 题面很像但关键失败机制不同，则不能被合并。

因此我们需要先声明一组“允许忽略的变换”：

```text
G_nuisance = {
  符号重命名,
  数值缩放,
  对象换壳,
  表示改写,
  领域迁移,
  次序重排,
  对偶化,
  ...
}
```

不同Tell允许忽略的变换不同。比如：

- 一个具体数论Tell只允许变量和数字变化；
- 一个中Level结构Tell允许对象系统变化，但保留操作角色；
- 一个高Level同构之桥Tell允许领域变化，但必须保留源对象、目标对象、翻译、可逆性和收益证书之间的关系。

**Level由允许忽略哪些变换共同决定。**这比“抽象感更高”更可操作。

### 2.3 什么叫“因果充分”

只在成功trace中反复出现的结构，不一定导致成功。它可能只是：

- 解答者的写作习惯；
- 某个领域常见符号；
- 成功后才补写的解释；
- 与真正关键动作高度相关但没有推动作用的伴随步骤。

所以一个候选Tell必须同时满足两种要求：

1. **充分性**：保留下来的信息足以让未来系统判断“此时采用哪类认知动作可能有用”。
2. **因果性**：该认知动作确实提高了产生预期中间进展的概率，而不只是和最终成功相关。

概念性地说，我们想找一个表示`z = phi(e)`，使它满足：

```text
不变性：对允许忽略的变换 g，phi(g·e) ≈ phi(e)
充分性：知道z后，仍能预测哪种认知动作会产生进展
选择性：负例和边界例不会被错误合并
压缩性：z不保留对决策无用的源题细节
可执行性：z能够实例化为未来AI的具体动作
```

这不是现成定理，而是本项目的目标定义。

### 2.4 非特化真正生成的是等价类，不是一句话

一个合格Tell代表的不是一条文本，而是一类分支事件：

```text
[e]_Tell = 所有满足同一适用边界、
           可采用同类认知动作、
           并产生同类进展信号的分支事件集合
```

自然语言提示只是这个等价类在运行时的一种渲染。

因此必须分开两个对象：

```text
TellCore    = 系统内部学到的可迁移认知技能
HintInstance = TellCore针对当前题、当前脉络、当前模型和当前预算的提示实例
```

这也重新解释333号的tell-hint多对多关系：

- 一个TellCore可以按不同强度、不同位置、不同功能渲染成多个hint；
- 同一句hint可能承载多个TellCore共享的通用控制动作；
- 非特化Pipe首先应优化TellCore，不能直接把“写出一句好提示”当成学习完成。

## 3. 非特化的完整需求：四层二十四项契约

371号的八个契约是正确骨架。进一步展开后，非特化至少有四层、二十四项需求。

## 3A. 从trace学习什么

### R1. 来源与谱系

必须知道Tell来自：

- 哪一道题；
- 哪一条正确或失败trace；
- 哪个分支事件；
- 哪个模型版本；
- 哪个提示环境；
- 哪种正确性审查。

没有谱系，就无法区分数学规律、模型习惯和提示模板造成的现象。

### R2. 分支事件切分

必须把长trace切成可归因事件，识别：

- 转向前状态；
- 未分叉位置；
- 实际动作；
- 转向后状态；
- 局部进展。

否则Tell会把前后无关步骤粘在一起，形成过长、过强、不可迁移的宏观摘要。

### R3. 因果贡献归因

必须区分：

- 必要动作；
- 促进动作；
- 仅仅伴随的动作；
- 成功后解释性补写；
- 可以删掉而不影响路线的动作。

这是防止“从成功解答中学到所有东西”的第一道门。

### R4. 对比集构造

单条成功trace最多产生一个假设。要形成知识，需要：

- 同机制正例；
- 表面不同正例；
- 表面相似负例；
- 差一个关键条件的边界例；
- 同题失败trace；
- 同动作但无进展的反例。

没有这些对比，系统只能猜不变量，不能知道边界。

### R5. 干扰因素声明

必须显式写出哪些变化应该被忽略，哪些变化会破坏Tell：

- 对象、符号、参数、领域、表示、目标、证书、步骤顺序；
- 哪些是nuisance；
- 哪些是mechanism-bearing feature。

这使“去掉表面特征”从口号变成可测试声明。

### R6. 认识论状态

候选Tell必须标记：

- 单trace假设；
- 多trace共同结构；
- 已有负例边界；
- 已验证近迁移；
- 已验证远迁移；
- 已有因果证据；
- 被反例修订或废弃。

系统不应把首次提炼结果直接当成稳定事实。

## 3B. Tell内部必须表示什么

### R7. 不变量内核

Tell必须说明真正保持不变的是：

- 对象角色；
- 关系结构；
- 操作顺序；
- 失败机制；
- 证据形态；
- 进展判据；
- 或它们的组合。

“使用极值原理”不是内核；“当局部约束难以同时控制时，选取极端对象，使所有邻接约束朝同一方向暴露”才接近内核。

### R8. 多轴抽象位置

Tell需要记录它在哪些轴上具体、在哪些轴上抽象，而不能只给一个Level：

- 对象特异性；
- 关系特异性；
- 操作特异性；
- 目标特异性；
- 触发特异性；
- 证书特异性；
- 时间跨度；
- 领域距离；
- 提示脚手架强度。

### R9. 适用边界

必须同时表示：

- 正触发；
- 负触发；
- 边界条件；
- 最小证据；
- 可拒绝状态。

非特化质量不仅由覆盖多少题决定，也由拒绝多少假朋友决定。

### R10. 参数槽与绑定规则

通用Tell不能把源题对象写死，但也不能完全没有对象。它需要参数化：

```text
<当前受阻的表示>
<候选替代表示>
<应保持的关系>
<期望出现的证书>
```

运行时系统必须知道怎样把当前题的对象绑定到这些槽位。没有绑定规则，“考虑对偶”“寻找不变量”仍然只是口号。

### R11. 内部认知策略

Tell必须说明AI实际做什么：

- 观察；
- 生成；
- 比较；
- 转换；
- 验证；
- 回退。

动作可以是一句话，也可以是层级化子任务，但不能只留下概念名。

### R12. 进展模型

Tell需要预测采用后应看到什么：

- 新对象；
- 新约束；
- 自由度下降；
- 复杂度下降；
- 可局部验证证书；
- 两条路线之间出现可比较量。

没有进展模型，就无法区分“AI执行了Tell”与“AI只复述了Tell”。

### R13. 终止条件

Tell必须规定：

- 成功终止；
- 无进展终止；
- 预算终止；
- 边界冲突终止；
- 被更高价值策略抢占。

退出条件不是附属字段，而是防止高Level空转的核心。

### R14. critic与修复

Tell必须知道常见错误形态：

- 误触发；
- 绑定错误；
- 操作执行不完整；
- 进展信号伪造；
- 局部成功但全局无效；
- 过度裁剪搜索空间。

critic需要给出诊断、局部补丁、fallback Tell或回到哪一层重新抽象。

### R15. 可组合性

真实数学解题很少只用一种思维力。Tell必须说明：

- 可与哪些Tell前后组合；
- 哪些Tell互斥；
- 谁是前置技能；
- 谁负责生成候选，谁负责检查证书；
- 组合后退出条件如何变化。

否则Tell库只能单条命中，不能形成真正的思维流程。

## 3C. 系统运行时怎样使用

### R16. 检索与识别

系统必须从当前thinking中识别：

- 当前数学处境；
- 已尝试路线；
- 可分叉位置；
- 正负触发证据；
- 应观察局部、非局部还是全局Level。

这与Tell分类学的排除功能直接对应。

### R17. 选择、排序与弃权

命中多个Tell时不能全部灌给Solver。选择器要估计：

- 适用概率；
- 预期进展；
- 负迁移风险；
- 提示成本；
- 与已有分支的重复度。

并且必须允许输出“证据不足，暂不提示”。弃权是高质量识别的一部分。

### R18. Hint实例化

同一TellCore需要根据：

- 当前题对象；
- 当前脉络；
- 分叉位置；
- Solver模型；
- 剩余预算；
- 已用过的提示；

生成不同HintInstance。Hint是上下文化编译结果，不是Tell本体。

### R19. 资源与位置控制

Tell需要决定：

- 放在根节点还是line分叉；
- 在首次提示、失败后critic还是事后反思注入；
- 用最低脚手架还是完整流程；
- 是否值得启动并行分支；
- 多久后检查进展。

这使提示成为计算资源分配问题。

### R20. 冲突与组合调度

如果多个Tell给出相反方向，系统要能：

- 并发展开；
- 根据证据排序；
- 先运行低成本判别Tell；
- 避免两个Tell互相抵消；
- 复用公共前缀。

非特化最终服务的是Grove树生长，而不是单次提示美学。

## 3D. 怎样验证和持续修正

### R21. 迁移距离验证

至少区分：

- 同题变体；
- 同域异对象；
- 异域同关系；
- 异域同失败机制；
- 表面相似结构不同；
- 完全不应触发。

“能用于三道题”不等于已经验证迁移，三道题可能仍在同一模板内。

### R22. 反泄漏与负迁移

必须同时测：

- 题目特定信息泄漏；
- 方法族泄漏；
- 搜索空间过度裁剪；
- 提示带来的错误自信；
- 在负例上造成的性能下降。

### R23. 过程因果归因

除了最终解题成功，还要观察：

- Tell是否被触发；
- 参数是否正确绑定；
- 指定认知动作是否出现；
- 预期进展信号是否出现；
- 进展是否中介了最终成功。

只有这条链出现，才能较有把握地说Tell激发了目标思维力。

### R24. 生命周期与漂移

Tell必须版本化记录：

- 新正例；
- 新负例；
- 边界收窄或放宽；
- prompt renderer变化；
- 不同模型上的效果；
- 模型升级后的失效；
- 合并、拆分、废弃原因。

一个Tell不是永久真理，而是带证据状态的可修订策略假设。

## 4. 学术界还能提供什么：五组二十八条应对路线

下面不是文献搜索结果，而是基于内在知识，把不同学术领域中与上述需求结构同构的方法系统地映射进来。

## 4A. 怎样学到“该保留什么”

### 路线A1：最小充分统计量、信息瓶颈与最小描述长度

这组理论共同处理一个问题：**怎样丢掉尽可能多的信息，同时保留完成目标所必需的信息。**

对非特化的直接启发是：

```text
好Tell不是最短，也不是最抽象；
而是对“选择下一认知动作”而言足够充分、
同时对源题表面细节依赖最小的表示。
```

可以把候选Tell的质量理解为：

```text
保留的决策信息
- 源题记忆
- 描述复杂度
- 泄漏风险
```

工程动作：

- 对Tell字段逐项消融，删掉后迁移效用不降则删除；
- 比较多个表达等价的Tell，优先更短但仍保持触发和操作能力的版本；
- 把提示token少误当成抽象好，必须同时看决策充分性。

这是对346号“保留关系、剥离表面”的形式化深化。

### 路线A2：因果表示与跨环境不变机制

相关学术思想强调：稳定可迁移的不是训练分布中的相关性，而是跨环境仍保持的机制。

对应到Tell：

- “成功解答里经常出现X”只是相关；
- “改变题面外壳后，X仍推动同类进展”才接近机制；
- “保持外壳但破坏关键关系后，X不再有效”进一步支持因果边界。

工程动作：

- 把同一机制放入多个题域环境；
- 主动干预表面特征、目标对象和常规入口；
- 只保留跨环境效应稳定的Tell内核；
- 把“结构保持变换有效、结构破坏变换失效”作为强证据。

这条路线直接补足371号成功解释图仍可能只解释相关性的缺口。

### 路线A3：Domain Generalization、稳健优化与最坏组风险

这组方法不只追求平均表现，而追求在不同环境、不同群组甚至最坏群组上的稳定性。

对应到Tell：

- 一个Tell在10道近同构题上成功、在1道远迁移题上崩溃，平均成功率可能仍很好；
- 但系统真正关心的是它在哪个迁移群组开始失效；
- 评价应看不同domain、不同surface、不同failure mechanism下的分组效果。

工程动作：

- 按迁移轴分组报告，不只报总体成功率；
- 优先修复最差迁移组；
- 对高风险Tell用最坏组效用而不是平均效用入库。

### 路线A4：对称性、等变性、取商与规范形

这是与“非特化”最本质同构的一条数学路线。

- **对称性**告诉系统哪些变化不应改变Tell身份；
- **等变性**告诉系统输入变化后，Tell参数应怎样对应变化；
- **取商**把等价trace事件合并；
- **规范形**从一个等价类中选出稳定代表，便于存储和检索。

工程动作：

```text
surface_transformations:
  - rename_symbols
  - rescale_parameters
  - dualize_roles
  - swap_domain_objects

binding_equivariance:
  输入对象变换后，Tell中的参数绑定应按同一角色变换

canonical_form:
  用“角色-关系-动作-证书”顺序存储，不保留源题叙述顺序
```

这条路线把353号C2“规范固定”和C5“取商”提升为非特化Pipe自身的核心操作。

### 路线A5：FCA、概念格、闭包与蕴含基

本项目已经采用FCA，但其价值不应只停留在给tell分类。对非特化本身，FCA还提供：

- **extent**：一个Tell假设实际覆盖哪些分支事件；
- **intent**：这些事件共同具有哪些固有属性；
- **闭包**：给定案例后，哪些属性是共同必然的；
- **概念格**：更具体与更一般Tell之间的偏序；
- **属性蕴含**：出现某组trigger时，通常还应具备哪些条件；
- **概念稳定性**：删掉少量案例后，这个概念是否仍存在。

关键修正是：

> Tell族更自然的结构不是一条Level直线，而是概念格中的一个局部子格。

有的Tell在对象轴更一般但在操作轴更具体；另一个Tell反过来。它们不可用单一Level比较，却能在偏序中表示。

### 路线A6：贝叶斯假设、层级模型与版本空间

371号已引入version space，本轮进一步强调**不确定性不能只写成状态标签，而应参与选择**。

同一trace可以支持多个Tell假设：

- H1：关键在换表示；
- H2：关键在构造证书；
- H3：关键在先固定规范代表；
- H4：三者组合才有效。

系统应保留候选及其证据权重，而不是由一次生成器判断唯一真相。

工程动作：

- 新正例提高兼容假设权重；
- 负例淘汰覆盖过宽假设；
- 边界例区分相邻假设；
- 跨题族共享证据，但保留题族特异差异；
- 运行时把不确定性纳入是否提示和是否并发。

### 路线A7：程序归纳、归纳逻辑编程与反例引导综合

如果Tell只有自然语言，难以判断两个版本是否真正不同。程序归纳路线建议先定义一个小型Tell语言：

```text
WHEN <state predicates>
BIND <role variables>
DO <cognitive operators>
UNTIL <progress or failure predicate>
VERIFY <certificate predicate>
ELSE <critic or fallback>
```

然后：

- 从正例综合候选程序；
- 用负例和反例排除错误程序；
- 对观察等价的程序合并；
- 只把最终程序渲染成自然语言hint。

这会把CEGAR式修订从文档流程推进为可执行的Tell综合。

## 4B. 怎样把Tell变成真正可复用技能

### 路线B1：分层强化学习中的Options

Options框架把一个可复用技能表示为：

```text
Option = (
  initiation set I,   # 在哪些状态可启动
  internal policy pi, # 启动后怎样行动
  termination beta    # 在哪些状态终止
)
```

这几乎精确对应本项目已经提出但尚未统一的字段：

```text
Tell Option = (
  trigger boundary,
  parameter binding,
  thinking procedure,
  progress model,
  exit condition,
  critic
)
```

它带来的核心修正是：

- 高Level思维力是Option模板；
- 低Level Tell是已经部分绑定的Option；
- HintInstance是Option在当前状态上的一次调用；
- Telling AI的任务是识别启动集并完成参数绑定；
- Solver执行后，系统根据终止条件判断继续、修复或回退。

这条路线是本轮最重要的新映射。它把“可操作化”从提示文风问题升级为技能表示问题。

### 路线B2：自动规划、STRIPS、HTN与宏操作

自动规划要求动作有前置条件和效果；层级任务网络把高Level任务分解成更低Level子任务；宏操作把反复出现的动作序列压缩成一个可复用单元。

对应到Tell：

- `precondition`说明何时可用；
- `parameters`说明需要绑定哪些数学角色；
- `method body`说明分解步骤；
- `effect`说明期待得到什么新处境；
- `failure condition`说明何时回退；
- `macro`说明哪些Tell序列值得整体复用。

这条路线主要解决R10、R11、R12和R15：参数绑定、执行、效果与组合。

### 路线B3：生产系统、impasse学习与chunking

经典认知架构中的生产规则通常形如“若处境满足条件，则执行动作”。一些架构还会在遇到impasse后，把成功解决impasse的推理编译成以后可直接触发的chunk。

这与Grove循环高度相似：

```text
分叉/impasse被识别
  → 新分支找到有效转向
  → 从转向前状态和成功路径中学习条件-动作规则
  → 下次在相似处境直接触发
```

它提醒我们两件事：

1. 学到的规则必须包含真正必要的状态条件，否则会过度泛化；
2. 也不能把整个源状态都写进条件，否则会退化成题目记忆。

这正是非特化的偏差-方差矛盾在认知架构中的版本。

### 路线B4：Hyper-heuristics与按实例算法选择

Hyper-heuristic不直接解决领域问题，而是在更高层选择或生成适合当前处境的低层启发式。按实例算法选择则根据问题特征，选择最可能有效的求解器或策略。

对应到本项目：

- Tell库是低层与中层认知启发式库；
- Telling AI是hyper-heuristic；
- 分类学提供筛选特征；
- 运行时选择器根据脉络状态挑选Tell；
- Grove分支允许保留多个候选而不强迫唯一选择。

重要启发：**非特化不仅要生成好Tell，还要学习“什么状态选择什么Tell”。**生成问题和选择问题必须分开评测。

### 路线B5：理性元推理与计算价值

一个策略可能适用，但不值得现在运行。理性元推理关心：再花一单位计算，预期能带来多少决策改进。

对Tell选择可以定义概念性效用：

```text
U(T | state, model, runtime)
  = 预期进展收益
  - 误触发损失
  - 提示成本
  - 分支启动成本
  - 与已有探索的重复成本
  - 泄漏风险惩罚
```

系统不应问“这个Tell是否相关”，还应问“现在注入它是否比继续观察、启动另一个分支或暂时弃权更值”。

### 路线B6：模型式诊断、冲突集与修复

故障诊断研究通常从观察到的异常，寻找最小冲突集和最小解释，再选择修复动作。

对应到Tell critic：

- 期望有新约束，实际没有；
- 可能原因是触发错、绑定错、操作错、证书错或题太难；
- 不应把所有失败都归为“Tell无效”；
- critic应寻找最小故障部件，并只修补必要部分。

这能把352号F1-F6失败归因推进到结构化诊断，而不只是结果标签。

## 4C. 怎样让迁移真的发生

### 路线C1：对比学习、概念获得与Variation Theory

共同思想是：学习者必须同时看到“什么变化了”和“什么保持不变”。

最强的Case Pack不是三个相似正例，而是一个对比四元组：

```text
P1：源题正例
P2：表面改变、机制保持的正例
N1：表面保持、机制破坏的硬负例
B1：只差一个必要条件的边界例
```

必要时再加：

```text
F1：异域远迁移正例
A1：带强诱饵的对抗负例
```

这种设计能让生成器真正看见“critical variation”，而不是凭语义相似度总结。

### 路线C2：交错练习、检索练习与条件化知识

知识能否迁移，不只取决于是否知道策略，还取决于是否知道何时检索它。把同类题连续呈现，容易学到“刚才用了什么”；把多类题交错呈现，才能学习“当前何时该用什么”。

对应到Tell验证：

- 不应只批量测试同一思维力题；
- 应把匹配题、近邻错配题和完全不匹配题交错；
- 评价识别端是否能在没有标签提示的情况下选择正确Tell；
- 把“策略知识”和“条件化检索知识”分开。

### 路线C3：类比编码、渐进对齐与schema induction

371号已引入这条路线。本轮补充一个关键点：远迁移通常不能靠一步从源题跳到远题，而需要从高表面相似例开始，逐步把注意力移动到关系相似。

这支持一种Tell学习课程：

```text
同壳同机制
  → 换壳同机制
  → 异对象同机制
  → 异域同机制
  → 表面相似但机制不同
```

每一步只改变少数维度，可以定位Tell在哪个迁移轴上失效。

### 路线C4：元学习、多任务学习与组合技能

元学习不只学习单个任务答案，而学习怎样用少量新案例快速适应。组合技能研究则关注能否把已学模块重新组合解决新任务。

对应到系统：

- 不应为每道新题从零生成Tell；
- 应学习可复用的trigger、binding、critic和renderer组件；
- 新Tell可以由旧组件组合而成；
- 少量边界例应足以调整适用范围，而不是重写全部文本。

这条路线的长期目标是“Tell生成器自己获得非特化能力”。

### 路线C5：Productive Failure与Preparation for Future Learning

一个提示不一定立即提高最终解题率，却可能让AI形成更好的表示、生成更有价值的失败分支，或为下一次提示准备条件。

这对Grove尤其重要，因为系统目标不是让单个AI一次做出，而是让两棵树生长并与正确脉络相遇。

因此Tell效用还应包括：

- 是否产生可复用的新节点；
- 是否暴露清晰失败原因；
- 是否让后续分支更容易检索到正确方向；
- 是否提高下一轮Tell的价值。

这修正了“只有本次成功才算有效”的短视评价。

## 4D. 怎样证明Tell真的有效

### 路线D1：随机化实验、因果中介与成分消融

最终成功只是终点变量。要证明Tell激发了目标思维力，需要检验完整链条：

```text
Tell注入
  → 目标trigger被识别
  → 指定认知动作出现
  → 预期中间进展出现
  → 最终成功概率变化
```

可以通过成分消融区分作用来源：

- 只有trigger；
- 只有method；
- 只有critic；
- trigger + method；
- method + critic；
- 完整Tell；
- 等长空流程；
- 等强度错配Tell。

如果只有完整Tell有效，说明组件协同重要；如果只有method就同样有效，则trigger或critic可能是冗余；如果等长空流程也有效，增益可能来自一般反思。

### 路线D2：Metamorphic Testing与性质驱动测试

很多Tell没有简单的“正确标签”，但可以声明变换前后应满足的关系：

- 变量重命名后，Tell选择不应改变；
- 表面外壳替换但机制保持时，Tell仍应触发；
- 破坏必要关系后，Tell不应触发；
- 对偶化后，参数绑定应按角色对应变化；
- 增加无关诱饵后，Tell效用不应大幅下降。

这种“变形关系”比随机找几道题更直接地检验非特化主张。

### 路线D3：构念效度、项目反应与差异项目功能

心理测量提醒我们：不能因为一个测试被命名为“对偶思维力题”，就认为它真的测到了对偶思维力。

对本项目的启发：

- 题目难度与Tell效应必须分开；
- 不同题是否共同测量同一潜在思维力，需要用跨题结果检查；
- 某题是否对特定prompt措辞异常敏感，需要识别；
- 不同模型上的Tell增益差异，可能是模型能力差异而不是Tell本体差异；
- 方差要拆成题目、Tell、模型、run和交互作用。

这意味着350号“每种思维力至少3题通过”只是初步规则，成熟阶段应采用层级统计或项目反应式模型，而不是固定阈值代替测量理论。

### 路线D4：Process Mining与conformance checking

系统已经拥有thinking trajectory和两棵树，这天然适合过程挖掘：

- 从多条trace中找反复出现的分支模式；
- 比较成功和失败路径的序列差异；
- 检查Solver是否按Tell定义的method执行；
- 发现预期流程外但有效的新变体；
- 将Tell从固定步骤升级为允许多种合法路径的过程模型。

这条路线可帮助系统从大量真实trajectory中学习，而不只靠人工阅读单条证明。

### 路线D5：对抗测试与假朋友生成

非特化最危险的不是漏掉一些正例，而是对大量表面相似题误触发。可以专门训练一个对抗生成器：

- 保留题面词汇，破坏机制；
- 保留机制名称，改变适用方向；
- 构造一个更短替代路线，使原Tell虽可用但不值得用；
- 制造会诱导错误参数绑定的对象；
- 制造Tell看似产生进展、实际不降低复杂度的伪进展。

这与353号C6量词博弈、C7反例压力形成直接对应。

## 4E. 怎样让Tell库长期成长而不腐化

### 路线E1：主动学习与实验设计

系统不应随机收集下一道题，而应选择最能区分当前候选Tell的案例。

优先测试：

- 两个Tell假设预测相反的题；
- 当前边界最不确定的题；
- 最差迁移组中的题；
- 可能暴露负迁移的题；
- 只改变一个关键属性的最小对照题。

这会把“继续出更多题”改成“出最有信息量的题”。

### 路线E2：持续学习、记忆巩固与概念漂移

Tell对某个模型版本有效，不代表对以后模型仍有效。模型能力增强后：

- 原先必要的脚手架可能变成冗余；
- 原先低泄漏的提示可能相当于直接给答案；
- 原先的bare失败题可能全部被解决；
- trigger行为和措辞敏感性可能改变。

因此Tell需要：

- 按模型版本记录效果；
- 定期重放代表性Case Pack；
- 对旧Tell做降强度、合并或退休；
- 保留历史版本和失效原因；
- 防止新案例覆盖掉旧边界知识。

### 路线E3：形式契约、运行时监控与安全降级

软件契约思想要求模块明确前置条件、后置条件和不变量。对应到Tell：

- trigger是前置条件；
- expected progress是后置条件；
- invariant kernel是执行中必须保持的关系；
- exit和critic是运行时监控；
- fallback是安全降级。

这条路线使Tell不仅可解释，也可由脚本检查部分运行状态。

### 路线E4：知识编译、缓存与多层表示

同一Tell不必只有一种存储形态：

- 语义核心用于推理和版本化；
- 规范化谓词用于检索；
- 高Level解释用于Telling AI理解；
- 低Level实例用于快速匹配；
- prompt renderer用于运行时注入；
- 统计摘要用于选择器估值。

这与高Level结构知识/低Level内容知识分离一致，但进一步强调：它们是同一技能对象的不同编译产物，不应被当成互不相关的文档条目。

### 路线E5：范畴化与自然性检查（长期、探索性）

这不是近期工程主线，但可作为跨域Tell的高Level数学判据：

```text
先翻译问题再应用方法
≈
先应用对应方法再翻译结果
```

如果两条路径在结构上“可交换”，跨域桥接更可能保留了真正机制；如果翻译后方法完全失去对应关系，所谓同构可能只是表面类比。

这条路线适合研究同构之桥、对偶、表示迁移，不适合作为当前所有Tell的强制字段。

## 5. 一个关键新发现：新增思维力也是非特化Pipe的操作符

353号新增的八种候选思维力，不只是未来要被非特化的“内容”，它们反过来组成了非特化方法本身。

| 候选思维力 | 在非特化Pipe中的元作用 |
|---|---|
| C1 概率存在与去随机化 | 在巨大Tell候选空间中先随机探索，再把稳定候选确定化 |
| C2 规范固定与对称破缺 | 为同一等价类选择稳定代表，避免重复存储 |
| C3 紧化/完备化 | 从有限Case Pack逐步逼近开放的高Level概念边界 |
| C4 对偶证书与不可行性证明 | 为Tell触发、成功和废弃建立可检查证书 |
| C5 取商与冗余压缩 | 把表面不同但机制相同的trace事件合并 |
| C6 对抗者量词博弈 | 主动寻找能击穿Tell边界的最坏负例 |
| C7 反例压力与定理修补 | 用失败案例收窄、拆分或修补Tell假设 |
| C8 语义不变量命名 | 发明能稳定描述跨题共同机制的新谓词和角色名 |

因此，非特化Pipe可以被理解为八种思维力的组合过程：

```text
C5取商
  → C2选规范代表
  → C8命名不变量
  → C4建立证书
  → C6生成对抗边界
  → C7用反例修补
  → C3从有限案例逼近开放边界
  → C1在候选空间中控制探索成本
```

这说明“寻找更多Powerful思维力”和“改进非特化”并不是两条独立任务线。思维力研究会直接提供非特化算法的元操作。

## 6. 对Tell族与钟形曲线的第三次修正

### 6.1 单一Level轴会压扁不可比较的Tell

考虑两个Tell：

- T1对数学对象非常通用，但操作写得很具体；
- T2只适用于图论对象，但操作流程高度通用。

谁的Level更高？没有唯一答案。

因此Level至少是一个向量：

```text
L(T) = (
  object_generality,
  relation_generality,
  operation_generality,
  goal_generality,
  trigger_generality,
  evidence_generality,
  temporal_span,
  domain_distance
)
```

提示形态和脚手架强度不是Tell语义Level本身，而是renderer维度，应另存。

### 6.2 Tell族更像假设格，不像一条直线

Tell之间可以存在：

- 一个比另一个在所有语义轴上更一般；
- 两者各自在不同轴更一般，彼此不可比；
- 两个Tell有共同上位概念；
- 一个高Level模板有多个不同实例化分支；
- 一个负例把原Tell拆成两个子概念。

这正是偏序和概念格，而不是线性Level。

保留“Level”作为人类直觉描述仍有价值，但系统内部不应依赖一个模糊标量完成检索、排序和版本细化。

### 6.3 “峰值”应改成上下文中的Pareto前沿

Tell质量至少包含：

- 触发准确率；
- 操作可执行性；
- 近迁移效用；
- 远迁移效用；
- 负迁移率；
- 提示成本；
- 泄漏风险；
- 可组合性；
- 模型适配性。

一个Tell可能远迁移强但成本高，另一个近迁移强且极便宜。两者都可能值得保留。

因此不应寻找一个全局“最优Level Tell”，而应保存当前证据下的Pareto前沿：没有另一个候选在所有重要指标上都更好。

### 6.4 指导力是情境效用，不是Tell固有常数

概念性地：

```text
U = f(
  TellCore,
  current_state,
  source_target_distance,
  solver_model,
  hint_renderer,
  injection_position,
  remaining_budget,
  competing_branches
)
```

所以同一Tell的指导力会随题目、模型和运行时变化。Tell本体应存“证据分布和适用范围”，而不是写一个固定的AI指导力分数。

## 8. 非特化Pipe V3：十五步闭环

### Step 0：冻结来源证据

保存题目、正确性、完整trace、模型、prompt、工具调用与运行环境，禁止成功后改写源数据。

### Step 1：切分分支事件

从长trace中抽取“处境—未分叉—认知动作—局部进展”单元，不直接摘要整份证明。

### Step 2：建立成功解释和替代解释

列出哪些动作可能导致进展，同时列出可能的混杂解释，避免一开始就锁定唯一故事。

### Step 3：构造对比四元组

至少准备源正例、换壳正例、同壳硬负例和单条件边界例。没有足够案例时，明确标记单trace假设。

### Step 4：声明允许变换与破坏变换

写清哪些变化不应影响Tell，哪些变化应使Tell失效。由此定义候选Level，而不是先拍一个Level数值。

### Step 5：生成Tell假设格

沿对象、关系、操作、目标、trigger、证书和时间跨度等轴生成少量相邻候选，并保留不可比较分支。

### Step 6：做因果充分压缩

消融候选字段，删除对动作选择和进展预测无贡献的源题信息；同时防止压缩过度导致不可操作。

### Step 7：编译为认知Option

为候选补齐启动集、参数槽、绑定规则、内部策略、进展模型、终止和critic。

### Step 8：建立组合关系

标记前置Tell、检查Tell、互斥Tell和常见宏序列，防止每条Tell成为孤岛。

### Step 9：生成HintRenderer族

分别生成低强度根提示、line分叉提示、失败后critic和完整流程脚手架。renderer与TellCore分版本。

### Step 10：执行变形与边界测试

用结构保持变换、结构破坏变换、诱饵和参数错绑测试不变量、等变性、拒绝能力和泄漏。

### Step 11：执行过程因果实验

记录trigger、绑定、目标动作、进展信号和最终成功；做组件消融和等长、等强度对照。

### Step 12：选择Pareto前沿入库

不是只留下成功率最高者，而是保留在迁移、成本、风险、可组合性上各有价值的非支配候选。

### Step 13：运行时选择与Grove展开

Telling AI识别启动条件；选择器估计效用；HintRenderer生成实例；脚本在根或line上开新边；随后按终止条件检查。

### Step 14：反例驱动持续细化

将误触发、漏触发、错绑定、无进展、泄漏和模型漂移分别用于收窄、放宽、拆分、合并、降强度或退休Tell。

## 9. 验证协议的再升级

### 9.1 从“5次bare全失败”改成基线分布

5次bare全失败是严格筛题门槛，但它不是稳定能力估计：

- 5次样本仍小；
- 它会偏向极难题；
- 可能把偶然失败当成稳定失败；
- 模型温度、工具使用和运行时差异会改变结果。

成熟验证应记录：

- bare成功概率估计；
- Tell条件成功概率估计；
- 增量效应及不确定性；
- 题目、模型和run层面的方差。

筛题阶段仍可保留5/5失败作为工程门槛，但科学结论不能只靠这条门槛。

### 9.2 不再要求证明“只有这种思维力能解决”

数学题通常有多条路线，“唯一思维力”很难成立，也很难验证。更合适的主张是：

> 在控制提示长度、一般反思、方法强度和题目难度后，这个Tell对预期推理机制产生可重复的增量因果贡献，并且该贡献能跨指定迁移距离保持。

这比“只有它能解”更窄，也更可证伪。

### 9.3 标准对比包

每个Tell至少需要：

| 类别 | 目的 |
|---|---|
| P-source | 源机制正例 |
| P-surface | 换表面、保机制 |
| P-domain | 换领域、保机制 |
| N-false-friend | 保表面、破机制 |
| N-direction | 同机制词汇、反方向操作 |
| B-minimal | 差一个必要条件的边界例 |
| A-decoy | 含强诱饵但不应误触发 |
| Z-abstain | 没有充分证据时应弃权 |

### 9.4 标准干预矩阵

| 条件 | 检验什么 |
|---|---|
| bare | 基线能力 |
| 通用鼓励 | 额外动力效应 |
| 等长空流程 | 一般反思结构效应 |
| 等强度错配Tell | 提示强度效应 |
| trigger only | 识别提醒本身的作用 |
| method only | 操作步骤的作用 |
| critic only | 失败监控的作用 |
| trigger + method | 进入条件与执行协同 |
| method + critic | 执行与监控协同 |
| full Tell | 完整认知Option效应 |
| 过强窄方法提示 | 标定泄漏上界 |

### 9.5 四层指标

**识别层**：

- trigger precision/recall；
- 负例弃权率；
- 参数绑定准确率。

**过程层**：

- 目标认知动作出现率；
- 预期进展信号出现率；
- 无进展退出是否及时；
- critic修复成功率。

**结果层**：

- 正确解答率；
- 证明质量；
- 相对bare增益；
- 近、中、远迁移斜率；
- 负迁移率。

**系统层**：

- 每单位token带来的有效分支数；
- 与正确解答脉络相遇所需总计算；
- 重复分支率；
- 新增可复用节点数；
- Tell库增长后的检索成本。

### 9.6 通过条件应是证据链，不是单一阈值

一个Tell进入“validated”至少需要同时满足：

1. 在结构保持变换上维持作用；
2. 在结构破坏负例上能拒绝或失效；
3. 完整Tell优于等长空流程和等强度错配Tell；
4. 目标过程标记先于最终成功出现；
5. 负迁移和泄漏风险在预注册范围内；
6. 对适用模型和迁移距离有明确边界；
7. 结果能被独立重复，而非单次漂亮案例。

## 10. 对Grove核心循环的直接影响

### 10.1 Tell是边生成策略，不只是匹配标签

在Grove中，Tell最终要决定是否从某个数学处境开新边。因此TellCore应预测：

- 新边走什么认知操作；
- 新边与已有边有何差异；
- 多久应检查是否产生进展；
- 无进展时怎样终止；
- 成功后哪些局部结构值得吸收回Tell库。

### 10.2 “分类学是排除机制”应升级为“分类学 + 选择器”

分类学负责缩小候选范围，但不能独自回答哪个Tell当前最值。运行时需要两层：

```text
分类学/FCA：排除明显不属于当前处境的Tell
效用选择器：在剩余Tell中按收益、风险、成本和新颖性排序
```

### 10.3 高Level概念应成为Option生成器

对可展开型高Level概念：

- 预先存常见Option模板；
- 运行时绑定当前对象；
- 必要时组合成宏策略。

对开放寻路型高Level概念：

- 不穷举所有目标方向；
- 生成候选绑定；
- 先运行低成本判别步骤；
- 只有出现收益证据才展开完整分支。

这比“高Level概念始终在场”更节制：语义上始终可用，运行时不必始终占用提示上下文。

### 10.4 Tell失败也能推动树生长

一个Tell即使没有直接解题，只要它：

- 排除了一个大方向；
- 产生了可验证反例；
- 暴露了错误绑定；
- 形成了新critic；
- 缩小了下一轮候选空间；

它仍可能对Grove循环有正价值。系统指标应记录这种信息增益。

## 11. 优先级：哪些学术路线最值得现在进入系统

### P0：立即改变非特化定义

1. **因果充分取商**：每个Tell声明不变量、允许变换和破坏变换。
2. **TellCore/HintRenderer/HintInstance分离**：停止把提示文本当Tell本体。
3. **Option结构**：加入启动集、参数绑定、内部策略、终止与critic。
4. **对比四元组**：单trace产出只能标记为假设，不能直接验证。
5. **过程因果链**：从只看最终成功升级为trigger—动作—进展—成功。

### P1：下一轮实验应加入

1. **多轴Tell假设格**：Level保留作人类描述，系统内部采用偏序字段。
2. **Metamorphic测试**：结构保持与结构破坏成对生成。
3. **组件消融**：trigger、method、critic分别测。
4. **弃权和负迁移指标**：不再只奖命中，不惩罚误触发。
5. **运行时效用选择**：将成本、重复度和分支新颖性纳入。

### P2：有数据规模后推进

1. Tell DSL与反例引导程序综合；
2. process mining自动发现分支事件和流程变体；
3. 层级统计、项目反应和模型漂移监控；
4. 主动学习选择最有信息量的新题；
5. Tell组合、宏操作和元学习。

### P3：长期理论研究

1. 同构之桥的自然性/可交换性判据；
2. 开放高Level概念的有限逼近与完备化；
3. 跨模型共享的认知技能表示；
4. 非特化质量的理论界限。

## 12. 最小可实施版本

如果只做一轮最小升级，不需要立刻实现全部二十四项。可以选一个已经有历史证据的思维力，完成以下闭环：

1. 从3条成功trace和3条失败trace切出分支事件；
2. 构造P1/P2/N1/B1对比四元组；
3. 声明允许变换和机制破坏变换；
4. 生成3个彼此相邻或不可比的TellCore候选；
5. 为每个候选补齐Option字段；
6. 各生成低强度、完整流程和critic三个renderer；
7. 运行标准干预矩阵；
8. 检查trigger—动作—进展—成功证据链；
9. 用一个硬负例触发第一次拆分或收窄；
10. 只把Pareto非支配版本标记为tested。

这一轮最重要的产物不是“Tell后成功了”，而是首次证明：

```text
我们知道它为什么触发，
知道它做了什么，
知道它何时停，
知道哪些变化不影响它，
知道哪一个反例会击穿它，
也知道成功并非只来自提示更长或方法泄漏。
```

## 13. 本轮对旧结论的明确修订

### 修订1：Level连续谱系仍成立，但不足以作为系统表示

人类可以继续用“更高/更低Level”讨论大致抽象度；系统应改用多轴表示和偏序关系。

### 修订2：钟形曲线保留为直觉，不再承担最优选择理论

指导力可能非单调，但真实选择对象是上下文相关的多目标Pareto前沿。

### 修订3：Tell族从同源文本族升级为候选技能假设族

同一trace可以产生多种因果解释、多种抽象域和多种Option编译，不只是同一句话的长短版本。

### 修订4：高Level Tell不是长提示，而是参数化Option模板

思维流程只是renderer的一种。真正的高Level知识是可生成、绑定和检查低Level动作的技能模板。

### 修订5：非特化成功不是跨三题有效，而是变换关系成立

关键证据是：保机制的变化不破坏效用，破机制的变化会使Tell拒绝或失效。

### 修订6：反例不是验证后的附加物，而是Tell定义的一部分

没有负例和边界例，就没有清楚的Tell身份。

### 修订7：思维力有效性应以增量因果贡献表述

不再追求难以证明的“唯一必要思维力”，而是证明某个认知技能对过程和结果具有稳定、低泄漏的增量作用。

## 14. 理论路线的最终判断

学术界没有一个现成领域直接解决“从数学AI trace生成非特化Tell”这个完整问题，但多个领域分别掌握了它的一部分：

- 统计学习告诉我们怎样压缩而保留充分信息；
- 因果学习告诉我们怎样区分机制与相关；
- 对称性和取商告诉我们怎样定义“表面不同但本质相同”；
- FCA和版本空间告诉我们怎样保留偏序、边界和多个候选；
- Options和自动规划告诉我们怎样表示可复用技能；
- hyper-heuristics和元推理告诉我们怎样在运行时选择；
- 对比学习和variation theory告诉我们怎样用正负例看见不变量；
- metamorphic testing告诉我们怎样直接测试“去特化后应保持什么”；
- 心理测量和因果实验告诉我们怎样避免把提示效果误叫成思维力；
- 主动学习和持续学习告诉我们怎样让Tell库长期细化而不腐化。

把这些路线压成一个最终公式：

```text
TellCore
  = 一个分支事件等价类的规范表示
  + 对该等价类有效的认知Option
  + 适用与拒绝边界
  + 过程进展与终止模型
  + 反例、证书和不确定性
  + 运行时选择与渲染规则
  + 跨模型、跨题族的版本化证据
```

非特化策略真正成熟的标志，不是系统能写出一句漂亮而通用的提示，而是：

> 当一个新的Solver trace到来时，系统能说明它与哪些旧处境在何种变换下等价，为什么某项认知技能此时值得启动，怎样把当前对象绑定进技能，预期何时看到什么进展，何时必须停，以及新的成败证据将怎样修正这项技能的边界。

到这一步，系统才不是在积累提示词，而是在积累可迁移的数学认知控制知识。

## 15. 旧非特化POC的统一纳入与证据重新定级

### 15.1 一句话回答

**此前所有与非特化有关的POC都可以、也应该纳入本框架。**

但“纳入框架”不等于把所有旧POC都追认为TellV3端到端验证通过。旧POC大多只验证了完整闭环中的某一个组件：有的验证trace能够被提炼，有的验证Tell能够被检索，有的验证近邻Tell能够被区分，有的验证脉络继承后的hint注入有效，还有的提供了抽象标签无效、机械压缩丢失语义等负证据。

所以最准确的处理方式是：

```text
旧POC结果 ≠ TellCore
旧POC结果 = EvidenceRecord
```

也就是说，每个旧POC都作为一条带适用范围的证据，挂到TellV3框架中它真正验证的组件上；不能把局部PASS直接升级成“非特化整体已经验证”。

### 15.2 全部旧POC在新框架中的位置

| **365/367/369/370号挑战队列** | 未来Case Pack、边界题和对抗题候选 | 可以成为近迁移、远迁移、机制保持、机制破坏或假朋友测试的题源 | 尚未完成的运行不能登记为经验支持；题目设计意图也不能替代真实baseline和过程证据 |

### 15.3 为什么旧POC不会被浪费

新框架并不要求旧POC当初就拥有TellV3全部字段。它允许把历史证据拆开使用：

- VMS-5支持“经验可以进入长期知识库”；
- VMS-6支持“某些数学操作不依赖符号外壳”；
- VMS-7g-v3支持“抽象标签renderer通常不足”；
- VMS-8支持“HintInstance必须绑定脉络和注入位置”；
- VMS-9支持“粗粒度检索键能够排除一部分候选”；
- VMS-10支持“近邻Tell需要更细intent和negative guards”；
- VMS-28支持“语义trace不能被闭元素枚举完全替代”；
- no-loss失败支持“任何抽取重构都必须做信息损失审计”；
- bare筛选线支持“实验题必须先形成真实、可观察的目标缺口”。

这些证据彼此并不竞争，而是落在不同层次：

```text
trace来源与抽取
  → 候选Tell表示
  → 粗筛与精细识别
  → Hint实例化与运行时注入
  → Solver过程变化
  → 解题结果
  → 失败回流与持续修订
```

旧POC已经覆盖了这条链中的很多局部箭头。新框架要做的是保留这些箭头的证据，同时停止把任意一条局部箭头误称为整条链已经闭合。

### 15.4 统一的EvidenceRecord结构

每个旧POC应迁移成一条或多条`EvidenceRecord`。这个对象记录“某个实验究竟支持什么”，而不是直接存一句PASS/FAIL。

```yaml
EvidenceRecord:
  evidence_id:
  poc_id:
  source_documents:
  execution_status: completed | partial | planned | not_run

  target:
    target_type: TellCore | HintRenderer | HintInstance | Retriever | Extractor | Selector | Protocol
    target_id:
    target_component:

  experiment:
    solver_model:
    problem_cases:
    intervention:
    controls:
    sample_size:
    manual_steps:
    runtime_conditions:

  observations:
    trigger_observed:
    target_action_observed:
    progress_signal_observed:
    final_outcome:
    negative_transfer_observed:
    information_loss_observed:

  interpretation:
    supports:
    contradicts:
    does_not_support:
    alternative_explanations:
    leakage_risk:
    confidence:
    scope_limit:

  follow_up:
    missing_controls:
    missing_positive_case:
    missing_negative_case:
    revalidation_needed:
```

这个结构有四个关键作用：

1. **阻止证据越级**：VMS-9的粗筛PASS不会被写成TellCore因果有效。
2. **保留负结果**：VMS-7g-v3和no-loss失败会成为renderer或extractor的反证，不会消失。
3. **显示人工介入**：VMS-8的人工方向匹配会留在`manual_steps`中，防止误认为自动闭环。
4. **允许未来补证**：1709+T05、更多同拓扑Tell、自动小概念提取等缺口可以直接挂在`follow_up`下。

### 15.5 四类证据状态必须分开

所有历史材料应归入下面四类之一：

| 状态 | 含义 | 典型例子 |
|---|---|---|
| **Positive Evidence** | 在限定条件下支持某个组件主张 | VMS-8支持lineage+方向注入；VMS-9支持粗筛 |
| **Negative Evidence** | 反驳某个实现或强主张 | VMS-7g-v3反驳静态抽象标签优势；no-loss POC反驳当时的无损重构 |
| **Protocol Evidence** | 验证实验门槛、对照或审计机制有必要 | bare筛选淘汰候选题；352号补充等强度对照 |
| **Planned Evidence** | 只有设计，没有执行结果 | 348号POC-A至I、尚未运行的挑战队列 |

最需要防止的是把`Planned Evidence`写成已验证，也要防止把`Negative Evidence`当成失败废料。

### 15.6 旧结论的五项正式降级

#### 降级1：VMS-9“验证去特化”

应改写为：

> VMS-9验证了两个手工构造的拓扑表示可以支持小规模候选过滤；它尚未验证该表示是跨环境稳定、因果充分的Tell不变量。

#### 降级2：VMS-10“任意近邻Tell都能区分”

应改写为：

> VMS-10验证了两个手工标记的近邻Tell能够用小概念区分；可扩展性、自动概念发现及正确hint效用仍待验证。

#### 降级3：VMS-8“Tell使成功率从0%到67%”

应改写为：

> VMS-8中“从失败thinking提取的脉络+人工匹配方向+运行时HintInstance”在3道题上取得2次成功；该结果支持完整引导包的可行性，但尚未隔离TellCore、renderer、lineage和人工选择各自的因果贡献。

#### 降级4：VMS-7g“高Level hint具有泛化指导力”

应改写为：

> VMS-7g系列证明模型能够理解并偶尔采纳高Level语言；奥赛难题版没有证明静态抽象hint提高成功率，反而为“只有抽象标签不足以形成认知Option”提供了负证据。

#### 降级5：348号“钟形曲线POC可以直接验证Level理论”

应改写为：

> 348号设计保留为历史实验资产，但应将单轴Level和固定钟形曲线改写为多轴Tell假设、不同renderer、迁移群组和上下文效用的比较。

### 15.7 旧POC合起来已经覆盖什么

按新框架重新看，旧POC已经给出以下局部可行性证据：

1. trace经验可以进入知识库；
2. 一部分表面变化不会破坏数学操作；
3. 静态抽象标签通常不够；
4. 脉络位置和具体方向组合可能显著改变结果；
5. 粗粒度拓扑可以完成第一轮排除；
6. 同拓扑近邻Tell需要下降到小概念层；
7. FCA枚举不能代替数学语义识别；
8. 抽取管线重构可能造成严重信息损失；
9. bare路线分析可以提前淘汰没有目标缺口的题。

这些结论足以说明TellV3不是凭空发明，而是对已有实验事实的统一解释和结构化升级。

### 15.8 仍然缺失的端到端POC

此前没有任何一场实验完整验证下面这条链：

```text
多条成功/失败trace
  → 分支事件切分
  → 候选因果解释
  → 允许变换与破坏变换
  → 多轴Tell假设格
  → 因果充分压缩
  → 编译成认知Option
  → 自动识别启动条件
  → 自动绑定当前对象
  → 生成HintInstance
  → 出现预期认知动作与进展信号
  → 在结构保持题上维持效用
  → 在结构破坏题上拒绝或失效
  → 用新反例修订Tell边界
```

这才是新框架意义上的完整非特化POC。

它与旧POC的关系不是“重新做一遍”，而是：

- 复用VMS-28的trace抽取经验；
- 复用VMS-9/10的粗筛与细分机制；
- 复用VMS-8的lineage和运行时注入；
- 复用352号的对照与泄漏审查；
- 复用bare筛选线的题目准入经验；
- 新增因果取商、Option编译、变形测试、组件消融和反例细化。

### 15.9 最终判断

**旧POC全部保留、全部有位置、没有浪费。**

但它们必须从“POC编号对应一个笼统PASS/FAIL”，迁移为“某条证据支持或反驳TellV3的某个组件主张”。迁移之后：

- 正结果不被夸大；
- 负结果不被丢弃；
- 人工介入不被隐藏；
- 未执行方案不冒充结果；
- 每个缺口都有明确的补证入口。

因此最准确的总判断是：

> 此前POC已经验证了非特化系统所需的多项局部能力，但还没有验证“因果充分取商→认知Option→自动运行时调用→跨变换稳定→反例修订”的完整闭环。TellV3框架不是推翻旧POC，而是给每一条旧证据重新确定坐标，并定义它们尚未共同完成的最后一段路。

## 16. Tell认知策略六门审计

本节记录一个新的总要求：

> 即使Tell的抽象层级合适，也必须继续追问：它是否已经成为一个可选择、可执行、可终止、可组合、可归责、可持续学习的认知策略？

这句话非常重要。它把非特化从“找到合适抽象”推进到“形成可运行策略”。抽象层级合适，只说明这条Tell不像源题复述，也不像空泛口号；但它仍可能只是一个漂亮的候选表达。只有通过下面六门审计，它才有资格进入Grove核心循环，成为系统可以调度的新边生成策略。

```text
候选Tell
  = 抽象层级合适的表达

合格TellCore
  = 候选Tell
  + 可选择
  + 可执行
  + 可终止
  + 可组合
  + 可归责
  + 可持续学习

生产级Tell策略
  = 合格TellCore
  + 证据版本
  + 运行时监控
  + 反例驱动修订
```

### 16.1 为什么这是抽象层级之后的第二审计

Level审计回答的是：

> 这条Tell在什么抽象粒度上表达？

六门审计回答的是：

> 这条Tell能否作为一个系统对象被选择、执行、停止、组合、归责和更新？

二者不是同一件事。一条Tell可以在Level上恰好处在峰值附近，但仍然不能运行。例如：

- 它说出了真正的不变量，但没有告诉系统什么时候该选它；
- 它指出了正确方向，但没有可执行动作；
- 它能启动推理，但不知道何时停止；
- 它单独有效，但与其他Tell冲突；
- 它成功后无法判断到底是Tell起作用，还是提示强度、模型随机性或人工选择起作用；
- 它遇到反例后无法修订，只能留下一个静态文本。

所以，抽象层级审计是语义门槛；六门审计是策略门槛。前者决定“这是否像一个可迁移Tell”，后者决定“它是否已经是Grove能使用的认知策略”。

### 16.2 六门审计表

| 审计门 | 核心问题 | 必须落到的系统对象 | 不通过时的典型失败 |
|---|---|---|---|
| **可选择** | 系统是否知道何时选它、为何选它、何时拒绝它？ | 启动集、负触发、选择分数、候选Tell排序、abstention规则 | 检索命中被误当成策略选择，导致假朋友迁移 |
| **可执行** | AI拿到它以后，是否知道下一步具体做什么？ | 参数槽、绑定规则、内部policy、动作序列、最小可执行脚手架 | Tell退化成“考虑不变量”“换个角度”等口号 |
| **可终止** | 系统是否知道执行到什么状态应停止、回退或让位？ | 进展模型、成功终止、无进展终止、预算终止、冲突终止 | AI一直围绕同一提示打转，或过早放弃有效方向 |
| **可组合** | 它能否和其他Tell、hint、解题路线共同工作？ | 前置条件、后置条件、冲突关系、依赖关系、调度策略 | 多条提示互相抵消，或重复推动同一条无效路线 |
| **可归责** | 成败能否归因到这个Tell及其具体组件？ | EvidenceRecord、组件消融、过程指标、lineage、干预矩阵 | POC只能给出笼统PASS/FAIL，无法知道哪个部件有效 |
| **可持续学习** | 新成功、失败和反例能否改变它的边界与版本？ | 生命周期、版本号、反例集、漂移检测、修订规则、退役规则 | Tell库变成静态提示库，旧错误不断复现 |

这六门不是“越多越好”的装饰字段，而是Tell进入系统前的最低策略契约。缺任意一门，Tell就只能作为候选知识、实验素材或人工提示存在，不能被宣称为成熟的非特化策略。

### 16.3 用六门审计整个理论框架

从现在开始，任何新的理论主张都应该说明它改善了哪一门审计，以及没有覆盖哪几门。

例如：

- 因果充分取商主要服务于可归责和可持续学习，因为它让系统知道保留下来的结构为什么有效，也知道反例应修订哪里；
- 多轴Tell假设格主要服务于可选择和可组合，因为它让系统能够比较不可比候选，而不是只在一条Level线上寻找峰值；
- Option结构主要服务于可执行和可终止，因为它把Tell从一句话变成有启动、policy和termination的认知动作；
- HintRenderer主要服务于可执行，但不能单独证明可归责；
- EvidenceRecord主要服务于可归责和可持续学习，但不能代替TellCore本身；
- 变形测试和假朋友测试主要服务于可选择、可归责和可持续学习；
- 组件消融主要服务于可归责；
- Grove运行时选择器主要服务于可选择、可组合和可终止。

因此，理论框架的审计方式应从“这个概念听起来是否高Level”改为：

```text
它解决了六门中的哪一门？
它依赖哪几门已经成立？
它会不会破坏其他门？
它的证据能否落入EvidenceRecord？
它失败后能否触发版本修订？
```

### 16.4 用六门审计技术框架

技术框架也要接受同一套审计。未来实现时，数据库、DSL、检索器、提示渲染器和运行时调度器都不能只存“Tell文本”，而要能回答以下问题：

1. **可选择**：当前problem state为什么触发这个Tell，而不是触发另一个Tell？
2. **可执行**：当前状态中的对象如何绑定到Tell参数槽？
3. **可终止**：执行后系统期待看到什么进展信号？没有进展时多久退出？
4. **可组合**：它能否与当前脉络中的已有策略共存？是否需要先后顺序？
5. **可归责**：如果本轮成功或失败，证据写到哪个EvidenceRecord？归因到TellCore、renderer、lineage还是selector？
6. **可持续学习**：本轮结果会新增正例、负例、边界例，还是触发Tell版本降级？

这意味着Tell库的最小生产结构不应是：

```yaml
tell:
  text: "尝试寻找保持关系的不变量"
  level: high
```

而至少应接近：

```yaml
TellStrategy:
  tell_core:
    invariant_claim:
    trigger_boundary:
    negative_boundary:
    parameter_slots:
    binding_rules:
    internal_policy:
    progress_model:
    termination:
    composition_contract:
  runtime_selection:
    selection_features:
    ranking_rule:
    abstention_rule:
  attribution:
    evidence_records:
    component_tests:
    process_metrics:
  learning:
    positive_cases:
    negative_cases:
    counterexamples:
    revision_rule:
    retirement_rule:
```

### 16.5 用六门重审旧POC

15节已经把旧POC统一纳入EvidenceRecord。六门审计给这些旧证据增加一个更直接的读法：

| 旧证据 | 已触及的审计门 | 仍缺什么 |
|---|---|---|
| **VMS-9/10** | 可选择的一部分：粗筛与近邻细分 | 还没有证明选择规则在大规模、自动化、跨域条件下稳定 |
| **VMS-8** | 可执行的一部分：lineage + runtime hint可以推动新AI | 还没有隔离TellCore、renderer、selector和人工匹配的贡献 |
| **VMS-7g** | 可执行的负证据：静态抽象标签不足 | 还需要把高Level概念编译成真正的Option再测 |
| **VMS-28c/d/e** | 可归责的输入层：trace分支、FCA视角、语义不变量 | 还没有完成trace到TellCore的因果取商 |
| **no-loss POC** | 可持续学习的前提：压缩不能丢失关键语义 | 还需要和反例驱动修订合并 |
| **352号协议** | 可归责的实验框架 | 还需要把干预矩阵落实到每个Tell组件 |
| **bare筛选线** | 可选择的题目准入与baseline控制 | 还不是Tell策略本身的有效性证据 |

由此看，旧POC不是零散历史，而是六门审计的局部证据。它们共同说明：系统已经触到每一门的一部分，但还没有任何一条完整TellStrategy同时通过六门。

### 16.6 对后续工作的直接要求

后续所有非特化研究、Tell分类学修订和技术实现，都应在文档或代码审查中显式回答六个问题：

1. 这条Tell如何被选择？
2. 这条Tell如何被执行？
3. 这条Tell如何终止或让位？
4. 这条Tell如何与其他Tell组合？
5. 这条Tell的成功、失败和中间进展如何归责？
6. 这条Tell如何从新证据中持续学习？

如果某个方案只能回答前三个问题，它是一个可运行提示策略，但还不是可学习Tell系统。如果只能回答第四、第五个问题，它更像审计协议，而不是策略本体。如果只能回答第六个问题，它只是知识管理机制，还没有解决推理现场的调用问题。

最终判定标准应写成：

> TellV3的目标不是制造更抽象的提示，而是制造可选择、可执行、可终止、可组合、可归责、可持续学习的认知策略。抽象层级只是第一门，六门审计才是整个理论和技术框架的总闸门。
