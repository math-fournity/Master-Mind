## 1. 背景与目标

### 1.1 为什么需要100万题

项目已有67838道题录入DB（problem_extraction_progress表），但只跑了789道。要系统性地评测AI数学能力分布、积累思维路径数据基座，现有题量不够。

212号文档调研了全球可下载的数学题库，发现电子化竞赛级题目约600万道。用户要求：**从中筛选最难的100万道，作为项目的核心题库**。

### 1.2 "最难"的定义

不是找千禧年难题（人类也没做出来），不是找K12基础题。是找**竞赛级及以上**的题——AI有知识储备但需要推理能力才能做的题：

| 层次 | 定义 | 典型来源 |
|---|---|---|
| **极难** | IMO/研究级，最强AI也大概率做不出来 | compfiles, FATE, miniF2F |
| **奥赛** | 国家级奥赛/IMO Shortlist级 | NuminaMath olympiad子集, olympiadbench |
| **竞赛** | AMC/AIME/Putnam级 | MathNet, Hendrycks L4-5, AoPS |
| **大量竞赛** | 竞赛题但难度分布广 | NuminaMath完整版, ODA-Math, OpenMathReasoning |

### 1.3 排除范围

- **纸质/PDF来源不取**——电子化文本来源已经足够多，不需要OCR
- **K12基础题不取**——GSM8K、Math23K、Orca-Math等，不是"最难"
- **合成题不取**——MetaMathQA、MathScale-QA等合成数据，不是真实竞赛题
- **预训练语料不取**——OpenWebMath、Proof-Pile等是训练用，不是测试题

## 4. 执行方案

### 4.1 Phase 1：已有数据送入queue（L1+L2）

**目标**：将已有的42,000道L1+L2题全部送入problem_queue。

**Check List**：
- [ ] 用`enqueue_problem.py --from-progress --tier 1`送入L1题（452道）
- [ ] 用`enqueue_problem.py --from-progress --tier 2`送入L2题（1732道）
- [ ] 确认tier 1+2的题在DB中已有正确difficulty_tier标记
- [ ] 验证queue状态：`enqueue_problem.py --status`

> 注意：当前DB中tier 1+2只有2184道，但L1+L2实际有42000道。原因是NuminaMath proof子集35153道被标为tier 3（因为difficulty_tier字段赋值时按source_dataset而非实际难度）。需要重新标定tier。

### 4.2 Phase 2：重新标定已有题的难度层级

**问题**：DB中`difficulty_tier`字段赋值不准确——NuminaMath proof子集35153道奥赛级题被标为tier 3，但实际是L2奥赛级。

**Check List**：
- [ ] 写脚本：按`metadata.competition_tier`和`metadata.answer_type`重新标定difficulty_tier
- [ ] 标定规则：
  - `competition_tier=olympiad` AND `answer_type=Proof` → tier 2（L2奥赛）
  - `competition_tier=olympiad` AND `answer_type≠Proof` → tier 2
  - `competition_tier=competition` → tier 3（L3竞赛）
  - `source_dataset IN [compfiles, fate, minif2f, matharena, aime, amc]` → tier 1（L1极难）
- [ ] 更新DB中所有已有题的difficulty_tier
- [ ] 验证：各tier题量符合预期

### 4.3 Phase 3：下载NuminaMath完整版

**目标**：从HuggingFace下载NuminaMath-1.5完整版（89.6万道），按competition_tier筛选。

**Check List**：

## 7. 与自动化运营系统的衔接

本文档的筛选策略产出题目录入`problem_extraction_progress`表后，用`enqueue_problem.py`送入`problem_queue`表，`auto_runner.py`自动取题做题。

**工作流**：
```
Phase 1-5筛选 → problem_extraction_progress表
                    ↓
enqueue_problem.py --from-progress --tier <n>
                    ↓
problem_queue表 → auto_runner.py → devin cli → 判定落盘
```

**送题策略**：
- 先送L1（极难）——量小但价值最高
- 再送L2（奥赛）——AI能力的核心测试区
- 最后送L3+L4——大规模数据积累
