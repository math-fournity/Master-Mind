## 一、Tell分类学研究是什么

### 1.1 一句话定义

Tell分类学研究的目标是：**为第六代AI数学系统建立一个Tell的分类体系，使得每个tell在分类体系中有明确位置、Telling AI可按分类体系分区、trace→tell匹配有匹配key、分类体系可扩展且有FCA数学基础。**

### 1.2 背景概念——trace/tell/hint三步链路

第六代AI数学系统的核心循环依赖一个"三步链路"：

1. **trace**——从推理AI的思维过程中识别出的"可泛化思维模式"。描述"解题者在这里用了某个可泛化的思维模式"或"推理AI在这里可以分叉但没分叉"。
2. **tell**——trace去特化后存入tell库的模式。tell取自poker术语——"AI不会主动告诉你它没考虑这个方向，但它的thinking会暴露"。tell是识别端：从推理AI的thinking中读出的分叉信号。
3. **hint**——从tell取出的方向提示，注入给新的推理AI。hint是注入端：给新AI的翻译方向。

**读tell，给hint**——这是引导树闭环的识别端结构（定义在 `000-v0-2026-08-08-引导树闭环-识别端结构定义.md`，项目根目录）。

### 1.3 为什么需要分类学

系统运行时需要启动多个Telling AI实例，每个负责识别一部分tell——这叫"Telling AI分区"。分区依据是什么？就是Tell分类学。如果没有分类学，Telling AI无法分区，trace→tell匹配也没有匹配key。

### 1.4 为什么用FCA

FCA（形式概念分析，Formal Concept Analysis）是一个数学框架，专门研究"名副其实的分类"。用FCA的好处：
- 分类有数学基础（不是拍脑袋分）
- 分类体系可扩展（新tell可以自然归入）
- 可以用程序验证分类的完备性（Next Closure算法）

**FCA与系统术语的对应**（双轨术语原则，330号）：
- 脉络 = 形式上下文 (G, M, I)
- 段 = 对象 g ∈ G
- 段特征 = 属性 m ∈ M
- 格化 = 计算概念格 B(G, M, I)
- Level视图 = 形式概念 (A, B)
- trace = 概念内涵 B
- tell库 = 多上下文概念格

**注意**：FCA语言用于术语规范化，不用于算法实现。系统采用"方式A"——用提示词驱动AI做格化，不用FCA算法直接计算。详见 `six/pipes.py` 中 `pipe_1_parser` 的docstring。

### 1.5 研究的五个阶段

```
学工具 → 建分类学（能分类的）→ 跑例子验证 → 撞到难分类的（高Level tell）→ 重新理解分类学本身
FCA学习笔记     先验Tell分类学      4道题再分析      333-340号深化         336/337号认知跃迁
00-07号          08号(v3)          reanalysis/        高Level概念           坐标轴不是点
                                                    两种类型              排除机制不是加速机制
```

**认知跃迁的核心逻辑**：
```
能分类的（有结构模式的局部tell）
    → 建分类学，跑例子验证
        → 撞到难分类的（高Level tell，没有明确结构模式）
            → 重新理解分类学本身是什么
                → 分类学不是"把东西放进盒子"
                → 而是"排除机制"——高Level概念是坐标轴，始终在场，不是被分类的点
```

## 二、当前分类学本体（v3）

### 2.1 分类学结构

**文件位置**：`FCA学习笔记/08-先验Tell分类学.md`（549行，68次edit，全session最高频文件）

**当前版本**：v3

**结构**：
```
tell的固有属性（形式背景的属性维度——tell本身的特点，不随题目位置变化）：
  第一层：domain（6个：数论/代数/组合/几何/分析/跨域）
  第二层：段结构模式（5大类：构造-分析-排除/探索-诊断-修复/跨域桥接/归约策略/累积-收敛）
  第三层：具体概念（domain×段结构模式的交叉；子模式在此层体现，如"无尽追逐"是"探索-诊断-修复"的子模式）

观察trace的Level选择（不是tell的属性，是检索时的参数——取决于trace结构，不取决于tell本身）：
  局部Level / 非局部Level / 全局Level
```

### 2.2 5大类段结构模式（必须记住）

| 模式 | 一句话定义 |
|---|---|
| 构造-分析-排除 | 构造对象→分析性质→排除不可能 |
| 探索-诊断-修复 | 探索方向→发现gap→诊断→修复（"无尽追逐"是此模式的子模式——诊断环节断裂） |
| 跨域桥接 | 把问题从一个领域翻译到另一个领域 |
| 归约策略 | 把大问题归约到小问题 |
| 累积-收敛 | 逐步累积信息→最终收敛到结论 |

### 2.3 6个domain

| domain | 包含什么 |
|---|---|
| 数论 (number_theory) | 整除性、素数、同余、模运算、p-adic赋值、二次剩余 |
| 代数 (algebra) | 群/环/域、多项式、线性代数、矩阵、特征值、Galois理论 |
| 组合 (combinatorics) | 计数、鸽巢、图论、组合设计、Ramsey理论、概率方法 |
| 几何 (geometry) | 欧氏几何、解析几何、拓扑、微分几何、代数几何 |
| 分析 (analysis) | 微积分、不等式、极限、连续、函数空间、复分析 |
| 跨域 (cross_domain) | 跨领域构造、同构之桥、归约、表示转换 |

### 2.4 版本演化历史

| 版本 | 触发 | 核心修正 | 关键认知 |
|---|---|---|---|
| v1 | 初始建立 | 四层结构：domain→trace类型→段结构模式→具体概念 | 初始构想 |
| v2 | FLT例子 | "局部/非局部/全局"从属性维度移到观察Level参数 | **FLT例子**：同一个tell在"题目就是证明FLT"中表现为全局，在"中间需要FLT"中表现为局部——所以"局部/非局部/全局"不是tell的固有属性，是观察方式 |
| v3 | FCA理论审查 | "无尽追逐"从第二层降级到第三层（"探索-诊断-修复"的子模式） | **FCA属性测试**：tell"应该转向X"在AI追逐时和不追逐但同样需要转向时都出现——tell相同，但"无尽追逐"只在前者中出现——所以"无尽追逐"不是tell的固有属性 |

### 2.5 两个关键修正认知（必须记住的洞察）

**洞察1（v2）**：tell的固有属性和观察trace的方式是正交的两个轴。"局部/非局部/全局"是观察方式（你看trace的粒度），不是tell的属性（tell本身的特点）。同一个tell在不同题目位置（整体目标vs中间步骤）有不同的Level显现，但tell本身不变。

**洞察2（v3）**：FCA要求形式背景的属性必须是对象的固有特征。测试方法：如果同一个对象在不同观察方式下属性值变化，那这个属性不是固有属性。"无尽追逐"是trace特征（AI在trace中的行为模式），不是tell属性——它随AI是否追逐而变化，不随tell本身变化。

### 3.2 逐文档核心内容

#### 333号——同构之桥的tell-hint多对多关系与高Level展开的两个担忧

**核心内容**：
1. **tell和hint是多对多关系**——一个tell可以对应多个hint（同一个trace识别结果可以触发多个不同的方向提示），一个hint也可能被多个tell指到。数据库schema中tell_hint_match集合需要支持多对多。
2. **高Level概念可以系统化地降低Level**——把抽象的高Level概念（如"同构之桥"）展开为一组低Level的具体形式（如"构造Frey曲线""构造Galois表示"）。
3. **两个担忧**：
   - 组合爆炸——降低Level时领域数×具体形式数可能导致tell/hint数量爆炸
   - 覆盖缺口——分类学后续细化后，已有的降低Level展开可能无法覆盖新增的细分领域
4. **验证状态分层（case_source）**：
   - `case_source: mathematics`——有数学案例支撑
   - `case_source: system`——有系统运行案例支撑
   - `case_source: none`——只有元模式支撑，没有具体案例
   - `case_source: none`的hint输出必须是低压力的——"你也可以考虑跨域"而不是"你应该跨域"

#### 334号——没有当前域案例时系统凭什么触发跨域提示

**核心内容**：
1. **三层依据**——系统在没有当前域案例时触发高Level tell识别，凭的是：
   - 层1（元模式）：跨域桥接是通用数学解题思维，不依赖具体案例
   - 层2（模式匹配）：当前trace呈现的特征匹配"需要跨域桥接"的适用条件
   - 层3（特定题目相关性）：当前题目的结构特征表明可能受益于跨域桥接
2. **"狼来了"问题**——如果系统频繁触发"考虑跨域桥接"但大多数情况下跨域不是正确方向，AI会学会忽略这个提示。频率控制：高Level触发应该是低频的、有选择的。
3. **Brouwer不动点定理案例**——AI在拓扑/代数拓扑内打转时，系统基于三层依据触发"考虑跨域桥接"的提示是有效的。

#### 335号——高Level概念需要充分解释的环节分析

**核心内容**：
1. **AI能理解高Level概念**（修正277号）——前提是"说清楚"，不是一句抽象的话，是定义+例子+为什么有用的完整解释。
2. **同一概念的三种解释**：
   - **执行型解释**（给推理AI用）——"怎么做"。当推理AI收到高Level hint后，它需要知道"同构之桥"是什么意思、怎么构造、有哪些成功案例。
   - **识别型解释**（给Telling AI用）——"什么时候需要"。当Telling AI需要识别trace中是否有"需要同构之桥"的信号时，它需要知道适用条件是什么。
   - **判断型解释**（给动态生成AI用）——"值不值得"。当系统需要动态生成一个新的高Level方向时，它需要知道适用范围、成功概率、代价。

#### 336号——高Level概念是分类学的坐标轴不是点 ⭐ 认知跃迁

**核心内容**：
1. **高Level概念是分类学的坐标轴不是点**——"跨域桥接"是段结构模式这个分类维度上的一个值（坐标轴上的刻度），不是被分类到一个类别中的对象。降低Level后的具体形式（如"构造Frey曲线"）才是分类学中的"点"。
2. **坐标系类比**：
   ```
   分类学 = 坐标系
     domain = x轴
     段结构模式 = y轴
     具体tell/hint = 坐标系中的点
     高Level概念"同构之桥" = y轴上"跨域桥接"这个刻度的名字
   ```
3. **结构知识与内容知识分离**：
   - 结构知识（不可分类的）：domain定义、段结构模式定义、子模式定义、高Level概念的三种解释文本——存储在分类学Schema + 高Level概念解释库
   - 内容知识（可分类的）：具体tell条目、具体hint条目——存储在tell库/hint库

#### 337号——分类学是排除机制不是加速机制 ⭐ 认知跃迁

**核心内容**：
1. **分类学从加速模型到排除模型**——分类学不是"帮你快速找到方向"（加速机制），而是"排除掉不相关的，剩下的始终在场"（排除机制）。
2. **高Level概念"始终在场"**（后被338号修正为"在专门目录中"）——高Level概念不是被分类后才出现的，它作为坐标轴始终存在。
3. **两个并行通道**——低Level Telling AI遍历具体tell条目，高Level Telling AI理解概念+判断适用条件。

#### 338号——高Level概念的存储和使用方式

**核心内容**：
1. **高Level和低Level存储使用方式相同**——都是放到一个AGENTS.md目录中，都有devin cli从中启动，对推理AI的上下文及trace进行识别。
2. **区别在描述方式**——低Level是具体tell条目（本身即具体），高Level是充分描述+例子（不能只是一句抽象的话）。
3. **区别在识别逻辑**——低Level遍历tell条目逐一匹配trace，高Level理解概念+格化脉络+判断适用条件。
4. **识别AI的任务详解**（338号§3.5）：
   1. 拿到推理AI的上下文和trace
   2. 理解高Level概念（通过AGENTS.md中的充分描述+例子）
   3. 对推理脉络做格化，找出有意义的Level视图
   4. 在每个Level视图下，检查思维脉络的每个位置是否符合高Level概念的适用条件
   5. 如果认定"推理AI应该考虑使用同构之桥" → 识别到tell → 输出方向性hint

#### 340号——高Level概念的两种类型（当前最前沿）

**核心内容**：
1. **第一种（可展开的）**——如构造-分析-排除、累积-收敛、探索-诊断-修复、归约策略：概念本身定义了展开维度（过程的阶段），可以预先降低Level为具体形式列表。组合爆炸可控，覆盖缺口有限。
2. **第二种（无法指定展开方向的）**——如同构之桥：概念本身不定义展开维度，目标领域开放，无法预先降低Level。主要靠充分解释+启发式触发+案例积累。组合爆炸风险高，覆盖缺口永远存在。
3. **两种类型的处理策略不同**：第一种遍历展开后的具体形式列表，第二种理解概念+格化脉络+判断适用条件（无列表可遍历）。

## 四、FCA再分析SOP

### 4.1 什么是FCA再分析

对已有题目profile用FCA先验分类学重新分析，识别原始profile遗漏的非局部/全局tell显现。这是验证和迭代分类学的主要手段。

### 4.2 主agent/subagent分工架构（铁律-1）

**主agent（流程管理者）**：
1. 选择题目
2. 从check list模板建立TODO List（铁律0）
3. 从prompt模板构造subagent prompt
4. 启动subagent（profile选`subagent_general`）
5. 验证产出（铁律0.5）
6. 如果发现分类学问题，自己执行修正流程（不委托subagent）
7. git commit

**subagent（具体分析者）**：
1. 加载V6提示词全文（步骤0）
2. 读原始profile（步骤1）
3. 按10步SOP执行FCA再分析（步骤2-9）
4. 产出再分析报告落盘
5. 返回执行摘要

### 4.3 10步SOP

| 步骤 | 内容 | 输入 | 输出 |

| 2 | 确定domain | 步骤1的domain + solution_text | domain列表（1-3个） |

## 八、关键认知总结（接手者必须记住的）

1. **分类学是排除机制不是加速机制**（337号）——分类学排除掉不相关的，剩下的始终在场。不是帮你快速找到方向，是帮你排除掉不需要考虑的。

2. **高Level概念是坐标轴不是点**（336号）——"跨域桥接"是段结构模式这个分类维度上的一个值（坐标轴上的刻度），不是被分类的对象。降低Level后的具体形式才是点。

3. **结构知识与内容知识分离**（336号）——分类学Schema维护的是结构知识（坐标轴和刻度），tell库/hint库维护的是内容知识（坐标系中的点）。修改结构知识需要完整审计，修改内容知识只需常规审计。

4. **tell和hint是多对多关系**（333号）——一个tell可以对应多个hint，一个hint也可能被多个tell指到。

5. **"局部/非局部/全局"是观察参数不是tell属性**（v2修正）——同一个tell在不同题目位置有不同的Level显现，但tell本身不变。

6. **"无尽追逐"是"探索-诊断-修复"的子模式不是独立模式**（v3修正）——它是trace特征不是tell属性。

7. **高Level概念有两种类型**（340号）——可展开的（组合爆炸可控）vs 无法指定展开方向的（覆盖缺口永远存在）。两种类型的处理策略完全不同。

8. **高Level概念可以被AI理解，只要说清楚**（335号）——不是一句抽象的话，是定义+例子+为什么有用的完整解释。同一概念需要三种解释（执行型/识别型/判断型）。

9. **高Level和低Level存储使用方式相同**（338号）——都在AGENTS.md目录中，都有devin cli从中启动。区别在描述方式和识别逻辑。

10. **分类学不是一次性建成的**——它在不断看新题的过程中被修正。修正很重要，但修正的全历史审计更重要。警惕"吃了后面忘了前面"。
