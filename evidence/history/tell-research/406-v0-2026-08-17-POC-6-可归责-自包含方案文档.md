## §0 自包含POC方案文档的设计规范（本节是所有POC方案文档的共用规范）

### 0.1 设计目标

一份POC方案文档要让未来20万上下文的AI**只加载这份文档+它索引的少数核心文档**，就能完整了解做好这次POC所需的所有背景知识，不需要用户另外指点应该读什么。

### 0.2 文档结构（每份POC方案文档必须包含的10节）

| 节 | 内容 | 作用 |

### 0.3 "自包含"的含义

"自包含"不是把所有背景知识复制进文档——那样文档会膨胀到无法加载。"自包含"是指：

1. **文档本身包含这个POC执行所需的全部操作信息**——输入/方法/输出/通过标准/执行约束
2. **文档明确列出需要全文加载的背景文档清单**——每份说明加载理由（这个POC为什么需要这份文档的内容）
3. **未来AI加载这份POC方案后，按照§8清单去全文加载被索引的文档**——不需要用户另外指点

### 0.4 被索引文档的精挑细选原则

每份POC方案文档的§8清单应该精挑细选——只列这个POC真正需要的背景文档，通常3-7份。如果索引太多，未来AI加载不完。

**挑选标准**：
- **必须加载**：这个POC不加载这份文档就无法正确执行（如题包/TellCore定义/通过标准来源）
- **建议加载**：这个POC加载这份文档能更好理解为什么这么做（如理论背景/原设计文档）
- **不列**：这个POC不需要这份文档的内容（如其他POC的方案文档）

```
{编号}-v0-{日期}-POC-{POC编号}-{POC名称}-自包含方案文档.md
```

### 1.3 核心问题

**POC-6回答**：

> 如果Tell有效，增益到底来自哪里？

这是整套POC中**最容易被忽略、也最重要的一门**。没有归责，所有成功都会被解释成"Tell有效"，但实际上增益可能来自提示长度、鼓励效应、人工选择、脉络继承或方法泄漏——而不是Tell的因果贡献。

### 1.4 为什么是Phase C的第一个

POC-6排在Phase C的第一个，因为它依赖Phase B的所有基础验证已经成立：

- POC-2.5确认了基础因果效应（Hint比bare更好）——**必须通过**，如果基础效应都不存在，干预矩阵没有意义
- POC-3确认了AI会执行预期认知动作——归责需要知道"AI是否执行了目标过程"才能区分"Tell有效"和"任何提示都有效"
- POC-4确认了终止行为正确——如果终止行为错误导致的失败被误归因为"Tell无效"，归责矩阵会得出错误结论

只有这些基础成立后，干预矩阵才能正确拆解增益来源。

## §2 理论背景——为什么需要这个POC

### 2.1 396号§5——有效性=因果贡献证明

396号§5（第三层深化）的核心论断：

> Hint有效 ≠ 解题成功。有效性是"trigger→认知动作→进展信号→成功"这条因果链出现，且在控制混杂后仍成立，且在结构保持变换下维持作用。

POC-6验证的就是"在控制混杂后仍成立"——通过干预矩阵把Tell承担的多个混杂功能拆开，确认增益确实来自Tell的因果贡献，而不是混杂因素。

### 2.2 372号§0——Tell在实验中承担多个混杂功能

372号§0明确指出了最大风险（这也是352号§0.2指出的）：

> Tell在实验中承担了多个混杂功能：
> - 它可能是真正的思维力引导（我们想要的）
> - 也可能是题目难度提示（混杂）
> - 也可能是解法空间裁剪（混杂）
> - 也可能是隐性方法泄漏（混杂）
> - 也可能只是增加了模型重试深度和自信（混杂）

如果不把这些混杂功能拆开验证，实验结果很漂亮但不可解释——你只知道"给了Tell后AI做出来了"，但不知道是Tell的因果贡献还是某个混杂因素。

### 2.3 396号§5.3——标准干预矩阵

396号§5.3引用了372号§9.4的标准干预矩阵——不只是bare vs Hint，而是：

| 条件 | 检验什么 |
|---|---|
| bare | 基线能力 |
| 通用鼓励 | 额外动力效应 |
| 等长空流程 | 一般反思结构效应 |
| 等强度错配Tell | 提示强度效应 |
| trigger only | 识别提醒本身的作用 |
| method only | 操作步骤本身的作用 |
| critic only | 失败监控的作用 |
| trigger + method | 进入条件与执行协同 |
| method + critic | 执行与监控协同 |
| full Tell | 完整认知Option效应 |
| 过强窄方法提示 | 标定泄漏上界 |

POC-6的干预矩阵就是从这个标准矩阵中选取的——首轮用轻量矩阵（6个条件），第二轮扩展为完整矩阵（11个条件）。

### 2.4 397号§1.7的审视结论

397号§1.7审视了373号的POC-6设计，结论是：

> **合理且关键。**372号§0说的"Tell在实验中承担多个混杂功能"正是靠这个矩阵拆开。通过标准（full Tell相对bare和通用鼓励有过程层增益/等长空流程不能稳定复制目标过程/错配Tell不能稳定复制目标过程/method only若同样有效应降级trigger或critic的贡献声明/如果所有提示都有效不能宣称目标Tell特异有效）是合理的。"如果所有提示都有效不能宣称目标Tell特异有效"——这条特别重要，387号dev-docs目录Mid-Hint对照实验已经显示"vein够时所有提示都有效"的情况。**无过度设计。**但注意POC-6依赖POC-2.5基础因果效应验证——如果基础因果效应都不存在，干预矩阵没有意义。

### 2.5 387号dev-docs Mid-Hint实验的警示

387号dev-docs目录的Mid-Hint对照实验（§十三~十四）揭示了一个关键风险——**vein够时所有提示都有效**：

- 00995 MH（有hint）：SUCCESS（13分钟）
- 00995 CONTROL（无hint）：SUCCESS（8分钟）——反而更快
- 00128 MH（有hint）：SUCCESS（4分钟）
- 00128 CONTROL（无hint）：SUCCESS（11分钟）

4个run都SUCCESS——Hint只改变方法不改变成败。这意味着在vein够的情况下，bare、通用鼓励、等长空流程、错配Tell、full Tell**可能都有效**——如果所有提示都有效，不能宣称目标Tell特异有效。

POC-6的通过标准中"如果所有提示都有效不能宣称目标Tell特异有效"这条标准在这里**特别重要**——如果POC-6的干预矩阵中所有条件都成功，必须承认目标Tell没有特异有效，增益来自一般提示效应或脉络继承，而不是Tell的因果贡献。

### 2.6 396号§4.3——三对象分离对归责的意义

396号§4.3（TellCore/HintRenderer/HintInstance三对象分离）对归责有直接意义：

> 不分离会导致：
> - 改了措辞就被误认为改了Tell
> - 一个renderer失败就否定整个思维力
> - 题目参数被写进Tell本体造成泄漏
> - 无法比较同一Tell在不同模型、位置和强度下的表现

POC-6的干预矩阵正是利用三对象分离来拆解增益来源——"method only"测试的是TellCore的internal_policy单独的效果，"trigger only"测试的是trigger_boundary单独的效果，"full Tell"测试的是完整认知Option的效果。如果method only和full Tell效果一样，说明trigger和critic是冗余的，增益来自method而不是完整认知Option。

### 2.7 不验证会留下什么gap

如果不做POC-6：
- 所有"Tell有效"的结论都不可信——可能只是提示长度效应、鼓励效应或泄漏
- POC-8端到端闭环无法归因——闭环成功后不知道是哪个组件有效
- TellStrategy不能被称为"可归责的认知策略"——没有归责，成功不可解释，失败不可定位

所以POC-6必须在POC-2.5通过（特别是场景2：vein不够时Hint补上了）的前提下进行。

## §4 输入——这个POC需要什么

### 4.1 题包——正迁移题

从382号CasePack v0的22道题中取**正迁移题4道**（373号§14.9指出POC-6最需要中等规模正迁移题、强对照题——bare、错配Tell、空流程差异可观察）。

选取标准（特别针对POC-6）：
- **不能太难**——如果所有条件都失败，矩阵无法归因（373号§14.9）
- **不能太易**——如果所有条件都成功，矩阵显示"所有提示都有效"，无法宣称Tell特异有效
- **bare失败已确认**（POC-2.5已验证）
- **vein不够**——POC-2.5的场景2（vein不够时Hint补上了），不是场景1（vein够时Hint无因果作用）
- 过程信号可观察——能区分"执行了目标过程"和"只是做出来了但没执行目标过程"

### 4.2 TellCore

383号确定的TellCore v0候选C（局部-全局表示切换），7字段最小充分集：
1. invariant_claim
2. trigger_boundary
3. negative_boundary
4. parameter_slots
5. internal_policy
6. progress_model
7. termination

POC-6需要从TellCore中**拆出不同组件**来构造干预条件：
- **trigger only**：只给trigger_boundary的提示（"当问题在自然表示下陷入困境时，考虑切换表示"）
- **method only**：只给internal_policy的提示（"切换到局部表示Z/pZ，在局部表示下找整除性/周期性/符号结构，提升回全局"）
- **critic only**：只给negative_boundary+progress_model的提示（"如果切换后找不到不变量，或如果题目关键结构与Z/pZ不变量不兼容，应该退出"）
- **full Tell**：完整7字段的HintInstance

### 4.3 干预条件

**首轮轻量矩阵（6个条件）**（373号§11.2）：

| 条件 | 给AI什么 | 检验什么 |
|---|---|---|
| **bare** | 只有题目 | 基线能力（应失败） |
| **通用鼓励** | 题目+"仔细思考，你一定能做出来" | 额外动力效应 |
| **等长空流程** | 题目+与full Tell等长但无目标内容的反思结构 | 一般反思结构效应 |
| **等强度错配Tell** | 题目+与full Tell等强度但目标不匹配的Tell | 提示强度效应 |
| **method only** | 题目+internal_policy提示 | 操作步骤本身的作用 |
| **full Tell** | 题目+完整7字段HintInstance | 完整认知Option效应 |

**第二轮扩展矩阵（追加5个条件，扩展为372号完整矩阵）**：

| 条件 | 给AI什么 | 检验什么 |
|---|---|---|
| **trigger only** | 题目+trigger_boundary提示 | 识别提醒本身的作用 |
| **critic only** | 题目+negative_boundary+progress_model提示 | 失败监控的作用 |
| **trigger + method** | 题目+trigger_boundary+internal_policy提示 | 进入条件与执行协同 |
| **method + critic** | 题目+internal_policy+negative_boundary+progress_model提示 | 执行与监控协同 |
| **过强窄方法提示** | 题目+"对这道题用模4分组"级别提示 | 标定泄漏上界 |

### 4.4 Solver模型

主模型：GLM-5.2 High（通过solver_harness启动）

从source trace题提取脉络。**关键**：POC-6需要在POC-2.5确认"vein不够"的题上进行——如果vein够，所有条件可能都成功（Mid-Hint问题重现）。所以POC-6使用vein但确保vein本身不够（POC-2.5的场景2）。

## §5 方法——这个POC怎么做

### 5.1 实验设计

**首轮**：对4道正迁移题，每道做6个干预条件（轻量矩阵），共24个run。

**第二轮**（如果首轮通过）：对同样的4道正迁移题，追加5个干预条件（扩展矩阵），共20个run。

### 5.2 观察指标

每个run记录（373号§11.3 AttributionMatrixResult结构）：

- **final_outcome**：解题成功/失败
- **target_action_observed**：是否出现目标认知动作（引入新表示/比较原表示与新表示/找到不变量/产生可验证lemma）
- **progress_signal_observed**：是否出现progress model预期的中间信号
- **leakage_risk**：泄漏风险评估
- **notes**：特殊观察

### 5.3 判定逻辑

**关键判定1：full Tell vs bare**
- full Tell成功 + bare失败 → Tell有增益（但增益来源待定）
- full Tell失败 + bare失败 → Tell无增益（回到POC-2.5确认基础效应是否存在）
- full Tell成功 + bare成功 → 题目不够难（正迁移题准入条件不满足）

**关键判定2：full Tell vs 通用鼓励**
- full Tell成功 + 通用鼓励失败 → 增益不是来自额外动力
- full Tell成功 + 通用鼓励也成功 → 增益可能来自额外动力（Tell特异性存疑）

**关键判定3：full Tell vs 等长空流程**
- full Tell成功 + 等长空流程失败 → 增益不是来自一般反思结构
- full Tell成功 + 等长空流程也成功 → 增益可能来自一般反思结构（Tell特异性存疑）

**关键判定4：full Tell vs 等强度错配Tell**
- full Tell成功 + 错配Tell失败 → 增益不是来自提示强度
- full Tell成功 + 错配Tell也成功 → 增益可能来自提示强度（Tell特异性存疑）

**关键判定5：full Tell vs method only**
- full Tell成功 + method only失败 → trigger和critic有贡献（完整认知Option重要）
- full Tell成功 + method only也成功 → **应降级trigger或critic的贡献声明**——增益主要来自method，trigger和critic可能是冗余的

**关键判定6：所有提示都有效（Mid-Hint问题重现）**
- bare失败 + 所有其他条件都成功 → **不能宣称目标Tell特异有效**——增益来自一般提示效应，不是Tell的因果贡献
- 这是387号Mid-Hint实验"vein够时所有提示都有效"的POC-6版本——必须诚实记录

### 5.4 过程层vs结果层

POC-6不只看最终成功/失败，还要看**过程层差异**（396号§5.4过程因果链）：

```
Tell注入
  → 目标trigger被识别
  → 指定认知动作出现
  → 预期中间进展出现
  → 最终成功概率变化
```

即使两个条件都成功，如果只有full Tell组出现了目标认知动作（引入新表示→比较→找不变量→可验证lemma），而其他条件组用不同方法成功，那仍然说明full Tell有过程层增益——它推动了目标认知策略，而不只是让AI做出来。

### 5.5 操作步骤

1. 从382号CasePack v0取4道正迁移题（确认POC-2.5场景2：vein不够时Hint补上了）
2. 从383号TellCore v0拆出不同组件：trigger_boundary / internal_policy / negative_boundary+progress_model / 完整7字段
3. 构造6个首轮干预条件（bare/通用鼓励/等长空流程/等强度错配Tell/method only/full Tell）
4. 从382号source trace题提取脉络
5. 对每道正迁移题，通过solver_harness启动6个首轮run
6. 记录每个run的final_outcome/target_action_observed/progress_signal_observed/leakage_risk
7. 按§5.3的判定逻辑分析结果
8. 如果首轮通过，构造5个第二轮扩展条件（trigger only/critic only/trigger+method/method+critic/过强窄方法提示）
9. 对每道正迁移题，通过solver_harness启动5个第二轮run
10. 产出AttributionMatrixResult

### 5.6 与POC-2.5的关键差异

POC-2.5验证的是"Hint是否比bare更好"（基础因果效应），POC-6验证的是"增益到底来自哪里"（归责）。两者的关系：

| | POC-2.5 基础因果效应 | POC-6 可归责 |
|---|---|---|
| 问题 | Hint比bare更好吗？ | 增益来自哪里？ |
| 对照 | bare vs bare+vein+Hint | bare vs 通用鼓励 vs 等长空流程 vs 错配Tell vs method only vs full Tell |
| 成功标准 | bare+vein+Hint成功率>bare成功率 | full Tell有过程层增益且其他条件不能稳定复制 |
| 关注 | 结果层（成功/失败） | 过程层（目标认知动作出现率）+ 结果层 |

POC-2.5是POC-6的前提——先确认"有增益"，再归责"增益来自哪里"。

## §7 通过标准

### 7.1 通过标准（373号§11.4）

**POC-6通过，需要满足**：

1. **full Tell相对bare和通用鼓励有过程层增益**——full Tell组的目标认知动作出现率明显高于bare和通用鼓励（不只是成功率更高，而是目标过程出现率更高）
2. **等长空流程不能稳定复制目标过程**——等长空流程即使成功，也不是通过目标认知动作成功的
3. **错配Tell不能稳定复制目标过程**——错配Tell即使成功，也不是通过目标认知动作成功的
4. **method only若同样有效应降级trigger或critic的贡献声明**——如果method only和full Tell效果一样，诚实承认trigger和critic可能是冗余的
5. **如果所有提示都有效，不能宣称目标Tell特异有效**——这是最关键的诚实性标准，387号Mid-Hint实验已经显示"vein够时所有提示都有效"的情况

### 7.2 不通过的处理

**如果条件1不满足（full Tell没有过程层增益）**：
- 增益可能不存在——回到POC-2.5确认基础因果效应
- 增益可能存在但来自结果层不是过程层——full Tell让AI做出来了但没有通过目标认知动作做出来——需要审视HintInstance是否正确渲染了目标认知策略

**如果条件2不满足（等长空流程也能稳定复制目标过程）**：
- 增益来自一般反思结构——任何等长的反思提示都能让AI进入目标过程
- Tell的特异性存疑——需要分析是目标过程本身不难触发，还是等长空流程恰好包含了目标过程的暗示

**如果条件3不满足（错配Tell也能稳定复制目标过程）**：
- 增益来自提示强度——任何等强度的提示都能让AI做出来
- Tell的特异性存疑——需要分析是题目本身不难（提示强度够了就行），还是错配Tell恰好包含了目标过程的暗示

**如果条件4触发（method only和full Tell效果一样）**：
- 这不是"不通过"——这是**重要的归责发现**：增益主要来自method，trigger和critic可能是冗余的
- 应该降级trigger和critic的贡献声明——在EvidenceRecord中诚实记录
- 可能需要回到POC-1简化TellCore——如果trigger和critic冗余，7字段最小充分集可能不是最小

**如果条件5触发（所有提示都有效——Mid-Hint问题重现）**：
- 这不是"不通过"——这是**重要的诚实性发现**：目标Tell没有特异有效，增益来自一般提示效应
- **不能宣称目标Tell特异有效**——在EvidenceRecord中明确记录
- 继续做POC-7（反例识别不依赖Tell特异有效）和POC-8（端到端闭环——但闭环报告要诚实记录"Tell没有特异效应"）

### 7.3 模糊结果的处理

**如果结果是mixed（不同题上增益来源不同）**：
- 记录哪些题上Tell有特异效应、哪些题上所有提示都有效
- 分析差异——是题目类型不同、还是vein质量不同、还是HintInstance强度对不同题效果不同
- 模糊结果不阻塞POC-7，但要在AttributionMatrixResult中明确记录哪些题上Tell有特异效应，后续POC只在这些题上做

### 7.4 通过后不意味着Tell"特异有效"——只意味着"增益可以归因"

**重要**：POC-6通过有三种可能的结果：

1. **Tell特异有效**（条件1-3都满足）：full Tell有过程层增益且其他条件不能复制——增益确实来自Tell的因果贡献
2. **Tell部分有效**（条件4触发）：增益主要来自method，trigger和critic冗余——应降级组件贡献声明
3. **Tell没有特异效应**（条件5触发）：所有提示都有效——不能宣称Tell特异有效

三种结果都是POC-6的合法产出——关键是**诚实归因**，而不是"通过"或"不通过"。即使结果是"Tell没有特异效应"，这也是重要发现——它揭示了增益的真实来源（一般提示效应或脉络继承），避免后续POC建立在错误归因上。

## §9 执行约束

### 9.1 Solver启动

数学Solver必须通过`xishujuzhen/solver_harness/solver_harness.py launch`启动，不能手动tmux、nohup或绕过harness。

### 9.2 ArangoDB

启动任何连接ArangoDB的脚本前，必须确认`echo $ARANGO_DB`输出`xishujuzhen_math_glm52`。

### 9.3 Git

- Git add必须显式路径，不能`git add -A`或`git add .`
- 产物文件（poc_6_result.yaml / poc_6_analysis.md / 每个run的导出）必须commit

### 9.4 POC运行记录

POC运行记录必须保留thinking、trajectory、proof或TUI导出。通过solver_harness自动保存。

### 9.5 证据分层

POC结论必须写成证据分层——不把"full Tell有过程层增益"升级成"Tell有效"。过程层增益只是因果贡献的一个维度，Tell是否真正"有效"还需要POC-8端到端闭环来综合验证。

### 9.6 诚实归责

POC-6最重要的执行约束是**诚实归责**——即使结果是"Tell没有特异效应"或"method only就够了"，也必须如实记录，不能为了"通过"而选择性报告。归责的目的不是证明Tell有效，而是**搞清楚增益到底来自哪里**。

### 9.7 失败不是废结果

如果POC-6显示"所有提示都有效"（Mid-Hint问题重现），这不是废结果——这是重要发现。它揭示了增益的真实来源（一般提示效应或脉络继承），避免后续POC建立在错误归因上。不通过的结果必须完整记录。

### 9.8 等长空流程和等强度错配Tell的构造质量

等长空流程和等强度错配Tell的构造是POC-6的关键难点——它们必须在长度和强度上与full Tell匹配，但内容上不包含目标认知策略。如果等长空流程恰好包含了目标过程的暗示（如"反思一下你的表示是否合适"），它就不是真正的"空流程"。构造时必须确认：等长空流程不包含目标认知动作的任何暗示，等强度错配Tell指向的认知策略与目标Tell完全不同。

### 9.9 选题不能极端

373号§14.9特别指出：POC-6尤其不应选极端难题。可归责实验需要各条件之间有可观察差异——如果所有条件全失败，矩阵无法告诉我们Tell组件是否有效；如果所有条件全成功，矩阵显示"所有提示都有效"但无法区分来源。选题时必须确保bare失败但full Tell成功的"中间难度"题目。
