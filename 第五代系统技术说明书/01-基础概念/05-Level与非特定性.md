## 1. Level（提示的抽象度）

**Level**是一个0到1的实数，量化提示的抽象度——也就是提示距离具体数学知识有多远。

- **Level → 1**：纯思维模式——跨领域通用的元认知策略，不依赖具体数学知识。例如"试试反证法"——任何领域都可以用这个策略，不需要知道具体定理。
- **Level → 0**：纯知识——绑定特定领域的具体定理/技巧。例如"用badly approximable性质"——这是数论中的具体定理，只在这个知识范围内有意义。

### 具体例子（来自矩条件极差题的10轮QA序列）

| 提示 | Level | 类型 | 说明 |
|---|---|---|---|
| "描述这道题的结构形状" | 1.0 | 纯思维模式 | 任何题目都可以问这个问题，不依赖数学知识 |
| "把每个点分解成最近关键点+偏差" | 0.7 | 思维操作 | "投影分解"是跨领域的思维模式，但"投影到根"有一定具体性 |
| "D能等于0吗？至少有多大？" | 0.5 | 量级感知 | "问问某个量至少有多大"是通用思维模式，但D是这道题特有的量 |
| "badly approximable性质" | 0.2 | 纯知识 | 数论中的具体定理，只在这个知识范围内有意义 |

### Level的本质

Level不是被精确赋值的，而是**被感知的**——它是经验的、模糊的、相对的。AI能感受Level的差异的模糊大小，但不需要精确计算。Level越高，提示越通用、越跨领域；Level越低，提示越绑定具体知识。

## 2. 非特定性程度（对答案知识的依赖度）

**非特定性程度**是一个0到1的实数（越大越特定），量化提示的有效性是否依赖于引导者知道正确解答路径。

- **非特定性 → 0**（完全非特定）——引导者不需要知道答案就能发出这个提示。例如"列出你能想到的所有可能方向"——任何题目都可以问，完全不需要知道答案。
- **非特定性 → 1**（完全特定）——引导者必须知道答案才能发出这个提示。例如"用badly approximable性质"——必须知道答案路径中需要这个性质才能发这个提示。

### 具体例子

| 提示 | 非特定性 | 说明 |
|---|---|---|
| "列出你能想到的所有可能方向" | 0.0 | 任何题目都可以问，完全不需要知道答案 |
| "把每个点分解成最近关键点+偏差" | 0.6 | 需要知道"投影到根"是正确方向才能发，但不需要知道后续步骤 |
| "D能等于0吗？至少有多大？" | 0.7 | 需要知道D是关键量才能发，这接近于知道答案 |
| "badly approximable性质" | 0.9 | 必须知道答案路径中需要这个性质才能发 |

### 非特定性的本质

非特定性衡量的是"引导者发出这个提示是否需要知道答案"。非特定性越低（→0），引导者越不需要知道答案，提示越安全（不会泄漏答案）；非特定性越高（→1），引导者越需要知道答案路径，提示越接近"递答案"。

## 3. Level和非特定性的关系

通常Level越低（越接近知识），非特定性越高（越需要知道答案）。但两者不完全等价——

**反例**：提示"D能等于0吗？至少有多大？"的Level=0.5（中等抽象——"问问某个量至少有多大"是通用思维模式），但非特定性=0.7（相当特定——要知道D是关键量才能发这个提示）。

这意味着：**Level和非特定性是两个独立的维度。**
- Level衡量的是"提示内容的抽象程度"
- 非特定性衡量的是"发出这个提示是否需要知道答案"

一个提示可以是中等抽象的（Level=0.5），但仍然相当特定（非特定性=0.7）——因为它虽然形式上是思维模式，但要知道哪个量是关键量才能发出。

## 4. Level在第五代中的应用

在第五代系统中，Level用于tell和hint的分层：

### tell端的Level分层

- **大概念**（高Level，对应L2级别）——tell的拓扑维度（problem_type + ai_method_type + gap_type），可跨题泛化
- **小概念**（低Level，对应L1-L2之间）——更细的区分概念，用于在大概念无法区分时进一步细分

### hint端的Level分层

- **高Level方向**（L2-L3级别）——如"翻译语言"，跨领域泛化
- **Low Level化方向**（L1级别）——如"翻译到模算术"，领域特化

### Pipe架构中的Level排序

Pipe 1优先匹配高Level（大概念缩小范围），Pipe 2用低Level（小概念做精准识别）。这是"先大概念后小概念"的策略——先用高Level缩小搜索空间，再用低Level精准定位。

## 5. 非特定性在第五代中的应用

### tell+hint的非特定性检验

tell识别（Pipe 0/1/2）和hint注入（翻译方向）都是**非特定的**——它们不需要知道答案就能工作。

检验方法：去掉答案等价信息后，tell识别和hint注入是否仍然有效？如果仍然有效，说明是非特定的；如果增益消失，说明特定性太高（等于递答案）。

### 非特定性=边界推进能力

这是第三代（伏羲）的核心洞察，第五代继承并工程化了：非特定性不是"抽象度高"，而是"方法可从形式化边界以外使用"=边界推进能力。检验一个引导方法是否非特定，就是检验它能否在不知道答案的情况下推进形式化边界。

### POC-VMS-8的验证

POC-VMS-8验证了高Level hint的非特定性——翻译方向（如"翻译到模算术"）不包含答案，但bare 0% → tree 67%的有效性证明：不需要知道答案，只需要给方向引导，就能帮AI突破卡点。

## 6. 最小知识传递

**最小知识传递**是第二代（燧人）提出的优化目标，第五代继承：

形式化定义：**argmax ΣLevel(h_i)**——在"AI能完成解题"的约束下，最大化所有提示的Level之和。

含义：优先给高Level（非特定、不泄漏答案）的提示。如果纯高Level提示无法完成解题，才适时降低Level走向知识端。

在第五代中，这个原则体现为：
- 优先给翻译方向（Level 0.5-0.8，不泄漏答案）
- 只有在翻译方向不够时才给更具体的知识（Level < 0.3，可能泄漏答案）
- hint_gradient提供从高泄漏到低泄漏的降级机制

POC-VMS-8验证了高Level hint（翻译方向）的有效性——bare 0% → tree 67%，证明高Level hint足够，不需要降低到知识端。
