## 1. 引导展开树（过程）

**引导展开树（Guided Expansion Tree）** 是从题目出发，在提示驱动下展开的所有可能解题路径构成的空间。

拆开说：

- **每个节点** = 一个数学处境——当前已知什么、当前表示是什么、当前猜想是什么、卡在哪里
- **每条边** = 一个提示Q（也就是一个hint）——引导从一个处境移动到另一个处境的语义移动
- **每条从根到叶的路径** = 一次完整的解题尝试
- **树的分支** = 在某个处境岔口，有不同的提示方向，每个方向展开出一条不同的路径

它**不是搜索树**——搜索是"在已知状态空间中找目标"，这里的路径不是预先存在于一个已知空间中等待被搜索，而是通过提示逐步**展开/生长**出来的。

它**不是决策树**——决策树是分类/回归模型，这里是解题过程的记录。

它**不是依赖图**——依赖图是数学知识之间的依赖关系，这里是解题的尝试路径。

引导展开树是**活的、正在生长的**。每当系统识别出一个新的tell并匹配了hint，引导树就长出一条新边，启动的新AI在新边上探索，产生新节点。

## 2. 解题记录树（产物）

**解题记录树（Solution Record Tree）** 是一道题在引导下被探索过的所有路径的完整记录——包括成功路径和失败路径。

- 根 = 题目
- 内部节点 = 解题过程中经过的各个处境
- 边 = 提示Q
- 叶节点 = 成功叶（证毕）/ 死路叶（走不通）/ 截断叶（超限停止）
- 多条成功路径可能并存

解题记录树是**展开完成后凝固的树**。它是引导展开树的完成态——同一棵树，只是停止生长了。

## 3. 两棵树的关系

**它们是同一棵树的不同阶段。**

- **引导展开树** = 过程中正在生长的树，活的，还在展开
- **解题记录树** = 展开完成后凝固的树，是引导展开树的完成态

如果不做后处理（剪枝、提炼），它就是引导展开树的完成态——同一棵树，只是停止生长了。

如果做后处理（剪掉死路、只保留成功路径、提炼成Pattern），那后处理后的产物是从这棵树中提取出来的，不是这棵树本身。

## 4. 为什么"DFS"不应在树的名字中

之前的文档把引导展开树称为"DFS引导架构"或"DFS树"。这个命名把遍历策略和树的结构混为一谈了：

| 概念 | 性质 | 独立于遍历策略吗 |
|---|---|---|
| 树的结构（节点+边+路径） | 空间结构 | 是——树是什么样子不取决于你怎么遍历它 |
| 遍历策略（DFS/BFS/并发） | 算法 | 否——遍历策略决定了你按什么顺序探索树 |

把"DFS"放进树的名字，隐含了一个假设：这棵树只能用DFS遍历。但并发DFS（识别N个方向→启动N个AI→并发探索）不是传统DFS，它是同时展开多个分支。未来可能还有其他遍历策略。

**正确做法**：树有树的名字（引导展开树/解题记录树），遍历策略有遍历策略的名字（串行DFS/并发DFS/...），两者分离。

## 5. 数据基座是过去解题记录树的沉淀

数据基座（也称为"稀疏矩阵"或"认知图"——三个名称指的是同一个ArangoDB图数据库）的作用是什么？

**数据基座是过去解题记录树的沉淀**——把过去树中的分叉点、成功路径、失败路径提炼成Pattern（模式），供未来生长新树时做模式识别。

```
过去的解题记录树 → 提炼 → 数据基座中的Pattern
                                    ↓
                              未来模式识别
                                    ↓
新的引导展开树 ← 检索到方向Q ← 数据基座中的Pattern
```

这是一个**自我增殖的循环**：树越长越全 → Pattern越积越多 → 模式识别越准 → 未来的树长得越全。

在第五代系统中，数据基座中的Pattern分为两类：
- **tell数据基座**——存储tell模式（什么时候该识别什么分叉信号），用于tell端的三层Pipe检索
- **hint字典**——存储翻译方向（什么时候该给什么方向引导），用于hint端的方向匹配

## 6. 评测标准：不是"做没做出来"，而是"树长得多完整"

如果系统的本质是"生长完整的解题记录树"，那系统的能力边界不是"能不能做出某道题"，而是**"能长出多完整的树"**。

| 系统等级 | 特征 |
|---|---|
| 弱系统 | 长出一条路径就停了（裸跑AI） |
| 中等系统 | 长出几条路径，找到一条成功的（当前guided实验） |
| 强系统 | 长出完整的树，所有值得探索的方向都探索到，成功路径和失败路径都记录，分叉点都标注 |
| 大师级系统 | 长出的树足够完整，从中提炼的Pattern能让未来类似题的树长得更快更准 |

**评测系统不应该只看"做没做出来"，应该看"树长得多完整"。** 一道题做出来了但只探索了一条路径，不如一道题做出来了同时记录了5条失败路径和3个分叉点——后者才是更完整的解题记录树，才是更有价值的资产。

一棵完整的解题记录树包含：

| 组成 | 价值 | 没有系统时AI的表现 |
|---|---|---|
| 成功路径 | 这道题的解答 | AI可能找到1条或0条 |
| 失败路径 | 什么方向走不通、为什么 | AI卡住就停了，不记录失败 |
| 分叉点 | 在什么处境下有哪些方向 | AI只走自己想到的一个方向，不知道还有其他 |
| 中间处境 | 解题经过的各个状态 | AI不记录中间状态，只给最终答案 |

## 7. 树在ArangoDB中的存储

两棵树在ArangoDB中维护，每道题一棵树。树=节点集合+边集合。主要集合包括：

- **tree_nodes**（document集合）——每个节点是一个数学处境，包含node_type（root/internal/leaf_success/leaf_deadend/leaf_truncated）、situation（六元组状态）、depth、path_from_root等字段
- **tree_edges**（edge集合）——每条边是一个提示Q，包含_from/_to（父节点→子节点）、hint_q（提示内容）、hint_level、ai_instance_id等字段
- **problems**（document集合）——每道题一棵树，包含status（growing/solved/exhausted）、solution_path等字段
- **ai_instances**（document集合）——每个推理AI实例的注册信息，包含entry_node_key（从哪个节点进入树）、脉络文本、hint_q、status等字段

详细的schema定义见07-工程规格/05-ArangoDB-schema.md。
