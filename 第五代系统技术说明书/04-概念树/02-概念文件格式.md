## 1. 概念文件的定义

**概念文件**是把不同的细分范围的概念（同一大概念下的所有小概念）放到同一个文件中的产物。这个文件可以被AI加载，用于对推理AI的上下文中"疑似为某个大概念下的小概念"的内容进行细化的"标记"分辨。

概念文件是Pipe 2的输入——当Pipe 1用大概念缩小到某个大概念范围后，Pipe 2加载该大概念对应的概念文件，用文件中的小概念信号词做标记分辨。

## 2. 概念文件的JSON格式

```json
{
  "concept_file_id": "CF-structural-enumeration-mismatch",
  "parent_big_concept": {
    "problem_type": "structural_existence",
    "ai_method_type": "enumeration_brute_force",
    "gap_type": "method_problem_mismatch"
  },
  "small_concepts": [
    {
      "name": "素数存在性",
      "standard_description": "AI在枚举序列参数a的值，试图用covering system覆盖所有情况，但问题是Mersenne素数的存在性，需要用二次剩余/Euler准则",
      "signal_markers": ["mersenne", "primality", "covering", "covering_system"],
      "related_tell_ids": ["tell-A-1631"]
    },
    {
      "name": "整除性判定",
      "standard_description": "AI在枚举差分参数a的值，试图逐一验证条件，但问题是最大奇因子差的整除性判定，需要用2-adic赋值分case分析模4行为",
      "signal_markers": ["largest_odd_divisor", "divisibility_4", "p_adic", "difference"],
      "related_tell_ids": ["tell-B-1709"]
    }
  ],
  "version": 2,
  "last_updated": "2026-08-08"
}
```

## 3. 各字段详解

### concept_file_id
概念文件的唯一标识符。命名规范：`CF-<大概念简述>`。

### parent_big_concept
该概念文件对应的大概念拓扑。包含problem_type/ai_method_type/gap_type三个维度。

### small_concepts
该大概念下的所有小概念列表。每个小概念包含：

- **name**：小概念名称，如"素数存在性"
- **standard_description**：标准化语言描述——AI在做什么/问题是什么/正确方向是什么
- **signal_markers**：小概念信号词列表——从标准化语言描述中提取的关键词，用于Pipe 2在thinking中做标记分辨
- **related_tell_ids**：使用该小概念的tell ID列表

### version
概念文件的版本号。随tell数量增长更新时递增——新增小概念或新增信号词时版本号+1。

### last_updated
最后更新时间。

## 4. POC-VMS-10中的概念文件示例

POC-VMS-10中的两个tell（tell-A和tell-B）的大概念拓扑完全相同，放入同一个概念文件：

```
概念文件：CF-structural-enumeration-mismatch
├── 大概念：(structural_existence, enumeration_brute_force, method_problem_mismatch)
├── 小概念1：素数存在性
│   ├── 信号词：mersenne, primality, covering, covering_system
│   └── 关联tell：tell-A (1631题)
└── 小概念2：整除性判定
    ├── 信号词：largest_odd_divisor, divisibility_4, p_adic, difference
    └── 关联tell：tell-B (1709题)
```

Pipe 2加载这个概念文件后，在thinking中统计两个小概念的信号词频次：
- 1631题的thinking中：mersenne/primality/covering命中856次→小概念1（素数存在性）胜出→选tell-A
- 1709题的thinking中：largest_odd_divisor/divisibility_4/p_adic命中41次→小概念2（整除性判定）胜出→选tell-B

## 5. 概念文件与大概念的对应

每个大概念对应**一个或多个**概念文件。当小概念数量多时可以分多个文件：

- 小概念少（<20个）→一个概念文件包含所有小概念
- 小概念多（20-100个）→按子领域分多个概念文件
- 小概念很多（100+个）→按更细的子分类分多个概念文件

分文件的目的是控制单个概念文件的大小——辅助AI的上下文是有限的，单个概念文件不能太大。

## 6. 概念文件与tell数据基座的关联

概念文件中的每个小概念通过`related_tell_ids`字段关联到tell_db中的具体tell文档。

概念文件是**tell数据基座的索引视图**——它把同一大概念下的tell按小概念分组，为Pipe 2提供结构化的检索入口。

```
tell_db集合（原始数据）
├── tell-A (big_concept=structural-enumeration-mismatch, small_markers=mersenne/primality/...)
├── tell-B (big_concept=structural-enumeration-mismatch, small_markers=largest_odd_divisor/...)
├── tell-C (big_concept=discrete-continuous-mismatch, ...)
└── ...

概念文件（索引视图）
├── CF-structural-enumeration-mismatch
│   ├── 小概念"素数存在性" → tell-A
│   └── 小概念"整除性判定" → tell-B
├── CF-discrete-continuous-mismatch
│   └── ... → tell-C
└── ...
```

## 7. 概念文件的版本管理

概念文件随tell数量增长需要更新——新增tell可能导致：
- 在已有小概念下新增related_tell_id
- 新建小概念（当新tell的内容不属于已有任何小概念时）
- 新增信号词（当新tell的标准化语言描述中出现新的区分性关键词时）

每次更新时版本号递增，记录last_updated时间。

概念文件和ArangoDB的concept_tree集合保持同步——文件系统中的概念文件和数据库中的concept_tree集合是一份数据的两个存储形式。详见04-概念树/05-概念树schema.md。
