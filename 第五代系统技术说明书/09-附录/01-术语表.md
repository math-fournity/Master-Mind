# 术语表

**前置阅读**：无（这是参考文件）
**来源**：000号、287号、256号、AGENTS.md术语备忘

---

| 术语 | 定义 |
|---|---|
| **tell** | 从推理AI的thinking中读出的分叉信号——AI没有考虑什么、在哪里可以分叉但没分叉。取自poker术语——观察对手揭示出的信息 |
| **hint** | 给新AI的翻译方向——从字典中匹配的具体翻译方向。如"翻译到模算术" |
| **Pipe 0** | tell识别三层架构的第一层：拓扑化——将thinking编码为带有结构和标注的拓扑结构 |
| **Pipe 1** | tell识别三层架构的第二层：形式化过滤——用拓扑相似/等价缩小tell范围（大概念匹配） |
| **Pipe 2** | tell识别三层架构的第三层：小概念标记分辨——在同分候选中用小概念精准识别 |
| **拓扑/拓扑化** | 将thinking编码为结构化的拓扑表示（problem_type + ai_method_type + gap_type）。不是关键词匹配或RAG语义相似，而是结构匹配 |
| **大概念** | tell的拓扑维度（problem_type/ai_method_type/gap_type），粗粒度，用于Pipe 1形式化过滤 |
| **小概念** | 大概念无法区分时引入的更细的概念，细粒度，用于Pipe 2小概念标记分辨。从tell的标准化语言描述中提取的信号词 |
| **概念树** | 大概念→小概念→概念树的层次化管理结构。无论tell数量如何增长、概念树如何膨胀，有限上下文的辅助AI都能系统化应对 |
| **概念文件** | 把同一大概念下的所有小概念放入同一个文件。可以被AI加载用于做细化标记分辨 |
| **引导展开树** | 过程——从题目出发在提示驱动下展开的所有可能解题路径构成的空间。活的、正在生长的 |
| **解题记录树** | 产物——引导展开树展开完成后凝固的树。包含成功路径、失败路径、分叉点、中间处境 |
| **Grove核心循环** | 引导树→推理AI→解题树→在终点节点检索→引导树新边→启动新推理AI→... |
| **脉络/lineage** | 从根到当前节点的路径+方向Q，构造给新推理AI的输入文本。让新AI在已有推理基础上继续探索 |
| **根分叉** | 分叉位置在根节点——AI从第一步就选错了方向，line上后面的point都是错误路径上的次级分叉 |
| **点分叉** | 分叉位置在line上的某个point——AI方向没错但在某个点走错了 |
| **Level** | 提示的抽象度（0-1实数）。→1纯思维模式（跨领域通用），→0纯知识（绑定特定领域） |
| **非特定性** | 发出提示是否需要知道答案（0-1实数，越大越特定）。→0完全非特定（不需要知道答案），→1完全特定（必须知道答案） |
| **Pattern** | 稀疏矩阵中存储的"什么时候该提示什么"的经验单元 |
| **DFS** | 深度优先搜索。串行DFS一次一个方向走不通回溯，并发DFS同时多个方向不需要回溯 |
| **辅助智能体/Guide** | 系统Pipe/园丁——采集thinking、整理两棵树、在节点上识别方向、构造脉络、启动新AI |
| **推理智能体/Solver** | 做题AI——在提示下尝试解题，产出每一步的推理 |
| **数据基座/稀疏矩阵/认知图** | 三个名称指同一个东西：所有Pattern经验的ArangoDB图数据库存储 |
| **分叉信号** | tell的成分1——从thinking中识别出的可以分叉但AI没分叉的位置 |
| **分叉类型** | tell的成分2——对分叉信号的抽象分类（翻译类型/操作路径类型/...） |
| **未探索诊断** | tell的成分3——AI为什么没走这条路、这条路通向什么 |
| **方向匹配** | tell的成分4——从未探索诊断到字典中具体翻译方向的映射 |
| **hint字典** | 高Level方向→分领域low level化→24+个翻译方向的离线建好冻结的字典 |
| **Hint梯度** | H0(元检查)→H1(思维操作)→H2(工具概念候选)→H3(确定关系)→H4(最终答案)的泄漏控制 |
| **回溯铁律** | 禁止同Session回溯，必须新Session重放Q序列到岔口换方向 |
| **标准化语言描述** | tell的自然语言描述，包含"AI在做什么/问题是什么/正确方向是什么"三部分。小概念信号词的来源 |
| **自我增殖** | 过去的解题记录树→提炼→Pattern→数据基座→未来模式识别→新的引导展开树→...的循环 |
