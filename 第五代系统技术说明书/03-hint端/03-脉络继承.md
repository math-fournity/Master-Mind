## 1. 脉络的定义

**脉络**是从根到当前节点的路径+方向Q，构造给新推理AI的输入文本。

当系统在推理AI的某个节点上识别出tell并匹配了hint后，不是只给新AI一个hint方向，而是给它**完整的脉络**——"你之前已经证明了X、Y、Z，现在请继续探索方向W"。

## 2. 脉络文本格式

脉络文本包含以下部分：

```
你正在解答以下数学题：
[题目原文]

之前已经进行了以下探索：

[节点0] 初始处境：题目给出的条件和目标
  → 提示Q1：[Q1内容]
[节点1] 处境：[从thinking中提取的数学处境描述]
  已证明：[已确立的结论]
  当前表示：[当前的数学表示]
  → 提示Q2：[Q2内容]
[节点2] 处境：[...]
  ...
[节点n] 当前处境：[当前节点的数学处境描述]
  已证明：[到目前为止已确立的结论]
  当前表示：[当前的数学表示]
  卡在：[当前卡点]

请理解验证以上路径后，继续探索以下方向：
[方向Q的内容]

继续推理，给出完整的推理过程。
```

脉络的本质是：把从根到当前节点的完整推理路径重放给新AI，让新AI在已有推理基础上继续探索，而不是从零开始。

## 3. 脉络继承解决了两个问题

POC-VMS-8的关键发现是：**单独给字典不够，单独给脉络不够，脉络+方向=成功。**

### 问题1：到达转折点

静态组的AI可能根本到不了需要翻译的那个点。例如1631题的关键转折点是x₃≡7(mod 8)→二次剩余→Euler准则。如果AI走了covering system方向，它可能永远到不了x₃≡7(mod 8)这个点。

脉络继承解决了这个问题——脉络把AI引导到转折点之前的位置，新AI从转折点继续，不需要自己走到那里。

### 问题2：知道何时翻译

静态组的AI即使到了转折点，也不知道应该在这里翻译。dictionary组的AI拿到24个翻译方向但不知道在什么时候用哪个。

脉络继承解决了这个问题——脉络中明确标注了"请从这里继续，继续探索以下方向"，新AI知道这是转折点，知道应该用给定的方向。

## 4. POC-VMS-8的完整结果

| 组 | 给AI什么 | 脉络来源 | 成功率 |
|---|---|---|---|
| bare | 只给题目 | 无 | 0/3 = 0% |
| abstract | 题目+"翻译到另一种语言" | 无 | 0/3 = 0% |
| dictionary | 题目+完整字典 | 无 | 1/6 = 17% |
| matched | 题目+匹配的具体翻译 | 无 | 2/6 = 33% |
| **lineage** | 题目+脉络+方向 | 手写标准解答脉络 | **2/2 = 100%** |
| **tree** | 题目+脉络+方向 | bare AI的thinking提取 | **2/3 = 67%** |

### lineage组 vs tree组的区别

| | lineage组 | tree组 |
|---|---|---|
| 脉络来源 | 手写标准解答脉络（到转折点为止的完整正确推理） | 从bare AI的失败thinking中提取 |
| 方向匹配 | 人工匹配 | 人工匹配 |
| 成功率 | 2/2 = 100% | 2/3 = 67% |

lineage组100%因为脉络是标准解答的——到转折点为止的完整正确推理。tree组67%因为脉络是从bare AI的失败thinking中提取的——可能有不完整的推理或错误的方向尝试。

**真实引导树中脉络来自bare AI的thinking**——所以tree组的67%更接近真实场景的预期成功率。

## 5. 根分叉vs line上分叉的脉络区别

分叉位置不同，脉络的内容不同：

### 根节点分叉

脉络只有题目本身——没有已建立的推理脉络，新AI从根节点重新开始走另一条路。

这和bare AI（完全无引导的AI）有什么区别？区别在于方向匹配给了新AI一个翻译方向，而bare AI没有。这本质上是"bare AI + 方向"。

### line上分叉

脉络包含line到分叉点为止的推理——新AI从分叉点继续走另一条路。新AI有一个"半成品"的推理基础，只需要从分叉点开始换方向。

## 6. 脉络来自bare AI的thinking提取

在真实引导树中，脉络不是手写的标准解答脉络，而是从bare AI的失败thinking中提取的。

### 提取过程

1. bare AI开始解题，thinking被mitmproxy流式截获
2. 系统从thinking中提取节点（数学处境），写入树
3. bare AI终止（token_limit/崩溃/错误答案）
4. 系统在bare AI的终点节点上识别tell→匹配hint
5. 构造脉络：从根到终点节点的路径（即bare AI走过的所有节点）+方向Q
6. 启动新AI，给它脉络+方向

### 脉络质量

从bare AI的thinking提取的脉络可能包含：
- 正确的推理步骤（AI走对的部分）
- 错误的方向尝试（AI走错的部分）
- 不完整的推理（AI没做完的部分）

这就是tree组（67%）比lineage组（100%）成功率低的原因——脉络质量影响新AI的起点质量。

未来的改进方向：从bare AI的thinking中**只提取正确的推理步骤**，过滤掉错误的方向尝试，提高脉络质量。这是08-验证状态/04-验证总结与待验证项.md中列出的待验证项之一。

## 7. 脉络构造的工程实现

脉络构造的工程实现在`tree_engine.py`的`construct_path_text`函数中：

```python
def construct_path_text(path_from_root, problem_text, direction_q):
    """从根到当前节点的路径构造脉络文本"""
    lineage_text = f"你正在解答以下数学题：\n{problem_text}\n\n"
    lineage_text += "之前已经进行了以下探索：\n\n"
    for i, node_key in enumerate(path_from_root):
        node = tree_store.get_node(node_key)
        lineage_text += f"[节点{i}] 处境：{node.situation_text}\n"
        if node.verified_conclusions:
            lineage_text += f"  已证明：{node.verified_conclusions}\n"
        if node.edge_from_parent:
            edge = tree_store.get_edge(node.edge_from_parent)
            lineage_text += f"  → 提示：{edge.hint_q}\n"
    lineage_text += f"\n请理解验证以上路径后，继续探索以下方向：\n{direction_q}\n"
    lineage_text += "\n继续推理，给出完整的推理过程。"
    return lineage_text
```
