## 1. 回溯铁律

**回溯铁律**是第二代（燧人）提出的硬约束，第五代继承：**禁止在同一个Session中让AI回溯到某个思路岔口。必须启动新Session，重放Q序列到岔口，在岔口换方向。**

### 回溯铁律的三个原因

1. **压缩边界风险**——同一Session中回溯会导致context混乱，AI无法区分"之前的思路"和"新的思路"。Session可能触发压缩（context超限时），压缩后之前思路的细节丢失，回溯后的新方向推理缺乏基础。

2. **context污染**——之前思路的推理输出已经进入context，回溯后这些输出会干扰新方向的推理。AI在思考新方向时会不断看到旧方向的输出，产生混淆。

3. **不可逆性**——AI的推理过程一旦发生，其输出已经影响了对问题的理解，无法在同一Session中"假装没想过"。AI看了旧方向的推理后，它的思维已经被塑造，不能回到"没看过"的状态。

### 正确做法

新Session + 重放Q序列到岔口 + 在岔口换方向。

这意味着回溯不是"在同一对话中后退"，而是"开一个新对话，把之前的Q序列重新发一遍到岔口处，然后换一个方向继续"。这样推理智能体在岔口处有一个干净的context，只包含到岔口为止的推理，不包含被回溯的分支。

## 2. 并发DFS根本不需要回溯

第五代的并发DFS根本不需要回溯——每个方向从一开始就是独立的Session，独立的推理AI，独立的context。

不存在"回溯到岔口"的操作，因为岔口的每个分支都已经有一个独立的探索者在走了。走不通的分支自然终止（token_limit/崩溃），不需要回溯来切换方向。

## 3. 回溯铁律在第五代中的约束

虽然并发DFS不需要回溯，但回溯铁律仍然是约束——**不能在同一个AI的Session中让它换方向。** 需要换方向时启动新AI。

| 场景 | 回溯铁律的约束 |
|---|---|
| 并发DFS | 不需要回溯——每个方向独立Session。回溯铁律自动满足 |
| 串行DFS（如果使用） | 必须遵守回溯铁律——走不通时启动新Session重放Q序列 |
| 同一AI的Session中 | 禁止换方向——不能在同一Session中让AI从方向A切换到方向B |

## 4. 新Session重放Q序列

当需要回溯（串行DFS场景）时，新Session的重放过程：

1. 确定回溯目标——从根到岔口的Q序列
2. 启动新Session（通过solver-harness启动新devin cli实例）
3. 按顺序重放Q序列——把每个Q依次发给新AI
4. 到达岔口后，换一个方向——发新的方向Q
5. 新AI从岔口开始探索新方向

新AI在岔口处有一个干净的context——只包含到岔口为止的推理（通过Q序列重放建立的），不包含被回溯的分支。

## 5. 节点同一性

节点同一性是回溯时判断"两个节点是否是同一个节点"的问题。第二代（燧人）采用"路径同一性为主、状态同一性为辅"的混合定义：

### 路径同一性（主）

**node_id由Q路径决定**——同一个Q路径必然到达同一个节点。这是确定性的——给定相同的Q序列，必然到达相同的node_id。

### 状态同一性（辅）

**节点内容（A）是概率性的**——同一个Q路径，不同Session中推理AI的回复可能不同。同一个问题给同一个AI，每次回答可能不一样。

### 引导者判断

**A'和A是否"本质相同"由引导者判断**——虽然AI的回复是概率性的，但引导者（辅助AI）可以判断两个回复是否本质相同（都是"用了相同的方法"或"得到了相同的结论"）。

## 6. 回溯铁律与脉络继承的关系

回溯铁律的"新Session重放Q序列"和第五代的"脉络继承"是同一个机制的两种表述：

| | 回溯铁律（第二代） | 脉络继承（第五代） |
|---|---|---|
| 触发 | 走不通时回溯 | AI终止后在终点节点检索方向 |
| 做法 | 新Session + 重放Q序列到岔口 + 换方向 | 新Session + 脉络（Q序列+处境）+ 方向Q |
| 本质 | 在干净context中从岔口继续 | 在干净context中从当前节点继续 |

两者都是"启动新AI，给它之前的路径，让它从某个点继续探索新方向"。第五代的脉络继承是回溯铁律在并发DFS场景下的自然实现——不需要"回溯"到岔口，因为岔口就是AI终止的终点节点。
