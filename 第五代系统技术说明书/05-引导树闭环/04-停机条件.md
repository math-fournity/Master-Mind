## 1. 停机条件

**与正确解答的脉络相遇时停机，不需要所有分支都探索完。**

这是第五代系统的停机原则。系统的目的不是"让AI做出来"，而是"让两棵树生长出来，在过程中与正确解答的脉络相遇"。当某条脉络到达正确解答时，系统停机。

## 2. 系统的目的不是让AI做出来

这个认知非常重要——它改变了系统的评测标准和停机逻辑：

| 旧认知 | 新认知 |
|---|---|
| 系统的目的是让AI做出来 | 系统的目的是让两棵树生长出来 |
| 做出来=成功，做不出来=失败 | 与正确解答的脉络相遇=成功，树的生长过程本身有价值 |
| 评测标准：做没做出来 | 评测标准：树长得多完整 |

在新认知下：
- 即便AI在思考到一半时崩溃了（token用尽），我们仍然得到了解题记录树的增长信息——它探索了一个脉络的一部分
- 如果AI最终解出来了，一切圆满
- 如果没有，它的思考和探索记录也是有价值的——只要它探索了最终的解题记录树的一个脉络

## 3. 停机判定

停机判定的流程：

1. **检测AI最终输出是否包含完成标记**——"证毕"/"QED"/"boxed"/"证明完毕"等
2. **如果包含，提取证明过程**
3. **用SymPy/形式化验证工具验证证明的正确性**
4. **如果验证通过，标记为leaf_success**——problem标记为solved，记录solution_path
5. **如果验证不通过，标记为leaf_deadend**——看似成功但实际错误
6. **problem solved后不再从该树的叶节点启动新AI**——停机

```python
def check_solution_found(ai_instance):
    """检测AI是否找到了正确解答"""
    # 1. 检查AI的最终输出是否包含完成标记
    final_output = get_ai_final_output(ai_instance)
    if not has_completion_marker(final_output):
        return False
    
    # 2. 提取证明过程
    proof = extract_proof(final_output)
    
    # 3. 验证证明正确性
    if verify_proof(proof, problem.answer):
        # 4. 验证通过→标记leaf_success
        mark_leaf_success(ai_instance.last_node)
        mark_problem_solved(ai_instance.problem_id, solution_path=ai_instance.last_node.path_from_root)
        return True
    else:
        # 5. 验证不通过→标记leaf_deadend
        mark_leaf_deadend(ai_instance.last_node)
        return False
```

## 4. 验证工具

| 证明类型 | 验证工具 | 说明 |
|---|---|---|
| 数值题（有数值答案） | SymPy数值验证 | 提取AI的答案，与正确答案比较 |
| 证明题（有证明过程） | SymPy符号验证 + 人工审核 | 验证证明的关键步骤是否正确 |
| Lean4形式化证明 | Lean4验证器 | 如果AI产出Lean4证明，用Lean4验证器验证 |

## 5. 假完成检测

AI可能给出错误证明但自认为完成——这叫**假完成**。需要用独立于AI的机制检测：

- AI写了"证毕"但证明过程有逻辑错误
- AI给出了答案但答案不正确
- AI的证明依赖了未验证的假设

假完成检测通过SymPy数值验证+人工抽查实现。在MathArena baseline中已检测到假完成案例——AI写了proof但答案是错的（只算了小情形就猜pattern）。

## 6. 停机后的操作

problem标记为solved后：

1. **记录solution_path**——从根到成功叶的路径（节点key序列）
2. **更新problems集合**——status=solved, solved_at=当前时间, solution_path=路径
3. **不再从该树的叶节点启动新AI**——停机
4. **其他并发分支可以继续运行**（如果它们的探索还有价值），但不再为已solved的problem启动新AI
5. **从完成的树中提炼Pattern**（如果系统配置了自我增殖）——树→Pattern→数据基座

## 7. 穷尽停机

除了"与正确解答相遇"的停机，还有**穷尽停机**——所有方向都探索完但没有找到正确解答。

穷尽停机的条件：
- 所有的叶节点都是leaf_deadend或leaf_truncated
- 没有可分配的节点（所有节点的retrieval_done=true且directions_identified为空或已全部探索）
- 没有正在运行的AI

穷尽停机时，problem标记为exhausted。虽然没有找到正确解答，但树的生长过程本身有价值——记录了哪些方向走不通、为什么走不通，这些信息可以用于改进数据基座。
