# ch2 知识点提取：Determination and representation

## 知识点清单

**P1 概念的闭包刻画 (all concepts are closures)**
- **是什么**：一个形式背景 (G, M, I) 的每一个形式概念都可以写成 (X'', X') 的形式——对某个对象子集 X 取两次导出（先 X' 得到公共属性，再 X'' 得到拥有这些属性的所有对象）。反过来，每个这样的对都是一个概念。这意味着：概念的外延恰好是属性外延的交集，概念的内涵恰好是对象内涵的交集。不需要去找"别的"概念——所有概念都已经被闭包算子 X↦X'' 捕获了。
- **为什么需要它**：没有这个刻画，你面对一个交叉表时不知道"概念一共有多少个、长什么样"——只能盲目搜索所有 (A, B) 对。Prop 21 把搜索空间从"所有子集对"压缩到"所有子集的闭包"，告诉你概念不是随意冒出来的，它们恰好是闭包系统的元素。这是从"概念是什么"（ch1 的定义）到"概念怎么找"（ch2 的任务）的第一步桥梁。
- **关键关系**：依赖 ch0 的闭包算子 + ch1 的导出映射；是 P2（Next Extent 算法）的前提——算法正是利用"概念外延构成闭包系统"这一事实来枚举；与 P8（蕴含与闭包等价）同源——两者都来自 A'' 的闭包性质
- **崩塌条件**：在无限背景中，X'' 的迭代可能需要超限步骤才能达到闭包，"所有概念都是 X''"仍然成立但枚举不再有限可完成。在概念格无穷时，"逐一列举"的方法在实践中失效
- **书内定位**：Proposition 21, 行 20

**P2 词典序与 Next Extent 算法 (lectic order and Next Extent algorithm)**
- **是什么**：给对象集 G 一个线性序（比如 1 < 2 < ... < n），然后定义子集之间的"词典序"（lectic order）：A < B 当且仅当 A 和 B 的最小差异元素属于 B。这和字典里单词排序的逻辑一样——从左往右找第一个不同的位置，谁在那个位置"有"谁就"大"。在这个序下，所有子集排成一条线。Next Extent 算法做的就是：给定一个概念外延 A，找到词典序中下一个概念外延 A⁺ = A ⊕ i，其中 i 是最大的满足条件的对象。从最小的外延 ∅'' 开始，反复调用"下一个"，就能不重不漏地枚举所有概念外延。
- **为什么需要它**：Prop 21 告诉你概念外延构成闭包系统，但没告诉你怎么高效枚举它们。朴素方法是遍历所有 2^|G| 个子集再做闭包——指数级浪费。词典序的关键洞察是：闭包系统在词典序下有结构——你可以从当前外延"跳"到下一个外延，跳过中间那些不是外延的子集。A ⊕ i 的构造保证了你每次跳到的恰好是下一个闭包系统元素，不会跳过也不会重复。这让枚举的效率从"遍历所有子集"变成"只遍历闭包系统元素"。
- **关键关系**：依赖 P1（概念外延是闭包系统）+ ch0 的 Next Closure 算法（Algorithm 1）；是 P3（约束推广）的直接基础；与 P13/P14（伪内涵的枚举）共享同一算法框架——Next Closure 不仅枚举外延，也枚举伪内涵
- **崩塌条件**：要求 G 有限且线性有序。无限集上词典序仍是全序但"下一个"可能不存在（没有后继）。对无限背景需要超限迭代，算法的"简单性"丧失
- **书内定位**：lectic order 定义行 386-389, Algorithm 3 行 371, Theorem 5 行 410

**P3 Next Closure 的约束推广 (constrained enumeration via Theorem 6)**
- **是什么**：Theorem 6 把 Next Extent 算法推广到任意满足一定条件的子族 F——只要 F 满足"A ∈ F 且 i ∈ G ⟹ (A ∩ {1,...,i-1})'' ∈ F"，就能用同样的 A ⊕ i 方法在词典序下枚举 F 的元素。关键在于 F 不必是完整的闭包系统，只需要在"去掉某个元素后的闭包"仍然落在 F 中。这让你可以在枚举时加约束：比如只生成大小超过某个阈值的外延（频繁项集），或只生成满足某种属性的等价关系。
- **为什么需要它**：很多时候你不需要所有概念，只需要满足某个条件的那些。比如数据挖掘中只要"频繁"的（支持度 ≥ Minsupp），或者组合学中只要"每类不超过 3 个元素"的划分。如果先枚举全部再筛选，浪费巨大。Theorem 6 让你在枚举过程中直接跳过不满足条件的，因为词典序的结构保证了"跳过"不会遗漏。这是 Next Closure 算法可扩展性的核心。
- **关键关系**：是 P2 的直接推广——P2 是 F = 全部外延的特例；应用场景包括频繁项集挖掘（Minsupp）和约束划分枚举
- **崩塌条件**：F 必须满足前缀闭包条件（(A ∩ {1,...,i-1})'' ∈ F）。如果约束条件不满足这个封闭性（比如"外延大小恰好为 5"），Theorem 6 不直接适用，需要调整
- **书内定位**：Theorem 6, 行 447

**P4 集合表示 (set representation)**
- **是什么**：一个偏序集 (P, ≤) 的集合表示，是一个从 P 到某个集合 X 的幂集 P(X) 的映射 rep，满足 x ≤ y ⟺ rep(x) ⊆ rep(y)。也就是说，它把偏序关系"翻译"成子集包含关系——序结构被忠实地编码为集合结构。任何偏序集都有这样的表示：取 X = P，rep(a) = (a]（a 的下闭包）。对概念格，可以用外延 rep((A,B)) = A，或用 M\B（属性补集），甚至两者合并 A ∪ (M\B)。
- **为什么需要它**：偏序集是抽象的——元素之间只有 ≤ 关系，没有"位置"。但画图需要位置。集合表示把抽象的序关系变成具体的集合包含关系，而集合包含关系可以被"向量加法"操作（见 P5），从而生成图上的位置。它是从"序结构"到"几何位置"的中间桥梁。此外，集合表示也揭示了偏序集的嵌入性质——任何偏序集都可以嵌入幂集格。
- **关键关系**：是 P5（加法线图）的前提——加法线图需要集合表示 + 网格投影；对概念格通常用不可约对象/属性来构造表示（连接 ch1 的 ∨-不可约/∧-不可约）；在 Section 6.4 有更深入讨论
- **崩塌条件**：集合表示本身不崩塌——任何偏序集都有。但表示的"质量"影响图的可读性：用不同的 X 和 rep 得到的图差异巨大。用全部对象做表示比用不可约对象冗余得多
- **书内定位**：Definition 39, 行 787

**P5 加法线图 (additive line diagram)**
- **是什么**：给定偏序集 (P, ≤) 的一个集合表示 rep: P → P(X) 和一个网格投影 vec: X → ℝ²（给 X 中每个元素分配一个 y 坐标为正的向量），每个元素 p 的位置被定义为 pos(p) = n + Σ_{x∈rep(p)} vec(x)。因为所有 vec(x) 的 y 坐标为正，如果 q < p 则 rep(q) ⊊ rep(p)，所以 pos(q) 的 y 坐标严格小于 pos(p)——上图下自动满足。关键特性：改变某个 x 的 vec 值，等价于平移所有"包含 x 的元素"——即平移一个主滤子，其余元素不动。这让图的交互式调整变得简单且有预测性。
- **为什么需要它**：画线图最难的不是画线，是定位——把节点放在哪里才能让图可读。加法线图把定位问题分解为两步：选集合表示（决定结构）+ 选网格投影（决定几何）。这种分解让你可以独立调整两者，而且"移动一个向量 = 平移一个滤子"的局部性让手动微调可控。更重要的是，任何有限线图都可以被解释为某个集合表示下的加法图——所以这不是一种特殊画法，而是所有线图的统一框架。
- **关键关系**：依赖 P4（集合表示）；用不可约属性做表示时，图中出现大量平行边——平行边是可读性的标志（同属性的概念对齐）；与 P6（嵌套线图）互补——加法线图处理中等规模，嵌套线图处理更大规模
- **崩塌条件**：网格投影不保证单射——两个不同元素可能被放到同一位置（碰撞），需要额外检查。当 |X| 很大时，向量求和可能导致位置挤在一起，可读性下降（约 50 个概念以上就困难）
- **书内定位**：行 800-814（加法线图构造），Definition 39 行 787

**P6 嵌套线图与属性分割嵌入 (nested line diagram and attribute splitting embedding)**
- **是什么**：把属性集 M 拆成 M₁ ∪ M₂（不必不相交），分别画两个子上下文 (G, M₁, I∩G×M₁) 和 (G, M₂, I∩G×M₂) 的概念格线图。然后把一个线图放进另一个线图的每个节点里——外层是 B(K₁) 的图，每个外层节点内部嵌入一个 B(K₂) 的图。Theorem 7 保证：原概念格 B(G, M, I) 通过 (A,B) ↦ ((B∩M₁)', B∩M₁), ((B∩M₂)', B∩M₂)) 嵌入到 B(K₁) × B(K₂) 中，且保持 ∨（sup）。实际操作中，把对象概念填入乘积图，然后对 sup 闭合，就得到原概念格在乘积中的像。嵌套图中，框之间的单线表示"重合的节点相连"，双线表示"上层每个元素 > 下层每个元素"。
- **为什么需要它**：单个线图超过约 50 个概念就不可读了。但如果你能把属性分成有意义的两组，每组的概念格可能只有十几个节点——两个小图的乘积（嵌套图）可以表示几百个概念。更重要的是，属性分割往往有语义意义（比如"形状属性"和"大小属性"），嵌套图让两组属性的关系一目了然。这不仅是可视化技巧——Theorem 7 是结构定理：概念格嵌入子格的乘积，这个嵌入是 ∨-保持的。
- **关键关系**：Theorem 7 是数学基础；依赖 ch1 的子上下文和概念格乘积；与 P5 互补——加法线图适合中等规模，嵌套线图适合更大规模；为后续章节的分解技术铺垫
- **崩塌条件**：如果 M₁ 和 M₂ 的选择没有语义意义，嵌套图只是把一个混乱的图分成两个混乱的图。当属性之间高度耦合时，子上下文的概念格仍然很大。乘积图的节点数是 |B(K₁)| × |B(K₂)|，如果两者都不小，嵌套图本身也不可读
- **书内定位**：Theorem 7, 行 861；嵌套线图构造行 845-916

**P7 属性蕴含 (attribute implication)**
- **是什么**：一个属性蕴含 A → B 是属性集 M 的两个子集构成的有序对，意思是"每个拥有 A 中所有属性的对象，也拥有 B 中所有属性"。形式上，T ⊆ M "尊重" A → B 如果 A ⊄ T 或 B ⊆ T（要么你不满足前提，要么你必须满足结论）。A → B 在上下文中成立，当且仅当每个对象的内涵都尊重它。这是把"如果...那么..."这种日常推理模式形式化到属性层面。
- **为什么需要它**：很多时候你手上没有完整的交叉表，但你知道一些规则——"有属性 a 的东西一定也有属性 b"。这些规则就是蕴含。蕴含让你在不显式列出所有对象的情况下，推断属性之间的依赖关系。更重要的是，蕴含和概念格是同一信息的两个面：蕴含决定了概念内涵的闭包系统，从而决定了概念格的结构（Prop 23）。所以你可以从蕴含出发重建概念格，也可以从概念格读出蕴含——两条路等价。
- **关键关系**：与 P8（蕴含 ↔ 闭包）是同一事实的两个面；P9（Mod(L) 闭包系统）说明蕴含决定了内涵系统；是 P10-P14 的全部基础——完备集、典范基、属性探索都建立在蕴含之上
- **崩塌条件**：蕴含只描述"确定性"的依赖——"有 a 就一定有 b"。对于概率性依赖（"有 a 的东西 80% 有 b"），蕴含无能为力，需要推广到部分蕴含/关联规则（见 Notes 节）。在 incomplete context（三值逻辑）中，蕴含需要修改（Burmeister 的工作）
- **书内定位**：Definition 40, 行 943

**P8 蕴含与闭包的等价 (implication ↔ closure equivalence)**
- **是什么**：A → B 在上下文中成立，当且仅当 B ⊆ A''。这是因为 A' 是所有拥有 A 中全部属性的对象集，A'' 是这些对象的共同属性集——如果 B 中的每个属性都属于 A''，就意味着"拥有 A 的对象都拥有 B"。而且，如果 A → B 在对象内涵中成立，它也在所有概念内涵中成立——蕴含的效力从对象层自动传播到概念层。
- **为什么需要它**：这把蕴含从"遍历所有对象检查"变成"做一次闭包运算检查"——A → B 成立吗？只需算 A'' 然后看 B 是否在里面。更深层地，它说明蕴含和闭包算子是同一件事：知道所有蕴含等价于知道闭包算子 X ↦ X''，等价于知道概念格结构。这是 FCA 的核心等价三角：形式背景 ↔ 蕴含 ↔ 概念格。
- **关键关系**：依赖 ch1 的导出映射和闭包算子；是 P9（Mod(L) = 闭包系统）的直接推论；让 P14（典范基 = {P → P''}）成为自然构造
- **崩塌条件**：未发现明显崩塌条件。B ⊆ A'' 的等价性来自导出映射的定义，在任何形式背景中成立
- **书内定位**：Proposition 22, 行 950

**P9 Mod(L) 闭包系统与闭包算子 L(X) (models form a closure system)**
- **是什么**：给定一组蕴含 L，所有"尊重 L"的属性子集构成一个集合 Mod(L) = {X ⊆ M | X respects L}。这个 Mod(L) 是 M 上的闭包系统——对任意交封闭。对应的闭包算子是 L(X)：从 X 出发，反复应用 L 中的蕴含（如果 A ⊆ 当前集合且 A → B ∈ L，就把 B 加进去），直到不再变化。最终得到的 L(X) 就是 X 在 Mod(L) 中的闭包。如果 L 是某个上下文的全部蕴含，则 Mod(L) 恰好是该上下文的所有概念内涵。
- **为什么需要它**：这说明蕴含不是散落的规则——它们通过 Mod(L) 组织成一个闭包系统，而闭包系统就是概念格的骨架。给你任意一组蕴含 L（哪怕不是从任何上下文来的），你都能构造一个闭包系统 Mod(L) 和一个对应的上下文 (Mod(L), M, ∈)，其概念内涵恰好是尊重 L 的集合。这意味着蕴含可以脱离具体上下文独立存在——你可以先定义"属性逻辑"，再让上下文去实现它。
- **关键关系**：依赖 P7（蕴含定义）+ P8（蕴含 ↔ 闭包）；是 P10（语义后承）的基础——A→B follows from L ⟺ Mod(L) = Mod(L ∪ {A→B})；为 P16（属性探索）提供理论——从空上下文出发，用反例逐步构建上下文
- **崩塌条件**：无限属性集上，L(X) 的迭代可能需要超限步骤才能收敛。有限集上无问题
- **书内定位**：Proposition 23, 行 975

**P10 语义后承与完备集 (semantic consequence and complete set)**
- **是什么**：A → B "语义上从 L 推出"（follows semantically from L），意思是：每个尊重 L 的子集也尊重 A → B。等价地说，Mod(L) = Mod(L ∪ {A→B})——加不加这条蕴含，闭包系统不变。一个蕴含集 L 是"完备的"（complete），如果上下文中的每条蕴含都能从 L 推出——L 虽然可能只有几条，但它们蕴含了全部信息。L 是"封闭的"（closed），如果每条从 L 推出的蕴含已经在 L 中。
- **为什么需要它**：一个上下文可能有成千上万条蕴含，但绝大多数是平凡的或可推出的。完备集让你用最少的蕴含表示全部信息——这是知识压缩。完备集的存在意味着：你不需要列出所有蕴含，只需要一个"基"，其余的可以推出。这直接引出了"能不能找到最小的完备集"的问题，答案是典范基（P14）。
- **关键关系**：依赖 P9（Mod(L) 闭包系统）——"follows from L"的判定通过 Mod(L) 实现；P11（Armstrong 规则）给出封闭性的语法刻画；是 P12（真前提完备性）和 P14（典范基完备性）的判定标准
- **崩塌条件**：语义后承的定义对无限 M 仍然成立，但完备集的存在性和有限性需要 M 有限。无限属性集上的完备集可能需要无穷多条蕴含
- **书内定位**：Definition 41, 行 993

**P11 Armstrong 规则 (Armstrong rules)**
- **是什么**：一组蕴含集 L 是封闭的（每条可推出的蕴含已在 L 中），当且仅当它满足四条 Armstrong 规则：(1) X → X（自反）；(2) 若 X → Y 则 X∪Z → Y（增广）；(3) 若 X → Y 且 Y∪Z → W 则 X∪Z → W（传递）；(4) 若 X → Yₜ 对所有 t 成立则 X → ∪Yₜ（并集）。这四条规则是语法层面的——不需要检查所有子集，只需检查这些推理规则是否封闭。
- **为什么需要它**：语义后承的定义（"每个尊重 L 的子集也尊重 A→B"）需要遍历所有子集——计算上不可行。Armstrong 规则把这个问题变成语法推理：只需检查能否用四条规则从 L 推出 A→B。这是从语义到语法的桥梁——完备性定理说两者等价。在实践中，判断 A→B 是否从 L 推出，只需算 L(A)（L 的闭包）然后看 B ⊆ L(A) 否。
- **关键关系**：是 P10（语义后承）的语法对偶——语义说"所有模型"，语法说"推理规则"；在 P17（子句作为额外推理规则）中被推广——子句提供 Armstrong 规则之外的推理规则
- **崩塌条件**：Armstrong 规则只对"纯"蕴含成立。当有背景知识（比如两个属性互为否定）时，需要额外推理规则（P17/P18 的子句规则）。规则 (4) 涉及无穷并集，在有限集上退化为有限操作
- **书内定位**：Proposition 24, 行 1005

**P12 真前提 (proper premise)**
- **是什么**：对属性集 A，定义 A• = A'' \ (A ∪ ∪_{n∈A} (A\{n})'')——即 A'' 中那些不属于 A、也不属于任何"去掉一个元素后的子集的闭包"的属性。如果 A• ≠ ∅，A 就是一个"真前提"。直觉上，A• 是那些"只有当 A 中所有属性同时出现才会被推出"的属性——去掉 A 的任何一个元素就推不出来了。所有形如 A → A• 的蕴含（A 是真前提）构成一个完备集：任何属性集 T 的闭包 T'' = T ∪ ∪{A• | A 是真前提, A ⊆ T}。
- **为什么需要它**：这是找到"小而完备的蕴含集"的第一个系统尝试。它去掉所有平凡蕴含（B ⊆ A 的）和可由子集推出的蕴含，只保留"不可再分"的那些——A• 只有在 A 的全部属性同时在场时才出现。这已经大大压缩了蕴含集。但它仍然不是最小的——有些真前提蕴含可以从其他真前提蕴含推出。这个"还不够小"的认识直接推动了伪内涵和典范基的发明。
- **关键关系**：是 P13（伪内涵）的前驱——真前提是"迭代无关"的，伪内涵是"递归"的，后者更精炼；Prop 25 证明真前提蕴含集是完备的；与 P14（典范基）对比——典范基是非冗余的，真前提集一般仍冗余
- **崩塌条件**：真前提集一般仍冗余——某些 A → A• 可以从其他真前提蕴含推出。这就是为什么需要伪内涵/典范基来进一步压缩
- **书内定位**：Definition 42, 行 1035；Proposition 25, 行 1056

**P13 伪内涵 (pseudo-intent)**
- **是什么**：P ⊆ M 是伪内涵，当且仅当 P ≠ P''（P 自己不是内涵），并且对于每一个真包含在 P 中的伪内涵 Q（Q ⊊ P），都有 Q'' ⊆ P。这是一个递归定义：伪内涵是"几乎成为内涵但差一步"的集合——它自己不是内涵，但它已经包含了所有比它小的伪内涵的闭包。直觉上，伪内涵是"触发一条新蕴含的最小前提"——你需要一条蕴含 P → P'' 来把它"修补"成内涵。
- **为什么需要它**：真前提（P12）虽然完备但冗余。伪内涵是递归定义的——它只要求"比它小的伪内涵的闭包已被包含"，这自然地形成了一个层级。每条伪内涵 P 对应一条不可被其他伪内涵蕴含替代的规则 P → P''。伪内涵的递归性保证了非冗余性：P 尊重所有其他伪内涵蕴含（因为 Q'' ⊆ P 对 Q ⊊ P 成立），所以 P → P'' 不能从其他规则推出。这是找到最小完备集的关键概念。
- **关键关系**：是 P14（典范基）的核心概念——典范基 = {P → P'' | P 伪内涵}；依赖 P10（完备性）和 P12（真前提作为前驱）；Prop 29 说明内涵 ∪ 伪内涵也构成闭包系统，可以用 Next Closure 枚举伪内涵
- **崩塌条件**：递归定义要求 M 有限——否则"比 P 小的伪内涵"可能无穷多，递归无法有限终止。无限 M 上伪内涵的存在性和可计算性是困难问题（见 Notes 节的复杂度讨论）。即使 M 有限，检测和计数伪内涵的计算复杂度也很高（Kuznetsov & Obiedkov 的结果）
- **书内定位**：Definition 44, 行 1133

**P14 典范基 (canonical basis / Duquenne-Guigues basis)**
- **是什么**：对所有伪内涵 P，取蕴含 P → P''（实践中写 P → P''\P），得到的集合 L = {P → P'' | P 伪内涵} 是完备且非冗余的——它包含了足够信息重建全部蕴含，且去掉任何一条都会丢失信息（每条都不能从其余推出）。Prop 28 进一步说明：任何完备集都至少包含和伪内涵一样多的蕴含——典范基在条数上是最小的。典范基的伪内涵可以用 Next Closure 算法在词典序下枚举（Algorithm 4）。
- **为什么需要它**：一个上下文可能有成千上万条蕴含，但你只需要典范基这一组——它是最小完备集，既不遗漏也不冗余。这是知识表示的极致压缩：用最少的规则表达全部属性逻辑。典范基的"典范性"不是美学——它是最小的：任何其他完备集都不比它短。在实践中，属性探索（P15）逐步构建的就是典范基。
- **关键关系**：依赖 P13（伪内涵）——伪内涵是典范基的前提；依赖 P2（Next Closure）——Algorithm 4 用 Next Closure 枚举伪内涵；Prop 28 保证最小性（任何完备集 ≥ 伪内涵数）；是 P15（属性探索）的输出
- **崩塌条件**：要求 M 有限。无限 M 上典范基可能不存在或无穷大。即使有限 M，计算伪内涵的复杂度是 #P-hard 级别的（见 Notes）。Algorithm 4 虽然简单但效率不是最优的——它同时计算内涵和伪内涵，而只需要后者
- **书内定位**：Theorem 8, 行 1136；Proposition 28（最小性）行 1175；Algorithm 4 行 1234

**P15 属性探索 (attribute exploration)**
- **是什么**：一种交互式知识获取方法。从一个可能为空的上下文开始，算法逐个（按词典序）生成伪内涵 P，对每条候选蕴含 P → P'' 询问用户："这个蕴含成立吗？"用户要么确认，要么提供一个反例（一个对象，其内涵包含 P 但不包含 P''）。反例被加入上下文。Prop 30 保证：只要新加的对象内涵尊重之前已确认的所有蕴含，之前找到的伪内涵序列不变——所以不需要从头开始。最终，用户得到了一个上下文和它的典范基。极端情况下从空上下文开始，用户通过提供所有反例"创造"了一个概念系统。
- **为什么需要它**：很多时候你不知道完整的交叉表，但你是领域专家——你能判断"有 a 和 b 就一定有 c 吗？"这种问题。属性探索把专家知识直接转化为蕴含系统，不需要先穷举所有对象。它只问"必要"的问题——每个问题对应一条无法从已有知识推出的蕴含。这比让专家手动列出所有规则高效得多，因为专家容易遗漏，而算法保证完备。Prop 30 的增量性保证了探索过程不需要回溯——每确认一条蕴含或加入一个反例都是永久进展。
- **关键关系**：依赖 P14（典范基）——探索的输出就是典范基；依赖 P13（伪内涵）——问题就是"P 是不是伪内涵，P → P'' 成立吗"；依赖 P2（词典序）——伪内涵按词典序逐个生成；Prop 30 是增量性的理论保证；推广到概念探索（concept exploration）和规则探索（rule exploration）
- **崩塌条件**：需要领域专家能可靠地判断蕴含和提供反例。如果专家知识不确定或有噪声，探索结果不可靠。对无限属性集，探索过程不终止。实践中，如果属性数很多，交互轮次可能很长（虽然每轮都是必要的）
- **书内定位**：行 1229-1276；Proposition 30, 行 1259

**P16 子句 (clause)**
- **是什么**：子句形如 ∧A → ∨S（A 和 S 是属性子集），意思是"每个拥有 A 中所有属性的对象，至少拥有 S 中的一个属性"。与蕴含 A → B 的区别在于结论是"或"（至少一个）而非"且"（全部）。一个子句 ∧A → ∨S 在上下文中成立，当且仅当每个对象内涵都尊重它（A ⊄ T 或 T ∩ S ≠ ∅）。子句比蕴含表达力强得多：Theorem 67（ch5）将说明子句能完全确定形式背景（至澄清和同构），而蕴含只能确定概念格不能确定上下文本身。
- **为什么需要它**：蕴含回答"有 a 就一定有 b 吗"，但有些知识是"有 a 就至少有 b 或 c 中的一个"——蕴含表达不了这种"或"。比如"每个生活在陆地上且能移动的生物，要么哺乳要么也生活在水中"——这是一个子句，不是蕴含。概念图中没有对象标签的节点就对应子句：那些属性组合是某些对象的共同特征，但没有单个对象恰好拥有这些属性。子句捕捉了"哪些概念内涵不是对象内涵"这一信息——这正是蕴含丢失的信息。
- **关键关系**：是 P17（子句作为推理规则）的基础；比 P7（蕴含）表达力更强——蕴含是子句 S 为单元素集的特例；Theorem 67（ch5）将证明子句完全确定上下文；与 P20/P21（半积和依赖）相关——子句在缩放后的多值上下文中决定额外推理规则
- **崩塌条件**：子句比蕴含难处理得多——算法上和直觉上都是。子句的完备基比典范基复杂得多，没有像伪内涵那样简洁的刻画。实践中通常只在需要时使用子句，而非全面替代蕴含
- **书内定位**：Definition 45, 行 1771

**P17 子句作为额外推理规则 (clauses as additional inference rules)**
- **是什么**：每条子句 ∧A → ∨S 对应一条超越 Armstrong 的推理规则 R_{∧A→∨S}：如果对所有 s ∈ S，X∪{s} → B 都成立，且 A ⊆ X，则 X → B 成立。Theorem 9 说明：一个蕴含集 L 是某个子上下文 (H, M, I∩H×M) 的全部蕴含，当且仅当 L 在 Armstrong 规则和所有"母上下文 K 的子句对应的推理规则"下封闭。也就是说，子句提供了 Armstrong 规则之外"免费"的推理能力——如果你知道"有 a 就一定有 b 或 c"，那么"X∪{b} → d"和"X∪{c} → d"一起就能推出"X → d"，而不需要单独验证。
- **为什么需要它**：Armstrong 规则是"纯"蕴含推理——它们在任何上下文中都成立。但具体上下文可能有额外结构（比如两个属性互为否定），这些结构给出额外推理能力。子句就是编码这种额外结构的语言。在属性探索中，如果你知道子句，就可以自动回答一些问题而不需要问用户——这减少了交互次数。对多值上下文缩放后的一值上下文，缩放尺度的子句提供了"背景知识"推理规则。
- **关键关系**：依赖 P16（子句定义）+ P11（Armstrong 规则作为基础层）；Theorem 9 是核心定理——刻画了子上下文蕴含集；与 P18（半积）配合——半积的子句来自因子，易于确定
- **崩塌条件**：需要知道母上下文的全部子句才能确定全部额外推理规则。但子句的数量可能很大，确定全部子句本身是困难问题。在实践中通常只用"最小子句"（prime implicants），但即使这些也可能很多
- **书内定位**：Proposition 31, 行 1791；Theorem 9, 行 1824

**P18 半积 (semiproduct of contexts)**
- **是什么**：给定一组形式背景 Sₘ = (Gₘ, Mₘ, Iₘ)，它们的半积 ⊔ₐ Sₘ 的对象集是各 Gₘ 的直积 ×Gₘ，属性集是不相交并 ∪̇{m}×Mₘ，关系定义为 (gₘ|m∈M) ∇ (m,n) ⟺ gₘ Iₘ n——即一个组合对象和属性 (m,n) 有关系，当且仅当它的第 m 个分量和 n 在 Sₘ 中有关系。每个因子 Sₘ• = (Gₘ, {m}×Mₘ, Iₘ•) 只看第 m 个分量。关键性质（Prop 32）：多值上下文经 plain scaling 得到的导出上下文，同构于半积的某个子上下文。半积的最小子句恰好来自各因子（Prop 33）——这意味着缩放后的额外推理规则可以逐属性独立确定。
- **为什么需要它**：多值上下文缩放后得到的一值上下文可能很大，直接处理困难。半积把它分解为各属性独立缩放的"因子"——每个因子只涉及一个多值属性的缩放尺度。Prop 33 说半积的额外推理规则（子句）来自各因子，所以你不需要处理整个导出上下文的子句，只需要处理每个缩放尺度的子句——这是从整体到部分的分解。在实践中，这让带背景知识的属性探索变得可行。
- **关键关系**：依赖 ch1 的 plain scaling（Def 36）；Prop 32 连接导出上下文和半积；Prop 33 让 P17（子句推理规则）在缩放场景中可操作；是 P19/P20/P21（依赖理论）在多值场景中的基础设施
- **崩塌条件**：半积的对象集是直积 ×Gₘ，当属性数多时对象数指数增长。半积本身可能很大——分解的是结构不是规模。Prop 32 的"子上下文"嵌入要求多值上下文是 complete 的（每个对象在每个属性上都有值），否则需要修改（Prop 35 引入属性副本）
- **书内定位**：Definition 46, 行 1869；Proposition 32, 行 1893；Proposition 33, 行 1912

**P19 函数依赖 (functional dependency)**
- **是什么**：在完整多值上下文 (G, M, W, I) 中，属性集 Y 函数依赖于 X，当且仅当：任何两个对象如果在 X 中所有属性上取值相同，则在 Y 中所有属性上取值也相同。等价地说，存在函数 f: W^X → W^Y 使得 f(m(g)|m∈X) = (n(g)|n∈Y)。这就是关系数据库理论中的函数依赖——"X 的值确定 Y 的值"。
- **为什么需要它**：函数依赖是数据建模的基础概念——它告诉你哪些属性是"冗余"的（可以从其他属性推出）。在数据库设计中，函数依赖用于规范化（消除冗余）。FCA 的贡献是把函数依赖翻译成蕴含（P21），从而用 FCA 的工具（典范基、属性探索）来处理数据库依赖问题。这是 FCA 和数据库理论的接口。
- **关键关系**：是 P20（序依赖）的特例——序依赖用 ≤ 替代 =；通过 P21（依赖到蕴含的翻译）转化为蕴含问题；在关系数据库理论中有等价概念
- **崩塌条件**：要求多值上下文完整（每个对象在每个属性上都有值）。不完整时需要 Prop 35 的修改（引入属性副本）。函数依赖只捕捉"精确等价"——不捕捉"越大越..."这种趋势性依赖
- **书内定位**：Definition 47, 行 1991

**P20 序依赖 (ordinal dependency)**
- **是什么**：在带序的多值上下文中（每个属性 m 的值集上有序 ≤ₘ），Y 序依赖于 X，当且仅当：对任何两个对象 g, h，如果在 X 中所有属性上 m(g) ≤ₘ m(h)，则在 Y 中所有属性上 n(g) ≤ₙ n(h)。这是函数依赖的"有序推广"——把"相等"推广为"有序"。序依赖总是蕴含函数依赖（因为相等意味着双向 ≤），但反过来不成立——序依赖更强，它要求序关系本身被保持。
- **为什么需要它**：函数依赖只说"X 相同则 Y 相同"，但很多依赖是趋势性的——"面积越大价格越高"不是函数依赖（相同面积可能不同价格），但它是序依赖（面积序 ≤ 保持则价格序 ≤ 保持）。序依赖捕捉了"单调关系"这种在数据分析和决策建模中常见的结构。FCA 把它翻译成蕴含（P21），让属性探索可以用于发现序依赖。
- **关键关系**：推广 P19（函数依赖）——取 ≤ₘ 为等价关系就退化为函数依赖；通过 P21 翻译为蕴含——在上下文 K_O 中 X → Y 成立；Θ-依赖是进一步推广——用任意关系 Θₘ 替代 ≤ₘ
- **崩塌条件**：序依赖要求每个属性值集上有序关系。序依赖蕴含函数依赖但反之不然——所以序依赖是更精细的约束，可能遗漏"非单调但仍然确定"的依赖。序依赖的"序保持"只要求出现在数据中的元组，不一定能扩展到整个 W^X → W^Y 的序保持映射
- **书内定位**：Definition 48, 行 2004

**P21 依赖到蕴含的翻译 (dependencies ↔ implications translation)**
- **是什么**：函数依赖和序依赖都可以翻译成一值上下文中的蕴含。对序依赖，构造上下文 K_O = (G×G, M, I_O)，其中 (g,h) I_O m ⟺ m(g) ≤ₘ m(h)——对象是对象对，属性是原属性，关系是"序保持"。则 Y 序依赖于 X ⟺ X → Y 在 K_O 中成立。对函数依赖，利用等式的对称性简化为 K_N = (P₂(G), M, I_N)，其中 {g,h} I_N m ⟺ m(g) = m(h)——对象是无序对象对。这样，依赖的完备基就是对应上下文的典范基。对不完整多值上下文，引入属性副本 m̂ 来处理缺失值（Prop 35）。Θ-依赖（用任意关系 Θₘ 替代 ≤ₘ）也用同样方法翻译。
- **为什么需要它**：这是 FCA 统一力量的展示——函数依赖和序依赖不是新的独立理论，它们就是蕴含在特定上下文中的表现。一旦翻译完成，FCA 的全部工具（典范基、属性探索、Next Closure）都可以直接用于依赖分析。你不需要为依赖重新发明算法，只需要构造正确的上下文。这种"归约"是 FCA 作为数学框架的核心价值——把不同领域的问题统一到同一语言。
- **关键关系**：依赖 P19（函数依赖）和 P20（序依赖）作为输入；依赖 P7-P14（蕴含理论）作为工具箱；Prop 34 是核心定理，Prop 35 是不完整上下文的推广；Θ-依赖是进一步推广（用任意关系替代序关系）
- **崩塌条件**：K_O 的对象数是 |G|²，K_N 是 |G|(|G|-1)/2——对大数据集，构造的上下文很大。翻译保持等价性但可能带来计算开销。不完整上下文需要属性副本，增加了属性数
- **书内定位**：Proposition 34, 行 2032；Proposition 35, 行 2065
