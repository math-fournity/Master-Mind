# 208-205 Check List：运行过程AI引导解决方案

> **文档定位**：205号方案的细化Check List。解决202号诊断的运行过程AI引导缺位。
>
> **入口门**：202号文档已完成；203-A已完成（泄漏审计可拦截AI生成的提示）；controller_belief.py已定义9种动作；stall_detector.py已定义7种卡点；DevinCliAdapter已能调用AI。
>
> **出口门**：AI引导的完成率显著高于纯经典计算引导；AI生成的提示全部通过泄漏审计；成本控制在预算内。
>
> **停止条件**：如果AI引导不提升完成率，或AI生成的提示无法通过泄漏审计，退回纯经典计算引导（STOP-205）。
>
> **依赖关系**：203-A（提示分级+泄漏审计）必须先于205-B（AI编译提示）完成。
>
> **来源追溯**：202号 + 205号 + orchestrator.py + controller_belief.py + stall_detector.py + guided_loop.py
>
> **措辞规范**：标注实现深度等级（D1-D4）+ 边界情况清单 + 覆盖标准。勾选格式：`[D1]/[D2]/[D3]/[D4]/[ ]`。

## 205-A 步骤7 AI诊断

> 来源：202号§三.3.2 + 205号§五.5.1 + stall_detector.py:114-200

- [ ] **205-A.0**：AI诊断调用时机定义 [预期D1]
  - 定义"不确定结果"的判定标准：多个卡点类型概率相近（max_confidence_diff < 0.2）
  - 定义"合理策略转换"的初步判定：Solver自报换方向但工具有进展
  - 覆盖标准：调用时机明确，不是每步都调用AI
  - 边界情况：经典计算给出确定结果（不调用AI——节省成本）

- [ ] **205-A.1**：AI诊断prompt设计 [预期D2]
  - prompt包含：Solver的response、经典计算的卡点候选、7种卡点类型定义
  - prompt要求AI：判断真卡点vs合理转换、选择真实原因、给出依据
  - prompt强调：不要只看关键词，要理解Solver的思路内容
  - 深度标准：有可执行的prompt模板
  - 边界情况：Solver response过长（截取最后2000字符）/ 过短（标注"信息不足"）

- [ ] **205-A.2**：AI诊断调用代码实现 [预期D2]
  - 在guided_loop.py的_detect_stall()之后增加AI诊断分支
  - 调用DevinCliAdapter或直接调用AI API
  - AI诊断结果替代经典计算的不确定结果
  - 深度标准：有可执行的AI诊断调用代码
  - 边界情况：AI调用超时（fallback到经典计算结果）/ AI调用失败（同上）

- [ ] **205-A.3**：AI诊断结果记录 [预期D2]
  - 在turn_history中增加`ai_diagnosis`字段
  - 包含：AI判断的卡点类型、置信度、依据、是否替代了经典计算结果
  - 边界情况：未调用AI（ai_diagnosis=null）

- [ ] **205-A.4**：POC验证——5个已有run对比测试 [预期D3]
  - 用guided_001-004 + complex_001的response
  - 对比AI诊断和经典计算诊断的结果
  - 重点关注：经典计算误判的case，AI能否正确判断
  - 覆盖标准：5个run全部对比，每个不确定case都有AI诊断结果

### 完整性标准

- [ ] **205-A.COMP**：AI诊断只在不确定时调用 [预期D2]
  - 边界情况：确定结果也调用AI（应被拒绝——浪费成本）

- [ ] **205-A.COMP2**：AI诊断有fallback [预期D2]
  - 覆盖标准：AI超时/失败时fallback到经典计算，不崩溃

## 205-B 步骤10 AI编译+泄漏审计

> 来源：202号§三.3.5 + 205号§五.5.2 + 203-A（泄漏审计）
> **前置依赖**：203-A必须先完成

- [ ] **205-B.0**：AI编译调用时机定义 [预期D1]
  - 定义何时调用AI编译：硬编码提示不够针对性时（response包含具体数学内容但硬编码提示是通用的）
  - 定义何时不调用：response过短（直接给meta级提示）/ response明确完成（不给提示）
  - 覆盖标准：调用时机明确
  - 边界情况：所有情况都调用AI编译（应被拒绝——成本太高）

- [ ] **205-B.1**：AI编译prompt设计 [预期D2]
  - prompt包含：卡点原因、Solver的response、K维度相关上下文、经典计算的提示骨架
  - prompt要求AI：
    1. 不包含答案或答案等价表述（会经过泄漏审计）
    2. 针对Solver的具体思路内容
    3. 优先给strategy，其次meta，最后才给knowledge
    4. 如果Solver方向对，只给meta；如果方向不对，给strategy引导换方向
  - 深度标准：有可执行的prompt模板

- [ ] **205-B.2**：AI编译调用代码实现 [预期D2]
  - 在guided_loop.py的_generate_hint()中增加AI编译分支
  - 调用AI生成提示
  - AI生成的提示必须经过203-A的run_four_gates()审计
  - 审计fail则降级为meta级提示
  - 深度标准：有可执行的AI编译+审计调用代码
  - 边界情况：AI生成的提示审计fail（降级为meta）/ AI调用超时（fallback到硬编码提示）

- [ ] **205-B.3**：AI编译结果记录 [预期D2]
  - 在turn_history中增加`ai_compiled_hint`和`leakage_audit`字段
  - 包含：AI生成的提示文本、四门审计结果、是否降级
  - 边界情况：未调用AI编译（ai_compiled_hint=null）

- [ ] **205-B.4**：POC验证——5个已有run对比测试 [预期D3]
  - 用guided_001-004 + complex_001
  - 对比AI编译提示和硬编码提示的有效率
  - 重点关注：AI编译的提示是否更针对性、是否通过泄漏审计
  - 覆盖标准：5个run全部对比

### 完整性标准

- [ ] **205-B.COMP**：AI生成的提示全部经过泄漏审计 [预期D3]
  - 边界情况：有AI提示绕过审计（应被拒绝——不允许有未经审计的AI提示）

- [ ] **205-B.COMP2**：AI编译有fallback [预期D2]
  - 覆盖标准：AI超时/审计fail时fallback到硬编码提示或meta提示，不崩溃

## 205-C 多轮智能规划

> 来源：202号§四.4.3 + 205号§五.5.3

  - 从状态归约结果中提取已探索区域
  - 覆盖标准：表示定义完整，能从现有状态归约中提取

- [ ] **205-C.1**：未探索区域提取 [预期D2]

  - 深度标准：有可执行的未探索区域提取代码
  - 边界情况：K维度为空（标注"无知识库——无法规划"）

- [ ] **205-C.2**：桥梁节点识别 [预期D2]
  - 桥梁节点 = 连接已探索区域和未探索区域的节点

  - 深度标准：有可执行的桥梁节点识别代码

  - prompt要求AI：选择最值得优先的未探索区域、选择到达路径、给出提示方向（不是提示内容）
  - 深度标准：有可执行的prompt模板

- [ ] **205-C.4**：AI规划调用代码实现 [预期D3]
  - 在guided_loop.py的多轮循环中，第2轮及以后调用AI规划
  - AI规划结果指导步骤10的AI编译（提示方向由规划决定，提示内容由编译决定）
  - 深度标准：有可执行的AI规划调用代码，与步骤10集成
  - 边界情况：AI规划与经典计算的卡点诊断矛盾（以AI规划为准，但记录矛盾）

- [ ] **205-C.5**：POC验证——complex_001多轮测试 [预期D3]
  - 用complex_001（3turns/2hints/未完成）作为测试case
  - 用AI规划替代硬编码提示
  - 检查：AI规划能否引导Solver完成（或至少比硬编码提示走得更远）
  - 覆盖标准：complex_001用AI规划重新运行，记录结果

- [ ] **205-C.6**：POC验证——complex_002多轮测试 [预期D3]

  - 覆盖标准：complex_002用AI规划重新运行，记录结果

### 完整性标准
