## 0. 本文档为什么不是又一个235

235号把218-234的讨论压成了"确定的共识 + 候选的结构 + 下一步跑例子"。这是一份合格的快照，但它有三个结构性缺陷：

第一，**它不产生新理解**。235把各文档的结论搬运到一起，但没有在综合中产生任何235之前不存在的洞察。一份好的综合不应该只是仓库，应该是熔炉——把不同的东西放在一起烧，烧出新的东西。

第二，**候选结构是清单不是结构**。235列了六个候选（Σ是范畴/C是偏序范畴/自然性是交换图/V-R是伴随/图册是Grothendieck拓扑/能量是序量），每个标"待验证"。但它们之间的依赖关系没有说，每个的可证伪条件没有说。这等于说"我们有一堆想法，跑例子看看"——这不是实验设计，是碰运气。

第三，**三层视角被分开陈列**。整个218-235的讨论实际上在三个层面上工作：现象层（解题时实际发生了什么）、边界层（形式化边界在推进）、结构层（用什么数学语言描述）。235把这三层放在不同章节，但没有说它们是**同一过程的三个视角**，更没有说结构层的正当性完全依赖于它是否忠实描述了前两层。

236号要做的三件事：

1. **统一三层视角**——显示现象层、边界层、结构层是同一个过程的三种描述，并给出结构层获得正当性的条件
2. **设计可证伪实验**——不是"跑跑看什么出现"，而是设计来区分候选结构的实验
3. **连接实际项目**——这套框架对建造数学大师系统意味着什么

## 1. 思想脉络（压缩叙事，作为活记忆）

这段叙事不是文档索引——它是理解后续所有内容的前提。如果你只读一节，读这一节。

### 1.1 起点：非特定性危机（218）

引导式数学解题实验（guided_001）成功了——AI在引导下解出了矩条件极差题。但用户提出了一个致命批判：Q序列可能是**特定化的**——引导者通过引用AI自己选的"最看好的5个方向"，隐含地确认了正确路径。这不是知识传递，但它是"面向答案做引导"的隐蔽形式。

危机的本质：**我们无法区分"引导者用感知引导"和"引导者用答案引导"——因为感知的结果恰好和答案一致。**

### 1.2 第一条线索：拓扑化（219-221）

如果引导者理解问题的拓扑结构（深层结构特征），就可以设计**结构化但非特定**的Q序列——指向拓扑特征而非特定解答路径。220号从小学例子（鸡兔同笼抬腿法、分数约分、因式分解、三角形内角和）中提取出"换基"这一统一拓扑。221号发现模式识别识别的是"当前表示与内在结构之间的不匹配"——即各种"不自然"。

### 1.3 第二条线索：形式化边界（222）

"不自然"的识别无法被形式化——它是感知，不是规则。但AI见过海量例子，能做模糊模式匹配，覆盖了感知层面的边界。边界没有消失但移动了：AI时代，感知层被AI覆盖，剩余边界是价值判断和审美。

222号留下了一个未回答的问题：**边界怎么移动？AI的感知怎么变成形式化成果？**

### 1.4 架构尝试：从外骨骼到纤维化到语义场（223-225）

223号提出"外骨骼"隐喻——经典计算包裹AI，提供支撑/约束/放大。224号放弃外骨骼，提出"问题空间纤维化"——基空间有拓扑，纤维有路径，AI感知/经典验证是纤维化的对偶角色。225号（codex）指出纤维化的三个限制（点化/路径化/检查者弱化），提出"语义场—证书闭环"：处境会生长，经典计算会反向生产语义，非特定性是自然性不是连续性。

### 1.5 数学化与反绑架（226-229）

226-v0从证书偏序开始数学化，发现V/R不是函子——不是严格伴随。226-v1提出七点精确化路线（Σ是site/C是偏序范畴/自然性是交换图/V-R是lax adjunction/图册是Grothendieck拓扑/障碍是H¹/能量是序量）。227号（codex）警告"不要被漂亮结构绑架"，提出五层骨架和八处修正。228号（两个版本）一个做方法论评价，一个做能力增益分析。229号综合两者。

核心张力：**226-v1的数学化野心 vs 227的反绑架克制。** 235号没有解决这个张力——它把两边都列上了。

### 1.6 材料基础与深层本质（230-234）

230号做了第一版综合。231号（codex）发现230号缺少材料基础——提出"双重知识生产"（同一批语料的训练路径和抽取路径）。232号评价231号，做了工程单元与数学结构的对应表。233号建立了**形式化边界移动机制**——222号和231号的统一：双重知识生产是边界两侧的必然结果，闭环的每一次运行推进边界一步。234号用边界视角解决了232号的五个问题。

### 1.7 235号的位置

235号把230-234整合进230的框架。它是合格的快照，但如§0所述，它不产生新理解、候选结构是清单、三层视角分开陈列。

## 2. 一个深层观念：形式化边界的推进

### 2.1 精确表述

数学知识有形式化边界两侧的两种成分：

- **可以形式化的**（边界以内）：定理依赖、证明步骤、证书目标、恒等式、不等式、类型——可以被显式化、可检查、可审计
- **不可形式化的**（边界以外）："不自然"的感知、模式识别、直觉、类比、结构感——无法写成规则，依赖于对大量例子的经验积累

形式化的边界是**本质性的**，不是"暂时无法形式化，未来可以"。"不自然"是一种感知，不是规则——你可以形式化"红色"的波长，但无法形式化"看到红色是什么感觉"。

### 2.2 边界推进的机制

222号说"AI时代边界没有消失但移动了"但没说怎么移动。233号给出了答案——闭环的每一次运行是边界推进的一步：

```
步骤1：AI从边界以外感知"不自然"（侦察——AI的黑盒能力）
步骤2：AI把"不自然"压缩成可检查目标（跨越边界——从感知到对象）
步骤3：经典计算在边界以内验证（操作——经典计算的精确能力）
步骤4：结果回写数据基座（边界向前推进，不可逆）
```

**数据基座的增长 = 形式化边界的推进。** 证书单调增长 = 边界推进不可逆。AI感知非单调 = 边界以外可修正。闭环 = 把非单调的感知不断压成单调的形式化。

### 2.3 三个统一

233/234号实现了三个统一：

1. **222号和231号统一**：双重知识生产（训练路径+抽取路径）是形式化边界两侧的必然结果——边界以外的感知进入AI训练，边界以内的形式化进入数据基座
2. **工程和数学统一**：数据基座（231号的工程概念）和数学结构（226/227的Σ/C/图册/obstruction）都是形式化边界的描述——同一件事的两个面
3. **求解和抽取统一**：闭环运行同时产出解和数据基座条目——单任务双产出，抽取是闭环的副产品

### 2.4 新综合：非特定性 = 方法可从边界以外使用

**这是236号的核心新洞察，不存在于218-235的任何文档中，但从218+233的逻辑中直接推出。**

218号危机：引导者通过引用AI选的特定方向，隐含地确认了正确路径。233号的诊断：引导者站在边界以内（知道答案）假装站在边界以外（做感知）——答案知识泄露。

但这里有一个更深的点，233号没有完全展开：

**一个方法是非特定的，当且仅当它可以从边界以外使用（在不知道答案的情况下）仍然产生有用的证书目标。**

一个方法如果只有在知道答案时才有效（引导者筛选了"最看好的5个方向"），它就不是从边界以外可用的——它依赖边界以内的知识。一个方法如果在不知道答案时仍然有效（纯元认知框架"描述第一步"），它就是从边界以外可用的——它不依赖边界以内的知识。

**这把218号的非特定性和233号的边界推进直接连接了：**

- 非特定性不是一个独立的设计目标，它是**边界跨越能力的条件**
- 一个方法能推进边界，当且仅当它能从边界以外使用
- 一个方法能从边界以外使用，当且仅当它是非特定的
- **非特定性 = 边界以外可用性 = 边界推进能力**

这个连接的实践含义：**检验一个引导方法是否非特定，就是检验它能否在不知道答案的情况下推进边界。** 这比226-v1的"交换图是否闭合"更根本——交换图是数学条件，边界以外可用性是操作性条件。交换图检查是边界以外可用性的一种形式化尝试，但边界以外可用性本身比交换图更原始。

## 3. 三层视角的统一

整个218-235的讨论在三个层面上工作。235号把它们分开陈列。236号要显示它们是**同一过程的三个视角**，并给出结构层获得正当性的条件。

### 3.1 现象层：解题时实际发生了什么

这是225号的领域。一个数学家（或AI）面对问题时：

- 感知到"不自然"（当前表示不匹配内在结构）
- 做语义移动（换表示、构造辅助对象、拆子目标）
- 产生证书目标（把模糊直觉压成可检查声明）
- 经典计算验证（成功/反例/障碍/未知）
- 结果回流，改变理解
- 处境在这个过程中**生长**——原题是不等式，中心化后变成矩问题，找到q(x)后变成多项式非负证书

现象层的核心词：**处境生长、语义移动、证书目标、结果回流**。

### 3.2 边界层：形式化边界在推进

这是222+233号的领域。现象层发生的事情，在边界层的视角下是：

- AI从边界以外感知"不自然"（侦察）
- AI把"不自然"压缩成可检查目标（跨越边界）
- 经典计算在边界以内验证（操作）
- 结果回写数据基座（边界推进，不可逆）

边界层的核心词：**边界以外、边界以内、跨越、推进、不可逆**。

### 3.3 结构层：用什么数学语言描述

这是226-227号的领域。尝试用精确数学语言描述边界层：

- Σ（语义场）= 边界两侧的处境空间
- C（证书偏序）= 边界以内的已征服领土
- 自然性（交换图）= 边界跨越的条件
- obstruction = 边界跨越的障碍
- 能量（序量）= 当前处境离可证状态的距离

结构层的核心词：**范畴、偏序、交换图、上同调、序量**。

### 3.4 三层是同一过程的三个视角

```
现象层：处境生长 → 语义移动 → 证书目标 → 结果回流
          ↕（同一过程的不同描述）
边界层：边界以外感知 → 跨越边界 → 边界以内验证 → 边界推进
          ↕（同一过程的不同描述）
结构层：Σ中的移动 → V产生证书目标 → C中验证 → C增长
```

这三层不是三个独立的东西，是**同一个闭环过程的三种描述**：
- 现象层描述**实际发生了什么**（第一人称视角）
- 边界层描述**这件事的意义**（边界在推进）
- 结构层描述**这件事的数学形状**（用什么结构刻画）

### 3.5 结构层获得正当性的条件

**这是236号对226-v1 vs 227张力的解决。**

226-v1的野心：直接宣布Σ是site、V-R是lax adjunction、obstruction是H¹。  
227的克制：不要被漂亮结构绑架，先跑例子。

236号的原则：**结构层的每个概念，只有在它忠实描述了现象层和边界层时，才获得正当性。**

具体地说：

| 结构层概念 | 现象层对应 | 边界层对应 | 获得正当性的条件 |
|---|---|---|---|
| Σ是范畴 | 处境之间有语义移动 | 边界两侧的处境空间 | 跑例子时确实看到语义移动有结构（可组合/有方向/有类型），而不是任意两个处境之间都能移动 |
| C是偏序范畴 | 证书有加强关系 | 边界以内的已征服领土 | 跑例子时确实看到证书有明确的加强/依赖/范围关系 |
| 自然性是交换图 | 方法在换表示后仍有效 | 边界跨越的条件 | 跑例子时确实看到方法在表示变换前后产生相容的证书目标 |
| V-R是伴随-like | 语义移动和证书结果有双向连接 | 跨越边界的两个方向 | 跑例子时确实看到双向连接有某种规律性（不只是随机） |
| 图册是Grothendieck拓扑 | 多个局部表示能共同看清处境 | 边界上的局部视角 | 跑例子时确实看到多个表示能粘合成全局理解 |
| obstruction | 局部证书拼不上 | 边界跨越的障碍 | 跑例子时确实看到粘合失败有结构（不是随机不一致） |
| 能量是序量 | 处境有"难度" | 离可证状态的距离 | 跑例子时确实看到难度是多维的且有好/坏方向 |

**这个表不是"待验证"的清单——它是每个结构概念的生死条件。** 如果跑例子时没有看到对应的现象，这个结构概念就不应该被保留。227的警告是对的：不要被漂亮结构绑架。但226-v1的野心也是对的：要追求可检查的数学条件。236号的解决：**追求可检查的数学条件，但每个条件必须绑定一个生死条件——什么现象出现它才活着，什么现象出现它就死了。**

## 4. 确定的共识（不再讨论）

这些是218-235所有讨论都同意的。列在这里不是为了重复，是为了把它们从"待讨论"中永久移出。

### 4.1 两种计算的本质区别

**AI计算**：处理还没有完全形式化的意义——感知、模式识别、类比、猜测表示变换、判断哪里不自然。擅长提出候选，但难以稳定区分"看起来像真的"和"已经被确认是真的"。

**经典计算**：处理已经被压缩成明确对象的任务——枚举、化简、因式分解、求解约束、检查类型、验证证明、生成反例。擅长精确执行，但不知道该算什么。

**两者互补**：AI从边界以外感知，经典计算在边界以内验证，闭环推进边界。

### 4.2 225的三个核心直觉

1. **处境会生长**：问题在解题过程中会变形——不等式→矩问题→多项式非负证书→对偶极值。问题不是静态点，是会生长的处境。

2. **经典计算会反向生产语义**：经典计算不只是检查——它主动产生结构（因式分解产生隐藏乘积，求解器产生反例，数值验证产生量级事实）。结果回流改变AI的理解。

3. **自然性>连续性**：非特定性不是"邻域内连续有效"（224的连续性），而是"表示变换下保持意义"（225的自然性）。数学策略的迁移经常跨越很远的表面距离——代数变几何，组合变概率——表面拓扑可能很远，但自然结构很近。

### 4.3 227的三个实质修正

1. **反例是证书**：反例证明"存在对象使猜想失败"=正向证书证明否定命题。三类：正向证书（证明X成立）/反驳证书（证明X不成立，通常是反例）→证书层；诊断反馈（类型错误、工具超时、翻译缺口）→反馈层。

2. **证书不能压成单一偏序**：证书带字段（claim/scope/strength/dependencies/checker/status）。范围收缩不是加强——"对n≥4且n偶数成立"不能替代"对n≥4成立"。把范围收缩误当成单调增长，系统会以为越来越强，实际只是越来越窄。

3. **obstruction≠H¹**：四级——descent failure（最一般）→obstruction object（可记录比较）→Čech 1-cocycle（差异写成转换函数时）→H¹ class（系数对象满足条件时）。H¹是特殊情况，不是所有粘合失败的默认形式。

### 4.4 218号非特定性危机的解决

**表层解决**（226-v1）：非特定性是可检查的数学条件——方法在表示变换下是否满足交换。

**深层解决**（233号）：引导者站在边界以内（知道答案）假装站在边界以外（做感知）=答案知识泄露。让不知道答案的AI做感知——它只能从边界以外感知"不自然"，不能从边界以内泄露答案。

**最终综合**（236号§2.4）：非特定性 = 方法可从边界以外使用 = 边界推进能力。检验一个方法是否非特定，就是检验它能否在不知道答案的情况下推进边界。

所有讨论都同意：不再堆抽象框架，跑闭环样例。

## 5. 开放问题：依赖图与生死条件

235号列了六个候选结构，每个标"待验证"。236号把它们组织成**依赖图**，每个给出**生死条件**——什么现象出现它活着，什么现象出现它就死了。

### 5.1 依赖图

```
Σ是范畴 ──────────────┐
                      ├──→ 自然性是交换图 ──→ V-R是伴随-like
C是偏序范畴 ──────────┘              │
                                    ↓
图册是Grothendieck拓扑 ──→ obstruction有结构
                                    │
能量是序量 ←─────────────────────────┘
```

**依赖关系的含义**：
- 自然性依赖Σ是范畴（没有态射就没有交换图）和C是偏序范畴（没有证书偏序就没有"相容"的判断标准）
- V-R是伴随-like依赖自然性（伴随需要两个方向的结构）
- 图册依赖Σ是范畴（覆盖是范畴上的结构）
- obstruction依赖图册（没有粘合就没有粘合失败）
- 能量依赖obstruction（粘合缺陷是能量的一个分量）

**实践含义**：跑例子时，先验证底层结构（Σ/C），再验证上层结构（自然性/图册），最后验证顶层结构（V-R/能量）。如果底层不成立，上层不需要验证。

### 5.2 每个候选的生死条件

#### 候选1：Σ是范畴

**活着的表现**：跑例子时，确实看到语义移动有结构——有些移动可组合（中心化后再找q(x) = 一个复合移动），有些移动有方向（特例化不能反过来证明原命题），有些移动有类型（表示变换vs归约vs形式化翻译）。

**死了的表现**：语义移动之间没有可组合性、没有方向性、没有类型区分——任何两个处境之间都能"某种移动"，移动之间没有结构。如果是这样，Σ只是集合，不是范畴。

**降级方案**：如果Σ不是范畴，自然性不能用交换图表达。但§2.4的"边界以外可用性"仍然有效——它是操作性条件，不依赖Σ的范畴结构。

#### 候选2：C是带字段的偏序范畴

**活着的表现**：跑例子时，确实看到证书有明确的加强关系（证明更强不等式→覆盖较弱不等式）、依赖关系（这个引理用了那些条件）、范围关系（对n≥4成立 vs 对n≥4且n偶数成立）。三类区分（正向/反驳/诊断）在实际中清晰。

**死了的表现**：证书之间没有明确的偏序——每个证书都是独立的，没有加强/依赖/范围关系。如果是这样，C只是集合，不是偏序范畴。

**降级方案**：如果C不是偏序范畴，证书账本仍然有用（记录已验证事实），但"单调增长"需要重新定义——不是偏序意义上的增长，只是集合意义上的扩张。

#### 候选3：自然性是交换图

**活着的表现**：跑例子时，确实看到同一个方法在表示变换前后产生相容的证书目标。例如"找统一编码对象"在原始表示和中心化表示中都产生了可用的多项式恒等式，且两个恒等式在C中可比较。

**死了的表现**：方法在表示变换前后产生不相容的证书目标，或者根本无法在不同表示中应用同一个方法。如果是这样，自然性不成立——方法依赖特定表示。

**降级方案**：如果自然性不成立，§2.4的"边界以外可用性"仍然有效。非特定性检查退回到操作性测试：在不知道答案的情况下，方法能否推进边界。

#### 候选4：V-R是伴随-like结构

**活着的表现**：跑例子时，确实看到语义移动和证书结果之间有某种规律性双向连接——不是随机的，而是"这类语义移动倾向于产生这类证书目标，这类证书结果倾向于触发这类语义更新"。

**死了的表现**：语义移动和证书结果之间没有规律性——每次连接都是随机的。如果是这样，V-R只是反馈循环，没有伴随-like结构。

**降级方案**：226-v0已经给出了降级方案——"反馈循环"。这是最弱但最安全的结构。227的修正也保留：伴随-like结构可能是闭包后的派生结构，不是原始结构。

#### 候选5：图册是Grothendieck拓扑

**活着的表现**：跑例子时，确实看到多个局部表示能共同看清处境（代数表示看清矩约束，多项式表示看清符号结构，极值表示看清支撑宽度），且局部证书在重叠处能粘合成全局证明。

**死了的表现**：多个局部表示之间无法对齐（没有重叠），或者局部证书在重叠处总是不一致（无法粘合）。如果是这样，图册概念不成立——每个表示是独立的，不能合成。

**降级方案**：227的修正保留——先定义局部证书预层Cert和重叠对象，site从可粘合的覆盖族中长出来。如果跑例子时没有可粘合的覆盖族，site概念不成立。

#### 候选6：能量是序量

**活着的表现**：跑例子时，确实看到处境有多个维度的"难度"（表示复杂度/证书距离/自由度残差/粘合缺陷/反例压力/形式化缺口），且好的语义移动在至少一个维度上降低难度。

**死了的表现**：难度无法分解成多个维度，或者好移动和坏移动在难度变化上没有可区分的模式。如果是这样，能量概念不成立——启发式退回到纯AI判断。

**降级方案**：227的"受控交换"和228-glm5.2的"双标准共存"都保留。如果能量不可形式化，启发式退回到AI判断+执行契约记录。

### 5.3 生死条件的统一原则

**每个候选结构的生死条件都绑定到一个具体的现象观察。** 这意味着：

1. 跑例子不是"看看什么出现"，而是**逐个检查每个候选的生死条件**
2. 如果一个候选死了，它的降级方案自动生效——框架不会崩溃，只是退回到更弱的结构
3. 如果一个候选活着，它获得了正当性——不是因为我们预设了它，而是因为现象中看到了它

**这就是226-v1的野心和227的克制的统一：追求可检查的数学条件（226-v1），但每个条件必须绑定生死条件（227的克制）。**

## 6. 执行契约的深层角色

### 6.1 执行契约不是表格，是边界跨越协议

228-codex提出执行契约——每次AI动作必须说明四件事：

```
Semantic Move
  我在改变什么处境？
  我预期降低什么困难？（允许填"探索性移动，暂不确定"）
  我能把它编译成什么经典计算任务？（必须填）
  经典计算返回后，我准备如何更新语义场？（必须填）
```

235号把这当成一个工程表格。但它的深层角色更重要：

**执行契约是边界跨越的协议。** 每次AI动作都是一次跨越边界的尝试。执行契约的四个字段对应边界跨越的四个环节：

| 执行契约字段 | 边界跨越环节 |
|---|---|
| 我在改变什么处境？ | 边界以外的处境定位 |
| 我预期降低什么困难？ | 边界以外的感知判断 |
| 我能把它编译成什么计算任务？ | 跨越边界——从感知到对象 |
| 经典计算返回后，我准备如何更新？ | 跨越后的回流——边界推进 |

### 6.2 为什么"编译成计算任务"和"返回后如何更新"必须填

228-glm5.2指出"预期降低什么困难"允许填"探索性移动"——数学家的探索性移动不是目标导向的。这是对的。

但"编译成什么计算任务"和"返回后如何更新"必须填——因为这两个是**闭环的关键**。没有"编译成计算任务"，AI的语义移动没有接上经典计算——它只是写了一段数学解释，没有跨越边界。没有"返回后如何更新"，经典计算的结果不会回流——边界不会推进。

**执行契约的真正功能是防止"假闭环"**——AI写了漂亮的数学叙述，但没有真正跨越边界（没有编译成计算任务），或者跨越了但没有回流（没有更新语义场）。执行契约强制每次动作都完成完整的边界跨越。

### 6.3 执行契约与§2.4的连接

§2.4说：非特定性 = 方法可从边界以外使用 = 边界推进能力。

执行契约是**边界推进能力的操作性检查**：如果AI能填完执行契约（特别是"编译成计算任务"和"返回后如何更新"），说明它的方法有边界推进能力——它可以从边界以外产生可检查目标并准备回流。如果AI填不完（说不出能编译成什么计算任务），说明它的方法没有边界推进能力——它只是在边界以外"想"，没有跨越边界。

**这把执行契约和§2.4的非特定性检验直接连接了：执行契约可填完 = 方法有边界推进能力 = 方法是非特定的。**

## 7. 实验设计：可区分的矩条件极差题样例

### 7.1 为什么不是"跑跑看"

235号说"跑矩条件题，看哪些结构自然出现"。这不是实验设计——这是碰运气。真正的实验设计应该**能区分候选**——跑完后能对每个候选说"活着"或"死了"。

236号的实验设计：跑矩条件极差题时，**逐个检查§5.2的生死条件**，跑完后对每个候选给出判定。

### 7.2 实验对象

矩条件极差题（第一部分：证明C=√5；第二部分：发现n^(-1/3)错误）。

选这道题因为它同时包含：换表示（中心化/多项式/对偶）、局部证书（恒等式/符号条件/反证）、反例压力（第二部分n^(-1/3)错误）、形式化目标（每个恒等式可被SymPy验证）、粘合问题（多个表示的局部结论能否合成整体证明）。

### 7.3 跑法（单任务双产出）

按闭环动力学跑，每一步记录执行契约+数据基座条目+生死条件检查：

### 7.4 跑完后对每个候选的判定

跑完后，对§5.2的六个候选逐个判定：

**候选3（自然性是交换图）**：
- 看到了方法在表示变换前后产生相容证书目标吗？
- 如果看到了→自然性成立（活着）

**候选4（V-R是伴随-like）**：

### 7.5 第二部分（n^(-1/3)错误）的特殊检查

第二部分重点检查：

1. **AI何时发现数值结果与题目声称不兼容**——这是边界以外的感知还是边界以内的验证？
2. **这个发现是反例证书还是诊断反馈**——227的三分类在实际中是否清晰？
3. **粘合障碍是什么级别**——descent failure / obstruction / Čech / H¹？227的四级在实际中是否可区分？
4. **题目错误的发现是形式化边界推进的哪一步**——从感知到证书的跨越在哪里发生？
5. **这个反例证书是否不可逆地留在了数据基座中**——边界推进的不可逆性是否成立？

### 7.6 五个验证目标

跑完后验证：

1. **闭环能解题**（230号）：最终证明能被证书账本支撑
2. **知识能成为燃料**（231号+234号修正）：数据基座条目作为闭环副产品自动产生
3. **工程概念和数学结构是否统一**（232号+234号）：工程单元字段是否对应数学结构
4. **形式化边界是否真的在推进**（233号）：哪些东西从边界以外被拉到边界以内？推进了哪些步骤？推进是否不可逆？
5. **边界推进路径的可复用性**（234号）：跑完后的数据基座条目能否帮助下一道相似题

**加上236号的新目标**：

6. **每个候选结构的生死判定**（236号§5.2）：六个候选分别活着还是死了？活着的获得了正当性，死了的降级。

## 8. 数据基座（231号+234号修正）

### 8.1 数据基座的深层定义

数据基座不是"数学工程单元库"——它是**形式化边界的显式记录**。每个数学工程单元标记着形式化边界的一个位置——这个位置上的东西已经被形式化了。

数据基座的增长 = 形式化边界的推进。

### 8.2 数学工程单元的结构（按边界位置四阶段组织）

**阶段1：边界标记（处境的当前状态）**
- 处境描述：对象、关系、条件、目标、领域
- 表示图册：原始表示、规范化表示、对偶表示、形式化表示

**阶段2：跨越边界（从感知到形式化的过程）**
- 语义移动：每一步为什么做、改变了什么、属于哪类移动
- 表示变换：中心化、换基、归一化、对偶化、构造辅助对象

**阶段3：边界以内（已形式化的产物）**
- 证书目标：这一步产生哪些可检查声明
- 证书结果：已验证、已反驳、未知、诊断失败
- 依赖关系：用到哪些条件、引理、定理、表示翻译
- 经典任务：SymPy、Sage、SMT、Lean、枚举或数值检查任务

**阶段4：边界以外的感知沉淀**
- 模式模板：可迁移的触发信号、证书模板、反例模板
- 自然性测试：换表示、换参数、取变体后方法是否仍产生同类证书目标
- 反例边界：哪些变体不成立，哪些条件删掉会失败

**四阶段形成时间结构**：起点（边界标记）→过程（跨越）→产物（边界以内）→经验（感知沉淀）→下一轮的起点。

### 8.3 分层形式化

不要求所有材料一开始就完全形式化。五层：
1. 结构化（拆成对象/条件/目标/步骤/依赖）
2. 规范化（同类操作统一命名）
3. 可执行化（编译成计算任务）
4. 局部证书化（计算结果写成可复查证书）
5. 完整形式化证明（最高层，不是所有材料都能达到）

系统允许不同成熟度的材料共存。

### 8.4 检索机制

数据基座不是RAG。检索不是找相似文本，是找**相似的边界推进路径**。

两个处境"相似"=面临相似的不自然+需要相似的跨越+产生相似的证书目标。

工程实现：
1. 粗筛：结构化字段匹配（处境类型+移动类型+证书类型）
2. 精化：图查询在依赖图中找连通路径
3. 排序（可选）：向量检索在剩余候选中排序

核心是路径结构匹配，不是embedding相似度。

### 8.5 抽取机制

**抽取就是闭环本身。** 求解过程自然产生数据基座条目——每步语义移动被记录，每个证书目标被编译，每个验证结果被回写。不需要单独做抽取。

**单任务双产出**——跑一次闭环，同时产出（a）问题的解和（b）数据基座条目。

### 8.6 时间尺度

- **短期可实现**（第一轮闭环就能验证）：数据基座支持运行时闭环——提供相似处境、证书模板、失败边界
- **中期效应**（数据基座积累到一定规模）：跨问题的模式迁移——一个问题发现的模式帮助另一个问题
- **长期正反馈**（数据基座积累到足够规模）：数据基座反过来生成训练数据，增强AI的边界以外感知

### 8.7 工程单元与数学结构的对应

**两者都是形式化边界的描述——同一件事的两个面：**

| 数学工程单元字段 | 226/227数学结构 | 形式化边界的位置 |
|---|---|---|
| 处境描述+表示图册 | Σ的对象+图册 | 边界两侧的处境空间 |
| 语义移动+表示变换 | Σ的态射 | 跨越边界的过程 |
| 证书目标+证书结果+依赖关系 | C的对象+态射+依赖链 | 边界以内的已征服领土 |
| 反例边界+失败边界 | obstruction | 边界跨越的障碍 |
| 模式模板+自然性测试 | 自然性交换图 | 边界跨越的条件 |

## 9. 十种能力（作为验证清单）

经典计算加入闭环后应获得的能力。跑例子时检查哪些出现：

1. **可靠性边界**——AI提出引理，经典计算回答是否成立
2. **反例生产**——经典计算搜索小模型、边界情况
3. **结构显影**——因式分解、消元、正规形显露新结构
4. **搜索空间裁剪**——不可行方向标记为死路
5. **局部证书积累**——局部等式/不等式/子引理逐步获得证书
6. **形式化压力**——迫使AI把模糊感觉压成可检查声明
7. **依赖审计**——维护依赖图，回答"如果这个条件删掉，哪些结论还成立"
8. **粘合检查**——检查多个表示的局部理解是否相容
9. **可回放性**——计算过程可记录、可重复、可复查
10. **模式库真实增长**——每个模式附带适用信号、证书模板、失败案例

**注意**：十种能力是列举不是结构。它们之间的关系待在跑例子中澄清——哪些是基础的，哪些是派生的，哪些是冗余的。

## 10. 与数学大师项目的关系

### 10.1 这套框架对实际系统建设意味着什么

数学大师项目的目标是制造能做数学研究的AI——提出猜想、构造证明、发现新定理。236号框架对这个目标的具体含义：

**数学大师 = 形式化边界推进系统。** 它不是一个"会做题的AI"，而是一个"能持续推进形式化边界的系统"。每一次运行，它从边界以外感知"不自然"，压缩成可检查目标，经典计算在边界以内验证，结果回写数据基座——边界向前推进一步。

这意味着数学大师的能力不等于"AI模型的推理能力"。它等于"AI感知 + 经典计算验证 + 数据基座积累 + 闭环反馈"的综合能力。一个更强的AI模型但没有闭环，可能不如一个稍弱的AI模型但有完整闭环——因为前者只能产生"可能的意义"，后者能把意义不断压成"可确认的资产"。

### 10.2 实现路径

从当前状态到数学大师的路径：

**第一步（当前）**：跑矩条件极差题闭环样例，验证§7的实验设计。这一步验证闭环能否工作、候选结构的生死判定、数据基座能否自动产生。

**第二步**：如果第一步成功，把闭环从单题扩展到一类题（矩条件极值问题类）。验证数据基座的跨问题迁移——第一道题的数据基座条目能否帮助第二道题。

**第三步**：从一类题扩展到多类题（不同拓扑的问题）。验证模式库的真实增长——不同问题类的模式能否互相迁移。

**第四步**：从有解答的题扩展到开放问题。验证系统能否在不知道答案的情况下推进边界——这是§2.4的最终检验。

**第五步**：从解题扩展到提出猜想。验证系统能否不仅推进边界，还能发现新的"不自然"——这是数学大师的终极能力。

### 10.3 与现有系统的关系

当前项目已有的组件：
- **ArangoDB认知图**（35个认知单元，51条边）→ 对应数据基座的早期形态
- **依赖图K**（定理依赖+思维拓扑+子模式映射）→ 对应Σ和C的早期形态
- **guided-math-solving元组群**（5个Skill）→ 对应闭环动力学的早期实现
- **执行契约**→ 对应边界跨越协议

236号框架不是推翻这些组件，而是给它们一个统一的深层理解：它们都是形式化边界推进系统的组件。认知图是边界位置的记录，依赖图K是边界结构的描述，guided-math-solving是边界推进的执行流程，执行契约是边界跨越的协议。

### 10.4 与GLM-5.2裸跑baseline的关系

AGENTS.md记录的GLM-5.2裸跑baseline：43道竞赛最难题，正确率18.9%，30道做不出来。这个baseline测量的是"AI模型的边界以外感知能力"——在没有闭环的情况下，AI能感知到多少"不自然"。

236号框架预测：加上闭环后，即使AI模型的感知能力不变（还是18.9%的题能感知到正确方向），系统的整体能力应该显著提升——因为感知到的"不自然"会被压成证书，证书会回流改变理解，理解会引导下一轮感知。**闭环的力量不在于让AI更聪明，而在于让每一次感知都变成不可逆的进展。**

这个预测是可验证的——用§7.7的对照实验，比较单纯AI路线和闭环路线在30道做不出来的题上的表现。

## 11. 纪律：不做什么

1. **不先写更高阶的抽象框架**——227和228-codex的共识。下一步是跑例子，不是写公理系统。
2. **不预设漂亮数学结构**——226-v1的教训。每个结构必须从例子中浮现，且通过生死条件检查。
3. **不把经典计算降级成事后验算器**——228-codex的警告。经典计算是边界以内的主动生产者，不是AI答完以后用来检查的工具。
4. **不把未证内容伪装成已证内容**——225号的纪律。所有未兑现的语义必须在账本里保持未兑现状态。
5. **不把形式化等同于全部Lean化**——231号的分层形式化。系统允许不同成熟度的材料共存。
6. **不单独做抽取**——234号的修正。抽取是闭环的副产品，单任务双产出。
7. **不放弃数学化**——228-glm5.2对228-codex的修正。工程骨架和数学结构是同一件事的两个面，不能只做工程不做数学。
8. **不让数学语言先于对象成熟**——227的核心警告。site、H¹、lax adjunction都应该从可运行样例里长出来，而不是先占住主位。

## 13. 一句话总结

> AI数学工程的深层本质是**形式化边界的持续推进**。数学知识有形式化边界两侧的两种成分——可以形式化的进入数据基座，不可形式化的进入AI训练。闭环的每一次运行，AI从边界以外感知"不自然"，压缩成可检查目标，经典计算在边界以内验证，结果回写数据基座——形式化边界向前推进一步，且不可逆。**非特定性 = 方法可从边界以外使用 = 边界推进能力。** 数学结构（Σ/C/自然性/图册/obstruction/能量）是边界推进过程的数学描述，每个结构绑定生死条件——现象中出现它就活着，没出现就降级。下一步用矩条件极差题跑通闭环，单任务双产出，逐个检查六个候选结构的生死条件，验证形式化边界是否真的在推进。
