## 二、方向分析

### 核心问题：接下来优先做什么？

| 路径 | 做法 | 利 | 弊 |
|---|---|---|---|
| **路径一：先做 AI 判读层** | 用现有 283 条规则 + 排盘引擎，做 analyze.py，跑真实命例，产出完整命理分析报告 | 系统能真正用了；能发现哪些规则常用；AI 判读的需求会反过来指导考据优先级；项目目标"AI 智能判读"能落地 | 117 条规则暂无出处，报告中标注"出处待考据" |
| **路径二：先做考据** | 继续做 179 个任务（A/B/C/D 任选），补全规则出处 | 规则库可审计性提升 | AI 判读层继续延后；系统还是只能排盘+求值，不能产出命理分析报告；考据优先级是猜的 |
| **路径三：并行** | 判读层和考据同时推进 | 两条线都不停 | 判读层需要 Master 深度参与，考据需要 Worker 并行，资源分散 |

### 推荐：路径一（先做 AI 判读层）

**推荐理由**：

1. **项目目标是"AI 智能判读"**，现在判读层是零，这是最大的缺口。排盘引擎和规则库都是为判读层服务的，服务对象还没建起来。
2. **考据优先级靠猜不如靠跑**。跑几个真实命例，就能知道哪些规则真正常用、哪些几乎不触发，然后针对性地考据常用规则。按章节顺序猜优先级，不如按实际使用反馈定优先级。
3. **117 条无出处规则不影响系统运行**，只影响可审计性。可以先标注"出处待考"跑起来，后续再补。
4. **判读层做出来后，系统从"排盘工具"变成"推命系统"**，这是一个质变。考据只是量变（覆盖率从 58.7% 到 ~75% 或 ~95%）。
5. **路径二的天花板明确**：即使 179 个任务全做完，覆盖率最多 ~75%，21 条规则在星平会海里没有出处，凶格局弱项无法解决。做完了判读层还是没建。

## 三、AI 判读层方案

### 目标

给定一个命主的出生信息，系统能产出一份完整的命理分析报告，包含：
- 性格 / 六亲 / 事业 / 财运 / 婚姻 / 健康
- 大限走势（每限吉凶）
- 流年运势
- 格局成破
- 每条判断都引用具体规则 + 具体数据

### 架构设计

```
输入：出生年月日时 + 经纬度
    ↓
[已有] build_chart() → 完整星盘 JSON
    ↓
[已有] eval_rules() → 283 条规则求值结果
[已有] score_rules() → 格局质量评分
    ↓
[新建] analyze.py → 命理分析引擎
    ├── 分析维度1：命宫/身宫 → 命主性格基调
    ├── 分析维度2：十二宫星曜 → 六亲/事业/财运/婚姻/健康
    ├── 分析维度3：格局判定 → 格局成破 + 等级
    ├── 分析维度4：大限走势 → 每限吉凶
    ├── 分析维度5：流年运势 → 流年吉凶
    └── 每条判断 → {判断文本, 引用规则, 引用数据, 出处状态}
    ↓
[新建] report.py → 报告格式化
    ├── JSON 格式（机器可读）
    ├── 文本格式（人可读）
    └── 每条判断标注：规则编号 + 数据来源 + 出处状态（已考据/待考据）
    ↓
输出：结构化命理分析报告
```

### 关键设计决策

1. **analyze.py 是代码，不是 AI prompt**：分析引擎用 Python 实现，调用 `build_chart()` + `eval_rules()` + `score_rules()`，按规则逻辑产出结构化判断。不是让 AI 在对话中临时判读。

2. **AI 的角色是调用和解释**：AI 调用 `analyze.py` 拿到结构化分析结果，然后在对话中解释、补充、综合。AI 不替代分析引擎，分析引擎也不替代 AI。

3. **出处状态分级**：
   - `已考据`：规则有 AUDIT 文件，引用具体古籍章节
   - `待考据`：规则可求值但无 AUDIT 文件，标注"出处待考"
   - `无出处`：规则可能是 MOIRA 软件作者原创组合

4. **先做最小可用版本**：先支持一个命例从输入到输出完整跑通，再迭代扩展。

## 六、不做什么

1. **不先做 179 个考据任务**：考据优先级等判读层跑完真实命例后再定
2. **不做 stop gate 修复**：stop hook 已移除，Master 在 tmux 中监控 Worker 更智能，后续不需要 stop hook
3. **不做新典籍 path list 构建**：21 条无匹配规则的出处考据，等判读层验证后再决定是否需要
4. **不做 Phase 6 扩展层**（相位/推运/返照/主限次限/日月食）：这些是高级功能，判读层先用已有的 283 条规则跑起来
