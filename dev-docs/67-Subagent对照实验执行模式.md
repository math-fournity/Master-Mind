# 67-Subagent对照实验执行模式

## 背景

在 xishujuzhen POC-1/POC-2/POC-3 的执行过程中，我们使用了两种 subagent 编排模式来执行对照实验。这两种模式值得记录下来，供后续 POC 和其他需要对照实验的场景复用。

## 模式一：双 Subagent 并行对照（POC-1/POC-2）

### 适用场景

需要对比两种条件下的 AI 输出质量，两组之间**没有依赖关系**——A 组的输入不依赖 B 组的输出，反之亦然。

### 执行方式

```
┌─────────────────────────────────────────────────┐
│  主 Agent（Devin）                                │
│                                                   │
│  1. 准备材料（生成 JSON、整理 study-notes 等）     │
│  2. 同时启动两个 background subagent              │
│                                                   │
│  ┌──────────────┐    ┌──────────────┐            │
│  │ Subagent A   │    │ Subagent B   │            │
│  │ (A组：对照)   │    │ (B组：实验)   │            │
│  │              │    │              │            │
│  │ 输入：        │    │ 输入：        │            │
│  │  study-notes │    │  依赖图JSON   │            │
│  │  星盘摘要     │    │  星盘摘要     │            │
│  │              │    │              │            │
│  │ 输出：        │    │ 输出：        │            │
│  │  分析结果     │    │  分析结果     │            │
│  │              │    │  +审计文件    │            │
│  └──────┬───────┘    └──────┬───────┘            │
│         │                   │                     │
│         └─────────┬─────────┘                     │
│                   ↓                               │
│  3. 收集两组输出                                   │
│  4. 盲评打分                                      │
│  5. 揭晓组别                                      │
└─────────────────────────────────────────────────┘
```

### 关键操作

**1. 同时启动两个 background subagent**

在一条消息中发出两个 `run_subagent` 调用，都设 `is_background: true`。这样两个 subagent 并行执行，互不等待。

**2. 等待完成**

用 `read_subagent` 的 `block: true` 依次等待两个 subagent 完成。第一个 `read_subagent` 会阻塞到 A 组完成，第二个会阻塞到 B 组完成（如果 B 组先完成了，第二个 `read_subagent` 会立即返回）。

**3. 盲评**

主 Agent 拿到两组输出后，**不看组别标记**，按统一的 5 维度评分标准打分。打分完成后再揭晓哪个是 A 组哪个是 B 组。

盲评的目的是避免主 Agent 在评分时偏向 B 组（因为 B 组用了主 Agent 自己设计的依赖图提示）。

### POC-1/POC-2 中的实际使用

- **POC-1**：A 组（直接读 study-notes）vs B 组（5 节点依赖图 JSON 提示）
- **POC-2**：A 组（增强版 study-notes）vs B 组（12 节点依赖图 JSON + 知识嵌入 + 审计要求）

两组的输入材料都由主 Agent 在启动 subagent 之前准备好，直接嵌入 subagent 的 task prompt 中。

### 优点

- 并行执行，等待时间短
- 实现简单，两个 subagent 互不依赖
- 盲评保证评分客观性

### 局限

- 两组之间没有依赖关系时才能用
- 如果 B 组的输入依赖 A 组的输出（或反过来），就不能并行

## 模式二：分阶段 Subagent + 并行对照（POC-3）

### 适用场景

B 组的执行分为多个阶段，**后一阶段的输入依赖前一阶段的输出**。同时 A 组不需要分阶段，可以和 B 组的第一阶段并行。

### 执行方式

```
┌──────────────────────────────────────────────────────┐
│  主 Agent（Devin）                                     │
│                                                        │
│  1. 准备材料（生成 JSON、整理 study-notes 等）          │
│                                                        │
│  2. 同时启动两个 background subagent                   │
│                                                        │
│  ┌──────────────┐    ┌──────────────────────┐        │
│  │ Subagent A   │    │ Subagent B-阶段一     │        │
│  │ (A组：对照)   │    │ (B组：解读JSON)       │        │
│  │              │    │                       │        │
│  │ 输入：        │    │ 输入：                 │        │
│  │  study-notes │    │  依赖图JSON           │        │
│  │  星盘摘要     │    │  星盘摘要             │        │
│  │              │    │                       │        │
│  │ 输出：        │    │ 输出：                 │        │
│  │  分析结果     │    │  大师级提示词          │        │
│  │ (不分阶段)   │    │  (interpretation)     │        │
│  └──────┬───────┘    └──────────┬────────────┘        │
│         │                       │                      │
│         │                       ↓                      │
│         │           3. 保存阶段一输出                   │
│         │                       │                      │
│         │                       ↓                      │
│         │           4. 启动 Subagent B-阶段二           │
│         │                       │                      │
│         │    ┌──────────────────┴──────┐              │
│         │    │ Subagent B-阶段二        │              │
│         │    │ (B组：双重提示下分析)     │              │
│         │    │                          │              │
│         │    │ 输入：                    │              │
│         │    │  依赖图JSON              │              │
│         │    │  大师级提示词(阶段一输出) │              │
│         │    │  星盘摘要                │              │
│         │    │                          │              │
│         │    │ 输出：                    │              │
│         │    │  结果文件                │              │
│         │    │  +审计文件(双重对照)     │              │
│         │    └──────────┬───────────────┘              │
│         │               │                              │
│         └───────────────┤                              │
│                         ↓                              │
│  5. 收集全部输出                                        │
│  6. 盲评打分（A组结果 vs B组结果）                      │
│  7. 揭晓组别                                           │
└──────────────────────────────────────────────────────┘
```

### 关键操作

**1. 同时启动 A 组和 B 组阶段一**

A 组不需要分阶段（直接读文档→分析→输出），所以 A 组的 subagent 一次性完成全部工作。B 组阶段一（解读 JSON）和 A 组并行启动。

**2. 等待 B 组阶段一完成**

用 `read_subagent` 的 `block: true` 等待 B 组阶段一完成。A 组可能同时完成，也可能稍后完成——不重要，因为 A 组的输出不参与阶段二。

**3. 保存阶段一输出**

B 组阶段一完成后，把输出保存到文件（如 `poc3_output_b_interpretation.md`）。这份文件是阶段二的输入。

**4. 启动 B 组阶段二**

把依赖图 JSON + 阶段一输出的大师级提示词 + 星盘摘要，一起嵌入阶段二的 task prompt 中。启动新的 subagent。

**5. 等待阶段二完成，同时收集 A 组输出**

用 `read_subagent` 等待阶段二完成。如果 A 组还没完成，也一并等待。

**6. 盲评**

和模式一一样——盲评 A 组结果 vs B 组结果，打分后揭晓。

### POC-3 中的实际使用

- **B 组阶段一**：解读 JSON → 大师级提示词（4811 字符）
- **B 组阶段二**：在 JSON + 大师级提示词共同提示下分析 → 结果（8604 字符）+ 审计（5326 字符）
- **A 组**：直接读增强版 study-notes → 分析结果（不分阶段，和 B 组阶段一并行）

### 优点

- 支持有依赖关系的多阶段流程
- A 组和 B 组阶段一并行，不浪费时间
- 阶段二的输入可以精确控制（只给阶段一的输出，不给阶段一的思考过程）

### 局限

- 比 模式一 复杂——需要管理阶段间的数据传递
- 阶段二必须等阶段一完成才能启动，有等待时间
- 如果阶段更多（三阶段、四阶段），管理复杂度进一步增加

## 两种模式的通用原则

### 1. 盲评

无论哪种模式，评分时都应该**盲评**——不看组别标记，按统一标准打分，打完再揭晓。

这是因为主 Agent 设计了 B 组的提示方式，天然有偏向 B 组的倾向。盲评是防止这种偏向影响评分客观性的机制。

### 2. 输入材料由主 Agent 准备

两组的输入材料都由主 Agent 在启动 subagent 之前准备好，直接嵌入 subagent 的 task prompt 中。subagent 不需要自己去读文件——所有需要的信息都在 task prompt 里。

这样做的原因：
- subagent 是无状态的，不能依赖之前的对话上下文
- 嵌入 task prompt 保证 subagent 拿到的材料完全可控
- 避免 subagent 读取文件时出错（路径错误、权限问题等）

### 3. subagent 用 background 模式

所有 subagent 都用 `is_background: true` 启动。这样主 Agent 可以在等待一个 subagent 的同时做其他事情（如准备下一阶段的材料）。

### 4. 输出保存到文件

subagent 的输出通过 `read_subagent` 收集后，立即保存到文件。这样做的原因：
- subagent 的输出可能很长，保存到文件方便后续引用
- 评分报告需要引用输出中的具体内容，文件引用比对话引用更可靠
- 文件可以被 git 跟踪，形成持久化记录

### 5. task prompt 要完整自包含

subagent 是无状态的，看不到主 Agent 的对话上下文。所以 task prompt 必须包含 subagent 完成任务所需的全部信息：
- 角色设定（"你是一位七政四余星学分析师"）
- 任务描述（"分析以下命盘的命宫"）
- 输入材料（星盘摘要、依赖图 JSON、参考知识等）
- 输出要求（输出什么文件、什么格式、什么内容）
- 约束（如"解读时不能改变 JSON 中的依赖关系"）

## 复用建议

### 何时用模式一（双 subagent 并行）

- 两组之间没有依赖关系
- 两组的工作量大致相当
- 需要快速得到对照结果

### 何时用模式二（分阶段 + 并行）

- B 组的执行有多个阶段，后阶段依赖前阶段输出
- A 组不需要分阶段
- 需要精确控制阶段间的数据传递

### 何时不用 subagent

- 对照实验只有一组（不需要对照）
- 实验条件简单，主 Agent 自己就能完成（不需要并行）
- 需要主 Agent 和 AI 交互式讨论（subagent 是一次性的，不能交互）

## POC 中的实际使用记录

| POC | 模式 | A组 | B组 | B组阶段 |
|---|---|---|---|---|
| POC-1 | 模式一 | 直接读 study-notes | 5节点依赖图 JSON | 1阶段（直接分析） |
| POC-2 | 模式一 | 增强版 study-notes | 12节点依赖图 JSON + 知识嵌入 + 审计要求 | 1阶段（直接分析） |
| POC-3 | 模式二 | 增强版 study-notes | 12节点依赖图 JSON + 解读要求 + 双重对照审计 | 2阶段（解读→分析） |

### POC-3 的具体执行时间线

1. 主 Agent 生成 JSON 和星盘摘要
2. 同时启动：A 组 subagent + B 组阶段一 subagent（解读 JSON）
3. B 组阶段一完成 → 保存大师级提示词
4. 启动 B 组阶段二 subagent（在 JSON + 大师级提示词共同提示下分析）
5. A 组完成（如果在步骤 3 之前完成）或 B 组阶段二完成
6. 收集全部输出 → 盲评 → 揭晓
