## 0. 一句话概括本文档

我们有一个引导式数学解题系统（燧人系统），它在做题AI卡住时发送元认知提示（Q）来激活AI的思维。这些Q所代表的"什么时候该提示什么"的经验，以Pattern的形式存储在稀疏矩阵（认知图/依赖图）中。**问题是：当做题AI停在了某个状态、需要某个特定Pattern时，系统如何从海量Pattern存储中精准提取此刻最需要的那一个（或那一批）？** 这是一个检索问题，但不是普通的文本检索——检索的判据不是文本相似性，而是思维状态的匹配，而思维状态匹配的机制我们还没有。

本文档用矩条件极差题第二问的完整QA序列作为案例，把这个检索问题从头到尾、具体地、可操作地描述清楚。

## 1. 背景：燧人系统是什么

### 1.1 核心理念

燧人系统（第二代数学大师系统）的核心理念是"钻木取火"——不给AI答案，而用元认知提问启发AI自己的思维。

面对一道数学题，做题AI（工作智能体）可能在某个地方卡住。此时引导者AI（助理智能体）发送一个提示Q，激活做题AI的某个思维方向，帮它继续推进。

### 1.2 两个智能体

| 角色 | 别名 | 职责 | 能力边界 |
|---|---|---|---|
| **工作智能体** | 做题AI | 在提示下尝试解题，产出每一步的推理 | 有数学能力但会卡住 |
| **助理智能体** | 引导者AI | 观察工作智能体的状态，决定发送什么Q | 能做模式识别，但内在知识不足以自己提出特定Q |

### 1.3 DFS引导架构

引导过程是一棵深度优先搜索（DFS）树：
- **节点** = 工作智能体的一个状态（一段推理输出 + 累积context）
- **边** = 引导者发送的一个Q（一个提示/发问）
- **根节点** = 题目本身
- **叶节点** = 成功叶（正确解答）/ 死路叶（卡死或错误方向）/ 截断叶（超限停止）

引导者在每个节点生成候选Q列表，按Level（抽象度）降序排列，一次发一个Q，走不通就回溯。

### 1.4 Level与非特定性

每个Q有两个标签：

**Level**（0到1实数）：提示的抽象度。
- →1：纯思维模式（"试试反证法"），跨领域通用
- →0：纯知识（"用badly approximable性质"），绑定特定领域

**非特定性程度**（0到1实数，越大越特定）：Q的有效性是否依赖于引导者知道正确解答路径。
- →0：完全非特定——引导者不需要知道答案就能发出这个Q
- →1：完全特定——引导者必须知道答案才能发出这个Q

### 1.5 稀疏矩阵（认知图/依赖图）

系统积累了大量"什么时候该提示什么"的经验。这些经验以Pattern的形式存储在稀疏矩阵中——一个ArangoDB图数据库，节点是认知单元/数学元素/思维模式，边是依赖关系。

每个Pattern大致包含：
- **触发条件**：工作智能体处于什么状态时该用这个Pattern
- **Q内容**：该发送什么提示
- **Level值**：提示的抽象度
- **历史使用记录**：这个Pattern过去在什么情况下用过、效果如何

**稀疏**的含义：Pattern数量巨大（随着系统积累不断增长），但在任何一个具体时刻，只有极少数Pattern与当前状态相关。

## 2. 案例：矩条件极差题第二问

### 2.1 题目

已知 $a_1, a_2, \ldots, a_n$ 为实数，满足：

$$\sum_{i=1}^n a_i = n, \quad \sum_{i=1}^n a_i^2 = 2n, \quad \sum_{i=1}^n a_i^3 = 3n$$

**(2)** 证明存在常数 $C_2 > 0$，使得对所有 $n \ge 4$，

$$\max a_i - \min a_i \ge \sqrt{5} + C_2 \, n^{-3/2}$$

### 2.2 证明路径概要（10步）

这道题的正确证明路径有10个关键步骤：

| 步骤 | 做了什么 | 知识成分(Level→0) | 思维模式成分(Level→1) |
|---|---|---|---|
| 1. 中心化 | $x_i = a_i - 1$ → $\sum x_i = 0, \sum x_i^2 = n, \sum x_i^3 = -n$ | 无 | 归一化(0.9) |
| 2. 关键多项式 | $q(x) = x^2 + x - 1$，根 $r = \frac{-1-\sqrt{5}}{2}, s = \frac{-1+\sqrt{5}}{2}$，$s - r = \sqrt{5}$ | $q(x)$的具体形式(0.3) | 寻找统一编码(0.85) |
| 3. 两个恒等式 | $\sum q(x_i) = 0, \sum x_i q(x_i) = 0$ | 无 | 恒等式挖掘(0.8) |
| 4. 紧性归约 | 设 $R = \sqrt{5} + \delta$，$\delta \le 1$ 时所有 $x_i$ 落在固定紧区间 | 无 | 紧性归约(0.8) |
| 5. 投影到根 | $\zeta_i \in \{r, s\}$（最近根），$e_i = x_i - \zeta_i$ | 投影的具体形式(0.4) | 投影分解(0.7) |
| 6. 稳定性方程 | $5D = 3\sqrt{5}(B_r - B_s) + 2C$ | 无 | 恒等式挖掘/扰动分析(0.8) |
| 7. D的量级 | $p = \frac{5-\sqrt{5}}{10}$ 二次无理 → $\|D\| \ge c/n$ | **badly approximable(0.2)** | 量级感知(0.5) |
| 8. $\sum e_i^2 \ge c/n$ | 由稳定性方程 + D下界 | 无 | 能量传递(0.6) |
| 9. $\sum q(x_i)^2 \ge c/n$ → $S \ge c/\sqrt{n}$ | 柯西不等式 | 柯西不等式(0.3) | 能量传递(0.6) |
| 10. $\delta \ge c/n^{3/2}$ | $q(x)$ 在正值区 $\le c\delta$ → $S \le n\delta$ | 无 | 能量传递(0.6) |

**关键瓶颈**：步骤7是纯知识瓶颈——badly approximable性质（Level 0.2），思维模式提示无法替代。

### 2.3 完整预演QA序列（10轮）

以下是引导者引导工作智能体完成第二问证明的完整QA序列。每轮包含Q（引导者发送的提示）、预期A（工作智能体的回复）、Level值、非特定性程度值。

---

**Q1**（Level 1.0, 非特定性 0.1）：
> "请读取problem.txt。不要解题。描述这道题的结构形状：结论是什么类型？和第(1)问有什么区别？条件和结论之间的'距离'有多远？"

→ **A1**：识别为渐近精细下界问题。第(1)问证极差≥√5（常数下界），第(2)问要证极差≥√5+C₂n^(-3/2)（渐近精细下界）。差距：需要定量分析δ=R-√5的量级，证明δ≥c/n^(3/2)。

---

**Q2**（Level 1.0, 非特定性 0.0）：
> "列出你能想到的所有可能方向——不要求正确，不要求完整，只要列出你脑中浮现的任何方向。"

→ **A2**：列出方向：复用第(1)问的q(x)和恒等式、在极差接近√5时做更精细分析、投影到根、扰动分析、数值实验观察δ量级、极值构型分析、紧性论证...

---

**Q3**（Level 1.0, 非特定性 0.0）：
> "对你觉得最有希望的方向，描述第一步会做什么。不要求真的做，只描述。"

→ **A3**：描述：先复用q(x)和两个恒等式，然后设R=√5+δ，分析δ很小时的行为。可能描述紧性归约思路——δ≤1时所有点落在固定紧区间内。

---

**Q4**（Level 1.0, 非特定性 0.0）：
> "选一个方向，试着做第一步。做多少算多少，做不出来也没关系。"

→ **A4**：设R=√5+δ，做紧性归约：δ≥1时结论显然成立，故只需讨论0≤δ≤1。此时所有xᵢ落在固定紧区间[r-1, s+1]。

---

**Q5**（Level 1.0, 非特定性 0.0）：
> "你得到了什么？这个结果和你要证明的结论之间还有什么差距？下一步你想怎么走？"

→ **A5**：完成了紧性归约，但还没有δ的定量下界。差距：知道δ≥0（第(1)问），需要δ≥c/n^(3/2)。需要更精细的分析。

---

**Q6**（Level 0.7, 非特定性 0.6）：
> "在极值构型附近，把每个点分解成'离它最近的关键点'加上'偏差'。"

→ **A6**：投影到最近根：以中点-1/2为界，ζᵢ=r（xᵢ≤-1/2）或ζᵢ=s（xᵢ>-1/2），定义eᵢ=xᵢ-ζᵢ。得到展开式q(xᵢ)=±√5·eᵢ+eᵢ²。由紧性得统一界|eᵢ|≤√5/2。

---

**Q7**（Level 0.8, 非特定性 0.4）：
> "把你的三个矩条件和偏差展开式做组合——求和、相乘、线性组合——看看能产生哪些'免费的恒等式'。"

→ **A7**：导出稳定性方程：
- 由Σxᵢ=0 → A_r+A_s=-D ... (1)
- 由Σq(xᵢ)=0 → -√5·A_r+√5·A_s+B_r+B_s=0 ... (2)
- 由Σxᵢq(xᵢ)=0 → **5D = 3√5(B_r-B_s) + 2C** ... (3)

其中D=Σζᵢ=kr+(n-k)s=√5(pn-k)，p=(5-√5)/10。

---

**Q8**（Level 0.5, 非特定性 0.7）：
> "你的稳定性方程里有一个量D，它取决于k和n的关系。D能等于0吗？如果D不能等于0，它至少有多大？"

→ **A8**：分析D=√5(pn-k)。D=0需要k/n=p，但p是无理数，所以D≠0。但|D|至少有多大？AI尝试各种估计但有困难——**这是知识瓶颈**。

---

**Q9**（Level 0.2, 非特定性 0.9）：
> "p=(5-√5)/10是二次无理数。数论中有一个标准事实：二次无理数的连分数部分商有界，因此它是badly approximable——存在常数c₀>0使得对任意整数k,n，|p-k/n|≥c₀/n²。你能用这个事实推出|D|的下界吗？"

→ **A9**：使用badly approximable性质：|p-k/n|≥c₀/n² → |pn-k|≥c₀/n → |D|≥c₁/n。由稳定性方程(3)：5|D|≤4√5·E，因此E=Σeᵢ²≥c₂/n。

---

**Q10**（Level 0.6, 非特定性 0.7）：
> "你现在知道了偏差能量的下界Σe²≥c/n。你需要把这个下界传递到极差的下界δ。想想q(x)在根附近的行为，以及柯西不等式。"

→ **A10**：完成最后步骤：
- |q(xᵢ)|≥c₃|eᵢ| → Σq(xᵢ)²≥c₄/n
- 令S=Σ_{q>0}q(xᵢ)，由Σq(xᵢ)=0知2S=Σ|q(xᵢ)|
- 柯西：Σ|q(xᵢ)|≥√(Σq(xᵢ)²)≥c₅/√n → S≥c₆/√n
- q(x)在正值区总长度α+β=δ，q(x)≤c₇δ → S≤nc₇δ
- 合并：nc₇δ≥c₆/√n → **δ≥c₈/n^(3/2)** ✓

## 3. 检索问题：从工作智能体的状态到稀疏矩阵中的Pattern

### 3.1 问题的提出

QA序列是预演——引导者事先知道正确路径，所以能按顺序发出Q1到Q10。但238号第8.1节明确指出：

> "预演是'已知答案倒推提示序列'，实际是'未知答案，边探索边决定下一步问什么'。这两者有本质区别。"

在实际运行中，引导者**不知道正确解答路径**。它面对的是工作智能体的一段推理输出，需要决定"下一步该发什么Q"。这个决策依赖于从稀疏矩阵中检索到与当前状态匹配的Pattern。

**检索问题是：给定工作智能体的当前状态（一段推理输出+累积context），如何从稀疏矩阵的海量Pattern存储中，提取此刻最需要的那一个（或那一批）Pattern？**

### 3.2 用Q8作为具体案例

以Q8为例，把检索问题具体化。

#### 3.2.1 Q8之前的状态

工作智能体在Q7之后产出了A7——导出了稳定性方程：

$$5D = 3\sqrt{5}(B_r - B_s) + 2C$$

其中 $D = \sqrt{5}(pn - k)$，$p = \frac{5-\sqrt{5}}{10}$。

工作智能体停在这里。它有稳定性方程，但不知道下一步该做什么。

#### 3.2.2 此刻需要什么

此刻需要的是Q8所代表的Pattern：
- **触发条件**：工作智能体有了稳定性方程，方程中有一个量D取决于整数k和n的关系，D不能为零但需要估计其下界
- **Q内容**："D能等于0吗？如果D不能等于0，它至少有多大？"
- **Level**：0.5（量级感知）
- **非特定性**：0.7（引用了特定的稳定性方程和量D）

#### 3.2.3 检索的输入和输出

**输入**：
- 工作智能体的当前推理输出（A7的内容：稳定性方程的推导过程和结果）
- 累积context（Q1-Q7的完整历史 + 工作智能体的所有回复A1-A7）
- 题目本身（第二问的题面）

**期望输出**：
- 从稀疏矩阵中检索到Q8这个Pattern（或包含Q8的一批候选Pattern）
- 交给助理智能体，由助理智能体判断此刻最需要Q8，放入DFS发送

#### 3.2.4 检索为什么难

**难点1：助理智能体怎么"看到"该发Q8了？**

A7的文本是一段数学推导。助理智能体读了这段文本，需要识别出"这里有一个量D需要估计下界"。但：

- **不是关键词匹配**：A7中可能出现"D""k""n"这些符号，但这些符号在其他完全不同的上下文中也会出现。关键词"D的下界"可能根本不在A7的文本中——AI可能只写了稳定性方程就停了，没有提到"下界"这个词。
- **不是RAG语义相似**：RAG会找"和A7文本最相似的存储文本"。但Q8的Pattern存储的不是"和A7相似的文本"，而是"当推理到达稳定性方程这个节点时，该问D的下界"这个**关系**。文本相似不等于状态匹配。
- **238号第3章说"形状匹配是拓扑的"**：但"拓扑匹配"具体怎么实现？什么是"推理的拓扑"？怎么计算两个拓扑之间的相似度？没有答案。

**难点2：怎么从海量Pattern中提取到Q8？**

稀疏矩阵中存储了大量Pattern——不只是这道题的10个Q，而是系统积累的所有经验。在"此刻"这个具体状态，可能：
- 没有任何Pattern完全匹配当前状态（因为每道题的具体推导都不同）
- 有多个Pattern部分匹配（Q8匹配，但可能Q6的某个变体也匹配，某个完全不同题目的某个Pattern也部分匹配）
- 需要的是**近似匹配**——找到"最接近此刻需要"的那一批

但"接近"的定义是什么？不是文本相似，不是关键词重叠，是什么？

**难点3：助理智能体的知识不足，怎么补？**

助理智能体能做模式识别——它可能识别出"这里需要某种关于下界的提示"。但它自己不知道Q8的内容（"D能等于0吗？它至少有多大？"）。它需要：
1. 从稀疏矩阵拿到一批候选Pattern
2. 在候选中判断"此刻最需要哪个"
3. 把选中的Q放入DFS发送

但步骤2本身又需要知识——如果助理智能体的知识不足以提出Q8，它的知识足以在候选中选出Q8吗？这里有一个**知识悖论**：需要知识才能提出Q8，也需要知识才能识别Q8是对的。如果助理智能体有足够的知识识别Q8，它大概也有足够的知识提出Q8——那为什么还需要稀疏矩阵？

### 3.3 检索问题的三层结构

把上面的分析整理一下，检索问题有三层：

#### 第一层：状态感知——助理智能体怎么"看到"工作智能体需要什么？

工作智能体停在某个状态。这个状态以什么形式被助理智能体"看到"？

| 方案 | 机制 | 问题 |
|---|---|---|
| 关键词 | 在工作智能体输出中匹配关键词 | 同一关键词在不同上下文含义不同；需要的概念可能不在文本中 |
| RAG语义相似 | 找与当前输出文本最相似的存储文本 | 文本相似≠思维状态相似；需要的是"关系"不是"文本" |
| 思维拓扑 | 匹配推理的结构形状 | 方向正确但实现未定义——"拓扑"怎么表示？怎么计算相似度？ |

238号第3章给了方向（"形状匹配是拓扑的"），但没有给实现。**"形状"怎么表示？"匹配"怎么计算？** 这是第一层未解决的问题。

#### 第二层：Pattern提取——怎么从海量存储中拿到最需要的那一批？

即使第一层解决了（助理智能体识别出了"此刻需要某种关于下界的提示"），怎么从稀疏矩阵中提取到Q8？

稀疏矩阵是"稀疏"的——Pattern数量巨大，此刻相关的极少。需要的是在海量存储中快速定位。

| 方案 | 机制 | 问题 |
|---|---|---|
| 全量扫描 | 遍历所有Pattern，逐一匹配 | O(n)复杂度，Pattern数量大时不可行 |
| 索引 | 为Pattern建索引，按某种key快速查找 | 索引key是什么？如果是关键词，回到第一层的问题 |
| 图遍历 | 从当前状态对应的节点出发，在依赖图中遍历 | 当前状态对应哪个节点？遍历方向是什么？ |
| 嵌入向量 | 把Pattern和当前状态都编码为向量，做最近邻搜索 | 编码方式是什么？向量空间中"近"意味着什么？ |

**核心困难**：无论用什么方案，都需要定义"此刻的状态"和"存储的Pattern"之间的**相似度/匹配度**。而这个匹配度的定义，取决于第一层（状态怎么表示）的答案。

#### 第三层：知识悖论——助理智能体的知识不足，怎么补？

即使前两层解决了（状态被识别了，候选Pattern被提取了），助理智能体怎么在候选中做最终选择？

**知识悖论**：
- 助理智能体的内在知识不足以提出Q8 → 所以需要稀疏矩阵的帮助
- 但要在候选中选出Q8，需要判断"Q8是此刻最需要的" → 这个判断也需要知识
- 如果助理智能体有足够的知识做这个判断，它大概也有足够的知识直接提出Q8 → 那为什么还需要稀疏矩阵？

**可能的破解方向**（本文档不解决，只列出）：
- 助理智能体不需要"理解"Q8的数学内容，只需要做**形式匹配**——"当前状态的形状和Q8的触发条件的形状匹配"
- 但"形式匹配"又回到了第一层——形状怎么表示、怎么匹配
- 或者：助理智能体不做选择，把所有候选都发给工作智能体，让工作智能体自己选——但这违反了"一次发一个Q"的DFS架构
- 或者：引入第三个角色——一个专门做Pattern匹配的组件，它不做数学，只做匹配

### 3.4 检索问题的完整描述

把三层合起来，检索问题的完整描述是：

**给定**：
1. 工作智能体的当前推理输出（自然语言+数学公式）
2. 累积context（完整QA历史）
3. 题目本身
4. 稀疏矩阵中的海量Pattern存储（每个Pattern包含触发条件、Q内容、Level、历史记录）

**求**：
- 从Pattern存储中提取此刻最需要的一个（或一批）Pattern
- 交给助理智能体放入DFS发送

**约束**：
1. 提取必须在合理时间内完成（不能全量扫描海量存储）
2. 提取的判据不是文本相似性，而是思维状态的匹配
3. 助理智能体的内在知识不足以自己提出Q，需要Pattern存储的辅助
4. 存在知识悖论：识别Q和提出Q可能需要同等知识

**未解决的核心问题**：
- **思维状态怎么表示？**（第一层）
- **思维状态之间的匹配度怎么计算？**（第一层+第二层）
- **知识悖论怎么破解？**（第三层）

## 4. 用Q8案例走一遍检索过程

让我们假设检索系统已经建好了，用Q8这个具体案例走一遍，看看每一步会遇到什么问题。

### 4.1 输入：工作智能体停在A7之后

工作智能体刚输出了A7——稳定性方程的推导。完整context包含Q1-Q7和A1-A7。

### 4.2 第一步：状态感知

系统需要从A7+context中识别出"此刻工作智能体需要的是关于量D的下界的提示"。

**如果用关键词**：A7中出现了"D""k""n""稳定性方程"等词。系统搜索包含这些关键词的Pattern。问题：可能有成百上千个Pattern包含"D""k""n"这些常见符号。而且Q8的核心——"D不能为零但需要下界"——这个语义可能不在A7的文本中。

**如果用RAG**：把A7编码为向量，在Pattern向量库中做最近邻搜索。问题：A7是一段具体的数学推导，它的向量编码会反映其文本特征。但Q8的Pattern存储的不是"和A7相似的文本"，而是"当推理到达稳定性方程这个结构节点时，该问D的下界"。文本相似不等于结构匹配。

**如果用思维拓扑**：把A7的推理结构编码为某种拓扑表示（比如："从三个矩条件出发→投影到根→展开→组合恒等式→得到稳定性方程"这个路径），在Pattern库中找拓扑相似的。问题：拓扑表示怎么做？这是一个开放问题。

### 4.3 第二步：Pattern提取

假设第一步以某种方式成功了——系统识别出"此刻需要关于下界的提示"。现在要从稀疏矩阵中提取相关Pattern。

稀疏矩阵中可能存储了：
- Q8的Pattern：触发条件="有稳定性方程+量D取决于整数关系"，Q="D能等于0吗？至少有多大？"
- 某个其他题的类似Pattern：触发条件="有递推关系+量取决于整数关系"，Q="这个量能等于0吗？"
- 某个完全不同的Pattern：触发条件="有不等式需要估计常数"，Q="常数能取到吗？"

系统需要从这些候选中选出Q8（或Q8+类似Pattern的一批）。选择的判据是什么？如果用触发条件的相似度，又回到了"相似度怎么计算"的问题。

### 4.4 第三步：助理智能体的角色

候选Pattern交给了助理智能体。助理智能体需要：
1. 读取候选Pattern
2. 判断哪个最匹配当前状态
3. 放入DFS发送

**知识悖论出现**：助理智能体读了Q8的Pattern——"D能等于0吗？至少有多大？"。它需要判断"这个Q对A7之后的状态有效吗？"这个判断需要理解D是什么、为什么D的下界重要——也就是需要数学知识。但助理智能体的知识不足以提出Q8，那它的知识足以判断Q8有效吗？

### 4.5 Q8案例的完整检索流程图

```
工作智能体输出A7（稳定性方程）
        │
        ▼
┌─────────────────────────┐
│ 第一步：状态感知          │
│ 输入：A7 + 完整context    │
│ 输出："需要关于D下界的提示"│
│ 机制：???（未解决）       │
└─────────────────────────┘
        │
        ▼
┌─────────────────────────┐
│ 第二步：Pattern提取       │
│ 输入：状态感知结果         │
│ 输出：候选Pattern列表     │
│ 机制：???（未解决）       │
│ 从海量存储中如何快速定位？ │
└─────────────────────────┘
        │
        ▼
┌─────────────────────────┐
│ 第三步：助理智能体选择     │
│ 输入：候选Pattern列表     │
│ 输出：选中的Q             │
│ 机制：???（未解决）       │
│ 知识悖论：识别Q和提出Q    │
│ 可能需要同等知识          │
└─────────────────────────┘
        │
        ▼
Q8放入DFS，发送给工作智能体
```

每一步的机制都标注了"???（未解决）"——这就是检索问题的现状：我们知道需要什么，但不知道怎么做。

## 5. 检索问题为什么是"稀疏矩阵中的检索"而不是普通检索

### 5.1 和普通检索的区别

| 维度 | 普通检索（如搜索引擎） | 本问题 |
|---|---|---|
| 查询 | 用户输入的关键词/自然语言 | 工作智能体的推理状态（数学推导+context） |
| 目标 | 找到与查询相关的文档 | 找到与当前思维状态匹配的提示Pattern |
| 匹配判据 | 文本相似性/语义相似性 | 思维状态的拓扑匹配 |
| 存储规模 | 海量文档 | 海量Pattern（随系统积累不断增长） |
| 结果 | 一批相关文档 | 一个（或少数几个）最需要的Pattern |
| 精度要求 | 相关即可 | 需要精准——错误的Pattern会误导工作智能体 |

### 5.2 为什么叫"稀疏矩阵中的检索"

"稀疏矩阵"是本项目的认知图/依赖图的隐喻：
- **矩阵**：认知单元之间有依赖关系，可以看作一个大矩阵（行和列都是认知单元，单元格是依赖关系）
- **稀疏**：大多数认知单元之间没有直接依赖关系，矩阵中大多数单元格为空

Pattern存储在这个稀疏矩阵中——每个Pattern关联着若干认知单元，触发条件是这些认知单元之间的某种结构关系。

检索的困难正是来自稀疏性：在海量稀疏存储中，此刻相关的Pattern极少，但它们分散在矩阵的各个位置，没有简单的索引能快速定位。

### 5.3 为什么不是RAG

RAG（Retrieval-Augmented Generation）是当前主流的检索增强方案，但它不适用于本问题：

1. **RAG检索的是文本，本问题检索的是关系**：RAG把文档编码为向量，找文本相似的。但本问题需要找的是"当前思维状态和存储Pattern的触发条件之间的结构匹配"，这不是文本相似。
2. **RAG的查询单一，本问题的查询是复合的**：RAG的查询是一段文本。本问题的"查询"是工作智能体的完整状态——包括当前推理输出、累积context、题目本身——这是一个复合的、结构化的查询。
3. **RAG的结果是文档，本问题的结果是动作**：RAG返回文档供生成模型参考。本问题返回Pattern供助理智能体执行（发送Q）。Pattern不只是信息，是一个行动指令。

## 6. 检索问题的开放方向（本文档不解决，只列出）

### 6.1 思维状态的表示

第一层的核心问题。可能的方向：

- **结构化表示**：把推理过程解析为结构化的步骤图（步骤→依赖→当前节点），用图的结构特征做匹配
- **拓扑表示**：238号第3章的"形状"概念——推理的拓扑结构。但拓扑怎么编码？
- **混合表示**：结构化表示（骨架）+ 语义嵌入（血肉），用骨架做粗筛、用嵌入做精排

### 6.2 匹配度的计算

第一层+第二层的核心问题。可能的方向：

- **图同构/子图同构**：当前推理的步骤图和Pattern的触发条件图之间做同构检测。但完全同构太严格，需要近似同构。
- **图嵌入**：把推理的步骤图编码为向量，在向量空间中做最近邻。但图嵌入的编码方式需要设计。
- **LLM作为匹配器**：让一个LLM判断"当前状态和Pattern的触发条件是否匹配"。但这又回到了知识悖论——LLM需要足够的知识才能做这个判断。

### 6.3 知识悖论的破解

第三层的核心问题。可能的方向：

- **形式匹配而非内容理解**：助理智能体不需要理解Q8的数学内容，只需要做形式匹配——"当前状态的形状和Q8的触发条件的形状匹配"。但"形式匹配"的实现又回到了第一层。
- **分层架构**：助理智能体只做粗筛（基于形式特征），工作智能体自己做精筛（从候选中选择对自己最有帮助的）。但这改变了DFS架构。
- **Pattern自带适用性描述**：每个Pattern不只存储Q内容，还存储"我在什么情况下有效"的自然语言描述。助理智能体读这个描述来判断是否匹配。但描述的精确度决定了匹配的准确度。

### 6.4 索引结构

第二层的工程问题。可能的方向：

- **按思维模式分类索引**：Pattern按其代表的思维模式（归一化、恒等式挖掘、投影分解、量级感知...）分类。状态感知先识别"需要什么思维模式"，再在该类下检索。
- **按数学结构分类索引**：Pattern按其关联的数学结构（不等式、递推、多项式、连分数...）分类。
- **多级索引**：先按大类（思维模式）粗筛，再按小类（具体结构）精排。
