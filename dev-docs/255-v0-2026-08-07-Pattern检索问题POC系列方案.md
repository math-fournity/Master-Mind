## 0. 一句话概括本文档

254号发现四代系统对检索问题的回应是"逐层深化、互补共存"，一个完整的检索方案需要整合四代的独特贡献。本文档设计8个递进式POC，从最基础的状态感知机制开始，逐步叠加Pattern提取和知识悖论解决机制，最终验证完整检索流程的端到端可行性和跨题泛化能力。每个POC有明确的pass/fail标准、CheckList和产出，用5道不同类型的数学题作为并行测试用例。

## 1. 背景：254号的核心发现与整合假设

### 1.1 核心发现

254号遍历四代系统设计文档后发现：

1. **四代互补共存**：四代系统对检索问题的回应不是"后来者替代前者"，而是逐层深化、互补共存。每代有其他代没有的、与检索问题相关的独特设计。
2. **几乎全部只设计未实现**：四代相关设计中唯一有POC验证的是盘古的拓扑覆盖验证（POC-9，AQL集合差集1次通过100%覆盖）和meta/normal分离。
3. **整合方向**：一个完整的检索方案可能需要整合四代的独特贡献——每层用不同代的设计组合。

### 1.2 整合假设

254号§7.1提出的整合方向：

| 层 | 整合方案 |
|---|---|
| 状态感知 | 伏羲的数学处境S（状态表示）+ 女娲的W_t六类分量（形式化schema）+ 燧人的安全第一步（感知入口）+ 盘古的拓扑覆盖验证（质量保证） |
| Pattern提取 | 伏羲的路径结构匹配（匹配范式）+ 盘古的三级种子选择（检索架构）+ 女娲的Hint梯度（泄漏控制）+ 燧人的DFS+回溯（搜索策略） |
| 知识悖论 | 伏羲的形式化边界移动机制（认识论基础）+ 女娲的8角色可见性矩阵（工程隔离）+ 燧人的最小知识传递（优化目标）+ 盘古的meta/normal分离（计算分工） |

**本POC系列的目标**：验证这个整合方案是否可行。不是验证单个代的设计，而是验证四代设计组合在一起能否解决253号定义的检索问题。

## 4. POC-1：形状描述的结构化与可区分性

### 4.1 验证目标

验证AI能否对数学题产出结构化的形状描述，且不同题目的形状描述可区分、可复现。

这是检索问题的**最基础POC**——如果AI连形状都描述不出来，后续的状态感知和Pattern提取都无从谈起。

### 4.2 整合机制

| 来源 | 设计 | 在本POC中的角色 |
|---|---|---|
| 燧人·214号第5章 | 安全第一步——让AI先描述形状而非解题 | 形状描述的prompt设计 |
| 燧人·214号第6章 | 连续发问六层渐进——观察→联想→描述方向→小尝试 | 形状描述的层次结构 |
| 伏羲·219-221号 | "不自然"种类——冗余/隐藏乘积/虚假自由度/隐藏直和 | 形状描述的结构化字段 |
| 伏羲·225号 | 数学处境S的字段——对象/关系/当前表示 | 形状描述的补充字段 |

### 4.3 形状描述的结构化字段schema

```
shape_description = {
    // 燧人·安全第一步的字段
    conclusion_type: enum,        // 结论类型：存在性/唯一性/极值/渐近精细下界/构造/证明/数值计算
    condition_type: enum,         // 条件类型：等式组/不等式/递推/函数关系/图结构
    distance: enum,               // 条件到结论的"距离"：直接/中等/远/极远
    directions: list[string],     // 想到的方向（自由列举）
    associations: list[string],   // 联想到的定理/方法/类似题（自由列举）

    // 伏羲·"不自然"种类的字段
    unnatural_types: list[enum],  // 不自然种类：冗余/隐藏乘积/虚假自由度/隐藏直和/无
    unnatural_description: string,// 不自然的具体描述

    // 伏羲·数学处境S的补充字段
    key_objects: list[string],    // 关键数学对象（如：多项式q(x)/根r,s/偏差e_i）
    key_relations: list[string],  // 关键关系（如：三个矩条件/稳定性方程）
    current_representation: string, // 当前表示方式
}
```

### 4.4 实验设计

**步骤1：形状描述prompt设计**

设计一个让AI描述形状的prompt（不解题），基于燧人的安全第一步：

```
请读取以下数学题。不要解题。描述这道题的结构形状：
1. 结论是什么类型？（存在性/唯一性/极值/渐近精细下界/构造/证明/数值计算）
2. 条件是什么类型？（等式组/不等式/递推/函数关系/图结构）
3. 条件和结论之间的"距离"有多远？（直接/中等/远/极远）
4. 你想到的所有可能方向（不要求正确，自由列举）
5. 你联想到的定理/方法/类似题（自由列举）
6. 这道题中有什么"不自然"的结构？（冗余/隐藏乘积/虚假自由度/隐藏直和/无）
7. 关键数学对象和关系是什么？
```

**步骤2：对5道题产出形状描述**

用devin CLI或API调用GLM-5.2，对T1-T5每道题产出形状描述。
- 每道题描述3次（测试可复现性）
- 记录每次描述的完整输出

**步骤3：可区分性检查**

对5道题的形状描述，检查：
- 任意两道题的形状描述是否至少有2个字段值不同
- 特别关注：T1（渐近精细下界）vs T2（IMO证明）vs T3（AIME数值）vs T4（USAMO证明）vs T5（HMMT数值）

**步骤4：可复现性检查**

对同一道题的3次描述，检查：
- conclusion_type是否3次一致
- condition_type是否3次一致
- distance是否至少2次一致
- unnatural_types是否至少2次一致

### 4.5 pass/fail标准

| 标准 | 阈值 | 权重 |
|---|---|---|
| AI对5道题都能产出结构化形状描述（不卡住） | 5/5 | 必须 |
| 任意两道题的形状描述至少2个字段不同 | 10/10对 | 必须 |
| 同一题目描述3次，conclusion_type至少2次一致 | 5/5题 | 必须 |
| 同一题目描述3次，condition_type至少2次一致 | 5/5题 | 必须 |
| 同一题目描述3次，unnatural_types至少2次一致 | 4/5题（允许1题不稳定） | 加分 |

**pass条件**：所有"必须"标准通过。
**fail条件**：任何"必须"标准未通过。
**partial**：所有"必须"通过但"加分"未通过——可以继续后续POC，但需记录不稳定性。

### 4.6 产出

1. **形状描述的结构化字段schema**（本POC§4.3的schema，根据实验结果调整）
2. **5道题×3次=15份形状描述数据**（JSON格式，存入ArangoDB）
3. **可区分性矩阵**（5×5，每对题目的不同字段数）
4. **可复现性矩阵**（5×3，每道题3次描述的字段一致性）
5. **实验报告**（pass/fail判定 + 不稳定字段分析）

- [ ] 对T1-T5每道题产出3次形状描述

## 5. POC-2：状态表示的形式化与可重建性

## 7. POC-4：路径结构匹配（精化）+DFS搜索

### 7.1 验证目标

| 盘古·78号 | AQL集合差集（路径匹配的确定性验证） | 精化结果的验证 |

| 女娲·122-v2 | 启发激活图H（P→X条件关系） | Pattern的触发条件匹配 |

### 7.3 路径结构匹配算法

**核心思路**：把当前状态和候选Pattern的触发条件都表示为图结构，在ArangoDB中用图查询找连通路径。

```
输入：当前状态S_current + 粗筛结果Pattern列表
输出：精化后的Pattern列表（按匹配度排序）

步骤1：构建状态图
- 从S_current的V_t/F_t/O_t/R_t中提取节点
- 节点间的边 = 状态转移关系（已验证→猜想→开放义务）

步骤2：对每个候选Pattern，构建触发条件图
- 从Pattern的trigger_condition中提取节点
- 节点间的边 = 触发条件中的结构关系

步骤3：路径结构匹配
- 在ArangoDB中，用AQL图查询找状态图和触发条件图之间的连通路径
- 匹配度 = 连通路径的长度和结构相似性
  - 路径长度越短，匹配度越高
  - 结构相似性 = 节点类型匹配数 / 总节点数

步骤4：DFS搜索
- 候选Pattern按Level降序排列
- 从最高Level的Pattern开始，模拟发送Q
- 如果"走不通"（匹配度低于阈值），回溯到下一个Pattern
- 回溯铁律：不在同一Session中回溯，记录回溯点
- DFS步数上限：10步
```

### 7.4 前置条件

- POC-3通过（Pattern存储已建立，粗筛结果可用）

### 7.5 实验设计

**步骤1：构建状态图和触发条件图**

对5道题的50个QA节点：
- 每个节点的状态图从POC-2的状态数据中构建
- 每个候选Pattern的触发条件图从POC-3的Pattern存储中构建
- 图数据存入ArangoDB

**步骤2：路径结构匹配**

对每个QA节点：
1. 取POC-3的粗筛结果作为候选Pattern列表
2. 对每个候选Pattern，用AQL图查询找连通路径
3. 计算匹配度（路径长度+结构相似性）
4. 按匹配度排序

**步骤3：DFS搜索模拟**

对每个QA节点：
1. 候选Pattern按Level降序排列
2. 模拟DFS：从最高Level开始，检查匹配度是否≥阈值
3. 如果匹配度<阈值，回溯到下一个Pattern
4. 记录DFS步数和最终选中的Pattern

**步骤4：精度评估**

对每个QA节点，已知"正确Pattern"：
- **precision@1** = top-1是否是正确Pattern
- **precision@5** = 正确Pattern是否在top-5中
- **DFS步数** = 找到正确Pattern用了几步
- **回溯次数** = DFS过程中回溯了几次

### 7.6 pass/fail标准

| 标准 | 阈值 | 权重 |
|---|---|---|
| precision@5=100%（正确Pattern在top-5中） | 45/50节点 | 必须 |
| precision@1≥60%（top-1是正确Pattern） | 30/50节点 | 必须 |
| DFS步数≤10 | 50/50节点 | 必须 |
| 回溯次数≤3 | 45/50节点 | 加分 |
| 精化时间≤5秒/节点 | 50/50节点 | 加分 |

**pass条件**：所有"必须"标准通过。
**fail条件**：precision@5<90%或DFS步数>10。
**partial**：precision@5≥90%但precision@1<60%——精化不够精确，需调整匹配度计算。

|---|---|---|
| H0 | 元检查——"你检查一下你的推导是否完整" | 无泄漏 |
| H1 | 思维操作——"试试把每个点分解成最近的关键点加偏差" | 无泄漏（只给操作方向） |
| H2 | 工具概念候选——"考虑用badly approximable性质" | 低泄漏（给了概念但没给具体内容） |
| H3 | 确定关系——"p=(5-√5)/10是badly approximable，|p-k/n|≥c₀/n²" | 高泄漏（给了具体数学事实） |
| H4 | 最终答案——"δ≥c/n^(3/2)" | 完全泄漏 |

**目标**：提取的Pattern应≤H2。H3和H4表示泄漏。

### 8.4 四门泄漏审计

| 门 | 检查内容 | 方法 |
|---|---|---|
| 门1·字面匹配 | Pattern的Q内容是否包含答案的字面文本 | 字符串匹配 |
| 门2·等价映射 | Pattern的Q内容是否包含答案的等价表述 | AI判断（Q内容是否数学等价于答案） |
| 门3·候选空间缩减 | Pattern是否大幅缩减了答案的候选空间 | 对比"有Pattern"vs"无Pattern"时AI的候选空间大小 |
| 门4·盲审者恢复 | 盲审者（不知道答案的AI）能否从Pattern恢复答案 | AI尝试从Pattern推导答案 |

### 8.5 前置条件

- POC-4通过（精化结果可用，每个节点有top-5候选Pattern）

### 8.6 实验设计

**步骤1：Hint梯度标注**

对POC-4的精化结果（50个节点×top-5=250个Pattern），标注Hint级别：
- AI读取Pattern的Q内容，标注H0-H4
- 标注prompt：```
阅读以下提示Q。判断这个提示的泄漏级别：
H0：元检查（只提醒检查，不给任何方向）
H1：思维操作（给操作方向，不给具体概念）
H2：工具概念候选（给概念名称，不给具体内容）
H3：确定关系（给具体数学事实/公式）
H4：最终答案（直接给答案）
```

**步骤2：四门泄漏审计**

对每个Pattern执行四门审计：
- 门1（字面匹配）：用Python字符串匹配检查Q内容是否包含答案
- 门2（等价映射）：用AI判断Q内容是否数学等价于答案
- 门3（候选空间缩减）：对比"有Q"vs"无Q"时AI的候选空间
- 门4（盲审者恢复）：让不知道答案的AI尝试从Q推导答案

**步骤3：最小知识传递验证**

对每个QA节点，从top-5候选Pattern中选择满足以下条件的Pattern：
1. Hint级别≤H2
2. 四门审计全通过
3. 在满足1和2的Pattern中，选Level SUM最大的

验证：这个选择是否与QA序列中实际发送的Q一致。

**步骤4：诚实不可知论实验**

对T1的Q9（知识瓶颈，Hint=H3）做特殊分析：
- Q9是"badly approximable"知识注入，Hint=H3
- 验证：如果强制Hint≤H2，AI能否完成Q9对应的步骤？
- 如果不能→确认Q9是真实知识瓶颈，Hint≤H2不可行
- 如果能→Q9不是真实知识瓶颈，可以降级到H2

### 8.7 pass/fail标准

**pass条件**：所有"必须"标准通过。
**fail条件**：非知识瓶颈Pattern的Hint>H2（泄漏）或四门审计未通过。
**partial**：Hint≤H2但最小知识传递选择与实际Q不一致——选择策略需调整。

## 9. POC-6：不知道答案的AI能否识别需要的Pattern

### 9.1 验证目标

验证伏羲的核心命题——边界以外感知不需要边界以内知识。即：不知道答案的AI能否识别出需要的Pattern类型，且与知道答案的AI一致。

这是知识悖论的**核心验证POC**——如果这个命题不成立，整个检索方案的认识论基础就崩塌了。

### 9.2 整合机制

| 来源 | 设计 | 在本POC中的角色 |
|---|---|---|
| 伏羲·222号 | 形式化边界——识别Q是边界以外感知，提出Q是感知+框架 | 核心命题 |
| 伏羲·233号 | 形式化边界移动机制——AI是边界以外侦察兵 | 认识论基础 |
| 伏羲·236号 | 非特定性=边界推进能力 | 非特定性的操作性定义 |
| 女娲·127号 | 8角色可见性矩阵——Truth Vault隔离 | 工程隔离 |
| 女娲·127号 | CapabilityToken——角色能力控制 | 角色隔离 |
| 女娲·200号 | 诚实不可知论——实验测量引导vs作弊 | 实验方法 |
| 燧人·214号第8.6节 | 引导者四种元认知能力——广度/品味/诊断/剪枝 | 引导者能力定义 |
| 燧人·214号第1章 | 路线B——思维模式不依赖具体知识 | 非特定性引导 |
| 盘古·86号 | meta/normal分离——拓扑vs语义 | 计算分工 |

### 9.3 实验设计

**步骤1：准备两个AI实例**

- **AI-A（知道答案）**：能访问truth_vault（包含完整QA序列和正确解答路径）
- **AI-B（不知道答案）**：不能访问truth_vault，只能看到当前状态和候选Pattern列表
  - AI-B的CapabilityToken设置：可读Workspace/Event/HeuristicRule，不可读truth_vault

**步骤2：Pattern类型识别**

对5道题的50个QA节点：
1. 给AI-A和AI-B相同的当前状态（POC-2的状态数据）
2. 给AI-A和AI-B相同的候选Pattern列表（POC-4的top-5精化结果）
3. 让AI-A和AI-B分别识别"此刻最需要哪个Pattern类型"
4. AI-A的prompt：```
你知道这道题的完整解答路径。以下是当前状态和候选Pattern列表。
请判断此刻最需要哪个Pattern（选择top-1）。
```
5. AI-B的prompt：```
你不知道这道题的答案。以下是当前状态和候选Pattern列表。
请判断此刻最需要哪个Pattern类型（选择top-1）。
你不需要理解Pattern的数学内容，只需要做形式匹配——
当前状态的形状和Pattern的触发条件的形状是否匹配。
```

**步骤3：一致性比较**

对每个QA节点，比较AI-A和AI-B的选择：
- **一致**：AI-A和AI-B选择了相同的Pattern
- **不一致**：AI-A和AI-B选择了不同的Pattern
- 计算一致率

**步骤4：泄漏审计**

对AI-B的选择结果，执行POC-5的四门泄漏审计：
- 验证AI-B的选择不依赖答案知识（通过泄漏审计）

**步骤5：引导者四种元认知能力评估**

对AI-B的表现，评估燧人定义的四种元认知能力：
- **广度**（生成候选Q）：AI-B能否从候选列表中识别出多个相关Pattern？
- **品味**（评估Level）：AI-B能否正确评估Pattern的Level值？
- **诊断**（判断A的状态）：AI-B能否正确识别做题AI的卡点类型？
- **剪枝**（回溯决策）：AI-B能否正确判断哪些Pattern不适用？

### 9.4 pass/fail标准

| 标准 | 阈值 | 权重 |
|---|---|---|
| AI-B与AI-A的选择一致率≥70% | 35/50节点 | 必须 |
| AI-B的选择通过泄漏审计 | 45/50节点 | 必须 |
| AI-B的"诊断"能力正确率≥80% | 40/50节点 | 必须 |
| AI-B的"品味"能力（Level评估）与AI-A相关系数≥0.6 | 5/5题 | 加分 |
| AI-B的"广度"能力（识别≥3个相关Pattern） | 40/50节点 | 加分 |

**pass条件**：所有"必须"标准通过。
**fail条件**：AI-B与AI-A一致率<70%（不知道答案的AI无法识别需要的Pattern）或泄漏审计未通过。
**partial**：一致率≥70%但"诊断"能力<80%——AI-B能识别Pattern但不能正确诊断状态。

### 9.5 产出

1. **AI-A和AI-B的选择对比数据**（50个节点的一致性）
2. **AI-B的泄漏审计结果**
3. **引导者四种元认知能力评估报告**
4. **Truth Vault隔离验证结果**
5. **POC-6实验报告**

## 10. POC-7：完整检索流程端到端

### 10.1 验证目标

POC-1到POC-6的所有成果。

### 10.3 完整检索流程

```
输入：工作智能体的当前推理输出 + 累积context + 题目本身

  ├─ 1a. 形状描述：用POC-1的prompt让AI产出形状描述
  ├─ 1b. 状态提取：用POC-2的prompt让AI提取W_t/S状态

第2步：Pattern提取（POC-3 + POC-4）
  ├─ 2a. 粗筛：用POC-3的三层索引缩小搜索空间到≤20%
  ├─ 2b. 精化：用POC-4的路径结构匹配+DFS搜索定位到top-5
  └─ 2c. 排序：按匹配度排序

第3步：知识悖论解决（POC-5 + POC-6）
  ├─ 3a. 泄漏审计：用POC-5的四门审计+Hint梯度过滤泄漏Pattern
  ├─ 3b. 最小知识传递：在通过审计的Pattern中选Level SUM最大的
  └─ 3c. 知识悖论验证：用POC-6的方法验证不知道答案的AI能识别

输出：选中的Pattern（Q内容 + Level + Hint级别）
