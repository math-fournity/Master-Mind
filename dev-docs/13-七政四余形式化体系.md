# 七政四余形式化体系

**目的**：从元数学角度建立七政四余的代数结构，使算子、命题、规则库具有形式化定义。

**核心洞察**：《星平会海》《星学大成》《果老星宗》中的所有命理规则，本质上是**命题型**——"X，则Y"。X 的结构是"a躔b"（或"a照b"、"a会b"），其中"躔"是一个算子（算符）。

---

## 零、形式化是一个开放过程

**这不是一个封闭的系统定义，而是一个持续的发现过程。**

我们不预设"七政四余的形式系统应该长什么样"，而是让古籍文本告诉我们它长什么样。当前文档中列出的 6 个算子（躔/照/会/守/冲/合）和 5 个集合（Star/Mansion/Palace/Dignity/Element），是**已识别的部分**，不是全部。

随着研究的推进：
- **新的算子会被发现**：古籍中还有"拱"/"夹"/"刑"/"穿"/"害"/"破"/"值"/"向"/"背"等关系词，它们可能构成新的算子。
- **新的集合会被定义**：神煞是一个开放集合，不同文献有不同的神煞体系。流年神煞、月建神煞、时支神煞——这些子集需要分别形式化。
- **新的命题结构会被揭示**：复合命题的逻辑连接词（∧∨¬→↔）可能不够用，需要引入时态算子（如"当...时"）、模态算子（如"可能"/"必然"）等。
- **集合的边界会扩展**：比如"星曜"这个集合，在某些文献中包含"文昌"/"天魁"/"天钺"等辅助星，这些是否应该加入 Star 集合，需要根据实际用法决定。

**为什么必须保持开放**：

1. **古籍是证据来源**：形式化的合法性来自古籍的支持，不是来自逻辑的自洽。如果古籍中出现了我们现有算子无法描述的规则，说明我们需要新的算子，而不是强行把规则塞进现有框架。
2. **跨体系研究的需要**：七政四余、八字、紫微斗数、铁板神数——每个体系都有自己的算子和命题结构。形式化的目标是建立一个**足够灵活的框架**，能容纳不同体系的形式化产物，而不是用一个体系的形式化去统一其他体系。
3. **大数据验证的需要**：当命例达到数万条时，统计分析会发现我们现有算子无法解释的模式。这些模式可能指向新的算子或新的命题结构。
4. **AI 推理的需要**：AI 要做命理判读，需要一个**可扩展的推理框架**。如果框架是封闭的，AI 就只能在预设的规则内推理；如果框架是开放的，AI 就能根据新发现的规则进行新的推理。

**形式化的工作方式**：

- **记录已知的，标注未知的**：当前文档中，已识别的算子和集合用正式定义，尚未确认但有候选的（如"拱"/"夹"）用"待发现"标注。
- **新发现必须可追溯**：每条新增的算子或命题，必须能追溯到具体的古籍出处和原文证据。
- **旧定义可以被修正**：如果后续研究发现某个算子的定义不准确（如 A2 审计发现紫炁的计算方式），必须修正定义，而不是维护一个"历史正确"的旧版本。
- **形式化边界是动态的**：随着研究推进，形式化体系的边界会不断扩展。今天的"完整"版本，明天可能只是"部分"版本。

## 一、集合定义（基本对象）

### 1.1 星曜集 Star

```
Star = {日, 月, 木, 火, 土, 金, 水, 罗, 计, 气, 孛}
```

- 11 个元素
- 子集划分：
  - **七政**：{日, 月, 木, 火, 土, 金, 水}（7 个）
  - **四余**：{罗, 计, 气, 孛}（4 个）
- 四余另有计算属性：
  - 罗睺 = 交点（北交点）
  - 计都 = 交点（南交点，罗睺对冲）
  - 紫炁 = 28年匀速线性运动
  - 月孛 = 交点（远地点，MEAN_APOG）

### 1.2 宿集 Mansion

```
Mansion = {角, 亢, 氐, 房, 心, 尾, 箕, 斗, 牛, 女, 虚, 危, 室, 壁, 奎, 娄, 胃, 昴, 毕, 觜, 参, 井, 鬼, 柳, 星, 张, 翼, 轸}
```

- 28 个元素（二十八宿）
- 每个宿有宿度（占据黄道的度数范围）
- 每个宿有五行属性
- 四象分组：苍龙（角-箕）、玄武（斗-壁）、白虎（奎-参）、朱雀（井-轸）

### 1.3 宫集 Palace

```
Palace = {命, 财帛, 兄弟, 田宅, 男女, 奴仆, 妻妾, 疾厄, 迁移, 官禄, 福德, 相貌}
```

- 12 个元素（十二宫）
- 每个宫有宫主（守护星）
- 顺序固定（从命宫逆时针排列）

### 1.4 庙旺状态集 Dignity

```
Dignity = {殿, 垣, 庙, 旺, 乐, 喜, 怒}
```

- 7 个元素
- 从强到弱：殿 > 垣 > 庙 > 旺 > 乐 > 喜 > 怒
- 每颗星在每个宫位有不同的庙旺状态

### 1.5 五行集 Element

```
Element = {金, 木, 水, 火, 土}
```

- 5 个元素
- 生克关系：木生火、火生土、土生金、金生水、水生木；木克土、土克水、水克火、火克金、金克木

### 1.6 名称集 Name

```
Name = {天贵, 天娼, 天寿, 天清, 天成, 天休, 天垒, 天模, 天冲, ...}
```

- 开放集（每条规则可定义新名称）
- 名称携带吉凶含义（天贵=吉，天娼=凶，...）

## 二、算子定义（基本运算）

### 2.1 躔算子（occupy）

```
躔: Star × Mansion → State
```

**输入**：一颗星 s ∈ Star，一个宿 m ∈ Mansion
**输出**：一个状态 s ∈ State

**自然语言**：s 缠 m 宿

**例子**：躔(木, 角) → 木缠角宿

**出现文献**：《星平会海》卷一"星曜躔度歌"，308 条规则（11星 × 28宿）

### 2.2 照算子（illuminate）

```
照: Star × Palace → State
```

**输入**：一颗星 s ∈ Star，一个宫 p ∈ Palace
**输出**：一个状态 s ∈ State

**自然语言**：s 照 p 宫

**例子**：照(木, 命) → 木照命宫

**出现文献**：《星平会海》卷一"星曜照宫歌"，132 条规则（11星 × 12宫）

### 2.3 会算子（conjoin）

```
会: Star × Star → State
```

**输入**：两颗星 s1, s2 ∈ Star
**输出**：一个状态 s ∈ State

**自然语言**：s1 会 s2

**例子**：会(木, 火) → 木星会火

**出现文献**：《星平会海》卷一"星曜交会歌"，约 60 条规则

### 2.4 守算子（guard）

```
守: Star × Palace → State
```

**输入**：一颗星 s ∈ Star，一个宫 p ∈ Palace
**输出**：一个状态 s ∈ State

**自然语言**：s 守 p 宫

**例子**：守(木, 命) → 木守命宫

**出现文献**：《星平会海》卷一"主星守宫歌"

### 2.5 冲算子（oppose）

```
冲: Star × Star → State
冲: Palace × Palace → State
```

**输入**：两颗星（或两个宫），形成 180° 对冲
**输出**：一个状态

**自然语言**：s1 冲 s2

**出现文献**：《星平会海》卷一"吊冲秘诀"

### 2.6 合算子（combine）

```
合: Star × Star → State
合: Palace × Palace → State
```

**输入**：两颗星（或两个宫），形成 60° 三合
**输出**：一个状态

**自然语言**：s1 合 s2

**出现文献**：《星平会海》卷一"五星变局"

## 三、状态结构（State）

每条算子的输出不是一个简单的值，而是一个**复合状态**：

```typescript
interface State {
  name: string;        // 名称，如"天贵"、"天娼"
  element: Element;    // 五行属性
  dignity: Dignity;    // 庙旺状态
  judgment: 吉凶;      // 吉凶判断
  description: string; // 详细描述
}
```

**关键**：同一个算子输入（如躔(木, 角)）在不同文献中可能有不同的状态描述。这不是矛盾，而是**不同学派的视角差异**。

## 四、命题结构

### 4.1 基本命题

每条命理规则是一个**命题**：

```
算子(输入) → 状态
```

或者用自然语言：

```
X = a 躔 b ⊢ Y = f(X)
```

其中：
- X 是算子应用的结果（条件）
- Y 是结论（推断）
- ⊢ 表示"蕴含"或"推出"

### 4.2 命题类型

| 类型 | 结构 | 例子 |
|---|---|---|
| **躔度命题** | 躔(星, 宿) → 状态 | 躔(木, 角) → 天贵 |
| **照宫命题** | 照(星, 宫) → 状态 | 照(木, 命) → 聪敏 |
| **交会命题** | 会(星, 星) → 状态 | 会(木, 火) → 通明 |
| **守宫命题** | 守(星, 宫) → 状态 | 守(木, 命) → 贵 |
| **冲照命题** | 冲(星, 星) → 状态 | 冲(火, 金) → 凶 |
| **组合命题** | ∧(命题1, 命题2) → 结论 | ∧(躔(木,角), 照(日,命)) → 贵 |

### 4.3 命题的复合

复杂命理判断是多个基本命题的**逻辑组合**：

```
∧(躔(木, 角), 会(木, 水), 照(日, 命)) → 大贵
∨(冲(火, 金), 冲(土, 水)) → 凶
¬(躔(罗, 角)) → 解凶
```

现有规则库中的每条规则，可以用形式化语言重写：

**原始格式**（rules_library.json）：
```json
{
  "id": "R001",
  "name": "日月并明",
  "condition": "@日庙旺 & @月庙旺 & @日月会",
  "judgment": "+"
}
```

**形式化格式**：
```
R001: ∧(庙旺(日), 庙旺(月), 会(日, 月)) → 大贵
```

### 5.2 eval_rules()

现有求值器的逻辑：

```
eval_rules(chart) → matched_rules
```

对应形式化系统中的**推导**：

```
Γ ⊢ ∧(命题1, 命题2, ..., 命题n) → 结论
```

其中 Γ 是当前星盘的所有事实（躔度、照宫、交会等）。

## 七、提取工作流

基于此形式化体系，从古籍提取规则的工作流：

### Step 1: 识别算子

从文本中识别算子关键词：
- "躔"/"缠" → 躔算子
- "照" → 照算子
- "会"/"郊会" → 会算子
- "守" → 守算子
- "冲" → 冲算子
- "合" → 合算子

### Step 2: 提取参数

从算子应用中提取参数：
- 星曜名称（木/火/土/金/水/日/月/气/孛/罗/计）
- 宿名（角/亢/氐/房/...）或宫名（命/财帛/兄弟/...）

### Step 3: 构建命题

将文本转换为命题形式：

```
"木缠角宿号天贵，诗礼传家居职位"
→ 躔(木, 角) → {name: "天贵", judgment: "贵", description: "诗礼传家居职位"}
```

### Step 4: 验证一致性

检查新提取的命题是否与已有规则库一致：
- 是否有矛盾？
- 是否有重复？
- 是否需要归并？

## 九、与元数学的关系

本形式化体系对应数学基础中的以下概念：

| 元数学概念 | 七政四余对应 |
|---|---|
| **形式语言** | 星曜/宿/宫/算子/命题的语法 |
| **公理** | 基本命题（躔度/照宫/交会的原始规则） |
| **推理规则** | ∧∨¬ 逻辑组合 |
| **定理** | 推导出的复合命题（如"日月并明"） |
| **模型** | 具体的星盘实例 |
| **语义** | 命理判断（吉凶/贵贱/贫富） |

**关键问题**：
- **一致性**：规则库是否自相矛盾？
- **完备性**：是否能推导出所有传统文献中的结论？
- **可判定性**：给定一个星盘，是否能算法化地判定所有命题？

这些问题目前没有严格证明，但形式化体系为未来研究提供了框架。

## 十、形式化的灵魂：解释框架

形式系统本身只是语法，没有灵魂。一个只有算子、命题、规则库的形式系统，就像一本只有语法规则没有语义的字典——它能告诉你"这个句子合不合语法"，但不能告诉你"这个句子是什么意思"。形式系统的灵魂来自**解释框架**：它把形式表达映射到经验现象上，让"躔(木,角)→天贵"不只是一个可求值的命题，而是一个**有意义的判断**。

### 三种可能的解释立场

| 立场 | 说什么 | 优点 | 缺点 |
|---|---|---|---|
| **因果论**（物理主义） | 星曜有磁场/引力/辐射，直接影响人体 | 最符合现代科学直觉 | 无实证；无法解释为什么火星距地球最近时仍是"凶星" |
| **相关论**（统计主义） | 星曜位置与人生事件统计相关，但非因果 | 能做大数据验证 | 只能描述"是什么"，不能解释"为什么" |
| **符号论**（语义主义） | 星曜是符号，表意不致因；天人同构，同一模式在不同层面显现 | 能解释"为什么"；与传统典籍一致 | 难以证伪 |
| **全息论**（同构主义） | 宇宙与人生是全息对应的——星象是"宇宙-人生剧本"的索引，周易卦象是另一个索引，同一套底层模式在不同维度上展开 | 能解释跨体系的一致性；与"天人感应"传统完全吻合 | 目前缺乏形式化定义 |

### 本项目的立场：全息论为主，因果论为辅

- **全息论（主）**：星曜是"宇宙-人生剧本"的全息索引。即便我们找不到物理层面的"场"或"作用力"，星象与人生之间仍然存在同构关系——宇宙的模式在人生中重现，人生是宇宙的微缩。这与周易占卜的卦象有相似性：卦象是另一套索引系统，指向同一套底层模式。躔(木,角)→天贵，意思是"当木星落在角宿时，这个宇宙配置与'贵'这个人生模式全息对应"。传统典籍说"天人感应"、"天人合一"，正是这个意思。周易说"仰则观象于天，俯则观法于地"，也是这个意思。
- **符号论**：作为全息论的补充——当全息对应关系暂时无法形式化时，先用符号-语义的方式描述。
- **因果论（辅）**：物理层面的关联可以作为辅助解释。比如月球引力对潮汐的影响——但这是物理层面的因果，不是命理层面的因果。

### 为什么这个立场重要

1. **避免伪科学陷阱**：如果坚持因果论，就必须证明"木星磁场如何导致人富贵"——这在目前是不可能的。全息论绕开了这个陷阱。
2. **与传统典籍一致**：《果老星宗》说"天地虽大，万物虽多，要之一理"——强调的是"理"（pattern/meaning），不是"力"（force/energy）。
3. **解释跨体系一致性**：七政四余、八字、紫微斗数、周易占卜——这些体系的底层模式相同，只是索引方式不同。全息论能解释为什么不同体系的判读常常指向相似的结论。
4. **保留扩展空间**：未来如果发现了物理层面的因果机制，全息论不排斥它——它只是说，在没有因果证据时，先用全息同构解释，不强行声称因果。
5. **形式化不受阻塞**：不管采用哪种解释立场，形式化工作（提取规则、构建命题、验证一致性）都可以正常进行。解释框架是形式化的"灵魂"，但不是形式化的"前提"。

### 形式系统的三层结构

```
┌─────────────────────────────────────────┐
│  Layer 3: 解释框架（灵魂）                │
│  "躔(木,角)→天贵" 意味着什么？             │
│  全息论 / 符号论 / 因果论 / 相关论          │
├─────────────────────────────────────────┤
│  Layer 2: 形式系统（骨架）                │
│  集合 + 算子 + 命题 + 推理规则             │
│  "躔(木,角)→天贵" 是一个可求值的命题        │
├─────────────────────────────────────────┤
│  Layer 1: 经验现象（血肉）                │
│  古籍中的命理规则、历史命例、人生经验         │
│  "木缠角宿号天贵，诗礼传家居职位"           │
└─────────────────────────────────────────┘
```

形式化的工作是**构建 Layer 2**（骨架）。解释框架是**赋予 Layer 3**（灵魂）。但 Layer 1（经验现象）是根基——如果形式系统不能描述经验现象，或者解释框架不能回应经验现象，那么整个结构就是空转。

## 十一、系统演化：经验包的迭代吸收

我们以形式化框架来系统化吸收现有星学文献，这个过程不是简单的"文本整理成数据库"，而是**系统的自我迭代**。

### 迭代结构

```
S-0 → [T-0] → S-1 → [T-1] → S-2 → [T-2] → S-3 → ...
       ↑           ↑           ↑
     经验包0      经验包1      经验包2
```

- **S-0**：初始系统（七政四余的基本算子和集合）
- **T-0**：第一批经验包（如《星平会海》卷一的星曜躔度歌 308 条规则）
- **S-1**：吸收 T-0 后的新系统（算子更精确，集合更完备，规则库更丰富）
- **T-1**：第二批经验包（如《星学大成》的格局规则、《果老星宗》的限运理论）
- **S-2**：吸收 T-1 后的更深系统
- ……

### 关键原则：不是吸收，是深化

不应该直接把 T-1 塞进 S-1（那是数据库录入），而是在 S-1 的视角下审视 T-1，问：
1. T-1 中有哪些 S-1 无法描述的规则？→ 这意味着 S-1 需要新的算子或集合
2. T-1 中有哪些规则与 S-1 矛盾？→ 这意味着 S-1 需要修正
3. T-1 中有哪些规则能统一 S-1 中零散的规则？→ 这意味着 S-1 需要更高层的抽象

### 深化出来什么？——定性+定量的认知

随着 T-0、T-1、T-2……被持续吸收，系统持续发现和定义新的概念。但从一开始就清楚：我们要构建的是**定性+定量**的认知。

- **定性**：星曜配置的格局、喜忌、方向（七政四余的强项）
- **定量**：能量的度量值（铁板神数的强项）

定量化的难点在于：很多概念（如"福气"、"贵气"）没有现成的度量单位。可能需要：
- 多参数化：一个"福气"由多个星曜参数共同决定
- 代数方程：星曜间的几何关系（光学关系）越紧密，能量越强
- 能量单位：建立自己的度量体系，类似铁板神数的数序

### 可能用到的数学工具

| 工具 | 命理应用 | 说明 |
|---|---|---|
| **向量点积** | 能量在特定方向的投影 | 星曜可视为方向向量，点积衡量其在命格方向上的分量 |
| **平行四边形法则** | 能量向量的合成 | 两颗星曜同时作用时，用牛顿的向量合成法获得合力的大小和方向 |
| **RGB 混色模型** | 能量的混合效果 | 如同三原色混合产生万千色彩，不同星曜能量混合产生复合效应（木火通明、金白水清等） |
| **频率/谐波** | 周期性共振 | 行星周期之间的谐波关系可能产生能量共振或相消 |
| **多维空间** | 多参数联合建模 | 当参数超过3个时，需要在高维空间中定义能量的度量和距离 |

这些数学工具不是强行套用，而是从命理问题本身出发：当我们说"木火通明"时，"通明"的强度如何度量？当我们说"众星拱北"时，"拱"的紧密程度如何量化？数学工具是回答这些问题的手段。

**数学工具的选择也是开放的**。我们不是在众多工具中"选择一个"，而是**同时持有多个工具**，在行进过程中不断对比考量。甚至最终都不是非此即彼的，而是**各有适用的场景**：向量点积适合度量方向性能量，RGB 混色适合描述能量混合的质变，频率谐波适合分析周期性共振。具体问题用具体工具，不预设哪一种"最好"。

### 根本问题

我们对星学到底能理解和把握到多么深刻的程度？这个问题没有预设答案——答案在 T-0、T-1、T-2……被持续吸收的过程中逐渐浮现。每一次吸收经验包，都可能发现我们之前想不到的概念、关系、规律。

这是本项目的研究态度：**不预设终点，但追求深度。** 形式化框架是脚手架，经验包是砖石，二者交替推进，系统才会长大。
