## 1. 实验目标

### 1.1 核心问题

通过tmux中的devin cli交互式session，验证：**连续的启发式提问是否可以通过"最小知识传递"引导AI做出竞赛级数学题？**

### 1.2 什么叫"最小知识传递"

全程所有发送给AI的提示，每个提示都有一个Level值（0到1，见214号第2章）。"最小知识传递"= **所有提示的Level之和最大化**——意味着每个提示都尽可能用高Level（纯思维模式），避免低Level（具体知识）。

- 理想情况：全程只给Level→1的思维模式提示（"试试反证法"、"找到不变量了吗"），不给任何Level→0的具体知识（"用q(x)=x²+x-1"、"用badly approximable"）
- 退化情况：如果纯思维模式提示不够，适时降低Level走向知识端，但要记录每次降Level的决策和原因

### 1.3 成功标准

| 标准 | 说明 |
|---|---|
| 最优 | 全程纯思维模式提示（Level SUM最大化），AI独立完成第(1)问证明 |
| 良好 | 需要少量知识提示（1-2次降Level），但大部分步骤由思维模式提示引导 |
| 可接受 | 需要多次知识提示，但记录了每次降Level的原因，为系统改进提供数据 |
| 失败 | AI完全无法推进，即使给了知识提示也做不出来 |

## 2. 实验对象

### 2.1 题目

矩条件极差题第(1)问：

> 已知 $a_1, a_2, \ldots, a_n$ 为实数，且 $\sum a_i = n$，$\sum a_i^2 = 2n$，$\sum a_i^3 = 3n$。求最大的常数 $C$，使得对所有 $n \ge 4$，$\max a_i - \min a_i \ge C$。

答案：$C = \sqrt{5}$。

### 2.2 为什么选这道题

1. 214号第4章已经对这道题做了完整的思维模式拆解，有10个极致提示作为参考
2. 第(1)问的解答中，步骤1-6全部可以被思维模式提示引导，只有步骤9是纯知识瓶颈——而步骤9属于第(2)问，不在本次实验范围
3. 这道题是项目的POC实验场核心题目，有完整的原始解答文档可对照

### 2.3 不做第(2)问的原因

第(2)问的最后一步需要badly approximable的数论知识（Level→0），这是214号第4章已经确认的知识瓶颈。本次实验的目的是验证"最小知识传递"的可行性，应该先在第(1)问上验证——如果第(1)问能纯靠思维模式提示做出来，就证明了路线B的可行性。

## 3. 实验设计

### 3.1 交互方式

在tmux中启动一个**交互式**devin cli session（不是`-p`一次性模式），通过tmux send-keys向session发送消息，通过tmux capture-pane观察AI的回复。

```bash
# 启动交互式session
tmux new-session -d -s guided-exp-1 "cd /data/math-agent-glm5.2-1 && devin --model glm-5-2"
# 发送消息
tmux send-keys -t guided-exp-1 "消息内容" Enter
# 观察回复
tmux capture-pane -t guided-exp-1 -p
```

### 3.2 题目传递

题目写入work_dir下的problem.txt（遵守214号第5章和session隔离铁律），第一条消息让AI读文件。

### 3.3 交互协议

遵循214号第6章的六层渐进发问框架：

| 层 | 性质 | 发什么 | 何时进入下一层 |
|---|---|---|---|
| L1 观察 | 必然安全 | "读problem.txt，不要解题，描述题目的结构形状" | AI给出形状描述后 |
| L2 联想 | 几乎安全 | "这些条件让你想到什么方向？列出所有方向" | AI列出方向后 |
| L3 描述方向 | 仍然安全 | "对每个方向，第一步会做什么？只描述不做" | AI描述完方向后 |
| L4 小尝试 | 可控风险 | "选最有希望的方向，试着做第一步" | AI尝试后有产出→L5，卡住→给提示 |
| L5 推进 | 自然过渡 | "得到了什么？和结论还有什么差距？" | AI推进后继续，卡住→给提示 |
| L6 卡点处理 | 如果卡住 | "卡在哪里？缺技巧还是缺思路？" | 根据AI回答决定给提示还是换方向 |

### 3.4 提示注入规则

当AI在L4或L5卡住时，从214号第4章的10个极致提示中选择匹配的提示注入。选择依据是AI在L1-L3描述的形状 + 当前卡点的性质。

**提示注入的Level评估**：每次给提示时，记录该提示的预估Level值：

| 提示 | 预估Level | 说明 |
|---|---|---|
| "能不能通过变换让条件更干净？" | ~0.9 | 归一化，几乎纯思维模式 |
| "多个约束能否被一个对象同时捕获？" | ~0.85 | 寻找统一编码，高度抽象 |
| "约束组合后会产生什么免费恒等式？" | ~0.8 | 恒等式挖掘，较抽象 |
| "关键对象的几何特征是否就是答案？" | ~0.85 | 结构对应，跨领域 |
| "假设下界不成立，符号行为和恒等式矛盾吗？" | ~0.9 | 反证法，纯思维模式 |
| "等号什么时候成立？什么构型达到极值？" | ~0.85 | 极值构型探测，跨领域 |

**降Level的决策规则**：
- 先给Level最高的提示
- 如果AI仍然卡住，给Level稍低的提示
- 只有在所有高Level提示都失败后，才降Level走向知识端
- 每次降Level时记录原因

### 3.5 实验记录

每次交互记录：

| 轮次 | 层 | 发送内容 | 预估Level | AI回复摘要 | AI状态 | 备注 |
|---|---|---|---|---|---|---|
| 1 | L1 | "读problem.txt，描述形状" | 1.0 | ... | ... | 安全步 |
| 2 | L2 | "想到什么方向？" | 1.0 | ... | ... | 安全步 |
| ... | ... | ... | ... | ... | ... | ... |

实验结束后计算：
- **Level SUM** = 所有提示的Level之和
- **Level均值** = Level SUM / 提示次数
- **降Level次数** = 从思维模式降到知识的次数
- **AI独立推进步数** = 没有提示AI自己推进的步数

## 4. 执行步骤

### Step 1：准备work_dir
- 清理/data/math-agent-glm5.2-1/下的所有文件
- 写入problem.txt（矩条件极差题第(1)问完整题面）
- 确认AGENTS.md存在且是Solver角色版本

### Step 2：启动tmux交互式session
- `tmux new-session -d -s guided-exp-1 "cd /data/math-agent-glm5.2-1 && devin --model glm-5-2"`
- 等待devin cli初始化完成

### Step 3：L1-观察
- 发送："请读取当前目录下的problem.txt文件。不要解题。请描述这道题的结构形状：结论是什么类型？已知条件是什么类型？条件和结论之间的距离有多远？"
- 等待AI回复，记录

### Step 4：L2-联想
- 发送："这些条件让你想到了什么方向？不要求正确，列出你能想到的所有方向。"
- 等待AI回复，记录

### Step 5：L3-描述方向
- 发送："对每个方向，如果走这个方向，第一步会做什么？不要求真的做，只描述。"
- 等待AI回复，记录

### Step 6：L4-小尝试
- 发送："选你觉得最有希望的方向，试着做第一步。做多少算多少，做不出来也没关系。"
- 等待AI回复，记录
- 如果AI有产出→L5
- 如果AI卡住→给提示（从214第4章提示集合中选Level最高的匹配提示）

### Step 7：L5-推进 / 提示注入循环
- 如果AI推进了："得到了什么？和结论还有什么差距？下一步想怎么走？"
- 如果AI卡住：给提示，记录Level值
- 循环直到AI完成证明或确认无法推进

### Step 8：L6-卡点处理（如果需要）
- "你卡在哪里了？是不知道下一步该做什么，还是知道方向但做不下去？"
- 根据AI回答决定：换方向 / 给更高Level提示 / 降Level给知识提示

### Step 9：实验结束
- 记录Level SUM、降Level次数、AI独立推进步数
- 评估实验结果（最优/良好/可接受/失败）
- 保存完整交互记录到runs/

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| devin cli交互式模式不支持在tmux中send-keys输入 | 改用`devin -p`多轮模式，每轮一个提示，用`--resume`保持session（但违反session隔离铁律——需要特殊处理） |
| AI在L1就卡住（连描述形状都不会） | 极不可能，但如果发生，说明AI基础能力有问题，需要换更简单的题先验证方法 |
| AI在L4尝试后走错方向 | 不纠正，让AI自己走一会儿，在L5检查时如果发现走偏再引导 |
| 交互轮次太多导致context过长 | 如果超过20轮还没完成，暂停并评估是否需要降Level |
| AI给出了错误证明但自认为完成了 | 实验后对照标准答案验证，记录"假完成"情况 |

## 7. 工程实现：--export + DFS树记录

### 7.1 --export参数

devin cli支持`--export <PATH>`参数，在每轮对话后自动导出对话记录到文件。

```bash
devin --model glm-5-2 --export /path/to/export.json
```

每个DFS分支使用独立的export文件，存放在`runs/guided_001/exports/session_<timestamp>.json`。

### 7.2 DFS树记录器（`scripts/dfs_tree.py`）

记录DFS探索过程的树状数据结构，支持：
- 添加根节点/子节点
- 记录每个节点的Q（提示）、A（回复）、Level值、状态
- 记录候选Q列表和已尝试的候选
- 回溯（弹出当前路径的栈顶）
- 获取从根到任意节点的Q序列（用于回溯后重放）
- 计算路径上的Level SUM
- 保存/加载到JSON文件

树文件：`runs/guided_001/dfs_tree.json`

节点结构：
```json
{
  "node_id": "0.1.2",
  "parent_id": "0.1",
  "depth": 2,
  "q_text": "试试反证法...",
  "q_level": 0.9,
  "q_category": "反证法",
  "a_text": "好的，假设极差<√5...",
  "a_status": "progressing",
  "candidates": [...],
  "tried_candidate_indices": [0],
  "session_id": "guided-exp-1",
  "export_path": "exports/session_xxx.json",
  "timestamp": "2026-08-06 ..."
}
```

### 7.3 实验运行器（`scripts/guided_exp_runner.py`）

辅助引导者操作的脚本，提供：
- `start_session()`：启动新tmux session + devin cli（带--export）
- `send_q(q_text, level, category)`：发送Q，捕获A，记录到DFS树
- `new_session_for_backtrack()`：回溯时启动新session
- `replay_to_fork(fork_node_id)`：重放Q序列到岔口
- `print_status()`：打印当前树状态和Level SUM

### 7.4 回溯操作流程

当DFS某条路走不通时：
1. `tree.backtrack()` — 弹出当前路径栈顶
2. `new_session_for_backtrack()` — 启动新session（干净context）
3. `replay_to_fork(fork_node_id)` — 重放Q序列到岔口
4. 在岔口发下一个候选Q（Level次高的）
5. 继续DFS

### 7.5 交互日志

每轮交互自动记录到`runs/guided_001/interaction_log.md`，包含：
- 轮次（node_id）
- Q文本、Level值、分类
- A文本、状态
- 当前路径Level SUM
