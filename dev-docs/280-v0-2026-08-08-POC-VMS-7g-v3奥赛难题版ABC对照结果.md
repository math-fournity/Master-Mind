## 实验目的

验证高Level思维方向hint（"翻译语言"）在奥赛难题上是否有胜率优势——相对于知识性hint和bare AI。

这是POC-VMS-7g系列的第三版：
- v1（简单题）：6个AI都成功，题目不够难
- v2（中等难度）：6个AI都成功，题目仍不够难
- v3（奥赛难题）：用OlympiadBench的奥赛题，预期bare会失败

## 实验设计

### 题目

从OlympiadBench的675道奥赛题中选10道，覆盖Algebra/Number Theory/Combinatorics/Geometry四个领域。

### 对照组

每道题3组对照：
- **bare**：无hint
- **knowledge**：知识性hint（从解答中提取关键定理和步骤）
- **highlevel**：高Level思维方向hint（统一的"翻译语言"hint，所有题完全相同）

### highlevel hint文本（所有题完全相同）

```
思维方向：不要在问题给定的原始语言中硬解。
把问题翻译到另一种数学语言——在原始语言中问题可能很复杂，但翻译后可能变得显然。
问自己：这个问题在另一种语言中会变成什么？什么语言能让这个问题变得简单？
常见的翻译方向：
- 从"枚举/构造"翻译到"结构/性质"
- 从"具体对象"翻译到"抽象不变量"
- 从"原始问题"翻译到"模运算/商结构/同态像"
```

### 运行

- 10个bare AI并发（用户允许10并发）
- 8个knowledge AI + 8个highlevel AI并发（只对bare失败的8道题跑对照）
- 每个AI在独立tmux session中运行，token限制相同

## 结果分析

### 高Level hint没有胜出

highlevel通过率（12%）反而低于knowledge（25%）。原因分析：

1. **highlevel hint太抽象**——"翻译到另一种语言"没有告诉AI具体往哪翻译。对奥赛题来说，AI需要的不只是方向，还需要具体的构造技巧和计算路径。

2. **knowledge hint太详细**——我把解答的关键步骤都写进了knowledge hint，几乎是手把手教。这不是公平的"知识性提示"对照——更像是"半解答"。

3. **6道题三组全失败**——题目对GLM-5.2太难了。即使有hint，AI也做不出来。这些题可能需要多次hint注入（动态引导），而不是一次性静态hint。

4. **highlevel-1760成功但不是因为翻译**——AI用了坐标法，不是"翻译语言"思维。说明highlevel hint对这道题没有起到引导作用，AI是靠自己的方法解出来的。

### 与POC-VMS-6v2的对比

6v2的动态引导（bare 0% vs guided 100%）之所以成功，是因为：
- 动态引导是**过程中的**——AI卡住时实时给方向
- 6v2的hint是知识性的——告诉AI"用什么定理"
- 6v2的题目是群论题——GLM-5.2有群论知识基础

7g-v3的静态高Level hint之所以失败，是因为：
- 静态hint是**一次性的**——开头给一次，之后AI自己跑
- 高Level hint太抽象——不给具体知识
- 奥赛题需要的不只是方向——还需要构造技巧和计算

## 结论

1. **静态高Level hint在奥赛题上没有胜率优势**——太抽象，AI不知道怎么用
2. **知识性hint有一定帮助**（25%），但knowledge hint设计不公平（太详细）
3. **奥赛题对GLM-5.2太难**——6/8道题三组全失败，需要动态引导而非静态hint
4. **高Level hint的价值可能需要动态注入才能体现**——在AI卡住时实时给方向，而不是开头一次性给

## 下一步方向

1. **动态高Level引导**——在AI解题过程中观察thinking，当AI卡住时实时注入"翻译语言"方向hint
2. **公平的knowledge hint**——只给定理名称，不给解答步骤
3. **选择"卡在翻译"的题**——选那些bare AI明确卡在"不知道往哪个方向走"的题，而不是卡在"计算太复杂"的题
4. **题目侧写系统**（05任务追踪）——先建设侧写系统，用侧写数据精准选题，而不是逐个阅读筛选
