# 80-数学大师项目启动认知基础

## 背景

2026-08-03，项目从星学（`~/MOIRA_chinese_astrology-main/`）迁移到数学（`/data/master-mind/`）。在完成 AGENTS.md 重写后，用户提出了项目启动的第一个根本问题：

> 如果我们这套系统成功了，真的制造出了数学大师，那么它应该可以解决什么问题？又需要积累什么知识呢？

本文档记录对这个问题的完整讨论，作为数学大师制造项目的认知基础。它直接关系到 AGENTS.md TODO section 中的"制定建设计划"和"设计依赖图初始结构"两项。

## 一、成功的数学大师能解决什么问题

数学研究大师做的事，按从具体到抽象排序：

### 1. 解题级研究

面对一个具体数学问题，知道该从哪个方向切入。这对应星学POC中的"看盘"——依赖图提示"这个问题涉及这些概念、这些工具、这些前置定理，它们的关系是这样的"。

### 2. 证明构造

面对一个猜想或定理，组织证明思路——哪些是前置、哪些是引理、走直接证明还是反证还是构造还是归纳。这对应星学中的"推限"——沿依赖路径组织。Wiles证明费马大定理就是极端案例：把椭圆曲线、模形式、Galois表示多个领域的工具组织成数百页的证明结构。

### 3. 猜想提出

从具体现象中抽象出一般规律，提出有价值的猜想。这是研究品味——不是所有猜想都值得提。大师知道哪些方向"有味道"。

### 4. 跨领域类比与迁移

这是"综述博士"最闪光的地方。范畴论统一了代数和拓扑；表示论连接了群论和调和分析；Langlands纲领连接了数论和自守形式。大师在A领域看到的结构，知道在B领域是否有对应——这正是依赖图中"跨领域映射边"的运用。

### 5. 识别问题本质

面对看似复杂的问题，识别它"真正"问的是什么——它是某个已知问题的变体，或属于某个已有理论的特例。这是大师直觉的核心。

### 6. 研究方向价值判断

不是所有问题都值得做。大师知道哪些问题重要、哪些是死胡同、哪些时机成熟。这是"知道该判断什么"在战略层面的体现。

### 7. 大型证明组织

把多个领域的工具组织成一个连贯的证明结构。这是依赖图在大规模下的运用——星学POC-7已经验证了71节点106边的可行性。

## 二、需要积累什么知识

对照星学POC中依赖图的实际结构（节点=知识单元，边=依赖关系），数学版需要积累五类东西：

### （一）数学知识本体（math-notes/ 主体）

| 类别 | 内容 | 星学对应 |
|---|---|---|
| **领域地图** | 代数/几何/分析/拓扑/数论/组合/逻辑/范畴论...每个领域的核心概念、定理、方法 | study-notes 01-13 步骤 |
| **工具库** | 范畴论/同调代数/表示论/调和分析/概率论...每个工具的适用场景和接口 | qizheng 计算接口 |
| **定理库** | 重要定理的陈述、证明思路、适用条件、与其他定理的关系 | rules_library.json |
| **反例库** | 哪些直觉是错的、哪些猜想被推翻了 | 星学中没有直接对应，但数学中极重要 |

### （二）数学意识（math-notes/数学意识/）

对应星学中的"五行生克、恩用仇难"——在数学中弥漫性存在的思维模式，不是某个问题的专属解法，而是贯穿整个研究过程的底层思维：

- **类比思维**：看到A领域的结构，联想B领域是否有对应
- **抽象化直觉**：什么时候该抽象、抽象到什么程度
- **极端情形检验**：先看平凡情形、退化情形、边界情形
- **对偶思维**：线性代数的对偶、范畴论的对偶、拓扑的对偶
- **局部-全局思维**：局部性质如何推出全局性质
- **存在性 vs 构造性**：什么时候只要证明存在就够，什么时候需要构造
- **有限 vs 无限**：从有限到无限时的陷阱和工具
- **连续 vs 离散**：连续问题离散化、离散问题连续化

这些就是星学POC中制造"螺旋上升环路"的垂直维度——每次研究不同问题时反复调用同一个意识，但上下文不同，产生新判断。

### （三）依赖图（xishujuzhen/ 的核心内容）

| 边类型 | 例子 | 星学对应 |
|---|---|---|
| **知识依赖边** | "理解层论需要先理解拓扑""同调代数依赖范畴论" | 步骤前置依赖 |
| **工具适用边** | "这种结构适合用范畴论""那种适合用解析方法" | 意识-步骤调用 |
| **跨领域映射边** | "代数几何中的概形 ↔ 拓扑中的空间""数论L函数 ↔ 调和分析特征" | 星学中没有直接对应，这是数学特有的高价值边 |
| **证明策略边** | "这种结构适合归纳""那种适合对偶论证" | 格局判定路径 |

**跨领域映射边是数学版依赖图相比星学版的最大增量**。星学中的跨宫依赖（命宫→官禄）是同一体系内的；数学中的跨领域映射（代数↔拓扑↔几何）是不同体系之间的结构同构——这正是Langlands纲领、范畴论统一性的核心，也是大师"综述博士"价值最高的地方。

### （四）计算工具接口

| 工具类型 | 候选 | 角色 |
|---|---|---|
| 符号计算 | SymPy / SageMath | 公式推导、符号运算 |
| 定理证明辅助 | Lean / Coq / Isabelle | 证明形式化验证 |
| 数值计算 | NumPy / SciPy | 数值实验、猜想验证 |

这些对应星学中的 `qizheng/`——提供精确计算原料，不代替数学判断。

### （五）研究案例库

历史上重要猜想被解决的过程：费马大定理、Poincaré猜想、Weil猜想、Fermat素数、Riemann猜想进展...

这些案例中大师是如何"知道该判断什么"的——这是依赖图的**实证来源**。星学POC的依赖图是从古籍和命例中提取的；数学版的依赖图应该从这些研究案例中提取——大师在解决这些问题时，实际调用了哪些知识、沿什么路径思考。

## 三、关键的诚实面对

星学POC中，依赖图的构建需要星学功力——判断"五行生克依赖昼夜"是一条边，需要懂星学。

数学版同样：**判断"代数拓扑依赖范畴论"是一条边、"数论依赖调和分析"是不是一条边，需要数学功力。** 依赖图的构建阶段需要"综述博士"参与，运行阶段才不需要。

这意味着项目的前期，数学认知的积累和依赖图的构建是同一件事——每编码一条依赖边，就是对数学思维的一次显化。这和星学项目中"study-notes显化知识内容，xishujuzhen显化知识间的思维依赖"是互补关系。

## 四、对项目建设的启示

本讨论直接关系到以下建设决策（待在建设计划中细化）：

1. **建设顺序**：数学知识本体的积累和依赖图的构建是同一件事的前期工作，不能先建图再填知识，也不能先填知识再建图——二者交替推进。
2. **第一个实验场的选择**：应选择一个跨领域映射丰富但规模可控的数学场景作为第一个POC，类似星学POC-1的5节点小图起步。
3. **研究案例库的优先级**：研究案例是依赖图的实证来源，应在早期就开始积累——从经典案例中提取大师的实际思维路径。
4. **数学意识的识别**：类比思维、对偶思维、局部-全局思维等是否真的具有"弥漫性"，需要在实际研究中验证，不能预设。
5. **跨领域映射边的设计**：这是数学版相比星学版的最大增量，也是价值最高的地方，但也是最难编码的——需要"综述博士"级别的数学判断。
