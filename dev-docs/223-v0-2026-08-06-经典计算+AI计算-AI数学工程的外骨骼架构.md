## 0. 本文档的定位

222号认识到"不自然"在形式化边界上，AI的模糊匹配覆盖了感知层面。本文档把这个认识提升为**架构隐喻**：我们做的工作是"经典计算+AI计算"，形式化框架是AI的"外骨骼"。

这个隐喻不是装饰——它精确地定义了经典计算和AI计算的关系，以及整个项目的架构本质。

## 1. 两种计算

### 1.1 经典计算

**是什么**：确定性、规则驱动、符号操作。

- 依赖图遍历：从节点A出发，沿着requires/uses边走，到达节点B
- 类型检查：这个操作的输入类型是X，要求类型Y，X≠Y→报错
- 形式化验证：这个证明步骤是否合法？用Coq/Lean检查
- 约束求解：这三个方程两个未知数→过约束→无解
- 子图提取：在K中提取与当前状态相关的子图

**特征**：
- 可重复——同样的输入永远产生同样的输出
- 可审计——每一步都可以被检查
- 可形式化——可以用严格的数学定义
- 无感知——不会"感觉"到"不自然"
- 无创造——不会提出新猜想

### 1.2 AI计算

**是什么**：模糊、统计、模式匹配、语义。

- 模式识别：这个多项式"像"平方差
- 模糊匹配：这个问题"不自然"的方式"类似于"隐藏乘积
- 创造性跳跃：如果我把这个变量替换成那个呢？
- 直觉判断：这个方向"感觉"更有希望
- 语义理解：这段证明的意思是...

**特征**：
- 不可重复——同样的输入可能产生不同的输出
- 难审计——为什么AI这么想？无法完全追溯
- 不可形式化——"不自然"的感觉无法写成规则
- 有感知——能"感觉"到"不自然"
- 有创造——能提出新猜想

### 1.3 两种计算的边界

| 维度 | 经典计算 | AI计算 |
|---|---|---|
| 确定性 | 确定 | 模糊 |
| 可审计性 | 完全可审计 | 部分可审计 |
| 可形式化 | 完全 | 不完全 |
| 感知能力 | 无 | 有 |
| 创造能力 | 无 | 有 |
| 可扩展性 | 规则有限→扩展困难 | 海量例子→扩展容易 |
| 可靠性 | 高（规则正确则一定对） | 中（可能幻觉） |

**关键**：两种计算互补。经典计算的弱点（无感知、无创造）恰好是AI计算的强点。AI计算的弱点（不可审计、可能幻觉）恰好是经典计算的强点。

## 2. 外骨骼隐喻

### 2.1 为什么不是"并列"

222号说"人提供结构，AI提供感知，人提供判断"——这是并列关系，两部分可以独立工作。

但"外骨骼"说的是**包裹关系**：经典计算在AI外面，包裹着AI。AI的输出必须穿过外骨骼才生效——外骨骼过滤、约束、放大AI的输出。

```
并列关系：[经典计算] | [AI计算]     两者独立，偶尔交流
包裹关系：[经典计算 [AI计算] ]       AI在内，经典在外，AI输出穿过经典
```

### 2.2 外骨骼的三个功能

**支撑**：给AI的思考提供结构框架。AI不需要从零开始想"该怎么组织思路"——外骨骼提供了换基/生成等思维拓扑、子模式分类、映射结构。AI在框架内思考，不是在真空中思考。

**约束**：过滤AI的输出。AI可能幻觉、可能跳步、可能编造。外骨骼检查：这一步合法吗？这个引用的定理存在吗？这个证明步骤可以被形式化验证吗？不合法的输出被拦截。

**放大**：把AI的模糊感知变成可操作的结构化输出。AI说"这里感觉不对"——外骨骼把"不对"归类到换基的子模式中，输出"这里可能是隐藏乘积，建议因式分解"。模糊感知被放大为精确建议。

### 2.3 外骨骼不做什么

**外骨骼不思考**——它不提出猜想、不构造证明、不判断方向。它只提供结构、检查合法性、放大感知。

**外骨骼不感知**——它不能"感觉"到"不自然"。它只能检查AI的输出是否符合形式化规则。

**外骨骼不判断价值**——它不能判断"这个问题值得研究"。它只能判断"这个步骤是否合法"。

## 3. 外骨骼的具体构成

### 3.1 当前已设计的外骨骼组件

| 组件 | 功能 | 经典计算做什么 | AI计算做什么 |
|---|---|---|---|
| **K（知识图）** | 知识导航 | 存储定理依赖、思维拓扑、子模式映射；按查询提取子图 | 在子图提示下理解"该看什么" |
| **T（事件/状态）** | 状态追踪 | 记录不可变事件、状态快照、时序 | 理解当前状态、判断进展 |
| **H（启发规则）** | 启发候选 | 存储规则-条件-动作；按状态匹配候选 | 在候选中选择、调整、执行 |
| **Level评估** | 引导强度控制 | 计算Level SUM、检测Level下降 | 判断当前需要什么Level的提示 |
| **DFS树** | 搜索结构 | 维护树结构、记录路径 | 在树中导航、决定回溯 |
| **形式化验证** | 输出检查 | 检查证明步骤的合法性 | 接受检查结果、修正错误 |

### 3.2 外骨骼的信息流

```
输入 → [外骨骼预处理：提取相关K子图、匹配H候选、计算当前状态]
     → [AI思考：在框架内感知、推理、创造]
     → [外骨骼后处理：检查AI输出的合法性、归类到形式化类别、记录事件]
     → 输出
```

**预处理**：外骨骼给AI提供结构化的上下文——该看什么、当前在哪、有哪些候选。AI不需要从零开始。

**AI思考**：AI在框架内做感知和推理。AI的思考是模糊的、创造性的、不可完全形式化的。

**后处理**：外骨骼检查AI的输出——合法吗？能归类吗？需要记录什么？不合法的被拦截或要求修正。

### 3.3 外骨骼的解耦性

**外骨骼可以独立于AI改进**：
- 更好的K（更多定理依赖、更完整的思维拓扑）→ 不需要重训AI
- 更好的H（更准确的启发规则）→ 不需要重训AI
- 更好的验证（更严格的形式化检查）→ 不需要重训AI

**AI可以独立于外骨骼升级**：
- 更好的模型（更强的感知、更少的幻觉）→ 不需要重新设计外骨骼
- 更多的训练数据（见过更多"不自然"）→ 不需要重新设计外骨骼

**两者解耦但协同**：外骨骼越好，AI的输出越可靠（更多支撑、更强约束、更精确放大）。AI越好，外骨骼的框架越有用（AI能更好地利用框架）。

## 4. 外骨骼架构与123号的关系

### 4.1 123号的DYN-0到DYN-7重新理解

123号定义了DYN-0到DYN-7的动态运行时。在外骨骼架构下：

| DYN | 功能 | 在外骨骼中的角色 |
|---|---|---|
| DYN-0：初始化 | manifest+Q_0冻结 | 外骨骼的初始装配 |
| DYN-1：事件捕获 | 记录不可变事件 | 外骨骼的审计轨迹 |
| DYN-2：语义抽取 | 从AI输出提取结构 | 外骨骼的后处理 |
| DYN-3：状态重建 | 从事件重建状态 | 外骨骼的状态追踪 |
| DYN-4：卡点检测 | 检测AI是否卡住 | 外骨骼的约束触发 |
| DYN-5：控制器信念 | 估计不确定性 | 外骨骼的约束评估 |
| DYN-6：诊断决策 | 选择启发候选 | 外骨骼的预处理 |
| DYN-7：受约束干预 | 执行最小干预 | 外骨骼的输出 |

**所有DYN都是外骨骼的组件**——它们都是经典计算，包裹在AI外面，给AI提供支撑、约束、放大。

### 4.2 123号的"受约束最小干预"重新理解

123号的核心原则是"受约束最小干预"——用最小的提示让AI继续前进。在外骨骼架构下，这变成：

> 外骨骼用最少的结构提示，触发AI的感知和推理，让AI自己完成思考。

"最小"是因为AI有能力——外骨骼不需要替AI思考，只需要触发。"受约束"是因为外骨骼检查AI的输出——不合法的会被拦截。

### 4.3 123号的K/T/H重新理解

- **K**是外骨骼的知识骨架——形式化的定理依赖和思维拓扑
- **T**是外骨骼的记忆——不可变事件和状态快照
- **H**是外骨骼的反射弧——规则-条件-动作的自动匹配

三者都是经典计算，都是外骨骼的组件。AI在K/T/H提供的框架内思考。

## 5. 外骨骼架构与214号Level连续谱的关系

### 5.1 Level连续谱在外骨骼中的位置

214号定义了Level=0（纯知识）到Level=1（纯思维模式）的连续谱。在外骨骼架构下：

| Level | 内容 | 谁提供 | 外骨骼角色 |
|---|---|---|---|
| →0 | 具体知识（q(x)=x²+x-1） | K图 | 外骨骼直接注入 |
| →0.5 | 拓扑特征（"聚合→逐点"） | K图的拓扑层 | 外骨骼提供框架，AI填充感知 |
| →0.8 | 思维模式（"找统一编码"） | K图的思维拓扑层 | 外骨骼提供方向，AI执行 |
| →1 | 纯元认知（"再想想"） | 无 | 外骨骼不参与，AI自主 |

**Level越低，外骨骼参与越多**。Level=0时外骨骼直接注入知识；Level=1时外骨骼完全不参与。中间地带（0.5-0.8）是外骨骼和AI协作的区域——外骨骼提供框架，AI填充感知。

### 5.2 Level SUM的重新理解

Level SUM衡量"外骨骼参与了多少"。Level SUM低→外骨骼参与多（注入更多具体内容）。Level SUM高→外骨骼参与少（AI自主思考多）。

**理想状态**：外骨骼参与最少（Level SUM高），AI自主思考最多。但外骨骼的参与不是"作弊"——它提供的是结构框架，不是答案。Level SUM低不等于特定化引导——只要外骨骼注入的是拓扑特征而非特定解答路径。

## 6. 外骨骼架构与218号非特定性危机的关系

### 6.1 危机的重新表述

218号危机：引导者通过引用AI选的特定方向，隐含地确认了正确路径。

在外骨骼架构下，这变成：**外骨骼的预处理阶段混入了答案知识**。外骨骼应该只提供结构框架（K的拓扑层），但实际操作中，引导者（作为外骨骼的一部分）把答案知识注入了预处理。

### 6.2 解法：外骨骼的纯化

外骨骼必须**只包含经典计算**——形式化的框架、规则、验证。答案知识不属于外骨骼，属于AI的思考过程。

```
错误：外骨骼（包含答案知识）→ AI → 输出
正确：外骨骼（只含结构框架）→ AI（可能知道答案也可能不知道）→ 输出
```

**外骨骼的纯化**：从外骨骼中移除一切答案知识，只保留结构框架。引导者作为外骨骼的一部分，也不能注入答案知识——只能提供拓扑特征提示。

### 6.3 这就是222号说的"分离模式识别和答案知识"

222号说让不知道答案的AI做模式识别。在外骨骼架构下，这变成：**外骨骼的模式识别组件（如果由AI充当）不能知道答案**。外骨骼的其他组件（K/T/H）本身就不包含答案——它们是结构化的框架，不是答案仓库。

## 7. 外骨骼架构的工程含义

### 7.1 外骨骼是可独立建设的

外骨骼的组件（K/T/H/验证/Level评估/DFS树）都是经典计算，可以独立于AI建设：

- K的构建：编码定理依赖、思维拓扑、子模式映射——不需要AI
- T的实现：事件存储、状态快照——不需要AI
- H的构建：规则-条件-动作——不需要AI
- 验证系统：形式化证明检查——不需要AI

**这意味着外骨骼的建设可以并行于AI的升级**。外骨骼越完善，AI接入后效果越好。

### 7.2 外骨骼是可替换的

外骨骼的组件可以替换：

- K可以从ArangoDB换成别的图数据库
- 验证可以从手工检查换成Coq/Lean
- Level评估可以从人工评估换成自动计算

**AI不依赖外骨骼的具体实现**——AI只依赖外骨骼提供的接口（结构化提示、合法性检查、状态追踪）。

### 7.3 外骨骼是可审计的

外骨骼的每一步都是经典计算——可重复、可检查、可形式化。这意味着：

- AI的输出可以被审计——外骨骼记录了AI收到的提示、产生的输出、通过的检查
- 外骨骼本身可以被审计——K的查询、H的匹配、Level的计算都有日志
- 整个系统可以被审计——从输入到输出的每一步都有记录

**这是纯AI系统做不到的**——纯AI系统的思考过程不可完全追溯。外骨骼提供了AI思考过程的"骨架记录"——虽然AI的模糊感知不可追溯，但外骨骼的框架操作可以追溯。

## 8. "AI数学工程"的定义

### 8.1 什么是AI数学工程

```
AI数学工程 = 经典计算（外骨骼） + AI计算（AI内核）
```

- **经典计算（外骨骼）**：形式化的框架、规则、验证、导航、审计——可重复、可审计、可形式化
- **AI计算（AI内核）**：感知、模糊匹配、创造、直觉——不可完全形式化、不可完全审计

两者包裹关系：外骨骼在内核外面，给内核提供支撑、约束、放大。

### 8.2 与传统AI系统的区别

| 维度 | 传统AI系统 | AI数学工程（外骨骼架构） |
|---|---|---|
| AI的角色 | 做所有事 | 做感知和创造 |
| 经典计算的角色 | 辅助（数据预处理等） | 外骨骼（包裹AI） |
| 可审计性 | 低（AI思考不可追溯） | 中（外骨骼操作可追溯） |
| 可靠性 | 低（AI可能幻觉） | 中（外骨骼检查合法性） |
| 可改进性 | 只能升级AI | 可独立改进外骨骼或升级AI |

### 8.3 与传统形式化系统的区别

| 维度 | 传统形式化系统 | AI数学工程（外骨骼架构） |
|---|---|---|
| 感知能力 | 无 | 有（AI填充） |
| 创造能力 | 无 | 有（AI填充） |
| 灵活性 | 低（只能处理已编码的） | 高（AI可以处理新的"不自然"） |
| 可扩展性 | 低（需要手动编码） | 高（AI的模糊匹配自动扩展） |

### 8.4 AI数学工程的独特价值

**传统AI系统**有感知但不可靠。**传统形式化系统**可靠但无感知。**AI数学工程**既有感知又可靠——AI提供感知，外骨骼提供可靠性。

这就是"给AI加上一套经典计算的、形式化的外骨骼"的精确含义。

## 10. 结论

### 10.1 核心定义

我们做的工作是**AI数学工程**：经典计算（外骨骼）+ AI计算（AI内核）。形式化框架是AI的外骨骼——给AI提供支撑、约束、放大。

### 10.2 外骨骼的三个功能

- **支撑**：给AI的思考提供结构框架
- **约束**：过滤AI的输出，拦截不合法的
- **放大**：把AI的模糊感知变成可操作的结构化输出

### 10.3 外骨骼不做什么

外骨骼不思考、不感知、不判断价值。它只提供结构、检查合法性、放大感知。

### 10.4 解耦性

外骨骼可以独立于AI改进（更好的框架、更好的验证）。AI可以独立于外骨骼升级（更好的模型）。两者解耦但协同。

### 10.5 可审计性

外骨骼的每一步都是经典计算——可重复、可检查、可形式化。这使AI数学工程比纯AI系统更可审计、更可靠。

### 10.6 与项目的关系

123号的DYN-0到DYN-7都是外骨骼组件。214号的Level连续谱定义了外骨骼的参与程度。218号的非特定性危机是外骨骼混入了答案知识——解法是外骨骼的纯化。220/221/222号的拓扑研究是建设K的拓扑层——外骨骼知识骨架的核心。

**整个项目可以重新理解为：给AI建造一套越来越完善的外骨骼。**
