# 255-v0 · 253号Pattern检索问题全库线索检索报告

> **文档定位**：本报告是对 `dev-docs/` 全库（约201份文档）逐份检索后，找出哪些文档包含253号问题（稀疏矩阵中Pattern检索的三层问题）解决线索的**详尽索引**。
>
> **目的**：为以后的AI（包括跨session、跨压缩边界后的AI）提供充分的检索提示——当需要研究253号Pattern检索问题时，直接查本报告即可定位最相关的文档，不必重新做全库扫描。
>
> **检索方法**：用201个独立subagent并发执行，每个subagent读取253号问题定义+一份待检文档，按统一格式判断相关性。本报告是所有subagent结果的汇总与提炼。
>
> **253号问题简述**：燧人系统（第二代数学大师系统）中，当工作智能体（做题AI）停在某个状态时，助理智能体（引导者AI）如何从稀疏矩阵的海量Pattern存储中精准提取此刻最需要的那一个（或那一批）Pattern？问题分三层：
> - **第一层（状态感知）**：助理智能体怎么"看到"工作智能体需要什么？思维状态怎么表示？拓扑怎么编码？匹配度怎么计算？
> - **第二层（Pattern提取）**：怎么从海量Pattern存储中快速定位到相关Pattern？索引结构是什么？相似度/匹配度怎么定义？
> - **第三层（知识悖论）**：助理智能体的内在知识不足以提出Q，但要在候选Pattern中选出正确的Q，这个选择本身也需要知识——怎么破解？

#### 3.3.1 文档214：提示策略路线选择与Level连续谱

- **角色分离架构**（§8.2）：引导者AI（助理智能体）vs 做题AI（工作智能体）。引导者不需要知道正确答案，但需要具备四种元认知能力：生成候选Q、评估Level、判断A的状态、回溯决策
- **DFS架构中的候选Q生成**（§8.4）：引导者生成候选Q列表，按Level降序排列，DFS优先选Level最高的Q（贪心），走不通就回溯

## 六、三层问题的线索覆盖度分析

### 6.1 第一层（状态感知）——线索中等

**核心问题**：思维状态怎么表示？拓扑怎么编码？匹配度怎么计算？

**最佳线索来源**：
1. **224号**：拓扑τ理论——状态=问题在τ中的位置，匹配=判断属于哪些开集（理论框架）
2. **122-v2/250号**：思维图T的节点/边类型 + 工作区W_t六元组（数据结构）
3. **219号**：问题拓扑6维度（编码方案）
4. **221号**：拓扑库+映射机制（检索框架）

**关键缺口**：从自然语言推理输出自动提取结构化拓扑特征的**具体算法**未定义。224号给出了拓扑τ的理论定义，219号给出了6维度框架，但都没有给出"怎么从Solver的文本输出中自动提取这6个维度的值"的算法。

### 6.2 第二层（Pattern提取）——线索较丰富

**核心问题**：怎么从海量Pattern存储中快速定位？索引结构是什么？相似度/匹配度怎么定义？

**最佳线索来源**：
1. **122-v2号**：H图子图模式匹配 + LHS/Guard/RHS结构（匹配机制）
2. **110/249号**：三层访问架构 + 三级种子选择机制（基础设施）
3. **239/236/234号**：结构化字段匹配+图查询+向量排序三阶段方案（检索算法方向）
4. **225-1号**：伴随关系F⊣G（匹配度的数学定义）
5. **226-v1号**：Grothendieck topology作为索引结构（数学框架）

**关键缺口**：
- "种子节点如何从当前状态中识别"——110/249号假设种子已知，但种子的识别正是第一层的问题
- "结构化字段的具体值怎么自动提取"——239号的"处境类型+移动类型+证书类型"需要从Solver输出中自动识别
- "图查询的连通路径怎么定义"——234号说"图查询在依赖图中找连通路径"但没定义"连通路径"

### 6.3 第三层（知识悖论）——线索最薄弱

**核心问题**：助理智能体知识不足以提出Q，但要在候选中选出正确的Q，这个选择本身也需要知识——怎么破解？

**最佳线索来源**：
1. **233号**：分离感知能力（边界以外）和答案知识（边界以内）——最深刻的分析
2. **224号**：两种计算分工——感知/识别/选择→AI模糊处理；检查/验证→经典计算
3. **214号**：角色分离+DFS探索+Level排序——架构层面破解方向
4. **222号**："不知道答案的AI"做模式识别——可验证实验设计（**尚未执行**）
5. **239号**：执行契约——从"内容理解"降级为"形式检查"

**关键缺口**：
- **"感知能力是否真的比提出Q需要更少的知识"未被证明**——222号提出了实验设计但未执行
- **"候选Q生成"的机制未解决**——214号说引导者"能想出多个可能的提示方向"，但如果想出候选需要数学知识，悖论仍然存在
- **"形式检查"的完备性未证明**——239号的执行契约能把"识别Q是否有效"降级为形式检查，但没证明"能填完执行契约"的Q一定有效

## 七、建议的解决路径

基于全库线索分析，建议按以下路径解决253号问题：

### 7.1 状态感知（第一层）

**方案组合**：224号的拓扑τ理论 + 219号的问题拓扑6维度 + 250号的W_t六元组

**具体路径**：
1. 用219号的6维度定义问题拓扑的schema
2. 用250号的W_t六元组记录运行时状态
3. 用224号的拓扑τ理论定义"状态=问题在τ中的位置"
4. **需要新建**：从Solver文本输出自动提取6维度值的算法（可能需要LLM作为提取器）

### 7.2 Pattern提取（第二层）

**方案组合**：122-v2号的LHS/Guard/RHS结构 + 110/249号的三层访问架构 + 239号的三阶段检索

**具体路径**：
1. Pattern存储采用122-v2号的LHS/Guard/RHS结构
2. 检索基础设施采用110/249号的三层访问架构（冷存储→种子选择→热工作集）
3. 检索算法采用239号的三阶段方案（结构化字段匹配→图查询→向量排序）
4. 匹配度计算参考225-1号的伴随关系F⊣G数学框架
5. **需要新建**：将第一层的状态感知结果（问题拓扑6维度）映射为检索种子的具体算法

### 7.3 知识悖论（第三层）

**方案组合**：233号的分离感知与答案知识 + 214号的DFS+Level排序 + 239号的执行契约 + 222号的实验验证

**具体路径**：
1. 采用233号的理论框架——助理智能体做"边界以外的感知"，不做"边界以内的内容理解"
2. 采用214号的架构方案——引导者生成候选Q列表，按Level排序，DFS探索验证
3. 采用239号的操作性检查——用执行契约作为"Q是否有效"的形式检查（不需内容理解）
4. **必须执行**：222号的实验设计——验证"不知道答案的AI能否做有效模式识别"
5. **需要新建**：如果实验证明感知能力不足以做有效选择，需要设计"人在环路"的fallback机制
