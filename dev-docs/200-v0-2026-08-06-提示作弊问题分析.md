## 一、问题陈述

**核心问题**：当前大师数学系统在辅助Solver解题时，提示机制是否存在作弊成分？如果存在，作弊到什么程度？设计中有哪些防线，这些防线当前是否生效？

**作弊的定义**（本文档采用的工作定义）：

| 层次 | 行为 | 是否作弊 |
|---|---|---|
| 给答案 | 提示中直接包含答案或答案的等价表述 | **作弊** |
| 给知识 | 提示中给出具体数学事实/定理/已知结果 | **灰色地带**——取决于"Solver本来是否应该知道" |
| 给策略 | 提示中给出解题方向/方法选择/小情形验证建议 | **不算作弊**——这是"引导"的本意 |
| 给元提示 | 提示中只说"继续"、"更详细一些" | **不算作弊** |

## 二、当前系统实际行为（实现层）

### 2.1 GuidedLoop的提示生成——硬编码，含具体数学知识

当前GuidedLoop（`runtime/guided_loop.py:262-271`）的提示是硬编码的，按卡点原因分5类：

| 卡点原因 | 提示内容 | 作弊分析 |
|---|---|---|
| `lack_knowledge` | "考虑C_4是偶圈，具有二部结构。已知R_k(C_4)的上界来自Bipartite Ramsey理论，下界来自射影平面构造。请查阅Conlon关于Ramsey数的讲义。" | **给知识**——直接告诉了上界/下界的来源 |
| `uncertain` | "尝试从小情形开始验证。先计算k=2,3,4时的R_k(C_4)精确值，看是否能发现模式。" | **给策略**——引导从小情形入手 |
| `need_more_info` | "关键信息是C_4的二部性使得ex(n,C_4)=O(n^{3/2})，而C_3的ex(n,C_3)=O(n^2)。这个差异直接决定了Ramsey数的阶。" | **给知识**——直接给了ex(n,C_4)的阶 |
| `response_too_short` | "请给出更详细的分析，包括：1) 已知上下界的来源，2) 你的猜测，3) 支撑猜测的推理。" | **给元提示**——要求更详细 |
| `unknown_stall` | "继续分析。尝试从极值图论的角度思考：C_4-free图的边数上界如何决定Ramsey数的阶？" | **给策略**——引导从极值图论角度思考 |

**结论**：5条提示中，2条是"给知识"（灰色地带），2条是"给策略"（不算作弊），1条是"给元提示"（不算作弊）。

### 2.2 当前系统缺失的防线

| 防线 | 设计中 | 实现状态 |
|---|---|---|
| truth_vault答案隔离 | 123号§23 | ❌ GuidedLoop未连接truth_vault |
| 四门泄漏审计 | 123号§23 + leakage_audit.py | ❌ GuidedLoop未调用leakage_audit |
| 候选规则不在线使用 | 189号§2.2 | ❌ 当前无规则库，提示全部硬编码 |
| 增益归因 | 123号§DYN-7 | ❌ 未记录提示的增益来源 |
| 诚实降级条款 | AGENTS.md核心假设§6 | ❌ 未做"去掉答案等价信息后增益是否消失"实验 |

## 三、设计目标（设计层）

### 3.1 truth_vault答案隔离

答案存放在truth_vault collection中，只有auditor角色可读。Controller/Matcher/Solver都看不到答案。

- **代码位置**：`visibility_labels.py:27-92`定义了14个collection的可见性矩阵
- **审计标准**：193号§2.1检查truth_vault是否被非auditor角色访问
- **当前状态**：可见性矩阵已定义，但GuidedLoop未使用

### 3.2 四门泄漏审计

`leakage_audit.py`定义了四门审计：

1. **门1·字面匹配**：提示中是否直接出现答案
2. **门2·等价映射**：提示中是否包含答案的等价表述（如"底数变成log k，指数k/3不变"）
3. **门3·候选空间缩减**：提示把可能的答案空间缩减到了多少
4. **门4·盲恢复**：只看题面+提示，能不能猜出答案

- **阈值**：DEFAULT_G0_4_THRESHOLD = 0.3（`leakage_audit.py:65`）
- **F2防线**：四门全部执行，每门独立分数，不允许只跑一门就声称通过
- **F6防线**：使用代理分数，不是互信息
- **当前状态**：代码已实现，但GuidedLoop未调用

### 3.3 增益归因

123号§DYN-7要求记录每条提示的增益来源：

- 提示发出后，Solver的进展是否改善？
- 改善的部分是"思路"（策略选择）还是"知识"（具体事实）还是"答案等价信息"？
- 如果增益主要来自"答案等价信息"→提示有作弊成分

- **当前状态**：GuidedLoop只记录了提示是否发出和Solver是否完成，未记录增益来源

### 3.4 诚实降级条款

AGENTS.md核心假设第6条：

> 若去掉答案等价信息后增益消失，系统必须降级为诚实的静态知识/证明编译器。

意思是：如果做实验发现——去掉提示中所有"等价于答案"的信息后，Solver的表现就没有提升——那说明之前的提升全靠"递答案"，系统必须诚实承认自己只是一个"把答案换个说法喂回去"的编译器。

- **当前状态**：未做此实验

## 四、更根本的问题：给思路和给知识的边界

即使完整设计版实现了三条线，还有一个更根本的问题：**给"思路"算不算作弊？**

比如提示"先计算k=2,3,4的小情形"——这没有给答案，但给了**解题策略**。如果Solver本来不知道该从小情形入手，这个提示让它会做了——这算不算作弊？

### 4.1 123号架构的回答——诚实不可知论

1. **不预设"给思路=作弊"或"给思路=引导"**——这取决于具体场景
2. **用实验测量**：对比"有提示"和"无提示"的表现差异，再对比"有提示但去掉答案等价信息"和"无提示"的表现差异
3. **如果去掉答案等价信息后增益消失**→降级为编译器
4. **如果去掉答案等价信息后增益仍在**→说明提示确实在引导思维，不是在递答案
5. **如果无法区分**→保持诚实，标注为"不确定"

### 4.2 给知识和给策略的灰色地带

"已知R_k(C_4)的上界来自Bipartite Ramsey理论"——这是给知识还是给策略？

- 如果Solver是一个"应该知道Ramsey理论但不记得"的AI——这是激活已有知识，不算作弊
- 如果Solver是一个"根本不知道Ramsey理论"的AI——这是教新知识，算不算作弊取决于"大师数学系统"的定位
- 如果Solver是一个"知道Ramsey理论但不知道该用它"的AI——这是给策略，不算作弊

**问题在于**：当前系统不区分这三种情况——提示是无条件硬编码的，不管Solver是什么状态都给同样的内容。

### 4.3 完整设计版的解决方案——状态依赖的提示

完整12步运行时的提示是**状态依赖**的：

1. **状态归约**把Solver的输出归约成结构化状态（开放义务、已验证命题、当前表示）
2. **卡点诊断**分析卡点原因（7种类型）
3. **模式匹配**在规则库中匹配适用的规则——规则有`applicable_domains`和`model_versions`字段，只对特定状态生效
4. **策略π选择动作**——9种动作中包括ABSTAIN（什么都不做）

这意味着：同一个卡点原因，不同Solver状态会得到不同的提示，或者不给提示。当前简化版没有这个能力——5种卡点原因对应5条硬编码提示，无条件给出。

## 五、当前系统的作弊成分诊断

### 5.1 诊断结论

| 维度 | 诊断 | 证据 |
|---|---|---|
| 给答案 | **无**（当前提示中不含答案） | 5条提示均不含R_k(C_4)的具体数值 |
| 给知识 | **有**（2/5条提示含具体数学事实） | "上界来自Bipartite Ramsey理论"、"ex(n,C_4)=O(n^{3/2})" |
| 给策略 | **有**（2/5条提示含解题方向） | "从小情形开始验证"、"从极值图论角度思考" |
| 给元提示 | **有**（1/5条提示只要求更详细） | "请给出更详细的分析" |
| 泄漏审计 | **未执行** | GuidedLoop未调用leakage_audit |
| 增益归因 | **未执行** | 未记录提示的增益来源 |

### 5.2 总体判断

**当前系统的提示机制存在作弊成分，但不是"递答案"式的作弊，而是"给知识"式的作弊。**

具体来说：
- 没有直接给答案（R_k(C_4)的具体数值）
- 但给了具体数学事实（ex(n,C_4)=O(n^{3/2})等），这些事实是Solver"做出来"的关键
- 如果Solver本来不知道这些事实，提示让它"会做了"——这个"会做"确实有作弊成分
- 如果Solver本来知道这些事实但没想到要用，提示只是激活了已有知识——这个不算作弊
- **当前系统不区分这两种情况**——这是最大的问题

### 5.3 与设计目标的差距

当前系统距离设计目标的差距：

1. **truth_vault隔离**：已设计未实现——GuidedLoop需要连接truth_vault
2. **四门泄漏审计**：已实现未调用——GuidedLoop需要调用leakage_audit
3. **状态依赖提示**：已设计未实现——GuidedLoop需要连接12步运行时
4. **增益归因**：已设计未实现——GuidedLoop需要记录提示的增益来源
5. **诚实降级实验**：已声明未执行——需要设计并执行"去掉答案等价信息后增益是否消失"的实验

## 六、后续行动建议

### 6.1 短期（当前简化版改进）

1. **提示分级**：把5条硬编码提示按"给答案/给知识/给策略/给元提示"分级标注
2. **给知识的提示加警告**：在给知识的提示前加"以下信息可能影响你的独立判断，请自行验证"
3. **记录提示级别**：在guided_loop_result.json中记录每条提示的级别（knowledge/strategy/meta）

### 6.2 中期（连接设计层）

1. **GuidedLoop连接leakage_audit**：每条提示发出前执行四门审计
2. **GuidedLoop连接truth_vault**：确保Controller看不到答案
3. **提示从规则库匹配**：替代硬编码提示

### 6.3 长期（验证核心假设）

1. **设计诚实降级实验**：
   - 实验组A：无提示
   - 实验组B：有提示（完整提示）
   - 实验组C：有提示但去掉答案等价信息（只保留策略和元提示）
   - 对比三组的表现差异
2. **如果C的表现≈A**→增益主要来自答案等价信息→降级为编译器
3. **如果C的表现≈B**→增益主要来自策略引导→不是作弊
4. **如果A < C < B**→部分来自策略，部分来自知识→需要进一步细分
