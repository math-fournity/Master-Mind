# 65-xishujuzhen POC-2 验证方案

## 1. 背景：POC-1 的结果与教训

### 1.1 POC-1 结果回顾

POC-1（64 号文档方案）执行结果为**部分成功**：

| 维度 | A组（直接读文档） | B组（依赖图提示） | 差异 |
|---|---|---|---|
| 完整性 | 5 | 4 | B 缺少度主星/升殿/宿位等概念 |
| 准确性 | 5 | 4 | B 有五行归属错误（卯宫误判为木） |
| 深度 | 5 | 5 | 持平 |
| 逻辑性 | 4 | 5 | **B 优势**——螺旋上升被显式走出 |
| 结构感 | 4 | 5 | **B 优势**——直接对应依赖图节点 |
| **综合** | **4.70** | **4.50** | A 高 0.20 |

### 1.2 POC-1 的三个教训

**教训一：依赖图太小**

5 个节点不足以覆盖命宫分析的全部相关知识。A 组在自由阅读 study-notes 时自发调动了依赖图外的知识（度主星、升殿、宿位泄气、克宿、间接影响），B 组被依赖图"框住"了。

**教训二：知识指针指向不存在的文件**

`study-notes/星学意识/阴阳昼夜.md` 不存在。B 组 AI 在缺乏知识支撑时犯了五行归属错误。依赖图提示不能只有结构指针，必须有实际知识内容支撑。

**教训三：没有审计机制**

B 组输出的是"裸结果"——没有证据表明 AI 确实走过了依赖图中的每一条边、处理了每一个环路。完整性不足的问题只在事后评分时才被发现，而不是 AI 在输出时自证。这对应 63 号文档八延伸（用户提出的新要求）。

### 1.3 POC-1 的正面发现

**依赖图提示确实带来了两个维度的增益：**
- 逻辑性（+1）：螺旋上升被显式走出，"第一次→第二次→层次提升"的递进清晰
- 结构感（+1）：分析结构直接对应依赖图节点

这说明方向是对的，问题在粒度和机制。

## 2. POC-2 的三个改进

针对 POC-1 的三个教训，POC-2 做三个改进：

### 2.1 改进一：扩展依赖图（5→12 节点）

| 新增节点 | 类型 | 说明 | POC-1 中遗漏的原因 |
|---|---|---|---|
| 度主星判断 | substep | 命度所在宿的五行主星 | POC-1 图中没有度主星概念 |
| 升殿判断 | 意识 | 星曜五行与宿五行一致时力量最强 | POC-1 图中没有宿位层面 |
| 宿位泄气 | 意识 | 星曜在非本五行宿位时泄气 | POC-1 图中没有宿位层面 |
| 恩用仇难定局 | 意识 | 以命主为核心的生克四分类 | POC-1 图中有五行生克但没有恩用仇难 |
| 颠倒颠 | 意识 | 生太过反为害、煞为权 | POC-1 图中没有这个意识 |
| 仇难外避分析 | substep | 仇星难星不在命宫的影响 | POC-1 图中没有这个步骤 |
| 间接影响分析 | substep | 命宫外星曜对命宫的间接影响 | POC-1 图中没有这个步骤 |

### 2.2 改进二：知识内容嵌入提示

POC-1 的知识指针只指向文件路径，但文件可能不存在。POC-2 改为**在提示 JSON 中直接嵌入知识内容**——每个"意识"节点不仅有指针，还有 `knowledge_content` 字段，包含该意识的核心知识摘要。

这样即使 study-notes 文件不存在，AI 也有足够的知识支撑来做判断。

### 2.3 改进三：审计要求（63 号文档八延伸）

提示 JSON 中增加 `audit_requirement` 字段，要求 AI 输出**两个配对文件**：

**文件一：结果文件**（命理分析结论）——和 POC-1 一样

**文件二：审计文件**（对依赖图覆盖完备性的自证）——新增

审计文件必须包含：
- **节点覆盖表**：逐节点列出是否处理、上下文、中间结论
- **边覆盖表**：逐边列出是否沿其思考、推理过程
- **环路处理表**：逐环路列出类型识别、走了几圈、上下文变化
- **完备性声明**：全部覆盖 / 有未覆盖项（列出并说明原因）

## 3. 验证命题

### 3.1 POC-2 验证的命题

### 3.2 与 POC-1 命题的区别

| | POC-1 | POC-2 |
|---|---|---|
| 依赖图大小 | 5 节点 | 12 节点 |

| 审计机制 | 无 | 配对审计文件 |
| 成功标准 | 5 维度显著优于 | 5 维度显著优于 + 审计覆盖≥90% |

### 3.3 POC-2 不验证什么

- 不验证 12 节点是否已经足够（可能仍需扩展）
- 不验证真实星盘（仍用简化盘）
- 不验证多场景（仍只做命宫分析）
- 不验证审计文件本身的质量评判（只看覆盖完备性，不评判审计内容的命理准确性）

## 5. 知识内容嵌入

### 5.1 每个"意识"节点的 knowledge_content

POC-2 在提示 JSON 中为每个"意识"节点嵌入知识内容摘要。内容来源是 study-notes 中的实际内容，精简为关键要点。

**庙旺平陷**：
```
状态等级：殿(最强) > 垣(极强) > 庙(强) > 旺(较强) > 乐(中等偏上) > 喜(中等) > 怒(弱)
判断依据：星曜五行与宫位五行的关系。如木星在寅(木宫)同气为庙。
升殿：星曜五行与宿五行一致时为升殿，力量最强。如木星在木宿(角/斗/奎/井)升殿。
```

**升殿判断**：
```
当星曜的五行与所在宿的五行一致时，称为"升殿"，力量最强。
二十八宿五行：角/斗/奎/井=木，亢/牛/娄/鬼=金，氐/女/胃/柳=土，房/虚/昴/星=日(火)，心/危/毕/张=月(水)，尾/室/觜/翼=火，箕/壁/参/轸=水。
本命星曜所在宿：木星在尾宿(火宿)、太阳在尾宿(火宿)、月亮在心宿(月宿)、火星在尾宿(火宿)、水星在尾宿(火宿)。
```

**宿位泄气**：
```
星曜在非本五行宿位时，如果星曜五行生宿五行，则为泄气（力量消耗）。
如木星在尾宿(火宿)，木生火，为泄气。
如果星曜五行克宿五行，则为克宿（星曜与宿位不谐）。
如水星在尾宿(火宿)，水克火，为克宿。
```

**五行生克**：
```
星曜五行：日=火，月=水，木=木，火=火，土=土，金=金，水=水
宫位五行：子丑=土，寅亥=木，卯戌=火，辰酉=金，巳申=水，午=日(火)，未=月(水)
生：木生火，火生土，土生金，金生水，水生木
克：木克土，土克水，水克火，火克金，金克木
比和：星曜与宫位同五行，如木星在寅(木宫)，无损耗无制约。
```

**阴阳昼夜**：
```
昼生属阳，夜生属阴。
昼生以太阳为主、月亮为辅；夜生以月亮为主、太阳为辅。
昼生对星曜的影响：
- 太阳：昼生得时，力量增强
- 月亮：昼生失时（月喜夜），力量折损
- 木星：昼生木旺（阳木得阳助）
- 火星/水星/土星：昼生无特殊增损
```

**恩用仇难定局**：
```
以命宫地支五行为命主，其他星曜按与命主的生克关系分为四类：
恩(生我)：核心吉星，扶助命主
用(我生)：次吉，但泄命主之气
仇(克我)：核心凶星，压制命主
难(我克)：次凶，但命主能制

寅宫木命的恩用仇难：
恩(水生木)=月亮、水星
用(木生火)=太阳、火星、罗睺
仇(金克木)=金星
难(木克土)=土星、计都
```

**颠倒颠**：
```
五行生克不是简单的"生就好、克就坏"：
- 生太过反为害：命主弱时恩星太多反把命主"溺爱"坏了
- 克中有生：命主强时仇星反而是激发命主的力量（煞为权）
- 物随类化：命坐火宫则官禄也属火，喜木气生，忌水孛克
```

## 8. 评判标准

### 8.1 结果文件评分（5 维度，同 POC-1）

| 维度 | 权重 |
|---|---|
| 完整性 | 0.25 |
| 准确性 | 0.25 |
| 深度 | 0.20 |
| 逻辑性 | 0.15 |
| 结构感 | 0.15 |

### 8.2 审计文件评分（新增，3 维度）

| 维度 | 满分 | 评判标准 |
|---|---|---|
| 节点覆盖率 | 100% | 12个节点中多少被标记为"已处理"且有中间结论 |
| 边覆盖率 | 100% | 16条边中多少被标记为"已沿其思考"且有推理过程 |
| 环路处理正确性 | 100% | 螺旋环路是否被正确识别为螺旋、走了2圈、上下文变化被记录 |

### 8.3 "显著优于"的定义（修订）

B 组显著优于 A 组需要同时满足：
1. B 组结果文件综合评分比 A 组高 **0.5 分以上**
2. B 组在**至少 3 个维度**上不低于 A 组
3. B 组在**至少 2 个维度**上比 A 组高 1 分以上
4. **B 组审计文件覆盖完备性 ≥ 90%**（新增条件）

### 8.4 审计文件的额外价值

审计文件不仅用于评分，还用于**诊断**：
- 如果 B 组某个节点未覆盖 → 说明提示中该节点的引导不够强
- 如果 B 组某条边未沿其思考 → 说明该依赖关系在提示中不够显式
- 如果 B 组螺旋环路只走了 1 圈 → 说明螺旋引导不够明确

这些诊断信息直接指导后续的依赖图和提示优化。

## 9. 成功/失败定义

### 9.1 成功

B 组满足"显著优于"的全部 4 个条件（含审计覆盖≥90%）。

含义：扩展依赖图 + 知识嵌入 + 审计机制三者结合，使依赖图提示的优势在完整性和准确性上不再劣势，同时在逻辑性和结构感上保持优势，且覆盖完备性可自证。

后续行动：扩展到更多分析场景（官禄宫、格局、大限），引入真实星盘。

### 9.2 部分成功

B 组在结果评分上达到"显著优于"，但审计覆盖 < 90%。

含义：结果质量好，但 AI 没有忠实走完依赖图——结果好可能是偶然的，不是依赖图引导的。需要加强提示中的审计要求。

或者：审计覆盖 ≥ 90%，但结果评分未达到"显著优于"。

含义：AI 忠实走了依赖图，但图本身的质量不够（节点/边/知识内容有问题）。需要优化依赖图内容。

### 9.3 失败

B 组结果评分未达到"显著优于"，且审计覆盖 < 90%。

含义：扩展依赖图和审计机制都没有解决问题。需要回到 63 号文档重新审视。

## 11. 诚实声明

POC-2 仍有以下局限：

1. **仍用简化盘**：不验证真实天文数据下的表现
2. **仍只做命宫分析**：不验证多宫、格局、大限等复杂场景
3. **12 节点可能仍不够**：命宫分析的完整知识可能需要更多节点
4. **审计文件本身不被外部审计**：AI 自己写的审计是否真实反映了它的思考过程，无法独立验证——AI 可能"声称"覆盖了某节点但实际没有深入思考。这是审计机制的固有局限。
5. **A 组材料补充后可能变强**：POC-2 给 A 组也补充了阴阳昼夜等知识，A 组可能比 POC-1 更强，B 组的相对优势可能更难体现。
