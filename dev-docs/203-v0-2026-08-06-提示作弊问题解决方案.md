## 文档信息

- **编号**：203

- **依赖**：200号 + leakage_audit.py + visibility_labels.py + guided_loop.py

---

## 一、问题回顾

200号文档诊断了当前系统的提示作弊成分：

1. **给知识式作弊**：5条硬编码提示中2条直接给了数学事实（如`ex(n,C_4)=O(n^{3/2})`）
2. **无泄漏审计**：leakage_audit.py已实现四门审计，但GuidedLoop未调用
3. **无truth_vault隔离**：visibility_labels.py已定义角色隔离，但GuidedLoop未使用
4. **无增益归因**：未记录提示的增益来源（思路/知识/答案等价信息）
5. **无诚实降级实验**：未验证"去掉答案等价信息后增益是否消失"

---

## 二、能不能解决？

**能解决，分三个层次：**

| 层次 | 问题 | 能否解决 | 解决方式 |
|---|---|---|---|
| 层次1 | 提示含具体数学知识 | **能完全解决** | 提示分级+泄漏审计拦截 |
| 层次2 | 无truth_vault隔离 | **能完全解决** | GuidedLoop连接visibility_labels |
| 层次3 | "给思路算不算作弊" | **不能完全解决，但能量化** | 诚实降级实验测量增益来源 |

**关键判断**：层次1和2是工程问题——代码已有，只需连接。层次3是科学问题——需要实验测量，不能靠推理回答。

---

## 三、能在多大程度上解决？

### 3.1 层次1——提示分级+泄漏审计（解决程度：90%）

**已有基础**：
- `leakage_audit.py`已实现四门审计（字面匹配/等价映射/候选空间缩减/盲恢复）
- `leakage_audit.py:65`已定义G0-4阈值=0.3
- `leakage_audit.py:124-179`的`run_four_gates()`方法可直接调用

**需要做的**：
1. 在GuidedLoop的`_generate_hint()`中，提示发出前调用`run_four_gates()`
2. 如果四门中任何一门FAIL，提示被拒绝，重新生成
3. 提示分级标注：knowledge/strategy/meta，记录到guided_loop_result.json

**解决程度**：90%——四门审计能拦截绝大多数泄漏。剩余10%是"等价映射"的精度问题（当前`_gate2_equivalence_mapping`用的是硬编码forbidden_patterns，需要更智能的等价检测）。

### 3.2 层次2——truth_vault隔离（解决程度：100%）

**已有基础**：
- `visibility_labels.py:27-92`已定义14个collection的可见性矩阵
- `visibility_labels.py`中truth_vault仅auditor可读

**需要做的**：
1. GuidedLoop初始化时创建truth_vault collection
2. 答案写入truth_vault
3. Controller/Matcher/Solver的可见性标签设置`can_read_truth_vault=False`
4. 步骤10编译提示时，Controller从K维度取知识，不从truth_vault取

**解决程度**：100%——这是硬隔离，代码层面保证。

### 3.3 层次3——诚实降级实验（解决程度：测量而非解决）

**已有基础**：
- AGENTS.md核心假设第6条已声明降级条款
- GuidedLoop已能生成run并记录结果

**需要做的**：
1. 设计三组对比实验（见第五节）
2. 执行实验
3. 根据结果决定：保持/降级/不确定

**解决程度**：这不是"解决"问题，而是"测量"问题。实验结果可能告诉我们"增益确实来自答案等价信息"——这时系统降级为编译器，这不算"解决"但算"诚实"。

## 四、是否需要连续POC验证？

**需要。三个层次都需要POC验证，但验证方式不同：**

| 层次 | POC类型 | 验证内容 | 预期轮次 |
|---|---|---|---|
| 层次1 | 单元测试 | 四门审计能否拦截已知的泄漏提示 | 1轮 |
| 层次2 | 集成测试 | GuidedLoop连接truth_vault后角色隔离是否生效 | 1轮 |
| 层次3 | 对比实验 | 三组实验的增益差异 | 3-5轮（需要足够样本） |

## 五、具体实施步骤

### 5.1 Phase 203-A：提示分级+泄漏审计（1轮POC）

**步骤A1**：在`guided_loop.py`中引入提示分级

```python
# 提示分级
HINT_LEVELS = {
    "knowledge": "给具体数学事实",
    "strategy": "给解题方向/方法选择",
    "meta": "给元提示（继续/更详细）",
}
```

**步骤A2**：在`_generate_hint()`中调用`run_four_gates()`

```python
from ..heuristics.leakage_audit import AnswerEquivalenceAuditor

auditor = AnswerEquivalenceAuditor()
four_gates = auditor.run_four_gates(hint, task)
if four_gates["overall_result"] == "fail":
    # 提示被拒绝，降级为meta级提示
    hint = "请继续深入分析。"
```

**步骤A3**：记录提示级别和审计结果到`guided_loop_result.json`

**步骤A4**：POC验证——用5个已有run回测，检查四门审计能否拦截已知的泄漏提示

### 5.2 Phase 203-B：truth_vault隔离（1轮POC）

**步骤B1**：GuidedLoop初始化时创建truth_vault

**步骤B2**：答案写入truth_vault（对于有标准答案的问题）

**步骤B3**：Controller编译提示时强制检查可见性标签

**步骤B4**：POC验证——检查truth_vault是否被非auditor角色访问

### 5.3 Phase 203-C：诚实降级实验（3-5轮POC）

**步骤C1**：设计三组实验

| 实验组 | 提示内容 | 验证什么 |
|---|---|---|
| A组（对照） | 无提示 | 基线表现 |
| B组（完整） | 完整提示（knowledge+strategy+meta） | 完整引导的效果 |
| C组（去知识） | 只保留strategy+meta提示 | 去掉答案等价信息后的效果 |

**步骤C2**：每组用5-10个问题运行GuidedLoop

**步骤C3**：比较三组的完成率、turn数、提示有效率

**步骤C4**：判断：
- C≈A → 增益主要来自知识 → 降级为编译器
- C≈B → 增益主要来自策略 → 不是作弊
- A < C < B → 部分来自策略，部分来自知识 → 需要进一步细分
