## 1. 问题定义

### 1.1 为什么要找这种题

本项目的核心假设（123号§DYN-0）是：

> 在部分问题族和研究状态上，**确定性结构计算+AI引导**能选择一个低成本、低泄漏、能增加已验证进展的最小干预。

要验证这个假设，必须找到**裸devin cli做不出来、但加了系统引导后能做出来**的题。如果题本身裸devin就能做，系统引导的增益无法体现（209号205-E实验已经看到：简单题裸devin也能做）。

### 1.2 "裸devin cli做不出来"的判定标准

不是"AI答不对"——任何AI都可能因为随机性答不对。真正的判定标准是：

| 维度 | 判定 |
|------|------|
| **正确性** | 裸devin cli给出的证明/解答在数学上是错的或不完整 |
| **稳定性** | 多次运行（≥3次）都做不对——不是偶然失败 |
| **卡点类型** | 卡在"不知道该用什么工具/方向"而非"计算错误"——后者是能力问题，不是引导能解决的 |
| **可引导性** | 卡点类型属于系统能给提示的范畴（lack_knowledge/uncertain/strategy_exhaustion），不是"需要全新数学发现" |

**关键区分**：
- "裸devin做不出来"≠"人类也做不出来"——我们找的是**AI能力边界内的题，但需要正确的方向引导**
- 不是找最难的题（如千禧年难题）——那些人类也没做出来，系统引导也没用
- 是找**AI有知识储备但不知道该调用什么**的题

## 2. 选题策略——三层漏斗

### 第一层：从已有题库中筛选候选

项目已有4个难题集，按"裸devin可能做不出来"的概率排序：

| 题源 | 路径 | 特征 | 候选概率 |
|------|------|------|----------|
| **Schweitzer竞赛** | `knowledge/competitions/hardest/Schweitzer/` | 研究级、开放书卷、10天考试、需研究生知识 | **高**——最接近"需要方向引导" |
| **Putnam A6/B6** | `knowledge/competitions/hardest/Putnam_A6_B6/` | 每场最难两题、需巧妙构造 | **中高**——需要非显然的构造 |
| **IMO Shortlist N6/G8等** | `knowledge/competitions/hardest/IMO_Shortlist/` | 难度5题、需要特殊技巧(如Vieta jumping) | **中**——技巧性强，AI可能见过 |
| **Arnold Trivium** | `knowledge/mathematicians/Arnold/trivium_100.md` | 计算型、考察直觉 | **低**——多数是计算题，AI擅长 |

**推荐**：优先从Schweitzer和Putnam A6/B6中选——这两类题需要"知道该用什么高级工具"，正是引导能发力的地方。

### 第二层：裸devin cli baseline测试

对第一层筛出的候选题，跑**裸devin cli baseline**（无系统引导，直接给devin cli做题）：

1. 每题跑**3次**（稳定性判定）
2. 用`/data/math-agent-glm5.2-{1,2,3}`三个Solver工作目录（AGENTS.md硬约束5）
3. 判定标准：
   - 3次全错/不完整 → **入选**（裸devin做不出来）
   - 3次中1次对 → **边缘**（需扩大样本到5次）
   - 3次全对 → **淘汰**（裸devin能做，不需要引导）

4. 验证标准：用`auto_audit_report`判定正确性，不能只看"AI说自己做对了"

### 第三层：卡点类型分析

对第二层入选的题，分析裸devin的**卡点类型**：

- 卡在"不知道用什么工具" → **适合系统引导**（入选实验组）
- 卡在"计算错误" → 不适合引导（是能力问题）
- 卡在"需要全新概念" → 不适合引导（超出系统知识库）

分析方法：看裸devin的response内容，用205-A的AI诊断分类：
- `lack_knowledge` → 适合（系统可以给知识候选）
- `uncertain` → 适合（系统可以给方向验证）
- `strategy_exhaustion` → 适合（系统可以给新策略）
- `response_too_short` + 内容空洞 → 不适合（能力问题）

## 3. 具体执行方案

### Phase 1: 候选题筛选（从题库中选10-15题）

从Schweitzer和Putnam A6/B6中按以下标准选：

1. **知识门槛高**：需要研究生水平工具（如测度论、表示论、代数拓扑）
2. **有明确正确答案**：能判定对错（不是开放问题）
3. **卡点可引导**：卡在"方向"而非"计算"
4. **领域多样**：覆盖代数/分析/组合/几何/数论，避免单一领域偏置

### Phase 2: 裸devin baseline测试（10-15题 × 3次 = 30-45次运行）

```
对每道候选题:
  for solver_dir in [math-agent-glm5.2-1, -2, -3]:
    裸devin cli做题（无系统引导）
    auto_audit判定正确性
  if 3次全错/不完整:
    入选实验组
  elif 3次中1次对:
    再跑2次（共5次），多数错则入选
  else:
    淘汰
```

**预算估计**：每次devin cli运行约2-5分钟（根据complex_001-005的经验），30-45次约1.5-4小时。

### Phase 3: 卡点分析（对入选题，5-10题）

分析裸devin的response，判定卡点类型是否适合引导。

### Phase 4: 系统引导对比实验（对最终入选题，3-5题）

对最终入选的题，跑**有系统引导**的版本（GuidedLoop），对比：
- 裸devin: 3次全错
- 系统引导: 是否能做对？（209号205-E已验证引导提示更针对性）

## 4. 风险与边界

### 4.1 可能的风险

| 风险 | 应对 |
|------|------|
| 裸devin对Schweitzer题全做对（AI训练数据可能包含） | 退到Putnam A6/B6，或找更新的Schweitzer题（2020年后） |
| 裸devin对所有题全做错（题太难） | 降低难度，退到Putnam A1-A5或IMO Shortlist难度4题 |
| 入选题太少（<3题） | 扩大候选池，或降低"做不出来"的判定门槛（从3次全错降到2次错） |
| 系统引导也做不对 | 这是有效结果——说明当前系统引导能力不足，需迭代 |

### 4.2 不做什么

- **不找千禧年难题级别的题**——人类也没做出来，验证不了系统价值
- **不找纯计算题**——AI计算能力已经很强，引导帮不上
- **不找AI训练数据必然包含的经典题**——如费马小定理（complex_005已验证裸devin能做）
- **不找开放性研究问题**——无法判定对错

## 5. 推荐方案

### 推荐：从Schweitzer 2020-2023年题开始

**理由**：
1. Schweitzer题是研究级难度，最可能卡在"方向"而非"计算"
2. 2020年后的题不太可能在AI训练数据中被详细解答
3. 开放书卷设计意味着这些题**允许查资料**——但裸devin cli禁止web_search（AGENTS.md硬约束5），所以正好测试"没有外部知识检索时的能力边界"
4. 项目已有Schweitzer题库（`knowledge/competitions/hardest/Schweitzer/`），不用从零收集

**备选**：如果Schweitzer题裸devin全做对，退到Putnam 2023-2024 A6/B6。

### 执行顺序

1. **先读Schweitzer题库**，选5道知识门槛高、有明确答案的题
2. **跑裸devin baseline**（5题×3次=15次运行）
3. **分析卡点类型**，筛出3道适合引导的题
4. **跑系统引导对比**（3题×3次=9次运行）
5. **落盘实验报告**
