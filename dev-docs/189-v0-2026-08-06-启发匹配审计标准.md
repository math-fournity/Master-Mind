## 一、模块功能概览

heuristics子系统负责从状态匹配启发规则、管理规则生命周期、审计答案泄漏、设计激活包。

| 模块 | 功能 |
|---|---|
| matcher | 启发匹配器，根据状态和事件窗口匹配规则，输出候选动作排序 |
| rule_store | 规则存储与生命周期管理（candidate→validated→published→retired） |
| rule_extractor | 从分叉点抽取候选规则的LHS/interface/RHS/guard/eta |
| leakage_audit | 答案泄漏代理四门审计（字面/等价/候选空间缩减/盲审者恢复） |
| activation_packet | 设计H0/H1/H2三级激活包，检测答案等价内容 |
| state_aligner | 对齐多个成功/失败运行，找共同状态和关键分叉点 |
| sparse_view | H图稀疏表示，计算候选激活分数a_t = W^T * p_t |
| models | HeuristicRule schema定义和生命周期状态枚举 |

## 二、审计检查项

### 2.1 规则匹配正确性（matcher.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 只用published规则 | 在线运行时只匹配published规则 | candidate/validated/retired规则不参与在线匹配 |
| 角色隔离验证 | match()入口强制调用角色隔离检查 | 未通过角色隔离验证时拒绝执行 |
| 不可见truth_vault | matcher不能访问truth_vault | 无truth_vault读取操作 |
| 离线模式不注入 | 离线模式只生成候选激活包，不实际注入提示 | MatcherOutput中只有候选，无注入动作 |
| 动作排序合理 | 候选动作按相关性和效果排序 | 排序基于激活分数a_t，不是随机 |

**判定**：通过=5项全通过；有缺陷=排序有小问题但规则筛选正确；失败=匹配了candidate规则或角色隔离失效或访问了truth_vault

### 2.2 规则生命周期管理（rule_store.py + models.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| candidate禁止在线提示 | candidate规则不能用于在线自动提示 | 在线运行时加载规则时过滤掉candidate |
| candidate→validated条件 | 需DYN-3因果实验通过+泄漏门通过 | 两个条件都满足才转移 |
| validated→published条件 | 需DYN-5跨3问题族+2模型版本复现 | 复现条件满足才转移 |
| 字段完整 | applicable_domains/model_versions/failure_cases/effect_evidence全部填充 | 4个字段都有非空值 |
| 状态枚举隔离 | HeuristicRule.status和Evidence.status用不同枚举类型 | 不混用枚举 |
| 审计记录 | 状态转移有审计记录 | 每次转移记录时间/条件/操作者 |

**判定**：通过=6项全通过；有缺陷=字段不完整但状态转移正确；失败=candidate规则被在线使用或状态转移条件不满足

### 2.3 答案泄漏审计（leakage_audit.py + activation_packet.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 四门全执行 | 字面匹配/等价映射/候选空间缩减/盲审者恢复全部执行 | 不允许只跑一门 |
| 代理分数 | 使用代理分数而非互信息 | 输出是代理分数 |
| 不掩盖高泄漏 | 不能用总分掩盖单门高泄漏 | 任一门超阈值就失败，不看总分 |
| 答案等价检测 | 激活包检测答案等价内容 | 检测到答案等价内容时标记为禁止级别 |
| 阈值验证 | 泄漏代理分数低于G0-4阈值 | 每门分数都低于对应阈值 |
| truth_vault权限 | 只有Auditor可读truth_vault | 非Auditor角色不能访问 |

**判定**：通过=6项全通过；有缺陷=四门执行但阈值设置不当；失败=漏执行门或泄漏超阈值或truth_vault被越权访问

### 2.4 激活包设计（activation_packet.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| H0/H1/H2分级 | 元检查/思维操作/概念工具候选分别对应H0/H1/H2 | 级别标注正确 |
| 不含目标结论 | 激活包不直接把目标结论加入V_t | 激活包内容是提示不是答案 |
| 禁止答案等价 | 激活包不含答案等价内容 | 检测到答案等价内容时拒绝 |

**判定**：通过=3项全通过；失败=激活包包含目标结论或答案等价内容

### 2.5 规则抽取质量（rule_extractor.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| LHS准确性 | 抽取的匹配模式准确反映分叉点特征 | LHS匹配的分叉点特征与实际一致 |
| RHS不写V_t | RHS不能直接写入V_t | RHS只提出候选状态扩展，真正写入需Reducer+Verifier |
| 模式匹配返回值 | 返回被匹配实体、字段约束和时间窗口 | 3个返回值都存在 |
| 默认candidate | 新抽取的规则默认status=candidate | status初始值为candidate |

**判定**：通过=4项全通过；有缺陷=LHS有小偏差但RHS正确；失败=RHS直接写入V_t或模式匹配返回值缺失

### 2.6 状态对齐（state_aligner.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 按内容哈希对齐 | 不按序号对齐，按内容哈希checkpoint对齐 | 对齐基于内容哈希 |
| 状态缺失处理 | 状态字段缺失需标记但不阻断对齐 | 缺失字段标记为missing，不报错 |
| 无共同状态 | 返回空列表 | 无共同状态时返回[]，不报错 |
| 无分叉点 | 返回None | 无分叉点时返回None，不报错 |
| checkpoint完整 | 包含Q_0/事件前缀/模型/工具/权限/预算/版本哈希 | 7个哈希字段都存在 |

**判定**：通过=5项全通过；有缺陷=对齐正确但checkpoint不完整；失败=按序号对齐或缺失字段导致报错

### 2.7 稀疏视图（sparse_view.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| H是计算视图 | H不是真值本体，是计算视图 | 不把H图当作知识库 |
| 多元关系 | 不把多元关系压成二元矩阵 | 使用incidence matrix不用邻接矩阵 |
| 条件因子不物化 | 条件因子不物化为独立节点 | 条件因子是规则的一部分，不是独立节点 |
| 7种数值 | 干预效果后验/证据运行数/迁移范围/泄漏风险/模型适用性/提示成本/历史副作用 | 7种数值都记录 |
| 不直接宣告正确 | 稀疏计算不能直接宣告Hint正确 | 激活分数只是候选排序依据，不是正确性保证 |

**判定**：通过=5项全通过；有缺陷=数值记录不全但视图性质正确；失败=把H当真值本体或条件因子物化或用邻接矩阵
