## 二、审计发现：5项需修正的实现偏差

### 偏差1：MatcherAction动作集合不完整

**三文件要求**：
- 123号§485-497冻结了9个完整动作：`continue_observing / ask_diagnostic_question / request_tool_check / retrieve_minimal_interface / inject_hint_0 / inject_hint_1 / inject_hint_2 / abstain / stop_or_escalate`
- 系统探讨.md第1588-1598行：只生成当前卡点+一个最小思维操作+必要知识接口+可选工具

**实现偏差**：原实现只有5个动作（CONTINUE_OBSERVING / ASK_DIAGNOSTIC / REQUEST_TOOL / ABSTAIN / CANDIDATE_ACTIVATION），缺少4个动作，且CANDIDATE_ACTIVATION不是123号定义的动作。

**修正**：补全为9个动作，inject_hint_0/1/2在离线模式下标注`offline_only=True`。

### 偏差2：checkpoint定义不完整

**三文件要求**：
- 123号§847冻结定义：`checkpoint = 序列化(Q_0/W_t, 关键事件前缀, 模型/工具/权限/预算, 版本哈希)`
- 123号§847：checkpoint不包含、也不能冻结LLM隐藏内部状态
- 123号§847：同一内容哈希checkpoint视为阻断/分层变量

**实现偏差**：原Checkpoint只有checkpoint_id/run_id/step_index/state_snapshot/timestamp，缺少Q_0、事件前缀、模型版本、工具版本、权限、预算、版本哈希7个字段。

**修正**：Checkpoint dataclass补全7个字段，compute_state_hash将这7个字段纳入哈希计算，record_checkpoints从state中提取这些字段。

### 偏差3：角色可见性未落实为visibility label和能力令牌

**三文件要求**：
- 123号§607：`这些边界要落实为collection、visibility label和能力令牌，而不是只写在角色prompt里`
- 123号§596-606：Heuristic Matcher可见性矩阵（局部模式/模型预算/规则效果/泄漏副作用可见；Truth Vault不可见；不能自动发布candidate）
- 系统探讨.md第1420-1446行：Heuristic Activation Engine不应直接看到Truth Curator保存的最终答案文本

**实现偏差**：原实现只有VISIBLE_COLLECTIONS和INVISIBLE_COLLECTIONS两个集合，没有visibility label和能力令牌的运行时检查机制。

**修正**：添加VISIBILITY_LABELS（8个标签）和CAPABILITY_TOKENS（6个令牌），添加check_visibility_label()和check_capability_token()运行时检查方法。

### 偏差4：稀疏计算未实现a_t=W^T*p_t公式

**三文件要求**：
- 系统探讨.md§10.4（第1943-1967行）：`a_t = W_{C,F,τ}^T * p_t`
- 系统探讨.md第1943-1967行：矩阵中的值不应只是0/1，而应包含7种数值（因果成功提升、证据次数、迁移范围、泄漏风险、模型适用性、提示成本、副作用）
- 123号§25（第554-562行）：H首版使用规则—条件—动作incidence/factor视图
- 123号§564：稀疏计算负责候选生成和排序，不能越过原始证据与发布状态直接宣告某Hint正确

**实现偏差**：原SparseViewBuilder只构建incidence matrix，没有实现a_t=W^T*p_t的稀疏计算公式，没有用7种数值组合作为权重。

**修正**：添加compute_activation_scores()方法，实现a_t=W^T*p_t公式，用RuleNumerics的7种数值组合作为权重，明确标注is_computation_view/no_direct_truth_claim。

### 偏差5：Agent依赖代理完全缺失

**三文件要求**：
- 123号§530：`Agent依赖代理至少包括：撤掉Hint后的独立继续率、同类后续状态再次求助率和单位已验证进展所需帮助量`
- 123号§510-516：多目标策略公式中的`D̂_dependence`就是Agent依赖代理
- 123号§23：`不能用一个总分掩盖高泄漏`——同理，不能用一个总分掩盖高依赖

**实现偏差**：原leakage_audit.py只有答案泄漏代理（AnswerEquivalenceAuditor + LeakageAuditor），完全没有Agent依赖代理。

**修正**：新增AgentDependencyProxy类，实现3个代理测量方法（measure_independent_continuation_rate / measure_re_assistance_rate / measure_help_per_verified_progress）+ measure_all_proxies()。Phase 3只做接口定义和占位实现，完整测量需要Phase 4/5在线实验数据。
