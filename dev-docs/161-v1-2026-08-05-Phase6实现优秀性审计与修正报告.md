## 一、审计方法论

### 1.1 三文件演进关系

三个文件存在大致的演进关系，但不是绝对的：

| 文件 | 性质 | 权威性来源 |
|---|---|---|
| `系统探讨.md` | 用户与AI的原始对话母本 | 第一性需求来源，只读 |
| `plan-dad3347dc4d8e542.md` | Devin plan文件 | 架构裁决的中间产物 |
| `123-v1` | 正式架构基线文档 | 最终权威架构基线 |

### 1.2 冲突裁决原则

当三文件存在冲突时，按以下原则裁决：

1. **123号是最权威架构基线**——它是正式落盘文档，经过完整crosswalk验证
2. **系统探讨.md是原始需求母本**——它的每一行都必须被覆盖，但严格化裁决以123号为准
3. **plan是中间产物**——它的裁决已被123号吸收或超越，当与123号冲突时以123号为准

### 1.3 审计维度

逐项检查Phase 6的11个模块是否满足三个文件中的：
- 硬性约束（防线、出口门、预注册门）
- 角色可见性边界（123号§28）
- 冻结纪律（123号§44）
- 风险防线（123号§56-57新增风险）

## 二、审计发现与修正清单

### 2.1 P6-1 published_loader.py：G0-5"未参与设计"问题族验证缺失

**发现**：G0-5验证只检查`applicable_domains`数量≥3，但123号§44明确要求"published通用规则至少跨3个**未参与设计**的问题族和2个模型版本复现"。如果3个applicable_domains全部参与了规则设计，仍然不满足G0-5。

**依据**：
- 123号§44："published通用规则至少跨3个未参与设计的问题族和2个模型版本复现"
- 系统探讨.md无直接对应，但123号是对原文的严格化

**修正**：
- `HeuristicRule`增加`design_participation_domains`字段
- `_validate_published_standard`方法改为计算`non_design_domains = applicable_domains - design_participation_domains`
- G0-5验证：`n_non_design >= 3`（不只是`n_applicable_domains >= 3`）

**文件**：`heuristics/models.py`、`runtime/published_loader.py`

### 2.2 P6-2 controller.py：控制器信念完整性

**发现**：9种动作完整（含continue_observing/ask_diagnostic_question/abstain/stop_or_escalate），missing_info_estimate字段存在，不确定估计基于公开产物。**无需修正**。

**依据**：123号§22"不给提示也是动作"、系统探讨.md§15.1"外显轨迹不是隐藏思维"

### 2.3 P6-3 budget.py + dependency.py：预注册门职责归属

**发现**：预注册门（δ、样本量、排除标准、CI方法）是策略π的职责，不是budget的职责。budget只负责5种预算执行约束。**无需修正**。

### 2.4 P6-4 error_recovery.py：checkpoint不代表隐藏状态

**发现**：123号§847明确要求"checkpoint不包含、也不能冻结LLM隐藏内部状态。即使温度为0，多个继续运行也可能非确定"。原实现缺少这个关键警告。

**依据**：123号§847（DYN-3定义）

**修正**：
- `verify_checkpoint_7_fields`方法docstring补入123号§847关键警告
- 返回结果增加3个字段：`checkpoint_excludes_hidden_state`、`non_determinism_acknowledged`、`layered_variable_not_identity`

**文件**：`runtime/error_recovery.py`

### 2.5 P6-5 model_layering.py：R-14防线"不同模型版本"验证

**发现**：`r14_defense: len(effects) > 1`只检查效果记录数>1，但123号§57要求"规则效果被单一模型版本绑架"——需要验证效果来自**不同的模型版本**。如果2条效果记录都来自同一模型版本，仍然是被绑架。

**依据**：123号§57新增风险"规则效果被单一模型版本绑架"

**修正**：
- `get_layered_effects`方法改为计算`model_versions_present`集合
- R-14验证：`n_distinct_versions > 1`（不只是`n_effects > 1`）
- 增加`r14_not_single_model_bound`字段

**文件**：`runtime/model_layering.py`

### 2.6 P6-6 gaming_detector.py：结构进展度量+隐蔽gaming

**发现**：
1. 结构进展度量只检查4种变化（nodes/edges/open_obligations/obligation_status），但123号§15工作区W_t=(V_t, F_t, O_t, R_t, D_t, E_t)有6个分量，缺少F_t（猜想前沿）和E_t（证据）变化
2. 缺少隐蔽gaming检测——Agent可能不直接说"我不知道"，而是反复输出无实质内容的填充文本

**依据**：123号§15工作区定义、123号§57新增风险

**修正**（subagent执行）：
- `measure_structural_progress`增加F_t（conjecture_frontier）和E_t（evidence）维度
- 新增`detect_subtle_gaming`方法检测重复性无实质内容输出
- `detect`方法增加`gaming_type`字段区分explicit_gaming/subtle_gaming/none

**文件**：`runtime/gaming_detector.py`

### 2.7 P6-7 long_term_attribution.py：反事实估计梯度+不确定度

**发现**：
1. `full_attribution`接口可能因`record_hint_chain`返回值被误用而产生warnings
2. 反事实估计用二值判断（≥50%完全否定），不符合系统探讨.md§15.2"观察到差异不等于因果"的干预要求
3. 缺少`attribution_uncertainty`字段

**依据**：系统探讨.md§15.2、123号§57"长程信用错误地归给最近一次提示"

**修正**（subagent执行）：
- `record_hint_chain`增加幂等性检查
- `full_attribution`改用`get_hint_chain()`获取已记录chain
- 反事实估计改为三级梯度：>70%强反事实、50-70%中等（降置信度）、≤50%归信用
- 增加`attribution_uncertainty`（high/medium/low）和`counterfactual_strength`字段

**文件**：`runtime/long_term_attribution.py`

### 2.8 P6-8 reactive_fallback.py：主动导航发布门

**发现**：123号§22明确要求主动导航必须等待发布门——"原题重复+跨题+跨模型+低泄漏+低副作用"全部通过。原实现只有3项判定（收益+独立性+泄漏），缺少5项发布门验证。

**依据**：123号§22、系统探讨.md§13

**修正**：
- 新增`verify_proactive_publishing_gate`方法
- 5项发布门：original_problem_repeated、cross_problem_transfer、cross_model_validated、low_leakage、low_side_effects
- 增加`no_single_success_bypass`字段——单次在线成功不能绕过发布门

**文件**：`runtime/reactive_fallback.py`

### 2.9 P6-9 policy_pi.py：λ冻结机制+预注册门

**发现**：`lambdas_frozen: True`只是声明性的，没有实际的冻结机制。123号§44明确要求"阈值不能在看完结果后补写。每个DYN protocol先用独立pilot估计方差，再冻结最小实际效应δ、样本量、排除标准和区间估计方法。具体阈值若调整，必须产生新protocol版本，不能回改历史。"

**依据**：123号§44冻结纪律

**修正**：
- `PolicyPiConfig`增加`frozen`、`frozen_at`字段和`freeze()`方法
- 增加`bump_version()`方法——冻结后修改λ必须创建新版本，旧版本不可回改
- 增加预注册门4字段：`pre_registered_delta`、`pre_registered_sample_size`、`pre_registered_exclusion_criteria`、`pre_registered_ci_method`
- `verify_p6_9_1_compliance`验证实际冻结状态和预注册门完整性

**文件**：`runtime/policy_pi.py`

### 2.10 P6-ROLE orchestrator.py：CapabilityToken强制执行

**发现**：123号§28明确要求"这些边界要落实为collection、visibility label和**能力令牌（capability token）**，而不是只写在角色prompt里"。原实现`verify_8_role_contracts`只返回静态dict描述，没有实际的CapabilityToken类来强制执行可见性边界。

**依据**：123号§28角色可见性矩阵

**修正**：
- 新增`CapabilityToken` dataclass——包含role_name、visible/invisible_collections、5个动作权限布尔值
- 新增`_build_role_tokens()`构建8角色的CapabilityToken
- 新增`get_role_token()`和`enforce_role_access()`方法——运行时强制执行权限检查
- 违反权限→抛出`PermissionError`（运行时强制阻断）
- `verify_8_role_contracts`增加8项权限约束验证
- `verify_p6_role_compliance`验证`capability_token_enforced`

**文件**：`runtime/orchestrator.py`

### 2.11 P6-EXIT test_phase6.py：预注册门不可回改

**发现**：P6-EXIT只验证3项（长期收益/泄漏/误触发），缺少123号§44的预注册门验证。

**依据**：123号§44

**修正**：
- 新增P6-EXIT-4测试项：预注册门不可回改
- 测试`PolicyPiConfig.freeze()`、`bump_version()`和4个预注册门字段
- 验证旧版本保持冻结状态（不可回改历史）

**文件**：`runtime/test_phase6.py`

## 四、审计结论

### 4.1 实现优秀性评估

Phase 6的11个模块在修正前已经实现了136号Check List的全部功能要求，但在以下方面存在实现深度不足：

| 维度 | 修正前 | 修正后 |
|---|---|---|
| G0-5验证 | 只检查数量≥3 | 检查"未参与设计"问题族≥3 |
| R-14防线 | 只检查效果记录数>1 | 检查不同模型版本数>1 |
| checkpoint警告 | 缺少隐藏状态警告 | 补入123号§847完整警告 |
| 结构进展度量 | 4维（V/O/R/D） | 6维（V/F/O/R/D/E） |
| 隐蔽gaming | 未检测 | 检测重复性无实质内容输出 |
| 反事实估计 | 二值判断 | 三级梯度+不确定度 |
| 主动导航发布门 | 3项判定 | 3项判定+5项发布门 |
| λ冻结 | 声明性 | 实际冻结机制+bump_version |
| 预注册门 | 未实现 | 4字段+不可回改验证 |
| CapabilityToken | 静态dict描述 | 运行时PermissionError强制 |

### 4.2 三文件冲突裁决记录

本次审计中未发现三文件之间的实质性冲突。三个文件的关系是严格化递进：

1. **系统探讨.md**提出"需要工具证据和结构进展，而不是只相信自报"（§15.4）
2. **plan**严格化为"检测自报停滞与工具/结构进展的不一致"（风险4）
3. **123号**进一步严格化为"限制奖励性帮助"（§57）+工作区6分量定义（§15）

Phase 6的修正按照这个递进关系，以123号为最终权威进行严格化。

### 4.3 仍需关注的待验证项

以下项不是Phase 6的实现缺陷，而是123号明确标注为"待验证"的架构级假设：

1. **DYN-0事件捕获真实性**——Phase 6实现了事件捕获接口，但真实性需DYN-0实验验证
2. **DYN-1状态重建一致性**——Phase 6实现了状态归约，但Krippendorff α≥0.80需实验验证
3. **DYN-3最小干预效应**——Phase 6实现了策略π，但效应区间下界>0需实验验证
4. **DYN-5跨题跨模型迁移**——Phase 6实现了模型版本分层，但跨3个未参与设计的问题族需实验验证

这些待验证项不应在Phase 6代码中预判结果，而应在后续DYN实验中独立验证。
