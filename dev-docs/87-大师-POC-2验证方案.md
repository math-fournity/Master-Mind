## 2. 题目

### 2.1 题面

已知 $a_1, a_2, \ldots, a_n$ 为实数，且
$$\sum a_i = n, \quad \sum a_i^2 = 2n, \quad \sum a_i^3 = 3n$$

**(2)** 证明存在常数 $C_2 > 0$ 使得
$$\max\{a_1,\ldots,a_n\} - \min\{a_1,\ldots,a_n\} \ge \sqrt{5} + C_2 n^{-3/2}$$

### 2.2 证明思路概要

第二问的完整证明需要以下研究级技巧：

1. **紧性归约**：把问题归约到有限维紧集上的极值问题
2. **投影到根**：把变量投影到 $q(x) = x^2 + x - 1$ 的根 $r, s$ 附近
3. **稳定性方程**：在极值构型附近做扰动分析，得到稳定性方程
4. **badly approximable 性质**：利用 $\sqrt{5}$ 是二次无理数，其连分数展开周期性导致 badly approximable 性质
5. **柯西不等式**：结合稳定性方程和 badly approximable 性质，得到 $n^{-3/2}$ 量级的下界

**关键数学意识**：
- **局部-全局思维**：从局部扰动（稳定性方程）到全局下界（极差）
- **逼近论思维**：badly approximable 性质是逼近论中的核心概念
- **不变量思维**：矩恒等式在扰动下保持——这是 POC-1 已验证的意识

## 3. 七步骤工作流设计

### 步骤1：依赖图解析（代码）

- **输入**：数学依赖图 JSON（手动构建的 15-20 节点图）
- **输出**：ArangoDB 中的 `dependency_graph`（dg_nodes + dg_edges + loops + kcs）
- **执行者**：代码（`import_math_graph_to_arangodb.py`，待编写）
- **性质**：纯数学，不涉及 AI

### 步骤2：展开图拓扑规划（meta AI）

- **输入**：ArangoDB 中的 `dependency_graph`
- **输出**：ArangoDB 中的 `unfold_topo`（G'_topo）
- **执行者**：meta AI（独立 subagent）
- **性质**：纯拓扑规划，不涉及数学知识内容
- **内容**：
  - 读取 ArangoDB 中的 dependency_graph
  - 为每个节点规划其在文字展开中的位置（section/段落）
  - 为每条边规划其在文字展开中的连接方式
  - 保持螺旋环路圈数
  - 输出 G'_topo JSON，写入 ArangoDB

### 步骤3：拓扑覆盖验证（代码）

- **输入**：ArangoDB 中的 `dependency_graph` 和 `unfold_topo`
- **输出**：拓扑覆盖验证报告
- **执行者**：TopologyVerifier 代码（已复制，零修改）
- **性质**：纯数学，确定性
- **验证**：节点覆盖、边覆盖、螺旋环路圈数保持
- **预期**：1 次通过，100% 覆盖

### 步骤4：按 G'_topo 转译（normal AI）

- **输入**：ArangoDB 中的 `dependency_graph` 和 `unfold_topo`
- **输出**：ArangoDB 中的 `unfold_full`（G'，含文字）+ 大师提示词文档
- **执行者**：normal AI（独立 subagent，不是步骤2的 meta AI）
- **性质**：数学知识，文字生成
- **内容**：按 G'_topo 结构逐节点填充数学文字，逐边填充连接文字

### 步骤5：KC 忠实审计（meta AI）

- **输入**：ArangoDB 中的 `dependency_graph`、`unfold_full`、`kcs`
- **输出**：KC 忠实审计报告
- **执行者**：meta AI（独立 subagent，不是步骤4的 normal AI）
- **性质**：数学知识验证，只做 1 次
- **内容**：验证每个 uf_node 的 text_content 忠实于对应的 kc

### 步骤6：分析（normal AI）

- **输入**：ArangoDB 中的 `dependency_graph` 和 `unfold_full`（大师提示词）
- **输出**：分析结果（第二问的完整证明）
- **执行者**：normal AI（独立 subagent）
- **性质**：数学知识，文字生成
- **内容**：按 G' 的结构进行第二问的完整证明

### 步骤7：分析覆盖审计（meta AI + 代码）

- **输入**：ArangoDB 中的 `dependency_graph` 和分析结果
- **输出**：分析覆盖审计报告
- **执行者**：meta AI（独立 subagent）+ TopologyVerifier 代码
- **性质**：拓扑验证（代码）+ 数学知识验证（meta AI）

## 8. 风险与缓解

### 风险1：第二问完整证明对 AI 太难

**风险**：第二问涉及 badly approximable 等研究级技巧，AI 可能无法给出完整证明。
**缓解**：这正是 POC 的价值——如果依赖图提示能帮助 AI 做出研究级证明，那是极强的证据。如果 AI 做不出来，可以降低到"给出证明思路"而非"完整证明"。

### 风险2：依赖图节点设计不准确

**风险**：18 节点的依赖图可能遗漏关键步骤或包含不必要的节点。
**缓解**：依赖图是手动构建的，可以迭代修正。拓扑覆盖验证会精确指出哪些节点/边未覆盖。

### 风险3：subagent 写文件失败

**风险**：POC-1 中 background subagent 无法写入 /Volumes 路径。
**缓解**：使用前台 subagent（已验证可写入 /Volumes 路径）。所有 subagent 输出直接写入 ArangoDB 或 /Volumes 路径文件。

### 风险4：ArangoDB 查询性能

**风险**：18 节点 25 边的规模在 ArangoDB 中查询延迟。
**缓解**：规模远小于星学 POC-9 的 71 节点 106 边，查询延迟 < 100ms。

## 10. 诚实声明

1. **第二问的完整证明可能对 AI 太难**：badly approximable 性质的运用是研究级技巧。如果三组 AI 都做不出来，POC 的正确性维度将无法区分——但拓扑覆盖维度仍然可以验证七步骤工作流的有效性。

2. **依赖图是手动构建的**：POC 不验证依赖图能否自动构建。18 节点的设计基于对第二问证明思路的理解，可能不完全准确。

3. **B 组有 q(x) = x^2 + x - 1 的具体构造提示**：与 POC-1 相同，这给了 B 组额外优势。后续 POC 可以测试不给具体构造的情况。

4. **评分者主观性**：A 组和 B' 组的评分仍依赖盲评。但 B 组的拓扑覆盖维度是数学确定的，不依赖评分者主观判断。

5. **本 POC 是七步骤工作流在数学领域的首次验证**：如果成功，后续 POC 将全部采用七步骤工作流。
