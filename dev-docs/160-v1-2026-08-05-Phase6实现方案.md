## 1. Phase目标

Phase 6目标——**完成DYN-6（在线闭环控制器）**。

把Phase 1-5建设的离线基础设施接入在线闭环运行时：
- 只加载published规则（P6-1）
- 9种动作的在线执行（P6-2）
- 预算和帮助依赖控制（P6-3）
- 错误状态恢复（P6-4）
- 模型版本分层和规则衰减（P6-5）
- gaming检测（P6-6）
- 长期归因（P6-7）
- 回滚到反应式模式（P6-8）
- 受约束最小干预策略π（P6-9）
- 12步在线循环+8角色在线运行时集成（P6-ROLE）

**出口门**：闭环长期收益为正，且不靠更高泄漏或无限帮助获得，且无误触发和过度帮助。

## 5. 逐项实现方案

### P6-1 只加载published规则

**做什么**：实现`published_loader.py`，从`heuristic_rules` collection中只加载`lifecycle_status=published`的规则。

**边界情况**：无published规则（返回空列表+告警）、published规则过多（分页加载）、candidate/validated规则试图进入在线运行时（拒绝+告警）。

**实现路径**：
1. `load_published_rules(model_version, applicable_domains)` → 查询`heuristic_rules` where `lifecycle_status='published'`
2. `validate_no_candidate(rules)` → 检查加载的规则中无candidate状态
3. `validate_no_validated_in_production(rules)` → 检查validated规则不自动进入生产H图
4. `validate_published_standard(rules)` → 检查published标准（G0-5：跨3个未参与设计的问题族和2个模型版本复现）

**预期D深度**：D3（不只是加载，还要验证published标准+拒绝非published）

### P6-2 9种动作+控制器不确定估计

**做什么**：实现`controller.py`，包含9种动作的执行函数和控制器不确定估计维护函数。

**9种动作**（123号§22）：
1. `continue_observing` → 不干预，继续观察
2. `ask_diagnostic_question` → 生成诊断问题
3. `request_tool_check` → 请求工具检查
4. `retrieve_minimal_interface` → 检索最小接口（复用retriever）
5. `inject_hint_0` → 注入H0元检查
6. `inject_hint_1` → 注入H1思维操作
7. `inject_hint_2` → 注入H2概念/工具候选
8. `abstain` → 弃权/不提示
9. `stop_or_escalate` → 停止或升级

**不确定估计**（P6-2.3，123号§22行481-484）：控制器维护对"当前策略、卡点类型、是否真的停滞"的不确定估计（置信度/概率分布），基于公开产物和工具事件更新，不假装读心。复用`state_reducer/controller_belief.py`作为基础。

**边界情况**：某动作无效果（告警）、动作执行失败（记录+回退）、控制器假装读取LLM内部状态（拒绝）、无不确定估计机制（拒绝）。

**预期D深度**：D2（9种动作全部可执行）+D3（不确定估计+无动作是合法动作）

### P6-3 预算+帮助依赖+4门泄漏代理复用

**做什么**：实现`budget.py`和`dependency.py`。

**5种预算控制**（P6-3.1）：token/计算/工具/分支/Hint预算。

**3种依赖代理**（P6-3.2，123号§23）：
1. 撤掉Hint后的独立继续率
2. 同类后续状态再次求助率
3. 单位已验证进展所需帮助量

**4门泄漏代理复用**（P6-3.4，123号§22）：在线运行时复用Phase 3已实现的`heuristics/leakage_audit.py`的4门检测（字面答案匹配/答案等价映射审计/候选空间缩减率/盲审者恢复率）。

**边界情况**：某预算超限（触发停止）、某代理未监控（拒绝）、4门检测未复用（拒绝）、只复用部分门（拒绝）。

**预期D深度**：D2（预算+依赖控制函数）+D3（4门复用+阈值验证）

### P6-4 错误状态恢复+checkpoint分层变量+4组对照

**做什么**：实现`error_recovery.py`。

**checkpoint 7字段**（123号§847，Phase 3已实现）：Q_0/W_t/关键事件前缀/模型/工具/权限/预算/版本哈希。

**checkpoint作为分层变量**（P6-4.4，123号§847）：同一内容哈希checkpoint视为阻断/分层变量，在每个checkpoint上随机分配并重复多个continuation。

**4组对照**（P6-4.4）：control（无提示）/H0（元检查）/H1（思维操作）/H2（概念/工具候选）。复用`experiments/treatment_groups.py`。

**边界情况**：无valid checkpoint（告警）、回退后状态不一致（拒绝）、checkpoint缺少7字段中任一字段（告警）、checkpoint未作为分层变量（拒绝）、4组对照不完整（拒绝）。

**预期D深度**：D2（恢复函数）+D3（分层变量+4组对照）

### P6-5 模型版本分层+规则衰减+再验证+退役

**做什么**：实现`model_layering.py`。

**4个子机制**：
1. 规则效果按模型/版本分层记录（P6-5.1）
2. 规则衰减机制——效果随模型升级衰减时降低权重（P6-5.2）
3. 规则再验证机制——模型升级后重新验证规则效果（P6-5.3）
4. 规则退役机制——效果消失或反例发现时退役为retired状态（P6-5.4）

**退役条件**（127号§9状态转移图）：published→retired（模型漂移/反例/更好规则替代）。退役规则归档但不删除。

**边界情况**：某模型无效果数据（标注"无数据"）、效果衰减但权重未降低（告警）、模型升级后未触发再验证（告警）、退役后规则被删除（拒绝——必须归档保留）。

**预期D深度**：D2（4个子机制全部可执行）+D3（退役符合状态转移图+归档不删除）

### P6-6 gaming三元判定

**做什么**：实现`gaming_detector.py`。

**三元判定机制**（系统探讨.md§15.4+154号修正）：
1. **停滞词识别**：Agent输出中包含停滞词（"我不知道"/"卡住了"/"无法继续"等）时标记"自报停滞"。停滞词列表可配置。
2. **工具证据验证**：自报停滞时，检查Agent是否真的调用了工具并产生了工具输出。只检查"声称调用了工具"不算——必须有工具调用实际记录和输出。
3. **结构进展度量**：自报停滞时，检查T图中是否有实际结构进展（新增节点/形成边/开放目标减少/义务状态变化）。只检查输出长度变化不算——必须是T图结构的实际变化。

**三元判定逻辑**：只有当（停滞词=True）AND（工具证据=False）AND（结构进展=False）时，才判定为gaming。

**边界情况**：无gaming行为、gaming行为隐蔽、Agent自报停滞但有工具证据（不算gaming）、Agent自报停滞但有结构进展（不算gaming）。

**预期D深度**：D2（三元判定函数）+D3（限制奖励性帮助）

### P6-7 长期归因3步法

**做什么**：实现`long_term_attribution.py`。

**3步归因方法**（154号修正）：
1. **提示链记录**：记录从首次提示到当前进展的完整提示链
2. **进展归因**：当进展发生时，回溯是哪个提示首次引入了导致该进展的H关系。信用归给首次引入该H关系的提示，不归给最近一次提示。
3. **反事实估计**：估计"如果没有该提示，是否也会达到该进展"（通过历史数据或对照组）。如果反事实估计显示没有提示也会达到进展，则不归信用给提示。

**边界情况**：长程信用被错误归给最近一次提示（拒绝）、归因不确定（标注"归因不确定"而非强行归因）、反事实估计无历史数据（标注"无对照数据"）。

**预期D深度**：D2（3步归因函数）+D3（验证长期收益计算正确）

### P6-8 回滚到反应式模式+主动导航判定条件

**做什么**：实现`reactive_fallback.py`。

**闭环失败4种定义**（154号修正）：
1. P6-EXIT-1不通过：闭环长期收益≤0
2. P6-EXIT-2不通过：收益为正但靠更高泄漏或无限帮助获得
3. P6-STOP-2触发：正确率提升以更高泄漏为代价
4. P6-STOP-3触发：gaming检测不一致率超阈值

**反应式救援5条理由**（系统探讨.md§13）：回滚时标注`REACTIVE_RESCUE_MODE=True`并记录5条理由。

**主动导航优于反应式3项判定**（P6-8.4，plan行912）：
1. 长期收益增加：主动导航的长期收益 > 反应式的长期收益
2. 独立性不恶化：主动导航的独立性指标不低于反应式
3. 泄漏不恶化：主动导航的泄漏指标不高于反应式

**边界情况**：闭环失败但未回滚（拒绝）、回滚时未记录5条理由（告警）、3项中任一项不满足就判定优于（拒绝）。

**预期D深度**：D2（回滚函数）+D3（5条理由+3项判定）

### P6-9 策略π+代理分数约束+6种任务类型进展度量

**做什么**：实现`policy_pi.py`和`task_progress.py`。

**策略π**（123号§23）：
```
max_π E[ΔProgress_κ] - λ1*C_hint - λ2*L̂_answer - λ3*D̂_dependence - λ4*C_compute
```

**代理分数约束**（P6-9.1，123号§22行510）：L̂_answer和D̂_dependence标注为"代理分数"，不是互信息或真实依赖度。

**6种任务类型进展度量**（P6-9.4，123号§22行530-533）：
1. prove/refute → 义务证据门与反例
2. construct → 候选对象通过的约束比例
3. compute → 已验证子计算
4. conjecture → 非重复、可证伪、通过初筛且未被反例否定的候选
5. classify → 覆盖
6. optimize/value → 界和决策论指标

**边界情况**：某λ未设置（告警）、L̂_answer/D̂_dependence被标注为互信息（拒绝）、6种任务类型共用一个粗糙计数（拒绝）、跨任务直接比较|V_t|（拒绝——必须归一化）。

**预期D深度**：D2（策略π+6种任务类型度量）+D3（代理分数约束+多指标报告）

### P6-ROLE 12步在线循环+8角色在线运行时集成

**做什么**：实现`orchestrator.py`。

**12步在线主链**（123号§32，159号修正P6-ROLE.COMP）：
1. 冻结 → 2. 建态 → 3. 独立探索 → 4. 事件捕获 → 5. 状态归约 → 6. 局部验证 → 7. 诊断决策 → 8. 模式匹配 → 9. 最小动作选择 → 10. 增量编译 → 11. 因果分叉 → 12. 归因收口

**8角色最小输入/输出契约核对**（P6-ROLE-3，123号§607）：逐角色核对8个角色的输入/输出/禁止操作（已在阶段4核对127号§10.4—10.11）。

**边界情况**：12步未全部实现（告警）、步骤10增量编译未从checkpoint继续（拒绝）、步骤11实验模式未用checkpoint分层（拒绝）、步骤12归因收口未保存失败路线（拒绝）、某角色越权访问（拒绝）。

**预期D深度**：D2（12步循环+Controller类）+D3（8角色契约核对+CapabilityToken验证）
