## 0. 这套方案是从哪里冒出来的——背景与起点

### 0.1 起点：30道做不出来的题

这套方案不是凭空设计的，它是被一个具体的失败逼出来的。

2026-08-06 凌晨，用5个tmux session并行测试了43道2024-2026年世界级竞赛最难题（IMO/USAMO/Putnam/USAMO/IMC/AIME/HMMT/SMT等各竞赛最后2-3道大题），GLM-5.2裸跑（无提示、无引导、禁网搜）的正确率只有 **18.9%**（37道有效题中做对7道）。

更关键的是 **Phase 1b 验证**（commit `8309ef5`，13:41）：修复了题目截断和token超限两个基础设施bug后，重测那30道做不出来的题，结果 **仍然 0/25 做出来**（排除5道API error）。这30道题的AI回复大多是 stuck——输出不到100字符就说"我不知道"。

结论（213号方案记录的）：**这30道题是GLM-5.2的真实能力边界，不是基础设施问题。需要进入提示干预。**

### 0.2 逼出来的核心问题

面对30道做不出来的题，要给提示干预。但怎么给？

- 给"用Vieta跳跃"、"考虑p-adic赋值"这种具体知识提示？某道题会做了，但换一个领域又不会了。
- 给"试试反证法"、"找到不变量了吗"这种思维策略提示？可能跨领域有效，但怎么决定什么时候给、给什么？

这就是214号文档要回答的根本问题。两个commit（`e111c7f` 13:49、`660347f` 13:56）先把决策写进了AGENTS.md，然后 `7aceab6`（13:57）把完整论证独立成214号文档。

## 1. 方案的第一根柱子：路线选择——思维模式而非知识堆砌

### 1.1 两条路线的根本区别

| 路线 | 本质 | 提示内容 | 效果边界 | 例子 |
|---|---|---|---|---|
| **路线A：堆砌知识** | 告诉AI"用什么知识" | 具体定理/技巧/公式 | 限于同一知识范围 | "用Vieta跳跃"、"考虑p-adic赋值"、"用Schur不等式" |
| **路线B：思维模式** | 告诉AI"怎么思考" | 跨领域的元认知策略 | **跨知识范围** | "试试反证法"、"找到不变量了吗"、"考虑极端情况" |

**本项目选择路线B。**（214号第1章，commit `e111c7f`）

### 1.2 为什么选路线B

路线A能取得某种成功——某道题会做了，变化一下，另外一道题也会做了。但**限于同样的知识范围**。换一个领域、换一个题型，又不会了。它是局部的、低级的。

路线B寻找的是**最深的、最通用的、最高抽象度的思维模式**。这些模式不依赖任何具体数学知识，能在数论、几何、组合、分析...任何领域应用。反证法就是最简单的例子——它不是任何领域的知识，而是一种通用的思维策略。

### 1.3 要找的提示的五个特征

1. **不依赖具体数学知识**——反证法不需要你知道任何定理
2. **元认知层面**——不是"知道什么"，而是"怎么思考"
3. **跨领域适用**——在数论、几何、组合、分析都能用
4. **可组合**——一道题可能需要反证法+极端原理+不变量
5. **有层次**——"反证法"比"考虑最小反例"更抽象；"找不变量"比"找面积不变"更抽象

### 1.4 对提示设计的指导意义

- ❌ 不要给AI"用Vieta跳跃"（知识级提示）
- ❌ 不要给AI"考虑p-adic分析"（知识级提示）
- ✅ 要给AI"你试过反证法吗？假设结论不成立会怎样"（思维模式级提示）
- ✅ 要给AI"你找到不变量了吗？什么量在变换下不变"（元认知级提示）
- ✅ 最好给AI"你考虑过极端情况吗？最大/最小的情形会怎样"（最泛化的方向指引）

### 1.5 这就是数学大师的真正价值

不是知道很多知识（那是知识库的事），而是在面对任何问题时知道该用什么思维策略。这就是"综述博士"的价值——知道在什么时候该看什么、该结合什么。依赖图K提供知识，思维模式提示提供策略，两者结合才是完整的数学大师。

## 2. 方案的第二根柱子：Level连续谱——思维模式与知识之间不是二分的

### 2.1 边界不是清晰的

思维模式和知识之间的边界不是清晰的。反证法是纯思维模式，Vieta跳跃是纯知识，但中间有大量灰色地带——"考虑对称性"、"用生成函数"、"找单调性"——它们既有知识成分，也有模式成分，无法截然分类。

### 2.2 Level标签

依赖图（稀疏矩阵）中的每个元素都有一个 **Level标签**：0到1之间的实数。

| Level | 含义 | 例子 |
|---|---|---|
| →0 | 纯知识：绑定到特定数学领域 | "Vieta跳跃"、"p-adic赋值"、"Schur不等式" |
| →1 | 纯思维模式：跨领域通用 | "反证法"、"找不变量"、"考虑极端情况" |
| 中间 | 灰色地带：部分知识部分模式 | "考虑对称性"、"用生成函数"、"找单调性" |

### 2.3 Level的三个本质属性（commit `660347f`）

1. **经验的**——无法从公理推导，只能从数学研究经验中感受。没有公式能算出"考虑对称性"的Level是0.4还是0.6。
2. **模糊的**——不是精确的数值。我们不说"反证法的Level=0.95"，而是说"反证法接近纯思维模式"。
3. **相对的**——只有通过两个元素的对比才有意义。不存在绝对坐标系，只有相对高低。

### 2.4 AI的角色：相对比较而非绝对赋值

我们无法给出任何元素的绝对Level值。但AI能够：
- **感受差异的模糊大小**——把两个元素放在一起，AI能感知"这个比那个更抽象/更泛化"
- **判断极其相近元素的细微高低差**——当两个元素非常接近时，AI仍能感知到它们之间细微的Level差异

**Level不是被赋值的，而是被感知的。** 依赖图中的Level排序不是通过某个算法计算出来的，而是通过AI的相对比较感受出来的。

### 2.5 对系统设计的指导

- 依赖图中每个节点带Level标签，但标签值是模糊的、相对的
- 提示生成器在选择提示时，可以按Level排序——优先选高Level（更通用）的提示
- 当AI卡住时，系统先给高Level提示（最通用的思维模式），如果不够再逐步降低Level走向具体知识
- AI自身也可以在研究中感知到某个依赖的Level，并反馈给系统修正

## 3. 方案的第三根柱子：形状——用带标注的拓扑结构观察思维

### 3.1 反证法带来的根本问题（214号第3章，commit `7abcd63` 14:06）

反证法是一个非常好的思考点，因为它给系统提出了非常多的问题。

**问题1：难道不是所有题、所有解题步骤，都应该思考一下是否应该运用反证法吗？**

反证法是如此通用，以至于在任何一个证明的任何一个步骤，都可以问一句"如果反过来假设呢？"。但显然不是每道题都需要反证法。那么：
- 系统什么时候应该提示AI"试试反证法"？
- 如果每道题都提示，提示就变成了噪声——AI会忽略它
- 如果只在"系统认为需要"时提示，系统凭什么判断需要？这个判断本身就需要比反证法更高级的元认知

这揭示了一个 **提示触发的悖论**：越通用的思维模式，越难决定什么时候该提示。因为它的适用范围太广了——几乎总是可以适用——所以"适用性"不能作为触发条件。触发条件必须是更精细的：不是"这道题能不能用反证法"，而是"这道题在当前这个卡点，用反证法是否可能突破"。

**问题2：我们的系统是关注"形状"的。**

"形状"不是题目表面的文字内容，而是：
- 问题的结构特征：是一个存在性命题吗？是一个唯一性命题吗？是一个极值问题吗？
- 解答的转折结构：解答在哪里从正面转向反面？在哪里从构造转向证明？在哪里从代数转向几何？
- 思维的拓扑：哪些思维模式经常一起出现？哪些模式之间有依赖关系？哪些模式是"入口"（一开始就该想到），哪些是"出口"（最后才用）？

带标注的拓扑结构意味着：依赖图中的节点不只是"反证法"这个标签，而是"反证法"在特定形状的问题中的特定使用方式。反证法在存在性命题中的形状，和反证法在极值问题中的形状，可能是不同的拓扑节点。

### 3.2 提取与触发的不对称

- **知识提取是机械的**——读题目和解答，标注提到的定理/公式/引理即可
- **模式提取是洞察的**——需要看出"这个解答的转折点其实是反证法"、"这个构造的灵感来自对称性考虑"，而这些从不在文本中直白写出

**提取**：不是在解答末尾标注"此题用了反证法"，而是在解答的每个关键转折点标注"这里从正面假设转向了反面假设"——是过程性的，不是总结性的。

**触发**：不是基于"这道题能不能用反证法"（太宽泛，几乎总能用），而是基于"当前卡点的形状，是否匹配反证法曾经成功突破过的形状"。形状匹配是拓扑的。

### 3.3 反证法给我们的最终启示

一个思维模式越通用，它的触发就越不能依赖"适用性"判断，而必须依赖"形状匹配"。系统不是在问"这道题能不能用反证法"，而是在问"当前思维状态的形状，是否和反证法曾经成功过的那些形状相似"。这是一个拓扑问题，不是逻辑问题。

## 4. 方案的第四根柱子：极致提示集合——纯思维模式级的启发式问题

### 4.1 实例分析：矩条件极差题（214号第4章，commit `35b1cbf` 14:14）

题目：已知 $a_1, \ldots, a_n$ 为实数，满足 $\sum a_i = n$，$\sum a_i^2 = 2n$，$\sum a_i^3 = 3n$。
(1) 求最大常数 $C$，使 $\max a_i - \min a_i \ge C$ 对所有 $n \ge 4$ 成立。答案：$C = \sqrt{5}$。

把这道题的解答步骤做了思维模式拆解：

| 步骤 | 思维模式成分（Level→1） |
|---|---|
| 1. 平移 $x_i = a_i - 1$ | **归一化**——"能不能通过变换让条件更干净？" |
| 2. 发现 $q(x) = x^2 + x - 1$ | **寻找统一编码**——"多个约束能否被一个对象同时捕获？" |
| 3. $\sum q(x_i) = 0$ 和 $\sum x_i q(x_i) = 0$ | **恒等式挖掘**——"约束组合后会产生什么免费信息？" |
| 4. $q$ 的根 $r, s$，$s - r = \sqrt{5}$ | **结构对应**——"关键对象的几何特征是否就是答案？" |
| 5. 反证：若极差 $< \sqrt{5}$ | **反证法** + **符号分析** |
| 6. 数值试探三点构型 | **极值构型探测**——"等号什么时候成立？什么构型达到极值？" |
| 7. 第(2)问：投影到最近根 | **投影分解**——"把每个元素拆成模板部分和偏差部分" |
| 8. 稳定性方程 | **扰动分析**——"在极值附近，偏差满足什么关系？" |
| 9. $D$ 的量级 $\ge c/n$ | **量级感知**——"偏差的量级被什么数论结构控制？" |
| 10. $\sum e_i^2 \ge c/n$ → $\delta \ge c/n^{3/2}$ | **能量传递**——"偏差的能量如何转化为目标量的下界？" |

### 4.2 关键观察

**步骤9是唯一一个纯知识瓶颈**——badly approximable数的有理逼近下界。这是Level→0的知识，AI如果没有这个知识，光靠思维模式提示很难自己发现。

**其余所有步骤都可以被思维模式提示引导。**

### 4.3 极致提示集合——10个纯思维模式级的启发式问题

如果我们追求极致——**只给启发式问题，不给任何具体知识**——那么以下提示集合可能引导AI走到正确解（或至少走到步骤9之前）：

1. **归一化**："你的条件里有三个矩约束。能不能通过一个简单的变量替换，让这些约束变得更整齐、更容易处理？"
2. **寻找统一编码**："你有三个约束...是否存在一个对象——比如一个多项式——能同时捕获其中两个约束？"
3. **恒等式挖掘**："把你的三个矩条件和这个对象做组合——求和、相乘、线性组合——看看能产生哪些'免费的恒等式'。"
4. **结构对应**："你找到的关键对象有什么几何特征？它的根在哪里？根之间的距离是多少？这个距离和你要证明的下界有什么关系？"
5. **反证法 + 符号分析**："假设你要证明的下界不成立——极差比那个距离更小。你的关键对象在这个区间里的符号行为是什么？这个符号行为和你的恒等式矛盾吗？"
6. **极值构型探测**："试着构造一个接近等号的例子——通常极值构型会退化成少数几个不同的值。"
7. **投影分解**："把每个点分解成'离它最近的关键点'加上'偏差'。"
8. **扰动分析**："在极值构型附近，把你的矩条件用偏差重新表达——你会得到一个关于偏差的'稳定性方程'。"
9. **量级感知**："你的稳定性方程里有一个项，它的值取决于整数对某个无理数的逼近。无理数被整数逼近的精度有下界吗？"
10. **能量传递**："你现在知道了偏差能量的下界。你需要把这个下界传递到极差的下界。试试柯西不等式。"

### 4.4 提示集合的四个特征

1. **没有一个是具体知识**——没有任何一个提示说"用 $q(x) = x^2 + x - 1$"、"用 badly approximable"、"用柯西不等式"。
2. **有Level层次差异**——提示1-6更通用（Level更高），几乎适用于任何不等式证明题；提示7-10更特定于"精细下界"类问题（Level稍低），但仍然不是具体知识。
3. **有形状针对性**——虽然每个提示都是通用的思维模式，但它们的排列顺序对应了这道题的解答形状。打乱顺序效果会差很多。
4. **步骤9是知识瓶颈**——提示9虽然用了"量级感知"的思维模式框架，但它暗示了"无理数逼近"这个知识方向。这验证了核心观点：**思维模式提示能走很远，但在某些关键节点，知识是不可替代的。**

### 4.5 提示的排列顺序就是"形状"

这10个提示的排列顺序本身就是一种形状信息。它编码了"矩条件极值问题"这类问题的典型解题路径。系统不需要告诉AI"这道题的形状是什么"，而是通过按顺序给出提示，让AI自然地沿着这个形状走。

## 5. 方案的第五根柱子：安全第一步——让AI先描述形状，而不是解题

### 5.1 问题（214号第5章，commit `1e9a482` 14:19）

AI面对难题会卡死——输出<100字符就说"我不知道"。原因不是AI没有能力，而是它试图一步到位给出完整解答，不知道从哪开始就放弃了。

### 5.2 核心idea：先描述形状，再匹配提示

系统关注"形状"（第3章），但形状不应该由系统从外部硬判断，而应该让AI自己先"看到"形状。

AI可能不会解题，但AI一定能：读题、分类（极值问题？存在性问题？不等式？）、列举条件类型、描述结论类型、列出想到的方向。

这些操作AI必然可以完成，因为它们不要求任何创造性——只是"读题并描述"，不是"解题"。

### 5.3 为什么这一步AI必然可以完成

| 要求 | 解题 | 描述形状 |
|---|---|---|
| 创造性 | 需要 | 不需要 |
| 具体知识 | 需要 | 不需要 |
| 正确性 | 必须 | 不要求（方向可以错） |
| 操作性质 | 构造 | 观察 |
| 失败风险 | 高（卡死） | 极低（读题即可） |

描述形状是**元认知观察**——不是"怎么解题"，而是"这道题长什么样"。这是最高Level的思维模式之一：不依赖任何知识，跨所有领域适用，是所有其他思维模式的前置条件。

### 5.4 安全第一步的具体设计

给AI的指令不是"解这道题"，而是：

> "不要解题。请描述这道题的结构形状：
> 1. 结论是什么类型？（求常数/证明存在性/证明不等式/计数/...）
> 2. 已知条件是什么类型？列出每个条件及其类型。
> 3. 条件和结论之间的'距离'有多远？是直接代入就能得到，还是需要构造/反证/深层变换？
> 4. 你想到了哪些可能的方向？不要求正确，只要列出你能想到的所有方向。
> 5. 这道题让你联想到了什么类型的其他问题？"

### 5.5 安全第一步的产出怎么用

AI给出的形状描述就是系统匹配提示的依据：

| AI描述的形状 | 系统优先给的提示 |
|---|---|
| "这是极值问题" | 极值构型探测——"等号什么时候成立？" |
| "结论需要证明存在性" | 反证法——"假设结论不成立会怎样？" |
| "条件是代数恒等式" | 恒等式挖掘——"约束组合后会产生什么免费恒等式？" |
| "多个约束需要同时满足" | 寻找统一编码——"多个约束能否被一个对象同时捕获？" |
| "需要证明精细下界" | 投影分解+扰动分析 |
| "想到了对称性方向" | 系统检查这个方向在依赖图中是否有成功路径 |

### 5.6 和传统"先理解题意"的区别

传统做法：让AI"理解题意"然后"开始解题"——理解和解题是分开的，理解完直接跳到解题，AI在解题阶段卡死。

新做法：让AI做结构分析，然后用结构分析的产出来选择提示——分析和提示是耦合的。AI永远不会面对"从零开始解题"的空白状态——它总是在提示引导下走下一步。

### 5.7 安全步序列

- **安全步1**：描述题目结构形状
- **安全步2**：对每个想到的方向，描述"如果走这个方向，第一步会做什么"（不要求真的做，只描述）
- **安全步3**：在所有方向中，选一个"最有感觉"的方向，做第一步的尝试
- **安全步4**：如果第一步尝试有产出，继续；如果卡住，回到安全步2换方向

每一步都是安全的——AI不会面对"给出完整解答"的压力，只需要做一小步。

## 6. 方案的第六根柱子：连续发问——从安全观察渐进走到解题

### 6.1 第5章的不足（214号第6章，commit `ac81aa7` 14:21）

第5章的"安全第一步"是**一步**——让AI描述形状，然后停下来，系统给提示让AI解题。但问题是：描述完形状之后，AI面对"现在开始解题"这个任务，可能**还是卡死**。安全第一步解决了"从空白页到有信息量输出"的问题，但没有解决"从有信息量输出到真正解题"的问题。

中间有一个断裂：安全步是安全的（描述形状），解题步是危险的（可能卡死），从安全步到解题步之间缺少过渡。

### 6.2 核心洞察：连续发问，渐进探索

不要在"描述形状"和"解题"之间设一道坎。而是**连续地发问**，让AI渐进地从观察走向探索走向尝试，每一步都是安全的，每一步的输出都为下一步提供context。

关键不是"先安全一步，再危险一步"，而是**让每一步都安全**——通过控制每步的粒度，让AI永远不会面对"给出完整解答"的压力。

### 6.3 为什么连续发问能避免卡死

AI卡死的根本原因是**任务粒度太大**——"解这道题"是一个巨大的任务，AI不知道从哪开始就放弃了。

连续发问把大任务分解成一系列小问题：
- 每个小问题AI都能回答
- 每个回答都产生信息，为下一个问题提供context
- AI在回答过程中逐渐"热身"，思维从被动观察过渡到主动探索
- AI不会意识到"我正在解题"——它只是在回答一系列看起来很简单的问题

这就是**渐进性**的力量：不是"会做"或"不会做"的二元判断，而是从"能看到"到"能描述"到"能联想"到"能尝试"到"能推进"的连续光谱。

### 6.4 六层渐进发问框架

**第一层：观察（必然安全）**
> "这道题的结论是什么类型？已知条件是什么类型？"

**第二层：联想（几乎安全）**
> "这些条件让你想到了什么？不要求正确，列出你能想到的所有方向。"

**第三层：描述方向（仍然安全）**
> "对每个方向，如果走这个方向，第一步会做什么？不要求真的做，只描述。"

**第四层：小尝试（开始有风险但可控）**
> "在你觉得最有希望的方向上，试着做第一步。做多少算多少，做不出来也没关系。"

**第五层：推进（有产出后自然过渡）**
> "你得到了什么？这个结果和你要证明的结论之间还有什么差距？下一步你想怎么走？"

**第六层：卡点处理（如果卡住）**
> "你卡在哪里了？是不知道下一步该做什么，还是知道方向但做不下去？如果是前者，我们换个方向；如果是后者，你缺的是什么——是一个具体技巧，还是一个思路？"

### 6.5 连续发问的关键性质

1. **每一步都比前一步要求更多，但增量很小**——AI不会突然面对巨大的跳跃。
2. **每一步的输出都是下一步的context**——信息在层与层之间流动和积累，AI不需要重新思考。
3. **AI不会意识到"我正在解题"**——每一步的问题看起来都很简单、很具体、很安全。但回答完所有问题后，它会发现自己已经走了很远。
4. **系统可以在任何一层介入给提示**——如果AI在第三层描述方向时列出的方向都不好，系统可以给一个思维模式提示。
5. **渐进不等于线性**——AI可能在第四层尝试后发现走不通，回到第三层换方向。关键不是走直线，而是**永远不面对空白页**。

### 6.6 三章合起来

- **第4章**提供了提示库（系统可以给什么提示）
- **第5章**提供了入口（AI先做安全观察）
- **第6章**提供了过渡机制（从安全观察渐进到解题）

连续发问框架中的每一层，都可以注入第4章的极致提示。提示不是从外部强加的，而是在渐进探索过程中自然出现的。

## 7. 方案的第七根柱子：最小知识传递——路线B的形式化定义

### 7.1 定义（214号第7章，commit `08dd327` 14:27）

"最小知识传递"就是路线B：以最大化的思维模式引导来帮助AI，而不是知识堆砌。

形式化表达：

$$\text{最小知识传递} \;=\; \arg\max_{H} \sum_{i=1}^{n} \text{Level}(h_i) \quad \text{s.t.} \quad \text{AI在} H \text{引导下完成解题}$$

其中：
- $H = (h_1, h_2, \ldots, h_n)$ 是一次引导过程中系统发送给AI的完整提示序列
- $h_i$ 是第 $i$ 条提示
- $\text{Level}(h_i) \in [0, 1]$ 是第 $i$ 条提示的Level值
- $\sum_{i=1}^{n} \text{Level}(h_i)$ 是所有提示的Level之和

**最大化Level之和**意味着：在引导AI解题的过程中，每一条提示都尽可能取高Level值（接近1，纯思维模式），尽可能避免低Level值（接近0，具体知识）。

### 7.2 约束条件

上述最大化不是无约束的。完整优化目标是：在"AI能完成解题"的约束下，最大化Level之和。如果纯高Level提示无法让AI完成解题，系统必须适时降低某些提示的Level（走向知识端），直到AI能完成。每次降Level都是对Level SUM的损失，但这是完成解题的必要代价。

### 7.3 与路线A的对比

路线A（知识堆砌）的优化方向恰好相反——它不关心Level之和，只关心AI能不能做出来，直接给最低Level的提示（具体知识），因为这样最快。但它不追求泛化能力——AI做完这道题后，换一个领域还是不会。

路线B追求的是：在"AI能完成解题"的前提下，**尽可能用高Level提示**——这样AI不仅做完了这道题，还在过程中练习了通用的思维模式，下次遇到不同领域的题也能用。

### 7.4 Level SUM的实践意义

- **每次给提示时，先尝试Level最高的**——先给"试试反证法"（Level≈0.9），不给"用$q(x)=x^2+x-1$"（Level≈0.1）
- **只有高Level提示失败后才降Level**——如果"试试反证法"没用，再给"看看函数的符号结构"（Level≈0.7），最后才给"考虑二次方程的根"（Level≈0.3）
- **记录每次降Level的原因**——降Level不是失败，而是系统学习的机会：什么形状的卡点需要降到什么Level

## 8. 方案的第八根柱子：DFS引导架构——思维路径的树状探索

### 8.1 预演的局限（214号第8章，commit `5913403` 14:39 起，到 `e772291` 20:18 共12个commit逐步构建）

215号附录A的预演有一个隐含假设：引导者知道正确路径，所以Q的顺序是预设的。但真正未来，引导者AI面对的是未知的题——它不知道正确路径是什么，只知道"在A出来时该问什么Q"。

预演是"已知答案倒推提示序列"，实际是"未知答案，边探索边决定下一步问什么"。这两者有本质区别。

### 8.2 核心架构：引导者陪着做题AI做DFS

引导者和做题AI是两个角色：
- **做题AI**：在提示下尝试解题，产出A（每一步的回复）
- **引导者AI**：观察做题AI的A，决定下一个Q（提示/发问）

引导者不知道正确路径，但它能在每个A出来时生成多个候选Q。一次只发一个Q，如果走不通就回溯换另一个候选Q。

这就是**深度优先搜索（DFS）**：搜索空间是"提示候选树"，评估函数是Level，目标是最小知识传递。

### 8.3 树的定义

- **节点** = 做题AI的一个状态（一个A + 当前累积的推理context）
- **边** = 引导者发送的一个Q（一个提示/发问）
- **根节点** = 题目本身
- **叶节点** = 三种：成功叶（正确解答）、死路叶（卡死或错误方向）、截断叶（超限强制停止）
- **一个节点的子边** = 引导者在该节点能想到的所有候选Q

### 8.4 DFS的执行规则

1. 在每个节点，引导者生成候选Q列表
2. **候选Q按Level降序排列**——优先探索高Level（更通用、更抽象）的提示。这是Level SUM最大化的贪心策略。
3. 一次只发一个Q，等待做题AI的A
4. 如果A是成功叶——探索结束
5. 如果A是死路叶——回溯到父节点，发送下一个候选Q（Level次高的）
6. 如果A是中间节点——在新节点继续DFS
7. 如果所有候选Q都走不通——回溯到更上层的节点

### 8.5 引导者的四种核心能力

引导者不需要知道正确答案，但需要具备：

1. **生成候选Q**——在任意A出来时，能想出多个可能的提示方向。（"广度"能力）
2. **评估Level**——对每个候选Q，能感知其Level值。（"品味"能力）
3. **判断A的状态**——能判断做题AI的A是"有进展"、"卡住"、"走错方向"还是"完成了"。（"诊断"能力）
4. **回溯决策**——能判断"这条路值得继续"还是"应该回溯换方向"。（"剪枝"能力）

这四种能力都不是具体数学知识——它们是元认知能力。引导者不需要会做题，但需要能"看"做题AI的状态并做出决策。

### 8.6 回溯的铁律：新Session，不原地回溯（commit `1ac76af` 14:43）

**禁止在同一个Session中让AI回溯到某个思路岔口。** 如果DFS的一条路失败了，必须重新启动一个新的Session。

为什么不能在原Session中回溯：
1. **压缩边界风险**：DFS探索可能跨越session的压缩边界。压缩后早期的推理细节可能丢失或变形。
2. **context污染**：在原Session中，AI已经走过了失败路径的推理过程。即使你告诉它"放弃这个方向"，那些失败的推理痕迹仍在context中，会影响AI的后续思考。
3. **不可逆性**：AI的推理context是单向流动的——你可以让它继续往前走，但不能让它"忘记"已经走过的路。

正确做法：新Session + 重放Q序列到岔口 + 在岔口换方向。

### 8.7 节点同一性的模糊定义（commit `a0b08d0` 20:07）

回溯机制假设：重放Q序列到岔口，新session的AI会给出和上次相同的A。但AI是非确定的——同样的Q序列在干净session中重放，A'**大概率**和A相似，但**不保证**完全相同。

本项目选择 **路径同一性为主、状态同一性为辅** 的混合定义：树的拓扑结构由Q路径决定（node_id由Q路径确定），但节点的内容（A）是概率性的。引导者需要判断A'和A是否"本质相同"——而这个判断也是经验的、模糊的、相对的，由引导者感知。

### 8.8 "Q相同但A有细微差异"——从判断同一性到判断适用性（commit `89b4121` 20:13）

不要试图判断A和A'是否"相同"——这是哲学陷阱。而是问一个实用主义的问题：

**"我准备发的下一个Q，对A'还有效吗？"**

- **有效** → 发它，继续DFS。A'的细微差异不影响下一步，记录为变体即可。
- **无效** → 调整Q。A'的细微差异改变了数学状态，原来的Q不再适用。
- **不确定** → 先发Q试试。

DFS树的价值不在于精确记录"AI当时在想什么"，而在于**指导下一步该问什么**。

### 8.9 数据持久化：从JSON到ArangoDB（commit `54212e7` 20:14, `e772291` 20:18）

QA树天然是图结构，存入ArangoDB。设计原则：
1. **不可复现的数据优先存**——AI回复、引导者决策、压缩事件，这些不可复现
2. **文件系统+ArangoDB双写**
3. **从第一轮就完整记录**——不等到系统成熟再开始记录
4. **引导者决策和AI回复同等重要**
5. **9层完整记录**：题目元数据→测试运行元数据→预演记录→DFS树→每个节点完整记录→Session级记录→引导者决策日志→结果验证→性能指标

3. 描述5个方向的第一步，发现执行顺序
4. 选择中心化+多项式非负性方向，完整推导：
   - 用$(b_i-m) \ge 0$蕴含$\sum(b_i-m)q(b_i)^2 \ge 0$
   - 取q为一次多项式得2×2矩阵半正定
   - $m \le -\varphi$, $M \ge \varphi-1$, 故$M-m \ge \sqrt{5}$
   - 两点分布验证三矩精确匹配
   - 数值验证n=10000时$d-\sqrt{5} \approx 0.0001$

### 10.4 连续发问框架验证成功

- 4轮纯元认知指令（Level=1.0）即可引导AI完成证明
- 无需注入任何具体数学知识
- AI从未面对"空白页"——每轮都是安全子任务

**注意**：AI实际走的路径（多项式非负性+半正定矩阵）和预演中设想的路径（找q(x)+反证法+符号分析）**不完全相同**，但都到达了C=√5。这说明元认知框架确实激活了AI自己的能力，而不是把AI按在特定路径上走。

## 11. 方案自己暴露的危机：218号——Q序列的非特定性危机与诚实分析

### 11.1 用户的深刻批判（commit `8449b52` 22:33）

guided_001成功后，用户提出了一个极其深刻的批判：

> "千万不要说，我们没有做知识传递，但是却面向了答案，做了特定的启发式Q序列传递。我十分担心，我们的启发式Q序列是特定性的，我怕我们看似成功了，但是这些启发性的提问是特定于某道题目的解答的，而不是努力非特定化过的。因为只有非特定化的Q，未来才具备最大的在非特定的各种情况下，对AI解其他的题目，有启发意义。"

### 11.2 什么叫"非特定性"

- **非特定性**：Q不依赖于特定题目的特定解答路径。换一道完全不同的题，用完全相同的Q（只改引用内容），AI仍能获得类似的启发效果。
- **特定性**：Q隐含地指向特定解答路径。虽然形式上是元认知指令（"描述第一步"、"试着做"），但通过引用特定内容，隐含地引导AI走特定路径。
- **为什么非特定性重要**：只有非特定化的Q，未来才具备最大的在非特定情况下对AI解其他题目的启发意义。特定化的Q看似成功，但只是"面向答案做引导"的伪装。

### 11.3 guided_001的Q序列逐个分析

| Q | 非特定性 | 问题 |
|---|---|---|
| Q1 "描述题目形状" | ✓ 完全通用 | 无 |
| Q2 "列方向" | △ 形式通用但引用了AI的特定内容 | 引用内容来自AI自身，不是引导者注入 |
| Q3 "对最看好的5个方向，描述第一步" | ✗ **严重问题** | 引用了AI自己选的5个方向——但这些方向恰好是解答这道题的关键方向！通过引用"最看好的5个"隐含地帮AI筛选了方向 |
| Q4 "选最有希望的方向，试着做" | ✗ 再次确认特定路径 | "执行顺序30→{4,29}→{8,9}"是在确认特定执行路径 |

### 11.4 核心问题

**隐含筛选**：Q1-Q2是非特定的，但Q3-Q4发生了特定化。虽然没有直接传递知识，但通过引用AI自己选的方向，隐含地：
1. 帮AI筛选了方向——AI列了30个方向，引用了"最看好的5个"，这本身就是筛选
2. 确认了正确路径——AI选的5个方向恰好是正确方向，引用强化了这个选择
3. 隐含了执行顺序——Q4引用"30→{4,29}→{8,9}"，这是在确认特定执行路径

**选择性引用的偏见**：如果AI选的5个方向中包含错误方向，引导者会引用错误方向吗？大概率不会——会选择性引用"更有希望的"方向。但这个"更有希望"的判断，就是引导者在做特定化引导。即使Q的形式是非特定的元认知指令，**引导者在选择引用哪些AI内容时，已经在做特定化判断**。

**层次设计的特定性**：即使Q3/Q4的**形式**是非特定的，整个Q序列的**层次设计**（L1观察→L2联想→L3描述→L4尝试）是基于预演的——预演中已经知道解答路径。这个层次顺序恰好适合这道题，但换一道需要"先尝试再观察"的题，可能就不适用。

### 11.5 真正的检验标准

**如果换一道完全不同的题，用完全相同的Q1-Q4的形式（只改引用内容），AI能不能做出类似进展？**

如果不能，说明Q序列的效力依赖于引用内容的特定性——实际上是在"面向答案做引导"，只是伪装成元认知指令。

### 11.6 非特定化的Q序列设计

| 轮次 | 纯非特定Q |
|---|---|
| Q1 | "请读取problem.txt。不要解题。描述这道题的结构形状：结论是什么类型？已知条件是什么类型？条件和结论之间的距离有多远？" |
| Q2 | "列出你能想到的所有可能方向——不要求正确，不要求完整，只要列出你脑中浮现的任何方向。" |
| Q3 | "对你觉得最有希望的方向，描述第一步会做什么。不要求真的做，只描述。" |
| Q4 | "选一个方向，试着做第一步。做多少算多少，做不出来也没关系。" |
| Q5 | "你得到了什么？这个结果和你要证明的结论之间还有什么差距？下一步你想怎么走？" |
| Q6（卡住时） | "你卡在哪里了？是不知道下一步该做什么，还是知道方向但做不下去？" |

### 11.7 非特定化的代价

非特定化可能降低成功率——如果AI自己选了错误方向，非特定化引导不会纠正它。但这正是检验：AI在纯元认知框架下，不靠引导者的隐含筛选，能不能自己找到正确路径？

- **如果成功率显著下降**，说明guided_001的成功依赖于引导者的特定化引导，而不是AI自身能力被元认知框架激活。
- **如果成功率不下降**，说明纯元认知框架本身就足够——AI只需要"被引导去观察、联想、描述、尝试"，不需要引导者筛选方向。

### 11.8 需要对照实验

用同一道题（矩条件极差题第一部分），用纯非特定Q序列（guided_003），看AI能不能做出来。这个问题的答案只能通过实验获得，不能通过理论推导。

### 11.9 同时启动的guided_002——故意错误实验

同一个commit还启动了guided_002：第二部分（证明存在$C_2>0$使$\max-\min \ge \sqrt{5} + C_2 n^{-1/3}$），**故意把指数写错**（正确应为$n^{-3/2}$）。

这个实验的目的是测试：在非特定引导下，AI能不能通过数值实验自己发现题目错误（数值显示差额是$O(1/n)$，与$n^{-1/3}$矛盾）。这测试的是AI的"量级感知+批判性思维"——不需要知识，需要的是对数值结果的敏感度和质疑题目的勇气。

## 12. 方案的全貌——一句话到一棵树

### 12.1 一句话

**用最通用的、非知识的、最高抽象度的思维模式提示（Level→1），通过连续的、渐进的、每步都安全的发问框架，引导AI从"描述形状"渐进走到"解题"，全程追求Level之和最大化（最小知识传递），在思维路径的树状探索（DFS）中找到一条从题目到正确解答的路径。**

### 12.2 八根柱子的关系

## 13. 方案的诚实自评——它自己知道自己的边界

这套方案不是被当作完美方案提出的，它在产生时就标注了自己的边界：

### 13.1 知识瓶颈是真实存在的

214号第4章明确指出：步骤9（badly approximable数的有理逼近下界）是**纯知识瓶颈**，思维模式提示能走很远，但在某些关键节点，知识是不可替代的。系统需要在思维模式提示不够时，适时降低Level走向知识端。

### 13.2 预演是乐观上界

215号附录A明确指出：预演中AI在Q5自己发现了q(x)=x²+x-1，这是最关键的一步。实际中AI可能试别的多项式，或者想不到用x²+x-1这个组合。预演Level SUM=8.45是乐观上界，实际预期6-8，最坏4-6。

### 13.3 非特定性危机是方案自己暴露的

218号不是外部批判的产物，而是方案在guided_001成功后**自己做的诚实分析**。它承认Q3-Q4发生了特定化，承认"即使Q的形式是非特定的元认知指令，引导者在选择引用哪些AI内容时，已经在做特定化判断"，承认需要对照实验来验证非特定化引导的有效性边界。

### 13.4 完全非特定化可能不够

218号第10.4节明确写道："完全非特定化可能降低成功率。需要找到'非特定化但有效'的平衡点——或者诚实承认'完全非特定化不够，需要某种半特定化'。这个问题的答案只能通过实验获得，不能通过理论推导。"

| 最小知识传递 | argmax ΣLevel(h_i) s.t. AI在H引导下完成解题。每条提示尽可能取高Level值 |
| Level SUM | 一次引导过程中所有提示的Level之和。最大化Level SUM = 最小知识传递 |
| 降Level | 高Level提示失败后，降低Level走向知识端。每次降Level记录原因 |
| DFS引导架构 | 引导者陪着做题AI做深度优先搜索，搜索空间是提示候选树，评估函数是Level |
| 回溯铁律 | DFS失败时必须启动新Session，禁止在原Session中回溯 |
| 节点同一性 | 路径同一性为主（node_id由Q路径确定），状态同一性为辅（A是概率性的） |
| 非特定性 | Q不依赖于特定题目的特定解答路径。换一道完全不同的题，用相同的Q仍能获得类似启发 |
| 特定性 | Q隐含地指向特定解答路径。通过引用特定内容，隐含地引导AI走特定路径 |
| 隐含筛选 | 引导者通过选择性引用AI自己选的方向，隐含地帮AI筛选了方向——特定化的隐蔽形式 |
