# 82-题库作为数学思维积累方向

## 背景

2026-08-03，在讨论数学大师项目的基础设施选型（81 号文档）后，用户提出：

> 我觉得，题库，其实是一个非常好的数学思维、思路积累的方向，你说对吗？

本文档记录对这个洞察的完整论证，作为项目认知基础的补充（80 号文档的延伸）。

---

## 一、核心论点

**一道题的解法路径，本身就是依赖图中一条思维路径的完整记录。**

星学项目中，依赖图的实证来源是命例——大师批命时实际调用了哪些知识、沿什么路径思考。数学中对应的东西就是题解——解题时实际调用了哪些定理、用了什么工具、怎么转换的。题库是**思维路径的结构化语料库**。

---

## 二、五个层次的价值

### 2.1 解法路径 = 依赖图的实证边

一道几何题的解法："作辅助线→转化为相似三角形→用相似比→得到长度关系→答案"。这条路径在依赖图中就是：

```
问题节点 → 相似三角形 → 相似比 → 长度关系 → 答案
```

每一步都是一条边，每条边都有实证来源（这道题确实这么解的）。

星学 POC 的依赖图是从古籍歌诀和命例中提取的；数学版的依赖图可以从题解中提取——而且更精确，因为数学解法的每一步都是可验证的，不像命例分析有主观性。

### 2.2 一题多解 = 图结构（而非线性链）的实证

同一道题往往有多种解法：代数法、几何法、组合法、分析法。这对应依赖图中从问题节点到答案节点的**多条路径**。

这直接验证了 xishujuzhen 的核心设计——思维是图结构的，不是线性的 chain-of-thought。如果每道题只有一种解法，线性链就够了；正因为有多解，才需要图。

### 2.3 不同解法之间的映射 = 跨领域映射边

一道题既可以用代数方法解，又可以用拓扑方法解——两条路径之间的对应关系，就是 80 号文档中说的"跨领域映射边"（数学版相比星学版的最大增量）。

**典型案例：Cayley-Hamilton 定理**
- 路径A（矩阵证明）：特征多项式 → 代入矩阵 → 矩阵恒等式
- 路径B（模论证明）：模的正合序列 → Nakayama 引理 → 结论
- 路径C（多项式环证明）：行列式恒等式 → 伴随矩阵 → 多项式整除

三条路径之间的映射，就是代数→模论→多项式环的跨领域结构同构。题库中大量这样的例子，是跨领域映射边最丰富的实证来源。

### 2.4 难度梯度 = POC 扩展的自然阶梯

| 题目难度 | 依赖路径长度 | 跨领域程度 | 对应星学 POC |
|---|---|---|---|
| 基础题 | 2-3 节点 | 单领域 | POC-1（5节点小图） |
| 中等题 | 5-10 节点 | 1-2 个领域 | POC-2/3 |
| 竞赛题 | 10-30 节点 | 2-3 个领域 | POC-4/5 |
| 研究级问题 | 30-100+ 节点 | 多领域 | POC-7（71节点） |

星学 POC 从 5 节点到 71 节点的扩展路径，在数学中可以自然地用题目难度梯度来实现——不需要人为设计复杂场景，题目本身就有天然的复杂度阶梯。

### 2.5 卡点 = 依赖图缺口的发现机制

解题时卡住的地方，几乎总是因为"不知道该调用什么知识"——这正是依赖图中缺失的边。收集卡点（"我在这道题的第3步卡住了，不知道下一步该用什么"）就是在发现依赖图的缺口。

这比星学中的"审计遗漏"更精确——数学中卡点是可以明确标注的（第几步、什么类型），而星学中的审计遗漏更模糊。

## 三、题库的边界：诚实面对

题库是**思维积累的素材**，不是研究能力的全部。80 号文档列了七层能力：

| 能力层 | 题库能训练吗 | 说明 |
|---|---|---|
| 1. 解题级研究 | **能，这是题库的主场** | 题库直接训练这个 |
| 2. 证明构造 | **能，证明题就是训练这个** | 证明题的解法路径就是证明构造的实例 |
| 3. 猜想提出 | 部分能 | 归纳猜想题能训练，但大部分猜想需要开放探索 |
| 4. 跨领域类比 | **能，一题多解的跨领域映射** | 不同解法间的映射就是跨领域边 |
| 5. 识别问题本质 | 部分能 | "这道题本质上是XX问题"的识别 |
| 6. 研究方向价值判断 | 不能 | 需要对领域的全局理解，超出题库范围 |
| 7. 大型证明组织 | 不能 | 需要研究级规模，超出单题范围 |

题库覆盖 1、2、4 层，部分覆盖 3、5 层，不覆盖 6、7 层。所以题库是**起点和基础**，不是终态。但它是一个非常好的起点——通过题库积累的依赖图，可以逐步扩展到研究级问题。

## 四、题库资源

| 来源 | 特点 | 价值 | 许可证/可用性 |
|---|---|---|---|
| **MathLib 100 Theorems** | Freek Wiedijk 的 100 个经典定理形式化 | 形式化验证的标杆题 | Apache 2.0（MathLib） |
| **IMO/CMO 竞赛题** | 完整解法、难度梯度、多解法常见 | 思维路径的优质语料 | 公开题面，解法版权各异 |
| **Putnam** | 美国大学生数学竞赛，覆盖大学数学 | 大学级思维路径 | 公开题面和解法 |
| **教材习题** | 覆盖面广、有难度梯度 | 基础思维路径积累 | 版权限制，需选用开源教材 |
| **Proofs from THE BOOK** | Erdős 的"天书"证明，每种最优美的证明 | 大师级思维路径的标杆 | 书籍版权，需人工录入关键案例 |
| **arXiv 研究论文** | 研究级问题和解法 | 扩展到 6、7 层能力的素材 | arXiv 开放许可 |

### 4.1 Proofs from THE BOOK 的特殊价值

特别值得注意——它收录的是 Erdős 心目中"上帝的天书里应该有的最优美证明"。这些证明代表的是大师级思维路径的标杆，正好对应 xishujuzhen 要工程化的"综述博士"思维。

**为什么标杆重要**：依赖图的质量上限 = 构建者的数学水平（80 号文档"关键的诚实面对"）。要构建高质量的依赖图，需要高质量的思维路径样本。Proofs from THE BOOK 提供的就是"什么是好的思维路径"的标准——它不是最长的路径，不是最短的路径，而是**最优美的路径**，即大师会选择的路径。

### 4.2 MathLib 100 Theorems 的双重价值

1. **思维路径语料**：100 个经典定理的形式化证明，每个都是一条完整的思维路径
2. **形式化验证基准**：这些定理已经在 Lean 4 中形式化，可以用来验证 xishujuzhen 提示下 AI 提出的证明是否正确

### 4.3 竞赛题的梯度价值

IMO/CMO/Putnam 竞赛题有天然的难度梯度（从初等题到研究级难题），且：
- 题面公开，易于获取
- 有官方解法和多种民间解法（一题多解）
- 有明确的难度分级
- 覆盖代数/几何/数论/组合/分析等多个领域

## 五、题库数据的结构化方案

题库不只是"题目+答案"的文本集合。要服务于依赖图构建，每道题需要结构化为：

### 5.1 题目记录结构

```
{
  "problem_id": "IMO-2025-P3",
  "source": "IMO 2025 Problem 3",
  "difficulty": "research-adjacent",
  "domain": ["combinatorics", "number_theory"],
  "statement": "...",                    // 题目陈述
  "statement_mathml": "...",             // MathML 格式（如有）
  "solutions": [
    {
      "method": "generating_function",
      "path": [                          // 解法路径（依赖图的实证边）
        {"step": 1, "concept": "generating_function", "action": "construct"},
        {"step": 2, "concept": "coefficient_extraction", "action": "extract"},
        {"step": 3, "concept": "partial_fraction", "action": "decompose"},
        {"step": 4, "concept": "asymptotic_analysis", "action": "estimate"},
        {"step": 5, "concept": "conclusion", "action": "derive"}
      ],
      "domains_traversed": ["combinatorics", "analysis"],
      "cross_domain_edges": [            // 跨领域映射边
        {"from": "generating_function", "to": "complex_analysis", "type": "analogy"}
      ],
      "elegant": false,                  // 是否属于"天书级"优美证明
      "source": "official"
    },
    {
      "method": "bijective_proof",
      "path": [...],
      "domains_traversed": ["combinatorics"],
      "cross_domain_edges": [],
      "elegant": true,
      "source": "folklore"
    }
  ],
  "stuck_points": [                      // 卡点（依赖图缺口）
    {"step": 3, "description": "不知道如何处理分母的渐近行为", "missing_edge": "partial_fraction → asymptotic_analysis"}
  ],
  "lean_formalized": false,              // 是否在 Lean 4 中形式化
  "lean_proof": null                     // Lean 4 证明（如有）
}
```

### 5.2 从题目记录到依赖图

题目记录中的 `solutions[].path` 是依赖图的实证边来源：

```
对每道题的每个解法：
  对 path 中的每一步：
    如果 concept 不在依赖图节点中 → 新增节点
    如果相邻 step 之间的边不在依赖图中 → 新增边（类型：解法路径）
  对 cross_domain_edges 中的每条边：
    如果边不在依赖图中 → 新增边（类型：跨领域映射）
  对 stuck_points 中的每个卡点：
    记录为依赖图缺口（missing_edge）
```

### 5.3 ArangoDB Collections 新增

在 81 号文档的 Collections 设计基础上新增：

```
├── 题库集合（新增）
│   ├── problems（题目库）
│   │   └── {problem_id, source, difficulty, domain[], statement, statement_mathml, ...}
│   ├── solutions（解法库）
│   │   └── {solution_id, problem_id, method, path[], domains_traversed[], cross_domain_edges[], elegant, source, ...}
│   └── stuck_points（卡点库）
│       └── {stuck_id, problem_id, step, description, missing_edge, resolved, ...}
```

## 六、题库建设路径

### Phase A：标杆题库（手工，高质量）

从 Proofs from THE BOOK 和 MathLib 100 Theorems 中选取 20-50 道题，手工结构化为上述格式。这个阶段的目标不是数量，而是**建立结构化标准**——什么样的解法路径记录是好的，跨领域边怎么标注，卡点怎么描述。

### Phase B：竞赛题库（半自动，中等规模）

从 IMO/CMO/Putnam 历年题目中选取 100-200 道，用 AI 辅助结构化（AI 提取解法路径，人工审核）。这个阶段验证结构化方案的可扩展性。

### Phase C：教材习题库（自动，大规模）

从开源教材习题中批量提取，AI 自动结构化，抽样人工审核。这个阶段积累规模——数千道题，覆盖基础到中等难度。

### Phase D：arXiv 研究级（HTML 管道，研究级）

从 arXiv HTML 论文中提取研究级问题和证明（依赖 81 号文档的 arXiv HTML 管道）。这个阶段扩展到 6、7 层能力。

## 七、题库与 POC 验证的整合

题库的难度梯度天然对应 POC 的扩展阶梯：

| POC 阶段 | 题库来源 | 节点规模 | 验证目标 |
|---|---|---|---|
| 数学 POC-1 | 基础题（1-2 解法） | 5-10 节点 | 依赖图提示 vs 无提示对照 |
| 数学 POC-2 | 中等题（2-3 解法） | 12-20 节点 | 知识内容嵌入提示 |
| 数学 POC-3 | 中等题 + AI 自解读 | 12-20 节点 | 双重提示 + 双重审计 |
| 数学 POC-4 | 跨领域题（2 领域） | 20-30 节点 | 跨领域映射边验证 |
| 数学 POC-5 | 竞赛题（3 领域） | 30-50 节点 | 静态+动态分析 |
| 数学 POC-6 | 竞赛题 + 交叉审计 | 30-50 节点 | 交叉审计方法 |
| 数学 POC-7 | 研究级问题 | 70-100 节点 | 大规模可行性 |
| 数学 POC-8 | 研究级 + 闭环 | 70-100 节点 | 闭环审计标准化 |

这个对应关系意味着：**题库建设本身就是 POC 验证的准备过程**。每结构化一批题，就为对应的 POC 准备好了实验材料。二者不是独立工作线，而是同一条工作线的两个面。
