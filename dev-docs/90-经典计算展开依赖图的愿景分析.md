# 90-经典计算展开依赖图的愿景分析

> **文档定位**：分析用户提出的愿景——经典计算负责依赖图的展开（G'_topo），AI 再根据展开结果进行转译。或至少给出展开推荐供 AI 参考，保证全覆盖。
>
> **来源**：用户在确认工作系统升级方案时提出的愿景。用户自己也不确定是否可以完全实现。

## 一、愿景陈述

> 经典计算负责依赖图的展开，然后 AI 再去根据展开的结果进行翻译。或者说，至少给出可能的展开推荐，让后续转译的 AI 可以参考，这种展开推荐的价值之一在于这种展开保证了对依赖图的全覆盖。

## 二、当前状态

在 POC-2 的七步骤工作流中：

| 步骤 | 执行者 | 内容 |
|---|---|---|
| 步骤1 | 代码 | 依赖图 G 导入 ArangoDB |
| **步骤2** | **meta AI** | **生成 G'_topo（展开图拓扑骨架）** |
| 步骤3 | 代码 | TopologyVerifier 验证 G'_topo 覆盖 G |
| 步骤4 | normal AI | 按 G'_topo 转译 |

**步骤2 是 AI 做的**。AI 读取 ArangoDB 中的 G，为每个节点规划 section/position，为每条边规划 connection 类型，保持螺旋环路。

**步骤3 是验证**。如果步骤2 的 AI 遗漏了节点或边，步骤3 会发现（覆盖率 < 100%），需要回到步骤2 让 AI 重新生成。

**愿景是**：步骤2 由经典计算（代码）完成，不需要 AI 参与。或者至少，经典计算给出推荐展开，AI 在推荐基础上做语义细化。

## 三、可行性分析

### 3.1 G'_topo 的内容拆解

G'_topo 的每个节点需要确定：

| 属性 | 说明 | 经典计算能否确定 |
|---|---|---|
| `node_id` | 与 G 相同 | ✅ 直接拷贝 |
| `section` | 章节位置 | ⚠️ 需要语义判断 |
| `position` | 章节内位置 | ✅ 拓扑排序可确定 |
| `type` | static 或 dynamic | ⚠️ 需要语义判断（意识节点=dynamic） |
| `traversal_order` | 全局遍历顺序 | ✅ 拓扑排序可确定 |

G'_topo 的每条边需要确定：

| 属性 | 说明 | 经典计算能否确定 |
|---|---|---|
| `from_node_id` | 与 G 相同 | ✅ 直接拷贝 |
| `to_node_id` | 与 G 相同 | ✅ 直接拷贝 |
| `edge_type` | 与 G 相同 | ✅ 直接拷贝 |
| `section` | 边所在章节 | ⚠️ 取决于端点的 section |
| `connection` | linear/shortcut/cross_section | ⚠️ 需要语义判断 |

G'_topo 的螺旋环路需要确定：

| 属性 | 说明 | 经典计算能否确定 |
|---|---|---|
| `loop_id` | 与 G 相同 | ✅ 直接拷贝 |
| `nodes` | 与 G 相同 | ✅ 直接拷贝 |
| `circles` | 与 G 相同 | ✅ 直接拷贝 |
| `section` | 环路所在章节 | ⚠️ 取决于节点的 section |
| `traversal` | spiral_static/spiral_dynamic | ⚠️ 需要语义判断 |

### 3.2 经典计算可以自动确定的部分

**1. 拓扑同构保证（全覆盖的根本保证）**

节点集和边集完全从 G 拷贝——这保证了 100% 覆盖。不需要 AI 参与。

**2. 拓扑排序（traversal_order 和 position）**

对 G 的 depends_on 边做拓扑排序，得到一个线性顺序。这个顺序就是 traversal_order。

算法：
```
1. 提取 G 中所有 edge_type == "depends_on" 的边
2. 构建 DAG（如果 depends_on 有环，报错）
3. 对 DAG 做拓扑排序（Kahn 算法或 DFS）
4. 拓扑序 = traversal_order
```

**3. 节点类型推断（type: static/dynamic）**

在数学项目中，节点的 type 字段已经存在于 G 中（step/substep/意识）。可以直接映射：
- step/substep → static
- 意识 → dynamic

**4. connection 类型推断**

根据拓扑距离和 section 关系自动判断：
- from 和 to 在同一 section 且 position 相邻 → linear
- from 和 to 在不同 section → cross_section
- from 和 to 构成环路的回边 → shortcut

### 3.3 经典计算难以自动确定的部分

**1. section 划分**

哪些节点属于"第一章"，哪些属于"第二章"？这需要理解证明的逻辑结构。

**但是**：可以用图论算法做近似划分：
- **按依赖链长度划分**：从入口节点出发，depends_on 链的第 1-5 个节点是第一章，第 6-8 个是第二章...
- **按强连通分量划分**：环路内的节点归为同一章
- **按 calls 边的汇聚点划分**：被多个 calls 边指向的意识节点归为最后一章

**2. 意识节点的位置**

意识节点（dynamic）不是证明步骤，它的"位置"是语义概念——它应该在所有调用它的步骤之后。

**但是**：可以用图论算法确定——意识节点只出现在 calls 边的 to 端（不被 depends_on），所以拓扑排序中它自然排在后面。

**3. spiral_static vs spiral_dynamic**

这需要理解环路每次遍历的上下文是否变化。

**但是**：可以用启发式规则——如果环路节点的 type 都是 dynamic（意识），则是 spiral_dynamic；如果包含 static 节点，则是 spiral_static。

### 3.4 结论：分层实现

| 层 | 内容 | 执行者 | 可行性 |
|---|---|---|---|
| **L0 骨架展开** | 节点集+边集+拓扑排序+traversal_order | **经典计算** | ✅ 完全可行 |
| **L1 类型推断** | static/dynamic + connection 类型 | **经典计算** | ✅ 用启发式规则可行 |
| **L2 section 划分** | 章节归属 | **经典计算（推荐）+ AI（细化）** | ⚠️ 经典计算给推荐，AI 可调整 |
| **L3 语义标注** | spiral_static/dynamic + section 命名 | **AI** | ⚠️ 需要语义理解 |

## 四、分层实现方案

### L0：骨架展开（经典计算，100% 保证覆盖）

```python
def generate_g_prime_topo_skeleton(graph):
    """从依赖图 G 生成 G'_topo 骨架（保证全覆盖）"""
    
    # 1. 直接拷贝节点集和边集（保证拓扑同构）
    nodes = [node_id for node_id in graph.nodes]
    edges = [(e.from, e.to, e.edge_type) for e in graph.edges]
    
    # 2. 拓扑排序（depends_on 链）
    dag = build_dag(edges, edge_type="depends_on")
    topo_order = topological_sort(dag)  # Kahn 算法
    
    # 3. 分配 traversal_order
    for i, node_id in enumerate(topo_order):
        g_prime_topo.nodes[node_id].traversal_order = i + 1
    
    # 4. 分配 type
    for node in g_prime_topo.nodes:
        node.type = "static" if graph.nodes[node_id].type in ["step", "substep"] else "dynamic"
    
    # 5. 分配 position（section 内位置，先按拓扑序连续分配）
    for i, node_id in enumerate(topo_order):
        g_prime_topo.nodes[node_id].position = i + 1  # 初始：全局连续，后续 L2 划分 section 后重分配
    
    # 6. 分配 connection 类型
    for edge in g_prime_topo.edges:
        from_node = g_prime_topo.nodes[edge.from]
        to_node = g_prime_topo.nodes[edge.to]
        if abs(from_node.traversal_order - to_node.traversal_order) == 1:
            edge.connection = "linear"
        elif is_back_edge(edge, topo_order):
            edge.connection = "shortcut"
        else:
            edge.connection = "cross_section"
    
    # 7. 拷贝螺旋环路（圈数保持）
    for loop in graph.loops:
        g_prime_topo.loops.append({
            "loop_id": loop.loop_id,
            "nodes": loop.nodes,
            "circles": loop.circles,  # 保持不变
            "traversal": infer_traversal_type(loop, graph),  # L3 启发式
        })
    
    return g_prime_topo
```

**L0 的保证**：
- 节点覆盖：18/18（直接拷贝）
- 边覆盖：25/25（直接拷贝）
- 螺旋环路圈数：保持不变（直接拷贝）
- TopologyVerifier 验证：**1次通过，100%覆盖**（因为是从 G 直接推导的）

### L1：类型推断（经典计算，启发式规则）

```python
def infer_connection_type(edge, topo_order, sections):
    """推断边的 connection 类型"""
    from_order = topo_order[edge.from]
    to_order = topo_order[edge.to]
    
    # 回边（环路）→ shortcut
    if to_order < from_order:
        return "shortcut"
    
    # 相邻 → linear
    if abs(from_order - to_order) == 1:
        return "linear"
    
    # 跨 section → cross_section
    if sections[edge.from] != sections[edge.to]:
        return "cross_section"
    
    # 默认
    return "cross_section"

def infer_traversal_type(loop, graph):
    """推断螺旋环路的遍历类型"""
    node_types = [graph.nodes[n].type for n in loop.nodes]
    if all(t == "意识" for t in node_types):
        return "spiral_dynamic"
    return "spiral_static"
```

### L2：section 划分（经典计算推荐 + AI 细化）

```python
def recommend_sections(topo_order, graph, max_section_size=5):
    """推荐 section 划分"""
    sections = {}
    current_section = 1
    current_size = 0
    
    for node_id in topo_order:
        node_type = graph.nodes[node_id].type
        
        # 意识节点单独成章
        if node_type == "意识":
            sections[node_id] = "意识章"
            continue
        
        # 证明步骤按依赖链分段
        if current_size >= max_section_size:
            current_section += 1
            current_size = 0
        sections[node_id] = f"第{current_section}章"
        current_size += 1
    
    return sections
```

**AI 细化的空间**：AI 可以调整 section 边界（如把"紧性归约"从第一章末尾移到第二章开头），或给 section 命名（如"第一章：矩条件与sqrt5下界"）。

### L3：语义标注（AI）

- section 命名（"第一章：矩条件与sqrt5下界"）
- spiral_static/dynamic 的最终确认
- position 在 section 内的重分配

## 五、价值分析

### 5.1 全覆盖保证

L0 骨架展开**从 G 直接推导** G'_topo，节点集和边集完全拷贝。TopologyVerifier 验证必然 1次通过 100%覆盖。

**这消除了 POC-2 步骤2 的不确定性**——meta AI 生成 G'_topo 时可能遗漏节点或边，需要步骤3 验证后回退。经典计算生成则不会有这个问题。

### 5.2 减少 AI 工作量

| 模式 | AI 需要做的工作 |
|---|---|
| 当前（POC-2） | AI 从零规划 G'_topo：section/position/type/connection 全部由 AI 决定 |
| L0 骨架 | AI 不参与 G'_topo 生成，直接进入步骤4 转译 |
| L0+L1 | AI 不参与，经典计算给出完整骨架+类型推断 |
| L0+L1+L2 | AI 只做 section 细化（调整边界+命名） |
| L0+L1+L2+L3 | AI 做语义标注（当前模式的子集） |

### 5.3 展开推荐的价值

即使不完全实现 L0（经典计算直接生成 G'_topo），只实现"展开推荐"也有价值：

- AI 在生成 G'_topo 时，可以参考经典计算的推荐
- 推荐保证了全覆盖——AI 在推荐基础上调整不会遗漏节点
- 推荐提供了合理的默认值——AI 只需要做语义优化

### 5.4 与工作系统升级的关系

这个愿景是工作系统升级的一部分——它把七步骤工作流中的步骤2 从 AI 做变为经典计算做（或经典计算推荐+AI 细化）。这进一步减少了 AI 的工作量，提高了确定性。

## 六、实现路径

### 阶段1：实现 L0 骨架展开

- 编写 `topo_generator.py`：从 ArangoDB 中的 G 生成 G'_topo 骨架
- 拓扑排序 + 节点集/边集拷贝 + 螺旋环路保持
- 用 POC-2 的依赖图测试：生成的骨架是否能通过 TopologyVerifier 100%覆盖

### 阶段2：实现 L1 类型推断

- 在 `topo_generator.py` 中加入 connection 类型推断和 type 推断
- 用 POC-2 的 G'_topo（meta AI 生成的）作为基准，对比经典计算的推断与 AI 的判断

### 阶段3：实现 L2 section 推荐

- 在 `topo_generator.py` 中加入 section 划分推荐
- 测试：推荐与 meta AI 的 section 划分的差异有多大

### 阶段4：验证

- 用 POC-2 的依赖图，经典计算生成 G'_topo
- TopologyVerifier 验证覆盖
- 与 meta AI 生成的 G'_topo 对比
- 如果经典计算版本通过验证，可以替代步骤2

### 阶段5：集成到七步骤工作流

- 步骤2 从"meta AI 生成"变为"经典计算生成（或推荐）"
- 如果完全实现 L0+L1，步骤2 不需要 AI 参与
- 如果实现 L2，步骤2 变为"经典计算推荐 + AI 细化"

## 七、诚实面对的不确定性

1. **section 划分的语义性**：L2 的 section 划分是图论近似，不一定符合数学证明的逻辑结构。AI 的细化可能大幅调整。

2. **connection 类型的边界情况**：L1 的启发式规则在简单图上有效，但在复杂图（如多个环路交叉）上可能不准确。

3. **spiral_static/dynamic 的语义性**：L1 的启发式规则（意识节点=dynamic）是近似，不一定总是正确。

4. **与 meta AI 的质量对比**：经典计算的 G'_topo 可能不如 meta AI 的"好"（从转译质量角度），因为 AI 能理解证明的逻辑结构。但经典计算的 G'_topo **保证全覆盖**，这是 AI 不能保证的。

5. **愿景的完全实现可能不可行**：L3 的语义标注（section 命名、spiral 类型最终确认）可能必须由 AI 完成。经典计算能做到 L0+L1+L2 推荐，L3 可能是 AI 不可替代的。

## 八、建议

**建议实现 L0+L1（骨架展开+类型推断），作为步骤2 的经典计算版本。L2 作为推荐供 AI 参考。L3 保留给 AI。**

这样：
- 步骤2 变为"经典计算生成骨架 + AI 语义细化"
- TopologyVerifier 仍然验证全覆盖（L0 保证）
- AI 的工作量减少（只需要做 L3 语义标注）
- 全覆盖由经典计算保证（不需要步骤3 的回退）
