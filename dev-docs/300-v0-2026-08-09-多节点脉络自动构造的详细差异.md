## 1. 脉络是什么

脉络是从根到当前节点的完整路径+方向Q，构造给新推理AI的输入文本。

当AI-1终止后，系统在AI-1的终点节点检索方向Q，然后构造"你之前已经证明了X、Y、Z，现在请继续探索方向W"的脉络文本给新AI。新AI理解验证已有推理后从转折点继续。

脉络是树生长引擎推动关系1的核心组件——没有脉络就没有"引导树→推理AI"的推动。

---

## 2. 两种脉络：根节点脉络 vs 多节点脉络

脉络有两种情况：

### 2.1 根节点脉络

AI-1从根节点开始就走错了方向（根分叉），AI-1终止后，新AI从根节点重新开始走另一条路。脉络只有题目+方向Q。

### 2.2 多节点脉络

AI-1走了几步才走错（点分叉），新AI从AI-1的某个中间节点继续。脉络包含AI-1走过的所有节点的处境+方向Q。

多节点脉络是更复杂的情况——需要从数据库中查从根到当前节点的所有节点和边，提取每个节点的处境描述，构造完整的推理路径文本。

## 3. Worktree侧的实现

### 3.1 代码位置

tree_engine.py中的`construct_path_text`函数（约30行），嵌在tree_engine.py中，不是独立文件。

### 3.2 完整代码

```python
def construct_path_text(problem_text: str, path_nodes: list, direction_q: str) -> str:
    """
    构造给新推理AI的脉络文本。

    简化版：根节点的脉络 = 题目 + 方向Q
    """
    if not path_nodes:
        # 从根节点开始
        text = f"""你正在解答以下数学题：

{problem_text}

系统识别出以下探索方向，请在此方向的引导下解题：

【方向】{direction_q}

请理解这个方向的含义，然后继续推理，给出完整的推理过程。
最终答案用 \\boxed{{}} 框出。
"""
    else:
        # 从中间节点开始（后续版本）
        text = f"""你正在解答以下数学题：

{problem_text}

之前已经进行了以下探索：
"""
        for i, node in enumerate(path_nodes):
            text += f"\n[步骤{i+1}] {node['situation_text']}\n"

        text += f"\n请理解验证以上路径后，继续探索以下方向：\n【方向】{direction_q}\n\n继续推理，给出完整的推理过程。\n最终答案用 \\boxed{{}} 框出。"

    return text
```

### 3.3 根节点脉络（path_nodes为空时）

只有题目+方向Q，没有已有推理。

### 3.4 多节点脉络（path_nodes非空时）

### 3.6 POC-VMS-8 tree组的手工脉络

POC-VMS-8的lineage组和tree组用了手工编写的脉络，不是自动生成的。

**1631_lineage.txt**的内容：

```
For a positive integer $a$, define a sequence of integers $x_{1}, x_{2}, \ldots$ by letting $x_{1}=a$ and $x_{n+1}=2 x_{n}+1$ for $n \geq 1$. Let $y_{n}=2^{x_{n}}-1$. Determine the largest possible $k$ such that, for some positive integer $a$, the numbers $y_{1}, \ldots, y_{k}$ are all prime.

要求：给出完整的解答，写入 proof.md 文件。

=== 已建立的脉络（请先理解并验证，然后从转折点继续）===

以下是本题已经建立的推理脉络。请先理解并验证每一步，然后从最后一步继续完成证明。

**已完成的推理：**

1. 如果 $y_i = 2^{x_i} - 1$ 是素数，则 $x_i$ 必须是素数（因为如果 $x_i = mn$，则 $2^m - 1 \mid 2^{x_i} - 1 = y_i$，所以 $y_i$ 合数）。

2. 因此如果 $y_1, y_2, \ldots, y_k$ 都是素数，则 $x_1, x_2, \ldots, x_k$ 都是素数。特别地 $a = x_1$ 是素数。

3. $x_1 = a$，$x_2 = 2a + 1$，$x_3 = 4a + 3$。

4. 我们要证明 $k \leq 2$。反证：假设 $y_1, y_2, y_3$ 都是素数，则 $x_1, x_2, x_3$ 都是素数。

5. 如果 $a$ 是奇素数（$a \geq 3$），则 $x_2 = 2a + 1 \equiv 3 \pmod{4}$，$x_3 = 4a + 3 \equiv 7 \pmod{8}$。

**请从这里继续：** 你需要利用 $x_3 \equiv 7 \pmod{8}$ 这个条件。考虑2是模 $x_3$ 的二次剩余还是非剩余？用Euler准则 $2^{(p-1)/2} \equiv \left(\frac{2}{p}\right) \pmod{p}$ 会得到什么？这如何与 $y_2 = 2^{x_2} - 1$ 联系起来？
```

**1843_tree.txt**的内容：

```
The equation $(x-1)(x-2) \cdots(x-2016)=(x-1)(x-2) \cdots(x-2016)$ is written on the board. One tries to erase some linear factors from both sides so that each side still has at least one factor, and the resulting equation has no real roots. Find the least number of linear factors one needs to erase to achieve this.

要求：给出完整的解答，写入 proof.md 文件。

=== 已建立的脉络（从bare AI的推理中提取，请先理解验证，然后从转折点继续）===

**问题重述：** 板上写着 $(x-1)(x-2)\cdots(x-2016)=(x-1)(x-2)\cdots(x-2016)$。擦除两边的一些线性因子，使每边至少剩一个因子，且结果方程无实根。求最少擦除数。

**已完成的推理：**

1. 擦除后，左边是子集 $A \subseteq \{1,2,\ldots,2016\}$ 的因子乘积，右边是子集 $B$ 的因子乘积。需 $A \neq \emptyset$，$B \neq \emptyset$，且 $\prod_{a \in A}(x-a) = \prod_{b \in B}(x-b)$ 无实根。

2. 擦除数 = $4032 - |A| - |B|$，最小化擦除数 = 最大化 $|A| + |B|$。

3. 如果 $|A| \neq |B|$，多项式 $f(x) = \prod_A - \prod_B$ 的次数为 $\max(|A|,|B|)$，首项系数为 $\pm 1$，当 $|x| \to \infty$ 时 $f$ 取正负值，由IVT有实根。所以必须有 $|A| = |B| = 1008$，擦除数 $\geq 2016$。

4. 当 $|A| = |B| = 1008$ 时，$f(x)$ 次数 $\leq 1007$。需要选择 $A, B$ 使 $f(x) = 0$ 无实根。

**卡点：** 如何选择 $A, B$（各1008个因子）使方程无实根？多项式符号分析太复杂。

**请从这里继续（翻译方向：T01 模算术）：**
不要用多项式符号分析。把因子按模4分类——$k \equiv 0,1,2,3 \pmod{4}$。
左边保留 $k \equiv 0,1 \pmod{4}$ 的因子，右边保留 $k \equiv 2,3 \pmod{4}$ 的因子。
然后证明：对任意实数 $x$，左右两边的乘积符号相反（或一边为零另一边不为零），所以方程无实根。
```

这些手工脉络比自动生成的脉络丰富得多——包含完整的推理步骤、明确的卡点、具体的方向引导。但它们是手工编写的。

## 4. Grove侧的实现

### 4.1 代码位置

独立的`xishujuzhen/research_runtime/tree_engine/path_constructor.py`文件（172行），`PathConstructor`类。

### 4.2 完整代码结构

```python
class PathConstructor:
    def __init__(self, tree_store: TreeStore):
        self.tree_store = tree_store

    def construct_path_text(self, node_key: str, direction_q: str) -> str:
        # 获取路径上的所有节点和边
        path_nodes = self.tree_store.get_path_nodes(node_key)
        path_edges = self.tree_store.get_path_edges(node_key)
        # ...构造脉络文本...

    def _get_node_summary(self, node: TreeNode) -> str:
        """获取节点的简要描述。"""
        if node.situation_text:
            text = node.situation_text[:300]
            if len(node.situation_text) > 300:
                text += "..."
            return text
        # 降级：从trajectory_segment提取
        segment = node.trajectory_segment or {}
        thinking = segment.get("thinking", "")
        if thinking:
            return thinking[:300] + ("..." if len(thinking) > 300 else "")
        return "(无处境描述)"

    def _extract_proven(self, node: TreeNode) -> str:
        """从节点situation提取已证明的结论。"""
        situation = node.situation or {}
        v_t = situation.get("V_t", [])
        if v_t:
            summaries = []
            for v in v_t:
                if isinstance(v, dict):
                    summaries.append(v.get("description", str(v)))
                else:
                    summaries.append(str(v))
            return "; ".join(summaries)[:500]
        return ""

    def _extract_representation(self, node: TreeNode) -> str:
        """从节点situation提取当前数学表示。"""
        situation = node.situation or {}
        f_t = situation.get("F_t", [])
        if f_t:
            return "; ".join(str(f) for f in f_t)[:300]
        return ""

    def _extract_stuck(self, node: TreeNode) -> str:
        """从节点situation提取当前卡点。"""
        situation = node.situation or {}
        u_t = situation.get("U_t", [])
        if u_t:
            summaries = []
            for u in u_t:
                if isinstance(u, dict):
                    desc = u.get("description", str(u))
                    severity = u.get("severity", "")
                    if severity:
                        summaries.append(f"{desc}({severity})")
                    else:
                        summaries.append(desc)
                else:
                    summaries.append(str(u))
            return "; ".join(summaries)[:500]
        return ""
```

### 4.3 自动从数据库查路径

```python
path_nodes = self.tree_store.get_path_nodes(node_key)
path_edges = self.tree_store.get_path_edges(node_key)
```

不需要从内存列表取节点——直接从ArangoDB查从根到当前节点的所有节点和边。利用tree_nodes集合的`path_from_root`冗余字段加速查询。

### 4.4 脉络格式（多节点）

```python
lines.append(f"你正在解答以下数学题：")
lines.append(problem_text)
lines.append("")
lines.append("之前已经进行了以下探索：")
lines.append("")

for i, node in enumerate(path_nodes):
    if i == 0:
        # 根节点
        lines.append(f"[节点{i}] 初始处境：{self._get_node_summary(node)}")
    else:
        lines.append(f"[节点{i}] 处境：{self._get_node_summary(node)}")
        # 输出已证明/当前表示（如果situation中有）
        proven = self._extract_proven(node)
        if proven:
            lines.append(f"  已证明：{proven}")
        representation = self._extract_representation(node)
        if representation:
            lines.append(f"  当前表示：{representation}")

    # 如果有对应的边（提示Q），输出
    if i < len(path_edges):
        edge = path_edges[i]
        lines.append(f"  → 提示：{edge.hint_q}")

# 最后一个节点的卡点
last_node = path_nodes[-1]
stuck = self._extract_stuck(last_node)
if stuck:
    lines.append(f"  卡在：{stuck}")

lines.append("")
lines.append("请理解验证以上路径后，继续探索以下方向：")
lines.append(direction_q)
lines.append("")
lines.append("继续推理，给出完整的推理过程。")

return "\n".join(lines)
```

每个节点包含：
- `[节点N] 处境`：situation_text的前300字符作为摘要
- `已证明`：从situation的V_t字段提取（已验证核心）
- `当前表示`：从situation的F_t字段提取（猜想前沿）
- `→ 提示`：边的hint_q内容
- `卡在`：最后一个节点的U_t字段（未探索诊断）

### 4.5 三个提取方法的六元组来源

`_extract_proven`从V_t提取、`_extract_representation`从F_t提取、`_extract_stuck`从U_t提取——这些字段来自六元组。

六元组是`DevinCliParserProvider`解析thinking后输出的ParseResult中的六元组状态（V_t/F_t/O_t/U_t/T_t/S_t）。`DevinCliParserProvider`用devin cli作为LLM parser，解析thinking文本为结构化的语义事件序列+思维轨迹图节点+六元组状态。

## 5. 差异的具体内容

| 维度 | Worktree侧 | Grove侧 |
|---|---|---|
| 代码位置 | tree_engine.py中30行函数 | 独立172行文件 |
| 路径获取 | 从内存`state['node_keys']`列表 | 从ArangoDB查`get_path_nodes`+`get_path_edges` |
| 节点摘要 | situation_text原样输出 | situation_text前300字符+`...`截断 |

## 6. 这个差异意味着什么

### 6.1 脉络质量影响新AI的起点质量

POC-VMS-8的实验结果证明了脉络质量的重要性：
- lineage组（手工脉络）：2/2 = 100%
- tree组（手工提取脉络）：2/3 = 67%
- bare组（无脉络）：0/3 = 0%

脉络越完整，新AI越能理解已有推理并在正确位置继续。

### 6.2 Worktree侧的自动脉络给新AI看到的信息

Worktree侧的自动脉络只有`situation_text`（操作类型描述），新AI看到的脉络是：

```
你正在解答以下数学题：
[题目原文]

之前已经进行了以下探索：

[步骤1] observation

[步骤2] candidate

[步骤3] resolution

[步骤4] claim

请理解验证以上路径后，继续探索以下方向：
【方向】[direction_q]
```

新AI看到的只是每一步的操作类型（observation/candidate/resolution/claim），不知道每一步**具体做了什么**、**证明了什么**、**当前表示是什么**、**卡在哪里**。

### 6.3 Grove侧的自动脉络给新AI看到的信息

Grove侧的自动脉络包含结构化字段，新AI看到的脉络是：

```
你正在解答以下数学题：
[题目原文]

之前已经进行了以下探索：

[节点0] 初始处境：题目给出的条件和目标
  → 提示：你选择哪个方向？第一步是什么？
[节点1] 处境：AI得到了稳定性方程5D=3√5(B_r-B_s)+2C
  已证明：中心化结果、q(x)定义、两个恒等式
  当前表示：稳定性方程5D=3√5(pn-k)
  → 提示：badly approximable推出|D|下界
[节点2] 处境：...
  卡在：D的量级问题

请理解验证以上路径后，继续探索以下方向：
badly approximable推出|D|下界

继续推理，给出完整的推理过程。
```

新AI看到的不仅是每一步的操作类型，还有：
- **每一步证明了什么**（V_t→已证明）
- **当前数学表示是什么**（F_t→当前表示）
- **每一步的方向引导是什么**（edge.hint_q→提示）
- **卡在哪里**（U_t→卡在）

这让新AI能更精确地理解已有推理的状态，从正确位置继续。

### 6.4 信息量对比

| 信息维度 | Worktree侧自动脉络 | Grove侧自动脉络 | Worktree侧手工脉络 |
|---|---|---|---|
| 每步操作类型 | ✅ situation_text | ✅ situation_text前300字符 | ✅ 完整描述 |
| 每步证明了什么 | ❌ | ✅ V_t字段 | ✅ 完整推理步骤 |
| 当前数学表示 | ❌ | ✅ F_t字段 | ✅ 具体公式 |
| 每步方向引导 | ❌ | ✅ edge.hint_q | ✅ 具体方向 |
| 卡点描述 | ❌ | ✅ U_t字段 | ✅ 明确卡点 |
| 可规模化 | ✅ 自动 | ✅ 自动 | ❌ 手工 |

Worktree侧的自动脉络在信息量上不如Grove侧的自动脉络，但Worktree侧的手工脉络在信息量上超过两者——只是不能规模化。

## 7. 这个差异的局限

### 7.1 Grove侧的六元组质量取决于LLM解析质量

Grove侧的`_extract_proven`/`_extract_representation`/`_extract_stuck`从六元组V_t/F_t/U_t提取信息。六元组是`DevinCliParserProvider`用devin cli作为LLM parser解析thinking后输出的。

如果LLM解析thinking后输出的六元组不准确，脉络中的"已证明""当前表示""卡在"字段也不准确。Grove侧的六元组解析在case_253中没有做严格的准确性验证——case_253验证的是整体闭环（3AI/59节点/solved），不是六元组每个字段的准确性。

### 7.2 Worktree侧的手工脉络比Grove侧的自动脉络更丰富

POC-VMS-8的`1843_tree.txt`手工脉络包含完整的4步推理+卡点+具体方向引导，比Grove侧path_constructor.py自动生成的脉络（situation_text前300字符+V_t/F_t/U_t字段）信息量更大。

但手工脉络不能规模化——每道题都需要人工编写，不能自动化。Worktree侧知道这个限制并明确列为待验证项。

### 7.3 两边都没有验证"自动脉络质量对新AI成功率的影响"

Worktree侧验证了手工脉络（lineage 100% vs tree 67%），Grove侧验证了自动脉络（case_253 solved），但没有做过"同一道题用手工脉络vs自动脉络的对照实验"。

因此我们不知道：
- Grove侧的自动脉络（含V_t/F_t/U_t）比Worktree侧的自动脉络（只有situation_text）对新AI成功率的提升有多大
- 自动脉络（Grove侧）是否能达到手工脉络（Worktree侧POC-VMS-8）的效果

---

## 8. 为什么两边会有这个差异

### 8.1 Worktree侧的优先级

Worktree侧在分叉后的工作重点是**验证设计理念的有效性**——tell+hint二元组、三层Pipe架构、概念树。脉络构造是实现这些理念的工具之一，但不是验证重点。

Worktree侧用手工脉络验证了"脉络继承+方向注入"的有效性（POC-VMS-8：lineage 100%，tree 67%），然后就去验证更核心的设计理念（POC-VMS-9/10的tell端去特化和小概念标记分辨）。自动脉络构造留到后面做（已列为待验证项）。

### 8.2 Grove侧的优先级

Grove侧在分叉后的工作重点是**让系统在真实环境中跑通**——case_253的端到端树生长引擎。脉络构造是树生长引擎的核心组件之一（推动关系1需要构造脉络给新AI），必须自动化才能让系统无人值守运行。

所以Grove侧优先实现了path_constructor.py的自动化——包含从数据库查路径、提取六元组字段、构造完整脉络格式。

### 8.3 两边的选择都是合理的优先级排序

Worktree侧验证概念有效性优先，Grove侧建设生产系统优先。这个差异不是"谁走得远"，而是"两边在不同阶段做了不同的事情"。

如果Worktree侧进入生产系统建设阶段，它也会需要自动脉络构造——它的283号和08-验证状态已经明确将此列为待验证项。如果Grove侧进入概念验证阶段，它也会需要做手工脉络对照实验——验证自动脉络vs手工脉络的效果差异。

---

## 9. 总结

### 9.1 差异的精确描述

两边在多节点脉络自动构造上的差异是：

- **Worktree侧**实现了根节点脉络自动构造（题目+方向Q）和多节点脉络简化自动构造（只有situation_text），完整的多节点脉络用手工编写。已明确将自动脉络采集列为待验证项。
- **Grove侧**实现了完整的多节点脉络自动构造（situation_text+V_t已证明+F_t当前表示+U_t卡点+edge.hint_q提示），全部自动从数据库查路径和提取六元组字段。

### 9.2 差异的影响

Grove侧的自动脉络给新AI的信息更丰富——新AI不仅知道每一步做了什么操作，还知道每一步证明了什么、当前表示是什么、卡在哪里。这让新AI能更精确地理解已有推理的状态，从正确位置继续。

### 9.3 差异的局限

1. Grove侧的六元组质量取决于LLM解析质量，未做严格的准确性验证
2. Worktree侧的手工脉络比Grove侧的自动脉络更丰富，但不能规模化
3. 两边都没有验证"自动脉络质量对新AI成功率的影响"

### 9.4 差异的根源

两边在不同阶段做了不同的事情——Worktree侧在验证概念有效性（用手工脉络够了），Grove侧在建设生产系统（必须自动化）。这不是"谁走得远"，而是"两边在不同阶段做了不同的事情"。
