## 1. 代际定位

### 1.1 第六代系统的命名

如果Worktree侧的系统叫"第五代"（tell+hint二元组+三层Pipe架构+概念树），那么Grove侧的系统可以叫**第六代**——它的核心特征是"系统与推理AI并行运行"+sessions.db采集+串行多AI树生长引擎+端到端实验验证。

### 1.2 第六代与第五代的关系

第六代不是凭空出现的——它从四代系统继承了理论基础，在第五代同时期独立发展了工程实现。第六代和第五代是**同期独立发展**的两个方向：

| 维度 | 第五代（Worktree侧） | 第六代（Grove侧） |
|---|---|---|
| 聚焦点 | tell端识别机制的理论框架 | 端到端效果验证的工程实现 |
| 核心产出 | tell+hint二元组理论、三层Pipe架构、概念树 | 可运行的树生长引擎、ArangoDB数据、case_253 solved |
| 验证方式 | POC-VMS-8/9/10（交叉验证、干扰tell） | A/B对照实验、串行多AI实验 |
| 技术说明书状态 | 52个文件已写完 | 尚未编写 |

### 1.3 第六代技术说明书的定位

第六代技术说明书**不应该**像第五代那样写52个文件——Grove代的优势是工程实践，不是理论框架。建议写一个**精简的技术说明书**（10-15个文件），重点覆盖：

1. **系统概述**（267号面相+三个推动关系）
2. **工程实现**（tree_engine + sessions_db_reader + node_extractor + termination_detector + path_constructor + pattern_matcher）
3. **实验验证**（A/B对照实验 + case_253端到端树生长实验）
4. **已知局限与改进方向**（policy选择逻辑 + 从第五代理论学习的升级路径）
5. **与第五代系统的关系**（互补性 + 合流路径）

这个精简说明书的核心价值是**可运行的端到端实践验证**——这是第五代系统技术说明书缺少的。
