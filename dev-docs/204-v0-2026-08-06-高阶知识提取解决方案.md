## 文档信息

- **编号**：204
- **版本**：v0

- **性质**：方案文档——解决201号AI在知识吸收中的缺位
- **解决问题**：201号文档诊断的高阶知识提取缺位
- **依赖**：201号 + batch_extractor.py + cognition_units_math.json + poc3/extraction_audit.md

---

## 一、问题回顾

201号文档诊断了当前系统在知识吸收阶段的AI缺位：

1. **三层提取未常态化**：`batch_extractor.py`有L1/L2/L3提取，只在POC3做过一次
2. **提取未连接吸收pipeline**：`batch_extractor.py`是独立脚本，新内容进来不自动触发
3. **L2/L3未存入稀疏矩阵**：提取结果是JSON文件，没写入ArangoDB的K维度
4. **AI未被用于提取**：subagent用硬编码prompt，不针对内容定制
5. **L4层完全不存在**：用户提到的"哲学"层无对应

---

## 二、能不能解决？

**能解决，但不同层级的难度差异很大：**

| 层级 | 能否解决 | 难度 | 原因 |
|---|---|---|---|
| L1自动化 | **能** | 低 | 已有`batch_extractor.py`，只需集成 |
| L2常态化 | **能** | 中 | 已有5个意识节点+POC3验证，需要pipeline化 |
| L3常态化 | **能** | 中高 | POC3验证过1条通过1条不通过，质量把控是关键 |
| L4新建 | **部分能** | 高 | 完全没有基础，需要定义schema+提取方法+质量标准 |
| 全流程自动化 | **部分能** | 很高 | AI提取质量不稳定，需要人审环节 |

**关键判断**：L1-L3是工程问题——已有基础，需要pipeline化。L4是探索性问题——需要先定义"什么是哲学洞察"再实现。全流程自动化不现实——AI提取的高阶知识质量需要人工审核。

---

## 三、能在多大程度上解决？

### 3.1 L1-L3常态化（解决程度：80%）

**已有基础**：
- `batch_extractor.py:36-44`已定义L1/L2/L3提取prompt
- `cognition_units_math.json`已有5个L2意识节点
- `poc3/extraction_audit.md`已验证L2/L3质量审计方法
- ArangoDB已有K维度的collection结构

**需要做的**：
1. 把`batch_extractor.py`从独立脚本改造成吸收pipeline的一个环节
2. 提取结果写入ArangoDB的K维度对应位置
3. 每次吸收新内容自动触发L1-L3提取
4. 提取结果经质量审计后才能发布

**解决程度**：80%——pipeline化是工程问题。剩余20%是"AI提取质量不稳定"——POC3中L3有1条不通过，说明AI提取的高阶知识需要审核。

### 3.2 L4哲学层新建（解决程度：60%）

**已有基础**：无——L4层完全不存在

**需要做的**：
1. 定义L4节点的schema
2. 设计L4提取的prompt
3. 定义L4质量标准（什么算"有洞察力的哲学"？）
4. 用费马大定理等经典案例做POC验证

**解决程度**：60%——schema和prompt可以定义，但"什么算哲学洞察"没有客观标准。L4的质量比L3更难把控——L3至少有"是否改变图结构"的客观判据，L4没有。

### 3.3 全流程自动化（解决程度：50%）

**需要做的**：
1. 内容输入→AI阅读→L1-L4提取→质量审计→存入ArangoDB
2. 质量审计本身也需要AI（L2是否真弥漫？L3是否真改变图结构？L4是否真有洞察？）
3. 审计不通过的提取结果退回重提取或人工审核

**解决程度**：50%——pipeline可以自动化，但质量审计需要人审环节。AI自审AI的提取结果有循环验证风险——提取AI和审计AI可能共享同样的盲点。

---

## 四、是否需要连续POC验证？

**需要。每个层级都需要POC验证：**

| 层级 | POC类型 | 验证内容 | 预期轮次 |
|---|---|---|---|
| L1-L3 pipeline化 | 集成测试 | 新内容进来能否自动触发提取并写入ArangoDB | 1-2轮 |
| L2提取质量 | 质量验证 | AI提取的L2是否真弥漫性（覆盖≥2领域） | 3-5轮（不同内容） |
| L3提取质量 | 质量验证 | AI提取的L3是否真改变图结构（不是元策略） | 3-5轮 |
| L4 schema+提取 | 探索性POC | L4提取的哲学洞察是否有价值 | 5-10轮 |
| L1-L4增益验证 | 对比实验 | 有高阶知识 vs 无高阶知识的Solver表现差异 | 5-10轮 |

## 五、具体实施步骤

### 5.1 Phase 204-A：L1-L3 pipeline化（1-2轮POC）

**步骤A1**：设计吸收pipeline接口

```python
class KnowledgeAbsorptionPipeline:
    def absorb(self, content: MathContent) -> AbsorptionResult:
        """吸收数学内容的完整流程"""
        # 1. AI阅读理解
        understanding = self.ai_read(content)
        # 2. L1提取
        l1 = self.extract_l1(understanding)
        # 3. L2提取
        l2 = self.extract_l2(l1, understanding)
        # 4. L3提取
        l3 = self.extract_l3(l1, l2, understanding)
        # 5. 质量审计
        audit = self.audit(l1, l2, l3)
        # 6. 存入ArangoDB
        if audit.passed:
            self.store_to_arango(l1, l2, l3)
        return AbsorptionResult(l1, l2, l3, audit)
```

**步骤A2**：把`batch_extractor.py`的逻辑迁移到pipeline中

**步骤A3**：提取结果写入ArangoDB的K维度：
- L1→K维度·requires/uses边
- L2→K维度·awareness节点
- L3→K维度·cross_domain边

**步骤A4**：POC验证——用3个新内容测试pipeline端到端

### 5.2 Phase 204-B：L4哲学层新建（5-10轮POC）

**步骤B1**：定义L4节点schema

```python
@dataclass
class PhilosophyNode:
    node_id: str
    insight: str           # 哲学洞察文本
    applicable_principle: str  # 适用原理
    source_evidence: List[str] # 来源证据（哪些定理/证明中提取的）
    applicable_domains: List[str]  # 适用领域
    verification_method: str  # 验证方法（如何判断这个洞察是否有价值）
```

**步骤B2**：设计L4提取prompt

```
从以下数学内容的证明中，提取1-3条哲学洞察。

哲学洞察的定义：
- 不是具体解题技巧
- 不是跨领域映射（那是L3）
- 是关于"数学本质"的认识——什么让数学工作？什么让证明深刻？什么连接了看似无关的领域？

例子：
- "等价性比相等性更深刻"——来自费马大定理的证明
- "深刻的数学真理往往隐藏在看似无关的领域之间"——来自朗兰兹纲领
- "简化陈述不等于简单证明"——来自费马大定理

请对以下内容提取哲学洞察：
{content}
```

**步骤B3**：用3个经典案例做POC验证：
- 费马大定理的证明
- 哥德尔不完备性定理
- 伽罗瓦理论

**步骤B4**：定义L4质量标准：
- 是否有具体来源证据（不是空泛的格言）
- 是否能指导具体决策（不是只说不做）
- 是否在多个领域有体现（不是某个领域的特例）

### 5.3 Phase 204-C：L1-L4增益验证（5-10轮POC）

**步骤C1**：设计对比实验

| 实验组 | Solver可用知识 | 验证什么 |
|---|---|---|
| A组 | 只有L1 | 基线表现 |
| B组 | L1+L2 | L2思维模式是否提升表现 |
| C组 | L1+L2+L3 | L3跨领域映射是否提升表现 |
| D组 | L1+L2+L3+L4 | L4哲学洞察是否提升表现 |

**步骤C2**：每组用5-10个问题运行GuidedLoop

**步骤C3**：比较四组的完成率、turn数、提示有效率

**步骤C4**：判断各层级的边际增益
