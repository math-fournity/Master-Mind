## 五、设计决策记录

### 5.1 为什么不直接删除历史记录，而是移到 skill

| 选项 | 利 | 弊 |
|---|---|---|
| **移到 skill**（选择） | 保留历史，按需可查 | 多一个 skill 文件 |
| 直接删除 | 最简 | 丢失历史信息，未来排查时无据可查 |

**推荐**：移到 skill。**推荐理由**：历史记录不是垃圾，是项目演进的证据链。Worktree 隔离的实施过程、数据丢失事件的排查过程、POC 实验的结论——这些在未来排查问题、做决策时可能需要参考。移到 skill 后，always-on 不占用上下文，但需要时能加载。

### 5.2 为什么认知资产索引用独立活文档而不是 skill

| 选项 | 利 | 弊 |
|---|---|---|
| **独立活文档**（选择） | 持续更新方便、rule 指向它即可 | 多一个文件 |
| Skill | 复用 skill 机制 | skill 是 on-demand 的，但认知资产索引需要每次新增认知时更新，不是"按需加载"的场景 |

**推荐**：独立活文档。**推荐理由**：认知资产索引的访问模式是"写多读少"——每次新增认知单元、新增 dev-docs 都要更新它，但 AI 很少需要"加载整个索引"。它是工作系统持续维护的活文档，不是按需加载的参考。用独立文档 + rule 指针最合适。

### 5.3 为什么数据丢失事件记录移到 dev-docs 而不是 skill

| 选项 | 利 | 弊 |
|---|---|---|
| **dev-docs**（选择） | 顺序编号、与项目其他文档一体管理 | 不如 skill 那样有 rule 自动匹配 |
| Skill | 有 rule 自动匹配 | 数据丢失记录是历史档案，不是"遇到场景才需要"的操作指南 |

**推荐**：dev-docs。**推荐理由**：数据丢失事件记录是项目历史档案，它的性质和 dev-docs/168（移除 Supervisor 方案）一样——是某个时间点发生的事的记录。放在 dev-docs 中，顺序编号，与其他项目文档一体管理。AGENTS.md 中只留一行指针。
