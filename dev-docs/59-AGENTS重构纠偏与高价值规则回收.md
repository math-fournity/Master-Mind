## 1 · 为什么记录

最近一次 `AGENTS.md` 重构把重点放在 `study-notes/` 新系统的终态认知、结构边界和解释框架上。这些新增认知本身有价值，但重构过程中发生了一个错误：部分旧 `AGENTS.md` 中的高价值操作规范被删除或压缩成抽象表述，没有在 `AGENTS.md` 中保留足够强的门控和索引。

用户指出的典型例子是：Check List XPATH 应该做到什么粒度。这不是普通说明，而是原典吸收、反向核对、完整性审计和未来 Worker/Auditor 工作质量的关键门槛。

本文件用于完成三件事：

1. 记录这次问题的成因；
2. 列出被删除或弱化的高价值内容及其后续价值；
3. 确立以后重构 `AGENTS.md` 时不得直接删除高价值规则的保全纪律。

---

## 2 · 根因

### 2.1 过度“认知宪章化”

重构时过度追求把 `AGENTS.md` 写成新系统认知宪章，强调“新系统是什么、不是什么、终态能力是什么”。这个方向本身成立，但不应以牺牲操作规范为代价。

### 2.2 把承接文档存在误认为 AGENTS 可以不保留强规则

XPATH 粒度、Check List 标记格式、吸收方式分类等内容仍存在于 `dev-docs/56` 和 `study-notes/README.md`，但 `AGENTS.md` 是跨 Session 的总闸门。未来 Session 不一定会主动读到这些外部文档。因此，凡是执行质量门，`AGENTS.md` 必须保留可执行摘要，而不是只留抽象概念。

### 2.3 没有逐段处置核对

`dev-docs/51` 已经规定：从 `AGENTS.md` 推出的内容不能丢失，要有承接文档和索引。但后续重构没有做“保留 / 迁移 / 索引 / 废弃理由”的逐段处置表，导致某些内容虽然没有彻底从项目消失，却从 always-on 门控中消失或弱化。

## 5 · 后续规则

以后任何 Session 重构 `AGENTS.md`，必须先做以下核对：

1. 旧内容是否是硬规则、操作门槛、路径规范、质量门、索引或长期认知资产；
2. 如果是，是否应该保留在 `AGENTS.md`；
3. 如果移出，承接文件在哪里；
4. `AGENTS.md` 是否保留了强约束摘要；
5. `AGENTS.md` 是否保留了索引；
6. 是否记录了迁出原因；
7. 是否列出逐段处置结果。

没有完成上述核对时，只允许改写、整合、去重，不允许直接删除。

---

## 6 · 本次结论

这次用户指出的问题成立：旧 `AGENTS.md` 中确实有多处对后续工作极重要的指导内容被删除或弱化。正确修复不是回滚全部新认知，而是把新系统终态认知与旧操作门槛合并：

- 新认知保留；
- 操作规则恢复；
- 索引重新接通；
- 以后重构建立保全纪律。
