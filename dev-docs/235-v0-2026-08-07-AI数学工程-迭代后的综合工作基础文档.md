## 1. 深层定义：形式化边界的持续推进

**这是233号的核心贡献，是整个项目的深层本质。**

### 1.1 形式化的边界

数学知识有形式化边界两侧的两种成分：
- **可以形式化的**：定理依赖、证明步骤、证书目标、恒等式、不等式、类型——这些可以被显式化、可检查、可审计
- **不可形式化的**："不自然"的感知、模式识别、直觉、类比、结构感——这些无法写成规则，依赖于对大量例子的经验积累

形式化的边界不是"暂时无法形式化，未来可以"——它是**本质性的边界**。"不自然"是一种感知，不是规则。

### 1.2 双重知识生产是边界两侧的必然结果

同一批数学语料因此有两条生命路径（231号的概念，233号的深层理由）：
- **训练路径**：语料→AI模型参数→黑盒模式识别能力（处理边界以外的感知）
- **抽取路径**：语料→结构化数据→白盒数据基座（处理边界以内的形式化）

两者不是替代，是互补。AI模型像数学直觉（边界以外的侦察兵），数据基座像实验记录+定理库+证书账本（边界以内的已征服领土）。

### 1.3 形式化边界的移动机制

**222号说"AI时代边界没有消失但移动了"但没说怎么移动。233号给出了答案：**

```
步骤1：AI从边界以外感知"不自然"（侦察——AI的黑盒能力）
步骤2：AI把"不自然"压缩成可检查目标（跨越边界——从感知到对象）
步骤3：经典计算在边界以内验证（操作——经典计算的精确能力）
步骤4：结果回写数据基座（边界向前推进，不可逆）
```

**数据基座的增长 = 形式化边界的推进。** 证书单调增长 = 边界推进不可逆。AI感知非单调 = 边界以外可修正。闭环 = 把非单调感知不断压成单调形式化。

### 1.4 三个统一

233/234号实现了三个统一：
- **222号和231号统一**：双重知识生产是形式化边界两侧的必然结果
- **工程和数学统一**：数据基座和数学结构都是形式化边界的描述（同一件事的两个面）
- **求解和抽取统一**：闭环运行同时产出解和数据基座条目（单任务双产出）

## 2. 确定的核心共识

这些是224-234所有讨论都同意的，不需要再讨论。

### 2.1 两种计算的本质区别

**AI计算**：处理还没有完全形式化的意义——感知、模式识别、类比、猜测表示变换、判断哪里不自然。擅长提出候选，但难以稳定区分"看起来像真的"和"已经被确认是真的"。

**经典计算**：处理已经被压缩成明确对象的任务——枚举、化简、因式分解、求解约束、检查类型、验证证明、生成反例。擅长精确执行，但不知道该算什么。

**两者互补**：AI从边界以外感知，经典计算在边界以内验证，闭环推进边界。

### 2.2 225的三个核心直觉

1. **处境会生长**：问题在解题过程中会变形——不等式→矩问题→多项式非负证书→对偶极值。问题不是静态点，是会生长的处境。

2. **经典计算会反向生产语义**：经典计算不只是检查——它主动产生结构（因式分解产生隐藏乘积，求解器产生反例，数值验证产生量级事实）。结果回流改变AI的理解。

3. **自然性>连续性**：非特定性不是"邻域内连续有效"，而是"表示变换下保持意义"。数学策略的迁移经常跨越很远的表面距离。

### 2.3 227的三个实质修正

1. **反例是证书**：反例证明"存在对象使猜想失败"=正向证书证明否定命题。三类：正向证书/反驳证书→证书层；诊断反馈→反馈层。

2. **证书不能压成单一偏序**：证书带字段（claim/scope/strength/dependencies/checker/status）。范围收缩不是加强。

3. **obstruction≠H¹**：四级——descent failure→obstruction object→Čech 1-cocycle→H¹ class。H¹是特殊情况。

### 2.4 218号非特定性危机的深层解决

**表层解决**（226-v1）：非特定性是可检查的数学条件——方法在表示变换下是否满足交换。

**深层解决**（233号）：引导者站在边界以内（知道答案）假装站在边界以外（做感知）=答案知识泄露。让不知道答案的AI做感知——它只能从边界以外感知"不自然"，不能从边界以内泄露答案。

### 2.5 下一步跑矩条件极差题

所有讨论都同意：不再堆抽象框架，跑闭环样例。

## 3. 候选的数学结构

有方向但需在跑例子中验证。**关键修正（234号）：这些数学结构都是形式化边界的抽象描述。**

### 3.1 语义场Σ是范畴（候选）

**方向**：Σ是范畴，对象是数学处境，态射是保持数学意义的操作（表示变换/规范化/对偶化/特例化/推广/形式化翻译）。

**形式化边界视角**：Σ是边界两侧的处境空间。态射是跨越边界的过程。

**待验证**：Σ是否需要范畴结构？态射分型（227）还是加标注（228-glm5.2）？加权/富范畴是否需要？

### 3.2 证书系统C是带字段的偏序范畴（候选）

**方向**：C是偏序范畴，证书对象带字段（claim/scope/strength/dependencies/checker/status）。三类证书（正向/反驳/诊断反馈）。

**形式化边界视角**：C是边界以内的已征服领土。证书增长=边界推进。

**待验证**：带字段证书对象是否可操作？三类区分是否清晰？

### 3.3 自然性是交换图（候选，分层）

**方向**：方法m是自然的，如果对于表示变换τ:S→S'，交换图（近似/可证）成立。分层：强自然性（等价表示下可证交换）/弱自然性（非等价但保目标的移动下lax交换）/经验稳定性（变体族上稳定产生同类证书目标）。

**形式化边界视角**：自然性是边界跨越的条件——方法在跨越边界时是否保持意义。

**待验证**：分层后可检查性是否保持？误差项怎么定义？

### 3.4 可证化V和反射R是伴随-like结构（候选，最不确定）

**方向**：V（语义→证书）和R（证书→语义）形成某种双向连接。226-v0发现V/R不是严格函子。候选：lax adjunction / Galois connection / 带效应闭环（Kleisli）/ 反馈循环。

**227的修正**：伴随-like结构不是原始结构，是闭环做稳定化、闭包化之后的派生结构。

**形式化边界视角**：V是跨越边界（感知→对象），R是反射（结果→理解）。两者是边界推进的两个方向。

**待验证**：跑例子时V/R的实际行为更像哪个候选？

### 3.5 图册是Grothendieck拓扑（候选，需从例子中长出来）

**方向**：覆盖是一组能共同看清处境的表示，粘合条件是局部证书在重叠处一致。

**227的修正**：先定义局部证书预层Cert: Σ_rep^op → Pos，先定义重叠和拉回。site从可粘合的覆盖族中长出来。

**形式化边界视角**：图册是边界上的局部视角——每个表示看清边界的某个部分，粘合是局部视角合成全局理解。

**待验证**：矩条件题的多种表示是否构成覆盖？重叠可定义？粘合条件满足？

### 3.6 能量是多分量序量（候选）

**方向**：六分量（表示复杂度/证书距离/自由度残差/粘合缺陷/反例压力/形式化缺口）。下降方式：Pareto改善（严格可检查）+受控交换（灵活但需双标准共存）。

**形式化边界视角**：能量是"当前处境离可证状态的距离"——离边界以内越近能量越低。

**待验证**：六分量可计算/估计？双标准共存可行？

## 4. 数据基座（231号+234号修正）

### 4.1 数据基座的深层定义

数据基座不是"数学工程单元库"——它是**形式化边界的显式记录**。每个数学工程单元标记着形式化边界的一个位置——这个位置上的东西已经被形式化了。

数据基座的增长 = 形式化边界的推进。

### 4.2 数学工程单元的结构（按边界位置四阶段组织）

**234号的修正**：231号列了九类内容但缺结构关系。234号按与形式化边界的关系重新组织为四阶段：

**阶段1：边界标记（处境的当前状态）**
- 处境描述：对象、关系、条件、目标、领域
- 表示图册：原始表示、规范化表示、对偶表示、形式化表示

**阶段2：跨越边界（从感知到形式化的过程）**
- 语义移动：每一步为什么做、改变了什么、属于哪类移动
- 表示变换：中心化、换基、归一化、对偶化、构造辅助对象

**阶段3：边界以内（已形式化的产物）**
- 证书目标：这一步产生哪些可检查声明
- 证书结果：已验证、已反驳、未知、诊断失败
- 依赖关系：用到哪些条件、引理、定理、表示翻译
- 经典任务：SymPy、Sage、SMT、Lean、枚举或数值检查任务

**阶段4：边界以外的感知沉淀**
- 模式模板：可迁移的触发信号、证书模板、反例模板
- 自然性测试：换表示、换参数、取变体后方法是否仍产生同类证书目标
- 反例边界：哪些变体不成立，哪些条件删掉会失败

**四阶段形成时间结构**：起点（边界标记）→过程（跨越）→产物（边界以内）→经验（感知沉淀）→下一轮的起点。

### 4.3 分层形式化（231号）

不要求所有材料一开始就完全形式化。五层：
1. 结构化（拆成对象/条件/目标/步骤/依赖）
2. 规范化（同类操作统一命名）
3. 可执行化（编译成计算任务）
4. 局部证书化（计算结果写成可复查证书）
5. 完整形式化证明（最高层，不是所有材料都能达到）

系统允许不同成熟度的材料共存。

### 4.4 检索机制（234号修正）

数据基座不是RAG。检索不是找相似文本，是找**相似的边界推进路径**。

两个处境"相似"=面临相似的不自然+需要相似的跨越+产生相似的证书目标。

工程实现：
1. 粗筛：结构化字段匹配（处境类型+移动类型+证书类型）
2. 精化：图查询在依赖图中找连通路径
3. 排序（可选）：向量检索在剩余候选中排序

核心是路径结构匹配，不是embedding相似度。

### 4.5 抽取机制（234号修正）

**231号把抽取和求解看成两个独立任务（"双任务"）。234号修正：抽取就是闭环本身。**

求解过程自然产生数据基座条目——每步语义移动被记录，每个证书目标被编译，每个验证结果被回写。不需要单独做抽取。

**修正**：单任务双产出——跑一次闭环，同时产出（a）问题的解和（b）数据基座条目。

### 4.6 时间尺度（234号修正）

- **短期可实现**（第一轮闭环就能验证）：数据基座支持运行时闭环——提供相似处境、证书模板、失败边界
- **中期效应**（数据基座积累到一定规模）：跨问题的模式迁移——一个问题发现的模式帮助另一个问题
- **长期正反馈**（数据基座积累到足够规模）：数据基座反过来生成训练数据，增强AI的边界以外感知

### 4.7 工程单元与数学结构的对应（232号+234号）

**两者都是形式化边界的描述——同一件事的两个面：**

| 数学工程单元字段 | 226/227数学结构 | 形式化边界的位置 |
|---|---|---|
| 处境描述+表示图册 | Σ的对象+图册 | 边界两侧的处境空间 |
| 语义移动+表示变换 | Σ的态射 | 跨越边界的过程 |
| 证书目标+证书结果+依赖关系 | C的对象+态射+依赖链 | 边界以内的已征服领土 |
| 反例边界+失败边界 | obstruction | 边界跨越的障碍 |
| 模式模板+自然性测试 | 自然性交换图 | 边界跨越的条件 |

## 5. 工程骨架

### 5.1 执行契约（228-codex，修正版）

每次AI数学动作必须说明四件事：

```
Semantic Move
  我在改变什么处境？
  我预期降低什么困难？（允许填"探索性移动，暂不确定"）
  我能把它编译成什么经典计算任务？（必须填）
  经典计算返回后，我准备如何更新语义场？（必须填）
```

**修正**（228-glm5.2）："预期降低什么困难"允许填"探索性移动"——数学家的探索性移动不是目标导向的。但"编译成什么计算任务"和"返回后如何更新"必须填——这两个是闭环的关键。

### 5.2 闭环动力学

```
循环：
  1. AI读取当前处境S和证书账本I，提出语义移动m
  2. m通过执行契约编译成经典计算任务
  3. 经典计算执行，返回结果r
     - 成功 → 证书c加入I（边界推进）
     - 反例 → 反驳证书加入I（边界推进——排除错误方向）
     - 障碍 → 诊断反馈加入反馈层（边界以外的信号）
     - 未知 → 保留为待解释的压力
  4. 结果r反射回语义场，更新S
  5. 同时，这一步的记录写入数据基座（单任务双产出）
  6. 回到1
```

### 5.3 对照实验设计（228-codex，修正版）

**同一批问题，两条路线跑**：

| 维度 | 单纯AI路线 | 闭环路线 |
|---|---|---|
| AI模型 | 同一个 | 同一个 |
| Prompt | 同样的初始题目 | 同样的初始题目 |
| 温度 | 相同 | 相同 |
| Python计算 | 允许（否则对比不公平） | 允许 |
| 执行契约 | 不要求 | 要求 |
| 证书账本 | 不维护 | 维护 |
| 结果回流 | 不强制 | 强制 |
| 数据基座 | 不维护 | 维护（单任务双产出） |

**比较指标**：
- 产生了多少可验证局部证书
- 发现了多少真实反例
- 排除了多少错误方向
- 有多少结论可以回放
- 有多少模式能迁移到变体题
- 最终证明中有多少步骤依赖可审计证据
- 出错时能否定位是猜想错、表示错、翻译错，还是检查器边界问题
- **新增（233号）**：形式化边界推进了多少步（多少东西从边界以外被拉到边界以内）

### 5.4 十种能力（228-codex，作为验证清单）

经典计算加入闭环后应获得的能力。跑例子时检查哪些出现：

1. 可靠性边界——AI提出引理，经典计算回答是否成立
2. 反例生产——经典计算搜索小模型、边界情况
3. 结构显影——因式分解、消元、正规形显露新结构
4. 搜索空间裁剪——不可行方向标记为死路
5. 局部证书积累——局部等式/不等式/子引理逐步获得证书
6. 形式化压力——迫使AI把模糊感觉压成可检查声明
7. 依赖审计——维护依赖图
8. 粘合检查——检查多个表示的局部理解是否相容
9. 可回放性——计算过程可记录、可重复、可复查
10. 模式库真实增长——每个模式附带适用信号、证书模板、失败案例

- 题目错误的发现是形式化边界推进的哪一步

### 6.3 五个验证目标

跑完后验证：

1. **闭环能解题**（230号）：最终证明能被证书账本支撑
2. **知识能成为燃料**（231号+234号修正）：数据基座条目作为闭环副产品自动产生
3. **工程概念和数学结构是否统一**（232号+234号）：工程单元字段是否对应数学结构
4. **形式化边界是否真的在推进**（233号）：哪些东西从边界以外被拉到边界以内？推进了哪些步骤？推进是否不可逆？
5. **边界推进路径的可复用性**（234号）：跑完后的数据基座条目能否帮助下一道相似题

## 8. 一句话总结

> AI数学工程的深层本质是**形式化边界的持续推进**。数学知识有形式化边界两侧的两种成分——可以形式化的进入数据基座，不可形式化的进入AI训练。闭环的每一次运行，AI从边界以外感知"不自然"，压缩成可检查目标，经典计算在边界以内验证，结果回写数据基座——形式化边界向前推进一步，且不可逆。下一步用矩条件极差题跑通这个闭环，单任务双产出（同时得到解和数据基座条目），验证五个目标。
