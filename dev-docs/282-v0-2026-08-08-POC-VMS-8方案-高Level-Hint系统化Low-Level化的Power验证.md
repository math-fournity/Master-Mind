## 要证明什么

**核心命题**：高Level Hint的系统化Low Level化，比抽象高Level Hint和bare AI都有显著胜率优势。

**不是trivial的证明**：不是简单列举"翻译到模算术/翻译到群论"然后说"看，列表有了"。而是要证明：

1. **预测力**——字典是在**没有看到具体题目**的情况下提前建好的，却包含了破解题目的确切翻译方向
2. **非显然性**——成功的翻译不是"数论题→模算术"这种trivial匹配，而是跨领域的非显然翻译
3. **可遍历性**——AI拿到字典后可以遍历找到正确的翻译，不需要人工匹配
4. **泛化性**——同一个字典在完全不同领域的题目上都有效

## 实验设计

### 第一步：离线建字典（不看任何具体题目）

用AI系统化枚举"翻译语言"这个高Level Hint在所有数学领域中的具体形式。

**关键约束**：建字典的AI**不知道**将来会遇到什么题目。字典是领域通用知识的形式化，不是针对特定题目的hint。

**字典结构**：
```
"翻译语言" → {
  "数论→模算术": "把整数方程/不等式转化为模p的同余问题",
  "数论→p-adic赋值": "把整除/幂次问题转化为p-adic赋值分析",
  "数论→二次剩余": "把素数判定/无解证明转化为二次剩余/Legendre符号问题",
  "数论→椭圆曲线": "把丢番图方程转化为椭圆曲线的有理点问题",
  "代数→群作用": "把计数/对称性问题转化为群在集合上的作用",
  "代数→表示论": "把抽象群/代数结构转化为矩阵/线性变换",
  "组合→生成函数": "把计数问题转化为幂级数的系数提取",
  "组合→线性代数": "把图/组合结构转化为矩阵/向量空间问题",
  "组合→概率": "把确定性计数转化为概率/期望论证",
  "几何→坐标化": "把几何关系转化为代数方程",
  "几何→复数化": "把平面几何转化为复数运算",
  "几何→射影": "把度量问题转化为射影不变量",
  "跨域：组合→代数": "把组合恒等式转化为代数结构（如群代数）的性质",
  "跨域：几何→数论": "把几何不变量转化为数论函数（如格点计数）",
  "跨域：分析→代数": "把连续问题转化为代数结构（如Fourier系数→群特征）",
  ...
}
```

字典建好后**冻结**——之后不再修改。

### 第二步：选题（选翻译是关键转折点的难题）

选5-8道题，满足：
- bare AI会失败（7g-v3已验证奥赛题满足这个条件）
- 解题的关键转折点是一个**翻译**操作
- 翻译方向**非显然**（不是"数论题→模算术"这种领域内的常规操作）
- 跨多个领域（数论/代数/组合/几何）

**选题标准的核心**：题目的标准解法中，有一个明确的"啊哈时刻"——把问题从一个语言翻译到另一个语言后变得可解。这个翻译不是领域内的常规操作，而是跨领域或跨子领域的非显然跳跃。

### 第三步：四组对照

| 组 | 给AI什么 | 验证什么 |
|---|---|---|
| **A组（bare）** | 只给题目 | baseline——bare AI能做多少 |
| **B组（高Level抽象）** | 题目 + "翻译到另一种语言"（7g-v3的highlevel hint） | 抽象hint没用——7g-v3已验证 |
| **C组（字典遍历）** | 题目 + 完整字典 + "遍历字典中的翻译方向，逐一尝试" | **核心验证**——AI能否自己从字典中找到正确翻译 |
| **D组（字典匹配）** | 题目 + 字典中匹配到的那个具体翻译（由另一个AI匹配） | 上界验证——如果匹配对了，效果如何 |

**C组是核心**：AI拿到完整字典后自己遍历，不需要人工匹配。这验证了"字典+遍历"的可行性。

**D组是上界**：如果匹配对了效果如何？D组成功率高说明字典内容是对的，匹配是瓶颈。D组成功率不高说明字典内容有缺失。

### 第四步：测量

**主要指标**：
- 通过率：A vs B vs C vs D
- **关键比较**：C >> B > A → 证明系统化Low Level化的power
- **次要比较**：D ≥ C → 匹配不比遍历差（说明遍历已经足够好）
- **泛化性**：同一个字典在不同领域的题上都有C >> B

**次要指标**：
- C组中AI尝试了几个翻译方向才找到正确的？（遍历效率）
- C组中AI找到的翻译方向是否和标准解答一致？（遍历准确性）

## 与7g-v3的关键区别

| | 7g-v3 | 本POC（VMS-8） |
|---|---|---|
| highlevel hint | 只给抽象方向"翻译到另一种语言" | 给完整字典，AI自己遍历找具体翻译 |
| knowledge hint | 手写的详细步骤（不公平对照） | 不需要——字典中的具体翻译就是knowledge |
| 字典 | 无 | 提前建好，冻结，不看题目 |
| 验证 | highlevel vs knowledge vs bare | 字典遍历 vs 抽象hint vs bare vs 字典匹配 |

## 说服学界的关键点

1. **字典是离线建的**——不看题目就建好了，却包含了破解题目的确切翻译。这不是"事后诸葛亮"，而是"预测"。

2. **AI自己遍历找到正确翻译**——不是人工匹配，是AI拿到字典后自己探索。这证明字典是可操作的，不是需要专家解读的抽象清单。

3. **跨领域泛化**——同一个字典在数论/代数/组合/几何题上都有效。这证明"翻译语言"是一个真正的跨领域思维模式，不是领域特定的trick。

4. **非显然翻译**——成功的翻译不是trivial的"数论题→模算术"，而是跨领域的非显然跳跃（如"组合→线性代数"、"几何→数论"）。这证明字典捕获了真正的数学洞察，不是常识。

## 开放问题

1. **字典的完备性**——AI枚举的翻译方向是否覆盖了所有重要的翻译？可能需要多轮枚举+交叉验证。

2. **遍历的token成本**——C组AI遍历20+个翻译方向需要多少token？是否需要在遍历前先做粗粒度筛选？

3. **选题的客观性**——如何确保选的题确实是"翻译是关键转折点"的题，而不是事后诸葛亮？可能需要先看bare AI的失败轨迹，确认失败原因是"没找到翻译方向"。

4. **字典匹配的方法**——D组中用什么方法匹配？人工匹配？AI匹配？检索系统匹配？这决定了字典的实用路径。
