## 204-A L1-L3 pipeline化

> 来源：201号§五.6.1 + 204号§五.5.1 + batch_extractor.py:36-44

- [ ] **204-A.0**：吸收pipeline接口设计 [预期D1]
  - 定义`KnowledgeAbsorptionPipeline`类
  - 定义`MathContent`输入schema：`{title, statement, proof, domain, methods}`
  - 定义`AbsorptionResult`输出schema：`{l1, l2, l3, audit, stored}`
  - 覆盖标准：接口定义完整，输入输出schema明确

- [ ] **204-A.1**：AI阅读理解环节 [预期D2]
  - pipeline第一步：调用AI完整阅读数学内容，形成结构化理解
  - 输出：`{key_concepts, proof_structure, domain_context, difficulty}`
  - 深度标准：有可执行的AI阅读调用代码
  - 边界情况：内容过长（分段阅读）/ 内容不完整（标注"理解不完整"）

- [ ] **204-A.2**：L1提取环节——从batch_extractor.py迁移 [预期D2]
  - 从AI理解中提取2-3种解法路径
  - 每种4-7步，每步标注`concept`和`action`
  - 深度标准：有可执行的L1提取代码，输出符合schema
  - 边界情况：只有1种解法（标注"解法单一"）/ 超过3种（选最有代表性的3种）

- [ ] **204-A.3**：L2提取环节——从batch_extractor.py迁移 [预期D2]
  - 从L1中抽象弥漫性思维模式
  - 标注`evidence_step`（来源步骤）和`applicable_domains`（适用领域，≥2个）
  - 深度标准：有可执行的L2提取代码，每个L2覆盖≥2领域
  - 边界情况：L2只覆盖1个领域（标注"非弥漫性——降级为L1技巧"）

- [ ] **204-A.4**：L3提取环节——从batch_extractor.py迁移 [预期D2]
  - 从L1/L2中识别跨领域映射范式
  - 必须改变图结构（新增跨领域边），不是元策略
  - 深度标准：有可执行的L3提取代码，每个L3有具体的跨领域映射
  - 边界情况：L3是元策略而非范式（标注"非范式级——降级为L2"）

- [ ] **204-A.5**：质量审计环节 [预期D3]
  - L2审计：是否真弥漫性（覆盖≥2领域，有具体例子）
  - L3审计：是否真改变图结构（有具体的跨领域映射，不是"应该去寻找映射"）
  - 审计不通过的提取结果退回重提取或标注"candidate"
  - 深度标准：有可执行的审计代码，参考POC3的extraction_audit.md方法
  - 边界情况：AI自审AI的提取（循环验证风险——标注"需人审"）

- [ ] **204-A.6**：存入ArangoDB K维度 [预期D2]
  - L1→K维度·requires/uses边
  - L2→K维度·awareness节点
  - L3→K维度·cross_domain边
  - 深度标准：有可执行的ArangoDB写入代码
  - 边界情况：ArangoDB连接失败（fallback到JSON文件，标注"未入库"）

- [ ] **204-A.7**：POC验证——3个新内容端到端测试 [预期D3]
  - 选择3个新内容（不在POC3中的定理/证明）
  - 端到端运行pipeline：AI阅读→L1→L2→L3→审计→存入ArangoDB
  - 记录每步的输出和审计结果
  - 覆盖标准：3个内容全部端到端完成

### 完整性标准

- [ ] **204-A.COMP**：pipeline从内容输入到ArangoDB存储全链路可执行 [预期D3]
  - 边界情况：某环节失败（有错误处理和fallback）

- [ ] **204-A.COMP2**：L2/L3质量审计执行 [预期D3]
  - 覆盖标准：每个L2/L3都有审计结果（通过/不通过/candidate）

## 204-B L4哲学层新建

> 来源：201号§三.3.3 + 204号§五.5.2

- [ ] **204-B.0**：L4节点schema定义 [预期D1]
  - 定义`PhilosophyNode`：`{node_id, insight, applicable_principle, source_evidence, applicable_domains, verification_method}`
  - 定义每个字段的含义和格式
  - 覆盖标准：schema定义完整，每个字段有明确含义

- [ ] **204-B.1**：L4提取prompt设计 [预期D2]
  - 设计L4提取的AI prompt
  - prompt包含：L4定义、例子（费马大定理/哥德尔/伽罗瓦）、输出格式要求
  - 深度标准：有可执行的L4提取prompt
  - 边界情况：AI提取的L4是空泛格言（标注"无具体来源——拒绝"）

- [ ] **204-B.2**：L4质量标准定义 [预期D2]
  - 标准1：有具体来源证据（不是空泛格言）
  - 标准2：能指导具体决策（不是只说不做）
  - 标准3：在多个领域有体现（不是某个领域的特例）
  - 深度标准：3个标准全部定义，每个有可执行的判定方法
  - 边界情况：L4只满足2个标准（标注"candidate——需更多证据"）

- [ ] **204-B.3**：POC验证——费马大定理案例 [预期D3]
  - 用费马大定理的证明作为输入
  - 提取L4哲学洞察
  - 审计L4质量（3个标准）
  - 预期L4：如"等价性比相等性更深刻"、"深刻真理隐藏在无关领域之间"
  - 覆盖标准：至少提取1条通过审计的L4

- [ ] **204-B.4**：POC验证——哥德尔不完备性定理案例 [预期D3]
  - 用哥德尔不完备性定理的证明作为输入
  - 提取L4哲学洞察
  - 预期L4：如"任何足够强的形式系统都有无法自证的真理"、"自指是数学的本质特征之一"
  - 覆盖标准：至少提取1条通过审计的L4

- [ ] **204-B.5**：POC验证——伽罗瓦理论案例 [预期D3]
  - 用伽罗瓦理论作为输入
  - 提取L4哲学洞察
  - 预期L4：如"对称性决定可解性"、"结构比元素更深刻"
  - 覆盖标准：至少提取1条通过审计的L4

- [ ] **204-B.6**：L4存入ArangoDB K维度 [预期D2]
  - L4→K维度·philosophy节点（新增collection）
  - 深度标准：有可执行的ArangoDB写入代码
