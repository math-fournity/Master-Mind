Phase 4是**第一个需要实际运行LLM实验的Phase**。目标：

- **DYN-3**：同可观测checkpoint分层的最小干预——验证非泄漏Hint的因果效应
- **DYN-4**：帮助量响应曲线——success/verified progress = f(assistance budget)

## 2. 关键实现决策

### 2.1 LLM后端：devin cli封装

Phase 4需要实际调用LLM生成continuation。经调研，devin cli可以作为LLM后端：

```bash
devin -p "prompt" --model <model> --respect-workspace-trust false
```

**优势**：
- 已有37个模型族可用（Claude Opus/Sonnet/Fable、GPT等）
- 非交互模式（-p/--print）适合自动化调用
- 模型版本可冻结（--model参数指定具体模型版本）
- 无需额外API key配置（devin cli已认证）

**封装设计**：

**模型版本冻结**（P4-3.1）：
- 首版实验模型：`claude-sonnet-5-low`（成本$2/MTok In·$10/MTok Out，适合大规模实验）

### 2.2 G0-3/G0-4预注册门：先跑pilot估计方差

123号§44要求"每个DYN protocol必须先用独立pilot估计方差"。实现方案：

**Pilot阶段**（G0-3/G0-4冻结前）：
1. 在Q_0（Ramsey C_5下界猜测）上跑小规模pilot（每处理组5次continuation）
2. 记录pilot的效应大小方差和泄漏代理方差
3. 根据pilot方差冻结G0-3（δ、样本量、排除标准、区间估计方法）

**Pilot的预注册**（在pilot结果前冻结）：
- pilot样本量：每处理组5次continuation（共20次）
- pilot只用于估计方差，不用于假设检验
- pilot结果不作为Phase 4出口门证据

**G0-3冻结值**（pilot后确定）：
- δ（最小实际效应）：根据pilot效应大小方差，取保守值（预计0.10-0.20）
- 样本量：根据pilot方差和δ，用功效分析确定（预计每处理组15-30次）
- 排除标准：continuation生成失败、预算超限、格式不合规
- 区间估计方法：Bootstrap置信区间（非参数，不假设正态分布）

**G0-4冻结值**（pilot后确定）：
- 泄漏门阈值：答案等价映射审计分数上限（预计0.30，即Hint最多传递30%答案信息）
- 候选空间缩减率上限（预计50%，即Hint不能把候选空间缩小超过一半）
- 盲审者恢复率上限（预计20%，即盲审者仅凭题面+Hint最多恢复20%答案）

### 2.3 实验设计：checkpoint分层随机实验

**Q_0**：Ramsey C_5下界猜测任务（128号§3冻结，已实现于q0.py）

**Checkpoint选取**（P4-1.1）：
- 从Phase 3的candidate规则中选取对应的checkpoint
- checkpoint包含§847的7个完整字段（q_0/event_prefix/model_version/tool_versions/permissions/budget/version_hash）
- Phase 3的state_aligner.py已实现checkpoint记录

**四组处理**（P4-2.1）：
- control：无提示
- H0：元检查——"你是否只在改指数？先列出表达式中可变化的结构部分。"（128号§3.2 Hint-0）
- H1：思维操作——"把底数和指数分开分析，并说明递归障碍影响哪一部分。"（128号§3.2 Hint-1）
- H2：概念/工具候选——"递归规模缩减有时由迭代对数描述；把它作为候选工具而非结论。"（128号§3.2 Hint-2）

**随机分配**（P4-1.2）：
- 在同一checkpoint层内随机分配continuation到4组
- 每组N次continuation（N由pilot方差分析确定）
- 随机种子记录到manifest（可复现）

**非确定性来源**：devin cli调用LLM时的采样随机性（即使prompt相同，每次调用的推理过程不同）

## 6. 逐项实现方案

### P4-0：G0-3/G0-4预注册门冻结（pilot→方差估计→冻结）

**做什么**：
1. 跑pilot实验：在Q_0上每处理组5次continuation（共20次）
2. 记录pilot的效应大小（control vs H0/H1/H2的进展差异）和方差
3. 记录pilot的泄漏代理分数和方差
4. 根据pilot方差冻结G0-3（δ/样本量/排除标准/区间估计方法）和G0-4（泄漏门阈值）

**边界情况**：pilot效应为零（无法估计方差→取保守δ）、pilot方差过大（需要大样本→成本评估）

**实现路径**：`pilot_runner.py` → `experiment_runner.py`（pilot模式）→ 人工审核冻结值

### P4-1：checkpoint分层+continuation分配

**做什么**：
1. 从Phase 3的candidate规则中选取对应的checkpoint（含§847的7字段）
2. 在同一checkpoint层内随机分配N个continuation到4组
3. 记录checkpoint内容哈希和随机种子

**实现路径**：`checkpoint_layer.py`，复用`state_aligner.py`的checkpoint记录

### P4-2：四组处理定义

**做什么**：
1. 定义control/H0/H1/H2四组处理的prompt
2. 从Phase 3的activation_packet加载H0/H1/H2激活包
3. 验证H0/H1/H2不含答案等价内容（128号§3.2禁止级别）

**实现路径**：`treatment_groups.py`，复用`activation_packet.py`

### P4-3：冻结模型/工具/题面/预算

**做什么**：
1. 冻结模型版本（claude-sonnet-5-low）
2. 冻结工具版本（devin cli版本）
3. 冻结题面（Q_0不变）
4. 冻结预算（token/计算/工具/分支/Hint预算）
5. 冻结G0-3预注册门（δ/样本量/排除标准/区间估计方法）

**实现路径**：`experiment_runner.py`的manifest冻结功能

### P4-4：完整日志/哈希/盲评/Truth Vault隔离

**做什么**：
1. 记录完整实验日志（所有事件/干预/结果）
2. 记录内容哈希（checkpoint哈希/事件哈希/输出哈希）
3. 执行盲评（评分者不知道处理分配）
4. Truth Vault隔离验证（Solver不可见Truth Vault）
5. 角色隔离验证（Auditor不参与Hint设计或Solver答题）
6. 角色边界落实为collection/visibility label/能力令牌（123号§607）

**实现路径**：`auditor.py` + `visibility_labels.py` + `capability_tokens.py` + `blind_evaluator.py`

### P4-5：测局部效应

**做什么**：
1. 测同一checkpoint的treatment vs control的局部效应
2. 估计ATE和异质性（分层或配对统计）
3. 验证非泄漏Hint的预注册主要效应区间下界>0且超过δ
4. 验证效应测量用任务类型特定的已验证进展（conjecture类型：非重复/可证伪/通过初筛/未被反例否定）

**实现路径**：`effect_estimator.py`，用Bootstrap置信区间

### P4-6：测帮助量曲线

**做什么**：
1. 建立帮助量响应曲线：success/verified progress = f(assistance budget)
2. 验证真正好的系统应在更少帮助下达到同等或更高进展
3. 记录多指标结果（进展/泄漏/依赖/成本/副作用），不用一个总分掩盖高泄漏

**实现路径**：`help_curve.py`

### P4-7：新题迁移

**做什么**：
1. 在未参与设计的迁移题上复现效果
2. 使用分层效应模型记录7个维度（问题族/数学领域/模型版本/Hint等级/提示格式/工具权限/时间位置）
3. 验证Ramsey案例的迁移维度（新的奇环问题C_7上是否迁移）

**迁移题设计**：C_7（七边形奇环）的Ramsey数下界猜测——与C_5结构相似但未参与Hint设计

**实现路径**：`migration_tester.py`

### P4-8：记录负效应和无效规则

**做什么**：
1. 记录Agent依赖代理3种（撤掉Hint后独立继续率/同类后续状态再次求助率/单位已验证进展所需帮助量）
2. 记录副作用（错误方向/误导/破坏自然探索）
3. 记录无效规则（效果不可复现的candidate规则）

**实现路径**：`side_effect_logger.py`，复用`leakage_audit.py`的AgentDependencyProxy（149号修正）

### P4-9：通过后才升为validated

**做什么**：

### P4-10：Ramsey案例验证维度
