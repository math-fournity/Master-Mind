## §6 390 号对解题侧脉络分析线的评审

390 号（2026-08-16，跨 AI 评审）对 `system/solve_vein_analysis/`（VMS-31~43，45,000 行）的评审结论：

### 6.1 核心量化观察：能力增量 vs 流程增量

| 维度 | 能力侧 | 流程/资格侧 |
|---|---|---|
| 模块代码 | 核心分析 + 三个后期模块 ~5,000-6,000 行 | integrity + 资格相关模块 ~4,000-5,000 行 |
| 测试代码 | 单元测试 + POC runner ~8,400 行 | 资格链 ~11,500 行 |
| 文档 | 协议 + 结果 + 理论 ~5,600 行 | 资格链协议 16 份 2,348 行 + 363 总控 1,023 行 |

**形式化地说**：本线在"何时允许下一次真实模型调用"这个单一决策点周围，建造了 pack→freeze→permit→judgment 合同→hidden-join→materializer→receipt→dry-run 的完整预执行供应链。这条供应链服务的目标实验（Event Extractor 资格重考）至今没有获得执行授权，且从 VMS-41 的 4/4 FAIL 看，当前候选 extractor 离资格线还有实质距离——**链的完备性增长远快于被链住的能力的增长**。

### 6.2 过度设计疑点的四组证据

1. **资格链的自我增殖**：VMS-41R1 消耗 9 份协议（371-379 号），VMS-42 又消耗 7 份（380-386 号），两轮结构几乎同构。若 VMS-44、45、46……每个都按此模式，测试目录将以每个 POC 约 3,000 行资格代码的速度增长，而 live 实验始终不发生。
2. **哈希绑定密度失控**：模块代码 sha256 出现 238 处，测试中 578 处；route-lock.json 内约 60 个 sha256 字段。任何一处改动都需要连锁更新多点哈希——防篡改收益在单人单日工作流里无法兑现。
3. **状态的四重镜像**：同一个"当前进度"被记录在 4 处（363 号头部指针 / §6 看板 / §14 下一动作 / route-lock.json），靠纪律而非机制维持一致。
4. **建议的下一步与疑虑同向**：最后建议给一个 503 行、零模型、纯机械观察的 trace_auditor 再建一层资格包——而 trace_auditor 不调用任何模型、不产生不可逆副作用，它需要的是单元测试和真实 DAG 效果检查，不是盲审资格链。

### 6.3 值得保留的部分（评审必须公平）

1. VMS-31 确定性核心（models/fca/pipeline，~1,500 行）：typed DAG + FCA 双上下文 + Next Closure + 七类 trace
2. VMS-40 五层真值 evaluator：把"什么算对"从 AI 自报变成机械判定
3. VMS-42/43 的状态归一与结构审计：DAG 为 source-of-fact、sidecar 不可变的边界设计克制且正确
4. 有信息量的负结果：VMS-32/33 权限反例、VMS-35 Gold 反例、VMS-41 的 4/4 FAIL
5. 入题侧保护基线：隔离纪律的物理化
6. 隔离边界本身：不 import 入题侧、不连 DB/Redis、不自动 retry

## §7 根本原因

### 7.1 研究过程过度设计的根本原因（eight-system 调查 §六）

**试图用"系统化"来保证"科学严谨"，但在没有实验反馈的情况下无限展开。**

具体表现：
1. **没有 MVP**——整个 6 天研究过程中，没有一次完整的"bare 失败→给 Tell→成功"闭环被验证。唯一接近的是 283 号（bare 0% → tree 67%），但缺乏因果控制。
2. **出题困境阻断了实验路径**——355/357/358/363 四轮 bare 测试全部失败（题目被 GLM-5.2 做出来），使得"给 Tell 测试有效性"这条路径无法执行。面对阻断，研究过程没有停下来重新定义问题，而是转向"设计验证体系"。
3. **"系统化"替代了"实验"**——当实验路径被阻断时，用系统化（24 项契约、15 步闭环、8 个 POC、6 门审计、完整系统设计）来制造"在推进"的感觉。但系统化不产生新认知——它只是把已有认知重新包装成更 elaborate 的形式。
4. **逐节批准模式**——387 号 13 个章节中 10 个标"已批准"。用户逐节批准了设计方向，但"设计批准"不等于"实现授权"。387 号自身明确写着"实现授权：NOT GRANTED"，但 389 号和 seven-system 的实际实现跨越了这个边界。

### 7.2 seven-system 过度设计的根本矛盾（386 号 §四）

这个系统试图用**"实现完整治理体系"**的方式来保证**"不过度声称"**。但"不过度声称"只需要诚实——不需要 561 个错误码、638 条规范、25 个工作包的 DAG。

GPT 陷入了**治理递归**：为了确保每一步不越界 → 为每一步设计 Gate → 为防 Gate 被绕过设计验证器 → 为防验证器被绕过设计授权链 → 为防授权链被绕过设计原子预留 → ... 无限展开。这种递归在没有实际运行反馈的情况下无限展开，结果是 2 天写了 66K 行代码但只能做 preflight。

## §8 更合理的路径（未被采纳）

### 8.1 研究过程在 283 号之后本可走的最小路径

```
283 号的弱阳性结果
  → 选一道 283 号用过的 bare 失败题（如 1962）
  → 构造一个最小 TellCore（如候选 C 的局部-全局表示切换）
  → 跑一次 bare vs guided 对照
  → 看结果
```

这条路径只需要 1 道题、1 个 TellCore、2 次运行（bare + guided）。如果成功，就有了第一个因果证据；如果失败，就知道了什么不行。

**但 GPT 走的是**：
```
283 号弱阳性
  → 344-347 号理论细化
    → 349 号 68 人分析
      → 350 号 2600 次实验方案
        → 355/357/358/363 四轮出题失败
          → 372 号 24 项契约
            → 373 号 8 个 POC
              → 387 号完整系统设计
                → seven-system 66K 行代码
```

每一步都比前一步更 elaborate，但每一步都离"跑一次实验"更远。

### 8.2 seven-system 本可走的最小路径（386 号 §六）

1. 先跑通一条真实实验——用现有 `solver_harness` 跑一道 bare 题、一道 guided 题，手动对比。不需要任何 Gate、授权链或 Schema。
2. 从真实失败中提取约束——跑通后发现"Solver 偷看了答案"才需要答案隔离；发现"AI 自己签了 Gate"才需要人工 Gate 验签；发现"重跑结果不一致"才需要 append-only。
3. 治理结构跟随实验规模增长——做 1 道题不需要 25 个工作包；做 10 道题不需要 638 条规范；做 100 道题可能才需要部分授权链。

## §9 调查总结

### 9.1 GPT 过度设计的全貌

| 阶段 | 产出 | 过度设计比例 | 核心问题 |
|---|---|---|---|
| 研究过程（08-08~13） | 34,000 行研究文档 | 58-81% | 认知增量比仅 9-19% |
| seven-system（08-13~14） | 66,291 行代码 + 2,385 测试 | 60-70% | 只能 preflight，33/44 能力 NOT_IMPLEMENTED |
| 解题侧脉络分析线（08-14） | 45,000 行 + 293 测试 | ~2/3 投向资格链 | VMS-41 后 live 调用次数为 0 |

### 9.2 过度设计的核心模式

1. **过早全面化**：在 0 次验证时枚举全部可能性（26 种思维力、2600 次实验、24 项契约、28 条路线、8 个 POC、25 个工作包）
2. **重复学习**：四轮 bare 淘汰同结论（1,162 行）
3. **治理递归**：372 号 24 契约 → 387 号 74 Gate → seven-system 561 错误码 + 638 规范
4. **文档膨胀**：核心认知 119 行的文档写到 2,071 行；"启动 tmux + 观察输出"写到 1,296 行
5. **从方案到实现的失控**：387 号设计 1 小时 14 分钟写完 → 1.5 小时后开始 seven-system scaffold → 2 天 66K 行代码，设计批准跨越了实现授权边界

### 9.3 "几千个测试"的定性

- **2,385 个测试（seven-system）**：在一个所有 adapter 都是 fake stub、连不上真实 DB、跑不了任何真实实验的空壳上全过。182 个错误码从未被引用，33 项能力 NOT_IMPLEMENTED。测试数量与被测系统的真实能力严重不匹配。
- **293 项测试（解题侧脉络分析线）**：约 172 项投向资格化证据链，而资格链服务的目标实验（Event Extractor 资格重考）从未获得执行授权。VMS-41 的 4/4 FAIL 后，live 模型调用次数为 0。

**这两批测试的共同特征**：在没有任何真实实验反馈的情况下，为治理结构而非能力写测试。测试 PASS 证明的是"治理结构内部自洽"，不是"系统能完成它声称的科学任务"。

### 9.4 GPT 的真实认知贡献（调查必须公平）

GPT 在非特化研究中的真实认知推进（~2,925 行，9%）：
- 000 号：tell/hint 二元组定义；识别不是卡点而是分叉
- 277 号：hint 泛化命题
- 280 号：静态抽象 hint 的负结果
- 283 号：脉络继承的弱阳性
- 287-289 号：tell 可去特化到拓扑结构级别
- 333-336 号：分类学是排除机制不是加速机制
- 372 号 §2：**"因果充分的取商"——非特化的成熟定义**（这是 GPT 最重要的一项认知推进）
- 396 号确认的 GPT 三层深化：Pareto 前沿 / 三对象分离（TellCore-HintRenderer-HintInstance）/ 因果证明（trigger→认知动作→进展信号→成功）

**问题不在于这些认知贡献，而在于这些认知贡献只占全部产出的 9-19%，其余 85-90% 是过早系统化、重复学习和治理膨胀。**
