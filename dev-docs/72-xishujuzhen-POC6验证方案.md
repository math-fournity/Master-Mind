# 72 · xishujuzhen POC-6 验证方案

## 一、实验定位

POC-6是xishujuzhen验证体系的关键转折点。前5个POC（POC-1到POC-5）都是在A组知识嵌入充分的情况下做的——A组的参考材料包含了与B组knowledge_content对等的命理知识。结果是B组优势主要在过程可审计性，而非结果创新性——两组结论高度一致，B组未产生A组没有的新命理洞察。

POC-6要回答一个根本性问题：**当A组知识缺失时，B组（依赖图+知识嵌入+三步流程+闭环审计）是否能产生A组无法产生的分析结果？**

如果答案是"是"——依赖图+知识嵌入的价值不仅在于可审计性，更在于知识嵌入本身能让AI完成知识缺失时无法完成的分析。

如果答案是"否"——依赖图+知识嵌入的价值仅在于可审计性，知识嵌入不产生新的分析能力。

### 同时测试的第二个维度：交叉审计

POC-5的第2步自审是解读AI自己审自己——如果解读AI有系统性盲区，自审可能发现不了。POC-6引入**交叉审计**：第2步自审由另一个AI实例审计，而非解读AI自审。

### 核心假设

1. **知识缺失放大B组优势**：A组缺失大限流年知识时，B组的边际增益应比POC-5更大（因为B组的knowledge_content包含了A组缺失的知识）。
2. **B组能产生A组无法产生的分析**：A组在动态分析上会因为知识缺失而产生错误、遗漏或浅层分析，B组则能完成完整的动态分析。
3. **交叉审计能发现AI自审发现不了的问题**：交叉审计（另一个AI实例审计）比AI自审更严格，能发现自审盲区。

### 与POC-5的对比

| 指标 | POC-5 | POC-6 |
|---|---|---|
| A组知识状态 | 充分（含大限流年知识） | **缺失（无大限流年知识）** |
| A组能否做动态分析 | 能 | **受限/不能** |
| 第2步审计方式 | AI自审 | **交叉审计（另一个AI实例）** |
| 预期B组优势 | 过程可审计性 | **过程可审计性 + 结果创新性** |
| 预期边际增益 | +3.95 | **> +3.95** |

## 二、场景设计

### 命主数据

复用POC-5的命主：1985年3月15日 06:00（卯时），昼生，35岁（2020年）。

### 依赖图

复用POC-5的依赖图（30节点40边，8跨宫依赖边）。依赖图不变——变化的只是A组的知识嵌入状态。

### A组知识缺失设计

A组参考材料（material_a_v6.md）**只包含静态分析知识**（命宫+官禄宫），**不包含大限流年知识**：

- **保留**：安命安身、状态判断、五行生克、阴阳昼夜、十二宫排布、官禄宫分析
- **删除**：第七章"大限流年分析"（洞微大限原理、12限框架、当前限分析、流年分析、限运吉凶综合）

A组仍然获得星盘摘要（poc5_chart_summary.txt）——其中包含大限框架、当前大限、限内星曜、流年信息等**原始数据**，但A组**没有解读这些数据的命理知识**。

这模拟了真实场景：用户可能有排盘数据（原始数值），但不知道如何解读动态分析部分。

### B组知识嵌入

B组的JSON中knowledge_content包含完整的大限流年知识（同POC-5）。B组的动态分析节点（限宫主庙旺、流年太岁关系、限内星曜配置、限内格局触发、限内行运星）都嵌入了knowledge_content。

### 对照变量

| 变量 | A组 | B组 |
|---|---|---|
| 静态分析知识 | 有 | 有（嵌入JSON的knowledge_content） |
| 大限流年知识 | **无** | **有**（嵌入JSON的knowledge_content） |
| 星盘原始数据 | 有（含大限流年数据） | 有（含大限流年数据） |
| 依赖图 | 无 | 有 |
| 跨宫依赖显式引导 | 无 | 有 |
| 第2步自审 | 无 | **交叉审计** |
| 第3步审计 | 无 | 有 |

## 三、交叉审计设计 ★新增

### POC-5的审计链（AI自审）

```
第2步：解读AI → 大师提示词 + 自审报告（解读AI自己审自己）
```

问题：解读AI可能有系统性盲区——如果它漏译了某个节点，它可能也不知道自己漏译了。

### POC-6的审计链（交叉审计）

```
第2步a：解读AI → 大师提示词
第2步b：审计AI（另一个实例）→ 交叉审计报告（审计解读AI的输出）
```

审计AI获得：
1. 原始JSON（审计基准）
2. 解读AI输出的大师提示词（被审计对象）

审计AI不获得：
- 解读AI的自审报告（如果有的话）——避免被自审结论影响

审计AI的任务：对照JSON，逐节点、逐边、逐跨宫依赖、逐环路检查大师提示词的转译忠实性。

### 交叉审计报告模板

与POC-5的自审报告模板相同（完整审计表），但审计主体从"解读AI自己"变为"独立审计AI"。

### 完整审计链

```
第1步：系统生成JSON
  ↓
第2步a：解读AI → 大师提示词
第2步b：审计AI → 交叉审计报告（转译忠实性）★交叉审计
  ↓
第3步：AI在JSON+大师提示词下分析 → 结果 + 审计报告（执行忠实性）
  ↓
闭环：JSON → 交叉审计（转译忠实性）→ 执行审计（执行忠实性）→ 结果可追溯
```

## 四、评分维度（6维度，同POC-5）

| 维度 | 满分 | 说明 |
|---|---|---|
| 1. 分析完整性 | 2.0 | 静态分析+动态分析+静态→动态跨宫过渡的覆盖完整性 |
| 2. 推理深度 | 2.0 | 螺旋环路处理、颠倒颠推演、跨宫依赖推演、动态分析推理 |
| 3. 知识准确性 | 2.0 | 庙旺判断、五行生克、恩用仇难、大限流年判断的准确性 |
| 4. 可审计性 | 2.0 | 节点/边/跨宫/环路覆盖审计、路径忠实性审计 |
| 5. 转译忠实性 | 2.0 | 第2步交叉审计报告的完整性和忠实性（仅B组有） |
| 6. 边际增益 | 2.0 | B组相比A组的综合增益 |
| **总分** | **12.0** | |

### POC-6特有的评分关注点

**维度3（知识准确性）**：重点关注A组在动态分析上的准确性——A组缺乏大限流年知识，是否能正确解读大限框架、限宫主、限内星曜、流年太岁？如果A组在动态分析上出现错误或浅层分析，B组在此维度的优势应更明显。

**维度6（边际增益）**：重点关注B组是否产生了A组无法产生的分析结果——这是POC-6的核心验证点。

## 五、核心假设与验证条件

### 假设1：知识缺失放大B组优势

**验证条件**：B组总分 - A组总分 > POC-5的+3.95分（10分制归一化）

**如果成立**：说明A组知识缺失时B组的优势更大，依赖图+知识嵌入的价值不仅在于可审计性。
**如果不成立**：说明即使A组知识缺失，A组仍能通过原始数据+通用命理知识完成动态分析，B组优势仍在可审计性。

### 假设2：B组能产生A组无法产生的分析

**验证条件**：A组在动态分析上出现以下至少一项：
- 错误判断（如限宫主判断错误、太岁关系判断错误）
- 遗漏关键维度（如未分析限内格局触发、未做流年-大限叠加）
- 浅层分析（如只列出大限框架但未做限宫主庙旺判断）

而B组在相同维度上完成完整分析。

**如果成立**：说明依赖图+知识嵌入能让AI完成知识缺失时无法完成的分析。
**如果不成立**：说明A组即使没有大限流年知识，也能通过通用命理知识+原始数据完成动态分析。

### 假设3：交叉审计能发现AI自审发现不了的问题

**验证条件**：交叉审计报告的转译忠实性 < 100%，或交叉审计发现了POC-5自审未发现的问题。

**如果成立**：说明交叉审计比AI自审更严格，能发现自审盲区。
**如果不成立**：说明AI自审已经足够严格，交叉审计未发现额外问题。
