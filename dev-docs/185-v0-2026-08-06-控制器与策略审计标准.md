## 二、审计检查项

### 2.1 控制器动作选择（controller.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 9种动作可执行 | 有执行函数不只是枚举 | 每种动作有对应执行逻辑 |
| 不读LLM内部状态 | 只基于公开产物和工具事件 | 输入无thinking/hidden_state |
| "无动作"合法 | continue_observe是合法操作 | 不强制每轮都干预 |
| 不确定估计 | 维护策略/卡点/停滞的不确定估计 | ControllerBelief有概率分布 |
| 预算约束 | 预算耗尽时stop，Hint预算不足时不inject_hint | 预算约束生效 |

**判定**：通过=5项全通过；有缺陷=动作可执行但估计有小偏差；失败=读取了LLM内部状态或预算约束失效

### 2.2 策略π选择质量（policy_pi.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 多目标公式 | E[ΔProgress] - λ1*C_hint - λ2*L̂_answer - λ3*D̂_dependence - λ4*C_compute | 5项都参与计算 |
| 代理分数标注 | L̂_answer和D̂_dependence是代理分数非互信息 | 标注为proxy |
| 不掩盖高泄漏 | 不用总分掩盖高泄漏或高依赖 | 单项超阈值时该动作不被选择 |
| 策略版本冻结 | 不能回改历史策略 | 历史决策不可修改 |
| 多指标报告 | 生成多指标报告 | 报告包含5项指标 |

**判定**：通过=5项全通过；有缺陷=公式正确但报告不完整；失败=用总分掩盖高泄漏或历史可回改

### 2.3 gaming检测（gaming_detector.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 三元AND逻辑 | 停滞词=True AND 工具证据=False AND 结构进展=False | 三个条件都满足才判定gaming |
| 工具证据要求实际输出 | 不只看声称，看实际工具输出 | 声称不算证据 |
| 结构进展要求T图变化 | 不只看输出长度变化 | 要T图结构变化 |
| 隐蔽gaming检测 | subtle_gaming类型 | 不只检测explicit_gaming |
| limit_reward_help | gaming时限制奖励/帮助 | limit_reward_help标志生效 |

**判定**：通过=5项全通过；有缺陷=三元逻辑正确但隐蔽检测不足；失败=只看声称或只看输出长度
