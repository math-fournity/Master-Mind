## 为什么需要侧写

### 当前痛点

在POC-VMS-7g-v3找题时，我需要从675道OlympiadBench题中找"需要翻译语言思维的数论题"。当前只能：
1. 按subfield筛选（Number Theory → 128道）
2. 逐个读题目文本判断是否适合
3. 逐个读解答判断需要什么思维模式

这相当于**没有索引的全表扫描**。

### 侧写后的查询

如果每道题都有侧写，查询变成：
```
FOR p IN problems_profiled
  FILTER p.thinking_patterns INCLUDES "translation"
  FILTER p.difficulty >= 0.7
  FILTER p.domain == "number_theory"
  FILTER p.answer_type == "numerical"
  FILTER p.bare_ai_expected == "fail"
  RETURN p
```

## 侧写维度设计

### 第一类：元数据维度（已有，从数据源继承）

| 维度 | 值 | 来源 |
|---|---|---|
| `source_id` | OlympiadBench id=1766 | 数据源 |
| `source_dataset` | olympiadbench / aops_1224 / compfiles | 数据源 |
| `domain` | number_theory / algebra / combinatorics / geometry | 数据源 |
| `subfield` | Number Theory / Algebra / ... | 数据源 |
| `answer_type` | Numerical / Expression / Proof / Multiple | 数据源 |
| `answer` | (0,±2), (4,±23) | 数据源 |
| `question_length` | 字符数 | 自动计算 |
| `has_solution` | true/false | 数据源 |

### 第二类：难度维度（需要标注）

| 维度 | 值 | 标注方式 |
|---|---|---|
| `difficulty` | 0-1实数 | AI标注（0= trivial, 0.5=本科, 0.7=竞赛入门, 0.9=IMO P5/6, 1.0=开放问题） |
| `difficulty_source` | "competition_level" / "textbook_level" / "research_level" | 数据源推断 |
| `competition_tier` | "regional" / "national" / "IMO" / "IMO_P5P6" | 数据源推断 |
| `bare_ai_expected` | "pass" / "fail" / "marginal" | AI预测（bare AI能否在token限制内解出） |
| `token_budget_needed` | 估算token数 | AI标注 |

### 第三类：思维模式维度（核心——需要AI分析解答后标注）

| 维度 | 值 | 标注方式 |
|---|---|---|
| `thinking_patterns` | ["translation", "contradiction", "invariant", "extremal", ...] | AI分析解答后标注 |
| `primary_pattern` | "translation" | 主要思维模式 |
| `knowledge_required` | ["quadratic_residue", "euler_criterion", "mersenne_prime"] | AI标注 |
| `key_insight` | "2是模p的二次剩余当p≡7(mod 8)" | AI标注（一句话描述关键转折点） |
| `translation_from` | "整数方程" | 翻译的源语言（如果primary_pattern=translation） |
| `translation_to` | "因式分解+2-adic赋值" | 翻译的目标语言 |

### 第四类：实验适用性维度（用于POC实验选题）

| 维度 | 值 | 标注方式 |
|---|---|---|
| `suitable_for_poc` | ["VMS-7g-translation", "VMS-7g-contradiction"] | 标注适合哪个POC实验 |
| `hint_tested` | ["translation_hint", "knowledge_hint"] | 已经测试过哪些hint |
| `bare_result` | "pass" / "fail" / "not_tested" | 实际bare测试结果 |
| `guided_result` | "pass" / "fail" / "not_tested" | 实际guided测试结果 |
| `discriminates_levels` | true/false | 这道题能否区分高Level hint和低Level hint的效果 |

## 实现方案

### 阶段1：自动标注（从已有数据提取）

对OlympiadBench的675道题，自动提取：
- 元数据维度（已有）
- `question_length`（自动计算）
- `difficulty_source`（从source推断）
- `has_solution`（检查solution字段）

### 阶段2：AI批量标注（思维模式维度）

对每道题，用一个AI实例分析解答，输出：
```json
{
  "problem_id": 1766,
  "thinking_patterns": ["translation", "case_analysis"],
  "primary_pattern": "translation",
  "knowledge_required": ["2_adic_valuation", "factorization"],
  "key_insight": "因式分解y²-1=(y-1)(y+1)后用2-adic赋值约束",
  "translation_from": "整数方程",
  "translation_to": "因式分解+2-adic赋值",
  "difficulty": 0.7,
  "bare_ai_expected": "fail",
  "suitable_for_poc": ["VMS-7g-translation"]
}
```

### 阶段3：存入ArangoDB

创建 `problem_profiles` 集合，每道题一个文档。支持AQL查询。

### 阶段4：查询接口

```python
def find_problems(thinking_pattern="translation", domain="number_theory", 
                  difficulty_min=0.6, bare_expected="fail"):
    """找适合特定POC实验的题"""
    aql = """
    FOR p IN problem_profiles
      FILTER @pattern IN p.thinking_patterns
      FILTER p.domain == @domain
      FILTER p.difficulty >= @diff_min
      FILTER p.bare_ai_expected == @bare_expected
      RETURN p
    """
    ...
```

## 开放问题

1. **AI标注的质量如何保证？** ——AI分析解答后标注思维模式，可能误判。需要抽样人工审核。
2. **思维模式标签体系是否完整？** ——当前从122号和214号继承，可能遗漏一些模式。
3. **难度标注的校准？** ——0.7对一道题和0.7对另一道题是否可比？需要用bare AI的实际表现来校准。
4. **侧写何时更新？** ——题目被用于POC实验后，应该更新实验结果维度。
