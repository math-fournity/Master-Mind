## 三、数学任务的类型与各自的正确性标准

### 3.1 证明类任务

**功能**：数学大师给出一个定理的证明。

**审什么**：

| 检查项 | 说明 | 标准 |
|---|---|---|
| 逻辑链完整性 | 每一步推理是否有前置依据 | 不能有"显然"、"易得"等跳步；每步要么是公理/定义，要么引用了前述结论 |
| 前提正确性 | 证明使用的前提是否正确 | 前提必须是已知定理/定义/已证引理，不能编造 |
| 结论正确性 | 证明的结论是否就是要证的命题 | 结论必须与命题一致，不能证了别的东西 |
| 无循环论证 | 证明不能依赖结论本身 | 检查有没有隐含使用了要证的命题 |
| 边界情况 | n=0, n=1, 退化情形 | 如果命题对所有正整数成立，检查n=1；如果涉及除法，检查分母为零 |

**判定标准**：
- **通过**：5项全通过
- **有缺陷**：逻辑链完整但有小错误（如计算错误但方法对）
- **失败**：逻辑链断裂或前提错误或循环论证

**验证方法**：
1. **自动化（首选）**：用SymPy验证关键计算步骤；用Lean 4形式化验证（如果证明结构化程度足够）
2. **AI辅助**：让另一个AI（审计AI）逐步检查证明，标注每一步的依据
3. **人工**：复杂证明需要人工审查

### 3.2 猜想类任务

**功能**：数学大师提出一个数学猜想。

**审什么**：

| 检查项 | 说明 | 标准 |
|---|---|---|
| 小情形验证 | 猜想在小情形下是否成立 | 至少验证3-5个小情形；如果小情形不成立，猜想直接失败 |
| 与已知结果一致性 | 猜想是否与已知定理/结果矛盾 | 如果与已知结果矛盾，猜想要么失败要么需要解释为什么已知结果错了 |
| 推理依据 | 猜想背后的推理是否有依据 | 不能凭空猜；必须有类比、归纳、推广等推理过程 |
| 可证伪性 | 猜想是否可证伪 | 必须能找到反例或证明——不能是"不可判定"的 |
| 新颖性（可选） | 猜想是否是已知结果 | 如果是已知结果，标注"已知"；如果是新的，标注"新猜想" |

**判定标准**：
- **通过**：小情形验证通过 + 与已知结果一致 + 有推理依据
- **有缺陷**：小情形验证通过但推理依据不足
- **失败**：小情形验证失败 或 与已知结果矛盾

**验证方法**：
1. **自动化**：用Python/SymPy计算小情形
2. **AI辅助**：让审计AI检查推理依据和与已知结果的一致性
3. **数据库对比**：查询OEIS/arXiv/MathLib看猜想是否已知

### 3.3 计算类任务

**功能**：数学大师计算某个数学量（如Ramsey数的下界）。

**审什么**：

| 检查项 | 说明 | 标准 |
|---|---|---|
| 计算正确性 | 计算结果是否正确 | 用SymPy/Python独立计算验证 |
| 构造有效性 | 如果是构造性结果，构造是否有效 | 构造必须满足要求的性质 |
| 界的紧度 | 如果是上下界，界是否紧 | 与已知最好界对比 |

**判定标准**：
- **通过**：计算正确 + 构造有效
- **有缺陷**：计算正确但构造有小问题
- **失败**：计算错误

**验证方法**：
1. **自动化（首选）**：用SymPy/Python独立计算
2. **数据库对比**：查询OEIS对比已知值

### 3.4 发现新方向类任务

**功能**：数学大师发现不同数学领域之间的结构同构或新连接。

**审什么**：

| 检查项 | 说明 | 标准 |
|---|---|---|
| 连接有效性 | 两个领域之间的连接是否真实存在 | 连接必须有数学依据，不能是表面相似 |
| 非平凡性 | 连接是否是已知的 | 如果是已知连接，标注"已知"；如果是新的，需要更强的证据 |
| 可验证性 | 连接是否可以验证 | 必须能构造具体例子或形式化定义 |

**判定标准**：
- **通过**：连接有效 + 非平凡 + 可验证
- **有缺陷**：连接有效但是已知的，或可验证性不足
- **失败**：连接无效（表面相似但数学上不成立）

**验证方法**：
1. **AI辅助**：让审计AI检查连接的数学依据
2. **人工**：新方向类任务通常需要人工审查

## 三、自动化验证工具链

### 4.1 SymPy验证（计算类 + 证明的关键步骤）

```python
import sympy

def verify_sum_identity(n_max=100):
    """验证 sum k^3 = (sum k)^2 对n=1..n_max"""
    for n in range(1, n_max + 1):
        lhs = sum(k**3 for k in range(1, n+1))
        rhs = sum(k for k in range(1, n+1))**2
        if lhs != rhs:
            return {"passed": False, "n": n, "lhs": lhs, "rhs": rhs}
    return {"passed": True, "verified_up_to": n_max}
```

### 4.2 Lean 4形式化验证（证明类——未来）

如果数学大师的证明结构化程度足够，可以翻译成Lean 4并形式化验证。这是最严格的标准，但需要大量前期工作。

### 4.3 AI辅助审查（证明类 + 猜想类）

让审计AI（可以是另一个devin cli实例）逐步检查证明：
```
prompt = f"""
你是数学证明审计员。请逐步检查以下证明，对每一步标注：
- [OK] 这一步正确，依据是[公理/定理/前述结论]
- [ERROR] 这一步错误，原因是[...]
- [SKIP] 这一步跳步了，缺少的推理是[...]

证明：
{proof_text}
"""
```

## 五、历史案例

### 5.1 run_20260806_guided_004

- **任务**：证明 $\sum_{k=1}^{n} k^3 = (\sum_{k=1}^{n} k)^2$
- **数学大师的证法**：数学归纳法
- **验证**：
  - 小情形验证：n=1,2,3,4,5 用Python计算，全部通过
  - 逻辑链完整性：归纳基础✓ + 归纳假设✓ + 归纳步骤✓
  - 无循环论证：✓
- **判定**：通过
- **质量评价**：归纳法是标准证法，但没有给出更有洞察的证法（如望远镜求和）

### 5.2 run_20260806_verify_001

- **任务**：猜测 $R_k(C_4)$ 的下界
- **数学大师的猜想**：$R_k(C_4) = k^2 + 2$（素数幂时）
- **验证**：
  - 小情形验证：k=2,3,4 精确命中，k=5 在可能集{27,28,29}内
  - 与已知结果一致性：$R_k(C_4) \in [k^2+2, k^2+k+1]$ 与Conlon的讲义一致
  - 推理依据：从C_4的二部性 → ex(n,C_4)=O(n^{3/2}) → 计数上界n≤k² → 猜测贴近下界
- **判定**：通过（有缺陷——k=5未确定，猜测可能不成立）
- **注意**：这个run用了web_search，在正式审计中应标记为"数据来源受污染"
