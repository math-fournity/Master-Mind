## 1. Task Schema（P0-4.1）

> 123号第十四节：初始任务不是无类型文本

### 定义

```
Task {
  task_id:          string          // 唯一标识符
  type:             enum            // 任务类型（见下）
  domain:           string          // 数学领域（如 number_theory, algebraic_geometry）
  objects:          list[string]    // 数学对象和表达语言 D
  premises:         list[string]    // 原始前提与约束 Γ_0
  goal:             string          // 目标 G_0
  success_conditions: list[string]  // 成功条件 χ_success
  stop_conditions:  list[string]    // 停止条件 χ_stop
  failure_conditions: list[string]  // 失败条件（可选）
}
```

### 任务类型枚举

| type | 含义 | Lean proof state关系 |
|---|---|---|
| `prove` | 证明 | Lean proof state是prove的严格特例 |
| `refute` | 证伪/找反例 | — |
| `construct` | 构造对象 | — |
| `compute` | 计算 | — |
| `classify` | 分类 | — |
| `optimize` | 优化/上下界 | — |
| `conjecture` | 生成并筛选猜想 | — |
| `explain` | 解释结构 | — |
| `value` | 研究方向价值判断 | — |

### 冻结声明

`Q_0`在运行时保持冻结。任务类型不只是`prove`——不让整个系统只适配定理证明。

## 2. Workspace Schema（P0-4.2）

> 123号第十五节：动态数学工作区

### 定义

```
Workspace {
  workspace_id:     string          // 唯一标识符
  task_id:          string          // 关联Task
  timestamp:        string          // 时点t

  V_t: {                            // 已验证核心
    verified_premises:    list[string]   // 已证明引理、已验证工具结果
    verified_lemmas:      list[string]
    verified_tool_results: list[string]
  }

  F_t: {                            // 猜想前沿
    candidates:        list[string]   // 候选、临时假设、未验证桥梁
    temporary_assumptions: list[string]
    unverified_bridges: list[string]
  }

  O_t: {                            // 开放研究义务（AND/OR超图引用）
    obligation_ids:   list[string]   // 指向Obligation schema
  }

  R_t: {                            // 当前表示及其转换
    active_representations: list[string]  // 当前表示ID
    pending_transforms:    list[string]  // 待执行的表示变换
  }

  D_t: {                            // 被证伪/拒绝/暂停/可恢复分支
    rejected_branches:  list[string]
    suspended_branches: list[string]
    recoverable_branches: list[string]
  }

  E_t: {                            // 每个命题与动作的证据
    evidence_ids:      list[string]  // 指向Evidence schema
  }
}
```

### 完整运行状态

```
RunState {
  S_t = (Q_0, W_t, L_≤t, b_t, B_t, M_t)
}
```

| 分量 | 含义 |
|---|---|
| `Q_0` | 冻结的初始任务 |
| `W_t` | 当前工作区 |
| `L_≤t` | 不可变事件历史 |
| `b_t` | 控制器对卡点/策略/缺失信息的带不确定性信念 |
| `B_t` | token/计算/工具/分支/Hint预算 |
| `M_t` | 模型版本/推理配置/权限/工具能力 |

### 冻结声明

- `Q_0`保持冻结，不混入临时假设
- 临时假设进入`F_t`，不进入`V_t`
- 被拒绝路线进入`D_t`，不与representation共用`R`
- `W_t`只能由版本化Reducer按明确字段规则派生，不能被直接修改

## 3. Event Schema（P0-4.3）

> 123号第十七节：外显过程是带冲突的事件结构

### 原始事件

```
RawEvent {
  event_id:           string        // 唯一标识符
  type:               enum          // 事件类型（见下）
  timestamp:          string        // ISO 8601时间戳
  run_id:             string        // 关联运行manifest
  workspace_ref:      string        // 关联工作区（可选，语义层填充）
  raw_payload:        object        // 原始未加工内容
  content_hash:       string        // SHA-256内容哈希
  causal_predecessors: list[string] // 直接前驱event_id列表（DAG边）
}
```

### 语义事件

```
SemanticEvent {
  event_id:           string        // 继承自原始事件
  raw_event_id:       string        // 指向原始事件
  type:               enum          // 语义事件类型（见下）
  timestamp:          string
  run_id:             string
  workspace_ref:      string        // 关联工作区
  obligation_ref:     string        // 关联义务（可选）
  evidence_ref:       string        // 关联证据（可选）
  payload:            object        // 抽取后的语义内容
  content_hash:       string        // 语义内容哈希
  causal_predecessors: list[string] // 语义层因果前驱
  conflict_with:      list[string]  // 冲突事件ID列表（#关系）
  confidence:         float         // 置信度 [0,1]
  source:             string        // 来源标注
}
```

### 事件类型枚举

```
observation / claim / representation / subgoal / candidate /
test / tool_result / contradiction / stall / backtrack / resolution /
hint_injection / state_reduction / verification
```

### 冲突关系

- `conflict_with`满足对称和非自反
- 若`e1 # e2`，两事件不能属于同一有效分支
- 首版只标记显式选择的互斥候选、被回退分支与其替代分支
- 不能仅因两个命题矛盾就推断生成事件冲突

### 三层保留

1. 原始事件（不可变）
2. 语义抽取（可重抽）
3. 状态快照（可重建）

### 冻结声明

- 原始事件append-only，不允许修改或删除
- 事件因果图是DAG（时间不倒流）
- "又回到同一想法"是两个不同时刻事件投影到相同语义状态，不是事件循环

## 4. Obligation Schema（P0-4.4）

> 123号第十六节：开放义务是AND/OR有向超图

### 义务节点

```
Obligation {
  obligation_id:      string        // 唯一标识符
  type:               enum          // 义务类型（见下）
  status:             enum          // 状态（open/discharged/suspended/failed）
  task_id:            string        // 关联任务
  parent_obligation:  string        // 父义务ID（可选）
  description:        string        // 义务描述
  evidence_refs:      list[string]  // 关联证据ID
  evidence_gate:      string        // 证据门要求
  sub_obligations:    list[string]  // 子义务ID列表
}
```

### 超边存储（非普通边）

```
ObligationHyperEdge {
  edge_id:            string
  source_obligations: list[string]  // U ⊆ N：前置义务集合
  target_obligation:  string        // v ∈ N：父义务
  mode:               enum          // all (AND) | any (OR)
  sufficiency_condition: string     // 充分性条件
  evidence_gate:      string        // 证据门要求
}
```

### 义务类型枚举

| type | 含义 |
|---|---|
| `prove` | 待证明 |
| `refute` | 待证伪 |
| `construct` | 待构造 |
| `compute` | 待计算 |
| `search` | 待搜索 |
| `compare` | 待比较 |
| `evaluate` | 待评估 |
| `interface` | 跨表示运输保真义务 |
| `verification` | 数值支持仍需证明或反例搜索 |
| `value` | 方向判断（重要性/可行性/信息增益/成本） |

### 冻结声明

- 超边本体存relation document，`role=source/target`的participant edges连接义务
- 循环依赖不自动释放义务，产生待审计的SCC
- 不用普通`depends_on`边伪装超边

## 5. Representation Schema（P0-4.5）

> 123号第十九节：表示运输比普通跨领域边更重要

### 定义

```
Representation {
  rep_id:             string        // 唯一标识符
  source_form:        string        // 源表示（如"整数方程"）
  target_form:        string        // 目标表示（如"椭圆曲线"）
  map_type:           enum          // equivalence/encoding/reduction/relaxation/duality/functor_candidate
  domain:             string        // 数学领域
  preconditions:      list[string]  // 前置条件
  forward_transport:  string        // 正向运输规则
  backward_transport: string        // 逆向运输规则（可选）
  preserved_invariants: list[string] // 保留量
  lost_information:   list[string]  // 信息损失
  soundness_obligation: string      // 保真义务ID（指向Obligation）
  evidence:           list[string]  // 证据ID列表
}
```

### map_type枚举

| map_type | 含义 |
|---|---|
| `equivalence` | 等价 |
| `encoding` | 编码 |
| `reduction` | 归约 |
| `relaxation` | 松弛 |
| `duality` | 对偶 |
| `functor_candidate` | 函子化候选 |

### 冻结声明

- 运输只在对应义务通过后成立，不能因边名叫`equivalence`就自动成立
- 首版不宣称已构成范畴——升级为真正范畴需另给恒等变换、可组合边的复合、结合律和结构保持证明
- 只有可逆且复合封闭的子图才可称为groupoid
- 普通跨领域边（dg_edges中的structural_analogy等）不自动成为表示变换

## 6. Evidence Schema（P0-4.6）

> 123号第三十一节：证据不是单一布尔值

### 定义

```
Evidence {
  evidence_id:        string        // 唯一标识符
  claim_id:           string        // 关联命题
  kind:               enum          // 证据类型（见下）
  polarity:           enum          // support / refute
  status:             enum          // pending / active / superseded / retracted
  scope:              string        // 有效范围（哪些前提和参数范围）
  assumptions:        list[string]  // 依赖假设
  artifact_hash:      string        // 可重放工具产物或来源的内容哈希
  source_event:       string        // 来源事件ID
  verifier:           string        // 验证者标识
  verifier_version:   string        // 验证者版本
  confidence:         float         // 置信度 [0,1]
  conflicts:          list[string]  // 冲突证据ID列表
}
```

### kind枚举

| kind | 含义 |
|---|---|
| `literature` | 文献引用 |
| `numerical` | 数值验证 |
| `symbolic` | 符号计算 |
| `formal_proof` | 形式证明（Lean/Coq等） |
| `counterexample` | 反例 |
| `human_audit` | 人工审计 |

### 派生认识状态

| 状态 | 含义 |
|---|---|
| `no_decisive` | 无决定性证据 |
| `support_only` | 仅支持 |
| `refute_only` | 仅反驳 |
| `mixed` | 支持与反驳并存 |

### 验证等级（Verifier输出状态）

> 123号§28 + 系统探讨.md§5.5：Verifier输出认识状态而非布尔值。
> 127号§6冻结声明明确`proved/formally_verified`是验证等级字段，不是证据本身。
> 以下6种验证等级是Verifier的完整输出枚举。

| 验证等级 | 含义 |
|---|---|
| `proven` | 已证明（人工审计或文献确认） |
| `formally_verified` | 形式验证（Lean/Coq等验证器通过） |
| `computationally_supported` | 计算支持（符号计算支持） |
| `numerically_tested` | 数值检验（数值验证通过但无形式证明） |
| `contradicted` | 矛盾（有反例或矛盾证据） |
| `unknown` | 未知（证据不足） |

### 冻结声明

- 同一命题的证据集合通过集合并合并，不把数值支持与形式证明排成伪造的总序
- `proved/formally_verified`是验证等级字段，不是证据本身——验证等级的完整6种枚举见上表
- 冲突不自动爆炸到整个知识库，生成范围/前提澄清义务
- 只有满足该命题类型预先指定的验证门，命题才进入`V_t`
- 首版不宣称已有数学意义上的"证据格"——升级需定义偏序、join、meet并验证封闭性

## 7. HeuristicRule Schema（P0-4.7）

> 123号第二十一节：启发先实现为类型化时序模式—动作规则

### 定义

```
HeuristicRule {
  rule_id:            string        // 唯一标识符
  LHS: {                            // 匹配模式 p
    pattern:           object       // 对当前工作区和关键事件窗口的类型化匹配模式
    matched_entities:  list[string] // 被匹配实体
    field_constraints: object       // 字段约束
    time_window:       object       // 时间窗口
  }
  interface: {                      // 接口（guard条件 g）
    context:          object        // 上下文约束
    temporal:         object        // 时序约束
    model_version:    list[string]  // 适用模型版本
    permissions:      list[string]  // 权限约束
    budget:           object        // 预算约束
    failure_types:    list[string]  // 失败类型约束
  }
  RHS: {                            // 动作 a（激活包）
    activation_packet: object       // 实际激活包
    check_question:   string        // 检查问题（优先加入）
    research_action:  string        // 研究操作
    new_representation: string      // 新表示（可选）
    open_subgoal:     string        // 开放子目标
    tool_call:        string        // 工具调用
    counterexample_direction: string // 反例方向
    theorem_candidate: string       // 有接口的定理候选
  }
  guard: {                          // 守卫条件
    leakage_bound:    float         // 泄漏上限
    side_effect_bound: float        // 副作用上限
    cost_bound:       float         // 成本上限
  }
  status:             enum          // lifecycle_status（见第9节）
  effect_evidence:    list[string]  // 效果后验证据ID列表
  applicable_domains: list[string]  // 适用问题族
  model_versions:     list[string]  // 已验证模型版本
  failure_cases:      list[string]  // 失败案例
  eta: {                            // η：效果后验
    applicability:    string        // 适用域
    leakage:          float         // 泄漏测量
    cost:             float         // 成本测量
    side_effects:     list[string]  // 副作用记录
  }
}
```

### 冻结声明

- 模式匹配必须返回被匹配实体、字段约束和时间窗口
- 动作只能提出候选状态扩展，真正写入`V_t`仍需Reducer与Verifier
- 激活包不应直接把目标结论加入`V_t`
- 原先的`L←I→R`只保留为未来DPO研究方向，首版不借用DPO记号冒充已完成形式化

## 9. 启发规则生命周期状态机（P0-7）

> 124号 P0-7.1—7.3，123号第二十一节/第四十四节

### 4个生命周期状态

| 状态 | 进入条件 | 允许操作 | 禁止操作 |
|---|---|---|---|
| `candidate` | 离线发现（从成功/失败运行中抽取） | 离线测试、模式匹配验证 | 在线自动提示、自动写入H图 |
| `validated` | 通过DYN-3因果实验且泄漏门通过 | 在线候选提示（仍需Auditor审计） | 自动发布到生产H图 |
| `published` | 通过DYN-5跨题与跨模型迁移，至少跨3个未参与设计的问题族和2个模型版本复现 | 生产H图使用 | — |
| `retired` | 模型漂移、反例发现或更好规则替代 | 归档、历史查询 | 任何在线提示 |

### 状态转移图

```
candidate ──(DYN-3因果实验通过+泄漏门通过)──→ validated
validated ──(DYN-5跨3问题族+2模型版本复现)──→ published
published ──(模型漂移/反例/更好规则替代)──→ retired
candidate ──(反例发现/效果不可复现)──→ retired
validated ──(反例发现/效果不可复现)──→ retired
```

### HeuristicRule schema中的lifecycle_status字段

`HeuristicRule.status`字段取值为上述4个状态之一。状态转移必须留下审计记录（转移时间、触发条件、证据引用）。

### 冻结声明

- candidate规则禁止在线自动提示——这是R-4（Agent可能迎合触发器）的核心防线
- published标准在Phase 4出口门前冻结（G0-5）
- 退役规则归档但不删除，保留历史因果追溯能力

## 10. Truth Vault与角色隔离矩阵（P0-5）

> 123号第二十八节：角色可见性与非干扰。P0-5必须把可见性矩阵落实为collection、visibility label和能力令牌。

### 10.1 Truth Vault定义（P0-5.1）

```
TruthVault {
  collection_name:    "truth_vault"  // ArangoDB collection名
  write_access:       ["truth_curator"]  // 只有Truth Curator可写
  read_access:        ["auditor"]     // 只有Auditor可读（验证用）
  contains:           ["ground_truth", "answer_equivalent_content", "scoring_rubrics"]
}
```

**Truth Vault的collection名和读写权限**：
- collection: `truth_vault`
- 写入：仅`truth_curator`角色
- 读取：仅`auditor`角色（验证时对照）
- Runner/Solver/HeuristicMatcher等**不可见**

### 10.2 Runner可见collection白名单（P0-5.2）

Runner/Solver可见的collection：
- `tasks`（Q_0冻结任务）
- `workspaces`（当前工作区压缩快照）
- `obligations`（开放义务）
- `evidence`（最小证据，非全库）
- `activation_packets`（当前激活包）
- `semantic_events`（最近关键事件）

Runner/Solver**不可见**的collection：
- `truth_vault`（Truth Vault）
- `heuristic_rules`（H全库——只能看到当前激活包，不能看到规则全库）
- `future_hints`（未来Hint序列）
- `other_groups`（其他实验组结果）
- `scoring_rubrics`（评分基准）

### 10.3 可见性矩阵（P0-5.3）

8个角色 × N个collection的可见性矩阵：

| collection \ role | solver | event_capture | state_reducer | retriever | heuristic_matcher | verifier | auditor | orchestrator |
|---|---|---|---|---|---|---|---|---|
| `tasks` | R | R | R | R | R | R | R | R |
| `workspaces` | R | R | R/W | R | R | R | R | R |
| `raw_events` | — | R/W | R | — | — | — | R | R |

### 10.4—10.11 逐角色可见性边界

#### Solver（P0-5.4）

- **可见**：`Q_0`、当前工作区压缩（`V_t/F_t/O_t/R_t/D_t`的预算内快照）、开放义务、最小证据、当前激活包
- **不可见**：H全库、未来Hint、ground truth、其他组、Truth Vault
- **最小输入**：`Q_0`、`V_t/F_t/O_t/R_t/D_t`的预算内快照、当前相关的少量`E_t`、最近关键事件、单个激活包、"从checkpoint继续"指令
- **输出**：公开研究产物、候选状态变更和工具请求
- **禁止**：看到H全库、完整未来路线、评分基准、其他组结果和Truth Vault

#### Event Capture / Trace Modeler（P0-5.5）

- **可见**：Solver公开产物、工具事件、分支、回退、提示差异
- **不可见**：隐藏CoT
- **不能做**：选Hint或裁决成功
- **输入**：Solver公开产物、草稿中被明确允许保存的研究文本、工具调用、提示、分支/回退和时间
- **输出**：不可变原始事件 + 带置信度的语义事件
- **语义事件类型**：`observation/claim/representation/subgoal/candidate/test/tool_result/contradiction/stall/backtrack/resolution`
- **禁止**：补写隐藏思维、选择Hint、判定最终答案、发布规则

#### State Reducer（P0-5.6）

- **可见**：类型化事件、旧快照、验证结果
- **不能做**：自行补写未发生的数学推理
- **输入**：版本化语义事件、上一快照、Verifier结果
- **输出**：`V/F/O/R/D/E`的新快照、派生依据、reducer版本
- **可复现约束**：相同事件+相同reducer版本必须得到可复现结果
- **禁止**：自行发明未发生的数学边

#### Retriever（P0-5.7）

- **可见**：当前义务、表示、权限和检索约束
- **不能做**：返回整图或答案专属材料
- **输入**：当前类型化义务、对象/前提、表示、权限、token预算、可接受证据等级
- **输出**：候选定义、定理接口、方法、反例、工具、表示映射、来源及裁剪理由
- **禁止**：把整个K、答案专属材料或未满足前提的定理直接送给Solver

#### Heuristic Matcher / Policy（P0-5.8）

- **可见**：局部状态模式、模型/预算、规则效果、泄漏/副作用
- **不可见**：Truth Vault答案文本
- **不能做**：自动发布candidate规则
- **输入**：当前工作区的局部模式、关键事件窗口、停滞假设及置信度、上下文、时序、模型版本、预算、候选规则效果、泄漏和副作用
- **输出**："继续观察/诊断/工具/无提示/候选激活包"的排序及理由
- **禁止**：读取答案文本、把candidate规则当published规则

#### Verifier（P0-5.9）

- **可见**：明确命题、前提、证明片段、工具输入、期望证据等级
- **不能做**：决定下一研究路线
- **输入**：明确命题或接口义务、前提、证明/计算片段、工具输入、期望证据等级、适用范围
- **输出**：认识状态、证据类型、范围、可重放产物和失败原因（不是单一布尔值）
- **禁止**：选择下一研究方向

#### Auditor（P0-5.10）

- **可见**：冻结manifest、处理/对照、输出、ground truth、证据和隔离记录
- **不能做**：参与提示设计和Solver输出
- **输入**：冻结manifest、处理分配、所有实际Hint、提示前后事件/状态、输出、ground truth、工具证据、哈希和隔离记录
- **输出**：泄漏、越过卡点、数学进展、语言重复、副作用、归因和规则生命周期裁决
- **禁止**：参与Hint设计或Solver答题

#### Orchestrator（P0-5.11）

- **可见**：内容哈希、随机化、权限、运行状态和归档
- **不能做**：修改冻结输入，补写任何组结果
- **输入**：运行配置、内容哈希、随机化方案、权限和各角色状态
- **输出**：可复现实验编排与证据归档
- **禁止**：修改冻结输入、补写组别结果、越权读取后再给Runner"总结提示"、把失败fallback冒充主线完成

### 10.5 逐组件最小输入/输出契约（P0-5.12）

以上P0-5.4—P0-5.11已完整记录123号第二十八节"逐组件最小输入/输出契约"的8个角色契约。每个角色的输入、输出和禁止操作均已明确。

### 10.6 角色隔离运行时强制机制（P0-5.13）

**不靠prompt约束，靠能力令牌（capability token）和权限标签（visibility label）强制。**

#### 能力令牌设计

```
CapabilityToken {
  token_id:           string        // 唯一标识符
  role:               enum          // 角色枚举
  granted_collections: list[string] // 授权可见collection
  write_collections:  list[string]  // 授权可写collection
  granted_fields:     object        // 按collection细分的可见字段
  expires_at:         string        // 过期时间（运行结束时自动失效）
  issued_by:          string        // 签发者（Orchestrator）
  run_id:             string        // 关联运行ID
}
```

#### 强制机制

1. **collection级访问控制**：每个角色启动时获得CapabilityToken，ArangoDB查询层验证token授权的collection列表
2. **字段级访问控制**：对敏感collection（如`heuristic_rules`），token指定可见字段子集
3. **写入控制**：只有token中`write_collections`列出的collection可写
4. **运行隔离**：token绑定`run_id`，不能跨运行访问
5. **自动失效**：运行结束后token自动失效

#### 实现路径

- Phase 0：定义CapabilityToken schema和可见性矩阵（本文件）
- Phase 1：实现token签发和验证逻辑
- Phase 2+：在ArangoDB查询层强制token验证

## 12. L1/L2/L3五正交字段设计（P0-6补充）

> plan明确要求："L1/L2/L3保留为历史标注，但拆为'语义角色、抽象度、复用范围、证据等级、干预效果'五个正交字段；不再映射为版本号"
> 123号第六十节裁决6+P0-6：取消L1/L2/L3=v1/v2/v3的错误映射

### 问题

旧系统把L1（解题思路）、L2（数学思维）、L3（范式思维）错误映射为同一认知单元的版本号v1/v2/v3。实际上L1/L2/L3是**提取层次**（从具体解法中提取的三个抽象度），不是版本号。版本链用v1/v2/v3等独立编号，与L1/L2/L3无映射关系。

### 5个正交字段

对从解法路径中提取的认知单元，用以下5个正交字段替代L1/L2/L3标签：

| 字段 | 含义 | 取值示例 |
|---|---|---|
| `semantic_role` | 语义角色——这个认知单元是什么类型的对象 | `specific_step` / `thinking_pattern` / `paradigm` / `theorem` / `method` / `counterexample` |
| `abstraction_level` | 抽象度——从具体到抽象的层级 | `L1`(具体步骤) / `L2`(思维模式) / `L3`(范式思维) |
| `reuse_scope` | 复用范围——在多大范围内可复用 | `single_problem` / `problem_family` / `domain` / `cross_domain` / `universal` |
| `evidence_level` | 证据等级——这个单元的证据强度 | `unverified` / `single_poc` / `multi_poc` / `cross_validated` / `formally_proven` |
| `intervention_effect` | 干预效果——作为提示注入时的因果效果证据 | `untested` / `candidate` / `validated` / `published` / `retired` / `counterproductive` |

### 与版本链的关系

```
认知单元cog_id: "extreme_checking"
  semantic_role: "thinking_pattern"
  abstraction_level: "L2"
  reuse_scope: "cross_domain"
  evidence_level: "single_poc"
  intervention_effect: "candidate"
  current_version: "v2"  ← 版本链独立于上述5字段
  versions: [v1(初始提取), v2(修正描述)]
```

### 冻结声明

- `abstraction_level`字段保留L1/L2/L3作为**提取层次标签**，但不再作为版本号使用
- 版本链（v1/v2/v3...）独立于5正交字段，记录同一认知单元的描述修订历史
- 旧数据中`cayley_hamilton`单元的v1(L1)→v2(L2)→v3(L3)标注是错误的，重建时必须拆为5正交字段+独立版本链
- 这5个字段是Phase 2状态重建时对认知单元进行类型化的基础
