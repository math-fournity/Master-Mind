# Phase 24b: 郑氏星案命格判断验证报告

## 验证目标

用格局规则引擎对郑氏星案40例排盘结果自动判断格局，与郑希诚原判的"所喜星格/所忌星格"对比，评估规则引擎的覆盖度和准确性。

## 验证方法

1. 对40例排盘结果调用`core.eval_rules(chart_data)`
2. 从星案原文提取每例的"所喜星格"和"所忌星格"
3. 统计规则库对郑氏星格的覆盖率
4. 分析命格等级与格局匹配数的相关性

## 验证结果

### 1. 规则库覆盖度

| 类别 | 郑氏星格种类 | 规则库命中 | 覆盖率 |
|------|------------|-----------|--------|
| 所喜星格 | 103种 | 24种 | **23.3%** |
| 所忌星格 | 69种 | 0种 | **0.0%** |

**关键发现**：规则库134条规则全部是喜格（sign="+"），完全没有忌格（sign="-"）。这是规则引擎的重大缺口。

### 2. 规则库命中的24种喜格

```
七政连环、五曜环阳、众曜拱南、八杀朝天、命临官贵、

身命升殿、身命殿垣、身坐卦禄、身居福地
```

### 3. 规则库未命中的79种喜格（主要缺口）

高频未命中星格：
- **夹拱类**：日月夹命、日月夹夫、日月夹财、日月夹辅、官福夹命、田财夹命（规则库缺夹拱逻辑）
- **相生类**：土金相生、火土相生、金水相生、金计相生（规则库有相生模板但命名不匹配）
- **得地类**：命主居福、福主居垣、财星升殿、福星升殿、官福得地（规则库缺"得地"判断）
- **朝天类**：夜火朝天、夜火朝阳、水星朝日、官福朝天（规则库缺"朝天"判断）

| 科第命 | 1 | 18.0 | 18-18 |
| ... | ... | ... | ... |
| 三品命 | 2 | 14.5 | 14-15 |
| 五品命 | 3 | 13.7 | 10-17 |
| 寻常命 | 3 | 12.0 | 10-15 |
| 府官命 | 1 | 9.0 | 9-9 |

**高命格（9例）平均13.6个格局 vs 低命格（10例）平均15.7个格局**

**结论：命格等级与格局匹配数无正相关，甚至出现负相关**。这说明：
1. 规则库的格局匹配数不能直接用于命格等级判断
2. 郑希诚的命格判断不是简单的"格局越多越好"，而是看格局的**质量**和**组合**
3. 规则库缺少忌格（减分项），导致低命格的匹配数反而偏高

## 结论与后续工作

### 当前状态
- **排盘引擎**：✅ 40/40全部匹配（Phase 24已验证）
- **格局引擎覆盖度**：❌ 喜格23.3%，忌格0%
- **命格等级判断**：❌ 无法用当前规则库的匹配数判断命格等级

### 需要补充的工作

1. **扩充忌格规则**（最高优先级）：
   - 从郑氏星案69种忌格中提取规则
   - 从果老星宗/星命溯源中提取更多忌格
   - 添加sign="-"的忌格规则

2. **扩充喜格规则**（高优先级）：
   - 补充79种未命中的喜格
   - 重点：夹拱类（日月夹命/官福夹命/田财夹命）、相生类、得地类、朝天类

3. **格局质量评分**（中优先级）：
   - 不是简单数格局数量，而是按格局的priority权重评分
   - 高priority格局（如日月夹命）权重高于低priority格局（如入垣）

4. **命格等级模型**（长期）：
   - 建立格局组合→命格等级的映射模型
   - 用郑氏星案40例作为训练数据
   - 考虑喜格/忌格的平衡、格局组合的协同效应
