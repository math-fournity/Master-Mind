## 一、模块功能

### 1.1 orchestrator（runtime/orchestrator.py）

12步在线循环编排 + 8角色在线运行时集成。

12步主链：
1. 冻结 → 2. 建态 → 3. 独立探索 → 4. 事件捕获 → 5. 状态归约
→ 6. 局部验证 → 7. 诊断决策 → 8. 模式匹配 → 9. 最小动作选择
→ 10. 增量编译 → 11. 因果分叉 → 12. 归因收口

8角色：solver / event_capture / state_reducer / retriever / heuristic_matcher / verifier / auditor / orchestrator

### 1.2 guided_loop（runtime/guided_loop.py）

系统引导数学大师的完整循环：
- Turn 1: solo explore（给数学大师问题，不给hint）
- 如果未完成：检测卡点 → 生成hint → guided explore
- 重复直到完成或预算耗尽

### 1.3 devin_cli_adapter（runtime/devin_cli_adapter.py）

连接12步运行时和真实devin cli实例：
- 每turn调用`devin -p`，在Solver工作目录运行
- 支持`--export`导出conversation.json
- 自动选择Solver工作目录

## 二、审计检查项

### 2.1 12步循环完整性

| 检查项 | 说明 | 标准 |
|---|---|---|
| 12步全执行 | 每次循环是否12步都执行了 | `all_12_steps_implemented == True` |
| 步骤顺序 | 12步是否按1→2→...→12顺序执行 | step_history按node_id排序后顺序必须是1,2,...,12 |
| 步骤角色正确 | 每步是否由正确角色执行 | 步骤3=solver, 步骤4=event_capture, 步骤5=state_reducer, 步骤6=verifier, 步骤7=orchestrator, 步骤8=heuristic_matcher, 步骤9=orchestrator, 步骤10=orchestrator, 步骤11=auditor, 步骤12=auditor |
| 步骤10从checkpoint | 步骤10是否从checkpoint继续 | `from_checkpoint == True` |
| 步骤11分层 | 步骤11是否用checkpoint分层 | `checkpoint_layered == True` |
| 步骤12保存失败路线 | 步骤12是否保存了失败路线 | `failure_routes_saved == True` |

**判定标准**：
- **通过**：6项全通过
- **有缺陷**：步骤全执行但顺序或角色有小问题
- **失败**：步骤缺失或顺序严重错误

### 2.2 引导循环有效性

| 检查项 | 说明 | 标准 |
|---|---|---|
| solo explore先于guided | Turn 1必须是solo explore（无hint） | `turn_history[0].is_hint == False` |
| hint只在卡点后给 | hint不能在solo explore阶段给 | solo explore阶段`hints_used == 0` |
| hint数量不超过预算 | hints_used ≤ max_hints | `hints_used <= max_hints` |
| turn数量不超过预算 | n_turns ≤ max_turns | `n_turns <= max_turns` |
| 完成判定合理 | completed=True时确实有完成信号 | final_response包含完成信号（证毕/QED/结论是等）且不以[ERROR开头 |
| 卡点检测准确 | stall_detected=True时确实有数学卡点信号 | response包含数学卡点信号（我不知道/无法确定等）或response过短；如果response包含工作系统关键词（认知种子/CP1-CP3/七步骤），应标记为"非数学卡点"而非"数学卡点" |
| hint内容相关 | hint内容与卡点原因相关 | hint的stall_reason与response中的卡点信号一致 |

**判定标准**：
- **通过**：7项全通过
- **有缺陷**：循环跑通但hint时机或内容有小问题
- **失败**：循环未跑通 或 hint在solo阶段给了 或 预算超限

### 2.3 Solver连接稳定性

| 检查项 | 说明 | 标准 |
|---|---|---|
| devin cli调用成功 | 每turn的returncode是否为0 | 所有turn的response不以`[ERROR`开头 |
| session_id获取 | 是否成功提取session_id | `session_id != ""`（第1turn后） |
| --export文件生成 | conversation.json是否生成 | `export_path文件存在且大小>0` |
| 工作目录正确 | devin cli的cwd是否是Solver工作目录 | sessions.db中`working_directory`是`/data/math-agent-glm5.2-*` |
| 无web_search | Solver没有使用web_search | tool_call_state中无web_search记录 |
| 无工作系统劫持 | Solver没有走CP1-CP3/pipeline | response中不包含"加载认知种子"/"CP1-CP3"/"七步骤"等 |

**判定标准**：
- **通过**：6项全通过
- **有缺陷**：调用成功但session_id或export有小问题
- **失败**：调用失败 或 工作目录错误 或 web_search被使用 或 工作系统劫持

### 2.4 引导效果度量

| 检查项 | 说明 | 标准 |
|---|---|---|
| solo成功率 | 无hint时数学大师能完成的比例 | 统计指标，跨多个run计算 |
| hint有效率 | hint后数学大师从"不能"变"能"的比例 | hint后completed=True的比例 |
| 干预时机 | 系统是否在正确时机干预 | 不过早（solo还没充分探索就给hint）不过晚（卡了很久才给hint） |
| token效率 | 正确完成所需的token数 | 与问题难度评分对比，不应过高 |

**判定标准**：
- 这些是统计指标，需要跨多个run计算，单次run无法判定
- **通过**：solo成功率 > 30% 且 hint有效率 > 20%
- **需关注**：solo成功率 < 10%（问题太难或数学大师太弱）或 hint有效率 < 5%（hint无效）

## 三、验证方法

### 3.1 从guided_loop_result.json提取

```python
import json

def audit_guided_loop(run_dir: str) -> dict:
    """审计一个run的引导循环"""
    with open(f"{run_dir}/guided_loop_result.json") as f:
        result = json.load(f)

    checks = {}

    # 2.2 引导循环有效性
    checks["solo_first"] = result["turn_history"][0].get("is_hint", False) == False
    checks["n_turns_ok"] = result["n_turns"] <= 5  # max_turns
    checks["n_hints_ok"] = result["n_hints"] <= 3  # max_hints
    checks["completed_has_signal"] = result["completed"] and any(
        sig in result["final_response"]
        for sig in ["证毕", "QED", "结论是", "综上所述", "一句话总结"]
    )

    return checks
```

### 3.2 从sessions.db提取

```python
def audit_solver_session(session_id: str) -> dict:
    """审计Solver的session"""
    conn = sqlite3.connect("~/.local/share/devin/cli/sessions.db")

    # 工作目录
    session = conn.execute("SELECT working_directory FROM sessions WHERE id = ?", (session_id,)).fetchone()
    checks["work_dir_correct"] = "/data/math-agent-glm5.2-" in session[0]

    # web_search检查
    tool_calls = conn.execute("SELECT tool_call_json FROM tool_call_state WHERE session_id = ?", (session_id,)).fetchall()
    checks["no_web_search"] = not any("web_search" in tc[0] for tc in tool_calls)

    return checks
```

### 3.3 从conversation.json提取

```python
def audit_export(run_dir: str, turn: int) -> dict:
    """审计--export文件"""
    with open(f"{run_dir}/turn_{turn}_conversation.json") as f:
        conv = json.load(f)

    checks = {}
    checks["export_has_session_id"] = bool(conv.get("session_id"))
    checks["export_has_metrics"] = bool(conv.get("final_metrics"))
    checks["export_has_steps"] = len(conv.get("steps", [])) > 0

    return checks
```
