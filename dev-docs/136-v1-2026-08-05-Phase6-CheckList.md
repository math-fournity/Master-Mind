## P6-6 gaming检测

> 来源：123号§51 + §56(R-4风险) + 系统探讨.md§15.4

- [ ] **P6-6.1**：实现gaming检测（Agent是否迎合触发器以获取帮助，153号v2 F10预防修正） [预期D2]
  - 系统探讨.md§15.4冻结的三元判定机制（代码必须实现全部3元判定，不只是"检测gaming"的概括）：
    1. **停滞词识别**：Agent输出中包含停滞词（如"我不知道"、"卡住了"、"无法继续"等）时，标记为"自报停滞"。停滞词列表必须可配置，不能硬编码固定列表。
    2. **工具证据验证**：自报停滞时，检查Agent是否真的调用了工具（SageMath/SymPy/Lean等）并产生了工具输出。只检查"声称调用了工具"不算工具证据——必须有工具调用的实际记录和输出。
    3. **结构进展度量**：自报停滞时，检查T图中是否有实际结构进展（新增节点/形成边/开放目标减少/义务状态变化）。只检查输出长度变化不算结构进展——必须是T图结构的实际变化。
  - **三元判定逻辑**：只有当（停滞词=True）AND（工具证据=False）AND（结构进展=False）时，才判定为gaming。如果Agent自报停滞但有工具证据或结构进展，不算gaming。
  - 深度标准：有可执行的gaming检测函数，实现三元判定机制
  - 边界情况：无gaming行为、gaming行为隐蔽、Agent自报停滞但有工具证据（不算gaming）、Agent自报停滞但有结构进展（不算gaming）
- [ ] **P6-6.2**：检测自报停滞与工具/结构进展的不一致 [预期D2]
  - 系统探讨.md§15.4："需要工具证据和结构进展，而不是只相信自报"
  - 深度标准：有可执行的不一致检测函数，对比自报停滞与工具/结构进展
  - 边界情况：自报停滞与工具进展一致（无gaming）、自报停滞与工具进展不一致（有gaming）
- [ ] **P6-6.3**：限制奖励性帮助（R-4风险防线） [预期D2]
  - 深度标准：有可执行的限制函数，检测到gaming时限制奖励性帮助
  - 边界情况：检测到gaming但未限制帮助（应被拒绝）

### 完整性标准

- [ ] **P6-6.COMP**：gaming检测基于工具证据和结构进展，不只相信自报（系统探讨.md§15.4 + R-4风险） [预期D3]

## P6-8 回滚到反应式模式

> 来源：123号§51 + §22(反应式vs主动式) + 系统探讨.md§13(反应式救援)

- [ ] **P6-8.1**：实现回滚机制（闭环失败时退回先观察再干预的反应式模式，153号v2 F10预防修正） [预期D2]
  - **"闭环失败"的具体定义（代码必须实现以下判定，不只是"闭环失败时回滚"的概括）**：
    1. P6-EXIT-1不通过：闭环长期收益≤0
    2. P6-EXIT-2不通过：收益为正但靠更高泄漏或无限帮助获得
    3. P6-STOP-2触发：正确率提升以更高泄漏为代价
    4. P6-STOP-3触发：gaming检测不一致率超阈值
  - **反应式救援模式5条理由（系统探讨.md§13，代码必须标注REACTIVE_RESCUE_MODE=True并记录5条理由）**：
    1. 当前最缺的是因果证据——反应式模式易做因果验证
    2. 只有先看到自然失败，才能知道系统补了什么
