# 108-数学大师全知识体系准备方案

> **文档定位**：为大规模"吸收-测试"自动化loop做准备。定义数学大师需要知道的**一切知识**的范围、来源、分批计划、自动化架构。

## 一、目标

把数学大师需要的全部知识，按"渐进积累、迭代测试"的原则，分批吸收进ArangoDB依赖图。每批吸收后立即测试，验证通过再继续下一批。

**终态**：依赖图覆盖数学大师做任意数学研究时需要的全部知识依赖——不仅是一道题的解法路径，而是整个数学知识体系的依赖网络。

## 二、知识范围（8大领域+3个横切层）

### 2.1 八大数学领域

| 领域 | 核心内容 | 关键定理/概念 | 估计题数 |
|---|---|---|---|
| **代数** | 群/环/域/模/线性代数/交换代数 | Cayley-Hamilton, 谱定理, Sylow定理, Jordan标准型, Hilbert零点定理, Nakayama引理, 结构定理 | 30-50 |
| **几何** | 微分几何/代数几何/黎曼几何 | Gauss-Bonnet, Stokes定理, Hodge定理, Riemann-Roch, Bezout定理, de Rham上同调 | 20-40 |
| **分析** | 实分析/复分析/调和分析/泛函分析 | 极值定理, Lebesgue收敛定理, Cauchy-Schwarz, Hahn-Banach, 开映射定理, Riesz表示, Paley-Wiener | 20-40 |
| **拓扑** | 点集拓扑/代数拓扑/微分拓扑 | Euler公式, Brouwer不动点, Borsuk-Ulam, 同伦群, 同调群, Poincaré对偶, 亏格公式 | 20-40 |
| **数论** | 初等数论/解析数论/代数数论 | Fermat小定理, Wilson定理, CRT, 二平方定理, Dirichlet定理, PNT, Hasse原理, 类数公式 | 20-40 |
| **组合** | 组合学/图论/Ramsey理论 | 二项式定理, Schur定理, Ramsey定理, Turán定理, 生成函数, 容斥原理, 鸽巢原理 | 15-30 |
| **逻辑/范畴论** | 数理逻辑/集合论/范畴论 | Gödel不完备性, Zorn引理, Yoneda引理, 伴随函子, 极限/余极限, Abel范畴 | 10-20 |
| **概率/动力系统** | 概率论/随机过程/动力系统 | 大数定律, 中心极限定理, 遍历定理, Birkhoff定理, Markov链收敛 | 10-20 |

## 四、自动化架构

### 4.1 "吸收-测试"Loop的设计

```
┌─────────────────────────────────────────────────┐
│            大规模"吸收-测试"自动化Loop            │
├─────────────────────────────────────────────────┤
│                                                  │
│  For each batch (10-20道题):                     │
│                                                  │
│  ┌─ 吸收阶段 ──────────────────────────────┐     │
│  │ 1. 选题：从待吸收队列中取10-20道         │     │
│  │ 2. L1提取：AI提取解法路径（2-3种/题）    │     │
│  │ 3. L2提取：AI二次分析抽象思维模式        │     │
│  │ 4. L3提取：AI三次分析提取范式思维        │     │
│  │ 5. 格式化：标准JSON格式                  │     │
│  │ 6. 导入ArangoDB：problems+solutions+     │     │
│  │    dg_nodes+dg_edges+意识节点+范式节点   │     │
│  └────────────────────────────────────────┘     │
│                  ↓                               │
│  ┌─ 测试阶段 ──────────────────────────────┐     │
│  │ 7. 依赖图完整性：节点/边/领域覆盖统计    │     │
│  │ 8. topo_generator：能否生成G'_topo       │     │
│  │ 9. TopologyVerifier：拓扑覆盖验证        │     │
│  │ 10. 子图提取：随机选1题提取依赖子图      │     │
│  │ 11. 跨领域连通性：跨领域边能否连通       │     │
│  │ 12. 回归验证：已有POC基线是否仍通过      │     │
│  └────────────────────────────────────────┘     │
│                  ↓                               │
│  ┌─ 判定 ─────────────────────────────────┐     │
│  │ 全部通过 → 继续下一批                   │     │
│  │ 有失败 → 修复后重测，不继续吸收          │     │
│  └────────────────────────────────────────┘     │
│                                                  │
└─────────────────────────────────────────────────┘
```

### 4.2 自动化的关键设计

| 设计点 | 方案 | 理由 |
|---|---|---|
| 选题 | 按领域分组，每次选同领域10-20道 | 同领域题之间依赖关系密集，批量提取效率高 |
| L1提取 | subagent并行，每题一个subagent | L1是从标准证明提取步骤，可并行 |
| L2/L3提取 | subagent批量处理（一个subagent处理5-10道） | L2/L3需要跨题综合，批量处理能看到模式 |
| 导入 | 脚本自动导入ArangoDB | 已有导入脚本，复用 |
| 测试 | 脚本自动跑6项测试 | 需要编写自动化测试脚本 |
| 判定 | 全通过→继续；有失败→停止 | 边吸收边测试纪律 |

## 八、诚实面对

1. **~2000节点是估计**：实际节点数取决于每道题的解法路径长度和概念重叠程度。领域间共享概念（如"多项式""群""拓扑空间"）会减少新增节点。

2. **L3提取质量是瓶颈**：POC-3审计发现L3-2应降级为L2。大规模吸收时L3提取质量需要持续监控——不能只追求数量，每批的L3质量需要抽查。

3. **自动化loop需要人监督**：完全自动化可能有风险（L2/L3提取质量下降不会自动检测）。建议每批结束后人工抽查1-2道的提取质量。

4. **MathLib 100的100道不全是"大师级"**：有些是很基础的题（如"sqrt(2)是无理数"）。需要筛选——优先选有跨领域映射和L3潜力的题。

5. **这个规模需要较长时间**：即使自动化，100+道题的三层提取（每道2-3个解法×L1+L2+L3）是大量subagent工作。按"渐进积累"原则，不追求一次性完成，而是分批稳步推进。
