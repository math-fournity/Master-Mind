# 108-数学大师全知识体系准备方案（v2：穷尽式）

> **⚠️ 本文档已被109号方案v3接替**：109号文档从"数学痴狂爱好者"视角重新发掘了全知识宇宙，从v2的七大来源扩展到十三大来源，节点估计从~110000扩展到~325000。v2的七大来源只是十三大来源的一个子集。v2的吸收Loop架构、校验策略、存档结构仍然有效，但知识范围、分批计划、工具需求以109号方案v3为准。
>
> **文档定位**：v1的思路是"每个领域选10几道题"——这不对。全能数学大师应该知道**一切**可得的数学知识。本方案改为穷尽式吸收。AI通过维基百科+内在知识还原内容，用SymPy/SageMath/Lean4校验正确性。

## 一、核心理念转变

### v1（错误）vs v2（正确）

| 维度 | v1（标杆题库选取） | v2（穷尽式吸收） |
|---|---|---|
| 范围 | 每个领域选10-15道标杆题 | 穷尽所有可得数学知识 |
| 题目 | MathLib 100 + THE BOOK ~40道 | IMO全部+Putnam全部+各国奥赛全部+教材习题全部 |
| 数学家工作 | 不涉及 | 所有知名数学家+所有菲尔兹奖得主 |
| 文献 | 不涉及 | 所有可得教材/专著/论文 |
| 知识生成 | 只从已有题解提取 | AI通过维基百科+内在知识**还原**，用软件校验 |
| 原文存档 | 不涉及 | 数据库/硬盘目录分类存档原文 |
| 规模 | ~140道题 | 数千~数万知识单元 |

### 关键洞察

1. **AI可以自己生成知识内容**：数学知识可以通过维基百科条目+AI内在知识还原，不需要从网上下载全部原文。比如"Grothendieck的概形理论"——AI知道它是什么，能从维基百科确认框架，然后用内在知识还原完整内容。

2. **数学可以用软件校验**：AI还原的数学内容可以用SymPy（代数验证）/SageMath（研究级计算）/Lean4（形式化证明）校验正确性。这是数学相比其他领域的独特优势——**生成的内容可以验证**。

3. **知识素材原文要存档**：不只是提取L1/L2/L3入依赖图，原文也要在数据库或硬盘目录中分类存档——大师看过原文，不只是看过提取后的依赖关系。

## 四、AI还原+校验流程

### 4.1 知识还原流程

```
选题（从穷尽清单中选一批）
  ↓
AI还原内容（维基百科框架 + 内在知识填充）
  ↓
软件校验
  ├─ SymPy：代数恒等式验证
  ├─ SageMath：数值实验/符号计算验证
  └─ Lean4：形式化证明验证（如有MathLib对应）
  ↓
校验通过 → 存档原文到knowledge/目录
  ↓
三层提取（L1/L2/L3）
  ↓
导入ArangoDB（原文入knowledge_docs + 依赖入dg_nodes/dg_edges）
  ↓
6项测试
```

### 4.2 校验策略

| 内容类型 | 校验方式 | 通过标准 |
|---|---|---|
| 代数恒等式 | SymPy `simplify()` | 恒等式成立 |
| 数值结论 | SageMath数值验证 | 数值匹配 |
| 存在性证明 | 构造+验证 | 构造的对象满足条件 |
| 形式化定理 | Lean4 `#check` | 类型检查通过 |
| 概念性描述 | 维基百科交叉校验 | 与维基百科一致 |
| 证明思路 | AI自审+交叉审计 | 逻辑自洽 |

## 九、诚实面对

1. **~110000节点是估计**：实际节点数取决于知识重叠程度。领域间共享概念会减少新增节点，但Wikipedia条目量大。

2. **AI还原质量是核心风险**：AI通过内在知识还原的数学内容可能有错误。**软件校验是关键**——SymPy/SageMath/Lean4可以校验大部分数学内容。但有些内容（如历史叙述、直觉描述）无法用软件校验，需要维基百科交叉校验+AI自审。

3. **Wikipedia 25000条是最大批量**：需要维基百科API批量获取。条目质量参差不齐——有些条目很详细，有些只有stub。需要筛选。

4. **这个规模需要很长时间**：即使自动化，~35000个知识单元的还原+校验+提取+导入是大量工作。按"渐进积累"原则，分批稳步推进，不追求一次性完成。

5. **不是所有内容都需要三层提取**：Wikipedia条目可能只需要L1（概念定义+基本性质），不需要L2/L3。三层提取优先用于竞赛题和数学家工作——这些有深度思维路径的内容。

6. **原文存档需要磁盘空间**：~35000个markdown文件，估计~2-5GB。当前D盘空间够用。
