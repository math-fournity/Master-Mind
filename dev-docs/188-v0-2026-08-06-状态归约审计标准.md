## 一、模块功能概览

state_reducer子系统负责从事件流重建工作区状态，是所有决策的基础。

| 模块 | 功能 |
|---|---|
| reducer | 两个独立StateReducer从事件流重建状态，计算Krippendorff α一致性 |
| progress | 进展偏序比较、状态等价判定、两种环路判别（平面vs螺旋） |
| obligation | 研究义务图（AND/OR超图）的存储、DAG验证、释放条件检查 |
| evidence | 证据状态存储、派生认识状态计算、冲突检测、验证门检查 |
| controller_belief | 控制器信念建模（卡点概率/停滞概率/策略置信度/gaming概率）+ 9种动作选择 |
| verification_gate | F_t→V_t验证门，确保已验证内容与未验证内容分离 |
| q0 | Q_0任务实例化（冻结的Ramsey案例） |
| workspace_store | 工作区ArangoDB存储接口，W_t只能由Reducer派生 |

## 二、审计检查项

### 2.1 状态重建准确性（reducer.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 可复现性 | 同一事件流+同一Reducer版本必须得到相同结果 | 相同输入两次运行结果完全一致 |
| 关键字段一致性 | 多观察者重建的Krippendorff α | 关键字段(V_t/F_t/O_t)α≥0.80，无字段低于0.67 |
| 不补写推理 | Reducer不能自行补写未发生的数学推理 | ReconstructedState中不能有事件流中没有的推理步骤 |
| 字段完整 | 重建状态包含V_t/F_t/O_t/R_t/D_t/E_t/stall_type | 7个字段全部存在 |

**判定**：通过=4项全通过；有缺陷=一致性α在0.67-0.80之间；失败=不可复现或α<0.67或补写推理

### 2.2 进展判别准确性（progress.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 进展向量比较 | improved/worsened/equal/incomparable判定 | 同一schema+同一任务+同一权重版本下比较 |
| 状态等价 | ~_{α,κ}等价判定 | 规范化键忽略措辞、变量改名、事件时间 |
| 环路判别 | 平面环路vs螺旋上升环路 | 平面=开放义务/证据门/冲突无改善；螺旋=同抽象类但更细粒度且至少一项严格改善 |
| 跨任务隔离 | 进展向量不跨任务比较 | 不同任务的ProgressVector不直接比较 |

**判定**：通过=4项全通过；有缺陷=环路判别有误但进展比较正确；失败=跨任务比较或环路判别错误

### 2.3 义务图完整性（obligation.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| DAG验证 | 义务图是否是有向无环图 | 检测自环/双向往返环/SCC，is_dag=True |
| 循环依赖处理 | 循环依赖不自动释放 | 产生SCC时标记为待审计，不自动release |
| AND超边释放 | 全部前置义务达到证据门才释放 | AND超边所有前置义务evidence gate passed |
| OR超边释放 | 任一前置义务达到证据门就释放 | OR超边至少一个前置义务evidence gate passed |
| 超边存储 | 超边本体存relation document | 不用普通depends_on边 |

**判定**：通过=5项全通过；有缺陷=DAG有小环但已标记；失败=有未检测的环或自动释放了循环依赖

### 2.4 证据状态正确性（evidence.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 派生认识状态 | no_decisive/support_only/refute_only/mixed | 按polarity统计，不对kind排序 |
| 冲突检测 | 支持与反驳并存时检测到冲突 | has_conflict=True时生成范围/前提澄清义务 |
| 冲突范围 | 冲突不爆炸到整个知识库 | 只生成局部澄清义务，不全局爆炸 |
| 验证门检查 | 只有满足验证门的命题进入V_t | gate_passed=True才can_enter_v_t |

**判定**：通过=4项全通过；有缺陷=冲突检测正确但范围控制不当；失败=派生状态错误或验证门失效

### 2.5 控制器信念合理性（controller_belief.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 只基于公开产物 | 信念估计不读取LLM内部状态 | 输入只有progress_history/budget/obligations/self_reported_stall |
| gaming概率处理 | gaming概率高时弃权 | gaming_prob > 阈值时action=abstain |
| 预算耗尽处理 | 预算耗尽时停止 | budget exhausted时action=stop |
| Hint预算检查 | Hint预算不足时不能注入Hint | hint_budget_remaining=0时不能select_hint |
| 动作空间完整 | 9种动作全部可选 | continue_observe/diagnose/tool_check/retrieve/inject_hint/abstain/stop等 |

**判定**：通过=5项全通过；有缺陷=动作选择正确但信念估计有小偏差；失败=读取了LLM内部状态或预算约束失效

### 2.6 V_t/F_t分离（verification_gate.py + workspace_store.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| F_t→V_t必须带证据 | 提升时必须有证据引用 | can_promote=True时必须有evidence_refs |
| 派生状态检查 | refute_only或mixed不能进入V_t | derived_state为refute_only/mixed时can_promote=False |
| V_t单调增长 | V_t原则上只增不减 | 已进入V_t的命题不被移除 |
| 临时假设隔离 | 临时假设不能混入V_t | 临时假设只在F_t中 |
| W_t不可直接修改 | W_t只能由版本化Reducer派生 | update_workspace只允许更新元数据 |
| 被拒绝路线隔离 | 被拒绝路线不在R_t中 | 被拒绝路线存入failure_routes，不进R_t |

**判定**：通过=6项全通过；有缺陷=分离基本正确但边界有小泄漏；失败=V_t/F_t混入或W_t被直接修改

### 2.7 Q_0冻结（q0.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 冻结验证 | Q_0在运行时保持冻结 | 内容哈希验证通过 |
| 不可反向升级 | 不能把119号结论升级回Q_0 | 不存在反向升级操作 |
| 只读实验基底 | Ramsey修正版材料冻结为只读 | 无写操作 |

**判定**：通过=3项全通过；失败=Q_0被修改或存在反向升级
