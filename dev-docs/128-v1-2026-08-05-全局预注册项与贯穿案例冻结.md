## 1. G0-1：关键事件完整清单

> 123号第四十四节：在Phase 1开始前，定义"关键事件"的完整清单。
> 以下清单是Phase 1事件捕获器（Event Capture）必须捕获的事件类型，不允许遗漏。

### 1.1 工具调用事件

| 事件类型 | 捕获内容 | 必须捕获 |
|---|---|---|
| `tool_call` | 工具名称、输入参数、调用时间 | 是 |
| `tool_result` | 工具返回值、执行状态、耗时 | 是 |
| `tool_error` | 错误类型、错误信息、重试次数 | 是 |

### 1.2 文本段落事件

| 事件类型 | 捕获内容 | 必须捕获 | 123号Event schema对应 |
|---|---|---|---|
| `claim` | AI提出的数学命题/断言 | 是 | `claim` |
| `proof_step` | 证明步骤（引理引用/推导/计算） | 是 | `claim`的子类型 |
| `conjecture` | AI提出的猜想 | 是 | `candidate` |
| `counterexample` | AI提出的反例或反例方向 | 是 | `candidate`(反例方向) |
| `representation_change` | AI切换表示（如从代数到几何） | 是 | `representation` |
| `subgoal` | AI提出新子目标 | 是 | `subgoal` |
| `test` | AI执行检验/测试（数值/极端/反例搜索） | 是 | `test` |
| `stall_declaration` | AI声明卡住/不确定 | 是 | `stall` |
| `backtrack` | AI放弃当前路线回退 | 是 | `backtrack` |
| `contradiction` | AI发现矛盾 | 是 | `contradiction` |
| `resolution` | AI解决矛盾/完成子目标 | 是 | `resolution` |
| `observation` | AI观察到的事实/模式 | 是 | `observation` |

### 1.3 分支点事件

| 事件类型 | 捕获内容 | 必须捕获 |
|---|---|---|
| `branch_fork` | AI选择分叉（选择路径A而非B） | 是 |
| `branch_abandon` | AI放弃某分支 | 是 |
| `hint_reception` | AI接收Hint | 是 |
| `hint_response` | AI对Hint的响应行为 | 是 |
| `checkpoint_continue` | 从checkpoint继续 | 是 |

### 1.4 状态变更事件

| 事件类型 | 捕获内容 | 必须捕获 |
|---|---|---|
| `obligation_discharge` | 义务被释放 | 是 |
| `obligation_create` | 新义务产生 | 是 |
| `evidence_add` | 新证据加入 | 是 |
| `evidence_conflict` | 证据冲突检测 | 是 |
| `workspace_update` | 工作区状态更新 | 是 |
| `state_reduction` | State Reducer执行状态归约 | 是 |
| `verification` | Verifier执行验证 | 是 |

### 1.5 与123号Event schema的对齐

123号第十七节和127号Event schema定义了14种语义事件类型：
```
observation / claim / representation / subgoal / candidate /
test / tool_result / contradiction / stall / backtrack / resolution /
hint_injection / state_reduction / verification
```

本清单§1.1—1.4覆盖了上述全部14种类型，并按捕获场景做了更细的分类（工具调用/文本段落/分支点/状态变更）。Phase 1事件捕获器必须能输出127号Event schema定义的全部14种语义事件类型。

### 1.6 冻结声明

此清单在Phase 1开始前冻结。Phase 1事件捕获器必须覆盖以上全部事件类型。如需新增事件类型，必须产生新protocol版本（G0-6）。

## 2. R-1—R-16：风险监控机制

> 123号第五十六/五十七节：每项风险在Phase 0建立监控机制，在每个Phase出口门检查风险是否触发停止条件。

### 原文八项风险

#### R-1：外显轨迹不等于隐藏思维

- **风险**：系统可能声称读取了AI的隐藏CoT
- **监控机制**：每个Phase的Event Capture文档必须明确声明"只处理公开研究产物与工具事件"
- **检查点**：每个Phase出口门检查Event Capture文档是否含此声明
- **触发停止**：发现任何声称读取隐藏CoT的文档或代码

#### R-2：A/B差异不等于因果

- **风险**：从非等价checkpoint做干预，导致A/B差异不能归因于干预
- **监控机制**：DYN-3实验必须从同/等价checkpoint做重复干预；记录checkpoint内容哈希
- **检查点**：Phase 4入口门检查checkpoint等价性验证机制
- **触发停止**：发现非等价checkpoint的干预实验

#### R-3：动态状态会累积错误

- **风险**：verified core与speculative frontier混淆，错误累积
- **监控机制**：V/F分离 + 状态更新带证据引用 + Reducer版本化
- **检查点**：Phase 2出口门检查V/F分离实现
- **触发停止**：发现F_t内容进入V_t without evidence

#### R-4：Agent可能迎合触发器

- **风险**：Agent可能迎合Hint触发器而非真正理解
- **监控机制**：检测自报停滞与工具/结构进展的不一致；限制奖励性帮助；Phase 6的gaming检测
- **检查点**：Phase 4/6出口门检查gaming检测机制
- **触发停止**：自报停滞与实际进展不一致率超过阈值

#### R-5：多元时序组合爆炸

- **风险**：规则匹配的组合爆炸
- **监控机制**：规则因子化（LHS/interface/RHS/guard）、稀疏匹配、按需物化
- **检查点**：Phase 3出口门检查规则因子化实现
- **触发停止**：匹配时间超过预算阈值

#### R-6：上下文膨胀

- **风险**：不可变日志直接灌入提示，导致上下文膨胀
- **监控机制**：冷/温/热/微包架构；快照只保留充分状态
- **检查点**：Phase 5出口门检查Context Compiler的token预算控制
- **触发停止**：单轮上下文超过模型token限制

#### R-7：模型漂移

- **风险**：规则效果随模型版本变化
- **监控机制**：效果按模型/版本分层；支持衰减、再验证和退役
- **检查点**：Phase 6出口门检查模型版本分层实现
- **触发停止**：published规则在新模型版本上效果衰减超过阈值

#### R-8：数学名词冒充实现

- **风险**：HoTT/拓扑/几何主张被当成已实现
- **监控机制**：所有数学主张标注"语义规格/实验分析/已实现"级别
- **检查点**：每个Phase出口门检查文档中的数学主张标注
- **触发停止**：发现未标注级别的数学主张

### 新增风险

#### R-9：状态抽取器系统性偏差

- **风险**：状态抽取器对不同AI输出有系统性偏差
- **监控机制**：Phase 2多观察者一致性测试（Krippendorff α）
- **检查点**：Phase 2出口门检查α值是否达到G0-2阈值
- **触发停止**：关键状态字段α < 0.80

#### R-10：Verifier只覆盖部分数学领域

- **风险**：验证器只覆盖部分数学领域，其他领域盲区
- **监控机制**：Phase 5验证路由声明覆盖域和盲区
- **检查点**：Phase 5出口门检查覆盖域声明
- **触发停止**：实验涉及验证器盲区领域

#### R-11：Hint让Agent形成帮助依赖

- **风险**：Agent依赖Hint，撤掉Hint后无法独立完成
- **监控机制**：Phase 4/6的依赖代理（撤掉Hint后继续率）
- **检查点**：Phase 4/6出口门检查依赖代理测量
- **触发停止**：无提示后续独立完成率低于G0-M10阈值

#### R-12：长程信用错误地归给最近一次提示

- **风险**：长程进展被归因于最近一次Hint
- **监控机制**：Phase 6的长期归因机制
- **检查点**：Phase 6出口门检查归因机制
- **触发停止**：归因误差超过阈值

#### R-13：Truth Vault或其他组输出越权

- **风险**：Truth Vault内容泄露到Runner可见范围
- **监控机制**：Phase 0可见性矩阵（127号文档）+ Phase 1权限令牌（CapabilityToken）
- **检查点**：每个Phase出口门检查可见性矩阵执行
- **触发停止**：发现Truth Vault内容出现在Solver上下文

#### R-14：规则效果被单一模型版本绑架

- **风险**：规则只在单一模型版本上有效
- **监控机制**：Phase 4跨模型验证 + Phase 6模型版本分层
- **检查点**：Phase 4出口门检查跨模型验证
- **触发停止**：规则只在1个模型版本上有效

#### R-15：原始来源许可证、版本和撤稿状态变化

- **风险**：引用的论文被撤稿或版本更新
- **监控机制**：Phase 5来源注册 + Phase 7证据状态模型
- **检查点**：Phase 5/7出口门检查来源注册
- **触发停止**：发现引用已撤稿论文作为有效证据

#### R-16：冷索引标签被误当成已理解知识

- **风险**：arxiv_papers的L4索引级被当成已理解知识
- **监控机制**：Phase 5冷层默认不进Solver上下文
- **检查点**：Phase 5出口门检查冷层隔离
- **触发停止**：L4索引级内容出现在Solver上下文

## 3. CC-R-0：Ramsey发现型案例冻结

> 123号第三十四节 + 124号 CC-R-0
> 冻结Ramsey修正版材料为只读实验基底（NI-5候选题族）

### 3.1 案例描述

**问题**：从arXiv:2608.02537让AI猜测R_k(C_5)下界。

**Agent已知**：
- R_k(C_3) ≥ k^{k/3-o(k)}
- C_5比C_3更难避免
- 上界与迭代对数定义

**失败轨迹**：反复改变指数（k/5、k/6），没有把"底数"和"指数"作为两个独立结构变量。

### 3.2 非泄漏干预阶梯（冻结）

| 级别 | 内容 | 裁决 |
|---|---|---|
| Hint-0 | "你是否只在改指数？先列出表达式中可变化的结构部分。" | 低泄漏元检查 |
| Hint-1 | "把底数和指数分开分析，并说明递归障碍影响哪一部分。" | 研究操作 |
| Hint-2 | "递归规模缩减有时由迭代对数描述；把它作为候选工具而非结论。" | 中等概念提示 |
| 禁止 | "底数变成log k，指数k/3不变" | 等价答案 |

### 3.3 验证维度（冻结）

- 是否从"只改指数"状态转向比较底数
- 是否产生可验证的新结构论证
- 无提示分支是否同样转向
- Hint-1是否已足够，Hint-2是否多余
- 新的奇环问题上是否迁移

### 3.4 冻结声明

- Ramsey修正版材料冻结为只读实验基底
- 这是新protocol的候选题族（NI-5），不是继续或补写尚未完成的POC-6修正版B组
- 不能反向把119号结论升级
- 原始材料来源：118号（方案）、119号（结果，已降级为低可信历史证据）、120-121号（纠偏）

## 4. CC-F-0：费马极限案例冻结

> 123号第三十五节 + 124号 CC-F-0
> 冻结费马案例的三层难度阶梯

### 4.1 三层难度阶梯（冻结）

| 层级 | 任务 | 难度 |
|---|---|---|
| Level 1 | 给定半稳定模性，重建Frey—Ribet到FLT的推论 | 最低 |
| Level 2 | 隐去Frey/Ribet桥梁，让AI自行发现 | 中等 |
| Level 3 | Wiles级模块接口（从历史前状态独立发现整条路线） | 最高 |

### 4.2 Level 1推论链（冻结）

```
假想FLT反例
→ Frey曲线
→ 半稳定性/导子
→ mod p Galois表示
→ Ribet降层
→ 不存在的低水平权2模形式
→ Frey曲线不模

半稳定模性
→ Frey曲线必须模

两路汇聚为矛盾
```

### 4.3 大师启发维度（冻结）

真正的大师启发不是只说"谷山—志村"，而是：
- 把无结构整数反例编码成更富结构的几何对象
- 把存在性问题改成两个理论的不相容性问题
- 在椭圆曲线、Galois表示和模形式之间换语言
- 用局部ramification约束全局对象
- 降低level直到目标空间为空
- 证明一个更强但接口更合适的桥梁定理

### 4.4 冻结声明

- 费马案例**不在Phase 1—6使用**——123号明确"不要把完整FLT作为第一个动态闭环POC"
- 它是Phase 7的压力测试案例
- 验证顺序：先验证Level 1（给定半稳定模性推出FLT），再逐层隐去桥梁，最后才研究Level 3（Wiles级模块接口）
- 展示整数方程→辅助几何对象→Galois表示/模形式→Ribet降层的表示运输和模块接口

### 4.5 贯穿Phase使用计划

| Phase | 使用内容 | CC编号 |
|---|---|---|
| Phase 0 | 冻结三层难度阶梯 | CC-F-0 ✓（本文件） |
| Phase 1—6 | 不使用 | — |
| Phase 7 | 先Level 1，再Level 2，最后Level 3 | CC-F-7 |
