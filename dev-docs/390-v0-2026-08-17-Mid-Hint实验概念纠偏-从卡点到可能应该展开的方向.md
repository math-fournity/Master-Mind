## 核心纠偏

### 被滥用的概念："卡点"

我在Mid-Hint实验中一直用的概念框架是：

```
推理AI卡住了 → 系统识别卡点 → 给hint帮AI突破卡点
```

这个认知把"识别"理解为"识别AI在哪里卡住了"——然后给hint帮它突破。

### 正确概念："可能应该展开的方向"

引导树闭环的实际操作是：

```
系统观察推理AI的完整thinking → 识别AI没有考虑的分叉位置 → 在这些位置注入方向 → 启动新AI走这些分叉
```

这个认知把"识别"理解为"识别AI没有考虑什么"——不是AI卡住了需要帮助，而是AI走了一条路，但还有很多路它没走。

### 关键区别

| | "卡点"（被滥用的概念） | "可能应该展开的方向"（正确概念） |
|---|---|---|
| 识别什么 | AI在哪里卡住了 | AI没有考虑什么分叉 |
| AI的状态 | 卡住了、需要帮助 | 在走某条路、但错过了其他路 |
| hint的作用 | 帮AI突破卡点 | 让新AI走AI没走的路 |
| 触发时机 | AI停了/重复了 | AI的thinking中任何可以分叉的位置 |
| 与引导树的关系 | 卡点→给hint→同一个AI继续 | 分叉位置→新边→启动新AI走新分支 |

### "可能应该展开"——关键词

不是AI"卡住了"需要帮助，而是AI的思维空间中有多个**可能**应该展开的方向，AI只走了其中一个，其他方向它没走。Tell要去识别的是这些"可能应该展开但没展开的方向"，Hint要去提醒的是这些方向。

"可能"这个词很重要——不是确定应该展开，而是可能应该展开。系统识别的是可能性，不是确定性。

## 与285号文档的对应

285号文档已经做过这个纠偏：

**错误认知**：
```
推理AI卡住了 → 系统识别卡点 → 给hint帮AI突破卡点
```

**正确认知**：
```
系统观察推理AI的完整thinking → 识别AI没有考虑的分叉位置 → 在这些位置注入方向 → 启动新AI走这些分叉
```

285号的关键洞察：
- **往往不是AI卡住了然后需要提示，而是AI根本就是走错路了。**
- "卡住"意味着AI到了某个点无法继续——需要帮它突破
- "走错路"意味着AI选了一个方向走下去了——需要在它没选的方向上开新分支
- AI的thinking不是一条线，而是一条**走了的线**——但在这条线上有很多**可以分叉但没分叉的位置**
- 每个可以分叉但没分叉的位置，都是引导树的一个**潜在新边**
- 系统的识别任务不是"找到AI卡在哪里"，而是"找到AI的thinking中所有可以分叉但没分叉的位置"

**我在Mid-Hint实验中重复了285号已经纠偏过的错误——把"走错路"理解成了"卡住"。**

## 对Mid-Hint实验的影响

我的Mid-Hint实验设计从根本上偏离了正确概念：

1. **vein中的"Stuck point"**——我用了"卡点"语言，把AI的状态描述为"卡在n≡2(mod 4)这个case"
2. **hint的设计**——我设计的hint是"帮AI突破卡点"（"switch to local representation"），而不是"让AI走它没走的路"
3. **对照实验的评估**——我只看"AI是否SUCCESS"，没有看"AI走了哪条路、没走哪些路"

### 正确的实验设计应该是

- 先让bare AI跑，观察它的完整thinking
- 从thinking中识别"AI可能应该展开但没展开的方向"——不是"AI卡在哪里"，而是"AI走了A路，但B路、C路也可能值得走"
- hint不是"帮AI突破卡点"，而是"提醒AI考虑B路或C路"
- 评估不是"AI是否SUCCESS"，而是"AI是否走了它原本没走的路"

## 与推导树POC的对比

推导树POC（POC-VMS-2 + POC-VMS-8）的核心循环：

```
引导树（给方向Q）→ 推理AI（探索）→ 解题树（记录结果）
                                    ↓
                              在终点节点检索
                                    ↓
                              引导树（新边=新方向Q）→ 启动新推理AI → ...
```

"在终点节点检索"——终点节点不一定是"卡点"，而是AI的thinking中任何可以分叉的位置。

POC-VMS-8的tree组实验验证了这个概念：
- **1843**：AI不是"卡住了"——AI选了多项式符号分析这条路走下去，走不通才停。系统识别的不是"AI卡在多项式符号分析"，而是"AI没考虑模4分组这条分叉"。
- **1631**：AI不是"卡住了"——AI选了covering system这条路走下去。系统识别的不是"AI卡在covering system"，而是"AI没考虑二次剩余这条分叉"。
- **1962**：AI不是"卡住了"——AI选了2-adic赋值的某种展开方式走下去。系统识别的不是"AI卡在计算复杂性"，而是"AI没考虑分case简化这条分叉"。

**所有三个案例都是"走错路"而非"卡住"**。我之前的理解是错误的——我把"走错路然后走不通了"理解成了"卡住"。

---

## 引导树的本质

引导树不是"帮AI突破卡点的工具"。

引导树是"在AI没走的路上开新分支的工具"。

- 每个AI的thinking中都有很多可以分叉但没分叉的位置
- 每个这样的位置都是引导树的一个潜在新边
- 系统在这些位置上检索方向、启动新AI、让树继续生长

---

## 开放问题

1. **如何识别"可以分叉但没分叉的位置"？** 这比识别"卡点"更难——卡点是显性的（AI停了/重复了），分叉位置是隐性的（AI走过了但本可以拐弯）。

2. **是否所有分叉位置都值得开新分支？** AI的thinking中可能有几十个可以分叉但没分叉的位置，不可能全部开新分支。如何筛选？

3. **"走错路"和"卡住"是否是两种不同的情况？** 有些时候AI确实卡住了（到了某个点真的无法继续），有些时候AI走错路了（选了错误方向走下去）。这两种情况的识别和hint是否不同？

4. **"可能应该展开"中的"可能"如何量化？** 系统识别的是可能性不是确定性——如何判断一个方向"可能"应该展开？什么标准？
