## 一、模块功能概览

verification子系统负责验证数学命题、检测卡点、路由验证工具。

| 模块 | 功能 |
|---|---|
| verifier | Verifier角色，输出6种验证状态（非布尔值），按证据类型优先级确定验证等级 |
| stall_detector | 检测7种卡点类型，基于工具证据和结构进展（非自报），区分真停滞和假性停滞 |
| verification_router | 命题级验证路由，4种路由规则，按验证等级分层路由 |
| capability_registry | 工具能力注册（Lean 4/SymPy/SageMath/NumPy/SciPy），定义职责边界 |

## 二、审计检查项

### 2.1 验证状态正确性（verifier.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 6种状态 | proven/formally_verified/computationally_supported/numerically_tested/contradicted/unknown | 只返回这6种之一，不返回true/false |
| 证据优先级 | formal_proof > symbolic > numerical > human_audit | 按优先级确定验证等级 |
| 只考虑active证据 | 非active状态的证据不参与验证 | 过期/撤回的证据被忽略 |
| 反驳优先 | 有反驳证据时返回contradicted | 存在polarity=refute的active证据时output=contradicted |
| 不决定研究方向 | Verifier不决定下一研究路线 | 只输出验证状态，不输出"下一步应该..." |
| 派生认识状态 | 无决定性/仅支持/仅反驳/支持与反驳并存 | 4种派生状态计算正确 |

**判定**：通过=6项全通过；有缺陷=状态正确但优先级有小问题；失败=返回了布尔值或决定了研究方向或反驳证据被忽略

### 2.2 卡点检测准确性（stall_detector.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 7种卡点类型 | 必要探索/语义重复/矛盾未处理/工具阻塞/表示不合适/策略耗尽/预算耗尽 | 检测结果必须是这7种之一 |
| 基于工具证据 | 不只相信自报，基于工具证据和结构进展 | self_reported_stall只是输入之一，不单独决定 |
| 假性停滞区分 | 必要探索（假性停滞）不应提示，应继续观察 | necessary_exploration类型不触发hint |
| 预算耗尽停止 | 预算耗尽时停止而非提示 | budget_exhausted类型action=stop不是inject_hint |
| 精度度量 | precision/recall/误触发时间/误判比例 | 4个度量指标都计算 |
| 校准集 | 有人工标注校准集 | 校准集存在且用于计算precision/recall |

**判定**：通过=6项全通过；有缺陷=7种类型正确但精度度量缺失；失败=只相信自报或假性停滞触发hint或预算耗尽触发hint

### 2.3 验证路由正确性（verification_router.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 预期等级必须指定 | expected_level不能为空 | 路由时必须指定预期验证等级 |
| 4种路由 | formal_proof→Lean 4, symbolic→SymPy/SageMath, numerical→NumPy/SciPy, mixed→分层路由 | 路由到正确的工具 |
| 分层路由 | 混合型按numerically_tested→computationally_supported→formally_verified分层 | 按等级从低到高分层 |
| Verifier约束验证 | 路由器验证Verifier输出6种状态、不返回布尔值、不决定研究方向 | 路由器对Verifier有约束检查 |
| 覆盖域声明 | Verifier覆盖域必须声明 | 不能验证覆盖域外的命题 |

**判定**：通过=5项全通过；有缺陷=路由正确但覆盖域未声明；失败=预期等级为空或路由到错误工具

### 2.4 工具能力注册（capability_registry.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 三类工具 | formal(Lean 4/MathLib) / symbolic(SageMath/SymPy) / numerical(NumPy/SciPy) | 三类都注册 |
| NumPy和SciPy都注册 | 不能只注册一个 | 两个都存在 |
| 工具输出不直接进V_t | 工具输出标注为"工具证据"，必须经Verifier确认 | 工具输出不能直接写入V_t |
| Lean 4只验证局部引理 | 不尝试验证整个大定理 | Lean 4的职责边界是局部引理 |
| 预留扩展接口 | "其他领域专用工具"的注册接口 | 接口存在且可用 |
| 能力定义完整 | tool_name/category/responsibilities/input_format/output_format/verification_level | 6个字段都填充 |

**判定**：通过=6项全通过；有缺陷=工具注册但不完整；失败=工具输出直接进V_t或Lean 4验证整个大定理

## 五、已细化项

1. **6种验证状态边界**：PROVEN, FORMALLY_VERIFIED, COMPUTATIONALLY_SUPPORTED, NUMERICALLY_TESTED, CONTRADICTED, UNKNOWN（verifier.py:28-33）。computationally_supported=符号计算支持，numerically_tested=数值验证
2. **precision/recall阈值**：代码中未明确定义阈值
3. **校准集构建方法**：StallAnnotationStore.insert_annotation()和get_annotations_for_run()（stall_detector.py:301-323）
4. **mixed类型分层路由**：_route_by_level()按expected_level分层——numerically_tested→NumPy/SciPy, computationally_supported→SymPy/SageMath, formally_verified→Lean 4（verification_router.py:122-136）
5. **Lean 4实际可行性**：local_boundary="只验证局部引理，不尝试验证整个大定理"，installed=False（需要单独安装）（capability_registry.py:125-139）
6. **GuidedLoop与Verifier连接**：目前GuidedLoop未调用Verifier，需后续集成
