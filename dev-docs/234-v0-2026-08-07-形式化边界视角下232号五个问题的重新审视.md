## 0. 本文档的定位

233号建立了"形式化边界推进"的思想武器：AI数学工程的深层本质是形式化边界的持续推进——AI从边界以外感知"不自然"，压缩成可检查目标，经典计算在边界以内验证，结果回写数据基座，边界向前推进一步。

本文档用这个思想武器重新审视232号对231号提出的五个问题。结论是：五个问题全部可以应对——不是被回避，而是被重新定位，每个问题在形式化边界视角下都有了对应的解法。

## 1. 问题1重审：抽取成本被低估→抽取就是闭环本身

### 1.1 232号的担忧

231号说数据基座需要从数学语料中抽取数学工程单元（九类内容）。232号指出：抽取成本非常高——需要理解解答的每一步、识别语义移动类型、编译证书目标、建立依赖图、找反例边界、沉淀模式模板。谁来做？AI做可能错，人做不可规模化。

### 1.2 形式化边界视角下的重新定位

抽取就是把边界以外的东西拉到边界以内。这**本身就是闭环的一次运行**。

231号把抽取和求解看成两个独立任务（"双任务"），232号继承了这个框架并担忧抽取成本。但在233号视角下：

- **求解闭环**：AI感知"不自然"→压缩成可检查目标→经典计算验证→结果回写数据基座
- **抽取**：把一道题的解答分解成处境、语义移动、证书目标、依赖关系等

这两个**是同一个过程**。求解过程自然产生数据基座条目——每一步语义移动都被记录，每一个证书目标都被编译，每一个验证结果都被回写。不需要单独做抽取。

### 1.3 修正

231号的"双任务"框架（求解+抽取）应该改为**单任务双产出**：跑一次闭环，同时产出（a）问题的解和（b）数据基座条目。不是跑两次做两件事，是跑一次得到两样东西。

这消除了232号的担忧——不是"谁来抽取"的问题，而是"闭环运行时自动抽取"的问题。抽取成本不是额外的，是闭环运行的副产品。

### 1.4 但有一个残留问题

如果抽取是闭环的副产品，那**第一次跑一道新题时**，数据基座里还没有这道题的条目——AI没有可参考的相似处境。这时AI只能靠自己的黑盒能力（训练路径的产物）做感知。

这意味着：**第一轮闭环主要依赖AI黑盒能力，后续轮次才能利用数据基座**。数据基座是逐渐积累的，不是一开始就有的。这不是问题——它只是说明数据基座的增长是渐进的，从第一轮闭环开始每一次运行都在增加条目。

## 2. 问题2重审：远期愿景放在了近景→边界推进的正反馈

### 2.1 232号的担忧

231号说"数据基座可以反过来生成更干净的训练数据、评测数据和微调数据"。232号指出这是远期愿景，需要数据基座积累到足够规模才有意义，但231号把它放在和"可执行""可反驳"并列的位置。

### 2.2 形式化边界视角下的重新定位

数据基座生成训练数据，是**边界推进的长期正反馈效应**。

短期：闭环推进边界 → 数据基座增长（已征服领土扩大）
长期：数据基座足够大 → 反过来增强AI的边界以外感知 → AI能感知更远的"不自然" → 闭环推进更远的边界

这是形式化边界推进的**正反馈循环**：
```
闭环运行 → 边界推进 → 数据基座增长 → AI感知增强 → 闭环能处理更难的问题 → ...
```

### 2.3 修正

231号的错误不是内容（正反馈确实存在），而是**时间标注**。应该明确区分：

- **短期可实现**（第一轮闭环就能验证）：数据基座支持运行时闭环——提供相似处境、证书模板、失败边界
- **中期效应**（数据基座积累到一定规模）：跨问题的模式迁移——一个问题发现的模式能帮助另一个问题
- **长期正反馈**（数据基座积累到足够规模）：数据基座反过来生成训练数据，增强AI的边界以外感知

231号把三者混在一起，让人误以为都是短期可实现的。修正后三者分清楚。

## 3. 问题3重审：九类内容缺结构关系→按边界位置组织

### 3.1 232号的担忧

231号列了九类抽取内容（处境、表示变换、语义移动、证书目标、经典任务、依赖图、反例边界、模式模板、自然性测试）。232号指出它们之间缺结构关系——哪些是基础的，哪些是派生的？

### 3.2 形式化边界视角下的重新定位

九类内容可以按**与形式化边界的关系**来组织，而不是基础/派生：

**边界以内的（已形式化的产物）**：
- 证书目标——被压缩成可检查声明的对象
- 证书结果——经典计算验证后的产物
- 依赖关系——证书之间的审计链
- 经典任务——边界以内的操作指令

**跨越边界的（从感知到形式化的过程）**：
- 语义移动——AI从边界以外感知后做出的操作
- 表示变换——改变处境的表示，让结构更清晰

**边界标记（处境的当前状态）**：
- 处境描述——当前问题在边界上的位置
- 表示图册——当前可用的局部视角集合

**边界以外的感知沉淀**：
- 模式模板——成功的边界跨越路径的可复用记录
- 自然性测试——方法在表示变换下是否保持意义的检查
- 反例边界——哪些方向被证明不可行的记录

### 3.3 修正

这比232号的"基础层/派生层"更精确。它给出的不是"哪些派生哪些"，而是"哪些在边界的哪个位置"。

结构关系也清楚了：
- 边界标记（处境/图册）是起点——描述当前在边界上的位置
- 跨越边界（语义移动/表示变换）是过程——从边界以外到边界以内
- 边界以内（证书目标/结果/依赖/经典任务）是产物——跨越后的成果
- 边界以外的感知沉淀（模式模板/自然性测试/反例边界）是经验——记录哪些跨越成功、哪些失败

这形成了一个**时间结构**：起点→过程→产物→经验→下一轮的起点。九类内容不是并列的清单，是闭环一个周期的四个阶段。

## 4. 问题4重审："不是RAG"工程上模糊→基于边界推进路径的相似性

### 4.1 232号的担忧

231号说数据基座不是RAG——RAG找相似文本，数据基座找相似处境。但232号指出"找相似处境"在工程上怎么实现没说清楚——向量检索？图查询？混合？

### 4.2 形式化边界视角下的重新定位

数据基座的检索不是找相似文本，是找**相似的边界推进路径**。

两个处境在数据基座中"相似"不是表面词汇相似，而是它们在边界推进过程中的位置相似：
- 面临相似的"不自然"
- 需要相似的跨越（相似的语义移动类型）
- 产生相似的证书目标
- 遇到相似的obstruction

### 4.3 工程实现

记录每个数学工程单元的**边界跨越路径**：
```
Path = (初始处境, 感知到的"不自然", 语义移动, 证书目标, 验证结果, obstruction)
```

检索时匹配路径相似度——不是embedding相似度，是**路径结构相似度**：
- 初始处境的结构是否相似（都是矩约束？都有极值目标？）
- 感知到的"不自然"是否同类（都是虚假自由度？都是隐藏乘积？）
- 语义移动是否同类（都是中心化？都是对偶化？）
- 证书目标是否同类（都是多项式非负？都是恒等式？）

这比向量检索精确，但需要一种新的相似性度量——**基于边界推进过程的相似性**。

### 4.4 修正

231号说"不是RAG"但没说怎么实现。233号视角下：检索的基本单位是**边界跨越路径**，相似性度量是**路径结构相似度**。这不是RAG的embedding相似度，是"边界跨越路径"的相似度。

工程实现可以是：
1. 第一阶段：用结构化字段匹配（处境类型+移动类型+证书类型）做粗筛
2. 第二阶段：用图查询在依赖图中找连通路径做精化
3. 第三阶段（可选）：用向量检索在剩余候选中做排序

这是混合检索，但核心是结构化字段匹配，不是向量检索。数据基座"不是RAG"的区分在工程上变清楚了——RAG的core是向量检索，数据基座的core是路径结构匹配。

## 5. 问题5重审：与226/227数学结构脱节→两者都是形式化边界的描述

### 5.1 232号的担忧

231号几乎不讨论226/227的数学结构（Σ/C/图册/obstruction/自然性）。232号做了对应表（数学工程单元字段↔数学结构），但只是工程概念和数学概念的对应，没有深层理由。

### 5.2 形式化边界视角下的重新定位

数学结构（226/227）和数据基座（231号）**都是形式化边界的描述**，只是一个用数学语言，一个用工程语言。

| 数学结构（226/227） | 数据基座字段（231号） | 形式化边界的位置 |
|---|---|---|
| Σ（语义场） | 处境描述+表示图册 | 边界两侧的处境空间 |
| Σ的态射 | 语义移动 | 跨越边界的过程 |
| C（证书偏序） | 证书目标+证书结果+依赖关系 | 边界以内的已征服领土 |
| 图册（Grothendieck拓扑） | 表示图册 | 边界上的局部视角 |
| obstruction | 反例边界+失败边界 | 边界跨越的障碍 |
| 自然性（交换图） | 自然性测试+模式模板 | 边界跨越的条件 |

### 5.3 深层理由

这不是偶然的对应——两者都是对**同一个东西**（形式化边界推进过程）的描述：

- 数学结构描述的是**边界推进的抽象结构**——Σ是处境空间，C是已征服领土，自然性是跨越条件，obstruction是跨越障碍
- 数据基座描述的是**边界推进的具体记录**——每个数学工程单元是一次边界推进的完整记录

抽象结构和具体记录描述同一件事，所以字段一一对应。这不是"工程概念碰巧对应数学概念"，而是"两者本来就是同一件事的两个面"。

### 5.4 修正

232号的对应表是对的，但缺少深层理由。233号给了深层理由：两者都是形式化边界的描述。这统一了226/227的数学化努力和231号的工程化努力——不是两套语言描述两件事，是两套语言描述同一件事。
