# 25道难题挑战类型分析方案

**文档编号**：258-v0
**日期**：2026-08-08
**状态**：方案设计
**关联**：213号方案（30道竞赛最难题baseline）+ 257号（POC-VMS进度追踪）+ 原语化论文07-验证/03（虚拟数学系统POC方案）

---

## 1. 目标

分析25道AI做不出但有解答的MathArena竞赛最难题，抽象出挑战类型，为POC-VMS-0的虚拟挑战构造提供模板。

这是POC-VMS"真实难题驱动的虚拟验证"方法论的第一步——**挑战抽象**。

## 2. 输入资源

### 25道难题

| 类型 | 数量 | 来源 | 解答形式 |
|---|---|---|---|
| 数值题 | 23 | AIME 2024-2026 / BRUMO / HMMT / SMT / CMIMC / APEX | 数值答案 |
| 证明题 | 2 | USAMO 2026 P4/P5 | sample_solution |

详见 `runs/matharena_25_hard_problems.json`

### AI baseline数据

每道题有GLM-5.2的完整response（Phase 1b验证，修复截断后），分布在 `runs/matharena_phase1b_*/` 的conversation.json中。

### 正确解答

- 23道数值题：有expected_answer（数值）
- 2道证明题：有sample_solution（完整证明）
- 部分题有grading_scheme（评分标准，含checkpoint）

## 3. 三步分析流程

### 第1步：提取25道题的AI response原文

从 `runs/matharena_phase1b_*/` 的conversation.json中提取每道题的AI完整response。

目前solutions.json只有response_preview（前23字符），不够分析。需要完整的AI输出才能判断AI为什么做不出。

**产出**：25道题的完整AI response文本

### 第2步：逐题分析"AI为什么做不出"

对每道题，对照三个东西：
- **题目**：要求什么
- **正确答案/解答**：正确路径是什么
- **AI的response**：AI尝试了什么、在哪里卡住/走错

**分析维度**：

| 维度 | 问题 | 判断方法 |
|---|---|---|
| 领域识别 | AI是否识别了正确的数学领域？ | 对比AI使用的方法和正确解法使用的方法 |
| 定理/技巧知识 | AI是否知道正确的定理/技巧？ | 检查AI response中是否提到正确解法的关键定理 |
| 定理/技巧应用 | AI是否知道但不会用？ | 检查AI是否提到定理但应用错误 |
| 思路方向 | AI是否有思路但方向错误？ | 对比AI的思路和正确解法的思路 |
| 计算/推理 | AI是否有思路但计算出错？ | 检查AI的推理链中哪里出错 |
| 卡点位置 | AI在哪里停下来？ | 检查AI response的结尾——是放弃了还是卡在某步 |

### 第3步：抽象挑战类型

把25道题的个体分析归类，抽象出若干**挑战类型**。

**可能的挑战类型**（待验证）：

| 挑战类型 | 描述 | 典型例子（待确认） |
|---|---|---|
| 跨概念推理跳跃 | AI知道A和B但不知道A→B的路径 | 矩条件极差题Q8：知道稳定性方程和badly approximable但不知道怎么连接 |
| 需要非显然构造 | AI知道所有相关定理但不会构造关键辅助对象 | 待分析 |
| 多约束联合 | AI能处理单个约束但不会联合多个约束 | 待分析 |
| 领域识别错误 | AI用错了数学领域的方法 | 待分析 |
| 计算复杂度 | AI知道方法但计算太复杂无法完成 | 待分析 |
| 证明结构缺失 | AI有思路但不会组织证明结构 | 待分析 |

这些挑战类型就是虚拟群论要构造的同类挑战的模板。

## 4. 对数学能力的诚实声明

第2步的逐题分析需要理解每道题的数学内容和正确解法。25道题中有些我可能不熟悉（如SMT #51 diff=164）。

**遇到我不懂的题时的处理**：
- 读sample_solution/正确答案
- 分析AI response的失败模式（不需要完全理解正确解法，也能判断AI在哪里走错）
- 标注"需要数学专家复核"

**不会做的事**：
- 不会假装理解我不懂的解法
- 不会编造AI失败的原因
- 对于无法判断挑战类型的题，标注"待定"

## 8. 开放问题

1. **分析粒度**：每道题分析到什么程度？只判断挑战类型，还是详细分析AI的推理链？
2. **数学正确性**：我的分析是否需要数学专家复核？如果需要，哪些题最需要？
3. **挑战类型的数量**：最终会抽象出几个挑战类型？太少（如3个）可能不够指导虚拟构造，太多（如15个）可能过度拟合25道题。
4. **虚拟群论的可构造性**：抽象出的挑战类型是否都能在虚拟群论中构造？有些挑战类型（如"领域识别错误"）可能在虚拟群论中不存在——因为虚拟群论只有一个领域。
