## 一、目的与适用场景

**解决的问题**：命主出生时间存疑或缺失（如"大约凌晨3点"、"只知道是上午"），需要根据已知人生事件反推精确出生时间（UT）。

**适用场景**：
- 出生时间窗口 ±N 小时，需收窄到分钟级
- 完全缺失出生时间，仅有日期，需用多个事件锚定
- 已有近似时间，需验证是否正确

**不适用场景**：
- 出生时间已精确到分钟且无疑问 → 直接 `build_chart()` 排盘，无需矫正
- 日期存疑（不知哪天）→ 需先用日期级反推，本工具以时间窗口内反推为主

## 二、算法原理

### 2.1 核心思想

七政四余星盘中，每颗行星在黄道上的位置是时间的单调（或近单调）函数。已知某事件发生时某颗行星"应该"在某个黄经度数，即可反推该时刻的 UT 时间。

**单点反推**：一个事件 → 一个目标黄经 → 一个反推 UT
**多点反推**：多个事件 → 多个目标黄经 → 多个反推 UT → 一致性检验 → 取中位数

### 2.2 反推函数

| 函数 | 位置 | 用途 |
|---|---|---|
| `core.find_date_at_sun_pos(target_degree, start_jd)` | <ref_snippet file="~/MOIRA_chinese_astrology-main/qizheng/core.py" lines="375-380" /> | 太阳黄经反推（用 swe.solcross_ut） |
| `core.find_date_at_planet_pos(planet_id, target_degree, start_jd)` | <ref_snippet file="~/MOIRA_chinese_astrology-main/qizheng/core.py" lines="380-385" /> | 其他行星反推（迭代求解） |
| 紫炁特例 | rectify.py L36-39 | 紫炁是匀速线性运动，直接公式：`jd = base_jd + (deg - base_lon)/speed` |

### 2.3 一致性评分

多点反推后，多个 JD 的标准差和极差（转成小时）越小越一致。评分 0-100：
- 0 小时差 = 100 分
- 24 小时差 = 0 分
- 公式：`(score_stdev + score_range) / 2`，其中 `score = max(0, 100 - hours*100/24)`

源码：<ref_snippet file="~/MOIRA_chinese_astrology-main/qizheng/core.py" lines="3180-3207" />

### 2.4 矫正结果取值

多点反推取所有有效 JD 的**中位数**作为矫正结果（抗异常值）。源码：<ref_snippet file="~/MOIRA_chinese_astrology-main/qizheng/core.py" lines="3243-3248" />

## 三、输入/输出契约

### 3.1 单点反推（rectify.py CLI）

**输入**：
```bash
.venv/bin/python3 -m qizheng.rectify \
  --year 1990 --month 5 --day 15 --hour 3.5 \
  --target '{"sun":54.0}'
```
- `--hour`：初始 UT 小数（搜索起点）
- `--target`：JSON，`{行星名: 目标黄经度数}`，行星名见 `core.BODIES`（sun/moon/mercury/venus/mars/jupiter/saturn/rahu/ketu/ziqi）

**输出**（真实示例）：
```json
{
  "input": {"start": "1990-05-15T03.5000", "jd": 2448026.6458, "target": {"sun": 54.0}},
  "results": {
    "sun": {"jd": 2448026.5892, "date_ut": "1990-05-15T02.1413", "delta_hours": -1.3587}
  }
}
```

### 3.2 多点反推（core.rectify_multi_point）

**签名**：`rectify_multi_point(targets, start_jd, ephe_path="ephe")`
- `targets`: `{"sun": 54.0, "moon": 200.0, "jupiter": 120.0}`
- `start_jd`: 搜索起始 JD

**返回**：
```json
{
  "results": {"sun": {"jd":..., "date_ut":..., "delta_hours":...}, ...},
  "consistency_score": {"score": 87.5, "stdev_hours": 1.2, "range_hours": 3.0, "mean_jd": ...},
  "jd_count": 3
}
```
源码：<ref_snippet file="~/MOIRA_chinese_astrology-main/qizheng/core.py" lines="3136-3177" />

### 3.3 完整迭代矫正（core.iterative_rectify）

**签名**：`iterative_rectify(birth_info, life_events, ephe_path="ephe")`
- `birth_info`: `{"year":1990, "month":5, "day":15, "hour":3.5, "lon":116.4, "lat":39.9}`
- `life_events`: `[{"year":2015, "event_type":"结婚", "description":"...", "target_planet":"moon", "target_degree":200.0}, ...]`

**返回**：
```json
{
  "original_ut": "1990-05-15T03.5000",
  "corrected_ut": "1990-05-15T02.1234",
  "corrected_jd": 2448026.5883,
  "delta_hours": -1.3766,
  "method": "multi_point_median",
  "targets": {...},
  "results": {...},
  "consistency": {"score": 87.5, ...},
  "history": [{"step":1, "action":"multi_point_rectify", ...}]
}
```

### 步骤 3 · AI 事件-星象映射（AI 智能层，非代码）

对每个事件，AI 判断对应哪个星象变化，给出 `{target_planet, target_degree}`：

| 事件类型 | 推荐锚定星曜 | 推断逻辑 |
|---|---|---|
| 婚姻/感情 | 月亮 / 金星 | 月亮过宫、7宫（妻妾）激活 |
| 事业突破 | 木星 / 太阳 | 木星过宫、10宫（官禄）激活 |
| 健康危机 | 火星 / 土星 / 罗睺 | 冲照6宫（疾厄）/8宫 |
| 生育 | 木星 / 月亮 | 5宫（男女）激活 |
| 父母变动 | 太阳 / 土星 | 4宫（田宅）/10宫 |
| 学业/考试 | 水星 / 文昌 | 科甲星激活 |

**关键**：target_degree 是 AI 根据事件性质推断的"该事件发生时该星曜应在的黄经度数"。这是 AI 智能层的核心判断，代码不替你做。

### 步骤 4 · 多点反推

**方式 A · 调用封装函数（推荐）**：
```python
from qizheng import core
core.init_ephe("ephe")
start_jd = core.jd_from_ymd_ut(1990, 5, 15, 3.5)
result = core.rectify_multi_point(
    {"moon": 200.0, "jupiter": 120.0, "sun": 54.0},
    start_jd
)
```

**方式 B · 一键完整 SOP**：
```python
result = core.iterative_rectify(
    birth_info={"year":1990,"month":5,"day":15,"hour":3.5,"lon":116.4,"lat":39.9},
    life_events=[
        {"year":2015,"event_type":"结婚","description":"...",
         "target_planet":"moon","target_degree":200.0},
        {"year":2018,"event_type":"生育","description":"...",
         "target_planet":"jupiter","target_degree":120.0},
```

### 步骤 5 · 一致性检验

查看 `result["consistency_score"]["score"]`：
- **≥ 80**：高度一致，矫正结果可信
- **60-80**：基本一致，可结合 AI 判断取舍
- **< 60**：不一致，需回到步骤 3 调整事件-星象映射假设，重新迭代

## 七、已知陷阱（必须避免）

1. **紫炁是线性运动**：不能用 `find_date_at_planet_pos`，必须用公式 `jd = base_jd + (deg - base_lon)/speed`。rectify.py 已特判（L36-39），自定义调用时注意。
2. **罗睺 true_as_north 开关**：罗睺有新法（真黄北极）/旧法（平均交点）两种模式，反推前确认 `core.set_four_yu_mode()` 设置一致。
3. **target_degree 是 AI 推断值**：不是事件"客观对应"的度数，是 AI 根据命理判断的假设值。推断错误会导致反推结果全错。一致性评分低时优先怀疑映射假设。
4. **搜索起点影响结果**：`find_date_at_*` 从 start_jd 附近搜索，若真实时间离起点很远（跨日/跨月），可能搜到错误的周期解。建议时间窗口 > 12 小时时分多段搜索。
5. **UT vs 地方时**：所有输入输出都是 UT，不是地方时。命主给的是北京时间需先减 8 小时。
6. **节气分年月 vs 农历分年月**：矫正后重新排盘时，四柱计算模式（`use_solar_terms`）需与原排盘保持一致。
