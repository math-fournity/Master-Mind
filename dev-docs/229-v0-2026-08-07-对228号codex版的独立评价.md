## 1. 228-codex做对了什么

### 1.1 把讨论从"用什么数学语言"拉回到"路线为什么更强"

226/227都在讨论Σ是不是site、V/R是不是lax adjunction、obstruction是不是H¹。228-codex问了一个更根本的问题：**这条路线到底比单纯AI多了什么能力？**

这个视角的切换是有价值的。226/227在数学化的细节里越陷越深，忘了回答"为什么"。如果这个问题回答不了，再精致的数学化也只是文档游戏。

### 1.2 十种能力的列举是具体的、可验证的

可靠性边界、反例生产、结构显影、搜索空间裁剪、局部证书积累、形式化压力、依赖审计、粘合检查、可回放性、模式库真实增长——这十个不是抽象口号，每一个都有具体的经典计算对应物（SymPy因式分解、Z3求解、Lean验证、SAT枚举等）。

### 1.3 "执行契约"是一个好的工程概念

每次AI动作必须说明四件事：
- 我在改变什么处境？
- 我预期降低什么困难？
- 我能把它编译成什么经典计算任务？
- 经典计算返回后，我准备如何更新语义场？

这比抽象结构更底层——它直接区分了"真正的工程闭环"和"只是写了一段数学解释"。

### 1.4 对照实验的提议是对的

不能只靠哲学判断说"这条路更强"。同一批问题，两条路线跑，比较可验证局部证书数、反例数、排除死路数、可回放结论数。这是实证验证。

## 2. 228-codex的问题

### 2.1 几乎完全放弃了数学化

228-codex说"不要再先写更高阶的抽象框架"。这在方法论上和227一致（先跑例子）。但它走得更远——它几乎不讨论226/227的任何数学结构。

这既是优点（不被绑架）也是缺点：**如果完全不数学化，十种能力和执行契约就只是工程清单，没有数学骨架**。225-227的数学化努力（自然性、图册、obstruction）在这个228号里完全消失了。

### 2.2 十种能力是列举但不是结构

十种能力之间有什么关系？哪些是基础的，哪些是派生的？

例如：
- "反例生产"和"搜索空间裁剪"——反例生产是不是搜索空间裁剪的一种？
- "结构显影"和"局部证书积累"——结构显影产生的结构是不是自动成为局部证书？

文档没有说。列举十种让人感觉很丰富，但没有结构关系就没有预测力——不能预测第十一种能力是什么，也不能预测哪些能力是冗余的。

### 2.3 "执行契约"可能太工程化

执行契约把每次AI动作变成四字段表格。这在工程上清晰，但可能丢失了数学思考的流动性——数学家经常不知道"预期降低什么困难"，他们是探索性的移动，不是目标导向的移动。

**矩条件极差题的例子**：AI中心化（b=a-1）时，它可能不知道这会"降低什么困难"——它只是感觉"一阶矩应该消掉"。强制它填写"预期降低什么困难"可能迫使它编造一个事后解释。

### 2.4 对照实验缺少控制变量设计

文档说"同一批问题，两条路线跑"，但没有说：
- 两条路线的AI部分是否用同一个模型？同样的prompt？同样的温度？
- 单纯AI路线是否允许AI用Python计算？如果允许，它已经在用经典计算了；如果不允许，对比不公平。
- "可验证局部证书数"怎么定义？AI自然语言写的证明算不算局部证书？

### 2.5 与226/227的关系不清

228-codex说"227是必要修正但还不够"——但它没有具体说227哪里不够。它只说227"还没有充分回答路线为什么值得走"。但227的目标不是回答这个问题——227的目标是修正226-v1的数学化路线。批评227没有做它没打算做的事，不太公平。

## 4. 理想的做法：两者结合

用228-codex的"执行契约"和"对照实验"作为工程骨架，用228-glm5.2的"接受227三个修正"作为数学基础。

跑矩条件极差题时：
1. 每次AI动作填执行契约（228-codex的工程骨架）
2. 经典计算结果回流，记录到证书账本（228-codex的闭环）
3. 同时记录哪些226/227的数学结构自然出现了（228-glm5.2的数学基础）
4. 不预设任何骨架，让结构从例子中浮现（226-v0的方法论）

### 4.1 具体执行方案

**矩条件极差题的闭环跑法**：

第一步：AI提出语义移动（如"中心化b=a-1"）
- 填执行契约：改变什么处境（消掉一阶矩）、预期降低什么困难（简化矩条件）、编译成什么计算任务（验证中心化保持极差）、返回后如何更新（如果保持，加入证书；如果不保持，换策略）

第二步：经典计算执行（SymPy验证中心化保持极差）

第三步：结果回流
- 成功→证书加入账本（正向证书：中心化是极差保持的表示变换）
- 失败→诊断反馈（如果不保持，为什么？）

第四步：AI基于账本更新
- 账本中有"中心化保持极差"→AI可以放心使用中心化表示
- 继续下一步语义移动

第五步：重复，直到证明完成

第六步：记录过程中自然出现的数学结构
- 中心化是表示变换吗？（226-v1第1点）
- "中心化保持极差"是证书吗？（226-v1第2点 + 227的证书字段化）
- 中心化在不同表示间交换吗？（226-v1第3点自然性）
- 多个表示能粘合吗？（226-v1第5点图册）
- 粘合失败时障碍是什么？（226-v1第6点 + 227的obstruction层级）

### 4.2 这个方案的优势

- 工程上可执行（执行契约是具体的）
- 数学上不放弃（记录结构是否自然出现）
- 不预设骨架（让结构从例子中浮现）
- 可对照（和单纯AI跑同一题比较）

## 5. 对228-codex的最终判断

### 5.1 价值

228-codex在"为什么走这条路"上比228-glm5.2好——它回答了228-glm5.2没回答的问题。十种能力的列举和执行契约的概念都是有价值的工程贡献。

### 5.2 不足

228-codex在"怎么数学化"上比228-glm5.2弱——它几乎放弃了数学化。十种能力是列举不是结构，执行契约可能太工程化，对照实验缺少控制变量设计。

### 5.3 整体判断

228-codex和228-glm5.2是互补的。理想的做法是两者结合：用228-codex的工程骨架（执行契约+对照实验）驱动跑例子，用228-glm5.2的数学基础（接受227三个修正）记录结构是否自然出现。
