## 一、工程目标

### 用户原始需求

把 `AGENTS.md` 中的大段内容外移到项目根目录的独立Markdown文件，在 `AGENTS.md` 中建立索引，声明什么时候应该加载哪个外部文档。

### 核心动机

`AGENTS.md` 原始大小320KB/4216行，远超devin cli的~15KB token限制。rules注入机制失效——系统提示"These rules were triggered but could not be injected due to token limits"，AI需要额外调用read工具读AGENTS.md，导致：
1. 每个 run 多 1-2 次 API 请求
2. prompt tokens 从 ~20K 涨到 42-75K
3. 高并发时同时 read → rate limit

### 用户硬性要求

**"不能压缩，必须改成外移"**——被压缩掉的细节内容必须外移到独立文件，不能只留指针。原始AGENTS.md的每一个字都必须在某个文件中保留。

## 五、设计原则

### 每个外移文件的文档头

```
# <文件名>.md — <标题>

> **加载时机**：<什么时候必须用read工具全文加载本文件>
> **AGENTS.md索引**：AGENTS.md "外部文档索引"节有指向本文件的索引行。

```

### AGENTS.md中的索引行

每个外移块在AGENTS.md原位置替换为索引行：

```
> **加载时机**：<什么时候必须用read工具全文加载该文件>。
```

AGENTS.md末尾的总目录，按"什么时候必须全文加载"组织所有外移文档：

```

| 文档 | 位置 | 什么时候必须全文加载 |
|---|---|---|
| ... | ... | ... |
```

### 精炼版+完整版的双层设计（仅Grove和规则指针两处）

对于Grove核心循环和"其他规则指针"两处：
- AGENTS.md中保留**精炼版**（核心认知/清单）
- 完整版外移到独立文件（`GroveCoreCognition.md`/`RulePointers.md`）
- 精炼版是完整版的子集，被压缩掉的细节在完整版中
- 精炼版中加索引行指向完整版

**这样设计的原因**：这两处内容是"最高认知优先级"和"规则指针"，AI进入repo时需要快速看到核心认知（精炼版），但需要完整细节时可以加载完整版。其他外移块则是纯外移（AGENTS.md中只有索引行，没有精炼版）。

## 六、always-on → on-demand 的降级说明

### 设计意图

原来所有内容在AGENTS.md中（理论上）总是被AI看到。瘦身后变成"AI判断需要时才加载"。

### 降级风险

如果AI场景识别失误，不会去读对应外部文件，等于内容对那个session"丢失"了。

### 缓解措施

1. **★ 外部文档索引节**在AGENTS.md末尾，按工作类型组织，AI可以快速扫描找到需要加载的文件
2. **每个索引行包含加载时机声明**——明确写"什么时候必须全文加载"
3. **精炼版保留核心认知**——Grove和规则指针两处，即使AI不加载完整版，精炼版也保留了最核心的认知
4. **文档头包含加载时机**——AI用read加载文件时，文档头第一眼就看到这个文件什么时候该用

### 仍存在的风险

- AGENTS.md本身42KB，仍然接近token限制。如果devin cli的rules注入机制token限制是15KB，AGENTS.md还是会被截断——只是截断的是末尾的"外部文档索引"节，而不是原来的中间内容
- 如果截断发生在索引节，AI看不到索引，就不会知道有哪些外部文件可加载

### 后续建议

如果42KB仍然触发token限制，可以考虑：
1. 把"外部文档索引"节移到AGENTS.md最前面（硬约束区之前），确保总是可见
2. 进一步外移"本repo基本信息"中的硬约束5-6（已归档内容）和"工作原则"中的详细说明
3. 把"系统技术说明书系列"21行外移到 `SixthGenRnD.md`

## 十、给下一个AI的接手说明

### 你需要知道的

1. **AGENTS.md是精简主文件**——42KB，包含硬约束+核心认知+索引。不是完整内容，完整内容在外移文件中
2. **★ 外部文档索引节是总目录**——在AGENTS.md末尾，按工作类型组织所有外移文件。按当前工作类型找到需要加载的文件
3. **每个外移文件有文档头**——加载时第一眼看到来源/定位/加载时机
4. **Grove和规则指针有精炼版+完整版**——AGENTS.md中是精炼版，完整版在 `GroveCoreCognition.md` 和 `RulePointers.md`
5. **原始备份在 `.agents_backup/`**——如果怀疑内容丢失，diff原始备份对应行号

### 你不应该做的

1. **不要把外移文件的内容复制回AGENTS.md**——这会重新膨胀AGENTS.md
2. **不要压缩外移文件**——外移文件是完整内容，不是精炼版
3. **不要删除AGENTS.md中的索引行**——索引行是AI找到外移文件的唯一线索
4. **不要删除"外部文档索引"节**——这是总目录

### 如果你要继续瘦身

1. 先读 `dev-docs/392-v0-2026-08-19-AGENTS_md瘦身外移改造方案.md` 了解方案
2. 用同样模式：切分body→加文档头→创建外移文件→AGENTS.md原位置替换为索引行→diff验证→更新索引节
3. **绝对不能压缩**——被删除的细节必须外移到独立文件
