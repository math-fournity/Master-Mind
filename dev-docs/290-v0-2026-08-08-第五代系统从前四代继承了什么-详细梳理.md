## 从盘古（第一代·静态图前置）继承的内容

盘古的核心理念：Master预先知道路线→写静态依赖图G→经典计算忠实展开→AI按图重建答案。

### 继承1：拓扑覆盖验证的数学确定性

| | |
|---|---|
| **来源** | [78] G'_topo拓扑骨架 + AQL集合差集（POC-9验证通过，1次通过100%覆盖） |
| **在第五代中的位置** | Pipe 1形式化过滤的数学基础——拓扑相似/等价匹配不是模糊的语义相似，而是结构化的字段匹配，可以用AQL精确执行 |
| **作用** | Pipe 1的过滤逻辑继承盘古的AQL集合差集思路——用结构化字段（大概念：problem_type/ai_method_type/gap_type）做硬筛+软筛，而不是embedding相似度 |
| **第五代的超越** | 盘古的拓扑覆盖验证是静态的（Master预先知道路线），第五代是动态的（从AI的实际thinking中提取拓扑） |

### 继承2：meta/normal分离

| | |
|---|---|
| **来源** | [86] meta/normal分离原则（POC-9验证通过）——meta operation（拓扑规划/验证/审计，纯数学不涉及领域知识）由不同AI实例完成，normal operation（转译/分析，需要领域知识）由另一个AI实例完成 |
| **在第五代中的位置** | 辅助智能体（系统Pipe）与推理智能体（Solver）的角色分离——辅助智能体做meta层面的事情（拓扑化、过滤、识别tell），推理智能体做normal层面的事情（数学推理） |
| **作用** | 辅助智能体不需要知道答案就能做tell识别——因为它做的是meta层面的拓扑匹配，不是normal层面的数学推理。这是知识悖论的工程解决方案 |
| **第五代的超越** | 盘古的meta/normal分离是静态的（meta AI预先规划拓扑），第五代是动态的（辅助智能体从推理AI的实际thinking中实时提取拓扑） |

### 继承3：确定性图遍历

| | |
|---|---|
| **来源** | [110] 三层访问架构——冷存储层（ArangoDB全部节点+边+原文）→热工作集（上下文200-800节点子图）→温查询层（按需展开） |
| **在第五代中的位置** | tell数据基座和hint字典的ArangoDB存储架构——10万级tell存储在ArangoDB中，Pipe 1用AQL查询快速检索，不需要全量加载 |
| **作用** | 解决规模问题——10万级tell不能全装入辅助AI上下文，用ArangoDB存储+AQL查询实现快速检索 |
| **第五代的超越** | 盘古的三层访问是为静态依赖图设计的，第五代是为动态tell检索设计的——但冷/热/温三层的架构思路完全继承 |

### 继承4：L1/L2/L3分层提取

| | |
|---|---|
| **来源** | [83] L1/L2/L3三层提取——L1解题思路（具体步骤，只在类似题中复用），L2数学思维（从L1抽象的思维模式，弥漫性跨题复用），L3范式思维（改变图结构本身，跨领域复用） |
| **在第五代中的位置** | tell和hint的Level分层——tell有大概念（L2级别，跨题泛化）和小概念（L1-L2之间，更细的区分），hint有高Level方向（L2-L3级别，跨领域泛化）和low level化方向（L1级别，领域特化） |
| **作用** | 提供Level分层的理论框架——第五代的"大概念→小概念→概念树"对应盘古的"L2思维模式→L1具体步骤"的分层思路 |
| **第五代的超越** | 盘古的L1/L2/L3是为静态依赖图的节点分类设计的，第五代是为动态tell的规模检索设计的——但分层提取的思路完全继承 |

## 从女娲（第二代·动态控制与角色隔离）继承的内容

女娲的核心理念：动态工作区W_t替代静态G，12步在线主链，8角色隔离矩阵。

### 继承5：外显思维图T

| | |
|---|---|
| **来源** | [122-v2] 外显思维图T——记录Agent实际思维轨迹，11种节点类型（observation/claim/representation/subgoal/candidate/test/tool_result/contradiction/stall/backtrack/resolution）+ 12种边类型（notice/infer/recall/transform/decompose/compare/test/reject/backtrack/generalize/analogize/ask_for_hint/activate） |
| **在第五代中的位置** | Pipe 0拓扑化的结构基础——将thinking编码为拓扑结构时，T图的节点/边类型是拓扑标注的候选维度。POC-VMS-9/10中用了3个维度（problem_type/ai_method_type/gap_type），但当tell数量增加时可以扩展到T图的11+12个维度 |
| **作用** | 提供thinking结构化的标准词汇表——T图定义了思维轨迹的可标注结构，这是Pipe 0拓扑化的形式化基础 |
| **第五代的超越** | 女娲的T图是设计但未实现（[122-v3]诚实诊断指出"旧系统实际没有实现T图"），第五代在POC-VMS-9/10中实现了简化版拓扑化（3个维度）并验证通过 |

### 继承6：动态工作区W_t六类分量

| | |
|---|---|
| **来源** | [123-v1] 动态工作区W_t=(V_t,F_t,O_t,R_t,D_t,E_t)——已验证核心/猜想前沿/开放研究义务/当前表示/被拒绝分支/证据 |
| **在第五代中的位置** | tell端"未探索诊断"的结构化框架——W_t的D_t（被拒绝分支）对应tell识别的"AI没走的路"，W_t的O_t（开放研究义务）对应"可以分叉但没分叉的位置" |
| **作用** | 提供状态感知的严格数学形式化——第六类分量是tell识别的结构化框架，特别是D_t（被拒绝分支）和O_t（开放义务）直接对应tell的核心概念 |
| **第五代的超越** | 女娲的W_t是为动态工作区设计的，第五代从中提取了D_t和O_t的概念用于tell识别，但不使用完整的六类分量——tell识别只需要"AI走了什么路、没走什么路"，不需要完整的工作区状态 |

### 继承7：8角色可见性矩阵+CapabilityToken

| | |
|---|---|
| **来源** | [127-v1] 8角色可见性矩阵（Solver/EventCapture/StateReducer/Retriever/HeuristicMatcher/Verifier/Auditor/Orchestrator）+ CapabilityToken机制（collection级访问控制+字段级访问控制+写入控制+运行隔离+自动失效） |
| **在第五代中的位置** | 辅助智能体与推理智能体的角色隔离机制——辅助智能体做tell识别时不能看到truth_vault（答案），只能看到推理AI的公开输出（thinking/trajectory） |
| **作用** | 解决知识悖论——辅助智能体不需要知道答案就能做tell识别，因为它只能看到推理AI的thinking，不能看到答案 |
| **第五代的超越** | 女娲的8角色矩阵是完整的设计但未在POC中验证，第五代简化为2角色（辅助智能体+推理智能体）并在POC-VMS-8/9/10中验证通过 |

### 继承8：启发激活图H与Hint梯度

| | |
|---|---|
| **来源** | [122-v2] 启发激活图H——P→X条件关系（看到模式P时激活X），Hint梯度（Hint-0元检查/Hint-1思维操作/Hint-2工具概念候选/Hint-3确定关系/Hint-4最终答案） |
| **在第五代中的位置** | hint端的Level梯度设计——281号的24个翻译方向是从高Level方向low level化而来，对应女娲的Hint-0到Hint-4梯度 |
| **作用** | 提供hint泄漏控制的框架——hint从高Level（不泄漏答案）到low level（可能泄漏答案）的梯度，第五代的"翻译方向"是Hint-1到Hint-2级别（思维操作+工具概念候选，不泄漏答案） |
| **第五代的超越** | 女娲的H图是设计但未实现，第五代在281号中实现了24个翻译方向的low level化并在POC-VMS-8中验证通过 |

### 继承9：7类卡点+4种洞

| | |
|---|---|
| **来源** | [188-v0] 7类卡点（策略耗尽/证据缺口/表示停滞/义务死锁/预算耗尽/假性停滞/答案泄漏风险）+ [123-v1] 4种洞（无验证接口/多路停滞/局部视图不一致/未知跨表示桥梁） |
| **在第五代中的位置** | tell端"分叉类型"的候选分类——7类卡点和4种洞是tell的粗粒度分类，可以作为Pipe 1形式化过滤的维度 |
| **作用** | 提供tell分类的已有资产——不需要从零定义tell的类型，7类卡点+4种洞已经是设计完成的分类 |
| **第五代的超越** | 女娲的7类卡点+4种洞是设计完成但未在POC中验证，第五代在POC-VMS-9/10中用了更简化的分类（method_problem_mismatch一种gap_type），但7类卡点+4种洞是未来扩展的方向 |

## 从燧人（第三代·非特定元认知提问）继承的内容

燧人的核心理念：非特定高Level元认知提问——钻木取火，不给火而教取火。

### 继承10：形状匹配是拓扑的

| | |
|---|---|
| **来源** | [214]第3章——系统关注"形状"——问题的结构特征（存在性/唯一性/极值）、解答的转折结构（正面→反面/构造→证明）、思维的拓扑（哪些模式经常一起出现/有依赖关系） |
| **在第五代中的位置** | Pipe 0拓扑化的理论基础——将thinking编码为拓扑结构，就是将thinking的"形状"提取出来。problem_type/ai_method_type/gap_type就是thinking的形状特征 |
| **作用** | 提供拓扑化的理论依据——"形状是拓扑的，不是文本内容"意味着Pipe 0应该提取结构特征，而不是做关键词匹配或RAG语义相似 |
| **第五代的超越** | 燧人的形状匹配是设计但未实现具体的形状表示和相似度计算方法，第五代在POC-VMS-9/10中实现了具体的拓扑化（3个维度+信号词频次）并验证通过 |

### 继承11：Level连续谱

| | |
|---|---|
| **来源** | [214]第2章——依赖图中每个元素带Level标签（0到1实数），Level是经验的、模糊的、相对的——AI能感受差异的模糊大小。Level不是被赋值的，而是被感知的 |
| **在第五代中的位置** | tell和hint的Level排序——tell有大概念（高Level）和小概念（低Level），hint有高Level方向和low level化方向。Pipe 1优先匹配高Level（大概念），Pipe 2用低Level（小概念）做细化分辨 |
| **作用** | 提供"先大概念后小概念"的理论依据——Level高的先匹配（大概念缩小范围），Level低的后匹配（小概念精准识别），这是Level SUM最大化的贪心策略在tell检索中的应用 |
| **第五代的超越** | 燧人的Level连续谱是为DFS引导架构的候选Q排序设计的，第五代将其应用于tell检索的分层过滤——先大概念（高Level）后小概念（低Level） |

### 继承12：DFS引导架构

| | |
|---|---|
| **来源** | [214]第8章——引导者AI陪着做题AI做DFS——节点=做题AI状态，边=引导者发送的Q（提示），根节点=题目，叶节点=成功/死路/截断。引导者在每个节点生成候选Q列表，按Level降序排列，一次发一个，走不通则回溯 |
| **在第五代中的位置** | 引导树闭环的DFS架构——第五代的引导展开树就是燧人的DFS树。每个节点是一个数学处境，每条边是一个hint。系统在每个节点识别tell→匹配hint→启动新AI走新分支 |
| **作用** | 提供引导展开树的完整架构设计——节点/边/根/叶的定义，候选Q按Level排序，回溯铁律等 |
| **第五代的超越** | 燧人的DFS是串行的（一次一个方向，走不通回溯），第五代升级为并发的（识别N个tell→启动N个AI→并发探索，不需要回溯） |

### 继承13：回溯铁律

| | |
|---|---|
| **来源** | [214]第8.9节——禁止在同一个Session中让AI回溯到某个思路岔口。必须启动新Session，重放Q序列到岔口，在岔口换方向。原因是压缩边界风险、context污染、不可逆性 |
| **在第五代中的位置** | 引导树闭环的回溯约束——当系统在某个节点识别出tell并启动新AI时，新AI在一个全新的Session中运行，继承脉络（从根到当前节点的Q序列），不共享context |
| **作用** | 保证树的每个分支context干净——新AI只包含到岔口为止的推理，不包含被回溯的分支 |
| **第五代的超越** | 第五代的并发DFS根本不需要回溯——每个方向从一开始就是独立的Session。但回溯铁律仍然是约束——不能在同一个AI的Session中让它换方向 |

### 继承14：安全第一步

| | |
|---|---|
| **来源** | [214]第5章——让AI先描述形状而非解题——AI必然能完成"读题并分类"（结论类型/条件类型/距离/想到的方向/联想），这是元认知观察，不依赖任何知识 |
| **在第五代中的位置** | Pipe 0拓扑化的入口——从thinking中提取拓扑结构就是"让AI描述形状"的工程化。Pipe 0提取的problem_type/ai_method_type就是"结论类型/条件类型"的简化版 |
| **作用** | 提供拓扑化的入口机制——AI必然能完成形状描述（不依赖知识），所以Pipe 0必然能从thinking中提取拓扑结构 |
| **第五代的超越** | 燧人的安全第一步是让AI主动描述形状，第五代是系统从AI的thinking中被动提取拓扑——不需要AI主动配合 |

### 继承15：连续发问六层渐进

| | |
|---|---|
| **来源** | [214]第6章——从观察→联想→描述方向→小尝试→推进→卡点处理，每一步都比前一步多一点点创造性，AI不会面对空白页 |
| **在第五代中的位置** | 脉络继承的设计——脉络不是突然给AI一个hint，而是从根到当前节点的完整路径（观察→联想→描述方向→...），让新AI在已有脉络基础上继续 |
| **作用** | 提供脉络构造的渐进式框架——脉络不是跳跃式的提示，而是渐进式的路径重放 |
| **第五代的超越** | 燧人的连续发问是串行的（一次一个Q），第五代的脉络继承是一次性的（把完整脉络给新AI），但渐进式的思路在脉络文本的构造中保留 |

### 继承16：最小知识传递

| | |
|---|---|
| **来源** | [214]第7章——形式化定义为argmax ΣLevel(h_i)——在"AI能完成解题"的约束下，最大化Level之和。如果纯高Level提示无法完成，必须适时降低Level走向知识端 |
| **在第五代中的位置** | hint端Level梯度的设计原则——优先给高Level hint（翻译方向，不泄漏答案），如果AI仍然做不出来，再给low level hint（更具体的知识）。281号的24个翻译方向都是高Level的（不泄漏答案） |
| **作用** | 提供hint设计的优化目标——最大化Level之和，即尽可能用高Level（非特定）的hint，只在必要时降低Level |
| **第五代的超越** | 第五代的POC-VMS-8验证了高Level hint（翻译方向）的有效性——bare 0% → tree 67%，证明高Level hint足够，不需要降低到知识端 |

### 继承17：引导者的四种元认知能力

| | |
|---|---|
| **来源** | [214]第8.6节——引导者不需要知道正确答案，但需要：生成候选Q（广度）、评估Level（品味）、判断A的状态（诊断）、回溯决策（剪枝）。这四种能力都是元认知能力，不是具体数学知识 |
| **在第五代中的位置** | 辅助智能体JD的核心能力——辅助智能体不需要知道答案，但需要：识别tell（诊断）、匹配hint（广度）、判断推理AI状态（诊断）、决定是否启动新AI（剪枝） |
| **作用** | 提供辅助智能体能力要求的定义——四种元认知能力对应tell识别+hint匹配+状态判断+启动决策 |
| **第五代的超越** | 燧人的四种能力是描述性的，第五代在POC-VMS-9/10中将"判断A的状态"和"生成候选Q"工程化为Pipe 0/1/2 |

### 继承18：ArangoDB持久化QA树

| | |
|---|---|
| **来源** | [214]第8.13节——QA树存入ArangoDB——case文档（元信息）、节点文档（每个节点的完整记录）、边（parent→child）。短期JSON+ArangoDB双写，中期提炼为H层启发规则，长期跨case的K层语义搜索 |
| **在第五代中的位置** | 引导展开树/解题记录树的ArangoDB存储——tree_nodes/tree_edges集合的schema设计 |
| **作用** | 提供两棵树的持久化方案——节点和边存入ArangoDB，支持图遍历查询 |
| **第五代的超越** | 燧人的QA树是串行DFS的记录，第五代是并发DFS的记录——但ArangoDB持久化的方案完全继承 |

## 从伏羲（第四代·形式化边界推进）继承的内容

伏羲的核心理念：形式化边界的持续推进，两种计算（AI管边界以外的感知，经典计算管边界以内的验证），数据基座增长=边界推进。

### 继承19：识别"不自然"

| | |
|---|---|
| **来源** | [219-221] 模式识别识别的是"当前表示与内在结构之间的不匹配"——即"不自然"（冗余/隐藏乘积/虚假自由度/隐藏直和等）。模式识别有两步结构：识别问题拓扑→映射到思维拓扑 |
| **在第五代中的位置** | tell端"分叉信号"的识别原理——tell识别的本质是识别AI的thinking与问题的内在结构之间的不匹配（AI走了错路=不自然）。Pipe 0拓扑化提取的就是这种不匹配的结构特征 |
| **作用** | 提供tell识别的理论依据——tell不是"AI卡住了"，而是"AI的表示与问题结构不匹配"（伏羲的"不自然"），即AI走了错路（285号的修正认知） |
| **第五代的超越** | 伏羲的"不自然"类型（冗余/隐藏乘积/虚假自由度/隐藏直和）是代数/几何领域的，第五代在POC-VMS-9/10中将"不自然"泛化为"方法-问题不匹配"（method_problem_mismatch），适用于更广泛的数学领域 |

### 继承20：形式化边界与知识分工

| | |
|---|---|
| **来源** | [222] 形式化的边界是本质性的。AI时代边界没有消失但移动了：AI见过海量例子，能做模糊模式匹配，覆盖了感知层面的边界。**分离模式识别和答案知识：让不知道答案的AI做模式识别——它的感知不会泄露答案。** |
| **在第五代中的位置** | 辅助智能体做tell识别的知识悖论解决方案——辅助智能体不需要知道答案就能做tell识别，因为tell识别是边界以外的感知（形式化匹配+小概念标记），不是边界以内的知识（答案） |
| **作用** | 从认识论层面解决知识悖论——识别tell和提出tell不需要同等知识，因为识别tell是感知（边界以外），提出tell是感知+框架（边界以外+边界以内的结构） |
| **第五代的超越** | 伏羲的"分离模式识别和答案知识"是理论层面的，第五代在POC-VMS-9/10中工程化了——Pipe 0/1/2做模式识别（不知道答案），hint字典提供方向（不包含答案） |

### 继承21：两种计算

| | |
|---|---|
| **来源** | [223][236] 两种计算——经典计算管边界以内的验证（AQL集合差集/数值验证/确定性图遍历），AI管边界以外的感知（识别"不自然"/感知Level/判断形状匹配/在候选中选择） |
| **在第五代中的位置** | Pipe 1（形式化过滤）=经典计算，Pipe 2（小概念标记分辨）=AI智能——正是两种计算的实例。Pipe 1用形式化方法（拓扑字段匹配/AQL查询）缩小搜索空间，Pipe 2用AI智能（小概念标记分辨）在缩小的空间中做模糊匹配 |
| **作用** | 提供三层Pipe架构的理论依据——Pipe 1（形式化）和Pipe 2（AI智能）的分工正是伏羲两种计算的实例。命题3"形式化+AI智能必须结合"直接对应 |
| **第五代的超越** | 伏羲的两种计算是为形式化边界推进设计的，第五代将其应用于tell检索——Pipe 1形式化缩小范围，Pipe 2 AI智能精准识别 |

### 继承22：数据基座是形式化边界的显式记录

| | |
|---|---|
| **来源** | [231][236] 数据基座是形式化边界的显式记录，每个数学工程单元标记着形式化边界的一个位置。数据基座单调增长——证书只加不删。抽取机制：抽取就是闭环本身，单任务双产出——跑一次闭环，同时产出问题的解和数据基座条目 |
| **在第五代中的位置** | tell数据基座和hint字典的单调增长机制——每次引导树闭环运行后，新的tell和hint被提炼并加入数据基座。数据基座只加不删，随着运行次数增加而增长 |
| **作用** | 提供数据基座增长的理论依据——tell和hint的积累不是手工录入，而是引导树闭环运行的副产品（单任务双产出） |
| **第五代的超越** | 伏羲的单任务双产出是设计但未实现，第五代在POC-VMS-5中验证了Pattern自动提炼闭环（trajectory→提炼→加载→检索→引导新AI→新trajectory→再提炼） |

### 继承23：路径结构匹配（非RAG）

| | |
|---|---|
| **来源** | [231] 检索机制不是RAG，而是找相似的边界推进路径——粗筛（结构化字段匹配）→精化（图查询在依赖图中找连通路径）→排序（可选：向量检索）。核心是路径结构匹配，不是embedding相似度 |
| **在第五代中的位置** | Pipe 1形式化过滤的检索机制——不是RAG（embedding相似度），而是结构化字段匹配（大概念拓扑匹配）+小概念标记（路径结构匹配）。AQL查询模板继承伏羲的"粗筛+精化+排序"三层检索 |
| **作用** | 提供tell检索的方法论——不用embedding相似度，用结构化字段匹配。这是Pipe 1的核心设计原则 |
| **第五代的超越** | 伏羲的三层检索是为数学工程单元设计的，第五代将其应用于tell检索——Pipe 1是粗筛（大概念匹配），Pipe 2是精化（小概念标记），排序是combined_score |

### 继承24：语义场证书框架

| | |
|---|---|
| **来源** | [225] 数学处境S作为基本对象（不是静态点），包含原始题目/对象/关系/当前表示/已尝试表示/已知例子/当前猜想/局部证书/未形式化结构感觉。表示图册A(S)允许一个处境用多个局部表示看清 |
| **在第五代中的位置** | tell端"未探索诊断"的richer表示——当Pipe 0拓扑化需要更细粒度时，可以从3个维度扩展到语义场证书框架的完整数学处境表示。特别是"未形式化结构感觉"对应tell识别中AI的隐性分叉信号 |
| **作用** | 提供tell识别的未来扩展方向——当3个拓扑维度不足以区分tell时，可以扩展到语义场证书框架的完整数学处境表示 |
| **第五代的超越** | 伏羲的语义场证书框架是完整的理论设计但未实现，第五代在POC-VMS-9/10中实现了简化版（3个维度）并验证通过，语义场证书框架是未来扩展方向 |

### 继承25：非特定性=边界推进能力

| | |
|---|---|
| **来源** | [236] 非特定性 = 方法可从边界以外使用 = 边界推进能力。检验一个引导方法是否非特定，就是检验它能否在不知道答案的情况下推进边界 |
| **在第五代中的位置** | tell+hint的非特定性检验标准——tell识别（Pipe 0/1/2）和hint注入（翻译方向）都是非特定的，因为它们不需要知道答案就能工作。检验方法：去掉答案等价信息后，tell识别和hint注入是否仍然有效 |
| **作用** | 提供非特定性的操作性定义——不是"抽象度高"而是"不知道答案也能工作" |
| **第五代的超越** | 伏羲的非特定性是理论定义，第五代在POC-VMS-8中验证了高Level hint的非特定性（翻译方向不包含答案，bare 0% → tree 67%） |

## 从核心洞察继承的内容

### 继承26：检索本质是模式识别

| | |
|---|---|
| **来源** | 命题2——检索本质是模式识别，输入是当前状态（不是查询关键词），输出是方向（不是具体内容），判据是模式匹配（不是相似性） |
| **在第五代中的位置** | tell检索的整体设计——输入是thinking（当前状态），输出是tell（应识别的分叉信号），判据是拓扑匹配+小概念标记（模式匹配） |
| **作用** | 提供tell检索的本质理解——不是RAG（文本相似度），而是模式识别（结构匹配） |

### 继承27：形式化+AI智能的混合

| | |
|---|---|
| **来源** | 命题3——形式化和AI智能各有所长必须结合。形式化方法处理边界以内的部分（可规则定义的），AI智能处理边界以外的部分（需要感知的） |
| **在第五代中的位置** | 三层Pipe架构的理论基础——Pipe 0/1（形式化方法）处理能形式化的部分（拓扑结构匹配），Pipe 2（AI智能）处理不能形式化的部分（小概念标记分辨） |
| **作用** | 提供Pipe分工的理论依据——为什么不能只用形式化（有些tell不适合形式化），为什么不能只用AI（10万级tell无法全装入上下文） |

### 继承28：小规模退化

| | |
|---|---|
| **来源** | 命题4——10个模式时检索问题退化为纯模式识别问题（没有索引/粗筛/精化的工程复杂度），可以专注于验证"AI能否做模式识别"这个核心命题 |
| **在第五代中的位置** | POC验证路径的设计——POC-VMS-9用2个tell验证tell识别+形式化过滤，POC-VMS-10用2个拓扑相同的tell验证小概念标记分辨。从小规模开始，逐步扩大 |
| **作用** | 提供验证路径的方法论——先在小规模下验证机制可行性，再逐步扩大规模 |

### 继承29：并发展开

| | |
|---|---|
| **来源** | 命题5——识别N个模式→启动N个推理智能体→每个走一个方向→并发探索。不需要回溯——每个方向从一开始就是独立的Session |
| **在第五代中的位置** | 引导树闭环的并发DFS——识别N个tell→匹配N个hint→启动N个新AI→并发探索。每个分支独立Session，独立工作目录，独立context |
| **作用** | 解决回溯铁律的痛点——不需要在同一Session中回溯，每个方向独立推进 |
| **第五代的超越** | 命题5是用户提出的洞察，第五代在POC-VMS-2中验证了并发DFS的工程可行性（2并发AI+实时采集+树生长） |

## 第五代的独特贡献（四代都没有的）

第五代不只是继承，还有四代系统都没有的全新机制：

| 独特贡献 | 内容 | 来源 |
|---|---|---|
| **tell+hint二元组** | 将"识别→给方向"明确命名为二元组tell+hint，tell是识别端（从thinking读出分叉信号），hint是注入端（给新AI的翻译方向） | 000号（v3修正） |
| **三层Pipe架构** | Pipe 0拓扑化→Pipe 1大概念过滤→Pipe 2小概念标记分辨，三层递进，解决10万级tell的规模检索 | 287号 |
| **概念树** | 大概念→小概念→概念树的层次化管理，无论tell数量如何增长、概念树如何膨胀，有限上下文的辅助AI都能系统化应对 | 287号（用户第六次原文） |
| **tell的去特化** | 从Level 0（题目特化的人工判断）提升到Level 1+（可泛化的拓扑结构），使tell可以被穷举 | 287号 |
| **拓扑相同且距离极近的tell区分** | 当大概念无法区分时，用小概念标记分辨——只要两个tell能用语言表达出区别，就能定义概念来区分 | 287号+POC-VMS-10 |
| **lineage继承+方向注入** | 脉络继承（从根到当前节点的完整路径）+方向注入（翻译方向hint），使新AI在已有脉络基础上继续探索 | POC-VMS-8验证 |
| **根分叉vs点分叉** | 分叉位置不只在line上的point，也可能在line的根节点——AI从第一步就选错了方向 | 000号（v2修正） |
