## 为什么记录

POC-6 原始实验曾被写成“方法论跨领域泛化最终验证成立”，但复查发现，B 组依赖图中的两个节点直接包含了正确答案或与正确答案等价的映射。原始增量因此不能作为可信的方法论证据。

120 号交接文档已经记录了修正版 A 组完成、修正版 B 组中断的状态，但继续执行前还存在六个需要正式解决的问题：项目总索引仍保留旧结论、修正版提示仍需明确测量边界、声明的数值螺旋环路与实际边集合不一致、违规审计证据不足、实验资产位于项目仓库外、单次随机运行不足以支撑“最终验证成立”。

本方案把这些发现变成可执行的实验纠偏流程。它不是新的 POC 结果，也不预设修正版 B 组一定成功。

---

## 摘要

1. 119 号文档只保留为“原始实验历史记录”，不得再作为 POC-6 的最终结论；120 号记录中断状态，本方案负责后续纠偏与证据闭环。
2. 修正版依赖图已经消除字面答案，但仍提供强方向性导航。POC-6 测量的是“不给出答案时，依赖图导航能否提高发现正确形式的概率”，不是“AI 能否完全独立发现答案”。
3. 先完成一次 B 组恢复性重跑，用于确认中断流程可以跑通；再进行至少 3 对同配置 A/B 配对复跑，必要时扩展到 5 对。单次 B 组成功只能算个案，不能再次写成最终验证。
4. 正式判定前必须同时通过输入冻结、答案泄漏审计、图拓扑审计、完整运行日志审计、盲评和项目内证据归档六道门槛。

## 一、适用范围与事实优先级

### 1.1 本方案处理什么

本方案只处理数学大师项目中的 POC-6 修正版：

- 题目：猜测多色 Ramsey 数 $R_k(C_5)$ 的下界增长阶；
- A 组：只读取共同题面；
- B 组：读取共同题面和修正版依赖图；
- 正确结果：$(\log k)^{k/3-o(k)}$；
- 核心问题：依赖图能否在不直接写答案的前提下，帮助 AI 从“改指数”转向“分析底数是否下降”。

本方案不处理 POC-7，也不据此宣布整个数学大师方法论已经完成跨领域最终验证。

### 1.2 文档事实优先级

发生冲突时，按以下顺序理解 POC-6 当前状态：

1. **本方案（121号）**：修正版重跑的纠偏标准、证据标准和判定标准；
2. **120号交接文档**：修正版 A 组已完成、B 组中断的事实记录；
3. **119号结果文档**：原始依赖图实验的历史记录，因答案泄漏而降级为低可信证据；
4. **118号方案文档**：保留原始实验设计背景，但其中直接指向答案的节点设计不得继续复用。

### 1.3 当前已知状态

| 项目 | 当前状态 | 证据 |
|---|---|---|
| 原始 A 组 | 猜测 $k^{k/5-o(k)}$ | `dev-docs/119-大师-POC-6验证结果-Ramsey数发现型问题.md` |

## 二、六项审计发现

### 2.1 项目总索引与当前事实冲突

复查时，`AGENTS.md` 仍把 119 号写成“方法论泛化性最终验证成立”，TODO 也把 POC-6 标记为完成，Memory Section 继续使用 `+4.0/10` 作为可信增量。120 号则明确指出，原始 B 组依赖图有两个节点直接写出答案，修正版 B 组尚未完成。本方案落盘时已同步纠正这些位置。

**影响**：下一个 Session 只读 `AGENTS.md` 时，会跳过修正版重跑并错误进入 POC-7。

**纠偏要求**：

- 119 号标记为“原始结果，因答案泄漏降级”；
- 120、121 号加入认知资产索引；
- POC-6 TODO 恢复为未完成；
- POC-7 明确依赖 POC-6 修正版证据闭环；
- 原 `+4.0/10` 只能在注明“原始泄漏版”的情况下引用。

### 2.2 修正版消除了字面答案，但仍有强方向性提示

修正版不再出现 `p=2(C_5): (log k)^{k/3}` 或 `k^{k/3} → (log k)^{k/3}`，这是必要纠正。但它仍要求 AI：

- 把 $k^{k/3}$ 分成底数和指数；
- 判断变化的是底数还是指数；
- 考虑迭代对数是否适用；
- 用不变量思维判断哪一部分保持不变。

这些信息没有直接给出公式，却已显著压缩候选空间。共同题面还向 A/B 两组都给出了迭代对数定义。

**影响**：如果把实验解释成“AI 独立发现 Steiner 定理”，提示过强；如果解释成“经典计算产生的思维导航是否能帮助 AI 走向正确方向”，这种提示正是被测对象。

**纠偏要求**：固定测量口径为：

> 在共同题面已经定义迭代对数的前提下，比较“无依赖图”和“有依赖图导航”两组发现正确增长形式的概率与推理质量。

同时执行三档内容审计：

| 档位 | 判定 | 例子 | 是否允许 |
|---|---|---|---|
| 直接答案 | 写出最终公式、精确参数或 `C_5 → log k` 的确定映射 | `p=2: (log k)^{k/3}` | 禁止 |
| 等价答案 | 虽未写公式，但唯一确定“底数变为 log k、指数 k/3 不变” | “从 C3 到 C5 底数降一层对数，指数不变” | 禁止 |
| 方向导航 | 提醒比较底数与指数、考虑迭代对数、做数值与极端检验，但不替 AI 选择 | 当前修正版节点 | 允许，但结果中必须声明提示强度 |

### 2.3 声明的数值螺旋环路与实际边集合不一致

当前 JSON 中确实存在一条结构环：

```text
R_k(C_5)下界猜测
→ C_3结果分析
→ 递归构造机制
→ C_5的递归障碍
→ 下降机制分析
→ 指数与底数的分离
→ 迭代对数作为工具
→ R_k(C_5)下界猜测
```

但 `spiral_loop` 字段声明的是：

```text
下降机制分析 → R_k(C_5)下界猜测 → 数值论证 → 回到猜测
```

实际边集合只有 `数值论证 → R_k(C_5)下界猜测`，缺少从猜测进入增长阶比较或数值论证的边。因此，**图中有环，但声明的三节点数值反馈环不成立**。

**纠偏要求**：

1. 把现有长环声明为“机制分析环”；
2. 增加 `R_k(C_5)下界猜测 → 增长阶比较`，与现有的 `增长阶比较 → 数值论证 → R_k(C_5)下界猜测` 组成“候选—数值反馈环”；
3. 如果当前格式只允许一个 `spiral_loop`，则只登记真实存在的主环，把第二个环放入单独的 `feedback_loop` 字段；
4. 重跑前用程序验证每个声明环的相邻节点都有对应边，不接受只靠文字目测。

### 2.4 只检查 `result.md` 不能证明没有违规

120 号给出的审计命令主要在最终结果中搜索 `web_search`、`master-mind` 等字符串。但 Agent 即使调用过网络或访问过项目目录，也通常不会把工具调用写进最终答案。

**影响**：`result.md` 没有违规字符串，只能证明最终文本没有自报违规，不能证明运行过程合规。

**纠偏要求**：每次运行至少保存四类证据：

1. 完整 tmux pane 日志，而不是只截最后一屏；
2. 最终 `result.md`；
3. 输入文件和 SHA-256 摘要；
4. 审计报告，分别记录网络调用、越界路径访问、输入差异和结果文件生成过程。

运行前设置足够大的 tmux history，并用 `pipe-pane` 持续写日志。运行结束后再用 `capture-pane -S -` 保存完整回看文本。若 Devin CLI 另有可验证的会话工具记录，应一并归档，但不能在未确认真实路径前猜测日志位置。

### 2.5 隔离目录中的资产不能自动成为项目 Git 证据

修正版依赖图位于 `/data/math-agent-2/`，A 组结果位于 `/data/math-agent-1/`。这两个目录都不在项目根 `/data/master-mind/` 下。

**影响**：120 号所说“先 commit 修正版依赖图和 A 组结果”不能直接通过项目仓库完成。只提交交接文档，会留下结论而没有原始证据。

**纠偏要求**：隔离目录继续用于运行，运行后由主 Agent 把只读副本归档到项目内：

```text
xishujuzhen/poc/math-poc6-revised/
├── frozen-inputs/
│   ├── problem.md
│   ├── agents-a.md
│   ├── agents-b.md
│   └── dependency_graph.json
├── runs/
│   ├── A1/
│   ├── B1/
│   └── ...
├── scoring/
│   ├── blind-label-map.json
│   ├── per-run-scores.json
│   └── aggregate-verdict.md
├── manifest.json
└── SHA256SUMS
```

隔离 Agent 仍然禁止访问项目目录；证据复制只能在运行结束后由主 Agent 完成。

### 2.6 单次运行不足以支撑最终验证

原始 A 组猜 $k^{k/5}$，修正版 A 组猜 $k^{k/6}$。虽然两者都错误，但差异证明发现型任务存在明显运行波动。单个 B 组即使猜对，也不能区分“依赖图稳定提高成功率”和“这一次随机走对了”。

**纠偏要求**：

- 恢复被中断的 B 组只用于恢复工作连续性；
- 正式判定采用至少 3 对独立 A/B 配对复跑；
- 如果 3 对结果分裂或接近边界，扩展到 5 对；
- 每一对必须使用相同模型、推理强度、CLI 版本、共同题面和运行规则；
- 每次使用全新会话，不继承其他组上下文；
- 报告全部运行，不挑选最好的一次。

## 三、方案目标与非目标

### 3.1 目标

1. 判断修正版依赖图在不给出直接或等价答案时，是否提高 AI 猜中正确增长形式的稳定性；
2. 判断依赖图是否改善 D2-D4 所代表的递归机制、C5 障碍和迭代对数分析；
3. 建立可复核的输入、运行、审计、评分、结论证据链；
4. 给出 `支持 / 有方向性证据但不足 / 不支持 / 实验无效` 四档判定，而不是只写成功故事。

### 3.2 非目标

1. 不证明 Steiner 定理；
2. 不把一次猜中解释为 AI 独立发现新数学；
3. 不在 POC-6 未闭环前进入 POC-7；
4. 不为了得到正结果继续增强提示，直到 B 组猜中；
5. 不用最终答案反向修改评分标准。

### Phase 1：依赖图内容与拓扑双审计

#### 1. 内容审计

逐节点检查：

- 是否写出最终公式；
- 是否给出与最终公式一一等价的确定映射；
- 是否引用论文标题、作者、定理编号等可能让 Agent 反推出答案的信息；
- 是否只是要求比较候选、识别变量、调用工具和执行检验。

审计输出必须逐节点给出 `禁止 / 允许但强提示 / 一般意识` 判定，不能只给整图一句“没有答案”。

#### 2. 拓扑审计

至少验证：

- 所有边的两端节点存在；
- 没有重复边；
- 每个声明环的每一步都在边集合中；
- “机制分析环”和“候选—数值反馈环”分别可遍历；
- `spiral_loop` 或替代字段与真实边一致；
- JSON 可解析。

#### 3. 修订冻结纪律

拓扑修复只能修复“声明与边不一致”，不得借机新增更靠近答案的知识内容。修复后重新生成哈希，此后所有 B 组使用同一版本。

#### 通过条件

- 直接答案和等价答案 remainder = 0；
- 声明但不存在的环 remainder = 0；
- 无效端点、重复边、JSON 错误 remainder = 0。

### Phase 3：A/B 配对验证性复跑

#### 1. 实验矩阵

先运行 3 对：

| 配对 | A组 | B组 | 唯一差异 |
|---|---|---|---|
| Pair 1 | A1 | B1 | B1读取冻结依赖图 |
| Pair 2 | A2 | B2 | B2读取冻结依赖图 |
| Pair 3 | A3 | B3 | B3读取冻结依赖图 |

若结果分裂或接近判定边界，再增加 Pair 4、Pair 5。恢复性 B 组不自动并入正式样本；只有当它从一开始就使用完全相同的冻结输入、配置和证据规范时，才可在实验开始前决定是否计入。

#### 2. 配对控制

每一对必须保持：

- 同一模型及明确模型标识；
- 同一推理强度和权限配置；
- 同一 Devin CLI 版本；
- 同一共同题面哈希；
- 同一固定 prompt；
- 同一输出要求；
- 全新独立会话；
- 相同的失效与补跑规则。

A/B 的启动顺序交替，避免总是先跑某一组。任何一组因工具故障、审批中断或证据缺失而失效，只能按预先定义的失效规则补跑同一单元，不能因为答案不好而补跑。

#### 3. 隔离要求

- 运行目录继续放在项目仓库外；
- 两组都禁止网络搜索；
- 两组都禁止访问 `/data/master-mind`；
- B 组只比 A 组多一个 `dependency_graph.json`；
- 各运行之间不得互看结果；
- 主 Agent 只监督和归档，不在中途提示数学内容。

### Phase 4：完整审计与盲评

#### 1. 运行合规审计

每个运行分别审计：

| 审计项 | 证据 | 失效条件 |
|---|---|---|
| 网络搜索 | 完整 transcript / 可用工具记录 | 调用 web_search、webfetch 或外部搜索命令 |
| 越界访问 | 完整 transcript / 文件访问记录 | 读取项目目录或另一组目录 |
| 输入一致性 | SHA-256 | 共同题面或规则哈希不一致 |
| 依赖图一致性 | SHA-256 | B 组图版本不一致 |
| 会话独立性 | manifest | 复用了含其他组信息的上下文 |
| 输出完整性 | `result.md` | 没有最终猜测或结果文件不完整 |

只检查最终文本不算完成审计。

#### 2. 盲评

- 把所有结果随机改为无组别标签的样本编号；
- 评分者不知道 A/B；
- 沿用 8 维 15 分制；
- 评分后再解盲；
- 保留评分理由，不能只保留总分。

#### 3. 主指标与辅指标

**主指标**：

1. 是否猜中 $(\log k)^{k/3-o(k)}$；
2. D5 最终猜测形式得分；
3. 每对的 B-A 总分差；
4. A/B 各自猜中次数。

**辅指标**：

- D2 递归机制；
- D3 C5 障碍；
- D4 迭代对数；
- D6 数值论证；
- 推理路径实际使用了哪些依赖图节点。

不得只报告最有利的维度。

### Phase 5：判定规则

#### 5.1 四档判定

| 判定 | 条件 | 允许写出的结论 |
|---|---|---|
| 支持 | 无失效运行；B 至少 2/3 猜中、A 至多 1/3 猜中；B 总分中位数高于 A；优势主要落在 D2-D5 | 修正版依赖图在本题上提供了可重复的发现导航增益 |
| 有方向性证据但不足 | B 总体优于 A，但没有达到上述组合条件，或样本扩展后结果仍分裂 | 观察到正向信号，尚不足以验证稳定增益 |
| 不支持 | A/B 命中与评分无一致优势，或 B 更差 | 当前修正版依赖图没有显示可重复增益 |
| 实验无效 | 存在答案/等价答案泄漏、输入不一致、违规工具调用、证据链缺失或盲评失效 | 不得对方法论作正负结论，先修复实验 |

#### 5.2 禁止的结论跳跃

即使判定为“支持”，也只能说明：

> 在 POC-6 这一个发现型 Ramsey 问题上，固定版本的方向导航依赖图表现出可重复增益。

不能直接推出：

- 数学大师方法论已经在所有数学领域成立；
- AI 已独立发现 Steiner 定理；
- 任意发现型问题都能被依赖图解决；
- POC-7 不再需要进行。

跨领域泛化只能由多个彼此独立、无答案泄漏、可重复的 POC 共同支持。
