# 66-xishujuzhen POC-3 验证方案

## 1. 背景：POC-2 的结果与九延伸的新要求

### 1.1 POC-2 结果回顾

POC-2（65 号文档方案）执行结果为**部分成功（但显著进步）**：

| 维度 | A组（增强版文档） | B组（扩展依赖图+知识嵌入+审计） | 差异 |
|---|---|---|---|
| 完整性 | 5 | 5 | 持平（POC-1 中 B 落后 1 分，已追平） |
| 准确性 | 5 | 5 | 持平（POC-1 中 B 落后 1 分，已追平） |
| 深度 | 5 | 5 | 持平 |
| 逻辑性 | 5 | 5 | 持平 |
| 结构感 | 4 | 5 | **B 优势**（+1） |
| **综合** | **4.85** | **5.00** | **B 领先 0.15** |

POC-1 中 B 组落后 0.20 分，POC-2 中 B 组领先 0.15 分。方向对了，但领先幅度不够大（"显著优于"要求领先 0.50）。

### 1.2 POC-2 的核心发现

> 当知识充足时（A 组也拿到了全部知识），依赖图提示的边际增益主要在结构感和逻辑性上，不在完整性和准确性上。完整性和准确性主要由"有没有知识"决定，不是由"有没有依赖图"决定。

这意味着：**JSON 作为提示词直接给 AI，它的价值有限——因为 JSON 是结构化的依赖清单，不是循循善诱的引导。** AI 拿到 JSON 后知道"该判断什么"，但不知道"该怎么去想"。

### 1.3 九延伸的新要求

63 号文档九延伸（及八延伸合观）提出了流程中的关键新环节：

**当前流程（POC-1/POC-2）：**
```
经典计算生成JSON → AI拿到JSON直接分析 → 输出结果+审计
```

**新流程（POC-3）：**
```
经典计算生成JSON → AI解读JSON生成大师级提示词 → AI在JSON+大师级提示词共同提示下分析 → 输出解读+结果+审计
```

新增环节是 **AI 解读 JSON**——AI 把生硬的依赖图，转译为占星大师级别的循循善诱的提示词。这份提示词是 AI 自己写给自己的。

**完美提示词 = 经典计算（JSON，结构）+ AI 解读（Markdown，语言）。**

### 1.4 审计文件的双重对照

合观后，审计文件不只是"逐节点/逐边对照 JSON"，它有双重对照：

1. **对照 JSON 证明覆盖完备性**（结构基准）：12 个节点是否全部处理？16 条边是否全部沿其思考？螺旋环路是否走了 2 圈？
2. **对照大师型提示词证明思考路径忠实性**（路径基准）：AI 是否循着大师型提示词的引导走的？有没有在提示词说"我们要进一步想"的地方跳过了？

**JSON 是审计的锚点。大师型提示词是引导的风。**

### 1.5 POC-3 验证的命题

> **当 AI 先解读 JSON 生成大师级提示词，再在 JSON + 大师级提示词共同提示下分析时，B 组相对于 A 组的优势是否显著增大？**

POC-2 中 B 组领先 0.15 分（主要靠结构感 +1）。POC-3 的假设是：大师级提示词的循循善诱会让 AI 的分析质量在所有维度上都有提升——不只是结构感，还有深度、逻辑性，甚至完整性和准确性（因为循循善诱的引导会让 AI 更深入地思考每个节点，而不是机械地走过）。

## 2. POC-3 的三个改进

### 2.1 改进一：AI 自解读环节（核心新增）

在 AI 拿到 JSON 后、开始分析前，插入一个解读环节：

**AI 解读 JSON，输出大师级提示词 Markdown 文档。**

解读要求：
- **逐节点解读**：这个节点是什么意思？在这个上下文中要判断什么？
- **逐边解读**：为什么从这个节点到那个节点？这条依赖关系的命理含义是什么？
- **逐环路解读**：这个螺旋环路意味着什么？第一圈和第二圈的上下文变化在命理上代表什么深化？
- **整体解读**：把所有依赖关系串成一条思维路径，用占星大师的语言循循善诱地引导。

**约束：AI 解读时不能改变 JSON 中的依赖关系。** 不能添加 JSON 中没有的节点或边，不能跳过 JSON 中的任何节点或边。解读是转译，不是创造。如果 AI 在解读中发现 JSON 缺少了某些应该有的依赖，应该在提示词中标注"依赖图中未覆盖但可能需要的分析维度"，而不是自行添加。

### 2.2 改进二：双重提示（JSON + 大师级提示词）

AI 在分析时同时拿着两份文件：
- 依赖图 JSON（结构化，客观，可审计）
- 大师级提示词（自然语言，循循善诱，AI 自己写的）

JSON 是审计基准，大师型提示词是引导。两者缺一不可。

### 2.3 改进三：审计文件双重对照

审计文件不只是"逐节点/逐边对照 JSON"，它同时对照两份基准：

1. **对照 JSON**：节点覆盖率、边覆盖率、环路处理正确性（同 POC-2）
2. **对照大师型提示词**：思考路径忠实性——AI 是否循着大师型提示词的引导走的？在提示词说"我们要进一步想"的地方，AI 是否真的进一步想了？在提示词说"这是螺旋的第二圈"的地方，AI 是否真的走了第二圈？

## 3. 验证命题

### 3.1 POC-3 验证的命题

> **在 AI 自解读（JSON→大师级提示词）+ 双重提示 + 双重对照审计 的条件下，B 组在 5 维度评分上达到"显著优于"A 组，且审计文件显示依赖图覆盖完备性 ≥ 90% + 思考路径忠实性 ≥ 80%。**

### 3.2 与 POC-2 命题的区别

| | POC-2 | POC-3 |
|---|---|---|
| 提示形式 | JSON 直接提示 | JSON + AI 自解读的大师级提示词 |
| 审计维度 | 单重对照（JSON 覆盖完备性） | 双重对照（JSON 覆盖 + 提示词路径忠实性） |
| 成功标准 | 5 维度显著优于 + 审计覆盖≥90% | 5 维度显著优于 + 审计覆盖≥90% + 路径忠实性≥80% |
| 输出文件数 | 2（结果+审计） | 3（解读+结果+审计） |

### 3.3 POC-3 不验证什么

- 不验证 12 节点是否已经足够（同 POC-2，仍用扩展图）
- 不验证真实星盘（仍用简化盘）
- 不验证多场景（仍只做命宫分析）
- 不验证解读文件本身的命理准确性（只看是否忠实转译了 JSON 依赖关系，不评判解读内容的命理对错）

## 4. 三步流程设计

### 4.1 第一步：经典计算生成 JSON（系统做，复用 POC-2）

复用 POC-2 的 `graph_v2.py` + `prompt_gen_v2.py` + `knowledge_content.py`，生成 12 节点 16 边的依赖图 JSON。

JSON 中新增一个字段 `interpretation_requirement`，要求 AI 在分析前先输出解读文件。

### 4.2 第二步：AI 解读 JSON 生成大师级提示词（AI 做，新增环节）

AI 拿到 JSON 后，不直接分析，而是先对 JSON 进行解读。

**解读文件的输出格式：**

```markdown
# 依赖图解读 · 大师级提示词

## 解读说明
本文件是 AI 对依赖图 JSON 的解读，把生硬的依赖关系转译为占星大师级别的循循善诱提示词。
本文件是 AI 自己写给自己的完美提示词。
约束：解读忠实于 JSON 中的依赖关系，不添加 JSON 中没有的节点或边。

## 思维路径

[用大师的语言，循循善诱地引导思维路径。不是清单，是带着走的引导。]

### 第一步：命主星判断
你看，命宫在寅，寅属木，木星就是命主星。我们要先判断命主星的强弱——
这是整个命宫分析的根基。怎么判断？要从三个层面看：
庙旺状态（星曜在宫位的力量）、五行生克（星曜与宫位的五行关系）、
阴阳昼夜（昼夜对星曜的影响）。这三个层面不是平行的，是有依赖关系的——
庙旺判断本身就需要调用五行生克（因为庙旺的依据就是五行关系），
而五行强弱又受昼夜影响（昼生木旺），所以五行生克和阴阳昼夜之间
形成了一个螺旋……

### 第二步：度主星判断
命主星判断完了，我们还要看度主星。命度落在尾宿，尾宿属火，
所以度主星是火星。度主星的强弱怎么看？要看升殿（火星属火，
尾宿也属火，同气为升殿）和宿位泄气（火星在尾宿是升殿不是泄气）……

[……继续逐节点、逐边、逐环路解读……]

## 螺旋环路解读

五行生克 ↔ 阴阳昼夜 这个螺旋环路，意味着什么？
第一圈，我们在"命宫/五行关系"的上下文中判断木星与寅宫的五行关系——比和。
第二圈，我们在"命宫/昼生"的上下文中重新审视五行强弱——昼生木旺，
木星从"庙+比和"升级为"庙+比和+昼生得时"三得俱全。
这不是循环论证，是深化——上下文变了，结论也递进了。

## 依赖图中未覆盖但可能需要的分析维度

[如果 AI 在解读中发现 JSON 缺少了某些应该有的依赖，在此标注。
不自行添加，只标注。]
```

### 4.3 第三步：AI 在 JSON + 大师级提示词共同提示下分析（AI 做）

AI 同时拿着两份文件：
- 依赖图 JSON（结构化，客观，可审计）
- 大师级提示词（自然语言，循循善诱，AI 自己写的）

在两份文件的共同提示下，AI 进行命理分析，输出结果文件 + 审计文件。

**审计文件的双重对照：**

```markdown
# 依赖图覆盖审计

## 一、对照 JSON 的覆盖完备性（结构基准）

### 节点覆盖表
[同 POC-2，逐节点列出是否处理、上下文、中间结论]

### 边覆盖表
[同 POC-2，逐边列出是否沿其思考、推理过程]

### 环路处理表
[同 POC-2，逐环路列出类型、圈数、上下文变化]

## 二、对照大师型提示词的思考路径忠实性（路径基准）

### 路径忠实性表

| 提示词引导位置 | 是否循其引导 | 实际思考过程 |
|---|---|---|
| "第一步：命主星判断——要从庙旺、五行、昼夜三个层面看" | 是 | 在结果文件第一章中，依次判断了庙旺（1.1）、五行（1.2）、昼夜（1.3） |
| "庙旺判断本身就需要调用五行生克" | 是 | 在1.1判断庙旺后，1.2立即调用五行生克分析比和关系 |
| "五行生克和阴阳昼夜之间形成了一个螺旋" | 是 | 在1.2五行判断后，1.3引入昼夜，并显式标注"螺旋的第二圈" |
| ... | ... | ... |

### 路径忠实性声明
- 大师型提示词中的引导点：N 个
- 已循其引导的点：M 个
- 未循其引导的点：（列出，说明原因）

## 三、完备性声明

### JSON 覆盖完备性
- 节点：12/12
- 边：16/16
- 环路：1/1

### 思考路径忠实性
- 引导点：N/N
- 忠实率：M/N × 100%
```

## 5. 对照实验设计

### 5.1 实验条件

| 条件 | 输入 | 与 POC-2 的区别 |
|---|---|---|
| **A 组（对照组）** | study-notes 相关内容（同 POC-2 增强版） | 不变 |
| **B 组（实验组）** | 三步流程：JSON → AI 解读 → JSON+大师级提示词共同提示下分析 | 新增解读环节，双重提示，双重对照审计 |

### 5.2 B 组执行方式

B 组分两个阶段执行（因为第二阶段的输入依赖第一阶段的输出）：

**阶段一：解读**
- 给 AI 依赖图 JSON + 星盘摘要
- 要求 AI 输出解读文件（大师级提示词）
- 不要求 AI 做命理分析

**阶段二：分析**
- 给 AI 依赖图 JSON + 大师级提示词（阶段一的输出）+ 星盘摘要
- 要求 AI 输出结果文件 + 审计文件（双重对照）

### 5.3 A 组执行方式

A 组不变——给 study-notes 材料 + 星盘摘要，直接输出结果。A 组没有 JSON，不做解读，不做审计。

### 5.4 为什么不分阶段给 A 组

A 组的流程是"读文档→分析→输出结果"，没有中间环节。给 A 组分阶段反而会改变它的实验条件。A 组的基线就是"直接读文档分析"。

## 6. 评判标准

### 6.1 结果文件评分（5 维度，同 POC-1/POC-2）

| 维度 | 权重 |
|---|---|
| 完整性 | 0.25 |
| 准确性 | 0.25 |
| 深度 | 0.20 |
| 逻辑性 | 0.15 |
| 结构感 | 0.15 |

### 6.2 解读文件评分（新增，3 维度）

| 维度 | 满分 | 评判标准 |
|---|---|---|
| 转译忠实性 | 100% | JSON 中的 12 个节点、16 条边、1 个环路是否全部在解读中被转译？有没有遗漏？有没有自行添加 JSON 中不存在的依赖？ |
| 大师语言质量 | 5 分 | 是否用循循善诱的大师级语言？是不是清单（低分）还是带着走的引导（高分）？ |
| 螺旋解读深度 | 5 分 | 螺旋环路是否被解读为"深化"而非"循环"？上下文变化是否被命理化解释？ |

### 6.3 审计文件评分（扩展，5 维度）

| 维度 | 满分 | 评判标准 |
|---|---|---|
| 节点覆盖率 | 100% | 同 POC-2 |
| 边覆盖率 | 100% | 同 POC-2 |
| 环路处理正确性 | 100% | 同 POC-2 |
| 路径忠实率 | 100% | 大师型提示词中的引导点，AI 实际循其引导的比例 |
| 路径忠实性声明质量 | 5 分 | 未循其引导的点是否说明了原因？原因是否合理？ |

### 6.4 "显著优于"的定义（修订）

B 组显著优于 A 组需要同时满足：
1. B 组结果文件综合评分比 A 组高 **0.50 分以上**（同 POC-2）
2. B 组在**至少 3 个维度**上不低于 A 组（同 POC-2）
3. B 组在**至少 2 个维度**上比 A 组高 1 分以上（同 POC-2）
4. **B 组审计文件 JSON 覆盖完备性 ≥ 90%**（同 POC-2）
5. **B 组审计文件思考路径忠实性 ≥ 80%**（新增条件）
6. **B 组解读文件转译忠实性 = 100%**（新增条件——解读不能改变 JSON 依赖关系）

## 7. 成功/失败定义

### 7.1 成功

B 组满足"显著优于"的全部 6 个条件。

含义：AI 自解读 + 双重提示 + 双重对照审计三者结合，使依赖图提示的优势在更多维度上体现，且 AI 的思考过程可被双重验证（结构覆盖 + 路径忠实）。

后续行动：扩展到更复杂的场景（双宫联动、格局+大限），引入真实星盘。

### 7.2 部分成功

**情况 A**：B 组结果评分达到"显著优于"，但解读文件转译忠实性 < 100% 或路径忠实性 < 80%。

含义：结果质量好，但 AI 没有忠实于 JSON 依赖关系或大师型提示词引导——结果好可能是偶然的，不是流程引导的。需要加强解读和审计的约束。

**情况 B**：解读和审计都达标，但结果评分未达到"显著优于"。

含义：AI 忠实走了流程，但自解读环节没有带来预期的质量提升。可能命宫分析场景已接近天花板，需要换更复杂的场景。

**情况 C**：解读转译忠实性 = 100% 且审计覆盖 ≥ 90% 且路径忠实性 ≥ 80%，但 B 组只比 A 组领先 0.15~0.49 分。

含义：流程被执行了，但边际增益不够大。和 POC-2 类似——命宫分析场景可能不足以体现自解读的价值。需要换更复杂的场景验证。

### 7.3 失败

B 组结果评分未达到"显著优于"，且解读或审计不达标。

含义：自解读环节没有解决问题。需要回到 63 号文档重新审视。

```
并行：A 组分析（subagent）
  输入：material_a_v2.md + 星盘摘要
  输出：poc3_output_a.md

第四步：评分
  → poc3_evaluation.md
```

## 9. 解读文件的引导风格示例

以下是大师级循循善诱的风格示例，供评分时参考"什么是好的解读"：

### 9.1 清单式（低分）

```
命宫分析步骤：
1. 判断命主星木星庙旺
2. 判断五行生克
3. 判断阴阳昼夜
4. 判断度主星升殿
5. 判断恩用仇难
6. 判断颠倒颠
7. 判断仇难外避
8. 判断间接影响
```

这是清单，不是循循善诱。和 JSON 没有本质区别。

### 9.2 大师级循循善诱（高分）

```
你看，命宫在寅，寅属木，木星就是命主星。我们要先判断命主星的强弱——
这是整个命宫分析的根基。

怎么判断？要从庙旺状态看起。木星在寅宫，寅属木，木星也属木，
同气相求，这是庙。庙是什么意思？是星曜在宫位中得到充分接纳，
力量根基扎实。但这只是第一层。

庙旺判断本身就依赖于五行生克——为什么木星在寅是庙？因为寅属木、
木星属木，五行比和。所以庙旺判断和五行判断不是平行的，是有依赖
关系的。我们要从庙旺走到五行。

到了五行这一层，我们看的不只是木星。命宫里还有太阳、月亮、火星、
水星，它们和寅宫的五行关系各不相同——太阳受生（木生火）、月亮
泄气（水生木）、火星受生（木生火）、水星泄气（水生木）。这些
关系决定了每颗星在命宫中的基本力量格局。

但五行强弱还不是最终的。五行受昼夜影响——昼生木旺，这就从
"得地"上升到了"得地又得时"。注意，这不是回到五行生克重新算
一遍，是在昼生条件下深化五行判断。上下文变了，从"五行关系"
变成了"昼生"，结论也递进了。这就是螺旋上升——第一圈看五行
关系，第二圈在昼生条件下重新审视五行强弱。

命主星判断完了，我们还要看度主星。命度落在尾宿，尾宿属火，
度主星是火星。度主星的强弱怎么看？要看升殿——火星属火，尾宿
也属火，同气为升殿，力量最强。这是宿位层面的判断，和宫位层面
的庙旺是不同的维度。

然后是恩用仇难定局。以命主木为核心，其他星曜按生克关系分为
恩（水生木=月、水）、用（木生火=日、火）、仇（金克木=金）、
难（木克土=土、计）。命宫内两恩两用齐聚，仇难外避——
这是好配置还是坏配置？不能简单判断。要用颠倒颠的意识——
命主极强时，用星之泄不是损害而是输出通道，仇星不是压制
而是激发（煞为权）。……

你看，整个分析不是走清单，是沿着依赖关系一步步深入——
庙旺→五行→昼夜（螺旋）→度主→恩用仇难→颠倒颠→仇难外避→
间接影响。每一步都有命理含义，每一步都和前一步有依赖关系。
```

### 9.3 风格判别标准

| 特征 | 清单式（低分） | 大师级（高分） |
|---|---|---|
| 连接词 | "第一步、第二步……" | "我们要先……然后……但还不够……" |
| 依赖关系解释 | 不解释为什么从这一步到下一步 | 解释为什么有这条依赖边 |
| 螺旋处理 | 不提或简单提"循环" | 解释上下文变化和命理深化 |
| 语气 | 客观清单 | 循循善诱、带着走 |
| 知识使用 | 不嵌入知识内容 | 在引导中自然嵌入命理知识 |

## 10. POC-3 的诊断价值

### 10.1 如果 POC-3 成功

说明：AI 自解读是缺失的环节——JSON（结构）+ AI 解读（语言）= 完整的大师级提示词。三步流程比两步流程更有效。

### 10.2 如果 POC-3 部分成功（情况 C：流程达标但边际增益不够）

说明：命宫分析场景已接近天花板。自解读的价值在更复杂的场景中才能体现。下一步应该换双宫联动或格局+大限场景。

### 10.3 如果解读文件质量低（清单式而非大师级）

说明：AI 的解读能力不足，或者解读要求不够明确。需要优化解读提示，或者考虑是否需要分步引导 AI 做解读（先逐节点解读，再整体串联）。

### 10.4 如果路径忠实性低

说明：AI 写了大师级提示词但没有循着它走——解读和分析脱节。可能需要在分析提示中更强调"请循着你在解读文件中写的引导走"。

## 11. 诚实声明

POC-3 仍有以下局限：

1. **仍用简化盘**：不验证真实天文数据下的表现
2. **仍只做命宫分析**：不验证多宫、格局、大限等复杂场景
3. **解读质量的主观性**：大师级语言质量是主观评判，不同评分者可能给出不同分数
4. **路径忠实性的固有局限**：AI 在审计文件中声称"循了引导"，但实际思考过程无法独立验证——AI 可能"声称"循了但实际没有。这是审计机制的固有局限（63 号文档八延伸已声明）
5. **自解读的循环风险**：AI 自己写提示词又自己循着走，可能形成自我强化的回音室——AI 写的引导可能恰好是自己本来就想到的，不是 JSON 带来的新引导。这需要通过对比"AI 没 JSON 时自由分析的路径"和"AI 有 JSON 时解读出的路径"来检验
