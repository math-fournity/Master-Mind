## 1. Phase 2目标

完成DYN-1（状态重建一致性）和DYN-2（卡点检测校准）。

**DYN-1**：不同抽取器能否一致识别命题、义务、表示、证据和拒绝分支。验收标准：关键状态字段Krippendorff α≥0.80，无关键字段低于0.67。

**DYN-2**：卡点检测能否区分必要探索和真正的停滞。验收标准：测precision、recall、误触发时间和"把正常探索误判为停滞"的比例，误判率低于预注册阈值。

## 5. 逐项实现方案

### P2-1：解析Q_0的Task schema [预期D2]

**做什么**：用128号§3冻结的Ramsey案例作为Q_0，实例化Task对象。

**Q_0内容**（来自128号§3.1）：
- task_id: "Q_0_ramsey_c5"
- type: TaskType.CONJECTURE（猜测R_k(C_5)下界）
- domain: "combinatorics/ramsey_theory"
- objects: ["R_k(C_5)", "C_5", "C_3", "k", "迭代对数"]
- premises: ["R_k(C_3) ≥ k^{k/3-o(k)}", "C_5比C_3更难避免", "上界与迭代对数定义"]
- goal: "猜测R_k(C_5)下界"
- success_conditions: 按conjecture类型——非重复、可证伪、通过初筛且未被反例否定的候选
- stop_conditions: ["预算耗尽", "反复改变指数无进展", "策略耗尽"]
- failure_conditions: ["只改指数不分析底数", "给出答案等价内容"]

**实现**：在`state_reducer/__init__.py`或单独的`q0.py`中定义`create_q0_ramsey()`函数，返回Task对象。

**边界情况**：Q_0在运行时保持冻结（P2-1.COMP3）——用frozen dataclass或运行时检查。

### P2-2：实现V/F/O/R/D/E工作区 [预期D2]

**做什么**：Phase 1已有Workspace/RunState dataclass（models/workspace.py），但只是类型定义。Phase 2需要：
1. 创建ArangoDB collections（workspaces）
2. 实现WorkspaceStore类（create/read/update_workspace）
3. 完善RunState的b_t/B_t/M_t字段

**关键约束**（P2-2.COMP2）：W_t只能由版本化Reducer派生，不能被直接修改。WorkspaceStore.update_workspace应拒绝直接修改W_t，只允许通过Reducer派生。

**实现**：`state_reducer/workspace_store.py`——WorkspaceStore类。

### P2-3：建立AND/OR研究义务 [预期D2]

**做什么**：
1. 定义Obligation dataclass（10种类型枚举 + 9个字段）
2. 实现ObligationExtractor（从SemanticEvent中提取义务关系）
3. 实现ObligationStore（义务图存储 + AND/OR超边）
4. 验证义务图是DAG（含自环检查——Phase 1教训）

**超边存储**（P2-3.COMP）：用relation document + participant edges，不用普通depends_on边。

**实现**：`state_reducer/obligation.py`——ObligationExtractor + ObligationStore。

### P2-4：区分验证核心和猜想前沿 [预期D2]

**做什么**：
1. 在Workspace schema中区分V_t和F_t（Phase 1已有dataclass，Phase 2需要实现分离逻辑）
2. 对Q_0标注哪些义务是验证核心、哪些是猜想前沿
3. 定义F_t进入V_t的验证门（按命题类型选择验证标准）

**关键约束**（P2-4.COMP）：F_t内容进入V_t必须带证据引用，否则触发R-3停止条件。

**实现**：`state_reducer/verification_gate.py`——VerificationGate类。

### P2-5：建立证据状态模型和冲突状态 [预期D2]

**做什么**：
1. 定义Evidence dataclass（12个字段 + 6种kind + 4种status）
2. 实现派生认识状态计算（no_decisive/support_only/refute_only/mixed）
3. 实现冲突检测和冲突状态标记
4. 实现EvidenceStore类（insert/update_status/mark_conflict）

**关键约束**（P2-5.COMP）：证据集合不把数值支持与形式证明排成伪造的总序。

**实现**：`state_reducer/evidence.py`——EvidenceStore + 派生认识状态。

### P2-6：多观察者重建一致性测试 [预期D3]

**做什么**：
1. 实现2个以上独立的StateReducer（不同实现策略）
2. 对同一事件流各自独立重建状态
3. 计算字段级Krippendorff α
4. 记录分歧案例和仲裁结果

**这是DYN-1的核心验收项。**

**实现**：`state_reducer/reducer.py`——StateReducer基类 + 2个独立实现。

### P2-7：卡点类型和校准集 [预期D2/D3]

**做什么**：
1. 定义7类卡点枚举（每类有判定条件）
2. 实现StallDetector类（从事件流和状态中检测卡点）
3. 人工标注校准集（对Q_0的多个运行标注卡点类型）
4. 测precision/recall/误触发时间/误判比例

**这是DYN-2的核心验收项。**

**实现**：`verification/stall_detector.py`——StallDetector + 7类卡点。

### P2-8：控制器信念建模 [预期D2]

**做什么**：
1. 实现BeliefEstimator类（输出b_t的概率分布或不确定性度量）
2. 定义9种动作枚举（Phase 1已有部分，Phase 2完善）

**关键约束**（P2-8.COMP）：控制器不假装读心——只基于公开产物和工具事件做估计。

**实现**：在`state_reducer/reducer.py`或单独的`controller_belief.py`中。

### P2-9：进展偏序定义 [预期D2/D3]

**做什么**：
1. 定义5个可测量分量（v_t/o_t/c_t/u_t/k_t）
2. 实现进展偏序计算函数
3. 区分两种环路（平面环路 vs 螺旋上升环路）
4. 定义状态等价关系`~_{α,κ}`和规范化键（F3修正补充）
5. 定义跨任务比较规则

**实现**：`state_reducer/progress.py`——ProgressOrder + 状态等价。
