## 3. 修正实施

### 3.1 修正A1：自环检查（123号§17）

**要求**：123号§17明确说"数据库只存其无环的直接前驱边，不存自环"。

**修正**：
- `events/store.py` `insert_raw_event`：插入前检查`event_id not in causal_predecessors`，自环则抛出`ValueError`
- `events/store.py` `verify_dag`：添加`self_loop_violations`字段，检查所有事件的自环

### 3.2 修正A2：事件图单调增长模式（系统探讨.md§7.1）

**要求**：系统探讨.md§7.1"即使Agent撤回了一个错误命题，也不应删除历史节点，而是增加：claim C → contradicted_by E → rejected C。事件图单调增长，当前信念集合可以非单调变化，这两层必须分开。"

**修正**：
- `models/event.py`：新增`CLAIM_CONTRADICTED`和`CLAIM_REJECTED`两种RawEventType
- `events/store.py`：新增`record_contradiction`、`record_rejection`、`verify_monotonic_growth`三个方法

### 3.3 修正A3：基础语义抽取器（123号§46/§28）

**要求**：123号§46 Check List"建立语义事件抽取版本" + §28 Event Capture输出"分两层——不可变原始事件和带置信度的语义事件"。

**修正**：
- 新增`events/extractor.py`：`SemanticExtractor`类，规则-based首版实现
- 支持20种RawEventType → SemanticEventType的映射
- 置信度估计（首版规则-based，后续Phase 2需要多观察者一致性测试DYN-1）
- 抽取失败返回None，不丢原始证据（三层保留）

### 3.4 修正A4：基础事件捕获器（123号§46/§28）

**要求**：123号§46 Check List"捕获公开文本和工具事件" + §28 Event Capture输入"Solver公开产物、草稿、工具调用、提示、分支/回退和时间"。

**修正**：
- 新增`events/capture.py`：`EventCapture`类
- 支持10种捕获方法：capture_text_output/text_draft/tool_call/tool_output/code_exec/branch_choice/backtrack/claim/stall/run_start/run_end
- 自动设置causal_predecessors（链接到上一个事件）
- R-1风险防线：只捕获公开产物，不捕获隐藏CoT

### 3.5 修正A5：事件捕获完整度度量（123号§44）

**要求**：123号§44"事件捕获完整度"是Phase 1核心指标。

**修正**：
- `events/store.py`：新增`measure_capture_completeness`方法
- 5个度量维度：
  1. 事件类型覆盖率（实际捕获类型占应捕获类型的比例）
  2. 因果链完整性（有causal_predecessors的事件比例）
  3. 时间戳完整性
  4. 内容哈希完整性
  5. 语义抽取覆盖率
- 总体完整度 = 各维度的最小值（短板效应）

### 3.6 修正A6：checkpoint多continuation验证（123号§39）

**要求**：123号§39"即使温度为0，多个继续运行也可能非确定。实验把同一内容哈希checkpoint视为一个阻断/分层变量。"

**修正**：
- `test_phase1.py`：新增`test_audit_6_checkpoint_multi_continuation`
- 从同一checkpoint创建3个不同continuation（选择A/选择B/放弃两个），验证checkpoint未被修改
