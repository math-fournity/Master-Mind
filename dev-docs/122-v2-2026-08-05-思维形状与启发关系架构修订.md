## 为什么修订

122号v1把数学大师系统整理成知识平面、研究运行平面、控制平面，并指出在线研究主链尚未闭合。但v1仍然默认：数学依赖图是知识平面的中心，研究运行时只需从这张图召回相关子图。

用户现在提出了更深一层的核心理念：

> 思维的形状是能够被看到和引导的。

在这个理念下，数学大师系统不只需要记录“数学上什么依赖什么”，还要记录：

1. Agent在一次真实解题中实际走过什么思维轨迹；
2. Agent在哪个局部形状上停住了；
3. 成功Agent比失败Agent多激活了什么方向；
4. 当未来Agent再次出现类似局部形状时，应给它什么最小启发；
5. 这个启发是否真的因果性地提高成功率，而不是事后看起来相关。

这使122号v1的八组件架构需要修订。数学大师系统的核心不应只有“知识依赖图”，还应增加“外显思维图”和“启发激活图”。

## 摘要

### 一句话结论

**数学大师系统真正要工程化的，不只是数学知识之间的依赖，而是“当Agent的当前思维呈现某种带标注的局部形状时，系统能识别这个形状，并激活一个经过验证、足够小且不直接泄漏答案的方向”。**

### v2的核心架构修正

系统至少需要三种不同的图：

1. **数学知识图 $K$**：记录数学对象、定理、方法之间客观或经过审核的关系；
2. **外显思维图 $T$**：记录某个Agent在某次研究运行中实际表达出来的思维轨迹；
3. **启发激活图 $H$**：记录“看到什么模式，在什么上下文和时机，应激活什么方向”的条件关系。

原来的稀疏矩阵，最接近的不是整张数学知识图 $K$，而是启发激活图 $H$：

```text
看到 P  → 想到 X
看到 P 和 R，并且处于上下文 C、停滞状态 F → 激活 X、S、T
```

Agent M不是一次性读取一份大提示词，而是一个闭环系统：

```text
独立尝试
→ 形成外显思维图
→ 检测停滞或缺口
→ 在启发图中匹配当前局部形状
→ 注入最小启发
→ 从当前状态继续思考
→ 验证是否取得进展
→ 更新启发关系的证据
```

## 一、核心公理：思维形状可观测、可比较、可干预

### 1.1 “思维有形状”是什么意思

这里的“形状”不是比喻性的装饰，而是指一次研究过程可以被外显为带标注的图：

- Agent看到了哪些事实；
- 提出了哪些子目标；
- 调用了哪些概念和方法；
- 做了哪些变换、类比和检验；
- 哪些分支继续推进；
- 哪些分支被否定或回退；
- 在哪里重复、停滞或矛盾；
- 最后是否到达答案。

如果这些内容能被编码成节点、边、标签和时间顺序，那么它们就具有可比较的形状。

### 1.2 我们看到的不是LLM内部大脑，而是外显投影

必须诚实区分：

- LLM内部真实激活状态通常不可见；
- Agent输出的思考文本、草稿、工具调用、中间命题和回退记录，是内部过程的一个外显投影；
- 外显投影可能不完整，也可能带有事后解释。

因此，本系统不声称“读取了LLM真正的内心思维”。系统建模的是：

> **可观测、可复现、可干预的外显研究轨迹。**

只要这个外显图能够预测Agent何时会失败，并且基于它的干预能稳定提高成功率，它就具有工程价值，不需要先证明它等同于模型的全部内部机制。

### 1.3 三个可证伪假设

| 假设 | 内容 | 如何证伪 |
|---|---|---|
| A1 可观测性 | 失败与成功轨迹存在稳定、可标注的结构差异 | 同类运行的轨迹无法稳定提取或对齐 |
| A2 可引导性 | 在关键差异点注入最小启发，能提高成功率 | 注入后没有增益，或只在原题上有效 |
| A3 可迁移性 | 某些“形状→启发”关系能跨题、跨模型复用 | 关系只适用于一条具体答案链，无法泛化 |

如果三者都不成立，“思维形状可被看到和引导”就只是漂亮比喻，而不是可运行架构。

## 二、题目不是静态文本，而是动态研究状态

### 2.1 原题只是初始状态

通常把题目写成固定的 $Q$。但Agent开始思考后，实际面对的任务已经变了：

- 它知道了新的中间结论；
- 排除了一些候选；
- 产生了新的子目标；
- 获得了工具输出；
- 暴露了自己的误区和卡点。

因此，第 $t$ 时刻的真实题目应写成：

$$
Q_t = Q_0 \oplus T_{0:t} \oplus E_{0:t} \oplus U_t,
$$

其中：

- $Q_0$：原始题面；
- $T_{0:t}$：截至当前的外显思维轨迹；
- $E_{0:t}$：工具、文献或审计证据；
- $U_t$：仍未解决的子目标、矛盾和停滞信号。

### 2.2 任意中间状态都可以重新成为一道题

把原题、已有推理、工具结果和当前卡点拼在一起，就得到一份新的问题状态。未来Agent不必从头解原题，而可以接着这个状态继续研究。

这意味着数学大师系统不是一次性prompt生成器，而是一个**过程性控制器**：它在每个状态重新判断“现在应该想到什么”。

### 2.3 对上下文编译器的修正

122号v1中的上下文编译器不能只在任务开始时工作一次。它应当在每次状态变化后增量工作：

```text
Q_t + 当前思维图T_t
→ 匹配启发关系
→ 选择最小激活包
→ 编译为增量提示
→ 生成Q_(t+1)
```

## 三、三图模型：K、T、H必须分开

### 3.1 数学知识图 $K$：数学世界是什么

$K$记录相对稳定、经过审核的数学关系：

- 定理依赖哪些引理；
- 方法适用于哪些结构；
- 一个结果推广、反驳或特化了什么；
- 哪些领域存在对偶、等价或类比；
- 哪些工具能够验证某类命题。

示例：

```text
谱定理 requires 内积空间 + 自伴算子
Cayley-Hamilton can_be_proved_by 伴随矩阵恒等式
局部-全局原理 applies_to 数论/代数几何/拓扑
```

它回答的是：

> 数学上，哪些对象和关系存在？

### 3.2 外显思维图 $T_i$：这次Agent实际上怎么想

每一轮运行 $i$ 都有自己的思维图 $T_i$。它不是规范知识，而是事件记录。

节点可以是：

| 节点类型 | 含义 | 示例 |
|---|---|---|
| observation | 从题面或证据中注意到的事实 | “上界指数是k/2” |
| claim | 当前认为成立的命题 | “C5下界应比C3下降” |
| representation | 当前采用的表示 | “把k^(k/3)拆成底数和指数” |
| subgoal | 需要解决的子问题 | “变化的是底数还是指数？” |
| candidate | 候选答案或方法 | “k^(k/6)” |
| operation | 正在尝试的思维动作 | “做极端检验” |
| tool_result | 工具返回 | “数值比较显示候选差距巨大” |
| contradiction | 发现冲突 | “候选与已知上界不相容” |
| stall | 停滞或重复 | “仍只在调整指数” |
| resolution | 已解决的局部结论 | “应改变底数而非指数” |

边可以是：

- `notice`：从题面注意到；
- `infer`：从前提推出；
- `recall`：联想到知识；
- `transform`：更换表示；
- `decompose`：拆子问题；
- `compare`：比较候选；
- `test`：做数值/极端/反例检验；
- `reject`：排除分支；
- `backtrack`：回退；
- `generalize`：推广；
- `analogize`：跨领域类比；
- `ask_for_hint`：触发外部启发；
- `activate`：提示后激活新方向。

每个节点和边还需要：时间、来源、置信度、状态、上下文、运行ID和模型版本。

它回答的是：

> 这一次，Agent实际走了哪条路？

### 3.3 启发激活图 $H$：什么时候应该想到什么

$H$保存的不是数学真理，也不是某次轨迹，而是经过实验验证的“触发→激活”关系。

最简单的启发：

$$
P \rightarrow X.
$$

含义不是“P逻辑推出X”，而是：

> 当当前思维状态出现模式P时，提醒Agent把X加入候选思考空间，可能提高继续推进的机会。

高阶启发：

$$
(P,R,C,F,\tau) \rightarrow (X,S,T),
$$

其中：

- $P,R$：当前已出现的多个模式；
- $C$：数学上下文；
- $F$：失败或停滞类型；
- $\tau$：时序条件；
- $X,S,T$：应被激活的概念、操作、表示或子目标集合。

它回答的是：

> 当Agent走到这种局部形状时，给它什么方向最可能有帮助？

### 3.4 三张图之间的关系

```text
数学知识图 K
  提供可激活的概念、方法、工具和关系
          │
          ▼
启发激活图 H：匹配(T中的局部模式) → 选择(K中的激活包)
          │
          ▼
外显思维图 T：记录提示前后Agent实际发生了什么
          │
          └──── 结果反过来更新H的证据
```

三图不能混成一张：

- $K$中的边可以是客观依赖；
- $T$中的边是一次运行发生过的事件；
- $H$中的边是条件化干预策略。

当前 `dg_edges` 同时承担知识依赖、解法路径和意识调用，正是122号v1发现模式分裂的深层原因。

## 四、P→X的数学本质：不是普通边，而是带条件的图改写

### 4.1 把多元关系化成高阶二元关系是成立的

用户提出：

```text
PR = (P,R)
XST = (X,S,T)
PR → XST
```

从集合论角度，这完全成立。任意多元关系都可以通过元组化、柯里化或关系重述，变成两个复合对象之间的关系。

因此可以把启发图抽象为：

$$
H \subseteq \mathcal{P} \times \mathcal{A},
$$

其中：

- $\mathcal{P}$：可识别的思维模式空间；
- $\mathcal{A}$：可注入的激活包空间。

模式识别于是成为一种广义二元关系：

$$
\text{看到模式} \longrightarrow \text{激活方向}.
$$

### 4.2 工程上不能把所有组合都压成一个复合节点

虽然数学上可以把 $(P,R)$ 看作一个节点，但如果每种组合都创建新节点，会产生组合爆炸：

- P单独出现时可能已经有弱提示价值；
- R单独出现时也可能有价值；
- P和R以不同顺序出现时含义不同；
- P、R、C、F的组合数量会指数增长；
- 复合节点会丢失内部结构，不利于跨题泛化。

因此推荐：

- 原子模式保留为独立特征；
- 多条件启发用**超边、因子或带guard的规则**表示；
- 查询时做子图模式匹配和条件合取；
- 只有高频稳定组合才物化为复合模式。

### 4.3 更准确的形式是图改写规则

每条启发可以写成：

```text
LHS：当前思维图中应出现的局部子图
Guard：上下文、时序、模型、失败类型等条件
RHS：应加入的概念/子目标/操作/工具节点和连接
```

形式上：

$$
(L,\; guard) \Rightarrow R.
$$

这不是把答案写进去，而是当左侧形状出现时，对当前思维图做最小扩展。

### 4.4 时序不能只当普通tag

以下两种情况不一定等价：

```text
先看到P，再经过两次失败才看到R
先看到R，随后立即看到P
```

因此启发关系还应支持：

- 先后顺序；
- 时间间隔；
- 重复次数；
- 已尝试但失败的操作；
- 当前路径深度；
- 是否发生回退。

时序模式本质上是对路径或事件序列的匹配，不只是节点集合匹配。

## 五、X不是答案，而是“激活包”

### 5.1 X可以是什么

X不应被限制为一个数学概念。它可以是：

- 一个概念：“考虑迭代对数”；
- 一个表示：“把表达式拆成底数和指数”；
- 一个操作：“比较多个候选而不是只检验一个”；
- 一个子目标：“先判断变化的是底数还是指数”；
- 一个意识：“做极端检验”；
- 一个工具：“对三个候选做数值数量级比较”；
- 一个反例方向：“尝试最小退化构型”；
- 一个跨领域类比：“把矩阵问题改写成模问题”。

因此推荐把右侧称为**激活包**，而不是答案节点。

### 5.2 激活包的最小性

系统应优先提供能造成进展的最小提示，而不是一次性给出全部后续路径。

可以使用不与现有L1/L2/L3冲突的H级别：

| 级别 | 提示内容 | 示例 | 泄漏风险 |
|---|---|---|---|
| Hint-0 | 只提示检查类型 | “你是否混淆了上界与下界？” | 很低 |
| Hint-1 | 提示思维操作 | “把底数和指数分开分析” | 低 |
| Hint-2 | 提示候选工具/概念 | “考虑迭代对数是否适用” | 中 |
| Hint-3 | 提示确定关系 | “底数可能下降一层对数” | 高 |
| Hint-4 | 给出最终形式或答案 | “答案是(log k)^(k/3)” | 直接答案 |

默认策略应从Hint-0开始，只有没有进展时逐级增加。

### 5.3 启发关系不应是布尔值

稀疏矩阵的格子不应只存0/1。每条启发至少要记录：

- 匹配条件；
- 激活包；
- 推荐H级别；
- 适用问题类型；
- 适用模型/版本；
- 触发时机；
- 成功提升；
- 证据运行数；
- 迁移范围；
- 泄漏风险；
- 失败案例；
- 当前审核状态。

因此它在实现上更像稀疏超图、稀疏张量或规则图，而不是普通二维0/1邻接矩阵。

## 六、如何从Agent A和Agent B发现P→X

### 6.1 理想化差分

设：

- $T_A$：失败Agent A的外显思维图；
- $T_B$：成功Agent B的外显思维图。

先对齐两张图：

1. 找共同观察、共同中间结论和共同操作；
2. 找最后一个稳定共同状态；
3. 找第一个关键分叉；
4. 识别B新增的X、表示变换、检验或子目标；
5. 识别A缺少的边或反复停滞形状。

候选启发可以写成：

```text
T_A局部形状中出现P，但没有激活X
T_B在同类局部形状中由P激活X，并最终成功
候选关系：P → X
```

### 6.2 现实中“其他都一样”通常不成立

LLM具有随机性。A和B可能在很多地方不同，成功不一定由X造成。因此单次轨迹差分只能产生**候选启发**，不能直接写入生产启发图。

### 6.3 相关性必须通过干预变成因果证据

验证P→X的关键实验是：

1. 选取多个会在P处停滞的A型运行；
2. 在相同或等价状态注入不超过预定H级别的X提示；
3. 设置未提示对照组；
4. 比较提示组是否更频繁越过卡点、找到正确方向或完成解答；
5. 在新的同类题上复测；
6. 审计提示是否直接泄漏答案。

只有当干预稳定产生增益时，P→X才从“相关观察”升级为“有因果证据的启发关系”。

### 6.4 启发关系的生命周期

```text
observed       从A/B轨迹差分中观察到
candidate      已抽取为候选关系
intervened     已做最小提示干预
validated      在原问题族重复验证
transferred    在新问题上迁移验证
published      进入生产启发图
retired        新模型已学会或关系被反例否定
```

模型升级后，某些启发可能不再需要；另一些启发可能只对特定模型有效。因此启发图必须版本化，不能假设永恒有效。

## 七、Agent M的真实运行方式

### 7.1 闭环总览

```text
1. 接收初始题目Q0
2. 独立尝试，不预先灌入全部启发
3. 持续形成外显思维图T_t
4. 检测停滞、重复、矛盾或主动求助
5. 从T_t提取局部模式P_t
6. 在启发图H中匹配规则
7. 从知识图K取得候选激活包
8. 选择最低有效H级别
9. 把增量提示编译进动态题目Q_(t+1)
10. Agent从当前状态继续，而不是从头重做
11. 工具和审计判断是否取得真实进展
12. 更新该启发关系的效果证据
```

### 7.2 两种运行模式

| 模式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 反应式救援 | Agent先独立思考，明确停滞后才提示 | 最少干扰，容易做因果实验，答案泄漏风险低 | 可能浪费前期探索，停滞检测不准时会延迟 |
| 主动式导航 | 一看到高置信模式P就提示X | 效率高，可提前避开已知死路 | 容易过度提示，让Agent失去独立发现机会 |

**推荐**：第一阶段以反应式救援为主。推荐理由：当前项目最需要先证明“某个启发是否真的造成增益”，而不是追求最快解题；反应式模式最容易形成清楚的A/B因果证据。高置信、跨题稳定的关系以后再升级为主动导航。

### 7.3 停滞信号

停滞不等于“没有最终答案”。可检测的信号包括：

- 重复同一个候选但没有新证据；
- 多轮只修改同一个参数；
- 已发现矛盾却继续沿原路径；
- 工具结果与当前结论冲突；
- 子目标长期没有出边；
- 多个分支都回到同一状态；
- 明确表达“不知道下一步”；
- 输出停止但仍有未解决目标。

### 7.4 提示后必须从当前状态继续

如果每次提示后都让Agent从原题重做，就无法判断启发是否修复了具体缺口。系统应保存checkpoint：

- 提示前思维图；
- 触发模式；
- 注入内容；
- 提示后新增节点和边；
- 是否越过卡点；
- 最终结果。

## 十、最小可证伪POC

### 10.1 目标

验证：

> 从失败/成功轨迹中发现并通过干预验证的启发关系，能否在不给出答案的情况下，提高A型Agent越过同类卡点的概率。

### 10.2 实验步骤

1. 选择一个可重复产生失败A和成功B的题目族；
2. 冻结模型、配置、题面和工具权限；
3. 运行多次无提示解答，收集成功与失败轨迹；
4. 把轨迹转成统一外显思维图；
5. 对齐A/B图，找候选P→X；
6. 给候选X设计Hint-0-Hint-2最小提示，不使用Hint-3/Hint-4；
7. 在新的A型运行中做干预；
8. 设置无提示对照；
9. 盲评是否越过卡点、是否正确、是否出现副作用；
10. 在同类新题上做迁移测试；
11. 只有重复增益且无答案泄漏时，才把关系升级为validated。

### 10.3 主要指标

- 卡点越过率；
- 完整解题成功率；
- 数学正确率；
- 提示后的新增有效节点/边；
- 提示级别；
- 答案泄漏风险；
- 跨题迁移增益；
- 对不同模型版本的稳定性；
- 无关分支或误导副作用。

### 10.4 与现有POC的关系

POC-1已经给出一个候选案例：A虽然做数值检验，却没有系统区分上界与下界；B在“数值检验意识”和螺旋提示下成功。它可以被重新解释为候选启发：

```text
模式P：发现原指数错误 + 使用极端构型 + 把构型上界当成目标下界
激活X：区分“候选构型给上界”与“命题要求统一下界”，并系统比较多个指数
```

但85号原实验只有单次运行，B组还得到具体构造提示，不能直接证明P→X的因果性。需要按121号证据标准重做。

## 十一、这个模型对原始信念的深化

### 11.1 稀疏矩阵真正记录的是什么

63号文档把矩阵解释为“分析时刻×知识/意识”的激活关系。v2进一步把它解释为：

> **当前外显思维形状×候选激活包，在上下文、时序和失败状态下的条件化关系。**

因此稀疏矩阵不是知识目录，也不是固定解法表，而是可验证的启发策略空间。

### 11.2 “大师的一次在场”可以部分转化为经验发现

原系统认为依赖边需要大师手工写入。新模型增加了一条生长路径：

```text
失败轨迹A + 成功轨迹B
→ 候选启发关系
→ 最小提示干预
→ 重复验证
→ 发布到启发图H
```

这不等于完全消除大师：

- 轨迹标签可能需要高水平判断；
- 候选X是否只是答案泄漏需要审核；
- 迁移边界需要数学理解；
- 生产发布仍需质量门。

但它让启发关系不再只能来自大师事前直觉，还可以来自真实成功/失败案例的经验差分。

### 11.3 综述博士和论文博士之间出现了桥

系统仍主要工程化综述博士，即已有启发的稳定调用。但当Agent B发现了图中没有的新P→X，并且这个关系通过干预和迁移验证后，系统就获得了一条新启发。

这不是完整的论文博士，却已经形成：

> 发现候选连接 → 证伪/验证 → 吸收为新启发

的受控创新入口。

## 十二、必须警惕的边界

1. **外显轨迹不等于真实内部思维。** 只把它当作可干预的行为模型。
2. **B用了X不等于X造成成功。** 必须做干预实验。
3. **P→X不一定通用。** 它可能依赖问题族、模型、提示格式和时间位置。
4. **复合节点会组合爆炸。** 多元启发优先用超边和guard表示。
5. **启发不能变成答案库。** 默认使用最低H级别，严格审计泄漏。
6. **过早提示会损害独立探索。** 第一阶段优先反应式救援。
7. **成功率不是唯一指标。** 还要看数学正确性、迁移、副作用和提示成本。
8. **思维图提取器本身可能误标。** 图抽取质量也必须有一致性和人工抽查。
9. **模型升级会改变缺口。** 新模型可能已经学会P→X，旧启发应退役或降权。
10. **“所有启发”不可穷尽。** 系统只能持续积累被观察、验证和发布的启发关系。

## 十三、结论 / 决策

1. **“思维的形状能够被看到和引导”正式提升为数学大师系统的基础公理，但“看到”限定为可观测的外显研究轨迹。**
2. **数学大师系统必须从单一依赖图升级为三图模型：数学知识图K、外显思维图T、启发激活图H。**
3. **稀疏矩阵的核心含义修正为条件化启发关系：当前思维模式→候选激活包，而不只是知识依赖。**
4. **题目是动态状态Q_t；Agent M应当独立尝试、检测卡点、匹配启发、注入最小提示并从checkpoint继续。**
5. **P→X只能从轨迹差分产生候选，必须经过最小提示干预才能获得因果证据。**
6. **多元和时序关系数学上可重述为高阶二元关系，工程上应保留内部结构，使用超边、guard和图模式匹配。**
7. **122号v1八组件修正为十组件，新增Thought Trace Modeler和Heuristic Activation Engine。**
8. **下一步不应立即构建大规模启发库，而应先做一个最小可证伪的A/B轨迹差分与干预POC。**
