## 两件事的定义

### 第一件事：去特化

之前POC中的tell是特化的——我作为辅助Pipe人工读thinking，用数学直觉判断"AI没走什么路"。这个判断是Level 0的（题目特化），不可泛化。

去特化要做的是：把tell从Level 0（题目特化）提升到可泛化的Level，使tell可以被穷举。

**穷举是降低tell识别难度的手段**——就像281号把"翻译语言"这个高Level hint展开成24个具体翻译方向一样，tell也需要被穷举成一组可枚举的模式。当初hint level太高推理AI不知所措，现在tell如果识别难度太高，负责识别tell的整套机制就无法有效地识别出推理AI上下文中应该被识别出来的各种tell。

### 第二件事：规模检索

去特化后的tell规模会很大——10万级别是一个虚数，意思是**不能假设系统的全部tell可以放入辅助AI的上下文中**，不能假设辅助AI可以暴力遍历所有tell，对照着推理AI的上下文去识别各个tell是否出现了。

**必须用其他手段（Pipe）将最终需要辅助AI去遍历的tell数量降低到一个合理的量级。**

这个"合理量级"的定义不是绝对数量，不是比例，而是**合理程度**：
- 确实其他手段、Pipe都上了，但如果继续过滤，真的会漏掉tell
- 所以会有一些tell，虽然不应该被识别到，但也送给辅助AI进行分析了
- 如果无效tell占比太高，可以去优化
- **初始的无效tell比例可以定为50%**——即送入辅助AI的tell中，允许最多50%是无效的（不应该被识别到但也被送进来了）

## 核心结构定义

### tell和hint的关系：多对多

tell和hint是多对多关系：
- 一个tell可以对应多个hint（同一个分叉信号可以触发多个不同的翻译方向）
- 一个hint可以被多个tell触发（同一个翻译方向可以在不同的分叉信号下被触发）

### tell可以穷举

tell可以穷举——穷举是降低tell识别难度的手段。就像hint端的24个翻译方向是从"翻译语言"这个高Level方向展开的，tell端的模式也是从某种高Level结构展开成可枚举的具体形式。

### 规模检索的分层架构

**核心原则1（用户第三次原文）**：识别已经用穷举的方式降低了思维难度的海量tell，绝对不能只依靠辅助AI或subagent去暴力遍历整个数据基座中对tell集合的积累。而是**首先要用其他技术手段，尤其是形式化的技术手段，缩小最终要提交给辅助AI或subagent去具体查看的tell的范围**。

**核心原则2（用户第四次原文）**：由于借鉴了hint降低Level的做法，形式化可以帮到tell端。就像hint有清晰可辨的结构和标注、可以分领域low level化一样，tell未来也是有清晰可辨的结构和标注的，有些tell也可以分领域low level化。**首先对推理AI的thinking做的第一件事，是将它按照系统使用和定义的标准方法，变成带有结构和标注的拓扑结构（或拓扑结构的集合），然后利用拓扑相似、拓扑等价对数据基座中的tell积累进行过滤。**这能极大地降低筛选出来的结果的数量，或者说提升有效tell在筛选后结果集合中的比例。

```
推理AI的上下文（含Thinking）
     │
     ▼
[Pipe 0] 拓扑化——将thinking变成带有结构和标注的拓扑结构（或拓扑结构的集合）
     │  按照系统定义的标准方法，将自然语言thinking编码为结构化拓扑
     │  这是Pipe 1过滤的前提——没有结构化拓扑就无法做拓扑相似/等价匹配
     ▼
[Pipe 1] 形式化过滤——利用拓扑相似/拓扑等价缩小tell范围（必须先做）
     │  将Pipe 0产出的拓扑结构与数据基座中tell积累的拓扑标注做匹配
     │  从10万级tell中筛出一部分候选
     │  允许无效tell进入（初始无效比例≤50%）
     │  但不能漏掉真tell
     ▼
[Pipe 2] 辅助AI/subagent——在缩小的范围内具体查看
     │  遍历Pipe 1筛出的候选tell
     │  对照推理AI的上下文判断每个tell是否真的出现了
     ▼
识别出的tell → 多对多映射 → hint方向 → 启动新AI
```

**关键约束**：
- **Pipe 0（拓扑化）是Pipe 1的前提**——thinking必须先被变成带有结构和标注的拓扑结构，才能做拓扑相似/等价匹配。这和hint端的做法对称——hint分领域low level化后有清晰结构和标注，tell也分领域low level化后有清晰结构和标注。
- **Pipe 1（形式化过滤）是必须先做的**——不能跳过Pipe 1直接让辅助AI暴力遍历全部tell。Pipe 1用拓扑相似/等价缩小范围，这是架构上的硬约束，不是优化选项。
- Pipe 1的目标是**不漏**——可以多送（无效tell≤50%），但不能少送（不能漏掉真tell）
- Pipe 2（辅助AI/subagent）的目标是**精准**——从Pipe 1缩小的范围内精准识别出真tell
- 初始允许无效tell比例≤50%——后续可以优化Pipe 0的拓扑化精度和Pipe 1的过滤精度

**tell和hint的结构对称性**：

| | hint端 | tell端 |
|---|---|---|
| 原始形态 | 高Level方向（"翻译语言"） | 高Level缺口（"方法-问题不匹配"） |
| Low Level化 | 分领域展开成24个翻译方向 | 分领域展开成可枚举的tell模式 |
| 结构和标注 | 每个方向有领域标签+翻译类型 | 每个tell有领域标签+拓扑标注 |
| 检索方式 | 从题目元数据匹配方向 | 从thinking拓扑匹配tell拓扑 |
| 过滤手段 | task_type+group_order硬筛 | 拓扑相似/拓扑等价 |
