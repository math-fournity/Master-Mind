## 3. 融合方案：后续每个POC实验如何与树生长结合

### 3.1 POC-VMS-2：小规模检索验证（10个Pattern）

**树生长方式**：检索介入时树分叉

```
根节点（新虚拟题）
  ├─ 方向A（检索到Pattern: 元素阶计算）
  │   └─ AI-1探索此方向
  │      └─ ...
  └─ 方向B（检索到Pattern: Python暴力枚举）
      └─ AI-2探索此方向
         └─ ...
```

**具体操作**：
1. 选10道新虚拟题（不在预演集中的题）
2. 对每道题：
   a. 在ArangoDB创建problem + 根节点
   b. 启动AI-1裸跑（作为baseline对照）
   c. 在根节点上做检索（用22个Pattern）
   d. 对每个检索到的方向，启动新AI实例（给它脉络+方向Q）
   e. 实时采集所有AI的trajectory，提取节点，更新树
   f. 某条脉络到达正确解答时停机
3. 对比：裸跑AI vs 有检索引导的AI，谁先解出来/谁解得更完整

**树在ArangoDB中的状态**：
- 每道题一棵树
- 树有分叉（不同检索方向→不同AI→不同分支）
- 叶节点有leaf_success/leaf_deadend/leaf_truncated

### 3.2 POC-VMS-3：大规模检索验证（10000+ Pattern）

**树生长方式**：大规模并发展开

**具体操作**：
1. 生成10000+虚拟题（从100个群×更多题目类型）
2. 对每道题启动树生长引擎主循环
3. 并发管理多个AI实例（5个并发额度）
4. 实时采集、实时整理树、实时检索、实时分配

**树在ArangoDB中的状态**：
- 10000+棵树
- 每棵树有多个分叉
- 数据基座中的Pattern被大量检索和使用

### 3.3 POC-VMS-4：核心验证——树→Pattern→树自我增殖

**树生长方式**：完成的树提炼新Pattern，新Pattern驱动新树生长

**具体操作**：
1. 从POC-VMS-3的10000+棵树中提炼新Pattern
2. 新Pattern加入数据基座
3. 用新数据基座重新解一批题
4. 验证：新数据基座是否让树长得更快更准

**树在ArangoDB中的状态**：
- 树不仅生长，还产出Pattern（树→Pattern→树闭环）
- Pattern库从22个增长到数百个

## 4. 树生长引擎的渐进式打磨

### 4.1 当前版本（POC-VMS-0/1回填版）

- **节点提取**：从thinking_readable.txt用regex解析，关键词匹配识别思维操作
- **边创建**：线性链，边=AI从一个思维操作转到下一个
- **局限**：只有线性链，没有分叉；节点提取依赖关键词匹配，不够精确

### 4.2 POC-VMS-2版本

- **节点提取**：同上，但实时提取（AI运行中就提取，不等结束）
- **边创建**：有分叉——检索到的每个方向Q创建一条边
- **新增**：脉络构造（从根到当前节点的路径文本，给新AI）
- **新增**：停机判定（检测AI是否给出正确答案）

### 4.3 POC-VMS-3版本

- **节点提取**：用DevinCliParserProvider提取六元组（V_t/F_t/O_t/U_t/T_t/S_t）
- **边创建**：同上，但支持大规模并发
- **新增**：并发AI管理（5个并发额度，自动分配）
- **新增**：实时树可视化（AQL查询树结构）

### 4.4 POC-VMS-4版本

- **新增**：从完成的树提炼新Pattern（树→Pattern）
- **新增**：Pattern质量评估（哪些Pattern被频繁使用、哪些有效）
- **新增**：Pattern去重和合并

## 5. 每个实验的标准流程（融合版）

后续每个POC实验都遵循以下流程：

```
1. 准备阶段
   - 生成虚拟题
   - 在ArangoDB创建problem记录

2. 启动阶段
   - 启动AI实例（通过solver-harness）
   - 在ArangoDB注册ai_instance
   - 创建根节点（tree_nodes, node_type=root）

3. 运行阶段（实时）
   - 采集AI的thinking（mitmproxy）
   - 从thinking提取新节点（node_extractor）
   - 在ArangoDB创建新节点和边
   - 更新AI的nodes_contributed

4. 检索阶段（在节点上）
   - 从数据基座检索Pattern
   - 在ArangoDB标记retrieval_done + directions_identified
   - 对每个方向启动新AI实例

5. 停机阶段
   - 检测AI是否给出正确答案
   - 标记leaf_success/leaf_deadend
   - 更新problem状态为solved
   - 记录solution_path

6. 产出阶段
   - 从完成的树提炼Pattern（POC-VMS-4+）
   - Pattern加入数据基座
```
