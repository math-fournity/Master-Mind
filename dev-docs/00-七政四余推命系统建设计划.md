## 一、终态目标

建设一个 **"代码精确排盘 + 规则库可审计 + AI 智能判读"** 的七政四余推命系统。

### 核心特征

1. **精确性**：天文计算由 Swiss Ephemeris 保证，不是人手翻表
2. **完备性**：星盘包含推命所需的全部参数，不缺项
3. **可审计**：每条命理判断都引用具体规则 + 具体数据，不是 AI 凭空联想
4. **可追溯**：规则来源明确（果老星宗卷几 / 星学大成卷几 / EvalRule 第几条）
5. **矫正能力**：对出生时间存疑的命主，能通过数值优化 + AI 判断联合矫正
6. **择日能力**（可选）：基于协纪辨方书的规则库，支持择日功能

### 终态工作流

```
输入：出生年月日时 + 出生地经纬度
     ↓
[代码层] 排盘引擎
     → 完整星盘 JSON（行星/宫位/宿度/化曜/神煞/庙旺/格局/限运）
     → 全部客观数据，精确到度分秒
     ↓
[知识层] 规则库查询
     → 根据星盘数据，查询命理规则库
     → 返回匹配的规则 + 断语 + 格局判定
     → 标注每条规则的来源
     ↓
[AI 层] 命理分析
     → AI 基于星盘 JSON + 规则库匹配结果
     → 产出命理分析报告：
       - 性格/六亲/事业/财运/婚姻/健康
       - 大限走势（每限吉凶）
       - 流年运势
       - 格局成破
       - 每条判断都引用具体规则和数据
     ↓
输出：结构化命理分析报告（可审计、可追溯）
```

### 与现有软件的区别

| 维度 | 现有软件（MOIRA/馥灵之钥等） | 本项目终态 |
|---|---|---|
| 排盘 | 画图给人看 | JSON 给 AI 看 |
| 分析 | 人脑判读 | AI + 规则库判读 |
| 规则 | 代码黑箱 | 结构化规则库，可审计 |
| 矫正 | 手动微调 | 数值优化 + AI 联合 |
| 输出 | 图形界面 | 结构化报告 + 可追溯引用 |

## 四、优先级与依赖关系

```
Phase 1（补全排盘）──┐
                     ├──→ Phase 3（格局分析）──→ Phase 5（规则引擎）──→ Phase 6（AI 分析）
Phase 2（命理参数）──┘                                                      ↑
                                                                            │

Phase 7（择日）── 独立，可并行
```

**关键路径**：Phase 1 → Phase 2 → Phase 3 → Phase 5 → Phase 6

**最大风险节点**：Phase 5（EvalRule 研究）——如果 EvalRule 包含完整的星格/神煞/判读规则，规则库就有源；如果只是简单条件判断，需要从典籍重新构建。

## 七、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| EvalRule 规则过于复杂，无法提取 | 中 | 高 | 从典籍重新构建规则库，不依赖 EvalRule |
| 二十八宿宿度需要岁差修正 | 高 | 中 | 使用 pyswisseph 的恒星位置 API |
| 农历转换算法复杂 | 中 | 中 | 考虑用现有的农历库（lunarcalendar/sxtwl） |
| 神煞数量庞大，提取耗时 | 高 | 低 | 分批提取，先提取核心神煞 |
| AI 分析层 prompt 设计困难 | 中 | 中 | 迭代设计，用真实命例测试 |
