## 一、终态目标

建设一个 **"代码精确排盘 + 规则库可审计 + AI 智能判读"** 的七政四余推命系统。

### 核心特征

1. **精确性**：天文计算由 Swiss Ephemeris 保证，不是人手翻表
2. **完备性**：星盘包含推命所需的全部参数，不缺项
3. **可审计**：每条命理判断都引用具体规则 + 具体数据，不是 AI 凭空联想
4. **可追溯**：规则来源明确（果老星宗卷几 / 星学大成卷几 / EvalRule 第几条）
5. **矫正能力**：对出生时间存疑的命主，能通过数值优化 + AI 判断联合矫正
6. **择日能力**（可选）：基于协纪辨方书的规则库，支持择日功能

### 终态工作流

```
输入：出生年月日时 + 出生地经纬度
     ↓
[代码层] 排盘引擎
     → 完整星盘 JSON（行星/宫位/宿度/化曜/神煞/庙旺/格局/限运）
     → 全部客观数据，精确到度分秒
     ↓
[知识层] 规则库查询
     → 根据星盘数据，查询命理规则库
     → 返回匹配的规则 + 断语 + 格局判定
     → 标注每条规则的来源
     ↓
[AI 层] 命理分析
     → AI 基于星盘 JSON + 规则库匹配结果
     → 产出命理分析报告：
       - 性格/六亲/事业/财运/婚姻/健康
       - 大限走势（每限吉凶）
       - 流年运势
       - 格局成破
       - 每条判断都引用具体规则和数据
     ↓
输出：结构化命理分析报告（可审计、可追溯）
```

### 与现有软件的区别

| 维度 | 现有软件（MOIRA/馥灵之钥等） | 本项目终态 |
|---|---|---|
| 排盘 | 画图给人看 | JSON 给 AI 看 |
| 分析 | 人脑判读 | AI + 规则库判读 |
| 规则 | 代码黑箱 | 结构化规则库，可审计 |
| 矫正 | 手动微调 | 数值优化 + AI 联合 |
| 输出 | 图形界面 | 结构化报告 + 可追溯引用 |

## 四、优先级与依赖关系（审计后更新 2026-07-15）

```
Phase 1（补全排盘）──┐
                     ├──→ Phase 3（格局分析骨架）──→ Phase 3.5（Java审计✅）──→ Phase 4（基础层补全）──→ Phase 5（核心层补全）──→ Phase 7（AI 分析层）

                                                                                                                                    │
Phase 6（扩展层）────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘

Phase 8（择日）── 独立，可并行
```

**关键路径**：Phase 1 → Phase 2 → Phase 3 → Phase 3.5 → Phase 4 → Phase 5 → Phase 7

**最大风险节点**：Phase 4.4 神煞完整体系（P1）——它被八字/流年/规则引擎三个核心功能块依赖，是最大解锁点。

**审计后新增的关键依赖**：
- 规则引擎求值器（P7）依赖符号表（P5）+ 内置函数（P6），而符号表又依赖神煞体系（P1）+ 八字（P2）+ 弱宫强宫（P3）+ 流年神煞（P4）
- 这意味着规则引擎的完整实现需要先完成 Phase 4 全部 + Phase 5.1-5.2，才能开始 Phase 5.3-5.5
