## 摘要

数学大师系统是一个引导式数学解题系统：做题AI（推理智能体）在数学题前可能卡住，引导者AI（辅助智能体）发送元认知提示（Q）来激活做题AI的思维。这些"什么时候该提示什么"的经验以Pattern的形式存储在认知图（稀疏矩阵/数据基座）中。**核心问题是：当做题AI停在某个状态时，系统如何从海量Pattern存储中找到此刻应考虑的方向？**

本文综述了数学大师系统四代演进（盘古→女娲→燧人→伏羲）中与检索问题相关的全部设计，按三层（状态感知/Pattern提取/知识悖论）组织。在此基础上，呈现用户对检索问题本质的核心洞察：**检索不是"找最相似的一个Pattern"，而是"找此刻推理智能体应该考虑的所有方向"；本质是模式识别；形式化方法和AI智能必须结合；小规模时退化为"加载全部+AI判断"；识别出多个方向时DFS可并发。** 这一洞察把检索目标从"精准提取一个"重新定义为"完备找全所有相关方向"，把检索和选择解耦，把四代系统的共同本质统一为"模式识别"，并提出了并发DFS架构。

## 1. 引言：数学大师系统与检索问题 <a name="1-引言"></a>

### 1.1 系统概述

数学大师系统是一个引导式数学解题系统，目标是让AI在不知道答案的情况下，通过元认知提示引导做题AI完成数学题的解答。

系统有两个核心智能体：

| 角色 | 别名 | 职责 | 能力边界 |
|---|---|---|---|
| **推理智能体** | 做题AI / 工作智能体 / Solver | 在提示下尝试解题，产出每一步的推理 | 有数学能力但会卡住 |
| **辅助智能体** | 引导者AI / 助理智能体 / Guide | 观察推理智能体的状态，决定发送什么提示Q | 能做模式识别，但内在知识不足以自己提出特定Q |

引导过程是一棵深度优先搜索（DFS）树：
- **节点** = 推理智能体的一个状态（一段推理输出 + 累积context）
- **边** = 辅助智能体发送的一个Q（一个提示/发问）
- **根节点** = 题目本身
- **叶节点** = 成功叶（正确解答）/ 死路叶（卡死或错误方向）/ 截断叶（超限停止）

### 1.2 什么是QA序列——具体例子

QA序列是辅助智能体引导推理智能体解题的完整对话记录。每一轮包含一个Q（辅助智能体发送的提示）和一个A（推理智能体的回复）。以下是一个简化的3轮QA序列片段，展示QA序列的基本结构和其中存在的多种情况：

---

**第1轮**

**Q1**（辅助智能体发送）：
> "请读取problem.txt。不要解题。描述这道题的结构形状：结论是什么类型？条件和结论之间的'距离'有多远？"

**A1**（推理智能体回复）：
> 这是一道渐近精细下界问题。需要证明极差≥√5+C₂n^(-3/2)。第(1)问只需要证极差≥√5（常数下界），第(2)问需要定量分析δ=R-√5的量级。差距：需要从"δ≥0"提升到"δ≥c/n^(3/2)"。

**情况类型**：**纯元认知观察**——Q1不涉及任何数学知识，只要求AI描述题目结构。任何AI都能回答，不需要知道答案。

---

**第2轮**

**Q2**（辅助智能体发送）：
> "在极值构型附近，把每个点分解成'离它最近的关键点'加上'偏差'。"

**A2**（推理智能体回复）：
> 投影到最近根：以中点-1/2为界，ζᵢ=r（xᵢ≤-1/2）或ζᵢ=s（xᵢ>-1/2），定义eᵢ=xᵢ-ζᵢ。得到展开式q(xᵢ)=±√5·eᵢ+eᵢ²。由紧性得统一界|eᵢ|≤√5/2。

**情况类型**：**思维操作引导**——Q2给了一个操作方向（"分解成最近关键点+偏差"），但没有给具体数学知识。AI需要自己完成投影的具体计算。

---

**第3轮**

**Q3**（辅助智能体发送）：
> "p=(5-√5)/10是二次无理数。数论中有一个标准事实：二次无理数的连分数部分商有界，因此它是badly approximable——存在常数c₀>0使得对任意整数k,n，|p-k/n|≥c₀/n²。你能用这个事实推出|D|的下界吗？"

**A3**（推理智能体回复）：
> 使用badly approximable性质：|p-k/n|≥c₀/n² → |pn-k|≥c₀/n → |D|≥c₁/n。由稳定性方程5|D|≤4√5·E，因此E=Σeᵢ²≥c₂/n。

**情况类型**：**知识性提示（必须提供）**——Q3直接给出了一个数论事实（badly approximable性质）。这不是思维操作引导，而是知识注入。**为什么必须提供知识性提示？** 因为推理智能体不知道"badly approximable"这个概念——这不是通过元认知思考能发现的，它是一个具体的数论知识点。无论怎么启发AI"想想D的下界"，如果AI不知道badly approximable性质，它就无法从|D|≠0推出|D|≥c/n的定量下界。这是纯知识瓶颈——思维模式提示无法替代。

---

**QA序列中存在多种情况类型**（详见§4完整10轮序列）：

| 情况类型 | 什么时候出现 | 例子 | 能否用元认知替代 |
|---|---|---|---|
| 纯元认知观察 | 序列开始，让AI描述形状 | Q1："描述这道题的结构形状" | 本身就是元认知 |
| 自由列举方向 | 序列早期，让AI发散 | "列出你能想到的所有可能方向" | 本身就是元认知 |
| 思维操作引导 | AI卡在某个操作步骤 | "把每个点分解成最近关键点+偏差" | 可以——给操作方向不给知识 |
| 量级感知引导 | AI有方程但不知道下一步问什么 | "D能等于0吗？至少有多大？" | 可以——引导AI关注正确的量 |
| **知识性提示（必须）** | **AI遇到纯知识瓶颈** | **"badly approximable性质"** | **不能——这是具体知识点，元认知无法替代** |
| 能量传递引导 | AI有中间结果但不知道怎么传递 | "把偏差能量下界传递到极差下界" | 可以——引导传递方向 |

**关键洞察**：QA序列中大部分Q是元认知提示（思维操作引导、量级感知引导等），但有时**必须提供知识性提示**。这不是系统的设计缺陷，而是数学思维的真实结构——有些步骤是知识瓶颈，不是思维瓶颈。系统必须能区分这两种情况：什么时候该给元认知提示，什么时候必须给知识。

### 1.3 两个关键标签

每个Q有两个标签，用于量化提示的性质：

#### Level（0到1实数）：提示的抽象度

- **→1：纯思维模式**——跨领域通用的元认知策略，不依赖具体数学知识
- **→0：纯知识**——绑定特定领域的具体定理/技巧

**具体例子**（来自§4的10轮QA序列）：

| Q | Level | 类型 | 说明 |
|---|---|---|---|
| Q1 "描述这道题的结构形状" | 1.0 | 纯思维模式 | 任何题目都可以问这个问题，不依赖数学知识 |
| Q6 "把每个点分解成最近关键点+偏差" | 0.7 | 思维操作 | "投影分解"是跨领域的思维模式，但"投影到根"有一定具体性 |
| Q8 "D能等于0吗？至少有多大？" | 0.5 | 量级感知 | "问问某个量至少有多大"是通用思维模式，但D是这道题特有的量 |
| Q9 "badly approximable性质" | 0.2 | 纯知识 | 这是数论中的具体定理，只在这个知识范围内有意义 |

#### 非特定性程度（0到1实数，越大越特定）：Q的有效性是否依赖于引导者知道正确解答路径

- **→0：完全非特定**——引导者不需要知道答案就能发出这个Q
- **→1：完全特定**——引导者必须知道答案才能发出这个Q

**具体例子**：

| Q | 非特定性 | 说明 |
|---|---|---|
| Q2 "列出你能想到的所有可能方向" | 0.0 | 任何题目都可以问，完全不需要知道答案 |
| Q6 "把每个点分解成最近关键点+偏差" | 0.6 | 需要知道"投影到根"是正确方向才能发，但不需要知道后续步骤 |
| Q8 "D能等于0吗？至少有多大？" | 0.7 | 需要知道D是关键量才能发，这接近于知道答案 |
| Q9 "badly approximable性质" | 0.9 | 必须知道答案路径中需要这个性质才能发 |

**Level和非特定性的关系**：通常Level越低（越接近知识），非特定性越高（越需要知道答案）。但两者不完全等价——Q8的Level=0.5（中等抽象）但非特定性=0.7（相当特定），因为"关注D的下界"是一个思维模式（中等Level），但要知道D是关键量才能发这个提示（高特定性）。

### 1.4 什么是Pattern——具体例子

Pattern是稀疏矩阵中存储的"什么时候该提示什么"的经验单元。每个Pattern描述一个"当推理智能体处于某种状态时，应该发送什么提示"的关系。

**具体例子**——Q8对应的Pattern：

```json
{
  "pattern_id": "P-008",
  "source": "矩条件极差题第二问-Q8",

  "触发条件": {
    "state_description": "推理智能体有了稳定性方程，方程中有一个量D取决于整数k和n的关系，D不能为零但需要估计其下界",
    "key_objects": ["稳定性方程", "量D", "整数k", "整数n"],
    "key_relations": ["D=√5(pn-k)", "p是无理数", "D≠0但|D|的量级未知"],
    "shape": {
      "conclusion_type": "渐近精细下界",
      "condition_type": "等式组（矩条件）",
      "distance": "远",
      "unnatural_types": ["隐藏乘积"],
      "unnatural_description": "稳定性方程中的D隐藏了一个无理数p与整数k/n的逼近关系"
    }
  },

  "Q内容": "你的稳定性方程里有一个量D，它取决于k和n的关系。D能等于0吗？如果D不能等于0，它至少有多大？",

  "Level": 0.5,
  "非特定性": 0.7,

  "Hint级别": "H1",
  "Hint说明": "思维操作——引导AI关注D的下界，不给具体数学知识",

  "历史使用记录": [
    {
      "case": "矩条件极差题第二问",
      "effect": "AI尝试估计|D|但有困难——识别出知识瓶颈",
      "next_pattern": "P-009（badly approximable知识注入）"
    }
  ]
}
```

**Pattern的关键组成部分**：

| 组成部分 | 作用 | 在检索中的角色 |
|---|---|---|
| 触发条件 | 描述"什么状态下该用这个Pattern" | 检索的查询目标——当前状态匹配触发条件 |
| Q内容 | 该发送什么提示 | 检索的输出——找到Pattern后发送的Q |
| Level | 提示的抽象度 | DFS排序依据——优先探索高Level |
| 非特定性 | 对答案知识的依赖程度 | 泄漏审计依据——非特定性高可能泄漏答案 |
| Hint级别 | 泄漏分级（H0-H4） | 泄漏审计依据——H3以上表示泄漏 |
| 历史使用记录 | 过去在什么情况下用过 | 经验积累——验证Pattern有效性 |

### 1.5 什么是DFS树——结构示意

引导过程是一棵深度优先搜索（DFS）树：

```
                    [根节点：题目]
                    /              \
              Q1 /                    \ Q1'
               /                        \
        [节点1：A1]                 [节点1'：A1']  ← 回溯后的替代分支
        /         \
    Q2 /           \ Q2'
      /              \
[节点2：A2]     [节点2'：A2']  ← 如果Q2走不通，回溯到节点1，换Q2'
    |
  Q3 |
    |
[节点3：A3]  ← 成功叶（证毕）
```

**回溯铁律**：禁止在同一个Session中让AI回溯到某个思路岔口。必须启动新Session，重放Q序列到岔口，在岔口换方向。原因是压缩边界风险、context污染、不可逆性。正确做法：新Session + 重放Q序列到岔口 + 在岔口换方向。

### 1.6 什么是稀疏矩阵（认知图/数据基座）

系统积累了大量"什么时候该提示什么"的经验。这些经验以Pattern的形式存储在稀疏矩阵中——一个ArangoDB图数据库，节点是认知单元/数学元素/思维模式，边是依赖关系。

**"稀疏"的含义**：Pattern数量巨大（随着系统积累不断增长，可能达到数十万），但在任何一个具体时刻，只有极少数Pattern与当前状态相关。

**具体例子**：假设系统积累了10000个Pattern。在矩条件极差题的Q8这个时刻，与当前状态相关的Pattern可能只有3-5个（Q8本身、Q9的预备Pattern、以及1-2个来自其他题目的类似"量级估计"Pattern）。10000个中找3-5个——这就是"稀疏"。

**稀疏矩阵的规模演进**：

| 模式数量 | 检索机制 | 复杂度 |
|---|---|---|
| 10个 | 加载全部+AI判断 | O(1)——加载一个文件，AI一次性判断 |
| 100个 | 粗筛（形式化）+AI判断 | O(log n)——先缩小到10-20个，AI判断 |
| 1000个 | 三级种子选择+精化+AI判断 | O(log² n)——层次索引+图遍历+AI判断 |
| 325000个 | 完整检索管线 | O(log³ n)——多级索引+向量检索+图遍历+AI判断 |

### 1.7 检索问题的提出

系统有两种运行模式：

- **预演模式**：Master事先知道正确解答路径→倒推QA序列→系统忠实执行。这是当前所有guided实验的实际状态。
- **实际模式**：Master不知道答案→系统感知推理智能体的状态缺口→从稀疏矩阵检索Pattern→引导AI自己找到答案。这是系统的设计目标。

检索问题是预演→实际的**唯一障碍**。在预演模式中，辅助智能体不需要检索——它已经知道该发什么Q。在实际模式中，辅助智能体不知道该发什么Q，需要从稀疏矩阵中检索。

**检索问题是：给定推理智能体的当前状态（一段推理输出+累积context），如何从稀疏矩阵的海量Pattern存储中，找到此刻应考虑的方向？**

如果检索问题不解决：
- 系统只能做Master事先知道答案的题
- 系统退化为"高级题库+执行器"，不是"真正的数学大师"
- 稀疏矩阵没有实际用途——Pattern存储了但检索不到

## 2. 检索问题的三层定义 <a name="2-检索问题的三层定义"></a>

检索问题有三层未解决的核心问题（详见[253号]§3）：

### 2.1 第一层：状态感知——辅助智能体怎么"看到"推理智能体需要什么？

推理智能体停在某个状态。这个状态以什么形式被辅助智能体"看到"？

| 方案 | 机制 | 问题 |
|---|---|---|
| 关键词 | 在推理智能体输出中匹配关键词 | 同一关键词在不同上下文含义不同；需要的概念可能不在文本中 |
| RAG语义相似 | 找与当前输出文本最相似的存储文本 | 文本相似≠思维状态相似；需要的是"关系"不是"文本" |
| 思维拓扑 | 匹配推理的结构形状 | 方向正确但实现未定义——"拓扑"怎么表示？怎么计算相似度？ |

### 2.2 第二层：Pattern提取——怎么从海量存储中快速定位到相关Pattern？

即使第一层解决了（辅助智能体识别出了"此刻需要某种提示"），怎么从稀疏矩阵中提取到相关Pattern？

| 方案 | 机制 | 问题 |
|---|---|---|
| 全量扫描 | 遍历所有Pattern，逐一匹配 | O(n)复杂度，Pattern数量大时不可行 |
| 索引 | 为Pattern建索引，按某种key快速查找 | 索引key是什么？如果是关键词，回到第一层的问题 |
| 图遍历 | 从当前状态对应的节点出发，在依赖图中遍历 | 当前状态对应哪个节点？遍历方向是什么？ |
| 嵌入向量 | 把Pattern和当前状态都编码为向量，做最近邻搜索 | 编码方式是什么？向量空间中"近"意味着什么？ |

**核心困难**：无论用什么方案，都需要定义"此刻的状态"和"存储的Pattern"之间的**相似度/匹配度**。而这个匹配度的定义，取决于第一层（状态怎么表示）的答案。

### 2.3 第三层：知识悖论——辅助智能体的知识不足，怎么补？

即使前两层解决了（状态被识别了，候选Pattern被提取了），辅助智能体怎么在候选中做最终选择？

**知识悖论**：
- 辅助智能体的内在知识不足以提出Q → 所以需要稀疏矩阵的帮助
- 但要在候选中选出正确的Q，需要判断"这个Q对当前状态有效吗" → 这个判断也需要知识
- 如果辅助智能体有足够的知识做这个判断，它大概也有足够的知识直接提出Q → 那为什么还需要稀疏矩阵？

## 3. 四代系统对检索问题的设计回应（综述） <a name="3-四代系统对检索问题的设计回应"></a>

数学大师系统经历了四代演进，每一代有中国神话命名和独立的技术说明书。本节综述每代与检索问题相关的设计，按三层组织。

### 面相视角下的四代演进

从面相C（设计过程自举）看，四代演进是自举循环的四个轮次——每代系统是上一代的解，也是下一代的约束；每代暴露的差距催生下一代：

| 代际 | 暴露的差距（催生下一代） | 面相归属 |

| 盘古→女娲 | 静态图无法应对动态推理；Master身兼数职 | 面相A（实践涌现：122号诊断架构断层） |
| 女娲→燧人 | 规则匹配粒度粗、Hint梯度泄漏、角色隔离未实现 | 面相A（实践涌现：200-202号危机诊断） |
| 燧人→伏羲 | 非特定性危机+形式化边界是本质性的 | 面相A+B（实践涌现+知识选取：218号危机+222号形式化边界） |

从面相4（树的生长）看，四代系统分别对应树生长的不同角色：

| 代际 | 在"树的生长"中的角色 | 最清晰的面相视角 |

### 3.1 第一代·盘古：静态图前置与拓扑确定性 <a name="31-第一代盘古"></a>

**核心理念**：Master预先知道路线→写静态依赖图G→经典计算忠实展开→AI按图重建答案。完美提示词可通过经典计算产生。

**面相视角**：面相1（两种计算）+ 面相B（知识选取）。盘古从"两种计算"视角看最清晰——经典计算展开G'_topo、AQL集合差集做拓扑覆盖验证，AI只负责L3语义标注。设计来自知识选取（AQL/图论/Kahn算法）。在"树的生长"（面相4）中，盘古是"预先画好树"——静态依赖图G是预先画好的解题记录树，系统只是忠实展开它。

**文档范围**：63-121号设计文档。

#### 第一层·状态感知

- **[63] 三维稀疏矩阵**：定义了三维稀疏矩阵——行是分析节点，列是星学意识，格子值是"这个节点是否调用这个意识"。三维化发生在追溯时：同一节点在不同上下文下调用同一意识产生不同结论。平面环路vs螺旋环路的判别标准：追溯一圈后是否产生新的判断维度。提供了"状态感知"的数学形式化——思维状态不是关键词匹配，而是三维稀疏矩阵中的上下文层。

- **[78] G'_topo拓扑骨架**：提出G'_topo（展开图拓扑骨架）——在转译之前先构造展开图的纯拓扑结构，标注每个节点和边在文字展开中的位置。G'_topo是G的同构拷贝，但结构显式化。将"状态感知"从文字层面提升到拓扑层面——思维状态不是文本相似度，而是图结构的拓扑覆盖关系，可以通过AQL集合差集精确验证。**此设计在星学项目POC-9中验证通过（1次通过100%覆盖）。**

- **[92] topo_generator分层展开**：设计L0-L3分层展开机制。L0骨架展开（节点/边拷贝+拓扑排序Kahn算法+traversal_order），L1类型推断（static/dynamic节点，linear/shortcut/cross_section边），L2 section划分，L3语义标注保留给AI。提供了"状态感知"的确定性计算基础——思维状态的拓扑结构可以通过经典计算自动生成，不依赖AI的随机判断。

#### 第二层·Pattern提取

- **[110] 三层访问架构**：设计冷/温/热三层访问架构解决325000节点规模问题。冷存储层（ArangoDB）：全部节点+边+原文。热工作集（上下文）：当前问题相关的200-800节点子图，~80K token预算。温查询层（按需展开）：AI推理中发起expand/dependencies/path等查询。**种子选择三级机制**：第一级层次索引定位（3层主题树，~20K token常驻）→第二级语义检索（问题embedding与325000节点embedding比对，返回top-20）→第三级图遍历扩展（BFS/DFS，深度3-5层，剪枝到200-800节点）。完整回答了"Pattern提取"问题——不是全量扫描O(n)，而是三级种子选择+图遍历+token预算剪枝。

- **[83] L1/L2/L3三层提取**：定义L1/L2/L3三层提取机制。L1（解题思路）：具体步骤，直接从解法文本读出，只在类似题中复用。L2（数学思维）：从L1中抽象的思维模式（如"寻找不变量"），弥漫性跨题复用。L3（新的思维方式）：范式级思维（如范畴论函子），改变图结构本身，跨领域复用。提供了Pattern的分层定义——检索的不是L1具体步骤，而是L2思维模式（弥漫性）和L3范式思维（跨领域）。

- **[78] 拓扑覆盖验证七步骤**：步骤1依赖图解析（代码）→步骤2展开图拓扑规划（meta AI生成G'_topo）→步骤3拓扑覆盖验证（TopologyVerifier代码，AQL集合差集，1次通过100%覆盖）→步骤4按G'_topo转译→步骤5 KC忠实审计→步骤6分析→步骤7分析覆盖审计。提供了Pattern提取的完整工程方案——Pattern提取不是AI的单次随机判断，而是七步骤工作流，其中拓扑覆盖验证是数学确定性的。**此设计在星学项目POC-9中验证通过。**

#### 第三层·知识悖论

- **[86] meta/normal分离**：明确提出meta/normal分离原则。meta operation：拓扑规划、拓扑验证、KC审计、分析审计（纯数学，不涉及领域知识）。normal operation：转译、分析（领域知识，文字生成）。meta和normal由不同AI实例完成，避免"既是运动员又是裁判"。部分解决了知识悖论——引导者AI（meta）负责拓扑层面的Pattern检索（纯数学，不需要领域知识），做题AI（normal）负责具体推理（需要领域知识）。**此设计在星学项目POC-9中验证通过。**

- **[95] 意识节点双重身份**：意识节点（不变量思维/局部-全局/逼近论/极端检验/数值检验）既是AI的工作认知（cognition_units中），又是数学依赖图的节点（dg_nodes中）。两套图共享同一个ArangoDB实例，集合名隔离。缓解了知识悖论——意识节点作为工作认知，引导者AI可以识别"需要调用什么思维模式"（meta层面），而不需要知道具体的数学知识内容（normal层面）。

- **[63] 直觉可形式化吗**：诚实面对了知识悖论——大师的"知道该判断什么"在大师脑中是直觉性的，但直觉的内容是可形式化的。大师大脑的模式匹配过程不可复制，但模式匹配的结果（该激活什么知识、沿什么路径思考）有客观结构，可以被提取和编码。给出了知识悖论的理论解决路径——引导者AI不需要复制大师的直觉体验，只需要复制直觉的输出（激活路径）。稀疏矩阵就是直觉输出的形式化载体。

### 3.2 中间代·女娲：动态控制与角色隔离 <a name="32-中间代女娲"></a>

**核心理念**：动态控制+角色隔离。从第一代的"完美提示词硬公理"降级为可证伪假设。动态工作区W_t替代静态G，12步在线主链替代七步骤，8角色隔离矩阵替代Master身兼数职。

**面相视角**：面相3（Pipeline网络）+ 面相A（实践涌现）。女娲从"Pipeline网络"视角看最清晰——8角色隔离矩阵是Pipeline网络的细化，每个角色是Pipeline中的一个Pipe。设计来自实践涌现（122号诊断架构断层、200-202号危机诊断）。在"树的生长"（面相4）中，女娲是"记录树的当前节点状态"——W_t六类分量是树当前节点的状态表示。

**文档范围**：122-202号设计文档。

#### 第一层·状态感知

- **[122-v2] 外显思维图T**：提出"思维形状可观测、可比较、可干预"公理，定义外显思维图T记录Agent实际思维轨迹（节点类型：observation/claim/representation/subgoal/candidate/test/tool_result/contradiction/stall/backtrack/resolution），边类型（notice/infer/recall/transform/decompose/compare/test/reject/backtrack/generalize/analogize/ask_for_hint/activate）。提供了状态感知的理论框架——思维轨迹可被编码成带标注的图，使"看到Agent需要什么"从抽象理念变为可工程化的图匹配问题。

- **[122-v3] 诚实诊断**：明确指出"旧系统实际没有实现T图和H图"，80-99号主要实现的是人工构建的静态证明图K及其展开，不应把v2的设计误说成当前能力。当前所谓"启发"是任务开始前的静态脚手架，不是观察AI当前思路后再按需矫正。诚实诊断了第一代的局限——静态提示展开≠动态状态感知，为中间代的动态工作区设计提供了基线。

- **[123-v1] 动态工作区W_t**：形式化定义动态数学工作区W_t=(V_t,F_t,O_t,R_t,D_t,E_t)，其中V_t是已验证核心、F_t是猜想前沿、O_t是开放研究义务（AND/OR超图）、R_t是当前表示、D_t是被拒绝分支、E_t是证据。定义事件结构L_≤t=(E_≤t,≺,#,λ)为带冲突的DAG。提供了状态感知的严格数学形式化——工作区是六类分量的结构化状态，事件是带因果和冲突关系的不可变流。

- **[127-v1] Schema冻结**：冻结Workspace/Event/Obligation/Representation/Evidence schema，定义Workspace包含V_t/F_t/O_t/R_t/D_t/E_t六类分量，Event包含RawEvent和SemanticEvent两层，Obligation是AND/OR超图。将123号的形式化定义落盘为可实现的数据库schema。

- **[188-v0] 状态归约审计标准**：定义state_reducer子系统审计标准——状态重建准确性（Krippendorff α≥0.80）、进展判别（状态等价~_{α,κ}、环路判别）、义务图完整性（DAG验证、AND/OR超边释放）、证据状态正确性、V_t/F_t分离。为状态感知的质量控制提供了审计标准——状态重建必须可复现、进展判别必须跨任务隔离。

#### 第二层·Pattern提取

- **[122-v2] 启发激活图H**：定义启发激活图H保存"触发→激活"的条件关系，最简形式P→X（看到模式P时提醒Agent把X加入候选思考空间），高阶形式(P,R,C,F,τ)→(X,S,T)（多元条件）。X是"激活包"而非答案，可以是概念/表示/操作/子目标/意识/工具/反例方向/跨领域类比。提出Hint梯度（Hint-0元检查/Hint-1思维操作/Hint-2工具概念候选/Hint-3确定关系/Hint-4最终答案），默认从Hint-0开始逐级增加。提出启发关系生命周期（observed→candidate→intervened→validated→transferred→published→retired）。提供了Pattern提取的核心机制设计——启发是条件化干预而非逻辑蕴含，激活包是最小非泄漏方向，Hint梯度控制泄漏风险。

- **[127-v1] HeuristicRule schema**：冻结HeuristicRule schema，定义规则包含lhs_pattern/guard_conditions/temporal_pattern/activation_packet/hint_level/applicable_domains/model_versions/status/evidence_summary/leakage_risk/failure_cases/version。冻结声明：candidate规则禁止在线自动提示（这是防Agent迎合触发器的核心防线），published标准在Phase 4出口门前冻结。

- **[189-v0] 启发匹配审计标准**：定义heuristics子系统审计标准——规则匹配正确性（只用published规则、角色隔离验证、不可见truth_vault）、规则生命周期管理（candidate禁止在线提示、candidate→validated需DYN-3因果实验+泄漏门、validated→published需DYN-5跨3问题族+2模型版本）、答案泄漏审计（四门全执行：字面匹配/等价映射/候选空间缩减/盲审者恢复）、激活包设计（H0/H1/H2分级、不含目标结论、禁止答案等价）。为Pattern提取的质量控制提供了审计标准。

#### 第三层·知识悖论

- **[127-v1] 8角色可见性矩阵 + CapabilityToken**：定义8角色可见性矩阵（Solver/EventCapture/StateReducer/Retriever/HeuristicMatcher/Verifier/Auditor/Orchestrator），Truth Vault collection只有truth_curator可写、只有auditor可读，Runner/Solver/HeuristicMatcher不可见。定义CapabilityToken机制（token_id/role/granted_collections/write_collections/granted_fields/expires_at/issued_by/run_id），通过collection级访问控制、字段级访问控制、写入控制、运行隔离、自动失效强制角色隔离。提供了知识悖论的工程解决方案——通过可见性矩阵和能力令牌强制角色隔离，确保引导者AI看不到答案。

- **[200-v0] 提示作弊问题与诚实不可知论**：诊断当前系统提示机制存在"给知识"式作弊。提出诚实不可知论——不预设"给思路=作弊"或"给思路=引导"，用实验测量：对比"有提示"vs"无提示"vs"有提示但去掉答案等价信息"的表现差异，如果去掉答案等价信息后增益消失→降级为编译器。提供了知识悖论的伦理解决方案——用实验而非预设判断"引导"vs"作弊"的边界。

- **[202-v0] AI在运行过程中的缺位**：诊断当前系统12步运行时的决策环节全部由经典计算完成（关键词匹配+阈值比较+硬编码规则），没有AI参与。建议新增"AI引导者"角色，在决策环节中介入——经典计算给出候选，AI从候选中选择或调整。AI引导者可见Solver公开输出/状态归约结果/稀疏矩阵K维度/候选规则列表/进展历史，但不可见truth_vault。提供了知识悖论的AI增强方案——承认经典计算在复杂场景下不足，引入AI引导者做智能分析，但通过可见性边界确保AI引导者看不到答案。

### 3.3 第二代·燧人：非特定元认知提问 <a name="33-第二代燧人"></a>

**核心理念**：非特定高Level元认知提问——钻木取火（不给火而教取火，不给答案而给思维启发）。八根柱子：路线B、Level连续谱、形状、极致提示集合、安全第一步、连续发问、最小知识传递、DFS引导架构。

**面相视角**：面相4（树的生长）+ 面相A（实践涌现）。燧人从"树的生长"视角看最清晰——DFS引导架构就是引导展开树的串行遍历策略，节点=做题AI状态，边=提示Q。设计来自实践涌现（guided_001/002/003实验）。在面相4中，燧人是"树的串行遍历策略"——一次一个方向，走不通回溯。用户的并发DFS洞察（§6.5）打破了串行预设，但树的结构不变。

**文档范围**：203-217号设计文档。核心技术文档为[214]（8章+8.14节）。

#### 第一层·状态感知

- **[214] 形状匹配是拓扑的**（第3章）：系统关注"形状"——问题的结构特征（存在性/唯一性/极值）、解答的转折结构（正面→反面/构造→证明）、思维的拓扑（哪些模式经常一起出现/有依赖关系）。依赖图中的节点不只是"反证法"标签，而是"反证法"在特定形状问题中的特定使用方式。定义了状态感知的核心概念——形状是拓扑的，不是文本内容，但未实现具体的形状表示和相似度计算方法。

- **[214] 安全第一步**（第5章）：让AI先描述形状而非解题——AI必然能完成"读题并分类"（结论类型、条件类型、距离、想到的方向、联想），这是元认知观察，不依赖任何知识。系统根据AI的形状描述匹配提示。提供了状态感知的入口机制——AI必然能完成形状描述，这是不依赖知识的元认知观察。

- **[214] 连续发问六层渐进**（第6章）：从观察→联想→描述方向→小尝试→推进→卡点处理，每一步都比前一步多一点点创造性，AI不会面对空白页。提供了渐进式状态感知的框架。

- **[214] Level连续谱**（第2章）：依赖图中每个元素带Level标签（0到1实数），Level是经验的、模糊的、相对的——AI能感受差异的模糊大小。Level不是被赋值的，而是被感知的。定义了思维状态的维度表示。

- **[205] AI诊断卡点**：当经典计算给出不确定结果时，调用AI分析Solver response内容，判断"是真的卡住了还是在做策略转换"、"真实原因是什么"。提供了AI理解做题AI状态的方案。

#### 第二层·Pattern提取

- **[214] DFS引导架构**（第8章）：引导者AI陪着做题AI做DFS——节点=做题AI状态（A），边=引导者发送的Q（提示），根节点=题目，叶节点=成功/死路/截断。引导者在每个节点生成候选Q列表，按Level降序排列，一次发一个，走不通则回溯。定义了Pattern提取的搜索框架。

- **[214] 候选Q按Level降序排列**（第8.4节）：优先探索高Level（更通用、更抽象）的提示，这是Level SUM最大化的贪心策略。

- **[214] 回溯铁律**（第8.9节）：禁止在同一个Session中让AI回溯到某个思路岔口。必须启动新Session，重放Q序列到岔口，在岔口换方向。原因是压缩边界风险、context污染、不可逆性。定义了回溯的硬约束。

- **[214] 节点同一性**（第8.10节）：采用"路径同一性为主、状态同一性为辅"的混合定义——node_id由Q路径决定（确定性），但节点内容（A）是概率性的，引导者判断A'和A是否"本质相同"。

- **[214] ArangoDB持久化设计**（第8.13节）：QA树存入ArangoDB——case文档（元信息）、节点文档（每个节点的完整记录）、边（parent→child）。短期JSON+ArangoDB双写，中期提炼为H层启发规则，长期跨case的K层语义搜索。

- **[214] 完整推理历史9层记录**（第8.14节）：从题目元数据到性能指标的全链路记录，包括每个节点的Q/A/Level/状态、引导者决策日志、session压缩事件。

- **[215] DFS树记录器**：记录DFS探索过程的树状数据结构，支持添加节点、记录候选Q列表、回溯、获取Q序列、计算Level SUM。

- **[216] 元组群guided-math-solving**：5个Skill（guided-rehearsal预演/guided-session-launch启动/guided-interaction连续发问/guided-backtrack回溯/guided-data-persist数据持久化）。定义了Pattern提取的工作流拆分。

#### 第三层·知识悖论

- **[214] 最小知识传递**（第7章）：形式化定义为argmax ΣLevel(h_i)——在"AI能完成解题"的约束下，最大化Level之和。如果纯高Level提示无法完成，必须适时降低Level走向知识端。定义了知识传递的优化目标。

- **[214] 引导者的核心能力**（第8.6节）：引导者不需要知道正确答案，但需要：生成候选Q（广度）、评估Level（品味）、判断A的状态（诊断）、回溯决策（剪枝）。这四种能力都是元认知能力，不是具体数学知识。定义了引导者AI的能力要求。

- **[214] 路线B vs 路线A**（第1章）：路线B（思维模式）寻找最深的、最通用的、最高抽象度的思维模式（反证法、找不变量、考虑极端情况），不依赖具体数学知识，跨领域适用。路线A（堆砌知识）给具体定理/技巧，限于同一知识范围。定义了非特定性引导的理念。

- **[205] AI引导者 vs 作弊问题**：如果引入AI编译提示，AI会不会变成"更高级的递答案"？解决关键是[203]的泄漏审计——无论提示是经典计算生成还是AI生成，都必须过四门审计。

- **[203] truth_vault隔离**：答案写入truth_vault，Controller/Matcher/Solver的可见性标签设置can_read_truth_vault=False，步骤10编译提示时Controller从K维度取知识，不从truth_vault取。定义了角色隔离的硬约束。

### 3.4 第三代·伏羲：形式化边界推进 <a name="34-第三代伏羲"></a>

**核心理念**：形式化边界的持续推进。两种计算（AI管边界以外的感知，经典计算管边界以内的验证），闭环把非单调感知压成单调形式化，数据基座增长=边界推进。非特定性=边界推进能力。

**面相视角**：面相1（两种计算）+ 面相4（树的生长）+ 面相B（知识选取）。伏羲从"两种计算+树的生长"交叉视角看最清晰——AI计算做模式识别（识别"不自然"=识别该往哪个方向展开树），经典计算做节点状态验证（数值验证=验证当前节点状态是否正确）。设计来自知识选取（形式化边界/伴随关系/范畴论）。在面相4中，伏羲是"树生长的认知机制"——形式化边界推进就是节点展开的认知机制：AI感知"不自然"→压缩成可检查目标→经典计算验证→结果回写数据基座→边界向前推进→树长出一个新节点。

**文档范围**：218-237号设计文档。核心文档为[225]、[231]、[233]、[236]。

#### 第一层·状态感知

- **[225] 语义场证书框架**：数学处境S作为基本对象（不是静态点），包含原始题目、对象、关系、当前表示、已尝试表示、已知例子、当前猜想、局部证书、未形式化结构感觉。语义场Σ是所有可能的数学处境组成的空间，相邻由结构关系决定（不是表面词汇）。表示图册A(S)允许一个处境用多个局部表示看清。AI的角色是解释处境、生成图册、识别模式、提出语义移动、编译证书目标、解释失败、维护叙述。提供了"状态感知"的完整框架——把思维状态表示为可生长的数学处境，而不是静态点；通过表示图册实现思维拓扑化；通过模式识别压缩当前处境的结构解释。

- **[219-221] 拓扑化研究**：问题拓扑包含约束类型、结论类型、核心鸿沟、关键桥梁、极值结构、修正来源、稳定性机制。模式识别识别的是"当前表示与内在结构之间的不匹配"——即"不自然"（冗余、隐藏乘积、虚假自由度、隐藏直和等）。模式识别有两步结构：识别问题拓扑→映射到思维拓扑。拓扑库从具体例子的抽象中积累。回答了"拓扑怎么表示"——问题拓扑的结构化描述；回答了"怎么计算相似度"——通过"不自然"的种类匹配，不是关键词匹配或RAG语义相似。

- **[222] 形式化边界**："不自然"无法被形式化，是感知不是规则。AI通过海量例子获得模糊匹配能力，覆盖了感知层面的边界。边界没有消失但移动了：AI时代感知层被AI覆盖，剩余边界是价值判断和审美。明确了状态感知的边界——"不自然"的识别在形式化边界上，AI的模糊匹配覆盖了感知层面，但边界没有消失。

#### 第二层·Pattern提取

- **[225] 模式范畴M与证书偏序C**：模式范畴M的对象是数学模式（不变量、对偶、极值等），态射表示模式之间的细化、组合和翻译。证书偏序C是已被某种可靠机制确认的数学事实，有自然的顺序关系。语义与证书之间有伴随关系：可证化（语义→证书）和反射（证书→语义）。模式图书馆保存可迁移的数学模式，每个模式说明适用信号、常见表示、可生成的证书目标等。提供了Pattern存储的结构——模式范畴M和证书偏序C；回答了"索引key是什么"——模式的适用信号、常见表示、可生成的证书目标；回答了"嵌入向量编码什么"——不是向量编码，而是结构化字段。

- **[231] 数据基座转向**：数学工程单元作为基本单位，包含原始材料、处境描述、表示图册、语义移动、证书目标、经典任务、证书结果、依赖关系、失败边界、模式沉淀。分层形式化：结构化→规范化→可执行化→局部证书化→完整形式化证明。**检索机制不是RAG，而是找相似的边界推进路径——粗筛（结构化字段匹配）→精化（图查询在依赖图中找连通路径）→排序（可选：向量检索）。核心是路径结构匹配，不是embedding相似度。** 完整回答了第二层的三个问题：索引key是结构化字段（处境类型+移动类型+证书类型）；图遍历方向是在依赖图中找连通路径；嵌入向量编码什么——核心是路径结构匹配，不是embedding相似度。

- **[236] 最终综合框架**：数据基座是形式化边界的显式记录，每个数学工程单元标记着形式化边界的一个位置。数学工程单元按边界位置四阶段组织：边界标记（处境的当前状态）→跨越边界（从感知到形式化的过程）→边界以内（已形式化的产物）→边界以外的感知沉淀。抽取机制：抽取就是闭环本身，单任务双产出——跑一次闭环，同时产出问题的解和数据基座条目。提供了Pattern提取的完整机制——不是全量扫描，而是通过结构化字段匹配+图查询+可选向量检索的三层检索；回答了"匹配度怎么计算"——路径结构匹配，不是embedding相似度。

#### 第三层·知识悖论

- **[222] 形式化边界与知识分工**：形式化的边界是本质性的，不是"暂时无法形式化，未来可以"。AI时代边界没有消失但移动了：AI见过海量例子，能做模糊模式匹配，覆盖了感知层面的边界。新的分工：人提供结构（WHERE to look），AI提供感知（WHAT is there），人提供判断（WHY it matters）。**分离模式识别和答案知识：让不知道答案的AI做模式识别——它的感知不会泄露答案。** 完整回答了知识悖论——引导者AI不需要有足够知识识别Q，它只需要有边界以外的感知能力（模糊匹配"不自然"）；识别Q和提出Q不需要同等知识，因为识别Q是感知（边界以外），提出Q是感知+框架（边界以外+边界以内的结构）。

- **[233] 形式化边界移动机制**：双重知识生产的深层原因：数学知识本身有形式化边界两侧的两种成分——可以形式化的进入数据基座，不可形式化的进入AI训练。数据基座是形式化边界的显式标记，记录"哪些东西已经被形式化了"。AI的黑盒能力是形式化边界以外的侦察兵，能感知到"不自然"但无法形式化。经典计算是形式化边界以内的验证器，能做精确操作但不能感知边界以外的东西。**形式化边界的移动机制：AI从边界以外感知"不自然"→压缩成可检查目标（跨越边界）→经典计算在边界以内验证→结果回写数据基座（边界向前推进）。边界推进的不可逆性：数据基座单调增长，证书只加不删。边界推进的非单调性：AI的感知是非单调的，但边界以内的形式化是单调的。** 从认识论层面解决了知识悖论——引导者AI只需要边界以外的感知能力（模糊匹配），不需要边界以内的知识；**为什么还需要稀疏矩阵（数据基座）——因为边界以内的知识需要被显式记录和积累，边界推进是不可逆的。**

- **[236] 非特定性=边界推进能力**：非特定性 = 方法可从边界以外使用 = 边界推进能力。检验一个引导方法是否非特定，就是检验它能否在不知道答案的情况下推进边界。执行契约是边界跨越的协议：每次AI动作都是一次跨越边界的尝试。闭环的深层定义：闭环是形式化边界的推进过程，每一次闭环运行，边界向前推进一步。提供了知识悖论的操作性解决方案——通过执行契约检验边界跨越能力；通过闭环推进边界，让边界以外的感知不断压成边界以内的形式化；非特定性不是设计目标，而是边界推进能力的条件。

### 3.5 四代演进趋势与互补共存 <a name="35-四代演进趋势"></a>

#### 演进趋势

| 层 | 趋势 | 说明 |
|---|---|---|
| 状态感知 | 静态图结构→动态形式化分量→模糊形状感知→可生长处境+不自然识别 | 越来越接近"思维状态的本质"，但离工程实现越来越远 |

## 4. 案例：矩条件极差题第二问的10轮QA序列 <a name="4-案例"></a>

### 4.1 题目

已知 $a_1, a_2, \ldots, a_n$ 为实数，满足：

$$\sum_{i=1}^n a_i = n, \quad \sum_{i=1}^n a_i^2 = 2n, \quad \sum_{i=1}^n a_i^3 = 3n$$

**(2)** 证明存在常数 $C_2 > 0$，使得对所有 $n \ge 4$，

$$\max a_i - \min a_i \ge \sqrt{5} + C_2 \, n^{-3/2}$$

### 4.2 证明路径概要（10步）

| 步骤 | 做了什么 | 知识成分(Level→0) | 思维模式成分(Level→1) |
|---|---|---|---|
| 1. 中心化 | $x_i = a_i - 1$ → $\sum x_i = 0, \sum x_i^2 = n, \sum x_i^3 = -n$ | 无 | 归一化(0.9) |
| 2. 关键多项式 | $q(x) = x^2 + x - 1$，根 $r = \frac{-1-\sqrt{5}}{2}, s = \frac{-1+\sqrt{5}}{2}$，$s - r = \sqrt{5}$ | $q(x)$的具体形式(0.3) | 寻找统一编码(0.85) |
| 3. 两个恒等式 | $\sum q(x_i) = 0, \sum x_i q(x_i) = 0$ | 无 | 恒等式挖掘(0.8) |
| 4. 紧性归约 | 设 $R = \sqrt{5} + \delta$，$\delta \le 1$ 时所有 $x_i$ 落在固定紧区间 | 无 | 紧性归约(0.8) |
| 5. 投影到根 | $\zeta_i \in \{r, s\}$（最近根），$e_i = x_i - \zeta_i$ | 投影的具体形式(0.4) | 投影分解(0.7) |
| 6. 稳定性方程 | $5D = 3\sqrt{5}(B_r - B_s) + 2C$ | 无 | 恒等式挖掘/扰动分析(0.8) |
| 7. D的量级 | $p = \frac{5-\sqrt{5}}{10}$ 二次无理 → $\|D\| \ge c/n$ | **badly approximable(0.2)** | 量级感知(0.5) |
| 8. $\sum e_i^2 \ge c/n$ | 由稳定性方程 + D下界 | 无 | 能量传递(0.6) |
| 9. $\sum q(x_i)^2 \ge c/n$ → $S \ge c/\sqrt{n}$ | 柯西不等式 | 柯西不等式(0.3) | 能量传递(0.6) |
| 10. $\delta \ge c/n^{3/2}$ | $q(x)$ 在正值区 $\le c\delta$ → $S \le n\delta$ | 无 | 能量传递(0.6) |

**关键瓶颈**：步骤7是纯知识瓶颈——badly approximable性质（Level 0.2），思维模式提示无法替代。

### 4.3 完整预演QA序列（10轮，标注情况类型）

以下是引导者引导工作智能体完成第二问证明的完整QA序列。每轮包含Q（引导者发送的提示）、预期A（工作智能体的回复）、Level值、非特定性程度值、**情况类型**。

---

**Q1**（Level 1.0, 非特定性 0.1）：
> "请读取problem.txt。不要解题。描述这道题的结构形状：结论是什么类型？和第(1)问有什么区别？条件和结论之间的'距离'有多远？"

→ **A1**：识别为渐近精细下界问题。第(1)问证极差≥√5（常数下界），第(2)问要证极差≥√5+C₂n^(-3/2)（渐近精细下界）。差距：需要定量分析δ=R-√5的量级，证明δ≥c/n^(3/2)。

**情况类型**：纯元认知观察——不涉及任何数学知识，只要求AI描述题目结构。任何AI都能回答，不需要知道答案。

---

**Q2**（Level 1.0, 非特定性 0.0）：
> "列出你能想到的所有可能方向——不要求正确，不要求完整，只要列出你脑中浮现的任何方向。"

→ **A2**：列出方向：复用第(1)问的q(x)和恒等式、在极差接近√5时做更精细分析、投影到根、扰动分析、数值实验观察δ量级、极值构型分析、紧性论证...

**情况类型**：自由列举方向——让AI发散思维，不评判对错。完全不需要知道答案。

---

**Q3**（Level 1.0, 非特定性 0.0）：
> "对你觉得最有希望的方向，描述第一步会做什么。不要求真的做，只描述。"

→ **A3**：描述：先复用q(x)和两个恒等式，然后设R=√5+δ，分析δ很小时的行为。可能描述紧性归约思路——δ≤1时所有点落在固定紧区间内。

**情况类型**：描述方向——让AI描述但不执行，降低认知负担。不需要知道答案。

---

**Q4**（Level 1.0, 非特定性 0.0）：
> "选一个方向，试着做第一步。做多少算多少，做不出来也没关系。"

→ **A4**：设R=√5+δ，做紧性归约：δ≥1时结论显然成立，故只需讨论0≤δ≤1。此时所有xᵢ落在固定紧区间[r-1, s+1]。

**情况类型**：小尝试——让AI开始执行，但允许失败。不需要知道答案。

---

**Q5**（Level 1.0, 非特定性 0.0）：
> "你得到了什么？这个结果和你要证明的结论之间还有什么差距？下一步你想怎么走？"

→ **A5**：完成了紧性归约，但还没有δ的定量下界。差距：知道δ≥0（第(1)问），需要δ≥c/n^(3/2)。需要更精细的分析。

**情况类型**：推进——让AI自我评估进展和差距。不需要知道答案。

---

**Q6**（Level 0.7, 非特定性 0.6）：
> "在极值构型附近，把每个点分解成'离它最近的关键点'加上'偏差'。"

→ **A6**：投影到最近根：以中点-1/2为界，ζᵢ=r（xᵢ≤-1/2）或ζᵢ=s（xᵢ>-1/2），定义eᵢ=xᵢ-ζᵢ。得到展开式q(xᵢ)=±√5·eᵢ+eᵢ²。由紧性得统一界|eᵢ|≤√5/2。

**情况类型**：思维操作引导——给了一个操作方向（"分解成最近关键点+偏差"），但没有给具体数学知识。AI需要自己完成投影的具体计算。需要知道"投影到根"是正确方向才能发，但不需要知道后续步骤。

---

**Q7**（Level 0.8, 非特定性 0.4）：
> "把你的三个矩条件和偏差展开式做组合——求和、相乘、线性组合——看看能产生哪些'免费的恒等式'。"

→ **A7**：导出稳定性方程：
> - 由Σxᵢ=0 → A_r+A_s=-D ... (1)
> - 由Σq(xᵢ)=0 → -√5·A_r+√5·A_s+B_r+B_s=0 ... (2)
> - 由Σxᵢq(xᵢ)=0 → **5D = 3√5(B_r-B_s) + 2C** ... (3)
>
> 其中D=Σζᵢ=kr+(n-k)s=√5(pn-k)，p=(5-√5)/10。

**情况类型**：思维操作引导——"恒等式挖掘"是跨领域的思维模式，但"把矩条件和偏差展开式组合"有一定具体性。

---

**Q8**（Level 0.5, 非特定性 0.7）：
> "你的稳定性方程里有一个量D，它取决于k和n的关系。D能等于0吗？如果D不能等于0，它至少有多大？"

→ **A8**：分析D=√5(pn-k)。D=0需要k/n=p，但p是无理数，所以D≠0。但|D|至少有多大？AI尝试各种估计但有困难——**这是知识瓶颈**。

**情况类型**：量级感知引导——"问问某个量至少有多大"是通用思维模式（中等Level），但D是这道题特有的量（高特定性）。**这是检索问题的核心案例——辅助智能体需要从稀疏矩阵中检索到这个Pattern。**

---

**Q9**（Level 0.2, 非特定性 0.9）：
> "p=(5-√5)/10是二次无理数。数论中有一个标准事实：二次无理数的连分数部分商有界，因此它是badly approximable——存在常数c₀>0使得对任意整数k,n，|p-k/n|≥c₀/n²。你能用这个事实推出|D|的下界吗？"

→ **A9**：使用badly approximable性质：|p-k/n|≥c₀/n² → |pn-k|≥c₀/n → |D|≥c₁/n。由稳定性方程(3)：5|D|≤4√5·E，因此E=Σeᵢ²≥c₂/n。

**情况类型**：**知识性提示（必须提供）**——Q9直接给出了一个数论事实（badly approximable性质）。这是H3级别（确定关系），不是元认知提示。**为什么必须提供？** 因为推理智能体不知道"badly approximable"这个概念——这不是通过元认知思考能发现的，它是一个具体的数论知识点。无论怎么启发AI"想想D的下界"，如果AI不知道badly approximable性质，它就无法从|D|≠0推出|D|≥c/n的定量下界。**这是纯知识瓶颈——思维模式提示无法替代。** 系统必须能识别这种知识瓶颈，并在必要时提供知识性提示。

---

**Q10**（Level 0.6, 非特定性 0.7）：
> "你现在知道了偏差能量的下界Σe²≥c/n。你需要把这个下界传递到极差的下界δ。想想q(x)在根附近的行为，以及柯西不等式。"

→ **A10**：完成最后步骤：
> - |q(xᵢ)|≥c₃|eᵢ| → Σq(xᵢ)²≥c₄/n
> - 令S=Σ_{q>0}q(xᵢ)，由Σq(xᵢ)=0知2S=Σ|q(xᵢ)|
> - 柯西：Σ|q(xᵢ)|≥√(Σq(xᵢ)²)≥c₅/√n → S≥c₆/√n
> - q(x)在正值区总长度α+β=δ，q(x)≤c₇δ → S≤nc₇δ
> - 合并：nc₇δ≥c₆/√n → **δ≥c₈/n^(3/2)** ✓

**情况类型**：能量传递引导——引导AI把中间结果（偏差能量下界）传递到最终目标（极差下界）。"能量传递"是跨领域的思维模式，但"q(x)在根附近的行为"和"柯西不等式"有一定具体性。

### 4.6 Q8作为检索问题的具体案例

以Q8为例，把检索问题具体化：

**Q8之前的状态**：推理智能体在Q7之后产出了A7——导出了稳定性方程 $5D = 3\sqrt{5}(B_r - B_s) + 2C$，其中 $D = \sqrt{5}(pn - k)$，$p = \frac{5-\sqrt{5}}{10}$。推理智能体停在这里。它有稳定性方程，但不知道下一步该做什么。

**此刻需要的是Q8所代表的Pattern**：
- 触发条件：推理智能体有了稳定性方程，方程中有一个量D取决于整数k和n的关系，D不能为零但需要估计其下界
- Q内容："D能等于0吗？如果D不能等于0，它至少有多大？"
- Level：0.5（量级感知）
- 非特定性：0.7（引用了特定的稳定性方程和量D）

**检索为什么难**（以Q8为例）：
1. **不是关键词匹配**：A7中可能出现"D""k""n"这些符号，但这些符号在其他上下文中也会出现。关键词"D的下界"可能根本不在A7的文本中。
2. **不是RAG语义相似**：RAG会找"和A7文本最相似的存储文本"。但Q8的Pattern存储的不是"和A7相似的文本"，而是"当推理到达稳定性方程这个节点时，该问D的下界"这个**关系**。
3. **知识悖论**：辅助智能体读了Q8的Pattern——"D能等于0吗？至少有多大？"。它需要判断"这个Q对A7之后的状态有效吗？"这个判断需要理解D是什么、为什么D的下界重要——也就是需要数学知识。

## 5. 用户的核心贡献：检索问题本质的重新定义 <a name="5-用户的核心贡献"></a>

### 5.1 用户原文（完整保留，不做任何修改）

> 我觉得在我看来，我们的系统将来可以控制推理智能体的思考过程，到达某一步的时候，我们的辅助智能体通过检索机制——这就是我们要设计的，把此刻推理智能体未来应该考虑的所有方向全部找到，辅助智能体用DFS未来维护这些方向。这些方向存储在我们的数据基座中，成千上万，但是对于推理智能体到达某一步的时候，真正需要它考虑的，可能只有屈指可数的几件事，怎么把这几件事检索出来？我想应该是辅助智能体在形式化+智能性查询机制的帮助下，在我们数据基座中，找到了所有候选项。本质上，这是一个模式识别的过程，模式识别要回答比如：到了这一步，推理智能体下一步应该考虑什么？甚至是未来应该考察一下什么方向？这种模式识别，我们尽量利用形式化的方法，但是AI智能模式识别，我们也是必须要用起来的。比如说，如果我们的系统积累的模式，只有10个，那么问题就简单了，把10个模式用一个文件写好，让辅助智能体每次加载这个文件，然后再加载推理智能体此刻的上下文，辅助智能体就可以知道，此时满足了什么模式？记录到DFS中，用于后续提示推理智能体就行了。甚至可以就在此时，比如识别出了2个模式，那么就把推理智能体当前的完整上下文，分别给两个新的推理智能体，同时把两个后续工作方向分别给这两个推理智能体安排上，这样DFS，都可以并发了。

### 5.2 五个核心命题

用户的表述包含五个核心命题，每个都是对检索问题的重要重新定义：

**命题1：检索目标是"找此刻应考虑的所有方向"，不是"找最需要的一个Pattern"**

> "把此刻推理智能体未来应该考虑的所有方向全部找到"

这把检索目标从"精准提取一个"重新定义为"完备找全所有相关方向"。检索和选择解耦——检索负责找全（完备性），DFS负责决定探索顺序（策略性）。

**命题2：检索本质是模式识别**

> "本质上，这是一个模式识别的过程，模式识别要回答比如：到了这一步，推理智能体下一步应该考虑什么？"

用"模式识别"替代"检索"来理解这个问题。模式识别的输入是当前状态（不是查询关键词），输出是方向（不是具体内容），判据是模式匹配（不是相似性）。

**命题3：形式化+AI智能必须结合**

> "这种模式识别，我们尽量利用形式化的方法，但是AI智能模式识别，我们也是必须要用起来的。"

这不是"形式化做不了才用AI"的退路，而是"形式化和AI各有所长必须结合"的主动选择。形式化方法处理边界以内的部分（可规则定义的），AI智能处理边界以外的部分（需要感知的）。

**命题4：小规模时问题退化**

> "如果我们的系统积累的模式，只有10个，那么问题就简单了，把10个模式用一个文件写好，让辅助智能体每次加载这个文件，然后再加载推理智能体此刻的上下文，辅助智能体就可以知道，此时满足了什么模式？"

小规模时检索问题退化为纯模式识别问题（没有索引、粗筛、精化等工程复杂度），可以专注于验证"AI能否做模式识别"这个核心命题。

**命题5：DFS可以并发**

> "甚至可以就在此时，比如识别出了2个模式，那么就把推理智能体当前的完整上下文，分别给两个新的推理智能体，同时把两个后续工作方向分别给这两个推理智能体安排上，这样DFS，都可以并发了。"

识别出N个模式→启动N个推理智能体→每个走一个方向→并发探索。不需要回溯——每个方向从一开始就是独立的Session，独立的推理智能体，独立的context。

## 6. AI对用户表述的深度理解 <a name="6-ai对用户表述的深度理解"></a>

### 6.1 检索目标的重新定义：从"找最相似的一个"到"找此刻应考虑的所有方向"

253号文档把检索问题定义为"从海量Pattern存储中精准提取此刻最需要的那一个（或那一批）Pattern"。这个定义的焦点是**精准提取**——在海量存储中找到最匹配的那一个。

用户的表述把检索目标重新定义为：**"把此刻推理智能体未来应该考虑的所有方向全部找到"**。

这不是措辞差异，而是本质差异：

| 维度 | 253号的定义 | 用户的定义 |
|---|---|---|
| 检索目标 | 最需要的那一个Pattern | 此刻应考虑的所有方向 |
| 数量 | 一个（或一批） | 全部相关方向（可能2个、3个、屈指可数个） |
| 焦点 | 精准（找最匹配的） | 完备（找全所有相关的） |
| 后续动作 | 选一个发给推理智能体 | 全部记录到DFS，每个方向一个分支 |

**为什么这个重新定义重要**：

253号的定义隐含了一个假设——检索的目的是"选一个最好的Q发给AI"。这把检索问题和选择问题耦合在一起：不仅要找到相关Pattern，还要判断哪个"最需要"。

用户的定义把检索和选择解耦了：
- **检索的阶段**：找全此刻应考虑的所有方向（完备性目标）
- **选择的阶段**：在DFS中维护这些方向，决定探索顺序（策略性目标）

解耦后，检索问题变得更清晰——检索不需要判断"哪个最好"，只需要判断"哪些相关"。判断"哪个最好"是DFS的策略问题，不是检索问题。

### 6.2 检索的本质是模式识别

用户明确指出：**"本质上，这是一个模式识别的过程"**。

模式识别要回答的问题是：**"到了这一步，推理智能体下一步应该考虑什么？甚至是未来应该考察一下什么方向？"**

这个表述有几个关键点：

1. **"到了这一步"**——模式识别的输入是当前状态（推理智能体到达的某一步），不是查询关键词或文本。
2. **"下一步应该考虑什么"**——模式识别的输出是方向（应该考虑什么），不是具体内容（具体怎么做）。
3. **"未来应该考察什么方向"**——不只是眼前的下一步，还有更远的方向。这意味着模式识别可以输出多步的规划，不只是单步的提示。

**模式识别 vs 检索的区别**：

| 维度 | 传统检索 | 模式识别 |
|---|---|---|
| 输入 | 查询（关键词/文本） | 当前状态（推理到达的某一步） |
| 输出 | 相关文档 | 应考虑的方向 |
| 判据 | 相似性 | 模式匹配（当前状态满足什么模式） |
| 数量 | 一批相关文档 | 屈指可数的几个方向 |
| 精度 | 相关即可 | 必须精准——错误方向会误导推理 |

用"模式识别"替代"检索"来理解这个问题，会改变设计思路：
- 不再是"建索引→查询→排序"的检索管线
- 而是"提取状态特征→匹配模式→输出方向"的识别管线
- 索引不再是关键词索引或向量索引，而是模式特征索引

**与四代系统的关系**：四代系统其实都在做模式识别，只是没有用这个词：
- 盘古的"三维稀疏矩阵"——行是分析节点，列是星学意识——本质上就是模式识别：当前节点调用哪些意识？这就是"到了这一步应该考虑什么"。
- 女娲的"启发激活图H"——P→X——就是模式识别：看到模式P时激活X。X是"应考虑的方向"。
- 燧人的"形状匹配"——形状是模式的表示，匹配是模式识别。
- 伏羲的"识别不自然"——不自然是模式的触发信号，识别不自然就是模式识别。

四代的差异在于**模式怎么表示**和**识别怎么做**，但本质都是模式识别。用户用"模式识别"把四代的共同本质点出来了。

### 6.3 形式化+AI智能的混合是必须的

用户明确指出：**"这种模式识别，我们尽量利用形式化的方法，但是AI智能模式识别，我们也是必须要用起来的。"**

这不是"形式化做不了才用AI"的退路，而是"形式化和AI各有所长必须结合"的主动选择。

**形式化方法能做什么**：
- 结构化字段匹配（伏羲·[231]：处境类型+移动类型+证书类型）
- 图遍历和路径查询（盘古·[110]：BFS/DFS + AQL）
- 拓扑覆盖验证（盘古·[78]：AQL集合差集）
- 确定性的状态提取（女娲·[123]：W_t六类分量的schema）

**AI智能模式识别能做什么**：
- 识别"不自然"（伏羲·[219-221]：冗余/隐藏乘积/虚假自由度/隐藏直和——这些无法用规则定义）
- 感知Level（燧人·[214]：Level是"被感知的"不是"被赋值的"）
- 判断形状匹配（燧人·[214]：形状是拓扑的，但拓扑相似度需要AI感知）
- 在候选中选择（知识悖论的破解：不知道答案的AI做形式匹配）

**为什么必须结合**：

形式化方法处理的是**形式化边界以内**的部分——可以用规则定义、可以用代码执行的部分。AI智能处理的是**形式化边界以外**的部分——需要感知、需要模糊匹配、无法用规则定义的部分。

这与伏羲的"两种计算"（[223]、[236]）完全一致——经典计算管边界以内的验证，AI管边界以外的感知。模式识别正好横跨两侧：先用形式化方法缩小搜索空间（边界以内），再用AI智能在缩小的空间中做模式匹配（边界以外）。

### 6.4 小规模验证路径：10个模式时问题退化

用户给出了一个关键的小规模验证路径：**"如果我们的系统积累的模式，只有10个，那么问题就简单了，把10个模式用一个文件写好，让辅助智能体每次加载这个文件，然后再加载推理智能体此刻的上下文，辅助智能体就可以知道，此时满足了什么模式？"**

这是一个极其重要的工程洞察——**小规模时检索问题退化为什么？**

**退化分析**：

| 模式数量 | 检索机制 | 复杂度 |
|---|---|---|
| 10个 | 加载全部+AI判断 | O(1)——加载一个文件，AI一次性判断 |
| 100个 | 粗筛（形式化）+AI判断 | O(log n)——先缩小到10-20个，AI判断 |
| 1000个 | 三级种子选择+精化+AI判断 | O(log² n)——层次索引+图遍历+AI判断 |
| 325000个 | 完整检索管线 | O(log³ n)——多级索引+向量检索+图遍历+AI判断 |

**小规模退化的意义**：

1. **验证机制可行性**：如果10个模式时AI能正确识别"此时满足了什么模式"，说明模式识别的机制是可行的——AI有这个能力。如果10个模式时都做不对，说明机制本身有问题，扩大规模也不会好。
2. **隔离变量**：小规模时检索问题退化为纯模式识别问题（没有索引、粗筛、精化等工程复杂度），可以专注于验证"AI能否做模式识别"这个核心命题。
3. **快速迭代**：10个模式的实验可以在几分钟内完成，不需要ArangoDB索引、图遍历等基础设施。

**这实际上定义了一个POC-0**——在小规模（10个模式）下验证AI能否做模式识别：
- 用矩条件极差题第二问的10个Q作为10个模式
- 写成一个文件（patterns.md）
- 辅助智能体加载patterns.md + 推理智能体当前上下文
- 辅助智能体判断"此时满足了什么模式"
- 验证：判断是否正确（与QA序列中实际发送的Q对比）

### 6.5 并发DFS：从串行探索到并发探索

用户的最后一个洞察是DFS架构的重大升级：**"甚至可以就在此时，比如识别出了2个模式，那么就把推理智能体当前的完整上下文，分别给两个新的推理智能体，同时把两个后续工作方向分别给这两个推理智能体安排上，这样DFS，都可以并发了。"**

**串行DFS（燧人·[214]第8章）vs 并发DFS（用户提出）**：

| 维度 | 串行DFS | 并发DFS |
|---|---|---|
| 探索方式 | 一次一个方向，走不通回溯 | 同时多个方向，并发探索 |
| 回溯 | 需要新Session重放Q序列（回溯铁律） | 不需要回溯——每个方向独立推进 |
| 资源消耗 | 1个推理智能体 | N个推理智能体（N=识别出的模式数） |
| 时间效率 | 串行，慢 | 并发，快 |
| Context污染 | 回溯时有风险（回溯铁律的 raison d'être） | 无回溯，无污染 |
| 决策点 | 走不通后回溯到岔口选下一个方向 | 多个方向同时走，哪个先成功用哪个 |

**并发DFS解决了回溯铁律的痛点**：

[214]8.9节的回溯铁律——"禁止在同一个Session中让AI回溯到思路岔口，必须启动新Session重放Q序列"——是因为串行DFS中，回溯会导致context污染和压缩边界风险。

并发DFS根本不需要回溯——每个方向从一开始就是独立的Session，独立的推理智能体，独立的context。不存在"回溯到岔口"的操作，因为岔口的每个分支都已经有一个独立的探索者在走了。

**并发DFS的工程要求**：

1. **多推理智能体并发**：需要同时启动多个devin cli实例，每个在不同的工作目录中运行。
2. **上下文复制**：每个并发分支需要继承"当前完整上下文"——把Q序列和A序列重放到岔口的状态，作为新分支的起点。
3. **方向注入**：每个并发分支需要注入"后续工作方向"——即识别出的模式对应的Q。
4. **结果收集**：需要收集所有并发分支的结果，判断哪个（或哪些）成功了。

**与tmux-agents-dir模式的契合**：

本项目的Solver工作目录采用tmux-agents-dir模式——每个实验在 `/data/math-agent-glm5.2-tmux-agents-dir/` 下有独立的工作目录，运行后保留全部记录。并发DFS的每个分支就是一个实验目录：

```
/data/math-agent-glm5.2-tmux-agents-dir/
├── 255-poc-1/                    # POC-1主实验
├── 255-poc-1-branch-A/           # POC-1并发分支A（模式1对应的方向）
├── 255-poc-1-branch-B/           # POC-1并发分支B（模式2对应的方向）
└── 255-poc-1-branch-C/           # POC-1并发分支C（模式3对应的方向）
```

每个分支独立运行，独立记录，独立保留。成功了的结果回收到主实验目录，失败了的结果也保留（用于分析为什么这个方向走不通）。

### 6.6 辅助智能体的角色更清晰

用户的表述让辅助智能体的角色比253号更清晰：

**253号的定义**：助理智能体观察工作智能体状态，决定发送什么Q。角色是"观察者+决策者"。

**用户的定义**：辅助智能体通过检索机制找到此刻应考虑的所有方向，用DFS维护这些方向。角色是"模式识别者+方向管理者"。

区别在于：
- 253号中辅助智能体要做两件事：识别需要什么（感知）+ 决定发什么（选择）
- 用户定义中辅助智能体只做一件事：识别此刻满足哪些模式（模式识别）。选择由DFS策略决定，不需要辅助智能体判断"哪个最好"

这与6.1节的"检索和选择解耦"一致——辅助智能体负责检索（找全所有方向），DFS负责选择（决定探索顺序）。

**辅助智能体的工作流程（基于用户表述）**：

```
1. 加载模式文件（小规模）或通过检索机制获取候选模式（大规模）
2. 加载推理智能体此刻的上下文
3. 做模式识别：此时满足了哪些模式？
4. 把识别出的模式对应的方向记录到DFS中
5. （如果并发DFS）为每个方向启动一个新的推理智能体
6. （如果串行DFS）按Level排序，一次发一个方向给推理智能体
```

步骤1-3是模式识别，步骤4-6是DFS管理。模式识别是核心能力，DFS管理是执行策略。

### 6.7 两棵树：引导展开树与解题记录树 <a name="67-两棵树"></a>

在§6.5讨论并发DFS时，我们注意到一个此前被忽略的问题：用户在§5原文中说"辅助智能体用DFS未来维护这些方向"——这里"DFS"被当作树的名字的一部分（"DFS引导架构"）。但DFS只是遍历策略之一，不是树本身。把遍历策略和树的结构混为一谈，会限制我们对系统的理解。

本节厘清两棵树的本质和命名。

#### 6.7.1 第一棵树：引导展开树（过程）

**本质：从题目出发，在提示驱动下展开的所有可能解题路径构成的空间。**

拆开说：
- **每个节点** = 一个数学处境（当前已知什么、当前表示是什么、当前猜想是什么、卡在哪里）
- **每条边** = 一个提示Q（引导从一个处境移动到另一个处境的语义移动）
- **每条从根到叶的路径** = 一次完整的解题尝试
- **树的分支** = 在某个处境岔口，有不同的提示方向，每个方向展开出一条不同的路径

它**不是搜索树**——搜索是"在已知状态空间中找目标"，这里的路径不是预先存在于一个已知空间中等待被搜索，而是通过提示逐步**展开/生长**出来的。每次提示都是一次展开操作，把当前处境展开到下一个处境。

它**不是决策树**——决策树是分类/回归模型，这里是解题过程的记录。

它**不是依赖图**——依赖图是数学知识之间的依赖关系，这里是解题的尝试路径。

**"DFS"只是遍历这个空间的策略之一。** 串行DFS是一种策略，并发DFS是另一种策略，未来可能还有其他策略。但空间本身独立于遍历策略。

**命名：引导展开树（Guided Expansion Tree）。**

命名理由：
1. **"引导"** 准确描述了树的驱动力——是辅助智能体的提示在驱动展开，不是推理智能体自己在搜索
2. **"展开"** 准确描述了树的成长方式——通过提示逐步展开/生长，不是在已知空间中搜索
3. **不预设遍历策略**——DFS、并发DFS、未来其他策略都可以作用于同一棵树
4. **和现有术语形成清晰对比**——从"DFS引导架构"到"引导展开树"，去掉了遍历策略的预设，保留了引导的本质

#### 6.7.2 第二棵树：解题记录树（产物）

**本质：一道题在引导下被探索过的所有路径的完整记录——包括成功路径和失败路径。**

拆开说：
- 根 = 题目
- 内部节点 = 解题过程中经过的各个处境
- 边 = 提示Q
- 叶节点 = 成功叶（证毕）/ 死路叶（走不通）/ 截断叶（超限停止）
- 多条成功路径可能并存

**命名：解题记录树（Solution Record Tree）。**

命名理由：
1. **"解题"** 明确了树的领域——是解题过程的记录，不是其他什么记录
2. **"记录"** 明确了树的性质——它是完成后的产物，是凝固的经验，不是正在展开的过程
3. **和"引导展开树"形成清晰对比**——引导展开树是过程（活的），解题记录树是产物（凝固的）
4. **不预设用途**——它可以是Pattern来源、可以是教学材料、可以是审计依据，名字不限制它的用途

#### 6.7.3 两棵树的关系

**它们是同一棵树的不同阶段。**

- **引导展开树** = 过程中正在生长的树，活的，还在展开
- **解题记录树** = 展开完成后凝固的树，是引导展开树的完成态

如果不做后处理（剪枝、提炼），它就是引导展开树的完成态——同一棵树，只是停止生长了。

如果做后处理（剪掉死路、只保留成功路径、提炼成Pattern），那后处理后的产物是从这棵树中提取出来的，不是这棵树本身。

#### 6.7.4 为什么"DFS"不应在树的名字中

之前的文档（特别是[214]第8章）把这棵树称为"DFS引导架构"或"DFS树"。这个命名把遍历策略和树的结构混为一谈了：

| 概念 | 性质 | 独立于遍历策略吗 |
|---|---|---|
| 树的结构（节点+边+路径） | 空间结构 | 是——树是什么样子不取决于你怎么遍历它 |
| 遍历策略（DFS/BFS/并发） | 算法 | 否——遍历策略决定了你按什么顺序探索树 |

把"DFS"放进树的名字，隐含了一个假设：这棵树只能用DFS遍历。但用户的并发DFS洞察（§6.5）已经打破了这个假设——并发DFS不是传统DFS，它是同时展开多个分支。未来可能还有其他遍历策略。

**正确做法：树有树的名字（引导展开树/解题记录树），遍历策略有遍历策略的名字（串行DFS/并发DFS/...），两者分离。**

### 6.8 系统的本质：生长完整的解题记录树 <a name="68-系统的本质"></a>

把两棵树的本质厘清后，系统的本质也变得清晰了：

**数学大师系统的本质是：在不知道答案的情况下，通过引导展开机制，让AI生长出一棵尽可能完整的解题记录树。**

拆开说：
- **"不知道答案"** = 系统和AI都不知道正确路径，这是和"预演模式"的根本区别
- **"引导展开机制"** = 辅助智能体做模式识别，找到此刻应考虑的所有方向，注入提示驱动展开
- **"让AI生长出"** = 树是AI在提示下自己长出来的，不是系统预先画好的
- **"尽可能完整"** = 这是目标——不是只找一条成功路径，而是把所有值得探索的方向都探索到

#### 6.8.1 "更全"是什么意思

一棵完整的解题记录树包含：

| 组成 | 价值 | 没有系统时AI的表现 |
|---|---|---|
| 成功路径 | 这道题的解答 | AI可能找到1条或0条 |
| 失败路径 | 什么方向走不通、为什么 | AI卡住就停了，不记录失败 |
| 分叉点 | 在什么处境下有哪些方向 | AI只走自己想到的一个方向，不知道还有其他 |
| 中间处境 | 解题经过的各个状态 | AI不记录中间状态，只给最终答案 |

**裸跑的AI只产出一条路径（如果运气好），或者直接卡住（如果运气不好）。** 它不产出树——它不探索多个方向，不记录失败，不保留中间状态。

**系统的作用是让AI从"产出一条路径"升级为"产出一棵树"。** 通过引导展开，让AI在卡住时换方向，在岔口并发探索，把成功和失败都记录下来。

#### 6.8.2 各组件的统一角色

如果系统的本质是"生长完整的解题记录树"，那之前讨论的所有组件都有了清晰的角色：

| 组件 | 在"生长树"中的角色 |
|---|---|
| 引导展开树 | 正在生长的树（过程） |
| 解题记录树 | 展开完成的树（产物） |
| 模式识别/检索 | 在每个节点决定"该往哪些方向展开"——树的分叉来源 |
| 辅助智能体 | 树的园丁——识别方向、注入提示、驱动展开 |
| 推理智能体 | 树的生长点——在每个节点做数学、产出下一个处境 |
| 稀疏矩阵/数据基座 | 模式识别的知识来源——决定分叉方向的依据 |
| 并发DFS | 同时展开多个分支——让树长得更快更全 |
| Level排序 | 决定展开顺序——优先展开高Level方向 |
| Hint梯度 | 控制每条边的"知识泄漏量" |
| 回溯铁律 | 不在同一Session回溯——保证树的每个分支context干净 |
| 四门审计 | 审计每条边是否泄漏答案——保证树的"诚实性" |
| 单任务双产出（伏羲） | 跑一次树的生长，同时产出树的解和数据基座条目 |

**之前这些组件看起来是分散的设计点，现在它们统一了——都是为了让树长得更全、更诚实、更可复用。**

#### 6.8.3 数据基座是过去解题记录树的沉淀

数据基座（稀疏矩阵）的作用是什么？

**数据基座是过去解题记录树的沉淀——把过去树中的分叉点、成功路径、失败路径提炼成Pattern，供未来生长新树时做模式识别。**

- 过去的解题记录树 → 提炼 → 数据基座中的Pattern
- 未来的引导展开树 ← 模式识别 ← 数据基座中的Pattern

这是一个**自我增殖的循环**：树越长越全 → Pattern越积越多 → 模式识别越准 → 未来的树长得越全。

#### 6.8.4 评测标准：不是"做没做出来"，而是"树长得多完整"

如果系统的本质是"生长完整的解题记录树"，那系统的能力边界不是"能不能做出某道题"，而是**"能长出多完整的树"**。

- **弱系统**：长出一条路径就停了（裸跑AI）
- **中等系统**：长出几条路径，找到一条成功的（当前guided实验）
- **强系统**：长出完整的树，所有值得探索的方向都探索到，成功路径和失败路径都记录，分叉点都标注（目标）
- **大师级系统**：长出的树足够完整，从中提炼的Pattern能让未来类似题的树长得更快更准

**评测系统不应该只看"做没做出来"，应该看"树长得多完整"。** 一道题做出来了但只探索了一条路径，不如一道题做出来了同时记录了5条失败路径和3个分叉点——后者才是更完整的解题记录树，才是更有价值的资产。

#### 6.8.5 从面相4回指其他面相：系统全景

§6.8用面相4（树的生长）作为统一视角。但树的生长不是孤立的——它需要其他面相提供基础设施。从面相4回指其他6个面相，得到系统全景：

| 面相 | 在"树的生长"中的角色 | 回指本文位置 |
|---|---|---|
| 面相1·两种计算 | 树生长需要两种计算：经典计算做节点状态提取和拓扑验证（确定性部分），AI计算做模式识别和方向选择（非确定性部分） | §3.1盘古G'_topo+AQL、§3.4伏羲"不自然"识别 |
| 面相2·语料双路径 | 树生长的知识来源有两条路径：路径1（训练）让AI有模式识别能力，路径2（抽取）让数据基座有Pattern。两条路径的产物在树生长中汇合——AI用训练获得的能力从数据基座的Pattern中做模式识别 | §3.4伏羲[233]双重知识生产 |
| 面相3·Pipeline网络 | 树生长的执行基础设施——辅助智能体是模式识别引擎Pipe，推理智能体是数学推理引擎Pipe，Pipe之间的认知激活就是树的分叉机制 | §3.2女娲8角色、§6.6辅助智能体角色 |
| **面相4·树的生长** | **系统本质——生长完整的解题记录树** | **§6.7-6.8本节** |
| 面相A·实践涌现 | 树生长的设计从实践中涌现——guided实验暴露了串行DFS的局限，催生了并发DFS的洞察 | §3.3燧人guided实验、§6.5并发DFS |
| 面相B·知识选取 | 树生长的设计从知识中选取——AQL/图论/形式化边界/伴随关系为树的生长提供数学基础 | §3.1盘古AQL、§3.4伏羲形式化边界 |
| 面相C·设计过程自举 | 树生长的设计过程是自举的——四代演进是自举循环，每代暴露的差距催生下一代对树生长机制的改进 | §3.5四代演进趋势 |

**系统全景**：数学大师系统通过引导展开机制生长解题记录树（面相4）。树的生长需要两种计算（面相1）——经典计算做确定性部分，AI计算做非确定性部分。两种计算通过Pipeline网络（面相3）执行——模式识别引擎Pipe决定分叉方向，数学推理引擎Pipe产出新节点。树生长的知识来自语料双路径（面相2）——AI的计算能力来自训练，Pattern来自数据基座抽取。四代演进（面相C）中，每代对树生长机制的改进来自实践涌现（面相A）或知识选取（面相B）。

## 8. 后续方向 <a name="8-后续方向"></a>

### 8.1 检索问题的最终定义（基于用户表述修正253号定义）

**给定**：
1. 推理智能体的当前状态（一段推理输出 + 累积context）
2. 数据基座中的模式存储（每个模式描述"什么状态下应该考虑什么方向"）

**求**：
- 此刻推理智能体应该考虑的所有方向（不是"最需要的一个"，而是"全部相关方向"）

**机制**：
- 模式识别：辅助智能体识别当前状态满足哪些模式
- 形式化+AI混合：形式化方法缩小搜索空间，AI智能做模式匹配
- 小规模退化：模式少时直接加载全部+AI判断

**输出**：
- 识别出的模式列表，每个模式对应一个方向
- 全部记录到DFS中，按策略探索（串行或并发）

**约束**：
1. 模式识别的输入是当前状态，不是查询关键词
2. 模式识别的输出是方向，不是具体内容
3. 形式化方法和AI智能必须结合
4. 辅助智能体不需要知道答案（知识悖论的约束）

### 8.2 具体待调查问题

1. **形状的结构化表示**：燧人的"形状"是拓扑的，但未实现具体表示。伏羲的"不自然"种类（冗余/隐藏乘积/虚假自由度/隐藏直和）是否可以作为形状的结构化字段？两者如何统一？

2. **Level的感知机制**：燧人的Level是"被感知的"而非"被赋值的"，但未实现感知算法。女娲的state_reducer（Krippendorff α≥0.80）是否可以为Level感知提供质量保证？

3. **路径结构匹配的算法**：伏羲的"路径结构匹配"是核心匹配范式，但未实现算法。盘古的AQL集合差集是否可以扩展为路径结构匹配的确定性验证？

4. **激活包与数学工程单元的统一**：女娲的"激活包"和伏羲的"数学工程单元"是否可以统一为同一个Pattern存储格式？

5. **并发DFS的上下文复制机制**：如何把Q序列和A序列重放到岔口的状态，作为新分支的起点？

6. **POC验证路径**：用矩条件极差题第二问作为POC测试用例，设计可验证的检索机制。

### 8.3 检索问题的认识论意义

检索问题最终指向一个关于数学思维本质的问题：**数学思维本身能不能被结构化到足以被检索？**

- 如果数学思维纯粹是直觉的、不可言传的 → 检索问题无解，只能依赖Master的直觉
- 如果数学思维完全可形式化 → 检索问题退化为经典计算，盘古的AQL差集就够了
- **现实是：数学思维在形式化边界上**——部分可形式化（边界以内），部分是感知（边界以外）

检索问题的本质，就是**在形式化边界上做模式识别**——用边界以外的感知能力定位缺口，用边界以内的形式化知识补全缺口。

这不是一个工程问题，而是一个关于**知识结构**的认识论问题。POC系列不是在解决一个技术难题，而是在验证一个认识论假设：**形式化边界上的模式识别是否可行**。

如果POC系列通过，我们验证的不只是一个检索机制，而是"数学思维可以被结构化到足以在形式化边界上做模式识别"这个更深的命题。如果POC系列失败，我们可能需要接受：数学思维中有某些成分永远在检索之外，只能依赖人的直觉。
