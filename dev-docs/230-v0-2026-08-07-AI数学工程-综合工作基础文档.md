## 1. 确定的核心共识

这些是224-229所有讨论都同意的，不需要再讨论。

### 1.1 两种计算的本质区别

**AI计算**：处理还没有完全形式化的意义——感知、模式识别、类比、猜测表示变换、判断哪里不自然、组织证明叙述。擅长提出候选，但难以稳定区分"看起来像真的"和"已经被确认是真的"。

**经典计算**：处理已经被压缩成明确对象的任务——枚举、化简、因式分解、求解约束、检查类型、验证证明、生成反例、维护依赖图。擅长精确执行，但不知道该算什么。

**两者互补**：AI负责把模糊数学意义压缩成值得计算的对象；经典计算负责把这些对象推进到可确认的结果；确认结果再回到AI的语义理解中。这个闭环是路线本身。

### 1.2 225的三个核心直觉

1. **处境会生长**：数学问题在解题过程中会变形——原题是不等式，中心化后变成矩问题，找到q(x)后变成多项式非负证书，再变成对偶极值问题。问题不是静态点，是会生长的处境。

2. **经典计算会反向生产语义**：经典计算不只是检查AI的输出——它主动产生结构。因式分解产生隐藏乘积，求解器产生反例，数值验证产生量级事实。这些结果回流改变AI的理解。

3. **自然性>连续性**：非特定性不是"策略在邻域内连续有效"（224的连续性），而是"方法在表示变换下保持意义"（225的自然性）。数学策略的迁移经常跨越很远的表面距离——代数变几何，组合变概率——表面拓扑可能很远，但自然结构很近。

### 1.3 227的三个实质修正

1. **反例是证书，不是语义场元素**：反例证明"存在对象使猜想失败"——这是正向证书，证明否定命题。它和"证明X成立"一样硬、一样可靠。三类区分：正向证书（证明X成立）→ 证书层；反驳证书（证明X不成立，通常是反例）→ 证书层；诊断反馈（类型错误、工具超时、翻译缺口）→ 反馈层。

2. **证书不能压成单一偏序**：证书有多个维度——声明（claim）、适用范围（scope）、强度（strength）、依赖链（dependencies）、检查机制（checker）、状态（status）。范围收缩不是加强——"对n≥4且n偶数成立"不能替代"对n≥4成立"。把范围收缩误当成单调增长，系统会以为越来越强，实际只是越来越窄。

3. **obstruction ≠ H¹**：粘合失败首先是descent failure（最一般）；当差异对象可被记录比较时是obstruction object；当差异能写成转换函数时是Čech 1-cocycle；只有当系数对象满足相应条件时才是H¹ class。H¹是特殊情况，不是所有粘合失败的默认形式。

### 1.4 218号非特定性危机的解决方向

218号危机：引导者通过引用AI选的特定方向，隐含地确认了正确路径——"面向答案做引导"的隐蔽形式。

解决方向：非特定性应该是一个**可检查的数学条件**，不是设计目标。具体方向是——方法在表示变换下是否满足交换（或近似交换/可证交换）。如果一个方法只对特定问题的特定表示有效，换表示就失效，它是特定的；如果在表示变换下仍然有效，它是非特定的。

**注意**：这个条件的精确形式还是候选的（见§2.3），但方向是确定的——非特定性必须可检查。

### 1.5 下一步跑矩条件极差题

所有讨论都同意：不要再先写更高阶的抽象框架，应该用一个具体例子跑通闭环。最自然的例子是矩条件极差题，因为它同时包含换表示、局部证书、反例压力、形式化目标和粘合问题。

## 2. 候选的数学结构

这些有方向但未验证。需要在跑例子中确认哪些自然出现、哪些不出现、哪些需要修正。

### 2.1 语义场Σ是范畴（候选）

**方向**：Σ是范畴，对象是数学处境，态射是保持数学意义的操作。

**态射类型**（227建议分型，228-glm5.2建议用标注替代分层）：
- 表示变换（换坐标、等价改写）——希望可逆，保持意义
- 规范化（中心化、归一化）——可能有损，可能丢掉冗余自由度
- 对偶化——可能是等价，也可能只是弱对偶
- 特例化——让命题变容易，但不能反向证明原命题
- 推广——让命题变强，但可能引入额外结构
- 形式化翻译——有忠实性问题

**待验证**：
- Σ是否需要范畴结构，还是集合就够了？
- 如果是范畴，态射是分型（227）还是加标注（228-glm5.2）？
- 加权范畴或富范畴是否需要（态射有"保持多少意义"的连续值）？

### 2.2 证书系统C是带字段的偏序范畴（候选）

**方向**：C是偏序范畴，但证书对象带字段，不是单一偏序。

**证书对象结构**：
```
Certificate
  claim        被证明的数学声明
  scope        声明适用的范围
  strength     声明的强度
  dependencies 依赖链
  checker      检查机制
  status       已验证、已反驳、诊断失败、未知
```

**偏序的层级**：
- 在固定claim和scope的纤维里，强度形成偏序
- 在固定结论强度时，适用范围按反方向排序
- 依赖链是审计图，不直接和结论强度混成一个序

**三类证书**：
- 正向证书（证明X成立）→ 证书层
- 反驳证书（证明X不成立，通常是反例）→ 证书层
- 诊断反馈（类型错误、工具超时、翻译缺口）→ 反馈层

**系统状态**：C的向下封闭理想I_t，单调增长（I_t ⊆ I_{t+1}）。

**待验证**：
- 带字段证书对象在实际中是否可操作？
- 三类区分在实际中是否清晰？

### 2.3 自然性是交换图（候选，分层）

**方向**：方法m是自然的，如果对于表示变换τ:S→S'，交换图（近似/可证）成立：

```
S ──m──→ S_V   （在S上用方法m，产生证书目标）
│        │
τ        τ'
│        │
S'──m'──→ S'_V  （在S'上用方法m'，产生证书目标）
```

**分层**（227建议）：
- **强自然性**：在等价表示下可证交换——可检查（交换图是否闭合）
- **弱自然性**：在非等价但保目标的移动下lax交换——部分可检查（需定义"松弛"的度量）
- **经验稳定性**：在变体族上稳定产生同类证书目标——统计判断，不是数学条件

**待验证**：
- 分层后可检查性是否保持？（228-glm5.2指出：分层后只有第一层可检查，后两层退回AI判断）
- 是否可以用数学证明/半形式化比较/统计测试分别覆盖三层？
- 误差项（交换图不严格闭合时的差异）怎么定义？

### 2.4 可证化V和反射R是伴随-like结构（候选，最不确定）

**方向**：V（语义→证书）和R（证书→语义）形成某种双向连接。

**226-v0发现**：V和R不是严格函子——不是每个语义移动都产生证书目标，一个移动可能产生多个目标。所以不是严格伴随F⊣G。

**候选结构**（从强到弱）：
- 严格伴随F⊣G——已排除（V/R不是函子）
- Lax adjunction——允许方向性不等式，误差项捕捉部分多值性
- Galois connection——在预序之间，不需要函子，但V不是预序映射
- 带效应的闭环（Kleisli范畴）——227建议，但未验证T的定义
- 反馈循环——226-v0的粗暴说法，最弱但最安全

**227的修正**：原始V/R是带效应的语义证书闭环。Galois connection或lax adjunction不是原始结构，而是对闭环做稳定化、闭包化之后可能出现的派生结构。

**待验证**：
- 跑例子时，V和R的实际行为更像哪个候选？
- 闭包化（α(S)=从S可稳定产生的证书理想，γ(I)=与I相容的处境约束）是否可行？

### 2.5 图册是Grothendieck拓扑（候选，需从例子中长出来）

**方向**：一个处境有一组局部表示（图册），覆盖是一组能共同看清处境的表示，粘合条件是局部证书在重叠处一致。

**227的修正**：不要直接宣布Σ是site。先定义局部证书预层Cert: Σ_rep^op → Pos，先定义重叠对象，先定义证书拉回。当某些覆盖族满足descent条件时，它们才构成Grothendieck拓扑。site不是预设，是从可粘合的覆盖族里长出来的。

**待验证**：
- 矩条件极差题的多种表示（代数/中心化/多项式/极值/对偶）是否构成覆盖？
- 重叠对象在实际中是否可定义？
- 证书拉回在实际中是否可操作？
- 粘合条件是否满足？如果失败，obstruction是什么级别？

### 2.6 能量是多分量序量（候选）

**方向**：语义能量不是单个实数，是六分量序量。

**六个分量**：
1. 表示复杂度（变量数、表达式长度、AST大小）——可近似计算
2. 证书距离（当前理想到目标证书的距离）——很难计算（等于问题难度）
3. 自由度残差（表面自由度减实际自由度）——代数中可算，一般只能估计
4. 粘合缺陷（不一致的局部证书对数）——有预层时可算，否则只能记录
5. 反例压力（例子在扰动下保持猜想的概率）——依赖例子生成器
6. 形式化缺口（模糊声明到可检查目标的转化率）——工程指标

**下降方式**：
- 226-v1：Pareto改善（至少一个分量下降且其他不上升）——可检查但太严格
- 227：受控交换（允许某个分量上升，如果可被解释、记录、后续偿还）——灵活但不可检查
- 228-glm5.2建议：双标准共存（Pareto作为严格标准，受控交换作为启发式标准）

**待验证**：
- 六个分量在实际中是否可计算/估计？
- Pareto改善是否太严格？受控交换是否太模糊？
- 双标准共存是否可行？

## 3. 工程骨架

这些是228-codex提出的工程概念，作为跑例子的操作框架。

### 3.1 执行契约

每次AI数学动作必须说明四件事：

```
Semantic Move
  我在改变什么处境？
  我预期降低什么困难？
  我能把它编译成什么经典计算任务？
  经典计算返回后，我准备如何更新语义场？
```

**228-glm5.2的警告**：执行契约可能太工程化——数学家的探索性移动经常不是目标导向的。中心化b=a-1时AI可能不知道"预期降低什么困难"，它只是感觉"一阶矩应该消掉"。强制填写可能迫使它编造事后解释。

**修正**：执行契约的"预期降低什么困难"字段允许填"探索性移动，暂不确定"。但"编译成什么计算任务"和"返回后如何更新"必须填——这两个是闭环的关键，不能省。

### 3.2 闭环动力学

```
循环：
  1. AI读取当前处境S和证书账本I，提出语义移动m
  2. m通过执行契约编译成经典计算任务
  3. 经典计算执行，返回结果r
     - 成功 → 证书c加入I
     - 反例 → 反驳证书加入I
     - 障碍 → 诊断反馈加入反馈层
     - 未知 → 保留为待解释的压力
  4. 结果r反射回语义场，更新S
  5. 回到1
```

### 3.3 对照实验设计

**同一批问题，两条路线跑**：

| 维度 | 单纯AI路线 | 闭环路线 |
|---|---|---|
| AI模型 | 同一个 | 同一个 |
| Prompt | 同样的初始题目 | 同样的初始题目 |
| 温度 | 相同 | 相同 |
| Python计算 | 允许（否则对比不公平） | 允许 |
| 执行契约 | 不要求 | 要求 |
| 证书账本 | 不维护 | 维护 |
| 结果回流 | 不强制 | 强制（每次经典计算结果必须改变下一步） |

**比较指标**：
- 产生了多少可验证局部证书
- 发现了多少真实反例
- 排除了多少错误方向
- 有多少结论可以回放
- 有多少模式能迁移到变体题
- 最终证明中有多少步骤依赖可审计证据
- 出错时能否定位是猜想错、表示错、翻译错，还是检查器边界问题

**注意**：单纯AI路线也允许Python计算——否则对比不公平。区别在于：单纯AI路线不强制执行契约、不维护证书账本、不强制结果回流。闭环路线强制这三件事。

## 4. 十种能力（228-codex，作为验证清单）

经典计算加入闭环后，系统应该获得这十种能力。跑例子时检查哪些出现了：

1. **可靠性边界**——AI提出引理，经典计算回答是否成立
2. **反例生产**——经典计算搜索小模型、边界情况
3. **结构显影**——因式分解、消元、正规形显露新结构
4. **搜索空间裁剪**——不可行方向标记为死路
5. **局部证书积累**——局部等式/不等式/子引理逐步获得证书
6. **形式化压力**——迫使AI把模糊感觉压成可检查声明
7. **依赖审计**——维护依赖图，回答"如果这个条件删掉，哪些结论还成立"
8. **粘合检查**——检查多个表示的局部理解是否相容
9. **可回放性**——计算过程可记录、可重复、可复查
10. **模式库真实增长**——每个模式附带适用信号、证书模板、失败案例

**注意**（228-glm5.2的修正）：十种能力是列举不是结构。它们之间的关系待在跑例子中澄清——哪些是基础的，哪些是派生的，哪些是冗余的。

## 5. 下一步：矩条件极差题闭环样例

### 5.1 为什么选这道题

矩条件极差题同时包含：
- 换表示（中心化、多项式表示、对偶表示）
- 局部证书（恒等式、符号条件、反证步骤）
- 反例压力（第二部分的n^(-1/3)错误）
- 形式化目标（每个恒等式可被SymPy验证）
- 粘合问题（多个表示的局部结论能否合成整体证明）

### 5.2 跑法

**第一部分（C=√5）**：

按闭环动力学跑，每一步记录：

| 步骤 | AI语义移动 | 执行契约 | 经典计算任务 | 结果 | 证书/反馈 | 语义场更新 |
|---|---|---|---|---|---|---|
| 1 | 中心化b=a-1 | 改变：消掉一阶矩；编译：验证中心化保持极差 | SymPy验证 | 成功 | 正向证书 | 可以用中心化表示 |
| 2 | 找q(x)使Σq(bᵢ)=0 | 改变：找多项式恒等式；编译：验证Σq(bᵢ)=0 | SymPy验证 | 成功 | 正向证书 | q(x)=x²+x-1可用 |
| 3 | ... | ... | ... | ... | ... | ... |

**第二部分（n^(-1/3)错误）**：

同样跑法，重点记录：
- AI何时发现数值结果与题目声称不兼容
- 这个发现是反例证书还是诊断反馈
- 粘合障碍是什么级别（descent failure / obstruction / Čech / H¹）
