# 102-AGENTS.md技术说明内联方案

> **文档定位**：把工作系统和数学大师系统的关键技术说明从dev-docs内联到AGENTS.md中，确保跨session/压缩后AI不丢失"怎么用"的意识。加上依赖标注，确保dev-docs更新时同步更新AGENTS.md。

## 一、问题

当前AGENTS.md有：
- 项目定位、核心信念、方法论核心（为什么做）
- dev-docs索引（89-101号文档列表）
- 工作系统纪律（5条约束）
- 工作系统实现状态（文件列表）

**缺什么**：没有"怎么用"的技术说明。AI跨session/压缩后，知道"有工作系统"，知道"有哪些文档"，但不知道"怎么执行CP1-CP6""怎么跑七步骤工作流""怎么用种子推荐表"。要读dev-docs才能恢复这些操作认知——但AI不知道自己需要读哪些文档的哪些部分。

## 二、方案

在AGENTS.md中新增两节技术说明，每节末尾加"依赖维护"标注：

### 2.1 工作系统技术说明（新增节）

内容包括：
- CP1-CP6工作流：每个CP是什么、怎么执行、具体命令
- 认知图查询：怎么查统计、怎么遍历、怎么审计
- 种子推荐表：怎么用、5种问题类型
- 回归验证：怎么跑、ground truth怎么建
- Hook机制：三个hook的分工、UserPromptSubmit.txt怎么改

### 2.2 数学大师系统技术说明（新增节）

内容包括：
- 七步骤工作流：每步是什么、怎么执行、具体命令
- 依赖图导入：怎么导入ArangoDB
- G'_topo生成：经典计算展开（topo_generator.py）
- TopologyVerifier：拓扑覆盖验证
- 三层提取：L1/L2/L3 + 版本链管理

### 2.3 依赖维护标注

每节末尾加一个"依赖维护"表：

```
| 本节内容 | 依赖文档 | 更新触发条件 |
|---|---|---|
| CP1-CP6工作流 | 91号文档 | CP流程变更时 |
| 种子推荐表 | 100号文档 | 推荐表内容变更时 |
| ...
```

当依赖文档更新时，必须同步更新AGENTS.md中对应的技术说明。

## 四、诚实面对

1. **AGENTS.md会变长**：新增两节技术说明会增加约100-150行。但这是有意的——这些内容是"跨session必须保持的操作认知"，值得占用always-on上下文。

2. **技术说明是摘要不是全文**：AGENTS.md中的技术说明是操作级摘要（怎么执行），不是完整方案（为什么这样设计）。完整方案仍在dev-docs中，AGENTS.md只放"怎么用"。

3. **依赖维护靠纪律**：依赖维护标注本身不能自动触发更新——靠AI读到标注后自觉同步。这和三层维护机制一致（CP4提示+AGENTS.md约束+认知图依赖）。
