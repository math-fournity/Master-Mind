## 1. Pipeline与元组群的关系

**两套独立系统**：

| 系统 | 关注什么 | 对应什么 |
|---|---|---|
| **guided-math-solving元组群** | 问什么Q、怎么评估Level、怎么回溯 | 数学引导方法论 |
| **执行Pipeline** | 怎么跑实验、怎么捕获数据、怎么处理工程问题 | 操作工作流 |

它们独立但通过接口对接：Pipeline调用元组群的Skill，但Pipeline自己管的是"实验运行的操作步骤"。

## 2. guided_001实际执行的Pipeline

### 步骤1：选题目+写problem.txt
- 从历史记录中获取题目
- 写入work_dir/problem.txt

### 步骤2：清理work_dir+启动session
- `find work_dir -maxdepth 1 -type f ! -name "AGENTS.md" -delete`
- `mkdir -p runs/<run_id>/{exports,captures}`
- `tmux new-session -d -s guided-exp-1 "cd work_dir && devin --model glm-5-2 --export <path>"`
- `tmux pipe-pane -t guided-exp-1 "cat >> runs/<run_id>/tmux_pipe.log"`
- 等待5秒，检查trust prompt

### 步骤3：循环执行引导交互
每轮交互的操作：
1. 通过`tmux send-keys`发送Q
2. `sleep 45-120`等待AI回复
3. `tmux capture-pane -t guided-exp-1 -p -S -100`捕获A
4. 判断A的状态（progressing/stuck/success/dead_end）
5. 更新dfs_tree.json
6. 决定下一步

### 步骤4：处理工程问题
实际执行中遇到的Pipeline级问题：

| 问题 | 处理方式 |
|---|---|
| AI回复被token限制截断 | 发送"请继续，你刚才的回复被截断了" |
| AI运行Python需要审批 | 捕获审批prompt，发送"1"(approve once)或"2"(always allow) |
| --export文件没生成 | 改用pipe-pane日志作为兜底记录 |
| capture-pane缓冲区不够 | 调整`-S`参数（如`-S -200`） |
| AI思考时间很长 | 增加sleep时间到90-120秒 |

### 步骤5：记录结果
- 保存dfs_tree.json
- 保存result_summary.json
- tmux_pipe.log自动记录（pipe-pane持续运行）
- session结束后transcript自动生成在`~/.local/share/devin/cli/transcripts/`

## 3. Pipeline中发现的工程问题

### 3.1 --export参数问题
- `--export <path>`在交互式模式下可能不生效
- 文档显示正确用法是`devin --export out.json -- fix tests`（带`--`分隔符）
- 交互式模式可能需要不同用法
- **解决方案**：依赖pipe-pane日志（兜底）+ session结束后的transcript（权威）

### 3.2 transcript生成时机
- transcript在session结束后才写入`~/.local/share/devin/cli/transcripts/`
- session运行中无法获取transcript
- **解决方案**：运行中用pipe-pane + capture-pane，结束后用transcript

### 3.3 审批prompt处理
- AI运行exec（如python3）需要用户审批
- 审批prompt出现在tmux pane中，需要手动选择
- **解决方案**：capture-pane检测审批prompt，send-keys发送选项编号
- **改进**：可以预先设置`--permission-mode dangerous`或配置always-allow规则

### 3.4 AI回复截断
- GLM-5.2的max output token限制可能导致长回复被截断
- 截断时显示"Response truncated"
- **解决方案**：发送"请继续"让AI继续输出

### 3.5 AI思考时间
- GLM-5.2在复杂推理时可能思考2-5分钟
- 思考期间pane显示"Thinking · Xm Ys"
- **解决方案**：增加sleep时间，或轮询检查pane状态变化

## 4. Pipeline的待规范化内容

以下内容在积累几次实验后，考虑升级为独立元组群或skill：

1. **session启动标准流程**（清理+启动+pipe-pane+trust prompt处理）
2. **交互循环标准流程**（send-keys+sleep+capture+判断+记录）
3. **工程问题处理手册**（截断、审批、超时、export失败）
4. **数据收集标准**（dfs_tree+pipe-pane+transcript+result_summary）
5. **结果验证标准**（和standard_answer对比+证明完整性检查）

## 5. 与guided-math-solving元组群的接口

Pipeline调用元组群的方式：

| Pipeline步骤 | 调用的元组群Skill |
|---|---|
| 选题目+写problem.txt | （无，Pipeline自己的步骤） |
| 预演 | Skill 1 guided-rehearsal |
| 启动session | Skill 2 guided-session-launch |
| 交互引导循环 | Skill 3 guided-interaction |
| 回溯（如需要） | Skill 4 guided-backtrack |
| 持久化数据 | Skill 5 guided-data-persist |
| 评估结果 | （无，Pipeline自己的步骤） |

Pipeline管"怎么跑实验"，元组群管"怎么引导AI"。两者通过Skill调用接口对接。
