## 一、模块功能概览

context_compiler子系统负责编译上下文（每段带5项记录）、审计最小性、记录裁剪、保存状态快照。

| 模块 | 功能 |
|---|---|
| context_compiler | 编译上下文，每段带5项记录，支持最小性审计和checkpoint连续性 |
| minimality_audit | 3项审计（冗余/缺失/预载），检查上下文是否被当前义务直接需要 |
| pruning_log | 记录裁剪操作（原因/时间戳/原始大小/裁剪后大小） |
| state_snapshot | 8字段充分统计量快照，与EventLog分离 |

## 二、审计检查项

### 2.1 上下文编译质量（context_compiler.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 5项记录 | 每段有source/visibility/evidence_level/token_cost/pruning_record | 5项全部存在 |
| 可追溯 | 每段可追溯到原始来源 | source字段指向原始来源 |
| 角色边界 | 落实为collection/visibility label/能力令牌 | 不只写在prompt里 |
| 按需展开记录 | 按需展开请求记录为事件 | 展开请求被记录 |
| checkpoint连续性 | 从checkpoint继续编译 | 不从头编译 |

**判定**：通过=5项全通过；有缺陷=5项记录有小缺失；失败=缺少5项记录或不可追溯或从头编译

### 2.2 最小性审计（minimality_audit.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 3项审计全执行 | 冗余/缺失/预载全部执行 | 3项都有结果 |
| 冗余检查 | 上下文是否被当前义务直接需要 | 无冗余error |
| 缺失检查 | 是否缺少必要内容 | 无缺失error |
| 预载检查 | 是否预载了未来答案路线 | 无预载error |
| 预载是error级 | 预载答案路线是error不是warning | 预载=error |
| 内容回溯 | 内容能回溯到open义务 | 所有内容都有对应义务 |

**判定**：通过=6项全通过；有缺陷=3项执行但有小遗漏；失败=有冗余/缺失/预载error或预载不是error级

### 2.3 裁剪记录（pruning_log.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 裁剪原因明确 | reason不能为空 | 每条裁剪记录有reason |
| 时间戳 | 自动生成时间戳 | timestamp字段非空 |
| 大小记录 | 原始大小和裁剪后大小 | original_size/pruned_size都有 |
| 可查询 | 支持按content_id查询 | 查询接口可用 |

**判定**：通过=4项全通过；有缺陷=有记录但原因不明确；失败=裁剪无记录或原因为空

### 2.4 状态快照（state_snapshot.py）

| 检查项 | 说明 | 标准 |
|---|---|---|
| 8字段完整 | q0/accepted_propositions/open_goals/current_representation/recent_key_path/rejected_routes_summary/tool_evidence/current_hint | 8个字段全部存在 |
| 充分统计量 | 只保留充分统计量不保留全部历史 | 不是全部历史 |
| 与EventLog分离 | 双层结构分离 | 快照和事件日志分开存储 |
| recent_key_path过滤 | 是过滤后的关键路径不是全部历史 | 经过过滤 |

**判定**：通过=4项全通过；有缺陷=8字段有小缺失；失败=字段缺失或与EventLog混在一起或保留全部历史
