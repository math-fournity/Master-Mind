# IMO 2009 P6 脉络分析——综合分析报告

## 0. 题目与证明概要

**题目**：蚱蜢在实轴上从0出发做n次向右跳跃，跳跃长度为n个不同正整数a₁,...,aₙ的某种排列。M是n-1个正整数的集合且不含s=a₁+...+aₙ。证明：可以选择跳跃顺序使蚱蜢从不落在M中的任何点上。

**证明策略**：WLOG排序a₁<...<aₙ，设x=a₁+...+a_{n-1}（除最大元外之和），对n做强归纳。按M中元素相对x的位置分三种情形：
- **Case 1**（x∈M且∃y∈M,y>x）：定义bad index，用注入+鸽巢找到好指标r，缩减M'=M∩(-∞,t]（t=x-aᵣ），归纳得p'，swap构造完整排列。
- **Case 2**（x∉M且∃y∈M,y>x）：直接缩减M'=M∩(-∞,x]，归纳得p'，末尾放aₙ。
- **Case 3**（所有m∈M满足m≤x）：令z=max(M)，M'=M\{z}，归纳得p'，若p'命中z则swap aₙ到命中位置跳过z。

### 看法差异

- **V5**（自由直觉）：段最粗，每段多特征标注，特征描述性强但粒度不均。如段7同时标注"注入构造/鸽巢论证/像集分离/双射上界"四个特征描述同一论证的不同侧面。无形式上下文，无法做FCA枚举。

- **V7**（结构化约束）：17个抽象特征，每段1-2特征。特征粒度统一但偏粗——"定义变量"同时覆盖x(段2)、t/M'(段12)、z/M'(段25)三种本质不同的定义。形式上下文稀疏，闭元素20个，主要捕获跨Case的步骤统一性（如ce_V7_6 {段14,20,26} 捕获三Case归纳应用）。

- **V8**（跨闭元素元模式引导）：31个特征，引入"x的使用"/"s的使用"/"aₙ的最大性"等跨切面特征，使元模式在形式上下文中可见。段最细（32段），闭元素48个。但段过细导致部分闭元素extent过大（如ce_V8_41有13段intent=[x的使用]）。V8独有的"s的使用"特征捕获了s的跨段角色（ce_V8_36），这是V10遗漏的。

- **V10**（跨闭元素元模式引导+关键实体）：27个特征，其中7个实体特征(实体:x/aₙ/强归纳/swap技巧/M'缩减/bad index/z)。段粒度回归自然（21段），实体特征直接编码跨闭元素元模式。闭元素37个。key_entities.json提供7个关键实体的跨段角色描述。闭元素语义可读性最好——如ce_V10_12 {段10,14,18} intent=[实体:M'缩减,实体:强归纳,应用归纳假设]直接读出"三Case统一归纳模式"。

### 基础格化选择

**选择V10为基础**，理由：
1. 段粒度自然——不过细(V8)也不过粗(V5)，每段对应一个可识别的思维步骤
2. 实体特征直接捕获跨切面模式——"实体:x"在11个段中出现，直接编码x的贯穿性
3. key_entities.json提供元模式线索——7个关键实体的跨段角色描述
4. 闭元素语义可读性最好——intent中的实体特征使闭元素的语义解读最直观

**交叉参考V8**：V8的"s的使用"和"aₙ的最大性"细粒度特征补充V10未覆盖的元模式。V8的ce_V8_36 {段7,8,9,段15} intent=[s的使用]是发现s作为隐藏贯穿变量的关键线索。

**交叉参考V7**：V7的粗粒度提供"三Case都有变量定义"的高层视角，作为交叉验证。

## 2. 形式上下文回溯检查

### 2.1 完备性检查

**结论：V10形式上下文不完备，发现2处需修正的遗漏。**

#### 遗漏1：aₙ的"跳过障碍"功能只标注在Case 3

V10的"跳过障碍"特征仅标注在段19（Case 3 swap跳过z）。但aₙ的跳过障碍功能实际贯穿三个Case：

| Case | 段 | aₙ的跳过机制 |
|------|-----|-------------|
| Case 1 | 段11 | aₙ放在倒数第二位，从t跳到s-aᵣ，越过(t,s-aᵣ)中的M元素 |
| Case 2 | 段15 | aₙ放在末位，从x跳到s，越过(x,s)中的M元素（含y） |
| Case 3 | 段19 | aₙ swap到位置k，越过z |

**修正**：为段11和段15增加"跳过障碍"特征。修正后ce_V10_11 {段11,段15,段19}的intent从[实体:aₙ,构造排列]丰富为[实体:aₙ,构造排列,跳过障碍]。

**注意**：此修正不创建新闭元素（extent不变），但丰富了已有闭元素的intent。即使修正后，"aₙ的跳过障碍功能"作为语义层面元模式仍需AI解读——程序看到的是"三个段共享跳过障碍特征"，AI识别的是"aₙ在三个Case中统一扮演跳过障碍角色，但机制不同（预防性放置 vs 修复性swap）"。

#### 遗漏2：s（总和）完全缺席

V10的key_entities.json列举了7个关键实体（x, aₙ, 强归纳, swap技巧, M'缩减, bad index, z），但**遗漏了s**。s在以下位置出现：

| 段 | s的角色 |
|-----|---------|
| 段6 | bad index定义：s-aᵢ∈M |
| 段7 | 注入论证：s-aᵢ>x映到M∩(x,∞) |
| 段8 | 鸽巢：好指标r满足s-aᵣ∉M |
| 段12 | Case 1验证：最终和s∉M |
| 段15 | Case 2构造：涉及s-aₙ=x |
| 段16 | Case 2验证：最终和s∉M |
| 段20 | Case 3验证：最终和s∉M |

且关键等式**s-aₙ=x**连接了s与aₙ和x——s是连接"论证→验证"的隐藏枢纽。

**修正建议**：在V10形式上下文中增加"实体:s"特征，标注在段6,7,8,12,15,16,20。这将产生新闭元素捕获s的跨段贯穿性。

**发现途径**：通过V8交叉验证发现——V8的ce_V8_36 {段7,8,9,段15} intent=[s的使用]已证明s的跨段模式在finer granularity下可被形式上下文捕获。

## 8. 元反思结果

### mrt_1: s作为隐藏的贯穿变量

- **模式类型**：闭环
- **描述**：s在bad index定义(s-aᵢ∈M)、注入论证(s-aᵢ>x)、鸽巢(s-aᵣ∉M)、三Case验证(s∉M)中均出现，且关键等式s-aₙ=x连接s与aₙ和x。s是连接"论证→验证"的隐藏枢纽。
- **为什么系统化步骤没覆盖到**：V10的形式上下文没有"实体:s"特征，导致s的跨段角色在V10的闭元素枚举中完全不可见。系统化步骤基于V10，自然遗漏了s。只有回到证明本身重新审视（或交叉参考V8）才能发现s的隐藏贯穿性——这证明了元反思和跨版本交叉验证的必要性。

### mrt_2: 三Case复杂度梯度

- **模式类型**：递进
- **描述**：Case 1最复杂（需要bad index定义+注入论证+鸽巢论证得好指标r，3步存在性论证链），Case 3中等（需要swap修复命中z的冲突，1步修复），Case 2最简单（直接缩减M'应用归纳，无需额外论证）。复杂度梯度：Case 1 > Case 3 > Case 2，反映了处理x∈M（需要避开x本身）比处理x∉M（x自然不在M'中）更难。
- **为什么系统化步骤没覆盖到**：系统化步骤分别分析了每个Case的内部结构和跨Case的统一模式，但没有识别"三Case的复杂度梯度"这个元模式。这需要AI比较三个Case的论证步骤数量和难度才能识别——程序看到的是段数和特征，看不到"论证复杂度"的语义层面差异。
