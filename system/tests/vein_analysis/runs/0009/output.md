## 1. 四版本格化对比

| 维度 | V5 | V7 | V8 | V10 |
|---|---|---|---|---|
| 段数 | 21 | 21 | 23 | 25 |
| 特征数 | ~2/段 | 15 | 41 | 37 |
| 形式上下文 | 无 | 有 | 有 | 有 |
| key_entities | 无 | 无 | 无 | 有 |
| 闭元素数 | — | 23 | 39 | 52 |
| 特征风格 | 朴素直觉 | 操作类型 | 角色分散 | 实体:角色统一 |

**看法差异分析**:

- **V5 (自由直觉)**: 段划分粗，Case 2的M'构造+归纳应用合在一个段中。特征命名朴素("鸽巢论证"/"验证")。作为基线有价值，但不足以做FCA。
- **V7 (结构化约束)**: 段划分与V5同粒度但特征标注规范化。15个操作类型特征(构造子问题/应用归纳假设/验证构造正确性等)。闭元素多为单段或2-3段，跨Case闭元素少(仅ce_V7_9{段10,段14,段18}=应用归纳假设等3个)。**缺少实体角色维度**——看不到"x贯穿三Case"或"aₙ跨Case复用"。
- **V8 (跨闭元素元模式引导)**: 段划分更细(23段)，引入角色维度(x有6种角色名:aₙ的位置角色等)。但角色命名分散导致闭元素碎片化(39个)，很多闭元素仅共享单一角色特征。**角色过细反而稀释了模式**。
- **V10 (实体角色统一)**: 段划分最细(25段)，用"实体X:角色"统一命名(实体x:分类标准/实体aₙ:跳过障碍/实体swap:跨Case复用/实体前缀和验证:跨Case验证)。这种命名使**跨Case闭元素自然涌现**——ce_V10_17{段13,段19,段23,段24}=前缀和验证跨Case、ce_V10_19{段12,段23}=swap跨Case、ce_V10_24{段11,段16,段22}=归纳应用跨Case、ce_V10_44{段3,段11,段16,段22}=强归纳框架。52个闭元素是4版本中信息最丰富的。

**选择V10为基础**: V10的实体角色特征将跨Case元模式烘焙进形式上下文，使FCA能自动发现跨Case模式。V10的key_entities.json提供交叉验证。V7过粗，V8角色碎片化。

## 5. AI优势元素

FCA(程序)能做的是段集合层面的完备枚举——给定形式上下文，Next Closure算法枚举所有满足A''=A的子集。但以下7个元素是FCA找不到但AI能识别的:

1. **bad index存在性论证链** (nonlocal): FCA的ce_V10_38只看到"三段共享bad-index概念"，看不到三步论证链的因果结构(定义→映射→计数)。
2. **预防性vs修复性避障对比** (nonlocal): FCA的ce_V10_19看到"两段共享swap+跳过障碍"，但看不到两种swap的语义对比(预防vs修复)。
3. **三Case统一M'缩减构造** (cross_case_merge): FCA的ce_V10_30看到"三段共享M'缩减构造"，但看不到三种构造策略的差异(截断至t/截断至x/剥离z)。
4. **x的多功能角色元模式** (cross_element_meta_pattern): x的4种角色分散在3个闭元素中，无单一闭元素能捕获x的统一枢纽角色。
5. **aₙ的多功能角色元模式** (cross_element_meta_pattern): aₙ的3种角色分散在2个闭元素中，无单一闭元素捕获aₙ的统一"最大元利用"角色。
6. **good index r的生命周期** (nonlocal): r在5段中扮演不同角色(获得/定义t/排除/放入/验证依据)，不共享单一特征故不构成闭元素。
7. **三Case统一前缀和验证模式** (cross_case_merge): FCA的ce_V10_17捕获到"四段共享前缀和验证"，但看不到验证模式在不同Case中的变体。

**AI优势的本质**: FCA是集合层面的运算(共享特征的段集合)，而AI做的是语义层面的判断(因果结构/策略对比/角色统一/生命周期)。这些语义关系不对应任何闭元素的内涵，但确实是数学思维上的有价值模式。
