## 2. 决定性证据

三份 stderr 均出现：

```text
Warning: --sandbox always uses the autonomous permission mode;
ignoring --permission-mode dangerous.
warning: rejected a tool call that requires confirmation.
Running in non-interactive mode. Use --permission-mode dangerous to auto-approve all tools.
```

这揭示当前 CLI 的一个真实组合语义：

1. 开启 `--sandbox` 后，显式 `--permission-mode dangerous` 被忽略；
2. sandbox 的自主模式仍会把某些 file-write 工具视为需确认；
3. `-p` 非交互模式无法回答确认；
4. 因而“要求模型自行写结果文件”不是一个可执行的无交互合同。

stderr 的最后一句建议 `dangerous`，但同一段又明确说它已被 sandbox 忽略。不能继续靠切换同一个 flag 猜测性重试。

## 5. 架构修正

不再让模型承担文件提交职责。下一版角色合同改成：

```text
模型只读最小视图
  → 在最终文本中返回带双标记的唯一 JSON payload
  → 机械 adapter 提取、JSON parse、canonicalize
  → adapter 写规定文件和 DONE/hash
  → evaluator 评分
```

这把两种职责分开：

- 认知角色负责语义判断；
- 可信机械 adapter 负责文件系统副作用、原子提交和格式封装。

同时给 Extractor 预先提供冻结的 source-span manifest，避免它为了算 hash 再创建脚本。新角色资产必须明确禁止 Write/Exec，只允许 Read 与最终 response。该修订形成新 asset set `0.2.0`，并由新 POC-VMS-34 验证。
