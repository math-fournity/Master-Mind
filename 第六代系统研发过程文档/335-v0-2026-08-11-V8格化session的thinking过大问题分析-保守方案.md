# 335号 · V8格化session的thinking过大问题分析——保守方案

**日期**：2026-08-11
**状态**：分析结论（已决策——不拆分，采保守方案）
**来源**：334号方案执行过程中V8反复超时（0005: 500秒, 0006: 1300秒+未完成）引发的拆分讨论

---

## 1. 问题现象

V8在多次运行中都是最慢的版本，且thinking内容大：

| 运行 | V5 | V7 | V8 | V10 |
|---|---|---|---|---|
| 0004 | 120秒 | 180秒 | 500秒 | 260秒 |
| 0005 | 80秒 | 320秒 | 500秒 | 240秒 |
| 0006 | 120秒 | 320秒 | **1300秒+未完成** | 420秒 |

V8的特征数（32个）不是最多的——V10的42个比V8多。但V8最慢。根因不只是特征数——是V8要求AI在thinking中做**"识别关键实体→分析每个关键实体在每个段中的角色→标注角色特征"**的语义分析，加上V8还会做矩阵验证+修正（0005的日志显示V8写完矩阵后发现错误，用Python脚本重新生成），进一步放大thinking量。

---

## 2. 拆分方案的讨论

### 2.1 拆分方案

把V8拆成两个子session：
- **V8a（段划分+常规特征标注）**：和V7一样，只做段划分+常规思维特征标注
- **V8b（关键实体角色特征补充）**：读V8a的segments.json，识别关键实体，对每个段分析关键实体的角色，补充角色特征到formal_context.json
- 程序合并V8a和V8b的形式上下文

### 2.2 拆分方案的风险

**风险1：认知过程断裂——和333号§2.4.1同类风险**

V8原版是一个session——AI在做段划分的同时，就在思考"这个段用了x的什么角色"、"这个段用了aₙ的什么角色"。**段划分和角色特征标注是同一个认知过程**——AI对每段的理解是整体的，常规思维特征和角色特征是同时考虑的。

拆分后，V8b读V8a的segments.json——V8b看到的是V8a已经划好的段。V8b的工作变成"在已有段划分上补充角色特征"，不是"在做段划分的同时识别角色特征"。**这个认知过程断裂了。**

具体后果：
- V8原版可能因为"aₙ在这个位置的角色变化"而把一个段分成两段——V8a不会这样做（V8a只考虑常规思维特征），V8b想分也来不及了（段划分已固定）
- V8a的段划分粒度可能不适合角色特征标注——某些段从常规特征看是一个段，但从角色特征看应该是两个段

**这就是333号§2.4.1的风险——(G,M,I)的不完美。** V8拆分后，(G,M,I)的构造分两步，V8a构造时不知道V8b需要什么段划分粒度，V8b补充时受限于V8a的段划分。合并后的(G,M,I)可能不如V8原版协调。

**风险2：角色特征标注不够深入——可能导致trace退化**

V8的独特价值是"跨闭元素元模式引导"——通过标注关键实体角色特征，让形式上下文能捕获跨闭元素元模式的段集合。这个价值依赖于AI对"关键实体在证明中的角色"的深入理解。

V8原版的认知路径：读解答→划段（同时考虑常规特征和角色特征）→构造矩阵
V8b的认知路径：读V8a的段划分→识别关键实体→对每个段标注角色特征→补充矩阵

V8b的认知路径是"在已有段划分上补充特征"——这是局部的、分析的，不是整体的、直觉的。**V8b可能只标注那些"明显"的角色特征，漏掉那些"需要在段划分时才能发现"的角色特征。**

如果V8b的角色特征标注不够准确，程序枚举的闭元素会不同，综合分析的输入不同，最终trace可能退化——**这和nonlocal trace退化是同类问题：认知路径的局限导致产出退化。**

**风险3：综合分析Agent的回溯检查可能发现不了V8b的问题**

333号方案的应对措施是综合分析Agent做"形式上下文回溯检查"。但回溯检查是检查"有没有遗漏的闭元素"——不是检查"角色特征标注是否准确"。

如果V8b漏标了某个角色特征（比如段15应该有"aₙ的最大性"但V8b没标），导致程序枚举少了几个闭元素，综合分析Agent的回溯检查可能发现不了——因为回溯检查是看"有没有在思维上属于同一层的段集合没被枚举到"，不是看"某个段的角色特征标注是否准确"。

**风险4：V8a和V8b对段的理解不一致**

V8a标了"鸽巢论证"，V8b标了"x的使用"——但V8b可能不知道V8a在标"鸽巢论证"时是基于什么理解。如果V8a和V8b对同一段的理解不一致，合并后的(G,M,I)可能不协调。

### 2.3 风险综合判断

**V8拆分确实有风险，主要风险是认知过程断裂——和333号§2.4.1记录的(G,M,I)不完美风险同类，但更严重。** 333号方案的风险是"AI做段划分时可能遗漏特征"，V8拆分的风险是"段划分和角色特征标注不在同一个认知过程中完成，可能导致段划分粒度不适合角色特征标注"。

**而且，这个风险恰恰可能引入nonlocal trace退化的同类问题**——V8b的认知路径是"从V8a的段划分出发补充角色特征"，不是"从解答内容出发整体理解段的角色"。这和综合分析Agent"从闭元素出发做语义解读"而不是"从段内容出发识别nonlocal trace"是同类问题——认知路径的局限导致产出退化。

---

## 3. 决策：不拆分，采保守方案

### 3.1 决策理由

V8拆分引入的风险（认知过程断裂→角色特征标注不够深入→闭元素不同→trace退化）大于它解决的问题（thinking太大→可能truncated）。

**核心原则：不因为工程问题（thinking太大）而牺牲认知质量（段划分和角色特征标注的统一认知过程）。** 333号方案的核心思想就是"程序做确定性运算，AI做语义判断"——V8的角色特征标注是语义判断，不应该因为thinking太大就拆成两步。

### 3.2 保守方案

V8的thinking太大问题，用以下方式解决：

**措施1：简化V8提示词——减少thinking中的验证工作**

V8在0005的日志显示它写完矩阵后还做了验证+用Python脚本重新生成。这些验证工作放大了thinking量。在V8提示词中明确：

```markdown
## 执行顺序——先写文件，不做验证

1. 读解答文本
2. 划段+标注特征（常规思维特征+关键实体角色特征）
3. 构造形式上下文矩阵
4. **立即写segments.json和formal_context.json**
5. 创建DONE.md

**不要在thinking中做矩阵验证**——矩阵验证是程序的工作，
verify_lattice_completeness.py会做。你只负责标注特征和构造矩阵。
```

**措施2：如果V8仍然超时——接受V8偶尔失败，用降级选项**

333号§6的待决策问题3已经提出了这个降级选项："如果某个版本的格化session失败了，是否可以用其他3个版本的格化结果继续？"

V8偶尔失败时，用V5/V7/V10三个版本的格化结果继续阶段1.5和阶段2。V8的独特价值（跨闭元素元模式引导）在阶段2的综合分析Agent中也会做（综合分析Agent的第五步"识别跨闭元素元模式"）——即使V8的格化结果缺失，综合分析Agent仍然能识别跨闭元素元模式，只是不是通过V8的角色特征引导程序枚举来捕获。

**措施3：设置V8超时阈值**

给V8设置一个超时阈值（如900秒/15分钟）。超过阈值后判定V8失败，用降级选项继续。避免V8无限等待阻塞整个管线。

### 3.3 降级选项的实现

在`_phase1_grading`中，等待4个格化session完成时，对V8设置超时：

```python
# V8超时阈值（秒）——V8的thinking通常比其他版本大
V8_TIMEOUT = 900

# 轮询时检查V8是否超时
if version == "V8" and elapsed > V8_TIMEOUT:
    print(f"  ⚠️ V8超时({elapsed}秒)，使用降级选项——用V5/V7/V10继续")
    # V8标记为失败，不等待V8的DONE.md
    # 阶段1.5和阶段2用V5/V7/V10的格化结果继续
```

334号方案解决的是"nonlocal trace退化"——综合分析Agent的工作流程改进。

335号方案解决的是"V8格化session的thinking过大"——格化阶段的工程问题。
