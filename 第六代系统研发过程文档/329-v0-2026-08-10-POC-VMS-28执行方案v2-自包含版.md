## 2. 概念定义（自包含）

| 概念 | 定义 | 来源文档 |

| **脉络（Vein）** | 一道数学题的解答从题目到答案的思维过程。过程A中是树状的（推理AI探索后折返），过程B中是线性的（已完成解答）。 | 319号§Vein dataclass |
| **段（VeinSegment）** | 脉络中的一个推理步骤或一段推理。最细的段划分是把脉络分成最小的推理步骤。 | 319号§VeinSegment dataclass |

| **Level视图（LevelView）** | 段的一种合并方式形成的"看法"。最细Level（Level 0）=每个段独立；最粗Level（Level N）=所有段合并；中间Level=几个段合并。 | 322号§1第一部分 |

## 3. 背景认知（为什么做这个POC）

### 3.1 这个POC验证的想法来自哪里

**来源**：314号问题2——"格化"是第六代系统的三个核心问题之一。

314号提出：脉络分成段后，段的不同合并方式形成不同Level视图，在每个Level上识别trace。但"哪些段可以合并"这个问题怎么解决？

**三种可能方式**（317号定义）：
- 方式A：AI用直觉判断哪些段可以合并（不运行FCA算法）
- 方式B：脚本运行FCA格遍历算法系统化枚举所有闭元素
- 方式C：AI做+FCA验证补漏

**用户的直觉**（320号触发）：用户认为"AI本身能力其实很强，就是一眼看过去，它能够实现、拿到合理的格后的我们想要的那些trace"。所以先验证方式A——如果AI能直接做，就不需要实现FCA算法。

### 3.2 为什么这个想法需要验证

- **不确定性1**：AI的直觉是否足够准确？AI能否判断"哪些段在思维上属于同一层"？
- **不确定性2**：AI是否会只产出最粗和最细两个Level，跳过中间Level？如果跳过中间Level，非局部trace就全漏了。
- **不确定性3**：AI产出的trace和我们已经积累的tell是否一致？如果不一致，可能是AI的直觉和我们的tell定义有偏差。

### 3.3 验证结果对系统实现的影响

- **成功**→`step_2_grid_vein()`的实现选方式A——用提示词驱动AI做格化，不用FCA算法。工程实现最简单。
- **部分成功**→分析哪些部分有效、哪些需要加强。可能需要V5提示词，或方式C（AI做+FCA验证补漏）。
- **失败**→方式A不可行，需要VMS-29（方式B，FCA算法）或VMS-30（方式C，AI+FCA验证）。

### 3.4 第一次POC的策略

用户决定（327号触发）："一次一套"——第一次POC只验证set_A V4提示词，不验证多套并发。多套并发（325号）留给后续POC。

## 4. 选题和理由

### 4.1 题目

**IMO 2009 Problem 6（蚱蜢问题）**
- **problem_id**：`compfiles_imo2009p6`
- **来源**：ArangoDB `problem_profiles`集合（数据库`xishujuzhen_math_glm52`，localhost:8529）
- **domain**：combinatorics
- **解答长度**：1905字符

### 4.2 题目内容

Let a₁, a₂, ..., aₙ be distinct positive integers and let M be a set of n-1 positive integers not containing s = a₁ + a₂ + ... + aₙ. A grasshopper is to jump along the real axis, starting at the point 0 and making n jumps to the right with lengths a₁, a₂, ..., aₙ in some order. Prove that the order can be chosen in such a way that the grasshopper never lands on any point in M.

### 4.3 为什么选这道题

| 理由 | 来源 |
|---|---|
| 解答有明确的结构——三种情况分类（Case 1/2/3），适合格化——可以合并成不同的Level视图 | 320号§1.3 |
| 有非局部trace——"强归纳+情况分析+鸽巢计数的组合策略"是跨整个证明的全局策略，不是单步的局部trace | 320号§1.3 / profile中的全局tell |
| 已有profile可以对比——profile中有8个局部tell+2个全局tell，AI产出的trace可以和这些tell对比 | 320号§1.3 / AGENTS.md§题目侧写Profile提取工作 |
| 解答长度适中——1905字符，不会太长导致AI处理困难，也不会太短导致没有格化空间 | 320号§1.3 |
| key_insight清晰——"定义关键变量x=去掉最大元素后的和，按M中元素相对于x的位置分三种情况"——这个insight本身就是非局部trace | 320号§1.3 / profile的key_insight字段 |

### 4.4 已有的trace（来自profile，用于对比，不给subagent看）

**局部tell（8个）**——来自profile的`tell_hint_pairs`：
1. AI面对排列存在性问题，尚未识别归纳结构和关键变量
2. AI列出多个方向但未识别强归纳是正确路径
3. AI尝试贪心排序但失败，未转向归纳
4. AI开始考虑归纳但未识别关键变量x=去掉最大元素后的和作为分类依据
5. AI在情况2中需要利用M'的基数约束来应用归纳假设
6. AI在情况1中需要鸽巢论证找安全元素，这是纯知识瓶颈——需要构造注入映射并计数
7. AI需要处理情况3并整合所有情况完成归纳证明

**全局tell（2个）**——来自profile的`global_tell_hint_pairs`：
1. AI在排列存在性问题中倾向于贪心/枚举，未识别强归纳+情况分析+鸽巢计数的组合策略
2. 鸽巢论证中'坏元素≤n-2而共有n-1个元素'这一计数，隐含了去掉安全元素后M的过滤子集M'满足归纳假设的基数约束

## 5. 执行方式

### 5.1 提示词

**set_A V4**（`第六代系统提示词积累目录/pipe_1_parser/step_2_grid_vein/set_A_fca_hassee/v4.md`）

V4包含（324号§1）：
- 第零部分：为什么我们要拿trace
- 第零点五部分：影响例子
- 第一部分：核心概念（FCA/Hasse图）
- 第二部分：Trace三种类型
- 第三部分：8种复杂情况
- 第三点五部分：7种反模式
- 第四点五部分：树状vs线性输入
- 第四部分：具体任务

**用附加章节B（线性输入）**——因为IMO 2009 P6的解答是已有题目和解答记录，是过程B（线性输入）。subagent不需要读附加章节A（树状输入处理）。

### 5.2 用subagent执行

用`run_subagent`启动一个`subagent_general`类型的subagent，给它：
1. V4提示词（set_A的v4.md内容，只包含附加章节B，不包含附加章节A）
2. IMO 2009 P6的解答文本（solution_text）
3. **不给subagent看profile中的tell_hint_pairs**——避免污染subagent的判断

### 5.3 subagent的产出

subagent按V4提示词第四部分产出：
1. **段划分**（Level 0）——把解答分成最细的段，每段给出段编号/内容/特征
2. **所有有意义的Level视图**——段的不同合并方式，每个Level给出合并方式+为什么有意义
3. **每个Level视图上的trace**——局部/非局部/全局trace，每个trace给出类型+模式描述+涉及哪些段
4. **反思**——自己可能漏掉了哪些Level视图和trace，最有价值的trace是哪个

## 6. 对比方法和判定标准

### 6.1 对比方法

把subagent产出的trace和profile中的tell_hint_pairs对比：

| 对比维度 | subagent产出 | profile已有 | 对比方法 |
|---|---|---|---|
| 段划分数量 | ? | 无（profile没有段划分） | 无对比基准，只看合理性 |
| Level视图数量 | ? | 2个（最细=局部tell，最粗=全局tell） | subagent是否产出中间Level |
| 局部trace数量 | ? | 8个 | 重合度/新增/漏检 |
| 全局trace数量 | ? | 2个 | 重合度/新增/漏检 |
| 非局部trace（中间Level） | ? | 0个（profile没有中间Level的trace） | subagent是否识别出profile没有的非局部trace |
| 是否识别出"强归纳+情况分析+鸽巢计数"组合策略 | ? | 是（全局tell 1） | 关键判定 |
| 是否识别出"鸽巢论证隐含基数约束" | ? | 是（全局tell 2） | 关键判定 |
| 反思质量 | ? | 无 | subagent是否识别出自己可能漏掉的东西 |

### 6.2 判定标准

**成功条件**（全部满足）：
1. subagent产出了多个有意义的Level视图（不只最粗和最细）
2. subagent产出的trace和profile中的tell有重合
3. subagent识别出了非局部trace（对应profile中的全局tell或新增的非局部trace）
4. subagent识别出了"强归纳+情况分析+鸽巢计数"组合策略

**失败条件**（任一满足）：
1. subagent只产出最粗和最细两个Level（没有中间Level）→ V4提示词的中间Level引导不够
2. subagent产出的trace和profile中的tell完全不重合 → V4提示词的trace定义和我们的tell定义不一致
3. subagent没有识别出非局部trace → V4提示词的非局部trace引导不够

**部分成功**（成功和失败条件都不满足时）：
1. subagent产出了多个Level视图但有些明显不合理 → V4提示词部分有效
2. subagent识别出了局部trace但漏了非局部trace → V4提示词在局部有效但非局部需要加强

### 6.3 验证结果对系统实现的影响

- **成功**→`step_2_grid_vein()`选方式A，可以考虑后续POC验证多套并发
- **部分成功**→分析哪些部分有效，考虑V5提示词或方式C
- **失败**→方式A不可行，需要VMS-29（方式B）或VMS-30（方式C）
