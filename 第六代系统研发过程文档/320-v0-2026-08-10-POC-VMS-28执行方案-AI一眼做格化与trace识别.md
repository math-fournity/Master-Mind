## 1. 选题

### 1.1 题目

**IMO 2009 Problem 6（蚱蜢问题）**
- **problem_id**：`compfiles_imo2009p6`
- **来源**：ArangoDB `problem_profiles`集合
- **domain**：combinatorics

### 1.2 题目内容

Let a₁, a₂, ..., aₙ be distinct positive integers and let M be a set of n-1 positive integers not containing s = a₁ + a₂ + ... + aₙ. A grasshopper is to jump along the real axis, starting at the point 0 and making n jumps to the right with lengths a₁, a₂, ..., aₙ in some order. Prove that the order can be chosen in such a way that the grasshopper never lands on any point in M.

### 1.3 为什么选这道题

1. **解答有明确的结构**——三种情况分类（Case 1/2/3），适合格化——可以合并成不同的Level视图
2. **有非局部trace**——"强归纳+情况分析+鸽巢计数的组合策略"是跨整个证明的全局策略，不是单步的局部trace
3. **已有profile可以对比**——profile中有8个局部tell+2个全局tell，AI产出的trace可以和这些tell对比
4. **解答长度适中**——1905字符，不会太长导致AI处理困难，也不会太短导致没有格化空间
5. **key_insight清晰**——"定义关键变量x=去掉最大元素后的和，按M中元素相对于x的位置分三种情况，在最难的情况中用鸽巢论证找到一个'安全'元素"——这个insight本身就是非局部trace

### 1.4 已有的trace（来自profile，用于对比）

**局部tell（8个）**：
1. AI面对排列存在性问题，尚未识别归纳结构和关键变量
2. AI列出多个方向但未识别强归纳是正确路径
3. AI尝试贪心排序但失败，未转向归纳
4. AI开始考虑归纳但未识别关键变量x=去掉最大元素后的和作为分类依据
5. AI在情况2中需要利用M'的基数约束来应用归纳假设
6. AI在情况1中需要鸽巢论证找安全元素，这是纯知识瓶颈
7. AI需要处理情况3并整合所有情况完成归纳证明

**全局tell（2个）**：
1. AI在排列存在性问题中倾向于贪心/枚举，未识别强归纳+情况分析+鸽巢计数的组合策略
2. 鸽巢论证中'坏元素≤n-2而共有n-1个元素'这一计数，隐含了去掉安全元素后M的过滤子集M'满足归纳假设的基数约束

## 2. POC方案

### 2.1 验证什么

AI能否用直觉判断做格化（不运行FCA算法，只给FCA闭包算子的概念），产出合理的Level视图，并在每个Level上识别trace。

### 2.2 怎么验证

**步骤1：准备输入**
- 从ArangoDB取出`compfiles_imo2009p6`的solution_text
- 不给AI看profile中的tell_hint_pairs（避免污染AI的判断）

**步骤2：给AI一个提示词**

提示词中包含：
- FCA闭包算子的概念（"有意义的合并"="闭元素"="属性闭包等于自身的段集合"），但不实际运行FCA算法
- 格化的定义——把脉络分成段，段可以合并成更大的段，合并后形成不同Level的视图
- trace的定义——在某个Level视图上识别出的思维模式
- 要求AI产出所有有意义的Level视图，并在每个Level上识别trace

**步骤3：AI产出**

AI产出：
- 脉络的段划分（最细Level）
- 所有有意义的Level视图（段合并的不同方式）
- 每个Level视图上的trace

**步骤4：对比**

把AI产出的trace和profile中已有的tell_hint_pairs对比：
- 重合度——AI产出的trace和profile中的tell有多少重合
- 新增——AI产出了profile中没有的trace
- 漏检——profile中有但AI没产出的trace
- 非局部trace——AI是否识别出了全局tell对应的非局部trace

**步骤5：FCA验证（可选）**

如果AI产出了多个有意义的Level视图，可以用FCA格遍历算法验证AI是否漏掉了有意义的Level视图——这其实是VMS-30（方式C）的验证内容，但可以在VMS-28中顺便做。

### 2.3 提示词设计

```
你是一个数学解题思维分析专家。你的任务是分析一道数学题的解答，做"格化"和"trace识别"。

## 概念说明

### 脉络
脉络是解答的思维过程——从题目到答案的推理路径。

### 段
段是脉络中的一个推理步骤或一段推理。最细的段划分是把解答分成最小的推理步骤。

### 格化（Level视图）
格化是把脉络分成段后，考虑段的不同合并方式。每种合并方式形成一个"Level视图"：
- 最细Level：每个段是一个节点
- 最粗Level：整个脉络是一个节点
- 中间Level：几个段合并成一段

"有意义的合并"是指合并后的段集合满足"闭元素"性质——即这些段的属性闭包等于自身。直觉上说，有意义的合并是把"在思维上属于同一层"的段合在一起。

不是所有合并都有意义——只有"在思维上属于同一层"的段合并才有意义。

### trace
trace是在某个Level视图上识别出的思维模式——"解题者在这里做了某个操作"或"解题者在这里用了某个策略"。

trace有三种类型：
- 局部trace：在单个段上识别出的思维模式
- 非局部trace：跨多个段的思维模式（如"反证法"跨整个证明，"构造-分析-排除"跨多个段）
- 全局trace：整个脉络层面的策略模式

## 你的任务

分析以下解答：

[解答文本]

请产出：

1. **段划分**：把解答分成最细的段，每段是一个推理步骤
2. **所有有意义的Level视图**：考虑段的不同合并方式，列出所有"在思维上属于同一层"的合并方式。对每个Level视图说明为什么这个合并是有意义的
3. **每个Level视图上的trace**：在每个Level视图上识别trace，说明trace的类型（局部/非局部/全局）和模式描述
```

### 2.4 关键判定

**成功条件**：
- AI产出了多个有意义的Level视图（不只最粗和最细）
- AI产出的trace和profile中的tell有重合
- AI识别出了非局部trace（对应profile中的全局tell）

**失败条件**：
- AI只产出最粗和最细两个Level（没有中间Level）→ AI的直觉判断不够
- AI产出的trace和profile中的tell完全不重合 → AI的直觉和我们的tell定义不一致
- AI没有识别出非局部trace → AI只看到了局部模式，没有看到全局策略

**部分成功**：
- AI产出了多个Level视图但有些明显不合理 → AI的直觉部分有效
- AI识别出了局部trace但漏了非局部trace → AI在局部有效但非局部需要FCA辅助

## 3. 执行计划

### 3.1 准备阶段

1. 从ArangoDB取出`compfiles_imo2009p6`的solution_text
2. 准备提示词（§2.3）
3. 不给AI看profile中的tell_hint_pairs

### 3.2 执行阶段

4. 用准备好的提示词让AI分析解答
5. 记录AI的产出（段划分、Level视图、trace）

### 3.3 对比阶段

6. 把AI产出的trace和profile中的tell_hint_pairs对比
7. 记录重合度、新增、漏检、非局部trace识别情况

### 3.4 结论阶段

8. 根据§2.4的关键判定，判断VMS-28是否成功
9. 如果成功→系统实现选方式A
10. 如果部分成功→分析哪些部分有效、哪些需要FCA辅助
11. 如果失败→需要VMS-29（方式B）或VMS-30（方式C）
