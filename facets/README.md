# 面相目录

> 看系统和看设计过程的切分维度。不是原语（不能执行/放置），不是概念框架（不是观察视角），不是性质标准（不检查任何东西）——是**元分类**，决定我们用什么角度来切分系统理解和设计过程。

## 为什么有这个目录

241号方案在建立原语目录时提出了"面相"概念，用来标记每个原语从哪个维度来。244号重构把面相从原语文件中删掉了，因为面相不是原语的属性，是**原语之上的分类维度**。245号方案把面相独立为第四层目录。

面相的价值：
1. 面相本身会演化——面相3是241号新增的，修正了面相1和2
2. 面相之间的关系是理念层的——面相3修正面相1的"AI计算黑箱"问题
3. 面相指导分类——新设计想法出现时，先问"它属于哪个面相？"
4. 面相覆盖度是健康指标——面相A和B的平衡反映实验与理论的平衡

## 面相与设计元素的关系

面相横切 primitives/concepts/criteria 三层——每个设计元素可以属于一个或多个面相。关系通过**正向引用**记录：元素文件的"来源"字段中有一行"面相归属"，面相文件不列元素清单。

面相覆盖度统计通过扫描元素文件的面相归属字段完成（低频操作，审查时做）。

## 面相文件格式

每个面相文件：定义 / 核心判断 / 来源 / 贡献 / 局限 / 开放问题 / 被修正by（如有）
