# 面相C：设计过程自举（Design Process Bootstrapping）

## 定义

这个面相从"设计过程怎么运行"这个维度来切分设计过程——设计过程是自举的：用原语设计系统→发现差距→用系统求解下一代设计→发现新原语→循环。

## 核心判断

```
我们让AI用原语设计了一代系统，
我们发现了系统和我们预期中的未来系统各个面向之间的差距，
我们用系统去求解如何在原语的集合上设计新的下一代系统。
在这个过程中，我们不断发现新的原语。

作为AI数学工程系统，它的设计过程是自举的。
```

自举（bootstrapping）：系统用自己来设计自己的下一代。这和编译器自举（用C编译器编译出更好的C编译器）是同构的。

与面相A/B的关系：
- A：原语从实践中涌现——回答"新原语的来源是什么"
- B：原语从知识中选取——回答"新原语的来源是什么"
- C：设计过程是自举的——回答"设计过程的动力学结构是什么"

C不替代A和B。新原语在C的循环中被发现，但它们的来源是A（实践涌现）或B（知识选取）。C说的是发现发生的**过程结构**，A/B说的是发现产生的**来源机制**。

## 来源

246号对话中由用户提出。用户观察到：原语集合形成了一个空间，系统设计是在这个空间上的多约束求解，而求解过程是自举的。

## 贡献

1. **识别了设计过程的循环结构**——设计不是一次性的"从需求到系统"，而是"设计→运行→发现差距→再设计"的循环。每一代系统是上一代的解，也是下一代的约束。

2. **把系统设计和AI的核心能力对齐**——多约束求解是AI特别擅长的。如果系统设计是CSP，那么AI不只是系统的组件（数学推理引擎），还可以是系统的**设计者**。

3. **解释了原语为什么不断涌现**——不是因为我们"想"出新的，而是因为自举循环的每一轮都会暴露当前原语集合的不足，不足之处就是新原语的涌现点。

## 局限

1. **自举还没有实际发生**——目前的设计过程是人在主导（人发现差距、人提出新原语、人决定下一代设计）。AI作为设计者的角色是预期，不是现实。
2. **自举的收敛性未知**——编译器自举是收敛的（每代编译器比上代更好）。系统设计自举收敛吗？还是可能振荡或发散？这取决于"更好"怎么定义。
3. **"差距"的识别机制不清楚**——自举循环中"发现系统和预期之间的差距"这一步，是靠人还是靠AI？如果是AI，AI怎么感知"预期"？

## 开放问题

1. **AI作为设计者的边界**——AI能做哪些设计决策？哪些必须人来判断？这关系到自举的自动化程度。
2. **自举的停止条件**——自举会一直循环下去，还是有一个"足够好"的终点？数学工程系统有没有"完成"的时候？
3. **自举和面相演化的关系**——每一轮自举会不会产生新面相？还是面相在某个点稳定下来，之后的自举只在现有面相内深化？
4. **自举和实验的关系**——自举循环中的"运行"就是跑实验吗？还是"运行"有更广的含义（如实际部署解决数学问题）？
