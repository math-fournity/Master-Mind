# 面相4：树的生长（Tree Growth）

## 定义

这个面相从"系统在做什么——系统通过什么机制让AI解题"这个维度来切分系统。系统的本质是生长一棵尽可能完整的解题记录树。

## 核心判断

```
数学大师系统的本质是：
在不知道答案的情况下，通过引导展开机制，
让AI生长出一棵尽可能完整的解题记录树。

有两棵树，是同一棵树的不同阶段：
- 引导展开树 = 过程中正在生长的树（活的）
- 解题记录树 = 展开完成后凝固的树（产物）

树的节点 = 数学处境
树的边 = 提示Q（引导从一个处境移动到下一个处境的语义移动）
树的分叉 = 在某个处境岔口，模式识别找到多个应考虑的方向
树的叶 = 成功叶（证毕）/ 死路叶（走不通）/ 截断叶（超限停止）

遍历策略独立于树的结构：
- 串行展开（原DFS）= 一次一个方向，走不通回溯
- 并发展开（并发DFS）= 多个方向同时展开，每个分支独立Session
- 未来可能还有其他策略

数据基座是过去解题记录树的沉淀：
- 过去的解题记录树 → 提炼 → 数据基座中的Pattern
- 未来的引导展开树 ← 模式识别 ← 数据基座中的Pattern
- 这是一个自我增殖的循环
```

## 两棵树

### 引导展开树（Guided Expansion Tree）——过程

**本质：从题目出发，在提示驱动下展开的所有可能解题路径构成的空间。**

- 每个节点 = 一个数学处境（当前已知什么、当前表示是什么、当前猜想是什么、卡在哪里）
- 每条边 = 一个提示Q（引导从一个处境移动到另一个处境的语义移动）
- 每条从根到叶的路径 = 一次完整的解题尝试
- 树的分支 = 在某个处境岔口，有不同的提示方向，每个方向展开出一条不同的路径

不是搜索树——路径不是预先存在于已知空间中等待被搜索，而是通过提示逐步展开/生长出来的。

不是决策树——决策树是分类/回归模型，这里是解题过程的记录。

不是依赖图——依赖图是数学知识之间的依赖关系，这里是解题的尝试路径。

### 解题记录树（Solution Record Tree）——产物

**本质：一道题在引导下被探索过的所有路径的完整记录——包括成功路径和失败路径。**

- 根 = 题目
- 内部节点 = 解题过程中经过的各个处境
- 边 = 提示Q
- 叶节点 = 成功叶（证毕）/ 死路叶（走不通）/ 截断叶（超限停止）
- 多条成功路径可能并存

一棵完整的解题记录树包含：

| 组成 | 价值 |
|---|---|
| 成功路径 | 这道题的解答 |
| 失败路径 | 什么方向走不通、为什么 |
| 分叉点 | 在什么处境下有哪些方向 |
| 中间处境 | 解题经过的各个状态 |

### 两棵树的关系

同一棵树的不同阶段：
- 引导展开树 = 过程中正在生长的树，活的，还在展开
- 解题记录树 = 展开完成后凝固的树，是引导展开树的完成态

如果不做后处理（剪枝、提炼），它就是引导展开树的完成态。
如果做后处理（剪掉死路、只保留成功路径、提炼成Pattern），后处理后的产物是从这棵树中提取出来的，不是这棵树本身。

### 为什么"DFS"不应在树的名字中

遍历策略和树的结构应分离：

| 概念 | 性质 | 独立于遍历策略吗 |
|---|---|---|
| 树的结构（节点+边+路径） | 空间结构 | 是——树是什么样子不取决于你怎么遍历它 |
| 遍历策略（DFS/BFS/并发） | 算法 | 否——遍历策略决定了你按什么顺序探索树 |

"DFS"只是遍历策略之一。串行DFS是一种策略，并发DFS是另一种策略，未来可能还有其他策略。树有树的名字，遍历策略有遍历策略的名字，两者分离。

## 各组件在"生长树"中的角色

| 组件 | 在"生长树"中的角色 |
|---|---|
| 引导展开树 | 正在生长的树（过程） |
| 解题记录树 | 展开完成的树（产物） |
| 模式识别/检索 | 在每个节点决定"该往哪些方向展开"——树的分叉来源 |
| 辅助智能体 | 树的园丁——识别方向、注入提示、驱动展开 |
| 推理智能体 | 树的生长点——在每个节点做数学、产出下一个处境 |
| 稀疏矩阵/数据基座 | 模式识别的知识来源——决定分叉方向的依据 |
| 并发展开 | 同时展开多个分支——让树长得更快更全 |
| Level排序 | 决定展开顺序——优先展开高Level方向 |
| Hint梯度 | 控制每条边的"知识泄漏量" |
| 回溯铁律 | 不在同一Session回溯——保证树的每个分支context干净 |
| 四门审计 | 审计每条边是否泄漏答案——保证树的"诚实性" |
| 单任务双产出（伏羲） | 跑一次树的生长，同时产出树的解和数据基座条目 |

## 来源

256号文档§6.7-6.8中由用户与AI的对话产生。用户提出两棵树需要独立于DFS的名字，AI分析出引导展开树（过程）和解题记录树（产物），用户进一步指出系统的本质就是生长完整的解题记录树。

## 贡献

1. **统一了系统所有组件的角色**——之前12个组件看起来是分散的设计点（模式识别、Level排序、Hint梯度、回溯铁律、四门审计等），现在统一了——都是为了让树长得更全、更诚实、更可复用。

2. **把遍历策略和树的结构分离**——之前"DFS引导架构"把遍历策略和树混为一谈。面相4说：树有树的名字，遍历策略有遍历策略的名字。这打开了遍历策略的设计空间——串行展开、并发展开、未来其他策略都可以作用于同一棵树。

3. **重新定义了评测标准**——不是"做没做出来"，而是"树长得多完整"。一道题做出来了但只探索了一条路径，不如做出来了同时记录了5条失败路径和3个分叉点——后者才是更完整的解题记录树，才是更有价值的资产。

4. **解释了数据基座的自我增殖循环**——树越长越全 → Pattern越积越多 → 模式识别越准 → 未来的树长得越全。数据基座不是外部注入的知识库，是过去解题记录树的沉淀。

5. **和面相3互补**——面相3从"Pipeline网络"看系统（AI是Pipe，Pipe之间有认知激活），面相4从"树的生长"看系统（AI在生长树，树记录了所有尝试）。面相3看的是静态结构（Pipe网络），面相4看的是动态过程（树在生长）。两者不矛盾——Pipe网络是树生长的执行基础设施。

## 局限

1. **"完整"的边界未定**——"尽可能完整"是目标，但什么时候树算"足够完整"？不可能无限展开所有方向。需要定义"值得探索的方向"的判据——这又回到模式识别的recall问题。

2. **树的规模可控性未知**——并发展开会让树快速变大。一棵有100个节点的树和一棵有10000个节点的树，后者的Pattern提炼价值更高，但存储、检索、管理的复杂度也更高。

3. **失败路径的价值待验证**——理论上失败路径有价值（"什么方向走不通"），但实际中失败路径的Pattern能否被未来模式识别利用，还没有实验验证。

4. **树的生长和压缩边界的关系未定**——引导展开树在生长过程中可能跨越Session压缩边界。压缩后，树的中间节点信息可能丢失。如何在压缩边界上保持树的完整性？

## 开放问题

1. **"值得探索的方向"的判据**——模式识别找到N个方向，哪些值得展开，哪些不值得？这关系到树的"完整性"和"可控性"的平衡。

2. **树的生长停止条件**——什么时候树算"长完了"？所有方向都探索到了？找到一条成功路径就够了？还是必须找到所有成功路径？

3. **多棵树之间的关系**——不同题目的解题记录树之间有什么关系？能否合并成一棵更大的"数学知识树"？还是每道题的树独立存在，通过数据基座的Pattern间接连接？

4. **树的生长和四代系统的关系**——四代系统分别对应树生长的什么角色？盘古的静态图是预先画好的树？女娲的动态工作区是树的当前节点状态？燧人的DFS是树的遍历策略？伏羲的边界推进是树生长的认知机制？

5. **面相4和面相1的关系**——面相1说"两种计算"（经典+AI），面相4说"树的生长"。两种计算在树生长中各扮演什么角色？经典计算是否负责树的确定性部分（节点状态提取、拓扑验证），AI计算是否负责树的非确定性部分（模式识别、方向选择）？
