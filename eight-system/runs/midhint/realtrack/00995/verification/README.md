# 00995 标准分类的程序验证

## 原始验证（2026-08-16，有bug）

- 脚本：`mean_int_search.py`（残差放置穷举：n×n格、Z_n每元素n次、行列和≡0）
- 原始结果：
  - n=2: IMPOSSIBLE（5节点）
  - n=3: POSSIBLE
  - n=4: POSSIBLE
  - n=5: POSSIBLE
  - n=6: **IMPOSSIBLE（171,041,709节点穷举）**
- 原始结论：分类"n可行⟺n奇数或4|n"，答案3800

## Bug发现（2026-08-17）

**MH实验中AI给出了n=6的可构造解，程序验证正确（1-36每个出现一次，所有行/列均值都是整数）。原始穷举代码有bug。**

### Bug根因

`mean_int_search.py`的`row_options`函数只生成**按residue排序的行**（如`(0,1,2,2,3,4)`），不生成非排序行（如`(0,3,4,1,2,2)`）。

```python
# row_options中的rec函数按residue 0,1,2,...,n-1的顺序填充
# 生成的行都是排序的：先所有0，再所有1，...
# 但实际解需要residue在行中交错排列
```

### 验证

AI给出的n=6解的每一行排序后，虽然每行sum仍≡0 mod 6，但列和变成`[0,0,3,0,0,3]`，不满足列约束。**n=6的解必须用非排序行才能同时满足行和与列和约束。**

n=2,3,4,5恰好存在排序行的解，所以搜索正确。但n=6不存在排序行的解，搜索错误地判定IMPOSSIBLE。

### 影响范围

- n=6: 原始判定IMPOSSIBLE **错误**，实际POSSIBLE（已构造验证）
- n=10,14,...,98: 原始信任"n≡2(mod 4)不可行"的分类，**这个分类本身可能错误**
- n=2: 原始判定IMPOSSIBLE **正确**（已独立验证）

## 修正后的结论

**n=6是mean-integer。** AI用doubling construction证明了所有n≡2(mod 4)且n≥6都是mean-integer。

- n=6的6×6 residue grid已程序验证：每个residue出现6次，所有row/col sum ≡ 0 mod 6
- 从residue grid lifting到1-36的完整grid已验证：1-36每个出现一次，所有行/列均值都是整数

**正确答案：5048**（S={1,3,4,5,6,...,100}={1,...,100}\{2}，sum=5050-2=5048）

**原始标准答案3800是错误的**——基于有bug的穷举代码得出的分类"n可行⟺n奇数或4|n"不正确。
