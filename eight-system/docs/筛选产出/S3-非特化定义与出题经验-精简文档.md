## 1. 非特化的成熟定义：因果充分的取商

> **来源**：372号 §2（L141-258），R1认知推进
> **预期用途**：eight-system非特化方案的核心定义

### 1.1 一句话定义

> **非特化不是把一段trace"总结得更抽象"，而是对解题处境做一次"因果充分的取商"，再把所得等价类编译成可识别、可选择、可实例化、可执行、可终止、可组合、可归责、可验证、可持续学习的认知技能。**

（372号 L13）

### 1.2 trace不是可直接泛化的最小单位

一条完整trace同时含有：

- 当前数学处境；
- AI已经尝试过的路线；
- 某个可分叉但未分叉的位置；
- 后来采用的转向；
- 转向之后出现的中间结果；
- 最终成功或失败；
- 大量对成功没有因果作用的叙述噪声。

如果直接对整条trace做摘要，最容易学到的是"这份解答讲了什么"，而不是"哪一个认知动作在什么处境下改变了搜索状态"。

因此，非特化的输入不应只是整条trace，而应先切成一个个**分支事件**：

```text
分支事件 e = (
  转向前处境 s,
  已走路线 h,
  未探索分叉 b,
  采取的认知动作 a,
  转向后处境 s',
  可观察进展 delta,
  后续结果 y
)
```

这里最重要的不是最终答案，而是`a`是否造成了`delta`。

（372号 L143-171）

### 1.3 什么叫"取商"

数学中的取商，是把若干表面不同但在目标关系下等价的对象视为同一个对象。

对应到非特化：

- 变量重命名不应产生新Tell；
- 数字替换不应产生新Tell；
- 对象从集合换成图，如果角色关系和认知动作没有改变，可能仍属于同一Tell；
- 题面很像但关键失败机制不同，则不能被合并。

因此我们需要先声明一组"允许忽略的变换"：

```text
G_nuisance = {
  符号重命名,
  数值缩放,
  对象换壳,
  表示改写,
  领域迁移,
  次序重排,
  对偶化,
  ...
}
```

不同Tell允许忽略的变换不同。比如：

- 一个具体数论Tell只允许变量和数字变化；
- 一个中Level结构Tell允许对象系统变化，但保留操作角色；
- 一个高Level同构之桥Tell允许领域变化，但必须保留源对象、目标对象、翻译、可逆性和收益证书之间的关系。

**Level由允许忽略哪些变换共同决定。**这比"抽象感更高"更可操作。

（372号 L173-205）

### 1.4 什么叫"因果充分"

只在成功trace中反复出现的结构，不一定导致成功。它可能只是：

- 解答者的写作习惯；
- 某个领域常见符号；
- 成功后才补写的解释；
- 与真正关键动作高度相关但没有推动作用的伴随步骤。

所以一个候选Tell必须同时满足两种要求：

1. **充分性**：保留下来的信息足以让未来系统判断"此时采用哪类认知动作可能有用"。
2. **因果性**：该认知动作确实提高了产生预期中间进展的概率，而不只是和最终成功相关。

概念性地说，我们想找一个表示`z = phi(e)`，使它满足：

```text
不变性：对允许忽略的变换 g，phi(g·e) ≈ phi(e)
充分性：知道z后，仍能预测哪种认知动作会产生进展
选择性：负例和边界例不会被错误合并
压缩性：z不保留对决策无用的源题细节
可执行性：z能够实例化为未来AI的具体动作
```

这不是现成定理，而是本项目的目标定义。

（372号 L207-231）

### 1.5 非特化真正生成的是等价类，不是一句话

一个合格Tell代表的不是一条文本，而是一类分支事件：

```text
[e]_Tell = 所有满足同一适用边界、
           可采用同类认知动作、
           并产生同类进展信号的分支事件集合
```

自然语言提示只是这个等价类在运行时的一种渲染。

因此必须分开两个对象：

```text
TellCore    = 系统内部学到的可迁移认知技能
HintInstance = TellCore针对当前题、当前脉络、当前模型和当前预算的提示实例
```

这也重新解释333号的tell-hint多对多关系：

- 一个TellCore可以按不同强度、不同位置、不同功能渲染成多个hint；
- 同一句hint可能承载多个TellCore共享的通用控制动作；
- 非特化Pipe首先应优化TellCore，不能直接把"写出一句好提示"当成学习完成。

（372号 L233-257）

### 1.6 三个根本补充

372号在§0中提出，仍有三个根本层次需要补齐（372号 L28-38）：

1. **Tell族不应只是一条按Level排列的曲线，而应是一个多轴的候选假设格。**很多Tell彼此不可简单比较高低。
2. **Tell不应只被建模成方法说明，而应被建模成认知Option。**它必须有启动集、选择依据、参数槽、绑定规则、内部策略、终止条件、组合接口、归责接口和结果模型。
3. **Tell有效性不能只靠解题成功率判断，而要证明它在控制混杂后，确实改变了预期的推理过程，并在结构保持变换下维持作用。**

这三个补充分别回答：

- 非特化究竟学到了什么；
- 学到的东西怎样被未来AI真正调用；
- 我们怎样知道学到的是思维力而不是泄漏、偶然或提示强度。

### 1.7 Level是向量不是标量，Tell族是假设格不是直线

> **来源**：372号 §6（L1110-1170），R1认知推进

**单一Level轴会压扁不可比较的Tell。**考虑两个Tell：T1对数学对象非常通用，但操作写得很具体；T2只适用于图论对象，但操作流程高度通用。谁的Level更高？没有唯一答案。

因此Level至少是一个向量：

```text
L(T) = (
  object_generality,
  relation_generality,
  operation_generality,
  goal_generality,
  trigger_generality,
  evidence_generality,
  temporal_span,
  domain_distance
)
```

提示形态和脚手架强度不是Tell语义Level本身，而是renderer维度，应另存。

**Tell族更像假设格（偏序和概念格），不像一条直线。**Tell之间可以存在：一个比另一个在所有语义轴上更一般；两者各自在不同轴更一般，彼此不可比；两个Tell有共同上位概念；一个高Level模板有多个不同实例化分支；一个负例把原Tell拆成两个子概念。

保留"Level"作为人类直觉描述仍有价值，但系统内部不应依赖一个模糊标量完成检索、排序和版本细化。

**"峰值"应改成上下文中的Pareto前沿。**Tell质量至少包含：触发准确率、操作可执行性、近迁移效用、远迁移效用、负迁移率、提示成本、泄漏风险、可组合性、模型适配性。一个Tell可能远迁移强但成本高，另一个近迁移强且极便宜。两者都可能值得保留。

### 1.8 新增思维力也是非特化Pipe的操作符

> **来源**：372号 §5（L1078-1106），R1认知推进

353号新增的八种候选思维力，不只是未来要被非特化的"内容"，它们反过来组成了非特化方法本身。

| 候选思维力 | 在非特化Pipe中的元作用 |
|---|---|
| C1 概率存在与去随机化 | 在巨大Tell候选空间中先随机探索，再把稳定候选确定化 |
| C2 规范固定与对称破缺 | 为同一等价类选择稳定代表，避免重复存储 |
| C3 紧化/完备化 | 从有限Case Pack逐步逼近开放的高Level概念边界 |
| C4 对偶证书与不可行性证明 | 为Tell触发、成功和废弃建立可检查证书 |
| C5 取商与冗余压缩 | 把表面不同但机制相同的trace事件合并 |
| C6 对抗者量词博弈 | 主动寻找能击穿Tell边界的最坏负例 |
| C7 反例压力与定理修补 | 用失败案例收窄、拆分或修补Tell假设 |
| C8 语义不变量命名 | 发明能稳定描述跨题共同机制的新谓词和角色名 |

因此，非特化Pipe可以被理解为八种思维力的组合过程：

```text
C5取商
  → C2选规范代表
  → C8命名不变量
  → C4建立证书
  → C6生成对抗边界
  → C7用反例修补
  → C3从有限案例逼近开放边界
  → C1在候选空间中控制探索成本
```

这说明"寻找更多Powerful思维力"和"改进非特化"并不是两条独立任务线。思维力研究会直接提供非特化算法的元操作。

## 2. Tell升级为迁移工程对象

> **来源**：371号 §0 + 一句话结论（L1-148），T1未验证的理论扩展
> **判断结论**：保留概念描述，剔除8个契约的详细展开
> **预期用途**：eight-system中Tell对象的工程化方向参考

### 2.1 核心概念

> **非特化不应只被理解为"把trace抽象到某个峰值Level"，而应升级为一套迁移工程：从一个或多个trace中提取可迁移的关系结构，把它封装成具备触发条件、退出条件、正负案例边界、提示强度、运行时策略、失败critic和版本细化历史的Tell方法对象。**

（371号 L8）

### 2.2 迁移工程的八个契约（概念骨架）

371号提出非特化至少同时承担八个契约，以下是概念骨架（详细展开见371号原文，但因未验证且属过早系统化，不纳入eight-system方案）：

1. **语义契约**：Tell不是"技巧名"或"题目解法摘要"，而是一个**关系结构 + 操作转向 + 成功信号**。
2. **操作契约**：AI拿到Tell后能做什么——下一步看什么对象、把哪些对象重命名/编码/取商/对偶化、哪条常规路线应该降权、怎样判断有进展。
3. **触发契约**：正触发（哪些thinking tell显示"这里值得试"）、负触发（哪些显示"这里不该试"）、边界触发（相似但本质不同，必须防止误触发）。
4. **退出契约**：尝试后没有产生新对象、产生的新对象没有降低自由度、证书无法被局部验证、同一转向重复多次仍未改变搜索空间、与负案例边界冲突。
5. **迁移契约**：区分near transfer（同领域换参数）、middle transfer（同关系结构换对象系统）、far transfer（不同领域保留深层操作结构）、negative case（表面相似但不应触发）。Tell的Level应和迁移距离绑定。
6. **反泄漏契约**：记录是否包含源题特有数字/构造、是否直接给出最终证书、是否把唯一关键中间对象换名写出、是否给了目标题的答案形态。反泄漏不是文风问题，是系统科学性问题。
7. **负迁移契约**：一个Tell即使能解A题，也可能误导B题。需要主动记录负迁移：表面相似但结构不同、结构相似但操作方向相反、操作相同但成本过高、转向会遮蔽更短证书、提示强度太高导致AI跳过必要验证。验证集必须包含"不该触发"的题。
8. **成本契约**：提示长度、需要Solver做几步额外分析、是否需要多分支并发、是否容易引发长篇空想、是否适合放入根提示/line提示/critic提示/事后反思提示。

### 2.3 Tell方法对象的YAML骨架

371号提出的Tell Schema v2概念骨架（L121-146）：


## 3. 出题经验条目E-001~E-017

> **来源**：356号 §5（L388-691），R3可复用工件
> **预期用途**：eight-system出题工作的经验库基础

### E-001：标准定理外壳会秒杀C4题

**来源**：355号 Q-C4-01 bare测试。

**现象**：GLM-5.2开局直接识别："This is a classic problem in extremal graph theory. It's essentially Motzkin-Straus theorem."

**经验**：即使题目证明短而漂亮，只要外壳贴近经典定理，bare就可能直接做出。这样的题不能测试"对偶证书与不可行性证明"。

**下次怎么改**：
- 不出现"无三角形图 + 顶点权重 + 边权二次型"；
- 不让目标函数看起来像Motzkin-Straus；
- 保留"最优对象支持集被压缩"的内部结构；
- 换成非图论外壳，或让证书从题目内部生成。

### E-002：标准概率方法外壳会秒杀C1题

**来源**：355号 Q-C1-01 bare测试。

**现象**：GLM-5.2开局直接识别："This is a classic extremal graph theory problem. The idea is to use the probabilistic method."

**经验**：只要题目写成"存在一个无某小子图且边数很多的图"，模型会自动调出随机图+删除坏结构。

**下次怎么改**：
- 避免标准随机图外壳；
- 加入两类坏事件，不能只删一种；
- 删除后还需要修补或二次选择；
- 让随机参数不是一眼平衡出来；
- 仍保持证明竞赛化，不引用高级定理。

### E-003：低难度完整格式会制造假安全感

**来源**：354号 Q-C4-02、Q-C6-02、Q-C1-02 的自审。

**现象**：这些题都有完整题面、证明、Tell、泄漏评分，但本质偏简单或太经典。

**经验**：格式完整不等于题目合格。文档结构只能保证可审查，不能保证题目难度。

**下次怎么改**：
- 每道题都必须真实bare；
- bare成功就淘汰；
- 不因"题目看起来像竞赛题"而跳过测试；
- 在文档里明确标注"低难度对照"和"验证候选"的区别。

### E-004：高Level思维力需要两层锁

**来源**：354/355综合。

**现象**：一层锁题目会被标准套路打开。例如C1只需要"随机+删除"，C4只需要"识别定理名"。

**经验**：高Level思维力题至少需要两层锁：1. 第一层：自然路线失败；2. 第二层：目标思维力不仅要被想到，还要被正确执行。

**下次怎么改**：
- C1：随机存在 + 坏事件修补；
- C4：构造下界 + 非标准上界证书；
- C6：策略建模 + 对抗者保持不可区分状态；
- C26：创造新语言 + 用新语言完成证明。

### E-005：标准谱极值外壳也会秒杀C4题

**来源**：357号 Q-C4-02 bare测试。

**现象**：循环相邻乘积上界题中，GLM-5.2很快把目标写成循环移位矩阵的Rayleigh商，在零和子空间上取最大特征值，并用Fourier向量给出等号构造。

**经验**：C4题不能只是从Motzkin-Straus换到谱定理。只要题面天然呈现"二次型 + 范数约束 + 正交约束"，模型会直接调出标准谱证书。

**下次怎么改**：
- 不让目标函数天然写成矩阵二次型；
- 不直接给出循环、路径、完全图、正交投影等标准谱外壳；
- 让上界证书由题目内部约束生成，而不是由对象名称触发；
- 局部估计可以给弱界，但不能让标准Rayleigh商一步封顶。

### E-006：弱阈值会留下贪心禁止值出口

**来源**：357号 Q-C1-02 bare测试。

**现象**：AP-free + Sidon组合存在题原本希望测试"概率存在 + 修补"，但GLM-5.2找到贪心构造：当前集合大小为m时，禁止加入的新值至多O(m³)，因此可以贪心做到N^{1/3}量级。

**经验**：两类坏事件不自动等于概率方法题。只要目标下界足够宽，逐点禁止值计数就可能绕开随机存在路线。

**下次怎么改**：
- 目标量级或常数要超过朴素贪心保证；
- 坏事件要有依赖结构，使单点禁止值计数不够；
- 随机后要有非平凡保留、删除或修补；
- 预审时必须主动写出"为什么贪心不够"。

### E-007：已命名的深定理外壳仍会被bare恢复

**来源**：358号 C4 skew Bollobás bare测试。

**现象**：GLM-5.2先在skew版本的排列法和普通外代数维数上卡住，但最终自己补出"随机投影到R^{a+b}"的关键步骤，完整证明m≤{a+b choose a}。

**经验**：题目即使不toy，只要它本质是已命名或高度经典的深定理，GLM-5.2仍可能通过长thinking恢复标准证书。88K thinking说明题是硬的，但bare成功说明它不能进入Tell测试。

**下次怎么改**：
- 避免Bollobás/Frankl/LYM/Fisher等已命名定理表面；
- 保留"先有弱维数上界，再压缩证书空间"的结构；
- 换成非标准对象，让证书必须从题面内部生成；
- 预审时主动问：模型是否可能说出这个定理名或作者名？

### E-008：独立随机选择加Chernoff不是合格C1锁

**来源**：358号 C1 有界和表示随机集 bare测试。

**现象**：GLM-5.2直接取p=3√(log N/N)，用Chernoff和union bound控制所有和表示数。虽然写出的尾界常数证明有一个可修复错误，但路线层已经成功。

**经验**：如果所有坏事件都能被独立二项尾界分别控制，再并合界扫掉，这仍然是标准概率方法外壳，不足以测试"概率存在与去随机化"。

**下次怎么改**：
- 让坏事件之间有真实依赖；
- 让独立选择只能给弱结论；
- 需要删除、修补、条件化或二阶段选择；
- 常数余量不能大到Chernoff一把梭。

### E-009：一次谎言问答太经典，且输出失败不是数学失败

**来源**：358号 C6 一次谎言问答下界 bare测试。

**现象**：GLM-5.2开头直接识别Ulam/Renyi一次谎言模型，在thinking中完整给出N(q+1)≤2^q的叶子计数证明，但未生成solution文件。

**经验**：C6不能用标准一次谎言或Hamming球计数模型。另一个实验经验是：输出文件缺失要单独记录，不能把它误判成数学失败。

**下次怎么改**：
- 改成多状态、非均匀代价、或动态候选维护；
- 让信息量计数给出弱界，真正结论需要对抗者策略；
- 观察thinking中是否维护"多个可能世界"，而不是只数叶子；
- 记录solution缺失这类落盘异常，但不要把它当作Tell成功空间。

### E-010：新造题必须和历史bare失败锚题同台比较

**来源**：362号第二轮竞赛级挑战题试产。

**现象**：连续几轮新造题都有完整证明骨架，也看起来像竞赛级难题，但真实bare测试后往往被GLM-5.2通过经典外壳或标准短路做出。相反，1631、1843、1709等历史题已经有真实bare失败、匹配Tell成功或错误Tell失败的证据。

**经验**：新题不能孤立评估。每一批新造题都要和历史真实bare失败题放在同一张测试表里，用历史锚题给难度和失败形态定标。否则"题面高级""证明漂亮"会替代"确实能卡住目标AI"的证据。

**下次怎么改**：
- 每轮新造题都配一组历史锚题；
- 新题只进入Stage B bare筛选，不直接叫Tell候选；
- 若新题bare成功，记录它的短路路线，作为下一版硬化材料；
- 若历史锚题在当前模型版本上转为bare成功，也要更新难度窗口，不能继续按旧证据使用；
- 对新题优先观察"它比历史锚题更容易还是更难被模型命名/短路"。

### E-011：三角化不能自动逃离Frankl-Wilson外壳

**来源**：363号 Q362-C4-01 bare测试。

**现象**：Q362-C4-01把经典模交条件改成有序三角条件，原本希望测试"评价证书 + 三角非奇异矩阵"的C4执行力。但GLM-5.2开局直接识别为Frankl-Wilson变体，并自然写出f_i(x)=prod(v_{A_i}·x - ℓ)，M_{ij}=f_i(v_{B_j})，随后用三角矩阵非零对角线和低次多重线性多项式空间维数完成路线。

**经验**：对称条件改成单向三角条件，不足以构成新外壳。只要题面同时出现"模交 forbidden residues + 低次多项式 + 维数上界"，模型仍会调出Frankl-Wilson/Alon-Babai-Suzuki一类记忆。

**下次怎么改**：
- 不把证书函数直接写成"对交集大小取多项式"；
- 隐藏评价对象与测试对象的配对关系；
- 换掉模交/有限域残基外壳，保留"对象-测试对象形成三角证书矩阵"的骨架；
- 或让三角矩阵只是中间层，最终还需要非模板的压缩/对偶化动作。

### E-012：多加一种干扰状态，不等于C6硬锁

**来源**：363号 Q362-C6-01 bare测试。

**现象**：Q362-C6-01在一次谎言搜索中加入一次沉默状态。GLM-5.2先直接识别为Ulam-Renyi型体积界；随后在"自适应会不会让不同干扰配置合流"处出现真实犹豫，但最终自行找到注入性引理完成证明。

**经验**：C6题不能只是在经典对抗模型中多加一个状态。只要答案仍可被固定目标逐条恢复，体积界会自然扩展，GLM-5.2能在bare中自行补上注入性。

**下次怎么改**：
- 让简单状态计数只给弱界，必须构造对抗者策略或势函数；
- 设计状态合流现象，使"每个配置一条不同transcript"失效，但仍需证明强下界；
- 让叶子覆盖能力依赖历史约束，而不是固定t的静态列表大小；
- 把卡点放在"如何维护多个可能世界"而不是"如何数干扰模式"。

### E-013：新题应从奥赛母题拆解开始

**来源**：364号奥赛母题分析法。

**现象**：连续多轮凭空新造题虽然有证明骨架，但容易落入经典外壳。相反，problem_profiles中真实奥赛题已经记录了自然错路、key insight、bare失败预测、tell/hint对，这些信息更适合指导造题。

**经验**：出题灵感应该从奥赛题的"失败机制和转向机制"中抽，不从题面表层抽。正确路径是：母题 -> 自然错路 -> 关键转向 -> 可迁移骨架 -> 换壳 -> 加第二层锁。

**下次怎么改**：
- 每轮新造题前，先选3-5道奥赛母题填写母题拆解表；
- 没有母题拆解表的新题只能算Stage A灵感题，不能直接进入Stage B bare筛选；
- 优先用主导层剥离、excess半群、规范化+容量函数、参数阈值反演这类可换壳骨架；
- 每道新题都要说明"保留母题哪一层，换掉哪一层，训练数据风险在哪里"。

### E-014：奥赛母题启发也有Level族

**来源**：366号奥赛出题启发的Level分层。

**现象**：364号的母题拆解和365号的母题本体测试仍偏Level 1-2：技巧复用和解法骨架复用。真正制造挑战的灵感不只是"这题用了什么方法"，而是"这题如何制造一个自然方法必然失败、必须迁移表示/证书/不变量的数学处境"。

**经验**：同一道奥赛题应生成"出题启发族"：Level 0题面复用、Level 1技巧复用、Level 2解法骨架、Level 3失败机制、Level 4命题机制、Level 5数学处境生成法。挑战GLM-5.2的新题应主要从Level 3-4出发。

**下次怎么改**：
- 每个母题先填Level 0-5启发表；
- 新题必须说明自己采用哪个Level的启发；
- Level 0-1题只能做sanity check，不能进入主力bare筛选；
- Level 2题可以做母题本体校准，但不等于新挑战题；
- 进入bare测试的新造题应来自Level 3-4的可操作化出题指令。

### E-015：先用真实题库筛Level 3-4机制盲区，再从盲区造题

**来源**：367号Level 3-4奥赛机制挑战池。

**现象**：直接新造题容易不知道自己是在造"经典骨架轻微变体"还是在造真正的GLM-5.2盲区。problem_profiles已经包含大量真实竞赛题的key_insight、bare_ai_error_prediction、tell/hint结构，可以先筛选出Level 3-4机制最强且预测bare失败的题，作为直接挑战池。

**经验**：更稳的路线不是"凭空造题 -> bare淘汰 -> 再猜"，而是：题库profile筛Level 3-4机制 -> 直接bare验证当前模型盲区 -> 从失败thinking提取命题机制Tell -> 再按该机制生成新变体题。这样能把"出题"建立在真实模型盲区上，而不是建立在人工难度自评上。

**下次怎么改**：
- 优先测试真实题库中Level 3-4机制强、尚无复测记录的题；
- 每题记录自然错路、失败机制、命题机制，而不只是标准解；
- 只有真实bare失败的机制，才优先拿来生成新题；
- 若真实题本体bare成功，则对应机制必须继续升Level或加第二层锁。

### E-016：Level不是标签，而是命题操作

**来源**：368号奥赛出题启发层级的操作化。

**现象**：366号已经提出奥赛出题启发有Level 0-5，但如果只把Level当分类标签，仍然可能停在"这题是Level 4机制"这种描述层。真正有用的不是给母题贴Level，而是说明在某个Level上保留什么关系、制造什么失败、迫使什么迁移。

**经验**：高Level出题要把一道奥赛题拆成两份脚本：解法脚本（这题怎么做？）和设障脚本（这题怎样让自然方法失败，并迫使解题者换表示/证书/不变量？）。Level 0-2主要复用解法脚本，容易被GLM-5.2的已有套路覆盖。Level 3-4主要复用设障脚本，更适合制造可观察的思维力挑战。最高Level的同构之桥不能只迁移正解，还必须迁移自然错路和失败机制。

**下次怎么改**：
- 每道新题都要写"源题角色图"和"目标题角色图"；
- 同构之桥必须检查对象、操作、自然入口、失败点、隐藏结构、证书六类角色；
- 高Level启发必须降回四件套：自然入口、失败点、隐藏结构、证书；
- 只写"仿某奥赛题"或"使用某Level 4机制"不够，必须写出具体命题操作。

### E-017：第二批机制探针应避开已被秒杀的高频外壳

**来源**：369号Level 4设障脚本挑战池。

**现象**：前几轮直接新造题反复说明，GLM-5.2对若干高频外壳非常敏感：多项式维数证书、随机图删除、一次谎言体积界、谱/Rayleigh商等。一旦题面靠近这些高频骨架，bare可能路线层直接成功。继续只在这些外壳里加参数，很容易制造"复杂但不难"的题。

**经验**：下一批机制探针应选更偏Level 4的设障脚本，而不是继续在高频技巧上加锁。369号选了四类：反向坍缩（正向构造爆炸，必须从目标集反向合并）、shifty闭包（直接生成对象爆炸，必须问哪些变换保持集合）、尺度势函数（普通空间分割不降复杂度，必须设计带权势函数）、逆映射不变量（表面优化其实是同一边界的两种计数）。

**下次怎么改**：
- 测试优先跑369的P0：shifty integers与polynomial collapse；
- 若bare失败，要从thinking中记录它是卡在"自然入口、失败点、隐藏结构、证书"的哪一项；
- 若bare成功，不能简单说"题不难"，要记录模型具体掌握了哪种Level 4设障脚本；
- 后续新造题应优先从真实bare失败的Level 4脚本跨领域变形，而不是凭空继续加复杂度。

## 4. 出题哲学与核心铁律

> **来源**：356号 §1-§2（L29-299），R3可复用工件
> **预期用途**：eight-system出题工作的方法论基础

### 4.1 POC难题不是普通竞赛题

| 类型 | 问的问题 | 好题标准 |
|---|---|---|
| 普通竞赛题 | 选手能不能做出来？ | 解法漂亮、难度合适、区分度高 |
| POC难题 | AI缺不缺某种思维力？ | bare卡在目标瓶颈，Tell后能突破，且Tell不泄漏 |

POC题不能只追求"难"。它必须让bare AI暴露一个**可观察的认知缺口**。

### 4.2 真正的题目来源：经典难题的思维力内核

一个经典难题至少有六层：

| 层 | 说明 | POC出题时怎么处理 |
|---|---|---|
| 表面外壳 | 图论、数论、几何、代数等题面对象 | 要经常换掉，避免训练数据触发 |
| 条件结构 | 哪些约束彼此作用 | 尽量保留核心约束关系 |
| 自然错路 | 大多数解题者会先走的路 | 要保留，作为bare卡点 |
| 关键转向 | 解法中"原来要这样想"的一步 | 这就是目标思维力 |
| 证书/构造 | 最终证明成立的对象或不变量 | 要保留可验证性 |
| 解法长度 | 正确路线是否能在竞赛篇幅内写完 | 必须控制，不能变成研究题 |

POC出题的核心动作是：**保留第2-5层，重写第1层，控制第6层。**

### 4.3 难题不是"加复杂度"，而是"制造必要转向"

让题变难有两种方式：1. 加很多条件、参数和计算；2. 让自然路线走到墙上，必须换一种思维力。第一种是噪音难度，不适合POC。第二种才是思维力难度。

一个好POC题应有这样的形状：

```text
题面看起来有自然入口
  ↓
bare AI走进去
  ↓
自然入口给出弱结果、假希望或循环
  ↓
AI需要一次目标思维力转向
  ↓
转向后证明变短、变清楚、可验证
```

如果bare AI一眼看出标准路线，题太熟。如果Tell后仍然不知道怎么做，题太硬。如果Tell必须说出具体方法名，题不纯。

### 4.4 POC题的六个零件

| 零件 | 它是什么 | 为什么需要 |
|---|---|---|
| 内核 | 从经典难题抽出的思维力结构 | 保证题有真实数学含量 |
| 外壳 | 新的题面对象和叙述 | 避免训练数据和定理名触发 |
| 诱饵 | 一条自然但不够的路线 | 让bare失败有可观察轨迹 |
| 锁 | 只有目标思维力能打开的瓶颈 | 保证Tell不是泛泛鼓励 |
| 证书 | 最终可审查的证明对象 | 防止开放题或玄学判断 |
| 余量 | 常数/条件上的缓冲 | 保证Tell后能做，不变成研究级 |

没有诱饵，bare可能随机乱走，无法分析。没有锁，任何提示都可能有效。没有余量，Tell后也可能做不出来。

### 4.5 七条核心铁律

**铁律1：真实bare失败是入场券。** 人工自评"P5/P6"不够。只有真实Solver bare失败，候选题才有资格进入Tell测试。

**铁律2：不能用toy案例测试高Level思维力。** 有些思维力只在足够复杂的情境中才真正出现。toy题可以做工具链sanity check，但不能作为思维力有效性的证据。

**铁律3：经典外壳会让题目失效。** 如果题目外壳直接触发经典定理名、经典模型名或标准套路，GLM-5.2可能不需要目标思维力就能完成。

**铁律4：难题要难在思维转向，不难在计算噪音。** 不合格的难：条件很长、计算很重、参数很多、证明步骤机械但繁琐、题意晦涩导致AI误读。合格的难：自然路线会失败、错误路线很诱人、关键转向需要目标思维力、Tell只给方向不给具体路线、Tell后AI仍需要自己完成数学。

**铁律5：题目必须有可观察卡点。** 一题能否用于Tell验证，取决于bare thinking里能不能观察到目标卡点。没有可观察卡点，就无法判断Tell是否真正改变了思维方式。

**铁律6：并发是观察能力，不是出题指标。** 并发测试的价值在于同时观察多个AI的thinking过程，而不是为了凑并发数而启动低质量题。

**铁律7：bare结果要分路线、证明、落盘三层判定。** bare失败不等于数学失败——可能是落盘失败、token limit或工具卡死。bare成功也不等于数学成功——需要检查proof是否valid。

### 4.6 思维力到出题卡点的映射

**C4（对偶证书与不可行性证明）**：
- 合格卡点：AI找到下界构造但无法证明没有更好对象；AI尝试局部估计但无法全局封顶；需要构造一个证书限制所有对象。
- 不合格外壳：直接是Fisher不等式、Motzkin-Straus、LP/SDP模板、循环矩阵/Rayleigh商/Fourier谱分解。
- 硬化方向：把证书藏在题目内部的辅助量里；让构造容易，上界不自然；让局部估计给出弱界。

**C1（概率存在与去随机化）**：
- 合格卡点：AI执着显式构造；存在性对象空间巨大；坏事件局部但多类；随机选择后需要删除、修补或条件化。
- 不合格外壳：标准随机图避小子图；标准随机染色并合界；只需一次期望小于1；独立选择+Chernoff+union bound即可完成。
- 硬化方向：两类坏事件一正一负；随机后需局部修补；明确排除朴素贪心禁止值计数能达到目标。

**C6（对抗者量词博弈）**：
- 合格卡点：AI给出静态构造但违反在线/对抗约束；题目有交替量词；对手能根据当前状态回应；证明需要维护候选集或安全区间。
- 不合格外壳：标准一次说谎问答；标准Hamming球/叶子计数下界；单步在线平衡；只有普通信息量下界。
- 硬化方向：多轮；双方信息不对称；对抗者需要保持多个可能世界；成功策略需要同时维护两个不变量。

## 5. bare淘汰的meta教训

> **来源**：355号、357号、358号、363号四轮bare淘汰记录的汇总提取（D2重复学习，提取一次meta教训）
> **预期用途**：eight-system出题难度预期的现实约束

### 5.1 核心meta教训

四轮bare淘汰（355/357/358/363号）反复得到同一结论：

**GLM-5.2在bare条件下能做出绝大多数竞赛级题目，包括经过硬化设计的题目。** 具体表现：

1. **经典定理外壳秒杀**（355号）：Motzkin-Straus、随机图删除法等标准外壳被开局直接识别。
2. **标准谱方法秒杀**（357号）：循环矩阵Rayleigh商、Fourier向量等标准谱证书被快速调出。
3. **已命名深定理仍可恢复**（358号）：Bollobás定理虽经skew变形，GLM-5.2通过88K thinking最终自行补出关键步骤。
4. **新造题变体仍被秒杀**（363号）：三角化Frankl-Wilson变体、多状态Ulam-Renyi变体均被bare路线层突破。

### 5.2 出题困境

这四轮淘汰揭示了一个根本困境：

- **AI能做出来的题无法用于非特化验证**——如果bare能做出来，题就不能测试"Tell是否改变了思维方式"。
- **GLM-5.2的数学能力极强**——对经典定理、标准方法、已命名结果的恢复能力远超预期，即使经过换壳、加锁、变形，仍可能被识别。
- **出题难度极高**——需要同时避开经典外壳、标准方法、已命名定理、贪心短路、标准谱证书等多个"秒杀区"。
- **凭空造题容易落入经典外壳**——连续多轮新造题都落入Motzkin-Straus、Frankl-Wilson、Erdos随机图、Ulam-Renyi等高频外壳。

### 5.3 应对方向

从四轮淘汰中提炼的应对方向（已沉淀为E-010~E-017经验条目）：

1. 新造题必须和历史bare失败锚题同台比较（E-010）。
2. 出题应从奥赛母题拆解开始，而非凭空造题（E-013）。
3. 奥赛母题启发有Level族，应从Level 3-4（失败机制/命题机制）出发（E-014）。
4. 先用真实题库筛Level 3-4机制盲区，再从盲区造题（E-015）。
5. Level不是标签而是命题操作，要写设障脚本而非解法脚本（E-016）。
6. 避开已被秒杀的高频外壳，选更偏Level 4的设障脚本（E-017）。

### 5.4 历史bare失败锚题

## 6. 六门审计概念

> **来源**：373号 §0-§2（L1-82），T2过早但可能有用的框架
> **判断结论**：保留六门审计概念骨架，剔除9个POC的详细通过标准和EvidenceRecord规格
> **预期用途**：eight-system验证方案的概念参考

### 6.1 核心概念

TellV3的POC不应再设计成一次"大实验"，而应设计成一套**六门审计POC套装**：先冻结题包，再逐门验证，最后端到端闭环。

这套POC的目标不是简单证明"非特化有效"，而是把一条候选Tell逐步推进成：候选Tell → TellCore → TellStrategy → 可被Grove运行时调度的认知策略。

每个POC只回答一个可归责问题。成功时知道哪个组件有效；失败时知道是哪一门没过。

### 6.2 六门审计的六个问题

1. **可选择**：系统知道什么时候选它吗？
2. **可执行**：AI知道拿到它以后做什么吗？
3. **可终止**：系统知道什么时候停、退、让位吗？
4. **可组合**：它能和其他Tell一起工作吗？
5. **可归责**：成败能归因到具体组件吗？
6. **可持续学习**：它能从新证据中修订自己吗？

### 6.3 POC套装结构（概念骨架）

| 编号 | 名称 | 主要审计门 | 核心问题 |
|---|---|---|---|
| POC-0 | Case Pack冻结 | 前置门 | 题包、对照、证据边界是否预先冻结？ |
| POC-1 | 因果取商 | 可归责、可持续学习 | TellCore是否保留因果有效结构，而不是源题表面？ |
| POC-2 | 可选择 | 可选择 | selector是否能选中正例、拒绝假朋友？ |
| POC-3 | 可执行 | 可执行 | HintInstance是否让AI执行预期认知动作？ |
| POC-4 | 可终止 | 可终止 | 有效、无进展、冲突场景中能否停止或让位？ |
| POC-5 | 可组合 | 可组合 | 多条Tell之间能否调度、排序、冲突处理？ |
| POC-6 | 可归责 | 可归责 | 增益能否归因到TellCore、renderer、selector或lineage？ |
| POC-7 | 可持续学习 | 可持续学习 | 反例能否修改边界、版本或退役策略？ |
| POC-8 | 端到端闭环 | 六门全覆盖 | 多trace到运行时调用再到反例修订是否完整闭环？ |

> **注**：373号中每个POC的详细通过标准、EvidenceRecord YAML规格、题包七类case定义等属D6（过早POC框架），不纳入eight-system方案。六门审计的概念骨架保留，待实际POC运行时再细化通过标准。

## 7. 非特化策略审查的关键认知

> **来源**：352b号 §0（L1-49），R1认知推进
> **预期用途**：eight-system实验协议设计的风险警示

### 7.1 最大风险

当前策略的最大风险不是Tell写得不够抽象，而是**Tell在实验中承担了多个混杂功能**：

- 它可能是真正的思维力引导；
- 也可能是题目难度提示；
- 也可能是解法空间裁剪；
- 也可能是隐性方法泄漏；
- 也可能只是增加了模型重试深度和自信。

如果不把这些功能拆开验证，实验结果会很漂亮，但不可解释。

### 7.2 从三步法到完整协议

把非特化策略从"三步法"扩展为：

```text
trace
  → 候选Tell族生成（IBE + 结构映射 + 可操作性）
  → 触发条件定义（什么时候该用）
  → Tell内部结构化（触发/执行/退出/校验）
  → 反事实泄漏审查（答案盲审 + 方法盲审 + 题族盲审）
  → 形态成本校准（提示长度/强度/搜索空间裁剪度）
  → 实验归因矩阵（成功、失败、误触发分别归因）
  → 入库或废弃
```

三步法仍然保留，但它只是"生成Tell"的核心，不再承担全部质量控制职责。

## 8. 思维力框架重整的关键认知

> **来源**：353号 §1（L24-37），R1认知推进
> **预期用途**：eight-system思维力分类的分层参考

### 8.1 26种思维力不是同一抽象层级

349号的26种思维力里至少混有四种层级：

| 层级 | 含义 | 例子 |
|---|---|---|
| 底层认知操作 | 可跨领域反复出现的基本动作 | 同构之桥、对偶/反演、不变量识别、特殊化 |
| 策略模板 | 多个底层动作组合成的解题路线 | 构造必然逃逸、找对递降量、信息融合时机 |
| 数学技术姿态 | 在特定数学文化中成熟的高阶技术形态 | 覆盖-提升、先验估计、结构化嵌入、平均化消解 |
| 历史突破叙述 | 描述重大工作"改变了什么"的宏观标签 | 框架创造、本质重构、统一化框架 |

如果后续直接追加新种类，新增项会和不同层级的旧项混在一起，导致分类学无法判断"这是新思维力，还是某个父类下的新子型"。
