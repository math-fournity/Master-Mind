# 两棵树实现时机与非特化研究的基本实践方式 · 决策记录

> **日期**：2026-08-16
> **性质**：用户与研究AI（Master Agent）的两次问答，完整落盘。第一次决定"两棵树"（引导树+解题树）在非特化研究阶段的实现时机；第二次确立非特化研究必须携带的基本实践方式。
> **地位**：用户直接确认的研究治理决策，对 eight-system 所有后续实验和工作方式有效。新AI必读（已从 NEW_AI_ONBOARDING.md 链接）。
> **一句话合并表述**：**动作先行，状态随后——循环的动作每圈都真，树的形态等动作教会我们它该长什么样。**

---

## 问答一：非特化研究这个阶段，要不要同时考虑实现和打磨"两棵树"？

**用户原话**：你觉得非特化研究这个阶段，要不要同时考虑实现和打磨"两棵树"？为什么？

**研究AI的回答**（完整）：

判断：**这个阶段不应该动手实现和打磨两棵树，但应该让所有实验产物保持"树形可回填"的记录纪律。**

### 为什么现在不该实现

**1. 当前实验里的"树"是退化的。** Mid-Hint 实验测的是一圈循环：bare 跑到卡点 → 提取脉络 → 注入 Hint → 新 AI 从中间继续。它对应的树是一条 2 节点 1 条边的路径。为这个图建通用树机制（增量插入、终点检索、多分支管理、停机条件、并发生长）是在给没有负载的机器造底盘——这正是 386/388 号调查里识别的模式 D1/D6（过早全面化、过早框架），研究过程 58-81% 的过度设计就是这么来的。

**2. 两棵树的价值前提是多旋转和多分支，而本实验明确排除了这两点。** 预注册写死了"只转一圈，不循环旋转"。树的真正收益——完备性检查、回溯、并发 DFS、停机条件——全部在第二圈以后才兑现。现在实现等于为还没被验证有效的东西建状态机。

**3. 因果问题和工程问题会互相污染。** 非特化研究现在回答的是**内容层面的因果问题**：Level 3 的 Hint 够不够具体、能不能在正交题面上迁移、半路注入是否优于前缀注入。树回答的是**状态管理问题**。两者混做，树实现里的 bug 会污染 Hint 效应的对照实验（引入混杂变量），实验的迭代速度也会被基础设施拖慢。Phase 0/1 之所以快，就是因为只有 prompt 文件加 contrast 脚本。

**4. 本项目已有实证：循环有效性验证不需要树。** 283 号 tree 组（bare 0% → tree 67%，Mid-Hint 的直接先例）用的就是脉络文本文件加字典方向，手工拼装，没有树基础设施。它验证的正是三个推动关系本身。

**5. 职责边界已经划走了。** 两棵树的实现是第六代 `system/` 的领地（TreeState schema、process_solve.py 都在那边，数据库里 gen-5/6 实验留下的 tree_nodes/tree_edges 就是它的雏形）。eight-system 被创立的目的之一就是从"系统工程吞没研究"里收窄回来。现在去做树，等于在实验线上重建 system/ 的领地，破坏刚恢复的边界纪律。

### 但有两件便宜的事现在就该做（对冲未来）

**1. 记录树形化。** 每次运行留下 `parent_run → 卡点节点描述 → hint边 → child_run` 的链式记录（字段级，不是文章级）。这样将来真正实现两棵树时是**回填**而不是重写。这也是运行痕迹全程保留规则的本来要求——Phase A 的 bare run、Phase B 的卡点提取、Phase C 的注入结果本来就要落盘，只需多加几个关联字段，成本几乎为零。

**2. 写下"毕业条件"。** 明确什么信号出现时才开始实现树，避免"感觉该做了"式的启动：
- Mid-Hint 成功，且下一个实验需要 **≥2 圈旋转**（Hint 链：注入后 AI 继续又卡，需第二次检索）；
- 一个卡点上需要**在多个 TellCore 之间做选择**（Selector 验证从"防误触发"升级为"真选择"）；
- 同一道题需要**并发多个 Solver** 生长分支；
- 循环需要**无人值守端到端**转起来。

另外一个天然衔接点：错题分析系统的 1521 条结果（失败路径 + 卡点 + 转折类型）本质上就是解题记录树的单层切片——它已经是一份"扁平化的失败侧树数据"。等树的毕业条件触发时，这份资产可以直接回填，不需要重新采集。

## 问答二：非特化研究必须带着的"基本实践方式"是什么？

**用户原话**：我认为，可以不去着急实现树，但非特化研究必须要带着一种基本的实践方式，对吗？你理解我说的这种基本的实践方式是什么吗？

**研究AI的回答**（完整）——理解正确，这种基本的实践方式就是：**每一轮非特化研究，都必须是核心循环的一次真实旋转——由我们亲手执行循环的每个动作，而不是把 Hint 当作静态文本做属性研究。**

### 一圈完整实践的五个真实动作

1. **真实地跑**——让推理 AI 在无提示状态下真实地解题，产生真实的探索过程和真实的卡点；
2. **真实地读（tell识别）**——从真实 thinking 中识别出"AI 在哪里、处于什么数学处境、为什么走不通"，这就是读 tell；
3. **真实地给（方向匹配）**——在这个卡点上匹配非特化 Hint，做出"往哪边引"的判断；
4. **真实地接（脉络继承）**——构造脉络文本，让新 AI 从中间处境续跑，而不是从头开始；
5. **真实地看**——三层判定（路线层/证明层/落盘层）观察这一圈转得有没有效。

**树是这一圈圈实践沉淀下来的状态；实践是动作本身。** 缓建树只是说"状态的机械化可以等"，绝不是说"动作可以省略或者被替代"——恰恰相反，在没有系统代劳的阶段，这些动作全部由研究者亲手承担，每一圈都不能缺斤短两。

### 为什么必须带着这种方式（项目已用事实回答过）

- **Phase 0/1 就是丢掉这种实践的代价**。它们把 Hint 预写在 prompt 开头——没有真实卡点、没有中间处境、没有续跑，循环的三个动作被抽掉了。结果是测出来的假说（token efficiency）是错的，要靠 Step 4 continue 实验修正成 cognitive scaffold，整个实验方向最后被迫修正为 Mid-Hint。Hint 的价值主张本来就是"卡点处的方向改变动作"，离开卡点去测它，测到的是别的东西。
- **283 号 tree 组是这种实践的正面范本**：bare 真跑 → 从失败 thinking 提取脉络到卡点 → 匹配字典方向 → 新 AI 续跑，全部手工，bare 0% → tree 67%。
- **手工实践就是在为未来的自动化测绘**。卡点识别、脉络提取、方向匹配——这些是系统将来要脚本化的环节，但哪些判断是机械的、哪些需要真正的判断力，只有一圈圈亲手做才能暴露出来。这就是"系统就是你"到"系统就是脚本"之间必经的中间态：先由人做，人做熟了才知道怎么把判断力编码进去。

### 对当前工作的具体含义

- Mid-Hint 的 Phase B（从 bare thinking 提取脉络到卡点、在卡点上匹配 TellCore 方向）不能简化成模板拼接——它就是实践方式的心脏；
- 构造正交新题时写设障脚本和 bare 预注册，本质上是在纸面上预演这一圈（预判 AI 会在哪卡、卡成什么样）；
- 每转完一圈留下 parent→卡点→hint边→child 的链式记录，就是这种实践向未来两棵树的天然沉淀。

---

## 两条决策的合并表述

**动作先行，状态随后。** 两棵树是状态、是工程、是 system/ 的领地，缓建并把毕业条件写明；基本实践方式是动作、是研究本身，每一圈循环的五个动作必须真实完整执行，由研究者亲手承担。研究每真实转一圈，未来树的一根枝条数据就有了；等实践把"哪些判断可机械化"暴露清楚，树的实现就是水到渠成的回填，而不是前置的工程冒险。
