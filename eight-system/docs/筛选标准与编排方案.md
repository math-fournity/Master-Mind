# Eight System · 非特化研究筛选标准与编排方案

> **日期**：2026-08-15
> **目标**：从 seven-system 构建前的"非特化"研究文档（约 34,000 行，60 份文档）中，筛选出真正的认知推进和可复用工件，剔除过早系统化和治理膨胀，产出一套可审计的非特化方案，用于 eight-system 的实现。
> **前置调查**：本方案基于 `eight-system/docs/` 下三份调查文档的结论——认知增量比仅 9-19%，过早系统化和膨胀占 58-81%。

---

## 一、筛选标准

### 1.1 保留标准（满足任一即保留）

| 编号 | 类别 | 定义 | 典型实例 |
|---|---|---|---|
| R1 | **认知推进** | 提出了新的、改变了理解的概念或命题 | tell/hint 二元组、hint 泛化命题、坐标轴不是点、因果充分的取商 |
| R2 | **实验证据** | 包含真实的实验结果数据（不是设计稿） | 283号 bare 0%→tree 67%、288/289号 tell 去特化验证结果 |
| R3 | **可复用工件** | 包含具体可用的 YAML/数据结构/经验条目 | 382号 TellCore 候选 YAML、356号出题经验 E-001~E-009 |
| R4 | **合理工程约束** | 来自科学方法内在要求的约束（仅适用于 387/389 号） | 因果实验骨架、答案隔离、append-only、多系统边界 |
| R5 | **负证据** | 真实的失败结果及其原因分析（不是重复记录） | 280号静态抽象 hint 的负结果、bare 淘汰的根本原因 |

### 1.2 剔除标准（满足任一即剔除）

| 编号 | 类别 | 定义 | 典型实例 |
|---|---|---|---|
| D1 | **过早全面化** | 在 0 次验证时枚举全部可能性 | 349号 26 种思维力、350号 2600 次实验方案、372号 24 项契约 |
| D2 | **重复学习** | 多次执行本质相同的实验得到相同结论 | 355/357/358/363 四轮 bare 淘汰同结论 |
| D3 | **治理递归** | 为约束自己不越界而无限展开的 Gate/验证器/授权链 | 387号 74 个 Gate、3 层授权链 |
| D4 | **文档膨胀** | 篇幅远超认知内容所需 | 352a号 1296 行描述启动 tmux 操作 |
| D5 | **无关工具/流程** | 与非特化认知无关的辅助系统设计 | 377-379号管道化系统、376号题库下载 |
| D6 | **过早 POC 框架** | 在 0 个 POC 运行时定义的 POC 通过标准 | 373号 8 个 POC 的通过标准 |

### 1.3 待定标准（需要 subagent 判断并说明理由）

| 编号 | 类别 | 判断原则 |
|---|---|---|
| T1 | **未验证的理论扩展** | 概念有价值但未验证——保留概念描述，剔除系统化展开。如 371号"Tell 升级为迁移工程对象"概念保留，但其后的 8 个契约展开剔除 |
| T2 | **过早但可能有用的框架** | 框架结构可能对未来有用，但时机过早——保留框架骨架，剔除详细枚举。如 373号 6 门审计的概念保留，8 个 POC 的详细通过标准剔除 |
| T3 | **CaseCard 等工件** | 在 POC 未运行时构造的详细工件——保留结构模板和少数代表性样例，剔除批量枚举 |

## 二、编排方案

### 2.1 分组原则

按**认知贡献聚类**分组，不按时间顺序——这样每个 subagent 的产出更内聚，整合时更容易拼成连贯方案。

### 2.2 五个 subagent 分工

| Subagent | 模块 | 负责文档 | 总行数 | 预计产出 |
|---|---|---|---|---|
| S1 | 核心理论 | 000 + 277-289 | 2,666 | 400-600 行 |
| S2 | 分类学认知 | 333-348 | 3,345 | 300-500 行 |
| S3 | 非特化定义 + 出题经验 | 349-373（重点约 4,000 行） | 15,470 | 300-500 行 |
| S4 | TellCore + CaseCard + 审计索引 | 382 + 383 + 388 | 3,833 | 600-800 行 |
| S5 | 合理设计决策 | 387 + 389 | 4,652 | 200-400 行 |

### 2.3 产出格式

每个 subagent 产出两个文件到 `eight-system/docs/筛选产出/`：

1. **`<模块名>-精简文档.md`**——筛选后的精简内容，只包含保留项
2. **`<模块名>-筛选审计表.md`**——列出读了哪些文档、保留了什么（标注 R1-R5）、剔除了什么（标注 D1-D6）、待定了什么（标注 T1-T3 + 理由）

### 2.4 整合阶段

5 个 subagent 完成后，主 agent 整合产出：

1. **`eight-system/docs/非特化方案-v1.md`**——一套连贯的可审计非特化方案
2. **`eight-system/docs/总筛选审计表.md`**——汇总 5 个 subagent 的审计表
3. **`eight-system/docs/实现路径建议.md`**——从最小端到端实验开始的实现路径

## 三、可审计性要求

### 3.1 每个保留项必须标注

- 来源文档编号
- 来源文档行数范围（如 `283号 L45-89`）
- 保留理由（R1-R5 中的哪一条）
- 在 eight-system 中的预期用途

### 3.2 每个剔除项必须标注

- 来源文档编号
- 剔除理由（D1-D6 中的哪一条）
- 是否有可能在未来需要时回取（是/否 + 回取条件）

### 3.3 每个待定项必须标注

- 来源文档编号
- 待定理由（T1-T3 中的哪一条）
- subagent 的判断结论（保留/部分保留/剔除）
- 判断依据

---

## 四、关键约束

1. **subagent 只做筛选和提取，不做新设计**——不发明新概念、不补充新内容、不评价研究过程的对错。只从已有文档中提取或剔除。
2. **保留原文的核心表述**——提取认知内容时，尽量保留原文的关键句和定义，不要改写。改写会丢失原意的精确性。
3. **剔除不等于删除原文**——原文仍在原位置不动。剔除只是意味着"不纳入 eight-system 的非特化方案"。
4. **产出必须自包含**——精简文档读完后能独立理解，不需要回查原文。但关键定义要标注原文出处。
