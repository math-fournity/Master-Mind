## 方案定位

本方案是从 seven-system 及其前置研究过程中**筛选出的真正认知推进和可复用工件**，剔除了过早系统化、治理递归和文档膨胀后的整合产物。它不是 seven-system 的修订版，而是一套**从最小端到端实验开始**的可审计非特化方案，用于 eight-system 的实现。

**核心原则**：先跑通一条真实实验，从真实运行中沉淀 Gate 和治理结构，而不是在空壳上预先铸造完整治理体系。

## 第一部分：核心理论

### 1.1 tell/hint 二元组（000号）

引导树闭环中"识别→给方向"的操作是一个二元组：

- **tell端**：从推理AI的thinking中读出的分叉信号——AI没有考虑什么、在哪里可以分叉但没分叉。取自poker术语——观察对手揭示出的信息。
- **hint端**：给新AI的翻译方向——从字典中匹配的具体翻译方向。

**读tell，给hint。** tell是输入（从推理AI读出），hint是输出（给新AI注入）。

**tell的四个组成成分**：
1. 分叉信号（Branch Signal）——识别可以分叉但AI没分叉的位置（line上分叉或根节点分叉）
2. 分叉类型（Branch Type）——对分叉信号的抽象分类
3. 未探索诊断（Unexplored Diagnosis）——判断AI为什么没走这条路、这条路通向什么
4. 方向匹配（Direction Matching）——从未探索诊断到字典中具体翻译方向的映射

**关键认知修正**：系统识别的不是"AI在哪里卡住了"，而是"AI的thinking中哪些位置可以分叉但AI没分叉"。往往不是AI卡住了需要提示，而是AI走错路了——它选了一个方向走下去，但还有很多方向它没走。系统在这些没走的方向上开新分支，启动新AI走新分支。

> 详细内容见 `筛选产出/S1-核心理论-精简文档.md` §1

### 1.2 hint 泛化命题（277号）

**核心命题**：同一个hint能跨题、跨题型、跨领域生效，只要那道题在"这个hint点"上有关联——哪怕两道题的表面样子和解题思路99%不同。

**不同Level的hint是不同的故事**：
- 知识性hint：故事是"知识传递"
- 思维方向hint：故事是"策略选择"
- 极高Level hint（如"同构之桥"）：故事是"范式引入"

这三个故事需要不同的机制、不同的验证方式、不同的积累方式，不能混为一谈。

> 详细内容见 `S1-核心理论-精简文档.md` §2

### 1.3 实验证据链

#### 负结果：静态抽象hint不够（280号，POC-VMS-7g-v3）

10道奥赛题，三组对照（bare/knowledge/highlevel）。对8道bare失败的题：
- bare: 0/8 = 0%
- knowledge: 2/8 = 25%
- highlevel: 1/8 = 12%

**结论**：静态高Level hint在奥赛题上没有胜率优势——太抽象，AI不知道怎么用。

#### 弱阳性：脉络继承+字典方向（283号，POC-VMS-8）

3道bare失败的题，引导树闭环（tree组）：
- bare: 0/3 = 0%
- tree: 2/3 = 67%

**最准确的证据表述**："从失败thinking提取的脉络 + 人工匹配的题目化方向 + 运行时HintInstance"在3道精选bare失败题上取得2次成功，并且成功proof使用了目标方向；它初步支持完整引导包的可行性，但**没有隔离TellCore、Renderer、lineage、人工选择、重启与新增预算各自的因果贡献**。

**脉络+方向的组合才是引导树的真正用法**：
- 字典提供了"翻译到什么"（Low Level化的具体形式）
- 脉络提供了"何时翻译"（到达转折点的路径）
- 两者结合才是引导树的真正用法

#### tell去特化验证（288-289号，POC-VMS-9/10）

- **POC-VMS-9**：tell可以去特化到拓扑结构级别（problem_type + ai_method_type + gap_type），形式化过滤（Pipe 0+Pipe 1）可以命中目标tell。全部PASS。
- **POC-VMS-10**：拓扑相同且距离极近的tell，可以用小概念标记分辨（Pipe 2）。只要两个tell能用语言表达出区别，就能定义概念来区分它们。全部PASS。

**三层Pipe架构**：
```
Pipe 0 拓扑化 → Pipe 1 形式化过滤（大概念，不漏） → Pipe 2 辅助AI（小概念标记，精准）
```

> 详细内容见 `S1-核心理论-精简文档.md` §3-6

### 1.4 四代演进对照（286号）

| 代 | tell识别方案 | 本质 |
|---|---|---|
| 盘古 | 三维稀疏矩阵、静态图 | 静态的状态感知 |
| 女娲 | 外显思维图T（11种节点+12种边） | 动态的结构化状态 |
| 燧人 | 元认知提问、连续发问六层 | 元认知提问 |
| 伏羲 | 识别"不自然"（冗余/隐藏乘积/虚假自由度/隐藏直和） | 识别表示与结构的不匹配 |

000号tell与四代的关键区别：回顾而非前向、路径未走而非表示不匹配、"走错路"而非"卡住"、动态而非静态、全line而非单点。

## 第二部分：分类学认知

### 2.1 坐标轴不是点（336号）——核心认知

**高Level概念是分类学的"坐标轴"，不是分类学中的"点"。**

"同构之桥"不是某个domain的——它是跨域桥接这个模式本身的名字。你不能把"跨域桥接"再归入一个更高的类别，它已经是属性维度本身了。

**结构知识与内容知识分离**：
- **结构知识**（分类学Schema/解释库中）：domain的定义、段结构模式的定义、高Level概念的三种解释文本——这些是坐标轴
- **内容知识**（tell库/hint库中）：具体的tell条目、具体的hint条目——每个条目有明确的{domain, 段结构模式}属性，是坐标系中的点

### 2.2 排除机制不是加速机制（337-338号）

分类学的价值不在于"把trace送入正确的分类目录"（加速），而在于"把不该参与的分类目录排除在Pipe之外"（排除）。

高Level概念和低Level具体tell一样，被放入专门的目录，有专门的AI从中启动进行识别。它不是"始终在场"的背景知识，而是和低Level一样是一个分类目录——只是描述方式不同。

### 2.3 去特化产出是Tell（344号）——核心认知

**去特化就是泛化，泛化就是Level提升——没有"去特化但Level不变"这种事。**

- Level是模糊连续谱系，不是离散等级
- "普通Tell"和"高Level Tell"是人为标签，不是二元分类
- 指导力不是单调的——Level 0（不去特化）指导力最低，Level ∞（过度去特化）指导力也最低，钟形曲线中间某处达到最大

### 2.4 Tell族的钟形曲线（345号）

同一个trace被不同去特化得到不同Level的Tell，构成一个"Tell族"。当按Level排序时，AI指导力呈现钟形曲线。系统应存储Tell族中的多个成员——不同场景用不同Level的Tell。

### 2.5 三步法找峰值（346号）

1. **用IBE找本质Level**——问"这个思维模式为什么在数学解题中有价值？"
2. **用结构映射保留关系、剥离表面**——保留操作关系结构，剥离表面特征
3. **检查可操作性**——AI拿到Tell后知道具体做什么吗？

Level是结果不是目标——正确抓住本质后Level自然落在峰值附近。

### 2.6 Tell的三种形态（347号）

| 形态 | 描述 | Level位置 |
|---|---|---|
| 一句话指示 | 简洁、具体、直接告诉AI做什么 | 钟形曲线中间偏左 |
| 思维流程引导式 | 逐步引导AI思维的流程 | 钟形曲线中间偏右 |
| 抽象标签 | 只有分类标签，无操作引导 | 钟形曲线右端（不应作为Tell存储） |

**钟形曲线修正**：同一Level的Tell，提示词形态不同，AI指导力不同。高Level Tell可以通过形态2（思维流程引导）恢复指导力。钟形曲线不是一条固定曲线，而是曲线族。

### 2.7 其他分类学认知

- **Tell↔Hint多对多关系**（333号）：一个tell可对应多个hint，一个hint可被多个tell触发。provenance与efficacy分账——数学有效≠系统有效。
- **触发依据三层**（334号）：元模式（高确定性）→模式匹配（中）→题目相关性（低/空）。层3为空时提示是方向性的，不是确定性的。
- **同一概念三种解释**（335号）：执行型（给推理AI）、识别型（给Telling AI）、判断型（给动态生成AI）。
- **高Level概念两种类型**（340号）：可展开的（过程型，展开维度固定）vs 无法指定展开方向的（方向型，展开维度开放）。

> 详细内容见 `筛选产出/S2-分类学认知-精简文档.md`

> **⚠️ 演化分析注（2026-08-15）**：§2.4-2.6的钟形曲线+三步法+形态修正是非特化研究中的**实践指导力峰值**。后续352号（降级为非单调假设）、371号（迁移工程+11变量+八契约+13条学术路线）、372号（帕累托前沿+9维偏序+概念格）逐步越过峰值——逻辑更正确但实践指导力下降。详见 `钟形曲线到帕累托前沿的演化分析.md`。方案保留§2.4-2.6（峰值），§3.3（Level是向量）和§3.1的"九个可"来自越过峰值的372号，应缩减。

## 第三部分：非特化定义

### 3.1 因果充分的取商（372号§2）——核心定义

> **非特化不是把一段trace"总结得更抽象"，而是对解题处境做一次"因果充分的取商"，再把所得等价类编译成可识别、可执行、可验证的认知技能。**

> **⚠️ 演化缩减注（2026-08-15）**：原372号§0的"九个可"（可识别/可选择/可实例化/可执行/可终止/可组合/可归责/可验证/可持续学习）来自372号的八契约+可持续学习，是越过峰值的过度设计遗产。缩减为"三个可"——可识别（触发）、可执行（操作）、可验证（反泄漏+语义）——其余六个在当前实验规模下不是核心约束。详见 `钟形曲线到帕累托前沿的演化分析.md` §5.4。

**trace不是可直接泛化的最小单位**——一条完整trace同时含有当前数学处境、已走路线、可分叉但未分叉的位置、采用的转向、转向后中间结果、最终成功或失败、大量叙述噪声。直接对整条trace做摘要，最容易学到的是"这份解答讲了什么"，而不是"哪一个认知动作在什么处境下改变了搜索状态"。

**分支事件**是非特化的输入单位：
```
分支事件 e = (转向前处境s, 已走路线h, 未探索分叉b, 采取的认知动作a, 转向后处境s', 可观察进展delta, 后续结果y)
```

**取商**：把若干表面不同但在目标关系下等价的对象视为同一个对象。需要声明"允许忽略的变换"集合G_nuisance（符号重命名、数值缩放、对象换壳、表示改写、领域迁移等）。**Level由允许忽略哪些变换共同决定**——这比"抽象感更高"更可操作。

**因果充分**：只在成功trace中反复出现的结构不一定导致成功。候选Tell必须同时满足：
- 充分性：保留下来的信息足以让未来系统判断"此时采用哪类认知动作可能有用"
- 因果性：该认知动作确实提高了产生预期中间进展的概率

**非特化生成的是等价类，不是一句话**：
```
TellCore    = 系统内部学到的可迁移认知技能
HintInstance = TellCore针对当前题、当前脉络、当前模型和当前预算的提示实例
```

自然语言提示只是等价类在运行时的一种渲染。非特化Pipe首先应优化TellCore，不能直接把"写出一句好提示"当成学习完成。

### 3.2 三个根本补充（372号§0，缩减版）

1. **Tell族不应只是一条按Level排列的曲线，而应是多维的**——很多Tell彼此不可简单比较高低（§3.3的T1/T2例子）
2. **Tell不只是方法说明，还需有触发条件和退出信号**——对应§3.1的"三个可"（可识别/可执行/可验证）
3. **Tell有效性不能只靠解题成功率判断，要证明它在控制混杂后确实改变了预期推理过程**——这是Phase 0的R/L/D/LD四组对照的设计依据

> **⚠️ 演化缩减注（2026-08-15）**：原372号§0的三个补充中，第1条被§3.3缩减（删除8维向量和概念格），第2条被§3.1缩减（"九个可"→"三个可"，删除认知Option的启动集/参数槽/绑定规则/组合接口/归责接口等），第3条保留（它是Phase 0实验设计的核心依据）。

### 3.3 Level是多维的（372号§6.1，缩减版）

单一Level轴会压扁不可比较的Tell。考虑两个Tell：
- T1对数学对象非常通用，但操作写得很具体
- T2只适用于图论对象，但操作流程高度通用

谁的Level更高？没有唯一答案。**Level是多维的**——这是372号§6.1中有教学价值的直觉认知。

> **⚠️ 演化缩减注（2026-08-15）**：原372号§6.1定义了8维Level向量L(T) = (object_generality, relation_generality, ...)，并进一步推出"Tell族是偏序和概念格""峰值应改成Pareto前沿"。8维向量在当前实验规模（1道题4次运行）下完全不可测量，帕累托前沿需要的研究规模远超当前能力。缩减为保留"Level是多维的"直觉认知和T1/T2例子，删除8维向量定义、偏序/概念格、帕累托前沿。在当前阶段用§2.4-2.6的"Level是模糊标量+形态维度"已经足够。详见 `钟形曲线到帕累托前沿的演化分析.md` §5.3。

### 3.4 思维力作为非特化Pipe的操作符（372号§5）

非特化Pipe可被理解为八种思维力的组合过程：
```
C5取商 → C2选规范代表 → C8命名不变量 → C4建立证书
→ C6生成对抗边界 → C7用反例修补 → C3从有限案例逼近开放边界 → C1控制探索成本
```

"寻找更多Powerful思维力"和"改进非特化"不是两条独立任务线。思维力研究直接提供非特化算法的元操作。

### 3.5 Tell升级为迁移工程对象（371号）

非特化应升级为迁移工程：从一个或多个trace中提取可迁移的关系结构，封装成具备触发条件、退出条件、正负案例边界、提示强度、运行时策略、失败critic和版本细化历史的Tell方法对象。

八个契约的概念骨架：语义契约、操作契约、触发契约、退出契约、迁移契约、反泄漏契约、负迁移契约、成本契约。

> 详细内容见 `筛选产出/S3-非特化定义与出题经验-精简文档.md` §1-2

### 3.6 Tell混杂功能风险（352b号）

最大风险不是Tell写得不够抽象，而是**Tell在实验中承担了多个混杂功能**：思维力引导、题目难度提示、解法空间裁剪、隐性方法泄漏、增加模型重试深度。如果不把这些功能拆开验证，实验结果会很漂亮但不可解释。

## 第四部分：TellCore与CaseCard

### 4.1 TellCore v0：局部-全局表示切换（382号）

**推荐候选C**——将模算术（层次1：模p）和p-adic赋值（层次2）统一为"局部-全局"策略。

**最小充分字段集（7个字段，来自383号字段消融）**：

```yaml
TellCore_minimal:
  invariant_claim: |
    当问题在全局/自然表示下陷入困境时，
    切换到局部表示（Z/pZ或Q_p），
    在局部表示下揭示隐藏的代数结构，
    将局部发现提升为全局结论。
  trigger_boundary:
    - 问题涉及整数的代数结构（整除性、素性、符号、幂、周期性）
    - 自然表示下的分析陷入困境
    - 问题中存在可以局部化的对象
  negative_boundary:
    - 问题核心在构造性而非分析性
    - 问题核心在几何结构而非代数结构
    - 问题已经在局部表示下
    - 问题在自然表示下有直接解法
    - 问题的核心困难在搜索空间大小而非结构隐藏
  parameter_slots:
    - p: 局部化的目标素数
    - level: 模p 或 p-adic赋值
    - objects: 需要局部化的对象
  internal_policy:
    step2: 分析问题条件，确定局部化目标p和层次
    step3: 将问题映射到局部表示
    step4: 在局部表示下寻找隐藏结构
    step5: 将局部发现提升为全局结论或约束
  progress_model:
    - 信号1: AI开始讨论"取模"或"p-adic赋值"
    - 信号2: AI在局部表示下发现了隐藏结构
    - 信号3: AI将局部发现与原问题目标建立联系
    - 信号4: AI成功将局部发现提升为全局结论
  termination:
    - 成功: 局部发现直接解决原问题或给出关键约束
    - 无进展: 尝试多个p或层次后未发现有用结构 → 退出
    - 部分进展: 局部发现给出部分约束 → 标记，考虑组合或分case
    - 冲突: 局部化导致丢失必要信息 → 让位给全局分析Tell
```

**字段消融核心发现**：
1. **1962的失败是TellCore设计的核心教训**——方向Tell（"切换到p-adic"）不够，需要操作路径Tell（step2-5的系统步骤）
2. **最小充分字段集是7个字段**——删除任一导致TellCore无法通过至少一门审计
3. **critic是假朋友拒绝的安全网**——2/5假朋友题需要critic协同
4. **TellCore v0不泄漏具体lemma**——Euler准则等具体数学工具不在TellCore中

### 4.2 CaseCard结构模板（382号）

CaseCard定义了每道测试题的完整元数据格式，包含10项评分维度：
1. bare基线 2. 策略中心性 3. 过程可观察 4. 假朋友可构造 5. 结构可变形

### 4.3 七项重要判断（388号）

1. 旧"Tell"一词负担了至少五种不同对象，必须拆开：TaxonomyTerm、TellCore、TellManifestation、TellRecognitionRecord、HintInstance

## 第五部分：出题经验

### 5.1 bare淘汰的meta教训

四轮bare淘汰（355/357/358/363号）反复得到同一结论：**GLM-5.2在bare条件下能做出绝大多数竞赛级题目**。经典定理外壳秒杀、标准谱方法秒杀、已命名深定理仍可恢复、新造题变体仍被秒杀。

**出题困境**：AI能做出来的题无法用于非特化验证。出题难度极高——需要同时避开经典外壳、标准方法、已命名定理、贪心短路、标准谱证书等多个"秒杀区"。

### 5.2 出题经验条目E-001~E-017

17条出题经验，每条含来源/现象/经验/下次怎么改。核心经验：

- **E-001/E-002/E-005/E-007**：经典定理/标准方法外壳会被秒杀——Motzkin-Straus、随机图删除、谱Rayleigh商、Bollobás等
- **E-004**：高Level思维力题至少需要两层锁——自然路线失败 + 目标思维力不仅要被想到还要被正确执行
- **E-010**：新造题必须和历史bare失败锚题同台比较
- **E-013**：出题应从奥赛母题拆解开始，而非凭空造题
- **E-014**：奥赛母题启发有Level族（Level 0-5），挑战GLM-5.2的新题应主要从Level 3-4出发
- **E-015**：先用真实题库筛Level 3-4机制盲区，再从盲区造题
- **E-016**：Level不是标签而是命题操作，要写设障脚本而非解法脚本

| 零件 | 作用 |

## 第六部分：合理工程约束

### 6.1 因果实验骨架（R4）

283号实验的问题：lineage、方向、新AI和新token窗口同时改变，最终成功只能支持"整个干预包有效"，不能证明其中任何一个组件单独有效。

**需要的因果实验骨架**：
1. **预注册**：arms、contrasts、资源、随机化、停止规则必须在看到结果前冻结
2. **随机化**：按case、source rollout、失败层和迁移距离做block；arm交错运行
3. **对照arm**：核心2×2矩阵——R（problem-only restart）、L（lineage-only）、D（direction-only）、LD（lineage+direction）。关键contrast：`LD−L`（direction的增量效果）、`(LD−L)−(D−R)`（direction是否依赖lineage）、`LD−R`（总效果）。还必须有distractor arm（LX）排除"任何额外建议都可能有帮助"
4. **盲化**：Proof Judge盲于arm；Solver盲于Case标签
5. **三审**：Process Auditor（机制执行）、Proof Judge（数学正确性）、Leakage Auditor（答案泄漏）三种真值分权，各自sealed后才能合并
6. **contrast级EvidenceRecord**：单次运行只产生观察性RunAudit；跨arm聚合后的预注册randomized contrast才允许生成EvidenceRecord

### 6.2 多系统边界隔离（R4）

1. 只读消费题海的冻结bundle，不直接消费即时Redis或未经聚合的DB标签
2. 不写回math:*生产流水线
3. 不import system.*——通过versioned JSON bundle对接
4. 自动评分不能直接改变TellCore或分类学本体，只能提出RevisionProposal

### 6.3 答案隔离（R4）

**永久不可见答案的角色**：Selector、HintRenderer、Solver、Process Auditor。

物理隔离要求：逻辑字段隐藏不能替代物理Vault/身份/路径隔离。

### 6.4 人工Gate不可绕过（R4）

模型不能自己签发Gate。需要人工Gate的场景：
1. QuestionRelease Gate——题目发布前人工批准
2. Case Role Freeze Gate——bare结果出来后人工冻结Case身份
3. Revision Gate——Tell晋级、边界修改、退休需两次职责分离的签署

### 6.5 append-only + 版本化（R4）

永不原地覆盖的内容：原始attempt证据、旧Tell版本、负EvidenceRecord、替代因果解释、被拒绝的RevisionProposal、题目角色冻结记录、分类学坐标历史版本。

题面变化必须新版本，使旧审稿和旧baseline失效。修订通过新版本和显式supersedes关系表达。

### 8.1 最小端到端实验

**先跑通一条真实实验**：

```
选一道bare失败题（如1631）
```

这条路径只需要1道题、1个TellCore、4次运行（R+L+D+LD）。如果成功，就有了第一个因果证据；如果失败，就知道了什么不行。

### 8.2 Phase 0实验结果（2026-08-15完成）

> **实验报告**：`eight-system/runs/phase0/experiment_report.md`
> **EvidenceRecord**：`eight-system/runs/phase0/evidence_record_001.md`
> **预注册文档**：`eight-system/runs/phase0/preregistration.md`

#### 4组结果

| Arm | 路线层 | 证明层 | 落盘层 | Verdict |
|---|---|---|---|---|
| R (bare) | FAIL | FAIL | FAIL | FAILED |
| L (lineage) | **SUCCESS** | partial (4/5) | FAIL | ROUTE_ONLY |
| D (direction) | **SUCCESS** | partial (4/5) | FAIL | ROUTE_ONLY |
| LD (lineage+direction) | **SUCCESS** | **SUCCESS** | **SUCCESS** | **SUCCESS** |

#### Contrast结果

**Proof Level:**
- C1 (LD−L) = 1：direction在lineage基础上增加proof完成
- C2 (LD−L)−(D−R) = 1：direction依赖lineage才能完成proof（交互效应）
- C3 (LD−R) = 1：总效果

**Route Level:**
- C1 (LD−L) = 0：direction不增加route finding（L自己找到了）
- C2 (LD−L)−(D−R) = -1：direction单独时route效果更强
- C3 (LD−R) = 1：总效果

#### 三个关键发现（修正了方案预期）

1. **Lineage alone足以引导route finding** — L（只有脉络）自己发现了QR/Euler方向（thinking中8处"quadratic residue"，2处"Euler's criterion"）。TellCore v0的direction hint不是在告诉AI它不知道的信息。

2. **Route finding ≠ Proof completion** — L和D都找到了正确路线但都hit了token limit。只有LD在token预算内完成了proof。

3. **TellCore v0的价值在于认知支架（cognitive scaffold），不是token efficiency** — Step 4 continue实验修正了原"token efficiency"假说：
   - L在thinking中**已完成完整证明**，continue后立即输出（105K chars thinking）
   - D在thinking中**未完成证明**，continue后从头开始再次失败（105K chars thinking，与L长度相似）
   - L和D的thinking长度相似但L完成而D没有 → 不是token数量问题，是**推理锚点**问题
   - Lineage提供推理锚点（x₃≡7(mod 8)作为出发点），direction提供工具提示（QR/Euler），两者组合使proof completion成为可能

#### Step 4 Continue实验结果（2026-08-15）

> **详细报告**：`eight-system/runs/phase0/experiment_report_step4.md`

| Arm | Continue结果 | 关键观察 |
|---|---|---|
| R | FAILED | continue thinking从头开始，仍无QR/Euler，hit token limit |
| L | **SUCCESS** | thinking中已完成证明，continue立即输出完整proof |
| D | FAILED | thinking中未完成证明，continue从头开始，hit token limit |

#### 对方案其他部分的修正

- **§2.4-2.6 钟形曲线理论的实证补充**：Phase 0实证表明指导力不是单一标量，需要分层测量——至少有"认知指导力"（route finding + thinking中完成证明）和"执行指导力"（token预算内完成proof输出）两个维度。同一Tell在这两个维度上的峰值可能出现在不同Level（L在认知维度已到峰值，执行维度还差一点；LD在两个维度都到峰值）。这与§2.6的"曲线族"修正一致——钟形曲线形状取决于测量维度。§2.5三步法找峰值的步骤3"检查可操作性"需要补充：必须指定测量维度。详见 `experiment_report_step4.md` §7。
- **§4.1 TellCore v0的字段消融核心发现**：原第4条"TellCore v0不泄漏具体lemma"仍然成立，但需要新增第5条——"TellCore v0的direction hint不是唯一路径，AI有能力从lineage中自己发现方向；TellCore v0 + lineage的核心价值是认知支架（推理锚点），不是信息传递或token效率"
- **§3.6 Tell混杂功能风险**：Phase 0实证了"Tell在实验中承担了多个混杂功能"——route finding、proof completion、thinking efficiency是三个不同的功能，需要分别验证
- **§6.1 因果实验骨架**：R/L/D/LD四组对照已验证可行，continue实验是有效的token budget扩展方法
- **§3.1 因果充分的取商**：lineage作为"预计算context"的价值机制需要重新理解——不是"省去的计算步骤"，而是"推理的锚点"
